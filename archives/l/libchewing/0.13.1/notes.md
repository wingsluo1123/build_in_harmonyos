# libchewing 0.13.1 OHOS adaptation notes

- Upstream: https://codeberg.org/chewing/libchewing (homepage https://chewing.im/), tag v0.13.1 (commit f071d2e95c531cc39bb4325cd5a5d0e1d51daef8).
- Release artifact libchewing-0.13.1.tar.zst (sha256 c897a5d0aadfdeb07784e1411ceac0efef2c97bea8143fb3b1dcde8274e14fc0) is zstd-compressed; OHOS Python tarfile cannot reliably extract .tar.zst (missing zstandard extension, code-signature blocks .so), so the recipe uses Codeberg git-archive .tar.gz (318937 bytes, sha256 a7c8c197c6d1a4cd715d7e7c6de97d975813840219e47dc539805fd5911aa7ee) plus the data submodule archive (libchewing-data at bfba418, 9093785 bytes, sha256 79a3597d8b53fd86188ccef08763618d63b8e0ebca06f5a15a409ec5aff70688) laid out to data/.
- Build system is CMake >= 3.27 with Rust >= 1.95 via Corrosion (corrosion_import_crate for chewing_capi, chewing_testhelper, chewing-cli). find_package(Corrosion QUIET) first, then FetchContent from github if missing. No Corrosion vendoring in this revision; if CI/true-machine fetch fails, next iteration will vendor or mirror it.
- CMake options for OHOS: BUILD_TESTING=ON (run upstream suite in build), BUILD_DOC=OFF (needs texinfo, unavailable), BUILD_DATA=ON (dictionary tsi.dat/word.dat/swkb.dat/symbols.dat required by tests), USE_VALGRIND=OFF (no valgrind on OHOS), USE_SYSTEM_CHEWING_CLI=OFF (use freshly built chewing-cli for dict generation). Toolchain: SDK true name CMAKE_SYSTEM_NAME=OHOS + PROCESSOR=aarch64 with build-folder-only Platform/OHOS.cmake and Platform/HarmonyOS.cmake shims (each include(Platform/Linux), via CMAKE_MODULE_PATH; fluidsynth precedent, libvpl/libmatio OHOS-name precedent). Latest preflight shows shims removed "System is unknown" but "C compiler identification is unknown" persists for profile /data/service/hnp/bin/clang, so generate() now probes each compiler candidate with --version plus trivial compile+link and pins the first working CMAKE_C/CXX_COMPILER (main + test_package); build() first emits short HMBS_CMAKE_DIGEST filtered lines to survive summary truncation. SDK ohos.toolchain.cmake still included first when found. Prior native-strip removed nothing (Conan 2.30 toolchain has no SYSTEM lines, log "no SYSTEM lines") so unknown HarmonyOS persisted; Linux masquerade and sysroot fallback depended on missing /data/service/hnp/ohos-sdk.org. Round-4 re-read: broadened discovery still returned candidates=0 with walk root missing /data/service/hnp/ohos-sdk.org, so the Linux+explicit-sysroot fallback never triggered and every cross variant failed; native needs no sysroot on the OHOS worker. Round-3 evidence: ohos.toolchain.cmake was NOT found at the two guessed globs (WARN in preflight), so conan fell back to HarmonyOS mapping that vanilla cmake 4.4.3 cannot parse; discovery is now broadened (conf user_toolchain, OHOS_* envs, recursive globs, depth-limited pruned walk with candidate logging) plus pre-configure clang --version sanity output and ls of /data/service/hnp/bin and ohos-sdk.org; if the toolchain file is genuinely absent, generate() falls back to Linux + explicit --target=aarch64-linux-ohos/--sysroot/CMAKE_SYSROOT derived from the SDK sysroot. Host harmonybrew llvm-ranlib is ignored for CMAKE_RANLIB. Only CMAKE_RANLIB is overridden to the hnp system symlink (libpano13 precedent: SDK native/llvm/bin ships llvm-ar but no llvm-ranlib). SDK llvm/lib is prepended before harmonybrew cargo-runtime bottles on LD_LIBRARY_PATH so SDK libs (libxml2.so.16) keep precedence during cmake try-compile. Global CC/CXX stay owned by CMakeToolchain; Rust-side C linking uses target-specific CC_aarch64_unknown_linux_ohos/AR/RANLIB + cargo target linker.
- Rust toolchain: recipe declares `tool_requires("rust-toolchain/1.97.1")` (below/0.11.0 + libetebase/0.5.8 precedent; no rustup bootstrap since stock rustup fails with "unrecognized OS type: HarmonyOS"). generate() prefers system cargo/rustc when present, otherwise stages signed copies from the tool_requires package (copy cargo/rustc + librustc_driver to build_folder/rust-toolchain and self-sign via binary-sign-tool, symlink read-only payload, marker idempotent), stages Harmonybrew openssl3/zlib bottles for cargo runtime libs on LD_LIBRARY_PATH (OHOS loader ignores DT_RUNPATH), probes CA bundle for rsproxy.cn sparse mirror, writes both source .cargo/config.toml and build cargo-home/config.toml, and exports CARGO/RUSTC/CARGO_HOME/LD_LIBRARY_PATH/SSL_CERT_FILE via conanbuild_rust so Corrosion can invoke cargo during cmake configure.
- Upstream tests: 14 C cases + 3 cargo tests = 17 ctest entries (ctest_entries). Tools (performance/randkeystroke/simulate/stress/testchewing/genkeystroke) are built via check target but not ctest entries. Curses optional (genkeystroke only if found). Valgrind duplicates only if valgrind present. Recipe parses ctest -N for discovered and per-test Passed/Failed lines (or LastTest.log) with identity passed+failed==executed, executed+skipped==discovered.
- test_package builds test_chewing.c against Chewing::chewing (chewing_new/version/KB/config/handle_Default/commit/buffer lifecycle, 6 checks) via CMake + CMakeDeps/Toolchain, runs ctest, emits HMBS_TEST_PACKAGE_RESULT, and re-emits HMBS_UPSTREAM_TEST_RESULT from package res/hmbs_upstream.json for cache-hit runs.
- No patches in this revision. No commands.json: package_type is library; chewing-cli binary is installed incidentally via cmake.install but not declared via bindirs, so L0k treats it as library.
