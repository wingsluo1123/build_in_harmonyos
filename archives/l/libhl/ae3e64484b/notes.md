## 编译步骤

上游仓库根只有 `Makefile.in`/`aclocal.m4`/`configure.ac`（**无预生成 `configure`**），
预生成的 `configure` 在 `build/` 子目录内
（其下的 Makefile.in 等是回指父目录的相对符号链接）；configure 依据自身路径相对当前目录
推导 srcdir，因此构建必须在 `build/` 内启动（srcdir=`..` → 仓库根）：

```bash
cd build
./configure --prefix=$DEFAULT_PREFIX
make static          # 或 make shared
# 上游手写 install 目标忽略 DESTDIR，需 LIBDIR=/INCDIR= 覆盖（配方改用 copy 打包）
```

配方以 Conan Autotools 辅助实现：`chdir(build/) + configure(build_script_folder=build/)`，
打包用 `copy()`（libhl.a / libhl.so + src/*.h）。

### R6 例外声明（修改生成文件 configure）
上述 umask 修复直接改写生成文件 `build/configure`，属 R6 的**显式例外**，依据：
1. 上游 tarball **根目录不含预生成 `configure`**（只有 `configure.ac`/`Makefile.in`/`aclocal.m4`），
   预生成的 `configure` 仅存在于 `build/`，且 `umask 077` 两行是 autoconf 生成
   config.status 临时目录逻辑的产物——无法通过改 `configure.ac` 局部消除。
2. `refresh-patch` 的 `EXCLUDE_DIRS` 硬编码包含 `build`（scripts/ohc/refresh_patch.py），
   且 `configure` 命中 `_is_likely_generated`（内容含 `Generated by GNU Autoconf`）被静默排除
   —— 手工放入 `patches/` 的 configure 补丁会被 refresh-patch 的 destructive 重建删除，
   `finish` step [1/10] 每次都会重建补丁，故 patches/ 无法承载该修复。
3. 修复内容为纯文本两处 `umask 077` 删除（`replace_in_file`，字符串与上游原文逐字一致），
   **无任何平台宏注入**，不改变 configure 逻辑分支。

## 注意事项
- shared 选项映射到上游 `make shared` / `make static` 目标（上游 install 目标不处理 shared，配方以 copy 打包两者）。
- 上游 configure.ac 含硬编码 `-I/-L /usr/local`（仅搜索路径，不影响产物与安装路径），配方未绕过。
- support/libut 子模块不在源码 tarball 内；CI 环境不取子模块、不跑上游单测，L1 消费者验证由 test_package 承担。
- `make` 固定 `-j1`（配方 `args=["-j1"]`）：CI 构建 #94441 在默认 `-j20` 下报
  `make: jobserver mkfifo: .../GMfifo46681: Operation not permitted`，随后 libtool 连续
  `fork: retry: Resource temporarily unavailable`，`make static` 以 Error 2 失败。
  根因见知识库 E074（鸿蒙 SELinux 禁止用户进程创建 FIFO，GNU make jobserver 依赖 FIFO
  传递并行令牌；同时高并发 fork 撞 worker 进程上限）。`Autotools.make` 检测到 args 中
  已有 `-jN` 便不再追加默认并行度，故显式 `-j1` 即为最终值。修复后本地 conan create
  实测 `RUN: make static -j1`，无 jobserver/fork 报错，test_package 1/1 Passed。
