# QSoas 3.3 HarmonyOS PC 适配说明

## 构建范围

QSoas 3.3 使用 qmake，正式依赖闭包为 `qt5/5.15.19`、`mruby/3.3.0` 和
`gsl/2.8`。构建使用已发布的 OHOS/armv8 制品，不在本配方中重建依赖。

上游 `build-info.rb` 只把主机名、当前时间以及可选 Git 信息写入
`src/build.hh`。正式 release 归档没有 `.git`，版本号已经由 qmake 定义；因此补丁增加
`prebuilt_build_info` 能力，由配方生成固定内容的 `build.hh`。构建命令同时设置
`RUBY=/qsoas-build-must-not-use-ruby`，证明构建过程中没有隐式使用 Worker 上的 Ruby。
这既保持版本和构建信息接口，也避免主机名、时间和构建路径进入产物。

已发布 Qt 包没有拆分发布 QtHelp、QtSvg，且部分 qmake `.pri` 保存了旧构建缓存路径。
配方在本包构建目录复制 qmake 元数据并改写为当前已发布 Qt 包路径，不修改 Qt 制品缓存；
`no_qthelp` 与 `no_qtsvg` 仅关闭不可用的帮助浏览器和 SVG 导出入口，核心数据处理、拟合、
脚本和外部函数能力均保留。应用图标改用 release 源码实际跟踪的 SVG 文件。

上游 ZIP 支持本来就是按 `/usr/include/zip.h` 是否存在而选择的可选能力。仓库中的
`libzip/1.11.4` 与 `qt5/5.15.19` 已发布二进制分别绑定 `zlib/1.3.1.1` 与
`zlib/1.3.1`；覆盖任一版本都会使另一个依赖在 `--build=never` 下缺少匹配制品。因此本次
不启用 ZIP 可选能力，也不把它计入功能或测试通过数。补丁提供通用 `LIBZIP_DIR` 入口，
用于依赖闭包一致的构建环境，而无需依赖宿主 `/usr/include`。

## B 类问题及修复

`ExternalFunction` 原实现把 `waitForStarted()`、写入和多次
`waitForReadyRead()` 当作彼此独立的等待。外部程序只要在每轮超时前持续输出一个字节，
即使永远不发送 `// -> DONE`，事务也不会结束。

修复以 `QElapsedTimer` 建立单调总截止时间，把剩余预算传给启动、写入排空和响应读取。
响应循环在每轮读取、追加或接受 `DONE` 之前检查剩余预算，因此缓冲区持续可读也不能绕过
截止点；累计响应另设 16 MiB 上限，避免无界内存增长。
任一步失败都会杀死并回收当前子进程、丢弃半包，再以非零状态报告错误。有效 JSON 加
`// -> DONE` 的正常路径保持不变。默认总预算为 30 秒；测试使用受限环境变量把预算缩短，
该变量只接受 100 到 300000 毫秒。

真机三臂验证使用安装后真实 `qsoas --pyfunc`：

- 原实现面对每 50 ms 输出空格、永不结束的助手进程，3 秒外层看门狗终止，退出码 124；
- 仅给每次 `waitForReadyRead()` 固定 200 ms 的伪修复仍被 50 ms 滴流续期，退出码 124；
- 单调总截止时间实现约 500 ms 后失败，返回非零，并确认助手进程已被回收；
- 持续高速输出完整行但永不结束的助手同样约 500 ms 后失败，证明检查不依赖缓冲区变空；
- 正常助手返回合法 JSON 和结束标记，`sample(2, scale=4)` 得到 8，退出码 0。

## 验证范围

消费者测试检查安装后真实命令，不以源码级断言代替：版本与确定性构建信息、正常外部函数
事务、慢滴流超时、异常退出、子进程回收，以及最终 ELF 的架构、签名、运行路径和私有路径
泄漏。QtHelp 与 QtSvg 属于未发布可选模块，不计入可用功能或测试通过数。

上游测试通过总入口运行 19 个目录套件。Linux 对照使用相同 QSoas 3.3、GSL 2.8 和输入，
`fits/implicit-fits` 不会中止，证明目标端的 `derivative is zero` 不能归为上游固有行为。
修复在一维求根迭代中显式消费 GSL 返回状态，使该可恢复种子失败回到上游已有的候选种子
选择逻辑，避免从 C 回调跨边界抛出 C++ 异常。上游文本后端测试依赖 Ruby 生成 126 个
输入文件；目标环境没有已发布 Ruby，因此使用仓库内的无依赖 Python 等价生成器。其输出
已在 Linux 上与原 Ruby 生成器逐文件比较，126/126 完全一致。最终总入口登记并完成
1616 个断言点：1610 个成功，50 个由上游标记为数值 `imprecision`（不属于失败），6 个
ZIP 断言因明确关闭的可选 libzip 能力产生异常；普通失败为 0。没有修改上游测试或放宽
期望值。

最终 CI、审核、合入和 release 发布状态以 PR 与制品仓结果为准。
