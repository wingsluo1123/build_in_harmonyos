# QSoas 3.3 路径 B 证据

## 问题边界

本条不是“给某次读取加超时”，而是外部计算事务的时间预算语义：进程启动、请求写入、响应
组帧和 `DONE` 完成标记必须消费同一个单调总截止时间。循环内重新使用相对超时会被持续碎片
输出无限续期。

## 真实生产路径

验证调用安装后的 `qsoas --pyfunc`，经过生产 `ExternalFunction`、`QProcess`、JSON 行协议
和 `DONE` 完成标记。助手只负责扮演协议对端；测试没有复制客户端等待循环。

## 可复现输入与输出

- 正常助手：返回 `{"values":[8.0]}` 与 `// -> DONE`，命令退出 0、结果为 8。
- 慢滴流助手：先返回合法 JSON，随后每 50 ms 输出一个空格，保持存活且永不发送 `DONE`。
- 持续可读助手：连续输出带换行的完整响应行，使读取缓冲区保持可读，但永不发送 `DONE`。
- 提前退出助手：返回半个 JSON 后退出。

原实现和“每轮等待 200 ms”的伪修复面对慢滴流均超过 3 秒，由独立看门狗以 124 终止。
正确修复以 500 ms 总预算失败，返回非零，并确认助手 PID 不再存在。提前退出也映射为明确的
事务失败。持续可读助手也在同一总预算内失败，证明截止检查发生在每轮消费数据和接受 `DONE`
之前，而不是只在读取暂时为空时执行。撤销核心补丁会稳定恢复看门狗失败。

## 修复不变量

1. 截止时间来自单调时钟，墙钟变化不改变预算；
2. 启动、写入排空和每轮读取只获得同一截止点的剩余时间；
3. 收到碎片不会延长截止点；
4. 即使缓冲区持续可读，每轮消费和接受完成标记前仍检查截止点；
5. 响应累计大小有明确上限，不能在截止前无界占用内存；
6. 超时、写入失败、提前退出或非法响应均杀死并回收旧进程、丢弃半包；
7. 完整合法事务仍返回原数值结果。

## 查重结论

正式知识查重为 `create`，最高相似度 0.08。开放草稿 `E429-draft-58E6` 的主要机制是 SCPI
字节流的短读组帧；本项目已经有明确 `DONE` 帧界，新增问题是多个等待阶段各自获得相对超时
导致总事务无界，以及失败后可复用进程与半包必须一起丢弃。

## 适用范围

适用于复用解释器、数值助手、插件宿主、语言服务器或编译服务的同步请求。一次性子进程若由
单个有界等待覆盖完整生命周期，可以使用更简单的模型；异步客户端还需要 request id 或
generation 隔离迟到回调，该部分不在本条测试分母内。
