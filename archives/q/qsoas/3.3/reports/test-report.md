> 测试日期：2026-10-16
> 目标环境：HarmonyOS PC aarch64，HongMeng Kernel 1.12.0
> 构建环境：HarmonyOS clang 15，Conan 2，OHOS 6.0 profile

上游计数单位是 QSoas 内置 `assert` 运行时实际登记的独立断言点，不是 `.cmds` 文件数。
总入口运行完成 1616/1616 个断言点；其中 1610 个成功，50 个结果由上游归类为
`imprecision` 而非失败。未把新增测试或构建成功计入上游分母。

## 上游测试边界

- 19 个目录套件由 `run-all-tests.cmds` 单次完整执行到最终汇总。
- `fits/implicit-fits.cmds` 在目标端原先因 Steffensen 某个候选种子的零导数错误跨 C 回调
  抛出 C++ 异常而中止。相同 QSoas 3.3、GSL 2.8 和输入的 Linux 对照没有中止；修复显式
  消费 GSL 迭代状态后，目标端使用后续候选种子完成该断言，结果按上游规则归为
  `imprecision`。
- `text-backends` 所需 126 个输入由无依赖 Python 生成器创建；与上游 Ruby 生成器的
  126 个输出逐文件比较完全一致，因此没有减少该组的 507 个断言点。
- `globs/zip.cmds` 的 6 个断言依赖本次明确关闭且不计入交付能力的 libzip，产生 6 个
  异常，不计通过。
- 其余断言没有普通失败；没有修改上游测试、放宽容差或把异常写成成功。

## 新增消费者验证

测试始终调用 Conan 包内绝对路径的真实 `qsoas`：

1. `--version` 返回 3.3，并包含确定性的 release 构建信息；
2. 外部函数助手返回合法 JSON 和 `DONE`，`sample(2, scale=4)` 返回 8；
3. 助手每 50 ms 输出碎片但永不发送 `DONE` 时，单调 500 ms 总截止时间生效，命令非零
   返回且助手进程已被回收；
4. 助手连续输出带换行的完整行、使缓冲区持续可读但永不发送 `DONE` 时，同一截止时间仍
   生效，命令非零返回且助手进程已被回收；
5. 助手在半包后退出时，命令非零返回并报告提前结束。

HarmonyOS 特有消费者场景还检查安装产物为 AArch64 ELF、恰有一个 `.codesign`、没有
`RPATH/RUNPATH`，且二进制不含 `/storage/Users/`、`/home/`、`/.conan2/` 或
`/.cache/` 私有路径。

## 三臂与回退负测

| 实验臂 | 同一慢滴流助手结果 |
|---|---|
| 原实现 | 3 秒外层看门狗终止，退出码 124 |
| 伪修复：每轮 `waitForReadyRead(200)` | 碎片持续续期，3 秒外层看门狗终止，退出码 124 |
| 正确修复：共享单调总截止时间 | 消费者 15/15 通过；慢滴流与持续可读响应均约 500 ms 非零返回并回收助手 |

三臂使用同一官方源码、同一真机及同一依赖闭包。原实现和伪修复只作为工作区外的验证变体，
不进入 Conan 制品或提交内容。
