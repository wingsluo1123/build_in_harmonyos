# sacc 1.07 adaptation notes

- Source: Debian original `sacc_1.07.orig.tar.xz`, SHA256 `900dad8059ff7b47d36ce845d0d8403f3f6a317c52d3c67d8b67cc1a93e178e2`; all 12 files match upstream tag commit `d70616c357a135b8e251fe1974cf88f529dbc67f`.
- License: upstream ISC `LICENSE`, copied into the Conan package.
- Build: upstream GNU make with `UI=ti`, `IO=tls`; Conan supplies the target compiler, LibreSSL and ncurses paths, and the static link order `-ltls -lssl -lcrypto -lpthread -lncursesw`.
- Upstream 1.07 source has no automated test target. The package adds four installed-program consumer checks: executable present, local Gopher menu selector and listing, local text selector and body, and missing-URL rejection. The fixture listens only on `127.0.0.1` and needs no external service.
- WSL Linux x86_64 with Conan 2.29.1: `conan create . --build=missing -r=ohpcd` passed source checksum, build, install, and four of four consumer checks; log `research/sacc-linux-conan-2.log` in the competition workspace.
- Official OHOS armv8 Buildbot #80046 compiled and packaged the original recipe, but the consumer suite passed only 2/4 checks: both local Gopher tests failed before the server accepted a connection. The CI process had no controlling terminal; upstream `setup()` unconditionally opened `/dev/tty` and exited first. A headless WSL reproduction produced the same 2/4 result and `/dev/tty` error. Patch `0001-allow-headless-output.patch` preserves terminal behavior when available and lets piped, noninteractive output proceed without a controlling terminal. With this patch, a fresh headless WSL `conan create` passed 4/4 checks (`research/sacc-linux-headless-fixed.log`). OHOS verification of the revised commit is still pending.
- TLS handshake, certificate behavior, file downloads, interactive terminal navigation, and actual HarmonyOS PC use remain unverified. The software manifest has no `built` version entry and `commands.json` has `binary=false` until the target CI and publication evidence exists.
- Registered knowledge `knowledge/graph/E028.kv` was applied to dependency isolation: the recipe links Conan-provided static `libncursesw.a` instead of installing a competing shared ncurses library into a system path. The package installs only the client and its documentation; this prevents the shared-library override pattern described by E028. This is a preventive application, not a claim that an OHOS runtime conflict was observed.
- B-path knowledge proposal: `knowledge/drafts/DRAFT-15167-mode-aware-controlling-terminal.kv` and the matching `.md` generalize the observed `/dev/tty` failure to mode-aware terminal acquisition in CLIs that support both interactive and batch commands. This recipe applies the mode gate through `0001-allow-headless-output.patch`; `knowledge/drafts/fixtures/` verifies legacy failure, headless batch success, headless interactive rejection, and PTY interactive success (Linux 4/4). The current OHOS revision still needs a valid target CI run. Existing `DRAFT-E569-mdp-stdin-tty-freopen-pty-dual-channel` addresses PTY testing for pure TUI flows; committee review must decide whether this proposal is distinct enough for B credit.
