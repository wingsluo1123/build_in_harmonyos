# 路径 B 证据：自动回复策略必须基于逻辑邮件头

## 失败现象

上游 `readheaders()` 对 `fgets()` 取得的物理行立即执行策略。合法折叠的
`Auto-Submitted` 或 `Precedence` 把字段值放在续行时，首行只有字段名，
原实现直接结束该字段判断；续行又不会重新进入对应 `switch` 分支。程序因此
把应抑制的自动/批量邮件登记进节流数据库并进入回复发送路径。

## 标准与根因

RFC 5322 2.2.3 规定语义分析前移除续行 CRLF，并把头字段作为展开后的逻辑值
解释。RFC 3834 规定自动回复器应识别 `Auto-Submitted`，且只有 `no` 表示并非
自动产生。根因不是缓冲区太小，而是安全策略在错误的抽象层——物理输入块——
上提前决策。

## 三臂真机实验

三臂保持相同官方源码、编译器、`db1-compat/2.1.3` 和 sendmail 捕获端：

1. 原始策略臂：普通邮件、折叠 `Auto-Submitted`、折叠 `Precedence` 均进入
   发送路径。
2. 局部假修复臂：只在空的 `Auto-Submitted` 首行后额外读取一个续行。
   它修好单一样本，但折叠 `Precedence` 仍绕过策略，且没有统一边界状态。
3. 正确修复臂：所有字段先经同一个有界逻辑头重组器，再由字段策略消费；
   两类折叠策略均抑制，普通邮件不受影响。

`fe5cc1481e5a6ddd5057cdeba42172c916c1b802d0003bfcfb0f745b21499631`。
最终安装后 12 场景日志包含在完整 `conan create` 中，其 SHA256 为

## 正确实现不变量

- 以空行结束头部，同时识别 LF 和 CRLF。
- 只有以空格或制表符开头的后续物理行能续接已有字段。
- 展开时去除续行前导 FWS，并插入一个空格。
- 物理行或逻辑头超过固定上限、首行就是续行等畸形输入均失败关闭。
- 字段名和策略 token 不区分大小写，但 token 精确比较，不做危险前缀匹配。
- 策略完成后才允许更新发送者节流记录并进入发送副作用。
- 出站自动回复带 `Auto-Submitted: auto-replied`，降低回复链再次触发自动响应的风险。

## 可复用诊断步骤

1. 搜索安全策略是否直接位于 `fgets`/`read` 循环的单次返回分支中。
2. 同时构造同一字段的单行、单续行、多续行、LF、CRLF 和越界输入。
3. 观测不可逆副作用，而不只观测解析返回值；本例观测数据库登记与实际
   sendmail 子进程输出。
4. 给每一种策略字段复用同一逻辑头读取器，不在各分支散落特殊续行代码。
5. 做局部特判假修复对照，并撤销核心重组逻辑确认测试稳定失败。

## 适用边界

适用于基于 RFC 5322 风格头字段执行循环抑制、鉴权、路由或内容策略的邮件
工具，以及任何允许 continuation/folding 的行式协议解析器。不适用于明确
禁止续行且规定每条物理记录独立的协议。`Precedence` 是现实兼容策略的第二
个实证字段，核心标准主张以 RFC 3834 `Auto-Submitted` 为准。

该知识不等同于普通整数/字符串截断，也不主张“增大行缓冲即可修复”；创新点
是把策略提交点从物理读取块提升到有界逻辑字段，并以实际发送副作用验证
失败关闭。
