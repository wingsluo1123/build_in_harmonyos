## 适配问题与解决方案

| 问题 | 根因 | 解决方案 |
|---|---|---|
| Conan 依赖无法被上游 CMake 稳定发现 | PulseAudio/JACK 只按系统模块或 pkg-config 探测 | 优先链接 CMakeDeps 的 imported targets，保留原探测作为回退 |
| 有限文件已发送完成却在 EOF 后报错退出 | 发送循环只处理负错误，错误地把 `read()==0` 送入样本数计算并下溢 | 三态处理读取结果，只有正长度进入分帧；以退出码、精确包数和帧边界共同回归 |
| 后端读取错误被报告为成功 | 负读取结果停止循环但没有写回进程状态 | 保留负错误码，并用目录读取稳定触发错误，断言非零退出且不发送报文 |
| 网络头依赖 `packed`、多字符常量与原生 `uint32_t` | 线格式被主机端序和实现定义行为隐式决定 | 头字段改为字节数组，显式设置 `VBAN` 魔数并以小端 helper 读写帧号（普通移植回归，不作为 B 类新增知识） |
| 默认 FIFO 固定在 `/tmp/vban_0` | HarmonyOS PC 的可写临时目录由 `TMPDIR` 提供 | 优先使用显式设备路径，否则使用 `$TMPDIR/vban_0`，关闭时清理真实路径 |
| 文件输入 EOF 后仍构造数据包 | `read()` 返回 0 未被视为正常结束 | EOF 返回成功并停止发送，防止 `format_nbs` 下溢 |
| 文本发送成功却以发送字节数作为进程状态退出 | `socket_write()` 的正返回值被直接传给 shell | 仅保留负错误码，成功统一返回 0，并由测试严格断言 |
| CLI 缺少可靠的无副作用探针 | 未提供 `--version` | 三个命令新增 `-v/--version`，成功退出 |
| 已发布的部分音频依赖缺少 HarmonyOS ELF 签名 | 真机加载器拒绝未签名共享库 | 测试时只复制并自签名临时运行库，绝不修改依赖包或产物 |

## 构建与依赖

配方使用 `CMakeDeps` 和 `CMakeToolchain`，完整保留上游默认开启的三种音频后端：

- `alsa-lib/1.2.16.1`
- `pulseaudio/17.0.1`
- `jack/1.9.22`

构建产物为 `vban_receptor`、`vban_emitter`、`vban_sendtext` 三个命令。

## 测试设计

`test_package` 通过被测 Conan 包的绝对 `bin` 路径执行命令，共 35 条断言：三个版本
探针、有限文件 EOF 精确包数、负读取错误传播、独立双向黄金 UDP 数据报、文件后端 UDP 原样回环，以及
使用 HarmonyOS `TMPDIR` 的命名管道能力测试。FIFO 可用与能力受限分支均执行 5 条断言。
当 HMDFS 支持 FIFO 时执行实际回环；不支持时严格验证失败码、诊断路径和无残留，
不会把平台限制伪装成跳过或成功。
这些测试不依赖 ALSA、PulseAudio 或 JACK 服务，却仍验证默认后端参与编译链接，
并覆盖线协议、套接字、文件、FIFO、EOF 与清理路径。
