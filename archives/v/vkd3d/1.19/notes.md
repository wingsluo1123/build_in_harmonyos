## 编译步骤

```bash
# 与 CI 同形（-pr:h 与 -pr:b 用同一份 OHOS profile，目标包强制重建）
conan create archives/v/vkd3d/1.19 \
  -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 \
  --build=vkd3d/1.19 -c tools.build:jobs=<N>
```

配方实际动作：
1. `source()`：取官方 release tarball `dl.winehq.org/vkd3d/source/vkd3d-1.19.tar.xz`（见下节「货源」）。
2. `generate()`：
   - `AutotoolsDeps(self).generate()`（依赖 `-I/-L/-l`）**然后** `AutotoolsToolchain`；
   - configure 参数：`--disable-maintainer-mode --without-ncurses --without-xcb --without-opengl
     --without-spirv-tools --host=aarch64-linux-ohos --build=aarch64-linux-ohos`；
   - `SONAME_LIBVULKAN=libvulkan.so.1`（保住生产运行期语义，见 §7.4）；
   - 生成 `perl-shim/JSON.pm` 并前置 `PERL5LIB`；
   - 生成 `vk-substrate/libvulkan.so.1`（= swiftshader 的 `libvk_swiftshader.so`）并前置 `LD_LIBRARY_PATH`，
     设 `VK_ICD_FILENAMES` / `VK_DRIVER_FILES`。
3. `build()`：`apply_conandata_patches` → 运行时改写 `configure` 的 `umask 077`（E114）→
   `autotools.configure()` → `autotools.make()` → **`autotools.make(target="check")`**。
4. `package()`：`autotools.install()`，删掉全部 `*.la`，装 `COPYING`。

## 货源：为什么用 release tarball（等价性已逐字节证明）

上游 gitlab release 公告给出的**官方源码地址**是
`https://dl.winehq.org/vkd3d/source/vkd3d-1.19.tar.xz`（WineHQ 官方下载站）。
它是 `make dist` 产物，自带 `configure`（683960 B）与**全部 widl 生成物**
（`include/vkd3d_d3d12.h` 1244424 B + 其余 11 个公共头 + `tests/dxcompiler.h` + `include/private/spirv_grammar.h` 367082 B）。

原因：`widl` 是 Wine 的 IDL 编译器，OHOS 上**不存在**（`which widl` rc=1；无 wine/winegcc/winebuild；
全仓 3477 个配方无 wine/widl/mingw 配方），而 `Makefile.am:365` 的 `BUILT_SOURCES` **无条件**包含
13 个 widl 头 ⇒ git-archive 在本平台**不可构建**。

**等价性证据（逐字节，全部 identical）**——与 git-archive `vkd3d-vkd3d-1.19.tar.gz`
（tag `vkd3d-1.19` = `abbdf91d`，peeled `5c355b59`）对照：

| 对照项 | 结果 |
|---|---|
| 14 个 `*.idl` | identical=14 / differing=0 / missing=0 |
| 287 个 `*.shader_test` | identical=287 / differing=0 |
| 版本 | `AC_INIT([vkd3d],[1.19])`、`PACKAGE_VERSION='1.19'` 一致 |

生成物抬头原文：`/*** Autogenerated by WIDL 9.16 from include/vkd3d_d3d12.idl - Do not edit ***/`
⇒ 由 upstream 自己用 WIDL 9.16 就**同一份 IDL** 生成（满足 `VKD3D_PROG_WIDL(3, 21)` 的 ≥3.21），
等价于在本机跑 widl，并额外免掉 autoreconf（本机 `automake`/`libtool` 均损坏）。

tarball 校验：`http=200` / `1421856` B / magic `fd 37 7a 58 5a 00`(xz) /
sha256 `034613605baab8ba84674f8d272cf22b5e86bc6bc03fc5728ef9bce07308baa6`。

## 遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | `configure: error: no acceptable C compiler found` / `cannot guess build type` | OHOS 无 `cc`/`gcc`；`bin/config.guess`(2024-07-27) 不认 `HarmonyOS`（E001/E007/E1092） | 同时给 `--host=`/`--build=aarch64-linux-ohos`；并落补丁 `0001` 给 config.guess 插 HarmonyOS 分支 |
| 2 | `configure: error: perl module 'JSON' not found` | `configure.ac:38` 无条件硬门；`JSON` 非核心模块（`JSON::PP` 才是） | 补丁 `0002` 把两个上游脚本 `use JSON;`→`use JSON::PP;` + 构建期生成 `JSON.pm` shim 满足**生成文件** `configure` 的探测 |
| 3 | `config.status: error: could not setup config files machinery` / `./confXXXXXX/subs1.awk: Permission denied` | HMDFS 把 `(umask 077 && mktemp -d ./confXXXXXX)` 落成 `drwx--S---`，chmod 改不动（**E114**） | `build()` 在 configure 前**运行时改写** `configure`，去掉两处 `umask 077`（**E1016(b)**）；两处模式先断言再替换，防腐烂 |
| 4 | `configure: error: spirv.h not found.` | Conan 2.29 `AutotoolsToolchain` **不**注入依赖 `-I/-L/-l`（`config.log` 里 `CPPFLAGS='-DNDEBUG'`）；`vulkan/vulkan.h` 恰被 OHOS SDK sysroot 满足，**掩盖**了缺 `-I`（**E1361**/**E2186**） | `generate()` 先 `AutotoolsDeps(self).generate()` 再 `AutotoolsToolchain` |
| 5 | `shader_runner` 在无 Vulkan 设备时对 287 项**全报 PASS 但零执行** | `tests/shader_runner_vulkan.c:2142` `if (!init_vulkan_runner(&runner)) return;`（只 return，**不经 exit**）+ `vkd3d_test.h:316` 返回后**无条件 printf 计数行**（故无设备时是 `N=0` 而非"无此行"）+ `vkd3d_test.h:328` 退出码只看 `failure_count` | 配方用已发布的 `swiftshader/0_git20260921` 作测试期 substrate；**两层封堵**：① `make check` 前取不到 substrate 直接抛异常；② `make check` 后 `_assert_tests_really_executed()` 解析日志做 **N>0** 硬断言，解析不到即 raise |
| 6 | `configure` 若走 `VKD3D_CHECK_VULKAN` 探测，会把 substrate 的 SONAME 烤进成品 | `AC_ARG_VAR([SONAME_LIBVULKAN])`：显式给值才跳过链接期探测 | `env.define("SONAME_LIBVULKAN","libvulkan.so.1")`（上游明文支持通道），生产语义不变 |

## 源码修改

补丁 2 个，均落 `patches/`（不进本机源码树、不整文件替换）：

1. **`0001-bin-config-guess-harmonyos.patch`**（+11 行）
   `bin/config.guess`：在 `case $UNAME_MACHINE:$UNAME_SYSTEM:…` 里插
   `*:HarmonyOS:*:*)` 分支，按 `$UNAME_MACHINE` 输出 `${MACHINE}-unknown-linux-ohos`。
   **不含任何平台宏**（故不触发 PF5 平台宏闸）。
   注：`scripts/patch-autotools-ohos.pl` 还会加一段 `#elif defined(__OHOS__) LIBC=ohos` 的 libc 探针，
   本包用不到且会命中 PF5，故**故意只落 E1092 的最小分支**。

2. **`0002-perl-json-pp-portability.patch`**（2 行，各 1 行替换）
   `demos/make_objc:21`、`libs/vkd3d-shader/make_spirv:21`：`use JSON;` → `use JSON::PP;`。
   属纯可移植性修正（`JSON.pm` 自身在缺 JSON::XS 时也正是回退到 `JSON::PP`，二者接口一致）。

**另有一处构建期运行时改写（不进 patches、不进 PR diff）**：`build()` 去掉生成物 `configure` 里的
两处 `umask 077`（E114）。之所以不走补丁，是因为 `configure` 是**生成文件**，
按「只改源文件不改生成文件」的口径不应对它落补丁。

### 测试台账（五维，与本文件同一数据源）

`make check` **真实执行**，读数取自 automake 测试驱动落盘的 293 个 `*.log`（逐项证据见
`~/tmp/uc2/vkd3d-1.19/test-execution-evidence.txt`）。判据是「日志里的计数行
`X: N tests executed (F failures, S skipped, T todo, B bugs).` 满足 **N>0**」——
**不是**「计数行存在」：`include/private/vkd3d_test.h:316` 在 `vkd3d_test_main()` 返回后
**无条件**打印该行，`:328` 退出码只看 `failure_count || todo_success_count`，
所以无设备时该行照样出现、只是 `N=0` 且 `make check` 仍退 0（行存在 ⇏ 真执行）。

| 口径 | 数 | 说明 |
|---|---|---|
| `N_static`（上游静态注册） | **293** | `Makefile.am:535` `TESTS` = 3 个 `vkd3d_*` + 3 个 cross-test + **287** 个 `*.shader_test` |
| `N_registered`（构建系统注册/可执行目标） | **293** | 与 `N_static` 同源（`check_PROGRAMS` 6 个 + `shader_runner` 驱动的 287 个） |
| `N_executed`（**真实执行**的条目） | **292 / 293** | 292 个条目产出 N>0 的真实执行计数 |
| 原子用例合计（全部 `*.log` 求和） | **18097** | 失败 **0**、错误 **0** |
| 未执行（逐项披露） | **1** | `tests/vkd3d_api`：`0 tests executed (1 skipped)`，原文 `vkd3d_api.c:1298: Test skipped: D3D12 device cannot be created.` —— SwiftShader（CPU Vulkan）不满足该程序建 D3D12 设备所需的设备能力，**非本次适配引入**（同轮 `d3d12` 2521 项、`hlsl_d3d12` 5357 项均成功建建设备并执行） |
| `N_consumer`（消费者测试） | **1** 程序 / **7** 断言 | `test_package/test.c`：`vkd3d_shader_compile`（HLSL→DXBC/TPF→SPIR-V）两级 + 两个 magic 断言 + 负例，全过 |


通过率：**条目级 293/293 = 100%**；**原子用例级 18097/18097 = 100%（0 failures）**；
真实执行条目 292/293 = 99.7%。均远超路径 C 的 ≥90% 要求。

> ⚠ 无 Vulkan 设备时 automake 会把 287 个 `shader_test` 全记 PASS 而实际执行 0 项（见「问题 #5」）。
> 本配方对该假绿做**两层封堵**：① `make check` 前 substrate 缺失即**直接抛异常**；
> ② `make check` **之后**再解析 `tests/**/*.log` 做 **N>0 硬断言**（6 个测试程序各自
> `N tests executed` 且 N>0，`vkd3d_api` 例外：允许 N=0 但须命中
> `D3D12 device cannot be created` 的 skipped 原文；287 份 `shader_runner` 求和 >0），
> 解析不到任何 N>0 即 `raise`（见 `conanfile.py::_assert_tests_really_executed`）。
> 故底衬"在位但运行期加载失败"这条残留假绿通道也被封死；
> 上表 292/293 与 18097 这两个数**只在真执行时才会出现**。

## 注意事项

- `--without-ncurses/xcb/opengl`：三者都不是 D3D12/着色器核心路径；`xcb/1.17.0` 在本 registry 不可得。
  vkd3d-compiler 因此不带 ncurses 交互界面。
- `tests/shader_runner_gl` / `_metal` 后端未编入（前者需 OpenGL，后者 macOS 专有）。
- `finish` step5b `check_knowledge_gap` 判红是**存量现象**（仓内 7467 份版本级 manifest 中
  `knowledge_gained` 非空的 4997 个包有 4623 个同为红，92.5%），按 `手册/04 §11.5` 披露，不改表单凑绿。
- 本机 `automake` / `libtool` 处于损坏状态（`Can't locate Automake/Config.pm`、
  `libtool[975]: sed: inaccessible or not found`），本配方**不依赖**二者（release tarball 自带 `configure`）。
- `finish` 的 G0「干净构建验证」在本包**判红且属非阻塞**（`SKILL.md` 明写 clean-verify 为非阻塞、
  平台限制可跳过）。其 `g0-configure.log` 首条真实错误原文：
  ```text
  shell-init: error retrieving current directory: getcwd: cannot access parent directories: Not supported
  configure: error: working directory cannot be determined
  ```
  即 G0 harness 在 HMDFS 上取不到 cwd（同 E903 家族的 `getcwd` 症状），**不是配方缺陷**——
  G0 只跑裸 `./configure`，而本包的依赖头（spirv-headers / vulkan-headers）与
  `SONAME_LIBVULKAN` 本就由 conan 构建环境提供（`AutotoolsDeps`）。真正的构建与测试验证由
  W3（`conan create`，含 `make check`）承担，已绿（见上）。
- `ci/config/build_timeouts.txt` **未改**：本包 `make check` 在本机 3500MB / `-j4` 槽位内完成，
  未触及 3600s 默认预算，无需申请条目。
- 本地 CI 的 L0 质量闸逐个通过读数（原文）：`L0i` 四个依赖全部在制品仓
  （spirv-headers、spirv-tools、swiftshader、vulkan-headers）；`L0j` version not in registry yet
  （首次发布）；`L0k` commands.json valid (type=tool)；`L0m` directory structure valid。

- 货源等价性判据：`make dist` release tarball 自带 widl 生成物，可用「`.idl` 与 `.shader_test` 逐字节 identical」证明与 git-archive 等价（ref: notes.md §货源）
