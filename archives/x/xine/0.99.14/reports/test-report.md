# xine 0.99.14（上游 xine-ui）验证报告

- 平台：OpenHarmony PC / aarch64（真机原生构建，build == host），`uname -s` = `HarmonyOS`
- 工具链：clang / clang++（ohos-sdk sysroot，`aarch64-unknown-linux-ohos`，musl libc）
- 构建系统：autotools（tarball 内已带预生成 `configure`，OHOS 上未重跑 autoreconf）
- 结论：**编译 PASS；上游测试入口 10 项全部登记，4 项实测 / 6 项不适用（逐项根因见 §2）；test_package 27 项断言 27/27 PASS（含 3 个鸿蒙特有消费者用例）**

## §1 上游测试清点（为什么是 10，不是别的数字）

xine-ui **没有自动化测试套件**。`make check` 递归进入 20 个不同的 check 目录
（共 27 次进入事件），19 条输出全部是 `Nothing to be done for 'check'` / `'check-am'`，
0 个测试程序被执行；`configure.ac` / 各 `Makefile.am` 中不存在 `TESTS=`、`check_PROGRAMS`，
也没有 ctest / pytest / CI workflow 入口。

三个数字统计对象不同，勿混用：**20** = 被进入的唯一目录数（含顶层 `<WORK>` 自身）；
**27** = make 的递归「进入」事件数（`doc/man`、`misc/desktops`、`src/xitk` 等会被父目录二次进入）；
**19** = 打印「无可执行目标」的行数（`'check'` 12 行 + `'check-am'` 7 行）。差的第 20 个目录是顶层
`<WORK>`：它只有 Enter/Leave 两行（原日志第 93–94 行），其 `check` 目标是纯递归转发，连
Nothing-to-be-done 都不打印。

证据已全部落进本 PR：`reports/upstream-test-census.txt` §A（`TESTS=`/`check_PROGRAMS` 0 命中的
普查命令）、§B（`make check` 94 行原始输出全文 + 上述计数定义）、§C（10 个入口的 automake
声明原文与行号）、§D（configure 关键行）、§E（`session_ctrl` 差分探针）、§F（`xine-bugreport`
交互阻塞记录）；§B/§D/§E 的摘录源日志另附 sha256 锚点（census §G）。

因此“上游测试用例”只能按**程序级入口**清点。上游在本 tarball 里真实注册的、
可称为“测试/自证入口”的程序共 **10 个**：

| # | 入口 | 注册方式 | 本次处置 |
|---|------|----------|----------|
| 1 | `xine` | `bin_PROGRAMS`（src/xitk/Makefile.am） | 实测（5 次调用） |
| 2 | `xine-check` | `bin_SCRIPTS`（misc/Makefile.am，由 build-xine-check.pl 生成） | 实测（1 次调用） |
| 3 | `xine-bugreport` | `bin_SCRIPTS`（misc/Makefile.am） | 实测（1 次调用，判定为交互式，不入自动化） |
| 4 | `session_ctrl` | `EXTRA_PROGRAMS`（src/xitk/Makefile.am，源文件 `ctrl_test.c`） | 实测（2 次：编译 + 运行尝试） |
| 5 | `test` | `EXTRA_PROGRAMS`（src/xitk/xine-toolkit/Makefile.am，源文件 `test.c`） | 不适用（上游代码腐化） |
| 6 | `xine-remote` | 条件 `bin_PROGRAMS`（HAVE_READLINE） | 不适用（readline 探测失败） |
| 7 | `fbxine` | 条件 `bin_PROGRAMS`（HAVE_FB） | 不适用（libc 无 pthread_cancel + 无 fb 控制台） |
| 8 | `aaxine` | 条件 `bin_PROGRAMS`（HAVE_AA） | 不适用（AM_PATH_AALIB 探测失败） |
| 9 | `cacaxine` | 条件 `bin_PROGRAMS`（HAVE_CACA） | 不适用（libcaca 未发布） |
| 10 | `dfbxine` | 条件 `bin_PROGRAMS`（HAVE_DIRECTFB） | 不适用（directfb 未发布 + 无 DirectFB 图形栈） |

计数口径（与 `test_package/MANIFEST.yml`、PR 正文完全一致）：

```
上游入口（程序级，清点）  = 10  = 实测程序 4 + 不适用入口 6
实测程序                  = 4   (xine / xine-check / xine-bugreport / session_ctrl)
实测用例调用（执行次数）  = 9   (xine 5 + xine-check 1 + xine-bugreport 1 + session_ctrl 2)
不适用入口                = 6   (test / xine-remote / fbxine / aaxine / cacaxine / dfbxine)
```

> 分母口径说明：4 个实测程序共发起 **9 次**真实调用；`test_package/test.sh` 的 **27** 是
> 断言数（一次调用可产生多条断言），不是用例数，两个数字不可互相折算，故两处分别声明。

## §2 实测记录（4 个实测程序 / 9 次调用）与 6 个不适用入口的根因

### 2.1 `xine` — 5 次调用，PASS

无 X display 环境下，`xine` 仍能完成版本横幅、用法打印与三种格式的 keymap 发射；
上游这些路径调用 `exit(1)`，所以 **rc=1 是上游设计行为**，断言按 rc=1 判定。

| 调用 | 实测结果 |
|------|----------|
| `xine --version` | rc=1；`This is xine (X11 gui) - a free video player v0.99.14.` |
| `xine --help` | rc=1；`^Usage: xine` 起手的完整用法表，含 `--keymap` |
| `xine --keymap=default` | rc=1；914 行 X11 格式 keymap，151 条 `key = ` 绑定，含生成器头 `Automatically generated by xine-ui version 0.99.14` |
| `xine --keymap=remapped` | rc=1；读取 `$HOME/.xine/keymap` 后重新发射，与安装文件 `cmp -s` **字节全等** |
| `xine --keymap=lirc` | rc=1；1367 行 lircrc 格式，151 个 `begin` 块 |

绑定内容用编译期表 `src/xitk/kbindings_common.c` 做独立来源交叉校验：
`Play → Return`、`Pause → space`、`Stop → S`，与发射结果一致（避免“自己证自己”）。

### 2.2 `xine-check` — 1 次调用，PASS

rc=0，44 行报告。关键行：

```
[ good ] .../bin/xine is in your PATH
[ hint ] unknown operating system (HarmonyOS)
         I don't know anything specific about your 'HarmonyOS' operating system.
[OUCH!!] No DISPLAY found. Need X to check X...
```

上游诊断脚本在鸿蒙内核（`uname -s` = HarmonyOS，非其已知的 Linux/BSD 分支）上
完整跑通，无显示时跳过 X 项并继续 → 平台侧行为正确。

### 2.3 `xine-bugreport` — 1 次调用，实测但不入自动化

`xine-bugreport` 是 `xine-check` 的副本 + 交互式菜单。非交互 stdin 下仍持续输出并被
自身提示阻塞：产出 2468 行后停在 `please select (1..16):`，`timeout 420` 后 rc=124。
判定：**上游交互式程序，无法无人值守跑完**，因此登记为实测入口（1 次调用）但不写进
`test.sh` 的自动断言。

### 2.4 `session_ctrl`（上游 `ctrl_test.c`）— 2 次调用，编译 PASS / 运行受平台策略阻止

上游把会话远程控制测试程序写成 `EXTRA_PROGRAMS`，`make all` 不构建它。配方显式构建：

```bash
make -j1 -C src/xitk session_ctrl     # PASS：产出 27008 字节 ELF arm64 动态可执行文件
```

运行尝试 `src/xitk/session_ctrl 0` → **rc=159（SIGSYS），无任何输出**。用独立探针程序
在 OHOS 上复现并定位（与 xine-ui 无关，属平台系统调用策略）：

| 探针 | 结果 |
|------|------|
| `setuid(geteuid())` | rc=0，进程存活 |
| `setreuid(getuid(), getuid())` | **rc=159（SIGSYS），进程被终止** |

`connect_to_session()`（定义在 `src/xitk/session_common.c:51`，`setreuid()` 调用在其 :68；由
`ctrl_test.c:38` 的 `main` 调用）无条件调用 `setreuid()` 来临时取得会话 socket 权限，
因此该入口在鸿蒙 PC 上**只能编译、不能执行**。配方按此写死：`build()` 编译 `session_ctrl`
（校验交叉编译与链接），不执行它。这是平台策略，不是适配缺陷，故不计为失败用例。

### 2.5–2.10 六个不适用入口的具体根因

| 入口 | 根因（实测证据） |
|------|------------------|
| `test`（src/xitk/xine-toolkit） | 上游自身腐化：`Makefile.am` 未给该目标任何 Imlib 头路径，`test.c` 使用的是本 tarball 中已不存在的 xitk/Imlib 接口（`ImlibData`、`ImlibInitParams`、`xitk_get_key_modifier`、`XITK_WIDGET_LIST_GC`、`xitk_slider_set_pos`…，`20 errors generated`，rc=2），在 Linux 上同样编不过；且需要真实 X display 才能运行。属上游死代码，不为它打补丁。 |
| `xine-remote`（HAVE_READLINE） | `m4/readline.m4` 的 `AC_CHECK_READLINE` 只遍历硬编码前缀（`/usr/include`、`/usr/local/include` 等），不查 `CPPFLAGS/LDFLAGS`，因此看不到 Conan 的 `readline/8.3`；其后续 ncurses 探测只试 `-lncurses`，而 OHOS ncurses 仅发布 `libncursesw.a`（无 `libncurses`/`libtinfo`）。configure 输出：`readline.h... not found` / `no readline found, xine network interface will be disabled`。 |
| `fbxine`（HAVE_FB） | `src/fb/keys.c` 调用 `pthread_cancel()` / `pthread_testcancel()`，OHOS sysroot 的 `pthread.h` 不声明、`libc.so` 也不导出（独立链接探针 `undefined symbol`）；鸿蒙 PC 亦无 framebuffer 控制台设备 → 配方显式 `--without-fb`（兄弟包 xine-lib 1.2.13 用同一结论，那里是改写源码，因为 pthread_cancel 在其核心路径上）。 |
| `aaxine`（HAVE_AA） | `AM_PATH_AALIB` 靠 `aalib-config\|aainfo` 探测，configure 输出 `checking for aalib-config... no` → `HAVE_AA` 未定义。字符画前端非核心播放路径。 |
| `cacaxine`（HAVE_CACA） | `checking for caca >= 0.99beta19... no` / `checking for caca cucul... no`；libcaca 未发布到制品仓。 |
| `dfbxine`（HAVE_DIRECTFB） | `pkg-config directfb` 无结果，directfb 未发布到制品仓；上游在 configure.ac 的可选依赖块里把它与 fonts 安装一同门控；鸿蒙 PC 无 DirectFB 图形栈。 |
