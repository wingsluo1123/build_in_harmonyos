# E1001: 纯 bash 脚本 + install-only Makefile 的包会被 lang-preflight 判为 c（bash 永不参与主体统计）→ env_unsupported；按 R47 §D.4 复核为 bash

## 基本信息
- **严重度**: 2
- **类别**: make, bash, env-unsupported, false-positive, lang-preflight
- **作者**: E28B

## 错误特征
```
语言不匹配: task=bash, detected=c → env_unsupported|build_system.*make|source_stats.*c:1
```

## 根因分析
lang_detect.py 三级判定对纯脚本包结构上无解：①_manifest_scan 只要顶层存在名为 Makefile 的文件就返回 (c/cpp, make)，而 d-shlibs 的 Makefile 是 install-only（all: 为空规则）；②_source_stats 按扩展名统计并把 bash 排除在 total/dominant 之外（D.4 视 bash 为辅助脚本），而 d-shlibmove/d-devlibdeps 本身无扩展名（只有 #!/bin/bash 头），永远计不进来；③唯一被统计到的 c 文件是上游 autopkgtest 夹具 debian/tests/uppercase.d/libUppercase.c。三者叠加 → detected=c，与 task=bash 不匹配 → 自动写终态 env_unsupported。该工具在结构上无法产出 detected_language=bash。

## 推荐方案
**方法**: manual-boundary-rule-override

**说明**: 收到 detected=c/env_unsupported 时先按 R47 §D.4 边界规则人工复核：确认 Makefile 的 all: 为空且无 C 编译目标、被统计的 .c/.cpp 均为测试夹具而非产品源码、主体是可执行脚本（无扩展名 + shebang）→ 判误报，任务语言成立。保留 lang-preflight 完整输出与它自动写入的 env_unsupported result.json 作为证据，继续按任务语言适配，终态用 result --force 覆盖。不改框架、不删上游夹具。

**修复命令**:
```
（流程决策；证据记录于 notes.md 的 language_evidence 与最终回报）
```

**验证**:
```
python3 scripts/ohc-run.py lang-preflight <软件> <版本> --src <源码目录> --lang bash
```
