# E1014: Meson sanity check 编译的 C++ 测试二进制因缺少 libc++_shared.so 运行库路径而不可运行

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, build-system, meson, toolchain
- **作者**: 6F06, 8D7D

## 错误特征
```
Executables created by cpp compiler .* are not runnable|Error loading shared library libc\+\+_shared\.so|sanity_check.*returncode: 127|\.exe.*-> 127
```

## 根因分析
OHOS SDK 的 clang++ 编译的测试二进制运行时依赖 libc++_shared.so，该库位于 SDK 的 <llvm>/lib/aarch64-linux-ohos/ 子目录；Conan profile 的 LD_LIBRARY_PATH 通常只覆盖 <llvm>/lib 根目录，导致 meson setup 的 sanity check 无法加载共享库而判定编译器 "not runnable"

## 推荐方案
**方法**: recipe-generate-ld-library-path-prepend

**说明**: 在 conanfile.py 的 generate() 中，将 OHOS SDK 的 <llvm>/lib/aarch64-linux-ohos 目录 prepend 到 os.environ["LD_LIBRARY_PATH"]（仅当目录存在），使 meson sanity check 能加载 libc++_shared.so；同时可用系统头文件满足上游对第三方头文件的无条件探测（如 src/vulkan/meson.build 探测 vulkan.h 命中 SDK sysroot /usr/include/vulkan）

**修复命令**:
```
os.environ["LD_LIBRARY_PATH"] = cpp_lib + os.pathsep + cur  （cpp_lib 指向 <SDK>/ohos/native/llvm/lib/aarch64-linux-ohos）
```

**验证**:
```
在 conanfile.py generate() 中把 <llvm>/lib/aarch64-linux-ohos prepend 到 LD_LIBRARY_PATH 后，conan create 的 meson configure 通过
```
