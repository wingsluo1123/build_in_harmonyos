# E1015: header-only 包的接口面两处缺口——依赖头必须按**组件**传递（否则消费者 file not found），且 Boost≥1.90 不再隐式提供 boost::next

## 基本信息
- **严重度**: 2
- **类别**: portability, headers, conan, packaging, boost
- **作者**: E629

## 错误特征
```
fatal error:\s+'boost/[A-Za-z0-9_/.]+\.hpp' file not found|no member named 'next' in namespace 'boost'; did you mean 'boost::foreach_detail_::next'|no member named 'next' in namespace 'boost'; did you mean simply 'next'|no matching constructor for initialization of 'AbstractBSGS<
```

## 根因分析
① 组件化依赖的包级目标没有包含路径——boost 配方声明了 components（headers/atomic/filesystem/...），此时 CMakeDeps 生成的包级目标 boost::boost 的 INTERFACE_INCLUDE_DIRECTORIES 是空的，只有 Boost::headers 组件带 include。header-only 包若只写 requires("boost/x.y.z", transitive_headers=True) 而不同时写 cpp_info.requires = ["boost::headers"]，消费者拿到的是一串空 include 列表 ⇒ 消费者编译自家 TU 时 #include <boost/shared_ptr.hpp> 直接 fatal error（设备里恰好装了 boost 头时会被「喂饱」而假绿）。② Boost 1.90 起 boost::next()/boost::prior() 的声明不再由 boost/utility.hpp、boost/iterator/* 等头间接引入——老代码（2011 年前后的 C++98 模板库）在这些头里用 boost::next 却没显式 include <boost/next_prior.hpp> ⇒ 模板实例化时报 no member named 'next' in namespace 'boost'（note 链极长，容易误判成编译器/标准库问题）。

## 推荐方案
**方法**: component-level-public-requires-plus-explicit-boost-include

**说明**: 配方 requirements() 里写 requires("boost/1.90.0.4.1", transitive_headers=True)，并在 package_info() 里写 self.cpp_info.requires = ["boost::headers"]（组件级，不是包级 "boost::boost"）；同时给上游源码补最小补丁在每个 boost::next 使用点显式 #include <boost/next_prior.hpp>（补丁不含平台宏，任意平台同一份）。

**修复命令**:
```
conanfile.py 的 requirements()/package_info() 各一行——self.requires("boost/1.90.0.4.1", transitive_headers=True) 与 self.cpp_info.requires = ["boost::headers"]；补丁在每个 boost::next 使用点的头文件里补 #include <boost/next_prior.hpp>
```

**验证**:
```
消费者侧——conan create 的 test_package 里 find_package(<pkg> CONFIG REQUIRED) + target_link_libraries(app PRIVATE <pkg>::<pkg>)，TU 内只 include 被测包的公开头、不写依赖包路径，编译通过即证明组件级传递生效；依赖版本侧——BOOST=$(conan cache path boost/1.90.0.4.1:<pkgid>) 后 ls $BOOST/include/boost/next_prior.hpp（存在），再 grep -rn 'boost::next' 上游源（缺 include 即命中）。
```
