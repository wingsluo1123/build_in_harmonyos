# E1016: GitHub archive 型 autotools 包在 OHOS 上自举必踩的四连（AM_ICONV / config.status umask / config.guess / PERL5LIB）——逐条判据与修法，外加 sysroot stub 库陷阱

## 基本信息
- **严重度**: 2
- **类别**: autotools, bootstrap-ohos
- **作者**: unknown

## 错误特征
```
'possibly undefined macro: AM_ICONV|can''t create \./conf[A-Za-z0-9]+/subs1\.awk|could not setup config files machinery|config\.guess: unable to guess system type|Perl_my_cxt_init: symbol not found'
```

## 根因分析
'Four independent defects hit in order when a recipe must run `autoreconf` because the source tree is a git snapshot with no generated `configure`. (1) Upstream uses AM_ICONV, whose macro comes from GNU gettext''s iconv.m4; that file is NOT in the OHOS build-tool closure (the conan gettext package installs no m4 files, HNP ships none), so autoconf aborts with ''possibly undefined macro: AM_ICONV''. (2) The generated configure creates its temp dir with `(umask 077 && mktemp -d ./confXXXXXX)`; HMDFS forces setgid and maps the directory owner to a shared uid, so it lands as drwx--S--- owned by 20001006 while the process euid is 20020085 -- config.status then cannot write ./confXXXXXX/subs1.awk and configure dies with ''could not setup config files machinery''. (3) AC_CANONICAL_HOST runs config.guess, which creates dummy.c inside the same kind of mktemp dir, giving ''can''t create .../dummy.c: Permission denied'' and then ''unable to guess system type''. (4) Declaring tool_requires(''autoconf/2.72'') pulls conan perl/5.42.2 whose buildenv exports a PERL5LIB pointing at its own XS modules; on OHOS autoreconf/autoconf resolve to /data/service/hnp/bin/*, whose shebang is pinned to HNP perl 5.42.0, so the load fails with "Can''t load .../perl5/5.42.2/.../Cwd.so ... Perl_my_cxt_init: symbol not found". Related fifth trap: the OHOS sysroot ships libz.so only as a stub (13888 B, every symbol at one address, SONAME libz.so; /system/lib64 has no libz.so and the runtime only provides /usr/lib/libz.so.1), so an upstream AC_CHECK_LIB([z],[deflate]) succeeds and writes DT_NEEDED libz.so, which cannot be loaded at run time.'

## 推荐方案
**方法**: four-step-recipe-bootstrap-fix

**说明**: '(a) Patch configure.ac: replace AM_ICONV with AC_CHECK_HEADERS([iconv.h], [], [AC_MSG_ERROR(...)]) plus AC_CHECK_FUNCS([iconv_open iconv iconv_close], [], [AC_MSG_ERROR(...)]) -- OHOS musl libc provides iconv, and the hard-fail semantics are preserved. (b) After autotools.autoreconf(), rewrite the generated configure in build(): drop the ''umask 077 &&'' prefix from the mktemp -d branch and replace ''(umask 077 && mkdir "$tmp")'' with ''mkdir "$tmp"''; raise if the pattern is gone so the workaround cannot rot silently. (c) Append --build=aarch64-unknown-linux-ohos and --host=aarch64-unknown-linux-ohos to AutotoolsToolchain.configure_args (automake 1.18''s config.sub normalises the triplet; build==host keeps configure native so AC_CHECK_LIB really links and runs). (d) tool_require only automake/1.18 + libtool/2.5.4 and rely on HNP''s autoconf 2.72, otherwise conan perl poisons PERL5LIB. Additionally call AutotoolsDeps(self).generate(): AutotoolsToolchain alone injects no -I/-L/-l for dependencies.'

**修复命令**:
```
"python3 - <<'PY'   # (b) only; full recipe bootstrap is in the .md / reports\nimport io\np = \"configure\"\nd = io.open(p, encoding=\"utf-8\").read()\nd2 = d.replace('tmp=`(umask 077 && mktemp -d \"./confXXXXXX\") 2>/dev/null`',\n               'tmp=`mktemp -d \"./confXXXXXX\" 2>/dev/null`')\nd2 = d2.replace('(umask 077 && mkdir \"$tmp\")', 'mkdir \"$tmp\"')\nassert d2 != d, \"E114 pattern not found in configure\"\nio.open(p, \"w\", encoding=\"utf-8\").write(d2)\nPY"
```

**验证**:
```
cd <src> && autoreconf -fi ; grep -c 'umask 077 && mktemp' configure ; grep -n 'AM_ICONV\|iconv.m4' configure.ac ; readelf -d <pkg>/lib/*.so | grep -E 'NEEDED|SONAME'
```
