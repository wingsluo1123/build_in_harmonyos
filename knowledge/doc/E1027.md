# E1027: FETCHCONTENT_SOURCE_DIR_<DEP> 目录名与 conan get(strip_root=True) 落位不一致，配置期报 Manually specified source directory is missing

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan
- **作者**: 56F6

## 错误特征
```
Manually specified source directory is missing: FETCHCONTENT_SOURCE_DIR_|__FetchContent_Populate
```

## 根因分析
conan.tools.files.get(..., strip_root=True) 剥掉 tarball 顶层目录（如 qdldl-0.1.8/），依赖源码直接落在 destination 目录本身；配方若按 tarball 目录名拼 FETCHCONTENT_SOURCE_DIR_<DEP>，该路径不存在，CMake 在 __FetchContent_Populate 直接报错。SOURCE_DIR 覆盖语义是‘把该目录当作依赖源码根’，与 tarball 内目录名无关。

## 推荐方案
**方法**: explicit-offline-dest-dir-shared-constant

**说明**: 给离线依赖指定显式目录名（如 <source>/_offline_deps/qdldl），并让 source() 的 destination 与 generate() 的 FETCHCONTENT_SOURCE_DIR_<DEP> 共用同一常量，杜绝两处路径漂移。

**修复命令**:
```
QDLDL_OFFLINE_SUBDIR = ('_offline_deps','qdldl'); get(self, **self.conan_data['sources']['qdldl'], destination=os.path.join(self.source_folder, *self.QDLDL_OFFLINE_SUBDIR), strip_root=True); tc.cache_variables['FETCHCONTENT_SOURCE_DIR_QDLDL'] = os.path.join(self.source_folder, *self.QDLDL_OFFLINE_SUBDIR)
```

**验证**:
```
conan create . 2>&1 | grep -E 'Manually specified source directory|FetchContent'
```
