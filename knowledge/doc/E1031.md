# E1031: Legacy target LINK_FLAGS can vanish from Conan CMake Ninja shared-link rules

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, cmake, linking, packaging
- **作者**: A7C1

## 错误特征
```
Error loading shared library .*/lib.*\.so|LoadName: <Not found>|LINK_FLAGS.*soname.*missing|build\.ninja.*soname.*missing
```

## 根因分析
A source patch can set a legacy target LINK_FLAGS SONAME option and configure successfully while the generated Ninja shared-link rule omits it; under a config-specific Conan CMake build, setting only a source property or only the generic cache flag can therefore leave the ELF without DT_SONAME even though the output filename is correct

## 推荐方案
**方法**: cache-bound-shared-linker-flags

**说明**: Inject the required shared-link option through CMakeToolchain cache_variables for both CMAKE_SHARED_LINKER_FLAGS and the active build-type variant such as CMAKE_SHARED_LINKER_FLAGS_RELEASE; verify the generated linker argv, keep OUTPUT_NAME as the logical stem without the conventional lib prefix, and expose the same stem through cpp_info.libs

**修复命令**:
```
set CMAKE_SHARED_LINKER_FLAGS and CMAKE_SHARED_LINKER_FLAGS_RELEASE in CMakeToolchain.cache_variables, run conan create, inspect build.ninja and llvm-readobj --dynamic-table, then verify the consumer links with -l<logical-stem>
```

**验证**:
```
compare the patched target property with CMakeCache.txt and the exact build.ninja shared-link argv, then inspect DT_SONAME with llvm-readobj and compile a Conan consumer using the logical -l stem
```
