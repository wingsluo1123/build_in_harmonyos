# E1035: refresh-patch 把 prebuild/autoreconf 生成物误判为源码补丁

## 基本信息
- **严重度**: 3
- **类别**: build-system, conan
- **作者**: 23A7

## 错误特征
```
补丁数不一致: manifest=0 vs disk=[0-9]+|0003-configure.ac.patch.*\+1097|G0 干净构建验证失败.*No such file or directory
```

## 根因分析
上游 tarball 无预生成 configure 的项目（如 povray 需 unix/prebuild.sh、abiword 需 autoreconf -fi）在探索树里会生成大量构建系统文件（根 Makefile.am/Makefile.in/configure.ac 副本、aclocal.m4、unix/config/config.guess 等）；refresh-patch --auto 对比 orig 与 work 差异时把这些【构建期生成物】全部打成补丁；但配方 build() 里会重新跑 prebuild/autoreconf 生成它们，补丁冗余且不含最终 configure 脚本，导致 G0 干净构建验证失败（./configure: No such file or directory）

## 推荐方案
**方法**: 配方在 build() 内跑 prebuild/autoreconf 的项目应保持【零补丁】设计：删除 refresh-patch 误生成的 patches/ 目录、清理 manifest 的 patch_generation/patch_classification 块、manifest patches_applied 保持 []；G0 干净构建验证的 ⚠️ 警告对 conan 配方流程可接受（conan-verify G2 才是权威门禁）

**说明**: 删除 refresh-patch 误生成补丁保持零补丁设计，prebuild/autoreconf 逻辑内联配方 build()

**修复命令**:
```
rm -rf ${ARCHIVE_DIR}/patches && git -C ${ARCHIVE_DIR} add -A
```

**验证**:
```
ls archives/<软件>/<版本>/patches/ 2>/dev/null | wc -l  # 非 0 而 manifest patches_applied 为 [] 即误判补丁
```
