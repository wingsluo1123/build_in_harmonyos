# E1041: Legacy AES CBC file format loses original plaintext length on partial blocks

## 基本信息
- **严重度**: 2
- **类别**: portability, testing, data-corruption
- **作者**: 88CF
- **来源 PR**: pending

## 错误特征
```
cmp: EOF on plain after byte [0-9]+|sectar AES CBC output differs from original C source
```

## 根因分析
sectar 1.02 writes only the keyfile name and a fixed-width 32-bit block size followed by AES CBC ciphertext. For the final partial 256-bit block it encrypts a zero-filled input buffer but does not serialize the original byte count; decrypt always writes a whole block. A 33-byte plaintext therefore decrypts to 64 bytes and byte-for-byte comparisons fail despite successful AES operation.

## 推荐方案
**方法**: preserve-format-and-align-consumer-input

**说明**: For compatibility tests of the original archive format use a full 32-byte multiple input, run installed CLI encrypt and decrypt, compare bytes and build and execute the decrypted consumer program. Record that arbitrary-length round-trip is not lossless; do not claim cryptographic integrity or pad removal.

**修复命令**:
```
python3 scripts/ohc-run.py conan-verify sectar 1.02
```

**验证**:
```
d=$(mktemp -d /root/tmp/sectar-kb-XXXXXX); cd "$d" && printf '%064d' 0 > key && printf 'sectar OHOS cross-platform test!!' > plain && qemu-aarch64 /root/tmp/sectar-ohos -k key -e -o enc.star plain && qemu-aarch64 /root/tmp/sectar-ohos -k key -d -o dec enc.star && ! cmp plain dec && printf 'sectar OHOS cross-platform test!' > plain && qemu-aarch64 /root/tmp/sectar-ohos -k key -e -o enc.star plain && qemu-aarch64 /root/tmp/sectar-ohos -k key -d -o dec enc.star && cmp plain dec
```
