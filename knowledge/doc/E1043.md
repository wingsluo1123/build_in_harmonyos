# E1043: 本仓 ncurses/6.6 在 uid 0 下忽略 TERMINFO/TERMINFO_DIRS/~/.terminfo，只查编译期默认的 //share/terminfo：x86 root runner 上 terminfo 类 CLI 的 test_package 找不到终端描述（tgetent=-1，vi 克隆退化为行模式或读 EOF 空转）；测试脚本在 uid 0 时经 unshare --user --map-user 以非特权 uid 运行，并使用 root 自有的 terminfo 条目副本

## 基本信息
- **严重度**: 2
- **类别**: runtime, testing, environment, permissions
- **作者**: BC71

## 错误特征
```
newfstatat(AT_FDCWD,"//share/terminfo"|newfstatat(AT_FDCWD, "//share/terminfo"|stat("//share/terminfo"|access("//share/terminfo"
```

## 根因分析
ncurses 出于安全考虑在特权进程中不读取终端数据库相关环境变量（_nc_env_access() 对 uid 0 返回假），本仓 ncurses/6.6 的该行为实测成立：同一个静态链接 libncursesw 的探针，TERMINFO 指向包内 share/terminfo 时以 root 运行 tgetent=-1，以 nobody 运行 tgetent=1（li=24 co=80）；qemu-aarch64 -strace 显示 root 下只 stat 了编译期默认的 //share/terminfo（包以 --prefix=/ 构建）。

## 推荐方案
**方法**: userns-unprivileged-uid-with-owned-terminfo-copy

**说明**: test.sh 在 id -u 为 0 时：先 cp 所需 terminfo 条目到工作目录（root 自有），再以 unshare --user --map-user=65534 --map-group=65534 前缀运行被测程序，TERMINFO 指向该副本；非 root（设备 CI）不走此分支。工作目录与被测文件仍可读写（映射 uid 对应外部 uid 0）

**修复命令**:
```
if [ "$(id -u)" = 0 ]; then mkdir -p "$WORK/terminfo/v"; cp "$TI/v/vt100" "$WORK/terminfo/v/"; TI="$WORK/terminfo"; as_user=(unshare --user --map-user=65534 --map-group=65534); fi; ${as_user[@]+"${as_user[@]}"} env TERM=vt100 TERMINFO="$TI" ./prog
```

**验证**:
```
TERM=vt100 TERMINFO=<ncurses>/share/terminfo ./probe; setpriv --reuid=65534 --regid=65534 --clear-groups env TERM=vt100 TERMINFO=<可读副本> ./probe   # 前者 tgetent=-1、后者 tgetent=1 即命中本条
```
