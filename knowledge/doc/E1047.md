# E1047: David Parsons 的 configure.sh/configure.inc 在构建机上编译并执行 config.sed（每次 AC_SUB）与 mkversio 等辅助程序：x86 runner 上动态链接的 OHOS 产物缺 ld-musl 加载器无法执行，configure 仍返回 0，Makefile 残留 @CC@，make 报 "CC@: No such file" Error 127；把编译器驱动为 "<cc> -static-pie" 解决

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, configure, toolchain, cross-compile
- **作者**: B898

## 错误特征
```
make: CC@: No such file or directory|CC@: not found|CC@: command not found
```

## 根因分析
configure.inc（discount、levee 等 Orc 系项目共用的 shell 版 autoconf 模拟器）没有「构建机编译器」概念：__ac_config_sed 用 "$AC_CC -o config.sed ngc$$.c"（只带 CC，不带 CFLAGS/LDFLAGS）编译一个转义小程序，之后每个 AC_SUB 都执行 ./config.sed 生成 config.sub 的 sed 规则；项目 Makefile 还会编译并执行 mkversio 生成 version.c。

## 推荐方案
**方法**: drive-compiler-as-static-pie

**说明**: 配方把 CC 设为 "<profile 的 C 编译器> -static-pie"、CFLAGS 加 -fPIE：config.sed、mkversio 与最终交付物都成为无 PT_INTERP 的 static PIE，x86 上经 qemu-aarch64 binfmt、AArch64 设备上原生都能执行（交付物仍保留 PIE + BIND_NOW + full RELRO）。-static-pie 必须放进 CC 而不是 LDFLAGS，因为 config.sed 只用 $CC 编译

**修复命令**:
```
self.run(f"CC={shlex.quote(cc + ' -static-pie')} CFLAGS='-O2 -fPIE ...' LDFLAGS='-L<dep>/lib' LIBS='-l<dep>' bash ./configure.sh ...", cwd=src)
```

**验证**:
```
grep -c '@[A-Z_]*@' Makefile   # 非 0 即 AC_SUB 失败；grep 'Could not open' config.log
```
