# E1048: termcap 时代程序自定义 LINES/COLS/UP/refresh 等与 curses 同名的全局符号：链接 R26 强制的静态 libncursesw.a 时 ld.lld 报 duplicate symbol（动态库场景被可执行文件符号抢占而静默通过）

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, linking, static-library
- **作者**: A841

## 错误特征
```
duplicate symbol: LINES|duplicate symbol: COLS|lib_setup.o:(.bss|lib_termcap.o:(.bss|(lib_setup.o):(.bss|multiple definition of `LINES'|multiple definition of `COLS'
```

## 根因分析
老式 termcap 程序（vi 克隆、行编辑器、终端游戏）在自己的 globals.c 里定义 int LINES, COLS; char *UP; 以及 refresh()/scroll() 等函数/变量，名字与 curses/terminfo 的公开符号相同。

## 推荐方案
**方法**: rename-own-globals-via-central-header-macros

**说明**: 在程序自己的中心头文件（所有 .c 最先包含、且早于 <termcap.h>/<curses.h> 的那个）里用宏把冲突名改为私有前缀：#define LINES levee_LINES 等。只改链接名，行为不变；termcap.h 里的 extern char *UP 随之同名改写，声明与定义保持一致；字符串字面量（如 :set scroll 选项名）不受影响

**修复命令**:
```
在中心头文件 #include "config.h" 之后加入 #define LINES prog_LINES / #define COLS prog_COLS / #define UP prog_UP / #define refresh prog_refresh ...（冲突清单用 verification_cmd 求交集得到）→ track-edit + refresh-patch --auto 生成补丁
```

**验证**:
```
llvm-nm --defined-only <程序>.o | awk 'NF==3{print $3}' | sort -u > own.txt; llvm-nm --defined-only libncursesw.a | awk 'NF==3 && $2 ~ /[TDBRC]/ {print $3}' | sort -u | comm -12 - own.txt   # 非空即会冲突
```
