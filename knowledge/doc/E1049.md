# E1049: refresh-patch 幻影补丁 —— .orig 基线损坏时零修改包也会产出"新增文件"补丁

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, packaging
- **作者**: 9F3C

## 错误特征
```
G0: 补丁 .* 应用失败|Reversed \(or previously applied\) patch detected|patch does not apply
```

## 根因分析
refresh-patch --auto 在"无编辑追踪器"时会回退到"排除规则扫描"，即对比 .work 与 .orig 两个目录树。当 .orig 基线本身被 init-build 的嵌套源码目录探测缺陷（F068：把 docs/ 的 Makefile 误判为源码根）破坏后，.orig 只含被误判目录的内容，与完整的 .work 逐文件比对时，上游原本就存在的文件会被判为"新增"，于是生成一连串 +N/-0 的 add-file 补丁。这些补丁在 G0 干净构建阶段应用时，目标文件已存在于归档中，patch 立即 FAILED，G0 被判失败。判据：work 树与上游归档逐字节一致（diff -rq 无输出）却仍产出补丁，即为基线污染而非真实改动。

## 推荐方案
**方法**: rebuild-orig-baseline-from-pristine-archive

**说明**: 不要逐条调试补丁内容，改为证伪补丁的必要性：把官方归档重新解压为干净的 .orig 基线，与 .work 做全树比对。若逐字节一致，说明上游源码零修改，正确结论是"零补丁"，动作是重建 .orig + 清空 patches/ + 在 manifest 记录 patches_count=0，而不是去修 patch 的 hunk 上下文。反之若确有差异，再逐文件确认差异来源。
