# E1052: CMake-only 发布包被 init-build 误判 autotools 导致 conan-init 生成错误配方

## 基本信息
- **严重度**: 2
- **类别**: detection, build-system, cmake, autotools, conan
- **作者**: 50E3, D2DF

## 错误特征
```
构建系统: autotools|BUILD_SYSTEM="autotools"|AutotoolsToolchain\(self\)
```

## 根因分析
init-build 从上游 URL/探针推断 BUILD_SYSTEM=autotools 并把结果传给 conan-init，然而 ttylog 官方 0.31 源码根目录有 CMakeLists.txt 且没有 configure；lang-preflight 已正确识别 cmake，两个阶段的判型未统一。

## 推荐方案
**方法**: inspect-source-then-replace-autotools-template

**说明**: 源码就位后按真实顶层构建入口复核判型；把 conan-init 生成的 AutotoolsToolchain/Autotools 改为 CMakeToolchain/CMake，修正版本 manifest、MANIFEST 和 notes，不直接运行不存在的 configure；无需改框架代码。

**修复命令**:
```
python3 scripts/ohc-run.py lang-preflight ttylog 0.31 --src "$BUILD_SRC_DIR" && python3 scripts/ohc-run.py conan-verify ttylog 0.31
```

**验证**:
```
tar tzf ttylog-0.31.tar.gz | grep CMakeLists.txt && ! tar tzf ttylog-0.31.tar.gz | grep -E '/configure$' && python3 scripts/ohc-run.py conan-verify ttylog 0.31
```
