# E1054: 老式 Makefile/CFLAGS 固定 -ansi（-std=c89）：musl 在 __STRICT_ANSI__ 下隐藏 strdup/strcasecmp 等 POSIX 声明，C89 隐式 int 加显式 (char *) 强转把 64 位指针截断，编译只有告警、运行即 SIGSEGV

## 基本信息
- **严重度**: 3
- **类别**: portability, musl, headers, make, runtime
- **作者**: 04E7

## 错误特征
```
cast to 'char \*' from smaller integer type 'int' \[-Wint-to-pointer-cast\]|implicit declaration of function '(strdup|strndup|strcasecmp|strncasecmp|fdopen|popen|fileno)'.*\[-Wimplicit-function-declaration\]
```

## 根因分析
-ansi（等价 -std=c89）使编译器预定义 __STRICT_ANSI__；musl features.h 只在未定义 __STRICT_ANSI__ 时才默认开启 _BSD_SOURCE/_XOPEN_SOURCE，于是 string.h 不再声明 strdup 等 POSIX 扩展，也不再引入 strings.h（strcasecmp）。

## 推荐方案
**方法**: generic-target-default-dialect-werror-implicit-decl

**说明**: 不走带 -ansi 的上游平台目标或 CFLAGS，改用通用目标并保持编译器默认 C 方言（或显式 -std=gnu99 及以上），同时加 -Werror=implicit-function-declaration，让任何隐式声明在编译期失败，而不是产出必崩的二进制；无需改源码。

**修复命令**:
```
make -j1 <通用目标> CC=<conan tools.build:compiler_executables 的 c> CFLAGS='-O2 -Werror=implicit-function-declaration'
```

**验证**:
```
printf '#include <string.h>\nint main(void){return strdup("x") != 0;}\n' | clang -ansi -Werror=implicit-function-declaration -x c -c -o /dev/null - 2>&1 | grep -q "implicit declaration of function 'strdup'" && echo "strict ANSI hides strdup"
```
