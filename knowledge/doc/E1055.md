# E1055: ConanFile.run() 输出流继承导致编译器全量静默失败（make 只报 Error 1，零诊断）

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan, compilation, environment
- **作者**: AC99

## 错误特征
```
make\[2\]: \*\*\* \[.*\.obj\] Error 1\|\*\*\* \[Makefile:[0-9]+: all\] Error 2
```

## 根因分析
ConanFile.run() 内部 conan_run() 的 stdout = stdout or sys.stderr 会把 recipe 进程的 stdout/stderr 句柄继承给子进程；在 OHOS/Conan2 组合下 clang 于该形态静默失败，所有编译单元都失败但没有任何 error:/warning: 行，make 只能报 Error 1。同一命令在交互 shell 下（或把整个 conan create 输出重定向到文件时）成功，因此极易被误判为环境问题。

## 推荐方案
**方法**: log-bound-build-steps

**说明**: 在 recipe 内为 configure/build/install 每步绑定独立日志文件：cmake.configure(stdout=log, stderr=log) / cmake.build(...) / cmake.install(...)，失败时回显日志尾部并抛出带日志路径的异常；autotools 用 self.run(cmd + " > log 2>&1")。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
conan create <recipe> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing 2>&1 | tee build.log   # 命中判据: build.log 含 "*** [xxx.obj] Error 1" 且 grep -c "error:" build.log = 0（零诊断）；修复后复跑 conan-verify（G2）与 finish（W3）应同时转绿
```
