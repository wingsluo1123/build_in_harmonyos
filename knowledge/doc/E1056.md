# E1056: OHOS libc/NDK 无 glibc 重入解析器 API（res_n*）——改用经典 res_query()/h_errno

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, libc, network, resolver
- **作者**: 9C4A

## 错误特征
```
use of undeclared identifier .res_ninit.|use of undeclared identifier .res_nquery.|use of undeclared identifier .res_nclose.|undefined (reference|symbol).*res_n(query|init|close)|cannot find -lresolv
```

## 根因分析
OHOS 的 libc（musl 系）与 NDK 头文件只提供经典非重入解析器 API（res_init/res_query/res_search/res_send/res_mkquery + dn_expand/dn_skipname，声明见 NDK resolv.h），不提供 glibc 的 res_ninit/res_nquery/res_nclose，也没有调用方持有的 struct __res_state 语义；从 glibc 移植的 DNS 客户端（自定义 MX/A/AAAA 查询）编译期报 use of undeclared identifier .res_n*.，链接期报 undefined symbol。实测 smtpping 1.1.4 Resolver 即此模式（nm -D /system/lib64/libc.so 无 res_n* 符号）。

## 推荐方案
**方法**: port-to-classic-resolver-api

**说明**: 把查询入口替换为 res_query(domain, C_IN, type, buf, len) + 全局 h_errno（保留 NO_DATA 空答案语义）；删除调用方 struct __res_state 成员与 res_ninit/res_nclose 调用；响应解析继续用 dn_expand/dn_skipname（OHOS nameser.h 提供 HEADER/T_A/T_MX/T_AAAA/C_IN/HFIXEDSZ/QFIXEDSZ/INT16SZ/INT32SZ/MAXDNAME/GETSHORT 全套，dn_expand 为 libc 弱符号但运行可用）。仅当程序单线程或 fork 并发时安全（进程级全局态）；多线程程序需加锁或自实现 DNS 客户端。

**修复命令**:
```
patch resolver.cpp: res_nquery(&m_res, domain, ...) -> res_query(domain, ...); m_res.res_h_errno == NO_DATA -> h_errno == NO_DATA; drop res_ninit/res_nclose; patch resolver.hpp: drop struct __res_state member, add #include <netdb.h> for h_errno
```

**验证**:
```
printf %s "#include <resolv.h>\nint main(){struct __res_state s;res_ninit(&s);return 0;}" > t.c && clang --target=aarch64-linux-ohos --sysroot=$OHOS_SDK/sysroot t.c -o t 2>&1 | grep -q res_ninit && echo CONFIRMED
```
