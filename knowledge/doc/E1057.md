# E1057: 老项目 AC_CHECK_LIB(curses) 在 OHOS conan ncurses（仅宽字符版 libncursesw.a）下检测失败，须改 ncursesw

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, autotools, dependency
- **作者**: zhcon-0.2.6 适配

## 错误特征
```
checking for main in -lcurses.*no|undefined reference to.*(tgetent|tgetstr|tgoto|setupterm)|term\.h.*file not found|ncursesw
```

## 根因分析
conan 制品仓的 ncurses/6.5 包只提供宽字符版静态库 libncursesw.a（含 termcap API：tgetent/tgetstr/tgoto/setupterm），不提供 libcurses.a。2003 年代老项目 configure.in 用 `AC_CHECK_LIB(curses, main)` 检测，OHOS 上返回 no，链接期因缺 termcap 符号失败。

## 推荐方案
**方法**: switch-curses-check-to-ncursesw

**说明**: 将 configure.in/configure 中 `AC_CHECK_LIB(curses, main)` 改为 `AC_CHECK_LIB(ncursesw, main)`（两处：configure.in 源头 + configure 生成文件同步改），Makefile 中 LIBS 变为 -lncursesw。zhcon 只用 termcap API，全部在 libncursesw.a 中，功能无损失。

**验证**:
```
ls ~/.conan2/p/ncurs*/p/lib/*.a 确认仅 libncursesw.a；grep -n "AC_CHECK_LIB(curses" configure.in
```
