# E1058: CI worker 与设备 Python 的 EXT_SUFFIX 口径不同：扩展后缀归一化与静态守卫必须环境驱动

## 基本信息
- **严重度**: 2
- **类别**: python, packaging, wheel
- **作者**: 4E17

## 错误特征
```
E580 guard FAIL: extension suffix normalisation regressed, still platform-tagged (CI 假失败)；同轮日志 normalised 0 extension module(s) to .cpython-312-aarch64-linux-ohos.so
```

## 根因分析
CI worker 的 HNP python 其 EXT_SUFFIX/SOABI 带 MULTIARCH 平台标签（.cpython-312-aarch64-linux-ohos.so），设备侧为 .cpython-312.so（MULTIARCH 为空）。同一份 wheel 在两环境里「归一化动作」与「合法文件名」都不同：sysconfig 归一化在 CI 退化为 no-op（renamed 0），而导入器接受的名字只有平台标签形式。若守卫再硬编码平台标签正则，就会把 CI 上本可加载的文件名判成归一化回归 → CI 假失败。

## 推荐方案
**方法**: 归一化目标一律取运行环境 EXT_SUFFIX（CI 上保持 no-op，设备上改名 93 个）；静态守卫的合法性判据改为运行解释器的 importlib.machinery.EXTENSION_SUFFIXES——文件名须能按「模块名(不含点)+接受后缀」解析，否则判回归，并断言扩展数不低于基线（93）。禁用硬编码平台标签正则。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
/data/service/hnp/bin/python3 -c "import importlib.machinery, sysconfig; print(sysconfig.get_config_var('EXT_SUFFIX'), importlib.machinery.EXTENSION_SUFFIXES)"
```

**验证**:
```
在 CI 与设备各跑一次 rec_command 比对；守卫 4 场景自检：设备真包(短名)=PASS、CI 形态(平台名+接受集含平台形式)=PASS、设备侧回归(平台名+只认短名)=FAIL、扩展数不足=FAIL
```
