# E1059: AM_GNU_GETTEXT conftest 在 64 位下指针截断导致 libintl 检测误判，回退 included intl 造成链接失败

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, autotools, nls
- **作者**: zhcon-0.2.6 适配

## 错误特征
```
cast from pointer to smaller type 'int' loses information|no matching function for call to '_nl_expand_alias'|undefined symbol: g_libintl_gettext|undefined symbol: libintl_gettext|GNU gettext in libintl.*no|included intl directory
```

## 根因分析
老版本 autoconf/gettext 的 AM_GNU_GETTEXT conftest 使用 `(int) gettext("")` 将指针强转 int（64 位下截断报错），且调用 `_nl_expand_alias(0)` 与新版 libintl.h 的零参原型不匹配，导致 "GNU gettext in libintl" 检测误判为 no，configure 回退到 "included intl directory" 路径（Makefile 引用 ${top_builddir}/intl/libintl.a）。但源码 tarball 往往不携带 intl/ 目录，最终链接报 g_libintl_*/libintl_gettext 未定义。

## 推荐方案
**方法**: fix-gettext-conftest-64bit

**说明**: 修改 configure 中 gettext conftest：(1) `(int) gettext("")` 改为 `(int)(long) gettext("")`（64 位先转 long 再截断）或 (intptr_t)；(2) `_nl_expand_alias(0)` 改为无参调用 `_nl_expand_alias()`。修复后 "GNU gettext in libintl... yes"，configure 走外部 libintl 路径，链接 -lintl。

**验证**:
```
grep -n "GNU gettext in libintl" config.log; 查看 conftest 编译输出 "cast from pointer to smaller type 'int'"; 链接报 g_libintl_* undefined
```
