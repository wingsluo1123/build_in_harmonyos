# E1062: 老 autoconf 生成 configure 的 ptrdiff_t 检测（C 模式无 stddef.h）误判 no，宏定义与 libc++ 头冲突

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, headers, autotools
- **作者**: zhcon-0.2.6 适配

## 错误特征
```
expected unqualified-id using ::ptrdiff_t|expanded from macro 'ptrdiff_t'|#define ptrdiff_t long|cast from pointer to smaller type|error: expected unqualified-id
```

## 根因分析
2001/2006 版 autoconf 的 AC_CHECK_TYPE(ptrdiff_t) 用 C 模式编译测试程序且 $ac_includes_default 不含 <stddef.h>，在 OHOS 上误判 ac_cv_type_ptrdiff_t=no，随后向 config.h 写入 #define ptrdiff_t long。libc++（-stdlib=libc++）的 <cstddef> 已声明 using ::ptrdiff_t，宏展开成 using ::long 导致 "expected unqualified-id" 编译错误。

## 推荐方案
**方法**: force-ptrdiff-t-yes-on-ohos

**说明**: 在 configure 脚本的 ptrdiff_t 检测前针对 *-linux-ohos 强制 ac_cv_type_ptrdiff_t=yes（libc++ 已提供该类型，属事实修正），config.h 输出 /* #undef ptrdiff_t */ 不再定义冲突宏。

**验证**:
```
grep -n "ptrdiff_t" config.h; clang++ -std=c++17 -stdlib=libc++ -DHAVE_CONFIG_H -I. -c src/xxx.cpp 报 "expected unqualified-id using ::ptrdiff_t"
```
