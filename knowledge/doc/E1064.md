# E1064: USB 后端初始化失败时未检查返回值，未初始化的 libusb 上下文/设备列表被解引用导致 Signal 11

## 基本信息
- **严重度**: 3
- **类别**: portability, runtime, memory, usb
- **作者**: 9B31

## 错误特征
```
Signal 11|core dumped|Error 139|libusb_init|libusb_get_device_list
```

## 根因分析
库的公共 API 直接调用 libusb_init(&ctx) / libusb_get_device_list(ctx, &list) 且不检查返回值；当运行环境没有可用 USB 栈（CI 容器/沙箱无法访问 USB 设备节点，或 /dev/bus/usb 权限被拒）时这两个调用失败并保持出参未初始化，随后解引用未初始化指针（或把它传给 libusb_free_device_list/libusb_exit）即 Signal 11。本机有 USB 环境时同样二进制能正常运行，因此该缺陷只在无 USB 的运行环境暴露（环境相关，非确定性崩溃）。

## 推荐方案
**方法**: patch-source-check-libusb-return

**说明**: 在库源码里补齐 libusb 返回值检查：出参先初始化为 NULL，libusb_init() 失败时直接返回"无设备"（count 返回 0 / 名字返回空串 / open 返回错误码），libusb_get_device_list() 失败时先 libusb_exit(ctx) 再返回；不要解引用或释放未初始化指针。用 refresh-patch --auto 固化为补丁，不直接改源码树。

**修复命令**:
```
python3 $SKILL_ROOT/scripts/ohc-run.py refresh-patch --auto <name> <version>
```

**验证**:
```
FAKE_LIBUSB_MODE=initfail LD_LIBRARY_PATH=<pkg>/lib:<libusb>/lib ./repro   # 用返回失败的 libusb 替身运行，未修复时 rc=139 (SIGSEGV)，修复后 rc=0 且返回"0 个设备"
```
