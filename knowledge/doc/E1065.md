# E1065: Python 包配方需对齐平台既有科学计算栈的依赖版本上限（numpy<2.3 约束）

## 基本信息
- **严重度**: 2
- **类别**: python, dependency, pip
- **作者**: 4E17

## 错误特征
```
ResolutionImpossible|Cannot install .* because these package versions have conflicting dependencies|requires numpy.*but you have|has requirement numpy
```

## 根因分析
平台既有 Python 科学计算栈（如 scipy 1.14.x）对 numpy 有上界约束（<2.3）。配方若让 pip 自由解析，会拉入 numpy>=2.3 从而与平台预装/预编译 wheel 冲突，或在离线安装时解析失败；而 pip 的解析器在缺少统一约束文件时不会自动回退到兼容版本。

## 推荐方案
**方法**: conan-recipe          # 见 DESIGN §5 impl 列表

**说明**: 在配方安装依赖时显式传递版本约束（如 numpy<2.3），先安装被约束的下游包再安装上层包；把实测通过的版本组合写入 conandata.yml/notes.md 作为事实源，并在 test_package 中导入关键依赖断言版本满足约束。

**修复命令**:
```
pip install --no-cache-dir 'numpy<2.3' && pip install --no-cache-dir -r requirements.txt
```

**验证**:
```
python3 -c "import numpy,scipy; from packaging.version import Version; assert Version(numpy.__version__)<Version('2.3'), numpy.__version__; print(numpy.__version__, scipy.__version__)"
```
