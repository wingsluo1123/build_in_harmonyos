# E1069: Cross GCC on OHOS: sync bundled prereq config.sub, clear STMP_FIXINC, install unprefixed target as/ld/nm shims

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, build-system, autotools, toolchain, cross-compile
- **作者**: 9F3C

## 错误特征
```
config.sub .*linux-ohos failed|stmp-fixinc.*Error 1|unknown architecture `armv4t'|unrecognized option `-march=armv4t'|getcwd: cannot access parent directories
```

## 根因分析
Three independent gaps appear when a GNU GCC cross compiler is built on HarmonyOS (host aarch64-linux-ohos) rather than natively. (1) GCC's top-level configure canonicalises the build triplet by executing EACH in-tree prerequisite's own config.sub, so patching only the top-level config.guess/config.sub is insufficient: the bundled releases predate OHOS by years (gmp 6.1.0 is from 2015) and reject aarch64-unknown-linux-ohos, aborting configure-gmp with "configure: error: .../gmp/config.sub aarch64-unknown-linux-ohos failed". (2) GCC's gcc/configure.ac records that for a cross build "we cannot run fixincludes", but STMP_FIXINC still defaults to stmp-fixinc; signing the freshly built host tools refreshes fixincl's timestamp, which invalidates gcc/stmp-fixinc and re-runs fixinc.sh, and that re-run is unreliable on HMDFS (getcwd: Not supported / Permission denied / Invalid argument, then "make: *** [Makefile:3246: stmp-fixinc] Error 1"). (3) GCC resolves its assembler/linker by searching its own exec prefixes for the UNPREFIXED program name (as, collect-ld, nm) before falling back to PATH; on OHOS the host PATH also contains the AArch64 host as, so a packaged cross driver silently picked the host assembler and every target compile died with "Error: unknown architecture `armv4t'" / "unrecognized option `-march=armv4t'".

## 推荐方案
**方法**: cross-gcc-ohos-three-point-fix

**说明**: Apply all three fixes together; any one alone leaves a deterministic build or test failure. (1) After applying the top-level config.guess/config.sub patches, COPY the patched pair into every vendored prerequisite tree (gmp/, mpfr/, mpc/) so their own config.sub recognises aarch64-unknown-linux-ohos. (2) Pass STMP_FIXINC= on the make command line (it propagates to sub-makes) so stmp-int-hdrs depends on nothing and fixincludes never runs for a header-less cross target. (3) Install unprefixed as / ld / collect-ld / nm sh shims into <package>/libexec/gcc/<target>/<version>/ that exec the target-prefixed programs supplied by the binutils tool_requires, at both build time (GCC searches its exec prefixes while building) and package time (the installed driver searches the same prefixes).

**修复命令**:
```
make --jobserver-style=pipe -j1 STMP_FIXINC= all-gcc; printf '#!/bin/sh\nexec arm-none-eabi-as "$@"\n' > "$D/as" && chmod 755 "$D/as"  # D=<pkg>/libexec/gcc/<target>/<ver>; -j1 (not -j2): the recipe builds serially because the host is memory-oversubscribed and HMDFS cannot host GNU make's FIFO jobserver
```

**验证**:
```
grep -c 'file://' archives/g/gcc-11-cross/26/conandata.yml; /data/service/hnp/bash <patched-tree>/config.sub aarch64-unknown-linux-ohos; /data/service/hnp/bash <pristine-tree>/gmp/config.sub aarch64-unknown-linux-ohos; grep -n 'STMP_FIXINC=' archives/g/gcc-11-cross/26/conanfile.py; ls <package>/libexec/gcc/<target>/<version>/{as,ld,collect-ld,nm}
```
