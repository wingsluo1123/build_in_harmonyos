# E1071: 上游用 IF(CMAKE_CROSSCOMPILING) 守卫构建路径剥离，原生 OHOS 构建下守卫恒假导致缓存绝对路径写入 .pc 并随制品发布

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, build-system, cmake, conan
- **作者**: 7C4E

## 错误特征
```
Cflags:.*-I/storage/|Cflags:.*-I.*/\.conan2/p/|Cflags:.*-I/usr/local|pkgconfig.*构建机绝对路径
```

## 根因分析
上游 CMakeLists 将"剥离构建机路径"的逻辑包在 IF(CMAKE_CROSSCOMPILING) 内（意图是仅在交叉编译时清理）；但 ohpcd 的 OHOS 构建是原生构建，conan toolchain 不下发 CMAKE_SYSTEM_NAME/CMAKE_SYSROOT，故 CMAKE_CROSSCOMPILING 恒为假，该分支永不执行。结果依赖的绝对 -I 路径（如 /storage/.../.conan2/p/<pkg>/p/include/...）被原样写入安装出的 .pc 的 Cflags，随制品发布，下游在别的机器上解析即失效。

## 推荐方案
**方法**: conanfile-package-postprocess

**说明**: 在 conanfile.py 的 package() 阶段规范化安装出的 .pc：删除 Cflags 中指向构建机的绝对 -I 项，仅保留可重定位的 ${includedir}；不改上游源码（上游意图正确，只是守卫在原生构建下不成立）。

**修复命令**:
```
grep -nE "^Cflags" ${PACKAGE_FOLDER}/lib/pkgconfig/*.pc
```

**验证**:
```
grep -E "^(prefix|Cflags|includedir)" <package_folder>/lib/pkgconfig/*.pc
```
