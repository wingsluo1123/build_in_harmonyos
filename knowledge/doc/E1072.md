# E1072: C++17 严格模式下 gnu 扩展宏 linux 未定义导致老代码平台分支失效（__u32/KDMKTONE/fd_set 未声明）

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, headers, build-system, autotools
- **作者**: zhcon-0.2.6 适配

## 错误特征
```
unknown type name '__u32'|unknown type name '__u16'|unknown type name '__u8'|use of undeclared identifier 'KDMKTONE'|use of undeclared identifier 'fd_set'|'linux/kd.h' file not found|defined\(linux\)
```

## 根因分析
2003 年代的老 C/C++ 代码大量使用 `#if defined(linux)` 判断 Linux 平台。`linux`（无下划线）是 GCC/Clang 的 gnu 扩展预定义宏，仅在默认 gnu 方言（如 gnu++17）下定义；当 conan profile 设置 compiler.cppstd=17 等严格 ISO C++ 模式（-std=c++17）时该宏不定义，平台分支整体失效：包含 <linux/kd.h>/<asm/types.h> 等内核头的代码被跳过，后续代码引用的 __u32/__u16/__u8/KDMKTONE 等类型与宏全部未声明，出现大量 "unknown type name" / "undeclared identifier" 编译错误。本地探索编译默认 gnu 方言不暴露，仅在 conan 干净构建（-std=c++17）暴露，形成本地编译通过但 CI/验证失败的反差。

## 推荐方案
**方法**: replace-defined-linux-with-__linux__

**说明**: 将 `#if defined(linux)` 统一替换为 `#if defined(linux) || defined(__linux__)`（或直接使用 __linux__）。__linux__ 是标准预定义宏，在 -std=c++17 严格模式下仍定义，兼容 gnu 方言与严格 ISO 模式，对 Linux/OHOS 均成立，不影响其他平台。

**验证**:
```
grep -rn "defined(linux)" src/ | grep -v "__linux__"; 或复现编译：clang++ -std=c++17 -stdlib=libc++ -c src/main.cpp 报 "use of undeclared identifier 'KDMKTONE'"
```
