# E1073: Python 扩展模块后缀归一化：OHOS wheel 的 -aarch64-linux-ohos.so 需在 pip install 之后重命名为本机 EXT_SUFFIX

## 基本信息
- **严重度**: 2
- **类别**: python, packaging, wheel
- **作者**: 4E17

## 错误特征
```
ModuleNotFoundError: No module named .*\\._|ImportError: cannot import name|EXTENSION_SUFFIXES|cpython-312-aarch64-linux-ohos|is not a valid platform tag
```

## 根因分析
OHOS 社区 PyPI 源预编译 wheel 内扩展模块按 PEP 425 平台标签命名（foo.cpython-312-aarch64-linux-ohos.so），而设备本地 Python 的 EXTENSION_SUFFIXES 只有 ['.cpython-312.so', '.abi3.so', '.so']（SOABI=cpython-312），导入器按 EXT_SUFFIX 拼接路径查找 → 找不到 .so 直接 ModuleNotFoundError。pip 安装会把文件名还原成 wheel 记录的平台后缀，因此归一化必须在 pip install 完成之后执行。

## 推荐方案
**方法**: conan-recipe          # 见 DESIGN §5 impl 列表

**说明**: 封装 OHOS 预编译 wheel 的 Python 配方，在 pip install 之后遍历 site-packages 把所有 *.cpython-312-aarch64-linux-ohos.so 重命名为 *.cpython-312.so；并在自检中断言扩展后缀全部等于本机 EXT_SUFFIX。

**修复命令**:
```
find <prefix> -name '*.cpython-312-aarch64-linux-ohos.so' -exec sh -c 'for f; do mv "$f" "${f%-aarch64-linux-ohos.so}.so"; done' sh {} +
```

**验证**:
```
python3 -c "import sys,sysconfig,glob,os; sfx=sysconfig.get_config_var('EXT_SUFFIX'); bad=[p for p in glob.glob(os.path.join(sys.prefix,'**','*.so'),recursive=True) if '-aarch64-linux-ohos' in os.path.basename(p)]; assert not bad, 'un-normalised OHOS extension suffix (local EXT_SUFFIX=%r): %r' % (sfx, bad)"
```
