# E1078: musl(OHOS) 无 pthread 取消 API，线程需改协作式退出

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, musl, posix, threading
- **作者**: D650

## 错误特征
```
undefined reference.*pthread_cancel|undefined reference.*pthread_setcancelstate|undefined reference.*pthread_testcancel|implicit declaration of function 'pthread_(cancel|testcancel|setcancelstate)'
```

## 根因分析
OHOS 用 musl libc，未提供 pthread_cancel/pthread_setcancelstate/pthread_testcancel（头文件不声明、libc 不导出符号）；glibc 下依赖取消点终止线程的代码在链接可执行文件时（--no-allow-shlib-undefined）报未解析符号。

## 推荐方案
**方法**: 改为协作式退出：①加 volatile 退出标志；②线程循环条件改 !stop_flag，阻塞等待（epoll_wait/poll/sleep）改有限超时以周期性观察标志；③销毁路径置标志 + pthread_join（原 detach 需去掉）；④删除 setcancelstate/testcancel 调用。

**说明**: 用「volatile 退出标志 + 有限超时等待 + pthread_join」替代 pthread_cancel，并删除 setcancelstate/testcancel；线程模型与对外语义不变，退出延迟以等待超时值为上界，glibc 与 musl 行为一致

**修复命令**:
```
grep -rn 'pthread_cancel\|pthread_setcancelstate\|pthread_testcancel\|PTHREAD_CANCEL' ${SRC_DIR} | cut -d: -f1 | sort -u   # 定位全部调用点；逐文件改为协作式退出并存为 patches/NNNN-<file>.patch（勿直接改工作副本）
```

**验证**:
```
printf '#include <pthread.h>\nint main(void){pthread_t t = 0; return pthread_cancel(t);}\n' > /tmp/pcancel_probe.c && ${OHOS_CLANG} /tmp/pcancel_probe.c -o /tmp/pcancel_probe -lpthread   # 期望 undefined reference to 'pthread_cancel'；亦可 grep -c 'pthread_cancel\|pthread_setcancelstate\|pthread_testcancel' ${OHOS_SYSROOT}/usr/include/pthread.h，结果为 0 即 musl 未声明
```
