# E1080: out-of-tree(VPATH) 构建下上游测试按裸文件名找不到参考产物：用 ${srcdir:-.} 定位

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, testing, filesystem
- **作者**: 1EC1

## 错误特征
```
diff: [A-Za-z0-9_.-]+: No such file or directory.*test|(FAILED|failed).*(diff|fixture).*No such file|[A-Za-z0-9_.-]+-example\.[a-z0-9]+: No such file or directory
```

## 根因分析
conan 默认 out-of-source 构建（构建目录与源码目录分离），make check 在构建目录运行测试脚本；而上游参考产物（golden/fixture）以 EXTRA_DIST 随源码发布，只存在于源码 test/ 目录。脚本用裸相对文件名引用它们，于是相对构建目录解析失败，六种输出格式全部 diff 失败。夹具并没有缺失——这正是与"tarball 漏打包夹具"类问题的分界。

## 推荐方案
**方法**: resolve-fixtures-via-srcdir

**说明**: 把脚本里对参考产物的裸文件名改为 ${srcdir:-.}/<name>。automake 的 am__check_pre 会向测试环境导出 srcdir=<源目录>，故 out-of-tree 构建能定位到源码树夹具；:-. 兜底使 in-source 构建行为完全不变（脚本用 POSIX 参数展开，不引入 bash 依赖）。只改定位方式，不改断言或期望内容。

**修复命令**:
```
diff -b testsuite-test.text "${srcdir:-.}/testsuite-example.text"
```

**验证**:
```
ls <src>/test/*-example.* 2>/dev/null | wc -l ; ls <build>/test/ ; grep -n "srcdir" <build>/test/Makefile | head
```
