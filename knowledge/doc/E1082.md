# E1082: Conan ncurses 包是平铺布局（单一 include/ncurses.h 即宽字符头、仅 libncursesw.a 无 libncurses.a）：假定发行版子目录布局的上游 configure 探测链全灭；且 AutotoolsDeps 注入 LIBS=-lncursesw 会让 AC_SEARCH_LIBS 判 "none required"、二次引发 USE_* 宏全不定义的 #error

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, conan, dependency
- **作者**: LCS4

## 错误特征
```
You need ncurses!|
```

## 推荐方案
**方法**: patch-probes-for-flat-layout

**说明**: 最小补丁修探测本身（不建 shim 目录、不加伪装宏，宽字符 API 真实存在于平铺头与库中）：(1) configure.ac 的 ncursesw 轮次在 $ac_cv_header_ncursesw_ncurses_h != yes 时回退用 $ac_cv_header_ncurses_h 作为宽字符头判据，让 AC_CHECK_LIB(ncursesw, addch/add_wch) 真实探测平铺 libncursesw.a（addch/add_wch 均存在），AC_SEARCH_LIBS 自然得出 -lncursesw，HAVE_WIDE_NCURSES/USE_NCURSES_W 与发行版布局结论一致；(2) 源码 include 块（如 includes.h）在 HAVE_NCURSESW_NCURSES_H 未定义时回退包含平铺 <ncurses.h>（distro 布局不受影响，双布局兼容）。配方侧配套：**不用 AutotoolsDeps**（其 LIBS 污染会让 AC_SEARCH_LIBS 判 "none required"，两宏全不定义 → #error），改用 AutotoolsToolchain 并手动把依赖 includedirs/libdirs 追加进 extra_cxxflags/extra_ldflags（AutotoolsToolchain 本身不注入依赖搜索路径），探测由 configure 自身完成。

**修复命令**:
```
grep -n "ac_cv_header_ncursesw_ncurses_h" configure.ac; grep -n "USE_NCURSES_W" src/includes.h   # 两个补丁锚点；补丁后在 config.log 确认 checking for library containing initscr... -lncursesw
```

**验证**:
```
P=$(conan cache path ncurses/6.5 2>/dev/null || echo ~/.conan2/p/ncurses*); ls $P/include/ncurses.h $P/include/ncursesw 2>&1; nm $P/lib/libncursesw.a 2>/dev/null | grep -c " T add_wch"   # 平铺布局指纹：头存在、无 ncursesw/ 子目录、add_wch 在 libncursesw.a
```
