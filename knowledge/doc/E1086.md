# E1086: glibc 内部类型/宏在 musl 下编译失败（bits/types.h、__uintN_t、__WORDSIZE、__glibc_likely）

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, libc, musl, headers
- **作者**: 1FC6

## 错误特征
```
fatal error: 'bits/types.h' file not found|fatal error: 'bits/[a-z0-9_./]+\.h' file not found|unknown type name '__uint8_t'|unknown type name '__intmax_t'|use of undeclared identifier '__glibc_likely'|use of undeclared identifier '__WORDSIZE'|undefined reference.*__glibc_unlikely
```

## 根因分析
上游直接使用 glibc 内部实现：<bits/types.h>、__uintN_t/__intmax_t/__uintmax_t、__WORDSIZE、__PRI64_PREFIX、__glibc_likely/__glibc_unlikely；musl(OHOS) 不提供这些内部符号与头文件。musl 下 isdigit/isalpha 是宏，会把原先仅告警的传参错误升级为硬错误。

## 推荐方案
**方法**: ①<bits/types.h>→<sys/types.h>；②删除 __ 前缀 typedef 重定义，改用 <stdint.h>/<inttypes.h>（PRIu64/UINTMAX_MAX 由标准头提供）；③__glibc_likely(x)/__glibc_unlikely(x)→(x)；④isdigit/isdigit 类宏的参数必须是 int 值（用 (unsigned char)*p）。

**说明**: 用 C/POSIX 标准头与标准类型替换全部 glibc 私有实现：<bits/types.h>→<sys/types.h>，__uintN_t/__intmax_t/__uintmax_t→<stdint.h>，__WORDSIZE→sizeof(void*)*8 或 UINTPTR_MAX，__PRI64_PREFIX→<inttypes.h> 的 PRId64/PRIu64，__glibc_likely/unlikely(x)→(x)；字分类宏实参强制 (unsigned char)

**修复命令**:
```
grep -rn 'bits/types\.h\|bits/[a-z0-9_]*\.h\|__uint[0-9]\+_t\|__intmax_t\|__uintmax_t\|__WORDSIZE\|__PRI64_PREFIX\|__glibc_likely\|__glibc_unlikely' ${SRC_DIR}   # 定位全部命中点；逐处改标准头并存为 patches/NNNN-<file>.patch（勿直接改工作副本）
```

**验证**:
```
printf '#include <bits/types.h>\n' > /tmp/glibc_internal_probe.c && ${OHOS_CLANG} -fsyntax-only /tmp/glibc_internal_probe.c   # 期望 fatal error: 'bits/types.h' file not found；再 grep -rn '__glibc_likely\|__glibc_unlikely\|__WORDSIZE\|__uint8_t\|__PRI64_PREFIX' ${SRC_DIR} 列出全部命中点
```
