# E1087: Automake 测试驱动无法以 shebang 启动测试脚本：改用 LOG_COMPILER 显式解释器

## 基本信息
- **严重度**: 2
- **类别**: selinux, portability, autotools, testing, shell
- **作者**: 1EC1

## 错误特征
```
test-driver:.*bad interpreter: Permission denied|bad interpreter: No such file or directory.*#!/(bin|usr).*(bash|sh)|FAIL\[?.*exit status: 126|Testsuite summary.*# FAIL:\s*1
```

## 根因分析
OHOS 内核/SELinux 拒绝"以 shebang 方式启动脚本"这一机制本身，与 shebang 指向的解释器是否存在无关。automake 的 test-driver 默认把 TESTS 中的脚本当可执行文件直接 exec，于是在鸿蒙上必然 126 失败。关键判据：把 #!/bin/bash 改成 #!/bin/sh 后错误只是从 "No such file or directory" 变成 "Permission denied"，说明不是路径问题，改写 shebang 无法解决。

## 推荐方案
**方法**: log-compiler-explicit-interpreter

**说明**: 给 make check 传 LOG_COMPILER=<可用 shell>，让 automake 驱动执行 `$(LOG_COMPILER) ./script`，脚本作为参数交给 shell，shebang 完全不被内核解析；无需修改上游任何测试文件，断言强度不变。仅当 TESTS 全为脚本时使用（混合 libtool/ELF 测试集须走 E228 的条件式 launcher）。

**修复命令**:
```
autotools.make(target="check", args=["-j1", f"LOG_COMPILER={shlex.quote(shell)}"])   # shell="/system/bin/sh"
```

**验证**:
```
make -j1 check LOG_COMPILER=/system/bin/sh 2>&1 | tail -20 ; grep -c "bad interpreter" test/test-suite.log
```
