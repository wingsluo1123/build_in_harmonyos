# E1089: 上游 golden 基准随版本语义变更失效（非平台差异）时，须先用「未修改源码在第二平台复现同一输出」证明基准过期，再按实测输出刷新

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, version, testing, upstream-defect
- **作者**: B1A2

## 错误特征
```
tests/test0.fasta|TCCTTGACCAGTTAGCAAGACGATATGCATCAAGTGCACTGGC|test0.sh
```

## 根因分析
上游在版本演进中改变了影响输出的语义（dawg 1.1 起 rand_real() 由 ILP32 位拼接 union 改为 (double)u/2^32、rand_bool() 由 <= 改为 <），却未重生成 golden 基准 tests/test0.fasta，导致 diff 型测试对**新版本自身**恒失败。上游在换构建系统时（dawg 1.2 由 autotools 迁 CMake）也没有迁移该测试：tests/CMakeLists.txt 为 0 字节、脚本仍读 autotools 的 top_srcdir，因此 ctest 从不注册它，失败被长期隐藏；Debian 则在 debian/rules 用 `|| true` 显式忽略。要点：这是**版本语义漂移**而非平台差异。

## 推荐方案
**方法**: prove-not-platform-drift-then-refresh-golden

**说明**: 先取「未修改源码 + 第二平台」的复现证据（发行版构建日志/打包补丁/deb 源码包 orig tarball 与 rules 的忽略语句）与「旧语义还原实验」，把基准归属钉死在上游旧版本语义上；确认非平台差异后，用**本版本源码的真实确定性输出**刷新基准，并在 notes.md/PR 正文写明：上游缺陷编号、上游未迁移该测试的证据（0 字节 tests/CMakeLists.txt、ctest 注册数 0）、发行版忽略语句、刷新前后 LCP 量化、以及"本机输出 == 第二平台输出"的逐行比对。外部引证必须把**原始响应字节**入库（逐份记录来源 URL、HTTP 状态码、sha256 与"证明了什么"），优先选离线可复核来源（发行版官方包内文件、邮件列表归档），抓取失败（如某 issue 路径 404 只回 9 字节 Not Found 页，而主机本身 200）也要原样留档并声明"未直接读到该页面"，同一事实的所有出现点同步同一口径；不得把无法复核的外部链接写成既成事实。测试仍需真实执行（不得改为跳过），并把基准刷新补齐为可复核的补丁（整文件替换用 delete-item + add-item 形态 + patch_strip: 0，见仓库既有口径）。

**修复命令**:
```
DAWG=<build>/src/dawg top_srcdir=<src> sh tests/test0.sh   # 刷新基准后应 rc=0；基准刷新补丁在 conandata.yml 的 patches 注册
```

**验证**:
```
① 判定基准是否过期：用**未修改**的上游源码在第二平台/工具链（或发行版打包记录）复现输出——dawg 实测 OHOS clang15/libc++/musl 与 Debian amd64 glibc/GCC 的输出逐行一致，而与该基准逐字节不同；当前 v1.2 输出与旧基准的最长公共前缀在 A/B/C/D/R 五条序列上全为 0。② 隔离机制：仅把 rand_real()/rand_bool() 还原为旧版本语义重编，LCP 立刻升为 A=2/B=26/C=10/D=50/R=50（最长 50/102，出现在 D 与 R），证明基准归属旧 RNG 语义而非平台。③ 刷新后确认测试转绿且非空跑：**sh tests/test0.sh** 退出码 0，且程序输出条数/比对长度断言成立（dawg 实测 5 条 × 105 列）。
```
