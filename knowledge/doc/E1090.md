# E1090: raw Makefile 配方用 make 命令行变量传 CFLAGS 时，字符串宏必须两级反斜杠转义，否则宏静默从字符串退化成浮点常量（唯一信号是 -Wformat 告警）

## 基本信息
- **严重度**: 2
- **类别**: build-system, make, toolchain, conan
- **作者**: D9DF

## 错误特征
```
format specifies type 'char *' but the argument has type 'double'|format '%s' expects argument of type 'char *', but argument|format specifies type 'char*' but the argument has type 'double'
```

## 根因分析
传给 make 的命令行变量值会被解析两次：make 先把它展开进 recipe 文本（原样拼接），执行 recipe 的 shell 再解析一次。上游 Makefile 里写 CFLAGS = -DVERSION=\"1.2\" 是正确的，因为 make 把带反斜杠的文本交给 recipe shell、由第二层把 \" 变成给编译器的字面引号；但当配方用命令行变量覆盖 CFLAGS 时，这层反斜杠必须由配方自己写出来——若配方里写成 shell 双引号包裹的 "-DVERSION=\"1.2\""，反斜杠在调用 make 的那个 shell 就被吃掉（第一层），make 变量里只剩 -DVERSION="1.2"，recipe shell 再把双引号剥掉（第二层），编译器最终收到 -DVERSION=1.2，宏从字符串常量变成浮点常量

## 推荐方案
**方法**: double-escape-in-recipe

**说明**: 在配方里构造 flags 字符串时，让反斜杠活到 make 的变量里：Python 侧写 '-D%s=\\"%s\\"'（源码里反斜杠加引号两个字符），并把这个值放进 shell 单引号参数（make CFLAGS='... -DNAME=\"x.y\"'），使 make 变量内容含 \"、recipe shell 再还原成 "。自检判据是编译日志里宏展开行应显示 #define NAME "x.y"（带引号）

**修复命令**:
```
self.run("make -j1 CC='%s' CFLAGS='%s'" % (cc, " ".join(cflags + ['-DNAME=\\"%s\\"' % ver])), cwd=self.source_folder)
```

**验证**:
```
grep -n "format specifies type 'char \*' but the argument has type 'double'" <build log>；同时核对 make 回显行：make 打印的是 -DNAME="x.y"（已被剥一层）还是 -DNAME=\"x.y\"（正确形态）
```
