# E1092: 老式 config.guess/config.sub 不识别 HarmonyOS/aarch64：最小补丁（+7/-1 行）替代整文件替换（补丁文件 5841 行）

## 基本信息
- **严重度**: high
- **类别**: platform, ohos, portability, build-system, autotools
- **作者**: D275, songzhenyan <apVBMI1DvwCqWTll.songzhenyan@noreply.gitcode.com>, B4CT
- **来源 PR**: !9639

## 错误特征
```
config.guess: unable to guess system type 后打印 UNAME_SYSTEM = HarmonyOS；configure 报 cannot guess build type / 或 triplet 被归一为 aarch64-unknown-linux-gnu 而非 aarch64-unknown-linux-ohos
```

## 根因分析
2003 年 autoconf 2.5x 附带的 config.guess 只有 *:Linux:*:* 一类分支，OHOS 上 `uname -s` 返回 HarmonyOS（老固件为 HongMeng）且机器为 aarch64 → 落默认分支报 "unable to guess system type"；config.sub 的 maybe_os 白名单不含 linux-ohos，且通用 `-linux*)` 分支会把 os 中的 linux 改写为 linux-gnu

## 推荐方案
**方法**: 最小补丁注入平台识别分支（不改脚本结构、不整文件替换）: config.guess 在 `${UNAME_MACHINE}:${UNAME_SYSTEM}:...` 的 case 首插入 HarmonyOS/HongMeng 命中分支直接输出 aarch64-unknown-linux-ohos；config.sub 在 maybe_os 白名单加 linux-ohos*，并在通用 -linux*) 之前插入 -linux-ohos*) 保持 os 不被改写。合计 +7/-1 行

**说明**: 两个补丁共 +7/-1 行即让 2003 年脚本产出 aarch64-unknown-linux-ohos，与仓库事实标准整文件替换（补丁文件 5841 行）结果等价；PR 体量下降 99.8%，审查规则不再判“变更过大”

**修复命令**:
```
patches/0001-config.guess.patch: 在 case "${UNAME_MACHINE}:${UNAME_SYSTEM}:${UNAME_RELEASE}:${UNAME_VERSION}" in 之后插入
```

**验证**:
```
sh config.guess   # 期望 aarch64-unknown-linux-ohos；sh config.sub "$(sh config.guess)" 期望同值；configure 日志应出现 checking build/host system type... aarch64-unknown-linux-ohos
```
