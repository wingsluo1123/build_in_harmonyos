# E1094: Scientific library cross-libc/arch validation: derive numeric tolerances from algorithm precision instead of one loose epsilon

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, testing
- **作者**: 62A2

## 错误特征
```
tolerance.*1e-3.*(julian|angle|sidereal|position)|FAIL.*diff=|assert.*fabs.*<.*1e-6|ok.*calc=.*diff=
```

## 根因分析
Single uniform epsilon cannot span algorithm precision classes: exact unit conversion rounds at ~1e-12 deg, julian day arithmetic at ~1e-9 day, IAU-1980 nutation truncates at ~1e-5 deg, VSOP87 at ~3e-4 deg, lunar ELP at ~1e-2 deg; a one-size-fits-all 1e-3/1e-6 epsilon either masks real algorithm errors (false pass) or flags precision-limited fixtures as failures. Upstream fixtures may also be frozen stale: libnova v0.16 ships 24/340 lntest expectations that disagree with the shipped algorithm identically on a second OHOS SDK clang/musl native build and the cross/OHOS package build (platform-independent); only expectations with authoritative proof (upstream master commit 7b60adc of 2016-09-12 for 3 nutation items, Meeus printed values, or epoch-correct independent reduction) may be corrected, all others must stay reported as failures

## 推荐方案
**方法**: derive-tolerance-from-algorithm-precision

**说明**: Derive each asserted tolerance from the algorithm class of the tested API: exact unit conversion 1e-8..1e-12 deg, julian day 1e-9 day, sidereal/nutation at print rounding (1e-7 h) or series truncation (1e-5 deg), planetary VSOP87 3e-4 deg, lunar ELP 1e-2 deg, rise/set/transit 1e-3 day with minute-granularity integer comparison; document the derivation in source comments and grade expected-value provenance (authoritative literature like Meeus, upstream fixture passed on this platform, or library output cross-checked by independent reduction)

**修复命令**:
```
grep -nE "EPS|TOL" archives/l/libnova/0.16/test_package/
```

**验证**:
```
grep -nE "EPS|TOL" test_package/*.c && conan create -pr:b=default -pr:h=ci/conan/profiles/ohos-aarch64 . --build missing
```
