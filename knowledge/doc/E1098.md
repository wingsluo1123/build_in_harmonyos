# E1098: 上游 Makefile.in 把 in-tree 相对 include 路径(-I../../src/include)写死，conan 独立 build 目录下头文件找不到

## 基本信息
- **严重度**: high
- **类别**: autotools, make, include-path, out-of-tree
- **作者**: FD15
- **来源 PR**: !9639

## 错误特征
```
src/util/bitvector.c:1:10: fatal error: 'util/bitvector.h' file not found
```

## 根因分析
上游 src 下的 Makefile.in 把 in-tree 相对路径直接写进编译选项, 形如 -I../../src/include, 而没有使用 automake 的 top_srcdir 变量; conan 2 的 layout 使用独立 build 目录 build-release/, 该相对路径被解析到 build-release/src/include 的空镜像 -> 头文件找不到; 本地手工 in-tree 编译不复现, 是本地过/CI 挂的典型差异

## 推荐方案
**方法**: 配方 generate() 用绝对路径补齐 include 根: 在 AutotoolsToolchain 上 tc.extra_cflags.append 追加 -I 加 self.source_folder 加 /src/include; extra_cflags 进入 CFLAGS 与 Makefile 自带 -I 叠加且顺序无关; 不要靠改 build 目录或用 --srcdir 规避

**说明**: generate() 中 tc.extra_cflags.append(f"-I{self.source_folder}/src/include") 注入绝对 include 根, 覆盖 Makefile 里失效的相对路径

**修复命令**:
```
tc.extra_cflags.append("-I" + self.source_folder + "/src/include")
```

**验证**:
```
grep -rnE '\-I\.\./\.\.' src/*/Makefile.in | head, 并在 build 目录下确认该相对路径解析结果不存在
```
