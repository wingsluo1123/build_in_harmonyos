# E1099: musl 的 <sys/file.h> 不传递包含 <fcntl.h>，glibc 上隐式可见的 struct flock/F_SETLK/fcntl() 在 OHOS 上变成 incomplete type 与未声明标识符

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, libc, musl, headers
- **作者**: EDF5

## 错误特征
```
incomplete type 'struct flock'|use of undeclared identifier 'F_SETLK'|use of undeclared identifier 'F_WRLCK'|call to undeclared function 'fcntl'
```

## 根因分析
glibc 的 <sys/file.h> 内部会 include <fcntl.h>，于是 struct flock 的定义、F_SETLK/F_WRLCK/F_UNLCK 常量与 fcntl() 原型全都间接可见；musl 的 <sys/file.h> 只声明 flock()/lockf() 相关接口，这些定义在 <fcntl.h> 里而不经 <sys/file.h> 暴露。源码只 include <sys/file.h> 时，glibc 上「碰巧能编」，musl/OHOS 上同一段文件锁代码同时报一个类型不完整、三个常量未声明与一个函数隐式声明

## 推荐方案
**方法**: add-explicit-fcntl-include

**说明**: 在原有平台条件块内（如 #if defined(__LINUX__)）<sys/file.h> 之后补一行 #include <fcntl.h>，不改逻辑、不加 __OHOS__ 条件编译；glibc 下重复 include 因头文件守卫而无害，因此该修复平台中立。先按 grep 枚举全部使用点（struct flock/F_SETLK/F_WRLCK/fcntl）再逐个条件块补齐

**修复命令**:
```
grep -rn 'struct flock\|F_SETLK\|F_WRLCK\|F_UNLCK' src/ && printf '#include <sys/file.h>\n#include <fcntl.h>\nstruct flock fl;\nint x = F_SETLK;\n' > p.c && clang -fsyntax-only p.c; echo rc=$?
```

**验证**:
```
printf '#include <sys/file.h>\nstruct flock fl;\nint x = F_SETLK;\n' > p1.c && clang -fsyntax-only p1.c; echo "sysfile-only rc=$?" ; printf '#include <sys/file.h>\n#include <fcntl.h>\nstruct flock fl;\nint x = F_SETLK;\n' > p2.c && clang -fsyntax-only p2.c; echo "with-fcntl rc=$?" ; printf '#include <fcntl.h>\n' > p3.c && clang -E p3.c 2>/dev/null | grep -m1 -oE '/[^\"]*fcntl\.h'
```
