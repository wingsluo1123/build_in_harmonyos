# E1100: test_package 脚本用 'readelf ... | grep -q' 早退管道：CI 侧 LLVM readelf 遇 EPIPE 报错并以 74 退出（本地 GNU readelf 静默通过）

## 基本信息
- **严重度**: medium
- **类别**: pr-check
- **作者**: BCF3
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/10031

## 错误特征
```
error: write on a pipe with no reader|Error 74 while executing|test package.*Error in test\(\) method
```

## 根因分析
CI worker 的 HNP 环境同时提供 GNU binutils readelf 与 LLVM llvm-readelf，测试环境 PATH 中 readelf 解析到 LLVM 实现；脚本里 'readelf ... | grep -q PATTERN' 的读端在 grep 命中后立即关闭，LLVM readelf 写剩余输出时写系统调用返回 EPIPE，其 raw_fd_ostream 报 'error: write on a pipe with no reader' 并以 74 (EX_IOERR) 退出；配合 set -e / set -o pipefail 使整个 test_package 脚本失败。本地是 GNU binutils readelf（忽略 EPIPE），因此本地 W3 全绿、CI 必挂——典型的环境实现差异导致本地不可复现的失败。

## 推荐方案
**方法**: 输出先落盘再匹配

**说明**: 把 readelf 输出重定向到文件（或 shell 变量），再对文件/变量做匹配，彻底避免读端早退的管道。

**修复命令**:
```
readelf -SW "$binary" > "$tmpdir/sections.txt" 2>&1 || fail "readelf -SW failed"; grep -q "\\.note\\.ohos\\.ident" "$tmpdir/sections.txt" || fail ".note.ohos.ident section missing"
```

**验证**:
```
llvm-readelf -sW <bin> 2>err.txt | grep -q UND; echo rc=29129?; cat err.txt
```
