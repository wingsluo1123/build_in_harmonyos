# E1101: 消费者配方 build() 未注入依赖运行库路径：in-tree 测试程序加载共享依赖失败

## 基本信息
- **严重度**: medium
- **类别**: dependency, testing, environment, shared-linking
- **作者**: A20A
- **来源 PR**: 9889

## 错误特征
```
Error loading shared library libpcsclite\.so\.1|Error loading shared library lib[^:]*: No such file or directory \(needed by|tests were run, 1 failed
```

## 根因分析
conan create 的构建期只自动应用工具链（build）环境，配方 build() 里 make check 触发的 in-tree 测试程序在运行期还要加载宿主依赖的共享库；依赖由 conan 管理、其 lib 目录不在任何全局搜索路径上，测试程序于是报 "Error loading shared library libpcsclite.so.1" 之类的加载错误直接失败（本包 make check 88 项中 1 项失败，正是 sim 测试）。这类失败在本地开发机上常被环境变量掩盖（CPPFLAGS/LDFLAGS/LD_LIBRARY_PATH 泄漏），必须用 scrubbed（无 ambient env）环境复现才会暴露，CI 干净环境首当其冲。

## 推荐方案
**方法**: 在配方 build() 中套上依赖的运行环境（conan 2 用法：from conan.tools.env import VirtualRunEnv; env = VirtualRunEnv(self).environment(); with env.apply(): 包裹 configure/make/make check）。注意 make check 必须也在 with 块内，否则测试程序仍找不到库；保持 make 调用在块内声明（autotools = Autotools(self) 缩进进块内即可）。反模式：不要用 -Wl,-rpath 把构建机路径烘进产物（pre-scan 明确反对 build-machine rpath），也不要依赖外部 LD_LIBRARY_PATH（CI 环境没有）。若确有需要，可在 generate() 中同时输出 RunEnv 供消费者使用，但构建期测试依赖的是这里的 with env.apply()。

**说明**: build() 内用 with VirtualRunEnv(self).environment().apply(): 包裹 configure/make/make check

**修复命令**:
```
在 conanfile.py 的 build() 中：env = VirtualRunEnv(self).environment() 然后 with env.apply(): 内依次 autotools.configure() / autotools.make() / autotools.make(target="check")，并在文件头 from conan.tools.env import VirtualRunEnv
```

**验证**:
```
LD_LIBRARY_PATH=<pcsc-lite pkg>/lib:<build>/src/*/.libs ./tests/sim/sim_test ; echo $?   # =0 证明库路径是唯一缺口（同一二进制不带该变量时 RC!=0）
```
