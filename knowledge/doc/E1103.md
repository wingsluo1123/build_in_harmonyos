# E1103: Release(-DNDEBUG)下 NDEBUG 守卫剔除的内部函数定义与无条件调用不一致,共享库残留未解析符号,消费者加载即失败

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, linking
- **作者**: FD39

## 错误特征
```
undefined symbol: [a-z0-9_]+|Symbol not found|error adding symbols: DSO missing|undefined reference to .* but library contains no definition
```

## 根因分析
上游库同时提供 release 与 debug 构建路径,把调试 helper 的定义放进 #ifndef NDEBUG,但调用点(或在 NDEBUG 之外的其他文件)未同步加守卫;上游默认 ./configure && make 不带 -DNDEBUG,因此缺陷长期潜伏。Conan/发行版 Release 构建由 AutotoolsToolchain 注入 -DNDEBUG 后暴露:定义被预处理剔除、引用仍在,libtool 默认不传 --no-undefined 故链接期不报错,直到消费者 dlopen 才炸

## 推荐方案
**方法**: remove-NDEBUG-guard-around-definitions

**说明**: 打补丁去掉 #ifndef NDEBUG 守卫(保留函数本体)使定义无条件编译;仅适用于纯日志/转储 helper,若有真实副作用则改为给调用点补同样守卫

**修复命令**:
```
patch -p1 < patches/0001-remove-ndebug-guard.patch
```

**验证**:
```
nm -D --undefined-only <pkg>/lib/lib<name>.so* | grep -v 'GLIBC\|libc\.'; grep -rn '#ifndef NDEBUG' <src>/*.c | head
```
