# E1104: AC_FUNC_MALLOC 误判使 config.h 定义 malloc=rpl_malloc，隐式声明在 aarch64 上截断指针

## 基本信息
- **严重度**: high
- **类别**: libc, autotools, configure-cache, pointer-truncation
- **作者**: D275
- **来源 PR**: !9639

## 错误特征
```
src/util/fileaction.c:190:13: error: incompatible integer to pointer conversion assigning to 'void *' from 'int' [-Wint-conversion] | checking for GNU libc compatible malloc... no
```

## 根因分析
AC_FUNC_MALLOC/AC_FUNC_REALLOC 以运行期探针判断 libc 的 malloc(0) 是否返回非 NULL; OHOS/musl libc 上 malloc(0) 合法返回 NULL, 探针判 no -> config.h 里定义 malloc=rpl_malloc 与 realloc=rpl_realloc; 工程内 rpl_malloc 在作用域内无原型 -> C 隐式声明按 int 返回 -> aarch64 指针截断, clang 15+ 直接按 -Wint-conversion 报错中止

## 推荐方案
**方法**: 在 conanfile.py 的 generate() 中向 configure 传 autoconf 标准 cache 变量覆盖运行期探针: ac_cv_func_malloc_0_nonnull=yes 与 ac_cv_func_realloc_0_nonnull=yes (不改源码); 验证 configure 日志不再出现 GNU libc compatible malloc ... no 且 config.h 不含 rpl_malloc

**说明**: 不改源码, 仅在 generate() 里向 configure 注入 autoconf 标准 cache 变量 ac_cv_func_malloc_0_nonnull=yes / ac_cv_func_realloc_0_nonnull=yes, 让探针走"已知答案"路径

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
grep -E "rpl_malloc|rpl_realloc" config.h 与 configure 日志中的 "checking for GNU libc compatible malloc"
```
