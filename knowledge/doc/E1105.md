# E1105: 栈上结构体未初始化 - 免硬件 (-n) 路径把垃圾句柄交给清理函数导致 SIGSEGV

## 基本信息
- **严重度**: 1
- **类别**: detection, portability, testing
- **作者**: C2B7

## 错误特征
```
Signal 11 \(core dumped\)|Error 139 while executing|exit 139|SIGSEGV.*libusb_release_interface|AddressSanitizer.*SEGV
```

## 根因分析
main() 里 `struct ledscreen maindisp;` 是栈上未初始化对象，随后 `disp = &maindisp;` 取址使用。即使运行在免硬件模式（-n，不打开任何设备），退出路径仍无条件调用 close_usbdev()，该函数把 disp->handle（栈垃圾值）交给 libusb_release_interface() / libusb_close()，于是每次运行都 SIGSEGV (exit 139)。

## 推荐方案
**方法**: zero-init-stack-struct

**说明**: 在取址使用前把栈上结构体整体零初始化（一行 memset(disp, 0, sizeof(*disp)); 或 `struct ledscreen maindisp = {0};`），使句柄字段为 NULL，清理函数的既有判空逻辑即可正常短路。属纯上游缺陷修复，不带任何平台宏。

**修复命令**:
```
track-edit add ${SOFTWARE} ${VERSION} ${SOURCE_FILE} && refresh-patch --auto ${SOFTWARE} ${VERSION}
```

**验证**:
```
未打补丁的二进制：`dcled -n -e -m HELLO; echo $?` → 输出 HELLO 后 139（Signal 11）。打补丁后同一命令 → 0。对照实验：同一源码用 valgrind/ASan 运行可定位到 close_usbdev → libusb_release_interface 帧。
```
