# E1109: CMakeDeps 丢弃 static-library 依赖的组件引用：下游编译报依赖头文件 file not found（libosmocore 1.11.0）

## 基本信息
- **严重度**: 2
- **类别**: cmake, linking, conan, dependency
- **作者**: 4892

## 错误特征
```
'talloc.h' file not found|Target .* links to: .*::.* but the target was not found|INTERFACE_LINK_LIBRARIES.*libosmocore::osmogsm
```

## 根因分析
Conan 2 对 package_type=static-library 的依赖默认 headers=False/libs=False，只要未声明 transitive_headers/transitive_libs，CMakeDeps 生成 *.cmake 时会把该依赖从 FIND_DEPENDENCY_NAMES 与 INTERFACE_LINK_LIBRARIES 中静默剔除；配方 cpp_info.components 里写的 talloc::talloc 引用随之丢失，下游（CI test_package）编译期 #include <talloc.h> 报 file not found，链接期报 undefined reference。实测 talloc/2.4.4 为 static-library 类型命中此行为，libusb/pcsc-lite 非 static-type 故保留。

## 推荐方案
**方法**: declare-transitive-headers-libs

**说明**: 在 requirements() 里对所有头文件/组件被公共头暴露或组件 requires 引用的依赖显式声明 transitive_headers=True, transitive_libs=True，使 CMakeDeps 保留组件引用与包含目录。

**修复命令**:
```
self.requires("talloc/2.4.4", transitive_headers=True, transitive_libs=True)
```

**验证**:
```
grep -n FIND_DEPENDENCY_NAMES <pkg>-config.cmake；conan install --requires=<pkg>/<ver> -g CMakeDeps 后确认依赖名与 <dep>::<dep> 出现在生成物
```
