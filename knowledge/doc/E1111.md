# E1111: 公共头文件与 ELF 动态库导出符号契约漂移：双向审计与最小别名修复

## 基本信息
- **严重度**: 2
- **类别**: headers, linking, packaging, testing, abi
- **作者**: 1catmint1 <goblinrs@yeah.net>

## 错误特征
```
undefined reference to .dtx_get_glyphmap_image.|symbol (.*) has no symbol table entry|dlsym.*dtx_get_glyphmap_image.*not found
```

## 根因分析
上游 C 库的公共头文件声明了某 API（drawtext.h:121 无条件声明 dtx_get_glyphmap_image 并注释其用途），但实现源码从未提供该符号——功能实现在另一名字下（font.c:721 的 dtx_get_glyphmap_pixels，返回 gmap->pixels 借用指针）。上游自身 examples/tools 恰好只用序列化/回调两条路径调用像素访问，从不直接调用该声明 API，故上游构建与演示全绿、缺陷不暴露；任何外部消费者按头文件编程即链接失败（undefined reference）。这是库自身头文件↔导出符号契约的单向漂移；反向漂移（库导出符号但头文件不声明，dtx_get_glyphmap_pixels 0.6 起未声明）同时存在，双向都不一致。

## 推荐方案
**方法**: dual-direction-symbol-audit-then-minimal-alias

**说明**: 先做双向符号审计（头声明集 vs nm -D 导出集，两个方向的差集），对"声明未导出"的每个符号在源码级核实：(1) 是否存在功能等价的实现符号（同签名/同所有权语义/同返回值），存在则加最小转发别名并保留原符号；(2) 公共头补齐"导出未声明"的反向漂移声明；(3) 条件编译块内的符号（#ifndef NO_OPENGL）判为非真实缺失不处理。补丁以 apply_conandata_patches 接入，patch_type: bugfix。

**修复命令**:
```
nm -D --defined-only lib/libX.so | sort -k3 → 与头文件声明集求差；diff 中每个符号先 grep 源码找实现名与签名；别名实现: unsigned char *sym_alias(args){return sym_impl(args);}；conandata.yml patches: - patch_file: patches/0001-*.patch, patch_type: "bugfix"
```

**验证**:
```
nm -D --defined-only <pkg>/lib/libX.so | awk '{print $NF}' | sort > /tmp/exported.txt; grep -oE '^[a-zA-Z_][a-zA-Z0-9_]* [a-zA-Z_][a-zA-Z0-9_]*\(' <pkg>/include/X.h | awk '{print $2}' | tr -d '(' | sort > /tmp/declared.txt; comm -23 /tmp/declared.txt /tmp/exported.txt  # 声明未导出; comm -13 反向
```
