# E1112: 1) 提取 pc flags 时循环展开 ${var} 并 replace('"','')；2) -L 用 LDFLAG

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan
- **作者**: A26E

## 错误特征
```
unable to find library -lcurl|-L"[^"]+"
```

## 根因分析
两类陷阱：1) PkgConfigDeps 生成的 .pc 里 Libs: -L"${libdir}" -lxxx 带引号变量引用，程序化提取 flags 若不展开变量+去引号，clang 收到字面 -L"/path" 找不到库；2) 上游 configure.ac 只用 AC_CHECK_LIB 探测库（如 klavaro 的 curl/libintl）却不把 -l 写进 LDADD（系统路径假设），用 env LIBS 注入会污染 configure 的 conftest（conftest 链接了这些库但运行时无 LD_LIBRARY_PATH → cannot run C compiled programs）。

## 推荐方案
**方法**: 1) 提取 pc flags 时循环展开 ${var} 并 replace('"','')；2) -L 用 LDFLAGS 注入（AC_CHECK_LIB 成功后自动把 -l 追加进 LIBS）；3) 缺失的 -l（如 proxy-libintl 的 -lintl，无对应 AC_CHECK）用补丁直接追加到 src/Makefile.in 的 xxx_LDADD——比 make args 传 LIBS=... 稳（conan autotools.make 对含空格 args 的引号处理会吞掉后续 token）。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```
