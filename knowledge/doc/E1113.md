# E1113: 纯 Makefile 项目头文件 typedef __off64_t：直接替换为标准 off_t（_FILE_OFFSET_BITS=64 时同 64 位），并用 >2GB 文件验证 LFS

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, musl, make
- **作者**: 3A59

## 错误特征
```
unknown type name '__off64_t'
```

## 根因分析
OHOS musl libc 不提供 glibc 私有 typedef __off64_t。纯 Makefile（无 configure）项目常在头文件里用 typedef __off64_t off_type 声明大文件偏移类型（如 fastahack 的 LargeFileSupport.h），编译期直接报 unknown type name

## 推荐方案
**方法**: direct-replace-with-off_t

**说明**: 头文件已 #define _FILE_OFFSET_BITS 64 时，直接把 typedef __off64_t off_type 替换为 typedef off_t off_type：off_t 在 LFS 下同为 64 位，语义等价，无需平台宏双分支（与 autotools 下用 libc-capability-guards 不同，纯 typedef 场景直接替换即可）。替换后构造 >2GB（如 3×1GB 序列）FASTA 验证 fseeko/ftello 在 >2GB 偏移处仍正确

**修复命令**:
```
patch: LargeFileSupport.h: typedef __off64_t off_type → typedef off_t off_type；验证: 构造 3GB fasta, fastahack -i && fastahack -r seq3:985950000..985950070（offset 2000070160 > 2GB）
```

**验证**:
```
make CXX=clang++ CXXFLAGS='-O3 -fPIC -D_FILE_OFFSET_BITS=64' -j1 && reports/ohos-lfs-test.sh
```
