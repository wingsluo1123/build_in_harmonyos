# E1114: 交付产物与上游测试靶向文件不一致时的验证盲区（单文件/amalgamation 类包）

## 基本信息
- **严重度**: 2
- **类别**: conan, version, testing, patch
- **作者**: CBFA

## 错误特征
```
upstream tests all PASS but the installed artifact was never compiled or executed|test binary includes a file that is not the packaged one|version macro of the shipped artifact is 0 / snapshot value|tests reference release/<x>-unsupported-snapshot instead of the versioned release
```

## 根因分析
单文件/amalgamation 类库把「生成产物」随源码树检入，上游测试套件却往往靶向另一个文件：开发期快照、未版本化产物、或生成器重新生成的临时副本。配方只搬运并安装其中一个文件时，测试仍然全绿，但被测试的从来不是被安装的那个文件；解码器/库的 initialize 还会比对自身版本宏，快照版本恒为 0 时测试语义也随之错位。此类假绿不会被编译警告、sha256 校验或「N 个用例全过」发现，只有把被安装产物的身份带进测试断言才能暴露。

## 推荐方案
**方法**: 在包内把上游测试的靶向文件改指到实际交付的产物（wuffs 实测：30 个 test/c/std/*.c 的 include 由未版本化 snapshot 改指版本化 release，补丁只改 include 行，不动断言与黄金值），并用 patch_ng 库调用复验补丁应用结果与探索树逐字节一致；同时在 test_package 消费者里断言被安装产物自报的身份/版本宏（wuffs 实测 WUFFS_VERSION==0x000040000、WUFFS_VERSION_STRING 前缀 0.4.0-alpha.10），让「装错文件」变成硬失败而不是静默通过。

**说明**: 把包内上游测试的靶向文件改指到实际交付产物，并在 test_package 中断言该产物自报的身份/版本，使「测试从未覆盖被安装文件」变成硬失败。

**修复命令**:
```
patch_ng.fromfile("<patch>").apply(strip=1, root="<src-tree>") ; diff -rq "<patched-tree>" "<exploration-tree>"
```

**验证**:
```
patch_ng.fromfile(f).apply(strip=1, root=tree) 逐补丁复验 + diff -rq 结果树与探索树；test_package 内断言 WUFFS_VERSION/WUFFS_VERSION_STRING
```
