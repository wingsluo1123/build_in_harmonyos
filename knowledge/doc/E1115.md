# E1115: R51 无测试上游大规模变体：元数据型包的批量交叉校验套件（46 tasks / 42 desc 段落 / 45 包 / 46 快照键）与通过率上报

## 基本信息
- **严重度**: 1
- **类别**: detection, ohos, packaging, testing
- **作者**: unknown

## 错误特征
```
上游.*无测试|no test|0 tests|无测试框架|tests/.*empty|上游测试.*\b0\b|test.*count.*0
```

## 根因分析
R51 要求适配前清点上游测试并实测回填，但大型 Debian blend 元包（45 二进制包 + 46 tasks + 42 desc 段落 + 38 版本 JSON）零测试框架零测试文件；"没有测试"不是技术故障而是资产形态使然——唯一可验证资产是打包结构/元数据有效性，且规模达 40+ 级，需**批量一致性校验**（非逐包抽查），并把校验做进 **test_package（消费者测试）**而非独立脚本，使验证与交付物同源、随 CI 自动执行，满足 R51"如实回填 N/N/通过率（禁占位符）"的申报要求

## 推荐方案
**方法**: metadata-validity-test-suite-large-scale-in-test-package

**说明**: 为大型元数据/打包型包设计批量结构/元数据有效性校验，落进 test_package 七类：①布局（tasks/ + tasksel desc + registry.json + 官方快照 + licenses 存在性）；②tasks/ 批量 Deb822 字段（Task/Description 非空、Install 布尔且计数分布固定）；③tasksel desc 结构（段落数、父任务名、Key 数且全部映射到已打包任务文件）；④**registry.json 与打包文件重新派生的逐任务交叉复核**（title/depends/suggests/recommends，非自证同义重复）；⑤control 声明包（数量、全 Architecture: all、前缀、描述摘要）；⑥官方依赖快照（主题集合 == tasks/ 文件集合、引用成员命名规范、**候选依赖 a|b 与逗号列表需按 [|,] 拆分后逐成员校验**）；⑦semantics（conan_requires == none 与 blends 降级规则）。关键设计：失败项不中断、逐项 [PASS]/[FAIL] 输出、最终汇总 N/N；**大规模特有**的三处解析口径 —— (a) blends-inject 注入注释行（首字符 ';'）不得折入字段值；(b) 空折叠续行（单个空格）折为空；(c) Debian 依赖字段的候选式（`a | b`）与逗号列表（`a, b, c`）必须拆成员校验，否则会误报上游"命名非法"

**修复命令**:
```
conan create <recipe_dir> -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64   # 参考实现 archives/d/debian-science/1.15/test_package/（33 项断言，实测 33/33=100%）
```

**验证**:
```
在仓库根目录执行 conan create archives/d/debian-science/1.15 -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64 → RC=0；观察 test_package 输出 "ALL checks PASSED"（33 项断言逐项 [PASS]，0 [FAIL]）
```
