# E1116: release tarball 子模块目录为空时，先判定测试入口是否真引用子模块，再决定是否按 E150 manual-download

## 基本信息
- **严重度**: 2
- **类别**: compat, build-system, meson, packaging, testing
- **作者**: 7873
- **来源 PR**: 9422

## 错误特征
```
munit/munit.h|fatal: not a git repository|.gitmodules|submodule
```

## 根因分析
GitHub/Gitee 官方 release tarball 只带 .gitmodules 与空子模块目录（E150 现象），

## 推荐方案
**方法**: check-runner-registration-before-manual-download

**说明**: 先做注册级依赖判定（构建系统实际编译每个测试入口时用了哪些宏与源），确认无人引用子模块头后再下"需要子模块"的结论；不可达即不补子模块，直接全量运行套件

**修复命令**:
```
for f in $(find <src>/test -name meson.build); do printf "%s bare=%s exe=%s\n" "$f" "$(grep -c 'TEST_BARE' $f)" "$(grep -c 'executable(' $f)"; done; grep -rn "submodule_header" <src>/test/*.h
```

**验证**:
```
逐注册文件核对 bare 宏与子模块头的引用关系（注意：真实引擎里
```
