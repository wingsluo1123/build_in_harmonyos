# E1121: Conan 拒绝单字符版本（ConanName 要求 >=2 字符）；任务卡单数字版本须目录保持任务卡值并用 set_version() 归一化制品版本

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, packaging, versioning
- **作者**: rapidhash3

## 错误特征
```
ERROR: Invalid package version
```

## 根因分析
conan/api/model/refs.py 的 ref 校验正则 ^[a-z0-9_][a-z0-9_+.-]{1,100}$ 对第二字符组要求 1 到 100 次重复，使版本总长至少为 2，单字符版本（如任务卡版本 3）在 conan create 导出阶段即报 Invalid package version；而仓库 CI 的 L0n 分支门禁按「分支去前缀 == 包目录名-版本目录」精确匹配、平台按该分支名关联任务，版本目录又必须保留任务卡原值

## 推荐方案
**方法**: dir-keeps-task-card-version-set-version-normalizes

**说明**: 归档目录与分支保持任务卡版本（过 L0n 精确匹配与平台关联）；配方不写字面 self.version 属性，改用 set_version() 把制品版本归一化为合规 slug（上游 tag 剥前缀如 rapidhash_v3 到 v3）；test_package/MANIFEST.yml 的 package 字段与制品版本对齐；notes 与版本级 manifest 留证目录-制品版本对应关系

**修复命令**:
```
conanfile.py: def set_version(self): self.version = "v3"  # 上游 tag rapidhash_v3 剥前缀
```

**验证**:
```
conan create archives/r/rapidhash/3 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=... 复现: ERROR: Invalid package version '3'（导出阶段立即失败，与源码无关）
```
