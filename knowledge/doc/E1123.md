# E1123: R51 无测试上游（元数据/数据型包）的验证补充模板：test_package 消费者校验套件 + 通过率回填口径

## 基本信息
- **严重度**: 1
- **类别**: detection, ohos, packaging, testing
- **作者**: unknown

## 错误特征
```
上游.*无测试|no test|0 tests|无测试框架|tests/.*empty|上游测试.*\b0\b|test.*count.*0|upstream_tests:\s*\[\]
```

## 根因分析
R51 要求适配前清点上游测试并实测回填，但元数据/数据型上游（Debian 源码包/blend 元包/纯配置包）零测试框架零测试文件；"没有测试"不是技术故障而是资产形态使然——唯一可验证资产是**打包产物的结构与语义自洽性**。正确做法不是外挂一个独立脚本，而是把校验做进交付物：test_package/ 消费者校验套件（经 test() 内 self.run 实际执行，满足 R34/L0d 非空壳要求），由 conan create 触发，断言数即"适配后测试用例数"，与上游 N=0 形成 PR 测试对比表的可核验数字

## 推荐方案
**方法**: test-package-consumer-validation-suite

**说明**: 为无测试上游把校验做进 test_package（而非外挂脚本），八大类断言：①打包布局（tasks/ + tasksel desc + registry.json + 官方快照 + licenses）；②诚实性（无 bin/ 目录、无 ELF 产物——数据包不得伪造成 CLI 工具）；③上游产物 Deb822 结构（Format 头/字段值与文件名一致/Description 非空）；④tasksel desc 结构（段落数/父任务/Key 层级）；⑤registry.json **从打包文件重新派生后再比对**（交叉复核，非同义反复）；⑥debian/control 声明一致性（包数/arch:all/元包↔任务映射不对称如实记录）；⑦官方依赖快照一致性（主题集合==任务文件集合、字段类型、去重引用数）；⑧语义记录（conan_requires==none 等）。R51 清点证据写入 test_package/MANIFEST.yml 的 upstream_test_evidence，断言数写入 assertion_count，与 test-report.md 三方一致

**修复命令**:
```
conan create archives/d/debian-pan/0.4 -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64   # 实测 RC=0，48/48 断言 PASS（参考实现：archives/d/debian-pan/0.4/test_package/test_debian_pan.py）
```

**验证**:
```
conan create archives/d/debian-pan/0.4 -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64；观察 test_package 输出 "checks: 48, failures: 0 ==> ALL PASSED (100.0%)" 与 build_and_test.sh 的 "Pass rate: 100.0% (1/1)"
```
