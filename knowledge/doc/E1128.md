# E1128: Debian +dfsg / 重打包 orig 压缩包根目录直接放文件（无顶层目录）：get(strip_root=True) 抛 ConanException，须去掉 strip_root；无构建系统的多文件源码包还会被 conan-init 误判成 autotools library 骨架

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, conan, packaging
- **作者**: D148

## 错误特征
```
Can't untar a tgz containing files in the root with strip_root enabled|The zip file contains more than 1 folder in the root|The zip file contains a file in the root
```

## 根因分析
conan.tools.files.untargz/unzip 的 strip_root 要求压缩包只有一个顶层目录：通过 commonprefix 取公共目录，根目录下直接是文件（如 TMalign.cpp / TMalign.f / TMscore.cpp / TMscore.f）时无公共目录，tgz 抛 "Can't untar a tgz containing files in the root with strip_root enabled"，zip 抛 "contains more than 1 folder in the root" 或 "contains a file in the root"。Debian 的 +dfsg / 重打包 orig 压缩包常把少量源文件直接放在根；模板与大多数配方默认写 strip_root=True，照抄即在 source() 阶段失败。另外这类无任何构建系统文件的源码包，init-build/conan-init 回退判成 autotools 并生成 package_type=library + cpp_info.libs 的骨架，需要手工改为直接编译（self.run 调用 conf 取得的编译器）+ package_type=application + bindirs。

## 推荐方案
**方法**: drop-strip-root-for-flat-archive

**说明**: 先 tar tf 看压缩包根结构：根目录直接是文件时，conanfile.py 的 source() 里 get(self, **self.conan_data["sources"][self.version]) 不要传 strip_root（默认 False，文件直接落在 source_folder）；有单一顶层目录时才用 strip_root=True。无构建系统的包不要沿用 conan-init 的 autotools/library 骨架：在 build() 里用 self.conf.get("tools.build:compiler_executables", default={}, check_type=dict).get("cpp","clang++") 取编译器直接编译，package_type=application，package_info 设 libdirs=[] includedirs=[] bindirs=["bin"]。

**修复命令**:
```
get(self, **self.conan_data["sources"][self.version])   # 不带 strip_root
```

**验证**:
```
python3 -c "from conan.tools.files.files import untargz; untargz('tm-align_20190822+dfsg.orig.tar.xz', '.', strip_root=True)"   # 期望抛 ConanException: Can't untar a tgz containing files in the root with strip_root enabled
```
