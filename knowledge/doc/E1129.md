# E1129: finish 的 refresh-patch --auto 会按 per-file 重命名补丁，导致 conandata.yml patch_file 引用失效

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, patch
- **作者**: 8BB0, 8543, pc2-25
- **来源 PR**: (本 PR)

## 错误特征
```
Patch file does not exist|export_sources\(\).*export_conandata_patches|patches/0001-.*\.patch
```

## 根因分析
finish step[1/10] refresh-patch --auto 从工作目录按 per-file 差异重新生成补丁（0001-<file>.patch），并把旧的 *-*.patch 移到 .patch-backup-*。若此前 conandata.yml 的 patch_file 引用的是手工命名（如 0001-use-env-bash.patch），重命名后 export_sources() 报 'Patch file does not exist'，conan create 失败。另注意 refresh-patch 只基于工作目录与 orig 的 diff，若某源文件改动未真正落盘（如 patch 应用不完整）会被静默遗漏。

## 推荐方案
**方法**: finish 前先跑 refresh-patch --auto 主动重命名，随后把 conandata.yml 的 patch_file 条目同步为新生成的 per-file 补丁名；确认全部预期源文件改动都已落盘（diff orig vs work）再生成补丁，避免遗漏。

**说明**: 在 finish 之前主动执行 refresh-patch --auto 并回写 conandata.yml；补丁生成后核验每个预期改动文件都出现在 patches/ 中（本例 3 个：compile_fail.sh / src/tz.cpp / zoned_time_deduction.pass.cpp）。

**修复命令**:
```
python3 scripts/ohc-run.py refresh-patch --auto chrono 3.0.4 && grep -n "patch_file" archives/c/chrono/3.0.4/conandata.yml
```

**验证**:
```
grep -n "patch_file" archives/c/chrono/3.0.4/conandata.yml && ls archives/c/chrono/3.0.4/patches/ && python3 scripts/ohc-run.py conan-verify chrono 3.0.4
```
