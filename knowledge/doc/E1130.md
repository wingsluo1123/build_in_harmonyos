# E1130: constexpr 标注的 C 风格函数在 C++17/20 常量表达式中因 (const void*) 转换不可求值（P2738 需 clang 19+）

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, clang, constexpr, cxx20
- **作者**: rapidhash3

## 错误特征
```
must be initialized by a constant expression|cast from 'const void \*' is not allowed in a constant expression|static assertion expression is not an integral constant expression
```

## 根因分析
C++ 常量表达式直到 C++26 P2738 才允许 void* 到具体对象指针的转换；给 C 库头加 constexpr 标注的项目（rapidhash v3 等）在 internal 函数体内写 const uint8_t* p=(const uint8_t*)key，使整条调用链在常量表达式中不可求值。OHOS clang 15.0.4 实测 C++17 与 C++20 均报 constexpr variable must be initialized by a constant expression，该能力 clang 19 才实现

## 推荐方案
**方法**: runtime-assert-or-clang19

**说明**: KAT/断言一律用运行期比较验证（test_package 口径），notes 声明常量表达式求值需 clang>=19（P2738/C++26）；不要为绕过它给上游头打补丁

**修复命令**:
```
将 static_assert(rapidhash(...)==KAT) 改为运行期 if 比较；或升级到 clang>=19 再启用编译期求值
```

**验证**:
```
clang++ -std=c++20 -c consumer.cpp 复现: error: constexpr variable 'kEmptyCx' must be initialized by a constant expression / note: cast from 'const void *' is not allowed in a constant expression
```
