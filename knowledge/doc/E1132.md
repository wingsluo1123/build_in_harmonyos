# E1132: CLI 工具 -h/--help 按设计返回非零退出码，test_package 的 self.run 需检查输出而非退出码

## 基本信息
- **严重度**: 1
- **类别**: detection, portability, testing
- **作者**: unknown

## 错误特征
```
Error in test\(\) method.*self\.run\(.*--help|self\.run\(.*--version.*ConanException: Error 1 while executing|unrecognized option: version
```

## 根因分析
部分上游 CLI 工具的 -h/--help 处理是 `return usage(), -1;`（如 fdkaac 1.0.9 src/main.c），打印完帮助横幅后以非零状态退出。Conan test_package 的 self.run() 默认把非零退出码当失败抛 ConanException，导致"帮助能正常打印"的二进制被误判为测试失败。这不是 OHOS 平台问题，是上游 CLI 设计与 Conan 测试约定的语义错配。

## 推荐方案
**方法**: check-banner-not-exit-code

**说明**: test_package 不假设 --help 退出码为 0：用 subprocess 捕获 stdout/stderr 后断言版本横幅文本存在（如 "fdkaac 1.0.9"），或 self.run(..., ignore_errors=True) 后另行校验输出；功能验证走真实编码/执行而非 --version

**修复命令**:
```
proc = subprocess.run([fdkaac, "--help"], capture_output=True, text=True); assert "fdkaac 1.0.9" in proc.stdout + proc.stderr
```

**验证**:
```
手动运行 packaged 二进制 --help，观察 stdout 有版本横幅且 $? 为 1；grep 上游源码 "case 'h'" 确认 return -1
```
