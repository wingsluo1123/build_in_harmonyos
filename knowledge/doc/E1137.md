# E1137: CMake install(FILES) 把源码头文件路径写成 ${CMAKE_BINARY_DIR}（文件实际在源码目录），cmake --install 必然失败

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, packaging
- **作者**: pc2-16
- **来源 PR**: feat/check-0.11.0

## 错误特征
```
file INSTALL cannot find \"[^\"]*/([Bb]uild|build)/[^\"]+\"|INSTALL cannot find.*libcompat\.h|cmake --install.*failed
```

## 根因分析
上游 CMakeLists 的 install(FILES ${CMAKE_BINARY_DIR}/xxx.h DESTINATION include) 假设头文件是 configure_file/生成物（存在于构建目录），但该文件实际是源码目录中的静态头文件；构建目录中不存在此路径 → cmake --install 执行安装清单时报 file INSTALL cannot find 直接失败。

## 推荐方案
**方法**: fix-install-source-dir-path

**说明**: 将 install(FILES) 中错误的构建目录路径改为源码目录路径（${CMAKE_CURRENT_SOURCE_DIR}/xxx.h），保留下划线中的文件名；若确为 configure_file 生成物则改装 ${CMAKE_CURRENT_BINARY_DIR} 并确认生成目标先于安装执行。

**修复命令**:
```
sed -i 's|install(FILES ${CMAKE_BINARY_DIR}/\(lib/\)\{0,1\}\([^ )]*\.h\)|install(FILES ${CMAKE_CURRENT_SOURCE_DIR}/\2|' <src>/CMakeLists.txt
```

**验证**:
```
grep -rn "install(FILES.*CMAKE_BINARY_DIR.*\.h" <src>/CMakeLists.txt && stat <src>/xxx.h
```
