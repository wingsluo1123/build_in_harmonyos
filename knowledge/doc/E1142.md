# E1142: clang -O2 常量折叠使 FPCR.FZ 运行时控制对已折叠常量失效（FTZ/DAZ 测试）

## 基本信息
- **严重度**: 2
- **类别**: platform, compiler, testing, optimization
- **作者**: PC32

## 错误特征
```
ftz_output_flush|daz_input_flush|flush-to-zero|_MM_FLUSH_ZERO
```

## 根因分析
clang -O2 在编译期将 FLT_MIN*0.5 等浮点常量表达式折叠为次正规常量，运行时 FPCR.FZ/DAZ 位对已折叠常量无作用；裸 asm 置 FPCR.FZ 后标量与 NEON vmul 实测均正常 flush（平台 FZ 有效），故非平台缺陷而是优化×运行时控制交互

## 推荐方案
**方法**: 诊断：分别以 -O0 与 -O2 编译同一 FTZ 测试对比；验证平台 FZ：裸 asm mrs/msr FPCR 置 bit24 后运行时输入 fmul 应返回 0。处置：此类上游测试如实记录优化敏感性，-O0 下全过即平台能力达标；业务代码依赖运行时 CSR 控制时注意编译器常量折叠会绕过

**说明**: 以 -O0 对照复验运行时 CSR 控制类测试；平台 FZ 经裸 asm 实证有效；失败如实记录为优化敏感性而非平台缺陷

**修复命令**:
```
clang++ -O0 -I. -march=armv8-a+fp+simd tests/ieee754.cpp tests/common.cpp tests/binding.cpp -lm -o /tmp/ieee754-O0
```

**验证**:
```
clang++ -O0 与 -O2 分别编译同一 FTZ 测试；-O0 全过而 -O2 失败即命中；裸 asm msr FPCR bit24 后运行时输入 fmul 应返回 0
```
