# E1143: 音频解码 CLI 的可审计合成 Fixture 与无声卡文件输出验证

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, runtime, testing
- **作者**: BC22

## 错误特征
```
audio: /dev/dsp: No such file or directory|audio output module|cannot open audio|No audio device|no sound card|/dev/dsp
```

## 根因分析
无声卡 CI/OHOS 环境缺少物理音频设备，音频解码 CLI 默认播放路径依赖 OSS/ALSA 等 /dev/dsp 设备节点而无法运行真实解码验证；需程序化生成最小、合法、确定、可审计的音频 fixture，改用文件 sink（wave/hex/raw/文本采样）执行同一条真实解码路径，并校验容器结构、音频参数、帧数/样本数与 dither 容差

## 推荐方案
**方法**: deterministic-fixture-file-sink-decode

**说明**: 确认默认路径依赖物理音频设备后，程序化生成最小合法且可审计的音频 fixture（不使用来源不明二进制样本），用 -o wave:/hex: 文件 sink 执行真实解码，校验容器 magic/格式/声道/采样率/位深、按帧数计算预期 PCM 样本数、对 dither 使用实测容差，并以第二种输出形式交叉验证；辅以不存在文件/垃圾输入负向测试；禁止把 --help/--version 或“输出文件存在”当成功

**修复命令**:
```
gen_fixture fixture.mp3 25 && madplay -o wave:out.wav fixture.mp3 && madplay -o hex:out.hex fixture.mp3 && python3 -c "import sys; sys.path.insert(0, 'archives/m/madplay/0.15.2b/test_package'); from test_madplay import check_wave, check_hex_dump; check_wave('out.wav', 25); check_hex_dump('out.hex', 25)"
```

**验证**:
```
gen_fixture fixture.mp3 25 && madplay -o wave:out.wav fixture.mp3 && madplay -o hex:out.hex fixture.mp3 && python3 -c "import sys; sys.path.insert(0, 'archives/m/madplay/0.15.2b/test_package'); from test_madplay import check_wave, check_hex_dump; check_wave('out.wav', 25); check_hex_dump('out.hex', 25)"
```
