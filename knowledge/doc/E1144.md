# E1144: 随机文件 CLOSE 后 reopen 写 NULL 缓冲区段错误：分配条件按指针判空修复

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, libc, runtime
- **作者**: 70DD
- **来源 PR**: "!8575"

## 错误特征
```
Segmentation fault \(core dumped\)|Signal 11 \(core dumped\)|get #1.*段错误|随机文件.*段错误|PUTGET.*Segv
```

## 根因分析
老式 C I/O 库（如 bwb_dio.c）的 bwb_close 释放随机文件缓冲区并正确置 NULL，但 bwb_open 对 previously-closed 设备（mode==DEVMODE_CLOSED 使 previous_buffer=TRUE）跳过缓冲区重分配，dev_table[].buffer 保持 NULL；FIELD 将变量 sbuffer 映射到 NULL+offset，GET 语句按 reclen 循环写入 NULL 指针触发段错误

## 推荐方案
**方法**: null-guarded-buffer-realloc

**说明**: 将缓冲区分配条件从 previous_buffer != TRUE 改为按 dev_table[].buffer 指针判空（==NULL 时分配）——保留"复用未释放缓冲区"的原设计意图（指针非 NULL 即有效），同时修复 CLOSE 后的 NULL 复用；修复点集中于 bwb_open 单处条件，不动 close/GET/FIELD 逻辑

**修复命令**:
```
if (( mode == DEVMODE_RANDOM ) && ( dev_table[ req_devnumber ].buffer == NULL )) { dev_table[ req_devnumber ].buffer = CALLOC( rlen + 1, 1, ... ); }
```

**验证**:
```
最小 .bas 二分复现（OPEN "r"→FIELD→LSET→PUT→CLOSE→reopen→FIELD→GET 逐语句叠加）定位崩溃语句；应用修复后同一序列与完整测试脚本（如 putget.bas 双记录往返）均正常完成
```
