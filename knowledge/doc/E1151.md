# E1151: 用 VirtualRunEnv + env=conanrun 提供运行期库路径，不擅改已发布依赖

## 基本信息
- **严重度**: medium
- **类别**: conan, dependency-link
- **作者**: 123C

## 错误特征
```
Error loading shared library libdeflate\.so\.0|Error relocating .*libdeflate_|Target .* links to .* but the target was not found|env argument to ConanFile\.run\(\) should be a list
```

## 根因分析
部分上游集成配方在 build() 中把 CMake 开关硬编码（libdeflate/1.25 的配方固定 -DLIBDEFLATE_BUILD_SHARED_LIB=ON -DLIBDEFLATE_BUILD_STATIC_LIB=OFF），因此 default_options = {"libdeflate/*:shared": False} 或 requires(..., options={"shared": False}) 都不会改变产物：conan 会按 shared=False 计算新的 package_id 并从源码重建，但重建出的包里仍然只有 .so。当消费者是静态链接 htslib 的 CLI 时，产物 DT_NEEDED 必然包含该 .so，直接执行报 Error loading shared library。另注：Conan 2 的 ConanFile.run(env=...) 只接受环境脚本名或 "NAME=VALUE" 列表，传 dict 会断言失败。

## 推荐方案
**方法**: 用 VirtualRunEnv + env=conanrun 提供运行期库路径，不擅改已发布依赖

**说明**: 在配方 generate() 中调用 VirtualRunEnv(self).generate()，build() 内运行上游测试用 self.run(..., env="conanrun")；test_package 同样用 env="conanrun"。不要为了消掉 .so 依赖去改已发布依赖的配方（违反 PR 原子性），也不要在 build() 里手拼 LD_LIBRARY_PATH 字典（Conan 2 不接受 dict）。

**修复命令**:
```
generate(): VirtualRunEnv(self).generate(); build(): self.run("bash tests/test.sh static", cwd=run_dir, env="conanrun")
```

**验证**:
```
readelf -d <pkg>/bin/<exe> | grep NEEDED；再以 conanrun 环境执行: bash <exe> --version（应成功）；对比无 LD_LIBRARY_PATH 时的 Error loading shared library
```
