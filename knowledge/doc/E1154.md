# E1154: HarmonyOS PC 无 polkit/pkexec：上游固定 QProcess::start("pkexec", ...) 提权失败但 exitCode()==0，功能静默失效

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, portability, runtime, qt6
- **作者**: FEB2

## 错误特征
```
QProcess.*pkexec|start.*pkexec.*failed|pkexec: not found|设备列表为空.*无报错|smartctl.*空结果|polkit.*missing|权限提升.*静默失败
```

## 根因分析
HarmonyOS PC 没有 polkit/pkexec（真机 command -v pkexec 无输出）。上游 GUI 应用常把特权外部命令写成 QProcess::start("pkexec", {tool, args})，在缺失 pkexec 时 QProcess::start 失败但 exitCode()==0、isOpen()==false，上层若只判断 exitCode 就会把失败当成功，最终表现为"功能静默失效/列表为空/无任何报错"（qdiskinfo 的设备列表即如此）。

## 推荐方案
**方法**: runtime-probe-with-fallback

**说明**: 把固定调用改为运行时探测 + 回退：定义 findExecutable(name)（按 PATH 逐个目录探测可执行文件，避免依赖 which 命令）与 getPrivilegeElevator()（探测 pkexec）；startProcess(proc, program, args, needs_root) 中若 needs_root 且 elevator 非空则执行 "pkexec program args"（保持 Linux 上游语义），elevator 为空则直接执行 "program args"。同时把外部工具缺失（如 smartctl 不在 PATH）转成明确的用户可见错误，而不是返回空字符串。

**修复命令**:
```
command -v pkexec || echo NO_POLKIT; python3 scripts/ohc-run.py graph show E550
```

**验证**:
```
QT_QPA_PLATFORM=offscreen HOME=$PWD/home TMPDIR=$PWD/tmp PATH=<stub_bin>:$PATH <pkg>/bin/<app> & sleep 8; kill $!; grep -c -- "--scan" smartctl-calls.log
```
