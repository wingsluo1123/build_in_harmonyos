# E1155: Conan 配方 generate() 漏掉 CMakeDeps：find_package 回退 Find 模块，静默链上宿主同名共享库（R26 违规 + 非封闭构建）

## 基本信息
- **严重度**: 2
- **类别**: cmake, linking, conan, packaging
- **作者**: F7C2

## 错误特征
```
NEEDED.*libz\.so|libz\.so\.1.*in.*lib|ZLIBConfig\.cmake.*not.*found
```

## 根因分析
配方 generate() 只调 CMakeToolchain(self).generate() 没有 CMakeDeps(self).generate()，build 目录里不会生成 <Pkg>Config.cmake；上游 CMakeLists 又用 find_package(ZLIB) + 旧式 ${ZLIB_LIBRARIES} 变量，于是 find_package 落到 CMake 内置 FindZLIB 模块模式，命中构建机 PATH/搜索路径里的同名库（本机实测：~/.harmonybrew/lib 的 zlib-ng 共享库），产出的 .so 出现 NEEDED libz.so.1：既违反 R26（系统同名库必须静态），又让包依赖 CI worker 上不存在的宿主路径。

## 推荐方案
**方法**: conan-recipe

**说明**: 配方 generate() 里显式生成 CMakeDeps（deps = CMakeDeps(self); deps.generate()），让 Conan 的 <Pkg>Config.cmake 进入 CMAKE_PREFIX_PATH；或退一步在 CMakeToolchain 上 tc.cache_variables["CMAKE_FIND_PACKAGE_PREFER_CONFIG"]=True 强制优先 config 模式

**修复命令**:
```
python3 -c "import conan.tools.cmake as m; print(m.CMakeDeps)"  # generate() 内: CMakeDeps(self).generate()
```

**验证**:
```
readelf -d <pkg>/lib/*.so | grep NEEDED   # 期望只出现 libc++_shared.so/libc.so；且 strings/llvm-nm 里能找到 zlib 符号（已静态内嵌）
```
