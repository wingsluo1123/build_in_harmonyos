# E1157: Bind Conan library mode to upstream CMake cache switches and an API consumer

## 基本信息
- **严重度**: 1
- **类别**: cmake, conan, build-mode-binding
- **作者**: A7F3

## 错误特征
```
DISABLE_DYNAMIC|DISABLE_STATIC|CMAKE_POSITION_INDEPENDENT_CODE|no registered CTest tests
```

## 根因分析
Some CMake libraries read project-specific cache variables for dynamic and static targets without declaring them as CMake options; leaving those variables at defaults can package an unintended target set, while a project with no CTest registration can pass without exercising its public API.

## 推荐方案
**方法**: explicit-cache-mode-and-consumer

**说明**: Map Conan shared/fPIC options to the upstream dynamic/static cache variables, set CMAKE_POSITION_INDEPENDENT_CODE for static builds, and require a consumer test that links the installed target and calls a real public API.

**修复命令**:
```
cmake -S . -B build -DDISABLE_DYNAMIC=ON -DDISABLE_STATIC=OFF -DCMAKE_POSITION_INDEPENDENT_CODE=ON
```

**验证**:
```
Configure with shared=false and fPIC=true, inspect the CMake cache and installed library names, then build a CMakeDeps consumer that calls a public API and run it when the target is executable.
```
