# E1160: 去掉强制全量解码的选项，走参考无关解码路径

## 基本信息
- **严重度**: medium
- **类别**: htslib-cram-reference
- **作者**: 4D8F

## 错误特征
```
Failed to open reference file.*test\.fa|cram_get_ref.*Failed to populate reference|cram_decode_slice.*Unable to fetch reference|Slice decode failure|Read 0 records
```

## 根因分析
CRAM 文件的头部 UR 字段记录了创建时的参考序列路径（上游 test.cram 为作者机器上的 /data7/hbb_megadepth/./test.fa），仓库并不附带该 FASTA。htslib 取参考序列的顺序是 --fasta > REF_PATH（默认 ENA 在线 md5 回取）> REF_CACHE；当 htslib 以 --disable-libcurl 构建时在线回取不可用，本地又无参考文件，任何需要参考序列的 CRAM 解码都会失败。megadepth 的 --alts 会调用 hts_set_opt(CRAM_OPT_DECODE_MD,1) 并把 SAM_SEQ 加入 CRAM_OPT_REQUIRED_FIELDS，从而强制全量解码，必然需要参考序列；不带 --alts 时仅请求 QNAME/FLAG/RNAME/POS/MAPQ/CIGAR/RNEXT/PNEXT，htslib 走参考无关解码路径。

## 推荐方案
**方法**: 去掉强制全量解码的选项，走参考无关解码路径

**说明**: 对 CRAM 输入不要传会请求 SAM_SEQ 的选项（megadepth 的 --alts 即属此类）；仅保留位置/CIGAR 类字段即可参考无关解码。若确实需要 SEQ，必须自备与 CRAM 头部 M5 匹配的参考 FASTA 并用 --fasta 指定，或让 htslib 具备 curl 以便在线回取。

**修复命令**:
```
./megadepth tests/test.cram --prefix test.cram --coverage --no-coverage-stdout --auc --annotation 400 ... （去掉 --alts）
```

**验证**:
```
MEGADEPTH=./megadepth; $MEGADEPTH tests/test.cram --prefix t --coverage --no-coverage-stdout --annotation 400 --min-unique-qual 10 --frag-dist --include-softclip --only-polya --read-ends --test-polya --no-annotation-stdout --no-auc-stdout --filter-out 260 --threads 4; diff tests/test.cram.coverage.tsv t.coverage.tsv（去掉 --alts 后应逐行一致，且日志出现 Read N records 而非 Read 0 records）
```
