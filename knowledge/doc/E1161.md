# E1161: Conan test_package 中 can_run() 的隐式跳过令 L1e 反向测试误判空壳

## 基本信息
- **严重度**: 3
- **类别**: ohos, conan, testing
- **作者**: 1C7E

## 错误特征
```
L1e: test passed WITHOUT package artifacts|L1_RESULT=fail: negative test: test does not depend on package
```

## 根因分析
正常 conan create 使用 -pr:h=OHOS -pr:b=OHOS 时 can_run() 为真；ci/conan/build_and_test.sh 的 L1e 刻意移走包内 bin/ 后用 conan test -pr OHOS 单 profile（build 变为 x86 默认），can_run() 变为假。test() 的 if can_run(self) 分支跳过真实消费者且返回 0，反向测试误认不依赖包。物理 x86 runner 上 QEMU 可运行 OHOS 静态 aarch64，因此跳过也掩盖了本可验证的功能。

## 推荐方案
**方法**: run-actual-target-consumer-on-qemu

**说明**: 不依赖 can_run() 假设物理架构；在 aarch64 真机直接执行，x86 有 qemu-aarch64 时显式用 QEMU 执行静态 test 可执行文件及其调用的包内 CLI，缺执行能力则明确失败而不是静默跳过。

**修复命令**:
```
python3 -c 'import platform,shutil; print(platform.machine(), shutil.which("qemu-aarch64"))'  # 对应 test() 选择 runner，然后 conan test 显式执行被测工具
```

**验证**:
```
CONAN_HOME=/data/harmony-compact/.conan2-ohos python3 scripts/ohc-run.py finish swuniq 0.5 built  # L1e 需报告 Negative test confirmed 且 W3 pass
```
