# E1162: OHOS uname -r 含空格，Makefile 内插 $(shell uname -r) 生成损坏编译宏

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, build-system
- **作者**: Awstme

## 错误特征
```
-D__HarmonyOS_HongMeng Kernel|error: no such file or directory: 'HongMeng'|no such file or directory: 'Kernel'|no such file or directory: '1_12_0'
```

## 根因分析
OHOS 的 uname -r 返回 'HongMeng Kernel 1.12.0'（含空格）。Makefile 里把 uname 输出内插进编译参数（如 BitMagic 平台 mk 的 OS_VER = -D__$(shell uname -s)_$(shell uname -r | sed ...)）时，空格把单个宏拆成多个参数：-D__HarmonyOS_HongMeng Kernel 1_12_0 中 Kernel、1_12_0 被编译器当作输入文件名，报 no such file or directory

## 推荐方案
**方法**: make-var-override-platform-tag

**说明**: 用上游预留的 make 变量顶层覆盖平台标签宏（BitMagic 为 OS_VER=-D__HarmonyOS_HongMeng__，单 token 等价定义）；若上游无预留变量，用 make 变量覆盖整段 PLATFORM_CXXFLAGS/CFLAGS。优先顶层覆盖，不改上游文件

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
uname -r（输出含空格即风险）；make -n 干跑查看展开后的编译命令是否含空格宏
```
