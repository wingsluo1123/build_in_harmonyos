# E1163: 无主构建系统上游的 shell configure 测试套件：环境变量覆盖去掉硬编码工具链并用生成的 CMake driver 在 conan create 内全量复现

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, headers, build-system, testing
- **作者**: S34A

## 错误特征
```
unable to find library -l(blas|lapack)|make.*\*\*\*.*(Error 127)|g\+\+.*not found|cannot find the GCEM library header|fatal error: '(stats|gcem)\.hpp' file not found
```

## 根因分析
上游仓库没有主构建系统（交付物为纯头文件或单目录源码），测试是"shell setup 脚本 + 每套件 configure.in/Makefile.in + 独立 .cpp 程序"结构；configure 脚本在非 darwin 平台硬编码 CXX=g++ 并默认链接 -lblas -llapack（darwin 给 -framework Accelerate），OHOS 环境既无 g++ 也无 blas/lapack，且头文件库本体根本不依赖这些库——链接失败完全来自测试套件的默认值而非库的适配问题。

## 推荐方案
**方法**: env-override-shell-configure-plus-cmake-driver

**说明**: 两步复现：设备探索阶段用 configure 自带的环境变量钩子覆盖默认值（CXX=clang++、STATS_MATRIX_OPS="" 置空 BLAS/LAPACK、GCEM_INCLUDE_PATH 指向 gcem 包 include、-s 开启 std::vector 包装器），不改上游源码跑通全量测试；配方固化阶段在 conanfile build() 里用 save() 生成 CMake driver（对每个测试程序 add_executable 绝对路径 + target_include_directories 指向 source include 与依赖包 include），cmake.build() 后逐个 self.run 断言退出码，使 conan create 在干净机器上自包含复现同一测试证据。

**修复命令**:
```
CXX=clang++ STATS_MATRIX_OPS="" GCEM_INCLUDE_PATH=<gcem-include> bash ./configure -s -o "-O2 -DNDEBUG" && make -j1 && ./xxx.test
```

**验证**:
```
grep -nE "CXX=g\+\+|lblas|llapack|STATS_MATRIX_OPS|GCEM_INCLUDE_PATH" tests/test_setup/configure.in；CXX=clang++ STATS_MATRIX_OPS="" bash ./configure -s 后 make 检查是否仍报 -lblas；conan create 日志中应出现全部 STATS_UPSTREAM_TEST[i/N]
```
