# E1165: 生成器-运行时分离包（如 ANTLR）的目标运行时在无生成器环境下的可审计消费者测试：手写生成代码等价物

## 基本信息
- **严重度**: 2
- **类别**: ohos, cross-compile, conan, testing, api
- **作者**: BEBE

## 错误特征
```
No rule to make target.*(parser|lexer)\.c|cannot find (antlr|Java|jar)|CLASSPATH.*antlr|requires a Java runtime|ERROR: Unable to find package.*(java|jdk)|test_package.*(fail|skip).*no generator|grammar.*\.g.*not compiled|unsatisfied.*generator.*requirement
```

## 根因分析
上游语言工具链是"宿主端生成器（ANTLR Java 工具：grammar→C 源）+ 目标端运行库（libantlr3c：驱动生成的 lexer/parser 源）"两件分离制品。制品仓只收录目标运行库包，不含生成器（Java 工具是构建期/开发期工具，不属于目标产物）；目标环境（OHOS AArch64）通常无 JVM。若 test_package 试图在目标环境运行 Java 生成器或要求制品仓新增 java/jdk 依赖，要么失败要么伪造"目标可运行 Java"的假象；若因此跳过消费者测试，则包的公共 API（字符流、token 流、识别、错误处理、资源释放）完全没有消费者级验证。

## 推荐方案
**方法**: handwritten-generated-code-equivalent-consumer-test

**说明**: 在 test_package 中手写"生成器本应生成的代码的等价物"——不调用生成器、不新增依赖，直接按上游生成代码的结构与 API 契约编写最小 lexer/parser C 源（等价于对 grammar 的最简识别机实现），与上游官方发布的示例/生成的代码形态对齐（可先在宿主用生成器产出参照物，或对照上游源码树中自带的生成代码样本），使消费者测试覆盖运行库的真实公共面：字符流构造、token 流构造、识别成功路径、语法错误路径、以及全套资源释放。生成器本身如需验证（如 ANTLR Java 工具），必须作为宿主工具另行验证，与目标运行库消费者测试严格分开；test_package 只消费目标运行库。

**修复命令**:
```
# 结构参照（宿主侧可选）: java -cp antlr-3.5.3-complete.jar org.antlr.Tool Tiny.g
```

**验证**:
```
grep -rn "java\|jdk\|antlr-3\.\|\.jar" test_package/ conanfile.py | grep -v "^Binary" | head; ldd $(find ~/.conan2/p -name "libantlr3c*" -o -name "*.so*" | head -1) 2>/dev/null | grep -i "jvm\|libjava" ; grep -c "assert" test_package/*.c; ctest --output-on-failure
```
