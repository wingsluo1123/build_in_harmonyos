# E1168: 按上游自身构建脚本的布局准备语言预检输入

## 基本信息
- **严重度**: medium
- **类别**: detection, build-system
- **作者**: 411A

## 错误特征
```
detected_language=mixed|build_system=none
```

## 根因分析
上游 CMake 工程不使用规范名 CMakeLists.txt，而是提供 CMakeLists.txt.<variant>（.ci/.static/.statlib/.windows），构建脚本用 ln -fs CMakeLists.txt.ci CMakeLists.txt 取别名。语言预检判定优先级为 manifest > 构建系统 > 源码统计，而构建系统探测只认规范名；探测落空后回退源码统计，若仓库同时含较多辅助脚本（bash/perl 构建与测试脚本）且 C/C++ 源码文件数很少（megadepth 顶层仅 megadepth.cpp + 若干头文件），主体占比不足 70% 便误判 mixed，进而触发错误的 env_unsupported 终态。

## 推荐方案
**方法**: 按上游自身构建脚本的布局准备语言预检输入

**说明**: 语言预检前先按上游构建脚本的方式补齐规范名构建文件（如 ln -fs CMakeLists.txt.ci CMakeLists.txt），使构建系统探测命中；不要因为探测器回退到源码统计得到 mixed 就立即写 env_unsupported。

**修复命令**:
```
ln -fs CMakeLists.txt.ci CMakeLists.txt && python3 scripts/ohc-run.py lang-preflight <pkg> <ver> --src <src>
```

**验证**:
```
在源码目录执行 ln -fs CMakeLists.txt.ci CMakeLists.txt 后重跑 python3 scripts/ohc-run.py lang-preflight <pkg> <ver> --src <src>，观察 build_system 由 none 变为 cmake、detected_language 由 mixed 变为 cpp
```
