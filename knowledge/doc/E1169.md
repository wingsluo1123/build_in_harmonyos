# E1169: explicit-dll-export-closure-and-platform-test-runner

## 基本信息
- **严重度**: 2
- **类别**: platform, linking, conan, packaging, runtime
- **作者**: 2301

## 错误特征
```
undefined reference.*fftw|cannot find.*internal.*symbol|linking C shared library.*threads|syntax error: unterminated quoted string|cmd.exe.*bash -c
```

## 根因分析
MinGW/GNU ld 会在 DLL 中出现显式 dllexport 时关闭隐式 export-all；若基础 DLL 没有导出线程模块所需的内部 API，线程 DLL 的 import-library 链接会失败。另一个独立边界是 Conan Windows 执行器通过 cmd.exe 调用 test()：POSIX 风格 bash -c '...' 的单引号不会由 cmd.exe 去除，反斜杠路径和 shell 展开会进一步造成未闭合引号。两类问题都可能在库本体编译成功后才暴露。

## 推荐方案
**方法**: explicit-dll-export-closure-and-platform-test-runner

**说明**: 对 MinGW shared 构建，仅在 Windows profile 下启用 CMAKE_WINDOWS_EXPORT_ALL_SYMBOLS 与 -Wl,--export-all-symbols，确保基础 DLL 的导出闭包覆盖子 DLL 链接需求；test_package 在 Windows 直接运行 VirtualRunEnv 提供 PATH 的 .exe，POSIX 才拼 bash -c 与 LD_LIBRARY_PATH。不要用全局 shell 权限或关闭链接错误绕过。

**修复命令**:
```
tc.variables["CMAKE_WINDOWS_EXPORT_ALL_SYMBOLS"] = True；tc.variables["CMAKE_SHARED_LINKER_FLAGS"] = "-Wl,--export-all-symbols"；if self.settings.os == "Windows": self.run("test_probe.exe", env="conanrun")；else: self.run("<bash> -c 'export LD_LIBRARY_PATH=...; ./test_probe'", env="conanrun")
```

**验证**:
```
cmake --build <build> --parallel 2；llvm-nm/objdump 检查基础 DLL 与 import library 的必需符号；Conan Windows test_package 使用 VirtualRunEnv 直接运行 test_probe.exe；目标 OHOS 侧独立执行上游 CTest 与消费者程序并回读 ELF SONAME/NEEDED/.codesign。
```
