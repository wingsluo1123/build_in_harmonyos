# E1172: Conan 2 的 test_package 里 ConanException 必须从 conan.errors 导入、依赖包名须经 Requirement.ref.name 取

## 基本信息
- **严重度**: 1
- **类别**: portability, conan, testing
- **作者**: EE2F

## 错误特征
```
cannot import name 'ConanException' from 'conan'|has no attribute 'name'.*Requirement|ImportError: cannot import name|AttributeError: 'Requirement' object has no attribute
```

## 根因分析
Conan 2 不再从 conan 顶层导出 ConanException（只在 conan.errors），且 self.dependencies.items() 的 key 是 Requirement 对象而非 ConanFileReference：直接 from conan import ConanException 会在加载 test_package/conanfile.py 时抛 ImportError: cannot import name 'ConanException' from 'conan'（G2 conan create 直接失败，错误信息里只有这行，看不出是自研测试代码的问题）；直接 ref.name 取包名则抛 AttributeError: 'Requirement' object has no attribute 'name'，包名要经 ref.ref.name 取。实测 tlog 14 的 test_package 两个都踩中。

## 推荐方案
**方法**: conan2-api-import-and-dependency-name

**说明**: (1) 异常一律 from conan.errors import ConanException（conan 顶层不导出）；(2) 遍历依赖用 for ref, dep in self.dependencies.items(): 时，包名取 ref.ref.name（ref 是 Requirement，其 .ref 是 RecipeReference），需要 cpp_info 用 dep.cpp_info；(3) 本地门禁：python3 -m py_compile 只能查语法，导入错误要到 conan create 的 test 阶段才暴露——最省的排查是直接 grep 全仓既有 test_package 的写法（archives/*/*/*/test_package/conanfile.py 里的 import 段）对齐。

**修复命令**:
```
# from conan import ConanFile; from conan.errors import ConanException; name = ref.ref.name
```

**验证**:
```
python3 -c "from conan.errors import ConanException; from conan import ConanFile"; python3 -m py_compile test_package/conanfile.py
```
