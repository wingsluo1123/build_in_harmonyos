# E1175: 依赖版本低于上游最低要求时的选择性 API 回移：版本探测、静态内联兼容层与依赖元数据同步

## 基本信息
- **严重度**: 2
- **类别**: compat, autotools, conan, dependency, version
- **作者**: 9BFA

## 错误特征
```
implicit declaration of function .plist_dict_.*|no member named .PLIST_OPT_|undefined reference to .plist_dict_|Package .libplist. requires .plist_dict_get_bool|libplist >= [0-9.]+ but found [0-9.]+|checking for libplist >= .* no
```

## 根因分析
上游项目按其声明的最低依赖版本使用 API（例如 libtatsu 1.0.5 的 configure.ac 要求 libplist >= 2.6.0 并在 tss.c 中使用 2.6.0 新增的 plist_dict_* 辅助函数），而本仓库制品仓只提供更旧的依赖版本（libplist/2.3.0）；被依赖库的公共头文件不导出任何版本宏，编译期无法 feature-test，导致旧版本下出现隐式函数声明、类型/枚举缺失与链接期 undefined reference。

## 推荐方案
**方法**: selective-static-inline-api-backport

**说明**: 只回移实际缺失的 API：从依赖库可信上游源码逐字提取公开实现，放入独立的 static inline 兼容头，用构建期版本探测（pkg-config --atleast-version）定义版本门控宏，仅旧版本编译兼容层，新版依赖继续用原生实现；同步 configure 最低版本、pkg-config Requires 与 Conan requires 三处元数据。

**修复命令**:
```
${PKG_CONFIG} --atleast-version=${newver} ${dep} || CPPFLAGS="$CPPFLAGS -D${DEP}_LT_${NEWVER}=1"；受影响 .c 中 #ifdef ${DEP}_LT_${NEWVER} #include "compat.h" #endif；compat.h 内全部函数标记 static inline
```

**验证**:
```
pkg-config --modversion ${dep} 与上游 configure.ac 声明的最低版本比较；对每个缺失 API 在旧版依赖头文件中 grep 符号名确认缺失、在上游 changelog/tag 确认首次出现版本；在依赖 >= 新版本的环境编译确认原生路径不受兼容层影响
```
