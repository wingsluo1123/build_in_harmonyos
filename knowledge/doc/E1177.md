# E1177: lld 把 GNU ld 专有 -export-dynamic 解析为 -e xport-dynamic，ELF entry=0x0 启动即段错误

## 基本信息
- **严重度**: 2
- **类别**: toolchain, linking
- **作者**: Awstme

## 错误特征
```
ld\.lld: warning: cannot find entry symbol xport-dynamic|Entry point address:\s+0x0|Segmentation fault \(core dumped\)
```

## 根因分析
上游 GNU ld 风格链接参数 -export-dynamic（单横线长选项，GNU ld 等价 --export-dynamic）被 OHOS 默认链接器 lld 按短选项聚类解析为 -e xport-dynamic（入口符号）。符号不存在时 lld 警告 cannot find entry symbol 且不设起始地址，ELF entry 落在 0x0（readelf -h 实测），二进制启动即 SIGSEGV（exit 139，亚秒级）。GNU ld 上正常、lld 上必坏，属工具链语义差异

## 推荐方案
**方法**: lld-entry-rdynamic-relink

**说明**: 以 clang driver 正确转译（-rdynamic → -Wl,--export-dynamic）且语义等价的 -rdynamic 替代 -export-dynamic。make 项目可顶层 make 变量覆盖（如 BitMagic：make relink COMMON_LDFLAGS=-rdynamic，零补丁）；CMake 项目改 CMAKE_EXE_LINKER_FLAGS。禁止用 --export-dynamic 双横线改上游文件替代变量覆盖（能不改上游就不改）

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
readelf -h <二进制> | grep 'Entry point address'（0x0 即中招）；用 -rdynamic 重链后应为非零地址且程序可启动
```
