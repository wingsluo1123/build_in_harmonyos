# E1178: Generated Autotools files break strict patch replay across upstream versions

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, toolchain, packaging
- **作者**: 61BA

## 错误特征
```
hunk no\.\d+ doesn't match source file|source file is different - b'.*'|Failed to apply patch
```

## 根因分析
Autotools projects ship generated files (configure, Makefile.in, aclocal.m4) whose line numbering and surrounding text depend on the autoconf/automake that generated them. When a recipe's portability patch was authored against release N and is replayed against release N+1, the semantic target of the hunk is unchanged but its byte offsets have shifted. GNU patch tolerates this with fuzz, whereas patch_ng (used by Conan apply_conandata_patches) matches at exact offsets and aborts the whole build.

## 推荐方案
**方法**: regenerate-patches-as-exact-offset-diffs

**说明**: Re-derive every ported patch from the real difference between the pristine new-version tree and a patched tree, so each hunk header matches the target file exactly and applies with zero fuzz under either patch engine. Replaying a fuzzy patch successfully is not sufficient evidence, because success under GNU patch does not imply success under patch_ng.

**修复命令**:
```
AS_IS="patch -p1 --forward --silent"; MISSES=0; for p in patches/*.patch; do rm -rf /tmp/t; cp -a src-pristine /tmp/t; ( cd /tmp/t && $AS_IS < "$p" ) || { echo "REGEN-NEEDED $p"; MISSES=$((MISSES+1)); }; done; echo "misses=$MISSES"
```

**验证**:
```
P=patches/0001.patch; rm -rf /tmp/o /tmp/w; cp -a src-orig /tmp/o; cp -a src-orig /tmp/w; ( cd /tmp/o && patch -p1 --dry-run --forward < "$P" ); ( cd /tmp/w && patch -p1 --forward < "$P" ); diff -u --label "a/$P" --label "b/$P" /tmp/o/FILE /tmp/w/FILE > regenerated.patch
```
