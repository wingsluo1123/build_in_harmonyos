# E1180: fgetc() 返回值存入 char 变量：AArch64 无符号 char 下 EOF 永不匹配，读输入死循环挂死

## 基本信息
- **严重度**: 1
- **类别**: abi, c-language, signedness
- **作者**: B5C3

## 错误特征
```
程序在读 stdin 或读文件时永久挂住|while .*(curchar|c) = fgetc.* != EOF. 恒真|-Wtautological-constant-out-of-range-compare|result of comparison of constant -1 with expression of type char is always true
```

## 根因分析
C 的 plain char 符号性由实现定义，AArch64 上 clang 默认无符号。用 char 变量承接 fgetc()/getchar() 的 int 返回值时，EOF(-1) 被截断成 255，x != EOF 恒真，读取循环永不退出（表现为构建后冒烟/测试直接挂死，而不是报错）。clang 的 -Wtautological-constant-out-of-range-compare 告警即是本模式的确定信号

## 推荐方案
**方法**: declare-fgetc-result-as-int

**说明**: 把承接 fgetc/getchar 返回值的变量声明为 int（POSIX 正确写法，跨平台无副作用），优先于全局 -fsigned-char；后者只把 char 变有符号从而让 -1 恰好相等，仍属依赖实现定义行为

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
grep -n "warning: result of comparison of constant -1 with expression of type" build.log   # 修复后应为 0 行
```
