# E1182: OHOS patch --dry-run 对新文件补丁有副作用：污染 orig 目录导致补丁头退化为 a/ 路径

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, build-system
- **作者**: AA22

## 错误特征
```
conan create: Failed to apply patch ... source/target file does not exist; 补丁头为 --- a/<newfile> 而非 --- /dev/null; orig 目录出现 0 字节新文件
```

## 根因分析
本机 patch 命令执行 patch --dry-run -p1 验证 --- /dev/null 新文件补丁时，会在 cwd（orig 目录）创建 0 字节目标文件。refresh-patch --auto 的 _dry_run 验证因此污染 orig；下一次 refresh-patch（或 finish 内置步骤）的 diff_pairs 收集阶段 orig_file.exists() 为真，改走 _diff_files 生成 --- a/<path> 头，GNU patch 在干净源码树应用时报 source/target file does not exist，conan create G2 失败

## 推荐方案
**方法**: 诊断：对比 patches/.patch-backup-* 两代补丁头；用 work/.edit-tracker.json 的 baseline 哈希校验 orig 纯净度。修复：删除 orig 中 0 字节污染文件 → refresh-patch --auto 重新生成 --- /dev/null 头 → 再删一次 orig 污染（dry-run 副作用会重现）→ 立即 finish（finish 内部 refresh-patch 在收集阶段看到干净 orig，生成正确补丁）。预防：连续两次 refresh-patch 之间必须检查并清理 orig

**说明**: 清理 orig 污染文件后重跑 refresh-patch --auto 生成正确 /dev/null 补丁头，随即 finish（勿在污染态反复 refresh）

**修复命令**:
```
find work/orig -size 0 -delete && python3 $SKILL_ROOT/scripts/ohc-run.py refresh-patch --auto <软件名> <版本> && find work/orig -size 0 -delete && python3 $SKILL_ROOT/scripts/ohc-run.py finish <软件名> <版本> published
```

**验证**:
```
find work/orig -size 0 | head; head -5 patches/00*-*.patch | grep '/dev/null' && echo '补丁头正常' || echo '补丁头已退化'
```
