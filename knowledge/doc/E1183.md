# E1183: pty 测试里把 script 的 typescript 指向 /dev/null，在只写 typescript 的实现上会丢光全部输出

## 基本信息
- **严重度**: 3
- **类别**: portability, posix, runtime, testing
- **作者**: 996F

## 错误特征
```
daemon run on a pty emits output \(bytes=0\)|pty output contains ESC7|assertions passed: [0-9]+/[0-9]+ \(skipped: 0\).*FAIL E1
```

## 根因分析
script(1) 各实现对"会话输出写到哪里"不一致：util-linux 版同时 tee 到 stdout 与 typescript 文件，而部分实现（含实测的 HarmonyOS worker 上的 script）只写 typescript 文件、stdout 为空。测试若统一写 `script -qc CMD /dev/null > out`，在本地 util-linux 上能从 out 取到数据因而掩盖缺陷，到 worker 上则 bytes=0。另有一层风险：合并写法 -qc 并非所有实现都接受，严格实现会直接报错退出

## 推荐方案
**方法**: typescript 指向真实文件而非 /dev/null，并在断言前把 typescript 与 stdout 两个通道 cat 成并集再统计；同时用与被测程序无关的探针命令（PTYPROBE）依次尝试 `-qc` 与 `-q -c` 两种调用形式判定 harness 可用性，探针失败才 skip

**说明**: 双通道并集统计 + 探针判活，让 runner 差异不会伪装成被测程序缺陷

**修复命令**:
```
script $style "sh -c '<prog>; sleep 6'" spin.ts > spin.out 2>spin.err; cat spin.ts spin.out > spin.all
```

**验证**:
```
script -qc "printf PTYPROBE" /tmp/probe.ts > /tmp/probe.out 2>&1; grep -c PTYPROBE /tmp/probe.ts /tmp/probe.out   # 期望两个文件至少各命中一次
```
