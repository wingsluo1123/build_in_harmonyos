# E1185: Clang address-significance directive rejected by GNU as

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, toolchain, asm, testing
- **作者**: 61BA

## 错误特征
```
unknown pseudo-op.*\.addrsig|unknown directive.*\.addrsig
```

## 根因分析
Clang emits the LLVM .addrsig assembly directive by default, while the selected GNU as version does not parse that directive when a build or test passes compiler-generated assembly through GNU as.

## 推荐方案
**方法**: suppress-clang-address-significance-directive

**说明**: When GNU as is intentionally the assembler under test, add -fno-addrsig through the build-system compiler flags so Clang omits only address-significance metadata while preserving generated code and all upstream tests.

**修复命令**:
```
AS_BIN="${AS_BIN:-$(command -v as)}"; clang -fno-addrsig -S fixture.c -o clean.s; "$AS_BIN" clean.s -o clean.o
```

**验证**:
```
AS_BIN="${AS_BIN:-$(command -v as)}"; clang -S fixture.c -o default.s; ! "$AS_BIN" default.s -o default.o; clang -fno-addrsig -S fixture.c -o clean.s; "$AS_BIN" clean.s -o clean.o
```
