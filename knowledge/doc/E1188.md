# E1188: 64 位平台指针截断对齐：以 int 承接 malloc 指针做对齐运算产生非法地址

## 基本信息
- **严重度**: 3
- **类别**: portability, 64-bit, image-processing, legacy-c
- **作者**: 4D1F

## 错误特征
```
Segmentation fault.*imageData|cast to smaller integer type 'int' from 'unsigned char|cast to 'unsigned char \*' from smaller integer type
```

## 根因分析
2007 年代 C 图像库用 (int)(ptr-1)/align*align+align 对 malloc 返回指针做对齐；指针先被截断为 32 位 int，64 位目标（aarch64/OHOS）上得到的高位丢失值既不等于原指针对齐结果也不可解引用，堆访问段错误；同模式 int 结果再被 cast 回指针。clang 15 编译期以 pointer-to-int/int-to-pointer cast 告警成对出现（每处 2 条）

## 推荐方案
**方法**: uintptr-t-pointer-alignment-rewrite

**说明**: 把对齐运算中的指针统一改为 uintptr_t 参与整型运算（(uintptr_t)(ptr-1)/align*align+align）并补 stdint.h；无平台条件宏、32/64 位语义一致；逐处替换而非全局 -fpermissive 类编译器开关

**修复命令**:
```
sed 替换模板: ((int)(ptr-1)/align) → ((uintptr_t)(ptr-1)/align); 验证: patch --dry-run -p1 后与探索副本 diff -rq 逐字节等价
```

**验证**:
```
make 2>&1 | grep -c "cast to smaller integer type 'int' from"; 消费者程序调用 camAllocateImage 后写 imageData 触发 SIGSEGV（native 冒烟实测 exit=139）；修复后同一消费者 24 项断言全过（SMOKE OK）
```
