# E1191: OHOS 无 libudev：udev 设备枚举依赖的 stub-libudev 适配模式（含 R40 功能降级声明）

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, device-enumeration, hid
- **作者**: calbee21 <calbee21@noreply.gitcode.com>

## 错误特征
```
fatal error: 'libudev.h' file not found|Could NOT find UDEV|pkg_search_module\(UDEV libudev REQUIRED\)|undefined reference to `udev_new'|udev_enumerate_new
```

## 根因分析
OHOS/HarmonyOS PC 不提供 libudev（无 systemd/udev 设备管理器）。上游为 Linux 编写的 USB/HID 外设库普遍通过 pkg-config 检测 libudev 并用 udev_enumerate 扫描 /sys/class/hidraw 等子系统发现设备。configure/cmake 阶段报 libudev.h 缺失或 pkg_search_module(UDEV libudev REQUIRED) 失败；链接阶段报 undefined reference to udev_new。注意分层：协议栈/加密/工具链（纯计算）与设备发现（平台强相关）是两个独立关注点，前者可完整移植，后者必须平台化。

## 推荐方案
**方法**: static-inline-stub-libudev-h

**说明**: 新增 src/stub-udev/libudev.h 头文件，为上游用到的每个 udev API 提供 static-inline stub（udev_new 返回 NULL、枚举函数返回 -1/NULL），语义化为"设备发现禁用"而非崩溃；CMakeLists 在 HarmonyOS 分支 include 该目录并关闭 udev 依赖（NFC_LINUX OFF、pkg_search_module 跳过）。协议栈/加密/CLI 完整保留，BUILD_TESTS=ON 跑上游纯逻辑 regress 验证。R40 要求：notes.md 显式记录设备发现降级（fido_hid_manifest → FIDO_ERR_INTERNAL）并标注需人工确认，后续版本接 OHOS HID-DDK 或 /dev/hidraw 直连。禁止单纯 return 0 空壳宏（R8）——每个 stub 必须保持 API 语义（失败路径）。

**修复命令**:
```
# 参考实现: archives/l/libfido2/1.15.0/patches/0004-src-stub-udev-libudev.h.patch + 0001-CMakeLists.txt.patch（HarmonyOS 分支: NFC_LINUX OFF + stub include dir）
```

**验证**:
```
grep -rn "libudev\|udev_" <src> | head; grep -rn "pkg_search_module(UDEV" <src>/CMakeLists.txt; ls /data/service/hnp/sysroot/usr/include/libudev.h 2>/dev/null || echo "no libudev in OHOS sysroot"
```
