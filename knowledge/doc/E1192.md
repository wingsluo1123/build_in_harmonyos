# E1192: OHOS 上 /tmp 只读且脚本用 zsh 时 heredoc 建临时文件失败（TMPPREFIX 未指向可写目录），导致 W3/CI 脚本内 heredoc 断言整体失效

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, hmdfs, ohos, build-system
- **作者**: VG08, 7B93

## 错误特征
```
can't create temp file for here document: read-only file system|read-only file system: /tmp\b
```

## 根因分析
HarmonyOS/OHOS 的 /tmp 不可写（HMDFS 只读）。zsh 的 here-document 不像 bash 那样用匿名管道，而是落一个临时文件，前缀取自变量 `TMPPREFIX`，**默认值为 /tmp/zsh**，且 zsh **不读取 TMPDIR** 来改写该前缀。因此任何 `#!/usr/bin/zsh` 脚本（如仓库的 ci/conan/build_and_test.sh）里的 `<<EOF` here-document 都报 "can't create temp file for here document: read-only file system"。脚本里靠 heredoc 内嵌 python/shell 片段的门禁（如 ci/conan/build_and_test.sh:439 的 L0i 依赖提取、:787 的目录结构检查）会以 "can't create temp file" 而不是真实判定失败，掩盖真实结论。

## 推荐方案
**方法**: export-tmpprefix-to-writable-dir

**说明**: 在调用侧（执行 finish / build_and_test.sh 的会话）导出 `TMPPREFIX=<可写目录>/zsh`（同时导出 TMPDIR 供其他工具使用），让 zsh 的 heredoc 临时文件落到可写路径。

**修复命令**:
```
export TMPDIR=$HOME/tmp TMPPREFIX=$HOME/tmp/zsh && python3 scripts/ohc-run.py finish <pkg> <ver> built
```

**验证**:
```
TMPPREFIX=$HOME/tmp/zsh zsh -c 'read -r l <<EOF
```
