# E1194: 上游硬编码 CC=gcc 构建内嵌主机工具（peg/leg 等），鸿蒙只有 clang → 先手动建主机工具绕开

## 基本信息
- **严重度**: 2
- **类别**: platform, build-system, toolchain
- **作者**: CDCF

## 错误特征
```
gcc: No such file or directory|Error 127|CC=gcc make
```

## 根因分析
鸿蒙 PC worker 只提供 clang 15（gcc/cc 均 exit 127）。不少老工程把构建期内嵌主机工具（PEG/lex/yacc 类生成器）的编译器硬编码成 CC=gcc，直接 make 必失败。由于 build==host（原生），可先用 conan 的 C 编译器把该工具单独建出来，令上层 Makefile 的 gcc 分支只剩 Nothing to be done

## 推荐方案
**方法**: prebuild-host-tool-with-conan-cc

**说明**: 配方 build() 里先 make -C <hosttool_dir> CC=<cc>，再跑主 make；不改上游源码、不引入平台宏

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
command -v gcc; echo $?
```
