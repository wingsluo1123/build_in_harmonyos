# E1196: 交叉构建中版本绑定的构建期数据生成器选择：同 ABI 环境复用目标工具或异构环境执行两阶段构建

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, autotools, cross-compile
- **作者**: A58D

## 错误特征
```
Cannot use the installed version of file.*to compile magic support files|magic support files.*version.*match|Exec format error.*[a-z_-]*(tool|generator|compiler)|cannot execute binary file.*generated|Failed to generate.*host.*tool|refusing to run.*cross.*executable
```

## 根因分析
上游构建分两阶段——构建期用工具 X 编译数据/代码产物 D，再把 D 与目标库一起安装；非交叉模式 X 就是刚构建的 target 二进制（可直接在构建机运行），交叉模式（--host≠--build）下上游改用构建机 PATH 上的同名系统工具并强制版本一致（D 的格式与库的解析器版本绑定），构建机没有该工具或版本不符时构建在 D 生成处中断；反之若构建系统不加区分直接运行 target X 则报 Exec format error。

## 推荐方案
**方法**: run-target-tool-on-same-arch-host-with-path-override

**说明**: 构建宿主与 target 同架构同 libc（HarmonyOS PC 构建 OHOS AArch64）时，直接用刚构建出的 target 工具编译构建期数据：通过 make 变量（如 FILE_COMPILE）传含路径的覆盖（路径含 / 时上游通常跳过系统版本检查），先完成工具目标再构建数据目标；构建出的数据产物架构无关（版本化二进制数据库），target 库运行时加载不受构建机架构影响。

**修复命令**:
```
make -j1 FILE_COMPILE=$PWD/src/file
```

**验证**:
```
grep -RInE "FILE_COMPILE|add_custom_command|BUILD_EXECUTABLE|\.mgc|mkenums" Makefile* */Makefile.am CMakeLists.txt | head; <target-tool> --version（在构建机上直接运行）; file <target-tool>（确认 ELF 机器）; make -n 2>&1 | grep -E "cannot execute|Exec format|version"
```
