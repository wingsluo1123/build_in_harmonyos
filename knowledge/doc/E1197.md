# E1197: OHOS 内核内存保护/ASLR 的探针测量与解读口径（含非 x86 探针适配）：先补目标架构最小 shellcode 恢复判定力，再按"内存类别×操作"矩阵实测，用"不可利用≠保护存在"口径解读并列明判定盲区

## 基本信息
- **严重度**: 2
- **类别**: platform, kernel, security, memory
- **作者**: 9C4A

## 错误特征
```
Executable .*: (Killed|Vulnerable)|No randomization|getvdso: No error information|Wrong architecture|blackhat mode not supported
```

## 根因分析
安全探针套件的判定力依赖目标架构最小 shellcode（上游 paxtest 的 shellcode.h 无 aarch64 分支时回退 x86 RET，ARM64 上可执行/不可执行内存都表现为 Killed，15 项 exec 探测退化为盲判）；同时 Killed/No randomization 等结果语义容易被误读为"保护存在"；OHOS 的 W^X/XPM、procfs（无 [vdso]）、aarch64 返回地址语义（x30）与 clang（无嵌套函数→blackhat 回落）造成若干测试项不可测或语义失效，需要显式列明

## 推荐方案
**方法**: fix-probe-arch-then-run-matrix

**说明**: 第一步先恢复探针判定力：为目标架构补齐最小"执行后正常返回"shellcode（aarch64 用 ret, 0xd65f03c0；ARM32/PPC/SPARC 上游已有分支可参照），此时可执行页应返回 Vulnerable、不可执行页 Killed，判定重新有正反两向。第二步按"内存类别 × 操作"矩阵实测并逐项留证：exec 系（anon/bss/data/heap/stack/shlib）× {直接执行, mprotect 后执行} + writetext + 随机化（多类各 1500 次采样）+ rettofunc。第三步按"不可利用≠保护存在"口径解读并显式列明盲区（无 arch shellcode 时的盲判、VDSO 不可测、rettofunc 的体系结构差异、blackhat 在 clang 下的回落）。
