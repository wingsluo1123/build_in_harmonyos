# E1198: L4 危险函数扫描对整个补丁文件做无上下文 grep，命中英文单词内嵌的 strcpy/sprintf/gets/strcat 子串

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, testing
- **作者**: 996F, GoliWie
- **来源 PR**: 未合并（分支 feat/libgee-0.20.8.1，run libgee-0.20.8.1）

## 错误特征
```
L4: Dangerous functions found in patches|L4_RESULT=warn: dangerous functions in patches
```

## 根因分析
L4 用 grep -rlE '(strcpy|sprintf|gets|strcat)\b' 扫描 patches/ 下的所有文件，包含补丁的人类可读说明头（commit-message 式前言）。说明里引用构建工具原始报错时，普通英文单词恰好内嵌了这些子串即误报——实测 spinner 的补丁说明里引用上游 make 报错 "No targets specified and no makefile found"，其中 "tar-gets" 内嵌 gets（\b 词边界只要求前一字符非词字符，不要求整词匹配），于是 L4 报 warn，尽管补丁 hunk 里根本没有这些函数

## 推荐方案
**方法**: 只改写补丁说明里的措辞以避开内嵌子串（例如把 "No targets specified..." 的引用改成 "there is no makefile for it to read"），保持 hunk 内容一字不动；随后用 grep -rlE 复扫确认无输出，并严格验证 patch --fuzz=0 仍能干净应用

**说明**: 只动说明文字、不动 hunk，绕开无上下文子串误报

**修复命令**:
```
grep -rlE '(strcpy|sprintf|gets|strcat)\b' <pkg>/patches   # 必须无输出
```

**验证**:
```
grep -rlE '(strcpy|sprintf|gets|strcat)\b' <pkg>/patches; grep -noE '(strcpy|sprintf|gets|strcat)\b' <pkg>/patches/*.patch
```
