# E1205: 上游测试宏把测试与基准可执行文件装进 share/，纯库包必须在 package() 中裁剪

## 基本信息
- **严重度**: 1
- **类别**: ohos, cmake, packaging, install
- **作者**: 0B67

## 错误特征
```
Packaged [0-9]+ (files|'.*' files): .*Tests|Packaged .*\.1 file|share/.*/tests|share/.*/demos|commands\.json|软件级缺失
```

## 根因分析
上游为了“make install 后仍能跑测试”把测试夹具可执行文件一并安装：CMake 测试宏里普遍写成 `install(TARGETS <test> RUNTIME DESTINATION share/<pkg>/tests ...)`，基准/示例则走 demos 目录。于是 `cmake --install` 之后包里混进几十个可执行文件。在 OHOS 上这些文件既不能直接运行（未签名），又会让一个纯库包被判定为混装应用（触发软件级 commands.json 要求、R38 的包类型判定），同时显著增大包体。

## 推荐方案
**方法**: prune-installed-test-binaries

**说明**: 保留 OSMSCOUT_/BUILD_TESTS=ON 让上游套件在 build() 里真实执行（Conan 2 的 conan create 不调用主配方 test()，套件必须放 build()），但在 package() 的 cmake.install() 之后递归删除安装出来的测试与基准目录，只留库/头/数据

**修复命令**:
```
rm(self, "*", os.path.join(self.package_folder, "share", "<pkg>", "tests"), recursive=True) ; 同理 demos 目录
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 | grep "Packaged" ; find <pkg> -type f -perm -u+x
```
