# E1206: Audit release versus tag source scope before restoring a conditionally registered CMake suite

## 基本信息
- **严重度**: 2
- **类别**: detection, build-system, cmake
- **作者**: XM11

## 错误特征
```
WITH_UNIT_TESTS.*ON|if\(EXISTS.*test|100% tests passed.*out of 1
```

## 根因分析
CMake can enable tests but conditionally omit a development suite when its source directory is absent. A release archive and a same-version Git tag can therefore register different denominators while both configuration and CTest exit successfully; the tests-on option is not evidence of full upstream coverage. An immutable official tag URL can end in a commit SHA while delivering tar.gz bytes. Conan uses the downloaded filename to choose archive handling, so declare the real filename/container without changing the URL or SHA256.

## 推荐方案
**方法**: source-bound-conditional-suite-inventory

**说明**: Inventory the authoritative upstream tag before accepting the release archive's denominator. If an eligible development suite is silently absent, obtain a complete immutable official source archive, verify its tree/blob closure, keep the upstream CMake entry enabled, and require all registered programs and named development cases to pass. Guard the recipe against the missing directory; report consumer assertions separately. An immutable official tag URL can end in a commit SHA while delivering tar.gz bytes. Conan uses the downloaded filename to choose archive handling, so declare the real filename/container without changing the URL or SHA256.

**修复命令**:
```
cmake -S complete-official-source -B build -DWITH_UNIT_TESTS=ON; cmake --build build --parallel 2; ctest --test-dir build --verbose --output-on-failure
```

**验证**:
```
Bind the immutable official tag tree and archive hash, inspect the conditional add_subdirectory and named case list, then run verbose CTest and compare both executable and logical-case denominators.
```
