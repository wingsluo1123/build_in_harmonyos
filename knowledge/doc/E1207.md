# E1207: conan 子进程继承 stdin 为 socket 时，OHOS SDK clang 静默 exit 1（无任何输出），make 仅报 Error 1；conan create 时把 stdin 重定向 /dev/null 即恢复

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, ohos, portability, build-system
- **作者**: VG08

## 错误特征
```
make: \*\*\* \[Makefile:\d+: [^\]]+\] Error 1|Error 2 while executing|inaccessible or not found|env argument to ConanFile\.run\(\) should be a list
```

## 根因分析
OpenDesk/HarmonyOS 桌面沙箱中，agent 会话的 stdin 是 socket。conan 用 subprocess.Popen(command, shell=True, cwd=...) 派生子进程时未指定 stdin，子进程继承该 socket。此后由 make 再派生出的 /data/service/hnp/**/llvm/bin/clang（180 字节 #!/bin/sh 包装脚本 → clang-15）会静默 exit 1：不打印版本、不打印诊断，只在 make 输出里留下 "Error 1"。同一命令在 agent 交互 shell（zsh）中 rc=0；把 conan 进程的 stdin 重定向为 /dev/null 后，conan 内部 self.run → make → clang 全链路恢复 rc=0。已排除环境变量（把 conan 子进程的 84 项 env 全量复制到交互 shell 后 clang 仍正常）、rlimit（/proc/self/limits 全 unlimited）、LD_LIBRARY_PATH、shell 种类（bash/sh/zsh 皆失败）、env=None（不走 conanbuild 包装亦失败）、cwd 与 HNP 挂载本身（/data/service/hnp/bin/bash 在 conan 子进程中可正常执行）。

## 推荐方案
**方法**: redirect-stdin-from-dev-at-conan-invocation

**说明**: 本地手工复现/门禁用 conan create 时，把 conan 进程自身的 stdin 重定向为 /dev/null（`conan create … < /dev/null`），使整条 self.run→make→clang 链路不继承会话 socket 型 stdin；ohc-run.py conan-verify / finish 同理（`python3 scripts/ohc-run.py finish <pkg> <ver> built < /dev/null`）。不要改配方去绕。

**修复命令**:
```
conan create archives/<l>/<pkg>/<ver> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing < /dev/null
```

**验证**:
```
conan create <pkg> -pr:h=<ohos profile> -pr:b=<ohos profile> < /dev/null   # 恢复 rc=0；去掉 < /dev/null 复现 rc=1
```
