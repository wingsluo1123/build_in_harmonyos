# E1208: Automake 自定义 check 与 check-am 的重复构建依赖引发共享 Tpo 文件竞争

## 基本信息
- **严重度**: 2
- **类别**: threading, build-system, autotools, test-harness
- **作者**: unknown

## 错误特征
```
mv:.*\.Tpo.*No such file or directory|failed to rename.*\.Tpo
```

## 根因分析
上游自定义 check 目标与 Automake check-am 同时依赖同一个 check_PROGRAMS；平行 check 可能重复启动相同测试对象编译，争用相同 .deps/*.Tpo 临时依赖文件。正常库构建成功不证明测试驱动的依赖图安全。 Autoconf creates config.status scratch directories in two branches with owner-only masks. On HMDFS, changing file modes later or repairing PR transport cannot establish creation-time access. Replace both creation branches with exclusive mkdir under the recipe-private TMPDIR, use umask 022 at creation, restore configure timestamps, and prefix TMPDIR after Conan environment activation. Preserve cleanup and every original test.

## 推荐方案
**方法**: serialize-only-overlapping-check-target

**说明**: 保留全部上游测试与测试源；库构建保持有界并行，显式把重叠的 make check 调用限制为 -j1。长期上游修复应消除重复目标依赖，而不是删除测试。 Autoconf creates config.status scratch directories in two branches with owner-only masks. On HMDFS, changing file modes later or repairing PR transport cannot establish creation-time access. Replace both creation branches with exclusive mkdir under the recipe-private TMPDIR, use umask 022 at creation, restore configure timestamps, and prefix TMPDIR after Conan environment activation. Preserve cleanup and every original test.

**修复命令**:
```
autotools.make(target="check", args=["-j1"])
```

**验证**:
```
conan create . --build=<root-package>/*; 核对所有测试组真实 Passed N out of N 终态与消费者退出码
```
