# E1209: Automake 测试子目录漏用依赖 CFLAGS 时分离编译头闭包和 Libtool 搜索路径

## 基本信息
- **严重度**: 2
- **类别**: headers, autotools, linking, dependency
- **作者**: unknown

## 错误特征
```
fatal error:.*boost/cstdint.hpp.*file not found
```

## 根因分析
根库 AM_CXXFLAGS 消费 BOOST_CFLAGS/ICU_CFLAGS 不代表独立测试子目录也消费它们；测试包含私有头时会缺依赖头。恢复所有全局依赖 -L 又会绕过已有私有 .la-free 隔离，让 Libtool 重新读陈旧 .la，必须分离编译和链接闭包。 A checkout-pr message saying main conflict can actually originate from missing binary patch data and an unsupported patch fallback option. Identify the first low-level Git apply error; encode and hash-restore the unchanged consumer sample rather than rebasing or deleting its test. Autoconf creates config.status scratch directories in two branches with owner-only masks. On HMDFS, changing file modes later or repairing PR transport cannot establish creation-time access. Replace both creation branches with exclusive mkdir under the recipe-private TMPDIR, use umask 022 at creation, restore configure timestamps, and prefix TMPDIR after Conan environment activation. Preserve cleanup and every original test.

## 推荐方案
**方法**: compile-only-header-closure-preserving-scoped-linking

**说明**: 对比库与测试 Makefile.am，确认当前发布包有头；用 Conan Toolchain extra_cxxflags 仅添加依赖 include 目录，不恢复全局 -L；保持逐依赖 scoped LIBS 的私有 .la-free 路径。安装公共头 traits 是另一层契约，单独验证。 A checkout-pr message saying main conflict can actually originate from missing binary patch data and an unsupported patch fallback option. ```

