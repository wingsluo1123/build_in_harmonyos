# E1210: config.sub 旧式 Linux 改写是否可达必须按 case 首匹配判断

## 基本信息
- **严重度**: 2
- **类别**: compat, detection, autotools
- **作者**: PM11

## 错误特征
```
machine .*aarch64-unknown-linux.*not recognized|linux-gnu-ohos|config.sub .*hunk
```

## 根因分析
存在 -linux*) 改写分支并不证明 OHOS 必经它；若同一 case 的更早白名单已匹配 -linux-ohos* 并以 ;; 结束，后面的 Linux-to-GNU 分支不可达。按脚本年份固定要求第三个空 case 会误增补丁。 A large mostly sparse binary sample can be transported as compressed text while preserving its original bytes. Bound decompression to expected_size+1 and require end-of-stream, no unused/trailing input, exact size and SHA256 before writing the consumer fixture. Autoconf creates config.status scratch directories in two branches with owner-only masks. On HMDFS, changing file modes later or repairing PR transport cannot establish creation-time access. Replace both creation branches with exclusive mkdir under the recipe-private TMPDIR, use umask 022 at creation, restore configure timestamps, and prefix TMPDIR after Conan environment activation. Preserve cleanup and every original test.

## 推荐方案
**方法**: inspect-real-case-control-flow

**说明**: 先修 maybe_os 的 kernel-OS 切分，再定位实际 os 处理 case 的首匹配及终止符。较早 OS 白名单已截住 OHOS 时无需重复空分支；只有仍可进入 -linux*) 时才按 E344 加守卫，并验证 canonical 输出不是 linux-gnu-ohos。 A large mostly sparse binary sample can be transported as compressed text while preserving its original bytes. ```

