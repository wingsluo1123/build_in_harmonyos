# E1213: cu 单元测试框架大版本 ABI 变更导致测试套件注册期段错误

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, testing, abi
- **作者**: CE0C

## 错误特征
```
Segmentation fault|CU_register_suites|CU_SuiteInfo|CU_SetUpFunc|CU_TEST_INFO_NULL|Run Summary.*14
```

## 根因分析
上游测试源码按旧版 CUnit 的 4 字段 CU_SuiteInfo（pName,pInitFunc,pCleanupFunc,pTests）初始化；cunit/2.1-3 在其中间插入 pSetUpFunc/pTearDownFunc，编译期只有 -Wincompatible-pointer-types 警告（CU_TestInfo[] 赋给 CU_SetUpFunc），运行时 pTests 保持 NULL，CU_register_suites 解引用空指针 → 测试二进制刚启动即段错误（core dumped），无任何用例输出。

## 推荐方案
**方法**: 编译期检查 CU_SuiteInfo 结构体字段数：若目标库测试源码使用 4 字段初始化器，必须搭配 cunit/2.1-2（4 字段布局）；2.1-3 及以后需改测试源码为 6/5 字段或使用 CU_SUITE_INFO_NULL 显式补齐。判据：报错行 warning: incompatible pointer types initializing 'CU_SetUpFunc'。验证命令：make -C tests check 应输出 Run Summary tests 行而非 Segmentation fault。

**说明**: 按目标库测试源码的 CU_SuiteInfo 初始化字段数选择 cunit 版本（4 字段→cunit/2.1-2）

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
make -C tests check 2>&1 | tail -20   # 期望输出 "Run Summary ... tests 14 14 13 1"；异常时输出 "Segmentation fault (core dumped)"
```
