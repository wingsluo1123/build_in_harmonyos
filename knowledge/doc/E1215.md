# E1215: 宏生成的解析器/函数定义（如 CParseC 的 CPC_* 解析器宏）在 clang 下报 "function definition is not allowed here"，需把宏调用提升到文件作用域或用命名解析器替代无名语句表达式解析器

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, compiler, testing
- **作者**: C579, 789F

## 错误特征
```
function definition is not allowed here|nested function|CPC_DEFINE_PARSER|statement expression.*function definition
```

## 根因分析
头文件库（header-only）用宏在函数体内"就地"定义解析器/局部函数以简化测试代码：宏展开后形成函数体内嵌的函数定义（GNU C nested function，gcc 专有扩展）。clang 从 2.0 起从未实现嵌套函数，报 "function definition is not allowed here"。本条目与 E544 的区别：E544 是手写嵌套函数（捕获外层局部变量，需改为显式指针参数）；本条目是宏生成的定义（解析器宏如 CPC_STRING/CPC_ALT/CPC_TAKE_QUOTED 在测试函数体内展开），通常不捕获外层变量，只需把宏调用整体提升到文件作用域；另有无名解析器变体（CPC_STRING_ 依赖语句表达式 + 嵌套函数）clang 同样不支持，需改用文件作用域命名解析器。

## 推荐方案
**方法**: hoist-macro-generated-definitions-to-file-scope

**说明**: 把测试函数体内宏生成的解析器定义（CPC_STRING/CPC_LABEL/CPC_ALT/CPC_TAKE_QUOTED 等）整体提升到文件作用域（名称唯一），断言逻辑与调用点保持不变；无名语句表达式解析器（CPC_STRING_ 等）改写成等价的文件作用域命名解析器。生成 patches/ 最小补丁，仅动测试源码不改库头文件。

**修复命令**:
```
"将 CPC_* 定义宏调用从函数体移到文件作用域（保持参数原样）→ 无名解析器改为 CPC_STRING(name, lit) 等命名形式 → clang -std=c99 -O3 -Wextra -Wall -Werror 重编译 → 运行测试二进制确认断言全过"
```

**验证**:
```
编译测试源报 "function definition is not allowed here" 且展开链含 CPC_ 宏；修复后 clang -std=c99 -Wall -Wextra -Werror 编译测试并运行全部通过
```
