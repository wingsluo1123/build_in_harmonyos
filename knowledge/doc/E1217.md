# E1217: 依赖自带 pkg-config 文件破损（prefix 指向已删除的构建目录）且头文件嵌套在子目录时：必须让 PkgConfigDeps 生成的 .pc 优先，并把嵌套 include 目录一并注入

## 基本信息
- **严重度**: 1
- **类别**: platform, ohos, conan, dependency, pkg-config
- **作者**: A4D6

## 错误特征
```
json_tokener.h: No such file or directory|fatal error: json_tokener.h file not found|json-c.pc|Package json-c was not found|PKG_CHECK_MODULES
```

## 根因分析
制品包内自带 json-c.pc 的 prefix 指向导出时的构建目录（已被 conan 清掉），pkg-config 因此解析出并不存在的 -I/-L；而上游源码用扁平写法 include json_tokener.h，包内头文件实际位于 include/json-c/（自带 .pc 原本靠 Cflags 里的 -I<includedir>/json-c 兜住），.pc 一坏这层兜底也消失。结果 configure 的 PKG_CHECK_MODULES(JSON, json-c) 或编译期 include 直接失败，看起来像源码问题，实为依赖元数据问题。

## 推荐方案
**方法**: prefer-generator-generated-pc-and-add-nested-include-dirs

**说明**: (1) generate() 里显式调用 PkgConfigDeps(self).generate()，并把 self.generators_folder 放在 PKG_CONFIG_PATH 最前，压过依赖包内自带的破损 .pc；(2) CPPFLAGS 除依赖 includedirs 外，补齐 <include>/<pkg> 这类嵌套目录（json-c 即 include/json-c）；(3) 验证要覆盖编译+链接两阶段，不要只看 configure 是否通过；(4) 若依赖的 .pc 确实不可用，直接在 flags 侧注入绝对 -I/-L，不依赖 pkg-config 解析。

**修复命令**:
```
PKG_CONFIG_PATH=<generators_folder>:<dep_pkgconfig_dirs> conan create . -pr:h=ohos-aarch64
```

**验证**:
```
printf include-json_tokener.c | clang -x c - -I<pkg>/include -I<pkg>/include/json-c -c -o /dev/null && echo HEADERS_OK
```
