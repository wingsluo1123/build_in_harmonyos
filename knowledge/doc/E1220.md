# E1220: 测试夹具的平台能力缺口会伪装成 PTY 工具功能失败：退出码透传型断言（wait）的识别与最小修法，并如实申报 CMAKE_SYSTEM 守卫用例

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, testing, pty
- **作者**: 9C4A

## 错误特征
```
ls: /: Permission denied.*wait|ASSERT: sexpect w|child exit status.*fixture|ctest.*failed.*sandbox.*EACCES
```

## 根因分析
通过 PTY 驱动子进程并断言其退出码的测试（expect 类工具的 wait）会把夹具命令依赖的平台能力缺失误报为被测功能失败：sexpect 的 chdir-after-logfile 用 ls -l / 产生日志输出，而 OHOS 沙箱拒绝列目录（EACCES），ls 非零退出被 wait 原样透传，断言失败但被测行为（logfile 在 chdir 前打开）完全正确。

## 推荐方案
**方法**: platform-neutral-fixture-command-and-honest-guard-accounting

**说明**: 夹具命令换成平台中立的等价物（同 cwd 的 ls -l $tmpfile，语义仍覆盖被测点），不要放宽/注释断言；报表中把 CMAKE_SYSTEM 守卫用例单列并注明上游设计来源，注册数、运行数、通过数分别如实呈现。

**修复命令**:
```
patches/0004-tests-chdir-after-logfile.sh.patch（1 行替换）+ MANIFEST.yml 列出 2 个守卫用例与原因
```

**验证**:
```
设备实测：原样 ls -l / → sexpect w 断言失败（ls: /: Permission denied）；改为 ls -l $tmpfile 后 25/25 通过；ctest -N 显示 OHOS 注册 25 项，Linux 守卫 spawn-nowait/still-open-after-exit 不注册
```
