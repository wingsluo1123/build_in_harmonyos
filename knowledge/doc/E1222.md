# E1222: CMake install 去掉 RPATH 重写 ELF 致 .codesign 失效——制品包内二进制 exec 报 Operation not permitted(rc=126)

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, conan, packaging, elfsign
- **作者**: 82B8

## 错误特征
```
Operation not permitted.*bin/|rc=126|Set non-toolchain portion of runtime path|codesign.*install|exec.*Operation not permitted
```

## 根因分析
conan create 成功后，构建树内的二进制可正常执行，但制品包 bin/ 内同一二进制 exec 报 Operation not permitted（rc=126）。根因：CMake 的 install 阶段会为去掉构建期 RPATH 而重写 ELF（日志可见 Set non-toolchain portion of runtime path ... to ""），任何 ELF 重写都会使链接器写入的 .codesign 段失效，OHOS 内核拒绝加载签名失效的 ELF，故 package() 内 cmake.install() 之后必须重新自签名。

## 推荐方案
**方法**: post-install-script

**说明**: 在 conanfile.py 的 package() 中把签名作为最后一步：cmake.install()（以及任何 strip/patchelf/objcopy 改写）完成后，遍历 self.package_folder 对所有 ELF 执行 E077 四步——llvm-objcopy --remove-section .codesign → binary-sign-tool sign -inFile X -outFile X -selfSign 1 → os.chmod(mode | 0o111) 恢复执行位；只对 os == "OHOS" 生效，非 ELF 与符号链接跳过。

**修复命令**:
```
llvm-objcopy --remove-section .codesign $f && binary-sign-tool sign -inFile $f -outFile $f -selfSign 1 && chmod a+x $f
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 --build=missing && $(conan cache path <ref>)/bin/<binary> --version; echo rc=$?
```
