# E1223: 手写 Makefile 在规则命令里写死字面量 g++ 且用 CPPFLAGS += 追加 -march=k8：环境变量 CXX 无效，误用宿主 g++ 产出 x86 目标文件导致链接 libpopt.a 'skipping incompatible'；-march=k8 在 OHOS clang 直接报错

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, toolchain
- **作者**: 6CBC

## 错误特征
```
unsupported argument 'k8' to option '-march='|skipping incompatible .*-lpopt|cannot find -lpopt|g\+\+ -D.*-c -o .*\.o
```

## 根因分析
patman 1.2.2 的 Makefile 把 g++ 作为字面量写在链接与编译规则的命令行里（不是 CXX 变量），因此 Conan AutotoolsToolchain 注入的 CXX（以及 make CXX=... 命令行覆盖）完全不起作用；构建机上若恰有宿主 g++，会静默产出 x86 目标文件，随后链接交叉编译的 libpopt.a 报 skipping incompatible / cannot find -lpopt（构建机没有 g++ 时则直接 g++: not found）。同一 Makefile 以 'CPPFLAGS += -O3 ... -march=k8' 追加（会与环境变量合并，只能用命令行 CPPFLAGS= 整体覆盖或改文件），而 OHOS clang 实测报 unsupported argument 'k8' to option '-march='。

## 推荐方案
**方法**: makefile-literal-compiler-to-cxx-var-drop-march

**说明**: 补丁把规则里的 g++ 改成 $(CXX)、删除 -march=k8（以及按需修版本串），由 Conan Toolchain 经环境变量提供 CXX/CPPFLAGS/LDFLAGS；配方里用 self.run('make <target>', cwd=self.source_folder) 并绕开上游 install -s。

**修复命令**:
```
sed -i -e 's/^\tg++ /\t$(CXX) /' -e 's/ -march=k8//' Makefile  # 然后 refresh-patch --auto
```

**验证**:
```
grep -nE '^[[:space:]]+(g\+\+|gcc|cc) |-march=' Makefile; make -n CXX=/data/service/hnp/bin/clang++ | head -3  # 仍显示 g++ 即为字面量
```
