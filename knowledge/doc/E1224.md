# E1224: 上游回调缺 msg==NULL 守卫，「查询失败」变成崩溃而非断言失败，测试框架汇总行随之消失

## 基本信息
- **严重度**: 3
- **类别**: portability, network, testing, memory
- **作者**: 5CC4

## 错误特征
```
Signal 11 \(core dumped\)|Segmentation fault|rc=139|框架汇总行缺失|无法取得真实用例数|PASS, run|FAIL, run
```

## 根因分析
库在查询超时/无可用应答时按约定以 msg==NULL 调用注册回调（fossa.c:7068 重试耗尽、fossa.c:7084 num_answers==0），而该回调把 msg 直接交给 ns_dns_next_record()，后者无条件解引用 msg->answers（fossa.c:6510），于是进程收到 SIGSEGV。崩溃发生在打印汇总行之前，「PASS/FAIL, run N」根本不出现，任何按汇总行取数的逐用例度量都拿不到值

## 推荐方案
**方法**: sibling-guard-offline-ab-probe

**说明**: 先在同一文件里找带同签名的姊妹回调作对照（上游 dns_resolve_timeout_cb 自己就写了 if (msg == NULL)），据此确认缺失守卫是上游遗漏而非本平台特有语义；再补最小平台中立守卫（NULL 时置成本函数既有的「错误」分支值，让断言正常失败），并用离线死地址（udp://127.0.0.1:9，不需要外网）做 A/B 探针，让「崩溃」与「修复后干净失败」在同一台机器上可重复复现

**修复命令**:
```
clang -O0 -g -I<pkg>/include probe.c -L<pkg>/lib -lfossa -lpthread -lm -o probe && ./probe U udp://127.0.0.1:9; echo rc=$? && ./probe G udp://127.0.0.1:9; echo rc=$?
```

**验证**:
```
grep -n "req->callback(NULL" fossa.c && grep -n "rr = (prev == NULL ? msg->answers" fossa.c && grep -n "if (msg == NULL)" test/unit_test.c
```
