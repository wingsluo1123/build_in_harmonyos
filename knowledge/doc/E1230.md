# E1230: 守护进程类 CLI 的 pty 测试只能抓到单帧——script 随前台父进程退出即销毁 pty

## 基本信息
- **严重度**: 2
- **类别**: portability, posix, build-system, runtime, testing
- **作者**: 0BF2

## 错误特征
```
daemon run on a pty emits output \(bytes=12\)|uncaught target signal 11|expected an absolute directory name|script: cannot open
```

## 根因分析
被测程序 fork 出守护子进程后，前台父进程立即退出；pty 由 script(1) 分配并随 script 退出被销毁，守护子进程失去控制终端后写 pty 触发 SIGSEGV。因此加大 timeout 无效，实测 timeout 6/12/20 秒抓到完全相同的单帧（12 字节）

## 推荐方案
**方法**: 在同一 shell 内让守护进程保持前台并追加 sleep 撑住 pty：TERM=vt100 timeout 25 script $style "sh -c '<daemon> -F -T 1; sleep 6'" spin.ts > spin.out 2>spin.err；typescript 必须指向真实文件并与 stdout 求并集后统计（见 E547），再用 grep -F 统计完整帧数并断言帧数>=3 且多个不同字形出现，证明"持续旋转"而非"吐过一帧"

**说明**: 用 sh -c 包裹 + 尾部 sleep 保持 pty 存活，并按帧计数而非字节数断言

**修复命令**:
```
TERM=vt100 timeout 20 script -qc "sh -c '<daemon> -F -T 1; sleep 6'" /dev/null > spin.out 2>/dev/null
```

**验证**:
```
for t in 6 12 20; do timeout $t script -qc "<daemon> -F -T 1" /dev/null | wc -c; done   # 三次结果相同即命中
```
