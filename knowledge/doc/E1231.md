# E1231: 原生（build==host==OHOS）cmake 构建的 “System is unknown to cmake” 只是告警，不需要 CMAKE_SYSTEM_NAME 覆盖

## 基本信息
- **严重度**: 1
- **类别**: ohos, portability, build-system, cmake
- **作者**: 0B67

## 错误特征
```
System is unknown to cmake|Platform/HarmonyOS|create: +Platform/|CMAKE_SYSTEM_NAME.*HarmonyOS|uname -s.*HarmonyOS
```

## 根因分析
OHOS 上 `uname -s` 返回 HarmonyOS，cmake 3.x/4.x 的 CMakeDetermineSystem 与已知系统表（Linux/Darwin/Android/…）不匹配，于是回落成 CMAKE_SYSTEM_NAME=HarmonyOS 并尝试 include Platform/HarmonyOS.cmake；该文件不存在时只打印 “System is unknown to cmake, create: Platform/HarmonyOS to use this system”。在 **build==host==OHOS** 的原生构建下这仅是缺 Platform 模块的告警：CMakeDetermineSystem 之后仍按默认 Unix 平台变量完成探测，实测 configure/编译/运行全部正常，不需要覆盖 CMAKE_SYSTEM_NAME（P001：鸿蒙是原生编译环境，不是交叉编译）。E092 的处方 `-DCMAKE_SYSTEM_NAME=Linux` 面向的是 conan CMakeToolchain 把 os=OHOS 映射成 cmake 不认的系统名导致 conan_toolchain 整体不可用的**交叉**场景，此处不适用，强行覆盖反而会引入交叉编译语义。

## 推荐方案
**方法**: accept-warning-no-override

**说明**: 判定为原生构建（conan_toolchain 的 generic_system 块为空、build/host 同 profile）时按告警放过，不设 CMAKE_SYSTEM_NAME；仅在真正交叉编译（build != host）且 conan_toolchain 注入了 cmake 不认的系统名时，才按 E092 显式覆盖或改走 ohos.toolchain.cmake

**修复命令**:
```
grep -n "generic_system" conan_toolchain.cmake   # 空块 + uname -s=HarmonyOS => 告警可忽略
```

**验证**:
```
cmake -S . -B build && cmake --build build && ./build/<target>；对照 uname -s 与 conan_toolchain.cmake 的 generic_system 块是否为空
```
