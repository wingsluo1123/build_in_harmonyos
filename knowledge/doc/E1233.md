# E1233: qmake 生成的 include 头文件是转发桩，直接 copy 会被迫打包整个构建树

## 基本信息
- **严重度**: 3
- **类别**: packaging
- **作者**: QT5B

## 错误特征
```
fatal error: '?QtCharts/[A-Za-z]+\.h'? file not found|No such file or directory.*\.\./\.\./src/charts/
```

## 根因分析
qmake 的 syncqt 在 build 目录生成的 include/<Module>/*.h 并非真实头文件而是转发桩，内容形如 #include "../../src/charts/qchart.h"（私有头桩位于 include/<Module>/<ver>/<Module>/private/ 且相对层级更深）；桩用相对路径指回构建树 src/，因此手工 copy include/ 后必须连同 51MB 构建树 src/ 一起打包才能编译，一旦剔除 src/ 则 55 个公开桩与 162 个私有桩全部指向空路径

## 推荐方案
**方法**: make-install-root

**说明**: 不手工 copy，改用 Qt 自带安装流程落地 syncqt 处理后的真实头文件：package() 中执行 make install INSTALL_ROOT=<tmpdir>，再把 <tmpdir>/<qtbase 包前缀> 下的 lib/ include/ qml/ mkspecs/ plugins/ 搬迁到 package_folder，并按 E543 的 _BUILD_DIR_PATTERN 重写 .pc/.prl/cmake config 的 prefix 回指本包；真实头文件内部使用 <QtCharts/...> 尖括号引用，天然自包含

**修复命令**:
```
self.run(f"make install INSTALL_ROOT={tmpdir}", cwd=self.build_folder)
```

**验证**:
```
head -1 <build>/include/QtCharts/qchart.h; grep -rl '\.\./\.\./src' <pkg>/include/ | wc -l; du -sh <pkg>
```
