# E1235: cmake option() without a description string silently disables the feature it enables

## 基本信息
- **严重度**: 3
- **类别**: detection, build-system, cmake
- **作者**: wanderlust_0823
- **来源 PR**: 7929

## 错误特征
```
all the tests are disabled|:BOOL=OFF.*TESTS|0 tests.*out of 0|Test #.*not found without any test
```

## 根因分析
CMake requires option(<variable> "description" [<value>]); with only two arguments the second token is parsed as the description and the cache variable defaults to OFF. An upstream line like option(LIBASD_BUILD_TESTS ON) therefore leaves tests disabled by default even though the source reads as "ON": the tests subdirectory is never added, ctest registers 0 tests, and configure/build exit 0 — a silent false green. The false green is compounded when a message(WARNING) about missing Boost looks like the cause, while the option() call is the real gate.

## 推荐方案
**方法**: pass-explicit-dashd-and-fix-option-signature

**说明**: Two independent fixes: (1) when building, pass the flag explicitly (-DNAME=ON) so the behavior does not depend on the malformed option() call; (2) patch option(NAME ON) to option(NAME "Build ..." ON) with a real description so upstream defaults match the documented intent. Then assert the registered test count is nonzero before trusting ctest output.

**修复命令**:
```
grep -nE 'option\([A-Za-z_]+ (ON|OFF|TRUE|FALSE)\)' CMakeLists.txt src/*/CMakeLists.txt
```

**验证**:
```
cmake -S . -B build -DNAME=ON && grep "NAME:BOOL" build/CMakeCache.txt
```
