# E1237: Conan 依赖 cpp_info 的相对 libdir 会以 -Llib 形式进入 LDFLAGS 并让 libtool 硬失败：autotools 包必须在 generate() 里过滤相对搜索目录

## 基本信息
- **严重度**: 1
- **类别**: platform, ohos, autotools, linking, conan
- **作者**: CB89

## 错误特征
```
-Llib|libtool: error: cannot determine absolute directory name|cannot determine absolute directory name of
```

## 根因分析
autotools 包在 generate() 里按依赖 cpp_info 拼 LDFLAGS 时，若某个依赖（或环境里继承的 -L 设置）暴露相对 libdir（如 lib），-Llib 会被原样写进 LDFLAGS；libtool 的 ltmain.sh 对每个 -L 实参做绝对目录判定，遇到相对目录立即 error cannot determine absolute directory name 并中止链接，与包自身源码无关。实测 tlog 14：conan create 首轮 LDFLAGS 含 -Llib -Llib（依赖 cpp_info.libdirs 混入相对项），libtool 硬失败；在 generate() 中剔除相对 libdir 后 LDFLAGS 干净、make 与 make check 全绿。

## 推荐方案
**方法**: filter-relative-libdirs-before-injecting-flags

**说明**: (1) generate() 里收集依赖 libdirs/includedirs 时统一用 os.path.isabs() 过滤，相对项直接丢弃；(2) 同时剔除从 environment 继承的 CPPFLAGS/LDFLAGS 里的相对 -I/-L，或改为不继承；(3) 复现判据：grep 生成的 conanbuild.sh，若含 -L<非绝对路径> 必然失败；(4) 不要改 libtool 脚本或加 -Wl,-rpath 绕开——问题在注入侧，不是链接器侧。

**修复命令**:
```
# generate() 内：libdirs = [p for p in cpp_info.libdirs if os.path.isabs(p)]
```

**验证**:
```
grep -E '(^| )-L[^/]' conanbuild.sh   # 期望无输出；随后 conan create 通过
```
