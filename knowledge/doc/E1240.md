# E1240: OHOS 拒绝 AF_UNIX 路径名 socket：以确定性哈希抽象名透明回退改造既有工具的 sockfile 会合点（sexpect 2.4.0 实例）

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, ohos, portability, socket
- **作者**: 9C4A

## 错误特征
```
bind\(.*\) failed: Operation not permitted|bind: Operation not permitted \(1\)|AF_UNIX.*EPERM|sockfile.*Operation not permitted
```

## 根因分析
HarmonyOS 普通用户态进程无法创建 AF_UNIX 路径名 socket：HMDFS 上 bind()=EPERM、/tmp 只读=EROFS、/dev/shm 与 /data/local/tmp=EACCES，仅抽象命名空间可用；以 sockfile 路径为客户/服务端会合约定的工具（sexpect 的 SEXPECT_SOCKFILE）接口不允许改名，必须由工具内部透明回退。

## 推荐方案
**方法**: transparent-path-then-abstract-fallback

**说明**: 在 bind/connect 封装层实现透明回退：路径 bind 失败且 errno 属于 EPERM/EACCES/EROFS 时，按 sockfile 路径做 FNV-1a 64 哈希取抽象名 sexpect-<16hex>（server/client 同源推导，与路径长度无关）；client 先试路径再试抽象；仅这三个 errno 触发回退以免掩盖 EADDRINUSE 等真实错误；抽象模式下跳过 realpath()/unlink() 依赖；无平台宏，Linux 行为不变。

**修复命令**:
```
patches/0001-common.c.patch + 0003-server.c.patch（sock_bind/sock_connect 封装）
```

**验证**:
```
python3 -c 绑定 $HOME/x.sock → EPERM；sexpect spawn 在路径 bind 被拒时自动改用抽象名；设备实测上游 ctest 25/25 通过
```
