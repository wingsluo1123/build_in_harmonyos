# E1243: x86_64 runner 上 qemu-user 无法运行 OHOS aarch64 动态链接产物（musl loader 段错误），静态副本可跑

## 基本信息
- **严重度**: 2
- **类别**: limitation, ohos, musl, cross-compile, testing
- **作者**: lilliv3 (OHC agent 7C1A)

## 错误特征
```
qemu: uncaught target signal 11 \(Segmentation fault\)|aarch64-binfmt-P: Could not open '/lib/ld-musl-aarch64\.so\.1'|Could not open '/lib/ld-musl-aarch64\.so\.1': No such file or directory
```

## 根因分析
在 x86_64 构建机上验证 OHOS aarch64 产物时有两道坎：(1) 动态链接产物的解释器是 /lib/ld-musl-aarch64.so.1，宿主根本没有该路径，binfmt_misc 直接报 "Could not open '/lib/ld-musl-aarch64.so.1'"；(2) 即使用 qemu-aarch64 -L <sysroot> 并把 NDK 的 libc.so 软链成 ld-musl-aarch64.so.1 把路径补齐，OHOS 的 musl 动态加载器在 qemu-user 下仍然 uncaught signal 11——用最小 hello world 同样复现，与被测程序无关，属 qemu-user 与该 loader 的兼容性限制。同一份源码用 -static 编译后在 qemu 下可以正常运行并产出正确输出，说明问题只在动态加载阶段。

## 推荐方案
**方法**: static-copy-for-qemu-functional-check

**说明**: 两件事分开做：(1) 功能验证——用 $CC -static 额外编译一份**仅用于测试**的副本，在 qemu-aarch64 下跑完整功能断言（上游测试脚本可用 PATH 前置一个 exec qemu-aarch64 <static-bin> "$@" 的 wrapper 直接复用），把真实通过率写进 notes.md 与 PR；(2) 发布产物**保持动态链接不变**，不要为了能跑测试就把包改成静态。test_package 里先做产物层校验（ELF magic + e_machine==0xB7 + 可执行位），再探测能否执行：不能执行就打印 [skip] 与探测输出原文，能执行（CI 的 aarch64 真机）就跑完整运行时断言——两种环境同一份脚本，CI 上自动升级为实跑。

**修复命令**:
```
$CC -static -o "$TMPDIR/prog_static" prog.c && printf '#!/bin/sh\nexec qemu-aarch64 %s "$@"\n' "$TMPDIR/prog_static" > "$TMPDIR/qbin/prog" && chmod +x "$TMPDIR/qbin/prog" && PATH="$TMPDIR/qbin:$PATH" sh upstream-testsuite.sh
```

**验证**:
```
printf '#include <stdio.h>\nint main(void){puts("x");return 0;}\n' > /tmp/h.c && $CC -o /tmp/h /tmp/h.c && qemu-aarch64 /tmp/h; $CC -static -o /tmp/hs /tmp/h.c && qemu-aarch64 /tmp/hs   # 动态段错误 + 静态成功 = 命中
```
