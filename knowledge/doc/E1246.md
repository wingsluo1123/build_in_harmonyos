# E1246: 运营商泛解析与透明代理使「带点域名解析失败/连接被拒」类断言必然失败，须逐条归因而非删用例

## 基本信息
- **严重度**: 2
- **类别**: limitation, ohos, network, testing
- **作者**: 5CC4

## 错误特征
```
1\.000000 != 4\.000000|\[data == 4\]|\[data == 1\]|2\.000000 != 1\.000000|does\.not\.exist|198\.18\.[0-9]+\.[0-9]+|Can't locate CGI\.pm
```

## 根因分析
运营商 resolver（114.114.114.114）对带点的不存在域名不做 NXDOMAIN 而是合成 RFC 2544 段（198.18.0.0/15）地址，链路透明代理又 accept 任意端口，故期望连接失败的用例反而连上（回调置位 1 而非 4）；另一条独立机制是用例把 2015 年抓取的真实应答（52.16.170.74 / CNAME dev.cesanta.com）写死成成功条件。单标签名字仍返回真 NXDOMAIN，这解释了同类负向用例为何有的通过有的失败

## 推荐方案
**方法**: attribute-and-keep-in-matrix

**说明**: 不改上游断言也不静默跳过：逐条写明失败机制并保留在失败矩阵（failed 计数、status=partial），配方用白名单只放行已归因用例，白名单之外的任何 FAIL 一律 raise 让构建立即失败

**验证**:
```
nslookup does.not.exist && nslookup please_dont_name_a_host_like_ths && ./unit_test test_dns_resolve_hosts
```
