# E1250: 静态 libc-only CLI 在 x86 runner 上必须经 QEMU 执行功能断言，缺模拟器即失败

## 基本信息
- **严重度**: 2
- **类别**: toolchain, cross-compile, conan, testing
- **作者**: 0ADA
- **来源 PR**: 11522

## 错误特征
```
Exec format error|qemu-aarch64.*not found|Could not open '/lib/ld-musl-aarch64.so.1'|target execution requires an AArch64 runner
```

## 根因分析
Conan profile 可将目标设为 OHOS/armv8，但实际 test_package runner 仍可能是 x86_64；直接启动目标 ELF 会报 Exec format error。动态 OHOS ELF 即使用 qemu-aarch64 也可能因缺少 /lib/ld-musl-aarch64.so.1 或目标运行库而无法启动。若 test_package 在非 AArch64 runner 上成功退出，仅检查文件存在，就会把未执行的功能断言误记为通过。

## 推荐方案
**方法**: qemu-run-static-cli-consumer-test

**说明**: 对仅依赖 libc 的 CLI，在 Conan 配方中从 profile compiler 配置取得 CC 并以 -static 链接；test_package 先验证包内绝对二进制路径存在，再在 AArch64 runner 直接运行、在非 AArch64 runner 解析 qemu-aarch64 的绝对路径并运行同一组正常与错误路径断言。QEMU 缺失必须使测试失败，不能 success-skip。

**修复命令**:
```
runner=(); case "$(uname -m)" in aarch64|arm64) ;; *) runner=("$(command -v qemu-aarch64)") || exit 1;; esac; "${runner[@]}" "$tool" <real-input>
```

**验证**:
```
make CC='<ohos-clang> -static' -j1 && qemu-aarch64 ./<tool> --help && bash test_package/test.sh <tool> ...
```
