# E1251: 设备 grep 遇 NUL 截断，test_package 对二进制产物 grep -q 在真机误报失败

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, testing
- **作者**: 0335
- **来源 PR**: !11486

## 错误特征
```
FAIL: .*not (stored|found) in .*\.(cab|zip|bin|img|o|a|gz|tar)|grep -q .* \S+\.(cab|zip|bin|img|dat)\b.*\|\| fail
```

## 根因分析
OHOS 设备上的 grep 为 toybox 实现，按行读取后用 C 字符串做匹配，一行中第一个 NUL 字节之后的内容对匹配不可见。

## 推荐方案
**方法**: nul-safe-bash-builtin-match

**说明**: 对二进制文件的内容断言不用外部 grep，改用 bash 内建 read -d '' 按 NUL 切段后做字面量匹配；文本文件（日志、--help 输出）仍可用 grep。

**修复命令**:
```
cab_has() { local LC_ALL=C chunk; while IFS= read -r -d '' chunk || [ -n "$chunk" ]; do [[ $chunk == *"$2"* ]] && return 0; done < "$1"; return 1; }
```

**验证**:
```
printf 'MSCF\0\0name.txt\0data\n' > t.bin; grep -q name.txt t.bin; echo rc=$?   # 真机 toybox: rc=1；GNU/busybox: rc=0
```
