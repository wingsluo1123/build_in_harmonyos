# E1252: 上游 Makefile 硬编码 -march=native 在 Conan 交叉构建（OHOS armv8）下会导致目标 CPU/arch 错误，需绕过 Makefile 或移除该 flag

## 基本信息
- **严重度**: 2
- **类别**: ohos, make, cross-compile, conan, arch-flags
- **作者**: TOMMYDS
- **来源 PR**: 7911

## 错误特征
```
-march=native|march=native|invalid arch|unsupported architecture.*native|CMAKE_SYSTEM_PROCESSOR|target-cpu native
```

## 根因分析
许多 C 库的上游 Makefile 直接把 -march=native 写死在 CFLAGS 里（如 tommyds 3.0）。在本地原生编译时可行，但 Conan 交叉构建（os=OHOS, arch=armv8）或 CI worker 上，-march=native 会让编译器按构建主机/工具链默认 CPU 生成代码，与目标平台不一致，且上游 Makefile 也不读 Conan 传入的 CC/CFLAGS。更糟的是这类项目往往同时没有 configure / install 目标。

## 推荐方案
**方法**: bypass-upstream-makefile-direct-compile

**说明**: 不要在 build() 里调用上游 make（其 CFLAGS 含 -march=native 且不读 Conan 环境）。改为：从 self.conf.get("tools.build:compiler_executables") 取 cc/ar/ranlib（R33，禁止裸用 ${CC}），直接用工具链默认 arch flags 编译聚合源文件生成静态库（如 libtommy.a: cc -fPIC -O3 -c tommy.c; ar rcs; ranlib），再按需编译运行上游自检程序作为测试门。

**修复命令**:
```
build() 内 self.run(f'"{cc}" -fPIC -O3 -c "{src}" -o "{obj}"') 与 self.run(f'"{ar}" rcs "{lib}" "{obj}"')；package() 手动安装头文件与 .a
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
