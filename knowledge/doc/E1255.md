# E1255: Conan 配方解析 ctest 输出设硬闸时必须用 ctest -V，且统计行缺失要 fail-closed

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, testing
- **作者**: NGS1

## 错误特征
```
UPSTREAM CTEST: 0|0 assertions executed|assertions executed, 0 skipped
```

## 根因分析
ctest --output-on-failure 只在用例失败时回显被测进程 stdout。若配方用正则解析测试程序自己打印的统计行（如 OK. Tests: N）来设质量硬闸，用例通过时该行根本不出现在 ctest 输出里，解析结果为 0，导致构建被误判为回归失败。

## 推荐方案
**方法**: 需要采集被测进程输出时用 ctest -V（verbose，逐行加 <num>: 前缀）；解析优先匹配被测程序自报的统计行而不是数测试用例行，并在统计行缺失时直接 fail-closed，防止套件中途 abort 被静默放过。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
日志同时含 '100% tests passed' 与被测程序统计行；把阈值临时调高可验证闸门确实会 raise
```
