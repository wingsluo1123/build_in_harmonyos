# E1257: 三件套: (1) 配方 generate() 生成重定位版 dap-config 写入 generators 目录, 内

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, portability, autotools, dependency-graph
- **作者**: unknown

## 错误特征
```
Cannot find libdap|dap-config script could not be found|segfault.*request_dds|Segmentation fault.*Connect|Error relocating.*lld
```

## 根因分析
libdap 3.20.x conan 包的 bin/dap-config 有打包缺陷: prefix=/ 为空且 -I/-L 硬编码构建时 conan cache 路径, 消费者 (gadap 等 AC_CHECK_LIBDAP 系软件) 在自身构建环境里拿到的路径全部无效。另两个关联陷阱: (1) tar 保留旧时间戳而 patch 更新 configure 后, Makefile 的 am--refresh/config.status--recheck 会用设备 autoconf (2.72) 重生成 configure, 补丁行号漂移且重新引入 E011 mktemp 陷阱; (2) libdap 3.20.6 Connect 对非 http 名字走 _local 分支 (d_http=0), 任何 request_dds/request_das 调用都是空指针解引用 segfault。

## 推荐方案
**方法**: 三件套: (1) 配方 generate() 生成重定位版 dap-config 写入 generators 目录, 内容按 self.dependencies 逐包拼接 -I/-L (指向消费者本机 conan 包目录), 通过 Environment.define_path("DAP_CONFIG", ...) 注入 — AC_PATH_PROG 优先认 $DAP_CONFIG 绝对路径 (与 libdap 配方运行时重写 .pc 同源手法); (2) build() apply patches 后用 os.utime 把 aclocal.m4/configure/Makefile.in/config.h.in/src,test 的 Makefile.in/gadap-config.in 时间戳拉平到 configure.ac, 防止 autoconf 重生成; (3) 消费者测试程序必须用不可达 http URL (如 http://127.0.0.1:1/x.dds) 测错误路径 — libdap Error 异常跨库传播被 catch 后返回错误码, 本地文件路径必然 segfault (上游设计: 只支持 OPeNDAP 远程数据源)。
