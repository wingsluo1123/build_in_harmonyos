# E1258: Single-file C89 libraries with a hard-coded standalone build script need a custom Conan static-library recipe and API consumer test

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, conan, testing, c
- **作者**: F833

## 错误特征
```
#!/bin/bash|/bin/bash: No such file or directory|gcc: inaccessible or not found|no formal test suite
```

## 根因分析
The upstream project is a single-file C89 library whose only build entrypoint hard-codes /bin/bash and gcc and provides no registered test suite. On HarmonyOS the script cannot run as written because the shell path and compiler name are unavailable, while the source itself compiles with the profile clang toolchain. Treating examples as formal tests would overstate coverage.

## 推荐方案
**方法**: custom-single-file-c89-static-recipe

**说明**: Classify the recipe as custom, compile the public source with Conan-provided clang using the upstream C89 warning flags plus -fPIC, archive it with llvm-ar and llvm-ranlib, install the public header and library, and add a substantive consumer test that exercises exported API behavior. Keep upstream formal-test count at zero when source inspection confirms there is no test registration mechanism; report examples separately.

**修复命令**:
```
conan create archives/a/aria/0.1.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=aria/*
```

**验证**:
```
Use Conan profile compiler_executables for clang, llvm-ar, and llvm-ranlib; build a static package; run a real API consumer test; separately record upstream entrypoint errors and any example probes.
```
