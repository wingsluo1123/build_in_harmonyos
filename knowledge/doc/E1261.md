# E1261: ECM 6.26 KDEInstallDirs6 在 configure 期运行 qtpaths 失败（exit 127）：沙箱 LD_LIBRARY_PATH 中不兼容 libc++_shared.so 遮蔽兼容版本，需注入 /system/lib64

## 基本信息
- **严重度**: 2
- **类别**: cmake, toolchain, conan
- **作者**: F19E
- **来源 PR**: 8505

## 错误特征
```
Qt6 qtpaths call failed: 127|Error loading shared library libc\+\+_shared\.so.*qtpaths|ecm_query_qt.*QT_INSTALL_PREFIX|KDEInstallDirs6\.cmake.*\(ecm_query_qt\)|Error relocating .*qtpaths.*_ZdlPv
```

## 根因分析
ECM 6.26 的 KDEInstallDirs6.cmake 在 configure 阶段通过 execute_process 运行 qtbase 包导出的 qtpaths 二进制（ecm_query_qt -> QT_INSTALL_PREFIX）。qtpaths 是 musl OHOS ELF，动态链接 libc++_shared.so；沙箱环境默认 LD_LIBRARY_PATH 中 /data/storage/el1/bundle/libs/arm64 下存在一个不兼容的 libc++_shared.so，遮蔽了 /system/lib64 下的兼容版本，导致动态加载器加载失败（"Error loading shared library libc++_shared.so" + 大量 "Error relocating" 符号缺失），qtpaths exit 127，cmake configure 直接 FATAL_ERROR。

## 推荐方案
**方法**: 在 conanfile 的构建/测试环境里向 LD_LIBRARY_PATH 前置注入兼容库目录：① /system/lib64（兼容 libc++_shared.so 所在）；② ohos-sdk 的 native/llvm/lib（glob /data/service/hnp/ohos-sdk.org/ohos-sdk_*/ohos/native/llvm/lib）。用 conan Environment().prepend_path 注入；configure（cmake.configure）、ctest 测试运行都要用同一环境（.vars(self).apply() 包住）；test_package 的 conanfile 也必须注入同样环境（消费者 configure 会 include KDEInstallDirs）。

**说明**: LD_LIBRARY_PATH 前置 /system/lib64 + SDK llvm lib，让 qtpaths 解析到兼容 libc++

**修复命令**:
```
export LD_LIBRARY_PATH=/system/lib64:$LD_LIBRARY_PATH
```

**验证**:
```
conan create archives/k/kpackage/6.26.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=default --build=missing && echo OK
```
