# E1262: HongMeng 内核版本串非标准（a.b.c 解析失败 + /proc/version 不可读）导致版本解析类测试环境性失败

## 基本信息
- **严重度**: 3
- **类别**: ohos, kernel, version, testing, procfs
- **作者**: EFE9

## 错误特征
```
FAIL: library/tests/test_version|procps_linux_version.*rc=1|cat /proc/sys/kernel/osrelease -> HongMeng Kernel [0-9.]+|/proc/version 不可读
```

## 根因分析
OHOS 的 /proc/sys/kernel/osrelease 返回非标准串 "HongMeng Kernel 1.12.0"（非数字开头的 a.b.c 格式），且 /proc/version 不可读（cat 返回 Permission denied）；依赖 sscanf("%d.%d.%d") 类格式从这两个文件解析 Linux 版本号的库（如 procps-ng libproc2 的 procps_linux_version()）解析失败返回 0，上游 test 断言 rc==0 && ver>0 不满足。procps 4.0.7 实测：8 个测试程序 7 PASS / 1 FAIL，唯一 FAIL 即 test_version 的 procps_linux_version 子用例（同程序 LINUX_VERSION macro 编译期子用例 PASS，证明仅运行时 /proc 解析路径受影响）

## 推荐方案
**方法**: treat-as-environment-limitation

**说明**: 定性为环境性失败而非适配缺陷：禁止修改上游断言（R9/G 门禁语义），不 patch 测试期望值。处理方式：1) conanfile.py build() 中 make check 用 try/except 包裹，捕获后 output.info 记录已知环境性失败继续构建；2) notes.md 如实记录统计（7 PASS/1 FAIL）与定性证据（osrelease 实际串 + /proc/version 不可读 + macro 子用例 PASS 对照）；3) 沉淀知识草稿；4) 若软件功能强依赖运行时版本号，优先走编译期 LINUX_VERSION 宏等已知常量路径而非运行时解析

**修复命令**:
```
cat /proc/sys/kernel/osrelease; make check 2>&1 | tee check.log; grep -E "^(PASS|FAIL)" check.log | sort | uniq -c
```

**验证**:
```
cat /proc/sys/kernel/osrelease; cat /proc/version; make check 后 grep FAIL
```
