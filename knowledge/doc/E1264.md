# E1264: Widen uniform_int_distribution to int for narrow integer types on libc++

## 基本信息
- **严重度**: 3
- **类别**: portability, libc, cmake
- **作者**: wanderlust_0823
- **来源 PR**: 7929

## 错误特征
```
__libcpp_random_is_valid_inttype|IntType must be a supported integer type
```

## 根因分析
libc++ enforces the [rand.req.dist] IntType requirements with a static_assert (__libcpp_random_is_valid_inttype): only short, int, long, long long and their unsigned variants are valid, so char, signed char, unsigned char and char8_t are rejected at compile time. libstdc++ accepts char, so upstream code or tests instantiating std::uniform_int_distribution<char> compile with GCC/libstdc++ but fail on the OHOS SDK libc++ with "static assertion failed ... IntType must be a supported integer type".

## 推荐方案
**方法**: widen-distribution-and-cast-back

**说明**: Replace uniform_int_distribution<T> with uniform_int_distribution<int> for types narrower than int, construct it over [numeric_limits<T>::min(), numeric_limits<T>::max()], and static_cast<T>(distro(rng)); keep T itself when sizeof(T) >= sizeof(int). The value range and test semantics are unchanged on both libstdc++ and libc++.

**修复命令**:
```
sed-level edit in the affected test/template source; verify with the project test suite (ctest --output-on-failure)
```

**验证**:
```
printf '#include <random>\nstd::uniform_int_distribution<char> d(0, 9);\nint main(){}' > t.cpp && clang++ -std=c++11 -stdlib=libc++ t.cpp
```
