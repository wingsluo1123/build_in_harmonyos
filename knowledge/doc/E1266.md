# E1266: macOS Objective-C “now playing” CLI 的可移植落点（__APPLE__ 双路径 + 诚实空结果）

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, portability, cli-contract, multimedia
- **作者**: E6ED

## 错误特征
```
Foundation/Foundation.h.*file not found|MediaRemote.framework|OH_AVSessionManager|getAllSessionDescriptors
```

## 根因分析
上游为 macOS 专属 Objective-C(++) CLI（Foundation/AppKit + 私有 MediaRemote），OpenHarmony native SDK 无 Objective-C 运行时与 Foundation，clang 首个阻塞即 Foundation/Foundation.h file not found；同时 native AVSessionKit（libohavsession.so）只导出 provider 侧 API，没有系统级查询控制器（OH_AVSessionManager / getAllSessionDescriptors / metadata getter 仅存在于 ETS/JS），故 native 侧无法复现“查询系统正在播放”的能力。

## 推荐方案
**方法**: guard-macos-with-apple-macro-and-map-to-provider-honest-empty

**说明**: 用补丁把上游 Objective-C 源文件整体包进 #if defined(__APPLE__)（原版逐字保留），非 Apple 分支提供纯 C++ 实现复刻上游 CLI 契约（子命令/字段键/每行一值/--json/退出码），并把可用能力映射到目标平台真正具备的原生 API；平台缺能力时返回上游“无数据”语义或如实失败，绝不伪造成功。

**修复命令**:
```
wrap src/*.mm in #if defined(__APPLE__) + portable C++ branch reproducing the CLI contract over the native AVSession provider API; return upstream's empty result when no native query exists
```

**验证**:
```
conan create archives/n/nowplaying-cli/2.1.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
