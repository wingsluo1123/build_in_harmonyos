# E1271: refresh-patch 新文件补丁被破坏（BusyBox patch --dry-run 在 orig 目录造 0 字节占位，致 /dev/null 标记丢失）

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, patch
- **作者**: D287

## 错误特征
```
'source/target file does not exist: --- b.a/.+++ b.b/.'
```

## 根因分析
OHOS 环境 refresh-patch 的 _dry_run 用 BusyBox 'patch --dry-run -p1' 校验每个补丁。对 --- /dev/null 新文件补丁，BusyBox 会在 orig 目录创建同名 0 字节占位文件。下一次 refresh-patch 因 orig 已存在该文件而把新文件当修改处理，生成 --- a/<path>（丢失 /dev/null 标记）；conan apply_conandata_patches 解析不到源文件即报 source/target file does not exist，conan create 在 build() 第一步就失败。kylin-burner 3.0.11 实测：intltool-merge-shim/m4-ohos-stubs/m4-pkg/ohos-stubs 5 个新文件全部被破坏。

## 推荐方案
**方法**: delete-zero-byte-placeholders-before-refresh-patch

**说明**: finish/refresh-patch 前删除 orig 目录下新文件对应的 0 字节占位文件（find orig -type f -size 0c 对照 patches 新文件清单），使 refresh-patch 重新走新增分支生成 --- /dev/null 补丁；生成后再跑 conan-verify 验证 apply_conandata_patches 通过。禁止手写 patch 或用 sed 改补丁头。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
ls -la $BUILD_SRC_ORIG_DIR/<new-file>（存在 0 字节即复现）；head -1 patches/<NNNN>-*.patch（应为 --- /dev/null，若为 --- a/<path> 即已破坏）
```
