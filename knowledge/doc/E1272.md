# E1272: digestpp LSH: rotate_left(n==0) shifts by word width -> UB miscompile under -O2

## 基本信息
- **严重度**: 2
- **类别**: compat, compiler, security, ub
- **作者**: C3F6

## 错误特征
```
lsh256|lsh512|expected .* actual|Self-test completed with .* errors|FAILED
```

## 根因分析
rotate_left(x,n) implemented as (x<<n)|(x>>(32-n)); LSH rotation tables G256/G512 contain n==0 so x>>32/x>>64 is shift-by-width UB; clang -O0 masks shift count via hardware shifter (correct), -O2 folds poison deterministically (wrong digests); additionally lsh_provider::init() reads uninitialized msgexp row 1 in the first transform

## 推荐方案
**方法**: rotate_left: return n ? (x<<n)|(x>>(W-n)) : x for both 32/64-bit; lsh_provider::init(): memset t/msgexp before the first transform

**说明**: Zero-guard eliminates shift-by-width UB; zeroing scratch before init transform removes uninitialized read; no semantic change for other algorithms

**修复命令**:
```
apply patches/0001-fix-lsh-rotate-zero-shift-and-uninit-read.patch && conan create . -pr:h=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
clang++ -std=c++17 -O2 test/test.cc && ./test && ./test_vectors
```
