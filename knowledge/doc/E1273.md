# E1273: cek 0.2.0 在 OHOS 上的 Go linker 工作区、测试 ELF 签名与网络测试分层

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, ohos, linking, go, testing
- **作者**: C0DE
- **来源 PR**: 9322

## 错误特征
```
link: mapping output file failed: permission denied|go test.*(fork/exec|exec).*(permission denied|operation not permitted|exec format error)|binary-sign-tool.*(sign|selfSign)|index\.docker\.io/v2.*(timeout|timed out)|gcr\.io/v2.*(timeout|timed out)
```

## 根因分析
纯 Go CLI 在 HarmonyOS 上同时受到三个不同阶段的约束：Go linker 在 HMDFS 工作区 mmap 链接输出可能返回 permission denied；Go test 生成的包级测试 ELF 和 Go SDK 内部工具在首次执行前没有 OHOS 签名时会被系统拒绝；上游 OCI registry 测试依赖 index.docker.io、gcr.io 或 daemon，网络不可达时会失败。只把最终 CLI 放到可执行目录、只 chmod、或把网络失败隐藏成 smoke 通过，都不能证明包已正确适配。

## 推荐方案
**方法**: ohos-go-workdir-sign-and-test-tiering

**说明**: 先固定 OHOS 目标为 GOOS=linux、GOARCH=arm64、CGO_ENABLED=0、GOTOOLCHAIN=local，缺失时下载并校验固定版本的官方 Go SDK；把 GOTMPDIR、GOCACHE、GOMODCACHE、测试 wrapper、签名临时文件和最终 link output 统一迁移到可执行的 OHOS 工作区；对 Go SDK ELF、生成的测试 ELF 和最终 CLI 在首次执行前使用 binary-sign-tool 自签；go test 在 OHOS 上按 package、-p 1、-vet=off 执行，并通过 /bin/sh 启动签名 wrapper；将不依赖外部服务的测试作为默认 smoke 门禁，完整 go list/go test 保留为显式 full 模式并记录真实计数；最后用 Conan test_package 直接消费安装后的 bin/cek。

**修复命令**:
```
export GOOS=linux GOARCH=arm64 CGO_ENABLED=0 GOTOOLCHAIN=local; export OHOS_GO_WORKDIR=/data/storage/el2/base/haps/entry/files/cek-conan-go; export OHOS_GO_EXEC_WORKDIR=/data/storage/el2/base/cache/cek-conan-go; bootstrap and sign Go 1.25.7 when absent; go list ./...; run smoke with go test -p 1 -vet=off -exec '/bin/sh <signed-wrapper>'; sign linked output; run CEK_UPSTREAM_TEST_MODE=full only when index.docker.io and gcr.io are reachable; run Conan test_package.
```

**验证**:
```
CI_PACKAGES="archives/c/cek/0.2.0" zsh ci/conan/build_and_test.sh；复核 reports/test-report.md、package/res/upstream_test_result.json 和 test_package/test.sh 的计数，并确认 Shadow CI #43472 的 L0/L1 通过。
```
