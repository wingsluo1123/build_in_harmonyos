# E1275: PARI gp nflist 同进程状态污染：前序 nflist([d,i],t) 批量查询改变后续 A5 精确计数断言结果，须按断言族分进程

## 基本信息
- **严重度**: 2
- **类别**: testing, determinism, gp-script, pari
- **作者**: B5C8

## 错误特征
```
a5_r2_0_full_table FAIL|#A5F==[0-9]+|nflist: domain error
```

## 根因分析
nflist 在 gp 进程内维护已加载表的内部状态。同一 gp 进程里先跑 650 条 nflist([deg,idx],t) 再执行 #nflist("A5",[1,524286^2],0)，返回值不再等于表内数据行数（实测由 15184 变小），断言假 FAIL。判据：同一脚本对上游原始解包目录与 conan 打包产物表现完全一致（同样 2 项 FAIL），故非打包差异而是解释器进程内状态。分进程后 QT 650/650、A5 语义 8/8 全通过。

## 推荐方案
**方法**: 测试驱动按断言族拆分进程：每个 family 单独生成 GP 脚本并各起一次 gp，由外部驱动合并逐用例结果并与期望清单比对（缺失即 FAIL）。生成器保留 --family 开关便于单独复现；不要把不同数据族塞进同一 gp 进程。

**说明**: 不同断言族分进程跑 gp，避免解释器内表状态互相污染导致精确计数断言假失败

**修复命令**:
```
for fam in qt a5; do python3 upstream-gp-sweep-generator.py <root> --family $fam --out sweep-$fam.gp; gp -q -f sweep-$fam.gp; done
```

**验证**:
```
python3 run-upstream-gp-sweep.py <pkg>/res/pari --gp <gp> --lib <pari/lib> --lib <gmp/lib> --out-cases upstream-test-cases.txt  # pari-nflistdata/20220729 打包产物实测 TOTAL=685 PASS=665 FAIL=0 SKIP=20 rc=0
```
