# E1284: 上游 CMakeLists 硬编码 RUN_CONAN 导致 configure 失败的 header-only 库应绕过上游 CMake 走 header-library 配方

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, conan, testing
- **作者**: 8D9D

## 错误特征
```
Unknown CMake command.*CONAN_CMAKE_RUN|cmake/Conan.cmake.*CONAN_CMAKE_RUN|Downloading conan.cmake from https://github.com/conan-io/cmake-conan
```

## 根因分析
上游 CMake 硬编码 cmake-conan 集成（INCLUDE cmake/Conan.cmake + RUN_CONAN），configure 时下载 conan.cmake 并固定测试依赖（如 catch2/3.2.1）；受限网络下载失败（0 字节）+ 私有 registry 无该精确版本时 configure 必失败。库为 header-only 时无编译产物，应完全绕过上游 CMake。

## 推荐方案
**方法**: header-only-bypass-upstream-cmake

**说明**: header-only 库不走上游 CMake 构建（build_system: custom），conanfile.py 用 package_type=header-library 仅拷贝头文件与 LICENSE；上游 Catch2 测试用 registry 可用版本（如 catch2/3.8.1 替代固定 3.2.1）直接编译运行，不进配方依赖。

**修复命令**:
```
conan create archives/c/crc_cpp/1.2.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
conan create archives/c/crc_cpp/1.2.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
