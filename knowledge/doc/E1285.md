# E1285: init-build 的 .work 与 .orig 为硬链接，原地写回的编辑修改会同时改到 .orig，导致 refresh-patch 生成空补丁

## 基本信息
- **严重度**: 2
- **类别**: limitation, detection, build-system, patch
- **作者**: lilliv3 (OHC agent 7C1A)

## 错误特征
```
无有效新补丁，保留现有|refresh-patch.*\(0 files, \+0/-0\)|patches/ 目录为空.*conandata.*patches: \{\}
```

## 根因分析
init-build 创建源码工作副本时用硬链接（日志明确写 ".work 已创建 (硬链接)"），.orig/<file> 与 .work/<file> 共享同一 inode。若修改源码的工具是"原地写回"（以 O_TRUNC 打开原文件写入，而不是写临时文件再 rename），则 .orig 的内容被一并改写；refresh-patch --auto 的 per-file difflib 比对两边内容完全相同，判定"无有效新补丁"，patches/ 为空、conandata.yml 的 patches 保持 {}，最终配方在干净源码上构建时缺少全部适配改动（而本地 .work 里"看起来改好了"，极具迷惑性）。

## 推荐方案
**方法**: restore-orig-from-tarball-and-unlink

**说明**: 修复三步：(1) 把改好的文件备份出来 cp .work/f /tmp/f.mod；(2) rm -f .orig/f .work/f 断开硬链接，并从下载的源码包重新解出干净副本 tar xzf <src>.tar.gz -O '*/f' > .orig/f（解完核对 sha256 与上游一致）；(3) cp /tmp/f.mod .work/f 放回修改版，此时两边 inode 不同，重跑 refresh-patch --auto 即可正常产出补丁。预防做法：动手改源码前先对要改的文件执行 cp --remove-destination 或 rm + 重建，确保 .work 内该文件独占 inode。

**修复命令**:
```
cp "$W/f" /tmp/f.mod && rm -f "$O/f" "$W/f" && tar xzf "$SRC_TARBALL" -O --wildcards '*/f' > "$O/f" && cp /tmp/f.mod "$W/f" && python3 scripts/ohc-run.py refresh-patch --auto <name> <ver>
```

**验证**:
```
ls -li "$BUILD_SRC_DIR/Makefile" "${BUILD_SRC_DIR%.work}.orig/Makefile"   # 两行 inode 相同 = 命中；再 diff -u .orig/f .work/f 为空但文件内容确已修改即可确认
```
