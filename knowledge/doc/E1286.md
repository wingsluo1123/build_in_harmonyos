# E1286: C++98 时代测试套件故意从析构函数抛异常：C++11 起析构隐式 noexcept，默认标准下 libc++abi 运行期 terminate（非库缺陷）

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, testing
- **作者**: 7707

## 错误特征
```
libc\+\+abi: terminating due to uncaught exception.*destructor|non-throwing exception specification but can still throw|Signal 6.*after partial suite progress
```

## 根因分析
C++11 将析构函数隐式异常规范改为 noexcept，C++98 下合法的"析构中 throw 并被框架捕获"语义（如 TUT 的 warn 结果类型）在 C++11+ 编译下离开析构即 std::terminate。套件前段逐组正常通过、特定组中途 abort；clang -Wexceptions 警告（'~T' has a non-throwing exception specification but can still throw）在编译期精确指向测试本地的抛出析构。库本体头文件不受影响（消费者不会故意从析构抛异常）。

## 推荐方案
**方法**: era-matched-std-for-upstream-suite

**说明**: 上游套件以时代匹配标准（-std=gnu++98）重编译运行，不改任何测试代码；交付头文件不限定标准，test_package 在目标默认标准下验证现代消费者路径，两条证据在 PR 中分开陈述（适配后统计只计 test_package，上游通过率单列）。

**修复命令**:
```
for f in selftest/*.cpp; do /data/service/hnp/bin/clang++ -std=gnu++98 -ftemplate-depth-100 -I"$src" -Wall -O2 -c "$f" -o "${f%.cpp}".o; done && clang++ *.o -o selftest && ./selftest
```

**验证**:
```
同套件同工具链对照：默认标准跑崩于 teardown 组（Signal 6）；-std=gnu++98 重编译后 ok:63 全绿 RC=0
```
