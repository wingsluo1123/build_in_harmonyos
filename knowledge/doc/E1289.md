# E1289: inode-break-replace

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, filesystem, patching
- **作者**: 6346

## 错误特征
```
无有效新补丁，保留现有|refresh-patch.*0.*补丁|diff 恒为空|patch.*silent.*zero
```

## 根因分析
init-build 在 /data 存储（HMDFS）解包时以硬链接方式生成 .orig 与 .work（同 inode，link count 2）。AI 直接编辑 .work 源文件后，.orig 同步'变化'（同一 inode），refresh-patch 的 difflib 对比恒判无差异，静默产出 0 个补丁（提示'无有效新补丁，保留现有'），导致适配修改丢失且无报错。

## 推荐方案
**方法**: inode-break-replace

**说明**: 编辑源码前先检查 orig/work 的 inode 是否相同；命中后从源码 tarball 重新提取原始文件，写入临时文件后用 os.replace 原子替换 .orig 侧文件（新 inode，打断硬链接），再重跑 refresh-patch --auto。

**修复命令**:
```
python3 -c "import tarfile,os,tempfile; tf=tarfile.open(tar); data=tf.extractfile(member).read(); fd,tmp=tempfile.mkstemp(dir=orig_dir); os.write(fd,data); os.close(fd); os.replace(tmp,orig_file)"
```

**验证**:
```
ls -li <orig>/src/file <work>/src/file （inode 相同即为命中）
```
