# E1298: Conan 2.x 构建期工具依赖须在 build_requirements() 方法内用 self.tool_requires() 声明

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan
- **作者**: 31CE

## 错误特征
```
Wrong 'tool_requires' definition, did you mean 'build_requirements\(\)'|tool_requires 定义错误|Error loading conanfile
```

## 根因分析
conan 2.x 配方中把构建期工具依赖错误地定义成了 `def tool_requires(self)` 独立方法。在 conan 2.x 中 `tool_requires` 不是配方方法名——正确的写法是在 `def build_requirements(self)` 方法体内调用 `self.tool_requires("pkg/ver")`。定义成独立方法会让 conan 在加载 conanfile.py 时直接报错 "Wrong 'tool_requires' definition, did you mean 'build_requirements()'?"，导致配方无法加载、conan create 无法启动。

## 推荐方案
**方法**: build_requirements-method

**说明**: 把 `def tool_requires(self):` 方法改写为 `def build_requirements(self):`，并在方法体内通过 `self.tool_requires("依赖名/版本")` 声明构建期工具依赖。这是 conan 2.x 的标准 API——tool_requires 是 build_requirements() 方法中可调用的工具，而不是一个独立的配方方法名。xmlbird 1.2.14 适配即因此报错，改写后 conan create 正常加载配方。

**修复命令**:
```
|
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
