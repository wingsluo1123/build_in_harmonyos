# E1304: GNU make shell for 循环目标掩盖子目录 make 失败，上游多目录构建静默丢产物

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools
- **作者**: AtomCode (glm-5.3) <noreply@atomgit.com>

## 错误特征
```
for d in .*\; do \(cd|make\[1\].*No such file or directory|cp: cannot stat.*(marpa|\.c|\.h|\.pdf).*No such file|Cannot open input file.*(copier|\.list)|make.*returned 0 but.*(missing|not generated)
```

## 根因分析
上游顶层 Makefile 用 shell for 循环递归构建多个子目录（如 libmarpa work/Makefile 的 sources 目标 `for d in ac ami dev tavl public; do (cd $$d; $(MAKE)); done`），子 shell 中 make 的退出码不传播：for 循环退出码只取决于最后一个目录的子 make。前面子目录因构建机工具缺失（cweave/pdftex/texinfo 等）失败并跳过生成 CWEB 派生产物时，顶层 make 仍返回 0，错误推迟到 copier 缺文件或消费者编译缺头文件才暴露，甚至被管道（`make ... | tail`）再次吞掉。

## 推荐方案
**方法**: per-subdir-make-target

**说明**: 不调用顶层 for 循环目标，改为按子目录逐个调用其真正的生成目标（sources/all），使每个子 make 失败立即显式暴露；若子目录默认 all 拖入不可用的文档规则（pdf/texi），先甄别并调用纯代码生成目标或先创建占位产物。

**修复命令**:
```
for subdir, target in (("dev","sources"),("ami","sources"),("tavl","all"),("public","all"),("ac","all")): self._run("(cd %s && make %s)" % (subdir,target), cwd=work_dir)
```

**验证**:
```
cd work && make sources; echo $? — 子目录 dev/ami 报 "cweave: No such file or directory"（Error 127）但整体仍返回 0 即命中；改为 (cd dev && make sources) 单独执行立即非零。
```
