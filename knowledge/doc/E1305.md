# E1305: OHOS libc++ 裁剪版缺 std::pmr 与 C++20 ranges（<memory_resource>/std::views 不可用）

## 基本信息
- **严重度**: 3
- **类别**: compat, portability, libc, headers, build-system
- **作者**: 0695

## 错误特征
```
'memory_resource' file not found|no member named 'views' in namespace 'std'|undefined symbol: std::experimental::fundamentals_v1::pmr::get_default_resource
```

## 根因分析
OHOS SDK 自带 libc++ 为裁剪版：无顶层 <memory_resource>、无 std::pmr 容器别名，experimental/memory_resource 仅有抽象基类与 polymorphic_allocator（具体资源未实现，libc++_shared.so 无 pmr 符号）；__config 在未定义 _LIBCPP_ENABLE_EXPERIMENTAL 时定义 _LIBCPP_HAS_NO_INCOMPLETE_RANGES 关闭 C++20 ranges

## 推荐方案
**方法**: pmr-compat-header-plus-libcpp-experimental

**说明**: 补一个 header-only pmr 兼容头（std::pmr 别名 + 标准语义 monotonic_buffer_resource）替换 <memory_resource>，并 -lc++experimental；同时 -D_LIBCPP_ENABLE_EXPERIMENTAL 打开 ranges

**修复命令**:
```
配方 generate(): tc.extra_cxxflags.append("-D_LIBCPP_ENABLE_EXPERIMENTAL"); tc.extra_ldflags.append("-lc++experimental")；补丁新增 source/ohos_pmr_compat.h 并把 #include <memory_resource> 改为 #include "ohos_pmr_compat.h"
```

**验证**:
```
用 $TMPDIR 建探针源码：printf '#include <memory_resource>\nint main(){return 0;}' > "$TMPDIR/pmr.cc" && $SDK/native/llvm/bin/aarch64-unknown-linux-ohos-clang++ -std=c++20 "$TMPDIR/pmr.cc" -o "$TMPDIR/pmr"（预期 fatal error: 'memory_resource' file not found）；ranges 探针同法（预期 no member named 'views'）
```
