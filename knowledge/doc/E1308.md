# E1308: Conan test_package 不能把同 target profile 误判为本机可运行

## 基本信息
- **严重度**: 2
- **类别**: ohos, cross-compile, conan, testing
- **作者**: 0335
- **来源 PR**: !11486

## 错误特征
```
Exec format error|Could not open '/lib/ld-musl-aarch64\.so\.1'|cannot execute binary file|test passed WITHOUT package artifacts|Skipping target execution on a non-AArch64 build machine
```

## 根因分析
Conan 的 can_run() 依据 host/build settings 判断可运行性；当 OHOS/armv8 profile 同时传给 host 和 build 时，它会返回 true，即使实际 runner 是 Linux/x86_64。test_package 随后直接运行 aarch64 musl ELF，出现 Exec format error 或缺少 /lib/ld-musl-aarch64.so.1。若简单 return 跳过测试，L1e 破坏性反向测试会误判测试不依赖被测包，或丢失真实功能执行证据。

## 推荐方案
**方法**: explicit-target-runner-with-artifact-assertion

**说明**: 优先在 AArch64 OHOS runner 上执行 test_package；x86 runner 则配置 qemu-aarch64 与含 lib/ld-musl-aarch64.so.1 的 QEMU_LD_PREFIX 后运行同一已安装二进制。若 CI 当前不能提供 QEMU，非目标架构分支只能在确认 self.dependencies[package].package_folder/bin/<tool> 存在后跳过执行，以保留 L1e 对安装产物的依赖证明；完整功能测试必须另用 QEMU 或 AArch64 runner 执行并如实写入测试报告。

**修复命令**:
```
QEMU_LD_PREFIX=<ohos-fakeroot> qemu-aarch64 -L "$QEMU_LD_PREFIX" <package_folder>/bin/<tool> <functional-args>
```

**验证**:
```
QEMU_LD_PREFIX=<ohos-fakeroot> qemu-aarch64 -L "$QEMU_LD_PREFIX" <package_folder>/bin/<tool> --help; CI_PACKAGES=archives/l/lcab/1.0b12 zsh ci/conan/build_and_test.sh
```
