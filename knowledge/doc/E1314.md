# E1314: private-static-libdir

## 基本信息
- **严重度**: 2
- **类别**: toolchain, linking
- **作者**: B756
- **来源 PR**: 6230

## 错误特征
```
Error loading shared library libzstd\.so\.1|undefined symbol: ZSTD_.*|archive member .*\.a is neither ET_REL nor LLVM bitcode
```

## 根因分析
libtool 链接时把所有 -Wl,* 参数聚合重排到 -L/-l 之前，导致 "-Wl,-Bstatic ... -lzstd ... -Wl,-Bdynamic" 的包裹对变成空操作（-lzstd 落在 -Bdynamic 之后按默认动态解析）；而传 .a 绝对路径时 libtool 又把整个归档嵌套拷贝进静态库产物（ld.lld 报 neither ET_REL）

## 推荐方案
**方法**: private-static-libdir

**说明**: 在 generate() 中把依赖的 libX.a 复制到 build_folder 下的私有目录（不含任何 .so），ZSTD_LIBS 等仅指向该私有目录 "-L<private> -lzstd"；同时从 AutotoolsToolchain extra_ldflags 中排除该依赖的原 libdir（否则原目录 .so 会先于私有目录被找到）。坑1: -Wl,-Bstatic/-Bdynamic 对被 libtool 前置重排而失效；坑2: .a 绝对路径被 libtool 作为 convenience library 嵌套拷贝进 .a 产物

**修复命令**:
```
mkdir -p $BUILD/zstd_static && cp $(conan cache path zstd/1.5.7.1)/lib/libzstd.a $BUILD/zstd_static/ && export ZSTD_LIBS="-L$BUILD/zstd_static -lzstd"
```

**验证**:
```
readelf -d <binary> | grep NEEDED
```
