# E1316: OHOS libc 不传递包含 <sys/types.h>，上游代码裸用 uint 编译失败

## 基本信息
- **严重度**: 2
- **类别**: libc, autotools, cpp
- **作者**: 8C4F, 6A03

## 错误特征
```
unknown type name .uint.|tools.h:.*uint.*not.*declared|error: unknown type name ..uint.
```

## 根因分析
上游代码在非 WIN32 分支依赖系统头文件传递提供 typedef uint（glibc 由 stdio/dirent 等传递包含 sys/types.h）。OHOS musl-libc 类实现不传递包含 sys/types.h，uint 未定义即报 unknown type name。lbreakouthd tools.h 仅在 #ifdef WIN32 下 typedef uint32_t uint。

## 推荐方案
**方法**: 在依赖 uint 的头文件中显式 #include <sys/types.h>（OHOS libc 定义 typedef unsigned u_int, uint;），或将 uint 替换为 uint32_t/stdint 类型。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
grep -nE 'u_int(64|32|16|8)_t' 源码目录 | head; # 存在则查翻译单元是否显式 #include <sys/types.h>
```
