# E1319: Re-sign HarmonyOS executables after their final content change

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, ohos, build-system
- **作者**: A434, 241D

## 错误特征
```
Operation not permitted.*(XaoS|lrelease)|(?:XaoS|lrelease): Operation not permitted|\.codesign section already exists
```

## 根因分析
HarmonyOS may reject an ELF with Operation not permitted when its .codesign data is stale or invalid, even when the section exists and execute permissions are present. CMake installation or RPATH rewriting can invalidate a freshly linked application signature, while a Qt host tool from Conan cache can also be denied at exec time. Re-sign only a build-local copy of dependency tools, then re-sign the installed application after the last install-time mutation.

## 推荐方案
**方法**: resign-elf-after-final-content-mutation

**说明**: On OHOS, create a private signed copy of any Conan-cached Qt host tool whose execution is denied, without modifying the immutable dependency cache. After CMake install has finalized the application binary and its RPATH, remove the old .codesign section, self-sign the installed ELF, preserve executable permissions, and replace it atomically. Confirm the tool launches and validate the application's real output on device.

**修复命令**:
```
llvm-objcopy --remove-section .codesign <private-ELF> && binary-sign-tool sign -inFile <private-ELF> -outFile <private-ELF>.signed -selfSign 1 && chmod 0750 <private-ELF>.signed && mv <private-ELF>.signed <private-ELF>
```

**验证**:
```
On an OHOS aarch64 device, run llvm-objcopy --remove-section .codesign <ELF>; binary-sign-tool sign -inFile <ELF> -outFile <ELF>.signed -selfSign 1; preserve executable mode and replace the ELF; then execute a real workload and inspect its output.
```
