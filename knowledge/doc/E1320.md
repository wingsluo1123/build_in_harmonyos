# E1320: 文件系统权限语义不可靠时优先使用上游自带的可靠性开关，而不是跳过测试用例

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, portability, posix, testing
- **作者**: 5CC4

## 错误特征
```
chmod 000.*rw-|chmod.*not effective|Permission denied.*expected
```

## 根因分析
HMDFS 上 chmod() 恒返回 0 但只加不减：有效模式 = 创建时模式 | 请求模式，world 位永远为 0（umask 000 新建文件仍是 -rw-rw----，随后 chmod 000/400 改不动），因此『改权限后访问应失败』这一断言前提在该平台必然不成立，且返回码无法暴露该失效

## 推荐方案
**方法**: upstream-unreliable-fs-switch

**说明**: 先在上游源码里找它为不可靠文件系统预留的编译期开关（如 Cesanta 的 TEST_UNDER_VIRTUALBOX、常见命名 NO_DNS_TEST / SKIP_PERM_TESTS），用 CFLAGS_EXTRA 传入，只关掉那一处断言块，零源码改动；受影响的只有该块而非整条用例

**修复命令**:
```
make -C test -j1 unit_test CC=$CC CFLAGS_EXTRA=-DTEST_UNDER_VIRTUALBOX
```

**验证**:
```
cd $HOME/tmp && touch f && chmod 000 f && ls -l f && cat f && echo READ_OK
```
