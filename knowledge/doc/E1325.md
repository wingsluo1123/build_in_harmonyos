# E1325: 制品仓对不存在的配方返回 acceleration policy 报错（易误判为 registry 不可达）

## 基本信息
- **严重度**: P2
- **类别**: registry
- **作者**: 24BF

## 错误特征
```
ERROR: error:system acceleration policy not enabled. [Remote: ohpcd]
```

## 根因分析
cnb.cool 制品仓的 Conan v1 兼容接口对“配方不存在”的查询返回 error:system acceleration policy not enabled，而不是 Recipe not found / 404。该文案与网络或鉴权无关，极易被误读为 registry 不可达，从而误触发 R41 重试与止损流程。（该文案由网关返回，其在“配方不存在”场景下的确切成因未在本条断言范围内；此处只固化可复现的现象与判定口径。）

## 推荐方案
**方法**: W0 依赖探测以 conan download <pkg>/<版本> -r=ohpcd --only-recipe 成功与否为权威判据（R35 口径）；conan search 仅可作为人工排查的辅助线索，不作为 binary 是否存在的依据（R35 明确 search API 对 binary 返回不完整）。看到 acceleration policy 报错应先按“该版本未发布”处理，而不是当作 registry 故障。

**说明**: 用 conan download --only-recipe 判定依赖是否发布；acceleration policy 报错按“未发布”解读。

**修复命令**:
```
conan download rtl-sdr/2.0.2 -r=ohpcd --only-recipe   # 权威判据 ; grep -n "Recipe not found" conan_create.log            # 如需排查非法 recipe
```

**验证**:
```
conan download rtl-sdr/2.0.2 -r=ohpcd --only-recipe 成功；rtl-sdr/0.9.0 返回上述 acceleration policy 报错——由 rtl-wmbus/1.1.0 的 W0 探测实测。
```
