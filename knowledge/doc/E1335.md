# E1335: 上游测试链接内部静态库可用私有符号，1:1 移植测试断言到消费者上下文（conan test_package）前须以 nm -D 过滤已导出符号

## 基本信息
- **严重度**: 2
- **类别**: limitation, portability, testing
- **作者**: 5C2D

## 错误特征
```
ld.lld: error: undefined symbol: .+_nearest_from_rgba|undefined symbol: .+_private|undefined reference to .*（私有头函数）
```

## 根因分析
上游 meson/autotools 的测试二进制链接库的内部静态库（如 libadwaita-1-internal.a，全部符号、无可见性过滤），因此可引用私有 API（仅私有头声明、未从 .so 导出的函数，如 adw_accent_color_nearest_from_rgba 仅声明于 src/adw-accent-color-private.h）。conan 消费者（test_package）只能链接已安装的 .so，其导出符号面窄于内部 .a——把上游测试断言 1:1 移植到消费者上下文即 ld.lld: error: undefined symbol。这是符号可见性差异，不是库缺陷：符号在公共接口中确实不存在。判别方法：同一编译单元/头文件内的兄弟函数（如 adw_accent_color_to_rgba）正常导出，仅私有头声明的函数缺失——对照 nm -D 输出即可定位

## 推荐方案
**方法**: 移植上游测试断言前逐符号验证可见性：nm -D --defined-only 已安装 .so | grep <函数名>。将断言集二分——公共 API 断言（1:1 移植，计入移植执行数字）与私有 API 断言（不入探针，按 E471 口径分类留证：函数名、私有头路径、nm -D 为空的证据、上游为何可用=链接内部 .a）。notes/test-report/PR 正文三处同口径写明：移植 N/N 公共 API 断言 + 私有 API M 条不可执行（分类留证）

**说明**: 先过滤符号可见性再移植断言，公私二分如实申报

**修复命令**:
```
nm -D --defined-only $PKG/lib/*.so.* | grep <sym>
```

**验证**:
```
nm -D --defined-only <安装目录>/lib/<lib>.so.<n> | grep <符号名>  # 空 = 私有不可移植；同文件兄弟函数应能列出
```
