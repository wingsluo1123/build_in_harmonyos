# E1336: Conan 2 shared-library 包的 STATIC 依赖向下游被强制 headers/libs=False（Skipped），PkgConfigDeps 把它从生成的 .pc Requires 链静默丢弃

## 基本信息
- **严重度**: 2
- **类别**: conan
- **作者**: 3DF5, Awstme
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/7671

## 错误特征
```
Package XXX was not found in the pkg-config search path（上游 gen 脚本按特定 pc 名探测，conan 依赖暴露的 pc 名不匹配）
```

## 根因分析
conan 依赖包经 PkgConfigDeps 暴露的 .pc 名与上游构建脚本探测的 pc 名不一致（rtpengine 案例：探测 libcrypto/libpcre2-8/libmariadb/libjwt，依赖包暴露 openssl/pcre2/mariadb-connector-c/libjwt2 系命名）

## 推荐方案
**方法**: conanfile.py generate() 中 PkgConfigDeps.generate() 后，把私有 prefix 下对应 .pc 复制/重命名为探测名（内容相同仅改 Name 字段），PKG_CONFIG_PATH 指向私有 prefix；禁止改共享依赖配方（影响面爆炸）；参考 archives/r/rtpengine/26.0.1.15/conanfile.py

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
wrapper .pc 注入后 gen-common-flags 22/22 探测通过（rtpengine 26.0.1.15 实测）
```
