# E1337: 复用输出缓冲区未 NUL 结尾，导致测试断言读到上一次调用的残留

## 基本信息
- **严重度**: P1
- **类别**: testing
- **作者**: 2F16

## 错误特征
```
测试断言行数/字段随调用顺序漂移（实际抓到 272 字节却报 8 行）
```

## 根因分析
harness 只在函数入口做 out[0]=0，读完子进程输出后按 used 写入短输出，却没在结尾写 out[used]=0。strlen()/逐行遍历会越过真实数据继续读到上一轮更长的残留，表现为“行数/字段断言被污染且随调用顺序变化”，且污染内容来自另一条命令的输出（例如 usage 文本），极具迷惑性。

## 推荐方案
**方法**: 捕获子进程输出到复用缓冲区时，入口置空之外必须在读循环结束后显式 out[used]='\0'（并保证 used < outcap）。

**说明**: 复用缓冲区每次调用都必须写终止符，不能只在入口清首字节。

**修复命令**:
```
/* 读循环结束后 */ ; if (outcap && used < outcap) out[used] = '\0';   /* 必须 */
```

**验证**:
```
修复前 decoded 8 lines 失败；修复后 2 lines 通过。定位手段：在 run_rtl 内 trace 每轮 used 与前 32 字节。
```
