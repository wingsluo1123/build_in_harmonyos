# E1339: GNU make 命令行赋值会击穿 ?= 推导 + := 重写的版本横幅逻辑

## 基本信息
- **严重度**: P1
- **类别**: build-system
- **作者**: EAA6

## 错误特征
```
Makefile 版本前缀重写被命令行赋值击穿（得到 master1.1.0 而非 1.1.0）
```

## 根因分析
GNU make 赋值优先级为 命令行 > makefile 赋值（含 := 与 ?=）> 环境变量 > 内置默认。典型 Makefile 用 ?= 从 git 推导版本再用 := 清空前缀（ifeq ($(BRANCH),master) BRANCH:=）。无 .git 时 git describe/rev-parse 失败，必须注入该值；若注入到命令行，优先级最高会使 BRANCH:= 失效、分支前缀不被清掉，横幅多出前缀。

## 推荐方案
**方法**: 把 ?= 变量经【环境】注入而非命令行——环境变量只是默认值，不干扰 Makefile 内部的 := 重写，分支前缀逻辑照常生效。conan 侧用 GnuToolchain(self).extra_env.define()。

**说明**: 用环境变量（extra_env）注入 git 推导型 Makefile 的 ?= 变量，让 Makefile 自身的前缀重写继续生效。

**修复命令**:
```
tc = GnuToolchain(self) ; tc.extra_env.define("BRANCH", "master") ; tc.extra_env.define("TAG", self.version) ; tc.generate() ; self.run('make release CC="<cc>" -j1', cwd=self.source_folder)
```

**验证**:
```
环境注入得 version.h 的 VERSION="1.1.0"（与 tag 版 master 检出一致）；命令行注入得 "master1.1.0"。由 rtl-wmbus/1.1.0 实测对照。
```
