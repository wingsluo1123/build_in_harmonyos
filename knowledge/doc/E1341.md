# E1341: CMake 4.x 工具链模式下 add_custom_command COMMAND 不展开 :: 命名空间 ALIAS 目标名：host 生成器被字面执行报 Error 127

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, cross-compile, host-tools
- **作者**: A482
- **来源 PR**: 11976

## 错误特征
```
Error 127|inaccessible or not found|::
```

## 根因分析
CMake 4.1.2 在设置 toolchain（CMAKE_SYSTEM_NAME 置位=交叉模式）后，add_custom_command(COMMAND ...) 中 :: 命名空间的 ALIAS 目标名不再展开为可执行文件真实路径，build.make 里保留字面量（cd ... && Zeek::BifCl ...）。host 生成器本身（bifcl/binpac/gen-zam）已真实构建成功且可执行，只有命令行未展开。交叉编译私有工具链（host 工具+目标产物）场景的典型陷阱。

## 推荐方案
**方法**: generator-expression-target-file

**说明**: 把 CMake 源中 COMMAND Zeek::BifCl/Zeek::BinPAC/gen-zam 改为生成器表达式 $<TARGET_FILE:Zeek::BifCl> 等，generate 期展开真实路径。重配置后验证 build.make 命令已展开为 ../tools/binpac/src/binpac，三生成步骤全过。通用做法，其他 host 生成器目标同样适用，无平台宏。

**修复命令**:
```
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=<toolchain.cmake> && grep -n 'TARGET_FILE' cmake/BifCl.cmake && make bif-std-types.bif
```

**验证**:
```
grep -n '::' build.make | head（出现字面 ALIAS 名=命中）；grep -n 'TARGET_FILE' build.make（应已展开为真实路径）
```
