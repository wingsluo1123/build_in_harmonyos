# E1342: 上游子包用绝对导入 from core.* 且 __init__ 未导出 RunConfig 导致整子系统不可导入（发布版与 master 同）：适配时记录为不可用面而非擅自打补丁，依赖证明改走可达路径

## 基本信息
- **严重度**: 2
- **类别**: compat, limitation, python, packaging, testing
- **作者**: 7A0A

## 错误特征
```
ImportError: cannot import name 'RunConfig' from 'riscemu'|ModuleNotFoundError: No module named 'core'|No module named 'core\.traps'|No module named 'core\.usermode_cpu'|Error while finding module specification for 'riscemu\.priv'
```

## 根因分析
riscemu/priv/{__main__,PrivCPU,ElfLoader}.py 写的是 Python 2 时代风格的顶层绝对导入 from core.usermode_cpu import * / from core.traps import *（应为 from ..core...），且 priv/__main__.py 里 from riscemu import RunConfig 而 riscemu/__init__.py 只导出 __version__/__author__/__copyright__；两条缺陷叠加使 priv 子系统（特权模式模拟器 + pyelftools ELF 加载器）在 2.2.7 与当前 master 上都不能 import，python -m riscemu.priv --help 直接 ImportError

## 推荐方案
**方法**: document-unreachable-upstream-subpackage-keep-fidelity

**说明**: 不修改上游源码（不补 from ..core 也不补齐 __init__ 导出）：在 notes.md/manifest.yaml 的未覆盖项与知识条目中显式记录该子系统不可用，消费者测试回避 riscemu.priv 导入；对 pyelftools 这类『仅被该死代码使用』的运行时依赖，改在 test_package 里直接用 ELFFile 解析真实 ELF（/proc/self/exe 或 python 解释器本体）证明其功能可用，而不是删依赖或假声明

**修复命令**:
```
python3 -c "from elftools.elf.elffile import ELFFile; f=ELFFile(open('/proc/self/exe','rb')); assert f.elfclass in (32,64); print(f.header['e_machine'], len(list(f.iter_sections())))"
```

**验证**:
```
python3 -c 'import riscemu.priv' ; echo rc=$?  # ImportError；python3 -m riscemu.priv --help  # ModuleNotFoundError: No module named 'core'；python3 -c 'from elftools.elf.elffile import ELFFile; f=ELFFile(open("/bin/ls","rb")); print(f.elfclass, list(f.iter_sections())[:1])'  # 证明依赖本身可用
```
