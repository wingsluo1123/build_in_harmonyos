# E1344: test_package 里写死 clang：交叉编译时用的是宿主编译器/链接器，链接 aarch64 静态库必然失败；应按 cross_building 取 profile 里的交叉编译器

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, cross-compile, conan
- **作者**: 72DB

## 错误特征
```
/usr/bin/ld: skipping incompatible .../p/lib/liblzma.a when searching for -llzma ; /usr/bin/ld: cannot find -llzma ; clang-15: error: linker command failed with exit code 1  (test_package test() 失败)
```

## 根因分析
test_package 的 test() 里直接执行 clang（如 self.run("clang -o test_xz test_xz.c -I... -L... -llzma", env=conanbuild)）。在交叉编译（host=OHOS aarch64、build=x86_64 Linux）下，conanbuild 环境里的 clang 是宿主 x86-64 编译器/链接器，而 -L 指向的是 aarch64 的 liblzma.a，于是 ld 报 skipping incompatible 并最终 cannot find -llzma。该写法只在 设备端原生构建（host==build）时才成立。

## 推荐方案
**方法**: recipe-conditional

**说明**: test() 里按 cross_building(self) 分支：交叉编译时从 self.conf 读取 tools.build:compiler_executables 的 c 项（profile 里配置的 OHOS 交叉编译器包装脚本）并追加 -static（静态链接后产物可在本机 QEMU/binfmt 下真实执行）；设备端原生构建保持原样调用系统 clang，命令与既有配方一致。

**修复命令**:
```
cc = self.conf.get("tools.build:compiler_executables", default={}, check_type=dict).get("c") or "clang"
```

**验证**:
```
grep -n 'self.run(f"clang' archives/*/*/*/test_package/conanfile.py   # 命中即为写死宿主编译器
```
