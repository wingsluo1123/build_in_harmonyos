# E1346: FUSE 挂载上 tempfile.mkdtemp 的 0700 目录导致子进程 getcwd 失败（configure 报 working directory cannot be determined）

## 基本信息
- **严重度**: medium
- **类别**: platform
- **作者**: 11D3

## 错误特征
```
working directory cannot be determined|getcwd: cannot access parent directories|Permission denied
```

## 根因分析
HarmonyOS PC 的用户态挂载（/storage/Users 上的 HMDFS 与 /data/storage/el2 上的 appdat）对目录权限的判定与内核常规语义不同：进程即使是一个 0700 目录的创建者/属主，其子进程在该目录内 getcwd() 也返回 EACCES（chdir 却可成功）。tempfile.mkdtemp() 按 libc 惯例创建 0700 目录，因此任何把临时目录当工作目录再派生 configure/sh 的流程（如 ohc clean-verify）都会在 configure 阶段报 working directory cannot be determined。补充实测：/data/service/hnp/bin/bash 的 getcwd 在 0755 的 appdat 目录里同样失败（bundle bash/python3//system/bin/sh 正常，SELinux 域同为 develop_tools_hap），ohc clean_verify.py:68 默认以它作 executable 跑 configure ⇒ CONFIG_SHELL=/system/bin/sh 可规避

## 推荐方案
**方法**: mkdtemp-chmod-755-sitecustomize

**说明**: 不改框架脚本的环境级修复：向 PYTHONPATH 注入 sitecustomize 包装 tempfile.mkdtemp 创建后 os.chmod(d,0o755)（el2/appdat 上 chmod 有效，E046 仅适用 /storage 的 HMDFS）；同时 export TMPDIR=/data/storage/el2/base/cache、CONFIG_SHELL=/system/bin/sh。框架级正解（应另开 PR）：clean_verify.py:82 mkdtemp 后补 chmod 0755

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
T=/data/storage/el2/base/cache/probe-700; mkdir -p $T; chmod 700 $T; (cd $T && pwd); echo RC=$?; chmod 755 $T; (cd $T && pwd); echo RC=$?
```
