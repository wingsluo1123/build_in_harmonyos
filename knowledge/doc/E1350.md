# E1350: COIN-OR autotools 配方依赖发现方式决定 libtool 是否解析依赖包 .la（libdir='//lib' 无效路径）：显式 --with-*-lib 绝对 .a 注入是最稳路径

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, packaging, libtool, coin-or
- **作者**: D942

## 错误特征
```
'//lib/lib.*\.la' is not a valid libtool archive|grep: //lib.*\.la: No such file or directory|sed: //lib.*\.la: No such file|libtool: link: .*lib\.la' is not a valid libtool archive|archive member .*\.a is neither ET_REL nor LLVM bitcode|Segmentation fault|Signal 11
```

## 根因分析
ohpcd 依赖包（clp/coin-or/coinutils/cgl/zlib）由 configure --prefix=/ 构建，其 .la 内 libdir='//lib' 在设备上不存在。cbc 配方 configure 若仅传 PKG_CONFIG_PATH + CPPFLAGS（无 --with-*-lib），生成的 Makefile 用 -lClp/-lOsi/-lz/-lCoinUtils/-lCgl/-lOsiClp 让 libtool 解析各依赖 .la → grep/sed //lib/libClp.la No such file → '//lib/libClp.la' is not a valid libtool archive → libCbc.la 链接失败（CI 全新构建权威复现 PR #10898）；本地增量构建复用旧对象未暴露。R02 曾因 osiUnitTest 段错误误判为 --with-*-lib 嵌套归档并移除注入，R03 恢复显式注入后修复：显式 --with-*-lib 传入绝对 .a 路径时 Makefile 直接引用可用归档，libtool 无需解析依赖 .la

## 推荐方案
**方法**: explicit-with-lib-absolute-archive-injection-plus-makefile-la-replace

**说明**: 组合方案（A+B）：① configure 显式注入 --with-*-lib='<dep>/lib/lib*.a …'（含传递依赖闭包绝对 .a 列表）；② make 前 find src -name Makefile -exec sed -i 把 -lClpSolver/-lOsiClp/-lClp/-lOsi/-lCgl/-lCoinUtils/-lz 替换为依赖包绝对 .a 路径（长名优先防子串误替）。单靠方案 A 只注入 configure 变量，libCbc.la 的 LIBADD 仍含 -l*，CI 缓存含 .la（libdir='//lib'）时 libtool 仍解析失败；方案 B 对有无 .la 的环境都生效。R03 最终验证：本地与 CI 全新构建 invalid libtool archive 计数 0、libCbc.la 链接成功、cbc CLI p0033 obj=3089、test_package 3/3 PASS
