# E1351: OHOS 已落盘 ELF 任何 in-place 字节改动后不可执行（strip/objcopy/meson install RUNPATH 剥离）

## 基本信息
- **严重度**: 1
- **类别**: platform, ohos
- **作者**: D372

## 错误特征
```
exec (llvm-objcopy|llvm-strip|meson install) 处理过的二进制报 Permission denied (EACCES) 或 Operation not permitted (EPERM)，文件 mode 770 且 ehdr/phdr/SELinux context 均正常（已落盘 ELF 任何 in-place 字节改动后不可执行）
```

## 根因分析
OHOS 内核/FS 对已落盘文件做完整性封印（推断与 lld 生成的 .note.ohos.ident 标识段相关，与 SKILL gotchas ELF 签名机制同族）；落盘后任何字节改动破坏封印 → exec 拒绝。两条证据链：①llvm-objcopy 输出（strip/纯重序列化，4.6KB hello 亦复现）→ EACCES/EPERM；②meson install 剥 DT_RUNPATH 的 in-place patch（1195 字节，大小不变）→ EPERM（stage 直接执行复现）。对照：clang/lld 原始产物与全新拷贝（cp/shutil.copy2）可执行

## 推荐方案
**方法**: package() 禁止 meson install / strip / llvm-objcopy 等一切链接后重写，一律对 build 目录原始产物做全新拷贝（conan copy/shutil.copy2=新文件写入，可执行实证）；build 目录产物携带的 DT_RUNPATH 异地为死路径无害，运行时库解析由 conanrunenv 承担；瘦身需求走 CI sign.sh 签名链。本机 /data/service/hnp/bin/llvm-strip 是 llvm-objcopy 符号链接别名（无独立 llvm-strip）
