# E1355: 用 python -c 'import <name>' 探测命令行工具（filecheck/lit 等）是否可用时，test_package 里的同名目录会被当作隐式命名空间包而导入成功，pip 安装被静默跳过，直到 lit 用例报 command not found (127)

## 基本信息
- **严重度**: 2
- **类别**: detection, build-system, python, conan, packaging
- **作者**: ADA3

## 错误特征
```
'filecheck': command not found|error: command failed with exit status: 127|Failed: 1|ModuleNotFoundError: No module named 'filecheck'
```

## 根因分析
Python 3.3+ 的隐式命名空间包规则让 import filecheck 在 PYTHONPATH 命中任意名为 filecheck/ 的目录时即成功（无需 __init__.py）；test_package 恰好把上游 lit 目录复制成 test_package/filecheck/ 并把它所在目录放入 PYTHONPATH，于是 import 探针恒真，_ensure_module 判定工具已装而跳过 pip install，真正缺失的是同名可执行文件 filecheck（PyPI 包），直到 lit 跑到用例才以 127 暴露；诊断成本被推迟到测试阶段

## 推荐方案
**方法**: cli-probe-with-shutil-which

**说明**: 区分两类依赖探针：Python 模块用 import 探针，命令行工具一律用 PATH 探针（shutil.which(name, path=env['PATH']) 或直接执行 --version），装完再复检一次并在失败时 raise ConanException，绝不静默继续

**修复命令**:
```
if not shutil.which('filecheck', path=env['PATH']): self._pip_install(env, python, 'filecheck==0.0.23'); assert shutil.which('filecheck', path=env['PATH'])
```

**验证**:
```
python3 -c "import filecheck" ; echo rc=$?   # 在 test_package 目录、PYTHONPATH 含 test_package 时 rc=0（假阳性）；ls $(dirname $(which python3))/filecheck  # 真实可执行文件不存在；shutil.which('filecheck') 返回 None
```
