# E1356: Conan copy() 默认 keep_path=True 造成 bin/bin、lib/lib 嵌套目录且软链悬空

## 基本信息
- **严重度**: 2
- **类别**: make, conan, packaging
- **作者**: A7AC

## 错误特征
```
unable to find library -l|bin/bin|lib/lib|dangling symlink|keep_path
```

## 根因分析
Conan copy() 默认 keep_path=True：当 makefile 产物自带 bin/、lib/ 前缀且 copy 模式含子路径（bin/g810-led、lib/libg810-led.so.0.4.3）时，会拷成 pkg/bin/bin/、pkg/lib/lib/ 嵌套目录；官方 makefile 生成的软链 libg810-led.so 指向同目录文件而实际文件被嵌套，符号链接悬空，消费者 -lg810-led 报 unable to find library。

## 推荐方案
**方法**: package() 拷贝自带 bin//lib/ 前缀的产物时用 copy(..., keep_path=False)；软链显式重建（os.symlink）保证 -l 可链接

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
conan create 的 test_package 消费者 -lg810-led 链接失败（ld.lld: unable to find library）；修复后 ls -la pkg/lib 检查 libg810-led.so -> libg810-led.so.0.4.3 可解析且 pkg/bin 无 bin/bin 嵌套
```
