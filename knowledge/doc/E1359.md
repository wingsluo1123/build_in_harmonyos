# E1359: aarch64 上隐式函数声明截断指针/浮点：老 C 代码编译全绿但启动即 SIGSEGV（malloc/get_node/atof/sin）

## 基本信息
- **严重度**: 2
- **类别**: compat, libc, aarch64, legacy-c
- **作者**: 9C4A

## 错误特征
```
implicitly declaring library function|call to undeclared function '(malloc|get_node|make_list|atof|sin|cos|log)'|Signal 11 \(core dumped\)
```

## 根因分析
C89 隐式函数声明假定返回 int。aarch64 上指针/浮点返回值被按 int 截断（或从错误寄存器读取）：malloc 返回的指针被截成 32 位导致堆损坏/段错误；atof/sin/cos 等返回 double 的函数被当 int 读导致结果错误。典型触发是老代码用发行版宏（如 jgraph 的 -DLCC）才 include <stdlib.h>，非该宏路径下 malloc 完全没有声明。

## 推荐方案
**方法**: unconditional-std-headers-and-pointer-prototypes

**说明**: 1) 在主头文件无条件 include <stdio.h>/<stdlib.h>/<string.h>/<math.h>，不要保留发行版宏开关（旧代码常把 stdlib.h 放在 #ifdef LCC 之类分支里）；2) 为返回指针的自研函数补声明（如链表 get_node/make_list），声明放在所有使用方都会包含的头文件里；3) 修复后用编译日志复查 -Wimplicit-function-declaration，返回指针/浮点的函数不应再出现在隐式调用列表；4) 这类问题的表现是编译成功、运行即崩，验证时必须用真实输入跑一遍二进制，不能只看编译结果。

**修复命令**:
```
make CC=clang 2>&1 | grep -c "call to undeclared function"   # 期望 0（危险函数）
```

**验证**:
```
grep -nE "call to undeclared function '(malloc|get_node|make_list|atof|sin|cos|log)'" build.log；修复后编译日志中不应再出现这些函数；再用真实输入运行二进制（如 jgraph -P < simple.jgr）确认不再 SIGSEGV。
```
