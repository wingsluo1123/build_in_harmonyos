# E1360: 从未被编译过的 header-only 上游库：clang 解析期急切检查非依赖构造，include 即编译失败（GCC 不暴露）

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, conan
- **作者**: 7707

## 错误特征
```
no matching constructor for initialization of.*Array1D|error: no matching constructor.*include time|In file included from.*\.h:.*error: no matching constructor
```

## 根因分析
两类上游潜伏缺陷只在 clang+真实编译时暴露：①类模板成员定义中非依赖类型成员的构造（如 Array1D<int> 成员从 (int, const int*) 初始化）被 clang 解析期急切检查（GCC 延迟到实例化），头文件一被 include 即报错；②声明未定义的悬空成员（如 Stopwatch::running()、Sparse_Matrix_CompRow 的 copy ctor/operator=）编译通过但链接期 undefined symbol。多见于上游无测试、发行版只装头文件从不编译的老库（NIST TNT 1.2.6 实例）。

## 推荐方案
**方法**: probe-include-and-link-then-patch-or-avoid

**说明**: 适配 header-only 老库先跑两级探针：①编译探针——#include 聚合头+空 main -fsyntax-only（暴露解析期错误）；②链接探针——逐组件实例化并链接空 main（暴露悬空声明）。解析期错误打最小补丁（改签名匹配既有重载）；悬空声明不打补丁，test_package 规避并在 notes/MANIFEST 声明。判断错误属解析期还是实例化期：报错无 'in instantiation of ... requested here' 注记 = 解析期。

**修复命令**:
```
printf '#include <tnt.h>\nint main(){return 0;}\n' | clang++ -x c++ -std=c++17 -stdlib=libc++ -I<pkg>/include -fsyntax-only -
```
