# E1361: Conan 2.29 AutotoolsToolchain 不向 CPPFLAGS/LDFLAGS 下发依赖的 -I/-L

## 基本信息
- **严重度**: high
- **类别**: build-system
- **作者**: 64CA

## 错误特征
```
configure: error: X11 library is required|checking for main in -lX11... no|undefined reference
```

## 根因分析
Conan 2.29 的 conan.tools.gnu.AutotoolsToolchain 生成的 conanautotoolstoolchain.sh 中 LDFLAGS 为空、CPPFLAGS 仅含 defines，不包含 dependencies.host 的 includedirs/libdirs（那是 AutotoolsDeps 的职责，但 AutotoolsToolchain 不自动组合）。上游 configure.ac 用 AC_CHECK_LIB([X11]) / AC_CHECK_HEADER 直接探测而非 pkg-config 时，探测必然失败并报 'X11 library is required'。另注意：configure 的 AC_CHECK_SIZEOF 会编译并运行 conftest，依赖共享库不在 LD_LIBRARY_PATH 时 conftest 退出 127，SIZEOF_UNSIGNED_INT/SIZEOF_UNSIGNED_LONG 静默变为 0

## 推荐方案
**方法**: explicit-flags-in-generate

**说明**: 在 conanfile.py 的 generate() 中遍历 self.dependencies.host，把 cpp_info.includedirs 拼进 CPPFLAGS（-I 前缀）、libdirs 拼进 LDFLAGS（-L 前缀），经 toolchain.environment().define() 注入后再 toolchain.generate(env=...)；同时把各依赖 libdir 加入 LD_LIBRARY_PATH 供 conftest 运行，把 PkgConfigDeps 的生成目录加进 PKG_CONFIG_PATH（依赖间有 Requires 时 configure 报 'Package xcb, required by x11, not found'）

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
grep -n LDFLAGS <build_folder>/build-release/conan/conanautotoolstoolchain.sh
```
