# E1363: libtool 吞掉裸 -static：交叉编译下程序仍是动态，OHOS 无设备端加载器导致 make check 全挂；须改用 libtool 的 -all-static

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, build-system, autotools
- **作者**: 4235

## 错误特征
```
aarch64-binfmt-P: Could not open '/lib/ld-musl-aarch64.so.1': No such file or directory  (make check 全部 FAIL)
```

## 根因分析
上游用 libtool 作链接驱动时，LDFLAGS 里的裸 -static 会被 libtool 当成自身参数消费、不转发给编译器，程序实际仍是动态链接（readelf -l 可见 INTERP = /lib/ld-musl-aarch64.so.1）。而 OHOS SDK 不随附设备端 musl 动态加载器，本机 QEMU/binfmt 无法执行该产物，上游 make check 的 18 个测试二进制全部报 Could not open '/lib/ld-musl-aarch64.so.1' 并 FAIL。xz 5.8.1 实测复现。

## 推荐方案
**方法**: extra-ldflags

**说明**: 在 conanfile.py 的 generate() 中，仅当 cross_building(self) 为真时向 AutotoolsToolchain 追加 libtool 的正确开关 -all-static，使程序真正静态链接；设备端原生构建不加该标志，保持上游默认行为（与已发布配方一致）。

**修复命令**:
```
tc.extra_ldflags.append("-all-static")  # 仅 if cross_building(self)
```

**验证**:
```
readelf -l <bin> | grep INTERP    # 有 INTERP 输出即仍为动态；改用 -all-static 后应无输出
```
