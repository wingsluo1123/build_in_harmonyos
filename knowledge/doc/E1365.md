# E1365: OHOS libc++ 15.0.4 的 <ranges> 头存在但算法成员整批缺失：std::ranges::sort/find/copy/transform 等全部 no member 编译错误

## 基本信息
- **严重度**: 2
- **类别**: platform, c++20, cplusplus, libcxx-stdlib
- **作者**: 34BB
- **来源 PR**: 11976

## 错误特征
```
no member named 'sort' in namespace 'std::ranges'|no member named 'find' in namespace 'std::ranges'|std::ranges::.*no member|__cpp_lib_ranges
```

## 根因分析
SDK 的 libcxx-ohos 中 <ranges> 头存在，但 __cpp_lib_ranges 未定义，std::ranges 命名空间的算法集（sort/find/copy/transform/unique/remove 等）整批缺失——命名空间在、算法不在，属硬平台约束（-stdlib=libc++ 单独探针同样编不过）。zeek 8.2.1 实测 47 文件 83+ 使用点，且经 .pac/.bif 模板源码链（Dict.h/telemetry）链式扩散全树报错。

## 推荐方案
**方法**: rewrite-ranges-to-classic-stl

**说明**: 机械映射表改写为等价经典 STL：std::ranges::sort(v,cmp)→std::sort(v.begin(),v.end(),cmp)；reverse_view→反向迭代器；ranges::unique（返回对）→std::unique（单迭代器）；ranges::remove+begin（erase-remove 惯用法）→v.erase(std::remove(...),v.end())。派生陷阱（zeek 实测 P9）：机械改写时把原始 C 数组当容器用 .begin()/.end() 会再报 member reference base type 错误，C 数组须用 std::begin/std::end——改写后须全树 grep std::ranges:: 清零 + C 数组调用点专项复查。

**修复命令**:
```
grep -rn 'std::ranges::' src/ auxil/ | wc -l（改写后应为 0）&& make
```

**验证**:
```
clang -E -dM -x c++ - | grep __cpp_lib_ranges（未定义=命中）；最小探针 std::ranges::sort 编译应报 no member
```
