# E1374: HNP 自带 JDK（/data/service/hnp/...）在某环境启动即报 “Failed to mark memory page as executable”，字面像平台 W^X 限制但实际是「该 JDK 构建在本机不可用」——须用 C 探针证伪（RWX mmap + mprotect(RX) 成功），改按 cmd-pkgs 自装 ~/bishengjdk17 解决

## 基本信息
- **严重度**: 3
- **类别**: toolchain, java, environment
- **作者**: F199

## 错误特征
```
Failed to mark memory page as executable - check if grsecurity/PaX is enabled
```

## 根因分析
HNP 自带的 bishengjdk17（/data/service/hnp/bin/java 与其 bishengjdk17.0.13_06.org 目录）在本适配环境执行任何 JVM 入口（java -version / javac / maven 调用的 java）都在 VM 初始化阶段失败，报 “Failed to mark memory page as executable - check if grsecurity/PaX is enabled”。该文案字面指向 W^X/PaX 内核策略，极易被判定为平台限制（仓库既有知识 E045 对 mmap/RWX/JIT 类问题即给 no-fix-platform-limitation 结论）。但实测：同一台机器上编译运行一个 C 探针做 `mmap(PROT_READ|PROT_WRITE|PROT_EXEC)` 与 `mprotect(PROT_READ|PROT_EXEC)` **均成功**（home 与非 home 目录皆然）→ 平台并未禁止 RWX，真因是该 JDK 构建在此环境不可用。改用同一台机器上经 cmd-pkgs 自装的 ~/bishengjdk17（BiShengJDK 17.0.13）后，java/javac/Maven 全部正常。

## 推荐方案
**方法**: probe-platform-then-switch-to-cmd-pkgs-jdk

**说明**: ①先用 C 探针确认平台是否真禁 RWX（探针源码：mmap(0,4096,PROT_READ|PROT_WRITE|PROT_EXEC,MAP_PRIVATE|MAP_ANONYMOUS,-1,0) 与 mprotect(p,4096,PROT_READ|PROT_EXEC)）；探针成功即证明不是平台限制，不要据此把库判为 env_unsupported/no-fix。②换 JDK：curl -fsSL https://gitcode.com/OpenHarmonyPCDeveloper/cmd-pkgs/releases/download/pkgs/install-jdk.sh -o ~/.install-jdk.sh && sh ~/.install-jdk.sh 17.0.13（装到 ~/bishengjdk17）。③配方侧把 _ensure_java() 的候选顺序固定为 JAVA_HOME → ~/bishengjdk17 → ~/usr/local/bishengjdk17 → PATH，确保不会回退到 PATH 中的坏 JDK（否则 mvn 内部仍会用到它并 BUILD FAILURE）。④test_package 的 test.sh / conanfile.py 解析 JAVA_HOME 时同样优先 ~/bishengjdk17。

**修复命令**:
```
sh ~/.install-jdk.sh 17.0.13 # 装到 ~/bishengjdk17；随后 export JAVA_HOME=~/bishengjdk17
```

**验证**:
```
① C 探针：clang -o rwx rwx.c && ./rwx（mmap RWX + mprotect RX 均打印 OK）② ~/bishengjdk17/bin/java -version（打印 openjdk version "17.0.13" ... BiSheng）
```
