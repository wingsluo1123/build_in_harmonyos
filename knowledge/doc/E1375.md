# E1375: 老式 autotools 工程（本例 irc2）在 Conan 里落地要同时满足 4 条约束——① **真正的 autoconf 可能在子目录**（`support/configure`，按官方做法复制到独立 `builddir` 后在其内 configure）② **`builddir` 必须位于源码树内**（`config.status` 用 `../support/Makefile.in` 这类相对上一级的模板，配合声明 `layout()`）③ **`builddir/config.h` 要先就位**（Makefile 规则依赖它，upstream 由 `support/config.h.dist` 提供）④ **`config.status` 的临时目录套路要求构建目录在可写挂载上**（conan 缓存挂载会 `Permission denied`）；另加两条编译器相关：C23 下 `f()` 等价 `(void)`，且老 Makefile 常以 `CFLAGS = $(OPTIMIZE) …` **覆盖**工具链 CFLAGS → `-std=gnu17` 必须从 configure 的 `OPTIMIZE=` 传入

## 基本信息
- **严重度**: 3
- **类别**: build-system, autotools, environment
- **作者**: F120

## 错误特征
```
No rule to make target 'all'|rm: ./confstat.*: Permission denied|mv: bad './confstat.*'|No rule to make target 'config.h'|expected 0, have 2（旧代码）
```

## 根因分析
老式 autotools 工程把"构建目录就是源码树内的一个子目录"当作默认用法（`config.status` 里的 `Makefile:../support/Makefile.in`、`version.c.SH:../ircd/version.c.SH.in` 都是相对上一级的路径）， 而 Conan 默认把 source 与 build 分开（甚至未声明 `layout()` 时两者指向同一处、也不是源码树）： * 模板解析不到 → `config.status` 生成不出 Makefile → `make` 报 `No rule to make target 'all'`； * `builddir/config.h` 没人准备 → `No rule to make target 'config.h'`（upstream 流程靠 `support/config.h.dist`）； * autoconf 的 `config.status` 会建临时子目录并 `rm`/`mv`，实测 conan 缓存挂载会拒绝这些操作 （`Permission denied` / `mv: bad`），换到 `/data/storage/el2/base/cache` 后同一流程正常； * 现代 clang 默认 C23，`int f();` 等价 `int f(void)` → 老代码"声明空参、调用带参"硬报错； 而老 Makefile 往往用 `CFLAGS = $(OPTIMIZE) …` 覆盖工具链注入的 CFLAGS，所以 `-std=gnu17` 只从工具链传是**不生效**的。

## 推荐方案
**方法**: source-tree-local-builddir-plus-config-h-plus-writable-mount-plus-optimize-flag

**说明**: ①分辨工程的真实构建入口：若顶层 `configure` 是自写脚本，去看 Debian 打包（`debian/rules` 的 `override_dh_auto_*`）——本例官方做法是 `mkdir builddir && cp support/configure builddir/ && cd builddir && ./configure …`；②配方里声明 `layout()`（`basic_layout`）让 `source_folder` 指向真正源码树，并把工作目录（含 builddir）放在**源码树内**；③把 `support/config.h.dist` 之类模板复制为 `builddir/config.h`（Debian 用的是它自己的 `debian/maint/config.h`）；④构建目录优先选**可写挂载**（本例 `/data/storage/el2/base/cache`），不可用时退回并在日志说明（`config.status` 的临时目录 rm/mv 在缓存挂载上会失败）；⑤编译标志要落在工程真正使用的位置：老 Makefile 用 `$(OPTIMIZE)` 就传 `OPTIMIZE='-O2 -std=gnu17'`（与 Debian 的 `DEB_CFLAGS_MAINT_APPEND=-std=gnu17` 同源意图），并用 `grep '^CC_CFLAGS' <builddir>/Makefile` 回验；⑥autotools 工具在 Conan 2 里的导入是 `conan.tools.gnu`（不是 `conan.tools.autotools`）。

**修复命令**:
```
mkdir builddir && cp support/configure builddir/ && cp support/config.h.dist builddir/config.h && cd builddir && ./configure --with-zlib OPTIMIZE='-O2 -std=gnu17' && make all
```

**验证**:
```
① `grep -n 'config_files=' <builddir>/config.status`（看模板相对路径）② `ls <builddir>`（是否有 Makefile / config.h）③ `grep -nE '^CC_CFLAGS|^CFLAGS|^OPTIMIZE' <builddir>/Makefile`（确认标志是否真的进入编译命令）④ 失败时把构建目录换到可写挂载重试
```
