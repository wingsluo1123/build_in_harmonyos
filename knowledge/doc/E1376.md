# E1376: Makefile CFLAGS ?= 被环境 CFLAGS 顶掉导致 vendored include 目录丢失

## 基本信息
- **严重度**: 2
- **类别**: compat, headers, build-system, make, environment
- **作者**: EF9C

## 错误特征
```
js0n\.h' file not found|fatal error: '[a-z0-9_]+\.h' file not found
```

## 根因分析
上游 Makefile 使用 CFLAGS ?= -O3 -g -Wall -I$(JSONDIR) 形式,环境里已导出的 CFLAGS（conan MakeToolchain/设备 profile/worker shell）会让 ?= 完全不赋值,整条默认值连同 vendored 头文件目录一起被丢弃,LDFLAGS ?= -lm 同理

## 推荐方案
**方法**: 始终用 make 命令行变量显式传入完整 CFLAGS/LDFLAGS（命令行优先级高于环境）并补齐 -I<vendored include> 与 -lm;编译器取自 conan conf tools.build:compiler_executables 而非 shell ${CC}（R33）

**说明**: make 命令行变量优先级高于环境，显式传完整 CFLAGS/LDFLAGS 即可保住上游默认值

**修复命令**:
```
make <target> CFLAGS="${UPSTREAM_DEFAULT_CFLAGS} -fPIC -I<vendored include>" LDFLAGS="-lm" -j1
```

**验证**:
```
grep -n 'CFLAGS ?=' Makefile; echo CFLAGS=$CFLAGS
```
