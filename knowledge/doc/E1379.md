# E1379: PkgConfigDeps 只生成聚合 pc（缺组件 gio-2.0.pc/gobject-2.0.pc 等）导致 autoconf PKG_CHECK_MODULES 多模块查询失败——pkg.m4 预设变量整体旁路

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, conan, pkg-config
- **作者**: E57E

## 错误特征
```
Package gio-2.0 was not found|consider adjusting the PKG_CONFIG_PATH|no package .gio-2.0. found
```

## 根因分析
conan 的 PkgConfigDeps 生成器只按配方 pkg_config_name/聚合 cpp_info 生成单个 pc（如 glib/2.84.0 仅 glib-2.0.pc），而上游 configure.ac 的 PKG_CHECK_MODULES 一次查询多个组件模块名（glib-2.0 gio-2.0 gobject-2.0），缺任一 pc 即中止；宿主应用包（如 bitlbee/3.6 只含 bin 二进制）也无 .pc 可用

## 推荐方案
**方法**: pkg-m4-preset-variable-bypass

**说明**: pkg.m4 的 _PKG_CONFIG 对每个变量独立判断：若 <MODULE>_CFLAGS 与 <MODULE>_LIBS 环境变量同时非空，pkg-config 完全不执行（连版本检查都跳过）。配方在 generate() 里经 AutotoolsToolchain 环境注入六个变量（值全部来自 self.dependencies 路径，R33 合规）+ GLIB_GENMARSHAL 等工具变量；plugindir 之类的 PKG_CHECK_VAR 查询会落回上游 configure.ac 的默认分支（如 $libdir/bitlbee）。注意此 conan 版本 AutotoolsToolchain.environment() 是方法且 generate(env=...) 接受扩展 env（替换会丢 CC/CFLAGS）。实例：bitlbee-facebook 1.2.2（archives/b/bitlbee-facebook/1.2.2）。备选：自建组件 pc 文件目录置于 PKG_CONFIG_PATH 首位

**修复命令**:
```
tc=AutotoolsToolchain(self); env=tc.environment(); env.define('GLIB_CFLAGS', '-I<dep>/include/glib-2.0 ...'); env.define('GLIB_LIBS', '-L<dep>/lib -lglib-2.0 ...'); tc.generate(env=env)
```
