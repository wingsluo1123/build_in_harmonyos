# E1381: libtool 1.3.3 archive_cmds 把外部 -l 归入 old_deplibs 导致 .so 缺 DT_NEEDED

## 基本信息
- **严重度**: 3
- **类别**: autotools, linking, conan, libtool
- **作者**: E29C

## 错误特征
```
Error relocating .*\.so: g_[a-z_]+: symbol not found|undefined reference due to --no-allow-shlib-undefined
```

## 根因分析
远古 libtool（ltconfig 1.3.x，archive_cmds 用 $deplibs 拼装）在构建 shared library 时，会把非系统搜索路径下的 -l 依赖（典型为 conan 包提供的 glib/tdb）分类进 old_deplibs 而非 $deplibs，这些库根本不会交给 linker。产物 .so 的 DT_NEEDED 只剩 libc.so，却仍带着大量未解析外部符号；因构建 shared 时未开 --no-undefined，链接期不报错，缺陷被推迟到消费者：可执行文件链接期报 ld.lld error undefined reference due to --no-allow-shlib-undefined，或运行期报 Error relocating symbol not found。同一 libtool 链接出的可执行文件（如本包 bin/pcap）NEEDED 完整，可作对照判据。

## 推荐方案
**方法**: 在 package() 阶段绕过 libtool 重建共享库：用同时构建出的静态归档以 -Wl,--whole-archive 加 -Wl,--no-as-needed 直接链接出 .so，把 DT_NEEDED 修复在产物本身，而不是把 --allow-shlib-undefined 之类的负担推给下游（cpp_info.sharedlinkflags 亦不可靠，CMakeDeps 不传导）。重建后按 HMDFS 规则先 os.remove 再 os.symlink 恢复 soname 链接；输入缺失必须 raise，不可静默 return，否则修复会悄然失效。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
cc -shared -Wl,-soname,libfoo.so.1 -Wl,--whole-archive libfoo.a -Wl,--no-whole-archive -Wl,--no-as-needed -L<dep>/lib -l<dep> -o libfoo.so.1.0.0
```

**验证**:
```
llvm-readelf -d <pkg>/lib/libfoo.so.* | grep NEEDED
```
