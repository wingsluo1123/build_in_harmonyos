# E1382: 上游 CMake 若把数据目录用 find_path 找出来（如 indi-3rdparty 的 INDI_DATA_DIR 经 INDI_ROOT 命中），该变量会是**依赖包的绝对路径**，而驱动的 install(FILES … DESTINATION ${INDI_DATA_DIR}) 会把产物写进依赖包、本包反而没有该文件——修法是在 toolchain 里预置该变量为相对路径（find_path 对已定义变量跳过搜索）或补丁改相对目的地

## 基本信息
- **严重度**: 3
- **类别**: cmake, conan, packaging
- **作者**: E058

## 错误特征
```
install.*DESTINATION.*<依赖包>/share/indi|数据文件不在本包|share/indi/<新文件> 出现在依赖包目录
```

## 根因分析
indi-3rdparty 的 cmake_modules/FindINDI.cmake 用 `find_path(INDI_DATA_DIR NAMES drivers.xml PATH_SUFFIXES share/indi …)` 定位 INDI 数据目录。适配时把 INDI_ROOT 指向预构建 libindi 的 package_folder（这是让 finder 命中依赖包的必要手段），而 libindi 包里确实带 share/indi/drivers.xml → find_path 命中，INDI_DATA_DIR 被定为**依赖包的绝对路径**。随后 indi-talon6/CMakeLists.txt 的 `install(FILES ${CMAKE_CURRENT_BINARY_DIR}/indi_talon6.xml DESTINATION ${INDI_DATA_DIR})` 因目的地是绝对路径而忽略 CMAKE_INSTALL_PREFIX → XML 被写进 **libindi 的包目录**（实测确实写进去了），本包只有 bin/ 没有 share/indi → 消费者校验报 "INDI data file is missing"。

## 推荐方案
**方法**: preset-directory-variable-to-relative-path-in-toolchain

**说明**: 在 recipe 的 generate() 里用 `tc.variables["INDI_DATA_DIR"] = "share/indi"` 预置该变量为**相对路径**——CMake 的 find_path 对已定义（非 NOTFOUND）的变量会**直接跳过搜索**，因此既避免了写入依赖包，又让 install() 以 CMAKE_INSTALL_PREFIX（= 本包）为基准落到 share/indi/。此路不需改上游源码。若上游变量名不可预置（例如被 include() 后强制覆盖），备选是加补丁把 install 目的地改成相对的 `${CMAKE_INSTALL_DATADIR}/indi`（GNUInstallDirs 已 include）。

**修复命令**:
```
tc.variables["INDI_DATA_DIR"] = "share/indi" # generate() 内，tc.generate() 之前
```

**验证**:
```
① 构建后 `grep '^INDI_DATA_DIR' <build>/CMakeCache.txt`（若为绝对路径即命中本问题）② `ls <本包>/share/indi/`（应含驱动 XML）③ `git status`/`find` 检查依赖包目录是否被写入
```
