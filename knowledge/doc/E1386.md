# E1386: OHOS <utmpx.h> 只声明 struct utmpx：用 configure 缓存变量 ac_cv_header_utmpx_h=no 绕过（无平台宏）

## 基本信息
- **严重度**: 2
- **类别**: platform, headers, autotools
- **作者**: D3C5

## 错误特征
```
call to undeclared function 'setutxent'|call to undeclared function 'getutxent'|incompatible integer to pointer conversion assigning to 'utmp_t \*'|undefined symbol: setutxent
```

## 根因分析
OHOS sysroot 存在 <utmpx.h>，AC_CHECK_HEADERS 判定 header 存在 → config.h 定义 HAVE_UTMPX_H；但该头只声明 struct utmpx，setutxent/getutxent/endutxent 等函数既未声明也未由 libc 导出，源码按 utmpx 分支编译即报隐式声明/类型转换错误。OHOS 的 <utmp.h> 提供可用的 stub API（setutent/getutent/endutent/utmpname，getutent() 返回 NULL）

## 推荐方案
**方法**: configure-cache-variable

**说明**: 配方 generate() 在 OHOS 下追加 configure 参数 ac_cv_header_utmpx_h=no，让源码走 <utmp.h> 分支；相比改源码插 __OHOS__ 守卫（E121 原方案），此写法不引入平台宏，满足 R8/PF5

**修复命令**:
```
tc.configure_args.append('ac_cv_header_utmpx_h=no')  # 仅 self.settings.os == 'OHOS'
```

**验证**:
```
clang -fsyntax-only -I. -Ilocal -Ilibrary/include -DHAVE_UTMPX_H src/w.c  # 复现报错
```
