# E1389: ①`Build-Depends` 里带 `<!nocheck>` 的条目（本例 shunit2）是**测试框架、不是运行期/构建期必需依赖**——制品仓没有它**不应据此放弃该库**，而应在 build() 内从上游取真实 tarball（钉 sha256）仅用于跑测试、不进产物；②解析测试框架输出时有三处字符级坑：**shell 重定向会吞输出**（要用 `subprocess` 直接捕获）、**框架会输出 ANSI 颜色码**（解析前必须剥离）、**test_package 环境的 PATH 可能不含 `/bin`**（`sh` 要按绝对路径候选解析）

## 基本信息
- **严重度**: 2
- **类别**: testing, environment, tooling
- **作者**: D089

## 错误特征
```
未取得 .* 运行结果（可能未真跑）|Ran \\x1b\[|FileNotFoundError: 'sh'|shunit2|<!nocheck>
```

## 根因分析
①包管理器语义：`<!nocheck>` 表示"仅在没有测试时才可省略"，属测试期依赖；把它当成硬依赖会导致 白放弃可适配的库。②输出解析：实测三个"看起来没问题但解析失败"的场景—— * 用 `bash -c "… > log 2>&1"` 时输出跑到了 conan 控制台、日志文件为空 → 误判"未真跑"； * shunit2 给数字/OK 着色，repr 是 `Ran \x1b[1;36m6\x1b[0m tests.` → `Ran (\d+) tests?` 永远匹配不到； * 消费者校验进程的 PATH 可能不含 `/bin` → `subprocess.run(["sh", …])` 直接 `FileNotFoundError: 'sh'`。

## 推荐方案
**方法**: fetch-test-only-framework-with-pinned-hash-and-capture-output-ansi-stripped

**说明**: ①**判定依赖性质**：`Build-Depends` 里带 `<!nocheck>` 的条目是测试专用 → 制品仓缺失不构成放弃理由，按"缺环境就下"从上游/Debian pool 取真实 tarball 并钉 sha256（写到 conandata 的独立小节，注明"仅测试用、不进产物"）；②**捕获输出用 `subprocess.run(..., stdout=PIPE, stderr=STDOUT)`**，不要依赖 shell 重定向（否则日志可能为空而误判）；③**解析前剥 ANSI**：`re.sub(r"\x1b\[[0-9;]*[A-Za-z]", "", raw)`，再 `" ".join(text.split())` 归一化空白，然后再匹配 `Ran (\d+) tests?` / `OK` / `FAILED`；④**shell 用绝对路径候选**：`shutil.which("sh")` → `/bin/sh` → `/usr/bin/sh` → `/system/bin/sh`，都找不到才按具名环境信号 SKIP；⑤失败时把捕获输出的**末尾若干行 + repr** 打进错误信息，避免"看起来一样却解析不到"的盲目排查。

**修复命令**:
```
python3 -c "import subprocess,re;p=subprocess.run(['/bin/sh','tests/functions_test'],stdout=subprocess.PIPE,stderr=subprocess.STDOUT);t=re.sub(r'\x1b\[[0-9;]*[A-Za-z]','',p.stdout.decode('utf-8','replace'));print(re.search(r'Ran (\d+) tests?',' '.join(t.split())))"
```

**验证**:
```
①`grep -n '<!nocheck>' debian/control`（确认是测试专用）②跑测试时打印捕获输出的 `repr()`（可立刻看出 ANSI 码/空白异常）③`grep -n 'sh' <test>/*` 与 `command -v sh`（确认 shell 是否可解析）
```
