# E1391: Header-only C++03 short-name macros expand to unqualified library-namespace symbols; silent-success test runners need an explicit pass flag for evidence

## 基本信息
- **严重度**: 2
- **类别**: headers, conan, testing
- **作者**: CL9E

## 错误特征
```
use of undeclared identifier 'the_log'|LOG_[A-Z]+ unqualified|silent success exit 0|All .* selected tests passed
```

## 根因分析
clue-style libraries define short LOG_* macros whose bodies reference helper names (e.g. the_log()) WITHOUT namespace qualification; the names resolve only when the consumer TU imports the library namespace the way upstream test TUs do. Qualified-macro spelling clue::LOG_INFO(x) is invalid because the macro is preprocessed before qualification. Additionally old lest_cpp03 builds print nothing on success (summary guarded by failures>0 or output.pass()), so a passing default run yields exit 0 with zero countable evidence.

## 推荐方案
**方法**: consumer-namespace-import-plus-pass-flag-evidence

**说明**: Write test_package sources mirroring the upstream test TU preamble (using namespace <lib>;) instead of qualifying macro calls; keep the upstream Makefile invocation as the blocking gate (failures do print) and collect numeric evidence from a separate run with the runner's pass-reporting flag (clue/lest_cpp03: ./test_clue -p).

**修复命令**:
```
make -j2 -C tests && (cd tests && ./test_clue -p)
```

**验证**:
```
conan create with upstream tests in build(); conan test for consumer; -p run for counts
```
