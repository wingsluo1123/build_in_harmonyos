# E1393: sane-backends 制品包把后端搜索路径编译为 /lib/sane（OHOS 不存在）导致无法枚举任何 SANE 设备；测试期可用 LD_PRELOAD 官方后端规避

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, runtime, testing, third-party-package
- **作者**: C8F7

## 错误特征
```
No scanners were identified|open of device .* failed: Invalid argument|sane_get_devices|/lib/sane
```

## 根因分析
sane-backends 1.2.1 的 libsane-dll.so 以 configure 前缀 / 编译，PATH_SANE_LIB 固化为 /lib/sane；OHOS 上 /lib 是指向只读 /system/lib 的软链，该目录不存在，故 dll 加载器无法 dlopen 任何 libsane-<backend>.so，sane_get_devices() 恒返回空列表（scanimage -L 无输出、sane_open 返回 SANE_STATUS_INVAL），所有消费者（libksane/ksanecore 等）都无法打开设备。

## 推荐方案
**方法**: 测试期规避：SANE 后端本身即完整 libsane 实现（导出 sane_init/sane_open/sane_read），在 test_package 运行环境中 LD_PRELOAD=<sane-backends>/lib/sane/libsane-test.so.1 直接驱动官方 test 虚拟后端，并设 SANE_CONFIG_DIR 指向从包内 etc/sane.d 复制的 test.conf（libksane 26.04.0 实践：端到端取图 314x393 通过）。根治：为 sane-backends 单独提依赖项修复 PR，把后端搜索路径改为包内 lib/sane 或引入可覆盖配置。

**说明**: 在测试环境中以 LD_PRELOAD 直接加载官方 libsane-test 后端（绕过 /lib/sane 缺陷），并用 SANE_CONFIG_DIR 指向复制的 test.conf，使消费者测试能够真实打开虚拟扫描仪并完成一次完整扫描

**修复命令**:
```
LD_PRELOAD=${SANE_PKG}/lib/sane/libsane-test.so.1 SANE_CONFIG_DIR=${TEST_BUILD}/sane.d ${TEST_BIN}/test_scan_flow
```

**验证**:
```
LD_PRELOAD=$(conan cache path sane-backends/1.2.1)/lib/sane/libsane-test.so.1 SANE_CONFIG_DIR=<test.conf 所在目录> scanimage -L
```
