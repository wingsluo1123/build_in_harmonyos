# E1396: numdiff/ssplit(): 分隔符串以分隔符结尾时指针向量槽位未初始化，musl 上向量扫描 SIGSEGV（malloc → calloc）

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, runtime
- **作者**: BD92

## 错误特征
```
Segmentation fault.*numdiff|numdiff.*-D.*SIGSEGV|ssplit.*uninitialized.*vector|is_char_in_vector.*SIGSEGV|core dumped.*numdiff
```

## 根因分析
ssplit(str, sep) 统计子串数 n 时，若 str 以 sep 结尾会把 n 多计 1；分配 n+1 个指针后仅填充 [0,i-1]，[i,n-1] 未初始化。glibc malloc 常返回清零内存掩盖该 UB，musl malloc 返回非零内存 → is_char_in_vector/remove_duplicates_from_string_vector 对垃圾指针 strchr/strcmp → 崩溃

## 推荐方案
**方法**: fix-uninitialized-pointer-vector-malloc-to-calloc

**说明**: 将 ssplit() 中 `malloc((n+1)*sizeof(char*))` 改为 `calloc(n+1, sizeof(char*))`，使所有槽位初始为 NULL，向量在正确位置终止；或等价地在填充循环后补 `sv[i] = NULL;`

**修复命令**:
```
sed -i 's/malloc ((n+1)\\*sizeof(char\\*))/calloc ((n+1), sizeof(char*))/' linesplit.c
```

**验证**:
```
printf '1  2\n3  4\n' > a; printf '1  2\n3  4\n' > b; numdiff -D 'a ' a b; echo "exit=$?"（修复前 exit=139 SIGSEGV，修复后正常比较）
```
