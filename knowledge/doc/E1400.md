# E1400: OHOS 制品生态无 .typelib，运行时依赖 GIRepository 的程序/测试必然失败

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, limitation, ohos
- **作者**: B1AB

## 错误特征
```
Typelib file for namespace .* not found|g-irepository-error-quark
```

## 根因分析
OHOS 制品仓的 glib2/2.88.0 以 introspection=disabled 构建，不生成 GLib/GObject/Gio 的 .typelib；gobject-introspection 包与 OHOS /system 系统镜像中也无任何 .typelib 文件。任何运行时调用 gi_repository_require() 加载命名空间的程序（如 template-glib 的 test-expr 表达式求值、pygobject 类绑定）在 OHOS 上必然报 Typelib file for namespace 'GLib' not found

## 推荐方案
**方法**: test-skipped-with-evidence

**说明**: 上游测试必须真实执行并采集失败证据（meson-logs/testlog.txt），对命中本模式的用例逐项申报 test_skipped（技术原因=平台无 typelib 数据），执行数/通过数/跳过数如实分开申报；不删除测试、不跳过整个套件、不伪造通过率

**修复命令**:
```
meson test -C ${BUILD_DIR} ${TEST_NAME}  # 必须用例级执行采集证据
```

**验证**:
```
find /system /data/service/hnp -name '*.typelib' 与 conan 包目录内 find '*.typelib'（均返回空）；复现命令 meson test -C builddir test-expr
```
