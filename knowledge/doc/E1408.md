# E1408: Prefer a published Qt feature variant before trimming required modules

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, ohos, cmake, conan
- **作者**: A434

## 错误特征
```
Qt6PrintSupportConfig.cmake|The following Qt components were not found: PrintSupport|Conflict between qtbase/6.11.1 and qtbase/6.11.1.3
```

## 根因分析
The default published qtbase recipe can disable a module required by an upstream Qt application even though another published HarmonyOS qtbase recipe variant contains it. Transitive Qt packages may still pin the older recipe version, causing a Conan version conflict or a missing binary package after selecting the capable provider.

## 推荐方案
**方法**: select-published-provider-and-override-transitive-pin

**说明**: Check all published HarmonyOS qtbase variants for the required CMake module; if an enabled provider exists, require that version with override=True so transitive Qt recipes converge before building.

**修复命令**:
```
self.requires("qtbase/6.11.1.3", override=True)
```

**验证**:
```
Inspect the selected provider package for Qt6PrintSupportConfig.cmake, then run conan graph info with the OHOS aarch64 profile and verify every Qt requirement resolves to one qtbase version.
```
