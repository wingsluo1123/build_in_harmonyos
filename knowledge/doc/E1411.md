# E1411: maven-bundle-plugin 4.2.1（内含旧 bnd）在 JDK 17.0.13+ 下抛 ConcurrentModificationException，导致 Maven 构建失败于 osgi-manifest 目标——pin 到 5.1.9（bnd 5.1.2）即可；同类还有 maven-javadoc-plugin 的 doclint heading-sequence 报错（<doclint>none</doclint>）

## 基本信息
- **严重度**: 3
- **类别**: build-system, java
- **作者**: A10A

## 错误特征
```
Internal error in maven-bundle-plugin: ConcurrentModificationException
```

## 根因分析
maven-bundle-plugin 4.2.1（2019 年版本，内含旧版 bnd）与 JDK 17.0.13+ 的 bnd/ZipFile 交互存在缺陷，构建到 manifest 生成（osgi-manifest 目标）时抛 java.util.ConcurrentModificationException，Maven 直接 BUILD FAILURE。实测报错：Failed to execute goal org.apache.felix:maven-bundle-plugin:4.2.1:manifest (osgi-manifest) on project jakarta.activation-api: Internal error in maven-bundle-plugin: ConcurrentModificationException。同一类"老插件 + 新 JDK"问题还包括 maven-javadoc-plugin 的 doclint：JDK 17.0.13+ 会强制校验 javadoc 注释的标题层级（<h3> 出现在 <h1> 之后即报 heading-sequence），需 <doclint>none</doclint>。

## 推荐方案
**方法**: patch-pom-to-pin-newer-maven-bundle-plugin

**说明**: 在归档的 patches/ 下加一个补丁改上游 pom：把 maven-bundle-plugin 的 <version>4.2.1</version> 改为 5.1.9（bnd 5.1.2）；如构建再报 javadoc heading-sequence，则在同一补丁里给 maven-javadoc-plugin 的 <configuration> 加 <doclint>none</doclint>。补丁用标准 unified diff（a/pom.xml、b/pom.xml 头，strip=1），并在 conandata.yml 的 patches: 段登记（patch_file / patch_description / patch_type: portability）。

**修复命令**:
```
patch -p1 --dry-run < patches/<pkg>-0001-jdk17-bundle.patch # 先 dry-run 确认可干净应用
```

**验证**:
```
打补丁前后各跑一次 mvn：`mvn clean package -B -DskipTests=false`（失败时日志含 ConcurrentModificationException；成功后 BUILD SUCCESS）；补丁即 pom 中该插件 <version> 由 4.2.1 改为 5.1.9
```
