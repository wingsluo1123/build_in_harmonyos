# E1412: 无构建系统的非 header-only C 库（嵌入式协议栈）conan 直接编译打包 + example 演示目录误提升

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan
- **作者**: 9FEC

## 错误特征
```
嵌套源码检测: 找到源码在 example|no such file or directory: CANopen.c|tools.build:compiler_executables:c.*does not exist
```

## 根因分析
init_build._promote_nested_source 仅按 C/C++ 构建标记识别源码子目录；无顶层构建标记的嵌入式协议栈 tarball 会把含 Makefile 的 example/ 演示目录误提升为源码根；且 conanfile build() 用相对路径编译 + 默认 cwd 为 build 目录时找不到源文件

## 推荐方案
**方法**: 1) 误提升时手动重建 .orig/.work（rm -rf; tar xzf --strip-components=1; cp -a; 重写 .tarball-sha256 并核对）; 2) conanfile build() 用 self.conf.get("tools.build:compiler_executables", default={}) dict 形式取编译器（R33），源码全部绝对路径并 cwd=src 编译，llvm-ar 归档; 3) package() 保留子目录头文件布局（CANopen.h include "301/CO_driver.h"）; 4) test_package 用上游 blank 驱动作为消费者硬件抽象层，调用 CO_new/CO_CANinit/CO_LSSinit/CO_CANopenInit/CO_CANopenInitPDO/CO_process/CO_delete 验证真实运行; 5) 提交前清理 conan-verify 残留 .ghfast-bak/.orig 并恢复官方 URL

**说明**: 无构建系统嵌入式协议栈 C 库适配要点：手动重建 .orig/.work 修正 example/ 误提升；dict 形式 compiler conf + 绝对路径 cwd=src 编译；头文件保留子目录布局；test_package 用 blank 驱动做消费者用例

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
ohc-run.py conan-verify canopennode 4.1 && ohc-run.py finish canopennode 4.1 published
```
