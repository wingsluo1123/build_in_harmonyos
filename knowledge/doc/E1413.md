# E1413: ArkTS/NAPI 像素缓冲集成契约：image.createPixelMap 不接受 NAPI external ArrayBuffer（colors mismatch/进程崩溃）；异步图像对象必须在全部 await 完成后 release（否则 use-after-free 崩溃）

## 基本信息
- **严重度**: 3
- **类别**: ohos, packaging, runtime, api, memory
- **作者**: 9C4C
- **来源 PR**: 10116

## 错误特征
```
colors mismatch|PixelMapNapi|ReadPixelsToBuffer|SIGSEGV\(SEGV_MAPERR\)
```

## 根因分析
两个并列契约（curtain 0.3 真机实测）。1) 内存语义：NAPI 用 napi_create_external_arraybuffer 返回像素缓冲（零拷贝、内存归 C 核心/NAPI finalizer 管理）时，ArkTS 的 image.createPixelMap(buffer, options) 不接受其内存/长度语义，实测报 PixelMapNapi: colors mismatch（或进程崩溃），无法建立 PixelMap；必须用 napi_create_arraybuffer + memcpy 返回拷贝。2) 生命周期：image 的 createPixelMap/getImageInfo/readPixelsToBuffer 是异步接口（内部经 napi_queue_async_work_with_qos 排队），若在 await 全部完成前 release ImageSource/PixelMap，异步回调 resolve 后 Promise 续体恢复执行时会触碰已释放对象，产生 SIGSEGV(SEGV_MAPERR)，cppcrash 崩溃栈特征：主线程 #01 at initAsync entry (Curtain.ets) + 提交栈 OHOS::Media::PixelMapNapi::ReadPixelsToBuffer → napi_queue_async_work_with_qos。

## 推荐方案
**方法**: copied-arraybuffer-and-release-after-all-awaits

**说明**: 1) NAPI 像素输出必须用 napi_create_arraybuffer(env, len, &data, &value) + memcpy(data, pixels, len) 返回拷贝，禁止 napi_create_external_arraybuffer；2) ArkTS 侧用 try/finally 或线性顺序，把所有 image 异步调用（source.createPixelMap / decoded.getImageInfo / decoded.readPixelsToBuffer）全部 await 完成之后，再统一 release() ImageSource 与 PixelMap；3) 多对象/循环场景把 release 集中到最后一个 await 之后（不要在中间 await 前释放任何 image 对象）；4) 验收口径：hilog 不再出现 colors mismatch 且 pixelMap=true；/data/log/faultlog/faultlogger 不再新增该应用 cppcrash；snapshot_display 截图出现真实画面。

**修复命令**:
```
hdc shell hilog -x | grep -E "PixelMapNapi: colors mismatch|pixelMap=|setSource="
```

**验证**:
```
hdc shell hilog -x | grep -E "PixelMapNapi|CurtainPage" ; hdc shell "ls -t /data/log/faultlog/faultlogger/ | grep curtainhost" ; hdc shell snapshot_display -f /data/local/tmp/shot.jpeg
```
