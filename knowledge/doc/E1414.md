# E1414: 上游 UI 工具包在 OHOS 无原生显示后端（仅 Broadway）时的应用级运行时适配模式：ArkUI 原生宿主 + 行为核心 C 移植，窗口矩形=幕布/组件区域

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, ohos, portability, runtime
- **作者**: 9C4B
- **来源 PR**: 10116

## 错误特征
```
cannot open display|Gtk-WARNING.*cannot open display|GdkBroadwayDisplay|only.*[Bb]roadway|no native display backend
```

## 根因分析
OHOS 已发布的 GTK 3.24.43 仅启用 Broadway（HTML5/浏览器）后端（X11/Wayland 关闭）；原生进程无 DISPLAY/WAYLAND_DISPLAY，上游 gtk_init 直接失败（Gtk-WARNING: cannot open display，退出 1）。即使启动 broadwayd，GTK 也只是渲染到浏览器画布，不能覆盖 HarmonyOS 原生桌面，也不能提供桌面窗口的 input shape/全屏/置顶语义。结论：上游窗口层在 OHOS 不可用，应用必须在原生 UI 栈上重建宿主，并把与平台无关的行为核心（几何状态机/缩放）移植为可独立测试的 C 代码（curtain 0.3 实测：34 个补丁全为新增文件，上游源码零修改）。

## 推荐方案
**方法**: arkui-native-host-with-ported-behavior-core

**说明**: 1) 不修改上游源码，新增 ArkUI 宿主工程（独立包名、全屏沉浸窗口）承载渲染与输入；2) 把平台无关的行为核心逐分支移植为无依赖 C（几何状态机=上游 callbacks.c；缩放语义=上游 utils.c::scale_surface，PNG 由平台 image 解码后 C 侧双线性+边缘镜像缩放）；3) 窗口矩形=幕布/组件矩形：初始全屏覆盖，拖拽释放后 recover()+moveWindowToAsync+resizeAsync 把窗口调整到剩余区域，窗口之外即桌面，天然实现“揭开区域可见 + 点击穿透”（等价上游 gtk_widget_input_shape_combine_region）；4) 触摸坐标=vp2px(windowX)+winX/winY 折算到屏幕绝对坐标驱动 C 状态机；5) 二进制资源（PNG）由 Conan package() 从上游源码树注入宿主 rawfile，不进补丁管线，图标用文本 SVG；6) 验证=无头 C 回归测试 + test_package + 真机 uinput/snapshot_display 逐行为取证（每步截图+日志）；7) 权限类限制（WINDOW_TOPMOST 返回 201、系统 Dock 恒在最上、自由窗口顶部热区）如实记录为 limitation。

**修复命令**:
```
hdc shell uinput -M -g 3000 1000 1700 1000 800 && hdc shell snapshot_display -f /data/local/tmp/curtain.jpeg
```

**验证**:
```
strings <gtk-pkg>/lib/libgtk-3.so | grep -E "broadway|wayland|x11" ; ./curtain 2>&1 | grep "cannot open display" ; hdc install -r entry-default-signed.hap && hdc shell aa start -b com.kasumizawamiyuu.curtainhost -a EntryAbility && hdc shell uinput -M -g 3000 1000 1700 1000 800 && hdc shell snapshot_display -f /data/local/tmp/curtain.jpeg
```
