# E1415: 非 worker OHOS 设备上 OCaml（Conan registry 包）原生链接的工具链闭包：GNU as 缺失、编译器程序路径烘焙与 -cc 覆盖丢参的诊断与设备侧修复

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, linking, environment, ocaml
- **作者**: 9C4A
- **来源 PR**: 14711

## 错误特征
```
sh: as: inaccessible or not found|Error: I/O error: as .*camlasm.*\.s|Error: I/O error: /data/service/hnp/bin/clang|ld\.lld: error: undefined symbol: main|undefined symbol: caml_(call_gc|alloc1|raise_exn)|Scrt1\.o
```

## 根因分析
(1) 制品仓 ocaml/4.14.1.1.x 由 CI worker 构建，Config.native_c_compiler 烘焙了 worker 绝对路径 /data/service/hnp/bin/clang，无 worker 工具链的设备上该路径不存在，ocamlopt 原生链接报 Error: I/O error: /data/service/hnp/bin/clang ...；(2) OHOS 镜像通常只有 LLVM 集成汇编器（clang -c），没有 GNU binutils 的 as，ocamlopt 把 aarch64 汇编交给裸命令 as，报 sh: as: inaccessible or not found / Error: I/O error: as ... camlasm*.s；(3) 以 -cc / OCAMLPARAM=_,cc=<cmd> 覆盖 C 编译器时，驱动用该命令整体替换 native_c_compiler 字符串，驱动追加的链接参数随之中断：.cmxs 共享链接丢 -shared（lld 按可执行方式链接并拉入 Scrt1.o，报 undefined symbol: main），可执行链接丢 -Wl,-E（宿主不再导出 OCaml 运行时符号，运行时插件 caml_* 解析失败）。

## 推荐方案
**方法**: device-local-ocaml-link-toolchain-closure

**说明**: 设备侧三步闭包：(a) as shim：exec "${CC:-clang}" -c "$@"；(b) ccwrap：-c 编译透传，*.cmxs/.so 补 -shared，可执行链接补 -Wl,-E；(c) profile [buildenv]/[runenv] 前置 shim 目录到 PATH 并导出 OCAMLPARAM=_,cc=<shim_dir>/ccwrap（runenv 覆盖 conan test 环境）。配套：配方侧 OCAMLLIB=<ocaml_prefix>/lib/ocaml；dune 安装树跟随符号链接复制。要点：闭包属设备侧工装，不写入归档（CI worker 原样可构建）。

**修复命令**:
```
printf '#!/bin/sh\nexec "${CC:-clang}" -c "$@"\n' > ~/local/bin/as && chmod +x ~/local/bin/as；ccwrap（cmxs→-shared；exe→-Wl,-E；-c 透传）；~/.conan2/profiles/ohos-aarch64{-device} 的 [buildenv]/[runenv] 设 OCAMLPARAM=_,cc=<shim_dir>/ccwrap 且 PATH=+(path)/<shim_dir>
```

**验证**:
```
P=<ocaml_pkg>; $P/bin/ocamlopt -config | grep -E "c_compiler|native_c_compiler|asm"; command -v as || echo "as missing"; OCAMLLIB=$P/lib/ocaml $P/bin/ocamlopt t.ml -o t.exe; OCAMLPARAM='_,cc=clang' $P/bin/ocamlopt -shared a.cmx -o a.cmxs
```
