# E1419: X11 家族在 ohpcd 制品仓按 .so 主版本命名：libxi/libxtst/libxext/libxfixes 固定拉 libx11/6.4.0，顶层再声明 libx11/1.8.x 会触发 conan 图版本冲突

## 基本信息
- **严重度**: 2
- **类别**: platform, build-system, conan
- **作者**: 9389

## 错误特征
```
Version conflict: Conflict between libx11/.* and libx11/.* in the graph|Conflict originates from libxi/|libx11/1\.8\.[0-9]+ vs libx11/6\.4\.0
```

## 根因分析
制品仓同时存在两套 X11 命名：旧的按上游版本号命名（libx11/1.8.13、libxi/1.8.3、libxtst/1.2.5）与按 .so 主版本命名的新组（libx11/6.4.0 = libX11.so.6.4.0、libxi/6.1.0、libxtst/6.1.0、libxext/6.4.0、libxfixes/6.1.0）。6.x 组的 recipe 内部固定 requires libx11/6.4.0，因此任何顶层声明 libx11/1.8.13 的 recipe 都会在 conan graph 解析阶段爆 "Version conflict: Conflict between libx11/6.4.0 and libx11/1.8.13 (Conflict originates from libxi/...)"，构建尚未开始即失败

## 推荐方案
**方法**: align-x11-family-to-soname-version-group

**说明**: 把 recipe 的 X11 依赖整体对齐到 6.x 同源组（libx11/6.4.0 + libxi/6.1.0 + libxtst/6.1.0），不要混用 1.8.x 旧 ref；先 conan graph info / conan download --only-recipe 确认组内每个 ref 已发布，再写 requires

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
conan graph info archives/x/xclicker/1.5.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
