# E1423: 上游 CMake 只 `target_link_libraries(... ${NOVA_LIBRARIES})` 而 `include_directories()` 不含该依赖的头目录；当主依赖的头（libindi 的 libastro.h）间接 `#include <libnova/utility.h>` 时编译报 fatal error——修法是用 ConanToolchain 的 extra_cflags/extra_cxxflags 注入依赖头目录（R33 合规，不改上游源码）

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, conan
- **作者**: 8D5D

## 错误特征
```
fatal error: 'libnova/utility.h' file not found
```

## 根因分析
indi-talon6 的头链是 talon6.h → indidome.h（libindi 的头）→ libastro.h → `#include <libnova/utility.h>`。而上游 CMakeLists 里只有 `target_link_libraries(indi_talon6 ${INDI_LIBRARIES} ${NOVA_LIBRARIES})` 与 `include_directories(${INDI_INCLUDE_DIR})`——**没有任何地方把 NOVA 的头目录加进 编译搜索路径**（工程假设 libnova 装在系统 /usr/include）。在 Conan 交叉构建下 libnova 位于独立 package_folder，于是编译失败。

## 推荐方案
**方法**: inject-dependency-include-dir-via-cmake-toolchain-flags

**说明**: 在 recipe 的 generate() 里对每个"头目录未被上游传入"的依赖追加编译标志： `tc.extra_cflags.append('-I"%s"' % dep_inc)` 与 `tc.extra_cxxflags.append('-I"%s"' % dep_inc)` （dep_inc 取自该依赖的 cpp_info.includedirs[0] 与 package_folder 拼接）。 走 ConanToolchain 参数而非裸环境变量（R33），与仓库既有做法一致（libindi 配方用同样方式注入 fftw 头）。不改上游源码。

**修复命令**:
```
tc.extra_cflags.append('-I"%s"' % nova_inc) && tc.extra_cxxflags.append('-I"%s"' % nova_inc)
```

**验证**:
```
编译日志出现 `fatal error: '<dep>/<header>.h' file not found`；修复后可用 `grep -o -- '-I[^ ]*<dep>[^ ]*' <build>/CMakeFiles/<target>.dir/flags.make` 确认标志已注入
```
