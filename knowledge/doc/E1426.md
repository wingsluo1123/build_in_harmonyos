# E1426: 手写 Makefile 硬编码 g++/-static：OHOS 上 make Error 127，且产物为非 PIE 的 ET_EXEC

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, make, packaging, hardening
- **作者**: 8644

## 错误特征
```
make: (g\+\+|gcc): No such file or directory\|make: \*\*\* \[Makefile:[0-9]+: .*\.o\] Error 127\|Type: *EXEC \(Executable file\)\|PIE disabled
```

## 根因分析
上游手写 Makefile 把 GNU 工具链名与链接标志硬编码：GPP = g++（OHOS aarch64 工具链只提供 clang++，原样构建立即 make Error 127）；CFLAGS = / LDLIBS = 用硬赋值会丢弃工具链传入的 CFLAGS/LDFLAGS；LDLIBS 中的 -static 产出非 PIE 的 ET_EXEC（readelf -h 显示 Type: EXEC），不满足鸿蒙硬化基线（conan-verify L4 报 PIE disabled）。

## 推荐方案
**方法**: makefile-toolchain-injection-and-static-pie

**说明**: 补丁把 GPP 改为 $(CXX)（由 Conan tools.build:compiler_executables 注入，满足 R33 禁止裸用 shell 变量），CFLAGS 改 +=、LDLIBS 改 $(LDFLAGS) 让工具链标志生效；若上游 -static 的"自包含单文件二进制"语义需要保留（OHOS CLI 不保证共享 libc++ 可用），改用 -static-pie：既保持 DT_NEEDED=0，又产出 PIE + full RELRO + NX。

**修复命令**:
```
'-GPP = g++ / +GPP = $(CXX) ; -CFLAGS = / +CFLAGS += ; -LDLIBS = -lm -static / +LDLIBS = $(LDFLAGS) -lm -static-pie'
```

**验证**:
```
$CXX_make -j1 && readelf -h ./<bin> | grep Type   # 期望 DYN；readelf -dW ./<bin> | grep -E "BIND_NOW|NEEDED"
```
