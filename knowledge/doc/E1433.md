# E1433: HMDFS 上执行的 ELF 降级到 SELinux adhoc_bin 域后无法 execve/加载 HMDFS 文件

## 基本信息
- **严重度**: high
- **类别**: platform
- **作者**: 79FC

## 错误特征
```
Permission denied|configure: Permission denied|exit 126|Error loading shared library|EACCES execve
```

## 根因分析
在 HarmonyOS PC 上，凡是从 HMDFS（/storage/Users/...）执行的可执行文件（如 pip 装在 ~/usr/local/bin 的 conan、python3 包装脚本背后的 ad-hoc ELF）都会触发域转换到受限 SELinux 域 u:r:adhoc_bin:s0；该域被策略禁止 execve HMDFS 上的任何文件（包括本进程刚创建并 chmod 755 的脚本），也无法从 HMDFS 加载 .so。症状极易误判为文件权限位问题：stat 显示 0o770/0o755、os.access(X_OK)=true、shell 侧（u:r:develop_tools_hap:s0 域）执行同一文件却成功，且 HMDFS 忽略 chmod（E046）进一步误导排查方向。实测：bash/python3(受信任)域 develop_tools_hap 可执行；conan/用户目录 python3 进程域 adhoc_bin 对 configure 直接 execve、sh -c、conanbuild.sh 环境、自建 0o755 脚本全部 EACCES；Conan 缓存迁到 appdat(el2 cache) 也无效

## 推荐方案
**方法**: trusted-python-shim

**说明**: 用受信任 bundle python 建 shim 统一入口替代 ~/usr/local/bin/conan；ohc-run.py 同理需要 python3 shim。进程保持在 u:r:develop_tools_hap:s0 域，execve HMDFS 脚本与加载 HMDFS .so 恢复正常。完整 test_package（需加载 HMDFS 上的依赖 .so）还需把 CONAN_HOME 指向非 HMDFS 目录（如 /data/storage/el2/base/cache/conan-home）

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
cat /proc/self/attr/current; ~/usr/local/bin/python3 -c "print(open('/proc/self/attr/current').read().strip())"; /data/storage/el1/bundle/libs/arm64/python/bin/python3 -c "print(open('/proc/self/attr/current').read().strip())"
```
