# E1440: Conan 构建环境导出的 CFLAGS 遮蔽上游 Makefile 的条件赋值默认值，导致项目自带 -I 包含路径丢失

## 基本信息
- **严重度**: 2
- **类别**: compat, headers, build-system, make
- **作者**: 5C0F

## 错误特征
```
file not found with <angled> include|fatal error: .*\.h: No such file or directory|No such file or directory.*\.h
```

## 根因分析
上游 Makefile 用条件赋值（CFLAGS ?=）定义默认编译参数，其中包含项目自身头文件目录（如 -Isrc）；当 recipe 通过构建环境/Toolchain 注入 CFLAGS 时条件赋值不再生效，项目的 -I 全部丢失，编译在第一个以 <subdir/header.h> 形式引用的内部头文件处报 file not found

## 推荐方案
**方法**: replay-upstream-default-cflags

**说明**: 在 recipe 的 build() 中显式复述上游 Makefile 的默认 CFLAGS（含全部 -I）后再拼接 Conan 工具链与依赖 flag；不要依赖 Makefile 自身的默认值

**修复命令**:
```
make CC="${CC}" CFLAGS="<上游默认 CFLAGS 全文> ${依赖 include}" LDFLAGS="${依赖 lib}" -j1
```

**验证**:
```
make -n | grep -c -- '-Isrc'   # 或对比 recipe 传入 CFLAGS 与 Makefile 默认 CFLAGS 的差集
```
