# E1442: PARI/GP 批处理脚本两坑：注释行尾反斜杠被当续行吞掉函数定义（0 用例仍 rc=0）；该 gp 构建无 file_exists/is_file/wildcards 文件系统原语

## 基本信息
- **严重度**: 3
- **类别**: portability, testing, gp-script, pari
- **作者**: 5A6B

## 错误特征
```
not a function in function call|error opening input file|SUMMARY pass=0 fail=0 total=0
```

## 根因分析
GP 词法把行尾反斜杠视为续行：以 GP 注释（双反斜杠）开头的说明行若以反斜杠结尾（常见于把 shell 命令示例换行写进注释），注释会跨行合并，把紧随其后的用户函数定义一并吞进注释。运行期报 not a function in function call，但批处理模式仍返回 rc=0，测试静默退化为 0 用例（假绿）。另一独立事实：制品仓发布的 pari/2.17.4 的 gp 未编译 OS 文件层，file_exists / is_file / is_dir / wildcards 都不是函数（extern 可用），GP 侧无法自枚举目录。

## 推荐方案
**方法**: 一、GP 注释行禁止以反斜杠结尾，命令示例写成整行；二、需要枚举被测目录时由外部脚本（Python）枚举并生成 straight-line 断言 GP 文件，gp 只做真实读取与比较；三、任何批处理测试必须断言用例数等于预期数，不得只看退出码——0 用例 + rc=0 是本类假绿的特征信号。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
python3 upstream-gp-sweep-generator.py <datadir> > sweep.gp; gp -f -q < sweep.gp | grep -c PASS  # 与预期用例数比对
```

**验证**:
```
生成的 sweep.gp 逐行输出 name|PASS，且 SUMMARY 的 total 等于枚举用例数（pari-galpol 打包产物实测 7337/7337 PASS）
```
