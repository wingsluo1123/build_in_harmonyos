# E1444: compile-time-dep-version-must-match-upstream-pom

## 基本信息
- **严重度**: 2
- **类别**: build-system, java
- **作者**: 5852

## 错误特征
```
no suitable method found for \w+|method does not override or implement a method|cannot find symbol.*org\\.osgi
```

## 根因分析
编译期依赖的**版本**必须与上游 pom 声明一致：H2 1.4.199 的 pom 写 <osgi.version>4.2.0</osgi.version>，若改用 6.0.0，则 BundleContext.registerService(String,Object,Dictionary) 的签名已经变化 → `no suitable method found for registerService(String,…)`；同理 enterprise 包给错版本会 cannot find symbol。看起来像「代码坏了」，其实是 API 版本错配。

## 推荐方案
**方法**: pin-compile-jars-to-the-exact-upstream-pom-versions

**说明**: ①先读上游 pom 的版本属性（如 <osgi.version>/<slf4j.version>），不要凭直觉取最新 ②把该版本钉进编译期 jar 清单（含 sha256）③报 no suitable method found / method does not override 时优先怀疑**版本错配**而非源码问题 ④把「与 pom 对齐」写进配方注释。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
grep -nE '<(osgi|slf4j|lucene)[^>]*version' pom.xml   # 先读上游版本属性，再钉同版本
```
