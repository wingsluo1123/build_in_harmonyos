# E1447: Conan CMakeToolchain SharedLibBock 强制注入 BUILD_SHARED_LIBS=ON（CACHE 变量，tc.variables 无法覆盖）导致 vendored 子库变共享

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, cmake, conan
- **作者**: 5415

## 错误特征
```
Setting BUILD_SHARED_LIBS = ON|Library .* not found in package|Error loading shared library .*libwavpack|tc.variables.*BUILD_SHARED_LIBS
```

## 根因分析
Conan 2.x CMakeToolchain 的 SharedLibBock 会根据 options.shared 强制注入 set(BUILD_SHARED_LIBS ON CACHE BOOL)，tc.variables 中设置的同名变量被其覆盖；当 CMake 项目内 add_subdirectory 引入 vendored 子库（wavpack/aiff/abseil 等）时，这些子库被构建为共享库，而上游 install 规则只安装主库，导致 package 内缺失子库 .so，test_package 运行时 Error loading shared library

## 推荐方案
**方法**: shadow-cache-variable-in-top-cmakelists

**说明**: 在项目顶层 CMakeLists.txt 中 include(SfizzDeps) 之前加普通变量 set(BUILD_SHARED_LIBS OFF)（非 CACHE），普通变量遮蔽 CACHE 并被子目录 add_subdirectory 继承，使 vendored 子库保持静态；主库由项目自身 SFIZZ_SHARED 选项单独控制

**修复命令**:
```
set(BUILD_SHARED_LIBS OFF) 置于 include(*Deps) 之前
```

**验证**:
```
conan create . -pr:h=ohos-aarch64 && llvm-readelf -d p/lib/libsfizz.so | grep SONAME
```
