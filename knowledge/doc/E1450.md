# E1450: 浏览器扩展类包（纯静态 web-extension）的适配范式——①**同一内容要按浏览器装多棵树**（chromium + firefox，firefox 树用 Mozilla 扩展 ID 目录）；②**`manifest.json` 是生成物而非源码文件**：必须按浏览器挑选模板生成（chromium ← `manifest-chromium.json`（`manifest_version=3`）、firefox ← `manifest-firefox.json`（`manifest_version=2`、带 `browser_specific_settings.gecko.id`）），漏生成会缺文件、两棵树用同一份会让 chromium 侧的 `manifest_version` 出错；③**"零依赖"要三处都空**（Build-Depends / Depends / 发布物内有无 `package.json`、`Makefile` 等构建声明）；④消费者校验做**三层**——结构（两棵树与必需文件）、**配置语义**（version / manifest_version / gecko id 与目录名一致）、**资源口径**（各内容目录文件数下限），只数文件个数会被"空目录装过去"骗过

## 基本信息
- **严重度**: 2
- **类别**: packaging, data-package, web-extension
- **作者**: 4DF0

## 错误特征
```
manifest_version 不符|manifest.json 不存在|两棵树内容不一致|空目录|gecko id 与目录名不一致
```

## 根因分析
上游把扩展内容与**按浏览器差异化的 manifest**分开存放（两份模板），由打包脚本挑选生成——Debian 的 `override_dh_auto_install` 正是 `cp manifest-<browser>.json debian/tmp/<browser>/manifest.json`。 不跑 dh 的适配若直接复制目录树，就会漏掉 `manifest.json`（源码里没有这个名字）或两棵树共用一份 （chromium 需要 `manifest_version=3`，firefox 需要 2）——两种错误都不会让"安装"失败，只在运行时/校验时才暴露。

## 推荐方案
**方法**: per-browser-trees-with-generated-manifest-and-three-layer-consumer-checks

**说明**: ①读 `debian/*.install` 得到每棵树的落点（firefox 树常带 Mozilla 扩展 ID 目录），读 `debian/rules` 得到 manifest 的生成规则；②在 `package()` 里对每个浏览器：复制内容目录 + 生成 `manifest.json`（从对应模板）；③`build()` 里加自检（模板存在、模板里的 `version` 与包版本一致、内容目录齐备）；④消费者校验三层——结构/配置语义/资源口径；语义断言至少要覆盖 `version`、`manifest_version`（按浏览器不同）与 gecko id（并与包内目录名**双向核对**）；⑤把"三处都空"作为零依赖的判定口径写进 manifest 的 knowledge_gained。

**修复命令**:
```
ls src/manifest*.json ; grep -A3 override_dh_auto_install debian/rules ; python3 -c "import json,sys;d=json.load(open(sys.argv[1]));print(d['version'],d['manifest_version'])" <树>/manifest.json
```

**验证**:
```
①`ls <src>/manifest*.json`（有几份模板？）②`grep -n manifest <debian>/rules`（官方挑选/生成规则）③装完后：`python3 -c "import json;print(json.load(open(p))['manifest_version'])"` 对两棵树分别核对 ④`find <树>/<dir> -type f | wc -l` 对照下限
```
