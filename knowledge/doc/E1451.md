# E1451: OHOS libc++ (15.0.4) 缺失标准 <memory_resource> 头：std::pmr 编译报错，强用 experimental 路径运行时 SIGSEGV

## 基本信息
- **严重度**: 2
- **类别**: platform, cplusplus, libcxx-stdlib, std-pmr
- **作者**: 4B77
- **来源 PR**: 11976

## 错误特征
```
fatal error: 'memory_resource' file not found|std::pmr::|undefined symbol.*get_default_resource|experimental/memory_resource
```

## 根因分析
OHOS SDK clang 15.0.4 的 libcxx-ohos（_LIBCPP_VERSION 15004）不带 C++17 标准 <memory_resource> 头，只有 <experimental/memory_resource>，且该 experimental 头对 monotonic_buffer_resource/全局资源函数只声明未定义（SDK libc 不导出符号）。直接 #include <memory_resource> 编译期 fatal error；强走 experimental 路径时 default-constructed polymorphic_allocator 链接/运行期引用 experimental::pmr::get_default_resource() 符号缺失 → 运行时 SIGSEGV（zeek broker 13 个单测全 SEGFAULT）。

## 推荐方案
**方法**: shim-header-pmr-backport

**说明**: 自写 shim 头 <memory_resource> 经 -I 注入 include 路径最前，不改上游源码：①复用 SDK experimental 头的真实基类 ②自实现正确 bump-pointer monotonic_buffer_resource（每次分配必须对齐，否则内存破坏）③inline 定义 new_delete_resource/get_default_resource/set_default_resource/null_memory_resource ④补 experimental::pmr::get_default_resource() 转发符号（命名空间对齐，否则 default-constructed polymorphic_allocator 运行期仍悬空）。修复后 13 个曾 SEGFAULT 的 broker 测试 100% 恢复。注意：仅 #include <experimental/memory_resource> + using-namespace 不够，monotonic buffer 与全局资源必须补定义。

**修复命令**:
```
cmake -S . -B build -DCMAKE_CXX_FLAGS="-I${OHOS_SHIM_DIR}" && ctest -R broker（13 个 SEGFAULT 项应全过）
```

**验证**:
```
find <sdk>/include/c++/v1 -name memory_resource（无标准头=命中）; llvm-nm -D <sdk libc.so> | grep get_default_resource（Not found=命中）
```
