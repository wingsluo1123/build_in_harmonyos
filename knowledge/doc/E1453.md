# E1453: C++17 迁移旧 C++ 静态库 auto_ptr→unique_ptr：拷贝语义所有权转移需补 std::move + Boost iterator_facade 限定调用改 ADL

## 基本信息
- **严重度**: 2
- **类别**: portability, cppstd, cxx, legacy-code, libcxx
- **作者**: unknown

## 错误特征
```
no member named 'auto_ptr' in namespace 'std'|call to implicitly-deleted copy constructor of 'std::unique_ptr'|boost::operator==.*no matching function|no member named 'mpl' in namespace 'boost'
```

## 根因分析
OHOS profile 统一 compiler.cppstd=17，std::auto_ptr 自 C++17 起被标准移除。旧 C++（2010 年代）静态库（luabind 0.9.1）公共头/源码以 std::auto_ptr 作为"按值持有/传参的所有权转移"手段（pointer_holder 成员、make_instance/constructor 的 holder_type 构造、scope 值传递、make_pointee_instance）。直接全局替换为 std::unique_ptr 后 unique_ptr 禁止拷贝，凡依赖 auto_ptr 拷贝即转移语义的调用点全部报 implicitly-deleted copy constructor，必须逐一补 std::move。同时 Boost>=1.73 起 iterator_facade 比较运算符定义于 boost::iterators 命名空间且仅 iterator_facade 经 using 引入，旧代码的 boost::operator op(x,y) 限定调用失效（no matching function），须改 ADL 非限定 x op y；Booost 1.90 移除若干传递头，boost::mpl::bool_ 需显式 include <boost/mpl/bool.hpp>。

## 推荐方案
**方法**: cpp17-unique-ptr-migration-copy-semantics-move

**说明**: 公共头+src 统一 std::auto_ptr→std::unique_ptr；对 auto_ptr 拷贝转移语义的每一处（pointer_holder 成员初始化、make_instance/constructor 的 holder_type 构造、class_base::add_member 的 scope 转移、make_pointee_instance 的 make_instance 调用）补 std::move；Boost iterator_facade 比较的 boost::operator op(x,y) 限定调用改为 x op y（ADL 非限定）；显式 include <boost/mpl/bool.hpp> 补传递头移除；以 cppstd=17 回归编译 src + conan create 消费者 test_package 复验，全部固化到 patches/0001-modern-boost-compat.patch。
