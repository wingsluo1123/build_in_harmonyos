# E1454: OHOS: strip 使 .codesign 失效后加载器静默忽略 LD_PRELOAD 拦截（无任何报错）

## 基本信息
- **严重度**: 3
- **类别**: ohos, packaging, runtime, elf
- **作者**: 408A

## 错误特征
```
interposition silently inactive|LD_PRELOAD.*(ignored|no effect)|SO_KEEPALIVE is OFF|hooked function never called|preload.*not applied
```

## 根因分析
OHOS 链接器为 ELF 注入 .codesign 代码签名块；strip 的任意变体（-s/--strip-debug/--strip-unneeded/-S）只重排节区布局、不改 .text/.dynsym 内容，却使覆盖整文件的签名失配。加载器对签名失配的 preload 库既不报错也不加载，于是 LD_PRELOAD 拦截静默失效，表现为 socket() 未被 hook / SO_KEEPALIVE 仍为 OFF，极易误判为 OHOS 不支持 LD_PRELOAD 或配方/源码错误。

## 推荐方案
**方法**: skip-strip-or-resign-after-strip

**说明**: 首选：配方不执行上游的 strip 步骤（本库改用 make -C src/ 避开根 Makefile 的 strip -s）。若下游或打包环节必须 strip，则 strip 后必须重签：llvm-objcopy --remove-section .codesign 后 binary-sign-tool sign -inFile X -outFile X.signed -selfSign 1 并替换原文件（参考 E077 四步）。

**修复命令**:
```
make -C src CC=<cc> -j1  # 跳过顶层 Makefile 的 cp+strip -s；如需 strip：llvm-objcopy --remove-section .codesign X.so && binary-sign-tool sign -inFile X.so -outFile X.signed.so -selfSign 1 && mv X.signed.so X.so
```

**验证**:
```
LD_PRELOAD=<lib.so> ./probe 应被拦截 -> strip 后同一命令静默不拦截；readelf -SW <lib.so> 两版 .codesign 均存在且内容哈希一致；llvm-objcopy --remove-section .codesign 加 binary-sign-tool sign -selfSign 1 后拦截恢复
```
