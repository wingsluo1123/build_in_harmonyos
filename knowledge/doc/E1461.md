# E1461: SCons 交叉编译：构造变量（CC/CXX/SHELL）未注入 → 编译器自检失败或子进程 sh 找不到

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system
- **作者**: 30EB

## 错误特征
```
Checking whether the C compiler works\.\.\. no|Checking whether the C\+\+ compiler works\.\.\. no|/system/bin/sh: .*: inaccessible or not found|sh: .*: inaccessible or not found|scons: .* not found
```

## 根因分析
SCons 只从 construction variables 取编译器（默认 gcc/g++），不读环境变量 CC/CXX；且它用 SHELL 构造变量直接 posix_spawn 执行 sh（不搜索 PATH），沙箱与 CI 内默认 shell 不可用 → 编译器自检 no / 子进程 127

## 推荐方案
**方法**: source-patch

**说明**: 给 SConstruct 打补丁：让环境变量 RHVOICE_SCONS_<NAME> 覆盖任意 construction variable，再由配方从 Conan toolchain 注入 CC/CXX/AR/RANLIB/SHELL 的绝对路径（R33：不用裸 shell 环境变量）

**修复命令**:
```
patch: for k,v in os.environ.items(): if k.startswith("RHVOICE_SCONS_"): base_env[k[len("RHVOICE_SCONS_"):]] = v ; then python3 -m SCons -j<N> CC=${CC} CXX=${CXX} SHELL=${SHELL}
```

**验证**:
```
grep -n "SHELL\|CC\|CXX" SConstruct | head; python3 -m SCons -n CC=<abs clang> CXX=<abs clang++> SHELL=<abs sh>
```
