# E1464: 两个 test_package 陷阱：①Maven 产物名常因 pom 的 finalName 而不含版本号（写死 jarkarta.activation-api-2.0.0.jar 会 "JAR not found"）须按目录发现；②`JAR=$(ls ... | head -1)` 在 `set -euo pipefail` 下会因 head 早退给 ls 触发 SIGPIPE（退出码 141）令脚本静默退出——连 echo 都不打印

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, testing
- **作者**: 26F4

## 错误特征
```
JAR not found at .*\.jar
```

## 根因分析
①上游 pom 常设 <finalName>，使产物名与 <artifactId>-<version>.jar 的默认约定不一致（实测 jaf-api：activationapi 产出 jakarta.activation-api.jar、activation 产出 jakarta.activation.jar，均无版本号）；test_package 若按 Maven 默认命名写死路径，就报 "JAR not found"，而构建本身是成功的。②在 `set -euo pipefail` 的脚本里写 `JAR_API="$(ls "$DIR"/a*.jar | head -1)"`：当匹配到 2 个及以上文件时，head 读够一行即退出，ls 继续写管道时收到 SIGPIPE 并以 141 退出；pipefail 把 141 视为失败 → set -e 立即终止脚本。表现为**脚本一行输出都没有、conan 只报 Error 1 while executing**，极难定位（旧写法还能出 "=== xxx 测试 ===" 首行，改写法后连首行都没了）。

## 推荐方案
**方法**: discover-artifacts-by-glob-not-pipe

**说明**: ①产物发现：不要按 "<artifactId>-<version>.jar" 写死，改用 glob 循环按类别挑（API jar 用 *-api*.jar，类 jar 用 *.jar 且排除 *-api*），并在取不到时打印 libexec/ 实际内容以便定位；②避免 `cmd | head` 直接进命令替换：改 for-glob 循环，或对管道兜底（`... | head -1 || true`），或临时 `set +o pipefail`。同思路适用于其它"发现产物/取第一条"的脚本场景。

**修复命令**:
```
for f in "$PKG_DIR"/libexec/*.jar; do [ -f "$f" ] || continue; case "$(basename "$f")" in jakarta.activation-api*) JAR_API="$f" ;; jakarta.activation*) JAR_IMPL="$f" ;; esac; done
```

**验证**:
```
bash -c 'set -euo pipefail; d=$(mktemp -d); touch $d/a1.jar $d/a2.jar; x="$(ls $d/a*.jar | head -1)"; echo got=$x'; echo exited=$? # 实测：无输出、退出码 1
```
