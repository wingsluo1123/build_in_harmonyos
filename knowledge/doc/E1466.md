# E1466: 纯 Python 库的运行期依赖在制品仓缺失时，**先确认该依赖是否在导入期就被 import**（本例 `jaraco.collections` 顶部 `import jaraco.text`）：导入期必需 → 不能当可选依赖省掉；随后按"已发布的走 Conan requires、未发布的随包捆绑"处理，而**同一命名空间（PEP 420）的多份实现可以各自装 `ns/<mod>` 直接合并**，无需改动任一包结构

## 基本信息
- **严重度**: 3
- **类别**: python, conan, packaging
- **作者**: 1B91

## 错误特征
```
ModuleNotFoundError: No module named 'jaraco.text'|Unable to find 'jaraco\.' in remotes|依赖未发布
```

## 根因分析
现象有两层容易误判的地方： ① **把运行期依赖当可选项**：`jaraco.collections` 的 `__init__.py:13` 就是 `import jaraco.text`，并在 `FoldedCaseKeyedDict` 里用 `jaraco.text.FoldedCase(key)` —— 在**导入期**就必须存在，删不掉； 若只看"用得不多的那一处调用"就判断可选，装出来的包 `import jaraco.collections` 直接炸。 ② **依赖确实未发布**：`jaraco.text` / `jaraco.functools` / `jaraco.context` 用 `conan install` 实测（两种拼写 `jaraco.text`、`jaraco-text` × 多版本）均 `Unable to find`， `archives/` 下也无目录 —— 而仓库 R36 要求"依赖先发布再构建下游"。 另有一个技术前提值得记住：`jaraco.*` 是 **PEP 420 命名空间包**（目录里没有 `__init__.py`）， 所以"本体 + 若干同命名空间的依赖"可以各装各自的 `jaraco/<mod>` 到同一个 site-packages 下自然合并。

## 推荐方案
**方法**: import-time-check-then-mix-requires-and-vendoring-with-namespace-merge

**说明**: ①先用"导入期"判据确认依赖是否必需（`grep` 导入位置 + `import` 试跑），不要凭调用次数判可选；②按可得性分流：**已发布的走 Conan `requires`**（本例 `more-itertools/11.1.0`），**未发布的纯 Python 小模块随包捆绑**（在 `conandata` 里为每个依赖钉 `url`+`sha256`，`source()` 解到 `_vendored/<name>/`，`package()` 把 `<name>/<ns>/<mod>` 并入 site-packages）；③因为命名空间是 PEP 420，多份实现各装 `ns/<mod>` 即可合并，**不需要给命名空间补 `__init__.py`、也不需要改写任何依赖的包结构**；④如实披露 R36 张力与替代路线（更彻底做法：先单独发布这些依赖配方，再把捆绑段换成 `requires`）。

**修复命令**:
```
PYTHONPATH=<site-packages>:<more-itertools site> python3 -c "import <pkg>; <调用若干真实 API>"
```

**验证**:
```
① `grep -rn "import <dep>" <pkg>/ | head` 看导入位置（`__init__.py` 顶部即导入期必需）② `python3 -c "import <pkg>"`（缺依赖会立刻 ModuleNotFoundError）③ `conan install --requires=<dep>/<ver>`（R35，两种拼写都试）
```
