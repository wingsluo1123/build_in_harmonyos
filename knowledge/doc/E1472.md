# E1472: 上游只在 target 存在时就链接 OpenMP::OpenMP_CXX，构建选项置 OFF 仍会注入 -fopenmp

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, linking, openmp
- **作者**: 0B67

## 错误特征
```
undefined symbol: __kmpc_|__kmpc_end_critical|__kmpc_for_static_init|__kmpc_global_thread_num|__kmpc_critical
```

## 根因分析
上游 CMake 把 OpenMP 接线写成 `if(TARGET OpenMP::OpenMP_CXX) target_link_libraries(<lib> OpenMP::OpenMP_CXX) endif()`——只判断 target 是否存在，不判断自家的 <PRJ>_BUILD_WITH_OPENMP 选项。OHOS clang SDK 自带 libomp.so / libomp.a / omp.h，find_package(OpenMP QUIET) 必然成功，于是即便选项已置 OFF，该库仍被 -fopenmp 编译；源码里 `#pragma omp critical` / `#pragma omp parallel for` 若无 `#ifdef _OPENMP` 守卫，就在静态归档里留下 __kmpc_* 未定义符号，而 Conan 的 package_info() 不会声明 libomp，任何消费者链接都失败（本地 conan create 的构建与测试阶段反而全绿，因为构建树里该目标自身带着 -fopenmp 与运行时）。

## 推荐方案
**方法**: disable-openmp-package-lookup

**说明**: 在 generate() 的 CMakeToolchain 里除 <PRJ>_BUILD_WITH_OPENMP=OFF 外，追加 CMAKE_DISABLE_FIND_PACKAGE_OpenMP=ON，让 find_package(OpenMP) 直接返回未找到、OpenMP::OpenMP_CXX 目标不存在，-fopenmp 不再注入；无 OpenMP 时 #pragma omp critical 退化为普通语句块、parallel for 退化为串行循环，语义等价

**修复命令**:
```
tc.variables["<PRJ>_BUILD_WITH_OPENMP"]=False ; tc.variables["CMAKE_DISABLE_FIND_PACKAGE_OpenMP"]=True
```

**验证**:
```
nm -u <pkg>/lib/lib<name>.a | grep -c __kmpc ; conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
