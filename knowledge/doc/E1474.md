# E1474: container-provided-java-apis-not-shipped-but-pinned-in-tests

## 基本信息
- **严重度**: 2
- **类别**: java, packaging, testing
- **作者**: 0AB6

## 错误特征
```
NoClassDefFoundError.*jakarta\.servlet|ClassNotFoundException.*jakarta\.servlet|cannot access.*jakarta\.servlet
```

## 根因分析
servlet/jsp/el 这类 API 属容器提供（pom 里 provided）：随包发会与容器冲突、也非本库职责；但消费者校验若不同时具备它们，impl 类在加载/调用时即 NoClassDefFoundError/ClassNotFoundException——校验结果会取决于测试侧有没有这些 API，而不是库本身好不好。

## 推荐方案
**方法**: ship-only-library-jars-fetch-container-apis-in-tests

**说明**: ①产物只放库自身 jar（本例 api + impl）；②消费者校验显式声明并自取所需容器 API 版本并逐个 sha256 钉校验；③网络不可达属具名环境信号 → 依赖它的端到端子项记 SKIP 并写明理由，其余项严格判定；④不要让测试侧缺 API 伪装成库缺陷。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
校验脚本内对自取的容器 API jar 逐个 sha256 比对（jakarta.servlet-api 6.0.0 / jakarta.servlet.jsp-api 3.1.0 / jakarta.el-api 5.0.0），版本与 pom 的 provided 声明一致
```
