# E1480: init-build F068 嵌套源码检测对无顶层构建文件的仓库（header-only 等）误提升含 Makefile 的子目录

## 基本信息
- **严重度**: 2
- **类别**: headers, build-system, init-build, tooling
- **作者**: 0BF5

## 错误特征
```
嵌套源码检测: 找到源码在.*，正在提升|\.orig 目录内容为某个子目录（如 demos/）而非仓库根
```

## 根因分析
F068 _promote_nested_source 以 configure/CMakeLists.txt/Makefile/meson.build 为 build marker：若仓库顶层无任何 marker（header-only 库典型形态，如 PortableGL 只有一个大头文件），会向子目录搜索（max_depth=3）并把第一个含 marker 的子目录（PortableGL 的 demos/ 有 Makefile）整体提升为源码根，导致 .orig/.work 内容错误（丢失 portablegl.h 等顶层文件）

## 推荐方案
**方法**: manual-fix-nested-promotion

**说明**: 手动重建 .orig：tarball 正确解压后把顶层包装目录内容（含 dotfiles，注意 glob * 不匹配 .github 等，需 shopt -s dotglob）全部移到 .orig 根，写入 .tarball-sha256；随后在 .orig 顶层放置 Makefile 占位（注释注明用途），使 _create_dual_track 的 orig_valid=True 防止重跑 init-build 时再次解压+误提升；cp -a 生成 .work；最后带 --project-dir 重跑 init-build --no-download

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
ls \$TMPDIR/builds/<name>-<ver>.orig/ | grep <顶层关键头文件> && ls <name>-<ver>.work/
```
