# E1484: Cross-built Conan provider metadata must be relocated by suffix and slash style before target consumers run

## 基本信息
- **严重度**: 3
- **类别**: ohos, qmake, cross-compile, conan, relocatable
- **作者**: 2301_80739235

## 错误特征
```
module .*\.pri.*not found|No such file or directory.*conan-home|cannot find.*\.prl|stale.*\.conan2/p/b
```

## 根因分析
A cross-built provider can embed its temporary Conan build or package root in generated metadata. The consumer then follows a host-only path even though the provider files were transferred correctly. Matching only Unix paths or only one metadata suffix leaves another qmake, libtool, pkg-config, or CMake entry stale. In the recipe environment, Environment.append on LD_LIBRARY_PATH replaces the worker's SDK runtime path; use append_path so linker tools retain required host libraries such as libxml2. CMakeDeps package and component config names must be taken from its generated guidance; provider component files are not necessarily on the consumer's CMAKE_PREFIX_PATH.

## 推荐方案
**方法**: metadata-root-relocation-and-consumer-smoke

**说明**: Derive the provider package_folder from Conan dependency metadata. Scan all relevant suffixes and both POSIX and Windows path spellings. Rewrite only exact provider build/package roots, preserve unrelated text, and use Environment.append_path for LD_LIBRARY_PATH overlays so SDK linker runtimes remain visible. Read the CMakeDeps generated find_package guidance and consume those package-level names/targets rather than guessing component config paths. Bind test() to the exact executable emitted by add_executable; a successful build with a stale test path is not a passing consumer. Then run the installed consumer and verify its output plus ELF machine type. A qmake configure success alone is insufficient.

**修复命令**:
```
target consumer build and run; provider metadata stale-root scan
```

**验证**:
```
Inspect every metadata file under the provider package; replace only identity-bound old roots with the current package_folder; assert no old root remains; run a real target consumer that loads the provider API and record target architecture.
```
