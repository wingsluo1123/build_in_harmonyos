# E1486: CMake 默认 CTest 清单与 Makefile 穷举程序分离时的测试盘点与 header-only 消费者验证

## 基本信息
- **严重度**: 2
- **类别**: headers, build-system, cmake, conan, testing
- **作者**: FM01

## 错误特征
```
ctest.*moddivnbenchmark.*modnbenchmark|FASTMOD_EXHAUSTIVE_TESTS|unit\\.c|cppincludetest2
```

## 根因分析
上游同时提供 CMake 和 Makefile 两套测试入口：默认 CMake 只注册 moddivnbenchmark、modnbenchmark 两个 CTest benchmark，Makefile 才构建 unit.c 与 cppincludetest2.cpp；后两者没有被默认 CTest 注册，且 cppincludetest2 只有在 FASTMOD_EXHAUSTIVE_TESTS=ON 时才加入 CTest。只按 CTest 数量写“完整测试”会夸大正确性覆盖，只按可执行文件数量写“用例”又会混淆测试目标与断言。

## 推荐方案
**方法**: source-registration-ledger-plus-consumer-smoke

**说明**: 先从构建文件逐项盘点 CTest 注册、Makefile 构建但未注册的程序和 opt-in 测试，再在 Conan build() 保留默认上游 CTest；对 header-only 包用 self.run() 执行直接调用真实 API 的消费者测试，并在 MANIFEST/PR 中分别报告目标数、实际执行数、显式检查数和未运行原因。

**修复命令**:
```
ctest --test-dir <build> --output-on-failure; <conan-test-package>/test_fastmod
```

**验证**:
```
ctest -N --test-dir <build>; rg -n 'add_test|FASTMOD_EXHAUSTIVE_TESTS|unit|cppincludetest2' CMakeLists.txt tests/CMakeLists.txt Makefile; clang++ -std=c++11 -I <package>/include <consumer>.cpp -o <consumer> && <consumer>
```
