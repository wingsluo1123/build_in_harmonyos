# E1488: Keep legacy Autotools desktop metadata builds independent of unavailable intltool

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, conan, desktop-entry, intltool
- **作者**: codex

## 错误特征
```
The intltool scripts were not found.*Please install intltool|intltool-update.*not found|intltool-merge.*not found
```

## 根因分析
The release configure script unconditionally expands IT_PROG_INTLTOOL and fails when intltool-update, intltool-merge, or intltool-extract is absent. The data Makefile then uses intltool-merge to turn .desktop.in files into .desktop files. On OHOS, the runner commonly lacks intltool. Runtime confirmation for this package is Needs verification until W3 runs on the target worker.

## 推荐方案
**方法**: package-local-intltool-probe-and-desktop-rule

**说明**: Remove IT_PROG_INTLTOOL from configure.ac for future regeneration; keep the generated configure usable with build-folder-only probe shims that report the required version; replace the data Makefile desktop rule with a deterministic sed conversion for underscore-prefixed keys. Do not package the shims.

**修复命令**:
```
conan create archives/a/activity-log-manager/0.9.7 --build=missing
```

**验证**:
```
Apply the recipe patches to a clean release tarball, run ./configure --disable-nls with the recipe-local probe tools on PATH, run make -j1, inspect data/*.desktop for Name/Exec/Type, then run make check on a worker with desktop-file-validate.
```
