# E1493: OHOS 只有 OpenGL ES 无桌面 OpenGL(libGL)：用 gl4es libGL.so 兼容层适配固定管线 GL 软件

## 基本信息
- **严重度**: 2
- **类别**: compat, limitation, portability, graphics
- **作者**: B1GL

## 错误特征
```
cannot find -lGL|undefined reference to .glBegin|Could not load EGL library|Could not initialize OpenGL / GLES library|no default font specified|glDrawRangeElements.*not found
```

## 根因分析
OpenHarmony PC 只提供 OpenGL ES 3.2(libGLESv3.so)+EGL（含 EGL_WINDOW_BIT 窗口表面），没有桌面 OpenGL(libGL.so)。依赖桌面 OpenGL 固定管线/立即模式(glBegin/glMatrixMode/glOrtho/客户端顶点数组/矩阵栈/纹理环境/光照/雾)的三方库/游戏，在 -lGL 链接与运行时上下文/固定管线调用处失败。这不是平台"能力缺失"，而是缺一个可移植的库层：用 gl4es（桌面 GL-over-GLES2 兼容层，内置 FPE 固定管线模拟）补 libGL 即可，属 B1 通用解决方案。

## 推荐方案
**方法**: ohos-desktop-gl-over-gles-compat

**说明**: 引入为 OHOS 构建的 gl4es 提供 libGL.so（NOX11 + DEFAULT_ES=2 + CMAKE_SYSTEM_NAME=Linux，运行时设 LIBGL_GLES=/system/lib64/libGLESv3.so）；消费方对可选 GL 扩展按"函数指针是否解析成功"来启用特性，避免 gl4es 缺 EXT/ARB 后缀名导致崩溃。

**修复命令**:
```
"cd gl4es && cmake -S . -B build -DNOX11=ON -DDEFAULT_ES=2 -DCMAKE_SYSTEM_NAME=Linux -DSTATICLIB=OFF && cmake --build build && ln -sf libGL.so.1 lib/libGL.so"
```

**验证**:
```
运行 gl4es 直连测试：创建 EGL pbuffer/window ES2 上下文后调 glGetString 与 glBegin/glEnd/glMatrixMode/glOrtho/glShadeModel/glEnableClientState/glTexEnvf，期望 "Renderer: GL4ES using HUAWEI" 且 glGetError()==GL_NO_ERROR；或 run test_package 离屏渲染（glReadPixels 非黑）。
```
