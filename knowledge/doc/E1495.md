# E1495: GTest 伪随机输入跨标准库差异 + 无 add_test 的测试集成（OHOS libc++）

## 基本信息
- **严重度**: 3
- **类别**: compat, libc, cmake, conan, testing
- **作者**: 5FC1
- **来源 PR**: 7486

## 错误特征
```
uniform_int_distribution.*byte.*sequence|cross-stdlib.*fingerprint|SecureUtilsTest.*FAILED|HMBS_UPSTREAM_TEST_RESULT.*status.*failed|failed: 135
```

## 根因分析
std::mt19937_64 engine output is fully specified by the C++ standard (constant across libstdc++/libc++), but std::uniform_int_distribution maps engine values to [0,255] in an implementation-defined way; so the byte sequence (and any hard-coded test expectation derived from it) differs between libstdc++ (GCC/Clang on Linux) and libc++ (OHOS toolchain) - a pseudo-random-input GTest case fails on exactly one of them. Separately (CMake-specific trap, NOT a universal mechanism): if a CMake project calls enable_testing() but never registers its test targets via add_test() (barrier's unittests/integtests are one example - only the GUI test guiunittests is registered), then ctest discovers 0 tests and exits 0 -> silent false-green: the pipeline believes upstream tests ran while none executed. This is a CMake/CTest discovery trap, not a general property of all build systems (Autotools uses make check, Meson uses test(), Rust/Go/Python auto-discover). The workaround is to run the test executable directly in conanfile build() (can_run guarded) and emit HMBS_UPSTREAM_TEST_RESULT; meanwhile parsing gtest output with regex [  FAILED  ]/[  PASSED  ] treats the brackets as a regex char class unless escaped to \[ \].

## 推荐方案
**方法**: parameter_mapping

**说明**: 1) 测试伪随机输入改为取引擎低字节 mt19937_64 & 0xFF（引擎输出标准规定、跨库一致），并同步更新硬编码期望值；不用 uniform_int_distribution。2) 【仅限 CMake 且上游测试目标未 add_test 注册】ctest 会静默跑 0 测试（false-green），不能依赖 cmake.test()；须在 conanfile build() 里 can_run() 守卫直接运行测试可执行文件并输出 HMBS_UPSTREAM_TEST_RESULT 标记；解析 gtest 输出时把 [  FAILED  ]/[  PASSED  ] 的方括号转义为 \[ \]。非 CMake 项目走各自机制（make check / test() / 自动发现），无需此绕过处理。

**修复命令**:
```
bytes.push_back(static_cast<std::uint8_t>(engine() & 0xFF));  (gen func); \[  FAILED  \] / \[  PASSED  \]  regex escape; print(f'HMBS_UPSTREAM_TEST_RESULT={json.dumps(marker)}', flush=True)
```

**验证**:
```
在 OHOS libc++ 下运行 unittests；对比 gtest 输出 [  PASSED  ] N tests / HMBS_UPSTREAM_TEST_RESULT status 应为 passed、failed=0
```
