# E1497: CMake 旧归档无 install/CTest 时的显式制品收集与诚实测试记录

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan, packaging, testing
- **作者**: 220E

## 错误特征
```
Compatibility with CMake < 3.5 has been removed|No tests were found|install.*rule.*not found|missing.*config_impl.hpp
```

## 根因分析
部分老 CMake 归档只定义库和示例目标，没有 install() 规则或 enable_testing()/add_test()；同时生成的公共配置头只存在于构建目录。现代 CMake 4 还会拒绝低于 3.5 的 cmake_minimum_required，导致直接配置失败。仅依赖 cmake.install() 会得到空包，或把 ctest 的 No tests were found 误报成上游测试通过。

## 推荐方案
**方法**: explicit-policy-and-artifact-staging

**说明**: 在 Conan CMakeToolchain 中设置 CMAKE_POLICY_VERSION_MINIMUM=3.5；先构建并直接运行 ctest，明确记录零 CTest 用例，再从源目录、构建目录和正式构建产物位置显式收集头文件、生成头、许可证和库，并用消费者测试验证真实 API。

**修复命令**:
```
cmake -S <src> -B <build> -DCMAKE_POLICY_VERSION_MINIMUM=3.5 && cmake --build <build> -- -j1 && ctest --test-dir <build> --output-on-failure
```

**验证**:
```
cmake -S <src> -B <build> -DCMAKE_POLICY_VERSION_MINIMUM=3.5 && cmake --build <build> -- -j1 && ctest --test-dir <build> --output-on-failure; then inspect the package and run a real consumer
```
