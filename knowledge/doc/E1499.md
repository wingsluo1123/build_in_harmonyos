# E1499: cmocka uintptr_t typedef 与新版 libc 冲突：用**编译器内建宏 __UINTPTR_TYPE__** 存在时跳过重复 typedef（避免 redefinition）

## 基本信息
- **严重度**: 2
- **类别**: compat, detection, libc, musl, headers
- **作者**: GCW8
- **来源 PR**: 11515

## 错误特征
```
redefinition of typedef .uintptr_t|conflicting types for .uintptr_t|typedef.*uintptr_t.*previously declared|__UINTPTR_TYPE__
```

## 根因分析
cmocka.h 自行 `typedef unsigned long uintptr_t;`（或类似），而新版 libc（musl/glibc ≥某版本）已通过标准头提供 `uintptr_t`，二者叠加导致 `redefinition of typedef 'uintptr_t'` 编译错误。解决方式应优先用**编译器内建宏** `__UINTPTR_TYPE__`（编译器已定义的 `uintptr_t` 底层类型宏）做条件：若 `__UINTPTR_TYPE__` 已定义（即编译器会通过内建宏提供 uintptr_t），则跳过 cmocka 的重复 typedef——这与用平台宏不同，是**编译器内建/标准机制**，合规（非平台宏、非 R8 违规）。

## 推荐方案
**方法**: ohos-cmocka-uintptr-guard

**说明**: 在 cmocka.h 中，当 `__UINTPTR_TYPE__` 已定义时跳过自定义 `uintptr_t` typedef（`#ifdef __UINTPTR_TYPE__` 守卫），避免重复定义；这是编译器内建宏机制，非平台宏。

**修复命令**:
```
(echo '__UINTPTR_TYPE__' | gcc -dM -E -x c - )   # 先验证内建宏存在再决定是否守卫
```

**验证**:
```
echo '__UINTPTR_TYPE__' | gcc -dM -E -x c - | grep UINTPTR   # 观察编译器是否内建提供 uintptr_t 底层类型
```
