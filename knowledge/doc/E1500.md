# E1500: PIDL 生成器的 Parse::Yapp 依赖：vendored Driver.pm + release tarball 预生成解析器，缺失时降级为 warning（OHOS）

## 基本信息
- **严重度**: 2
- **类别**: build-system, perl, generated-code, idl, pidl
- **作者**: GCW8
- **来源 PR**: 11515

## 错误特征
```
Can't locate Yapp|Parse::Yapp|pidl.*yapp|Could not find perl module Yapp|pidl:.*failed
```

## 根因分析
Samba 的 PIDL（IDL→NDR/RPC 代码生成器）依赖 Perl 模块 Parse::Yapp（yapp 命令）对 IDL 文法做 LR 解析。OHOS 无 yapp/Parse::Yapp（perl tool_requires 也不含）。但 **release tarball 自带预生成的解析器**（IDL.pm/Expr.pm 等），因此"yapp 缺失"不一定致命——上游把它当硬失败是过度防御；本地构建失败点恰在 `Can't locate Yapp/Parse::Yapp`。

## 推荐方案
**方法**: ohos-pidl-yapp-degrade

**说明**: ① 配方 `tool_requires` 声明 perl；② 把 vendored `Parse::Yapp::Driver.pm`（CPAN Parse-Yapp 1.21，注入 export_sources）放进程可加载路径；③ PIDL wscript 把"yapp 缺失"由硬失败改为 `Logs.warn` 降级——release tarball 带预生成解析器，生成阶段用预生成产物即足够。

**修复命令**:
```
(export PERL5LIB=<vendored-parse-yapp>; export PATH=$PATH:<perl-tools>; python3 buildtools/bin/waf pidl)
```

**验证**:
```
perl -MParse::Yapp -e1 2>&1   # 观察是否可加载；不装源下跑 waf 观察 yapp 降级日志
```
