# E1501: ethtool_cmd_speed 符号级链接探测：glibc 提供的符号在 musl 缺失，用**链接结果**定义 HAVE_，不用平台宏

## 基本信息
- **严重度**: 2
- **类别**: detection, libc, musl, socket, glibc
- **作者**: GCW8
- **来源 PR**: 11515

## 错误特征
```
ethtool_cmd_speed|HAVE_ETHTOOL_CMD_SPEED|undefined reference to .ethtool_cmd_speed|declared here but not defined
```

## 根因分析
`ethtool_cmd_speed` 是 glibc 提供的符号，libc（musl）无对应实现。若在源码/头文件中按平台分支判断，会引入平台宏（违反 R8/PF5）；而按"头文件里存在声明"判断会误判（声明存在但链接符号缺失）。正确做法是**符号级链接探测**：写一个引用 `ethtool_cmd_speed` 的小程序/tu 并尝试链接，由工具链真实链接结果决定是否定义 `HAVE_ETHTOOL_CMD_SPEED`。

## 推荐方案
**方法**: ohos-symbol-link-probe

**说明**: 用 waf 的链接探测（build a small program that references the symbol ↔ link success）定义 `HAVE_ETHTOOL_CMD_SPEED`，由工具链真实链接结果决定，不使用平台宏。

**修复命令**:
```
(cd $TMPDIR && echo 'int ethtool_cmd_speed(void); int main(void){return ethtool_cmd_speed();}' | ${CC} -x c - -o /dev/null 2>&1)
```

**验证**:
```
python3 buildtools/bin/waf configure 2>&1 | grep -i ethtool   # 观察 Checking for HAVE_ETHTOOL_CMD_SPEED
```
