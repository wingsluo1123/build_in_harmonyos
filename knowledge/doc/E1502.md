# E1502: mkstemp 探针的 musl 安全语义：`恰 0600` vs `属主可读写且组/他人无写`，用 TMPDIR 规避 /tmp 只读（OHOS）

## 基本信息
- **严重度**: 3
- **类别**: compat, detection, ohos, libc, musl
- **作者**: GCW8
- **来源 PR**: 11515

## 错误特征
```
Checking for HAVE_SECURE_MKSTEMP|mandatory failure for this one|The configuration failed|mkstemp.*0600|secure mkstemp
```

## 根因分析
Samba `lib/replace` 的 `HAVE_SECURE_MKSTEMP` 探针（execute=True）运行时在 `TMPDIR(/tmp)` 创建 `test.XXXXXX` 并断言其 mode 恰为 `0600`。OHOS `/tmp` 只读（E002），且 HMDFS 把新建文件权限归一化为 `0640`（chmod 不生效，E046）——探针**在任何可写目录都必然判 not found**；上游把该探针标为 `mandatory=True`（注释 "lets see if we get a mandatory failure for this one"），configure 直接中止。判定标准过严：musl/OHOS 的语义是"属主可读写且组/他人无写"即安全，与"恰 0600"不一致。

## 推荐方案
**方法**: ohos-mkstemp-secure-probe

**说明**: 探针改用 TMPDIR（可写目录）并放宽安全判定为「属主可读写且组/其他无写权限」（而非恰 0600），由探针**真实结果**驱动 `HAVE_SECURE_MKSTEMP`；不硬编码设备路径、不强改 chmod。

**修复命令**:
```
./configure   # 配合 conan 注入可写 TMPDIR；或按需置 build env TMPDIR=<W>/tmp
```

**验证**:
```
(cd $TMPDIR && umask 077; touch t && stat -c%%a t)   # 观察实际 mode；运行 configure 观察 HAVE_SECURE_MKSTEMP 结果
```
