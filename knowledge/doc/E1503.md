# E1503: Waf 私有 Python 构建系统跨平台（OHOS）适配：`configure`/`make` 包装脚本调用链 + CROSS_COMPILE 真实语义注入 + 禁止直接调用 waf

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, configure, python, waf
- **作者**: GCW8
- **来源 PR**: 11515

## 错误特征
```
The configuration failed|IN_LAUNCH_DIR|PYTHONHASHSEED=1 missing|Don't use waf directly|Could not build a python embedded interpreter
```

## 根因分析
Samba 系（samba/tdb/talloc/tevent/ldb）使用自带 waf（wafsamba），非 autotools/cmake。其 waf 目录不能直接执行：`configure`/`make` 包装脚本要求 `$PYTHON` 指向可用 python3、自行 `export PYTHONHASHSEED=1`、`unset LD_PRELOAD`，且 `wscript` 的 `conf.IN_LAUNCH_DIR()` 要求源码根目录原地构建；交叉编译时必须用 CROSS_COMPILE 注入目标三元组/clang 绝对路径，并注意 pyembed 探针（python3-config --embed 可能输出 musl 缺失的 -lintl）在 OHOS 上不可通过。以上任一不满足即 configure 中断或产出非目标产物。

## 推荐方案
**方法**: ohos-waf-build-policy

**说明**: 用 `configure`/`make` 包装脚本走 waf 调用链（源码根目录原地构建，`$PYTHON=python3` + PYTHONHASHSEED/WAF_MAKE 由脚本注入）；交叉编译经 `CROSS_COMPILE=<triplet>-` + `--cross-answers`（仅当确有真实语义依据时）注入，把 clang 绝对路径写进 conan 的 build env（CC/CXX/AR/RANLIB/PKG_CONFIG_PATH/CPATH/LIBRARY_PATH/PERL5LIB 单点注入）；C-only 包用官方 `--disable-python` 规避 pyembed 失败，并用 `PYTHONHASHSEED` 保证可复现。

**修复命令**:
```
PYTHON=python3 ./configure --prefix=${PREFIX} && make -j$$(nproc) && make install
```

**验证**:
```
PYTHON=python3 ./configure --prefix=$PREFIX && make -j$$(nproc)
```
