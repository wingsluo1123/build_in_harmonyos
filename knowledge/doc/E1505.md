# E1505: Header-only CMake 包的 CTest 目标数与逻辑用例数分层核对

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, conan, packaging, testing
- **作者**: EC9B

## 错误特征
```
ctest.*1.*(105|logical)|upstream_test_count|test_package.*upstream|assertion_count.*8
```

## 根因分析
CMake/CTest 把一个可执行测试驱动登记为一个 CTest target，但驱动的 main() 可能顺序调用多个逻辑测试并遍历数据回归；若适配只记录其中一个口径，或把 test_package 消费者断言并入上游统计，就会虚报覆盖范围。header-only INTERFACE 包还需要单独验证安装后的 CMake target 消费链路。

## 推荐方案
**方法**: ctest-logical-test-inventory

**说明**: 先用 ctest -N/CTestTestfile.cmake 记录可执行 target 数，再源码核对测试驱动展开调用、逻辑测试族和数据循环数量；上游通过率只按上游入口报告，test_package 作为独立消费者验证并统计其真实断言。

**修复命令**:
```
ctest --test-dir <build> -N && ctest --test-dir <build> --output-on-failure
```

**验证**:
```
cmake -S <src> -B <build> && cmake --build <build> && ctest --test-dir <build> --output-on-failure; awk '/int main\(/,/^}/' <src>/tests/unit.cpp; conan test <src>/test_package <ref>
```
