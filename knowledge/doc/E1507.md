# E1507: OHOS long-double math references can be non-finite for representable inputs

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, libc, testing, numerical
- **作者**: CD40
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/7601

## 错误特征
```
reference is not finite|std::log.*-inf|std::log10.*-inf|std::log2.*-inf|long double.*(128|16 bytes)|numeric_limits<long double>::min
```

## 根因分析
On HarmonyOS PC aarch64 the C++ long-double representation has extended range, but the device libc math reference functions can return -inf for representable subnormal-range inputs such as 1e-500L and numeric_limits<long double>::min(). An upstream comparison against that reference is not a valid oracle for those cases; this is a platform libc/reference limitation, not evidence that the library implementation itself produced the wrong value.

## 推荐方案
**方法**: finite-oracle-guard-with-independent-regression

**说明**: Keep every upstream test active, guard only the comparison when the device reference is non-finite, emit a named skip containing the exact function and input, and validate the library result through the remaining upstream cases plus a consumer check that uses a finite ordinary-range oracle.

**修复命令**:
```
cmake --build build --target gcem_tests && for t in build/tests/*.test; do "$t" || exit $?; done
```

**验证**:
```
Check sizeof(long double) and numeric_limits<long double>::min(), evaluate std::log/std::log10/std::log2 for 1e-500L and min(), require explicit finite-oracle evidence, then rerun the complete upstream suite and an independent consumer regression.
```
