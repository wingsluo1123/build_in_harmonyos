# E1509: Exact dependency override requires a new package identity and target-toolchain binding

## 基本信息
- **严重度**: 2
- **类别**: cmake, cross-compile, conan, dependency-closure
- **作者**: 2301_80739235
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/issues/2490

## 错误特征
```
missing.*binary.*after.*override|SDL2Config\.cmake|cannot find -lSDL2
```

## 根因分析
A Conan package ID includes settings, options, and the resolved dependency graph. Replacing an exact transitive provider with a newer ABI-compatible provider changes the downstream binary closure even when source files are unchanged. A Windows-hosted CMake invocation also keeps host linker rules unless the official target toolchain establishes the OHOS system, target triple, sysroot, lld, and archiver before the compiler probe. Native CMake config filenames are case-sensitive and cannot be inferred from generated Conan targets.

## 推荐方案
**方法**: versioned-closure-and-official-target-toolchain

**说明**: Use the next adaptation version rather than replacing a released recipe revision. Declare one exact provider version and preserve transitive headers/libs. Before CMake configure, verify the provider's real native Config.cmake filename and bind its directory. In the host profile load the SDK's official OHOS toolchain, which sets CMAKE_SYSTEM_NAME, target triple, sysroot, lld, and llvm-ar. Re-resolve the full graph, build the new package, and compile the independent consumer set against the resulting package identity.

**修复命令**:
```
self.requires("sdl2/2.32.10"); tools.cmake.cmaketoolchain:user_toolchain=["<sdk>/native/build/cmake/ohos.toolchain.cmake"]; test -f "<package>/lib/cmake/SDL2/SDL2Config.cmake"
```

**验证**:
```
conan graph info <recipe> --build=never; conan create <recipe> -pr:h=<ohos-profile> -pr:b=<windows-profile>; cmake --build <test-package> -- -j2
```
