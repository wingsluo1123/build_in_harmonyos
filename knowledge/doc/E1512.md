# E1512: physical-library-metadata-binding

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, metadata, package-info
- **作者**: 2301_80739235
- **来源 PR**: 8474

## 错误特征
```
"Library '.*' not found in package|CMakeDeps.*library.*not found in package"
```

## 根因分析
CMake projects may add an ABI version to the installed shared-library filename (for example libtbb.so.12.3 or libtbb12.dll.a) while retaining an unversioned namelink or logical target name (libtbb.so and TBB::tbb). Declaring one platform's linker lookup name for every target makes CMakeDeps search for a file that is not present, so the package builds but its consumer configuration fails.

## 推荐方案
**方法**: physical-library-metadata-binding

**说明**: After package(), derive cpp_info.libs from the platform's actual linker lookup name while preserving the upstream CMake target name in set_property(cmake_target_name). Verify the Windows import-library layout separately from the OHOS/Linux shared-library namelink layout, and branch on shared/static mode when names differ.

**修复命令**:
```
"conan create <recipe> -c tools.build:jobs=2; inspect package lib/; run test_package consumer"
```

**验证**:
```
Build and package the recipe, list package lib/ contents, then run conan create with a real consumer; require CMakeDeps configure and the consumer executable to pass.
```
