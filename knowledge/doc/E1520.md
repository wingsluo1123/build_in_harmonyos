# E1520: Published Conan versions require a new recipe and branch identity

## 基本信息
- **严重度**: 2
- **类别**: conan, evidence, registry, repair, versioning
- **作者**: 2301_80739235
- **来源 PR**: pending

## 错误特征
```
'version_not_incremented|already published with different recipe|cnb.cool.*409|recipe.*collision'
```

## 根因分析
The OHPCD CI registry gate rejects a changed recipe when the same package/version already has a published recipe because the remote does not support parallel recipe revisions for that identity. A local build PASS cannot override this registry identity conflict.

## 推荐方案
**方法**: create-successor-version

**说明**: Preserve the failed PR and CI receipt as immutable history. Increment only the adaptation suffix (for example X.Y.Z -> X.Y.Z.1), keep the upstream source URL/version unchanged, regenerate candidate tree and contract hashes, and submit a distinct PR with exact branch/package/version identity.

**修复命令**:
```
'freeze failed CI -> create successor directory/branch -> update recipe+manifest+test identity -> new Issue/PRE_CREATE -> new PR/POST_CREATE -> exact-head CI'
```

**验证**:
```
run exact-head CI; when L0 reports version_not_incremented, query the suggested successor version, create a new version directory, update recipe self.version and conandata keys, use feat/<package>-<version> branch, and bind a new Issue/PR contract.
```
