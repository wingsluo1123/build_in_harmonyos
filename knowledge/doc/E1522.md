# E1522: Device signer acceptance is distinct from local ELF signature structure

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime, security, exact-byte, w3
- **作者**: 2301_80739235
- **来源 PR**: pending

## 错误特征
```
'Permission denied|RC=126|unsigned.*ELF|codesign.*section|binary-sign-tool.*missing'
```

## 根因分析
A host-side structural signer can add a .codesign section and satisfy an ELF section-count check, but the target enforces its own signer and filesystem execution policy. Executing an unsigned or locally mocked ELF after transfer therefore returns RC=126 even when the file is AArch64, executable, and linked with the expected shared library.

## 推荐方案
**方法**: transfer-then-device-resign

**说明**: Preserve unsigned source artifacts locally and transfer them with byte/sha readback. In PREPARED, operate only on task-private device copies: strip stale .codesign, sign with the endpoint's real binary-sign-tool, require exactly one .codesign section and owner execute, then launch exactly once. Treat any RC=126 as a terminal run failure and create a new successor after release; never relabel a local mock-sign result as target PASS.

**修复命令**:
```
'exact-byte transfer/readback -> device re-sign each ELF -> readelf section count == 1 -> chmod 755 -> unique launch -> process-clean -> release/postrelease'
```

**验证**:
```
transfer exact bytes; device llvm-objcopy --remove-section .codesign; device binary-sign-tool sign -inFile <copy> -outFile <copy> -selfSign 1; device llvm-readelf -SW <copy>; chmod 755 <ELF>; run once with LD_LIBRARY_PATH=<root>
```
