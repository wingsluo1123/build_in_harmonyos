# E1525: Conan profile 中含空格 sysroot 的字符串序列化不能替代 argv 边界

## 基本信息
- **严重度**: 3
- **类别**: platform, cmake, cross-compile, conan, argument-boundary
- **作者**: C91F

## 错误特征
```
no such file or directory.*sysroot|unknown argument.*sysroot|C compiler cannot create executables.*sysroot|clang.*error.*path.*space|ninja.*subcommand failed.*--sysroot
```

## 根因分析
Conan conf/profile 中的 cflags 和 cxxflags 会经历配置解析、buildenv 脚本生成、CMake toolchain 拼接以及 Ninja 命令行解析。把带空格的 Windows sysroot 路径写成一个已经嵌套引号的字符串，只保护当前解析层；后续层可能去掉或转义引号，使 clang 最终收到多个 argv 元素。配置文本看似含完整路径并不能证明编译器参数边界仍然成立。

## 推荐方案
**方法**: task-private-no-space-sysroot-projection

**说明**: 在任务唯一根内创建无空格、无重解析点的 sysroot 投影；逐文件复制并记录文件数、总字节数和零 reparse points，把规范绝对路径直接写入 Conan flag，再以 verbose 编译命令和目标 ELF 双重验证。原 SDK 保持只读，不修改全局 profile。

**修复命令**:
```
Copy the immutable SDK sysroot to F:/HarmonyPC/<task>/toolchain-local/sysroot, bind its inventory, then pass --sysroot=F:/HarmonyPC/<task>/toolchain-local/sysroot as one flag element.
```

**验证**:
```
conan install/create 后检查生成的 buildenv 与 compile_commands.json 或 ninja -v，证明 --sysroot=<absolute-path> 是单一 argv 元素；执行最小编译并用 readelf -h/-d 验证目标 ELF 架构与依赖闭包。
```
