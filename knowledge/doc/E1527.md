# E1527: glibc/libstdc++ 宽松而 musl/libc++ 严格的六类 OHOS C++ 移植差异及修复组合（含 CI worker 上 SDK lld 动态依赖修复位）

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, posix, headers
- **作者**: unknown

## 错误特征
```
cannot initialize a variable of type 'char \*' with an rvalue of type 'int'|no member named 'clock_cast' in namespace 'std::chrono'|missing 'typename' prior to dependent type name|unknown type name 'mode_t'|use of undeclared identifier 'STDIN_FILENO'|invalid operands to binary expression \('__bind<int|reverse_iterator<It> requires It to be a bidirectional iterator|Error loading shared library libxml2\.so\.16
```

## 根因分析
上游 C++ 库普遍按 glibc/libstdc++ 开发，六类差异在 OHOS(musl/libc++) clang15 下暴露：(1) GNU strerror_r 返回 char* 而 POSIX/musl 返回 int；(2) 依赖类型名缺 typename（gcc 宽松、clang 严格，P0634 未覆盖别名/类外定义场景）；(3) C++23 特性（std::chrono::clock_cast、std::string::contains）libc++15 未实现；(4) 公共头裸用 POSIX 类型/宏（mode_t、STDxx_FILENO）依赖 glibc 环境传递包含；(5) 内部头 using namespace std 后裸调用 POSIX 函数名（bind），libc++ 模板精确匹配抢占 C 函数；(6) 迭代器 category 声明（input）与实现（有 operator--）不符，libc++ reverse_iterator 静态断言拒绝。另有一处独立的基础设施位：CI worker 上 OHOS SDK 的 lld 依赖 libxml2.so.16，worker loader 搜索路径未覆盖 SDK llvm/lib，链接子进程无法启动。

## 推荐方案
**方法**: per-error-portability-patch-set

**说明**: 按错误类别逐个补丁（全部可对 gcc/c++26 无损）：(1) strerror_r 按 POSIX 语义改写（返回值==0 时消息在缓冲区）；(2) 补显式 typename；(3) clock_cast<FileClock> 改 file_clock::from_sys（C++20 规定的 sys 链转换；跨时钟时长差异处补显式 time_point_cast）；(4) 公共头补 #include <sys/types.h>/.ih 补 unistd.h；(5) 裸 bind 改 ::bind；(6) category 改 bidirectional_iterator_tag（实现确有 operator-- 时）。基础设施位：conanfile 子进程环境注入 LD_LIBRARY_PATH=<realpath(cxx)>/../lib（SDK llvm/lib 自带 libxml2.so.16；注意编译器路径可能是符号链接，必须 realpath，否则推导出不存在路径使修复失效）。

**修复命令**:
```
conan create archives/b/bobcat/6.14.00 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
conan create archives/b/bobcat/6.14.00 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
