# E1530: Distinguish a missing Automake real script from its missing shebang interpreter before repairing the build

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, autotools, perl, conan
- **作者**: 2501_91199785

## 错误特征
```
\.aclocal-real: No such file or directory|Cwd\.c: loadable library and perl binaries are mismatched|ac-config-macro-dirs\.m4: no such file or directory
```

## 根因分析
On HarmonyOS PC, the published Automake package contained .aclocal-real, but its shebang named absent /data/service/hnp/bin/perl; the wrapper therefore reported the real script as No such file or directory even though it existed. After bypassing that ambiguity, inherited Perl library paths could load an incompatible Cwd binary module, and Automake's Perl module directory still had to be distinguished from its aclocal macro directory.

## 推荐方案
**方法**: invoke-published-automake-real-scripts

**说明**: In the recipe's build environment, use the native Perl executable for ACLOCAL and AUTOMAKE, set PERL to that interpreter, limit PERL5LIB to the Automake package's pure-Perl module directory, pass share/aclocal-<version> to --automake-acdir and share/automake-<version> to --libdir, then run autoreconf -fi. Preserve the published dependency package.

**修复命令**:
```
PERL=<native-perl> PERL5LIB=<automake-share>/automake-<version> ACLOCAL='<native-perl> <automake-bin>/.aclocal-real --automake-acdir=<automake-share>/aclocal-<version> --system-acdir=<automake-share>/aclocal' AUTOMAKE='<native-perl> <automake-bin>/.automake-real --libdir=<automake-share>/automake-<version>' autoreconf -fi
```

**验证**:
```
First test -f <automake-bin>/.aclocal-real and test -e <shebang-interpreter> separately; inspect the shebang with head -n 1; invoke the real scripts with native perl; run autoreconf -fi and conan create with an installed-package consumer on the target.
```
