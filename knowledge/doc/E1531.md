# E1531: 混合语言 Automake 测试须分别绑定实际展开的测试驱动入口

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, testing
- **作者**: A6F2

## 错误特征
```
FAIL:.*\.pl|FAIL:.*\.yaml|binaryload_event_call
```

## 根因分析
Automake 发布包的生成规则可把 C 测试的 LOG_COMPILE 直接定义为其他变量，并给 YAML 等扩展名注册独立的 YAML_LOG_COMPILER；直接设置 LOG_COMPILER 只覆盖默认路径。Perl 测试内部再 exec 相对 Libtool wrapper，完全绕过 Automake 的外层 launcher。因此单一测试启动覆盖无法保证全量 make check 真正执行。

## 推荐方案
**方法**: bind-effective-test-drivers

**说明**: 从生成的 Makefile 而非变量惯例确认每类测试的真实入口；分别覆盖 LOG_COMPILE 与扩展名专用 *_LOG_COMPILER。条件 launcher 只对有 .libs 同名 ELF 的 Libtool wrapper 使用 shell，真实 ELF 原样执行；脚本内部直接调用的 wrapper 须以最小源码补丁显式交给 shell。保持原 TESTS 集、断言、退出码和日志分母。

**修复命令**:
```
make check LOG_COMPILE='<shell> <conditional-launcher>' YAML_LOG_COMPILER='<shell> <yaml-launcher>'
```

**验证**:
```
grep -n -e '^LOG_COMPILE' -e '^YAML_LOG_COMPILER' tests/Makefile; inspect each test driver command and per-test .trs/.log records
```
