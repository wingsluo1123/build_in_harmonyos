# E1535: conan 2.29.1 backup-sources 离线喂源码必须同时提供 sha256 与 sha256.json 元数据，缺一即 NotFoundException

## 基本信息
- **严重度**: 2
- **类别**: network, conan, backup-sources, offline-build, source-mirror
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: ""

## 错误特征
```
Checking backup: <base>|Sources for <url> not found in remote backup <base>
```

## 根因分析
conan 2.29.1 的 backup-sources 查找（caching_file_downloader._do_download）对每个源码包要求 <base>/<sha256> 与 <base>/<sha256>.json 两个文件同时存在，缺 .json 元数据即使正文可下载（HTTP 200）也判 NotFoundException；且该版本不支持 file:// scheme（"No connection adapters"），纯路径报 'No scheme supplied'——旧版离线喂源码方案（file:// 基址 + 仅 sha256 命名文件）在新版 conan 上整体失效。

## 推荐方案
**方法**: dual-file-backup-metadata

**说明**: 在镜像/本地源目录同时放置 <sha256>（源码包本体）与 <sha256>.json（元数据 {"references": {"<name>/<ver>": ["<原始URL>", "<镜像URL>"]}, "timestamp": <epoch>}）；json 的 urls 需包含实际会被请求的每个 URL 形态（含镜像注入后的完整 URL），否则 URL 交集校验失败触发重下载循环。基址用 http(s)（本机起 python http.server 亦可），勿用 file:// 或纯路径。

**修复命令**:
```
printf '{"references": {"pkg/ver": ["https://官方URL", "https://镜像URL"]}, "timestamp": 1760352000}' > <缓存目录>/<sha256>.json
```

**验证**:
```
curl -s -o /dev/null -w "%{http_code}" http://<base>/<sha256> 返回 200 仍可能 NotFoundException；须同时 curl <base>/<sha256>.json 也为 200 才能通过。
```
