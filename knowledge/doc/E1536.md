# E1536: 原生语言扩展触发架构安装根提升时的制品身份绑定

## 基本信息
- **严重度**: 2
- **类别**: perl, packaging, runtime
- **作者**: BCOW

## 错误特征
```
Files found in blib/arch|installing files in blib/lib into architecture dependent library tree|INSTALLED_MODULE_DIFFERS
```

## 根因分析
MakeMaker检测到blib/arch中的原生扩展后，会把同包的Perl模块也安装到架构目录。纯Perl安装根的惯例不能迁移到XS包；未绑定真实安装路径的收尾检查会在真实构建/API成功后错误失败，也可能让消费者加载别处同名模块或旧ABI扩展。 本轮实际CI进一步表明：消费者仍沿用构建目录身份门禁时，生产侧修复不足以闭环；配置投影和消费者分别使用真实UID所有的0700实例临时根，保留原加载、API和inode断言。

## 推荐方案
**方法**: installed-architecture-root-and-actual-xs-binding

**说明**: 按真实安装结果区分通用模块根和架构根，消费者保留解释器核心/架构路径且绑定本包XS加载路径。源模块与官方成员比较，原生扩展以当前解释器真实编译/API证明ABI，不拿同名文件或SONAME替代。只修精确校验入口错误，不搬移官方安装布局或重解释已失败事务。 本轮实际CI进一步表明：消费者仍沿用构建目录身份门禁时，生产侧修复不足以闭环；配置投影和消费者分别使用真实UID所有的0700实例临时根，保留原加载、API和inode断言。

**修复命令**:
```
conan cache path <actual-ref#RREV:PID#PREV>; <actual-private-perl> <original-import-and-public-api-probe>
```

**验证**:
```
保留原make install路径记录，对实际Conan ref/RREV/PID/PREV查询包根，逐项检查pm及已加载XS路径，核对官方源字节及实际公开API、完整原TAP与独立目标回执。
```
