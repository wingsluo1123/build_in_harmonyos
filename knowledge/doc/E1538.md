# E1538: 负向 libc 探测与源码内联 raw syscall 的执行边界

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, syscall
- **作者**: DBS2

## 错误特征
```
SIGSYS|close_range.*NO|undefined reference to.*close_range
```

## 根因分析
libc符号检测返回NO并未覆盖项目随后用__NR宏和inline syscall重新定义HAVE能力的路径；目标进程域真实SIGSYS，必须保留完整原portable close-all/CLOEXEC语义，不把未trace的上游信号归因为具体策略。

## 推荐方案
**方法**: retain-original-complete-portable-fallback-on-observed-target

**说明**: 同一构建能力选项守卫libc和raw fastpath，原完整fd枚举、close和CLOEXEC回退不改；负向能力探测与实际执行验收分层。close_range默认auto，实际SIGSYS域由配方显式disabled；不伪造HAVE_CLOSE_RANGE探测结果。

**修复命令**:
```
查精确源inline syscall路径；保存真实签名own-fd控制；用同一构建能力guard绑定两个fastpath后立即fresh原语义目标验证，不复跑未漂移旧探针制造进度。
```

**验证**:
```
对照实际configure输出和源宏重定义，用一个真实自有fd的签名控制/同raw调用比较RC，再fresh执行原close/CLOEXEC语义组并核对完整receipt链。
```
