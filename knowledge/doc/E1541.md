# E1541: 具有设备副作用的命令行程序应按原始源码身份隔离可测试配置数据面

## 基本信息
- **严重度**: 2
- **类别**: device-safety, source-identity, test-isolation
- **作者**: 2301_80739235
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/13933

## 错误特征
```
consumer-only-help-output|configuration-parser-reimplemented-in-test|test-starts-global-device-daemon
```

## 根因分析
工具没有独立库接口时，帮助输出仅证明启动，复制或重写解析逻辑的消费者只验证测试自身；直接运行正常 main 又可能创建系统设备、抓取输入或启动守护进程。配置解析与设备副作用必须按真实调用边界分离，且测试必须证明引用的是交付版本的原始实现。

## 推荐方案
**方法**: immutable-production-source-parser-isolation

**说明**: 将官方原始实现按精确 SHA256 随包携带，消费者仅重命名 main 后包含该实现，调用无设备副作用的真实解析函数并使用实际依赖库查询结果。保留输入构造、文件读取、数据转换和对象释放完整流程；独立执行普通与平台场景。明确列出未执行的设备创建、事件抓取、注入和守护服务行为。

**修复命令**:
```
执行实际 installed CLI 的帮助与非法参数，再执行 consumer_tests.py consumer 和 harmony；不得把结构字段检查分别膨胀为多个专项用例。
```

**验证**:
```
编译引用哈希绑定官方实现的消费者，把独占目录中的合法配置文件实际解析为数据对象，读取并核验名称、身份字段与事件能力，要求 RC0、源文件哈希不变及完整清理；平台专项另用中文内容和 HMDFS 路径。
```
