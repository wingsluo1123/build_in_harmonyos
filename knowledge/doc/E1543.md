# E1543: 关闭可选 TLS 后仍须保留非 TLS 协议的必需散列闭包

## 基本信息
- **严重度**: 2
- **类别**: dependency, optional-feature, protocol
- **作者**: 2301_80739235
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/14507

## 错误特征
```
non-TLS-protocol-exits-when-TLS-backend-disabled
```

## 根因分析
可选 TLS 后端的编译开关同时控制了独立协议使用的散列实现。禁用 TLS 后构建仍可成功，普通 HTTP 测试也能通过，但非 TLS 握手路径调用散列时会退出；把传输加密与协议散列当成同一能力导致功能闭包断裂。

## 推荐方案
**方法**: separate-protocol-hash-from-optional-transport-encryption

**说明**: 先保留失败测试和精确错误路径，确认必须的原语并非 TLS 特有。从已发布目标二进制选用真实公开散列 API，将 include/lib 与产品依赖显式绑定；只在原 TLS 实现缺席时启用补充提供者。保留原协议用例并增加标准向量，不以常量摘要、空实现或禁测通过。

**修复命令**:
```
对 TLS=OFF 的最终候选执行原协议握手与已知向量；以独立完整套件运行的 RC、清单、日志和输入 SHA-256 判定结果。
```

**验证**:
```
在 TLS 关闭配置下执行原始非 TLS 协议测试，并独立比对固定输入的标准散列向量；核对制品仓精确 OHOS RREV/PID/PREV、完整静态链接闭包和实际目标执行结果。
```
