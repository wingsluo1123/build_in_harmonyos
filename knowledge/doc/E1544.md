## 错误特征

```
RC0-with-empty-or-filtered-suite|runtime-XML-registration-mismatch
```

## 根因分析
使临时文件创建恢复只证明框架能够启动，不证明原完整套件执行。继承的选择器可改变运行清单，RC0或框架百分比不绑定原注册分母；一个外层入口也不等于一个内部用例。

## 推荐方案
**方法**: isolate-selection-and-bind-runtime-identities

**说明**: 先按精确框架实现绑定任务私有临时目录；清除继承的测试选择和fork覆盖环境，保持框架默认隔离。单独设置本次XML结果路径；对未修改的注册源盘点ID，要求运行XML与其双向相等、无重复/失败/跳过，并同时核对RC和整行摘要。按入口数、内部案例数分层记录。

**修复命令**:
```
使用隔离子进程环境执行原套件；以源注册ID、XML结果ID、唯一数和精确摘要联合判定，不以单一退出码或百分比判断完成。
```

**验证**:
```
原始测试源注册清单与运行XML ID集合/唯一数逐项相等；全体结果成功、RC0、摘要分母相等；定向宿主空XML加RC0负例必须拒绝并明确不计入目标分母。
```
