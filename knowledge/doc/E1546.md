## 错误特征
```
tmpfile-returns-null|zero-as-null-pointer-constant|old-style-cast|COMMAND_FAILED-upstream
```

## 根因分析
已有 TMPDIR-aware mkstemp/fdopen 临时流方案只解决运行时存储路径；把同一后端强制包含进 C 与 C++ 多标准严格告警 TU 后，C 风格 malloc 转换和 OHOS NULL=0L 会被 C++ 的 old-style-cast 与 zero-as-null-pointer-constant 告警拒绝。降低上游告警或删掉失败用例会隐藏兼容性缺陷。

## 推荐方案
**方法**: language-aware-test-only-temporary-stream-backend

**说明**: 后端只作用于原上游测试编译。C++11 及以上用 nullptr，C++98 保持其允许的 NULL，C++ malloc 用 static_cast，C 保持 C 转换；TMPDIR 必须是任务私有 storage/Users 子目录，mkstemp 独占创建、fdopen w+b、立即 unlink，失败关闭描述符。原生产头和所有测试断言、sanitizer 与排序场景不改。把重复运行场景和内部故意 Todo skip 分开计数，不扩大独立用例分母。

**修复命令**:
```
在测试私有编译参数中添加 -include ohos_test_tmpfile.h，保留原逐 TU 标准和 Weverything/Werror；C++11+ 采用 nullptr、C++ malloc 采用 static_cast；以原 CTest 清单执行并回读 JUnit。不要对生产安装头注入该后端。
```

**验证**:
```
保留原 CMake 源清单、逐 TU 标准与严格告警；签名真实 try_run 和测试 ELF；ctest --show-only=json-v1 与 JUnit 精确核对注册清单、命令场景与结果；另验消费者、鸿蒙专项、唯一 launch 与 release/postrelease。
```
