## 错误特征
```
harmony_failure_stage=5|file_uid=.*parent_uid=.*process_uid=|st_uid.*getuid.*mismatch
```

## 根因分析
HMDFS 将新建文件的存储属主投影为文件服务 UID；它和进程 UID 不是同一身份域。把二者强行相等作为可访问性门禁会使已完成写入的消费者误报失败，单纯放宽 mode 也不证明读回和 signed dlopen 可行。

## 推荐方案
**方法**: separate-process-and-filesystem-identities

**说明**: 固定任务私有父目录并新鲜读回其存储属主；独占创建 fixture，比较文件与父目录身份，随后校验完整字节、实际功能和清理。代码加载还须单独验证 native signer 与真实 dlopen。

**修复命令**:
```
执行 test_package/harmony_tests/hmdfs_loader.c，并从同一 run 的原始日志、输入哈希、receipt/WAL 与 validator 回读验证。
```

**验证**:
```
对冻结目标日志比较 file_uid、parent_uid、process_uid，并要求 exclusive create、55-byte exact readback、实际 signed library parse 与 cleanup 全链路 RC0；进程 UID/boot/PID 仍由原事务独立校验。
```
