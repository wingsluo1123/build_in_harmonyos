## 错误特征
```
deliberately-false-predicate-returns-zero|assertion-count-correct-but-condition-not-evaluated
```

## 根因分析
无类型约束的 C 测试宏接受倒置的 condition 与 message 参数；非空字符串指针作为条件恒真，即使故意为假的条件也会计数并 RC0。早期源码解包失败使消费者错误尚未被执行到。与 NDEBUG 删除断言不同，这里断言被执行但检查了错误的值。

## 推荐方案
**方法**: source-bound-macro-signature-and-false-predicate-control

**说明**: 先按既有 E483 修正解包元数据而保持源码 URL/SHA；读实际宏定义，纠正 condition/message 顺序；用最小故意失败控制证明断言可发现错误。将宿主负例、原始上游预期失败和目标专项分开计数，保留各自输入和日志 SHA。

**修复命令**:
```
mu_assert(condition, message)
```

**验证**:
```
使用精确哈希头文件，分别编译并执行倒置假条件、正确假条件与正确真条件，检查 RC 0/1/0 与失败计数 0/1/0；随后执行真实目标消费者及独立平台专项。
```
