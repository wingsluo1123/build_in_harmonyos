# E1552: Conan binary download ThreadPool requires SemLock even with a single worker

## 基本信息
- **严重度**: 2
- **类别**: portability, posix, conan
- **作者**: A716

## 错误特征
```
multiprocessing/synchronize.py|_multiprocessing.SemLock|OSError: \[Errno 28\] No space left on device
```

## 根因分析
Conan binary downloads use multiprocessing.pool.ThreadPool for every nonzero core.download:parallel value; that pool allocates a multiprocessing SimpleQueue with SemLock before any binary download, so unavailable semaphore resources can fail even a one-package download.

## 推荐方案
**方法**: task-private-core-download-parallel-zero

**说明**: First distinguish SemLock initialization ENOSPC from file extraction/disk/inode ENOSPC; use supported core.download:parallel=0 in the task-private Conan home global.conf, preserving the exact published binary RREV/PID/PREV and tests.

See the paired Markdown for the exact evidence-backed implementation and verification sequence.
```

```
