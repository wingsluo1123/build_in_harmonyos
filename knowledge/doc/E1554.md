# E1554: Exception-macro API drift in shipped SWIG bindings requires typed guards and ordered language exception mapping

## 基本信息
- **严重度**: 2
- **类别**: compat, build-system, python
- **作者**: 2501

## 错误特征
```
expected expression|unexpected namespace name|MARISA_THROW_IF
```

## 根因分析
A core C++ error macro changed from error-code arguments to exception types, while shipped binding sources still pass old enum constants. Fixing only compilation loses the language-level memory exception contract when a generic exception catch precedes the specific allocation catch.

## 推荐方案
**方法**: preserve-typed-failure-and-regenerate-binding

**说明**: Preserve every allocation guard using the real typed allocation exception. In the source interface map bad_alloc to MemoryError before the generic exception mapping, then regenerate the wrapper with the declared SWIG dependency. Link the released core library; verify module origin and original tests. Ordinary successful tests do not prove memory-exhaustion handling.

**修复命令**:
```
Regenerate from the original .i after typed source guard and ordered exception catch changes.
```

**验证**:
```
Compare the macro declaration with every source caller; regenerate wrapper from the modified interface; run original core tests, complete binding sample and installed-module consumers with module-origin assertions.
```
