# E1559: OHOS 解释器 sys.platform 不稳定——依赖它的第三方纯 Python 包在部分构建上 ImportError（外部依赖须随包 shim）

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, ohos, python, packaging
- **作者**: C1A7

## 错误特征
```
Sorry: no implementation for your platform|don't know how to enumerate ttys on this system|sys\.platform = 'ohos'|list_ports_posix
```

## 根因分析
OHOS 上 os.uname().sysname 与 platform.system() 稳定报 HarmonyOS，但 sys.platform 随解释器构建而变（HNP 解释器报 linux，worker 自带解释器报 ohos，另有构建报 harmonyos/ohos-*）。依赖 sys.platform 做平台分派的第三方纯 Python 代码会因此踩空：pyserial 3.5 的 serial/tools/list_ports_posix.py 按 `plat = sys.platform.lower()` 前缀匹配已知平台，'ohos' 不在其列 → 直接 `raise ImportError("Sorry: no implementation for your platform ('{}')")`；而 tinyprog 在 import 期就 `from serial.tools.list_ports import comports`，于是 import 即失败。本地（linux）全绿、CI（ohos）构建期冒烟必红，属"环境语义不可迁移"（W0b）

## 推荐方案
**方法**: ship-sitecustomize-platform-shim

**说明**: 随包下发 sitecustomize.py（CPython 启动时按 PYTHONPATH 自动导入），仅在 sys.platform 为 ohos/harmonyos 时把正确实现注册到第三方分派器要查的模块名下——本例把 pyserial 的 serial.tools.list_ports_linux 注册为 serial.tools.list_ports_posix，使 `from serial.tools.list_ports import comports` 在 OHOS 上可用。shim 用 `sys.modules.setdefault` 注册、try/except ImportError 兜底，且对非 OHOS 平台零动作（透明）——可参考本仓 cruft 随包下发 sitecustomize.py 的处理

**修复命令**:
```
|
```

**验证**:
```
python3 -c "import sys; print(sys.platform)"; python3 -c "import serial.tools.list_ports as m; print(m.comports.__module__)"（在目标解释器上实测；本地 linux 通过不代表 OHOS 通过）
```
