# E1560: pip 传递依赖闭包随镜像索引浮动——纯 Python 配方须钉死闭包并断言无原生扩展

## 基本信息
- **严重度**: 2
- **类别**: python, dependency, packaging
- **作者**: 3500

## 错误特征
```
ImportError: Error loading shared library .*\.so: Permission denied|Error loading shared library .*rpds.*|ModuleNotFoundError: No module named '(rpds|referencing)'
```

## 根因分析
顶层依赖只钉直接 requirement（如 jsonmerge==1.9.2），其传递依赖约束很松（jsonmerge 仅要求 jsonschema>2.4.0）→ 选版完全交给 resolver；而镜像索引对 rpds-py 的可见性逐次不同（实测 pip download rpds-py 报 "from versions: none"，同一镜像另一次却给出该 wheel），于是同一份配方本地回溯到无依赖的纯 Python jsonschema 2.6.0，CI 选中 jsonschema>=4.18 → referencing → rpds-py（Rust 扩展）。CI profile 把 /data/service/hnp/bin 前置，HNP 进程不能 dlopen 用户存储路径的 .so（E212），构建期自检 `tinyprog --help` 于是报 ImportError: Permission denied

## 推荐方案
**方法**: pin-pip-closure-and-assert-native-free

**说明**: 把顶层依赖与关键传递依赖全部用 == 钉死，并优先选纯 Python 版本（本例 jsonschema==2.6.0，满足 jsonmerge 的 >2.4.0 且无任何原生依赖）；同时在 build() 内扫描 stage 全树，出现 .so/.pyd/.dylib 即失败并点名漂移的依赖——让"闭包漂移"在本地暴露，而不是在 CI 表现为一个与依赖无关的权限错误

**修复命令**:
```
python3 -m pip install --no-compile --target=<stage> <top-level 全钉> jsonschema==2.6.0; find <stage> -name '*.so' -o -name '*.pyd' | grep -q . && raise
```

**验证**:
```
find <stage> -name '*.so' -o -name '*.so.*' -o -name '*.pyd' | wc -l; python3 -m pip download rpds-py --no-deps -i <index>（探测镜像是否提供该原生 wheel）
```
