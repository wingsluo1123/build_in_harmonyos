# E1568: Autoconf 空值能力宏不能按数值 1 的正则误判为缺失

## 基本信息
- **严重度**: 2
- **类别**: compat, detection, autotools, conan
- **作者**: 2501

## 错误特征
```
Required published feature was not detected|#define HAVE_[A-Z_]+ /\*\*/
```

## 根因分析
AC_DEFINE 的空 value 会生成 #define FEATURE /**/；它为 #ifdef/defined 提供真实能力，但仅接受空白或 1 的配置头解析器拒绝注释空值，把已成功编译链接的探测误判为缺失。

## 推荐方案
**方法**: preserve-autoconf-presence-macro-semantics

**说明**: 先回读上游 AC_DEFINE、生成头与源码消费方式，确认这是存在性宏；后置检查按已证明的空值/1/空注释定义格式识别，仅修检查器，不改探测结果、不缓存伪成功、不关闭功能，未知或数值宏 fail closed。

**修复命令**:
```
re.search(r"^#define[ \t]+" + feature + r"[ \t]*(?:1|/\*\*/)?[ \t]*$", config, re.M)
```

**验证**:
```
回读实际 config.h 和 configure 日志；最小检查接受空定义、1、/**/，拒绝 undef、0、未匹配宏；随后对修复候选执行原生构建和实质消费者。
```
