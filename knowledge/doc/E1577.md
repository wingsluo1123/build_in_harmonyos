# E1577: MPD headless（OHOS）消费者测试：null 输出零依赖播放闭环 + add/play/status 状态机断言（协议坑：play N=播放列表索引 / add=music_directory 相对路径）

## 基本信息
- **严重度**: 1
- **类别**: ohos, socket, testing
- **作者**: B1E3

## 错误特征
```
play N 空列表报 Bad song index|add 0: 前缀报 No such directory|headless 无音频设备环境播放闭环无法用 ALSA/JACK 验证
```

## 根因分析
MPD 协议语义三坑：①play N 是当前播放列表索引（非数据库 ID），启动时列表为空 → "Bad song index"；②add <uri> 取 music_directory 相对路径，listall 用的 0: 数据库索引前缀不能传 add → "No such directory"；③播放闭环的唯一可观测信号 = status 轮询的 state=play→stop 迁移（headless 无音频输出）。mpd 0.24 的 null 输出插件在 output_plugins_sources 初始值中（无条件编译），audio_output { type "null" } 配置使 headless 环境零新依赖完成 协议→队列→解码→输出线程 端到端验证

## 推荐方案
**方法**: 消费者测试模板（R40 核心功能验证）：①python3 wave 生成 3s wav（440Hz/44100Hz mono；≥2s 才能稳定捕获状态窗口，0.5s 过短）；②独立配置（独立 port/music_dir/db/log）：audio_output { type "null" name "X" }——注意 0.24 配置格式无等号（name "value"）；③python3 socket 客户端：recv greeting → listall → add <相对路径> → play 0 → 每 0.4s 轮询 status 直到 state=stop 且 saw_play（20 次 ≈ 8s 窗口）；④仅 saw_play 与 saw_stop 均为真才 exit 0（play→stop 闭环证明），失败输出 mpd 日志 tail；⑤mpd --no-daemon <conf>（0.24 配置路径是位置参数，无 --config 选项）

**说明**: null 输出零依赖播放闭环 + 协议状态机断言
