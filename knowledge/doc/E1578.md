# E1578: Windows-hosted OHOS builds need separate Autoconf and CMake tool identities

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, conan, path-quoting, windows-hosted
- **作者**: 2301_80739235
- **来源 PR**: "9782"

## 错误特征
```
"syntax error: unexpected (|no acceptable ld found in $PATH|cannot find input file: `F'|inappropriate file type or format|dummy.c: Permission denied|TMPDIR"
```

## 根因分析
A Conan recipe crossed incompatible execution boundaries. w64devkit invokes compiler paths through a POSIX shell, so Bash arrays and space-bearing tool paths fail; old Autoconf also splits generated F:/ source paths at the drive colon. Windows CMake can compile through a shell wrapper from make but cannot directly execute that .sh wrapper for its link step. OHOS workers may additionally expose a shared TMPDIR that denies package writes; a generated toolchain env file can be overridden by the worker process environment, so config.guess still fails before compilation unless the recipe process and shell wrapper both bind temporary probes to the task build directory.

## 推荐方案
**方法**: task-private-tool-identity-contract

**说明**: Use POSIX-compatible task-local wrappers for the Autoconf phase and bind LD, AR, RANLIB, NM, and STRIP; keep shell utilities and make under a no-space task path; invoke legacy Autoconf from the build directory with a relative configure path so config.status never parses a drive colon as a template separator; on OHOS workers bind TMPDIR to the writable task build folder in the generated environment, the recipe process environment, and any task shell wrapper, pass an explicit build triplet when legacy config.guess cannot write its mktemp dummy probe, use umask 022 for worker ACLs that reject private config.status files, provide a task-local mktemp shim when the worker rejects private subdirectories, and explicitly bind PATH-resolved bash to SHELL/CONFIG_SHELL so Autoconf and libtool do not mix incompatible shell builtins. For a Windows-hosted CMake consumer, resolve the wrapper's native clang.exe identity and carry its target, quoted sysroot, lld, and platform flags into one custom CMakeToolchain instance.

**修复命令**:
```
"bind CC/CXX/LD/AR/RANLIB/NM/STRIP; use relative configure; resolve native clang.exe for Windows CMake; carry --target, quoted --sysroot, -fuse-ld=lld and platform flags; read back RC and consumer build output"
```

**验证**:
```
"sh -n <posix-wrapper>; conan create <recipe> -pr:h=<ohos-profile> -pr:b=<windows-profile>; conan create <recipe> -pr:h=<ohos-profile> -pr:b=<linux-profile>; verify generated TMPDIR is task-local and writable"
```
