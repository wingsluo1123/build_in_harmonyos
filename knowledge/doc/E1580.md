# E1580: Header-only Conan 包的接口目标与上游构建标志隔离

## 基本信息
- **严重度**: 1
- **类别**: portability, cmake, packaging, testing
- **作者**: A1B2

## 错误特征
```
header-only.*CMake.*target|namespace.*util::variant|march=native.*cross
```

## 根因分析
纯头文件库没有二进制产物，若配方不声明 includedirs、空 libdirs 与可消费的 CMake interface target，下游 find_package 或链接阶段会失败；上游 Makefile 的 -march=native 等宿主优化标志也不能直接带入 OHOS 交叉 consumer。

## 推荐方案
**方法**: explicit-header-package-interface

**说明**: 使用 package_type=header-library，仅复制公开头文件与许可证；package_info 明确 includedirs、空 libdirs/bindirs/libs，并设置稳定的 cmake_file_name/cmake_target_name。test_package 通过 CMakeDeps/CMakeToolchain 构建真实 API consumer，test() 保留显式 self.run；上游测试可独立运行，但上游宿主专用优化参数不进入 Conan recipe。

**修复命令**:
```
copy include/**/*.hpp 到 package_folder/include；self.cpp_info.set_property("cmake_target_name", "<namespace>::<target>")；target_link_libraries(consumer PRIVATE <namespace>::<target>)
```

**验证**:
```
conan create <recipe> -tf=test_package -c tools.build:jobs=2；确认 CMakeDeps 解析 mapbox::variant（或对应接口目标）、consumer 实际调用 API 并在交叉构建下完成编译链接。
```
