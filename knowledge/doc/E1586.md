# E1586: OHOS SDK 的 linux/*.h 可能缺少上游 UAPI 的 static inline 助手（linux/fsmap.h 缺 fsmap_sizeof/fsmap_advance）：链接期 undefined symbol，应以项目内 compat 头复制最小实现并切换调用方 include

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, kernel, portability, headers
- **作者**: unknown

## 错误特征
```
undefined symbol: fsmap_sizeof|undefined symbol: fsmap_advance|ld\.lld: error: undefined symbol: [a-z_]+.*(fsmap|uapi|helper)|implicit[- ]function.*(fsmap_sizeof|fsmap_advance)
```

## 根因分析
Linux UAPI 头除结构体/宏外还提供少量 static inline 助手（如 include/uapi/linux/fsmap.h 的 fsmap_sizeof/fsmap_advance）。OHOS SDK sysroot 的同名头可能只保留结构体、裁掉这些函数。调用方（新版代码往往假定助手存在）编译时不报头缺失、链接时报 undefined symbol（示例：xfs_io/xfs_scrub/xfs_spaceman 引用 fsmap_sizeof/fsmap_advance，ld.lld: undefined symbol）。纯头内容差异，与 ABI 无关。

## 推荐方案
**方法**: project-local-compat-header-for-missing-uapi-inlines

**说明**: (1) capability 确认：定位实际使用的 sysroot 头（clang -H 输出路径），grep 确认缺失的 static inline；再用 compile/link 探针复现 undefined symbol。(2) 在项目 include/ 新建最小 compat 头（如 include/fsmap_compat.h）：#include <linux/fsmap.h> 后按上游 UAPI 原文复制缺失实现，签名与语义须一致——输入：上游 UAPI 头中缺失的 static inline 列表；输出：项目内 compat 头 + 调用方 include 切换（可被 refresh-patch 生成为新建文件补丁）。(3) 仅把真正使用助手的调用方从 #include <linux/fsmap.h> 换成 #include "fsmap_compat.h"，不动的文件保持原样。(4) R8 合规：不加 __OHOS__ 平台宏、不修改系统头、不写空壳 stub（复制的是有实质逻辑的上游实现，注释写明出处与原因）。(5) 反向检查：若未来 SDK 更新后提供了同名 inline，compat 头会导致重复定义——升级 SDK 时需重新评估（在注释中标注适用 SDK 版本）。

**修复命令**:
```
ls /data/service/hnp/ohos-sdk.org/*/ohos/native/sysroot/usr/include/linux/   # 定位 sysroot 头目录；与上游 UAPI 同名头逐一对diff
```

**验证**:
```
clang -H -E -xc /dev/null -include linux/fsmap.h 2>&1 | grep fsmap; grep -n "static inline" /data/service/hnp/ohos-sdk.org/*/ohos/native/sysroot/usr/include/linux/fsmap.h; grep -rn "fsmap_sizeof\|fsmap_advance" --include=*.c --include=*.h .
```
