# E1587: OHOS libc 不声明且不导出 reallocarray()：上游报隐式声明/int→pointer 转换或补声明后 undefined symbol，应以 __builtin_mul_overflow + realloc 的溢出检查实现原地替代

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, portability, libc, musl
- **作者**: unknown

## 错误特征
```
call to undeclared function 'reallocarray'|use of undeclared identifier 'reallocarray'|undefined symbol: reallocarray|incompatible integer to pointer conversion initializing .* with an expression of type 'int'
```

## 根因分析
reallocarray() 是 glibc/BSD 扩展（POSIX.1-2024 收录），语义等于 realloc(ptr, nmemb*size) 但带乘法溢出检查（溢出置 errno=ENOMEM 并返回 NULL）。OHOS 的 libc 实测两缺：① <stdlib.h> 不声明（定义 _GNU_SOURCE 也无效）；② libc 不导出符号（手动 extern 声明后 ld.lld 报 undefined symbol: reallocarray）。上游在 C99+ 下调用未声明函数：clang 直接 error（或把返回值当 int，报 incompatible integer to pointer conversion）；补声明则死在链接期——两种报错形态同根因。

## 推荐方案
**方法**: provide-overflow-checked-reallocarray-shim-at-source-level

**说明**: 不要用「extern 声明」或「-Dreallocarray=realloc」绕过：前者死在链接期，后者丢失溢出检查语义。推荐在调用点所在模块（或项目私有 compat 头）定义静态实现，语义与 libc 版本一致——输入：ptr（可为 NULL）、nmemb 与 size（乘法可能溢出）；输出：成功返回可 free 的新指针，乘法溢出时置 errno=ENOMEM 返回 NULL，其余失败沿用 realloc 语义（原块保留）。实现用 __builtin_mul_overflow（clang/gcc 均有）做乘法检查后调用 realloc；命名带项目前缀（如 xfs_reallocarray）避免与未来 libc 声明冲突。xfsprogs 7.2.0 补丁 0009 参考实现：static void *xfs_reallocarray(void *ptr, size_t nmemb, size_t size) { size_t bytes; if (__builtin_mul_overflow(nmemb, size, &bytes)) { errno = ENOMEM; return NULL; } return realloc(ptr, bytes); }

**修复命令**:
```
grep -rn "reallocarray" --include=*.c --include=*.cpp --include=*.h .   # 先清点调用点，再逐个原地替换
```

**验证**:
```
printf '#define _GNU_SOURCE\n#include <stdlib.h>\nvoid *(*p)(void*,size_t,size_t)=reallocarray;\n' > r.c && clang -c r.c -o /dev/null; printf '#include <stdlib.h>\nextern void *reallocarray(void*,size_t,size_t);\nint main(){void*p=reallocarray(0,1,1);free(p);return 0;}\n' > r2.c && clang r2.c -o r2; grep -rn "reallocarray" --include=*.c --include=*.h .
```
