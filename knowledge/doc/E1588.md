# E1588: clang 15 拒绝 C23 的「case 标签后声明」：expected expression + use of undeclared identifier；声明上移到函数/循环顶部或给 case 体加花括号即可

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, clang, compilation
- **作者**: unknown

## 错误特征
```
error: expected expression|use of undeclared identifier '[a-zA-Z_]+'|case [^:]*:\s*\n\s+(const|size_t|int|struct|char|bool|unsigned|long|enum)
```

## 根因分析
C23（及新 GCC 扩展）允许标签（case/default）后直接跟声明；clang 15 未实现该语法（实测默认/gnu11/gnu17 一律报 "expected expression"，且不支持 -std=gnu23），解析失败后同一声明块的使用点连锁报 "use of undeclared identifier"。上游若用 clang≥16/new GCC 开发与 CI，在 OHOS/clang15 上首次暴露。

## 推荐方案
**方法**: hoist-declaration-out-of-switch-or-brace-the-case-body

**说明**: 两种等价修法（按最小 diff 选择）：① 首选把声明移到函数/循环顶部（零语义变化、兼容所有 C 版本，实例：xfsprogs healthmon.c 把 const size_t minsz 移到函数作用域）；② 或给该 case 体加花括号 { } 形成独立块（局部性强、diff 略大）。禁止用 -std=gnu2x/换编译器绕过（OHOS 工具链固定 clang 15）。输入：编译错误定位到的声明语句与所属 case；输出：声明位置调整后的源码补丁——调整后须复核初始化时机与作用域语义（声明在 case 内初始化、使用点同分支内即可安全上移；若跨分支使用需保留原作用域语义）。全树扫描可一次性找出所有命中点（见 verification_cmd 第 3 条），避免编译-修-再编译循环。

**修复命令**:
```
clang -std=gnu23 -c t.c -o /dev/null   # clang15 报 invalid value 'gnu23'，可佐证不可用 gnu23 绕过
```

**验证**:
```
printf 'int f(int c){switch(c){case 1: const int x=2; return x; default: return 0;}}\n' > t.c && clang -std=gnu11 -c t.c -o /dev/null; clang -std=gnu23 -c t.c -o /dev/null; grep -rn -A1 "case [^:]*:$" --include=*.c . | grep -E "^[^:]*-[[:space:]]*(const|size_t|int|struct|char|bool|unsigned|long)"
```
