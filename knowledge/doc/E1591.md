# E1591: Python 程序用 sys.platform.startswith('linux') 分平台时在鸿蒙PC上必然走进 else 分支（CPython on OHOS 报 'ohos'）：OHOS 与 Linux 同族（/proc + clock_gettime 全可用），应把 'ohos' 并入 linux 分支，而不是新写后端

## 基本信息
- **严重度**: 2
- **类别**: platform, compat
- **作者**: unknown

## 错误特征
```
System = .* not supported|ERROR:root:System = ohos not supported|sys\.platform.*not supported|platform .* not supported.*exit
```

## 根因分析
CPython on OpenHarmony 的 sys.platform 实测为 'ohos'（不是 'linux'），platform.platform() 为 'HarmonyOS-HongMeng_Kernel_1.12.0-aarch64-64bit'。任何以 sys.platform.startswith('linux') / == 'linux' 判断的 Python 程序在鸿蒙PC上都会落进 else 分支；若 else 是"不支持则退出"（tuptime 5.2.5 即 logging.error + sys.exit(1)），程序完全不可用且没有任何降级。把 'ohos' 当成"另一个 OS"去新写一套后端是错的：OHOS 用 HongMeng 内核，但对上层暴露的就是 Linux 接口——/proc/uptime、/proc/stat、/proc/sys/kernel/random/boot_id 与 clock_gettime(CLOCK_BOOTTIME/CLOCK_MONOTONIC) 实测全部可用，正是 Linux 后端消费的全部接口。

## 推荐方案
**方法**: add-ohos-to-linux-family-branch

**说明**: (1) 先实测而不是照文档假设：`python3 -c "import sys;print(sys.platform)"` → 'ohos'；(2) 修复就是把 'ohos' 并入 Linux 分支（`sys.platform.startswith(('linux','ohos'))` 或 `in ('linux','ohos')`），因为 OHOS 暴露的 /proc 与 clock_gettime 接口与 Linux 完全一致，这是实质适配不是 stub；(3) **不要**为 OHOS 新写一套后端（重复代码、无从验证），也**不要**用 try/except 把"不支持"吞掉（会掩盖真正的不兼容）；(4) 给 Python 包打这类补丁属于 patch_type=portability，不含平台宏（R8 面向 C 的 __OHOS__ 禁令在此无对应物）；(5) 在 test_package 里留一条**仅 OHOS 生效**的回归用例（断言走 Linux 后端、rc=0、不出现 'not supported'），移除补丁即失败。

**修复命令**:
```
python3 scripts/ohc-run.py refresh-patch --auto <name> <ver>   # 生成 patches/0001-*.patch
```

**验证**:
```
python3 -c "import sys,platform;print(sys.platform, platform.platform())";  python3 <tool> -f <writable-db>; echo "exit=$?"   # 期望 rc=0 且日志出现 System = Linux
```
