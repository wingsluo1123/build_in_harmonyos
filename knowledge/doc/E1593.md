# E1593: OHOS 目标机只有 zh_CN / en_US.UTF-8 / C locale：es_ES、fr_FR 构造即抛异常，上游 locale 相关 SECTION 会优雅跳过（不是用例失败，也不是漏测）

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, runtime, environment, locale
- **作者**: unknown

## 错误特征
```
collate_byname<char>::collate_byname failed to construct for (es_ES|fr_FR)|locale\(\) name not valid|locale not availale on this machine
```

## 根因分析
OHOS 设备镜像未安装 es_ES / fr_FR 的 locale 数据源；libc++ 的 collate_byname<char> 构造失败 → std::locale("es_ES") 抛 std::runtime_error。上游 tuning-library 的 run-all-tests 会额外以 LANG=es_ES / fr_FR / zh_CN / 空各跑一遍，其中 “Test All Constraints SCL and KBM in Spain” SECTION 自己 try/catch 后设 spainAvailable=false 打印 INFO 跳过；main() 里的 std::locale::global(std::locale(getenv("LANG"))) 也落在 catch 分支。全程不影响 TEST_CASE 通过判定。

## 推荐方案
**方法**: report-locale-skip-as-platform-fact-not-test-failure

**说明**: (1) 先用上面的探针程序把目标机实际可用的 locale 集合打出来，写进测试报告/notes，别靠猜；(2) 测试报告必须区分三种“跳过”：TEST_CASE 级跳过（Catch2 summary 的 skipped）、SECTION 级按设计跳过（上游 try/catch）、以及因为 locale 缺失而整条路径未覆盖（本条）；(3) 不要为了“全绿”删除/改写上游 locale 用例，也不要塞入伪造的 locale 数据；(4) 若必须在 OHOS 上真正跑到 es_ES 分支，只能先补目标机 locale 数据（属镜像能力，非配方可解决），否则在报告里如实标注该分支未覆盖。

**修复命令**:
```
./tuning-library-tests "Internal Constraints between Measures" ; LANG=es_ES ./tuning-library-tests
```

**验证**:
```
printf '#include <locale>\n#include <cstdio>\nint main(){for(auto n:{"es_ES","fr_FR","zh_CN","en_US.UTF-8","C"}){try{std::locale l(n);printf("%%s OK\\n",n);}catch(std::exception&e){printf("%%s THROW %%s\\n",n,e.what());}}}' > /tmp/loc.cpp && clang++ -std=c++17 /tmp/loc.cpp -o /tmp/loc && /tmp/loc
```
