## 推荐方案
**方法**: compare-mangled-type-names-as-fallback-after-hash-mismatch

**说明**: 最小复现（可脱离 pytorch 验证，实测数据）：两个 DSO，一个用 -fvisibility=hidden 编译、一个默认；两边各自 typeid(std::optional<long>).name() / .hash_code()。实测 hidden 侧 **name 相同（NSt4__n18optionalIlEE）而 hash 不同（exe=373858220048 / dso=390721439352）**，默认可见性侧 hash 相同（两侧均 370141349968）；改用 strcmp 比 mangled 名，两种情况都判定相等。注意 hidden 变体里导出的入口函数要显式标 __attribute__((visibility("default")))，否则连调用都链接不上（这本身就是"hidden 传染"的旁证）。

**修复命令**:
```
bash -c 'd=$(mktemp -d); printf "#include <optional>\n#include <typeinfo>\nextern \"C\" __attribute__((visibility(\"default\"))) unsigned long f(){return typeid(std::optional<long>).hash_code();}\n" > $d/a.cpp; printf "#include <cstdio>\n#include <optional>\n#include <typeinfo>\nextern \"C\" unsigned long f();\nint main(){printf(\"exe=%%lu dso=%%lu\\n\",typeid(std::optional<long>).hash_code(),f());}\n" > $d/m.cpp; clang++ -std=c++17 -fPIC -shared -fvisibility=hidden -o $d/liba.so $d/a.cpp && clang++ -std=c++17 -o $d/m $d/m.cpp -L$d -la -Wl,-rpath,$d && $d/m'
```

**验证**:
```
nm -D <lib.so> | grep '_ZTI.*<mangled-type>'   # 若动态符号表里没有、而静态表 nm <lib.so> 里是 d/t，即 local 未导出副本
```
