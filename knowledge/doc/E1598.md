# E1598: USE_OPENMP=ON 的库仍让消费者的 at::parallel_for 单线程：该函数是 ATen 的 inline 模板（每个消费者 TU 各自实例化），消费者未编 -fopenmp 时 `#pragma omp parallel` 被静默忽略——必须在 package_info() 里把编译标志导出给消费者（只需编译标志，勿再加第二个运行时）

## 基本信息
- **严重度**: 2
- **类别**: build-system, openmp, package-info, performance
- **作者**: unknown
- **来源 PR**: 12795

## 错误特征
```
distinct threads = 1|parallel_for.*single thread|pragma omp parallel ignored|omp_get_max_threads\(\).*20.*distinct threads.*1|no OpenMP flag on consumer
```

## 根因分析
at::parallel_for / at::parallel_reduce 定义在 aten/src/ATen/Parallel-inl.h（经 ParallelOpenMP.h）里，是 inline 模板而非已编译的库函数：每个使用它的翻译单元都会各自实例化，其中的 `#pragma omp parallel` 也就在消费者 TU 里展开。若消费者 TU 编译时没有 OpenMP 标志，编译器不认识该 pragma 会静默忽略（不报错不警告），循环退化为串行；而库内部同样使用该模板的代码因带标志仍可并行，于是出现"库报告 20 个 worker、消费者观测到 1 个线程"的割裂。判定用 A/B：同一 libtorch_cpu.so（sha256 核对同一文件），消费者分别带与不带 -fopenmp，观测到 20 与 1。官方 libtorch 的 CMake 包在有 OpenMP 时会向消费者传播编译标志，自建 Conan 配方易漏掉这一步。

## 推荐方案
**方法**: export-openmp-compile-flag-only-not-another-runtime

**说明**: 在配方 package_info() 中添加 self.cpp_info.cflags/cxxflags 的 `-fopenmp=libomp`。关键：只导出编译标志，不要再加链接库——若 OpenMP 运行时已静态链入 libtorch_cpu.so（llvm-nm -D 可确认 omp_*/__kmpc_* 是 T 定义符号且无未解析项），消费者目标文件会直接解析到该 .so 内的实现；此时再加第二个 libomp 会引入"一个进程两个 OpenMP 运行时"（OMP: Error #15）。验证方式：编译一个消费者，统计 at::parallel_for 回调里出现的不同 thread::id 数量，应在 set_num_threads(N) 后接近 N。

**修复命令**:
```
grep -m1 PYTORCH_BLAS_USE_CBLAS_DOT <build>/CMakeCache.txt; nm -D --defined-only <pkg>/lib/libtorch_cpu.so | grep -c '__kmpc_fork_call'
```

**验证**:
```
nm -D --defined-only <pkg>/lib/libtorch_cpu.so | grep -E '__kmpc_fork_call|omp_get_max_threads'   # 确认 OMP 运行时已静态链入并被导出
```
