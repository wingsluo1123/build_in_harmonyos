# E1601: 上游为单体仓（monorepo）且被适配组件无独立 tag：不能按 tags/<ver>.tar.gz 取源、也不能把整仓当包子树——须用 commit 钉定 codeload 归档，在 source() 里把包子目录上提为源根（补丁路径随之上提），并为无 configure 的 git 快照 autoreconf -fi 自举

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, packaging, source, structure
- **作者**: libusbauth-configparser-1.0.5
- **来源 PR**: 14972

## 错误特征
```
autoreconf: 'configure\.ac' or 'configure\.in' is required|configure\.ac: No such file or directory|cannot find input file|archive/refs/tags/.*(404|Not Found)|configure: No such file or directory
```

## 根因分析
单体仓（一个 git 仓库，多个组件各占一个子目录，各自带 configure.ac / CMakeLists.txt / Makefile.am）常见于「一组强相关工具」型上游。当制品仓/发行版按「组件」粒度建包时，两个前提同时不成立：① **组件没有独立 tag** —— 仓库 tag 是整仓代次（或干脆不打 tag），故 /archive/refs/tags/<vX.Y.Z>.tar.gz 取不到组件版本对应的源（多点半 404 或取到的是别的代次）；② **不能把整仓当包子树** —— get() 取到的是 usbauth-all-<sha>/，组件树在其下的 libusbauth-configparser/ 子目录里，若直接在源根跑 autoreconf/configure/CMake 会因根目录没有 configure.ac/CMakeLists.txt 而报 'configure.ac is required' / 'No such file or directory'。此外该快照常是**纯 git 归档**（不含生成物），没有现成 configure，必须自举。注意与 component-split-from-umbrella-tarball 的区别：那型是「一份 tarball 用目录级构建入口（Kbuild）拆组件」，本型是「一个 git 仓库里每个组件都是自洽的子项目，各带自己的构建脚本」。

## 推荐方案
**方法**: pin-commit-and-lift-subdir-to-source-root

**说明**: "① 版本号取自组件子目录的构建脚本（autotools 取 AC_INIT 第二参；CMake 取 project(VERSION)；否则取 CHANGELOG/version 文件），并核验它确实对应你想交付的代次。② 源地址用官方 **codeload** 的 commit 化端点 https://codeload.github.com/<owner>/<repo>/tar.gz/<commit-sha>，sha256 本地核验后写进 conandata.yml（不要用 refs/tags，组件可能没有 tag）。③ source() 里 `get(..., strip_root=True)` 拿到 <repo>-<sha>/ 的内容后，把 `<组件子目录>/` 内的条目 `shutil.move` 到 source_folder 根并 rmdir 空目录——autotools/CMake 只有在一棵自洽的树（根目录就有 configure.ac/CMakeLists.txt）里才正确工作。④ 补丁在**上提之后**应用（apply_conandata_patches 以 source_folder 为 base），故 patch 里的路径是 `src/xxx.c`、`CMakeLists.txt`，而不是 monorepo 的完整子路径 `libxxx/src/xxx.c`——否则 patch -p1 落不到文件。⑤ 若该快照无 configure，用 `autoreconf -fi` 自举（automake/libtool 经 tool_requires 拉入；autoconf 家族与 flex/bison 常在设备 /data/service/hnp/bin），并配 VirtualBuildEnv 把 tool_requires 的 bin 注入 conanbuild PATH。"

**修复命令**:
```
|-
```

**验证**:
```
git ls-remote --tags <upstream> | tail                # 看有没有组件级 tag（常为空）
```
