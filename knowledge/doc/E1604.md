# E1604: musl 派生 sysroot 上"libc 结构 × 内核 UAPI 再定义"同名冲突：仅同时包含两侧头文件的 TU 报重定义，须用 libc 鉴别探针（而非平台宏）在引入 UAPI 头期间临时改名

## 基本信息
- **严重度**: 3
- **类别**: detection, portability, libc, musl, headers
- **作者**: @hejin111 <hejin111@noreply.gitcode.com>
- **来源 PR**: 13620

## 错误特征
```
redefinition of 'struct sockaddr_storage'|redefinition of 'struct sockaddr'|redefinition of 'struct msghdr'|redefinition of 'struct ifreq'|redefinition of 'struct in_addr'|struct .* previously defined here|note: previous definition of .struct
```

## 根因分析
glibc 的 <linux/socket.h> 用 #ifndef __GLIBC__ 屏蔽 UAPI 侧结构定义，musl 派生的 OHOS sysroot 中的 UAPI 头照抄 bionic（无条件 #include <sys/socket.h> 且无该互斥），于是 <net/if.h>（经 <sys/socket.h> 提供 sockaddr_storage 等）与 <linux/socket.h>（经 <linux/rtnetlink.h>）在同一个 TU 内双双生效，C 不允许结构体重定义 → 编译失败；glibc 环境同类代码永不触发，故上游代码"在 Linux 上没问题"。

## 推荐方案
**方法**: rename-uapi-symbol-in-libc-probe-window

**说明**: 在引入 UAPI 头文件的窗口内，用 libc 鉴别探针（#if defined(__linux__) && !defined(__GLIBC__)）把冲突符号宏改名，出窗口后 #undef 还原；glibc 路径行为逐字不变，且不使用平台宏 __OHOS__。

**修复命令**:
```
# {\n# if defined(__linux__) && !defined(__GLIBC__)\n#   define sockaddr_storage __linux_uapi_sockaddr_storage\n#   define RESTORE_SOCKADDR_STORAGE 1\n# endif\n#include <linux/rtnetlink.h>\n#ifdef RESTORE_SOCKADDR_STORAGE\n# undef sockaddr_storage\n# undef RESTORE_SOCKADDR_STORAGE\n#endif\n# }
```

**验证**:
```
python3 knowledge/tools/libc-symbol-clash/detect-libc-symbol-clash.py includes --src <src> [--sysroot "$OHOS_SYSROOT"] --min-severity HIGH
```
