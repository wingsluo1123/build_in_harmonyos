# E1610: 非 Windows 音频 GUID 兼容结构误用有符号字段，导致标准 C++ 列表初始化缩窄错误

## 基本信息
- **严重度**: 2
- **类别**: portability, c++, audio, source-patch
- **作者**: SD67

## 错误特征
```
narrowing conversion of .* from 'unsigned int' to 'int'|constant expression evaluates to .* outside the range of type 'int'|KSDATAFORMAT_SUBTYPE_PVOC|GUID.*Data1
```

## 根因分析
旧音频库在非 Windows 平台自行声明 GUID 时使用 int/short 字段，而 Windows GUID 的 Data1/Data2/Data3 是无符号 32/16/16 位。合法 GUID 常量的最高位可置 1；以这些常量初始化有符号字段会触发 C++ narrowing 错误。sndobj 2.6.7 的 KSDATAFORMAT_SUBTYPE_PVOC 第一字段为 0x8312b9c2，正好触发此问题。

## 推荐方案
**方法**: source-patch

**说明**: 在非 Windows GUID 兼容结构中将 Data1 改为 unsigned int、Data2/Data3 改为 unsigned short；保持 32/16/16 位宽和布局，不改变 Windows.h 路径。随后编译实际引用该常量的单元并运行已安装消费者测试。

**修复命令**:
```
patch -p1 < patches/0001-src-SndWaveX.h.patch
```

**验证**:
```
clang++ -std=c++17 -c src/PVRead.cpp -Isrc -Iinclude && conan create archives/s/sndobj/2.6.7 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
