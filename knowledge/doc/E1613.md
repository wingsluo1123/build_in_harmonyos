# E1613: 旧 Autotools 在 OHOS 上不识 musl 三元组且硬编码 GNU binutils 工具名

## 基本信息
- **严重度**: 3
- **类别**: ohos, musl, build-system, autotools
- **作者**: 4523

## 错误特征
```
Invalid configuration.*linux-musl|no acceptable ld found in \$PATH|ar: inaccessible or not found
```

## 根因分析
旧版 config.sub 的 OS 白名单早于 linux-musl；configure 假设 PATH 含 ld，生成的 Makefile 固定 AR=ar。OHOS 设备提供 ld.lld 与 llvm-ar/llvm-ranlib，单靠编译器变量不能修正三处探测。

## 推荐方案
**方法**: precise-config-sub-musl-extension-and-explicit-llvm-tools

**说明**: 精确补充临时 config.sub 的 linux-musl 分支；构建环境指定 LD=ld.lld，make 命令行覆盖 AR=llvm-ar 与 RANLIB=llvm-ranlib；不改共享 PATH。

**修复命令**:
```
使用目标设备现有 ld.lld、llvm-ar、llvm-ranlib 的解析绝对路径，并核对 configure 与 Makefile 实际命令行。
```

**验证**:
```
在一次性构建副本中先验证 config.sub 可识别目标三元组，再运行 configure、make、make check、package 和消费者测试。
```
