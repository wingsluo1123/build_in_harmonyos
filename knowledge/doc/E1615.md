# E1615: 分包 Qt 模块的 qmake 元数据不能沿用 qtbase 的库根目录

## 基本信息
- **严重度**: P1
- **类别**: qt-module-path
- **作者**: QD1

## 错误特征
```
clang-15: error: no such file or directory: */qtbase/*/lib/libQt6Core5Compat.so
```

## 根因分析
Qt5Compat 单独发布为 Conan 包，但其 qt_lib_core5compat.pri 中的 $$QT_MODULE_LIB_BASE 仍解析到 qmake 所在 qtbase 包。qmake 因而生成指向 qtbase/lib/libQt6Core5Compat.so 的绝对链接输入，而实际库在 qt5compat/lib；额外添加 -L 无法覆盖错误的绝对路径。

## 推荐方案
**方法**: 仅在构建目录创建 mkspecs/modules 覆盖层，复制模块自己的 .pri，将模块的 QT_MODULE_LIB_BASE 与 QT_MODULE_INCLUDE_BASE 改为该 Conan 包的实际 lib/include 目录，再通过 QMAKEPATH 让 qmake读取覆盖层。

**说明**: 不改已发布的 Qt 包、不改 sysroot、不靠额外 -L 掩盖错误的绝对输入；对生成的 Makefile 做路径断言，使同类元数据错误在长时间编译前暴露。

**修复命令**:
```
QMAKEPATH=<build>/qmake-overlay qmake6 src/src.pro && grep libQt6Core5Compat.so Makefile && make -j1
```

**验证**:
```
检查 qmake 生成 Makefile 的 LIBS 是否包含真实模块包中的 libQt6Core5Compat.so，再执行 make、conan create 和消费者测试。
```
