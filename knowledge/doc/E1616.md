# E1616: 并发请求测试须证明请求重叠，不能以返回数推断连接和工作线程数

## 基本信息
- **严重度**: P2
- **类别**: test-determinism
- **作者**: KD14

## 错误特征
```
async responses complete but live server-object count is below the requested parallelism
```

## 根因分析
异步调用的完成数只证明响应数，不能证明请求曾同时在服务端存活；若首批响应在后续连接建立前完成，连接可能被复用或对应服务对象已经退出，使瞬时对象数小于请求数。目标平台调度差异会暴露这种竞态。

## 推荐方案
**方法**: 在所有平台统一使用已有的短时慢响应分支，让全部请求在首个响应完成前进入服务端；明确断言该请求的预期响应内容，保留原并发度断言和完整测试分母。

**说明**: 修正测试前提而非降低门槛；若生产代码无证据故障，不应将并发断言改为跳过或仅重试至绿色。

**修复命令**:
```
makeAsyncCalls(client, numRequests, true /* slow */); ctest --output-on-failure --no-tests=error -j1
```

**验证**:
```
在同一目标平台以有界慢响应夹具保持请求重叠，保留原连接数与线程数断言，并完整执行上游测试清单；对比未加夹具的偶发失败日志。
```
