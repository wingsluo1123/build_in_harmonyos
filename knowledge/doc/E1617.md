# E1617: Initialize required dependency context before constructing an installed library object

## 基本信息
- **严重度**: 2
- **类别**: conan, runtime, dependency-initialization
- **作者**: 2501

## 错误特征
```
consumer enters main and version check passes, then crashes at constructor requiring a global event loop
```

## 根因分析
A consumer can link and load a packaged library correctly while omitting a dependency's process-local default context. When the public constructor immediately dereferences that context, the test crashes even though packaging and dynamic loading have succeeded.

## 推荐方案
**方法**: dependency-context-first-consumer

**说明**: Bind the context dependency explicitly in test_package, create and set its default before constructing the tested object, then destroy the object before clearing and releasing the context. Keep this test separate from the upstream test count.

**修复命令**:
```
Inspect constructor and official example call order; run a fresh target Conan create with the corrected consumer and verify upstream and consumer totals independently.
```

**验证**:
```
Compare the library constructor with upstream examples, initialize and register the required default context in the consumer, run the installed-package test, then unregister and release the context after object destruction.
```
