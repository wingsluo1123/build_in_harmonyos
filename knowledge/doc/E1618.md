# E1618: GNU patch dry-run success does not prove Conan patch-ng can apply a whitespace-drifted hunk

## 基本信息
- **严重度**: 2
- **类别**: portability, conan, patch-delivery
- **作者**: 2501

## 错误特征
```
hunk no.1 doesn't match source file|expected:.*actual:.*indent
```

## 根因分析
GNU patch can accept a hunk with fuzz by dropping mismatched context, whereas Conan patch-ng validates the context bytes at the target location. A one-space indentation error in an unchanged context line can therefore pass a local dry-run but fail the actual Conan build before configure. A release configure shebang and inherited CONFIG_SHELL can select different interpreters. A mksh-only print choice then damages generated Libtool when config.status is run by Bash. Explicitly invoke the declared Bash configure interpreter and keep that interpreter bound in CONFIG_SHELL/SHELL.

## 推荐方案
**方法**: byte-exact-conan-patch-preflight

**说明**: Compare every context line with the source bytes including indentation, validate with the same patch-ng engine and zero fuzz used by Conan, then run the changed script and a fresh target Conan create. A release configure shebang and inherited CONFIG_SHELL can select different interpreters. A mksh-only print choice then damages generated Libtool when config.status is run by Bash. Explicitly invoke the declared Bash configure interpreter and keep that interpreter bound in CONFIG_SHELL/SHELL.

**修复命令**:
```
Use a fresh task-private source copy for patch_ng fuzz=False, then run sh config.sub aarch64-unknown-linux-ohos and the current Conan recipe.
```

**验证**:
```
Run patch_ng.fromfile(...).apply(strip=1, root=<fresh source copy>, fuzz=False); execute the patched script's target tuple probe; then confirm a fresh Conan create proceeds beyond apply_conandata_patches.
```
