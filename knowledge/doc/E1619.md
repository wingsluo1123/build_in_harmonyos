# E1619: Revalidate official source owner and archive hash for each new upstream version

## 基本信息
- **严重度**: 2
- **类别**: conan, release, source-identity
- **作者**: 2501

## 错误特征
```
historical source_url owner differs from official current release owner
```

## 根因分析
A historical recipe records the owner and URL of its own released tag, not an immutable owner for all future versions. Replacing only the version in that URL can target a stale repository path and leave the new source identity unproven.

## 推荐方案
**方法**: per-version-official-release-identity

**说明**: Resolve the maintainer's current release page and tag for the requested version, pin its official archive URL and SHA256 in conandata, and use a byte-identical local source archive for target-only offline validation without changing the checked-in URL.

**修复命令**:
```
Inspect release tag and historical manifest; compute SHA256 of the official tarball; verify the W3 bundle hash and Conan source log before reporting build success.
```

**验证**:
```
Compare historical source_url with the current official release tag and homepage, download the versioned archive, check its SHA256, then bind that exact archive and hash to the target Conan create log.
```
