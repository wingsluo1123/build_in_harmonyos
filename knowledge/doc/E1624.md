# E1624: 内核不支持 madvise(MADV_FREE) 返回 EINVAL，上游把它当作不可失败前置条件直接断言终止进程

## 基本信息
- **严重度**: 3
- **类别**: compat, kernel, portability, syscall, runtime
- **作者**: D86C

## 错误特征
```
madvise|MADV_FREE|EINVAL|errno=22|linuxMadvFreeForkBugCheck|serverAssert|Assertion failed
```

## 根因分析
madvise(MADV_FREE) 依赖内核实现该建议；不支持的内核返回 -1 且 errno=EINVAL。部分上游把它写成"不可失败"的探测前置条件——探测失败即断言或直接终止进程(如 keydb 的 linuxMadvFreeForkBugCheck 用 serverAssert)，于是进程在启动期被杀。而被探测的 arm64 fork bug 只存在于"实现了 MADV_FREE"的内核上，不支持的核天然不受影响，把 EINVAL 当致命错误在语义上就是错的。

## 推荐方案
**方法**: degrade-probe-to-not-affected

**说明**: 把 madvise 失败当作"探测无法执行"→ 返回"不受该 bug 影响"，并记录一条警告，而不是断言或终止进程；因为被探测的 bug 仅存在于实现了 MADV_FREE 的内核上。

**验证**:
```
最小复现探针：mmap 一段内存 → mprotect 可写 → 分别调用 madvise(MADV_FREE) 与 madvise(MADV_DONTNEED)，比较两者返回值与 errno。若 MADV_FREE 返回 -1 且 errno=EINVAL 而 MADV_DONTNEED 返回 0，即确认本模式。
```
