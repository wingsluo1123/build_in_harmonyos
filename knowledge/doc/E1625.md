# E1625: meson subproject 上游 wrap-git 拉取不可达时，把修复后源码目录随 conan 包 exports_sources 预置 + wrap_mode=nodownload

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, meson, conan, testing
- **作者**: 3069

## 错误特征
```
subprojects/.*/meson\.build: static_library got unknown keyword arguments|wrap-git|Could not resolve 'gitlab.gnome.org'|Unknown option
```

## 根因分析
meson 测试依赖常用 wrap-git 子项目（如 libglib-testing→gitlab.gnome.org）。OHOS CI 环境上游 git 服务不可达（503），且旧版子项目 meson.build 可能用了新版 meson 已拒绝的参数（static_library 带 version/soversion、docs 需 gtkdoc-scan），导致干净构建无法拉取也无法配置

## 推荐方案
**方法**: 将修复后的子项目源码目录放进 conan 包（exports_sources = patches/*, subprojects/*），conan 自动复制到 source 目录；MesonToolchain project_options['wrap_mode']='nodownload' 禁止 meson 走 wrap 拉取；子项目 meson.build 做新 meson 兼容修复（static_library 去 version/soversion、docs 条件化）

**说明**: 预置目录 + nodownload 双保险：meson 检测到 subprojects/<name>/ 已存在就用本地，彻底绕开上游网络依赖；libmalcontent 0.10.2 + libglib-testing 0.1.0 先例

**修复命令**:
```
conanfile: exports_sources='patches/*','subprojects/*' + MesonToolchain project_options['wrap_mode']='nodownload'
```

**验证**:
```
conan create 干净构建（修复前 wrap 拉取失败/meson 配置报错；预置目录 + 本地修复后构建通过，测试正常执行）
```
