# E1627: OHOS 上系统 gdbus-codegen 的 shebang #!/usr/bin/python3 不可用，meson 须在 native file [binaries] 声明可用 wrapper

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, meson, toolchain
- **作者**: BE90

## 错误特征
```
gdbus-codegen.*No such file or directory|Error 126|/bin/sh: /data/service/hnp/bin/gdbus-codegen
```

## 根因分析
OHOS 系统 /data/service/hnp/bin/gdbus-codegen 是 glib 2.38 的符号链接，shebang 为 #!/usr/bin/python3（普通路径无该解释器）；meson gnome.gdbus_codegen 用 find_program('gdbus-codegen') 从 PATH 优先命中该系统版本，运行时 /bin/sh 报 No such file or directory（code 126）

## 推荐方案
**方法**: conanfile generate()：①从 glib 包复制可用的 gdbus-codegen 并在 generators_folder 生成同名 wrapper（shebang #!/usr/bin/env python3 + runpy 转发）；②把 wrapper 路径写入 conan_meson_native.ini 的 [binaries] 段（meson find_program 优先 native file 声明）；③同时在 gio-2.0.pc 写入 gdbus_codegen 变量

**说明**: meson find_program 查找顺序为 native file [binaries] > PATH，声明 wrapper 可完全绕开系统坏脚本；仅改 PATH 前置不可靠（Meson.configure 用 env=conanbuild 覆盖环境）

**修复命令**:
```
conanfile generate(): 从 glib 包复制 gdbus-codegen 生成 wrapper，写 conan_meson_native.ini [binaries] gdbus-codegen=<wrapper>
```

**验证**:
```
meson setup（命中 /data/service/hnp/bin/gdbus-codegen 报 code 126）；在 conan_meson_native.ini [binaries] 声明 gdbus-codegen='<glib包>/bin/gdbus-codegen wrapper' 后 find_program 优先命中 wrapper 构建通过
```
