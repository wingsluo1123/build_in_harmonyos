# E1630: musl 以 NULL 定义 glibc 的 program_invocation_name 系列，启动早期 strdup(NULL) 导致进程无输出 SIGSEGV

## 基本信息
- **严重度**: 3
- **类别**: compat, portability, libc, musl, runtime
- **作者**: F3B5

## 错误特征
```
program_invocation_name|program_invocation_short_name|strdup|setproctitle|spt_init|SIGSEGV|rc=139
```

## 根因分析
glibc 在程序启动时由运行时填充 program_invocation_name(全路径) 与 program_invocation_short_name(basename) 两个全局量；musl 不提供它们，部分兼容层/shim 只能把它们定义成 NULL。上游若在 main() 早期对这两个量做 strdup() 深拷贝(如 setproctitle 的 spt_init)，strdup(NULL) 即解引用空指针，进程在打印任何输出之前崩溃。

## 推荐方案
**方法**: seed-program-name-globals

**说明**: 在启动最早阶段(进入 main 后、调用 spt_init 之前)按 glibc 语义为这两个全局量赋值：program_invocation_name = argv[0] 原样，program_invocation_short_name = basename(argv[0])，再让原有深拷贝照常执行；不要在兼容层里把它们静态定义为 NULL。

**验证**:
```
同一包内对比链接与不链接 setproctitle.o 的两个可执行文件：前者 rc=139 无输出、后者正常，即可判定。进一步用 gdb 复现栈帧至 strdup。
```
