# E1634: nose-only test shapes are silently dropped by unittest discovery: recovery runner plus a case-count floor and an exact xfail whitelist are required for honest accounting

## 基本信息
- **严重度**: 2
- **类别**: python, conan, testing
- **作者**: 5F23

## 错误特征
```
unittest discover: Ran [0-9]+ tests.*OK \(skipped=[0-9]+\) while the upstream suite is larger|generator test_.* yielded nothing|plain object test class never collected
```

## 根因分析
unittest's discovery collects TestCase subclasses and module-level test_* functions only, while nose also collected generator methods (yield) and plain object classes. discovery therefore exits 0 having run a subset, and a report that quotes only "Ran N tests" understates the upstream total. The gap cannot be closed by installing nose: 1.3.7 is Python 2 syntax and raises SyntaxError on import under 3.12, not ModuleNotFoundError.

## 推荐方案
**方法**: shim-plus-recovery-runner-with-case-floor

**说明**: Ship a minimal shim (about 7 assertion helpers plus SkipTest) as a declared patch so the upstream test sources stay untouched, and add a recovery runner as a second declared patch that replays the nose-only definitions in upstream's own invocation style (chdir into the tests directory, relative imports). Give the runner a MIN_CASES floor and a per-entity coverage gate so a silently shrinking generator makes the build fail, and xfail CPython drift with an exact whitelist that was itself reverse-verified (injecting a new failure must make the run exit non-zero).

**修复命令**:
```
python3 <pkg>/tests/_ohc_extra_upstream_tests.py  # expect: ran=<N> unexpected_failures=0 known_drift=<K>
```

**验证**:
```
python3 -m unittest discover -s <pkg>/tests -p 'test_*.py' -v  # then the recovery runner: python3 <pkg>/tests/_ohc_extra_upstream_tests.py
```
