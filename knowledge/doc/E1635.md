# E1635: New-file patches must carry a /dev/null source header: patch_ng only treats a hunk as file creation when the --- line contains dev/null, while GNU patch -p1 happily accepts --- a/<new-path> and gives a false green

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, patch
- **作者**: 2757

## 错误特征
```
Failed to apply patch.*000N.*\.patch|source/target file does not exist: --- b'a/|patchset.apply -> False
```

## 根因分析
Conan applies recipe patches through patch_ng, whose PatchSet.apply() branches on "dev/null" in item.source to create a file (patch_ng.py:1059-1063, save(target, new_file)). A patch written as --- a/<new-path> / +++ b/<new-path> / @@ -0,0 +1,N @@ takes the ordinary branch instead, findfiles() cannot locate the source side, and the build dies with "source/target file does not exist". GNU patch -p1 accepts the very same file because a -0,0 hunk header implies creation, so verifying with patch -p1 only reports success and the failure surfaces later inside conan create.

## 推荐方案
**方法**: generate-new-file-patches-with-devnull-header-and-verify-with-patch-ng

**说明**: Generate file-creation patches with the /dev/null source label (diff -u --label /dev/null --label b/<repo-rel-path> /dev/null <file>) and verify them with the same parser Conan uses: patch_ng.fromfile(path).apply(strip=0, root=<extracted-tree>). Conan calls apply() with strip=0 and patch_ng already strips the a//b/ prefixes, so passing strip=1 silently writes to a path with the first component removed and can still return True.

**修复命令**:
```
python3 -c "import patch_ng; p=patch_ng.fromfile('patches/0003-x.patch'); print(p.apply(strip=0, root='/tmp/tree', fuzz=False))"
```

**验证**:
```
diff -u --label /dev/null --label b/<path> /dev/null <file> > patches/000N.patch  # then: python3 -c "import patch_ng;print(patch_ng.fromfile('patches/000N.patch').apply(strip=0, root='<tree>'))"
```
