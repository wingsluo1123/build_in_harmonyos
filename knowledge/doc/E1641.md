# E1641: 静态库配方 + 制品仓 shared-only 依赖：FIND_LIBRARY_SUFFIXES 钉 .a 找不到依赖、test/工具目标全静态链接拒绝动态对象

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, linking
- **作者**: 08C5

## 错误特征
```
attempted static link of dynamic object|Library 'xml2' not found in package|set(CMAKE_FIND_LIBRARY_SUFFIXES .a)|ld.lld: error: undefined symbol
```

## 根因分析
上游静态构建分支常把 CMAKE_FIND_LIBRARY_SUFFIXES 钉成 .a（期望依赖也静态），但制品仓该依赖只有共享二进制（如 libxml2/2.15.3 配方硬编码 BUILD_SHARED_LIBS=ON）→ find_library 必败；即便放宽后缀让 find_library 找到 .so，test/工具目标常再叠 -static CXX 标志与 LINK_SEARCH_END_STATIC（追加 -Wl,-Bstatic），ld.lld 直接拒绝链接动态对象。

## 推荐方案
**方法**: ①补丁把后缀放宽为 .a;.so（静态优先共享兜底）；②给 -static 与 LINK_SEARCH_END_STATIC 加开关变量（如 OHOS_BUILD_PARTIAL_STATIC），OHOS 下保留部分静态（libopenbabel.a + NEEDED libxml2.so.16），运行期靠 conanrun env LD_LIBRARY_PATH 指向 conan 包目录；③conan 缓存内依赖 .so 的 symlink 链要在 generate() 实体化（HMDFS symlink 间歇 EACCES 会让 CMakeDeps 库扫描找不到 libxml2.so）。实例：openbabel/3.1.1 patches/0001/0002/0005
