# E1642: conan CMakeToolchain 强制 CONFIG 优先后，上游 Module 风格全大写 <PKG>_FOUND 判断失效，静默回退到错误分支（Eigen2 API/禁用 CML）导致静态链接 undefined symbol

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, conan
- **作者**: DDE8

## 错误特征
```
Found Eigen2:|undefined symbol: OpenBabel::the.*Charges|no member named 'svd' in 'Eigen::Matrix'|no matching member function for call to 'solve'|libxml2 not found - disabling CML support
```

## 根因分析
conan 2.x CMakeToolchain 设 CMAKE_FIND_PACKAGE_PREFER_CONFIG=ON，find_package(Eigen3/LibXml2) 走 CONFIG 模式命中 CMakeDeps 生成的 config，只定义 Eigen3_FOUND/LibXml2_FOUND（与包名同形）；上游按 Module 惯例判全大写 EIGEN3_FOUND/LIBXML2_FOUND → 恒 false → 回退 Eigen2 API 分支（对 Eigen3 头编译 Eigen2 代码）或排除 XML 格式/插件源码，最终静态链接时 undefined symbol。cpp_info.includedirs/libdirs 还可能是相对 package_folder 的相对路径，isfile 探针必须先锚定为绝对路径。

## 推荐方案
**方法**: ①补丁把上游判断改为 if(EIGEN3_FOUND OR Eigen3_FOUND)（含带空格变体）；②module-mode 消费的变量（EIGEN3_INCLUDE_DIR、ZLIB_LIBRARY、LIBXML2_LIBRARY/LIBRARIES）在 recipe generate() 显式注入为绝对路径（EIGEN3 探针文件=signature_of_eigen3_matrix_library）；③若上游 test/tools 分支 set(libs )，CONFIG 模式不填全大写变量，需 recipe 直接注入 LIBXML2_LIBRARIES 缓存变量。实例：openbabel/3.1.1 patches/0001/0003/0004/0005
