# E1647: Raku module packaging and runtime environment on OHOS

## 基本信息
- **严重度**: 2
- **类别**: conan, dependency, runtime, testing
- **作者**: DBC4

## 错误特征
```
"Error loading shared library libmoar.so|Cannot find Log in:|Perl 6/Raku 6.d module executed with Perl 5|Your printf-style directives specify 0 arguments"
```

## 根因分析
Raku 6.d modules require Rakudo and its MoarVM runtime; the Perl 5 executable is not compatible. The Rakudo package's bin/raku dynamically loads libmoar.so from its package lib directory, and module discovery requires RAKULIB to point at the packaged module tree. On OHOS the MoarVM port reports $*KERNEL.name as "harmonyos" and a HongMeng kernel release, whereas Linux reports "linux" - this is the reliable way to bind a test to the OHOS target. Separately, Raku's Str.fmt treats its first positional argument as the format string, so role methods that delegate template dispatch via $template.fmt(|@args) do not provide sprintf semantics and die at runtime.

## 推荐方案
**方法**: use-published-rakudo-and-export-runtime-paths

**说明**: Declare a pinned published rakudo runtime dependency, package pure Raku modules without a fake native build step, set RAKULIB to the package module directory, add the Rakudo package lib directory to LD_LIBRARY_PATH, and disable MoarVM JIT for HarmonyOS execution. For OHOS-specific tests assert on $*KERNEL.name eq 'harmonyos' (Linux reports 'linux'), which genuinely fails off-target. Declare only os/arch settings when nothing is compiled. Do not assert on Raku template dispatch that relies on Str.fmt with caller-supplied arguments.

**修复命令**:
```
"self.requires(\"rakudo/2025.11\", run=True); env[\"RAKULIB\"] = module_dir; env[\"LD_LIBRARY_PATH\"] = rakudo_lib + os.pathsep + env.get(\"LD_LIBRARY_PATH\", \"\"); env[\"MVM_JIT_DISABLE\"] = \"1\"; is $*KERNEL.name, 'harmonyos'"
```

**验证**:
```
"conan create archives/r/raku-log/0.3.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=raku-log/*"
```
