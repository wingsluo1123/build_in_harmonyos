# E1648: task-private-device-signer-closure-and-consumer-proof

## 基本信息
- **严重度**: 2
- **类别**: ohos, permissions, security, consumer, target-validation
- **作者**: 2301_80739235

## 错误特征
```
'Permission denied|Error 126|\.codesign section missing|signing tool unavailable'
```

## 根因分析
A target runner can receive a valid AArch64 ELF and still fail with RC126 or EPERM when the task-private executable was signed with a host-only certificate path or when the target signer is absent; a signature section check alone also does not establish target trust or executable permission.

## 推荐方案
**方法**: task-private-device-signer-closure-and-consumer-proof

**说明**: Treat signing as an immutable input closure. Use the official native OpenHarmony binary-sign-tool on the target with selfSign=1, sign only task-private copies, and verify the signed output before execution. A host JAR/certificate result can be useful structural evidence but is not a substitute for the target signer. On the target, set owner/group/other execute bits and prove the installed consumer executes as the same owner. Do not replay a consumed launch after a signer or payload change; create a successor run.

**修复命令**:
```
'binary-sign-tool sign -selfSign 1 -inFile pending.elf -outFile signed.elf; chmod 755 signed.elf; binary-sign-tool display-sign -inFile signed.elf'
```

**验证**:
```
Freeze the official host inspection and device signer closure by bytes/SHA-256; transfer the native OpenHarmony signer into the task root; sign task-private copies on-device with selfSign; verify AArch64 ELF identity, one valid .codesign block, changed output bytes, owner execute mode after transfer, and an exact target consumer run.
```
