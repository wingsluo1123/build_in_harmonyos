# E1650: GLibTools.cmake 用 pkg-config 变量定位 glib-compile-schemas，conan 生成的 .pc 无该变量

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, configure, glib
- **作者**: E7C2

## 错误特征
```
file failed to open for reading.*oauth2|pkg_config_custom_content|Cannot find glib-compile-schemas|glib_compile_schemas
```

## 根因分析
GLibTools.cmake 在非 CMAKE_CROSSCOMPILING（OHOS 上构建机=目标机，CMAKE_HOST_SYSTEM_NAME 也是 HarmonyOS）分支走 pkg_check_variable(GLib_COMPILE_SCHEMAS gio-2.0 glib_compile_schemas)，而 PkgConfigDeps 生成的 gio-2.0.pc 没有该变量 → configure FATAL 'Cannot find glib-compile-schemas'；此外 hnp 的 gdbus-codegen/glib-mkenums 是 /usr/bin/python3、/usr/bin/perl shebang 的坏脚本，conan glib 包内 ELF 工具未签名（loader 拒绝执行）

## 推荐方案
**方法**: seed-cmake-cache-and-pc-variable

**说明**: 双管齐下：给 gio-2.0 组件注入 pkg_config_custom_content={glib_compile_schemas: <可运行路径>}，同时用 tc.variables 预置 CMake cache（GLIB_MKENUMS/GDBUS_CODEGEN 取 conan glib 的 python 脚本、GLIB_COMPILE_* 取 hnp 的 ELF 并把 libffi 目录加入 LD_LIBRARY_PATH）

**修复命令**:
```
tc.variables["GLIB_COMPILE_SCHEMAS"]="/data/service/hnp/bin/glib-compile-schemas"
```

**验证**:
```
grep -n glib_compile_schemas <generators>/gio-2.0.pc；head -1 /data/service/hnp/bin/{gdbus-codegen,glib-mkenums}
```
