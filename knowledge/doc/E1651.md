# E1651: nss 包内裁剪版 libsqlite3.so 按 -L 顺序遮蔽独立 sqlite3 静态库

## 基本信息
- **严重度**: 2
- **类别**: linking, dependency-graph, lib-order, sqlite
- **作者**: E7C2

## 错误特征
```
undefined symbol: sqlite3_vfs_find|undefined symbol: sqlite3_release_memory|undefined symbol: sqlite3_vfs_register
```

## 根因分析
nss 包 lib/ 里带了自用的 libsqlite3.so（版本脚本裁剪导出，缺 sqlite3_vfs_find/vfs_register/release_memory），而独立 sqlite3/3.49.1 包只有静态 libsqlite3.a；pkg-config 按模块顺序输出 -L，nss 的 libdir 排在 sqlite3 之前时 -lsqlite3 命中前者，camel-db.c 等需要 vfs 注册的代码链接失败

## 推荐方案
**方法**: reorder-link-modules

**说明**: 把 pkg_check_modules 里的 sqlite3 提到 nss 之前，使 -L 顺序让独立 sqlite3（静态归档）先命中

**修复命令**:
```
pkg_check_modules(CAMEL REQUIRED gio-2.0 gmodule-2.0 sqlite3>=... ${mozilla_nss} ${mozilla_nspr})
```

**验证**:
```
llvm-readelf --dyn-syms <nss>/lib/libsqlite3.so | grep -c sqlite3_vfs_find（0 即裁剪版）
```
