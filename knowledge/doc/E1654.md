# E1654: PkgConfigDeps 按 conan 包名生成 .pc，与上游 pkg-config 模块名不一致时探测 miss（gstreamer.pc vs gstreamer-1.0.pc）

## 基本信息
- **严重度**: 2
- **类别**: autotools, conan, pkg-config, gstreamer
- **作者**: B649

## 错误特征
```
No pkg-config for|undefined symbol: g_once_init_enter|undefined symbol: g_type_register_static
```

## 根因分析
依赖配方未调用 cpp_info.set_property('pkg_config_name', ...)，PkgConfigDeps 以包名产出 gstreamer.pc，而上游 PKG_CHECK_MODULES 查的是真实模块名 gstreamer-1.0；探测失败后 DF_CHECK_LIBRARY 之类宏退化为仅 -lgstreamer-1.0，丢掉 Requires: glib-2.0 的传递库，链接期报 glib 符号未定义

## 推荐方案
**方法**: generate-pkgconfig-alias-file

**说明**: 在 generate() 里把 PkgConfigDeps 产出的 gstreamer.pc 复制为 gstreamer-1.0.pc 别名（保留 Requires: glib-2.0），并把别名目录前置到 PKG_CONFIG_PATH，使传递库随 pkg-config 一起展开

**修复命令**:
```
generate() 内把 gstreamer.pc 复制为 pkgconfig-alias/gstreamer-1.0.pc（保留 Requires 行），并将该目录前置到 PKG_CONFIG_PATH
```

**验证**:
```
pkg-config --libs gstreamer-1.0 展开出 -lglib-2.0 -lgobject-2.0 等全链
```
