# E1656: 制品仓 gmp/6.3.0.1 已发布包未导出 include 目录（includedirs 为空），nettle 公开头里的 <gmp.h> 在编译期找不到

## 基本信息
- **严重度**: 2
- **类别**: ohos, headers, cmake, conan, dependency
- **作者**: 0755

## 错误特征
```
gmp\.h.*No such file|'gmp\.h' file not found|gmp\.h: No such file or directory|Cannot find include file.*gmp
```

## 根因分析
制品仓里 gmp/6.3.0.1 的已发布制品（含 revision）在 Conan 元数据中未声明 include 目录，CMakeDeps 生成的 `gmp-release-<arch>-data.cmake` 里 `set(gmp_INCLUDE_DIRS_RELEASE )` 为空；而 nettle 的公开头（nettle/*.h）会 include <gmp.h>，于是任何包含 nettle.h 的编译单元（gnutls、以及被适配库本身）都因找不到 gmp.h 失败。包内其实装了 <pkg>/include/gmp.h，只是没有通过 cpp_info 暴露出来。

## 推荐方案
**方法**: inject-dependency-include-dir

**说明**: 在配方 generate()/build() 里取依赖包的私有 prefix（<dep_package_folder>/include）注入到上游构建，使 <gmp.h> 可达：CMake 工程可用 `tc.variables["GMP_INCLUDE_DIR"]=...` 再由补丁把它 append 到 Nettle 目标；Makefile/autotools 工程用 `CPPFLAGS=-I<dep_package_folder>/include`。绝不写死 /usr/include。

**修复命令**:
```
python3 -c "import os;print(os.path.join(self.dependencies['gmp'].package_folder,'include'))"  # 配方内取路径，禁止硬编码
```

**验证**:
```
grep -n 'gmp_INCLUDE_DIRS' <build_folder>/generators/gmp-*-data.cmake ; ls <gmp_package_folder>/include/gmp.h
```
