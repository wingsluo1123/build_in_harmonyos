# E1659: OHOS musl 不支持 IRELATIVE 重定位：代码用 ifunc（GNU indirect function）做运行期分发时，链接产物含 R_AARCH64_IRELATIVE，动态加载器不处理 -> 二进制编译链接全过但一启动就崩

## 基本信息
- **严重度**: 3
- **类别**: platform, compat, ohos, musl, runtime
- **作者**: F35A

## 错误特征
```
R_AARCH64_IRELATIVE|IRELATIVE|DEATH_CPU_USE_IFUNC|ifunc|relocation.*unsupported
```

## 根因分析
ifunc（__attribute__((ifunc))）让符号解析推迟到加载期，由加载器执行 resolver 并把结果写回，链接器为此产出 R_AARCH64_IRELATIVE 重定位。OHOS 的 musl 动态加载器（ld-musl-aarch64.so）不实现 IRELATIVE 处理路径，于是相关符号保持未解析：轻则 Error relocating ...: symbol not found，重则进程在 libc 初始化阶段直接异常终止。现象具有极强误导性——编译、链接、甚至 readelf -d 看依赖都正常，只有真正运行（或 test_package 冒烟）才暴露。nCine 引擎默认 DEATH_CPU_USE_IFUNC=ON（cmake/ncine_helpers.cmake），用于 memcpy 等热点的 CPU 特性分发，即为此坑。

## 推荐方案
**方法**: disable-ifunc

**说明**: 在构建配置里关闭 ifunc 分发（nCine 用 -DDEATH_CPU_USE_IFUNC=OFF；自研代码则改为编译期静态选择或运行时条件分支）

**修复命令**:
```
cmake -DDEATH_CPU_USE_IFUNC=OFF ...
```

**验证**:
```
readelf -r <bin> | grep -c IRELATIVE   # 修复前 >0，修复后应为 0；随后 <bin> --version 应能正常退出
```
