# E1660: 依赖图中存在两份 GObject：libsoup3 r1/r2 把 glib2 静态内嵌进 libsoup-3.0.so

## 基本信息
- **严重度**: 3
- **类别**: portability, linking, dependency-graph, glib
- **作者**: E7C2

## 错误特征
```
cannot register existing type 'gchar'|_g_value_types_init: assertion failed|GLib-GObject-CRITICAL
```

## 根因分析
libsoup3 3.6.5-r1/r2 的 cpp_info 依赖 glib2/2.88.0（shared=False），libsoup-3.0.so 把 glib2 的 GObject 静态并入并导出其符号（DT_NEEDED 无 libgobject）；与 gtk4 链使用的共享 glib/2.84.0.1.1 在同进程加载即出现两套类型系统，进程启动即 SIGABRT

## 推荐方案
**方法**: swap-dependency-revision

**说明**: 换用 libsoup3/3.6.5-r3（该修订改为依赖共享 glib/2.84.0.1.1，libsoup-3.0.so 动态链接 libgobject-2.0.so.0）

**修复命令**:
```
self.requires("libsoup3/3.6.5-r3")
```

**验证**:
```
llvm-readelf -d <libsoup>/lib/libsoup-3.0.so | grep -E 'NEEDED|SONAME'（无 libgobject-2.0.so.0 即内嵌）；llvm-nm -D --defined-only libsoup-3.0.so | grep ' T g_type_register_static'
```
