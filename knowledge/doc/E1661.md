# E1661: qmake .pri 转 CMake 时内嵌 #include 的 .cpp 不可再单独编译（QtLockedFile 命名空间外定义）

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, cmake
- **作者**: B1CC
- **来源 PR**: 14176

## 错误特征
```
use of undeclared identifier 'QtLockedFile'; did you mean 'QtLP_Private::QtLockedFile'
```

## 根因分析
SASM 内嵌 singleapplication 子树中 qtlocalpeer.cpp 在 QtLP_Private 命名空间内 #include qtlockedfile.cpp/qtlockedfile_unix.cpp（源码内嵌），将这两个 .cpp 再列入 CMake 单独编译会使类定义落在命名空间外

## 推荐方案
**方法**: port-pri-sources-verbatim

**说明**: 严格按 .pri 的 SOURCES 清单移植：只编 qtsingleapplication.cpp 与 qtlocalpeer.cpp，不把 qtlockedfile.cpp / qtlockedfile_unix.cpp 列为编译单元（它们由 qtlocalpeer.cpp 内嵌）

**修复命令**:
```
cmake -S . -B build && cmake --build build   # 源列表去掉 qtlockedfile*.cpp
```

**验证**:
```
grep -n '#include "qtlockedfile' singleapplication/qtlocalpeer.cpp
```
