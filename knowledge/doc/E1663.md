# E1663: Query the device-selected OHAudio callback frame size after stream creation

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime, testing, audio
- **作者**: A6F1

## 错误特征
```
callback frame count mismatch|requested frame count differs from OHAudio callback size|OH_AudioRenderer_GetFrameSizeInCallback|OH_AudioCapturer_GetFrameSizeInCallback
```

## 根因分析
The frame count requested while building an OHAudio stream is not necessarily the frame quantum selected by the device. On the tested HarmonyOS PC, the request was 480 frames and OHAudio selected 960 frames. A backend that keeps sizing buffers or reporting RtAudio bufferFrames from the request can process the wrong number of samples per callback, misreport delivered frames, or access beyond the allocated device buffer.

## 推荐方案
**方法**: query-device-selected-ohaudio-callback-quantum

**说明**: After creating each renderer or capturer, query its actual callback frame size, reject query errors or zero, publish that value as the stream bufferFrames, and size callback buffers from actual frames times channels and sample width with overflow checks.

**修复命令**:
```
Create OHAudio stream -> GetFrameSizeInCallback -> allocate and report using the returned frame count
```

**验证**:
```
On an AArch64 HarmonyOS device, create renderer and capturer streams with a 480-frame request, query each created stream with its GetFrameSizeInCallback API, allocate and process using the returned frame count, and verify callback frame totals and buffer byte sizes against that value.
```
