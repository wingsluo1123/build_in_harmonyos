# E1664: refresh-patch --auto 自动重命名补丁文件后 conandata.yml 的 patch_file 路径失效，conan-verify G2 与本地 CI W3 连锁失败

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, patch, workflow
- **作者**: 9F0D

## 错误特征
```
patch 文件路径或格式错误| conandata.yml 中 patch_file 路径与 patches/ 目录下文件不一致| L1_RESULT=fail: conan create failed| G2: FAIL
```

## 根因分析
scripts/ohc/refresh_patch.py 的 --auto 模式固定按源文件相对路径命名补丁（NNNN-<路径，/ 换成 ->.patch，也是仓库内主流命名约定），且不回写 conandata.yml。作者若先把补丁命名成描述式（如 0001-ohos-cmake-portability.patch）并在 conandata.yml 中引用，finish 内部再次调用 refresh-patch --auto 会按工具约定重命名补丁文件，而 conandata.yml 仍指向旧名 → conan apply_conandata_patches() 找不到补丁 → conan create 失败 → G2 与 W3 连锁失败，finish 只给「patch 文件路径或格式错误」提示。

## 推荐方案
**方法**: align-patch-filenames-with-tool-convention

**说明**: 以 patches/ 目录内实际文件名为唯一事实来源，把 conandata.yml 每个 patch_file 改成工具自动命名（NNNN-<文件名>.patch），不要手工重命名补丁文件；改完在纯净源码上 patch --dry-run -p1 验证可应用，再跑 conan-verify 确认 G2 通过。

**修复命令**:
```
python3 -c 'import pathlib;d=pathlib.Path("archives/<字母>/<包>/<版本>");t=(d/"conandata.yml").read_text();print("\n".join(f"{p.name} {\"ok\" if p.name in t else \"*** MISSING in conandata.yml ***\"}" for p in sorted((d/"patches").glob("*.patch"))))'
```

**验证**:
```
ls archives/<字母>/<包>/<版本>/patches/ && grep -n patch_file archives/<字母>/<包>/<版本>/conandata.yml && cd <纯净源码> && for f in archives/<字母>/<包>/<版本>/patches/*.patch; do patch --dry-run -p1 < $f; done
```
