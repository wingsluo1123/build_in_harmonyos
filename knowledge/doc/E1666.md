# E1666: ohpcd libcurl/8.5.0 以 CURL_USE_OPENSSL=OFF 构建，需要 TLS 的消费方必须改用 curl/8.15.0.x

## 基本信息
- **严重度**: 2
- **类别**: conan, dependency, curl, tls
- **作者**: 68A9

## 错误特征
```
unsupported protocol scheme|CURLE_UNSUPPORTED_PROTOCOL|https://.*failed|CURL_USE_OPENSSL
```

## 根因分析
制品仓存在两个 curl 配方：libcurl/8.5.0 的 generate() 写死 CURL_USE_OPENSSL=OFF（产物无 TLS 后端），curl/8.15.0.x 则 CURL_USE_OPENSSL=True 并 requires openssl/3.5.6.1。消费方按 pkg-config 模块名 libcurl 取用时容易拿到无 TLS 的那个；configure 只探测 curl_easy_strerror，问题延后到运行期 https 请求才暴露

## 推荐方案
**方法**: prefer-tls-capable-curl-package

**说明**: 把 requires 从无 TLS 后端的 libcurl/8.5.0 换成 curl/8.15.0.x（该配方 CURL_USE_OPENSSL=True 并 pin openssl/3.5.6.1），并在消费方验证编译期与运行期 curl 版本一致

**修复命令**:
```
self.requires('curl/8.15.0.1')  # 不要用 libcurl/8.5.0
```

**验证**:
```
被测程序打印 curl 版本与 TLS 后端（如 pianod -v -v 输出 SSL package: OpenSSL / curl runtime version）
```
