# E1668: POSIX shared memory and semaphore names collide in the tested OHOS runtime

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, posix, threading
- **作者**: 03B9

## 错误特征
```
QSharedMemory::attach.*already exists|shm_same_name_create=-1 errno=17
```

## 根因分析
The tested runtime uses one object namespace for sem_open and shm_open. Qt creates a same-name internal semaphore before creating or attaching shared memory.

## 推荐方案
**方法**: separate-internal-ipc-name

**说明**: Give the internal semaphore a distinct deterministic, bounded name while preserving the user-visible shared-memory key and locking.

**修复命令**:
```
Apply qtbase/6.11.1.2 patch 0023 and execute the upstream shared-memory tests, retaining their assertions and adding ownership-based fixture cleanup.
```

**验证**:
```
Compile and run the self-contained native C reproducer in the paired document, then run tst_qsharedmemory with the candidate library.
```
