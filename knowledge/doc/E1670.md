# E1670: OHOS ELF 重签必须用 env=None，conanbuild env 破坏 binary-sign-tool

## 基本信息
- **严重度**: 3
- **类别**: ohos, meson, conan, codesign
- **作者**: 2F28

## 错误特征
```
binary-sign-tool|Permission denied|Error loading shared library|invalid signature|codesign
```

## 根因分析
OHOS 工具链在链接时自动添加 .codesign 签名；meson install 重写 RPATH(dynstr) 使签名失效，loader 以 EPERM 拒绝加载 .so。需在 package() 中重新签名，但 conanfile 的 self.run() 默认应用 conanbuild env，其 LD_LIBRARY_PATH 会破坏 Java 版 binary-sign-tool，生成无效签名，加载仍 EPERM

## 推荐方案
**方法**: package() 中 meson.install() 后用 llvm-objcopy --remove-section .codesign + binary-sign-tool sign -selfSign 1 重签 bin/ 与 lib/ 下所有 ELF；self.run(..., env=None) 避免 conanbuild env 干扰签名工具

**说明**: meson.install() 重写 RPATH 破坏链接期自动签名，package() 内必须重签：先 llvm-objcopy 移除失效 .codesign 段，再用 binary-sign-tool sign -selfSign 1 重签；关键点是 self.run 传 env=None，否则 conanbuild env 的 LD_LIBRARY_PATH 破坏 Java 版签名工具生成无效签名

**修复命令**:
```
self.run('binary-sign-tool sign -inFile f -outFile f -selfSign 1', env=None)
```

**验证**:
```
conan create gdk-pixbuf/2.44.6.1 -o gdk-pixbuf:shared=True && gdk-pixbuf-query-loaders --version && echo $?
```
