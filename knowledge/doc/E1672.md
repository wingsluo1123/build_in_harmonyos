# E1672: target-runtime-capability-gating

## 基本信息
- **严重度**: 2
- **类别**: platform, runtime, memory, capability, upstream-tests
- **作者**: 2301_80739235
- **来源 PR**: 8474

## 错误特征
```
"SIGTRAP.*malloc|test_malloc_compliance.*Failed|RLIMIT_AS|malloc.*proxy"
```

## 根因分析
Some upstream allocator tests assume glibc allocator interposition or enforceable address-space limits. A non-glibc OHOS runtime can compile these tests but trap during malloc proxy startup or cannot enforce RLIMIT_AS, so compile success is not evidence that the runtime contract exists.

## 推荐方案
**方法**: target-runtime-capability-gating

**说明**: Keep the core allocator and supported tests enabled. Disable the optional malloc proxy component when allocator interposition is unavailable and omit only the address-space compliance test when the target cannot enforce its required limit. Record each excluded test and reason in the target inventory.

**修复命令**:
```
"set the CMake component capability in the recipe; guard the exact CTest registration; run the remaining tests"
```

**验证**:
```
Build the normal allocator library, probe the target capability or use a reproducible terminal failure, gate only the unsupported optional tests/components, and run the complete remaining CTest inventory with named exclusions.
```
