# E1673: capability-scoped-exception-visibility

## 基本信息
- **严重度**: 2
- **类别**: platform, abi, capability, shared-library, visibility
- **作者**: 2301_80739235
- **来源 PR**: 8474

## 错误特征
```
"unsafe_wait.*catch|Subprocess aborted.*global_control|header.*Failed"
```

## 根因分析
A C++ exception class defined in a shared library can retain hidden visibility on a Linux-like target whose libc is not glibc. The producer and test executable then use different RTTI identities, so catches for the exception fail or the default assertion path aborts even though compilation and linking succeed.

## 推荐方案
**方法**: capability-scoped-exception-visibility

**说明**: Preserve hidden visibility for ordinary symbols, but push default visibility around the exported exception type when the target's runtime/ABI capability requires it. Use a compiler/platform capability condition, not an application-level workaround or a blanket visibility change.

**修复命令**:
```
"patch the exception declaration; run patch-ng strict replay; run the affected throw/catch CTest cases"
```

**验证**:
```
Build the shared library and its test executable with hidden default visibility, run a throw/catch test across the shared-library boundary, and require the specific exception catch plus the complete remaining CTest inventory to pass.
```
