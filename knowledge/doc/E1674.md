# E1674: 生成型纯数据包必须同时绑定测试数据根与产物语义闭包

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, packaging, testing
- **作者**: 2301_80739235

## 错误特征
```
no \.po files found in domain directory|not well-formed \(invalid token\)|no element found: line 1, column 0|generated (JSON|XML|catalog).*(empty|count drift)
```

## 根因分析
纯数据项目的测试脚本若按当前工作目录解析相对数据路径，Meson 从 build 目录启动时可能匹配零个输入仍返回成功；生成器若直接拼接 XML 属性、遗漏数据域分支或只在下一组开始时冲刷上一组，还会产出存在但非法、空白或尾组缺失的文件。构建目标数量、文件存在性和测试进程 RC 0 都不能证明生成数据语义完整。

## 推荐方案
**方法**: source-bound-tests-and-semantic-generated-output-validation

**说明**: 测试输入从脚本自身或显式 source root 解析并在零输入时失败；生成器先统一转义目标格式的属性值，逐域覆盖全部声明输入，并在 EOF 显式冲刷最后分组；消费者解析所有生成文件、比对逐域记录数，并验证兼容链接与发现元数据。

**修复命令**:
```
resolve test data from Path(__file__).parent; fail when input inventory is empty; parse outputs and assert output_count == source_count for every declared domain
```

**验证**:
```
meson test -C <build> --print-errorlogs --no-rebuild; parse every generated artifact; compare per-domain output record counts with authoritative source counts; reject empty inventories and zero-byte outputs; run the packaged consumer against the installed tree
```
