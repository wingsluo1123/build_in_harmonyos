# E1676: A test target does not guarantee that the library artifact is packaged

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, testing, artifact-packaging
- **作者**: 2301_80739235
- **来源 PR**: pending

## 错误特征
```
Library .* not found in package|conan_package_library_targets|check target
```

## 根因分析
A hand-written build system can define a test or check target that depends only on test executables and object files, while the archive or shared library target remains outside that dependency graph. Running check alone can therefore report passing upstream tests but leave the package without the library named by Conan package_info.libs. The consumer then fails during CMakeDeps generation with a missing-library error.

## 推荐方案
**方法**: explicit-artifact-and-test-targets

**说明**: Inspect the upstream target graph before writing the recipe. Invoke the artifact target (for example all or libname.a) explicitly, then invoke check/test. After package(), assert that every library in cpp_info.libs exists under the package lib root, and run the consumer through the normal generated build files.

**修复命令**:
```
make -C <source> <artifact-target> check; test -f <package>/lib/<library>; conan create <recipe> -pr:h=<target-profile> -pr:b=<build-profile>
```

**验证**:
```
Build the explicit artifact target and the complete upstream test target in one bounded invocation; list the package lib/include roots before compiling an independent test_package consumer.
```
