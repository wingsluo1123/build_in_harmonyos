# E1679: Tolerate non-numeric kernel release strings when parsing version numbers at runtime

## 基本信息
- **严重度**: 3
- **类别**: portability, runtime, version-parsing
- **作者**: akajhsbnz
- **来源 PR**: 7006

## 错误特征
```
stoi: no conversion|std::invalid_argument.*stoi|C\+\+ exception with description "stoi
```

## 根因分析
std::stoi on the leading token of a kernel release string assumes a pure numeric format; OHOS returns "HongMeng Kernel 1.12.0" so the first token is non-numeric and the exception propagates from an unguarded global/platform singleton, failing every test that touches it.

## 推荐方案
**方法**: tolerant-version-parse

**说明**: Wrap stoi in try/catch for std::invalid_argument and std::out_of_range; on parse failure default the version to 0.0 so downstream feature detection falls back to safe paths.

**修复命令**:
```
try { major = std::stoi(parts[0]); minor = std::stoi(parts[1]); } catch (const std::invalid_argument&) { major = 0; minor = 0; } catch (const std::out_of_range&) { major = 0; minor = 0; }
```

**验证**:
```
Run the failing test binary before the fix to see 'stoi: no conversion'; apply the tolerant parse; re-run and observe the exception disappear.
```
