# E1680: 包图解析成功不能代替语言运行时强依赖闭包

## 基本信息
- **严重度**: 2
- **类别**: dependency, packaging, runtime
- **作者**: MRUNTIME

## 错误特征
```
Can't locate .* in @INC|ModuleNotFoundError|Cannot find module
```

## 根因分析
二进制包的配方可能遗漏上游语言元数据中的强依赖，图节点 Download 且 info_invalid 为空仍只证明声明的包图；实际解释器导入时会暴露未声明模块。主线仅有 published 元数据而无可执行配方时也不能视为实际提供者。另一个真实平台差异是HMDFS构建目录投影UID并非进程UID，不能把安全临时根的真实所有权条件误施于整个Conan构建树。 本轮实际CI进一步表明：消费者仍沿用构建目录身份门禁时，生产侧修复不足以闭环；配置投影和消费者分别使用真实UID所有的0700实例临时根，保留原加载、API和inode断言。

## 推荐方案
**方法**: source-requires-graph-and-real-import-closure

**说明**: 区分强运行依赖、核心模块、作者测试与可选后端；每个非核心强依赖绑定真实可执行配方和已发布身份。遇到实际缺模块先沿原错误链补最底层，禁止假aggregate、共享site目录回退或伪造缓存。遇到构建目录UID误判时，仅对实际非链接可写POSIX父根创建每实例独有TemporaryDirectory，子根0700和进程UID严格核验，保留原测试与解释器ABI；只改变TMPDIR，不改系统账户、缓存所有权或认证保护。原生单项成功不能迁移为全父包或发布通过。 本轮实际CI进一步表明：消费者仍沿用构建目录身份门禁时，生产侧修复不足以闭环；配置投影和消费者分别使用真实UID所有的0700实例临时根，保留原加载、API和inode断言。

**修复命令**:
```
conan install --requires=<real-provider/version> --build=never; <actual-private-interpreter> <original-import-and-public-api-probe>
```

**验证**:
```
对比上游 runtime requires 与真实禁构建回退包图；在隔离目标解释器实际逐模块加载、执行真实公开API并回读模块路径与哈希；完整原测试和官方Conan/Finish分别核验。
```
