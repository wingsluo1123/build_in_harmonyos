# E1683: 预生成二进制测试输入的内部完整性与构建消费者绑定

## 基本信息
- **严重度**: 2
- **类别**: packaging, dex, integrity, test-fixture, zip
- **作者**: redex-r219

## 错误特征
```
BadZipFile.*Bad CRC-32.*classes\.dex|Bad CRC-32.*\.dex|DEX.*checksum.*mismatch|aapt2.*Exec format error
```

## 根因分析
传输字节一致不证明 ZIP/DEX 内部校验有效；内部校验有效也不证明构建消费者会读取该文件。prebuilt 模式默认关闭、未绑定预期哈希或 out-of-tree 相对路径落在 build 目录时，仍会调用目标不能执行的宿主生成器。

## 推荐方案
**方法**: task-local-rebuild-and-hash-bind

**说明**: 先核对内部完整性，已知唯一可解释的校验元数据损坏仅修复任务副本；再显式启用既有 prebuilt 模式、绑定冻结预期哈希、按消费者工作目录部署源/build 副本。保留原测试清单和断言；用损坏输入拒绝与原生执行分别验证。

**修复命令**:
```
源与内部完整性校验 -> 必要时 create-new 修复副本 -> 显式 configure 模式与预期 SHA256 -> 核验真实消费路径 -> 有效/损坏定向 -> 原生测试。
```

**验证**:
```
python3 -c "import zipfile; a=zipfile.ZipFile('fixture.apk'); print(a.testzip())"
```
