# E1684: 原生构建与真实账户、认证、权限转换能力必须分阶段验证（PR15075补充）

## 基本信息
- **严重度**: 3
- **类别**: platform, limitation, detection, posix, testing
- **作者**: 2301_80739235
- **来源 PR**: 15075

## 错误特征
```
no passwd entry for self|not installed setuid|REAL_NAMED_ACCOUNT_MISSING
```

## 根因分析
原生编译签名和 usage 不证明真实运行 UID 有命名账户，也不证明认证后端或有效身份转换可用；在账户解析前失败不能计为 parser PASS。

## 推荐方案
**方法**: phase-separated-real-capability-validation

**说明**: 先读原模式控制流，仅对不消费账户/groups的独立纯语法路径延迟NSS初始化，保留原真实UID降权和parser；普通执行及带命令策略/认证路径不省略检查。按真实部署与NSS分支精确验证原安全拒绝，将其与正向认证和身份转换分别统计。

**验证**:
```
记录原生 configure/build RC、getpwuid、UID/EUID、0755部署及每个原命令RC/stdout/stderr；非法parser仅RC1与原syntax error同时接受；Harmony普通执行须真实NSS对应的原精确安全拒绝。r010 CLI3/3和安全拒绝1/1，认证与身份转换未证明；各历史反例及完整SHA见配对MD，不读取凭据。
```
