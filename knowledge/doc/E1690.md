# E1690: Repair installed public headers that include private dependency headers

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, headers, conan
- **作者**: 2501

## 错误特征
```
alsa/seq_event.h file not found|public header includes unexported dependency header
```

## 根因分析
An installed library header includes a dependency subheader not supplied by the published dependency package; downstream consumers fail even when the library itself compiled in a richer source tree. Autoconf can select the mksh print builtin while detecting the configure interpreter, then execute config.status under Bash where print does not exist. That breaks generated Libtool contents even though configure returns success. Use a declared Bash tool consistently for configure and generated-helper execution.

## 推荐方案
**方法**: public-umbrella-include-and-transitive-requirements

**说明**: Replace the private include with the dependency public umbrella header, declare the dependency in the recipe, and ensure downstream compile and link metadata exposes the required public headers and libraries. Autoconf can select the mksh print builtin while detecting the configure interpreter, then execute config.status under Bash where print does not exist. That breaks generated Libtool contents even though configure returns success. Use a declared Bash tool consistently for configure and generated-helper execution.

**修复命令**:
```
patch exported header include; conan create <recipe> -pr:h=<ohos-profile> -pr:b=<ohos-profile>; inspect installed-header consumer compile and run
```

**验证**:
```
Build an installed-package consumer including only the library public header, using the exact published dependency graph, and execute a real API assertion.
```
