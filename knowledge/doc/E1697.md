# E1697: 私有 Python 应用依赖被 Conan 消费图跳过，嵌入式解释器库无法作为运行闭包发布

## 基本信息
- **严重度**: 3
- **类别**: python, conan, runtime
- **作者**: 4E8A

## 错误特征
```
Error in package_info\(\).*package_folder.*NoneType|expected str, bytes or os.PathLike object, not NoneType
```

## 根因分析
共享 C 库嵌入 Conan Python 时，若 Python 与另一宿主依赖的同名传递库版本冲突，可能必须将 Python 要求设为 visible=False；但 Python 包类型为 application，消费者图会跳过这个私有二进制，package_info 中读取其 package_folder 得到 None，运行时也缺 libpython。no_skip=True 保留二进制；仅保留二进制不等于导出运行环境，还须明确传递解释器和库路径。

## 推荐方案
**方法**: retain-private-python-runtime-closure

**说明**: 先核对公开依赖与 Python 的完整二进制版本图；只在确需隔离冲突版本且 API/ABI 完全封装时将 Python 设为 visible=False、no_skip=True，并在 package_info 导出 PYTHONHOME 与 libpython 的运行库路径；构建、测试和安装中凡调用 Python 的步骤均显式应用依赖库运行环境。

**修复命令**:
```
conan graph info <recipe> -pr:h=<ohos-profile> -pr:b=<ohos-profile> -r=ohpcd && conan create <recipe> -pr:h=<ohos-profile> -pr:b=<ohos-profile> --build=never
```

**验证**:
```
对干净 Conan home 执行 conan create；确认消费者图安装 Python 二进制、package_info 不含 None 路径、上游测试全量通过且安装包消费者能初始化 Python 并加载真实模块
```
