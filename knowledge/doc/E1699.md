# E1699: Snapshot-carried configured outputs must be removed from the temporary source before Autotools regeneration

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, source-snapshot
- **作者**: 2501

## 错误特征
```
config.status.*already exists|stale generated Makefile.*compiler|autoreconf.*generated outputs
```

## 根因分析
A source snapshot can include host-specific configure outputs alongside authoritative Autotools inputs. A fresh autoreconf or configure in that mixed tree may consume stale config.status, Makefile or config.h, inherit another host's flags, or fail before generating a target-consistent build.

## 推荐方案
**方法**: exact-generated-output-quarantine

**说明**: Inventory generated versus authoritative source files. Fail if an expected generated output is absent or is a symlink, delete only the exact generated set from the Conan copy before autoreconf, then assert target toolchain flags and installed binary after the clean configure.

**修复命令**:
```
In build(), remove only the verified generated files from self.source_folder before autoreconf --force --install.
```

**验证**:
```
Inspect the release archive file inventory, remove only expected generated outputs from Conan's disposable source copy, then run autoreconf, target configure, make, package and installed-tool consumer.
```
