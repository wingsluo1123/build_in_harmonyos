# E1705: 上游 tarball 404 不一定是版本不存在：先核域名错位再用 Debian watch 与同族先例三角定位

## 基本信息
- **严重度**: 2
- **类别**: upstream-sourcing
- **作者**: calbee21

## 错误特征
```
404 Not Found.*downloads|HTTP 404 on upstream tarball|curl: (22|56).*The requested URL returned error: 404
```

## 根因分析
上游站点存在易混淆域名变体（如 kokkinizita.net vs 官方 kokkinizita.linuxaudio.org），直探变体全部 404 会误判为"官方源不可达"。

## 推荐方案
**方法**: domain-triangulation-via-debian-watch-and-sibling-recipes

**说明**: 上游直探 404 时按三步三角定位：①查同仓同作者/同站先例包的 conandata.yml 上游 URL 形态（域名+目录结构）；②查 Debian sources 的 debian/watch 文件（官方跟踪的版本页与文件名模式）；③候选 URL 用 HEAD 请求验证（200 + Content-Type + Last-Modified 与版本年代吻合即实锤）。三者一致才写进 conandata，仍定不到则如实申报来源（Debian orig tarball）或存证报批，不硬造 URL。

**修复命令**:
```
'git show origin/main:archives/<l>/<同族包>/<版本>/conandata.yml; curl -sL https://sources.debian.org/data/main/<z>/<包名>/<版本>-1/debian/watch; curl -sIL <候选URL>'
```

**验证**:
```
curl -sIL <候选官方URL> | head -5; curl -sL https://sources.debian.org/data/main/<首字母>/<包名>/<版本-修订>/debian/watch
```
