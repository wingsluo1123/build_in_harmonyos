# E1717: E017 镜像注入残留清理：conan-verify/finish 将官方 conandata URL 临时改写为 ghfast 镜像后生成的备份/锁/缓存残留的识别、清理与原子性排除

## 基本信息
- **严重度**: 2
- **类别**: portability, conan, packaging, atomicity, cleanup
- **作者**: pc3-44
- **来源 PR**: (未授权创建)

## 错误特征
```
conandata.yml.ghfast-bak|conandata.yml.orig|.build-status.json.lock|build-cache/predl_cache|gh-proxy.com/file|ghfast.top|JC1.*bak|JC5.*未登记
```

## 根因分析
E017 机制在 github.com:443 不可达时为保证 conan get() 能拉源码，运行期把 conandata.yml 的官方 sources URL 临时改写为 ghfast.top/gh-proxy 镜像并注入 .build-cache/predl_cache 下载缓存；conan 用归档 SHA-256 硬校验内容，镜像仅作传输通道，但回滚不彻底会在工作区留下非交付残留：conandata.yml.ghfast-bak（镜像注入前备份）、conandata.yml.orig（回滚/再生成残留，url 被改写为 gh-proxy.com/file://... 本地缓存路径）、.build-status.json.lock（空锁文件）、.build-cache/predl_cache/*.tar.gz（下载缓存）。这些文件被 junk_check JC1/JC5 拦截，且本地 file:// 形态不可提交（破坏 R39 官方源约束、CI 无法复现）。

## 推荐方案
**方法**: e017-residual-cleanup

**说明**: 识别并物理删除 E017 镜像注入生成的非交付残留（conandata.yml.ghfast-bak / conandata.yml.orig / .build-status.json.lock / .build-cache/），保持 conandata.yml 官方 URL + 归档 SHA-256 不可改写（R39），重跑 finish/W3 复验（退出码 0、JC_RESULT=pass、.ci-result.json exit_code=0），最终原子性审计确保残留不进入 staged/diff/候选 PR。

**修复命令**:
```
rm -f <残留> && rm -rf .build-cache && python3 scripts/ohc-run.py finish <pkg> <ver> built --project-dir <worktree>
```

**验证**:
```
rm -f archives/l/lexy/2025.05.0/conandata.yml.ghfast-bak archives/l/lexy/2025.05.0/conandata.yml.orig .build-status.json.lock && rm -rf .build-cache && git ls-files --others --exclude-standard | grep -v '^archives/l/lexy/' ; python3 scripts/ohc-run.py finish lexy 2025.05.0 built --project-dir <worktree>
```
