# E1727: scope-junk-check-to-current-library-diff

## 基本信息
- **严重度**: 3
- **类别**: build-system
- **作者**: pc1-18

## 错误特征
```
Junk Files: [0-9]+|JC_RESULT=fail: junk_check failed|L0_RESULT=fail: junk_check failed|检查模式: full \([0-9]+ 个文件\)
```

## 根因分析
ci/scripts/junk_check.sh 的扫描范围判定按优先级 pr.diff → incremental(git diff origin/main...HEAD) → full(git ls-files)。当当前库变更尚未提交（adapt 阶段所有新文件均为未跟踪/未 stage 状态）时，git diff origin/main...HEAD 为空，junk_check 回退 full 模式用 git ls-files 整仓扫描，命中 main 基线中历史提交遗留的垃圾路径（如 goaccess/1.10.2/ncurses-headers.tar.gz、scudo-malloc/19.1.6/.manifest-complete 等），从而阻塞一个本身构建/测试/配方全部通过的有效当前库 Adapt。这是扫描范围缺失当前库 diff 表示导致的治理问题，不是当前库缺陷。

## 推荐方案
**方法**: scope-junk-check-to-current-library-diff

**说明**: 将 W3 junk_check 的扫描范围限定到当前库 diff 检测，并对可证实的基线噪声路径采用精确隔离+恢复证据，使 W3 行为路径限定化。不得引入通配符/全局忽略规则、不得删除无关库、不得修改当前库来掩盖框架/基线问题。

**修复命令**:
```
临时隔离精确基线路径后重跑 W3/finish：git rm --cached <精确路径> && python3 scripts/ohc-run.py finish <lib> <ver> built && git add -f <精确路径>（隔离与恢复均须记录前后 SHA-256 与 git 原子性）
```

**验证**:
```
python3 scripts/ohc-run.py finish <lib> <ver> built 2>&1 | grep -q "W3 本地 CI 模拟通过"
```
