# E1732: A test binary compiled from part of the upstream test target can exit 0 with zero cases executed

## 基本信息
- **严重度**: 3
- **类别**: detection, warnings, conan, testing
- **作者**: W082
- **来源 PR**: 7318

## 错误特征
```
\[doctest\] test cases: 0 \| 0 passed \| 0 failed \| 0 skipped|\[doctest\] Status: SUCCESS!|\[doctest\] assertions: 0 \| 0 passed|\[==========\] 0 tests from 0 test suites ran|\[  PASSED  \] 0 tests
```

## 根因分析
In doctest and Catch2 the file that defines the framework main (DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN) compiles and links on its own, and the framework registers only the translation units actually present in the binary. Running that binary reports an empty summary and exit code 0, which every build-system-level success check reads as a pass. Separately, TEST_CASEs wrapped in feature-test-macro guards (#if SEMVER_HAS_CONSTEXPR, __cpp_lib_format, __cpp_impl_three_way_comparison and similar) are preprocessed out of the registration list, so even a complete build reports a lower number than a source scan of the same tree.

## 推荐方案
**方法**: build-the-declared-upstream-target-and-assert-nonzero-case-count

**说明**: Derive the compiled file list from the upstream test target itself (the SOURCES of the add_executable in test/CMakeLists.txt, minus targets that need their own configuration such as a generated-header or MSVC-only TU, and state that exclusion explicitly), never from a guessed single file. After the run, assert on the summary line rather than on the exit code: fail the build when the parsed case count is zero or when the binary registers fewer cases than the upstream target it claims to reproduce.

**修复命令**:
```
awk '/add_executable\(/{f=1} f&&/\.cpp/{print} /\)/{f=0}' <source>/test/CMakeLists.txt; <test-binary> | tee /dev/stderr | grep -qE 'test cases: [1-9][0-9]* \|'
```

**验证**:
```
<test-binary> | tail -3; <test-binary> --list-test-cases | grep -cE '^[^=[:space:]]'; grep -cE '^[[:space:]]*TEST_CASE\(' <upstream-test-dir>/*.cpp
```
