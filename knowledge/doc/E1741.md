# E1741: OHOS libc++ chrono duration::rep 为 long long 时不能只按 int64_t 名称匹配

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, headers, cxx, libcxx
- **作者**: ALPACA

## 错误特征
```
no matching function for call to .to_bytes.|no matching function for call to .from_bytes.|requirement .*long long.* was not satisfied
```

## 根因分析
C++ 固定宽度整数类型是 typedef 别名而不是跨平台统一的名义类型。OHOS libc++ 将 std::chrono::milliseconds::rep 暴露为 long long，而 alpaca 0.2.1 的序列化重载、类型信息和大小端处理只用 std::is_same_v<T, int64_t> 匹配；在 OHOS 上若 int64_t 是另一种 64 位整数类型，chrono 测试会在编译期找不到 to_bytes/from_bytes 重载。

## 推荐方案
**方法**: alias-equivalent-fixed-width-integer-overloads

**说明**: 对 64 位有符号整数处理统一覆盖 int64_t 与 long long：补齐序列化、反序列化和 type_info 的约束，并在大小端转换时以同宽 int64_t 指针调用既有实现；保持字段类型和字节编码格式不变。

**修复命令**:
```
在相关 enable_if/type_info/byte_swap 分支加入 long long；设备端重新编译并运行完整上游测试，不以仅能编译消费者替代上游测试证据。
```

**验证**:
```
cmake -S . -B build -DALPACA_BUILD_TESTS=ON -DALPACA_BUILD_BENCHMARKS=OFF && cmake --build build -j1 && ./build/test/tests
```
