# E1743: Inject a build-system capability macro instead of an OHOS source macro for proc/self/exe process name

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, libc, build-system
- **作者**: 8B28
- **来源 PR**: 7521

## 错误特征
```
util_get_process_name|process_test|__OHOS__|__OHOS_FAMILY__|getprogname not available|program_invocation_name
```

## 根因分析
OHOS musl libc lacks program_invocation_name/getprogname but provides /proc/self/exe; a source-level __OHOS__ guard binds platform adaptation to an uncontrolled macro definition and violates rule R8 (no OHOS conditional-compilation macros in source/patches).

## 推荐方案
**方法**: portability-patch

**说明**: In meson.build, gate on host_machine.system() == 'harmonyos' (or an equivalent build-system platform check) to inject a platform-independent capability macro (e.g. HAVE_READ_PROC_SELF_EXE); in C source, branch only on that capability macro and use readlink("/proc/self/exe") as a POSIX fallback. Never reference __OHOS__/__OHOS_FAMILY__ in source or patches.

**修复命令**:
```
If cc.has_header_symbol('errno.h','program_invocation_name', args:'-D_GNU_SOURCE'): pre_args += '-DHAVE_PROGRAM_INVOCATION_NAME'.  If not that && host_machine.system()=='harmonyos': pre_args += '-DHAVE_READ_PROC_SELF_EXE'
```

**验证**:
```
ninja -C <build> src/util/process_test src/gallium/tests/trivial/ohos_adapt_test && GALLIUM_PIPE_SEARCH_DIR=<build>/src/gallium/targets/pipe-loader <build>/src/gallium/tests/trivial/ohos_adapt_test
```
