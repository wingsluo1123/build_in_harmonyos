# E1744: pkg.m4 预置变量判定是 test -n "$VAR"——空串预置等于未预置，configure 掉进 pkg-config 查询并中止；独立的 GLIB 模块检查（acinclude.m4）同样必须非空预置

## 基本信息
- **严重度**: 2
- **类别**: autotools, configure, conan, pkg-config
- **作者**: Awstme
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/7671

## 错误特征
```
The pkg-config script could not be found|checking for DBUS... no|configure: error: pkg-config|No package.*found
```

## 根因分析
pkg.m4 展开后的预置变量判定是 test -n "$VAR_CFLAGS" 语义，空串不算预置：Conan 配方以空串初始化任一 DBUS_CFLAGS/DBUS_LIBS/GLIB_CFLAGS/GLIB_LIBS 都会让 configure 掉进 pkg-config 查询路径并在 OHOS（无目标 pkg-config/.pc）中止；且部分包经 acinclude.m4 引入独立于 PKG_CHECK_MODULES 的模块检查（libaudclient 的 checking for GLIB ... glib-2.0 >= 2.28，判定同为 test -n）——每个模块检查涉及的全部 CFLAGS/LIBS 预置变量必须全部非空才算预置成功，中止点报的是误导性的 pkg-config 查询失败而非预置缺陷

## 推荐方案
**方法**: all-preset-vars-nonempty

**说明**: 与 dbus-glib/0.114 已验证配方一致：DBUS_CFLAGS/DBUS_LIBS/GLIB_CFLAGS/GLIB_LIBS 四个预置变量在 conanbuild 环境内全部赋非空真实值（指向 E236 la-free 构建私有目录内的依赖头与归档，取自 conan dependencies cpp_info，不用占位串），configure 的 DBUS PKG_CHECK_MODULES 与独立 GLIB 检查同时走预置分支；配合 unset CONFIG_SHELL（姊妹草稿 DRAFT-autoconf269-config-shell-unset-not-empty）后调用 configure

**修复命令**:
```
DBUS_CFLAGS="-I$DEP/include/dbus-1.0 ..." DBUS_LIBS="$DEP/lib/libdbus-1.a ..." GLIB_CFLAGS="-I$DEP/include/glib-2.0 ..." GLIB_LIBS="$DEP/lib/libglib-2.0.a ..." unset CONFIG_SHELL; ./configure ...
```

**验证**:
```
conanfile build() 内以空串预置任一 *_CFLAGS/*_LIBS 后 conan create，configure 在对应模块检查点报 pkg-config 查询失败；四个变量全部非空后两检查点同时走预置分支、conan create EXIT=0；grep -n 'test -n "$DBUS_CFLAGS"' configure 可见判定原样代码
```
