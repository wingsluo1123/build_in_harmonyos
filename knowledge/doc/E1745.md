# E1745: autoconf 2.69 configure 的 CONFIG_SHELL 重执行块 × hnp bash getcwd 失败；绕过必须 unset 而非置空——空 SHELL 被 AC_SUBST 进构建文件后 GNU make 直接 exec "-c"

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, ohos, autotools, conan, shell
- **作者**: Awstme
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/7671

## 错误特征
```
working directory cannot be determined|make: -c: No such file or directory|getcwd: cannot access parent directories|SHELL = $
```

## 根因分析
双重机制均经设备实测：(1) autoconf 2.69 生成的 configure 在 CONFIG_SHELL 非空时无条件 exec $CONFIG_SHELL 重执行自身（2.71 生成无此块，dbus-glib 同环境未触发），CI profile 的 hnp bash 5.3 启动 getcwd 在 HMDFS 上对过期 PWD 失败，configure 以 working directory cannot be determined 中止；(2) 若以 CONFIG_SHELL=（空但已设置）绕过，configure 前导 SHELL=${CONFIG_SHELL-/bin/sh} 对空值不回退，空 SHELL 被 AC_SUBST 进 buildsys.mk，GNU make 以空 SHELL 拼接 [-c, recipe] 直接 exec "-c" 报 make: -c: No such file or directory（Error 127），诊断 make -p | grep ^SHELL 可见空值

## 推荐方案
**方法**: unset-config-shell-before-configure

**说明**: 配方 build() 内调用 configure 前显式 unset CONFIG_SHELL（POSIX unset，不是赋空值），以 conanbuild 环境手工调用 configure 并保留 load_toolchain_args 的官方 configure_args：重执行块不触发、前导真正回退 /bin/sh（toybox ash 无 getcwd 问题）、AC_SUBST 进 buildsys.mk 的 SHELL=/bin/sh；仅对 configure/make 子进程生效不改 profile。替代轨道见姊妹草稿 DRAFT-ohos-autotools-configure-re-exec-cwd-env（保留 CONFIG_SHELL=bash 并预置 os.environ["PWD"]），两轨择一

**修复命令**:
```
self.run(f'unset CONFIG_SHELL; "{configure}" {configure_args}', cwd=self.build_folder, env="conanbuild")
```

**验证**:
```
profile 设 CONFIG_SHELL 后 conan create → configure 报 working directory cannot be determined 并伴随 getcwd errno 风暴；CONFIG_SHELL= 绕过后 conan create → make 报 make: -c: No such file or directory，make -p | grep '^SHELL' 输出 "SHELL = "；unset 后 conan create EXIT=0，buildsys.mk 内 SHELL = /bin/sh
```
