# E1746: audacious buildsys.mk（自研非 automake）适配三事实：仅源内构建（无 VPATH）、无 check 目标（上游无自动化测试）、静态链 LIBS 追加顺序必须依赖在后——GNU ld 单遍左到右解析

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, autotools, linking, conan
- **作者**: Awstme
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/7671

## 错误特征
```
No targets specified and no makefile found|undefined reference to `g_|LIBS.*GLIB_LIBS.*DBUS_LIBS
```

## 根因分析
audacious 家族用自研 m4/buildsys.m4 + buildsys.mk.in（非 automake），发布 tarball 自带预生成 configure 与检入顶层 Makefile：(1) 顶层 Makefile include 生成的 buildsys.mk 且无 VPATH 支持，Conan basic_layout 的 out-of-source build 目录里 make 报 No targets specified and no makefile found，必须 folders.source == folders.build 源内构建；(2) buildsys.mk.in 无 check 目标、四个 Makefile 与 configure.ac 均无 TESTS/check_PROGRAMS/check-local、无 tests/ 目录 → 上游无自动化测试（no_tests 审计口径）；(3) 链接规则 ${LD} -o $@ $$objs ${LIB_LDFLAGS} ${LDFLAGS} ${LIBS} 把 LIBS 全部置于目标对象之后由 GNU ld 单遍左到右解析，上游 Makefile 的 LIBS += ${GLIB_LIBS} ${DBUS_LIBS}（glib 归档在前）在静态链下无法闭合 libdbus-glib-1.a 的 g_* 引用，必须交换为依赖在后

## 推荐方案
**方法**: in-source-layout-plus-libs-order-patch

**说明**: layout() 强制 folders.source=folders.build="."（generators 挪到 conan 子目录）；上游测试审计按 no_tests 口径申报、消费者侧 test_package 以 dlopen+全量导出面覆盖（本包 82 断言）；conandata 补丁交换 Makefile 的 LIBS 追加顺序为 DBUS_LIBS 先、GLIB_LIBS 后，多条静态依赖链按消费者先于依赖的拓扑序追加

**修复命令**:
```
def layout(self): self.folders.source = "."; self.folders.build = "."; self.folders.generators = "conan"  # 补丁：-LIBS += ${GLIB_LIBS} ${DBUS_LIBS} → +LIBS += ${DBUS_LIBS} ${GLIB_LIBS}
```

**验证**:
```
basic_layout 下 conan create → make 报 No targets specified and no makefile found，folders.source=build="." 后通过；grep -rnE '(^|[^A-Za-z_])TESTS|check_PROGRAMS|check-local' Makefile src/*/Makefile buildsys.mk.in configure.ac → 零命中；静态链下交换 LIBS 追加顺序前 make 报 undefined reference to 'g_type_*' 等、交换后全链闭合
```
