# E1747: test_package 的 HarmonyOS 专项测试必须具备 NDEBUG 安全的失败路径、可验证前置条件并纳入自动化门禁

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, testing, openharmony
- **作者**: unknown

## 错误特征
```
ALL_.*ASSERTIONS_PASSED.*NDEBUG|test_package.*assert.*only|locatePath.*print.*only|test_package.*hmos.*not.*in.*add_test|药.*hmos|.*assert.*NDEBUG.*test_package|-lloc
```

## 根因分析
专项测试只用 assert() 判定成败时，Conan build_type=Release 注入 -DNDEBUG 使 assert 整体不求值，测试在任何失败场景下都返回 0（静默通过）；locatePath 等路径解析 API 若无真实文件前置条件则只能打印空结果（空转）；仅手动单独运行的专项测试不进入 conan create 的 test_package 自动化路径，CI 无法证明其被执行；测试注释里的链接命令若与实际 recipe 链接目标不一致（如 -lloc 不存在），会误导维护者复现。

## 推荐方案
**方法**: check-macro-and-resource-precondition-and-ctest

**说明**: (待补充)

**修复命令**:
```
①测试源：用 CHECK(cond) 宏（非零 return + 打印行号）替代 assert；②locatePath：先 mkdir+fopen 真实数据文件到模块目录，再断言 locatePath 返回非空且实际文件存在；③test_package/CMakeLists.txt：add_executable(test_<lib>_hmos ...) + add_test(NAME test_<lib>_hmos COMMAND ...)；④测试头注释链接命令用实际 -l<lib>（从 conanfile package_info.cpp_info.libs 对照）
```

**验证**:
```
1) grep -c 'CHECK(' test_package/test_*.cpp；2) conan create 日志 grep 'Running tests' 后看 Test N: test_* hmos Passed；3) -DNDEBUG 单独编译运行专项测试，确认失败场景仍返回非零；4) grep 测试注释中链接命令与 conanfile.py package_info 的 libs 一致
```
