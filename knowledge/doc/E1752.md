# E1752: Anchor header-only package layout to the top-level public tree before selecting nested build projects

## 基本信息
- **严重度**: 2
- **类别**: headers, build-system, packaging, testing
- **作者**: Awstme

## 错误特征
```
first nested CMakeLists.txt|bench/eggs-variant|wrong source root|strict_variant headers missing
```

## 根因分析
Some source archives contain a valid top-level public header tree and test tree plus unrelated nested examples or benchmarks. A first-match recursive build-file detector can select the nested benchmark as the source root, causing the recipe to package the wrong headers or report the wrong build system even though the requested library is present at the archive root.

## 推荐方案
**方法**: top-level-public-tree-anchor

**说明**: Prefer a top-level public include tree and its declared upstream test entry when they exist. Treat nested CMake projects as candidates only after proving that their targets consume the requested library tree. Preserve the complete upstream inventory and separate executed PASS from expected conditional SKIP.

**修复命令**:
```
find <source> -maxdepth 2 -type d -name include -o -name test; rg -n "project\(|add_executable|strict_variant" <source>
```

**验证**:
```
Inspect the archive inventory, identify the public include/<library>/ tree and upstream test entry before accepting an automatically promoted nested source root; then build and run the source-keyed upstream inventory plus a real consumer.
```
