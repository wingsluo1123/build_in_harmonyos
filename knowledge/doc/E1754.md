# E1754: AFL++ 4.40c 新增 cmplog pass 专项测试在 OHOS LLVM 15/ARM 失败——按平台限制豁免，勿当核心回归

## 基本信息
- **严重度**: 2
- **类别**: platform, llvm, testing, arm, cmplog
- **作者**: 232

## 错误特征
```
cmplog loop back-edge detection test failed|cmplog routines pass instrumentation test failed|cmplog non-standard integer size test failed|CMPLOG too slow to test in ARM CI
```

## 根因分析
AFL++ 4.40c 在 test-llvm.sh 中新增 3 个 cmplog 专项测试（test-cmplog-loops.sh 循环回边 back-edge 检测 / test-cmplog-routines-pass.sh 例程插桩 / test-cmplog-bitint.sh 非标准整数），验证 4.40c 新实现的 cmplog LLVM pass 行为（__cmplog_rtn_hook_* 例程 hook、循环回边去重、位整数支持）。OHOS SDK 使用 LLVM 15.0.4，这些 4.40c 新 pass 功能在 LLVM 15 / ARM 环境下不完整工作：routines/back-edge 依赖较新的 LLVM 行为，bitint 测试在上游脚本中自注已知问题（issue #2704）；上游 ARM CI 亦标记 cmplog 太慢无法测试（issue #2056，脚本内 "CMPLOG too slow to test in ARM CI"）。核心 fuzz 功能不受影响：test-basic.sh 全绿，test-llvm.sh 主体（llvm_mode/threadsafe/dlopen/hardened/laf-intel/floatingpoint/instrumentlist/persistent）全过。（实锤：afl-tools 4.40c 鸿蒙 PC 实机，clang/LLVM 15.0.4，2026-09-04）

## 推荐方案
**方法**: upstream-new-test-exemption

**说明**: 上游新增功能的专项测试失败时按三步判定后豁免（TEST_QUALITY_SPEC §3.3），在 manifest/notes 声明豁免依据，不阻塞 PR：①对比上一版本（4.33c）test-llvm.sh 确认测试为新增（非既有回归）；②查上游脚本注释/issue（bitint=issue #2704，ARM CI=issue #2056）；③跑核心测试确认无回归（basic + llvm 主体全绿）。

**修复命令**:
```
判定模板：1) git diff 上一版本 test-llvm.sh | grep cmplog 确认新增；2) 查上游 issue #2704/#2056 与脚本内 "too slow" 注释；3) test-basic.sh 全绿 + test-llvm.sh 主体全绿 = 无核心回归 → 豁免并记录
```

**验证**:
```
cd <构建目录>/test && ./test-llvm.sh 2>&1 | grep -E "cmplog.*test failed|too slow to test in ARM CI"
```
