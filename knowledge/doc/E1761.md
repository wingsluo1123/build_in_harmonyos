# E1761: 静态 OpenSSL（libcrypto.a）下，上游含错误注入的自定义 OpenSSL 符号与静态库重复定义；按上游官方 HUNTER_ENABLED 守卫跳过该测试文件

## 基本信息
- **严重度**: 2
- **类别**: portability, linking, testing, security, link
- **作者**: unknown

## 错误特征
```
duplicate symbol: EVP_PKEY_CTX_new_from_name|EVP_PKEY_CTX_new_from_pkey|OSSL_PARAM_BLD_new|libcrypto.a|HUNTER_ENABLED|static linking
```

## 根因分析
依赖 OpenSSL 且测试含错误注入的 C/C++ 库（如 jwt-cpp OpenSSLErrorTest.cpp）会自定义同名 OpenSSL 符号（EVP_PKEY_CTX_new_from_name / EVP_PKEY_CTX_new_from_pkey / OSSL_PARAM_BLD_new）以触发/探测错误路径。动态 libcrypto.so 时自定义符号覆盖库符号；静态 libcrypto.a 时两者在同一可执行文件内重复定义，ld.lld 报 duplicate symbol。上游官方在 OpenSSLErrorTest.cpp 用 `#ifndef HUNTER_ENABLED // Static linking (which hunter always does) breaks the tests (duplicate definition), so skip them` 守卫，tests/CMakeLists.txt 在 HUNTER 分支也定义 HUNTER_ENABLED=1。即静态构建下跳过该文件是上游官方语义。

## 推荐方案
**方法**: upstream-hunter-static-guard

**说明**: 静态 OpenSSL 构建测试时，按上游官方 HUNTER_ENABLED 守卫语义编译：给测试目标加 -DHUNTER_ENABLED 宏（等价上游 Hunter 静态构建），使含错误注入自定义符号的测试文件（OpenSSLErrorTest.cpp 类）按 `#ifndef HUNTER_ENABLED` 被排除，其余用例正常运行。不得为了强跑该文件而改用动态链接或删除守卫（破坏上游语义），也不得伪造 0/0 通过率。

**修复命令**:
```
cmake ... -DCMAKE_CXX_FLAGS="-DHUNTER_ENABLED" && make -j4 jwt-cpp-test && ./jwt-cpp-test
```

**验证**:
```
cmake -DJWT_BUILD_TESTS=ON -DCMAKE_CXX_FLAGS=-DHUNTER_ENABLED ... && make -j4 jwt-cpp-test && ./jwt-cpp-test
```
