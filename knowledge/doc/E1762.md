# E1762: conandata.yml 注释中出现裸 http(s) URL 会被 W3 pre-download 正则误当作源码 URL，并在 replace 时把完整归档 URL 内该子串一并改写为 file:// 导致 conan create 403/NotADirectoryError

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, ci-script, pre-download, url
- **作者**: unknown

## 错误特征
```
gh-proxy.com/file://|predl_cache|NotADirectoryError|403: Forbidden|conan create failed|source URL(s)
```

## 根因分析
ci/conan/build_and_test.sh 的 pre-download 脚本用正则 `https?://[^\s"']+` 从 conandata.yml 提取源码 URL，注释行中的裸仓库 URL（如 `https://github.com/Thalhammer/jwt-cpp`）也会被匹配；随后 `content.replace(url, f'file://{local_path}')` 会对完整归档 URL（`https://github.com/Thalhammer/jwt-cpp/archive/refs/tags/v0.7.1.tar.gz`）内含的该短子串也执行替换，生成畸形 `file://.../predl_cache/{hash}_jwt-cpp/archive/refs/tags/v0.7.1.tar.gz`；conan get() 先试 `https://gh-proxy.com/file://...`（403），再试本地畸形路径（NotADirectoryError），conan create 失败。

## 推荐方案
**方法**: comment-remove-bare-url

**说明**: conandata.yml 注释中不写裸 http(s) URL（仓库根或归档均可），只保留官方 sources.url 一处官方归档 URL + 对应 SHA-256；注释可写纯文本（名称/版本/tag）而不含 URL，避免被 pre-download 正则误提取与子串改写污染。若确需引用官方来源，写完整 tag 描述文字而非 URL，或参考既有库（range-v3 0.12.0）的注释风格。

**修复命令**:
```
（编辑 conandata.yml 注释去掉 URL）; python3 scripts/ohc-run.py finish <pkg> <ver> built
```

**验证**:
```
git show HEAD:archives/j/jwt-cpp/0.7.1/conandata.yml | grep -c 'https://' && python3 scripts/ohc-run.py finish jwt-cpp 0.7.1 built
```
