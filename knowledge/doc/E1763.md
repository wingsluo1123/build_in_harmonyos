# E1763: OHOS CMakeToolchain/GNUInstallDirs 把 CMake 库包装进 lib/<triplet> 子目录，CMakeDeps 从 lib/ 找不到库（find_package 失败）的识别与配方级修复

## 基本信息
- **严重度**: 2
- **类别**: portability, cmake, conan, packaging, install-path
- **作者**: unknown

## 错误特征
```
Library '.*' not found in package|cmakedeps_macros.cmake.*conan_package_library_targets|lib/[a-z0-9-]*linux-ohos|CMAKE_LIBRARY_ARCHITECTURE
```

## 根因分析
OHOS Conan 的 CMakeToolchain/GNUInstallDirs 在交叉编译时把 CMAKE_LIBRARY_ARCHITECTURE 计算为 OHOS GNU triplet（如 aarch64-linux-ohos）。若上游 CMakeLists 用 `install(TARGETS <t> DESTINATION lib/${CMAKE_LIBRARY_ARCHITECTURE})`（Debian 风格 multiarch 写法），即使配方在 generate() 传入 `-DCMAKE_LIBRARY_ARCHITECTURE=""`，安装产物仍落到 `lib/<triplet>/` 与 `include/<triplet>/`。CMakeDeps 默认从 `lib/`、`include/` 生成 `-L`/`-I` 与 target，找不到 `libjson11.a` → test_package `find_package(json11)` 报 `Library 'json11' not found in package`（cmakedeps_macros.cmake 的 conan_package_library_targets）。

## 推荐方案
**方法**: flatten-triplet-install-dirs

**说明**: 在 conanfile.py 的 package() 中，cmake.install() 之后遍历 self.package_folder 下 lib/、include/ 内所有 triplet 子目录，把其中文件 rename 到 lib/、include/ 顶层并删除空子目录，使 CMakeDeps 能从默认 lib/ 找到库。不动上游源码，配方级通用修复。

**修复命令**:
```
在 package() 内用 pathlib 遍历 lib/ include/ 下子目录并 rename 到顶层（见 archives/j/json11/1.0.0/conanfile.py）
```

**验证**:
```
conan-verify 后 test_package find_package 通过（G2→G4 + L2/L4/L5 PASS）；`conan create ... --build=missing` 产物位于 lib/libjson11.a 而非 lib/aarch64-linux-ohos/。
```
