# E1780: header-only 库无可选 fmt 依赖时，basic logging 降级宏必须经 conanfile.py package_info 的 cpp_info.defines 声明给 CMakeDeps 消费者

## 基本信息
- **严重度**: 2
- **类别**: headers, conan, compile-definition, logging, optional-dependency
- **作者**: unknown

## 错误特征
```
fatal error: ['"]?fmt/format\.h['"]? file not found|Errors:.*fmt:.*not found|common\.hpp:.*fmt/format\.h.*file not found
```

## 根因分析
上游 header-only 库（如 Sophus）在 CMake 配置期找不到 fmt target 时自动启用 basic logging，并把 SOPHUS_USE_BASIC_LOGGING=1 作为 INTERFACE_COMPILE_DEFINITIONS 写进其导出目标（SophusTargets.cmake）。但 Conan 消费者的 CMakeDeps 生成 target 只从配方 package_info() 读取编译定义，并不会继承上游导出的 INTERFACE_COMPILE_DEFINITIONS；若不声明该宏，消费者 test_package 会走到 #include <fmt/format.h> 分支而找不到 fmt 头文件，主包却能正常构建（主包自身已带宏）。

## 推荐方案
**方法**: propagate-basic-logging-macro-via-cpp-info-defines

**说明**: 在 conanfile.py package_info() 中通过 self.cpp_info.defines = ["<LIB>_USE_BASIC_LOGGING=1"] 显式声明降级宏，与上游"无 fmt 时自动开启 basic logging"的行为保持一致，确保 CMakeDeps 消费者（test_package 与下游）编译时不会回落进 fmt 头文件分支。

**修复命令**:
```
package_info() 中增加 self.cpp_info.defines = ["SOPHUS_USE_BASIC_LOGGING=1"]，然后重跑 conan-verify 直至 G2 通过并观察到 test_package 的 L1e 破坏性负测确认消费者真实依赖被测包。
```

**验证**:
```
conan create archives/s/sophus/1.22.10 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable && grep -q "SOPHUS_USE_BASIC_LOGGING=1" <归档>/conanfile.py
```
