# E1789: Verify release tarballs before relying on CMake submodules

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan, source
- **作者**: unknown

## 错误特征
```
"include could not find requested file: tools; Unknown CMake command configure_and_install"
```

## 根因分析
"The release archive preserves references to a CMake helper submodule but omits the submodule files, so configure-time includes and custom install macros are unavailable. Fetching the SSH submodule from inside a recipe is not a pinned, reproducible source boundary."

## 推荐方案
**方法**: "verify archive completeness, avoid unpinned submodule fetches, and use a deterministic header-only recipe when the public API is independent"

**说明**: "Separate source completeness from compiler compatibility. For a header-only library, package the public headers with a deterministic Conan recipe, compile real shipped examples using the profile compiler, and exercise the generated package target in test_package."

**修复命令**:
```
"test -d cmake/common || fail; clang++ -std=c++17 -Isrc/include example/connection_fsm/connection_fsm_tests.cpp -o connection_fsm"
```

**验证**:
```
"inspect the official tarball for .gitmodules and the referenced directory; compile shipped examples with the OHOS profile compiler; conan create <archive> -pr:h=<ohos-profile> --build=missing"
```
