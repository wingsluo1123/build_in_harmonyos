# E1790: Offline Conan packaging for CMake projects that fetch PackageProject at configure time

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan, offline-build
- **作者**: unknown

## 错误特征
```
Could not download CPM.cmake or PackageProject.cmake during CMake configure
```

## 根因分析
Upstream CMake projects may fetch CPM/PackageProject helper modules during configure and may only define a build target without install rules. This makes an otherwise dependency-free library fail in offline CI and leaves Conan package() with no portable artifact boundary.

## 推荐方案
**方法**: replace-network-helper-with-explicit-install

**说明**: Remove configure-time helper downloads when they are only used to install/package the library; declare a static or shared target explicitly, add GNUInstallDirs install(TARGETS) and install(DIRECTORY) rules, then let Conan CMake.install() package the resulting files.

**修复命令**:
```
include(GNUInstallDirs); install(TARGETS <target> ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}); install(DIRECTORY include/ DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})
```

**验证**:
```
conan create <archive> -pr:h=<ohos-profile> -pr:b=<ohos-profile> --build=missing; test_package must link and execute a real API consumer.
```
