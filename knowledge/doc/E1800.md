# E1800: OHOS 平台 mmap 单次虚拟地址空间预留上限导致分配器 pagemap 初始化失败（禁用 random_pagemap mitigation）

## 基本信息
- **严重度**: 3
- **类别**: ohos, libc, syscall, memory, pagemap
- **作者**: SNMALLOC

## 错误特征
```
Failed to initialise snmalloc\.|PAL::error.*Failed to initialise|mmap.*Out of memory|Cannot allocate memory.*mmap|reserve.*nullptr.*pagemap
```

## 根因分析
HarmonyOS 平台对单次 mmap 匿名映射的虚拟地址空间预留有上限（实测 256GB 成功、384GB 失败，errno=12 ENOMEM）。snmalloc 0.7.5 的 check 变体（SNMALLOC_CHECK_CLIENT）默认启用 full_checks mitigations（含 random_pagemap），FlatPagemap::init() 按 REQUIRED_SIZE + 4*next_pow2(REQUIRED_SIZE) 预留约 1280GB（256GB + 4×256GB），超过平台上限导致 mmap 返回 ENOMEM，PAL::reserve 返回 nullptr，pagemap.h 触发 PAL::error("Failed to initialise snmalloc.") 并 SIGABRT。非 check 变体（无 random_pagemap）仅预留 256GB，恰好可通过。

## 推荐方案
**方法**: disable-pagemap-randomization-for-ohos

**说明**: 在 src/snmalloc/mitigations/mitigations.h 增加 __OHOS__ 平台分支（参照上游已有 OPEN_ENCLAVE / NetBSD / CHERI 平台特例先例）：CHECK_CLIENT ? full_checks - random_pagemap : no_checks。仅禁用 pagemap 随机化 mitigation，保留其余全部检查（metadata_protection、freelist 边等）。这样 pagemap 只预留 REQUIRED_SIZE（256GB），低于平台上限。

**修复命令**:
```
patch 增加 __OHOS__ 分支：`#elif defined(__OHOS__) CHECK_CLIENT ? full_checks - random_pagemap : no_checks;`；重新 cmake --build && ctest 验证 check 变体通过。
```
