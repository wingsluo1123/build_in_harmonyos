# E1829: conan Autotools.make(args=[...]) 传含引号/$VAR 的 make 变量会被 sh -c 剥引号并在子 shell 展开；需要字面量（如 $ORIGIN rpath）时应 configure 后直接改写 Makefile

## 基本信息
- **严重度**: 2
- **类别**: autotools, linking, conan, shell-quoting
- **作者**: unknown

## 错误特征
```
RUNPATH.*\[\$?\{?ORIGIN.*empty|RUNPATH.*\[/lib:/../lib\]|rpath.*\$ORIGIN.*expanded|LDFLAGS_EX.*ORIGIN|Library runpath: \[//lib[^]]*\]
```

## 根因分析
conan 的 Autotools.make() 把 args 纯拼接进命令行，经 self.run()（shell=True / sh -c）执行。含单引号的参数（如 LDFLAGS_EX=-Wl,-rpath,'$$ORIGIN/../lib'）中，单引号被外层 shell 按词法剥离，$$ 经 make 转义为 $ 后在 recipe 子 shell 里无引号保护，$ORIGIN 作为未定义 shell 变量被展开为空串，链接器最终收到 /../lib 这类无效 rpath（readelf 显示 RUNPATH=[//lib:/../lib]）。结论：跨 conan→sh→make→recipe-shell→linker 四层传递时，凡需要"字面量进入最终产物"的 token（$ORIGIN、含空格/引号的 flag），都不能经 make 命令行变量传；应改为 configure 之后用 replace_in_file 直接改写 build 树的 Makefile 全局文件（Makefile.global 等），纯文本替换不经 shell 解析链，make 展开 $$→$、配方 shell 单引号保留字面量，链接器正确记录 $ORIGIN。

## 推荐方案
**方法**: rewrite-makefile-global-after-configure

**说明**: (待补充)

**修复命令**:
```
①configure 后用 conan.tools.files.replace_in_file 把 build 树 src/Makefile.global 的 "LDFLAGS_EX = \n" 替换为 "LDFLAGS_EX = -Wl,-rpath,'$$ORIGIN/../lib'\n"；②make 只传普通参数 autotools.make(args=["-j8"])；③（对比）不要用 args 传 LDFLAGS_EX=...——实测 $ORIGIN 被展开为空
```

**验证**:
```
1) readelf -d <bin> | grep -i runpath 确认 $ORIGIN 字面保留；2) 把二进制+so 复制到任意 bin/lib 结构，清空 LD_LIBRARY_PATH 后运行成功；3) W3 L2 smoke 全绿（此前 21/35 失败）；4) grep '^LDFLAGS_EX' <build>/src/Makefile.global 确认改写生效
```
