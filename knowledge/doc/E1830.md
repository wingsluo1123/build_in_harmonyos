# E1830: OHOS 本机 PATH 首位的 install shim 不支持分离参数形式，autotools 项目 make install 报 cp: bad '<mode>'

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, autotools, toolchain, install
- **作者**: unknown

## 错误特征
```
cp: bad '.*': No such file or directory|install.*-c -m.*bad|use_install_sh|install-sh.*shim|Error 1.*install$
```

## 根因分析
OHOS PC 开发环境（本机与 CI profile buildenv）将 $HOME/usr/local/bin 前置到 PATH，其中存在一个 install 包装脚本（shim）。该 shim 只解析合并形式（install -m755 src dst 风格或 plain cp 语义），对 autotools 标准安装脚本发出的分离参数形式 install -c -m 755 src dst 会把模式位 '755' 当作源文件参数，底层 cp 报 "cp: bad '755': No such file or directory"，导致 make install 中断（Error 1）。这不是被构建软件的 bug，而是宿主工具环境与 autotools 安装约定的兼容性问题。

## 推荐方案
**方法**: switch-to-bundled-install-sh

**说明**: (待补充)

**修复命令**:
```
①优先用软件自带的安装器切换开关：PostgreSQL 原生支持 `make install use_install_sh=yes`（改用自带 config/install-sh，正确处理分离参数与所有安装模式），配方 package() 写 autotools.install(args=["use_install_sh=yes"])；②无该开关的 autotools 项目：配方里将系统 install 重定向（tc.env 定义 INSTALL=<source>/install-sh 路径）或 recipe 手动 copy 产物；③切勿尝试修改 shim 本身（影响整机工具链）
```

**验证**:
```
1) which install 确认首位居 $HOME/usr/local/bin；2) install -c -m 755 <src> <dst> 手工复现 cp: bad '755'；3) make install 观察首个失败目标即 INSTALL_* 类规则；4) make install use_install_sh=yes 后全量安装成功且产物权限正确（stat -c %a bin/postgres = 755）
```
