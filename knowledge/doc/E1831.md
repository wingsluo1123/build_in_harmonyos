# E1831: PG 18.3 自带 config.sub 已识别 aarch64-linux-ohos；OHOS PC 原生构建显式传 --build 即可跳过 config.guess，无需外置 config.sub/config.guess 拷贝

## 基本信息
- **严重度**: 1
- **类别**: platform, ohos, autotools
- **作者**: unknown

## 错误特征
```
config.guess.*unable to guess|cannot guess.*config.guess|Invalid configuration.*ohos|configure: error: cannot run.*config.guess|cp.*usr/local/share/config
```

## 根因分析
旧适配方案（2026-06 手动构建）从 $HOME/usr/local/share/config/ 拷贝外置 config.sub/config.guess 进源码树，原因有二：①PG 自带 config.sub 当时不能识别 aarch64-linux-ohos；②config.guess 的数据库不识别 OHOS，且其临时文件探测在 hmdfs 上受 umask 077 破坏。但该外置路径是本机环境产物，CI 干净环境不可依赖。实测 PG 18.3 官方 tarball 的 config/config.sub（2024-01-01 版起）已包含 *-linux-ohos 识别；而 configure 只要收到显式 --build=<triplet> 就完全跳过 config.guess 调用。因此 OHOS PC（本机即 aarch64 OHOS，原生非交叉）构建只需 tc.configure_args.append("--build=aarch64-linux-ohos")，既跳过 config.guess 的两大问题，又不依赖任何外置文件。

## 推荐方案
**方法**: explicit-build-triplet-skip-config-guess

**说明**: (待补充)

**修复命令**:
```
①确认自带 config.sub 支持：grep "ohos" config/config.sub；②配方 generate() 中（settings.os==OHOS 时）追加 tc.configure_args.append("--build=aarch64-linux-ohos")；③不要拷贝任何外置 config.sub/config.guess；④umask 077 修复仍需保留（configure 自身与 config.guess 的 hmdfs 兼容问题独立存在）
```

**验证**:
```
1) grep -c "linux-ohos\|linux_ohos" <src>/config/config.sub（应 >=1）；2) configure --build=aarch64-linux-ohos 后 config.log 无 config.guess 调用痕迹、host=build=aarch64-linux-ohos；3) ls 确认无外置 config.sub 拷贝动作；4) conan create G2 PASS
```
