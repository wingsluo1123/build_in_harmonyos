# E1833: aarch64 上 char 默认为 unsigned 时，上游 C++ 测试源码用负值列表初始化 char 触发编译期 -Wc++11-narrowing；修复位在测试构建标志（-fsigned-char）而非库工具链

## 基本信息
- **严重度**: 2
- **类别**: aarch64, abi, c-language, cxx-tests, signedness
- **作者**: unknown

## 错误特征
```
constant expression evaluates to -[0-9]+ which cannot be narrowed to type 'char'|cannot be narrowed to type 'char'|Wc++11-narrowing|fsigned-char
```

## 根因分析
aarch64 ABI 使 plain char 默认为 unsigned；上游若按 x86/有符号 char 语义在测试源码中把 -1/-2 等负值写入 char 的列表初始化（如传递 debug sample 数组），C++11 列表初始化在编译期即因窄化拒绝（-Wc++11-narrowing），在编译阶段失败，尚未进入运行期断言差异（与 E419 的运行时 INT8 API 结果差异是同一根因的两种表现）。header-only 库无编译产物：修复不落在库工具链 cflags，而落在测试/验证构建的命令行标志。

## 推荐方案
**方法**: test-build-fsigned-char-for-header-only

**说明**: 不改上游源码。header-only 库：在测试/验证构建命令 add -fsigned-char（clang++ 测试编译），库配方无 cflags；带库编译产物的库：测试目标 add_compile_options(-fsigned-char) 或配方 toolchain cflags 与 E419 同法。保持上游测试期望不变并跑全量套件。

**修复命令**:
```
clang++ -std=c++17 -fsigned-char -I external -I include test/*.cpp test/shared/*.cpp -o hfsm2_test && ./hfsm2_test
```

**验证**:
```
clang++ -std=c++17 -I include -I external test/*.cpp test/shared/*.cpp -o test_bin   # 失败: -Wc++11-narrowing
```
