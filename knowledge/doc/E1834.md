# E1834: Header-only CMake 包的测试子模块物化、公共依赖负对照与安装配置复制残留联合核验

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, dependency, packaging, testing
- **作者**: AWST

## 错误特征
```
sol2-targets\.cmake|allocator::construct.*deprecated|unused-but-set-variable|empty.*vendor/(range-v3|span-lite)|a span of some sort is required|can't concat str to bytes|ctest \['--output-on-failure'\]|'settings\.os\.version' value not defined
```

## 根因分析
三类独立根因叠加在同一包上。(1) GitHub v0.8 源码归档保留空的 range-v3/span-lite 子模块目录，而其 CTest 测试直接以 vendor 路径包含这些头文件；span-lite 还实际是 C++17 bit_span 的公共依赖，只用 bit_vector 类消费者测试无法暴露这一点。(2) 安装配置文件错误复制了 sol2 的 targets/变量名。(3) build 期的 single header 生成脚本用 os.popen('git describe ...').read() 取版本戳，解码使用宿主 locale 推导的文本编码：CI worker 上解析为 str-buffered codec，于是在 codecs.BufferedIncrementalDecoder.decode 里抛 "can't concat str to bytes" 让 make 在 1% 中止，而设备端恒为 UTF-8 所以本地全绿。此外 OHOS libc++ C++17 会把上游测试的 allocator::construct 弃用诊断与 unused-but-set-variable 在上游 -Werror 下变成硬错误。

## 推荐方案
**方法**: pinned-test-source-installed-target-audit-and-dependency-negative-control

**说明**: 在 conandata 中固定官方测试子模块 tarball 与 SHA256，source() 物化测试目录；range-v3 不进入包，span-lite 既作为公共 Conan 依赖又用于上游测试；对安装后的 config.cmake 做 target/变量审查并生成窄补丁；给消费者测试单独放一条必然经过该公共依赖的用例，并用"移除依赖头路径后编译失败"作负对照证明依赖必需；每条消费者断言都做改错期望值→看到真实失败→复原→重跑通过的取证，并核对复原前后测试源码 sha256 一致；用 CMAKE_SYSTEM_NAME=Linux 进入兼容 CMake Unix 分支，仅针对设备实际诊断调整 warning 严格度；CTest 入口数、聚合驱动逻辑用例数和断言数分层统计；对 build 期 Python 生成器用 conan.tools.env.Environment 在 build 作用域 pin PYTHONUTF8=1 + PYTHONIOENCODING=utf-8，避免宿主 locale 解析成 str-buffered codec 时 make 在 1% 崩掉（本地可用 PYTHONIOENCODING=idna 强制复现该崩溃，再 source 生成的 conanbuild.sh 反证修复有效）。

**修复命令**:
```
cmake --build <build> --target test -- -j2 (串行 ctest --output-on-failure); <runtime-driver> --reporter compact; find_package(itsy.bitsy CONFIG REQUIRED); clang++ -fsyntax-only 去掉依赖头路径做负对照
```

**验证**:
```
conan create archives/i/itsy_bitsy/0.8 -pr:h="$PWD/ci/conan/profiles/ohos-aarch64" -pr:b="$PWD/ci/conan/profiles/ohos-aarch64" --build=missing --build=itsy_bitsy/*
```
