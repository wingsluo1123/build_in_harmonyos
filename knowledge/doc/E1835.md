# E1835: Separate a header-only core when release CMake forces a missing optional binding submodule

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, conan, dependency
- **作者**: wanderlust_0823
- **来源 PR**: none

## 错误特征
```
add_subdirectory.*pybind11|downloading pybind11|pybind11.*CMakeLists.txt|git submodule.*update
```

## 根因分析
The release tarball omits the pybind11 submodule, but the top-level CMake path unconditionally enters extlib/python and add_subdirectory(pybind11); the documented C++ header-only core can compile independently, so the binding bootstrap should not define the core package boundary.

## 推荐方案
**方法**: verify-release-contents-and-package-core-component-separately

**说明**: Inspect the exact release archive and .gitmodules, reproduce the clean configure failure, then package only the independently documented core component with a real consumer test. Keep binding and upstream-suite status separate; never fetch an unpinned submodule or claim the whole project is adapted.

**修复命令**:
```
test -f extlib/pybind11/CMakeLists.txt || true; cmake -S . -B build; conan create archives/l/libasd/1.5.6 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
find . -path '*pybind11/CMakeLists.txt'; cmake -S . -B build; clang++ -std=c++11 -I. <core-consumer.cpp>
```
