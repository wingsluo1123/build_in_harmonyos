# E1838: Preserve OHOS AArch64 ELF interceptor correctness across GNU hash, RELRO, relocation slots, and TLS

## 基本信息
- **严重度**: 2
- **类别**: ohos, compiler, linking, runtime
- **作者**: unknown

## 错误特征
```
"could not find definitions for vital function(s): 'abort' 'vfprintf'; segmentation fault while writing GOT; recursive malloc mock"
```

## 根因分析
"OHOS AArch64 ELF loaders and clang runtime differ from the assumptions in older dynamic-interception code: GNU hash may replace SysV hash, RELRO protects GOT pages, function addresses can use GLOB_DAT instead of JUMP_SLOT, and emulated TLS can re-enter a mocked allocator."

## 推荐方案
**方法**: "probe GNU/SysV hash and both AArch64 relocation slot kinds, write only the target RELRO page temporarily, and disable emulated TLS only for the affected AArch64 Clang build"

**说明**: "Keep SysV lookup with a uint32_t GNU-hash fallback, collect GLOB_DAT together with JUMP_SLOT, temporarily mprotect only the GOT page and restore read-only protection, then verify the real mock/reset and allocator paths."

**修复命令**:
```
"readelf -dW app; readelf -rW app; clang -fPIC -fno-emulated-tls ...; ctest --test-dir build --output-on-failure"
```

**验证**:
```
"clang -target aarch64-linux-ohos -fPIC probe.c; cmake -DCMAKE_SYSTEM_NAME=Linux -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DCMAKE_C_FLAGS=-fno-emulated-tls; ctest --test-dir build --output-on-failure"
```
