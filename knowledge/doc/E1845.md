# E1845: HarmonyOS只读/tmp环境下TMPDIR重定向与mprotect守卫页受限时stack_allocator降级策略

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, portability, syscall, build-system
- **作者**: hmbs-executor
- **来源 PR**: 8536

## 错误特征
```
Read-only file system|HMBS_PLATFORM_CAPABILITIES.*tmpdir|protected_stack_allocator.*mprotect|mprotect.*guard
```

## 根因分析
HarmonyOS真机预检环境/tmp为只读挂载，直接写入/tmp触发Read-only file system；同时protected_stack_allocator依赖mprotect设置守卫页，在受限沙箱中mprotect被拒绝抛异常，两者分别阻塞编译期临时文件与运行期协程栈分配，属平台能力限制而非单库缺陷

## 推荐方案
**方法**: tmpdir-redirect-with-guard-page-fallback

**说明**: 配方与测试包双层TMPDIR重定向复用HMBS注入可写路径，并将mprotect守卫页受限的protected_stack_allocator降级为standard_stack_allocator且标记SKIP，移除与libc++冲突的-static-libstdc++并持久化上游测试证据，提炼为跨库可复用的只读/tmp与guard页兼容模式

**修复命令**:
```
conanfile.py新增_writable_tmpdir()复用HMBS_TMPDIR/HMBS_PLATFORM_CAPABILITIES.tmpdir并在build()导出TMPDIR/TMP/TEMP透传至clang/ar子进程；test_package/conanfile.py在build()/test()前置同逻辑并透传；test_boost_coroutine.cpp将protected_stack_allocator调用包裹try/catch失败时SKIP而非FAIL
```

**验证**:
```
真机preflight日志显示HMBS_PLATFORM_CAPABILITIES.tmpdir已注入且TMPDIR指向可写路径，无Read-only file system报错；test_package中standard_stack_allocator必过，protected路径try/catch转为SKIP非FAIL，HMBS_TEST_PACKAGE_RESULT与HMBS_UPSTREAM_TEST_RESULT均为passed
```
