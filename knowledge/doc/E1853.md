# E1853: Dear ImGui 1.92 headless consumers must prebuild the font atlas and drop unreferenced OHOS system libs

## 基本信息
- **严重度**: 2
- **类别**: platform, conan, runtime, testing
- **作者**: wanderlust_0823
- **来源 PR**: none

## 错误特征
```
font atlas is not built|Calling.*NewFrame.*font|Error loading shared library libc\+\+\.so.*libace_ndk|relocating /system/lib64/.*symbol not found
```

## 根因分析
imgui 1.92 with a backend that lacks ImGuiBackendFlags_RendererHasTextures builds font glyphs lazily; a consumer test that calls NewFrame without any platform backend leaves the atlas unbuilt, the first glyph access dereferences null baked data and crashes (SIGSEGV right after the IM_ASSERT_USER_ERROR log line). Independently, imgui propagates ace_ndk.z/EGL/GLESv3 as system libs; linking them without --as-needed keeps them in DT_NEEDED even when unreferenced, and libace_ndk.z.so pulls the application-only Ace/NAPI runtime chain whose libc++ inline namespace collides with the hnp toolchain libc++.

## 推荐方案
**方法**: prebuild-font-atlas-and-as-needed-system-libs

**说明**: In the consumer test, after CreateContext set io.DisplaySize/io.DeltaTime, call io.Fonts->Build() and io.Fonts->GetTexDataAsAlpha8() before NewFrame (legacy atlas path), then draw inside an ImGui::Begin/End window so vertices are actually emitted and assert TotalVtxCount>0. For runtime library hygiene add target_link_options(... "LINKER:--as-needed") so the unreferenced imgui system libs stay out of DT_NEEDED.

**修复命令**:
```
io.Fonts->Build(); io.Fonts->GetTexDataAsAlpha8(&px,&w,&h); ImGui::NewFrame(); ... target_link_options(exe PRIVATE "LINKER:--as-needed")
```

**验证**:
```
./consumer  # headless imgui+implot frame on device; see rec_command for the working sequence
```
