# E1854: CMakeDeps serializes empty includedirs for transitive dependencies - propagate them in package_info

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, packaging, testing
- **作者**: wanderlust_0823
- **来源 PR**: none

## 错误特征
```
fatal error.*file not found.*#include|Could not find a package configuration file|cpp_info.*includedirs.*empty
```

## 根因分析
On the OHOS conan 2.29.1, CMakeDeps data files fill include dirs for DIRECT dependencies but leave the includedirs entry empty for TRANSITIVE ones (libdirs still filled). A package B that wraps dependency A passes conan find_package(B) and B::B correctly, but consumers including A headers through B::B get no -isystem for A and die on the first A include, even though the whole CMake target chain (B::B -> B_DEPS_TARGET -> A::A) is present.

## 推荐方案
**方法**: package-info-explicit-include-propagation

**说明**: In the wrapper package package_info(), copy the dependency include dirs into the wrapper cpp_info so the always-direct wrapper target carries them, and keep cpp_info.requires for link propagation. Verify with conan install -g CMakeDeps before rerunning conan create.

**修复命令**:
```
in package_info set cpp_info.requires to a::a and cpp_info.includedirs.extend(dependencies[a].cpp_info.includedirs)
```

**验证**:
```
conan install --requires B/x -g CMakeDeps, then grep INCLUDE_DIRS in the dependency data cmake file
```
