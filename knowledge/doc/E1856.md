# E1856: OHOS 双宏(__OHOS__/__linux__)使 Linux 条件编译选中 <asm/termbits.h>，termios API 全部失去原型且 OHOS kernel-uapi 头无 TCGETS2：优先上游自带回退开关经 make 用户变量注入，免补丁修复

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, libc, headers, build-system
- **作者**: unknown

## 错误特征
```
implicit function declaration.*tcsetattr|implicit function declaration.*tcsendbreak|implicit function declaration.*cfsetispeed|use of undeclared identifier 'TCGETS2'|asm/termbits\.h
```

## 根因分析
OHOS clang（aarch64-linux-ohos triple）同时定义 __OHOS__ 与 __linux__，因此 `#if defined(__linux__)` 类条件编译会选中内核 uapi 的 <asm/termbits.h> 而放弃 <termios.h>。OHOS sysroot 的 termbits 头提供 struct termios 与 ioctl 常量，但 (a) 不含任何 termios 函数原型——tcgetattr/tcsetattr/cfsetispeed/cfsetospeed/cfgetospeed/tcsendbreak 全部变成隐式函数声明（clang 15 下每个调用点一条 -Wimplicit-function-declaration 警告，bootterm 实测 11 条；这些函数均返回 int，能链接成功，属静默质量劣化而非编译失败），(b) 缺少 TCGETS2 宏，Linux 路径引以为傲的自定义波特率（BOTHER）分支实际从未启用。长期只编译 SPGLIB 存在侧的代码同理，无人编译的 #else 回退分支会腐烂（参见 band_plot.c 类案例的反面：有回退开关的上游反而保持可用）。

## 推荐方案
**方法**: upstream-knob-make-variable-injection

**说明**: 当上游自带编译期回退开关（bootterm 的 NO_TCGETS2、同类如 NO_GETTEXT/--disable-*），优先经构建系统的用户挂点注入开关选择 libc 自洽配置，而不是打源码补丁或发明 __OHOS__ 守卫：①行为等价可证——linux 路径想要的 kernel-uapi 符号（TCGETS2）在 OHOS sysroot 本就不存在，默认构建同样没有该能力；②消除全部隐式声明警告；③补丁数为零，上游升级零冲突，PF5/R8 平台宏闸天然干净；④开关经 make 命令行变量传入（Makefile 硬赋值 CC/CFLAGS 时命令行变量是唯一合法覆盖点，R33 的编译器同样从 compiler_executables conf 注入）。在 PR/notes 中说明开关语义与行为等价性证据。

**修复命令**:
```
make -j1 CC="<compiler_executables.c>" USR_CFLAGS="-DNO_TCGETS2"
```

**验证**:
```
make -j1 CC=<conan-cc> USR_CFLAGS="-DNO_TCGETS2" && ./bt -V  # 退出码 0，无警告，横幅无 TCGETS2 行（与默认构建行为一致）
```
