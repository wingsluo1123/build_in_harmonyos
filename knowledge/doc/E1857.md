# E1857: OHOS-target qmake binaries cannot run as Windows host tools

## 基本信息
- **严重度**: 2
- **类别**: qmake, cross-compile, host-toolchain, qt, target
- **作者**: algobox

## 错误特征
```
WinError 193|not a valid Win32 application|The system cannot execute the specified program|qmake6 binary|No QTextCodec header found|QtCore5Compat/QTextCodec|QWebChannel file not found|expected expression|msg.split|Core5Compat.so|Unknown module(s) in QT: core5compat
```

## 根因分析
Conan can resolve qtbase/6.11.1 and expose qmake6, but that executable is built for the OHOS target ABI. A Windows host can inspect the package and resolve its dependency graph, yet cannot execute the target binary as a build tool.

## 推荐方案
**方法**: host-native-tool-or-runner-only-validation

**说明**: Keep Windows-host work limited to source inspection, dependency graph resolution, and metadata validation. Run the full qmake build only on a host that can execute the tool, or switch the recipe to a host-native qmake package if one is available.

**修复命令**:
```
On Windows host, stop after conan graph info; on OHOS-compatible runner, execute the full conan create flow.
```

**验证**:
```
python -c "import subprocess; subprocess.run([qmake6, '-v'], check=True)"
```
