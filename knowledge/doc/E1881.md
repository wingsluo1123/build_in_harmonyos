# E1881: OHOS musl keeps the gets symbol and gates only its declaration behind C11: legacy calls just warn, link and run, so a command-line macro is bounded-read hardening rather than a required fix

## 基本信息
- **严重度**: 2
- **类别**: platform, libc, declarations, deprecated-api, hardening
- **作者**: GoliWie

## 错误特征
```
implicit declaration of function 'gets'|call to undeclared library function 'gets'|implicit-function-declaration.*gets
```

## 根因分析
musl stdio.h gates the gets() declaration with

## 推荐方案
**方法**: command-line-macro-bounded-fgets

**说明**: Redirect every gets(s) call site with one

**修复命令**:
```
make DEFINES="-D'gets(s)=fgets(s,8192,stdin)'" ... (protomat: append the same define to CFLAGS)
```

**验证**:
```
/data/service/hnp/bin/llvm-nm -D /lib/ld-musl-aarch64.so.1 | grep -wE "gets|fgets|getline" && printf '#include <stdio.h>\nint main(void){char b[8];gets(b);puts(b);return 0;}' | /data/service/hnp/bin/clang -xc - -o "$TMPDIR/getsprobe" && echo ok | "$TMPDIR/getsprobe"
```
