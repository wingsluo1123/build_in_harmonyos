# E1882: 2006/07 年代 config.guess 无统一尾部输出结构，E007 的 GUESS= 变量式补救注入后不生效仍报 unable to guess，须改用 echo+exit 旧式分支

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, patch, config.guess
- **作者**: GoliWie
- **来源 PR**: pending（feat/libmirage-1.0.0 交付 PR）

## 错误特征
```
unable to guess system type（已按 E007/patch-autotools-ohos.pl 打补丁——脚本含 HarmonyOS 分支或 grep -c 'GUESS=' >0——仍报同横幅，stderr + exit 1 + 空 stdout；未打补丁时报同横幅；签名本体落回 E007，本条诊断增量在"已打补丁仍失败"这一入口）
```

## 根因分析
机理链（pristine 2006-07-02 版脚本三态实验实测，timestamp 行为证）：(1) 该代脚本主 case 的各分支自行 `echo <三元组>` + `exit ;;` 自行输出并退出，GUESS 变量在脚本内零处出现、也不存在脚本尾部统一打印 GUESS 的出口；(2) E007 官方补救（scripts/patch-autotools-ohos.pl:51-63）注入的分支为现代形态 `GUESS=${MACHINE}-unknown-linux-ohos` + `;;`——只赋值不输出，控制流越出 case 进入 LIBC/dummy.c 探测段，最终到达脚本尾部 "unable to guess system type" 横幅（stderr）+ exit 1 + 空 stdout；(3) 失败是响亮的而非静默的；"拿到空三元组"仅在调用方同时吞 stderr 且忽略退出码时出现（边注）。判别特征：脚本已含 HarmonyOS 分支/GUESS=>0 却仍报同横幅 = 代际形态不匹配，而非补丁未打

## 推荐方案
**方法**: echo-exit-branch-injection

**说明**: 在主 case 顶部（第一个分支位，惯用 *:NetBSD:*:* 分支前）注入 echo+exit 形式的 HarmonyOS 分支（三行：`*:HarmonyOS:*:*)` / `echo aarch64-unknown-linux-ohos`（或 MACHINE case 后 echo）/ `exit ;;`），与同项目 config.sub 参与构建时的 linux-ohos*（KERNEL-OS 组合白名单）与 -ohos*（OS 列表）两处白名单同步。同型先例：libdaemon 0.14 补丁 0001；libmirage 1.0.0 补丁 0001 同型。注入内容与 E007 面向现代脚本的 GUESS= 形态互斥使用——按脚本代际二选一（判据 grep -c 'GUESS='）

**修复命令**:
```
L=$(grep -n -m1 -E '^[[:space:]]*\*:NetBSD' config.guess | cut -d: -f1) && head -n $((L-1)) config.guess > cg.new && printf '%s\n' '    *:HarmonyOS:*:*)' '	case "$UNAME_MACHINE" in' '	    aarch64|arm64) MACHINE=aarch64 ;;' '	esac' '	echo ${MACHINE}-unknown-linux-ohos' '	exit ;;' '' >> cg.new && tail -n +$L config.guess >> cg.new && mv cg.new config.guess && sh config.guess
```

**验证**:
```
# 前提：任一年代 config.guess，guard：grep -c 'GUESS=' 与 grep -c HarmonyOS 均须为 0（以 pristine 树顶层脚本为例；timestamp 行应早于 2010）
```
