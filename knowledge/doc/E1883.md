# E1883: bison 3.8 接受已弃用的 %pure_parser 但生成的纯解析器不向 lexer 传 scanner 实参，与 %reentrant flex lexer 的三参 yylex 约定冲突，应迁移为 %define api.pure true 并补 %lex-param

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, conan, bison, flex
- **作者**: GoliWie
- **来源 PR**: pending（feat/libmirage-1.0.0 交付 PR）

## 错误特征
```
too few arguments to function call, expected 3, have 2|too many arguments to function call, expected 0, have 2|POSIX Yacc does not support %pure_parser|deprecated directive.*%pure_parser
```

## 根因分析
完整机理链（设备 bison 3.8.2 实测）：(1) 旧式指令 %pure_parser 仍被 bison 3.8 接受（仅 POSIX-Yacc 模式下警告），但 3.x 骨架已废弃 YYLEX_PARAM 桥接宏——生成 parser 对 yylex 的调用点签名由"纯度 + %lex-param"决定，而不再是 .y 序言里的 3 参原型声明或 #define YYLEX_PARAM；(2) .y 显式声明三参 yylex(yylval,yylloc,yyscanner) 且 .l 为 %reentrant bison-bridge bison-locations 时，纯骨架调用 yylex(&yylval,&yylloc) 缺第三参 → 编译错 too few arguments to function call, expected 3, have 2（image-ccd-parser.c:1546 实测）；(3) 反例组：非重入 flex 声明零参 extern int yylex (void) 时，保留纯解析器的两参调用在原型可见时硬报错 too many arguments to function call, expected 0, have 2（探针 pa.c:1129 实测），无原型时靠隐式声明侥幸编译且 yylval/yylloc 桥接被静默丢弃（语义损坏）→ 纯解析器与任何 flex 形态均不再默认兼容，必须成对迁移：.y 侧 %define api.pure true + %lex-param {void *scanner} ↔ .l 侧 %reentrant + bison-bridge + bison-locations

## 推荐方案
**方法**: migrate-pure-parser-with-lex-param

**说明**: 对每个含 %pure_parser 的 .y 成对迁移两处指令：替换为 %define api.pure true 并紧随追加 %lex-param {void *scanner}（scanner 名与 %parse-param 声明一致）；生成 parser 随即以 yylex (&yylval, &yylloc, scanner) 三参调用，与 %reentrant + bison-bridge + bison-locations 的 flex lexer 匹配。同型实例：libmirage 1.0.0 image-ccd/image-cue/image-toc 三解析器（补丁 0005，bison 3.8.2 编译通过）。若 .y 尚有 %error-verbose 一并替换为 %define parse.error verbose 消除弃用警告（可选）

**修复命令**:
```
perl -pi -e 's{^%pure_parser$}{%define api.pure true\n%lex-param {void *scanner}}' <each *.y>   # 已实测：替换后 bison 3.8.2 生成 yylex (&yylval, &yylloc, scanner)；等价做法为对 .y 生成 per-file 补丁（conandata.yml 声明，build() 内 apply_conandata_patches）
```

**验证**:
```
D=$(mktemp -d) && cd $D
```
