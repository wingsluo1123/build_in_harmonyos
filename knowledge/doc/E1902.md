# E1902: OHOS SDK clang 15 未随附 libclang_rt.msan.a，MemorySanitizer 测试变体在 OHOS PC 无法链接（ASan/UBSan 可用）

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, toolchain, llvm, testing
- **作者**: CMP20

## 错误特征
```
cannot open .*libclang_rt\.msan\.a|No such file or directory.*libclang_rt\.msan|fsanitize=memory.*linker command failed|MemorySanitizer.*not available
```

## 根因分析
OHOS SDK（ohos-sdk_26.0.0.18）自带的 clang 15 工具链 lib 目录未包含 libclang_rt.msan.a（MemorySanitizer 运行时）。上游测试的 MSan 变体（如 cmp 20 Makefile 的 cmpmemtest: -fsanitize=memory -fno-omit-frame-pointer）编译通过但在链接阶段 ld.lld 报 cannot open libclang_rt.msan.a，属平台工具链能力缺失，不是当前库源码/配方错误；同工具链 ASan（libclang_rt.asan.a）与 UBSan（libclang_rt.ubsan.a）运行时齐全可用。

## 推荐方案
**方法**: asan-ubsan-variants-platform-gap

**说明**: 将 MSan 变体如实记录为平台工具链限制（不可链接），不伪造结果；用同工具链可用的 ASan/UBSan 变体覆盖消毒器验证，并在测试台账中写明 MSan 变体的命令、退出码、首错（ld.lld cannot open libclang_rt.msan.a）与恢复条件（工具链提供 msan 运行时）；MSan 变体是同一用例集的不同构建配置，不作为独立上游用例缺失。

**修复命令**:
```
见验证命令；记录到 notes.md 测试台账与最终回报。
```

**验证**:
```
clang -fsanitize=memory -o x x.c 2>&1 | grep -E 'libclang_rt\.msan|error' ; ls /data/service/hnp/ohos-sdk.org/*/ohos/native/llvm/lib/clang/15.0.4/lib/aarch64-linux-ohos/ | grep -E 'asan|ubsan|msan'
```
