# E1912: OHOS toybox ln rejects GNU long options (--symbolic/--force/--relative); tolerate in install scripts and create symlinks via python

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, toolchain, install, symlink
- **作者**: A7F3
- **来源 PR**: 8333

## 错误特征
```
Unknown option 'symbolic'|Unknown option 'relative'|ln --symbolic|ln --relative|ln: Unknown option
```

## 根因分析
OHOS 用户空间命令由 toybox 提供，ln 只支持短选项（-s/-f），不识别 GNU coreutils 长选项 --symbolic/--force/--relative；meson/CMake 等构建系统生成的安装脚本常用 GNU 长选项（如 meson.add_install_script 输出 ln --symbolic --force --relative），执行即报 "Unknown option" 并退出非零，导致 conan package()/install 失败。

## 推荐方案
**方法**: portability-patch

**说明**: 两层修复：① 补丁给构建系统安装脚本的 ln 调用加 || true 容错（失败不终止 meson install）；② 配方 package() 用 python os.symlink（相对目标，如 ../bin/kmod）显式创建符号链接，等价于 ln --relative，保证多路调用工具链接不丢失。

**修复命令**:
```
meson.build: ln_s = 'ln --symbolic --force --relative "$DESTDIR@0@/kmod" "$DESTDIR@1@" || true'; conanfile.py package(): for tool in ("depmod","insmod","lsmod","modinfo","modprobe","rmmod"): os.symlink("../bin/kmod", os.path.join(package_folder,"sbin",tool))
```

**验证**:
```
conan create . --user=ohpcd --channel=stable -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
