# E1913: OHOS 设备会话 getlogin_r(3)/LOGNAME 空成功语义导致身份类软件以空用户名继续运行，应显式拒绝空串并回退候选身份链（env → getlogin_r → getpwuid）

## 基本信息
- **严重度**: 3
- **类别**: libc, musl, posix, runtime, environment
- **作者**: unknown

## 错误特征
```
invalid identifier `'|co: invalid identifier|ci: invalid identifier|Who are you\?  Please setenv LOGNAME|no password entry for userid|co aborted|ci aborted
```

## 根因分析
OHOS 设备会话 getlogin_r(3) 返回 0（成功）但缓冲区为空串，LOGNAME 环境变量存在但为空串，且 /etc/passwd 无 HMDFS uid 条目（getpwuid_r 无 pw_name）。上游身份解析链（如 rcs src/b-excwho.c getusername() 的 JAM 宏）不拒绝空串，把"空成功"缓存为有效身份，后续 ci/co 以空用户名参与符号校验与锁归属，触发 checkidentifier 失败（invalid identifier 后接空名）或整体中止，上游测试群失败。

## 推荐方案
**方法**: reject-empty-identity-then-fallback-chain

**说明**: 源码层在身份缓存点显式拒绝空串并回退候选链（env → getlogin_r → getpwuid_r），如 rcs src/b-excwho.c 的 `#define JAM(x) (BE (username) = (x) && *(x) ? (x) : NULL)`，补丁遵循上游风格、英文注释说明 OHOS 理由，可向上游提交（P005）；同时配方/会话层注入非空 LOGNAME（构建与测试环境强制非空，如 export LOGNAME=builder），双实例同 run 验证。

**修复命令**:
```
patch src/b-excwho.c: "#define JAM(x)  (BE (username) = (x) && *(x) ? (x) : NULL)"; env: export LOGNAME=builder（conan recipe: if not os.environ.get("LOGNAME"): os.environ["LOGNAME"]="ohos-builder"）
```

**验证**:
```
cd "$(mktemp -d 2>/dev/null || pwd)" && printf '%s\n' '#include <unistd.h>' '#include <stdio.h>' '#include <string.h>' '#include <pwd.h>' '#include <stdlib.h>' 'int main(void){char b[256];int r=getlogin_r(b,sizeof b);struct passwd*p=getpwuid(getuid());printf("getlogin_r=%d len=%d LOGNAME=[%s] pw_name=[%s]\n",r,r==0?(int)strnlen(b,sizeof b):-1,getenv("LOGNAME")?getenv("LOGNAME"):"(unset)",p&&p->pw_name?p->pw_name:"(none)");return 0;}' > idprobe.c && /data/service/hnp/bin/clang idprobe.c -o idprobe && ./idprobe && echo "shell LOGNAME=[$LOGNAME]"
```
