# E1933: 跨小版本 bump 成熟 cmake 配方时，熵源类选项默认值可能被上游改成 AUTO，须重断言显式值

## 基本信息
- **严重度**: 3
- **类别**: ohos, libc, cmake, security, build-config
- **作者**: EXPAT
- **来源 PR**: 9050

## 错误特征
```
EXPAT_WITH_GETRANDOM|getrandom|no entropy|XML_.*Random|SYS_getrandom|evaluate_detection_results
```

## 根因分析
expat 2.8.2 时代 cmake 的 EXPAT_WITH_GETRANDOM 默认 OFF（配方须显式 =ON 才有熵源）；2.8.4 的 CMakeLists 改为 expat_shy_set(EXPAT_WITH_GETRANDOM "AUTO" CACHE ...)（默认 AUTO）再 evaluate_detection_results(... HAVE_GETRANDOM ...) 自动探测。纯 bump 若照抄旧版本「默认 OFF 所以显式 =ON」的推理、却不去核对新版本该选项的默认与探测逻辑，可能在新版本默认已覆盖需求的假象下漏配，或反之在 AUTO 探测口径与真机 libc 能力不一致时悄悄退化为无熵源。

## 推荐方案
**方法**: reassert-explicit-option-on-upstream-default-change

**说明**: 版本 bump 时逐项核对上游新 CMakeLists 中配方显式传过的每个 cache 选项：若默认值/取值集合/探测语义变化（如 OFF→AUTO + evaluate_detection_results），继续显式传确定性取值，使行为与已验证旧线一致，不随上游 AUTO 探测结果漂移。expat 2.8.4 保持 -DEXPAT_WITH_GETRANDOM=ON。

**修复命令**:
```
在 bump PR 中 diff 新旧两版 CMakeLists.txt 的选项声明（expat_shy_set 默认值）与探测分支；对变化选项显式写回配方；重跑完整上游 runtests 作为证据。
```

**验证**:
```
grep -n "expat_shy_set(EXPAT_WITH_GETRANDOM" <src>/CMakeLists.txt && grep -n "evaluate_detection_results(EXPAT_WITH_GETRANDOM" <src>/CMakeLists.txt && cmake -B build-ohos -S <src>/expat -DCMAKE_TOOLCHAIN_FILE=<ohos.toolchain> -DEXPAT_WITH_GETRANDOM=ON -DEXPAT_BUILD_TESTS=ON -DEXPAT_BUILD_TOOLS=OFF && cmake --build build-ohos && ./build-ohos/tests/runtests
```
