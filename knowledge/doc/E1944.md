# E1944: OHOS hnp bash 在 getcwd() 失败的执行上下文启动时内置 PWD 未定义，set -u 脚本引用 ${PWD} 必现 "unbound variable"，调用方应显式传 PWD=<工作目录>

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, runtime, environment, shell
- **作者**: sea_crab
- **来源 PR**: (随库 PR 交付，PR 号待定)

## 错误特征
```
PWD: unbound variable|getcwd: cannot access parent directories|shell-init: error retrieving current directory
```

## 根因分析
完整因果链（设备实测，2026-09-09 复现）：(1) 工具实现证据——OHOS hnp bash（/data/service/hnp/bin/bash，5.3）启动时若环境未带 PWD，则以 getcwd(2) 初始化内置 PWD；在 ssh 远程命令、清洁 env（env -i / subprocess 空 env）等派生上下文中该 getcwd() 跨目录失败（home 报 Operation not permitted，/tmp 与 /data/service/hnp/bin 报 Permission denied，深层 storage 路径报 Not a tty/Not supported），bash 打印 "shell-init: error retrieving current directory" 且 PWD 保持未定义（探针原文见 verification_cmd）；(2) 触发命令——任何在该上下文以 hnp bash 执行、且启用 set -u（或 set -euo pipefail）后引用 ${PWD} 的脚本（案例 dehydrated 0.7.2 line 9 set -u、line 348 load_config 配置搜索 "${PWD}"）；(3) 失败点——首次 ${PWD} 展开即报 "PWD: unbound variable" 并按 set -u 语义退出，脚本尚未来得及输出业务诊断；(4) 归类——OHOS hnp 域进程的执行上下文语义问题（getcwd 受限 + bash PWD 初始化回退缺失），非库缺陷、非 HMDFS 独有（/tmp 等本地目录同样失败）。间歇性来源：经 conan 聚合 shell / mksh 等会导出 PWD 的父进程间接执行时不复现，故"部分执行上下文"必现。

## 推荐方案
**方法**: explicit-pwd-env-when-spawning-hnp-bash

**说明**: 调用方在派生 hnp bash 前显式提供 PWD 环境变量并指向真实工作目录：conan self.run 用命令前缀 'cd "<dir>" && PWD="<dir>" <bash> script'（cd 与 PWD 成对，cwd 参数与 PWD 值一致）；python subprocess 用 env["PWD"]=<脚本所在目录>；CI 直跑脚本前 export PWD=$PWD。一次赋值即同时消除 "shell-init getcwd" 诊断与 "unbound variable" 退出两个症状；不修改被测脚本、不污染上游判定。

**修复命令**:
```
self.run('cd "%s" && PWD="%s" "%s" <script> <args>' % (src, src, bash_path))
```

**验证**:
```
设备任意新 shell 可复现（只读探针，不写文件）——
```
