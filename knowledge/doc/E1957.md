# E1957: OHOS musl 工具链默认优化不发射 unwind tables，栈追踪库运行时输出 0 帧空栈

## 基本信息
- **严重度**: 2
- **类别**: platform, libc, debugging, unwinding
- **作者**: unknown

## 错误特征
```
backtrace frames: 0|frames: 0\b|<empty trace>|_Unwind_Backtrace.*0 frame|stack trace.*empty|trace\.frames\.size\(\) == 0
```

## 根因分析
OHOS musl 环境的 clang 默认编译优化（-O1/-O2）不发射 .eh_frame/unwind tables（glibc 生态的 GCC/clang 发行版默认带 -fasynchronous-unwind-tables）。所有依赖帧指针回溯或 unwind 信息的栈追踪方案（execinfo backtrace、libgcc _Unwind_Backtrace、libbacktrace、backward-cpp、boost::stacktrace、cpptrace）在运行时拿不到任何帧信息：backtrace() 返回 0、_Unwind_Backtrace 回调一次都不触发。编译链接全部成功，只有运行期才能发现空栈——构建期完全无告警。实测对照：同一程序加 -funwind-tables 后 backtrace 返回 3 帧、_Unwind_Backtrace 回调正常、cpptrace generate_trace() 完整输出含文件名/行号的栈帧。

## 推荐方案
**方法**: add-funwind-tables-flag

**说明**: 对需要运行时栈展开的目标（库本体、测试程序、消费方示例）在编译选项中显式加 -funwind-tables。Conan 配方里通过 CMakeToolchain 全局注入（tc.variables["CMAKE_CXX_FLAGS"] 追加）或对特定 target 加 target_compile_options；test_package/CMakeLists.txt 对测试目标显式添加。注意：栈库的公共头文件里 CPPTRACE_FORCE_NO_INLINE 等宏只能保证函数不被内联，不能弥补缺失的 unwind tables。

**修复命令**:
```
CMakeLists.txt: if(NOT MSVC) target_compile_options(<target> PRIVATE -funwind-tables) endif()；或 Conan generate(): tc.variables["CMAKE_CXX_FLAGS"] = "... -funwind-tables"
```

**验证**:
```
写最小探针验证：void* buf[16]; int n = backtrace(buf, 16); 不带 -funwind-tables 时 n==0（空栈），带 -funwind-tables 编译后 n>=2（真实帧）。或跑栈库自带的栈追踪测试观察是否输出 0 帧。
```
