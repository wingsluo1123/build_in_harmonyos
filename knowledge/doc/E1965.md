# E1965: AC_PROG_LEX(yywrap) 在链接不到 yywrap 库时把 LEX 静默降级为 ':'，scanner 规则空转导致构建失败——应在 make 前按上游原命令行预生成生成物

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, autotools, flex, lex
- **作者**: sea_crab / 不知对不队 (curator 汇编)
- **来源 PR**: pending（随 feat 分支交付）

## 错误特征
```
yywrap not found; giving up on flex|cannot stat.*lex\.yy\.c|No rule to make target.*scan\.c|^LEX = :$
```

## 根因分析
autoconf AC_PROG_LEX/AM_PROG_LEX(yywrap) 在选定 flex 后用 -lfl 链接探测 yywrap 符号；探测失败的直接原因不是 flex 缺失而是 libfl 不在默认链接搜索路径（OHOS 设备 flex 2.6.4 的 libfl.a 位于 /data/service/hnp/flex.org/flex_2.6.4/lib，默认路径 clang -lfl 报 ld.lld: error: unable to find library -lfl，已实测）。探测失败后 configure 仅打 WARNING: yywrap not found; giving up on flex 并把 LEX 降级为 ':'（LEXLIB 置空），不报错不中止；随后 make 执行 scanner 规则 "$(LEX) $< && mv lex.yy.c $@" 时 ':' 空转成功、lex.yy.c 不存在 → mv 失败或编译期缺 scanner .c → 构建失败。源头树按上游惯例不含生成物时必现

## 推荐方案
**方法**: pregenerate-lex-yacc-outputs-before-make

**说明**: 在 make 前用上游 Makefile 规则的原样命令行预生成全部 scanner/parser 产物，使 make 不再调用 $(LEX)/$(YACC)。要点：(1) 命令必须逐字取自上游 Makefile.in 规则（如 flex servscan.l && mv lex.yy.c servscan.c、bison -tdv 后按 y.tab.h/y.tab.c 与目标名 cmp 后 mv），不得手写等价命令引入版本差异；(2) 生成动作放进 recipe build() 而非补丁进源码，保持源树可向上游提交；(3) scanners 自带 yywrap 的包无需 -lfl，预生成后链接面不变

**修复命令**:
```
cd $SRC && flex servscan.l && mv lex.yy.c servscan.c && bison -tdv servparse.y && { cmp -s y.tab.h servparse.h || mv y.tab.h servparse.h; } && { cmp -s y.tab.c servparse.c || mv y.tab.c servparse.c; } && rm -f y.tab.h y.tab.c   #（对每个 scanner/parser 重复；YACC 用 configure 选定的 bison -y 等价命令）
```

**验证**:
```
在设备上新 shell 依次执行：printf 'int yywrap(void){return 1;}\nint main(void){return 0;}\n' > /data/storage/el2/base/probe-fl.c && /data/service/hnp/bin/clang /data/storage/el2/base/probe-fl.c -lfl -o /data/storage/el2/base/probe-fl（预期 ld.lld: error: unable to find library -lfl，证明默认路径无 libfl）；再加 -L/data/service/hnp/flex.org/flex_2.6.4/lib 重复（预期链接成功，证明 libfl 存在仅路径不可达）；最后对任一含 .l 且不带生成物的 autotools 源树跑 configure 后 grep -E '^LEX' Makefile（预期 "LEX = :"）且 config.log 含 "giving up on flex"；删除 /data/storage/el2/base/probe-fl*
```
