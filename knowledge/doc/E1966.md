# E1966: 同名 cmake_file_name 的两个 Conan 包在同一 CMakeDeps 生成目录互相覆盖（后装覆盖先装，组件 target 丢失）

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, packaging, dependency-resolve
- **作者**: unknown
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/9258

## 错误特征
```
Could not find a package configuration file provided by "Boost"|but the target was not found. Possible reasons include|Boost::filesystem|CMakeDeps necessary find_package
```

## 根因分析
Conan 2.x CMakeDeps 按 recipe 的 cpp_info.set_property("cmake_file_name", X) 生成 <X>Config.cmake。当依赖图里两个包声明相同的 cmake_file_name（如 boost1.84 与 boost1.84-thread 都注册 "Boost"）且安装到同一 generator 目录时，后写入的 <X>Config.cmake/<X>Targets.cmake/<X>-Target-*.cmake 会整组覆盖先写入的——主包的组件 target（Boost::filesystem/Boost::headers 等）完全丢失，消费者 find_package(Boost COMPONENTS filesystem) 报 "Could not find a package configuration file provided by Boost" 或链接期报 "Target links to: Boost::filesystem but the target was not found"。典型触发：Debian 风格的拆分包系列（boost1.84 / boost1.84-thread / boost1.84-locale ...）都被上游配方写成 cmake_file_name="Boost"。

## 推荐方案
**方法**: deps-set-property-rename

**说明**: 在消费方配方的 generate() 里用 CMakeDeps.set_property 给其中一个包改 cmake_file_name，使其生成独立命名的 config 文件组，两包共存：主包独占原名，改名包用自己的新名查找。改名只影响本配方的生成目录，不修改已发布依赖包。

**修复命令**:
```
def generate(self):
```

**验证**:
```
conan install --requires=boost1.84/1.84.0 --requires=boost1.84-thread/1.84.0 -g CMakeDeps && ls "<generators>/" | grep -c BoostConfig
```
