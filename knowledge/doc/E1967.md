# E1967: C++17+libc++ 下 using namespace std 与全局 data 标识符歧义导致旧 C++ 库编译失败（farmhash 1.1.0 确认实例）

## 基本信息
- **严重度**: 2
- **类别**: toolchain, c++, libcxx
- **作者**: pc2-4 <noreply@atomgit.com>

## 错误特征
```
reference to 'data' is ambiguous|candidate found by name lookup is 'data'|candidate found by name lookup is 'std::data'|20 errors generated
```

## 根因分析
旧 C++ 源码（如 2015 年 farmhash）在文件顶层有 `using namespace std;`，并在多个命名空间（farmhashcc/farmhashmk/farmhashna 等）的自测区声明全局数组 `static char data[kDataSize];`。C++17 在 `<iterator>` 中新增了 `std::data` 函数模板；当工具链注入 `-std=c++17 -stdlib=libc++` 时，未限定的 `data` 在数组变量与 std::data 模板之间产生名字查找歧义（`reference to 'data' is ambiguous`）。默认 C++14 构建不触发（std::data 不存在），因此本地手工 make 常绿而 conan create 红。

## 推荐方案
**方法**: 将冲突的全局/命名空间级 `data` 数组（含全部引用）改名为非 std 同名标识符（如 farmhash_data），保留注释/宏语义，不改公共 API。

**说明**: 在自测区 `static char data[kDataSize];` 及所有引用处统一改名（farmhash 共 9 处声明、100 处 token），`data-parallel` 等注释保留不改。这是最小改动：只影响自测代码，不改变库的公共头文件与 ABI。备选：移除 `using namespace std;` 需全局改动更激进；调低 cppstd 会降低工具链默认配置一致性。

**修复命令**:
```
见 archives/f/farmhash/1.1.0/patches/0003-src-farmhash.cc.patch（rename data→farmhash_data，仅自测区）
```

**验证**:
```
clang++ -std=c++17 -stdlib=libc++ -I src -c src/farmhash.cc  # 修复前报 ambiguous；修复后 exit 0
```
