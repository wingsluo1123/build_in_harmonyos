# E1969: 凡修改 CMakeToolchain.variables/cache_variables 的每一轮 conan crea

## 基本信息
- **严重度**: medium
- **类别**: cmake, conan, testing
- **作者**: unknown

## 错误特征
```
CMakeCache.txt.*:STRING=.*旧值|改了配方.*宏没生效|CXX_DEFINES = -D.*=1.*预期.*=0
```

## 根因分析
conan 2.x 对相同 package_id（settings/options/deps 不变，recipe 内容不参与）复用同一 p/b/<pkgid>/b 构建目录；CMakeToolchain 将 tc.variables 以 set(... CACHE ...) 写入，CACHE 变量已存在且无 FORCE 时不覆盖。修改 conanfile 中的 CMake 变量后重跑 conan create，configure 仍取上一轮旧值（CMakeCache.txt 实测 FLATBUFFERS_LOCALE_INDEPENDENT:STRING=ON 残留），编译与配方声明背离，造成修复无效的验证假象。

## 推荐方案
**方法**: 凡修改 CMakeToolchain.variables/cache_variables 的每一轮 conan create 前，删除该包构建缓存 rm -rf $CONAN_HOME/p/b/<pkgid前缀>*；核验不信任配方与日志，直接读构建目录 CMakeCache.txt 与 CMakeFiles/<target>.dir/flags.make 的实际宏和旗标值；同包多轮失败会按 recipe revision 派生多个平级包目录，用 ls -dt 取最新定位。
