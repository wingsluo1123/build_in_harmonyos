# E1972: 只补 config.guess 时 config.sub 会把 OHOS 三元组静默规范化成 <machine>-unknown-linux-gnu-ohos（configure/make 全绿、host_os=linux-gnu-ohos）；Conan 仅在 cross_building() 为真时注入三元组，剪枝不是通用修复

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, conan, config.guess, config.sub
- **作者**: Awstme
- **来源 PR**: pending（feat/digup-0.6.57 交付 PR）

## 错误特征
```
aarch64-unknown-linux-gnu-ohos|linux-gnu-ohos|S["host_os"]="linux-gnu-ohos"
```

## 根因分析
机理链（GNU config 脚本 timestamp 2020-01-01 + Conan 2.29.1 实测；hunk 隔离实验见 verification_cmd）：(1) config.guess 补丁输出 4 段 aarch64-unknown-linux-ohos，该版 config.sub 由 case $1 in 的两条分支处理——4 段走 *-*-*-*（config.sub 125-128 行，位置在 ambiguous 分支之上）得到 basic_machine=aarch64-unknown / os=linux-ohos，3 段（Conan 注入形态）走 *-*-*) ambiguous 分支（129-150 行）；(2) 两条分支最终都受 OS 列表（1357 行 `-linux-gnu* | -linux-android*` 那一行）管辖：白名单没有 linux-ohos* 时，1397 行的 OS 归一化 case 中具名分支 linux*) 的 os=`echo $os | sed -e 's|linux|linux-gnu|'` 把 os 静默改写成 os=linux-gnu-ohos（最终完整三元组为 aarch64-unknown-linux-gnu-ohos），rc 恒为 0、无任何告警；(3) hunk 分工（拆开应用 0002 的两个 hunk 实测）：只应用 134 行 ambiguous 列表 hunk 时 4 段仍被静默改写成 -gnu-ohos（说明该 hunk 对 4 段无效）；只应用 1357 行 OS 列表 hunk 时 4 段正确、3 段响亮报 Invalid configuration ... system `ohos' not recognized（rc=1）；两个 hunk 齐备时两种形态都得到 aarch64-unknown-linux-ohos；(4) 错误身份被 configure 全盘采信并落盘，形态为 config.status 中的 S["host_os"]="linux-gnu-ohos"（注意不是 shell 赋值语法），任何 case $host_os in *-gnu*|linux-gnu*) 分支会被错误命中、linux-ohos 分支永不命中；因为 configure/make 全绿且产物可运行，该缺陷只能靠 config.sub "$(config.guess)" 原样返回与 S["host_os"] 断言发现，不能用「configure 是否通过」替代。(5) 附带澄清：AutotoolsToolchain 的三元组生成被 if self._is_cross_building: 包住（_is_cross_building = not is_universal_arch and cross_building(self)），本仓库 CI 把同一 profile 传给 -pr:h 与 -pr:b 故 cross_building() 为 False、不注入任何 --host/--build，configure 会自行调用 config.guess；只有异构 build profile 才出现 --host=aarch64-linux-ohos --build=x86_64-linux-gnu

## 推荐方案
**方法**: pair-gnuconfig-patches-and-assert-roundtrip

**说明**: 把 config.guess 与 config.sub 的 OHOS 补丁作为**一个原子改动**成对补齐：config.guess 增加 HarmonyOS 分支（按脚本代际选 echo+exit 或 GUESS= 形态），config.sub 的两处 hunk 都要补 —— ambiguous 三元组列表（该版 134 行）与 OS 列表（1357 行）各加 linux-ohos*。两处缺一不可且分工不同（hunk 隔离实验实测）：4 段形态 <machine>-unknown-linux-ohos（config.guess 产出）走 *-*-*-* 分支，只由 OS 列表 hunk 放行（只补 ambiguous 列表时它仍被静默改写成 <machine>-unknown-linux-gnu-ohos）；3 段形态 <machine>-linux-ohos（Conan 注入）走 ambiguous 分支，两个 hunk 都缺一不可（缺 ambiguous 列表 → 落 *) 兜底被拆错；缺 OS 列表 → 仍被静默改写）。真正的静默改写是该版 1397 行 OS 列表兜底的 os=`echo $os | sed -e 's|linux|linux-gnu|'`，rc 恒为 0。补完后必须显式断言 config.sub "$(config.guess)" 与 config.guess 输出逐字节相同（不能用「configure 是否通过」替代），并核验 config.status 中 S["host_os"] 为 linux-ohos 而非 linux-gnu-ohos（注意是 S["host_os"]=... 形态，grep '^host_os=' 恒为空）。不要为了「让 config.guess 生效」去剪掉 Conan 的 --host/--build：同构 profile（本仓库 CI）下本来就没有三元组，剪枝是空操作；异构 profile 下剪枝会让 configure 在构建机上判定平台

**修复命令**:
```
sh config.guess; sh config.sub "$(sh config.guess)"   # 两者必须输出同一三元组
```
