# E1984: test_package 提供 stub proc-address 回调（签名必须为 GLADloadfunc=GLAD

## 基本信息
- **严重度**: medium
- **类别**: platform, testing, graphics, link
- **作者**: unknown

## 错误特征
```
(无编译错误) 在无 GPU/EGL/GLFW 上下文的 CI 上无法运行函数指针表 loader（glad/GLEW/EGL loader）的运行用例，导致 run 类上游用例全部未执行
```

## 根因分析
函数指针表 loader（glad 等）的运行用例依赖真实 GL/GLES/EGL 上下文：upstream run 用例链接 -lglfw/-lgdi32 并创建显示上下文，CI 无 GPU/显示服务器即硬阻塞。但 loader 的初始化路径本身（gladLoadGL → glad_gl_find_core_gl 版本解析 → 函数表填充 → 扩展探测）不依赖真实上下文，可以用 stub get-proc-address 驱动真实执行。

## 推荐方案
**方法**: test_package 提供 stub proc-address 回调（签名必须为 GLADloadfunc=GLADapiproc(*)(const char*)，GLADapiproc=void(*)(void)，返回值不是 void*）：对 glGetString 返回"4.6.0"版本串（驱动 glad_gl_find_core_gl 的 sscanf 版本解析），对 glClear 返回真实无害函数地址（验证表填充），其余返回 NULL；随后断言 gladLoadGL 返回值非 0、GLAD_GL_VERSION_4_6==1、表项非 NULL。这样在无 GPU 上下文 CI 上真实执行 loader 初始化代码路径且不跳转到假地址。
