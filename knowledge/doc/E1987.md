# E1987: flang-ohos 精简运行集链接需显式注入 SDK sysroot/resource-dir 与 FortranRuntime/Decimal，不可依赖默认探测

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, linking, fortran
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: 本 PR

## 错误特征
```
No CMAKE_Fortran_COMPILER could be found|cannot open Scrt1\.o|cannot open crti\.o|cannot open crtbeginS\.o|unable to find library -l:libunwind\.a|libclang_rt\.builtins\.a: No such file or directory|linker command failed with exit code 1
```

## 根因分析
flang-ohos/20.1.0 为设备原生 LLVM Flang 精简运行集（仅 bin/flang + libLLVM/libMLIR/libclang-cpp.so.20.1 + libFortran{Runtime,Decimal}.a），不含 clang builtins、crt 对象与 libomp。① 裸调用 flang 编译 Fortran 可过（前端自足），链接必败：ld.lld 报 cannot open Scrt1.o/crti.o/crtbeginS.o、unable to find -l:libunwind.a、cannot open <flang>/lib/clang/20/lib/aarch64-linux-ohos/libclang_rt.builtins.a（设备 P2-A 实证，EXIT=1）；② 正确契约=编译注入 --sysroot=<SDK>/native/sysroot -resource-dir=<SDK>/native/llvm/lib/clang/15.0.4，链接注入 -L<SDK>/native/llvm/lib/aarch64-linux-ohos（libunwind/libomp）-L<flang>/lib -lFortranRuntime -lFortranDecimal，运行 flang/lld 需 LD_LIBRARY_PATH=<SDK>/native/llvm/lib:<flang>/lib（前者补 lld 依赖的 libxml2.so.16，后者补 flang 运行期 libLLVM/libMLIR/libclang-cpp）——注入后同一程序链接并运行成功（设备 P2-B 实证，EXIT=0）；③ 库若不含任何对外 C 接口（纯 Fortran 静态库），CMake 的 find_package(LAPACK/OpenMP REQUIRED) 依赖 FindLAPACK/FindOpenMP 链接探测，在 flang 精简运行集 + SDK 组合下不可靠（探测可执行文件链接同样踩 ①的坑），需确定性 Find 模块 shim 或 CMAKE_TRY_COMPILE_TARGET_TYPE=STATIC_LIBRARY 规避；④ 无任何注入时 CMake 直接报 No CMAKE_Fortran_COMPILER could be found（设备默认工具链无 Fortran 编译器，phase-a-configure.log 实证）。

## 推荐方案
**方法**: tool-requires-with-explicit-injection

**说明**: recipe 声明 tool_requires("flang-ohos/20.1.0")，在 generate() 统一注入：CMAKE_Fortran_COMPILER=<flang>/bin/flang；CMAKE_Fortran_FLAGS="-fPIC --target=aarch64-linux-ohos --sysroot=<SDK>/native/sysroot -resource-dir=<SDK>/native/llvm/lib/clang/15.0.4"；CMAKE_EXE_LINKER_FLAGS 含 -L<SDK>/native/llvm/lib/aarch64-linux-ohos -L<SDK>/native/llvm/lib -L<flang>/lib -lFortranRuntime -lFortranDecimal；build() 置 LD_LIBRARY_PATH=<SDK>/native/llvm/lib:<flang>/lib；package() 把 libFortranRuntime.a/libFortranDecimal.a 复制进包内 lib 并在 package_info.libs 声明（消费方链接闭包）。仓内先例：openblas 0.3.34、lapack 3.12.1；本 run devicexlib 0.9.1 按此全绿（CI L0-L5 pass）。

**修复命令**:
```
conanfile.py generate()（摘要）：tc.variables["CMAKE_Fortran_COMPILER"]=fc; tc.variables["CMAKE_Fortran_FLAGS"]="--target=aarch64-linux-ohos --sysroot=%s -resource-dir=%s"%(sdk_sysroot,sdk_resdir); tc.variables["CMAKE_EXE_LINKER_FLAGS"]="-L... -lFortranRuntime -lFortranDecimal"; build(): os.environ["LD_LIBRARY_PATH"]=os.pathsep.join([sdk_llvm_lib, flang_lib])
```

**验证**:
```
设备自包含两段对照（实测 EXIT 与输出见 reports/builder/draft-probes.log P2-A/P2-B）：①裸调用复现——printf 'program hello\n  print *, "flang link contract ok"\nend program\n' > hello.f90 后 env LD_LIBRARY_PATH=<SDK>/native/llvm/lib:<flang>/lib <flang>/bin/flang hello.f90 -o hello_a，预期 ld.lld 报 Scrt1.o/crtbeginS.o/libclang_rt.builtins.a/libunwind 一组错误且 EXIT=1；②契约注入通过——同 env 下 <flang>/bin/flang --sysroot=<SDK>/native/sysroot -resource-dir=<SDK>/native/llvm/lib/clang/15.0.4 hello.f90 -o hello_b -L<SDK>/native/llvm/lib/aarch64-linux-ohos -L<SDK>/native/llvm/lib/clang/15.0.4/lib/aarch64-linux-ohos -L<flang>/lib，预期 EXIT=0 且 ./hello_b 打印 "flang link contract ok"。其中 <SDK>=/data/service/hnp/ohos-sdk.org/*/ohos/native（glob 取最新），<flang>=conan 缓存 flang-ohos 包目录（conan cache path 或 dependencies.build 取得）。
```
