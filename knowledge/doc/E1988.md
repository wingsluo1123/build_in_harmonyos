# E1988: flang 报 Must be a constant value（use 关联 kind 参数作 kind 选择器）：并行/HMDFS 下跨文件 .mod 非确定性损坏所致，串行构建 + CPU 等价默认化消除；"接口体无 host association 被拒"假设已被最小探针证伪

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, toolchain, compiler, fortran
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: 本 PR

## 错误特征
```
error: Must be a constant value|integer\(kind=[a-z_]+\), intent\(in\) :: async_id|error: Semantic errors in .*\.f90
```

## 根因分析
症状：flang-ohos 20.1.1 编译含跨文件模块依赖的 Fortran 库时，在 use 关联 kind 参数（如 integer(kind=dxl_async_kind)，dxl_async_kind = kind(0)，由 devxlib_async 模块导出）的全部 kind 选择器处报 "error: Must be a constant value"（devicexlib 0.9.1 实测 42 处，集中于 devxlib_memcpy.f90:3458-3891 的 h2h_async 接体段），make 报 Error 2。机理核验（2026-09-11 设备实证）：① 最小判别探针——module + use 关联 kind 参数 + interface body + submodule 实现完整结构——在 flang 20.1.1 下串行编译/运行全部通过，IMPORT 变体同样通过，证明"接口体无 host association 被 flang 拒绝"这一机制假设不成立（构造本身 flang 兼容）；② pristine 的 devxlib_memcpy.f90 全文件（5543 行、含全部 168 处该构造）在可信 .mod 依赖下串行 -cpp 编译 0 错误；③ 该错误仅在 -j20 并行构建中出现，且与 "make: jobserver mkfifo: Operation not permitted"（HMDFS 不支持 FIFO jobserver，同 E074）同现，本 run 期间 HMDFS 已多次实证静默丢文件与可见性延迟（patch 生成阶段 scp/tar 文件需重试可见）——综合判定最可能机制为并行构建下跨文件 .mod 读取非确定性损坏，消费侧对导入参数常量值求值失败，kind 选择器是首当其冲的报错点；④ 修复后（串行构建 + DXL_ASYNC_DECL 宏 CPU 等价默认化）8 套件 176/176 上游测试全过（linalg 16、malloc 28、mapping 28、buffer 10、memcpy 28、memcpy_async 28、memset 28、pinned 10，nfail 全 0），错误类消除。

## 推荐方案
**方法**: serial-build-plus-cpu-equivalent-kind-defaulting

**说明**: 两层修复（本 run 已验证）：1) 构建纪律——含跨文件 .mod 依赖的 Fortran 库在 OHOS/HMDFS 上必须串行构建（CMAKE_BUILD_PARALLEL_LEVEL=1 / cmake --build -j1），这是正确性要求而非性能选择（HMDFS 不支持 make FIFO jobserver，同 E074；并行下 .mod 未生成/损坏即被消费）；2) 消费侧去依赖——把 integer(kind=<use关联参数>) 声明改经 DXL_ASYNC_DECL 宏：CPU-only 配置展开为等价默认 integer（kind(0)==default kind），GPU 能力宏分支展开原文，消除消费侧对导入参数常量保真的依赖。devicexlib 0.9.1 补丁 0002 覆盖 9 个文件 410 处声明，修复后 8 套件 176/176 上游测试全过。

**修复命令**:
```
build(): os.environ["CMAKE_BUILD_PARALLEL_LEVEL"]="1" 后 CMake(self).build()；补丁侧：文件头 #if defined __DXL_CUDAF || defined __DXL_OPENACC || defined __DXL_OPENMP_GPU / #define DXL_ASYNC_DECL integer(kind=dxl_async_kind) / #else / #define DXL_ASYNC_DECL integer / #endif，并全文替换 integer(kind=<param>) → DXL_ASYNC_DECL（conandata patches 注册，flang -cpp 可处理该宏）。
```

**验证**:
```
判别序列（设备自包含）：① 写最小判别探针 probe_mod.f90（module probe_impl 内 integer,parameter::dxl_async_kind=kind(0)；module probe_mod use probe_impl 后 interface body 声明 integer(kind=dxl_async_kind) dummy；submodule (probe_mod) 给 module procedure 实现）+ probe_main.f90（call 之），用 flang-ohos 串行编译运行——通过即证明构造 flang 兼容、排除接口体语义拒绝（探针全文见 doc_file 与 run 报告 reports/builder/draft-probes.log，P1-A/P1-B 均 EXIT=0 且 "probe ok"）；② 对真实库：取 pristine 源文件 + 可信 .mod 依赖（上次成功构建的 p/mod 目录）串行 flang -c -cpp 编译，0 错误 = 构造兼容确认（本 run REPRO-EXIT=0，见 reports/builder/repro-real.log）；③ 真实故障重现特征：并行 -jN 构建同一库，出现成批 "Must be a constant value"（仅集中部分区段）且伴随 GMfifo jobserver 告警——非确定性，串行后不可复现即确认本条。
```
