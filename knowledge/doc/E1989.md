# E1989: OHOS multimodalinput injection authorization is asymmetric per event type: key injection is authorization-free while mouse injection and monitors get INPUT_PERMISSION_DENIED and RequestInjection stalls in AUTHORIZING, so injection CLIs must gate commands by real capability and point to OH_Input_RequestInjection instead of polling the callback

## 基本信息
- **严重度**: 2
- **类别**: platform, api
- **作者**: GoliWie

## 错误特征
```
INPUT_PERMISSION_DENIED|InjectMouseEvent.*201|AddMouseEventMonitor.*201|RequestInjection.*3900005|INPUT_INJECTION_AUTHORIZING|status=AUTHORIZING
```

## 根因分析
The OHOS multimodalinput security model grades injection authorization by event type and caller shape, not by a single switch. The SDK sysroot ships usr/include/multimodalinput/oh_input_manager.h (declaring the UNAUTHORIZED/AUTHORIZING/AUTHORIZED state machine, OH_Input_RequestInjection, API 20, and OH_Input_CancelInjection) and libohinput.so, but the actual runtime behavior is undocumented: OH_Input_InjectKeyEvent returns INPUT_SUCCESS without any authorization, while OH_Input_InjectMouseEvent and OH_Input_AddMouseEventMonitor return INPUT_PERMISSION_DENIED (201) in non-interactive sessions, and OH_Input_RequestInjection returns INPUT_INJECTION_AUTHORIZING (3900005) with the registered callback never firing and OH_Input_QueryAuthorizedStatus staying AUTHORIZING. A tool that assumes one uniform injection capability therefore reports false failures or deadlocks waiting for an authorization transition that cannot complete in that session.

## 推荐方案
**方法**: command-level-capability-split-with-authorization-guidance

**说明**: Run the probe first, then map every CLI command to the injection API it actually needs. Commands on authorization-free APIs (key injection) stay first-class. Commands on gated APIs (mouse injection, event monitors, pointer read-back) must check the gate and fail explicitly with a diagnostic that names OH_Input_RequestInjection as the authorization path; their tests must accept exactly two outcomes, authorized success or denied-with-diagnostic. Do not degrade the free capability because the gated one is denied, and do not fake success on the gated one.

**修复命令**:
```
Add dual-outcome negative assertions for every gated command and an explicit unsupported boundary (same E240 pattern) for commands whose API surface does not exist at all (no pixel read-back, no clipboard write); embed the OH_Input_RequestInjection hint in the gate diagnostic.
```

**验证**:
```
In a fresh device shell: test -f /data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot/usr/include/multimodalinput/oh_input_manager.h && test -f /data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot/usr/lib/aarch64-linux-ohos/libohinput.so; then save the complete standalone probe source from doc_file section 'Verification' as probe_ohinput.c (self-contained C program, no run artifacts needed) and run /data/service/hnp/bin/clang --target=aarch64-linux-ohos --sysroot=/data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot -lohinput probe_ohinput.c -o probe_ohinput && ./probe_ohinput, which must print inject_key_a down=0 up=0 (key injection free), add_mouse_monitor: result=201, inject_move_initial: result=201, request_injection: result=3900005, auth_callback: called=0 status=none, query_authorized_after_request: result=0 status=AUTHORIZING, inject_move_after_request: result=201.
```
