# E1990: When sources are bound to desktop-only frameworks and the OHOS sysroot has no ObjC runtime the dependency closure is unsatisfiable: reimplement the CLI contract in portable C anchored by upstream tests with an OHOS native C API backend, and keep GNUstep only as a fallback closure

## 基本信息
- **严重度**: 2
- **类别**: platform, dependency
- **作者**: GoliWie

## 错误特征
```
Foundation/Foundation.h.*not found|fatal error: .*objc/objc.h|fatal error: .*Cocoa/Cocoa.h|framework not found|cannot find -lobjc|undefined symbol: _objc_
```

## 根因分析
The OHOS native sysroot ships no ObjC runtime: usr/include/objc does not exist and no libobjc is present under usr/lib/aarch64-linux-ohos, so #import <Foundation/Foundation.h> and -framework Cocoa/Carbon cannot compile or link. The closure gap cannot be bypassed with build flags; it forces an explicit route decision. Family practice distinguishes three cases: cross-platform projects grow an OHOS native backend on their existing platform abstraction; partially portable CLIs keep the portable core and add a backend with capability split; fully framework-bound sources must stay in-tree uncompiled for provenance while the observable CLI contract is reimplemented in portable C over OHOS C APIs.

## 推荐方案
**方法**: contract-anchored-reimplementation-with-native-capi-backend

**说明**: Keep the family-level decision table; do not narrow the pattern to a single face. (1) Cross-platform projects add an OHOS native backend on their existing abstraction: synergy-core 1.20.4 consumes oh_input_manager.h in its OHOS platform layer (patches 0004/0027/0028/0042; 0027 adds src/lib/platform/OHOSKeyState.cpp) — cite it as a native-backend injection-consumer practice, NOT as a closure-unsatisfiable case, since its OHOS backend was not forced by a macOS closure. (2) Partially portable CLIs keep the portable core, add the OHOS backend and split capabilities with negative tests: screenresolution 1.6 (E240, CoreGraphics read-only queries onto OH_NativeDisplayManager). (3) Fully framework-bound sources (100% ObjC) cannot link any route: keep macOS sources in-tree uncompiled for provenance, pin the observable CLI contract by porting the upstream test suite 1:1 as oracle, reimplement that contract in portable C over OHOS C APIs as an additive backend, and give every capability boundary an explicit unsupported diagnostic with a negative test.

**修复命令**:
```
Probe the sysroot first (verification_cmd), then pick the tier. Anchor the reimplementation on upstream tests: portable assertions 1:1, platform-blocked assertions replaced only with a named reason, boundaries asserted as explicit unsupported dual-outcome tests.
```

**验证**:
```
In a fresh device shell: (1) test ! -e /data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot/usr/include/objc must pass (no ObjC headers); (2) ls /data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot/usr/lib/aarch64-linux-ohos | grep -i objc must print nothing (no libobjc); (3) printf '#import <Foundation/Foundation.h>\nint main(void){return 0;}\n' > probe_objc.m && /data/service/hnp/bin/clang --target=aarch64-linux-ohos --sysroot=/data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/sysroot -fsyntax-only probe_objc.m must fail with 'Foundation/Foundation.h' file not found.
```
