# E1991: musl 将 stdin/stdout/stderr 声明为 FILE *const，对标准流赋值在 OHOS 上必然编译失败，freopen 重关联应直接调用、不回赋

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, compilation
- **作者**: oh-device-porting-v2 curator <noreply@atomgit.com>

## 错误特征
```
cannot assign to variable '(stdin|stdout|stderr)' with const-qualified type 'FILE \*const'|variable '(stdin|stdout|stderr)' declared const here|extern FILE \*const stdin
```

## 根因分析
完整因果机理链——(1) 工具实现证据：OHOS SDK musl sysroot stdio.h:62-64 声明 `extern FILE *const stdin/stdout/stderr;`（musl 将标准流对象指针定为 const 只读，禁止重绑定）；glibc 的 stdio.h 将 stdin 声明为非 const `extern FILE *stdin;`。(2) 触发命令：make 编译含对标准流赋值的源文件（didiwiki 3.0.5 src/ci.c:181 `stdin = freopen(NULL,"r",stdin);`，`-t` 交互分支清空行缓冲的老式惯用法）。(3) 失败点：clang 报 "error: cannot assign to variable 'stdin' with const-qualified type 'FILE *const'"——硬错误而非 warning，无编译开关可绕过 → ci.o 失败 → make Error 2 → conan build 失败（真实日志：本机 builder/ci-run-5.log:264-271）。(4) 归类：musl/glibc 头文件声明语义差异导致的编译失败。(5) 修复语义依据：POSIX 规定 freopen 关闭并重关联该流；musl 与 glibc 的 freopen 均在原 FILE 对象上就地重关联并返回其指针，原代码的回赋等于把同一指针写回，纯冗余——删除赋值后全平台行为不变。

## 推荐方案
**方法**: 删除对标准流的赋值，直接调用 freopen（本 run 落地形态：patches/0002-fix-stdin-const-assign.patch，将 `stdin = freopen(NULL,"r",stdin);` 改为 `freopen(NULL,"r",stdin);`，全库 grep 确认仅此一处对标准流赋值，各平台行为不变，补丁可向上游提交）

**说明**: 按 C/POSIX 语义 freopen 自身完成流重关联，返回值无需回赋到全局标准流变量；这是语义等价修复而非平台 hack，满足 P-PATCH-003（补丁可向上游提交）。
