# E1992: 上游 tarball 携带 in-tree configure 残留时 Conan VPATH 构建必报 source directory already configured，应在 source() 清理残留

## 基本信息
- **严重度**: 2
- **类别**: autotools, conan, packaging, vpath
- **作者**: oh-device-porting-v2 curator <noreply@atomgit.com>

## 错误特征
```
configure: error: source directory already configured; run "make distclean" there first
```

## 根因分析
完整因果机理链——(1) 上游发布习惯：部分 autotools 项目直接从已构建的源码树打 tarball 发布，归档内携带 config.status/config.log/config.h/stamp-h1/Makefile 等 in-tree configure 产物（didiwiki 3.0.5 tarball 112 条目即含全套残留）。(2) 触发命令：Conan basic_layout/VPATH 约定下，源码复制到 build folder 后在 build 目录执行 `sh <src>/configure`。(3) 失败点：autoconf 生成的 configure 检测到 srcdir 存在 config.status，判定"源目录已按另一构建目录配置过"，直接 as_fn_error "source directory already configured; run \"make distclean\" there first"（同一 generated autoconf 宏在 archives/a/advancescan/1.18/patches/0008-configure.patch:3762-3764 可见）→ configure 退出 1 → conan build 失败。(4) 归类：上游归档卫生 × autoconf VPATH 检测语义 × Conan VPATH 构建约定三者的确定性冲突；残留文件均由本次 configure 重新生成，可安全删除。

## 推荐方案
**方法**: 在 recipe source() 解包后按固定清单删除 in-tree configure 残留：config.status、config.log、config.h、stamp-h1、顶层与各级子目录 Makefile（didiwiki 另含 src/scripts/docs 三级）（本 run 落地形态：archives/d/didiwiki/3.0.5/conanfile.py source() residues 清单，文件存在才删，逐项 os.remove）

**说明**: 这些文件全部由本次 configure 重新生成，删除不损失任何上游语义；比补丁改 configure 或 make distclean 更确定。配方树 103 个 conanfile.py 含同样的 "config.status" 清理实践（abook/alien-arena/aldo/aribb24/asterisk-*/atool/awf-gtk 等），属既成工程惯例的知识化。

**修复命令**:
```
见 archives/d/didiwiki/3.0.5/conanfile.py source()（residues 列表 + 逐项存在性判断删除）
```

**验证**:
```
# 三段自包含探针（Builder 2026-09-10 在 ohpc2 真机 fresh sandbox 实测，tarball SHA-256 290aee7f… 与官方双源核验一致；error signature 另由 ci-run-4.log 与 advancescan/1.18 notes 两 run 日志证实）：(1) 门禁复现：tar xzf ciwiki-3.0.5.tar.gz && mkdir b && cd b && sh ../ciwiki-3.0.5/configure --prefix=/tmp/probe  → configure: error: source directory already configured; run "make distclean" there first（任何 checking 前，configure 退出 1）。(2) 残留核验：解包后 ls 顶层即见 config.status、config.log、config.h、stamp-h1、Makefile，另有 src/scripts/docs 三级子目录 Makefile，全套 8 件。(3) 清理后：rm 上述 8 个明确路径文件后同命令 → 不再报 already configured，正常进入 checking（实测 9 项 checking 输出；显式 CC 时推进到 creating ./config.status；裸 PATH 探针 shell 无 C compiler 时止于编译器检测——尾部差异均属探针沙箱环境，与残留门禁无关）。
```
