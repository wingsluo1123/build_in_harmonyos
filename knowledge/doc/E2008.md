# E2008: Before scheduling the test window, read the test sources for

## 基本信息
- **严重度**: medium
- **类别**: threading, testing, strategy
- **作者**: unknown

## 错误特征
```
upstream stress-style validate program with compile-time iteration constant (ITERATE/LOOP define) runs for hours on shared OHOS device, OOM-killed or never finishes inside make check
```

## 根因分析
Concurrency libraries ship stress-style validate programs whose iteration counts are compile-time constants (ifndef-guarded defines such as ITERATE 5000000). configure probes CORES from /proc/cpuinfo (20) while the container/cgroup exposes fewer cores (8), so the test runs oversubscribed on a shared multi-tenant device — a single module takes hours of CPU, may be OOM-killed, and blocks the whole make check.

## 推荐方案
**方法**: Before scheduling the test window, read the test sources for ITERATE/thread constants and the progress output format. Prefer compile-time override (pass the original CFLAGS plus one extra -DITERATE=N to make) over editing test sources; keep thread counts, argv and per-iteration correctness assertions identical to upstream. Declare every overridden program item-by-item in the PR upstream-test-modification section (file, reason, change, result). On shared devices run at low priority (nice 19) and gate with device health probes (MemFree plus fork probe).
