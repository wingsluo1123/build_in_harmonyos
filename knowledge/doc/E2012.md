# E2012: musl features.h 不隐式定义 _POSIX_C_SOURCE，上游以 defined(_POSIX_C_SOURCE) 判定 POSIX 系统的探测会落 #error Unknown system，应补 __linux__/__unix__ 族宏或改能力探测

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, libc, musl, detect
- **作者**: unknown

## 错误特征
```
#error Unknown system|#error.*[Uu]nknown.*system
```

## 根因分析
glibc features.h 在默认（gnu）方言、未显式指定特性宏时，经隐式 _DEFAULT_SOURCE 将 _POSIX_C_SOURCE 定义为 200809L（glibc ≥2.19，feature_macros(7)）；musl features.h 只消费用户提供的特性宏、从不自行定义，且 clang 对任何目标 libc 均不预定义 _POSIX_C_SOURCE。因此上游"以 defined(_POSIX_C_SOURCE) 当 POSIX 系统探测器"的代码（典型：#if defined(_POSIX_C_SOURCE)…#define USE_POSIX … #elif defined(_WIN32) … #else #error Unknown system）在 glibc/Linux 恒真，在 musl/OHOS 恒假，落入 #else 分支 #error，库或测试 harness 构建失败。OHOS clang 实证（-E -dM）：__linux__/__unix__/__OHOS__ 均预定义为 1，__MUSL__ 不定义，_POSIX_C_SOURCE 含 features.h 后仍未定义。

## 推荐方案
**方法**: extend-probe-with-linux-family-macro

**说明**: 在上游探测链追加 || defined(__linux__)（或更泛 || defined(__unix__)），保留原有分支与 #error 兜底。进配方的改动走 conandata 补丁并带完整元数据（P-PATCH-004）；若改动仅服务上游测试门禁 harness 且配方 COIN_BUILD_TESTS=OFF 不构建测试（coin 4.0.10 案例），则改动保留在门禁构建树、不进配方交付物，并留 pristine A/B 反证日志。

**修复命令**:
```
#if defined (_POSIX_C_SOURCE) || defined (_POSIX_SOURCE) || defined(__APPLE__) || defined(__FreeBSD__) || defined(__linux__)；验证=探针②③；门禁场景另留 pristine 构建失败日志与 diff 证明唯一差异
```

**验证**:
```
# ① 工具实现证据（任意目录，零落盘）：musl 不回显特性宏；glibc 机器上运行同命令应得 ECHO_POSIX_DEFINED（glibc 侧另见 feature_macros(7)）
```
