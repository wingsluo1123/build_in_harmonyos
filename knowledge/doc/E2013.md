# E2013: 库公开头直接 include musl 垫片头(obstack/argp)与 elfutils 头时, OHOS 消费者仅 link 库 target 会因 CMakeDeps 传递依赖 include 元数据为空而编译失败, 需显式 requires+link 传递依赖

## 基本信息
- **严重度**: 2
- **类别**: musl, headers, cmake, conan, packaging
- **作者**: unknown

## 错误特征
```
fatal error: .*(obstack\.h|argp\.h|dwarf\.h).* file not found|(musl-obstack|argp-standalone|elfutils)_INCLUDE_DIRS_RELEASE \)
```

## 根因分析
Conan 2 CMakeDeps 在消费端只对直接 requires 的包生成含 include dirs 的完整配置; 传递依赖包的 *-data.cmake 中 INCLUDE_DIRS_RELEASE 置空. dwarves.h 公开头第14-16行直接 #include <obstack.h>/<dwarf.h>/<elfutils/libdwfl.h>, OHOS-musl 由 musl-obstack/argp-standalone/elfutils 提供, 消费者仅 find_package(dwarves)+link dwarves::dwarves 时拿不到传递头路径. 库自身构建不报错(CMakeToolchain CMAKE_INCLUDE_PATH 兜底注入掩盖)

## 推荐方案
**方法**: consumer-explicit-transitive-require

**说明**: 消费者(如 test_package)在 requirements() 显式声明传递依赖 musl-obstack/argp-standalone/elfutils, CMakeLists 显式 find_package 并 link 对应 target; 避免仅依赖库 target 的隐式传递. 主配方 requirements 保留 requires 声明以传播链接关系

**修复命令**:
```
def requirements(self):\n    self.requires(self.tested_reference_str)\n    self.requires("musl-obstack/1.2.3")\n    self.requires("argp-standalone/1.5.0")\n    self.requires("elfutils/0.195")  # 公开头传递依赖 -> 消费者显式声明
```

**验证**:
```
conan create archives/d/dwarves/1.30 -pr:h=<repo>/ci/conan/profiles/ohos-aarch64 -pr:b=<repo>/ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable; 修复前 fatal error: 'obstack.h' file not found 且 musl-obstack-<arch>-data.cmake 中 INCLUDE_DIRS_RELEASE 为空; 修复后 consumer 编译链接运行 OK (dwarves version: 130, consumer: OK), W3 L1 pass
```
