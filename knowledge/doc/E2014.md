# E2014: OHOS 无 CMake 平台模块导致 CMAKE_SHARED_LIBRARY_SONAME_C_FLAG 未定义, SOVERSION 不产出 DT_SONAME(无版本化符号链接), W3 L5a 报缺少 DT_SONAME; 配方 generate() 显式注入 -Wl,-soname, 修复

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, linking, conan, packaging
- **作者**: unknown

## 错误特征
```
.*\.so 缺少 DT_SONAME|DT_SONAME.*not found|SOVERSION.*soname|System is unknown to cmake.*Platform/HarmonyOS
```

## 根因分析
OHOS 无 CMake 平台模块(configure 报 System is unknown to cmake, create: Platform/HarmonyOS), CMAKE_SHARED_LIBRARY_SONAME_C_FLAG 未定义(Linux 上为 -Wl,-soname,). 上游 CMakeLists 虽设 PROPERTIES VERSION x.y SOVERSION n, 但链接命令缺 soname flag, 产出无 DT_SONAME 的 .so 且无版本化符号链接, 下游链接器无法按 SONAME 寻址. 与打包期问题(E274 缺 symlink / E316 缺实体)不同, 本候选为构建期 flag 未注入

## 推荐方案
**方法**: cmake-toolchain-soname-flag-injection

**说明**: 配方 generate() 中 CMakeToolchain 变量显式补 CMAKE_SHARED_LIBRARY_SONAME_C_FLAG="-Wl,-soname,", 使 SOVERSION 属性真正产出 DT_SONAME 与版本化符号链接; 无需改上游 CMakeLists

**修复命令**:
```
tc = CMakeToolchain(self)\ntc.variables["CMAKE_SHARED_LIBRARY_SONAME_C_FLAG"] = "-Wl,-soname,"\ntc.generate()
```

**验证**:
```
conan create archives/d/dwarves/1.30 -pr:h=<repo>/ci/conan/profiles/ohos-aarch64 -pr:b=<repo>/ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable; 修复前 llvm-readelf -d libdwarves.so 无 SONAME 且包内无 .so.1 链接, W3 L5a fail; 修复后包内出现 libdwarves.so.1/.so.1.0.0, readelf 显示 (SONAME) [libdwarves.so.1], W3 L5a pass
```
