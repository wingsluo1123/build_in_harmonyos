# E2021: autotools 包把运行时数据目录（SHAREDIR=--prefix/share）在 configure 阶段烧进二进制：安装到其它前缀后默认查找失败，需改为 exe 相对查找并保留编译期回退

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, autotools, conan, packaging
- **作者**: unknown

## 错误特征
```
Opening '.*share/.+' failed \(No such file or directory\)|SHAREDIR.*prefix|--prefix=.*datarootdir|getenv.*readlink.*exe
```

## 根因分析
上游 Makefile/C 源码把 `-DSHAREDIR=\"${prefix}/share\"` 编译进二进制，运行期只认编译期绝对路径；Conan 打包后包会被安装/迁移到任意路径（含 conan 缓存的 hash 目录），绝对路径必然失效。同类写法还有 LOCALEDIR、内置插件目录、字体/模板路径等。

## 推荐方案
**方法**: 1) 优先改源码为“相对可执行文件查找”：用 /proc/self/exe 推导 <bindir>/../share/<pkg>/，未命中回退编译期 SHAREDIR（保留开发树内运行能力）；2) 注意 readlink 不写 NUL 终止符，必须显式补 '\0'，否则静态缓冲区残留上次字节导致路径错乱；3) 无法改源码时，退路是在 recipe 的 generate()/build() 中把 --prefix 指向 self.package_folder，使烧入路径与安装布局一致（仅覆盖 conan 缓存布局，迁移仍会失效）；4) 验证：把安装树拷贝/移动到另一目录后直接运行 CLI 默认路径（不传 -f/-n 等显式参数）。
