# E2026: symlink-signature-preserving

## 基本信息
- **严重度**: 2
- **类别**: ohos, linking, conan
- **作者**: unknown
- **来源 PR**: "https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/9573"

## 错误特征
```
Error loading shared library /storage/.*\.conan2/p/.*\.so: \(needed by .*\)
```

## 根因分析
制品仓部分二进制包（实例：fontconfig/2.18.1 的 libfontconfig.so.1）的 DT_NEEDED 条目是发布机 conan 缓存的绝对路径（如 /storage/Users/currentUser/.conan2/p/expat…/p/lib/libexpat.so）。下游包在 CI worker 上构建时缓存位于 $HOME/.cache/conan2，绝对路径不存在 → OHOS musl loader 按路径解析失败（LD_LIBRARY_PATH 无法补救绝对路径 NEEDED）。且不可用 patchelf 改写 ELF：OHOS 内核对 so 做代码签名校验，修改过的副本加载直接 "Permission denied"（实测 dlopen 复现）。

## 推荐方案
**方法**: symlink-signature-preserving

**说明**: build() 阶段扫描依赖图全部 .so 的 DT_NEEDED（可用 readelf -d 或内嵌 ELF 解析），收集"绝对路径且本地不存在"的条目；对每个缺失路径，从依赖图找同名（basename）真实库文件，在烙印绝对路径处创建 symlink 指向真实文件——文件内容不变（签名有效），loader 按绝对路径打开 symlink 即加载成功。配合测试命令内联注入全依赖链 LD_LIBRARY_PATH（含传递依赖，conanbuild env 只带直接依赖）。注意：只创建调用用户 HOME 树内路径，仅缺失时创建。

**修复命令**:
```
readelf -d <dep>.so | grep NEEDED  # 找绝对路径条目; mkdir -p <烙印路径父目录> && ln -s <依赖图真实库> <烙印绝对路径>
```
