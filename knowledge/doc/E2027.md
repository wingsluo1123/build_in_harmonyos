# E2027: set-env-var

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, environment
- **作者**: unknown
- **来源 PR**: nagios 4.5.14

## 错误特征
```
Error: temp_path '/tmp' is not a valid directory|can't create temporary file /tmp/.*: Read-only file system
```

## 根因分析
部分 autotools 软件（nagios 为典型）的 configure.ac 里定义了自己的 --with-temp-dir 选项处理同名 shell 变量 TMPDIR，未传该参数时无条件设 TMPDIR="/tmp"，覆盖了从环境继承的可写 TMPDIR；后续所有 conftest/config.status 的临时文件都落到只读 /tmp（E002 场景）。

## 推荐方案
**方法**: set-env-var

**说明**: 传 --with-temp-dir=$TMPDIR 显式覆盖 configure 内部 TMPDIR 变量；若软件无该选项但也在脚本内写死 TMPDIR=/tmp，需打补丁改默认值。注意边界：--with-temp-dir 解决的是「configure 内部 TMPDIR 变量遮蔽环境变量」问题（写死 /tmp 只读，E002）；不要扩大为修改 config.guess 的 umask——config.guess 的临时目录走 $TMPDIR/cgXXXXXX 绝对路径（用户属主可写目录，0700 无访问问题），其 umask 077 是上游安全底线（防 TOCTOU），无需也不应改动。真正需要 umask 处理的是 config.status 的相对路径 ./confXXXXXX（HMDFS setgid 构建目录属主≠构建 uid 时 077 产生 drwx--S--- 不可访问，E012/E136）——该处用 conanfile 运行时注入 umask 022（保留属主私有语义又不失 HMDFS 可写性），不进补丁。

**修复命令**:
```
./configure --with-temp-dir=$TMPDIR ...
```
