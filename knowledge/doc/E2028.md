# E2028: shim-redirect

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, linking, conan
- **作者**: unknown
- **来源 PR**: nagios 4.5.14

## 错误特征
```
checking for SSL libraries\.\.\. configure: error: Cannot find ssl libraries|ld\.lld: error: unable to find library -lssl
```

## 根因分析
autotools 软件（nagios/nrpe/其它 with-ssl 探测式 configure）的 SSL 检测分两步：(1) 头文件探测——--with-ssl-inc 指向 conan openssl 的 include 目录时，若命中 "$dir/include/openssl/ssl.h" 分支，CFLAGS 会加 "-I$dir/include/openssl"，而 conftest 的 #include <openssl/ssl.h> 在该前缀下找不到（双层 openssl 拼接）；(2) 库探测——configure 只认 libssl.$soext（.so），conan 的 openssl 包是静态库（libssl.a/libcrypto.a）。

## 推荐方案
**方法**: shim-redirect

**说明**: 构造 SSL shim 目录：(a) shim/include/ssl.h 内容为一行 "#include <openssl/ssl.h>" 转发 + shim/include/openssl 软链接到 conan openssl 真实头目录——configure 探测 "$dir/include/ssl.h" 命中 SSL_INC_PREFIX="" 分支，CFLAGS 加 "-I shim/include"，conftest 的 #include <ssl.h> 经转发头与同前缀的 openssl/ 软链都能解析；(b) shim/lib/ 下做 libssl.so→libssl.a、libcrypto.so→libcrypto.a 符号链接——configure 的 soext 探测通过，链接行保持 -lssl -lcrypto 实际解析到静态库，最终二进制静态自包含。configure 参数：--with-ssl=<shim> --with-ssl-inc=<shim>/include --with-ssl-lib=<shim>/lib。

**修复命令**:
```
mkdir -p shim/include shim/lib && printf '#include <openssl/ssl.h>\n' > shim/include/ssl.h && ln -s $OPENSSL_DIR/include/openssl shim/include/openssl && ln -sf $OPENSSL_DIR/lib/libssl.a shim/lib/libssl.so && ln -sf $OPENSSL_DIR/lib/libcrypto.a shim/lib/libcrypto.so
```
