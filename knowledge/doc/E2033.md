# E2033: GCC snapshot 在 HarmonyOS 上需要拆分 source 阶段、本地 tarball 回退与生成器前置

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, autotools, toolchain, bundled-prerequisites
- **作者**: pc1-47-executor

## 错误特征
```
self.settings access in source() method is forbidden|settings.os.version value not defined|GCC_SNAPSHOT_SOURCE_TARBALL|gengtype-lex.cc|move-if-change|get_patches.sh|unknown option code|posix_spawn: Permission denied|posix_spawnp: Permission denied|collect-ld|real-ld|mkheader.sh|OHOS SDK sysroot headers were not found|native/llvm/ohos-sdk.org|conan create TIMED OUT after 3600s|Downloaded 88.7MB|7676387 pass(es)|build_jobs() returned 1|all-target-libgcc
```

## 根因分析
GCC snapshot 是自举型工具链包，不只是一个普通库。它依赖 bundled GMP/MPFR/MPC，还需要 flex 在 generator 阶段生成 gengtype-lex.cc；同时 Conan 的 source() 不能读取 self.settings，OHOS 分支逻辑必须放到 settings 无关路径。HarmonyOS/HMDFS 下又会叠加脚本直 exec、只读 /tmp、工作目录恢复和权限位差异，所以必须把 source 解包、本地 tarball 回退、short-lived prepare 进程、shell 包装入口和显式 TMPDIR/SHELL/CONFIG_SHELL 一起处理，才能把 fresh build 跑完整。

## 推荐方案
**方法**: source-range-cache-plus-generator-toolreq

**说明**: 在 source() 中优先消费 CI file:// 缓存或本地 tarball，远程大包使用有序镜像、并行 Range、有限重试和最终 SHA256；保留 bundled GMP/MPFR/MPC 解包；将 flex 作为 tool_requires 单独适配；对 OHOS 构建显式设置 TMPDIR、CONFIG_SHELL、SHELL，并用有上限的 pipe jobserver；C/static-libgcc 产品关闭 decimal-float，并对 target libgcc 去掉继承的 debug flags。

**修复命令**:
```
config_options(): self.settings.rm_safe("os.version"); source(): if GCC_SNAPSHOT_SOURCE_TARBALL exists, extract it, otherwise consume file:// cache or bounded Range URLs; build_requirements(): self.tool_requires("flex/2.6.4"); generate(): default compiler executables to /data/service/hnp/bin/clang and /data/service/hnp/bin/clang++, then inject flex/bin plus FLEX/LEX; build(): export TMPDIR/CONFIG_SHELL/SHELL and invoke configure/make through shell wrappers with OHOS -j4 pipe jobserver, --disable-decimal-float, and target CFLAGS_FOR_TARGET/CXXFLAGS_FOR_TARGET=-O2 -fPIC while retaining the lower generic cap for non-OHOS
```

**验证**:
```
在 OHOS 设备上执行 `GCC_SNAPSHOT_SOURCE_TARBALL=<local_tar.xz> conan create archives/g/gcc-snapshot/20260705 -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64 --build=missing`，应先完成 source 解包并继续进入 build/package；若缺少 flex 或 shell 包装，通常会在 gengtype-lex.cc、move-if-change、get_patches.sh 或 mkheader.sh 附近失败；目标编译阶段应确认 `-B/data/service/hnp/bin/` 位于构建树 `-B` 之前，并检查 `collect2 -debug` 解析到的 `collect-ld` 是真实 signed ELF。
```
