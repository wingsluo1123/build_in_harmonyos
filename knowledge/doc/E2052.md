# E2052: djb/spac packages fail cross compilation when Makefile rules run build-time generators as target binaries - solve with a two-stage build (native bootstrap generator run, then full target-toolchain build)

## 基本信息
- **严重度**: 2
- **类别**: cross-compile, compile-two-stage
- **作者**: unknown

## 错误特征
```
cannot execute binary file: exec format error|crc-gentab|attempted to run the target compiler on the build machine|Generated source is out of date
```

## 根因分析
djb/spac-style trees (bglibs and the untroubled.org family) drive compilation through generated wrapper scripts (conf-cc/conf-ld baked into compile/ltcompile/load/makeshlib) and Makefile rules that EXECUTE build-time generators, e.g. bglibs `crc/*_table.c: crc-gentab`. Under OHOS cross compilation the generator is built for the TARGET (aarch64) and cannot run on an x86 worker (exec format error), or conversely a build-machine compiler leaks into target objects if conf-* keep a host cc. A naive `make` therefore fails or silently produces host-architecture artifacts; choose(1) runtime probes also degenerate under cross and must fall back to both-branches-compilable candidates.

## 推荐方案
**方法**: native-bootstrap-generator-then-target-build

**说明**: Two-stage pattern. Stage 1 (bootstrap): detect a machine-resident compiler by standard name (gcc/clang/cc via PATH probe script; never bare env CC per R33), run `make crc-gentab`-style generator targets only, execute the generator to emit the generated sources (CRC tables). Stage 2 (target): overwrite conf-cc/conf-ld (first line = target compiler from the Conan profile) so the spac wrapper scripts bake the cross toolchain, `make sysdeps.h libraries` with generator prerequisites now satisfied; keep all staging paths private to build_folder (R49/E524). Drive libtool via tool_requires (CI ships none). For choose(1) runtime probes rely on the choose contract that both branches must compile and pick at runtime via sysdeps.h. Never mark generator outputs as stale again (touch) and never run target ELFs on the build machine.

**修复命令**:
```
apply the two-stage recipe flow and rebuild with conan create archives/b/bglibs/2.04 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
conan create archives/b/bglibs/2.04 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
