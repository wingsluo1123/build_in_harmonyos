# E2055: OHOS Conan 包对自生成运行时 image 的原生构建、路径重定位与测试闭环

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, testing, relocatable, generated-runtime-image
- **作者**: codex

## 错误特征
```
source/target file does not exist|Failed to apply patch|cannot open image|strdup.*undeclared|zl.*version.*help.*failed
```

## 根因分析
部分解释器、编译器或自举工具的上游 Makefile 不止编译目标程序，还会立即运行该程序生成默认 image、字节码或后续构建输入。上游默认路径通常面向 /usr/local 或源码树，与 Conan package_folder 不同；OHOS 还要求新链接的 ELF 在首次执行前完成签名，并可能通过 feature-test macro 才暴露 strdup 等 POSIX/GNU 声明。只做交叉编译、硬编码构建路径或只执行消费者 marker 都无法证明安装后工具可用。

## 推荐方案
**方法**: native-build-sign-generate-relocate-and-test

**说明**: 在 build() 中按“应用最小补丁 -> 编译目标解释器 -> OHOS binary-sign-tool 签名 -> 运行目标解释器生成 image -> 在同一构建目录执行完整上游回归”的顺序完成构建；用 ZENLISP_IMAGE 覆盖编译期默认 image 路径，并由 package_info() 导出 ZENSRC 运行时库目录。test_package 必须执行安装后的二进制、加载包内资源并验证代表性业务行为。若目标环境复现 Conan patch 应用器错误，可通过配置 shell 显式调用设备 patch -p1，但仍须保留补丁文件、L4 检查和与实际应用语义一致的验证。

**修复命令**:
```
compile native interpreter; sign ELF; generate image; run upstream test.l/test.OK; run installed test_package
```

**验证**:
```
conan create archives/z/zenlisp/2013.11.22 --build=missing
```
