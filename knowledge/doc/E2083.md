# E2083: 闭源平台框架承载 CLI 工具的全部核心语义（LaunchServices/Apple Events/CoreFoundation），目标平台无等价运行时，无可拆分的可移植子集 → 平台阻塞而非配方问题

## 基本信息
- **严重度**: 3
- **类别**: platform, limitation, portability, headers
- **作者**: LAUNCH

## 错误特征
```
fatal error: 'sys/attr\.h' file not found|fatal error: '[^']*\.framework/Headers[^']*' file not found
```

## 根因分析
工具的核心功能不是建立在 POSIX 可移植层之上，而是整体构建于闭源平台框架（launch 的全部动词 launch/list/quit/finder/trash/cdev 等，通过 LaunchServices 的 LSOpenItemsWithRole/LSOpenURLsWithRole、Apple Events 的 AESendMessage/AEBuildAppleEvent、CoreFoundation 的 CFString/CFURL/CFBundle/CFRunLoop 以及 Mach 调用 getattrlist 组合实现）；框架未提供源码、未提供目标平台 SDK，目标平台（OHOS）的 sysroot 不含这些框架的头文件与库；因而这些调用点没有可替换的开源实现，也不存在“可移植子集”——删掉任何一个调用点都等价于删除对应功能动词，工具退化为空壳

## 推荐方案
**方法**: honest-block

**说明**: 承认平台阻塞：核心语义由闭源框架承载，不存在可移植子集。不得通过空 stub、假实现、删除核心功能或跳过验证宣称适配成功；以源码级证据（调用点行号、sysroot 检查、交叉编译首错）登记 blocked，为未来平台能力变化保留重评估入口

**修复命令**:
```
echo "launch 1.2.5: blocked (closed LaunchServices/AppleEvents/CoreFoundation frameworks, no portable subset)"
```

**验证**:
```
tar -xzf launch-{version}.tar.gz && cd launch-{version} && clang -c -target aarch64-linux-ohos main.m -o /dev/null 2>&1 | head -3  # 未移植时首错 fatal error: 'sys/attr.h' file not found；补 sys/attr.h 后依次出现 CoreFoundation/CarbonCore 等框架头缺失，证明非单点缺失而是全链路框架缺失
```
