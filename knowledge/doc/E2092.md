## 推荐方案
**方法**: canonical-platform-name-ohos

**说明**: 在配方 generate() 中把 CMAKE_SYSTEM_NAME 显式设为平台真名 "OHOS"（而不是让它停在 Conan 默认的 HarmonyOS、也不是伪装成 Linux）。SDK/cmake 随带 Modules/Platform/OHOS.cmake，其内容为 include(Platform/Linux)，因此 UNIX、SONAME flag、Threads 查找等 POSIX 语义全部就位：守卫分支被编译、共享库带真实 DT_SONAME、version script 覆盖完整 API，且 CMake 不再打印 "System is unknown to cmake"（CMAKE_DL_LIBS 本就有 Platform/GNU.cmake 兜底，不属于本修复补齐的项）。平台身份真实，不引入 Linux 专有逻辑（systemd/dbus/X11 等由具体工程自行判断，不由系统名强行引入）。诊断期必须逐个读守卫块，避免把不在 UNIX 块内的东西（如 libvpl 的 version script 与 ${CMAKE_DL_LIBS} 链接）算作被跳过。

**修复命令**:
```
conanfile.py generate(): tc.variables["CMAKE_SYSTEM_NAME"] = "OHOS"; 重新 conan create 后核对 nm -D --defined-only <pkg>/lib/*.so | grep -c ' T ' 与 llvm-readelf -d <pkg>/lib/*.so.* | grep -E 'SONAME'
```
