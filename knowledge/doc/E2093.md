# E2093: EA 系编译型库头文件依赖的传递 include 下发（cpp_info.requires + test_package 显式 find_package）与 debug operator new 消费者契约

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, conan, dependency, packaging
- **作者**: unknown

## 错误特征
```
fatal error: 'EABase/eabase.h' file not found|include could not find requested file|target_link_libraries.*bare.*target|No compatible configuration found
```

## 根因分析
EA 系列库（EABase/EAAssert/EASTL/EAStdC 等）的公开头文件相互 include（eaassert.h → "EABase/eabase.h"）。上游 CMakeLists 用裸目标名（target_link_libraries(EAAssert EABase)）假设依赖以 add_subdirectory 内嵌源码树；干净 Conan 构建无该目标，且 header-only 依赖（eabase）经 CMakeDeps 生成的 INCLUDE_DIRS 为空，导致依赖 include 目录不传播到消费者编译行，消费者/库本体编译报 'EABase/eabase.h' file not found。另有上游 CMakeLists include() 子模块内 .cmake 模块（CommonCppFlags 位于 test/packages/EASTL/scripts/CMake）因子模块缺失而失败的连带问题。

## 推荐方案
**方法**: 三层修复组合：

**说明**: ① 在 recipe package_info() 中显式设置 self.cpp_info.requires =

**修复命令**:
```
sed/手工修改 conanfile.py：self.cpp_info.requires = ["eabase::eabase"]；
```

**验证**:
```
修复前：conan create . -pr:h=ci/conan/profiles/ohos-aarch64
```
