# E2103: BSD kqueue 原生工具在 OHOS 移植：以 inotify 忠实重写事件源（映射表 + 三大陷阱）

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, event-notification, inotify, kqueue
- **作者**: unknown

## 错误特征
```
sys/event\.h: No such file or directory|
```

## 根因分析
kqueue 是 BSD 私有内核事件机制，OHOS 内核（HongMeng）从未实现该 syscall；musl libc 相应不提供 sys/event.h 与 kqueue/kevent 符号。这是平台 API 家族缺失，不是构建检测问题（无法靠 -I/-l 修复），也不是可 shim 的用户态库缺口（libkqueue 与 epoll-shim 在 OHOS 均有行为性失败记录）。但 kqueue 的 EVFILT_VNODE 子集语义（文件/目录变化边沿通知）与 inotify 的能力正交重叠，可构造一一映射。

## 推荐方案
**方法**: Rewrite the kqueue event source as inotify with the EVFILT_VNODE mapping table (NOTE_WRITE→IN_MODIFY|IN_CREATE|IN_DELETE|IN_MOVED_*, NOTE_DELETE→IN_DELETE_SELF, NOTE_RENAME→IN_MOVE_SELF|IN_MOVED_*), keeping CLI/stdout/exit codes byte-identical; upstream assertions ported 1:1 and executed in build()

**说明**: Faithful inotify rewrite of kqueue EVFILT_VNODE waiters on OHOS (libkqueue/epoll-shim routes are proven failures — see E399)

**修复命令**:
```
conan create archives/k/kqwait/1.0.3 -pr:h ~/.conan2/profiles/ohos-aarch64-local -pr:b ~/.conan2/profiles/ohos-aarch64-local --build=kqwait/*
```
