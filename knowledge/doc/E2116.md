# E2116: JIT/汇编器类 header-only 库的纯编码断言消费者验证

## 基本信息
- **严重度**: 2
- **类别**: ohos, headers, consumer-testing, encoding-assertion, jit-assembler
- **作者**: codex

## 错误特征
```
JIT.*executable memory.*unavailable|Catch2.*(not found|No such file)|instruction encoding.*assertion.*failed|mmap.*RWX.*(denied|Operation not permitted)
```

## 根因分析
AArch64 汇编器/代码发射器类 header-only 库（oaknut、asmjit 等）的上游测试几乎全部依赖执行生成的机器码（mmap RWX 可执行内存，受 OHOS W^X 策略 E045 影响），并依赖测试框架（Catch2 3 等）可能未发布到制品仓。消费者测试若照搬上游方式，会因 JIT 不可执行或框架缺失而无法运行；需要一种不执行 JIT、不依赖测试框架、跨架构可移植的验证方式。

## 推荐方案
**方法**: pure-encoding-assertion

**说明**: 用汇编器的非执行模式（CodeGenerator 写入单个 uint32_t / VectorCodeGenerator 发射到 std::vector）生成指令，断言机器码与已知编码向量一致。编码向量优先取自上游测试的 T() 宏向量（如 tests/general.cpp、tests/basic.cpp）与源码 emit<"..." 模板，而非 README 示例——README 可能把 32 位与 64 位编码写混（实测 oaknut README 写 MOV(W0,42)=0xd2800540，实为 64 位 MOVZ X0；正确 32 位 MOVZ W0 是 0x52800540）。断言为确定性位运算，不 mmap 执行、不依赖 Catch2，可在任意架构编译运行。

**修复命令**:
```
emit instructions into buffer/vector -> assert machine code equals known vectors from upstream tests and emit templates
```

**验证**:
```
CI_PACKAGES="archives/o/oaknut/1.2.2-git20240301.94c726c" zsh ci/conan/build_and_test.sh
```
