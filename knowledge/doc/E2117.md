# E2117: resupply-full-cflags-with-quoted-version-define

## 基本信息
- **严重度**: 2
- **类别**: build-system, make, conan
- **作者**: unknown

## 错误特征
```
use of undeclared identifier 'VERSION' (define missing entirely) | invalid suffix '[0-9.]+' on floating constant (define re-supplied but quoting stripped by shell layers)
```

## 根因分析
Plain-Makefile projects carry per-project flags in an append (e.g. CFLAGS += -Wall -Wextra -DVERSION='"$(VERSION)"' -O2 -g); a recipe that builds with an explicit command-line assignment (make CFLAGS=...) silently DEACTIVATES every += append because GNU make gives command-line variables highest priority and a makefile += on a command-line variable is ignored (unlike an environment variable where += still appends), so upstream defines are lost with two compile-time faces both reproduced on smemstat 0.02.13 (clang 15 / OHOS aarch64): (a) define missing entirely -> "use of undeclared identifier 'VERSION'"; (b) define re-supplied but quoting stripped by one of the two shell layers (invocation shell, then make recipe expansion) so the bare token reaches the compiler -> "invalid suffix '.13' on floating constant".

## 推荐方案
**方法**: resupply-full-cflags-with-quoted-version-define

**说明**: Supply the COMPLETE flag set on the make command line (document in the recipe that the Makefile's += appends are inactive) and re-add upstream defines in the upstream quoting form so double quotes survive both shell expansions to the compiler: the CFLAGS value must literally contain -DVERSION='"X.Y.Z"' (single quotes eaten by the invocation shell, double quotes eaten by the recipe shell, leaving a C string literal). Build the assignment with shlex.quote() so shell metacharacters in include/lib paths cannot split the argument. Passing CFLAGS via the environment instead would preserve += appends, but the explicit command-line form is deterministic and keeps R33 compliance (no reliance on ambient shell variables).
