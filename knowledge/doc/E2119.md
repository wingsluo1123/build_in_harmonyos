# E2119: OHOS musl 的 catgets() 不校验描述符有效性，catopen() 失败返回的 (nl_catd)-1 哨兵被直接解引用 → 每次调用必 SIGSEGV；glibc 对无效描述符容错返回 fallback 字符串，故 glibc 交叉编译/开发机上永不触发

## 基本信息
- **严重度**: 3
- **类别**: portability, musl, syscall, runtime, locale
- **作者**: LOUT

## 错误特征
```
segmentation fault|SIGSEGV (core dumped)|signal 11|rc=-11|crashed with signal 11
```

## 根因分析
POSIX 规定 catopen() 失败返回 (nl_catd)-1（哨兵值，非 NULL）。程序常见防御写法只判 NULL（if (cat) catgets(...)），把 -1 当有效描述符传给 catgets()。glibc 的 catgets() 对无效描述符防御性容错（返回 fallback 字符串），musl（OHOS libc）直接按指针解引用 → 落到 0xFFFFFFFFFFFFFFFF 非映射页 → SIGSEGV。凡「glibc 上正常、OHOS 上一运行就段错误」且进程用到 nl_types（message catalog）即命中本模式

## 推荐方案
**方法**: guard-sentinel-in-macro

**说明**: 在 catgets() 调用处（或其包装宏）同时排除 NULL 与 (nl_catd)-1 两个无效值：(cat) != (nl_catd)0 && (cat) != (nl_catd)-1 ? catgets(cat, set, msg, s) : s。不关闭 locale 功能、不改 catopen 调用、不砍本地化路径——只按 POSIX 哨兵语义补防御检查。lout 3.43.4 实测：补丁 4 行后，-r3 全量用户手册 PS 后端和 -p -r1 全量 plain 后端均正常完成；plain 的 -r2+ 截断为上游既有行为

**修复命令**:
```
patch -p1 < patches/0001-guard-catgets-against-invalid-nl_catd-sentinel.patch
```

**验证**:
```
帧指针回溯定位崩溃帧是否落在 catgets() 调用点；确认 catopen() 调用返回值未被检查；在 OHOS 目标机 strace 下看进程是否在崩溃前 openat() locale catalog 失败（ENOENT）后继续运行
```
