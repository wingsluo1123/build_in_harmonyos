# E2124: CMakeDeps 多包同名 cmake_file_name 互覆盖致 DEPS_TARGET 断链

## 基本信息
- **严重度**: 2
- **类别**: packaging
- **作者**: unknown

## 错误特征
```
"CMake Error at .../X-Target-release.cmake: The link interface of target \"X_DEPS_TARGET\" contains: <pkg>::<pkg> but the target was not found."
```

## 根因分析
制品仓中多个包共享同一 cmake_file_name（如 boost/1.84.0 的 "Boost" 与 boost1.84-thread 的 "Boost"）。CMakeDeps 为每个 conan 包生成同名 <file_name>-Target-release.cmake，后处理的包覆盖先处理的——boost/1.84.0 的全部组件 target（Boost::headers/filesystem）从生成文件中消失，只剩 boost1.84-thread 的 Boost::thread。下游包 package_info 若用包级 cpp_info.libs（无 components），CMakeDeps 会为直接依赖生成默认包级 target 名（boost::boost），该 target 在任何生成文件中都不存在 → test_package 的 cmake configure 在 Generating 阶段失败。

## 推荐方案
**方法**: 两步修复：① 下游配方 package_info() 改用 components 定义（comp.libs + comp.requires 引用各依赖包的组件名，如 "boost::boost_headers"），CMakeDeps 走组件链展开，不再生成包级默认名；注意 conan 要求所有直接 requires 必须出现在某个组件的 requires 里（完整性检查），否则 package_info() 报 "The direct dependency 'boost' is not used by any (cpp_info/components).requires"。② 若依赖组件的 target 仍被覆盖（Boost::headers 不在生成文件中），在 test_package 的 CMakeLists.txt 里 find_package 之前为缺失 target 提供 INTERFACE IMPORTED 占位（add_library(Boost::headers INTERFACE IMPORTED)）——空接口合法，consumer 无需真实使用它。
