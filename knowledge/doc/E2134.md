# E2134: automake 并行测试脚本带 #!/bin/bash shebang 时在无 /bin/bash 的 HarmonyOS 上 30 个测试全部 exit 126，用 LOG_COMPILER/TEST_LOG_COMPILER=/bin/sh 兜底

## 基本信息
- **严重度**: 2
- **类别**: test-harness-interpreter
- **作者**: unknown

## 错误特征
```
test-driver.*No such file or directory|exit status: 126|# FAIL: 30|# PASS:  0
```

## 根因分析
automake 并行测试框架（test-driver）对 TESTS 注册的 shell 脚本是"直接 exec"：execvp 只看脚本的 shebang，不经过 LOG 之外的任何解释器。HarmonyOS 的 /bin 下只有 /bin/sh（mksh），没有 /bin/bash；凡是脚本首行为 #!/bin/bash 的测试，exec 返回 ENOENT，test-driver 报 "<script>: No such file or directory"、退出码 126（不是 127，也不是脚本自身的 exit 1），表现为全部 N 个测试同因失败、PASS=0——即使脚本内容全是 POSIX 构造（export/test/grep/exit）也会被误判为"测试全挂"。与之区分：脚本真正执行后失败是 exit 1 并带脚本自己的输出；段错误是 "Signal 11 (core dumped)"。

## 推荐方案
**方法**: automake-log-compiler-sh-fallback

**说明**: 在定义 TESTS 的 Makefile.am 头部加两行 `LOG_COMPILER = /bin/sh` 与 `TEST_LOG_COMPILER = /bin/sh`，随 autoreconf 进入生成的 Makefile 的 $(LOG_COMPILE)/$(TEST_LOG_COMPILE)，test-driver 会改以 /bin/sh 解释脚本，shebang 被绕开。只对"脚本内容实为 POSIX shell"的项目安全（本例 30 个脚本只用 export/test/grep/exit）；若脚本确实使用 bash 特性（数组、[[、process substitution），仍可先用 /bin/sh 暴露真实差异再逐个评估。补丁同时用 automake 原生 XFAIL_TESTS 声明确知失败的上游用例（本例 som_test 上游自身段错误），使 make check 退出码归零而账本透明呈现 XFAIL:1。选择该方案而非逐个改 30 个脚本的 shebang：一处声明 vs 30 文件 diff，且不碰上游测试语义。

**修复命令**:
```
make check -j1（应用补丁后 PASS 29 / XFAIL 1 / FAIL 0，对照修复前 # PASS: 0 / # FAIL: 30 / exit 126）
```

**验证**:
```
conan create archives/l/libgctp/2.0.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
