# E2138: plutovg 渲染位图表面在 little-endian 平台为 BGRA 字节序；断言渲染像素须按 byte[0]=B,byte[1]=G,byte[2]=R,byte[3]=A 映射，勿按 RGBA

## 基本信息
- **严重度**: 2
- **类别**: platform, cmake, runtime, testing, graphics
- **作者**: unknown

## 错误特征
```
FAIL: center pixel rgba=\(0,0,255,255\)|FAIL: .*rgba=\(0,0,255,255\), expected \(255,0,0,255\)
```

## 根因分析
plutovg_surface 的像素数据在 little-endian 平台上按 premultiplied BGRA 存储（byte[0]=蓝, byte[1]=绿, byte[2]=红, byte[3]=Alpha）。渲染一个 fill="#ff0000" 的矩形后逐字节读取 Bitmap::data() 会得到 (0,0,255,255)：若按 RGBA 顺序解读会误判为蓝色，实际渲染正确。lunasvg 的 Bitmap::data()/stride() 直接透传 plutovg_surface 数据，无通道转换。注意 Bitmap::clear(uint32_t) 接受的是 ARGB 整数，与 data() 的字节序不同，两种 API 的通道语义需分别对待。

## 推荐方案
**方法**: bgra-byte-mapping-for-render-assertion

**说明**: 断言 plutovg 渲染结果时按 BGRA 映射读取：r=data[i+2], g=data[i+1], b=data[i+0], a=data[i+3]（i= y*stride + x*4）。在注释中明确字节序，避免后续按 RGBA 误读。

**修复命令**:
```
python3 $SKILL_ROOT/scripts/ohc-run.py conan-verify <name> <ver>
```

**验证**:
```
conan create 的 test_package 消费者测试与鸿蒙专项测试：渲染 #ff0000 矩形后断言 data()[offset+2]==0xff、data()[offset+3]==0xff，1/1 + 3/3 全部 PASS；按 RGBA 写则 FAIL
```
