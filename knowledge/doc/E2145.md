# E2145: vendored Catch 1.x有符号URNG与新版libc++ uniform_int_distribution静态断言冲突的幂等兼容修复

## 基本信息
- **严重度**: 3
- **类别**: compat, ohos, libc, headers, build-system
- **作者**: hmbs-executor
- **来源 PR**: 10298

## 错误特征
```
__libcpp_random_is_valid_urng<Catch::RandomNumberGenerator>|uniform_int_distribution\.h.*static_assert|shuffle\.h.*uniform_int_distribution
```

## 根因分析
Catch 1.9.6 RandomNumberGenerator声明typedef std::ptrdiff_t result_type为有符号类型，新版OHOS LLVM libc++强制要求URNG result_type为无符号整数，std::shuffle内部uniform_int_distribution<long>对其做__libcpp_random_is_valid_urng有效性静态断言导致上游测试编译拦截

## 推荐方案
**方法**: idempotent-test-framework-urng-compat-patch

**说明**: 编译前对vendored catch.hpp做幂等兼容修复，将RandomNumberGenerator::result_type由有符号std::ptrdiff_t改为unsigned int，仅动测试框架头不动测试逻辑与断言

**修复命令**:
```
conanfile.py: 导入replace_in_file，在_run_upstream_tests编译前替换typedef std::ptrdiff_t result_type为typedef unsigned int result_type
```

**验证**:
```
真机preflight build()上游测试编译通过且HMBS门禁全部通过，原v2:compile:test_assertion_failed消失
```
