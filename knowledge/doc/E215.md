# E215: 配置工具(--cflags)指向已删除 staging 目录，导致头文件发现失败

## 基本信息
- **严重度**: 2
- **类别**: tool-compat|config-tool|staging
- **触发工具**: configure|clang|conan
- **阶段**: configuration

## 错误特征
```
configure:6448: checking ncursesw/ncurses.h usability
configure:6448: /data/service/hnp/bin/aarch64-unknown-linux-ohos-clang -c -fPIC -O2 -O3 ... -I$HOME/tmp/test-install-ncurses-6.4/include conftest.c >&5
conftest.c:98:10: fatal error: 'ncursesw/ncurses.h' file not found
#include <ncursesw/ncurses.h>
         ^~~~~~~~~~~~~~~~~~~~
1 error generated.
```

**关键词**: ncursesw6-config, --cflags, --includedir, 死路径, staging, test-install, file not found, header not found, config tool, include path

## 触发条件
- 构建系统: autotools（Conan 配方经 AutotoolsToolchain 调 configure）
- 阶段: configuration（头文件存在性检查 AC_CHECK_HEADERS）
- 前置: 配方通过 *-config 工具（ncursesw6-config）获取 include/lib 路径，且该工具生成时前缀与安装前缀分离

## 根因分析

编译配置文件工具（如 `ncursesw6-config`）在构建时生成，其 `--cflags`/`--includedir`/`--prefix` 指向当时的 staging 前缀（如 `$HOME/tmp/test-install-ncurses-6.4`）。staging 目录在测试后被清理，config 工具保留死路径；而 `--libs` 往往仍指向有效安装目录（如 `$HOME/usr/local/lib`）。

典型不一致（gnu-typist 2.10.1 实测）：

| 输出 | 路径 | 状态 |
|------|------|------|
| `--cflags` | `-I$HOME/tmp/test-install-ncurses-6.4/include` | ❌ 目录已删除 |
| `--libs` | `-L$HOME/usr/local/lib -lncursesw` | ✅ 有效 |
| 真实头文件 | `$HOME/usr/local/include/ncursesw/ncurses.h` | ✅ 存在 |

**核心认知：配置工具存在（which 命中）≠ 其返回路径可用，必须验证返回路径实际存在。** 头文件与库本身是同一套 ncurses 6.4 构建（版本宏 6.4.20221231、WIDECHAR=1、libncursesw.a 含 add_wch 宽字符符号），坏掉的只是 config 工具的 `-I` 路径。

**影响范围**: 所有通过 *-config 工具获取 include/lib 路径的 Autotools 配方；staging 与最终安装前缀分离的 OHOS 本地构建。

## 验证
```bash
ncursesw6-config --cflags          # -DNCURSES_WIDECHAR -I$HOME/tmp/test-install-ncurses-6.4/include（死路径）
ls -d $(ncursesw6-config --cflags | sed 's/.*-I//')   # No such file or directory
ncursesw6-config --libs            # -L$HOME/usr/local/lib -lncursesw（有效）
grep -E 'define NCURSES_VERSION' $HOME/usr/local/include/ncursesw/ncurses.h  # 6.4.20221231
```

## 解决方案

### 推荐方案
校验配置工具输出的路径存在性，不盲信原始输出：
1. 逐 token 解析 `--cflags`，过滤不存在的 `-I<dir>`（保留 `-D` 宏定义）；
2. 若过滤后无有效 `-I`，从有效 `--libs` 的 `-L<libdir>` 推导同级 `<libdir>/../include`；
3. 校验推导目录中真实头文件（如 `ncursesw/ncurses.h`）存在后再作为 `-I` 使用；
4. 头与库必须来自同一安装树（同版本、同构建），保持一致性。

Conan 配方实现（gnu-typist 2.10.1，`generate()` 内）：
```python
_ncurses_keep = []
for _tok in _ncurses_cflags.split():
    if _tok.startswith("-I") and not os.path.isdir(_tok[2:]):
        continue
    _ncurses_keep.append(_tok)
if not any(_t.startswith("-I") for _t in _ncurses_keep):
    for _tok in _ncurses_libs.split():
        if _tok.startswith("-L"):
            _inc = os.path.normpath(os.path.join(_tok[2:], "..", "include"))
            if os.path.isfile(os.path.join(_inc, "ncursesw", "ncurses.h")):
                _ncurses_keep.append("-I" + _inc)
            break
```

### 禁止做法
- ❌ 硬编码已删除的临时目录路径（`-I.../tmp/test-install-*`）—— 不可复现，其他环境必失败
- ❌ 复制系统头文件、伪造 header 或 `ln -s` 绕过头文件检查 —— 违反配方自包含与可复现原则
