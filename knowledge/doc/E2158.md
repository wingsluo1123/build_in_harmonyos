# E2158: CTest add_test 硬编码 TEST_PATH 路径在多配置/自定义输出目录下失效，改用 $<TARGET_FILE:${target}> 生成器表达式

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, testing, ctest, openharmony
- **作者**: unknown

## 错误特征
```
add_test\(\$\{exec\} \$\{TEST_PATH\}|TEST_PATH/\$\{exec\}|add_test.*TEST_PATH|No such file.*test.*executable|test executable.*not found.*ctest
```

## 根因分析
上游 CMake 用 add_test(${exec} ${TEST_PATH}/${exec}) 注册 CTest，把测试可执行文件路径硬编码为 ${TEST_PATH}/${exec}；该路径依赖构建目录布局（如 RUNTIME_OUTPUT_DIRECTORY 被改写、multi-config 生成器附加 Debug/Release 子目录、Conan 交叉构建下输出目录变化）时，ctest 运行时找不到测试二进制，表现为测试丢失/No such file。CMake 提供 $<TARGET_FILE:${target}> 生成器表达式，在生成期解析目标实际产物路径，天然规避目录布局差异。

## 推荐方案
**方法**: generator-expression-target-file-for-add-test

**说明**: (待补充)

**修复命令**:
```
将 add_test(${exec} ${TEST_PATH}/${exec}) 改为 add_test(NAME ${exec} COMMAND $<TARGET_FILE:${target}>)，其中 ${target} 为对应测试可执行文件目标名；若目标由函数/宏内联创建（如 UnitTests.cmake 的 add_unit_test），在函数内已有 ${target} 变量直接引用即可，无需硬编码目录。
```

**验证**:
```
1) grep -n 'add_test' 上游 CMakeLists/UnitTests.cmake 确认硬编码路径；2) 补丁后 ctest 输出 'Passed' 且测试总数与 add_test 注册数一致（如 blitz 57/57）；3) 故意改写 RUNTIME_OUTPUT_DIRECTORY 后 ctest 仍能找到测试二进制
```
