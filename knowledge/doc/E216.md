# E216: finish Step 8 submit 预检三项产物无安全正式生成入口（框架能力缺口）

## 基本信息
- **严重度**: 2
- **类别**: framework-capability-gap|finish|submit
- **触发工具**: finish|ohc-run|submit
- **阶段**: testing|packaging

## 错误特征
```
Step 8/8: submit 就绪预检...
  ❌ test-report.md — 需创建 reports/test-report.md
  ❌ packaging/ — 需创建 packaging/ 目录并打包
  ❌ .staging-verified — 需创建 .staging-verified 空文件
  ✅ build-closed marker
  ⚠️ 3 项未就绪，submit 前需修复
⚠️  编译收尾部分完成: gnu-typist 2.10.1 → built
⚠️    失败步骤: step5b, step8
```

**关键词**: finish, Step 8, submit 就绪预检, test-report.md, staging-verified, packaging, official_framework_capability_gap, 框架缺口, 无安全入口, conan-init 覆盖, 伪造产物

## 触发条件
- 工具: `ohc-run.py finish <name> <ver> built`
- 阶段: Step 8（submit 就绪预检）
- 前置: 配方已通过 conan create / test_package / conan-verify / W3，本地原子性已通过，准备提交 PR

## 根因分析

finish Step 8 只做**存在性检查**（`finish.py:348-380 step8_submit_readiness`），不生成任何产物。框架内三项产物的正式生成入口均不在安全路径上：

| 产物 | 唯一生成入口 | 问题 |
|------|-------------|------|
| `reports/test-report.md` | `ohc build` driver Step7 `_step7_check`（driver.py:967） | 同一管线 Step9 `conan_init(force=True)` 覆盖已验证配方 |
| `.staging-verified` | `ohc build` driver Step8 `_step8_staging`（driver.py:1032） | 同上 |
| `packaging/**` | `PackageBuilder`/`package_cli`（package_builder.py:318） | `package` 命令**未注册**进 `cli._MODULES`，`ohc-run.py package` → Unknown command |

关键代码事实：
- `driver.py:1082-1084`：Step9 无条件 `conan_init(self.software, self.version, force=True, ...)`；
- `driver.py:99`：`should_run(step) = step >= resume_from`，`--resume-from` 仅支持 Step3-Step9，**无法跳过 Step9**；
- `verify-build` 只写 `reports/quality-report.md`，`clean-verify`/`conan-verify`/`finish` 均不生成这三项。

**结论**：不存在不覆盖已验证配方的安全入口 → 分类 **`official_framework_capability_gap`**。Expect（R102/R103）与 gnu-typist（PR #2965）均曾记录同类问题。

**影响范围**: 已通过 conan create/conan-verify/W3 且配方已人工验证的库，在提交 PR 前跑 finish 的 Step 8 预检时全部命中该缺口。

## 验证
```bash
python3 ohc-run.py finish gnu-typist 2.10.1 built
# 观察 "3 项未就绪，submit 前需修复" + "失败步骤: step5b, step8"
python3 ohc-run.py package gnu-typist 2.10.1
# ❌ Unknown command: package（未注册）
```

## 解决方案

### 推荐方案
**不伪造 Step 8 产物。** 如实记录框架缺口：
1. finish 以 `built` 收尾（不宣称完整 finish 通过）；
2. 在 notes.md/知识条目中记录 `official_framework_capability_gap` 及恢复条件；
3. PR 正文明确"Step 8 因框架能力缺口未完成"；
4. 不创建/提交 `reports/test-report.md`、`packaging/**`、`.staging-verified`、`.build-closed` 或 `reports/**`。

**恢复条件**：框架提供不调用 conan_init 的产物生成入口（独立 staging-verify/package 命令），或 finish 对 v3.0 conan 配方豁免 Step 8 产物检查。

### 禁止做法
- ❌ 手动创建 `reports/test-report.md`、`touch .staging-verified`、伪造 `packaging/` —— 伪造预检产物=虚假 finish 状态，W4 审计/CI 校验失败
- ❌ 用 `--resume-from` 或修改 driver 跳过 Step9 conan-init —— 覆盖已验证配方/越权改框架
