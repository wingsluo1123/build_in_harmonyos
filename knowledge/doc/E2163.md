# E2163: OHOS distributed fs denies file-create inside mktemp 0700 dirs and O_APPEND opens for conan-task processes

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, ohos, portability, autotools, fs
- **作者**: codex

## 错误特征
```
>-
```

## 根因分析
On the /storage/Users distributed fs (hmmac=use_task), directories created by `mktemp -d` get mode 0700 with an ACL fixed at creation; on affected devices even the owning task cannot create files inside them, and `chmod 777` does not rebuild the ACL. Separately, opens with O_APPEND (`cat >> file`, `echo >> file`) are denied for the conan process tree on affected devices while the same operations succeed from an interactive SSH session. Autoconf 2.71 config.status hardcodes its temp dir in the cwd and assembles subs1.awk via `cat >>`, so every autotools configure fails at "could not setup config files machinery" on such devices.

## 推荐方案
**方法**: pre-created-fixed-tmpdir-plus-recipe-patch

**说明**: Pre-create the config.status temp dir with plain `mkdir -p` plus `chmod 777` (a plain-mkdir dir behaves correctly; a chmod-fixed mktemp dir does not), then patch configure/config.status to use it via ${TMPDIR:-.}/cs instead of mktemp. Sign any freshly built executable with binary-sign-tool before a make rule invokes it. For gettext references (g_libintl_gettext et al.) link a passthrough stub archive (E508). Retry only after the distributed fs client state has settled; deletion storms from concurrent cleanups poison the same subtrees.

**修复命令**:
```
mkdir -p "${TMPDIR:-.}/cs" && chmod 777 "${TMPDIR:-.}/cs"; sed -i 's|.*mktemp -d.*|tmp="${TMPDIR:-.}/cs" \&\& mkdir -p "$tmp" \&\& chmod 777 "$tmp" \&\&|' config.status; sh ./config.status && make -j1
```

**验证**:
```
d=$(mktemp -d /storage/Users/currentUser/x/confXXXXXX) && echo t > "$d/f" && echo OK || echo DENIED; echo a > f && echo b >> f && cat f; stat -f /storage/Users/currentUser | grep -E "Type|Inodes"
```
