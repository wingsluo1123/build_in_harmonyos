# E2191: unqlite 1.2.1 Jx9 引擎 count() 内置函数在 unqlite_compile 阶段崩溃（Signal 11），脚本应迭代 foreach 而非 count()

## 基本信息
- **严重度**: 2
- **类别**: runtime, embedded-db, script-engine
- **作者**: unknown

## 错误特征
```
Signal 11|core dumped|unqlite_compile.*count|Segmentation fault.*count
```

## 根因分析
unqlite 1.2.1 的 Jx9 脚本引擎在编译含 count() 内置函数（作用于数组字面量 [1,2,3] 或 db_fetch_all() 返回数组）的脚本时在 unqlite_compile() 内部崩溃（Signal 11，进程退出码 139）。不含 count() 的脚本（print、db_create、db_store、db_fetch_all + foreach）编译与执行均正常。官方样例 samples/4.c 即用 foreach 迭代 db_fetch_all 结果而非 count()。1.2.1 CHANGELOG 的 SyMemBackend 池路径简化疑为引入点；非 OHOS 平台问题（上游 amalgamation 用 clang 直编同样复现）。

## 推荐方案
**方法**: jx9-foreach-instead-of-count

**说明**: Jx9 脚本中避免 count()（尤其作用于数组字面量与 db_fetch_all() 结果），改用 foreach($data as $value){ ... } 迭代；过滤集合用 db_fetch_all('users',$callback) 后逐条打印/处理。与上游官方样例 4.c 的做法一致，不需 patch 上游源码，仅调整脚本。

**修复命令**:
```
"$zCallback = function($rec){ if( $rec.age < 30 ){ return FALSE; } return TRUE; }; $data = db_fetch_all('users',$zCallback); foreach($data as $value){ print $value..JX9_EOL; }"
```

**验证**:
```
最小复现：unqlite_open(":mem:") 后 unqlite_compile(pDb, "print 'n=' . count([1,2,3]);", len, &pVm) 返回前崩溃；对照 "print 'hello';" 正常。修复后：脚本用 foreach($data as $value){ print $value..JX9_EOL; } 迭代，unqlite_compile+vm_exec 正常，输出含 JSON 记录行。
```
