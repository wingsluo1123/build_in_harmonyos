# E2205: 纯脚本 CLI 包本地 conan create 全过但 CI L0 质量闸（L0k commands.json / L0p settings 四项）必挂——闸逻辑在 CI 脚本层，conan 引擎不检查

## 基本信息
- **严重度**: 3
- **类别**: conan, ci-quality-gate, cli-tool, pure-script-package
- **作者**: unknown

## 错误特征
```
L0k: CLI tool detected but commands\.json missing|L0p: settings 缺少 'compiler'|本地 conan create 通过.*PR CI 失败
```

## 根因分析
ci/conan/build_and_test.sh 的 L0 质量闸（L0a-L0p）在 CI 脚本层以 grep/python 检查执行，conan create 引擎完全不感知。L0k (R38) 对 package_type="application" 或产出 bin/ 可执行文件的包强制要求软件级目录 commands.json（type=tool + name 含包名 + versions 含版本号）；L0p 强制 settings 同时声明 os/compiler/build_type/arch 四项。纯脚本包最容易犯这两处：无编译直觉导致 settings 只写 "os", "arch"；"只是脚本"心态导致漏 commands.json。两处失败只在推送后的 CI 构建中暴露，本地 conan create（同款 profile）exit 0 无任何警告，形成"本地通过、PR CI 失败"的盲区。

## 推荐方案
**方法**: 本地推送前用 build_and_test.sh 闸逻辑复刻 L0 检查

**说明**: (1) conanfile.py 固定 settings = "os", "compiler", "build_type", "arch" 四项全声明（纯脚本包 compiler/build_type 实际不用，仅 profile 兼容与 L0p）；(2) 凡产出 bin/ 可执行文件（package_type="application" 或 package() 写 bin/）必须在 archives/<x>/<包名>/ 提供 commands.json，按 templates/commands.json.template 填 type="tool"、name 含包名、versions 含 包名/版本 ref；(3) 推送前零成本复刻闸：python3 ci/conan/detect_bindirs.py <conanfile> 判定是否 CLI 工具 + 校验 commands.json 三字段；grep settings 行确认四项；校验 archives/<首字母>/<包名>/<版本> 4 段结构 + slug 字符集（L0m）；分支名精确等于 包名-版本 可带 feat/ 前缀不许后缀（L0n）；(4) conan download 包/版本 -r=ohpcd --only-recipe 预检 L0j (R37)：404=首次发布安全，已存在且 recipe 有修改必须递增版本后缀；(5) L1 无需 no_official_test.txt 豁免：test_package 经 self.run("sh test.sh") 真实执行（日志含 Launching test_package/Running test()）即过 L1a，上游无可执行测试框架时 MANIFEST.yml 声明 upstream_test_in_build: false 即可（L1c 仅 info 不拦）。

**修复命令**:
```
conan create archives/c/cht.sh/0.0-git20220418.571377f -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing && python3 ci/conan/detect_bindirs.py archives/c/cht.sh/0.0-git20220418.571377f/conanfile.py
```

**验证**:
```
conan create archives/c/cht.sh/0.0-git20220418.571377f -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
