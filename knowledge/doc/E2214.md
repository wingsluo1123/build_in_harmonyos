# E2214: 编译器后端的设备内端到端运行证据链：测试驱动先失效（/tmp 硬编码），验收须以"生成→执行→行为比对"为准

## 基本信息
- **严重度**: 2
- **类别**: portability, make, compiler, testing, codegen
- **作者**: 9C4A
- **来源 PR**: 10377

## 错误特征
```
cannot open '/tmp/[^']+'|[0-9]+ of [0-9]+ tests failed
```

## 根因分析
上游测试驱动把宿主机假设写死，失败点不在被测编译器：tools/test.sh 第 7 行 tmp=/tmp/qbe.zzzz，OHOS /tmp 只读（E002 同族）使全部用例在写出临时汇编前即失败（49 of 50 tests failed / cannot open '/tmp/qbe.zzzz.s'），"后端坏了"是伪象；同时设备内运行证据还需要配方补齐一整套环境契约：C 编译器须经 CC 传入（脚本 ${CC:-cc} 的默认值在干净 PATH 下不可依赖）、TARGET 由被测程序自描述（qbe -t? = arm64；config.h 由 Makefile 依 uname -m 生成 T_arm64）、用例内嵌 driver 经 awk 抽取后与生成的 .s 一起交给 cc 链接（嵌套编译）、-lpthread 在 OHOS clang 15.0.4 可直接链接、原生路径（TARGET 为空）不得启用交叉/qemu 分支；计数与判定边界同样是契约的一部分：test/ 共 64 个 .ssa 而 make check 的 glob [!_]*.ssa 只执行 50 个（14 个下划线前缀为上游设计排除）、dark.ssa 由首行声明在 arm64 跳过、qbe.ref 不随源码包发布且上游对汇编文本差异只打印且恒返回 0——汇编一致不是验收标准，行为（stdout diff / 返回码）才是。

## 推荐方案
**方法**: tmpdir-aware-driver-plus-native-e2e-contract

**说明**: 最小且行为保持地让驱动接受 TMPDIR（tmp=${TMPDIR:-/tmp}/qbe.zzzz；默认行为不变、不引入平台宏、无绝对路径），配方侧补全环境契约（编译器取自 tools.build:compiler_executables、TMPDIR 指向 build 目录、SHELL=sh 兼容无 /bin/sh 主机、原生路径不启用 qemu、无 install(1) 时用 copy 安装）；验收硬标准是"生成→链接→原生执行→行为比对"，编译通过不算数，汇编文本一致也不算数（qbe.ref 缺失时上游根本不会执行比对）。

**修复命令**:
```
patch -p1 -i patches/0001-tools-test.sh.patch && TMPDIR=<build>/qbe-test-tmp CC=<clang> sh tools/test.sh all
```

**验证**:
```
设备侧三条：①原样复现 sh tools/test.sh all → 期望 "49 of 50 tests failed" 且 cannot open '/tmp/qbe.zzzz.s'；②补丁后 TMPDIR=<writable> CC=<clang> sh tools/test.sh all → 期望 49 [ok] + 1 上游声明 skip（dark.ssa，arm64）+ "All is fine!"；③消费者 E2E：QBE_BIN=<pkg>/bin/qbe QBE_TEST_CC=<clang> bash test_package/test_qbe.sh → qbe -t?=arm64、hello stdout 相等、退出码 42、非法 SSA 非零拒绝（12 断言）
```
