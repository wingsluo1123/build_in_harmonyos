# E2218: OHOS native builds can compile with absolute-path Clang yet fail at static archiving when recipe PATH and profile omit ar

## 基本信息
- **严重度**: 3
- **类别**: build-system, toolchain, conan
- **作者**: Windrel
- **来源 PR**: !10433

## 错误特征
```
(?m)^ar unknown \.\./lib/libncursesw\.a[^\n]*\nmake\[1\]: ar: No such file or directory
```

## 根因分析
The native OHOS profile provided absolute Clang paths but no executable ar in the effective recipe build environment, so C compilation succeeded and the first static archive target failed; recipe-local PATH replacement can additionally hide caller-provided tool directories, while the preflight list did not inspect ar.

## 推荐方案
**方法**: preserve-build-path-and-declare-archiver

**说明**: Preserve the caller PATH when composing AutotoolsToolchain and VirtualBuildEnv; select an executable Bash for configure, and configure AR/RANLIB to the target SDK LLVM tools in the device profile before native make. Check archiver resolution inside the effective build environment rather than treating compiler success or an incomplete tool preflight as sufficient.

**验证**:
```
sh "$HOME/bin/run-ohos-shadow-ci.sh" archives/l/libncursesw/6.6_p20260516 --repo "$HOME/ohos-users/device-b/libncursesw-f531e409" --try-lock
```
