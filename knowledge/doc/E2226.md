# E2226: "CMake configure-time download assets: Conan source acquisition and build-directory staging"

## 基本信息
- **严重度**: 2
- **类别**: network, build-system, cmake, conan, testing
- **作者**: Codex-2
- **来源 PR**: 8977

## 错误特征
```
file\(DOWNLOAD\).*scap_files|conan create.*TIMED OUT|Configuring done.*3600
```

## 根因分析
Some CMake projects keep real upstream tests enabled but download binary test fixtures with file(DOWNLOAD) while configuring; URL-driven ExternalProject dependencies can fail at the same boundary even when the main source is correct. A clean CI worker can fetch the package source yet stall in configure or the first build step on each asset; disabling the suite would hide the original test denominator. The inputs need the same checksum-bound acquisition and staging boundary as other Conan sources, while the upstream test registration remains unchanged.

## 推荐方案
**方法**: conan-source-checksummed-asset-and-build-staging

**说明**: Record every official asset URL and SHA256 in recipe constants; use Conan tools.files.download() in source() to acquire each file with checksum verification; before CMake configure, copy raw test fixtures into CMAKE_BINARY_DIR/scap_files and URL-driven ExternalProject archives into the exact <name>-prefix/src location that CMake probes. Keep the upstream test option and registration enabled, and report raw static, registered, runner, executed, skipped, and consumer counts independently.

**修复命令**:
```
"conanfile.py SCAP_FILES/BUNDLED_SOURCES; source(): download(..., sha256=...); if the official virtual-host S3 endpoint has TLS EOF, verify the official path-style endpoint for the same object; build(): copy verified files to Path(self.build_folder)/scap_files or Path(self.build_folder)/<prefix>-prefix/src/<filename> before CMake(self).configure()"
```

**验证**:
```
grep -RnE 'file\\(DOWNLOAD|CMAKE_BINARY_DIR.*/(fixtures|scap_files)' <source>; conan create <recipe> --profile:host <ohos-profile> --profile:build <ohos-profile>; inspect the configure log for staged assets and zero fixture downloads; run the complete upstream suite and test_package
```
