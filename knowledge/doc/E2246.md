# E2246: CMakeToolchain 不写 CMAKE_SYSTEM_NAME 使 CMake 落到 uname 的 HarmonyOS（无对应 Platform 模块）→ 链接期 RPATH 能力为空，上游 ctest 中链接本包 .so 的用例全部以「Error loading shared library」失败（不是缺依赖，是搜索路径为空）

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, cmake, linking, testing
- **作者**: iKalous_OscarP
- **来源 PR**: pending

## 错误特征
```
Error loading shared library lib[a-zA-Z0-9_.-]+\.so(\.[0-9]+)?\)|Error relocating .*: [a-zA-Z_0-9]+: symbol not found|System is unknown to cmake
```

## 根因分析
① conan 2.29.1 的 CMakeToolchain 生成的 conan_toolchain.cmake 里没有任何 CMAKE_SYSTEM_NAME 赋值（实测 grep 无输出，CMakeCache.txt 里也查不到该变量），

## 推荐方案
**方法**: hand-cmake-the-spelling-it-has-platform-module-for

**说明**: 在 generate() 里显式给出 CMake 认得的那个拼法：`tc.cache_variables["CMAKE_SYSTEM_NAME"] = "OHOS"`（走 Platform/OHOS.cmake → include(Platform/Linux)）。

**修复命令**:
```
grep -n 'CMAKE_SYSTEM_NAME' archives/l/libmongocrypt/1.20.1/conanfile.py
```

**验证**:
```
uname -s; grep -in system_name ~/.conan2/p/b/libmo*/b/build/Release/generators/conan_toolchain.cmake; B=$(ls -dt ~/.conan2/p/b/libmo*/b/build/Release | head -1); grep -c -- '-Wl,-rpath' "$B/CMakeFiles/example-state-machine.dir/link.txt"; llvm-readelf -d "$B/example-state-machine" | grep -cE 'rpath|runpath'
```
