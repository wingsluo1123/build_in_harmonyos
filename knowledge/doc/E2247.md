# E2247: OHOS libc 既无 dlinfo/RTLD_DI_LINKMAP 也不能用 dlpi_addr==handle 比对，dlopen 句柄是脱敏指针，反查已加载库路径只能 dlsym 已知导出符号后交给 dladdr

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, libc, headers, runtime
- **作者**: iKalous_OscarP
- **来源 PR**: pending

## 错误特征
```
call to undeclared function 'dlinfo'|implicit declaration of function 'dlinfo'|undefined reference to dlinfo|undeclared identifier 'RTLD_DI_LINKMAP'|Cannot get path of loaded library on this platform
```

## 根因分析
OHOS sysroot 的 <dlfcn.h> 不声明 dlinfo、libc.so 也不导出该符号（动态符号表只有 dladdr 与 dl_iterate_phdr）；同时 dlopen() 返回的是不可解释的 token（实测 0x906a8f02f29aa087），

## 推荐方案
**方法**: resolve-known-symbol-then-dladdr

**说明**: 在平台分支链里为 OHOS 单独加一支（必须排在 __linux__ 之前，因为 OHOS 的 clang 同时预定义 __linux__ 和 __OHOS__）：先用 mcr_dll_sym/dlsym 在该句柄里解析一个"必然存在于目标库中"的导出符号，再把它交给 dladdr()，取 Dl_info.dli_fname 作为库路径。被探测的符号名要按调用方语义选取：crypt_shared 库一定导出 MONGOC_CSFLE_FUNCTIONS_X 的首项 mongo_crypt_v1_status_create，libmongocrypt 自身一定导出 mongocrypt_version，两个都试即可覆盖两类句柄。命中后 mcr_dll_path_supported() 仍返回 true，让上游"必须拿到路径"的 assert 成立。

**修复命令**:
```
sed -n '/#elif defined(__OHOS__)/,/^#elif defined(__linux__/p' src/os_posix/os_dll.c
```

**验证**:
```
SDK=$HOME/.harmonybrew/opt/ohos-sdk@26.0.0.18/native; grep -c dlinfo "$SDK/sysroot/usr/include/dlfcn.h"; "$SDK/llvm/bin/llvm-nm" -D --defined-only "$SDK/sysroot/usr/lib/aarch64-linux-ohos/libc.so" | grep -E 'dlinfo|dladdr|dl_iterate_phdr'; conan create archives/l/libmongocrypt/1.20.1 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```
