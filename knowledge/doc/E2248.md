# E2248: Upstream test scripts that hardcode a raw.githubusercontent.com path into an external data repo break after the repo restructures; recover by git sparse-cloning the data repo, adapting the data format, and regenerating the test input with the upstream generator

## 基本信息
- **严重度**: 2
- **类别**: test-data-drift
- **作者**: unknown

## 错误特征
```
Cannot open input file: constellation/test_input.txt|hygdata_v3.csv.*404|raw.githubusercontent.com/astronexus|HYG-Database
```

## 根因分析
astronomy's generate/run downloads hygdata_v3.csv from https://raw.githubusercontent.com/astronexus/HYG-Database/master/hygdata_v3.csv, then make_constellation_data.py turns it into constellation/test_input.txt used by ctest. The external repo restructured (root file moved to hyg/v3/hyg_v3X.csv.gz), so every mirror of the hardcoded URL returns 404 and the ConstellationTest has no input file.

## 推荐方案
**方法**: git-sparse-clone-same-generation-data-plus-format-adaptation

**说明**: Do not patch the upstream test script. Recover the data from the same repository generation: git clone --depth 1 --filter=blob:none --sparse <repo> && git sparse-checkout set <subdir> to fetch only the needed data files over a working mirror (e.g. gh-proxy); pick the same-generation data version the upstream generator expects; if the repo now stores quoted CSV but the generator expects plain headers, convert with Python's csv module (reader->writer, no quoting); then run the upstream generator exactly as written. Verify by running the affected test and reporting the generated case count.

**修复命令**:
```
git clone --depth 1 --filter=blob:none --sparse https://gh-proxy.com/https://github.com/astronexus/HYG-Database hygclone && cd hygclone && git sparse-checkout set hyg/v3 && gunzip -k hyg/v3/hyg_v33.csv.gz && python3 -c "import csv; ...plain csv..." && cd .. && python3 make_constellation_data.py && ./ctest all
```

**验证**:
```
python3 make_constellation_data.py && ./ctest all (ConstellationTest PASS with 117958 cases)
```
