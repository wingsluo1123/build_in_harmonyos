# E2249: clang15/OHOS upgrades -Wfortify-source (sscanf fixed-width specifier vs buffer) and -Wmisleading-indentation to hard errors under upstream -Wall -Werror test builds; downgrade the specific classes instead of patching sources

## 基本信息
- **严重度**: 2
- **类别**: toolchain, strict-warning
- **作者**: unknown

## 错误特征
```
'sscanf' may overflow; destination buffer in argument [0-9]+ has size [0-9]+, but the corresponding specifier may require size [0-9]+|misleading indentation; statement is not part of the previous 'if'|\[-Werror,-Wfortify-source\]|\[-Werror,-Wmisleading-indentation\]
```

## 根因分析
Upstream test harnesses (generate/ctbuild, demotest, gravsim) compile with -Wall -Werror. The OHOS clang15 toolchain enables stricter checks than the upstream gcc environment: -Wfortify-source flags sscanf calls whose %Ns specifier can exceed the destination buffer (e.g. %20s into char[20], needing 21 for NUL), and -Wmisleading-indentation flags irregularly indented if/else blocks in legacy numerical code (e.g. NOVAS). Both are promoted by -Werror, breaking the build even though the code is correct.

## 推荐方案
**方法**: downgrade-specific-warning-classes-in-test-build

**说明**: Do not patch the upstream source. When the failure is a specific -W<class> promoted by -Werror in test-only code, append -Wno-error=<class> (not a blanket -Wno-error) to the compile line for the test harness. Prefer wrapper scripts that append the flags after -Werror so ordering cannot re-enable them. Keep the library itself compiled with strict flags; document the difference in the test report.

**修复命令**:
```
CC wrapper: exec clang "$@" -Wno-error=fortify-source -Wno-error=misleading-indentation  (invoked for ctbuild/generate builds)
```

**验证**:
```
clang -O3 -ffp-contract=off -Wall -Werror -Wno-error=fortify-source -Wno-error=misleading-indentation -o ctest -I ../source/c/ ../source/c/astronomy.c ctest.c -lm && ./ctest all
```
