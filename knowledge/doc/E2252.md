# E2252: C++17 auto_ptr→unique_ptr 迁移后：抽象基类缺虚析构触发 -Wdelete-abstract-non-virtual-dtor（header-only 库可直接替换）

## 基本信息
- **严重度**: 2
- **类别**: portability, abstract-class, cppstd, cxx, legacy-code
- **作者**: unknown

## 错误特征
```
no template named 'auto_ptr' in namespace 'std'|delete called on '.*' that is abstract but has non-virtual destructor|invalid UTF-8 in comment
```

## 根因分析
OHOS profile 设定 compiler.cppstd=17；std::auto_ptr 自 C++17 起被标准移除。旧 C++（约 2010s）库公共头直接使用 std::auto_ptr 作成员/局部变量。直接替换为 std::unique_ptr 后，删除动作改经 unique_ptr 的 typed delete 进行：当所指类型是"纯虚但析构非虚"的抽象基类时，clang 按 -Wdelete-abstract-non-virtual-dtor 告警，上游 -Werror 将其提升为 fatal。头部替换还会连带暴露同文件组的其他 2013 年遗留问题：注释中的 Latin-1 非法 UTF-8 字节触发 -Winvalid-utf8。header-only 库无 ABI 包袱，直接替换即可；有 ABI 约束的库需布局兼容 shim（见 bulletml 草稿）。

## 推荐方案
**方法**: cpp17-unique-ptr-direct-replace-plus-virtual-dtor

**说明**: header-only 库直接 std::auto_ptr → std::unique_ptr（含测试源）；对 unique_ptr 删除的抽象基类补充 virtual 析构；注释中非法 UTF-8 字节以 latin-1 字节级修复。全部以 patches/ 固化；若 refresh-patch 无法生成含非法字节的补丁，改由配方 build() 内 replace_in_file(encoding="latin-1") 修复。

**修复命令**:
```
sed -i 's/std::auto_ptr/std::unique_ptr/g' 公共头 测试源 && 为抽象基类添加 virtual ~T() {} && python3 -c "d=open(f,'rb').read();open(f,'wb').write(d.replace(b'\\xe4', 'ä'.encode('utf-8')))"；随后 refresh-patch --auto 生成补丁；conan create 复验 test_package 消费者编译运行
```

**验证**:
```
conan create archives/i/igloo/1.1.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable（test_package 1/1 通过）&& ./igloo-tests && ./snowhouse-tests（114/114、177/177 通过，exit 0）
```
