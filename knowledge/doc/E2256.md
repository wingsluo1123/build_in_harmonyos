# E2256: autotools 交叉适配六类高发坑：① AX_PROG_CC_FOR_BUILD 用全局 LIBS 链接宿主编译器 → "C compiler cannot create executables"；② host/build 同一 profile 时 conan 不传 --host，configure 去运行目标程序；③ 静态 readline/ncurses 的最终链接与 install 重链缺 -l 顺序

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, linking, cross-compile, packaging
- **作者**: staralsnow

## 错误特征
```
C compiler cannot create executables|AX_PROG_CC_FOR_BUILD|cannot run C compiled programs|undefined symbol: add_history|m4 subprocess failed|-lreadline .* -lncursesw|cannot guess build type|subs1.awk: Permission denied|could not setup config files machinery|z_errmsg.*recompile with -fPIC|system.vpi.*gzclose.*symbol not found
```

## 根因分析
① iverilog configure.ac:17 AX_PROG_CC_FOR_BUILD 的「宿主编译器可用」检查使用全局 $LIBS 链接本机 gcc；AutotoolsDeps 把目标库（aarch64 的 -lreadline/-lbz2/-lz）写进 LIBS，本机 gcc 找不到这些目标库（或架构不符）→ configure: error: C compiler cannot create executables。② WSL 工作流 host/build 用同一 OHOS cross profile（ci/conan/build_and_test.sh 对 -pr:h/-pr:b 用同一 profile），conan 的 cross_building(self) 为假 → AutotoolsToolchain 不传 --host；但 CC 仍是 OHOS 交叉 clang，产出的 aarch64 程序被 configure 尝试运行 → cannot run C compiled programs。③ 注册表 readline/ncurses 只有静态库（ncurses 配方禁止 shared），且为通过 ① 清空了 LIBS，configure 的 AC_CHECK_LIB(readline) 无法解析 readline 内的 ncurses 符号 → 探测 no、HAVE_LIBREADLINE 未定义但代码仍引用 add_history；最终链接与 make install（install 依赖 all，会重链）都缺 -lreadline/-lhistory/-lncursesw → undefined symbol: add_history。附加：bison 由 deb/自定义工具提供时需 BISON_PKGDATADIR + M4 指向同目录，否则 "m4 subprocess failed"。

## 推荐方案
**方法**: autotools-cross-libs-host-guards

**说明**: 三条固定判据：① 若 configure 报 C compiler cannot create executables 且项目含 *_FOR_BUILD 宏：在 AutotoolsToolchain 的 configure_args 追加 "LIBS="（保留 CPPFLAGS/LDFLAGS，AC_CHECK_LIB 仍能定位目标库）——清空只影响 configure 期间的 LIBS；② 若配置阶段出现 "cannot run C compiled programs" 且日志显示 build==host（同 profile 工作流）：在对 OS==OHOS 的 configure_args 里补 --host=aarch64-linux-ohos，且 build_requirements 改用真实机器架构判断（platform.machine()）决定是否 tool_requires 注册表工具，避免把 aarch64 生成工具放到 x86_64 上跑；③ 若最终链接/ install 报缺 readline/ncurses 符号：把静态链接顺序抽成 recipe 方法（-lreadline -lhistory -lbz2 -lz -lformw -lmenuw -lpanelw -lncursesw -lpthread），在 build/check/install 三处都传 LIBS=（make install 会重新链接）。另：运行期模块/资源路径若被写死为 $(prefix)，交叉/relocation 后需用项目自身开关（如 -B）指定实际路径。

**修复命令**:
```
# ① configure 期：tc.configure_args.append("LIBS=")# ② OHOS 且非交叉时补 --host# ③ 所有 make 调用：# autotools.make(args=["-j1", "LIBS=-lreadline -lhistory -lbz2 -lz -lformw -lmenuw -lpanelw -lncursesw -lpthread"])# autotools.make(target="check", args=[...同 LIBS...])# autotools.install(args=[...同 LIBS...])
```

**验证**:
```
conan create archives/<...> -pr:h=<ohos cross profile> -pr:b=default（交叉）；检查 configure 命令行是否含 --host；grep -nE "cannot create executables|cannot run C compiled programs|undefined symbol: add_history" reports/*.log；grep -n "AX_PROG_CC_FOR_BUILD" configure.ac；grep -nE "^LIBS|^LDFLAGS" <build>/Makefile
```
