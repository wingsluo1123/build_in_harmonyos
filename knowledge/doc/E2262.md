# E2262: D 语言项目的 OHOS 适配：工具链经 ohpcd 取得（ldc+llvm），无 dub 时走 GNUmakefile 绕开；且 LDC 1.42.0 前端拒绝 inout 形式的 opEquals

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, toolchain, conan, language
- **作者**: ohpcd <ohpcd@localhost>

## 错误特征
```
cannot implicitly convert expression of type.*inout|cannot find -lphobos2|ldc2: command not found|object\.d.*not found|std\.algorithm.*not found|Error loading shared library libLLVM\.so\.(\d+)|only parameters or stack-based variables can be `inout`
```

## 根因分析
三层成因。(1) 框架层：D 不在 LANG_ENUM（c/cpp/rust/python/go/perl/lua/nodejs/java/bash/mixed/other），且 .d 未登记于 lang_detect 的 _EXT_LANG，语言预检会把 .d 源码回退判为 c（误判而非报错，静默）。(2) 环境层：设备侧无任何 D 工具链，但 ohpcd 已有 ldc/1.42.0（提供 bin/ldc2、bin/ldmd2、libdruntime-ldc.a、libphobos2-ldc.a、include/d/）与 llvm/20.1.0（ldc2 的 NEEDED libLLVM.so.20.1 来源，ldc recipe 已自动 requires），故工具链可经 tool_requires 取得；唯一真缺的是 dub（ohpcd 无该制品）。(3) 编译器层：LDC 1.42.0 的 DMD 前端（v2.112.1）拒绝 `inout typeof(this)` 作为参数/成员值——core.internal.newaa 以 const 限定的 Key 实例化模板时，const(inout(Value[Key])) 无法转换为所需的 inout(const(Value[Key]))，报 "only parameters or stack-based variables can be inout"。

## 推荐方案
**方法**: tool-requires-ldc-plus-makefile-path

**说明**: 以 tool_requires("ldc/1.42.0") 引入 D 工具链（其依赖 llvm/20.1.0 由 ldc recipe 自动带入，提供 ldc2 所需的 libLLVM.so）；构建入口优先选**不需要 dub** 的路径——上游若同时提供 GNUmakefile/meson.build/dub.json，选 GNUmakefile（只需 DC，按 dmd→ldc→ldc2→gdc 探测）。显式传三个参数：DC=ldc2、DCFLAGS="-O -I<ldc>/include/d"（ldc2 默认 import 路径在制品上不可用，不给会报 object/std.algorithm not found）、LDFLAGS="-L-L<ldc>/lib"（不给则链接失败）。若项目源码用 inout 形式的 opEquals，需打补丁改为现代 D 惯用的 scope const。版本号经 GIR_TO_D_VERSION 之类的变量注入（tarball 无 .git 时构建脚本会回退到上游写死值）。

**修复命令**:
```
make -f GNUmakefile DC=ldc2 GIR_TO_D_VERSION=v<ver> DCFLAGS="-O -I<ldc_pkg>/include/d" LDFLAGS="-L-L<ldc_pkg>/lib"
```

**验证**:
```
① 设备侧确认无 D 工具链：`for t in dmd ldc2 ldmd2 gdc dub; do command -v $t; done`（全部为空）。② ohpcd 制品：`conan search "ldc/*" -r=ohpcd` → 1.42.0（Found 1）；`conan search "dub/*" -r=ohpcd` → Found 0。③ ldc2 可运行性：在不设 LD_LIBRARY_PATH 时 `ldc2 --version` 报 `Error loading shared library libLLVM.so.20.1`（缺运行期库搜索路径，非缺库），设好后输出 `LDC 1.42.0 ... target aarch64-unknown-linux-ohos`。④ 构建：`make -f GNUmakefile DC=ldc2 GIR_TO_D_VERSION=v0.23.3 DCFLAGS="-O -I<ldc>/include/d" LDFLAGS="-L-L<ldc>/lib"` → 产出 girtod。⑤ 补丁必要性：不打补丁的原始源码同样报 newaa 的 inout 错误。
```
