# E2280: 上游 release tarball 里 git 子模块为空目录 —— 树内构建不可行，需把该子模块换成外部工具/包并做运行期接线

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, conan, packaging
- **作者**: 11115
- **来源 PR**: 11115

## 错误特征
```
No rule to make target .*abc.*|cannot open .*libs/cxxopts/include/.*|is not configured as a git repository, and 'abc' folder is missing|fatal error: .*cxxopts.hpp: No such file or directory
```

## 根因分析
GitHub 的 refs/tags/<v>.tar.gz 归档不会包含 git 子模块内容（子模块目录是空目录，甚至完全不出现）；而项目的 Makefile/源码仍按树内路径引用它。两种常见后果：① 构建期需要该子模块的源码/头文件（如 libs/cxxopts/include/cxxopts.hpp）；② 运行期需要该子模块产出的二进制（如 ABC 逻辑综合器）。若只按报错补一个目录，运行期仍会在 exec 时找不到二进制。

## 推荐方案
**方法**: 构建期需要的头文件/源码，从对应的 conan 包物化到树内路径（build() 里复制，不改上游）；运行期需要的外部二进制，声明为 host requirement，用项目的『外部工具』开关（如 ABCEXTERNAL）指向它，并在 package_info() 用 runenv_info 导出运行期环境变量（若程序优先读环境变量）

**说明**: ① cxxopts：glob conan 包的 include/*.hpp 复制到 libs/cxxopts/include/；② abc：self.requires("abc/...")（host，而非 tool_requires，因为运行期 exec），make 时传 ABCEXTERNAL=<abc 包 bin/abc> 与 DISABLE_SPAWN=0；package_info 里 runenv_info.define("ABC", <消费者自己的 abc 路径>)，避免把构建机缓存绝对路径固化进产物。

**修复命令**:
```
make ENABLE_ABC=1 ABCEXTERNAL=<abc-pkg>/bin/abc DISABLE_SPAWN=0 ; runenv_info.define("ABC", abc_bin)
```

**验证**:
```
tar -tzf <tarball> | grep -c '<submodule>/.'（0 表示 0 个文件；目录项仍可能为 1）；make -n <目标> 看是否引用该目录；运行期执行产物看是否 spawn 外部二进制
```
