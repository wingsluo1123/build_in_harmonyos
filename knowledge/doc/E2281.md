# E2281: 制品仓 bison 二进制硬编码 /data/service/hnp/bin/m4 —— 非鸿蒙设备上生成语法分析器时 EIO/Error 141

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, toolchain, conan
- **作者**: 11115
- **来源 PR**: 11115

## 错误特征
```
bison: input/output error|bison: .*/share/bison/m4sugar/m4sugar\.m4: cannot open|make.*Error 141|make.*Error 1.*verilog_parser
```

## 根因分析
制品仓发布的 bison/3.8.2 二进制在编译时把 m4 路径写死为鸿蒙设备路径 /data/service/hnp/bin/m4（可用 strings <bison>/bin/bison | grep -F '/data/service/hnp' 实证）。该路径在非鸿蒙主机（如 WSL 交叉构建）不存在，bison 调用 m4 失败；由于 bison 与 m4 之间是管道，写端先死会让 make 看到的是 SIGPIPE 派生的 Error 141，真正的报错是 bison: input/output error（EIO），极易误判为磁盘/权限问题。

## 推荐方案
**方法**: 仅当设备路径不存在时（os.path.exists("/data/service/hnp/bin/m4") 为假）在 make 的环境前缀里注入 M4=<shutil.which("m4")>；设备上该路径存在则分支不触发，行为与 CI 一致

**说明**: _m4 = 'M4="%s"' % shutil.which("m4") if (not os.path.exists("/data/service/hnp/bin/m4") and shutil.which("m4")) else ""；与 BISON_PKGDATADIR=<bison 包>/share/bison 一起注入。

**修复命令**:
```
M4=/usr/bin/m4 BISON_PKGDATADIR=<bison-pkg>/share/bison make -j1 ...
```

**验证**:
```
strings <bison 包>/bin/bison | grep -F '/data/service/hnp'；以及 <bison>/bin/bison --version；对照实验：同一主机上普通 OHOS aarch64 二进制读写文件正常，可排除磁盘/权限
```
