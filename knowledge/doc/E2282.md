# E2282: 本机用通用 Alpine musl loader 运行 OHOS aarch64 二进制时缺 __fd_chk —— 用 QEMU_SET_ENV 只给 guest 注入 shim

## 基本信息
- **严重度**: 2
- **类别**: platform, libc, musl, runtime, testing
- **作者**: 11115
- **来源 PR**: 11115

## 错误特征
```
Error relocating .*: __fd_chk: symbol not found|Error loading shared library libc\+\+_shared\.so|Error loading shared library libz\.so
```

## 根因分析
本机跑 OHOS aarch64 二进制需要 loader + 运行库。用免 root 的通用 Alpine musl 作 loader 时，OHOS musl 的 fortify 助手符号 __fd_chk（OHOS sys/select.h:33 声明 void __fd_chk(int fd)，FD_SET/FD_CLR 宏调用它）不存在，程序在重定位阶段以 symbol not found 退出；同时 SDK sysroot 的 libc.so 只是 72KB 链接桩（所有 _chk 符号同址），不能当 loader。另外 libc++_shared.so / libz.so 需要从 SDK 的 aarch64 目录补进 LD_LIBRARY_PATH。

## 推荐方案
**方法**: 编译一个只定义 void __fd_chk(int fd){(void)fd;} 的 aarch64 共享库，用 QEMU_SET_ENV=LD_PRELOAD=<shim> 注入 —— 该变量由 qemu 解释，只作用于 guest 进程，不会污染宿主编译器等 x86 进程

**说明**: ① SDK clang 编 shim：aarch64-unknown-linux-ohos-clang --sysroot=<sdk>/sysroot -shared -fPIC fdchk.c -o libfdchk.so；② export QEMU_SET_ENV="LD_PRELOAD=<abs>/libfdchk.so"（注意：直接 export LD_PRELOAD 会让宿主 x86 进程报 wrong ELF class）；③ LD_LIBRARY_PATH 补 <sdk>/llvm/lib/aarch64-linux-ohos 与 <sdk>/sysroot/usr/lib/aarch64-linux-ohos。

**修复命令**:
```
QEMU_SET_ENV="LD_PRELOAD=$PWD/libfdchk.so" LD_LIBRARY_PATH="$SDK/llvm/lib/aarch64-linux-ohos:$SDK/sysroot/usr/lib/aarch64-linux-ohos:$TCL_LIB" ./yosys -V
```

**验证**:
```
先 ldd/readelf 看 DT_NEEDED；再用 nm -D <通用 musl loader> | grep __fd_chk 确认缺失；注入 shim 后同一二进制应正常输出
```
