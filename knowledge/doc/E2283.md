# E2283: 自带 Makefile 的 install 目标用 $(STRIP) 默认解析到宿主 strip，交叉构建时 strip 无法识别 aarch64 ELF

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, build-system, install
- **作者**: 11115
- **来源 PR**: 11115

## 错误特征
```
strip: Unable to recognise the format of the input file|strip:.*file format not recognized|make.*\[Makefile:[0-9]+: install\] Error 1
```

## 根因分析
自带 Makefile 常写 STRIP ?= strip（默认取 PATH 上的宿主 GNU strip）。交叉构建时宿主 strip 的 BFD 后端不支持 aarch64-ohos ELF（或该发行版未编入 aarch64 目标），于是 make install 在 strip 步骤以 Unable to recognise the format 失败；编译与链接其实都已经成功，失败只发生在安装阶段。

## 推荐方案
**方法**: 从配置的 C 编译器同目录取 llvm-strip（OHOS SDK 在 llvm/bin 下随 clang 一起提供），以 STRIP="<abs>/llvm-strip" 传给 make install；找不到时保持 Makefile 默认，native 构建不受影响

**说明**: compilers = self.conf.get("tools.build:compiler_executables", ...); cc = compilers.get("c"); cand = os.path.join(os.path.dirname(cc), "llvm-strip"); _strip = 'STRIP="%s"' % cand if os.path.isfile(cand) else ""；再把 _strip 加进 make install 的环境前缀。

**修复命令**:
```
STRIP="$SDK/llvm/bin/llvm-strip" make install PREFIX=$PKG ...
```

**验证**:
```
grep -n 'STRIP' Makefile；再在构建机上跑 strip -S <cross-built-binary> 复现；改用 <CC 同目录>/llvm-strip -S 同一二进制应成功
```
