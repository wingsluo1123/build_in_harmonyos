# E2284: 自带 Makefile 项目自赋 CXX/CC（非 ?=）时 conan 的 tools.build:compiler_executables 失效，交叉构建静默产出宿主对象

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, build-system, conan
- **作者**: 11115
- **来源 PR**: 11115

## 错误特征
```
/usr/bin/ld: skipping incompatible .*\.so when searching for|skipping incompatible .*libtcl8\.6\.so|file format not recognized; treating as linker script|relocation R_AARCH64_.* cannot be used
```

## 根因分析
自带 Makefile（非 autotools/cmake/meson）的项目若用 CXX := / CC := （非 ?=）自行赋值，conan profile 的 tools.build:compiler_executables 只能通过构建环境变量/工具链文件生效，到不了 make；make 于是调用宿主 gcc/g++，编出宿主 x86_64 对象，直到链接阶段才以 skipping incompatible .../libtcl8.6.so 暴露，且对象文件已经全部生成、不重编就不会再报。

## 推荐方案
**方法**: 在 self.run 的**环境前缀**里显式传 CC="<cross-cc>" CXX="<cross-cxx>"（值取自 self.conf.get("tools.build:compiler_executables", default={}, check_type=dict)），与 CXXFLAGS/LIBS 同一方式；不要用 make 命令行变量（会覆盖 Makefile 自身的 CXXFLAGS 并丢掉 -I.）

**说明**: 环境前缀注入：`{} CXXFLAGS="..." make ...`.format('CC="%s" CXX="%s"' % (cc, cxx))。R33 要求值来自 self.conf，禁止裸用 ${CC}；仅在 conf 提供时注入，未提供时保持 Makefile 默认。

**修复命令**:
```
CC="$CROSS_CC" CXX="$CROSS_CXX" make -j1 ...   # 值来自 self.conf 的 tools.build:compiler_executables
```

**验证**:
```
在 build() 前后对比 file <build>/*.o 或 readelf -h <build>/yosys：出现 ELF 64-bit LSB relocatable, x86-64 即为宿主对象；加 CC=/CXX= 后应变为 ARM aarch64
```
