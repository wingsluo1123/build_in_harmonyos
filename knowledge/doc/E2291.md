# E2291: polyseed 上游 UTF-8 惰性归一化用 `*p < 0` 判定非 ASCII，AArch64 ELF ABI 默认 char 无符号使该分支静默失效，多语言 encode/decode 往返断言失败（SIGABRT exit 134）；-fsigned-char 重编后 51/51 全过

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, char-signedness
- **作者**: unknown, 8543

## 错误特征
```
Assertion failed: res == POLYSEED_OK.*test_roundtrip|Signal 6 \(core dumped\)|CHAR_MIN=0
```

## 根因分析
AArch64 ELF ABI 默认 plain char 为无符号（x86-64 相反）。polyseed 的

## 推荐方案
**方法**: cmake-toolchain-extra-cflags-fsigned-char

**说明**: 把承接 getc()/fgetc() 返回值的变量类型改为 int（与标准规定的返回值域一致），使 EOF 可表示、状态机恢复出口。单行类型修正即可，不动算法、不加平台宏；用三组同机对照证明必要性——A 上游源码+默认选项 → timeout 25 rc=124，B 上游源码+`-fsigned-char` → rc=0（隔离出“符号性”这一唯一变量），C 打补丁+默认选项 → rc=0 且上游 `make test` 输出 Test OK——并把该对照表写进 notes 与 test-report。上游/发行版若已有同名修复（Debian 的 fix_infinite_loop.patch），按其语义对齐（只要求修同一处、同一类型转换，不假设两份补丁文件逐字相同），保证补丁可向上游提交（P005）。

**修复命令**:
```
仅改接收变量类型一行（如 `sed -i 's/^    char c;$/    int c;/' looktxt.c`，务必先 grep 确认该行就是 getc 的接收变量）；随后 `timeout 25 ./looktxt --verbose --test examples/Al.lau </dev/null` 验证 rc=0，并跑上游 `make test` 取 Test OK
```

**验证**:
```
timeout 25 ./<pkg-bin> --verbose --test examples/<官方输入> < /dev/null; echo "rc=$?"   # 124=挂起(未修复), 0=已修复。跑对照务必重定向 stdin，避免把等待标准输入误判为死循环。符号性：对含 #include <limits.h> 的探针文件跑 `clang -dM -E probe.c | grep -i CHAR_UNSIGNED` 并打印 CHAR_MIN。源码侧定位：先用 `grep -n "getc("` 找读取点，再用 `grep -nE "^[[:space:]]*(char|int)[[:space:]]+[a-z_]+[[:space:]]*;"` 找接收变量声明，并核对二者是否同一函数（打印函数边界，勿凭函数名猜测）
```
