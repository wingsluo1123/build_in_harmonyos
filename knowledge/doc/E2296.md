# E2296: Deliver a system-same-name library (e.g. libEGL) as static_library in the Meson recipe so conan-verify G3/R26 passes on OHOS

## 基本信息
- **严重度**: 1
- **类别**: ohos, conan, packaging, egl, r26
- **作者**: unknown

## 错误特征
```
R26 违规: 系统同名库输出了 \.so|与系统同名 \.so 冲突|Gate3|G3.*FAIL|system-same-name
```

## 根因分析
OHOS PC 系统镜像 /lib64 自带图形栈共享库（libEGL.so / libEGL_mesa.so / libGLESv3.so 等）。mesa 启用 -Degl=enabled 后交付的 libEGL.so 与系统同名，conan-verify G3（R26 系统同名库隔离）将包内所有 .so 基名与 /lib、/lib64 比对，同名即判 FAIL（CI 侧 L5/R26 同规则但为 warn 口径）。

## 推荐方案
**方法**: static-lib-egl-for-r26

**说明**: (待补充)

**修复命令**:
```
patch src/egl/meson.build: libegl = shared_library(...) -> static_library(...)，去掉 version/soversion/vs_module_defs 参数（meson 1.11.1 static_library 不接受 version/soversion）；GLESv1_CM/GLESv2/gbm/OSMesa 无系统同名冲突保持共享；conanfile.py package() 需 `import glob`（SONAME 复制 loop 使用）；egl.pc 保持生成（pkg-config --libs egl -> -lEGL 解析 libEGL.a）。
```

**验证**:
```
python3 scripts/ohc-run.py conan-verify mesa 24.3.4.1.1 && grep 'G3' reports/conan-verify-report.md
```
