# E2317: "conandata.yml sources 带 filename 键时配方 get() 再传 filename 关键字冲突（TypeError）"

## 基本信息
- **严重度**: "2"
- **类别**: conan, packaging, conandata, recipe
- **作者**: "libsmraw-20240506"
- **来源 PR**: "None"

## 错误特征
```
"TypeError: get() got multiple values for keyword argument 'filename'|got multiple values for keyword argument 'filename'|Error in source() method"
```

## 根因分析
"conandata.yml 的 sources 段自带 filename 键（url/sha256/filename 三键形态，用于避免 Conan 对无扩展名/镜像 URL 的归档格式误判）时，配方 source() 里再显式写 filename=<名字> 会让 get(self, **self.conan_data[\"sources\"], filename=...) 展开出两个同名关键字，Python 调用绑定立即抛 TypeError；构建尚未开始，报错点在 source() 首行，极易被误判为 conandata 字段名拼写或 conan 版本问题。"

## 推荐方案
**方法**: "conandata-single-source-of-truth-for-get-kwargs"

**说明**: "二选一并保持单一来源：①推荐——conandata.yml 保留 url/sha256/filename 三键，配方写成 get(self, strip_root=True, **self.conan_data[\"sources\"])，不在调用点重复任何键（libfsapfs/20240429 先例）；②conandata 只留 url/sha256，配方显式传 filename=<名字>。改完用 py_compile 与 yaml.safe_load 双自检，再进采信轮。"

**修复命令**:
```
"python3 -m py_compile <conanfile.py> && python3 -c \"import yaml; yaml.safe_load(open('<conandata.yml>'))\""
```

**验证**:
```
"python3 -c \"from conan.tools.files import get; d={'url':'u','sha256':'s','filename':'a.tar.gz'}; get(None, **d, filename='b.tar.gz', strip_root=True)\" —— 设备直接执行即复现同型 TypeError（不联网、不建文件）；修复形态同命令去掉第二个 filename 后返回 TypeError: 'NoneType' 对象不可调用之前的正常参数绑定（不再报 multiple values）。"
```
