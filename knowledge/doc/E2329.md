# E2329: 预编译 Ada 运行时 libgnat.a 非 PIC 且不可重建：Ada 绑定在 OHOS 只能静态交付（同一错误签名，处置与 E005 不同）

## 基本信息
- **严重度**: 2
- **类别**: ohos, ada-binding, gcc-ada, immutable-toolchain-artifact, only-delivery
- **作者**: none

## 错误特征
```
libgnat\.a.*relocation R_AARCH64_ADR_PREL_PG_HI21.*can not be used when making a shared object|recompile with -fPIC|cannot find -lgnat
```

## 根因分析
gcc-ada/9.5.0 只交付静态 Ada 运行时 adalib/libgnat.a 与 libgnarl.a，且其中对象不是 -fPIC 编译。上游 Ada 库若产出 libX.so 并把 -lgnat 链进去，ld 报 R_AARCH64_ADR_PREL_PG_HI21 ... can not be used when making a shared object; recompile with -fPIC。关键区别：E005 假设非 PIC 的 .a 是项目自己的、可加 -fPIC 重编；这里 libgnat.a 是第三方预编译工具链产物，适配范围内无法重编，所以"加 -fPIC"不可用，唯一自洽处置是改交付形态。另 adalib 目录按编译器版本命名（9.5.0），用被测库版本拼路径会找不到 -lgnat。

## 推荐方案
**方法**: recognize-immutable-nonpic-runtime-switch-to-static-only

**说明**: 先判定非 PIC 的 .a 是否属于本项目：若可为它加 -fPIC 重编（E005 场景），走 E005；若它来自工具链/第三方且适配范围内不可重编（libgnat.a 场景），不要尝试绕 linker，直接改交付形态——配方固定 shared=False，并在 validate() 里对 shared=True 抛 ConanInvalidConfiguration 说明预编译运行时非 PIC；只构建静态目标（make obj/libX.a obj/X.gpr），package() 手工安装 .a + ALI + .ads/.adb + .gpr，绕开上游 make install 同时装 .so 的动作；链接用 glob <toolchain>/lib/gcc/*/*/adalib 定位运行时并 -L，不要用被测库版本号拼路径。

**修复命令**:
```
validate() 对 shared=True 抛 ConanInvalidConfiguration；make obj/libgmpada.a obj/gmpada.gpr LDLIBS="-L<gmp dir> -lgmp -lgnarl" LDFLAGS="<default> -L<adalib>"; package() 手工装 .a/.ali/.ads/.gpr
```

**验证**:
```
conan create <recipe> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
