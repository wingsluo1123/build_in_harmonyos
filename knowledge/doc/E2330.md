# E2330: OHOS 上由 C/C++ 头生成 Ada 绑定规格（gcc-ada 无 g++）：驱动链接误判须加 -fsyntax-only，输出文件名/包名与上游 glob 不符须显式生成

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, ada-binding-generation, code-generation, gcc-ada
- **作者**: none

## 错误特征
```
undefined reference to .main.|obj/.*_gmp_h\.ads: No such file or directory|--dump-ada-spec|g\+\+-9: No such file or directory
```

## 根因分析
gcc-ada/9.5.0 以 --enable-languages=c,ada 构建，不含 g++/libstdc++，而 libgmpada 的 Makefile 默认 CXX := g++-<gnat_version> 并用 g++ --dump-ada-spec 从 gmp.h 生成绑定规格；OHOS 的 gcc 驱动签名包装器把任何不含 -c/-S/-E/-fsyntax-only 的调用判为链接，于是 --dump-ada-spec tmp.h 走到链接器并报 undefined reference to main。改用 C 驱动（gcc）后，GCC 实际产出 obj/gmp_h.ads（package gmp_h is），既不匹配上游 sed 源 glob obj/*_gmp_h.ads，也不匹配 sed 规则 ^package .*_gmp_h is$，构建在 sed 处断掉。

## 推荐方案
**方法**: c-driver-fsyntax-only-explicit-spec-generation

**说明**: 用 gcc-ada 的 gcc（C 驱动）替代 g++，并追加 -fsyntax-only，避免被 OHOS 驱动包装器判为链接；不要依赖上游的 *_gmp_h.ads glob，改为在配方 build() 中显式生成 src/gmp-h.ads：先 dump 得到 obj/<header>_h.ads（package <header>_h），把 package/end 行临时改名为 TMP_<header>_h 后套用未修改的上游 sed，输出到 src/gmp-h.ads；随后上游 make 目标因时间戳更新而自动跳过。

**修复命令**:
```
gcc -I<inc> -Wall -Wextra -fsyntax-only --dump-ada-spec tmp.h; sed -e 's/^package gmp_h is$/package TMP_gmp_h is/' -e 's/^end gmp_h;$/end TMP_gmp_h;/' obj/gmp_h.ads | sed -f gmp-h.ads.sed > src/gmp-h.ads
```

**验证**:
```
cd <src> && <gcc-ada>/bin/gcc -I<gmp include> -Wall -Wextra -fsyntax-only --dump-ada-spec tmp.h && ls obj/gmp_h.ads
```
