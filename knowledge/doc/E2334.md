# E2334: ohpcd 的 gcc-ada/9.5.0 只装 gnatbind/gnatchop/gnatclean/gnatlink/gnatls/gnatmake，缺 gnatprep；凡上游 Makefile 用 $(ADAPREP) 从 .adb_p 生成 .adb 的 Ada 库都会在 make 阶段 Error 127

## 基本信息
- **严重度**: 3
- **类别**: autotools, toolchain, ada, gcc-ada, gnat
- **作者**: ohpcd

## 错误特征
```
make\[1\]: gnatprep: No such file or directory|Error 127|gnatmake: .*\.ali. WARNING: ALI or object file not found after compile
```

## 根因分析
gcc-ada/9.5.0 的 bin/ 只有 gnatbind、gnatchop、gnatclean、gnatlink、gnatls、gnatmake 六个 GNAT 工具，没有 gnatprep（libexec/gcc/.../ 也只有 cc1/cc1plus/gnat1/collect2/lto-wrapper）。而 AdaCurses 的 src/Makefile.in:88 定义 ADAPREP = gnatprep、:241 用 $(ADAPREP) -DADA_TRACE=@ADA_TRACE@ @GNATPREP_OPTS@ $(srcdir)/$(ABASE)-trace.adb_p $@ 生成 terminal_interface-curses-trace.adb。CI 原生构建因此终止于 make[1]: gnatprep: No such file or directory（Error 127），把 CI 50329 误判为普通编译错误。

## 推荐方案
**方法**: materialize-a-minimal-gnatprep-shim-first-on-PATH

**说明**: 不要试图把 gnatprep 塞进 PATH 就完事——gcc-ada 真的没有；也不要改上游 Makefile 绕过（会丢掉 trace 编译单元或与上游行为脱钩）。正确做法是用确定性、无第三方依赖的等价实现补齐这个缺失工具，并保证 configure 的 gnatprep -T 探测失败（缺输入文件时立即 exit 2）从而 GNATPREP_OPTS 为空、构建期不会被喂 -T，也绝不会去读 stdin 挂死。

**修复命令**:
```
在 generate() 里把最小 gnatprep 实现写入 <generators>/gnatprep-bin/gnatprep（shebang 用 sys.executable），env.prepend_path("PATH", bindir)；实现需支持 -D name[=value]、#if/#elsif/#else/#end if; 与 $name 替换
```

**验证**:
```
ls <gcc-ada 包>/bin | grep -c '^gnatprep$'   # 期望 0； ls <gcc-ada 包>/libexec/gcc/aarch64-linux-ohos/9.5.0/  # 无 gnatprep； grep -rn 'gnatprep' <源码>/src/Makefile.in
```
