# E2348: Raw Makefile link step hardcodes `gcc`; generate() provides a gcc->clang wrapper on PATH so make works where only clang exists

## 基本信息
- **严重度**: 2
- **类别**: build-system, make, toolchain, conan
- **作者**: unknown

## 错误特征
```
make: gcc: No such file or directory|gcc: not found|Error 127.*gcc|md2html target.*gcc
```

## 根因分析
Some raw (non-autotools/cmake/meson) makefiles hardcode the compiler binary name in specific link rules (e.g. `gcc ... -o bin/md2html`) in addition to a CC variable. The OHOS CI/toolchain environment provides clang but not gcc, so only that target fails with `make: gcc: No such file or directory` while other targets built via $(CC) succeed. Passing CC=clang on the make command line does not fix hardcoded occurrences.

## 推荐方案
**方法**: generate-gcc-wrapper-in-private-prefix

**说明**: In conanfile generate(), create a private build-folder bin/ dir containing a `gcc` wrapper script `#!/bin/sh\nexec <CC> "$@"` (resolving <CC> from the Conan toolchain conf `tools.build:compiler_executables` dict's "c" key — R33 forbids relying on shell env vars like ${CC}; fall back to shutil.which("clang") only if the conf is empty), chmod +x it, and prepend that dir to PATH when running make. Keeps the injection in the build folder only (R49: no shared /usr/local pollution; the compiler id comes from the Conan toolchain).

**修复命令**:
```
generate(): read compilers = self.conf.get("tools.build:compiler_executables", default={}, check_type=dict); cc = compilers.get("c") or shutil.which("clang"); write build_folder/bin/gcc wrapper -> cc; build(): PATH="<build>/bin:$PATH" make CC=<cc> CFLAGS=... all
```

**验证**:
```
PATH="<build>/bin:$PATH" make CC=clang all within conan create; the previously failing target links successfully.
```
