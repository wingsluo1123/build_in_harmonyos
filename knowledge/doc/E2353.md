# E2353: conan 2.29 package_info 双向校验二象性 - override=True 依赖不能进 cpp_info.requires 而其余直接依赖缺一不可

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, packaging
- **作者**: wanderlust_0823
- **来源 PR**: none

## 错误特征
```
"The direct dependency .* is not used by any .*(cpp_info).*(requires)|not a direct requirement|Version conflict: Conflict between .* in the graph"
```

## 根因分析
conan 2.29.1 在 package_info() 评估阶段对 cpp_info.requires 做双向校验 - 正向每个图中真实存在的直接依赖(本包->依赖的建图边)必须出现在 cpp_info.requires 否则报 The direct dependency X is not used by any (cpp_info.components).requires - 反向 cpp_info.requires 的每个条目必须对应真实直接依赖 而 override=True 声明的 require 不建图边 只参与全图版本解析 写进去报 not a direct requirement。两条规则合起来意味着 为解决跨路径精确钉版冲突而使用 override=True 的依赖只能留在 requirements() 里 不能出现在 cpp_info.requires 中 而其余全部非 override 直接依赖必须逐条列出 缺一不可。conan 2 对同包多路径精确钉版不一致直接报 Version conflict 错误 不存在就近覆盖优先

## 推荐方案
**方法**: direct-deps-cppinfo-requires-complete-listing

**说明**: package_info 里用完整清单列出全部非 override 直接依赖的 name 前缀条目 - override=True 的依赖保持在 requirements() 做全图版本解析但不进 cpp_info.requires - 链接与传播经其余直接依赖或 libarchive 等中间包链条完成

**修复命令**:
```
in package_info set cpp_info.requires = [d + "::" + d for each non-override direct requirement d] - keep requires(zlib/x, override=True) in requirements() only
```

**验证**:
```
对照法 - requires() 中非 override 的包名集合 必须等于 cpp_info.requires 中 name 前缀集合 减去 override=True 的包 - 另可用 conan graph info 复现 Version conflict 的冲突来源
```
