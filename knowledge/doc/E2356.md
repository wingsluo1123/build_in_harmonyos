# E2356: 同 tarball CMake 子库独立成包：①交付面裁剪时必须覆盖 install(TARGETS) 全集 ②主 N 取父 tarball 注册面最大值并给 NOT_RUN 自洽台账（rule4 只判少报）

## 基本信息
- **严重度**: 1
- **类别**: cmake, conan, packaging, testing, review-gate
- **作者**: unknown

## 错误特征
```
file INSTALL cannot find|Total Tests:\s*0|No tests were found|HWY_ENABLE_TESTS.*install|install\(TARGETS.*hwy_test|上游实测 N > 声明 N|rule4.*少报|gtest_discover_tests
```

## 根因分析
两件事叠在一起才会踩坑。①【构建面】上游把子库的安装规则藏在功能开关里（Highway：`if (HWY_ENABLE_TESTS) install(TARGETS hwy_test …)`），所以「只为交付子库而最小化构建」时该开关不能关；同时 `cmake --build --target` 一旦只编子库目标，`cmake --install` 会对 install(TARGETS) 里**未构建**的目标报 `file INSTALL cannot find …`（CMake 不会跳过缺失产物），必须让构建目标集合 ⊇ install(TARGETS) 全集。②【N 口径】外部审查是脚本化 rule4「上游实测 N > 声明 N 即不通过」，而子包声明自己的用例数必然小于父 tarball 全量注册面（libgmpxx 实测：自身 22 vs 父面 190/200 → FAIL）。CMake 工程还有第三层：`gtest_discover_tests` 的 ctest 用例数**不是静态可读的**——每个 `HWY_EXPORT_AND_TEST_P` 注册点会按运行时支持目标数展开（Highway aarch64 实测 ×2），只按 `add_test` 或源文件数申报同样会被下一轮口径超过。
