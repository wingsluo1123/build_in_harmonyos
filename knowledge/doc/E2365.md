# E2365: LLVM 系编译器运行时库在 OHOS/musl 上引用 glibc 专属扩展（feenableexcept）致未定义符号：需按 AArch64 FPCR 直写替代，并只切出可独立编译的 C 运行时代码

## 基本信息
- **严重度**: 2
- **类别**: portability, toolchain, fortran, runtime
- **作者**: Hawkninja21
- **来源 PR**: 11519

## 错误特征
```
call to undeclared function 'feenableexcept'|undefined reference to 'feenableexcept'|undefined symbol: feenableexcept|U feenableexcept
```

## 根因分析
LFortran（LLVM 系现代 Fortran 编译器）的 C 运行时库 liblfortran_runtime（src/libasr/runtime/lfortran_intrinsics.c）中 _lfortran_enable_fpe_traps() 在 #elif defined(__linux__) 分支调用 feenableexcept()（lfortran_intrinsics.c:8524）。feenableexcept 是 GNU/glibc 扩展，OHOS 使用的 musl 不提供——OHOS SDK sysroot 的 libc.so 仅导出 fegetexceptflag，无 feenableexcept。实测该符号是 liblfortran_runtime 在 OHOS 上唯一的非 libc/libm 未定义符号（llvm-nm -D -u）：编 .so 时因 -shared 默认允许未定义符号而看似通过，运行期调用该函数即符号解析失败；编静态库并被消费者调用时链接期直接 undefined reference。次要子模式=组件切分：上游顶层 CMake 强依赖 LLVM/MLIR 全量编译编译器主体，而运行时库本身是可独立编译的单文件 C（唯一前置 libasr/config.h，上游由 CMake configure_file 生成，全特性关闭时仅版本宏），因此正确做法是只切出该 C 运行时组件独立构建；Fortran 侧运行时模块（src/runtime/*.f90，CMAKE_Fortran_COMPILER=lfortran 自举）在无 LFortran 编译器的 OHOS 上不可交付。

## 推荐方案
**方法**: non-glibc-guarded-portable-replacement

**说明**: 在保留 glibc 路径的前提下，为 glibc 之外的 libc 追加等价实现，守卫用 POSIX 语义（__GLIBC__/__aarch64__）而非平台名（避免 __OHOS__ 空壳语意、符合「源码修改四不」）。对 feenableexcept：以 ARMv8-A FPCR 的 trap-enable 位（8=IOE/9=DZE/10=OFE/11=UFE/12=IXE）直接 mrs/msr 读写替代（与该文件既有 Apple/ARM64 分支同一手法）：#if defined(__GLIBC__) feenableexcept(excepts); #elif defined(__aarch64__) { mrs fpcr; 置位; msr fpcr; } #else (void)excepts; #endif。同时按「组件切分」只编译可独立编译的 C 运行时源文件，私有生成 libasr/config.h（等价于上游 configure_file 在全特性关闭时的产物），产出与上游同名的 .a/.so 与头文件。仓内先例：openfast 的 flang-ohos 全链经验（-resource-dir/-L<sdk>/llvm/lib/aarch64-linux-ohos 分工）。

**修复命令**:
```
conanfile.py build()（摘要）：cc=self.conf.get("tools.build:compiler_executables")["c"]; ar=dirname(cc)/llvm-ar; self.run(f'{cc} -O2 -fPIC -I"src" -I"inc" -c .../lfortran_intrinsics.c -o lfortran_intrinsics.o'); self.run(f'{ar} rcs liblfortran_runtime_static.a lfortran_intrinsics.o')；generate(): 写 inc/libasr/config.h（版本宏）；patches/0001-musl-feenableexcept-fallback.patch 提供 __GLIBC__/__aarch64__ 守卫实现。
```

**验证**:
```
①编译并查看未定义符号：clang -O2 -fPIC -I<src>/src -I<inc> -c <src>/src/libasr/runtime/lfortran_intrinsics.c -o o.o 后 llvm-nm -u o.o | grep feenableexcept（未打补丁时命中）；②核对 musl 不提供：llvm-nm -D --defined-only <sysroot>/usr/lib/aarch64-linux-ohos/libc.so | grep -c feenableexcept 为 0；③补丁后复验：应用 0001 后 clang ... -shared 产出 .so，llvm-nm -D -u 中 feenableexcept 消失（其余 157 个未定义符号全为 libc/libm 标准符号），且 test_package 调用 _lfortran_enable_fpe_traps(1) 不崩溃。
```
