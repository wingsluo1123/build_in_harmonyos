# E2372: "CMake>=4 的 CMAKE_POLICY_VERSION_MINIMUM 必须经命令行 cache 传入，toolchain 文件变量无效"

## 基本信息
- **严重度**: P1
- **类别**: build-system
- **作者**: DS-7
- **来源 PR**: PRE_CREATE

## 错误特征
```
"Compatibility with CMake < 3.5 has been removed.*CMakeLists.txt.*cmake_minimum_required"
```

## 根因分析
"CMake>=4 删除了 <3.5 policy 兼容。cmake_minimum_required 在 CMakeLists 顶部执行，而 CMakeToolchain 文件在 project() 时才加载——通过 conan tc.variables[...] 传的 CMAKE_POLICY_VERSION_MINIMUM 是普通变量，写入 toolchain 文件，加载时机晚于 cmake_minimum_required，因此完全不生效（配置仍然失败）。经验汇总 §12.2 已提示'老 policy 变量需在 configure(variables=...) 显式传递'，但未说明根本原因与 toolchain 无效的机理。"

## 推荐方案
**方法**: "把 CMAKE_POLICY_VERSION_MINIMUM 作为命令行 cache 变量传入：conan 配方中写 cmake.configure(variables={'CMAKE_POLICY_VERSION_MINIMUM': '3.5'})（CMake helper 会以 -D 参数传给 cmake，cache 初始化先于 CMakeLists 执行）；等价命令行 cmake -DCMAKE_POLICY_VERSION_MINIMUM=3.5 ..。"

**说明**: (待补充)

**修复命令**:
```
"cmake.configure(variables={\"CMAKE_POLICY_VERSION_MINIMUM\": \"3.5\"})  # conan 配方内"
```

**验证**:
```
"grep -n 'CMAKE_POLICY_VERSION_MINIMUM' CMakeCache.txt  # 配置成功的构建目录应含 UNINITIALIZED=3.5"
```
