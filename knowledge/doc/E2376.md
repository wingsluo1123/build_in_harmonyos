# E2376: GCC/Clang 泛化分支中的 x86 "lock; xadd" 内联汇编在 aarch64 交叉面必炸：__atomic_fetch_add 内建是零语义漂移的等义替换（返回旧值 + 全屏障）

## 基本信息
- **严重度**: 1
- **类别**: arch-portability-inline-asm
- **作者**: unknown

## 错误特征
```
"unrecognized instruction mnemonic|did you mean: add, addp, adds, addv, fadd, madd"
```

## 根因分析
"一些 2010s 库把 boost 的 atomic_count_gcc_x86 实现拷进 '#if _MSC_VER / #elif SUNPRO/AIX / #else' 链的最后一只 #else 分支，分支判据只有编译器厂牌、没有目标架构判据 —— 在 aarch64 上clang 走进这只分支后，x86 专用的 'lock\n\t xadd %1, %0' 内联汇编被本地汇编器拒绝，报 'unrecognized instruction mnemonic: lock'（并把 xadd 误推荐为 add/addp/adds/addv/fadd/madd）。quickfix 1.15.1 的 src/C++/AtomicCount.h:163 即此形态：arm/i386 之外的每一个 GCC/Clang 目标（aarch64/riscv/loongarch…）都会命中。"

## 推荐方案
**方法**: replace-inline-asm-with-atomic-builtin

**说明**: 把 atomic_exchange_and_add 的内联汇编体替换为 __atomic_fetch_add(pw, dv, __ATOMIC_SEQ_CST)：内建返回"修改前"的旧值，与 xadd 的返回值语义一致；SEQ_CST 提供与原 "memory","cc" clobber 等价的全屏障。函数签名、调用点的 +1/-1 语义都不动，补丁是纯局部替换、全架构可用、可上游化。不要用 mutex 兜底分支（语义漂移 + 性能回退），也不要手写 aarch64 的 ldxr/stxr 内联汇编（维护成本高且 clang 有更好的内建）。

**修复命令**:
```
conan create archives/q/quickfix/1.15.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
"d=\"$PWD/atomiccount-probe\" && mkdir -p \"$d\" && printf 'int main(){ int v=0; return (__atomic_fetch_add(&v,1,__ATOMIC_SEQ_CST)!=0); }\n' > \"$d/probe.c\" && clang -fsyntax-only \"$d/probe.c\" && echo \"builtin OK on this target\""
```
