# E2386: shell 补全脚本包的 test_package 需要「双桩」：被补全命令桩（满足脚本顶部 `command -v <cmd>` 守卫并喂子命令列表）+ bash-completion 框架函数桩；另外收窄 PATH 做负向测试必须在子 shell 内部进行，否则连解释器都找不到

## 基本信息
- **严重度**: 2
- **类别**: portability, testing, shell
- **作者**: nyaco3 <aqjCItYW1QmEJQuF.gcw_XDpqZ8sO@noreply.gitcode.com>

## 错误特征
```
complete: [a-z-]+: no completion specified|bash: _get_comp_words_by_ref: command not found|_filedir: command not found|bash: command not found|COMPREPLY.*(empty|未生成)|declare -F _[a-z]+.*not found
```

## 根因分析
现代 shell 补全脚本普遍有两项运行期前提。其一是**存在性守卫**：整段定义挂在 `command -v <cmd> >/dev/null 2>&1 &&` 之后（cargo.bashcomp.sh 的函数定义与 `complete -F _cargo cargo` 由 `&&` 串成一条链），PATH 里没有被补全命令时函数不定义、补全不注册——CI clean 环境几乎不会装被补全的命令（cargo/docker/pip），于是 `complete -p <cmd>` 报 "no completion specified"，容易被误读为"脚本损坏"，测试作者转而退化成 `grep 'complete -F'` 这种字符串断言（PF3/L1e 判定为空壳）。其二是**框架依赖**：脚本调用 bash-completion 提供的 `_get_comp_words_by_ref`/`_filedir`/`_comp_command_offset`，clean 环境未必装 bash-completion，直接驱动补全函数会报 command not found。此外负向测试（验证守卫生效）若在**外层**写 `PATH=<empty> bash -c …`，会连 `bash` 自身都无法定位，报 `bash: command not found`——失败原因与被测对象无关，是夹具自身 bug。

## 推荐方案
**方法**: double-stub-harness-for-completion-tests

**说明**: test_package 自带两个夹具：①被补全命令桩（可执行脚本，实现脚本真正调用的子命令，如 `cargo --list` 输出 "Installed Commands:" + 子命令表，供 `awk 'NR>1 {print $1}'` 解析），放进 PATH 满足守卫；②bash-completion 框架函数桩（`_get_comp_words_by_ref` 把 COMP_WORDS/COMP_CWORD 映射到 cur/prev/words/cword，`_filedir`/`_comp_command_offset` 置空）。桩函数内**不得**用 local，靠 bash 动态作用域写回补全函数里已声明的 `local cur prev words cword`。再用 `COMP_WORDS=(cmd "")` + `COMP_CWORD=1` 直接驱动补全函数并断言 COMPREPLY 内容，即可在零外部依赖下做到真实功能验证（R34/PF3）。负向断言（无命令时不注册）把 PATH 收窄写在子 shell **内部**：`bash -c 'PATH="$2"; source "$1"; declare -F _cmd …' _ <file> <emptydir>`，source/declare/echo 均为内建。

**修复命令**:
```
printf '%s\n' '_get_comp_words_by_ref(){ local a; for a in "$@"; do case $a in cur) cur="${COMP_WORDS[COMP_CWORD]}";; prev) prev="${COMP_WORDS[COMP_CWORD-1]:-}";; words) words=("${COMP_WORDS[@]}");; cword) cword=$COMP_CWORD;; esac; done; }' '_filedir(){ :; }' '_comp_command_offset(){ :; }' > harness.bash
```

**验证**:
```
bash -c 'PATH="$STUB_DIR:$PATH"; source harness.bash; source <completion_file>; complete -p <cmd>; COMP_WORDS=(<cmd> ""); COMP_CWORD=1; _<cmd>; printf "%s\n" "${COMPREPLY[@]}"'  # 期望输出 -F _<cmd> 与非空候选
```
