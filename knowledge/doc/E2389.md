# E2389: 单头 SIMD 封装库后端激活验证契约：OHOS clang 仅预定义 __ARM_NEON（无 __ARM_NEON__），编译通过与 API 断言均不足以证明后端激活——需先于 include 的双拼写编译期门禁 + 不透明输入 + 指令级反汇编三重证据

## 基本信息
- **严重度**: 2
- **类别**: ohos, headers, consumer-testing, simd-backend, verification
- **作者**: device-b
- **来源 PR**: 11245

## 错误特征
```
neither __ARM_NEON__ nor __ARM_NEON defined|__ARM_NEON__ not defined on aarch64|use of undeclared identifier .float32x4_t.
```

## 根因分析
OHOS SDK clang（aarch64-unknown-linux-ohos）只预定义 __ARM_NEON 而不定义 __ARM_NEON__（标准 aarch64 clang/gcc 两者皆有），依这两种拼写做后端分发的单头 SIMD 库与消费者探针都会误判；同时纯头文件打包不打编译标志使宏选择对打包方不可见，API 断言数值与后端无关，-O3 又会把常量输入的向量路径完全折叠（实测向量指令数为 0），三层混淆叠加导致『打包成功+测试通过』与『SIMD 后端激活』之间没有验证链

## 推荐方案
**方法**: simd-backend-three-layer-evidence

**说明**: 消费者测试固定三层证据且各层有已知混淆因子须主动排除：①编译期双拼写宏门禁（aarch64 上 __ARM_NEON__ 与 __ARM_NEON 任一即可，且必须置于 #include <psimd.h> 之前，否则被测头的误导性报错先行）；②API 已知值断言用 __asm__ volatile("" : "+r"(x)) 不透明输入（否则 -O3 常量折叠后二进制零向量指令）；③llvm-objdump 反汇编计数 blend 路径的 bsl 族指令（vbslq_s8 专属映射，可区分回退形态）。禁止把 fmla 存在或 qfma 融合数值当后端证据

**验证**:
```
llvm-objdump -d test_psimd | grep -cE 'bsl|bit|bif' （>0 配合双拼写宏门禁与不透明输入 = blend NEON 路径激活；完整五步证据链见同名 .md 与 reports/knowledge-evidence.md）
```
