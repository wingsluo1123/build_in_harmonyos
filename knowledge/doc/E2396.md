# E2396: Conan 预编译 C++ 模块进入 HAP 后的 SDK 运行库装载契约（E088 扩展）

## 基本信息
- **严重度**: 2
- **类别**: ohos, linking, packaging, runtime
- **作者**: 9C4A

## 错误特征
```
load libc++_shared.so failed, namespace=ndk no inherits|namespace=moduleNs_default|Error loading shared library libc++_shared.so
```

## 根因分析
Conan shell 消费者与 HAP 应用的动态链接命名空间不同；预编译工程仅复制业务模块时遗漏动态 SDK C++ 运行库，系统同名库存在并不能证明应用可见。

## 推荐方案
**方法**: package-matching-sdk-runtime-in-hap-private-libs

**说明**: 定位实际消费者和 NEEDED；从实际 C++ 编译器查询匹配 SDK libc++_shared.so，校验路径存在；安装到 HAP 工程目标 ABI 私有库目录并保留 SDK NOTICE；消费者检查包内容，最终 HAP 实机调用原生功能，并比较 strip 前后的 ELF 分配节。

**修复命令**:
```
详见配套 Markdown 中 CMake 片段与 HAP 验证命令。
```

**验证**:
```
llvm-readelf -d libboulderhost.so；核查最终 HAP libs/arm64-v8a 后安装并进入原生游戏/编辑器；见随附可复现步骤和证据报告。
```
