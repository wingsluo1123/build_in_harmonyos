# E2408: 上游 Makefile 测试目标硬编码 gcc 时，无 gcc 的 OHOS 平台用 clang 等价编译（保持 -std=c89 -Wall -Wextra -Wpedantic -Werror）并显式 -Wno-tautological-constant-out-of-range-compare 抑制 clang 独有诊断；上游测试 16/16 全绿

## 基本信息
- **严重度**: 2
- **类别**: ohos, make, toolchain, gcc-missing, upstream-tests
- **作者**: unknown

## 错误特征
```
/bin/sh: gcc: inaccessible or not found|make: \*\*\* .* Error 127|clang-?[0-9]*: error: result of comparison of constant -1 with expression of type 'char' is always false \[-Werror,-Wtautological-constant-out-of-range-compare\]|error: .* -Wtautological-constant-out-of-range-compare
```

## 根因分析
①OHOS PC 平台无 gcc（仅 clang），而上游 Makefile 的测试目标（如 test_optimized）硬编码 gcc 编译命令，直接执行报 "gcc: inaccessible or not found"（exit 127）；②换用 clang 等价编译后，clang 对"无符号目标上 `char == -1` 恒假"类比较给出 -Wtautological-constant-out-of-range-compare 诊断，在上游 -Werror 严格度下硬失败——该诊断 gcc 从不触发，属编译器实现差异而非源码缺陷；OHOS AArch64 上 plain char 默认为无符号进一步放大此类比较。

## 推荐方案
**方法**: clang 以与上游 gcc 完全等价的参数编译（同一 -std/-Wall/-Wextra/-Wpedantic/-Werror/-O/-ldl），仅追加 -Wno-tautological-constant-out-of-range-compare 抑制 clang 独有诊断；若源码用 plain char 存有符号状态（AVL 平衡因子 -1/0/1、EOF 哨兵等）再追加 -fsigned-char 恢复上游语义。不改上游测试一行。

**说明**: (待补充)

**修复命令**:
```
clang src/*.c tst/*.c -Wall -Wextra -Wpedantic -Werror -Wno-tautological-constant-out-of-range-compare -fsigned-char -std=c89 -O3 -ldl -o ContainersTest && ./ContainersTest
```
