## 错误特征
```
"File was truncated|ttyrec2ansi.*output.*missing tail byte|command substitution.*NUL byte|ttyrec.*header.*len field"
```

## 根因分析
"OHOS system shell (mksh) and bash both strip NUL bytes from the byte stream during $(...) command substitution (NUL cannot be represented in the result string), while the upstream testsuite writes binary inputs to temp files and compares output files with cmp. Any upstream test or consumer harness that round-trips binary data (ttyrec headers, termios sequences, escape payloads) through command substitution gets silently corrupted data."

## 推荐方案
**方法**: "Always transport binary test data (headers with \\x00, escape sequences, ttyrec frames) via temp files (printf > file, then tool < file > outfile, compare with cmp/cat) instead of $(...) command substitution. This matches the upstream testsuite technique (stdin.$id / stdout.$id) and keeps NUL bytes intact. For pty-based tools (pipetty), also invoke the child through a script FILE (pipetty </dev/null sh script.sh) rather than `pipetty sh -c '...'`, which fails on OHOS mksh."
