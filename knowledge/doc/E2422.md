# E2422: OHOS GLib 上 GApplication 的 ARG_CALLBACK 选项在解析内调用 exit() 会 futex 死锁（仅 --help 可退出）

## 基本信息
- **严重度**: 2
- **类别**: ohos, deadlock, exit, futex, gapplication
- **作者**: unknown

## 错误特征
```
siril-cli --version 无输出|futex 死锁|wchan FUTEX|进程挂起不退出
```

## 根因分析
通过 g_application_run()/g_application_add_main_option_entries 注册的 G_OPTION_ARG_CALLBACK 选项（如 --version/--copyright）在回调里调用 exit() 时，OHOS 的 glib 实现在选项解析路径持有内部锁/会话资源，exit() 触发的清理在同一线程上再等该锁 → 永久 futex 阻塞。GLib 内建 --help 走错误返回路径，不受影响，因此症状是"--help 能退、用户回调选项全挂死"。

## 推荐方案
**方法**: pre-gapplication-print-options

**说明**: 在 main() 里创建 GApplication 之前，手工扫描 argv 识别纯"打印并退出"选项（--version/-v、--copyright/-c、--format/-f 等），printf 后直接 return，完全不进入 g_application_run()；输出格式与上游 GOptionEntry 回调保持一致。普通启动与其余选项照旧走 GApplication。

**修复命令**:
```
在 main() 开头调用 _cli_handle_early_print_options(argc, argv)，命中即 return EXIT_SUCCESS；保留 --help 交给 glib 内建处理
```

**验证**:
```
timeout 10 <打包>/bin/<cli> --version; echo $?
```
