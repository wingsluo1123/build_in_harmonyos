# E2423: OHOS 目标机上 autotools 的 conftest 无法执行——必须传 --host/--build 让 autoconf 进入 cross 模式

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, ohos, autotools, configure, cross-compile
- **作者**: unknown

## 错误特征
```
cannot run C compiled programs.|If you meant to cross compile, use .--host.|Error loading shared library libcairo.so.2|checking whether we are cross compiling
```

## 根因分析
configure 的 conftest 链接 conan 依赖后会带出 NEEDED 的动态库（gtk/cairo/opencv…），而这些 .so 位于 .conan2 HMDFS 缓存路径，运行时加载器默认不搜索；此外本机无会话总线，GLib/GTK 库加载还可能二次死锁。autoconf 在"本机模式"下执行 ./conftest 失败 → "cannot run C compiled programs"。

## 推荐方案
**方法**: autoconf-cross-triplet-args

**说明**: 在 AutotoolsToolchain.configure_args 显式传 `--build=x86_64-unknown-linux-gnu` 与 `--host=aarch64-unknown-linux-ohos`，使 host≠build、autoconf 判定 cross_compiling=yes，从而跳过一切 conftest 执行（仅编译/链接探测）。同时检查 configure.ac 中所有 `test "$cross_compiling" != "yes"` 分支：会把内置子构建（如 siril 的 htmesh、librtprocess）改成 AC_MSG_ERROR 的，需改为允许走 cmake 内部构建或降级为可选。

**修复命令**:
```
tc.configure_args.append("--build=x86_64-unknown-linux-gnu"); tc.configure_args.append("--host=aarch64-unknown-linux-ohos"); 处理 cross 分支中的 AC_MSG_ERROR
```

**验证**:
```
conan create archives/<软件>/<版本> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
