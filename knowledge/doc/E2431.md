# E2431: OHOS 设备 uname -s 返回 HarmonyOS：上游 Makefile 按 uname 分支选择链接规则时，HarmonyOS 不匹配任何分支导致共享库/插件目标静默变空；非 override 变量用 make 命令行参数（非环境前缀）覆盖即可

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, build-system, make
- **作者**: unknown

## 错误特征
```
Nothing to be done for 'all'|unable to find library -l|undefined reference to pe_|No rule to make target.*\.so|PLATFORM_OS
```

## 根因分析
大量纯 Makefile 工程用 `PLATFORM_OS := $(shell uname | cut -d_ -f1)` 之类写法按内核名分支选择链接/安装规则，分支只有 Linux/*BSD/GNU/Darwin/CYGWIN。OHOS 设备 `uname -s` 返回 `HarmonyOS`，所有 ifeq 分支都不命中：共享库或插件目标的配方为空，make 把它当"无事可做"（Nothing to be done）静默跳过——不报错、继续编其余目标，直到下游链接 `-l<name>` 才以 unable to find library 暴露，形态极易被误判成"上游源码损坏"或"依赖缺失"。两个加重因素：①若变量以**环境变量前缀**传入（`PLATFORM_OS=Linux make`），子 Makefile 里的 `PLATFORM_OS := $(shell uname…)` 是普通赋值，会覆盖环境值，伪装成"已经传了还不好使"；②目标若无 .PHONY 且配方为空，重跑也是 Nothing to be done，缓存假绿。

## 推荐方案
**方法**: pass-platform-os-as-make-command-line-argument

**说明**: 修复分两步，方向反了会白折腾：①传参方式必须是 **make 命令行参数**（`make PLATFORM_OS=Linux …`，变量名与上游一致），命令行变量随 MAKEFLAGS 传递到全部子 make 且优先级高于 Makefile 内普通赋值；环境前缀（`PLATFORM_OS=Linux make`）无效——子 Makefile 的 `:= $(shell uname…)` 普通赋值会覆盖环境值。与 autotools 家族"config.guess 不识别 HarmonyOS 就显式传 --host=aarch64-unknown-linux-ohos 三元组"（abiword-plugin-* 先例）同一思想：不识别就不让上游猜。②验收必须看"目标真的产出文件"而不是 make 退出码：确认 lib*.so/插件 .so 实际存在，或对空配方场景 grep 构建日志确认无 Nothing to be done。选择分支值时用 Linux（OHOS 上 musl+ELF 语义与 Linux 分支完全一致），不要新增 HarmonyOS 分支去改上游 Makefile——命令行覆盖零补丁，返修面最小。

**修复命令**:
```
make -j1 PLATFORM_OS=Linux CC=clang AR=llvm-ar CFLAGS="-I<openssl>/include" LDFLAGS="-L<openssl>/lib"
```

**验证**:
```
uname -s; grep -c "PLATFORM_OS=Linux" "$HOME/ws/worktrees/pev-0.82/archives/p/pev/0.82/conanfile.py"
```
