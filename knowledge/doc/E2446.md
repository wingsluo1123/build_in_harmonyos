# E2446: "Vendor every build input in conandata.yml as separate keys 

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, recipe
- **作者**: unknown

## 错误特征
```
"conan/CI build fails on 'Can't find file to patch' for a file that the upstream Makefile generates mid-build, or the build stalls/fails at a wget/curl/git clone step embedded in the upstream Makefile (OWLURL-style bootstrap downloads)"
```

## 根因分析
"Self-hosting projects compile a bootstrap tool first (here: Owl Lisp from a pinned precompiled C source), use it to generate the real source file (rad/*.scm -> radamsa.c), then compile the artifact. Package metadata systems assume all patched inputs exist before the build, so registering a patch against the generated file and applying it up front always fails; and upstream Makefiles that fetch the bootstrap/library over the network during build break hermetic CI builds."

## 推荐方案
**方法**: "Vendor every build input in conandata.yml as separate keys (main tarball via sources:, bootstrap via e.g. owl_bootstrap:, library archive via hex_library:) and download them as raw files with sha256 verification; recreate the upstream layout in build() before compiling the bootstrap tool; run the generation step, then apply the platform patch to the just-generated file with 'patch -p1' from build(), and only then run the final compile. Keep the conandata patches: entry for metadata visibility but document why apply_conandata_patches() must NOT be called at build start. Prove determinism by building twice and comparing sha256 of the generated file before relying on the patch applying cleanly."
