# E2447: "Inside the runtime's poll/select wrapper, pre-check each fd

## 基本信息
- **严重度**: 1
- **类别**: platform, compat, runtime
- **作者**: unknown

## 错误特征
```
"process hangs (State=S, wchan=EVENTPOLL, CPU time frozen) exactly when stdout is redirected to /dev/null or /dev/zero; same command with stdout to a pipe or regular file completes normally"
```

## 根因分析
"OHOS musl/kernel never reports POLLOUT (writability) for character devices: poll(fd=/dev/null or /dev/zero, POLLOUT) returns 0 revents at any finite timeout and select()/poll() with infinite timeout never return at all — while write(2) to the same fd succeeds and POLLIN on /dev/null as well as POLLOUT on pipes and regular files all behave correctly. Runtimes that implement non-blocking ports as poll-then-write (Owl Lisp VM do_poll using select(nfds,...,NULL); same pattern possible in other script-language VMs and event loops) therefore sleep forever as soon as stdout is redirected to /dev/null or /dev/zero."

## 推荐方案
**方法**: "Inside the runtime's poll/select wrapper, pre-check each fd in the WRITE set with fstat(): if S_ISCHR(st.st_mode), treat the fd as immediately writable and return without calling select/poll. Keep pipes, sockets and regular files on the native path (their POLLOUT reporting is correct on OHOS, and pipes need real backpressure). This is a ~14-line patch at the single choke point where the VM maps Scheme ports to poll(fd)."
