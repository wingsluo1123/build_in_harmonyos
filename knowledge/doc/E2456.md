# E2456: 浮点→无符号直接转型是架构分歧 UB：MSVC/x86 参考实现产出补码模式而 aarch64 fcvtzu 饱和为 0，跨架构等价写法须经 int64_t 中转（rcheevos 5/2712 上游测试失败实证）

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, musl, compiler, testing
- **作者**: device-b
- **来源 PR**: 11282

## 错误特征
```
Found:[[:space:]]+0 == -1$|Found:[[:space:]]+5900 == 4100|implicit declaration of function .fseeko.
```

## 根因分析
C 标准中负浮点直接转无符号是未定义行为，各架构合法实现不同——MSVC/x86 参考路径产出测试套件编码的补码模式（-1.0f→0xFFFFFFFF），而 aarch64 的 fcvtzu 指令对负值饱和为 0，导致依赖该 UB 的上游测试在 aarch64 失败；同类构建期问题：musl 把 fseeko64/ftello64 定义为指向 fseeko/ftello 的无条件宏，但严格 -std=c89（无 feature 宏）下 musl 隐藏这些 POSIX 声明，-Werror 构建报 implicit declaration

## 推荐方案
**方法**: float-to-unsigned-via-int64-plus-default-source

**说明**: 浮点→无符号改为 (unsigned)(int64_t)f 中转，复现 MSVC/x86 参考语义且各架构一致（正负值均正确，包括 [INT_MAX,2^31) 区间）；c89 严格构建的 musl LFS 调用补 -D_DEFAULT_SOURCE 暴露 fseeko/ftello 声明（*64 名只是无条件宏别名，无独立符号）

**验证**:
```
make -C test ARCH=x64 CC=clang runtests （修复前 2707/2712，补 int64 中转后 2712/2712）
```
