# E2459: CMakeToolchain 默认 CMAKE_FIND_PACKAGE_PREFER_CONFIG=ON：上游 find_package 命中了 config 却拿不到经典大写变量，构建静默变成空壳

## 基本信息
- **严重度**: 3
- **类别**: detection, cmake, toolchain, conan, dependency
- **作者**: OpenDesk <opendesk@local>

## 错误特征
```
Can't find OpenSSL.*stop .* building|Can't find zlib.*stop .* building|NOT [A-Z_]+_FOUND[^\n]*return\(\)|find_package\([A-Za-z0-9_]+\) 命中 config 但 [A-Z_]+_FOUND 仍未定义
```

## 根因分析
conan 的 CMakeToolchain 在 generic_system 块里默认写 set(CMAKE_FIND_PACKAGE_PREFER_CONFIG ON)（conf tools.cmake.cmaketoolchain:find_package_prefer_config 默认 True；实测生成文件第 137/139 行）。于是上游裸 find_package(OpenSSL) 优先走 CONFIG 模式，命中 CMakeDeps 生成的 openssl-config.cmake，而后者只定义小写 openssl_* 变量与 openssl::openssl 目标；上游依赖的经典 MODULE 变量（OPENSSL_FOUND / OPENSSL_INCLUDE_DIR / OPENSSL_LIBRARIES / OPENSSL_CRYPTO_LIBRARY / OPENSSL_SSL_LIBRARY）一个都不存在。若上游用 if (NOT OPENSSL_FOUND) 做门禁并 return()，configure 只打印 WARNING 就静默放弃后半段配置——不报错、但目标全不生成（比硬失败更隐蔽）。

## 推荐方案
**方法**: bridge-classic-find-vars-to-conan-package

**说明**: 在 generate() 里把经典变量显式接到 conan 包（不改上游源码、不动 PREFER_CONFIG）：置 XXX_FOUND=True 并在需要时给出 INCLUDE/LIB 路径，使上游门禁通过且 include/link 指向 conan 包。若上游用 imported target 则无需此步。

**修复命令**:
```
tc.cache_variables["OPENSSL_FOUND"]=True; tc.cache_variables["OPENSSL_ROOT_DIR"]=pkg; tc.cache_variables["OPENSSL_INCLUDE_DIR"]=pkg+"/include"; tc.cache_variables["OPENSSL_CRYPTO_LIBRARY"]=pkg+"/lib/libcrypto.a"; tc.cache_variables["OPENSSL_SSL_LIBRARY"]=pkg+"/lib/libssl.a"; tc.cache_variables["OPENSSL_LIBRARIES"]=ssl+";"+crypto
```

**验证**:
```
grep -n "PREFER_CONFIG" <generators>/conan_toolchain.cmake   # 默认 ON；再 grep configure 日志是否出现 "Can't find .*: stop .* building"
```
