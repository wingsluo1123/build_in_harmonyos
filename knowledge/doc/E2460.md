# E2460: OHOS 共享库缺 DT_SONAME 的第二症状：install(EXPORT) 生成的 *Targets-release.cmake 被打上 IMPORTED_NO_SONAME，下游只能按完整路径链接（CI L5c 拦截）

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, linking, packaging, relocatable
- **作者**: OpenDesk <opendesk@local>

## 错误特征
```
缺少 DT_SONAME|IMPORTED_NO_SONAME TRUE|soname_gate_failed|L5_RESULT=fail: soname_gate_failed|L5c:.*\.cmake.*IMPORTED_NO_SONAME
```

## 根因分析
根因与既有 libharu/E383 条目相同：CMake 4.1.2 无 Platform/HarmonyOS.cmake（只有 Platform/OHOS.cmake，内容仅 include(Platform/Linux)，而 conan 把 os=OHOS 映射为 CMAKE_SYSTEM_NAME=HarmonyOS），使 CMAKE_SHARED_LIBRARY_SONAME_{C,CXX}_FLAG 为空、链接模板 <SONAME_FLAG> 为空 ⇒ .so 无 DT_SONAME。**增量**：CMake 的 export 生成器在写 IMPORTED_* 时，会依据同一 SONAME flag 是否为空来决定 IMPORTED_NO_SONAME 与 IMPORTED_SONAME——flag 为空 ⇒ 导出的 xxxTargets-release.cmake 里带 `IMPORTED_NO_SONAME TRUE`，下游 find_package 后只能按完整路径（而非 -lfoo + SONAME）链接，CI 的 L5c 门禁会直接判 fail。即「一个缺失的平台模块」同时污染了产物 ELF 与它的 CMake 包元数据。

## 推荐方案
**方法**: rules-override-soname-flag

**说明**: 在 generate() 写一份规则文件，把 CMAKE_SHARED_LIBRARY_SONAME_{C,CXX}_FLAG 恢复为 -Wl,-soname,，并用 CMAKE_USER_MAKE_RULES_OVERRIDE_{C,CXX} 指向它（该 override 在 CMakeCInformation/CMakeCXXInformation 中、平台模块之后被 include，故能覆盖）。此时工具链/链接规则在 project() 之后才生效，因此 tc.cache_variables 注入是可行的（与 CMAKE_POLICY_VERSION_MINIMUM 的时机陷阱相反）。

**修复命令**:
```
save(self, rules, 'set(CMAKE_SHARED_LIBRARY_SONAME_%s_FLAG "-Wl,-soname,")\n' % lang); tc.cache_variables["CMAKE_USER_MAKE_RULES_OVERRIDE_%s" % lang] = rules
```

**验证**:
```
llvm-readelf -d <pkg>/lib/libfoo.so | grep -E 'SONAME|NEEDED' ; grep -n 'IMPORTED_SONAME\\|IMPORTED_NO_SONAME' <pkg>/lib/cmake/<Pkg>/<Pkg>Targets-release.cmake
```
