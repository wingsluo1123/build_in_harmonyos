# E2473: "CLI 工具消费者测试的断言只选两类管道可观测证据：①stdout 重定向后的文件内容（-F 等整页直通路径的输出）；

## 基本信息
- **严重度**: P2
- **类别**: conan, testing, cli
- **作者**: unknown

## 错误特征
```
"smoke: .* missing (line|numbered|diagnostic)|grep -q.*out.txt.*fail|cli assertion passed standalone but failed in conan test|rc=0 on missing file|stdin: /dev/null"
```

## 根因分析
"conan 2 的 test() 阶段以 env=\"conanrun\" 执行消费者脚本时，进程的 stdin 被接到 /dev/null（VirtualRunEnv 无 tty）。这使 CLI 分页器/交互工具的可观测行为与手工运行不一致：①显示层特性（less -N 行号、 -M 提示符等）只存在于 tty 渲染路径，管道输出里根本不出现；②读取 stdin 的工具（less 在参数文件打开失败后回落读 stdin）读到 EOF 后'正常'退出，错误场景 rc 反而为 0。把手工终端里的行为预期直接写成断言，必然假阴性。"

## 推荐方案
**方法**: "CLI 工具消费者测试的断言只选两类管道可观测证据：①stdout 重定向后的文件内容（-F 等整页直通路径的输出）；②stderr 诊断文本（grep 错误关键词）。交互/显示层特性要么不进消费者测试、要么用上游自带的脚本化仿真套件（如 less 自带的 lesstest：pty + 模拟终端）承载。"

**说明**: (待补充)

**修复命令**:
```
"less -F missing.txt < /dev/null > /dev/null 2>err.txt || true; grep -qi 'no such' err.txt  # 断言 stderr 诊断而非 rc"
```
