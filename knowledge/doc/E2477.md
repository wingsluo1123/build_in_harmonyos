# E2477: "测试框架一律用 self.test_requires()（写在 build_requirements() 里，host

## 基本信息
- **严重度**: P1
- **类别**: cmake, conan, testing
- **作者**: unknown

## 错误特征
```
"fatal error: 'gtest/gtest.h' file not found|fatal error: 'gmock/gmock.h' file not found|fatal error: 'benchmark/benchmark.h' file not found|INCLUDE_DIRS_RELEASE\\s*\\)"
```

## 根因分析
"Conan 2.29 的 CMakeDeps 为 build 上下文包（类属性 tool_requires / build_context_activated 激活的依赖）生成的 *-data.cmake 中 INCLUDE_DIRS 为空——GTest-release-armv8-data.cmake 里 set(gtest_GTest_gtest_INCLUDE_DIRS_RELEASE )（空），而同一构建目录中 host 上下文依赖（tinyxml2/qhull 等）的同一变量正常展开为 ${pkg}/include。结果：配方 build() 里编译上游测试 TU 时编译行没有任何测试框架的 -I，configure 阶段 find_package 能找到目标（config 存在）但编译必炸 'gtest/gtest.h' file not found，错误看似'头文件没装'实为上下文选择错误。"

## 推荐方案
**方法**: "测试框架一律用 self.test_requires()（写在 build_requirements() 里，host 上下文、不传递给消费者），不要用类属性 tool_requires 也不依赖 build_context_activated：host 上下文的 CMakeDeps 数据文件 INCLUDE_DIRS 正常生成，find_package(GTest) 拿到的 GTest::gtest 目标自带 include 传播，测试 TU 编译行自动获得 -I。仓库先例：adept-math/2.1.3 用 self.test_requires('gsl/2.8') 供上游测试。判别方法：检查 build/<config>/generators/<Pkg>-*-data.cmake 中 INCLUDE_DIRS 是否为空，同时对照一个 host 依赖的同名变量即可定位是上下文问题而非包损坏。"

**说明**: (待补充)

**修复命令**:
```
"def build_requirements(self): self.test_requires('gtest/1.17.0.1')"
```
