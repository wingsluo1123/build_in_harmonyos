# E2478: "接收 getc/fgetc/getchar/ungetc 返回值的变量一律声明为 int（C 标准：这些函数返回 in

## 基本信息
- **严重度**: P1
- **类别**: portability, memory, c
- **作者**: unknown

## 错误特征
```
"rc=143 [(]Signal 15 [)]|VmHWM=[0-9.]+GB|KILL pid=.* comm=|out of memory|std::bad_alloc"
```

## 根因分析
"aarch64 上主流工具链（OHOS clang 等）把 plain char 默认实现为无符号（char != signed char，unsigned char 为默认）。以 `char ch;` 接收 getc()/fgetc()/getchar() 返回值的 C 代码，EOF(-1) 存入后变为 255，`while ((ch = getc(fp)) != EOF)` 永不成立 → 单字符读循环不终止、行缓冲 realloc 指数扩容直到内存耗尽或被止损。上游在有符号 char 平台（x86-64 glibc）开发测试，从不复现；aarch64 上 KB 级输入即可吃掉 GB 级内存（pullseq 实测 34 字节 FASTA → 6.4GB RSS，同根因可回溯解释此前 10.26GB 冒烟事故——当时被误判为'输入过大'）。"

## 推荐方案
**方法**: "接收 getc/fgetc/getchar/ungetc 返回值的变量一律声明为 int（C 标准：这些函数返回 int 以容纳 EOF）。修复点按 getc 站点定位：grep -n 'getc(' 排查每个读循环的接收变量类型。pullseq 实例：file_read.c:23 `char ch;` → `int ch;` 单行修复，全源码仅此一处站点。"

**说明**: (待补充)

**修复命令**:
```
"sed -i 's/^\\(\\s*\\)char ch;$/\\1int ch;/' src/file_read.c  # 逐站点：把接收 getc 返回值的 char 变量改 int"
```
