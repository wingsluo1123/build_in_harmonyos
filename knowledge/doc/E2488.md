# E2488: W0 依赖检查发现 autotools Makefile.in 无条件硬编码 LIBS += -lxxx（非 AC_CHECK_LIB 条件驱动）时，无法通过 ignored_requires 剔除，必须将依赖库拆为独立 Conan 包先行适配发布

## 基本信息
- **严重度**: 3
- **类别**: autotools, conan, dependency-analysis, workflow
- **作者**: gcw_6YxinkyD
- **来源 PR**: (本 PR 提交后回填)

## 错误特征
```
cannot find -l[a-z]+|No such file or directory.*-l
```

## 根因分析
部分 autotools 项目将依赖库硬编码在 Makefile.in 的 LIBS 变量中（LIBS += -llcrq），无论 configure 探测结果如何，链接行始终包含该 -l 选项。当此类依赖不在 Conan 制品仓中时，链接阶段 ld 报 cannot find -lxxx。ignored_requires 只能阻止 Conan 拉取依赖，无法修改上游 Makefile 的链接行为

## 推荐方案
**方法**: decompose-hard-dependency-into-separate-conan-package

**说明**: W0 阶段识别硬依赖后，创建独立 worktree/分支/PR 适配依赖库，发布到制品仓后主库配方 self.requires 声明。纯 C 无外部依赖的库（如 lcrq）适配成本低，可快速先行

**修复命令**:
```
# W0 判定命令\ngrep -rn 'LIBS.*+=.*-l' src/*/Makefile.in\ngrep -n 'AC_CHECK_LIB\|AC_ARG_WITH\|without-' configure.ac\n# 硬依赖：Makefile 无条件 += 且 configure 无 --without 选项
```

**验证**:
```
grep -n 'LIBS.*+=.*-l' src/Makefile.in && grep -n 'AC_CHECK_LIB\|AC_ARG_WITH' configure.ac；无条件硬编码且无 --without 选项的依赖判定为硬依赖
```
