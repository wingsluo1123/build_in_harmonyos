# E2489: 头文件中的 extern inline 定义在 clang 默认 C17 内联语义下每个编译单元都发出强符号，链接期 duplicate symbol，应加 -fgnu89-inline 回到上游所依赖的 GNU89 语义

## 基本信息
- **严重度**: 2
- **类别**: toolchain, linking
- **作者**: ifile-1.3.9

## 错误特征
```
ld.lld 报 duplicate symbol argp_usage|duplicate symbol _option_is_short|duplicate symbol argp_fmtstream_write
```

## 根因分析
因果链。glibc 时代的 argp（含 argp-standalone 与各包内嵌副本）按 **GNU89 内联语义** 书写。argp/argp.h 在 `#ifdef __OPTIMIZE__` 下 `#define ARGP_EI extern inline`，并把 argp_usage、_option_is_short、_option_is_end 的 **函数体直接写进头文件**；argp-fmtstream.h 同族（AFS/ARGP_FS_EI，8 个 argp_fmtstream_* 函数）。上游另用 argp-fs-xinl.c 与 argp-xinl.c 里 `#define ARGP_FS_EI`（置空后再次包含头文件）保证 **恰好一个 TU** 发出外部可见的实体。这套写法只有在 GNU89 语义下成立——GNU89 里 `extern inline` 表示"仅供内联的副本，不发独立符号"。clang 默认走 C99/C17 内联语义，其中 `extern inline` 的含义反过来——**在本 TU 发出一份额外的强外部定义**。于是每个包含 argp.h 的编译单元都产出 argp_usage 等强符号，与真实定义所在的 argp-parse.c/argp-help.c 相撞，链接期报 duplicate symbol。触发条件含任何 -O 优化（它定义 __OPTIMIZE__，头中的定义块才生效）；-O0 时该块被条件编译跳过、症状消失，极易被误判成"优化等级问题"。

## 推荐方案
**方法**: compile-with-fgnu89-inline

**说明**: 给编译标志加 -fgnu89-inline，让 clang 恢复上游所依赖的 GNU89 内联语义，extern inline 不再在每个 TU 发出强符号。一个标志即可，不动上游一行源码，也不影响其它编译单元。conan 配方写 tc.extra_cflags.append("-fgnu89-inline")；裸 Makefile 写 CFLAGS="-O2 -fgnu89-inline"；autotools 传 ./configure CFLAGS=... 或直接 make CFLAGS=...。

**修复命令**:
```
conan 配方 generate() 中 tc.extra_cflags.append("-fgnu89-inline")；等价手工命令 make CFLAGS="-O2 -fgnu89-inline"
```

**验证**:
```
三臂对照（真机）：A 臂 CFLAGS="-O2" 得 20 条 duplicate symbol 且无产物；B 臂加 -fgnu89-inline 得 0 条并产出可执行文件；C 臂换 -fcommon 仍 20 条且无产物（证明 -fcommon 非解）。          双臂对照（真机 HarmonyOS PC，ifile 1.3.9，clang-15 交叉 aarch64-unknown-linux-ohos）。cd <src> && make clean；臂 A，make CC=<clang> AR=<llvm-ar> RANLIB=<llvm-ranlib> CFLAGS="-O2"，预期 ld.lld：error：duplicate symbol 计数 20、无产物，且 llvm-nm --defined-only opts.o 里 argp_usage 计 1、llvm-nm --defined-only libifile.a 里 argp_usage 计 13；臂 B，同命令 CFLAGS="-O2 -fgnu89-inline"，预期 duplicate symbol 计数 0、产物生成、llvm-nm --defined-only opts.o 里 argp_usage 计 0、实体只由 argp/libargp.a 提供 1 份。两臂唯一变量是内联语义开关。
```
