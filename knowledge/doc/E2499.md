# E2499: 框架 L1e 重跑 conan test 只传 -pr（host profile）不传 -pr:b ⇒ build profile 回落 CONAN_HOME 的 default(os=Linux) ⇒ test() 里的 can_run()/cross_building 早退护栏必然命中 ⇒ 测试体被静默跳过，L1e 把真测试判成假测试

## 基本信息
- **严重度**: 2
- **类别**: cross-compile, conan, testing, ci-harness
- **作者**: 主理-33

## 错误特征
```
fake test detected \(R34\)|test does not depend on .* must call its API|consumer test skipped: target cannot run|negative test: test does not depend on package
```

## 根因分析
ci/conan/build_and_test.sh 内两处 conan 调用的 profile 参数不对称（行号为本窗 grep -n 实测）。第 316/318 行的 conan create 同时传 -pr:h 与 -pr:b 且指向同一份 OHOS profile，host 与 build 一致故不构成交叉，can_run() 为真，test() 实跑；第 1646-1647 行 L1e 的破坏性反向验证重跑 conan test 只传 -pr "$PROFILE_FILE" 而无 -pr:b，build profile 因此回落到 CONAN_HOME 的 profiles/default（实测该文件为 os=Linux），host=OHOS 配 build=Linux 被判为交叉构建，cross_building(self) 为真而 can_run(self) 为假。凡在 test() 里放「跑不了就 return」这类早退护栏的配方，都会在 conan create 阶段实跑、却在 L1e 阶段静默 return 0；而 L1e 的判据恰好是退出码（第 1650 行的 [fail] 分支），并且该调用用 >/dev/null 2>&1 丢弃全部输出（第 1647 行），护栏自己打印的 skipped 提示连日志都进不去。后果是验证通道本身失真且失真方向与 R34 的意图相反：真测试（确实依赖被测包）被 L1e 判成假测试而 FAIL，真·假测试（压根不依赖被测包）因同样返回 0 而落到第 1656 行的 [ok] 分支被放行。这不是配方写错、也不是 conan 行为异常，而是 harness 两处调用参数不一致所致。

## 推荐方案
**方法**: harness-pass-pr-b-to-l1e-conan-test

**说明**: 把第 1646-1647 行的 L1e 调用与同一脚本第 316/318 行的 conan create 对齐，补上 -pr:b "$PROFILE_FILE"。属框架文件改动，必须单开一个 PR，不得夹进任何包的配方 PR。补 -pr:b 只是把护栏的判定前提恢复正常，不改变 L1e 的判据本身；建议同批把该调用的 >/dev/null 2>&1 改为留档，否则"测试被跳过"与"测试真的不依赖被测包"在日志里无法区分。

**修复命令**:
```
conan test "$TEST_PKG_DIR" "${pkg_name}/${pkg_ver}" -pr "$PROFILE_FILE" -pr:b "$PROFILE_FILE" --build=missing
```
