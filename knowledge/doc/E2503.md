# E2503: autoconf 2.13 生成的 configure 把命令行上的 VAR=value 当成 host 三元组解析并 error 退出——老 autotools 包传旗标必须改走环境变量通道

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, configure, argument-parsing, autoconf-2.13
- **作者**: 主理-45-子代理3
- **来源 PR**: pending

## 错误特征
```
"configure: warning: [A-Za-z_]+=[^:]+: invalid host type|configure: error: can only configure for one host and one target at a time"
```

## 根因分析
"autoconf 2.13（1998 年那一代）生成的 configure 在参数循环里把「不以 - 开头的位置参数」一律交给 host/target 三元组识别逻辑处理，**没有**现代 autoconf 对命令行 `VAR=value` override 的支持路径。于是 `./configure CC=/path/to/clang CFLAGS=-DXX` 不报「未知选项」，而是把这两个赋值各判成一个非法的 host 类型，逐条打 `configure: warning: <VAR>=<value>: invalid host type`；这两个位置参数又分别占掉 host 与 target 两个槽位，于是随后的自洽性检查判定「同时配置 host 和 target」，以 `configure: error: can only configure for one host and one target at a time` 终止——rc=1 且**不产出 Makefile / config.status**。同名变量的**环境变量**通道在这个世代完全有效（configure 按 `${CC-…}` 一类标准取法读环境）。后果面：仓内同族惯用写法是往 `tc.configure_args` 里塞 `\"LDFLAGS=…\"` / `\"LIBS=-ldl\"`（对照先例 archives/a/alpine/2.26/conanfile.py），该写法照搬到 2.13 世代的 configure 上必红。根因是该世代 autoconf 自身的参数协议，与鸿蒙/工具链/musl 无关。"

## 推荐方案
**方法**: switch-var-override-channel-by-autoconf-generation

**说明**: 给 autoconf 2.13 世代的老 configure 包写配方时，把「CC/CFLAGS/CPPFLAGS/LDFLAGS/LIBS 从哪里进去」当成一个必须先实测再落笔的问题：先 `head -6 configure` 看生成版本号，再用一条环境变量臂和一条命令行臂做 A/B 探针（各存一份日志），确认通道归属后才决定写 `tc.configure_args` 还是 `Environment()` define。判别不确定时以两臂实测退出码为准，不靠版本号猜测。

**修复命令**:
```
cd <worktree>/archives/s/sntop/1.4.3 && conan create . --build=missing -pr:h=ohos-aarch64 -pr:b=ohos-aarch64
```

**验证**:
```
env CC="$(command -v clang)" CFLAGS=-DM12_ENV_MARKER sh ./configure --prefix=/tmp/x >/tmp/arm-env.log 2>&1; echo "ENV_RC=$?"; grep -n 'CC = '"$(command -v clang)" Makefile; grep -n 's%@CFLAGS@%-DM12_ENV_MARKER%g' config.status; sh ./configure --prefix=/tmp/y CC="$(command -v clang)" CFLAGS=-DM12_CMD_MARKER >/tmp/arm-cmdline.log 2>&1; echo "CMD_RC=$?"; grep -c 'invalid host type' /tmp/arm-cmdline.log
```
