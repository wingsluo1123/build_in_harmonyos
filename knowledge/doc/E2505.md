# E2505: GCC target library（libgcobol）在 OHOS 上的独立构建与多环节适配

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, musl, build-system, toolchain, compiler
- **作者**: unknown

## 错误特征
```
No space left on device|configure: Permission denied|cannot find install-sh|no acceptable ld found|subs1.awk.*Permission denied|unknown type name '_Float32'|unable to find library -lgcc|__divti3: symbol not found|Link tests are not allowed after GCC_NO_EXECUTABLES
```

## 根因分析
GCC target library 深度耦合 GCC 树（configure 依赖 ../gcc/BASE-VER 与树根 aux 脚本），无独立 tarball；OHOS 叠加 HMDFS 权限限制、LLVM-only 工具链、C++ 编译器 C23 类型差异、compiler-rt（非 libgcc）链接模型，普通 C/C++ autotools 配方无法直接复用。

## 推荐方案
**方法**: gcc-target-library-standalone-build

**说明**: 在 source() 用 download()+tarfile 只选择性解压 libgcobol/ 与 gcc/BASE-VER 及树根 aux 脚本（避免解压 2GB GCC 树耗尽 HMDFS 磁盘）；build() 用 /bin/sh 执行 configure（HMDFS 无执行位）、export LLVM 工具链绝对路径（E012）、patch configure 的 mktemp 到 $TMPDIR（E011/E052/E060）、patch 源码 _Float32/_Float64→float/double（C23 类型 clang++ 不认识）；make 链接阶段显式 LIBS='-lclang_rt.builtins'（128-bit 运算符号在 compiler-rt，OHOS 无 libgcc）。

**修复命令**:
```
|
```

**验证**:
```
tar -tf gcc-16.1.0.tar.xz | grep -E 'libgcobol/configure|gcc/BASE-VER|install-sh'; /data/service/hnp/bin/clang++ --print-file-name=libclang_rt.builtins.a; nm -D libgcobol.so 2>/dev/null | grep -E '__gg__power_of_ten'
```
