# E2525: 幂级数求导循环 j==0 读 t[-1] 的越界 UB：-O3 静默清零导数输出而 -O0/-O2 正常（libgal VSOP87 实例）

## 基本信息
- **严重度**: 2
- **类别**: portability, autotools, numerical, optimizer, out-of-bounds
- **作者**: unknown

```
Test [A-Za-z_0-9]+ \[\d+\]\[\d+\].*failed|[0-9]+ tests failed|Expected value:.*Actual value:
```

## 根因分析
求导惯用法 `v += a * ( j * t[j-1] * cp - t[j] * c * sin(p) )` 对 j==0 项数学上应为 `-a*t[0]*c*sin(p)`（幂次 0 的导数系数 j=0），作者依赖 `0 * t[-1] == 0` 掩盖越界读；这是未定义行为，-O3 的向量化/重排可自由利用（实测速度分量输出 ~4.8e-9，恰为丢弃主项后的残差），而 -O0/-O2 布局下 t[-1] 落在有限栈值上、0*有限=0 掩盖了缺陷。判据三件套：①同一输入 -O2 正确而 -O3 错误；②错误量级是"少了一类项"的残差而非 NaN/精确 0；③对 j==0 加守卫后所有优化级一致正确——三者齐即可断定 UB 被优化器利用，而不是平台 libm/浮点问题。

## 推荐方案
**方法**: guard-j0-term-semantics-preserving

**说明**: 最小语义保持修复：把 `j * t[j-1] * cp` 包成 `(j > 0 ? j * t[j-1] * cp : 0.0)`——j==0 的导数贡献本来就只来自 `-t[j]*c*sin(p)` 项，守卫后任何优化级都不再触碰 t[-1]。不要用"把 t 数组多开一位并令 t[-1]=0"之类的布局补丁（改动面大且掩盖意图），也不要降优化级（-O2 也只是碰巧不炸）。

**修复命令**:
```
patch -p1 -i patches/0002-vsop87-j0-ub.patch && clang -O3 -o probe probe.c <subdir-sources> && ./probe
```

**验证**:
```
①同输入三档编译：clang -O0/-O2/-O3 → 仅 -O3 输出异常；②修复后（(j>0 ? j*t[j-1]*cp : 0.0)）三档输出逐位一致且与上游参考值吻合；③上游测试计数核对：libgal ephemerides 修复前 618/549（pass/fail）→ 修复后 1167/0
```
