# E2534: OHOS 的 /dev/shm 只开放"数据面"：open/write/shm_open/mmap/unlink 可用，但对 /dev/shm 上的文件 flock/fcntl 加锁、枚举、建子目录、改时间戳、inotify 一律 EACCES(13)——"只用文件"不等于不受影响

## 基本信息
- **严重度**: 2
- **类别**: platform, hmdfs, posix, tmpdir
- **作者**: unknown

## 错误特征
```
"flock.*(Permission denied|EACCES)|fcntl.*F_SETLK.*(Permission denied|EACCES)|mkdir.*dev/shm.*(Permission denied|EACCES)|opendir.*dev/shm.*(Permission denied|EACCES)|mkdtemp.*dev/shm.*(EACCES|Permission denied)|create_directories.*dev/shm|futimens|utimensat|inotify_add_watch"
```

## 根因分析
推断（**未取证内核/namefs 实现**）：OHOS 的 /dev/shm 由 namefs 管理，对本进程呈"只写虚拟目录"——

## 推荐方案
**方法**: route-shm-locks-and-dir-ops-off-dev-shm

**说明**: ①"在 /dev/shm 下建目录/枚举"的代码路径改到可写目录（TMPDIR/XDG_RUNTIME_DIR）；

**修复命令**:
```
补丁在 flock 失败处检查返回值并降级/改道锁文件路径后重跑探针与 make check
```

**验证**:
```
clang --sysroot=... -o probe probe_ledmon_shm.c && ./probe（设备 ~/tmp/uc2/hw-5/probe/probe_ledmon_shm.c；逐字复现 amd_sgpio.c:229-241 与 config_file.c:283 序列）
```
