# E2536: peek-datagram-size-with-msg-trunc-then-recv

## 基本信息
- **严重度**: 3
- **类别**: libc, 'ohos, netlink, runtime'
- **作者**: hw-2

## 错误特征
```
'NETLINK: Packet too small or truncated! \d+!=\d+!=\d+|recv\(\): Inappropriate|Packet too small or truncated! \d+!=16!=\d+'
```

## 根因分析
'固定 2KB 栈缓冲装不下本机 RTM_GETLINK dump（19276B/单条~1340B），recv 静默截断致遍历半截头部而报错 (1) 2004 年前后的独立 netlink 工具普遍把单次应答硬编码成小栈缓冲，如 ifmetric src/nlrequest.c netlink_request() 的 `char replybuf[2048]` + `recv(s, &replybuf, sizeof(replybuf), 0)`，随后用 `for (; bytes > 0; p = NLMSG_NEXT(p, bytes))` 在同一缓冲内遍历多消息。 (2) netlink 是**数据报**语义：内核把一个 skb 内打包的多条 nlmsghdr 作为**一个** 数据报投递；用户缓冲不足时 recv() **静默截断**并返回缓冲长度（不给 ENOBUFS、 不设 MSG_TRUNC 就无从得知），不报错。 (3) 截断后最后一个消息只剩半截头部：`p->nlmsg_len`（实测 1340）> 剩余 bytes （实测 728），NLMSG_OK/长度自检失败 → 打印 `NETLINK: Packet too small or truncated! 728!=16!=1340` 并 return -1。 (4) HarmonyOS PC 命中概率显著高于普通 Linux：真机 /proc/net/dev 有 14 个接口， 其中华为无线类接口（Hisilicon0/wlan0/wlan1/p2p0/chba0/nan0/ancowlan0）带大量 802.11 相关 IFLA_* 属性，单条 RTM_NEWLINK 约 1340B（普通以太网口约 76B）。 (5) 因为 getifn()/RTM_GETLINK 是这类工具的**第一个**调用，症状是"程序完全跑不起来" 而不是"某功能不可用"——最容易得出"OHOS 不支持 netlink"的**错误**结论。'

## 推荐方案
**方法**: peek-datagram-size-with-msg-trunc-then-recv

**说明**: '先用 MSG_PEEK|MSG_TRUNC 窥探数据报真实长度（不出队），再按需 malloc 完整收取 不要用固定缓冲，也**不要**直接在收数据的 recv() 上加 MSG_TRUNC 后"读不到就重试" ——那种写法数据报已被**消费掉**，重试读到的是下一个数据报，会把整条消息静默丢掉 （dump 结果不完整，比报错更坏）。正确姿势是两步： 1) 先用 `recv(s, &probe, sizeof(probe), MSG_PEEK | MSG_TRUNC)` **窥探**： MSG_TRUNC 使返回值为数据报**真实长度**，MSG_PEEK 保证**不出队**； 2) 按真实长度（不小于一个下限，本例 4096）malloc，再用普通 recv() 完整收取， 然后照原逻辑遍历；每条退出路径记得 free()。 这样对任意接口数量/属性大小都成立，无需猜"多大够用"。 实测：本机 RTM_GETLINK dump 19276B/14 条（65536 缓冲时 truncated=0）， RTM_GETROUTE 仅 1708B/22 条（故只读路由表的工具可能不显现此 bug）。'

**修复命令**:
```
'见 patches/0001-netlink-dump-datagram-buf.patch（strip: 1，peek 长度后动态 malloc） # ifmetric 0.3 patches/0001-netlink-dump-datagram-buf.patch（strip: 1）： # #define NETLINK_REPLY_MIN 4096 # want = recv(s, &probe, sizeof(probe), MSG_PEEK | MSG_TRUNC); # buflen = want < NETLINK_REPLY_MIN ? NETLINK_REPLY_MIN : (size_t) want; # replybuf = malloc(buflen); # bytes = recv(s, replybuf, buflen, 0); # 参考: archives/i/ifmetric/0.3/conanfile.py + patches/0001-netlink-dump-datagram-buf.patch'
```
