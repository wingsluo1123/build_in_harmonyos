# E2539: ohpcd/本仓没有名为 libudev 的包 —— 它是 pkg-config 的**能力名**，须由提供者（eudev 或 systemd，其配方把 pkg_config_name 设为 libudev）满足；conan 侧 require 写提供者包名，meson 侧探测名保持 libudev

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, build-system
- **作者**: AtomCode <noreply@atomgit.com>
- **来源 PR**: 12300

## 错误特征
```
Dependency "libudev" not found|libudev.*not found|dependency\('libudev'\)|pkg-config.*libudev.*not found
```

## 根因分析
libudev 是**能力名**（pkg-config 模块名）而非**包名**。历史上由 systemd 提供，现亦可由 eudev 提供；两者都安装 libudev.pc，故 pkg-config --exists libudev 成立，但仓库里并没有叫 libudev 的 conan 包（ohpcd 实查 0 条）。上游 meson.build 常写死 dependency('libudev') 且无 fallback（libinput 1.26.2 meson.build:146 即如此），于是「conan 依赖名」与「meson 探测名」不一致，configure 期报 Dependency "libudev" not found。

## 推荐方案
**方法**: require-provider-package-and-expose-pc-module

**说明**: conan 侧 require **提供者包**（优先 eudev/3.2.14，轻量且不带整个 systemd），并确保其 .pc 可被 meson 找到（PKG_CONFIG_PATH 或 PkgConfigDeps）；meson 侧探测名**保持** dependency('libudev') 不改写上游。

**修复命令**:
```
self.requires("eudev/3.2.14")  # 并确认 pkg-config --exists libudev 返回 0
```

**验证**:
```
conan search 'libudev/*' -r=ohpcd; pkg-config --exists libudev && echo OK; grep -n "dependency('libudev')" <src>/meson.build
```
