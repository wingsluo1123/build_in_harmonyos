# E2544: 'suckless 系裸 Makefile 把编译器与路径烧死（CC=cc、X11INC=/usr/X11R6/include），且 X11 头族分属两个 Conan 包（X11/Xlib.h 属 libx11、X11/X.h 属 xorgproto 协议头）⇒ OHOS 交叉环境下不打补丁，在 make 命令行覆盖聚合变量 CC/INCS/LIBS，遍历全部 host 依赖（含传递）拼绝对 -I/-L 注入'

## 基本信息
- **严重度**: 2
- **类别**: ohos, make, cross-compile, dependency-injection
- **作者**: 'DS-33（dmenu 5.4 实证入池）; QC-23（lsw 0.3 认领并补第三层症状与判别法）'
- **来源 PR**: 'lsw 0.3 交付 PR（机制证据随该 PR 的 notes.md 与 knowledge/drafts 成对提交）'

## 错误特征
```
'make: cc: No such file or directory|No such file or directory. Makefile:. Error 127|fatal error: X11/Xlib.h file not found|fatal error: X11/X.h file not found|Xlib.h.44.10. fatal error.*X11/X.h|-I/usr/X11R6/include'
```

## 根因分析
'suckless 家族用可编辑 config.mk 加裸 Makefile，CC=cc 在 OHOS 不存在（无 cc 别名），X11INC/X11LIB 被写死为 /usr/X11R6 而交叉环境无该目录；更隐蔽的一层是 X11 头文件族分属两个 Conan 包——libx11 交付 Xlib.h，而 Xlib.h 内部 include 的 X.h/Xproto.h 等协议头由 xorgproto 交付（归档内 libx11/6.4.0 以 requires xorgproto/2025.1 且 transitive_headers=True 声明，cpp_info.requires 亦含 xorgproto::xorgproto）。配方若只取直接依赖的 cpp_info.includedirs 首项（即 libx11 自己的 include 目录），症状会从缺 Xlib.h 迁移成缺 X.h，极易被误判为依赖未发布而去 block 依赖。GNU make 语义里命令行变量覆盖文件内赋值，而 config.mk 的 INCS/LIBS 正是引用那些路径变量的聚合变量，故命令行直接覆盖 INCS/LIBS 即可整体绕开；路径须遍历 self.dependencies.host.values() 含传递依赖，并用 os.path.join(dep.package_folder, d) 转绝对，因为 cpp_info.includedirs 与 libdirs 本身是相对 package_folder 的路径。'

## 推荐方案
**方法**: '零补丁：在 make 命令行覆盖上游聚合变量 INCS/LIBS（而非逐个改被烧死的路径变量），路径来自全部 host 依赖（含传递）的 package_folder 拼接绝对路径；编译器取自 conan conf。'

**说明**: '上游源码零改动、conandata.yml 无 patches 段；聚合变量覆盖一次性带入 xorgproto 等传递依赖的 include，避免只注直接依赖导致的缺协议头。'

**修复命令**:
```
'make CC=<conf tools.build:compiler_executables 的 c 项> INCS=<空格分隔的 -I 绝对路径集，来自全部 host 依赖> LIBS=<空格分隔的 -L 绝对路径集> -lX11 lsw'
```

**验证**:
```
'make CC=<conf tools.build:compiler_executables 取得> INCS="<遍历 self.dependencies.host 全部包得到的绝对 -I 串>" LIBS="<同样遍历得到的绝对 -L 串> -lX11" lsw'
```
