# E2550: vendored kernel-tools 头 compiler_types.h/compiler-gcc.h 与 OHOS/bionic sysroot 的 linux/stddef.h 条件包含冲突

## 基本信息
- **严重度**: 2
- **类别**: compat, kernel, libc, headers, build-system
- **作者**: staralsnow

## 错误特征
```
Please don't include <linux/compiler-gcc.h> directly|_TOOLS_LINUX_COMPILER_H_|compiler_types.h.*compiler-gcc.h
```

## 根因分析
项目内 vendored 的 Linux tools/include 版 linux/compiler_types.h 无条件 #include <linux/compiler-gcc.h>，而 compiler-gcc.h 的守卫要求 _TOOLS_LINUX_COMPILER_H_ 已定义（只有 linux/compiler.h 会定义它）。OHOS/bionic sysroot 的 <linux/stddef.h> 会 #include <linux/compiler_types.h>；由于 -I <vendored headers> 排在隐式 sysroot 之前，解析到 vendored 版，守卫未置 -> #error。glibc 宿主 linux/stddef.h 不 include compiler_types.h，故只在 OHOS/bionic 暴露。

## 推荐方案
**方法**: relocate-compiler-gcc-include

**说明**: 把 vendored linux/compiler_types.h 中对 <linux/compiler-gcc.h> 的包含移到 linux/compiler.h（在 #define _TOOLS_LINUX_COMPILER_H_ 之后），保持"compiler.h 是唯一正规入口"的上游语义；平台无关，不改判定宏。等价可选方案是调整 -I 顺序让 sysroot 的 linux/ 优先，但会影响 vendored 头的其他覆盖，风险更大。

**修复命令**:
```
patch -p1 < patches/NNNN-headers-linux-compiler.h.patch; patch -p1 < patches/NNNN-headers-linux-compiler_types.h.patch
```

**验证**:
```
printf '#include <linux/stddef.h>\n' | cc -I<vendored headers> -E -xc - -o /dev/null; printf '#include <linux/stddef.h>\n' | cc -E -xc - -o /dev/null
```
