# E2552: OHOS seccomp 以 SIGSYS 杀死 unshare(CLONE_NEWNET|CLONE_NEWNS)，上游隔离测试套件第一步即 core dump

## 基本信息
- **严重度**: 2
- **类别**: platform, syscall, testing, security
- **作者**: staralsnow

## 错误特征
```
invalid system call (core dumped)|Executing tests in separate net- and mount namespaces.*invalid system call
```

## 根因分析
上游测试 runner 常用 exec unshare -n -m 建私有 net/mount namespace 以隔离地建 veth、挂 bpffs；OHOS 的 seccomp 策略不放行 unshare/CLONE_NEWNET/CLONE_NEWNS，进程在第一步即被 SIGSYS 杀死并 core dump，用例一条也不执行。

## 推荐方案
**方法**: bypass-unshare-with-did-unshare

**说明**: 若只要拿到测试结果，可置 DID_UNSHARE=1 让 runner 跳过 unshare 重执行、落宿主 netns 继续；此时 veth/bpffs 仍受 SELinux/内核限制（见同批另一条）。判定"上游不可跑"须以本 syscall 拦截为硬证据，而非写"未执行"。

**修复命令**:
```
DID_UNSHARE=1 sudo env PATH=$SHIMS:/data/service/hnp/bin:/usr/bin:/vendor/bin:/system/bin bash ./test_runner.sh ./test-libxdp.sh
```

**验证**:
```
sudo env PATH=... /data/service/hnp/bin/bash ./test_runner.sh ./test-libxdp.sh 2>&1 | grep -E "Executing tests in separate net-|invalid system call"
```
