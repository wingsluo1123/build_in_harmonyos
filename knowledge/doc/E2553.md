# E2553: 交叉构建中 clang -target bpf 不继承默认 sysroot 搜索列表，BPF 对象编译缺 <linux/types.h>

## 基本信息
- **严重度**: 2
- **类别**: build-system, toolchain, cross-compile
- **作者**: staralsnow

## 错误特征
```
linux/types.h: No such file or directory|fatal error: 'linux/types.h' file not found|clang.*-target bpf.*fatal error
```

## 根因分析
用 clang 的 bpf/bpfeb/bpfel 目标编译 eBPF 程序时，clang 不会把驱动自身的默认 sysroot 头目录（<sysroot>/usr/include 及其 arch 子目录）加入 include 搜索列表；而常见自定义构建脚本只把 arch 子目录写进 ARCH_INCLUDES，于是 BPF 编译参数里缺 <sysroot>/usr/include，<linux/types.h> 解析失败。x86_64 宿主上该头常由宿主 /usr/include/linux/types.h 兜住而不报错，只有交叉/真机（如 OHOS）才暴露。

## 推荐方案
**方法**: inject-compiler-default-includes

**说明**: 构建期解析编译器自身的 include 搜索列表（cc -E -Wp,-v -xc - 的 stderr），把其中所有真实存在的绝对目录以 -I 注入 BPF 编译参数（如 make 的 ARCH_INCLUDES，进而进入 BPF_CFLAGS）；不要只注入 arch 子目录，也不要依赖宿主 /usr/include 兜底。

**修复命令**:
```
ARCH_INCLUDES="$(cc -E -Wp,-v -xc - 2>&1 | awk '/search starts here/{f=1;next} /End of search list/{f=0} f && /^\//{printf "-I%s ",$1}')"; make BPF_CFLAGS="$BPF_CFLAGS $ARCH_INCLUDES"
```

**验证**:
```
cc -E -Wp,-v -xc - 2>&1 | sed -n '/search starts here/,/End of search list/p'; clang -target bpf -I<sysroot>/usr/include -c bpf_prog.c -o /tmp/prog.o
```
