# E2559: 解码库编译期未启用完整性检查时，损坏 payload 不触发解码失败；损坏流测试应改损坏结构性字节（LZMA2 块控制字节）作确定性断言

## 基本信息
- **严重度**: 3
- **类别**: ohos, testing, corrupt-stream, decoder, integrity-check
- **作者**: pc4-37

## 错误特征
```
corrupt stream rejected safely.*FAIL|
```

## 根因分析
minlzlib 的 CRC 校验由编译期宏 MINLZ_INTEGRITY_CHECKS 控制，上游

## 推荐方案
**方法**: corrupt-structural-byte

**说明**: 先用字节扫掠实验确定使解码确定性失败的字节位：对 XZ 流每个偏移

**修复命令**:
```
循环 i in 0..len(stream): bad=copy(stream); bad[i]^=0xFF;
```

**验证**:
```
对候选字节位逐个异或 0xFF 后调用 XzDecode，统计哪些偏移使
```
