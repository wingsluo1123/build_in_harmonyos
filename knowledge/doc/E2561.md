# E2561: 头文件-only CMake 库适配：compile_commands.json 复制目标守卫 + conan CMakeDeps 下 boost 头文件-only（SYSTEM include）消费

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, build-system, cmake, conan
- **作者**: 0AE8

## 错误特征
```
Error copying file.*compile_commands.json|copy_compile_commands_json.*Error 1|undefined symbol: init_unit_test|Boost::headers.*not found|missing .typename. prior to dependent type name
```

## 根因分析
两类可复用问题：(1) 头文件-only(INTERFACE) CMake 库无任何编译规则，上游无条件注册的 copy_compile_commands_json 自定义目标复制不存在的 compile_commands.json，全量构建必然失败；(2) conan CMakeDeps 对 boost 只生成 Boost::boost 伞目标（链接全部组件静态库，含自带 main() 的 libboost_unit_test_framework），上游 Boost::headers 目标在 CONFIG 模式不存在，链接伞目标与 Catch2::Catch2WithMain 的 main 冲突。

## 推荐方案
**方法**: guard-custom-target-plus-system-include

**说明**: (1) 用 if(EXISTS ${CMAKE_BINARY_DIR}/compile_commands.json) 守卫 compile_commands 复制目标，无编译规则时跳过，有规则时行为不变；(2) 头文件-only 库不链接 Boost::boost，改用 target_include_directories(... SYSTEM INTERFACE ${Boost_INCLUDE_DIRS}) 仅注入头文件，SYSTEM 同时豁免项目 -Werror 告警；boost::json 由测试 TU 内 <boost/json/src.hpp> 提供实现。(3) boost::mpl 依赖类型（at<...>::type）在 clang15/libc++15 严格 C++20 下需显式 typename。

**修复命令**:
```
cmake -S <src> -B build -DBUILD_TESTS=ON -DCMAKE_TOOLCHAIN_FILE=<conan>/conan_toolchain.cmake && cmake --build build -j1 --target _test
```

**验证**:
```
conan create archives/c/confu_json/1.2.4 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
