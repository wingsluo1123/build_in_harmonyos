# E2569: 用 --system-zstd 链系统/conan libzstd 时，python-zstandard 会按上游设计关闭 pool API（HAVE_ZSTD_POOL_APIS 仅定义于 ZSTD_SINGLE_FILE 捆绑构建），故上游 test_features 必失败 —— 属有意取舍，应据实申报

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system
- **作者**: AtomCode <noreply@atomgit.com>
- **来源 PR**: 12210

## 错误特征
```
test_features|backend_features|multi_compress_to_buffer|multi_decompress_to_buffer|HAVE_ZSTD_POOL_APIS|ZSTD_SINGLE_FILE
```

## 根因分析
c-ext/python-zstandard.h 里 #ifdef ZSTD_SINGLE_FILE 分支包含 <zstd.c> 并 #define HAVE_ZSTD_POOL_APIS，其注释明示「We use private APIs from pool.h. We can't rely on availability of this header or symbols when linking against the system libzstd. But we know it works when using the bundled single file library.」；setup_zstd.py 的 system_zstd 分支只加 -DZSTD_MULTITHREAD、不加 -DZSTD_SINGLE_FILE。于是 --system-zstd 构建下 backend_c.c 中 #ifdef HAVE_ZSTD_POOL_APIS 包住的 multi_compress_to_buffer / multi_decompress_to_buffer 不注册，而上游 test_features 的期望集是按**捆绑构建**写的 -> 恰好失败一条。附带：--system-zstd 是 setup.py 的 argv 开关（sys.argv.remove），pip 的 PEP517 构建路径无法透传自定义 argv。

## 推荐方案
**方法**: declare-upstream-tradeoff

**说明**: 接受并据实申报——把 test_features 列入 ALLOWED_TEST_FAILURES，并在 notes.md / MANIFEST.yml / PR 正文引用上游 python-zstandard.h 注释说明「链接系统 libzstd 无法依赖 pool.h 私有 API」，禁止静默放行。

**修复命令**:
```
setup.py bdist_wheel --system-zstd -d <wheels> && pip install --target=<staging> <wheels>/*.whl
```

**验证**:
```
grep -n -A6 "ifdef ZSTD_SINGLE_FILE" c-ext/python-zstandard.h; grep -n -A6 "system_zstd" setup_zstd.py
```
