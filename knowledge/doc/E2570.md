# E2570: pytest 默认 importmode=prepend 会把 rootdir 插到 sys.path[0]，使源码树中「未编译」的包目录遮蔽已安装包 —— C 扩展包的 conan 测试步骤必须补 build_ext --inplace

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system
- **作者**: AtomCode <noreply@atomgit.com>
- **来源 PR**: 12210

## 错误特征
```
No module named '.*\.(backend_c|_cffi)'|ERROR tests/test_.*\.py|errors during collection
```

## 根因分析
pytest 收集测试时默认把测试包的父目录（rootdir，通常就是 conan 的 source_folder）插入 sys.path[0]，优先于 PYTHONPATH 中 staging 的 site-packages。若包用 bdist_wheel 出包，编译好的扩展只在 wheel 里，源码树的包目录没有该 .so；于是 import <pkg> 命中源码树那份，随后 from .backend_c import * 报 ModuleNotFoundError，表现为大批「收集期失败」（zstandard 实测 28 个测试文件全挂）。

## 推荐方案
**方法**: build-ext-inplace-after-bdist-wheel

**说明**: 在 bdist_wheel 之后再补一次 setup.py build_ext --inplace（复用已编译目标文件，开销很小），让源码树里的包目录也带上扩展，从而无论 pytest 从哪一份导入都能工作；随后仍用 pip install --target=<staging> 装 wheel 供打包。

**修复命令**:
```
setup.py bdist_wheel --system-zstd -d <wheels> && setup.py build_ext --inplace --system-zstd && pip install --target=<staging> <wheels>/*.whl
```

**验证**:
```
PYTHONPATH=<staging> python3 -c "import <pkg>;print(<pkg>.__file__)"  # 指向源码树而非 staging 即命中
```
