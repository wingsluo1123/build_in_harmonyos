# E2574: layered-capability-probe-and-default-fallback

## 基本信息
- **严重度**: 2
- **类别**: ohos, kernel, portability, security, io-uring
- **作者**: unknown

## 错误特征
```
'Signal 31 \(core dumped\)|SIGSYS|exited on signal 31|rc=159'
```

## 根因分析
HongMeng Kernel 1.12.0 的 app 域 seccomp 对 io_uring 按 syscall 拆分放行：io_uring_setup(425) 返回 fd（实测 fd=3），但 io_uring_register(IORING_REGISTER_PROBE) 触发 SIGSYS(31) 且为 SECCOMP_RET_KILL 不可捕获（rc=159）；liburing 的 io_uring_queue_init 内部即注册 PROBE，故一切常规 liburing 初始化在 OHOS app 域必崩。区别于 E051（未实现 syscall）与 E246（整只 syscall 被拦）：本机制是"同一子系统内 setup 可用、驱动不可用"，凡以 setup 成功推断 uring 可用的探测都会得出假阳性。

## 推荐方案
**方法**: layered-capability-probe-and-default-fallback

**说明**: 打包期对带 io_uring 可选路径（meson dependency required:false 类）的包在 OHOS 一律默认取降级档（如 plocate 配方 with_uring=False），保留 option 供放行内核，不得凭 setup 成功开真值；能力探测必须驱动到 io_uring_register 或一次 submit/enter 往返；降级路必须验到"建库→查询→比对断言"的正确性级别，否则 SIGSYS 前的绿灯全是假通过。反例（勿做）：装 SIGSYS handler 与把 queue_init 当可返回错误均无效，进程在 register 点位已被击杀。

**修复命令**:
```
|
```
