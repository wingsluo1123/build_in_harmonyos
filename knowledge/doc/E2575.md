# E2575: 'automake 1.10.x（本包由 1.10.1 生成）的 DEFAULT_INCLUDES 不含 $(top_srcdir)：公开头自引用 <pkg/x.h> 的老包在 VPATH 构建下必挂（in-tree 才靠 -I.. 蒙对）'

## 基本信息
- **严重度**: 3
- **类别**: autotools, environment, automake, include-path, vpath
- **作者**: [hw-9]
- **来源 PR**: ''

## 错误特征
```
'fatal error: .*/<pkg>/<own-header>.h file not found（同包公开头自引用 <pkg/...>，且编译行 DEFAULT_INCLUDES 只有 -I. -I$(srcdir) -I$(top_builddir)）'
```

## 根因分析
'automake 生成的 COMPILE 行取 -I 来源为 DEFAULT_INCLUDES + INCLUDES + AM_CPPFLAGS + CPPFLAGS(+AM_/per-target CXXFLAGS)。automake 1.10.x（本包实测由 1.10.1 生成） 在子目录 Makefile 里把 DEFAULT_INCLUDES 落成 "-I. -I$(srcdir) -I$(top_builddir)"，不含 $(top_srcdir)；而 2005-2012 年代一批包的公开头互相写成 #include <pkg/xxx.h>，只有"含 pkg/ 子目录的那一层"作 -I 才可解析。同目录(in-tree)构建时 top_builddir 恰为 .. 指向源码根，问题被掩盖；conan 的 basic_layout 走 out-of-source，top_builddir 指向构建树（其 pkg/ 子目录只有 Makefile 与 .libs），于是同一行 include 找不到。上游若未写 AM_CPPFLAGS = -I$(top_srcdir)（jaula 的 Makefile.am 甚至注明为 bug 1827161 而删掉了 AM_CPPFLAGS），任何 -I 都补不上这一层。'

## 推荐方案
**方法**: inject-src-root-via-am-cxxflags-make-command-line

**说明**: '不改上游任何 Makefile.am/头文件，用 make 命令行变量（优先级高于 Makefile 内赋值）把源码根注入 AM_CXXFLAGS。AM_CXXFLAGS 出现在 COMPILE 行且 automake 默认未赋值，覆盖它不丢任何既有 flags，也不碰 CPPFLAGS 里来自 AutotoolsDeps 的依赖 -I。 前置判据（第 4 步取证，必须做）：grep 上游 Makefile.am/Makefile.in 是否对被覆盖变量使用 `+=` 或已有赋值——make 命令行 `var=value` 会整体作废 Makefile 内对该变量的所有 += 追加（见 经验文档/B草稿库/DRAFT-PKG-VER-make-commandline-override-kills-plus-equals）。本包取证结果：`grep -c AM_CXXFLAGS jaula/Makefile.am` = 0，且 jaula/Makefile.in 只在 CXXCOMPILE/CXXLINK 里引用 AM_CXXFLAGS、从无赋值行 ⇒ 覆盖不丢任何东西。若目标变量本身带既有值（如 CFLAGS/CPPFLAGS），必须把既有值一并重述进命令行。'

**修复命令**:
```
'autotools.make(args=["-C", "<subdir>", "-j1", "AM_CXXFLAGS=-I{}".format(self.source_folder)])'
```

**验证**:
```
'cd <worktree> && conan create archives/j/jaula/1.4.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64；反证：grep "^DEFAULT_INCLUDES" <build_folder>/jaula/Makefile'
```
