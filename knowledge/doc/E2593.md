# E2593: aarch64 宿主上的 ARM32 交叉 GCC：collect-ld 让位、前缀命名面、配方自建目标汇编器与消费者端到端用例

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, autotools, toolchain, compiler
- **作者**: SunShine_06

## 错误特征
```
arm-linux-ohos-gcc|armv5t|gcc-16.1.0.tar.xz|collect-ld|ELF32|_build_target_gas|_install_target_gas|armelf_linux_eabi|unknown pseudo-op|posix_spawnp: Permission denied|gcc.c-torture/execute|上游 N 少报
```

## 根因分析
lib32-gcc 是在 aarch64 HarmonyOS PC 宿主上自举、向 32 位 ARM（arm-linux-ohos）发射代码的交叉编译器包。collect2 按「名字外层（real-ld→collect-ld→ld）× COMPILER_PATH 前缀内层」双重搜索，configure 自动生成的构建树 gcc/collect-ld shebang 脚本跨前缀抢先命中，HMDFS 禁止不可信链 direct spawn shebang 脚本，导致 torture 全批链接失败。交叉 make install 只装前缀名且版本 symlink 记录真实内部版本（16.1.0 ≠ 包版本名 16.1.1）；设备 GNU binutils 2.45 只有 AArch64 后端，ARM32 目标汇编必须由配方自建的 GNU ARM gas 补齐。

## 推荐方案
**方法**: unlink-collect-ld-plus-recipe-built-target-gas-plus-consumer-flow

**说明**: torture/build 前幂等 unlink 构建树 collect-ld/real-ld 让 collect2 落到设备多目标 GNU ld；driver wrapper 合成四名字并从版本 symlink 解析内部版本；配方在 build() 期自建 GNU ARM gas（binutils 官方源 make all-gas）装为 target-tools/as 与包内 bin/as 并签名；torture 采用 compile+link+readelf 验证口径（N 取套件全家底 1685、N′ 取执行数 100）；test_package 构造跨 TU 消费者端到端流程（31 断言）；超时条目走独立基础设施 PR；版本名与源码版本解耦（conandata 头注 + sha512 逐字节比对）。

**修复命令**:
```
_run_torture_execute_subset(): unlink gcc/collect-ld and gcc/real-ld (OHOS-only, idempotent); _install_ohos_driver_wrapper(): rename real driver to arm-linux-ohos-gcc-<ver>.real, synthesize gcc/prefixed/versioned/cpp wrappers via /bin/sh; _build_target_gas(): download binutils from conandata.yml mirror list in build(), make all-gas, install as target-tools/as; _install_target_gas(): copy to p/bin/as then sign; test_package: gcc -E probe -> -c consumer_lib.c -> -c consumer_main.c -> link consumer_program -> llvm-readelf -h/-s assertions -> -DEXPECT_OHOS=1 test_gcc.c
```

**验证**:
```
在 OHOS 设备上执行 `conan create archives/l/lib32-gcc/16.1.1 -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64 --build=lib32-gcc/*`；torture 子集应 100/100（compile+link 口径，N′=100 / N=1685）；test_package 消费者端到端流程应 2 用例 / 31 断言全通过（预处理 → 编译 TU-A/TU-B → 汇编 → 链接 → 产物校验，含 -dumpmachine==arm-linux-ohos、readelf ELF32/ARM、跨 TU 符号 DEFINED、__OHOS__ 编译期断言）。
```
