# E2595: 纯 Python 包的 PyPI sdist 可能不含测试辅助文件，且 tests/ 会在模块级构造对象而让「收集期」就需要可选 extra —— 两者都表现为整个测试文件 ERROR，而本机恰好装了该 extra 时会假绿

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system
- **作者**: AtomCode <noreply@atomgit.com>
- **来源 PR**: 12205

## 错误特征
```
No module named 'tests\..*'|ERROR tests/test_.*\.py|errors during collection|ModuleNotFoundError.*No module named '(arrow|ruamel|cloudpickle)'
```

## 根因分析
(1) 上游 MANIFEST.in 只 include 少数文件（construct 2.10.70 仅 README.rst/LICENSE），导致 tests/declarativeunittest.py 未进 sdist，而 5 个测试文件都 `from tests.declarativeunittest import *` -> 收集期 ModuleNotFoundError，整个文件 ERROR。(2) construct 的 Timestamp 是可选适配器（extra=arrow），tests/ 在模块级构造 Timestamp(...)，其 ctor 内 import arrow -> pytest 一收集即失败，同样表现为文件级 ERROR。(3) 本机若恰好装了这些 extra（arrow/ruamel.yaml/cloudpickle），本地全绿而 CI 失败 —— 环境假绿。

## 推荐方案
**方法**: fetch-missing-test-helper-from-pinned-tag

**说明**: 构建期从上游**固定 tag** 的 raw URL 取回缺失测试辅助文件，并在取不到时 raise ConanException（不静默跳过，R51）；固定 tag 而非 master 以避免上游漂移。

**修复命令**:
```
urllib 下载 https://raw.githubusercontent.com/construct/construct/v2.10.70/tests/declarativeunittest.py 到 <source>/tests/
```

**验证**:
```
tar tzf <pkg>.tar.gz | grep -E "declarativeunittest|MANIFEST.in"; python3 -c "import arrow, ruamel.yaml"  # 本机是否恰好装了 extra
```
