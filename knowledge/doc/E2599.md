# E2599: OHOS PC（clang 15 / 鸿蒙 musl）上 open_memstream + fwrite 写回调模式可确定性崩溃（SIGSEGV/SIGILL，所有 -O 级别复现），测试工具链应改用真实临时文件承载写入

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, toolchain, testing, aarch64
- **作者**: unknown

## 错误特征
```
Signal 4|Signal 11|SIGSEGV|SIGILL|core dumped|test-lcfs.*FAIL|tmpfd > 0
```

## 根因分析
鸿蒙 musl 的 open_memstream 实现缺陷族（见 E302/DRAFT-13533：fclose 前不 fflush 丢数据）；本候选是该缺陷的另一表现：测试用 open_memstream 承载 EROFS 序列化输出（fwrite 回调 + 增长 buffer），在 clang 15 各优化级别下确定性崩溃（-O0 SIGSEGV、-O1/-O2 SIGILL、带额外 fprintf 布局或 ASan/UBSan 下偶发通过），崩溃随二进制/堆布局漂移。等价真实文件写入（fdopen/mkstemp）稳定通过（20 次探针 0 崩溃）。

## 推荐方案
**方法**: substitute-real-temp-file

**说明**: 测试或工具的输出承载从 open_memstream 替换为真实临时文件（mkstemp + fdopen，写后 unlink），保留原有写入语义（文件回调接口不变）；对必须保留内存承载的场景，先 fflush 再 fclose 并做行为探针（见 E302/DRAFT-13533）。

**修复命令**:
```
testwrite_node: 用 mkstemp(getenv("TMPDIR") 路径)+fdopen 替代 open_memstream，写后 fclose+unlink；重跑 tests/test-lcfs
```

**验证**:
```
./tests/test-lcfs（未补丁: exit 132/139 崩溃；隔离实验 test_basic 单测 8/8 崩溃）；补丁后 3/3 exit 0；等价探针（memstream vs tmpfile 各 20 次）memstream 偶发崩溃、tmpfile 0 崩溃
```
