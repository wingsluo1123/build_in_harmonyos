# E2600: openssl 的 Conan PkgConfigDeps 只生成 openssl-crypto.pc/openssl-ssl.pc，meson 的 dependency('libcrypto') 找不到 libcrypto.pc——配方 generate() 需按依赖包 prefix 生成 libcrypto.pc 垫片并加入 pkg_config_path

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, meson, conan, pkg-config
- **作者**: unknown

## 错误特征
```
Dependency "libcrypto" not found \(tried pkg-config and system\)|meson.build.*libcrypto|pkg-config.*libcrypto
```

## 根因分析
Conan 2 的 PkgConfigDeps 对 openssl 生成 openssl.pc/openssl-crypto.pc/openssl-ssl.pc（组件名命名），不生成 libcrypto.pc；而 meson 项目常按 pkg-config 惯用名写 dependency('libcrypto')（composefs meson.build:52）。结果 conan create 时 meson 报 "Dependency libcrypto not found (tried pkg-config and system)"，即使 openssl 已正确解析。

## 推荐方案
**方法**: pkgconfig-shim-in-generate

**说明**: 在 conanfile.py generate() 中，从 self.dependencies["openssl"].package_folder 读取依赖包前缀，生成 libcrypto.pc（prefix/libdir/includedir + Libs: -lcrypto），放入独立 pc 目录并 prepend 到 tc.pkg_config_path（PkgConfigDeps 生成的 .pc 之前）；同模式可推广到任何"惯用 pkg-config 名"缺失的场景。

**修复命令**:
```
generate(): 写 build_folder/libcrypto-pc/libcrypto.pc（prefix=openssl package_folder），tc.pkg_config_path = pc_dir + 原值；重跑 conan create
```

**验证**:
```
conan install --requires=openssl/4.0.1 -g=PkgConfigDeps 后 ls *.pc（仅 openssl*.pc 无 libcrypto.pc）；配方生成 libcrypto.pc 垫片后 meson configure 通过（Dependency libcrypto found）
```
