# E2603: 上游自带**手写 configure** 且只把 `--help`/`--prefix` 列入 case 白名单时，其余命令行 `var=value` 一律被静默丢弃、同名环境变量只在"探测落空不给变量赋值"的分支里意外存活，而 CFLAGS 被无条件重写 ⇒ 交叉工具链**只能经 make 命令行行内变量**传入，且不能拿 configure 退出码 0 当配置成功

## 错误特征
```
make: O2: No such file or directory | parse_logos.o Error 127 (ignored) | configure prints C compiler not found! yet exits 0, generated Makefile.default ends up with CC=（空值）、CFLAGS=-O2
```

## 根因分析
上游手写 configure 自己实现参数解析，while 循环里 `case "${1%=*}"` 的白名单只有 --help 与 --prefix，未匹配到的命令行 token（含 CC=…、CFLAGS=… 形态）被 shift 静默丢弃；随后脚本又用 which gcc、which cc 两级探测重算 CC，双落空时只打印 C compiler not found! 而不赋值也不退出（于是环境里已有的 CC 反而原样存活，纯属该分支不赋值的副作用），再按 `if [ $CC = gcc ]` 无条件重写 CFLAGS，最后把 CC/CFLAGS 一并 echo 进 Makefile.default 并以 0 退出 ⇒ configure "成功"而生成物里是空编译器，make 阶段命令行首词塌成 -O2，报错离根因两层远且被 (ignored) 前缀吞掉；宿主装有 gcc/cc 时更糟，宿主编译器被直接烧进生成物、产出宿主架构对象
