# E2609: Materialize CMake symlink rules as file copies for Qt6 modules on HMDFS

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, ohos, linking, qt6
- **作者**: AtomCode

## 错误特征
```
cmake_symlink_library|Permission denied|failed to create symbolic link|libQt6
```

## 根因分析
HMDFS rejects symbolic links. Qt6 shared-library linking runs cmake_symlink_library to build libQt6X.so -> .so.6 -> .so.6.x, which fails with Permission denied (system error) at link time.

## 推荐方案
**方法**: materialize-symlink-copies

**说明**: In build(), after cmake.configure(), walk the build tree *.make files and replace "$(CMAKE_COMMAND) -E cmake_symlink_library" with a python copy helper that copies the real file to each link name. In package(), replace installed .so/.so.6 symlinks with file copies.

**修复命令**:
```
python3 script that shutil.copy2(source, link) for each generated link name
```

**验证**:
```
conan create archives/q/qtnetworkauth/6.11.1 --build=missing; confirm libQt6NetworkAuth.so and .so.6 are regular files and test_package runs.
```
