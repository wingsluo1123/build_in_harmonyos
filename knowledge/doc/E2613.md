# E2613: 上游 install 钩子以 `ln -s $(DESTDIR)$(bindir)/<prog>` 自建别名时，conan package() 不带 DESTDIR 安装会把**构建期 package_folder 绝对路径**烙进符号链接目标 ⇒ 包内别名在换 CONAN_HOME/换机后悬空；修法=package() 内把该链接改写为相对目标，HMDFS 拒绝建软链时退化为复制

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, autotools, packaging, symlink, relocatability
- **作者**: QC-10
- **来源 PR**: (本 PR)

## 错误特征
```
'ls -l bin/<alias> -> <构建期绝对 package_folder>/bin/<prog>|dangling symlink after package relocation|包内别名换 CONAN_HOME 后不可解析'
```

## 根因分析
'上游 install 钩子用 `ln -s $(DESTDIR)$(bindir)/<prog>` 建立别名，而 conan 的 package() 以 `make install`（prefix=package_folder、**无 DESTDIR**）安装 ⇒ automake 把 $(DESTDIR) 展开为空、$(bindir) 展开成构建期 package_folder 下的绝对路径，于是别名链接的目标被**固化成构建机上的绝对路径**写进交付包。原地自测（同一 CONAN_HOME、同一路径）链接仍能解析，所以 conan create、G4 产物检查与 test_package 都不会报错；只有当包被复制到别的 CONAN_HOME 或由其它机器从远端拉取时，目标路径不再存在，别名才暴露为悬空链接——属于"可重定位性"类静默缺陷，判据是链接目标里出现 package_folder 绝对前缀。'
