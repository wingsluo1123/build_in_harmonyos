# E2626: glib 公开头不在 <prefix>/include 子目录下，消费者须补 -I<prefix>/include/glib-2.0 与 -I<prefix>/lib/glib-2.0/include

## 基本信息
- **严重度**: 2
- **类别**: conan, consumer, glib, include-path
- **作者**: SunShine_06 <apYppkJJLBwLbnc6.SunShine_06@noreply.gitcode.com>
- **来源 PR**: playerctl 2.4.1 PR（待提交）

## 错误特征
```
fatal error: 'glib.h' file not found|
```

## 根因分析
glib 的公开头布局沿袭其自身 .pc 的 Cflags：glib/gobject/gio 头位于 <prefix>/include/glib-2.0，平台生成的 glibconfig.h 位于 <prefix>/lib/glib-2.0/include（gio-unix 头另在 <prefix>/include/gio-unix-2.0）。conan 组件化 glib 包把这些目录挂在各 component 的 cpp_info 上，根 cpp_info.includedirs 不暴露它们；消费者 test_package 只用根 cpp_info 时 clang 找不到 glib.h。

## 推荐方案
**方法**: cpp-info-union-with-glib-layout

**说明**: test_package conanfile 生成 -I 时取「依赖 cpp_info 通用路径 ∪ glib 布局兜底（include/glib-2.0、lib/glib-2.0/include、include/gio-unix-2.0）」的并集。多余 -I 无副作用，缺一个即编译失败。

**修复命令**:
```
见 archives/p/playerctl/2.4.1/test_package/conanfile.py build() 的 -I 组装逻辑
```

**验证**:
```
conan create archives/p/playerctl/2.4.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing   # test_package 编译含 #include <glib.h>
```
