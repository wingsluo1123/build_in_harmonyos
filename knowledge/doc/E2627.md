# E2627: glib 2.84.0.1 的 GObject 内部原子锁断言（gobject.c:649 object_bit_unlock）在 OHOS/musl 上间歇触发，子进程 bail out 污染消费者测试

## 基本信息
- **严重度**: 1
- **类别**: ohos, musl, atomic, blocking-risk, flaky-test
- **作者**: SunShine_06 <apYppkJJLBwLbnc6.SunShine_06@noreply.gitcode.com>
- **来源 PR**: playerctl 2.4.1 PR（待提交）

## 错误特征
```
GLib-GObject:ERROR:.*gobject\.c:649:object_bit_unlock: assertion failed|
```

## 根因分析
glib 2.84.0.1 的 GObject 引用计数/对象锁实现依赖原子位操作语义（gobject/gobject.c:649 object_bit_unlock 校验 _object_bit_is_locked == lock_bit）。在 OHOS/musl 工具链上该断言间歇性触发：子进程（如 playerctld 守护进程）打印 GLib-GObject:ERROR 后 bail out。表现有两态：stdout 被断言文本污染（文本断言失败）或子进程无输出（pytest-timeout 5s 超时）。同一代码路径在一轮内通过/失败表现相反（test_commands 通过 vs test_basics 失败），凡涉及后台守护进程 + 多播放器切换的用例更易命中。本适配零源码补丁、零二进制改写，故非消费方引入，归因于依赖层 glib 的 musl 原子实现。

## 推荐方案
**方法**: upstream-report-and-glib-rebuild

**说明**: 短期：消费者测试对含 playerctld/GObject 后台驻留的用例按 TEST_QUALITY_SPEC 如实申报失败与归因，不裁剪用例；在具备 session bus 的环境独立实跑并留存日志。中期：向 glib 适配方申报，排查 glib 2.84.0.1 在 OHOS/musl 的原子操作（g_atomic_* / G_GNUC_EXTENSION / __atomic 内建）实现，必要时重建 glib 包。

**修复命令**:
```
grep -n "object_bit_unlock" ~/tmp/*/logs/*.log   # 定位断言原文
```

**验证**:
```
sh run-upstream-tests.sh -o asyncio_mode=auto   # 需具备 session bus 的环境；失败用例 #1/#6/#7/#8/#10/#17
```
