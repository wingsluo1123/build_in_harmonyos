# E2638: cyrus-sasl utils/testsuite 双门槛：getopt 返回值须 int（char 无符号平台 EOF 判定恒真）+ 首个用例需 sasldb 口令库（机制最小包必然阻塞）

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, autotools, testing, evidence
- **作者**: ran (feat/cyrus-sasl-digestmd5-2.1.28)

## 错误特征
```
Failed with: Invalid parameter|comparison of constant -1 with expression of type 'char' is always true|sasl_checkpass\(\) failed on simple case|Must be able to read sasldb
```

## 根因分析
两道独立门槛串联：(1) 可移植性——utils/testsuite.c 的 `main()` 用 `char c` 承接 `getopt()` 返回值，OHOS clang 下 `char` 为无符号，`while ((c = getopt(...)) != EOF)` 中 -1 转为 255 恒不等 → 循环体落 `switch` 的 `default:` → `usage()` + `fatal("Invalid parameter")` 并 exit(3)，任何用例都未执行（同族 cyrus-sasl-sql 已有 0003-testsuite-use-int-for-getopt 先例）；(2) 夹具依赖——修好 (1) 后 `main()` 的第二个动作即 `test_checkpass()`，其要求已初始化的 sasldb 口令库（源码 NOTE 原文 "Must be able to read sasldb, which needs to be setup with a username and a password"），而 DIGEST-MD5 机制包按设计 `--with-dblib=none`（configure 输出 `checking DB library to use... none` + `WARNING: Disabling SASL authentication database support`），口令库后端在 cyrus-sasl 中属独立子包，故 harness 在首个用例即 fatal，其余 18 个标号阶段不可达。

## 推荐方案
**方法**: minimal-portability-patch-plus-honest-evidence

**说明**: 先打最小可移植性补丁（utils/testsuite.c：`char c` → `int c`，只改承接 getopt 返回值的变量，不动任何断言逻辑），使 harness 可运行；再对 harness 的夹具依赖（sasldb）如实申报：配方 build() 仍真实构建并执行 harness，`HMBS_UPSTREAM_TEST_RESULT` 记录真实计数与具体技术原因（status=blocked_by_userdb），不冒充通过；机制级验证由 test_package 的消费者检查承担；MANIFEST.yml 的 upstream_test_audit 逐条列出入口、真实读数与阻塞原因。

**修复命令**:
```
patches/0001-utils-testsuite.c.patch：`-    char c;` / `+    int c;`（--enable-static 下 testsuitestatic 复用同一测试源，两 harness 均生效）
```

**验证**:
```
1) `make -C utils testsuite` 构建 harness；2) `SASL_PATH=<empty-dir> ./utils/testsuite` 与 `./utils/testsuitestatic`：修复前输出 `usage()` + `Failed with: Invalid parameter`（rc=3），修复后进入用例并在 `Checking plaintext passwords...` 处报 `Failed with: sasl_checkpass() failed on simple case`（rc=3）；3) 变体 `-n`/`-r N`/`-a` 结果一致（`-n` 只跳过后续 do-correct 段，不跳过 test_checkpass）；4) 证据行 `HMBS_UPSTREAM_TEST_RESULT` 应如实给出 discovered=19/executed=1/passed=0/failed=1/skipped=18 与 status=blocked_by_userdb。
```
