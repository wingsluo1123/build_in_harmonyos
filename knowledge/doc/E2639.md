# E2639: 上游 configure 按可选工具/分支条件静默降级为子集构建，未探测到的依赖需配方自行注入

## 基本信息
- **严重度**: 2
- **类别**: build-system, cross-compile, packaging, dependency-closure
- **作者**: staralsnow

## 错误特征
```
bpftool not found or doesn't support skeleton generation; not building all tools|fatal error: 'pcap/pcap.h' file not found|cannot find -lpcap|sbin/xdp-bench: No such file or directory
```

## 根因分析
上游 configure 对"可选工具"和"依赖"的探测是分支/环境条件性的：①可选工具（如 bpftool gen skeleton）探测失败时直接清空变量，顶层 Makefile 随之静默不构建依赖它的目标；②某些依赖探针（zlib/libelf/libpcap）只在 vendored-libbpf 分支执行，走 system-libbpf 分支时 configure 直接 return，根本不会发现该依赖。配方若假定 configure 已完成全部依赖探测、或假定产物一定是全量工具集，就会在链接期（找不到 -lpcap）或打包期（少了一批可执行文件）出错。

## 推荐方案
**方法**: assert-actual-artifacts-and-inject-conditional-deps

**说明**: 配方必须对"探测结果"负责而不要对"探测动作"负责：①对 configure 分支未覆盖的依赖，直接从依赖包解析 cpp_info 得到 include/lib 目录并显式注入编译/链接参数（例如 system-libbpf 分支下把 libpcap 的 -I/-L 写进 CFLAGS/LDFLAGS，不能依赖 check_pcap）；②构建后枚举实际产物（sbin/ 下真实可执行文件、lib/bpf/*.o），据此声明 commands.json 与 package_info.bindirs；③把"因缺可选工具而少构建的目标"作为上游既定行为如实写进 notes/MANIFEST/PR，禁止伪造全量或塞占位产物。

**修复命令**:
```
conan create . -pr:h=<profile> -pr:b=<profile>; ls -1 <package>/sbin; grep -n 'USER_LIBS' <src>/xdp-dump/Makefile
```

**验证**:
```
sh configure 2>&1 | grep -i 'not building all tools|pcap support|libbpf support'; grep -n 'USER_LIBS\|check_pcap' Makefile */Makefile configure; ls -1 $PKG/sbin
```
