# E2640: OHOS/bionic 下 libc 头与内核 UAPI 头的结构体冲突：同名双定义 + UAPI 改名

## 基本信息
- **严重度**: 2
- **类别**: kernel, portability, musl, headers, cross-compile
- **作者**: staralsnow

## 错误特征
```
redefinition of 'ethhdr'|redefinition of 'sysinfo'|arithmetic on a pointer to an incomplete type 'struct udphdr'|previous definition is here.*linux/if_ether\.h|previous definition is here.*linux/sysinfo\.h|forward declaration of 'struct udphdr'
```

## 根因分析
OHOS/bionic 把内核 UAPI 与 libc 头拆开且未实现 glibc 的 libc-compat 互操作：libc 头 netinet/if_ether.h、sys/sysinfo.h 无条件定义 struct ethhdr / struct sysinfo，而内核头 linux/if_ether.h、linux/sysinfo.h 也定义同名结构体（前者仅在 __UAPI_DEF_ETHHDR 为 0 时让位），同一 TU 里同时包含即 redefinition；更甚者 UAPI 把 UDP 头改名为 struct __kernel_udphdr，struct udphdr 只在 libc-only 的 <netinet/udp.h>，而 clang -target bpf 不能引 libc 头，于是内核侧解析助手拿到的是不完备类型。

## 推荐方案
**方法**: guard-or-restore-uapi-struct

**说明**: 按形态分别处理：①同名双定义——在会同时看到两套头的 TU 顶部，于任何 include 之前置 __UAPI_DEF_ETHHDR=0（等价 glibc libc-compat），或对 sysinfo 预先定义内核头 guard _LINUX_SYSINFO_H 跳过 UAPI 版本，让 libc 定义成为唯一定义；②UAPI 改名——在仅给 bpf/内核侧使用的公共头里，用构建期特性宏（如 HAVE_OHOS_BPF，由配方在 config.mk 注入 HAVE_FEATURES）回补 struct udphdr 的 UAPI 定义；不要给 bpf 目标引 <netinet/udp.h>。

**修复命令**:
```
printf '#ifndef __UAPI_DEF_ETHHDR\n#define __UAPI_DEF_ETHHDR 0\n#endif\n' >> /tmp/guard.h; cc -include /tmp/guard.h -c source.c; printf '#define _LINUX_SYSINFO_H\n' >> /tmp/guard2.h; cc -include /tmp/guard2.h -c source.c
```

**验证**:
```
grep -n 'ethhdr' $SYSROOT/usr/include/netinet/if_ether.h; grep -n '__UAPI_DEF_ETHHDR' $SYSROOT/usr/include/linux/if_ether.h; grep -n 'struct __kernel_udphdr' $SYSROOT/usr/include/linux/udp.h; grep -n 'struct udphdr' $SYSROOT/usr/include/netinet/udp.h
```
