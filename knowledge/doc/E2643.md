# E2643: "按“类型/名字/签名”三类逐项迁移，不要按单个报错点零散修补：①被删的 <fst/types.h> 在消费方自有基础头

## 基本信息
- **严重度**: P1
- **类别**: build-system
- **作者**: unknown

## 错误特征
```
"fst/types.h.*file not found|no member named .FST_FLAGS|no matching function for call to .stptri_|no viable overloaded .=.*StateIterator"
```

## 根因分析
"OpenFst >= 1.8 对 1.7 API 做了成批破坏性改名/删除：移除 <fst/types.h> 全局定宽别名；全局 flag 改为 FST_FLAGS_*；MapFst/MapFstOptions 改名 ArcMapFst/ArcMapFstOptions；自由函数 Map() 改名 ArcMap()；FstPrinter::Print 收流引用且 dest 变 string_view；FloatWeightTpl::GetPrecisionString 返回 string_view；MatcherBase::Properties 形参改 uint64_t；StateIteratorData::base 改 unique_ptr；CompactFst 静态 WriteFst() 移除（改用构造后 Write()）。任何仍按 1.7 写的消费方库（kaldi 等）在 1.8 下都会以这些签名不匹配报错，且报错点分散在多个头文件、看起来互不相关。"

## 推荐方案
**方法**: "按“类型/名字/签名”三类逐项迁移，不要按单个报错点零散修补：①被删的 <fst/types.h> 在消费方自有基础头里用 <cstdint> 复刻全局别名（using int8 = int8_t; ... uint64 = uint64_t;）；②FST_FLAGS_* 直接改名；③MapFst(Map)、MapFstOptions → ArcMapFst(ArcMap)、ArcMapFstOptions（注意排除库自身的 xxxMap( / CreateMapFst / ->Map( 成员调用，只改自由函数与类型名）；④FstPrinter::Print(&os,..) → Print(os,..)；⑤StateIteratorData::base = new X → data->base.reset(new X)；⑥CompactFst 写盘改 fst::StdCompactAcceptorFst f(fst); f.Write(os, opts);。一次改完再整体编译，否则会连续多轮踩下一个签名。"
