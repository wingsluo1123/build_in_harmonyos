# E2644: "不要逐个例程改调用；改“声明来源”即可：让消费方基础头（如 kaldi 的 matrix/kaldi-blas.h）在

## 基本信息
- **严重度**: P1
- **类别**: dependency
- **作者**: unknown

## 错误特征
```
"no matching function for call to .s?[dt][gp]e?[ts][rv][fi]_|lapack.h.*FORTRAN_STRLEN|cblas-wrappers"
```

## 根因分析
"OpenBLAS 自带的 LAPACK >= 3.10 头文件（lapack.h）无条件定义 LAPACK_FORTRAN_STRLEN_END，把 Fortran 例程声明改成带 2 个隐藏字符串长度参数（如 stptri_ 由 5 参变 7 参）；而按 CLAPACK/f2c 风格编写的消费方代码仍是 5 参指针调用（stptri_(char*,char*,int*,float*,int*)），于是 clang 报 'no matching function'，且同一文件里会连续报出多个不同例程（sgetrf_/sgesvd_/ssptrf_/ssptri_ ...），看起来像一堆独立错误。"

## 推荐方案
**方法**: "不要逐个例程改调用；改“声明来源”即可：让消费方基础头（如 kaldi 的 matrix/kaldi-blas.h）在 HAVE_OPENBLAS 分支不再 #include \"lapacke.h\"，改为引入随源码自带的 CLAPACK 原型头（f2c.h + clapack.h）——同一例程同一 ABI、纯指针参数，与 CLAPACK 风格调用一致。副作用：该分支后续的 #undef abs/dabs/complex 等清理要保留。另一条路是改用 LAPACKE_* 接口，但改动面大且有列主序/返回值语义差异。"
