# E2646: OHOS 上 select/poll 对字符设备写端 fd 永不报告可写，依赖写端就绪的程序会永久挂起

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, socket, chardev
- **作者**: unknown

## 错误特征
```
socat /dev/null /dev/null hangs|data transfer loop hangs|select.*write fd never writable|POLLOUT never ready|character device write
```

## 根因分析
OHOS 内核 poll/select 对字符设备（/dev/null、/dev/zero）的 O_WRONLY fd 从不返回 POLLOUT/可写（普通文件、socketpair 立即就绪）。依赖 select/poll 等待写端就绪后再写入的程序（如 socat 双向数据转移循环）会永久阻塞在 poll/select。

## 推荐方案
**方法**: skip-pollout-for-non-socket-write-fd

**说明**: 对非 socket 写端 fd（fstat 后 S_ISREG/S_ISCHR，含普通文件/字符设备）视为始终可写：不加入 poll 集合（fd=-1）并直接置 maywr=true，跳过 POLLOUT 等待。写普通文件/字符设备不会阻塞，等待 POLLOUT 本就不必要。**r02 细化**：①仅对 S_ISREG/S_ISCHR 生效，管道/FIFO 排除（STALL 等地址故意填满写管道，须保留 POLLOUT 等待，否则 write 阻塞且循环死等）；②当转移循环 4 个 poll fd 全部禁用且某方向 mayrd&&maywr 已就绪时（如 readbytes 消耗后 EOF 待处理），跳过 poll 直接进入 transfer 评估（retval=1 模拟就绪），避免 select 空 fd 集+NULL 超时永久阻塞。

**修复命令**:
```
socat.c 数据转移循环：fd2out/fd1out 赋值处，if (fd>=0 && fstat(fd,&st)==0 && (S_ISREG(st.st_mode)||S_ISCHR(st.st_mode))) { fd=-1; maywr=true; }（两处对称分支）；fd 全部 <0 且 (mayrd1&&maywr2)||(mayrd2&&maywr1) 时 retval=1 跳过 xiopoll
```

**验证**:
```
timeout 10 socat /dev/null /dev/null; echo $?  # 修复前挂起(RC=124 超时杀)，修复后 RC=0
```
