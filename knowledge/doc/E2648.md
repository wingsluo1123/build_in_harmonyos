# E2648: 上游测试数据缺失导致 gtest 二进制中途 SIGTRAP，通过率被严重低估

## 基本信息
- **严重度**: 2
- **类别**: testing, pass-rate, testdata, upstream-tests
- **作者**: AtomCode <atomcode@atomgit.com>
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/12667

## 错误特征
```
Signal 5 \(core dumped\)|ReadTestData .*testdata/|SIGTRAP.*_test|error running test executable
```

## 根因分析
上游 libjxl 的测试数据位于独立仓库 libjxl/testdata，发布 tarball（github.com/<repo>/archive/refs/tags/vX.Y.Z.tar.gz）不含该 git 子模块。libjxl/lib/jxl/test_utils.cc 的 GetTestDataPath() 在编译期由宏 -DTEST_DATA_PATH（CMake 变量 JPEGXL_TEST_DATA_PATH，默认取 <conan source folder>/testdata）固化，因此运行时设置 TEST_DATA_PATH 环境变量完全无效。数据缺失时 ReadTestData() 触发 JXL_CRASH() → SIGTRAP，整个测试二进制中止、后续用例不再执行 → 通过率被严重低估（libjxl-tools/0.11.2 实测：未补数据 409/4778 = 8.6% 假象；补齐后 4778/4782 = 99.92%）。

## 推荐方案
**方法**: fetch-testdata-to-compile-time-path

**说明**: 先用 compile_commands.json 确认编译期宏指向的确切路径；再从可用的 GitHub 代理镜像（本仓库 CI 既有 gh-proxy.com）取回上游 testdata（libjxl/testdata 未使用 git-lfs，raw 内容可直接下载；本机 git-lfs 为失效软链、raw.githubusercontent.com 直连超时），解到宏指向的路径后逐个运行测试二进制统计。若确实无法获取数据，必须如实给出通过率口径与受阻原因，禁止把崩溃计为通过/跳过。

**修复命令**:
```
python3 fetch-testdata.py  # 经 gh-proxy.com 逐文件拉 raw 内容; cp -r <testdata>/. <conan-source-folder>/testdata/
```

**验证**:
```
grep -o 'DTEST_DATA_PATH=[^ ]*' <build>/compile_commands.json 取得编译期期望路径；把数据放到该路径后重跑全部测试二进制，[ OK ] 数应大幅上升、core dump 消失；通过率应以「定义用例 / 已执行 / 通过 / 断言失败」四项分开报告。
```
