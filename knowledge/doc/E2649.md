# E2649: 已发布共享库的 DT_NEEDED 为无 SONAME 的 libz.so，而依赖仓只提供静态 libz.a

## 基本信息
- **严重度**: 2
- **类别**: linking, conan, dependency, self-contained
- **作者**: AtomCode <atomcode@atomgit.com>
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/12667

## 错误特征
```
Error loading shared library libz\.so|needed by .*libpng16\.so\.16|no loader default path provides libz\.so
```

## 根因分析
制品仓（ohpcd）的 zlib/1.3.1.1 仅产出静态 lib/libz.a；而已发布的 libpng/1.6.58 的共享库 libpng16.so.16 其 DT_NEEDED 记录为不带版本号的 "libz.so"（上游 libpng 链接宿主 libz 时未写入 SONAME）。OHOS 系统运行时只提供 /usr/lib/libz.so.1，不存在名为 libz.so 的文件 → 干净环境下 libpng16.so.16 载入失败，进而 cjxl/djxl 报 Error loading shared library libz.so；只有在宿主 /usr/local 前缀存在 libz.so 时才"偶然"可用。

## 推荐方案
**方法**: synthesize-shared-lib-from-static-archive

**说明**: 静态库已带 -fPIC 时，可在 package() 中用一次最小链接调用把 libz.a 整体（--whole-archive）打包成 SONAME 为 libz.so 的共享库，与 libpng16.so* 一并放入包内 lib/，由 $ORIGIN/../lib RPATH 解析。这样既与配方所链接的 zlib 版本保持一致，又不向系统 /lib、/lib64 安装任何同名库（不污染系统运行时，符合 R26 初衷）。

**修复命令**:
```
"<cc>" -shared -fPIC -Wl,-soname,libz.so -o <pkg>/lib/libz.so -Wl,--whole-archive <zlib_pkg>/lib/libz.a -Wl,--no-whole-archive
```

**验证**:
```
env -i "<package>/bin/<tool>" --version 必须 rc=0；readelf -d "<package>/lib/libpng16.so.16" | grep NEEDED 中每个库都应能在包内 lib/ 或系统默认路径解析；ls "<package>/lib/libz.so" 存在且 readelf -d 显示 SONAME 为 libz.so。
```
