# E2650: CMake 库的隐式必需依赖（PNG/APNG）偶合宿主同名库，导致产物包不自包含

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, dependency, find-module, self-contained
- **作者**: AtomCode <atomcode@atomgit.com>
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/12667

## 错误特征
```
Error loading shared library libpng16\.so\.16|Error relocating .*png_.*: symbol not found|Found PNG: .*/usr/local/|Found ZLIB: .*/usr/local/|DT_NEEDED.*libpng16
```

## 根因分析
上游 libjxl 的 extras 编解码器无条件执行 find_package(PNG)（APNG 编解码无条件编译），即使配方并未声明 libpng。CMake 官方模块 FindPNG 会先 find_package(ZLIB)，再读取缓存变量 PNG_PNG_INCLUDE_DIR/PNG_LIBRARY；这些变量在构建机上默认由宿主前缀（如 /storage/Users/currentUser/usr/local，装有 openssl 之外自建的 libpng 1.6.43）满足，于是 cjxl/djxl 得到 DT_NEEDED libpng16.so.16，而包的 lib/ 未随附该库 → 仅在宿主 LD_LIBRARY_PATH 存在时才"可用"，干净环境 env -i 下报 Error loading shared library libpng16.so.16 / symbol not found。构建日志出现 "Found PNG: <宿主前缀>" 是该缺陷的先兆。

## 推荐方案
**方法**: declare-and-pin-find-modules

**说明**: 在 requirements() 显式声明被隐式依赖的库（本例 libpng/1.6.58，其传递依赖 zlib/1.3.1.1）；在 generate() 用 tc.cache_variables 把 CMake 官方 Find 模块的缓存变量钉到 Conan 包内实际文件（PNG_PNG_INCLUDE_DIR / PNG_LIBRARY / ZLIB_INCLUDE_DIR / ZLIB_LIBRARY）；package() 把共享库（libpng16.so*）复制进包内 lib/ 并保持 $ORIGIN/../lib RPATH；test_package 增加 env={} 空环境往返断言，使「不自包含」类缺陷无法再被 conanrun 注入的宿主 LD_LIBRARY_PATH 掩盖。

**修复命令**:
```
tc.cache_variables["PNG_PNG_INCLUDE_DIR"]=f"{pp}/include"; tc.cache_variables["PNG_LIBRARY"]=f"{pp}/lib/libpng16.so"; tc.cache_variables["ZLIB_INCLUDE_DIR"]=f"{zp}/include"; tc.cache_variables["ZLIB_LIBRARY"]=f"{zp}/lib/libz.a"; copy(self,"libpng16.so*",f"{pp}/lib",f"{self.package_folder}/lib",keep_path=False)
```

**验证**:
```
env -i "<package>/bin/<tool>" --version 必须 rc=0 且无 Error loading shared library；readelf -d "<package>/bin/<tool>" 中每个非系统 DT_NEEDED 都应能在包内 lib/ 找到；构建日志中 "Found PNG:"/"Found ZLIB:" 必须指向 Conan 包路径而非宿主前缀。
```
