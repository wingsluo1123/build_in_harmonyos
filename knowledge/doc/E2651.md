# E2651: JPEGXL_STATIC=ON 向 EXE_LINKER_FLAGS 追加 -static，与共享依赖（brotli .so）冲突

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, link, shared-dependency, static
- **作者**: AtomCode <atomcode@atomgit.com>
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/12667

## 错误特征
```
JPEGXL_STATIC.*-static|ld\.lld: error: attempted static link of dynamic object|unable to find library -lbrotli|attempted static link of dynamic object
```

## 根因分析
libjxl 的 JPEGXL_STATIC=ON 会向 EXE_LINKER_FLAGS 追加 -static，强制整个可执行文件（含所有传递依赖）静态链接；当某个 Conan 依赖（如 brotli/1.2.0）配方仅产出共享库 .so 时，lld 拒绝把动态对象静态链接而报错。该选项语义为「产出全静态可执行」，与「外部依赖以共享形式提供」的制品仓现实直接冲突。

## 推荐方案
**方法**: keep-in-tree-static-but-shared-deps-dynamic

**说明**: 保留内建库静态（BUILD_SHARED_LIBS=OFF），同时令 JPEGXL_STATIC=OFF，让外部依赖保持共享；再把共享依赖的 .so（及其间接需要的运行时库）复制进包内 lib/，并烘焙 CMAKE_INSTALL_RPATH / CMAKE_BUILD_RPATH=$ORIGIN/../lib，使工具自包含可运行（随包 .so 与二进制一并进行 OHOS 签名）。

**修复命令**:
```
tc.variables["BUILD_SHARED_LIBS"]="OFF"; tc.variables["JPEGXL_STATIC"]="OFF"; tc.variables["CMAKE_INSTALL_RPATH"]="$ORIGIN/../lib"; package(): copy(self,"libbrotli*.so*",f"{bp}/lib",f"{self.package_folder}/lib",keep_path=False)
```

**验证**:
```
conan create 链接阶段不得出现 attempted static link of dynamic object；readelf -d <pkg>/bin/<tool> | grep NEEDED 应列出包内共享依赖（libbrotlidec.so.1 等）且都能在包内 lib/ 解析；env -i <pkg>/bin/<tool> --version 可运行。
```
