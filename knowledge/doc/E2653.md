# E2653: 上游 CMake 默认在线 clone vcpkg 并以其 toolchain 接管依赖，空 VCPKG_ROOT 挡不住（离线 configure FATAL）⇒ 补丁短路 clone + 强制 system-deps

## 基本信息
- **严重度**: 2
- **类别**: portability, network, build-system, cmake, toolchain
- **作者**: 主理-22
- **来源 PR**: 待建（本 PR 内提交）

## 错误特征
```
vcpkg will be cloned into|clone_vcpkg_from_baseline|Failed to run the clone_vcpkg_from_baseline|You must specify a repository to clone
```

## 根因分析
上游把 vcpkg 当作默认依赖通道：顶层 CMakeLists 在 VCPKG_ROOT（默认

## 推荐方案
**方法**: patch-shortcircuit-vcpkg-clone-and-force-system-deps

**说明**: 用补丁把上游 clone 条件前置 VCPKG_ROOT 真值判断（改成 if(VCPKG_ROOT AND (NOT WIN32 OR BASH_VERSION_RESULT EQUAL 0) AND NOT EXISTS ${VCPKG_ROOT})），并在 generate() 里用 **tc.cache_variables["VCPKG_ROOT"] = ""** 下发空值（cache_variables 正是由 conan 展开为命令行 -D 的路径）（⚠不能只用 tc.variables：上游在 project() 之前就 set(...CACHE...) 了默认值，toolchain 变量抢不到）；空值即短路整块在线 clone。同一补丁给 vcpkg 产物安装块加 if(VCPKG_INSTALLED_DIR) 守卫，防 VCPKG_INSTALLED_DIR 为空时把宿主 /lib 打进包。第二处补丁把无 vcpkg 分支的 pkg_check_modules 改成「有 CMake config 包就用它、否则回退 pkg-config」（cryptopp 上游无 .pc，Conan 只产 CMake config）。所有上游开关（FULL_REQS/WITH_FUSE/USE_*/ENABLE_*）同样经 tc.cache_variables 下发（conan 展开为命令行 -D），因为上游在 project() 之前 include 的 option() 模块会抢占 tc.variables。补丁后走上游自带的 else 分支（日志出现 Using system dependencies），依赖全部由 Conan 的 CMakeDeps 注入，构建不再依赖外网。补丁只加条件/加分支、不改既有语义，保持可向上游提交的形态（P005）。

**修复命令**:
```
patches/000N-shortcircuit-vcpkg-clone.patch + patches/000N-system-deps-via-cmake-config.patch；conanfile.py generate()：tc.cache_variables["VCPKG_ROOT"]=""、tc.cache_variables["FULL_REQS"]="OFF" …（conan 展开为命令行 -D）
```

**验证**:
```
'1) 上游触发点（判定是否命中本形态）: grep -n "clone_vcpkg_from_baseline\|vcpkg will be cloned" CMakeLists.txt; 2) 空 VCPKG_ROOT 仍会 clone（把顶层条件抄进 cmake -P 脚本，不编译，set(VCPKG_ROOT "" CACHE PATH "") 后 if((NOT WIN32) AND NOT EXISTS ${VCPKG_ROOT}) 为真）; 3) 真实症状复现（代理指向不可达端口即断网，无需改上游）: env https_proxy=http://127.0.0.1:9 GIT_TERMINAL_PROMPT=0 cmake -S <src> -B /tmp/probe-vcpkg -DVCPKG_ROOT= 2>&1 | tail -20 → 出现 -- vcpkg will be cloned into 与 Failed to run the clone_vcpkg_from_baseline，RC=1; 4) 打补丁后同一命令 → 不再出现 vcpkg will be cloned，改为出现 Using system dependencies; 5) 时序陷阱自检（判定"选项到底生没生效"）: grep -n "include(megacmd_options)\|^project(" CMakeLists.txt 看 include 是否在 project() 之前；若在之前，再 grep 生成物 <build>/generators/conan_toolchain.cmake 里同名 set(...CACHE...) 行与 configure 日志里该选项的实际取值，两者不一致即命中本陷阱，必须改走命令行 -D（Conan 配方侧即 tc.cache_variables）; 6) 依赖通道自检: pkg-config --list-all | grep -c . （本机为 0）与 ls <build>/generators/*.pc（Conan CMakeDeps 下为空）⇒ 证明 system-deps 分支的 pkg_check_modules 必挂，需 0002 类补丁'
```
