# E2657: OHOS C 库连 POSIX 标准函数 sockatmark(3) 都不声明也不导出，需按特性改发该函数规范自身定义的底层 ioctl(fd, SIOCATMARK, &val)

## 基本信息
- **严重度**: 2
- **类别**: compat, libc, musl, headers
- **作者**: 主理-26 <z26@local>

## 错误特征
```
call to undeclared function 'sockatmark'|implicit declaration of function 'sockatmark'|undefined symbol: sockatmark|referenced by support.c
```

## 根因分析
sockatmark(3) 由 POSIX.1-2001 标准化，glibc 与 macOS 都在 <sys/socket.h> 里声明它，因此上游 C 代码普遍把它当作"POSIX 就有"而直接使用。OHOS 工具链的 C 库既不声明也不导出该符号：编译期 clang 报 call to undeclared function 'sockatmark'（-Wimplicit-function-declaration，非致命），链接期 ld.lld 报 undefined symbol: sockatmark（致命）。缺的不是 GNU/BSD 扩展，而是 ISO POSIX 标准函数，所以 musl 上游"不实现非 POSIX 扩展"这一条常见解释在此不成立——musl 自己确实提供 sockatmark，且其实现就是发一条 SIOCATMARK ioctl。OHOS 的 SDK 头 <bits/ioctl.h> 反而提供了 SIOCATMARK，缺的只是那层 POSIX 包装。

## 推荐方案
**方法**: reimplement-posix-func-via-underlying-ioctl

**说明**: 在调用方补一个本地静态包装函数，直接发 sockatmark(3) 规范自身定义的底层操作 ioctl(fd, SIOCATMARK, &atmark)（POSIX 原文即"equivalent to ioctl(fildes, SIOCATMARK, &atmark)"，musl 的 sockatmark 亦是同一条 ioctl），因此与参考实现同构而非伪造返回值。开关按特性分流（#ifdef SIOCATMARK）而非按平台分流：具备该 ioctl 的平台走 ioctl，不具备的平台保留原 POSIX 调用，对 glibc/macOS 零行为变化，补丁里不含任何平台宏。失败时返回 -1 并把 errno 交给调用方，与 POSIX 错误语义一致。

**修复命令**:
```
patch: 在 src/support.c 增加 static int socket_atmark(int fd){ #ifdef SIOCATMARK int atmark=0; if (ioctl(fd,SIOCATMARK,&atmark)<0) return -1; return atmark; #else return sockatmark(fd); #endif } 并把 sockatmark(RemoteFD) 调用点换成 socket_atmark(RemoteFD)，同时补 #include <sys/ioctl.h>（实例: archives/q/qperf/0.4.11/patches/0001-support-sockatmark-via-siocatmark.patch）
```

**验证**:
```
grep -rn sockatmark <OHOS-sysroot>/usr/include || echo NO_DECLARATION; grep -rn 'define SIOCATMARK' <OHOS-sysroot>/usr/include/*/bits/ioctl.h; printf '#include <stdio.h>\nint sockatmark(int);\nint main(void){printf(\\"%%d\\", sockatmark(0));return 0;}\n' > t.c && clang t.c   # 链接期报 undefined symbol: sockatmark
```
