# E2673: init-build 按 URL 猜测构建系统把 codeload 的 CMake 项目误判为 autotools，配方模板需按源码重写

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, init-build, template
- **作者**: unknown

## 错误特征
```
BUILD_SYSTEM=autotools.*CMakeLists|conanfile.*Autotools 模板|生成的.*autotools.*配方|conan-verify.*模板.*不匹配|BUILD_SYSTEM="autotools"
```

## 根因分析
init_build._guess_build_system(url) 仅按 URL 字符串关键字判断：含 "cmake" 判 cmake、含 "mesonbuild" 判 meson、含 "openssl"/"python" 判 custom，其余一律默认 "autotools"。codeload.github.com 官方 tag 归档 URL（形如 .../tar.gz/refs/tags/vX.Y.Z）不含任何 cmake/meson 关键字 → 被默认判为 autotools，conan-init 据此生成 Autotools 模板 conanfile.py（AutotoolsToolchain/Autotools）。实际项目是 CMakeLists.txt 构建时，模板与构建系统不符：conan create 会尝试 configure/make 而项目根本没有 configure 脚本。

## 推荐方案
**方法**: 以源码实际构建系统为准重写配方：build 驱动已按 CMakeLists.txt 正确编译（产物 OK），但 conan-init 生成的 autotools 模板必须替换为 CMake 模板（conan.tools.cmake.CMake/CMakeToolchain/cmake_layout + generate() 设 BUILD_SHARED_LIBS），并同步修正 manifest.yaml 的 build_system=cmake 与 cpp_info.libs（按上游 CMake 目标名，如 libgff 的 gff 目标 → libs=["gff"]）。

**说明**: 1) 在源码 work 目录确认 CMakeLists.txt 存在、无 configure 脚本；2) 用 templates/conanfile-cmake.py.tmpl 重写 conanfile.py（设置 settings/options/layout/source/generate/build/package/package_info，generate() 中 tc.variables["BUILD_SHARED_LIBS"]="OFF"，package_info 中 cpp_info.libs 用上游 CMake 目标 basename）；3) 修正 manifest.yaml build_system: cmake；4) test_package 若模板是 C 项目而上游头文件是 C++，须改为 CXX 项目 + .cpp 源（find_package(libgff REQUIRED) + target_link_libraries libgff::libgff）；5) 重新运行 conan-verify 全门禁。

**修复命令**:
```
python3 scripts/ohc-run.py conan-verify <name> <ver>
```

**验证**:
```
grep -q '^BUILD_SYSTEM="autotools"' .build-context-<name>-<ver> && grep -q CMakeLists.txt "$HOME/tmp/builds/<name>-<ver>.work/CMakeLists.txt"  # 两者并存即触发本模式
```
