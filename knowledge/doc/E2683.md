# E2683: Keep optional SIMD call sites aligned with compiled implementation objects

## 基本信息
- **严重度**: 3
- **类别**: cmake, linking, runtime, arm-neon, source-selection
- **作者**: Theresa
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/10297

## 错误特征
```
undefined symbol: (MergeUVRow|YUY2ToUVRow|ARGBToYMatrixRow)_(NEON|SVE|SVE2)
```

## 根因分析
The target compiler enabled AArch64 SIMD call sites while the CMake-generated target omitted matching NEON and SVE implementation objects, so the final link referenced symbols that no compiled object defined.

## 推荐方案
**方法**: aligned-generic-simd-fallback

**说明**: When optional SIMD implementation objects cannot be selected reliably, disable the corresponding declarations and dispatch call sites together so the generic implementation remains linkable and functionally testable.

**验证**:
```
Run the failing link baseline, disable LIBYUV_DISABLE_NEON LIBYUV_DISABLE_SVE LIBYUV_DISABLE_SVE2 together, then execute libyuv_unittest and the installed-package consumer.
```
