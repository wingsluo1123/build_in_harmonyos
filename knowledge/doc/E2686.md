# E2686: conan 2.29.1 在 export 阶段拒绝裸单段版本号（version="1" → ERROR: Invalid package version '1'）；版本号须归一化为多字符形式（如 1.0），语义不变

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, recipe, versioning
- **作者**: unknown

## 错误特征
```
Invalid package version '[a-z0-9_]{1}'
```

## 根因分析
conan 2.x 的版本引用校验要求版本号至少 2 字符（首字符 + 至少 1 个后续字符）。上游版本为单字符/单段（如 "1"、"2"、"a"）时 export 阶段即拒绝，报 Invalid package version。上游项目常用语义版本（X.Y）极少触发；但以 Homebrew 公式版本为钉死口径的三方库会踩中——公式允许裸 "1"，conan 不允许（fabric-completion 即此例，公式 fabric-completion version=1）。

## 推荐方案
**方法**: normalize-multi-char-version

**说明**: 版本号归一化为与原语义一致的多字符形式（首选补零段 X.0，如 1 → 1.0），同步归档目录名、分支名（L0n R40 精确匹配）、manifest/conanfile/test_package 全部版本引用；官方 main 无裸单段版本号先例，归一化与本库惯例一致。

**修复命令**:
```
grep -n 'version' conanfile.py && conan create . --build=missing
```

**验证**:
```
conan create . --build=missing  # version="1": export 即 ERROR Invalid package version '1'; version="1.0": 通过（真机 conan 2.29.1 最小复现实证）
```
