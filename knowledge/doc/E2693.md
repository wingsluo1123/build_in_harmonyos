# E2693: 零构建系统裸 C 库（仅 .c/.h 源码）的 Conan 配方模式：static-library 绕 shared 契约 + conf 编译器直接编译 + 平铺头文件安装

## 基本信息
- **严重度**: 2
- **类别**: build-system, compiler, conan, packaging, static-library
- **作者**: pc7-18

## 错误特征
```
Package type is 'library', but no 'shared' option declared|conan-init.*autotools.*模板|No makefile|no build system
```

## 根因分析
①上游仅提供 .c/.h 源码、无任何构建系统（无 Makefile/configure/CMake）时，ohc-run.py conan-init 按 URL 猜测构建系统会误判为 autotools 并生成错误模板；②Conan 2 的 package_type="library" 强制要求声明 shared 选项契约（Package type is 'library', but no 'shared' option declared），纯静态库不便引入无意义的 shared 分支；③无构建系统意味着 build() 必须手写直接编译（clang -c + llvm-ar rcs），package() 必须平铺拷贝头文件与 .a。

## 推荐方案
**方法**: static-library-plus-direct-compile-plus-flat-header

**说明**: ①package_type 声明为 "static-library"（而非 "library"），绕开 Conan 2 的 shared 选项契约；②build() 中从 Conan conf 取编译器（conf 子键在 OHOS 适配版 Conan 2.29.1 未注册时 try/except 回退 PATH 上的 clang/llvm-ar，R33 合规），执行 clang -c -O2 -fPIC -std=c99 直接编译 .c 并用 llvm-ar rcs 打包静态库；③package() 用 copy 平铺拷贝公共头文件（log.h/log_cfg.h 同目录互 include，必须同层）与 libembedded-log.a，LICENSE 一并拷贝；④cpp_info.libs 声明库名。

**修复命令**:
```
package_type = "static-library"; def build(): cc = conf_get_or_fallback("c", "clang"); ar = conf_get_or_fallback("ar", "llvm-ar"); self.run(f"{cc} -c -O2 -fPIC -std=c99 -I{src_dir} {src_dir}/log.c -o log.o"); self.run(f"{ar} rcs libembedded-log.a log.o"); def package(): copy(self, "log.h", src=src, dst=include, keep_path=False); copy(self, "log_cfg.h", src=src, dst=include, keep_path=False); copy(self, "libembedded-log.a", src=build, dst=lib, keep_path=False)
```

**验证**:
```
python3 scripts/ohc-run.py conan-verify embedded-log 1.0.1 2>&1 | grep -E "G[0-4]: PASS|配方验证通过"
```
