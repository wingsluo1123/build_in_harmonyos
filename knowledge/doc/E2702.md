# E2702: 数据包不要把上游 .pc.in 直接装进包：在 package() 里用 self.package_folder 现写 

## 基本信息
- **严重度**: 3
- **类别**: autotools, pkg-config, packaging, relocatable, data-package
- **作者**: unknown

## 错误特征
```
pkg-config --variable=prefix .* (returned|= )\s*$| .*datafiles are not installed| Please install .* package| prefix=@prefix@| @prefix@|@VERSION@|@exec_prefix@
```

## 根因分析
上游是"库/工具 + 独立数据包"的拆分结构，消费方没有把数据目录 写死，而是通过 pkg-config 反查：先取 uctodata 的 prefix， 再拼 /share/ucto。于是 .pc 里的 prefix 成为数据目录的**唯一** 来源。配方若照搬上游 .pc.in（内含 @prefix@），或干脆不装 .pc， 消费方拿不到目录，configure 直接报"datafiles are not installed"。 这类包通常没有源码，无法靠编译失败暴露问题，只能靠显式断言兜住。

## 推荐方案
**方法**: 数据包不要把上游 .pc.in 直接装进包：在 package() 里用 self.package_folder 现写 .pc 的 prefix，并同时设置 cpp_info.resdirs 与 pkg_config_name 覆盖"找 datadir"与"找 pkg-config 名"两条消费路径；装配契约交给 test_package 真实执行 pkg-config --variable=prefix 断言，而不是照搬含 @prefix@ 的 .pc.in。

**说明**: 纯数据包没有可重定位的 pkg-config 契约时，消费方 configure 反查不到数据目录，报 "datafiles are not installed"。修法：package() 用 package_folder 现写 uctodata.pc（不装含 @prefix@ 的 .pc.in），并补 cpp_info.resdirs / pkg_config_name，使 pkg-config --variable=prefix 返回真实包目录。

**修复命令**:
```
pkg-config --variable=prefix uctodata
```

```
|
```
