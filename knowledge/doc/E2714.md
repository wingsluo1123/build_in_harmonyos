# E2714: "Create the worktree with --no-checkout; write sparse-checko

## 基本信息
- **严重度**: P1
- **类别**: git\, windows\, workflow\, worktree
- **作者**: unknown

## 错误特征
```
"unable to create file .*Invalid argument|Could not reset index file to revision|can't open input file.*build_and_test|幽灵修改|worktree.*No such file or directory"
```

## 根因分析
"Two chained Windows worktree pitfalls. (1) origin/main contains a committed filename ending in two CR characters (archives/g/gama/2.29/patches/0002-dataparser-ungated.patch\\r\\r); Win32 cannot create files with control characters, so ANY full checkout of origin/main on Windows fails at 100% with 'Invalid argument' and git rolls back the worktree. (2) 'git worktree add' seeds the new worktree's index from the current repo's index, which carries skip-worktree bits (for files Windows cannot materialize) and staged user content — a subsequent read-tree/checkout can materialize files whose bytes come from the MAIN worktree's staged blobs, producing phantom modifications in a brand-new worktree."

## 推荐方案
**方法**: "Create the worktree with --no-checkout; write sparse-checkout patterns directly into <main>/.git/worktrees/<lib>/info/sparse-checkout with printf (bypassing Git Bash MSYS path mangling which silently rewrites '!/archives/' into '!C:/Program Files/Git/archives/'); exclude archives/ and re-include your own package dir; then run 'git read-tree -u --reset HEAD' (--reset discards the inherited index — note '-mu --reset' is an invalid flag combination); finally require 'git status --short' to be completely empty before starting any work. Long-term fix is renaming the CR-suffixed file from a Linux checkout."
