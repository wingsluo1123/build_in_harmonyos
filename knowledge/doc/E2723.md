# E2723: DL 推理 header-only 库的上游测试数据生成依赖 Python TF/Keras 后端（OHOS aarch64/musl 无 TF 轮子）时的完整恢复路径：鸿蒙社区源 jaxlib ohos_aarch64 轮子 + keras 版本适配 + 层兼容实现 + 语义对齐，使上游测试 7/7 全部实际运行通过

## 基本信息
- **严重度**: 2
- **类别**: dl-inference, test-data-generation
- **作者**: unknown

## 错误特征
```
No module named 'keras'|No module named 'jax'|Could not find a version that satisfies the requirement tensorflow|test_model_.*\.json.*No such file|Invalid node index|Two-Pool Gather.*mismatch|value shape should be
```

## 根因分析
frugally-deep 类 DL 推理 header-only 库的上游测试数据由 keras_export/generate_test_models.py（用 keras 构建模型并训练）生成 .keras，再经 convert_model.py 转换为 .json；两者强制依赖 Python 训练后端（TensorFlow/JAX/torch）。OHOS aarch64（musl libc）无 tensorflow 轮子（默认 PyPI 与鸿蒙社区源均 No matching distribution），keras 可装但 numpy backend 引依赖的 jax 亦缺失；且 keras 3.15.1 的 MultiHeadAttention 在 jax backend 存在 value_dim≠key_dim reshape 冲突、IntegerLookup/IndexLookup 在 __init__ 无条件要求 TF、Adaptive* 池化层在 keras≤3.12 缺失、jax backend 的 adaptive pooling（Two-Pool Gather）窗口计算与 fdeep C++ 的 adapt_range 公式逐点不一致——任一未解决都会导致测试数据不可用或 verify 数值失败。

## 推荐方案
**方法**: community-source-ohos-jaxlib + keras-version-adaptation + layer-compat-shim + fdeep-semantics-alignment

**说明**: ①鸿蒙社区源 pypi.cnb.cool 提供 jaxlib cp312-ohos_aarch64 专用轮子（SHA-256 与 simple 页一致），直接下载解压到 site-packages 即可使 jax backend 可用（无需 pip 临时目录，规避共享区 inode 限制）；②keras 选用 3.14.1（3.15.1 的 MHA jax reshape 有 bug、≤3.12 缺 Adaptive* 层），jax backend 冒烟验证 GQA(use_gate)/MHA(value_dim≠key_dim)/Adaptive* 全通过；③IntegerLookup/IndexLookup 无 TF 时用 keras ops 实现语义等价层（output_mode='int'、num_oov_indices==1、vocabulary、mask_token，语义同 fdeep integer_lookup_layer），register_keras_serializable 后注入 keras.layers；④adaptive pooling 按 fdeep adapt_range 公式（输出索引 i 对应窗口 [floor(i*in/out), ceil((i+1)*in/out))，in==1 折叠 [0,1)）直接实现并 patch keras.src.backend.jax.nn 子模块（注意是子模块而非父模块属性），使 convert 生成的 target 与 fdeep C++ 逐点一致；⑤上游脚本原样生成 .keras → convert_model.py 原样转 .json → 测试目标原样加载运行，不改变任何测试语义。

**修复命令**:
```
python3 -m pip install jaxlib==0.10.2 -i https://pypi.cnb.cool/... ; KERAS_BACKEND=jax python3 keras_export/generate_test_models.py <model> <out>.keras ; KERAS_BACKEND=jax python3 keras_export/convert_model.py <out>.keras <out>.json ; clang++ -std=c++17 test/test_model_*.cpp -o bin/<name> && ./bin/<name>
```

