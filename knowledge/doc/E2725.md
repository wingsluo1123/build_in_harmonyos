# E2725: 上游测试/样例源码使用 Windows 反斜杠 include 路径（`..\..\code\foo.h`），POSIX 编译器按字面解析导致 'file not found' — 补丁改为正斜杠即可

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, portability, build-system
- **作者**: unknown

## 错误特征
```
fatal error: '\.\.\\\.\.\\code\\|file not found|no such file or directory.*\\\\include|'\\\\' file not found
```

## 根因分析
Windows 优先开发的上游项目测试源常写 `#include "..\..\code\fts_fuzzy_match.h"`（反斜杠）。POSIX 文件系统中 `\` 是普通字符，路径按字面拼接无法解析 → clang 报 `fatal error: '..\..\code\...' file not found`。这不是平台宏问题（R8 无涉），是源码字面路径的平台可移植缺陷。

## 推荐方案
**方法**: patch-backslash-include-to-forward-slash

**说明**: 在 patches/ 中用最小补丁将反斜杠 include/路径改写为正斜杠（`..\..\code\` → `../../code/`），保持其余内容不变。补丁格式 a/b 前缀 + patch -p1 可应用（已用干净 .orig 验证）。仅当上游确实包含反斜杠路径时使用；不要引入 __OHOS__ 宏。

**修复命令**:
```
git diff 生成补丁并放入 patches/0001-*.patch；conan create 复验
```

**验证**:
```
clang++ -std=c++17 -I code tests/fuzzy_match/fts_fuzzy_match_test.cpp -o fts_test_upstream
```
