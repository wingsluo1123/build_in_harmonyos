# E2726: STB 风格单头文件库（fts_fuzzy_match 等）的 test_package/消费者源必须在 include 前定义实现宏（如 FTS_FUZZY_MATCH_IMPLEMENTATION），否则声明可见而实现缺失 → 链接 undefined symbol

## 基本信息
- **严重度**: 2
- **类别**: headers, conan, packaging, testing
- **作者**: unknown

## 错误特征
```
ld.lld: error: undefined symbol: fts::fuzzy_match|undefined symbol: .*IMPLEMENTATION|ld.lld: error: undefined symbol
```

## 根因分析
STB 风格单头文件库把完整实现放在 `#ifdef XXX_IMPLEMENTATION` 块内（公共接口只有声明）。consumers 只 `#include <header>` 而忘记定义宏时，编译期一切正常（头文件声明可见），但链接期 ld.lld 报 undefined symbol。这是 header-only 与常规库 test_package 的最大差异：header-only 库的"链接成功"依赖消费者正确实例化实现宏，配方本身没有可链接产物可兜底。

## 推荐方案
**方法**: define-implementation-macro-before-include

**说明**: test_package 测试源（以及独立消费者程序）在 `#include <xxx.h>` 之前定义该库的实现宏 `#define FTS_FUZZY_MATCH_IMPLEMENTATION`（与上游 tests 用法一致，非平台宏、无需 patch）。实现宏不发生冲突：宏内部是 static 函数，单翻译单元实例化即可。

**修复命令**:
```
test_package/test.cpp 首行（include 前）添加对应宏定义
```

**验证**:
```
conan create archives/l/lib_fts/1.2.8 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
