# E2751: Debian native 源包作 conan 钉死源的方法论：pool tarball + .dsc Checksums-Sha256 互证；salsa gitlab /-/archive/ gzip 流不可钉死；备源取同文件镜像（installation-birthday 20 实证）

- **类别**: ohos, conan, debian, pinning, sourcing
- **作者**: unknown

## 根因分析
一类任务（依赖类三方库）上游为 Debian 源包而非 github 发行：无 tag/release 之外的独立发行物，版本号即 Debian sid 版本。钉死要点：(1) native 包（dsc Format: 3.0 (native)）无 .orig.tar，pool 里的 tar.xz 即完整源；(2) 钉死依据 = .dsc 文件 Checksums-Sha256 字段（与 tar.xz 本地下载实测互证）；(3) salsa gitlab 的 /-/archive/<ref>/*.tar.gz 是服务端即时打包的 gzip 流，每次请求字节可能不同，不可作 sha256 钉死源（git ls-remote 可确认 tag 存在作旁证）；(4) 无 gitcode 镜像时备源取官方镜像站同文件（如清华 TUNA，同字节同 sha256，且设备侧下载更稳）；(5) debian/ 打包目录（cron 集成/manpage 生成规则/autopkgtest）属发行集成，不进入 conan 包载荷。

## 推荐方案
**方法**: pool-tarball-plus-dsc

**说明**: conandata 主源 = deb.debian.org pool tarball，sha256 取 .dsc；备源 = 清华 TUNA 同路径同文件；manifest/notes 记录「salsa tag ↔ Debian 版本」对应关系；上游测试若仅 autopkgtest，在探针中复刻其语义并声明。

**修复命令**:
```
curl -sO https://deb.debian.org/debian/pool/main/…/<pkg>_<ver>.dsc && grep -A2 Checksums-Sha256 <pkg>_<ver>.dsc
```

**验证**:
```
sha256sum <pkg>_<ver>.tar.xz  # 与 .dsc Checksums-Sha256 一致（installation-birthday_20.tar.xz: e1ed3ef6…a5621 实证）
```
