# E2753: "上游用 .symver/version-script 绑定 glibc 符号版本节点，在 musl/OHOS 上链接期即失败"

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, libc, musl, build-system
- **作者**: "TGFAT-1 <tgfat-1@local>"
- **来源 PR**: ""

## 错误特征
```
"ld.lld: error: .* has undefined version GLIBC_[0-9.]+|symbol .* has undefined version|expected a '@' in the name"
```

## 根因分析
"glibc 的符号版本机制（.symver 汇编指示 + --version-script 里的 GLIBC_x.y 节点）是 glibc 专有；OHOS 用 musl，libc.so 里不存在任何 GLIBC_x.y 版本定义，ld.lld 因此在'符号有版本引用但找不到版本定义'处直接报错。次生坑：把 .symver 第二个参数去掉 @ 试图表达'无版本别名'也不行——OHOS 的 clang 内联汇编前端（IntegratedAsm/AArch64）强制要求 .symver 名字带 @，报 expected a '@' in the name"

## 推荐方案
**方法**: "symver-alias-branch"

**说明**: "用 #if defined __GLIBC__ 包住原 .symver 块（glibc 路径零改动），#else 分支对每个拦截点用 __attribute__((alias)) 把'当前 ABI 变体'导出为未版本化的公开名；同时把 --version-script 参数化成可替换变量，OHOS 侧换一份匿名（无版本节点名）的 local-only map，只把 _22/_225/_232/_233 实现名设为 local。载体要求：这份 OHOS-only map 由配方 build() 用 save() 生成，不要用补丁新增文件——本仓 finish 的 refresh-patch --auto 只按'已存在的源文件'逐个重生成补丁并静默丢弃 new-file hunk，落地后会报 ConanException: Patch file does not exist"

**修复命令**:
```
"sed -i 's/--version-script=libfaketime.map/--version-script=$(VERSION_SCRIPT)/' src/Makefile && make VERSION_SCRIPT=libfaketime.map.ohos"
```

**验证**:
```
'grep -rn "\.symver\|version-script" src/ && nm -D --defined-only <so> | grep -E "GLIBC_|_2[0-9]+$"'
```
