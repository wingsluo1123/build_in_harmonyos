# E2754: 任务指定包名与上游真名不一致（libblzf vs liblzf）时，R40 分支名校验要求归档目录/包名/commands.json 全部对齐分支名而非改分支；版本迭代须同步 commands.json versions（R38）

## 基本信息
- **严重度**: 2
- **类别**: conan, ci-quality-gate, cli-tool, package-naming, version-bump
- **作者**: unknown

## 错误特征
```
L0k: commands\.json missing version .*(R38)|L0n: branch name mismatch \(R40\) — 分支完全不包含 包名-版本号
```

## 根因分析
PR 分支名 feat/libblzf-3.6.1 为任务指定分支名（任务要求包名即 libblzf，非 typo），但归档曾用上游真名 liblzf 建目录 archives/l/liblzf/3.6.1/。CI 的 L0k (R38) 按 pkg_name 解析软件级 commands.json 的 versions 未登记 3.6.1 报 commands_json_r38；L0n (R40) 要求分支名（去前缀）精确等于 pkg_name-pkg_ver，pkg_name=liblzf 与分支 libblzf-3.6.1 不匹配报 branch_name_r40。两处都在 L0 gate 拦截。次要：本地复跑时 origin/main 落后，junk_check.sh 的 git diff origin/main...HEAD merge-base 过旧把历史已合并包全算进本 PR，JC6 误报 N 包；先 git fetch origin main 再复跑即恢复合规。

## 推荐方案
**方法**: align-package-name-with-branch-and-sync-commandsjson

**说明**: 把归档目录/包名/commands.json name/manifest software 全部对齐任务分支名（libblzf），上游 conandata URL 保持官方源（R39：包名可不同于上游名）；版本迭代时同步 commands.json versions 补新版本条目；本地复跑前先 fetch origin main。

**修复命令**:
```
git fetch origin main && CI_PACKAGES="archives/l/libblzf/3.6.1" CI_BRANCH="feat/libblzf-3.6.1" zsh ci/conan/build_and_test.sh
```

**验证**:
```
CI_PACKAGES="archives/l/libblzf/3.6.1" CI_BRANCH="feat/libblzf-3.6.1" zsh ci/conan/build_and_test.sh
```
