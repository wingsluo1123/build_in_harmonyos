# E2760: Legacy Python setup.py templates can require Git history absent from codeload archives

## 基本信息
- **严重度**: 2
- **类别**: build-system, python, packaging, versioning
- **作者**: 328

## 错误特征
```
Missing version information.*autogen\.sh|Didn't find a git repository.*no tags found|%%version%%
```

## 根因分析
Some legacy Python projects leave release metadata as %%version%% templates and invoke autogen.sh from setup.py when the tokens remain. The generator uses git describe --tags, but GitHub codeload archives contain source files without .git or tag refs. Running setup.py/pip against that archive therefore fails before installation even though the pure-Python module itself is usable. Shyaml 0.6.2 and vaab/colour 0.1.5 share this .package/autogen.sh pattern.

## 推荐方案
**方法**: pinned-release-metadata-and-direct-module-staging

**说明**: Pin the upstream tag archive and SHA-256, substitute only release-derived placeholders from the Conan recipe version, and stage the pure Python module plus an equivalent relocatable CLI entry point without invoking a VCS-dependent autogen step.

**修复命令**:
```
python3 -c "from shyaml import __version__; assert __version__ == '0.6.2'"; then run the installed CLI and the upstream doctest/docshtest suite
```

**验证**:
```
Inspect setup.py/setup.cfg for %%version%% and the fallback autogen.sh; extract the pinned codeload archive, verify .git is absent, then run the package's documented setup.py --version or pip install command and record the missing-repository error.
```
