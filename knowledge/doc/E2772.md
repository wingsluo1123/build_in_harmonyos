# E2772: 旧库用 __GLIBC__ 数值比较和 HAVE_* definedness 误判 musl 能力

## 基本信息
- **严重度**: 2
- **类别**: libc, feature-guard
- **作者**: tank_you

## 错误特征
```
conflicting types for getline|getdelim|implicit declaration of ether_hostton
```

## 根因分析
musl 未定义 __GLIBC__，在 #if 数值比较中被当作 0 导致旧 getline 原型启用；configure 将 HAVE_ETHER_HOSTTON 定义为 0 时，definedness 检查又误删 fallback 声明。

## 推荐方案
**方法**: guard-libc-identity-and-test-feature-values

**说明**: 对 __GLIBC__ 数值判断先检查 defined；对明确为 0/1 的 HAVE_* 宏检查值；验证真机原生配置、安装包及行为。

**修复命令**:
```
'#if defined(__GLIBC__) && __GLIBC__ < 2; #if !HAVE_ETHER_HOSTTON'
```

**验证**:
```
inspect config.h and preprocessed headers; conan create with OHOS profile; compare loopback UDP payloads
```
