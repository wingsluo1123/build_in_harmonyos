# E2773: 上游 cgit 快照端点失效时用 Debian pristine orig 取指定 commit；

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, python, link, port
- **作者**: unknown

## 错误特征
```
snapshot.*400|snapshot.*502|no reconfigure|print statement|
```

## 根因分析
三类在"只提供 git 仓 + 自带老测试 + 静态自注册"的历史库上共同的适配障碍。(1) 目标 commit 没有上游 release tarball，且 cgit 快照端点服务端故障（simulavr 2026-09-27 实测 tar.gz/tar.bz2/xz=502、zip=400，对 commit hash 与 tag 均如此），只能退到 Debian pool 的 pristine orig.tar.xz——它是上游原始树（无 debian/ 打包目录），配套 debian.tar.xz 不使用，做法同 nicovideo-dl/cppnumericalsolvers 先例，并按 PF7 官方托管例外登记。(2) 老 autotools 项目的 regress/ 套件是 Python 2，Python 3 下 120 文件里 85 个无法字节编译，make check 无法运行；移植为 Python 3 后仍有两处残留——(8*1024/2-1) 作为 %x 参数在 py3 的真除法下变 float 触发 TypeError（// 在 py2/py3 语义一致，最小修复），以及 modtest/ 中依赖 avr-gcc 的文件无需/不可运行。(3) 设备经 AVR_REGISTER 宏在静态初始化期自注册（每设备一个 registrar 对象，main 不直接引用任何设备符号）；静态链接只拉取被引用符号所在归档成员 → 全部 registrar 被丢弃 → 设备表为空、`-d <device>` 报 Invalid device。上游始终以共享 libsim.so 交付（Debian 实证 NEEDED libsim.so + RUNPATH）故无此问题；但 OHOS musl 忽略 DT_RUNPATH 且 CI L2 执行 bin/ 时不设 LD_LIBRARY_PATH，共享方案运行时找不到 .so；而 -Wl,--whole-archive libsim.la 因 libtool 重排标志而无效，最终靠 automake convenience library（noinst_LTLIBRARIES + 把对象的 $(am_libsim_la_OBJECTS) 并入程序的 OBJECTS）保留全部对象。(4) 构建主机跑不了 autoreconf（autoconf 家族不在 PATH、设备无 automake/aclocal/libtoolize、HMDFS 拒绝 execve 自建文件），须提交 autoreconf 产物 preconf/。

## 推荐方案
**方法**: pinned-downstream-orig + preconf + convenience-lib + sh-configure + port-upstream-test-harness

```
conandata.yml: sources.url + sha256 (Debian orig)；
```
