# E2775: 旧 C 源包预带静态归档时强制重建并验证 inline 外部符号

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, static-library, legacy-c, reproducibility
- **作者**: tank_you
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/12716

## 错误特征
```
undefined reference to complex_mul|undefined symbol: complex_mul|archive has U complex_mul but no T complex_mul
```

## 根因分析
旧源包自带 libconvolve.a，普通 make 可能复用原归档；同一 inline 定义在 Clang C99 语义下不产生 complex_mul 外部符号，而调用方目标文件存在 U complex_mul。只看到归档生成并不能证明可链接。

## 推荐方案
**方法**: force-rebuild-and-consumer-link

**说明**: 用目标编译器对源包执行 make -B；在该包中用 -fgnu89-inline 保持原 GNU89 外部定义语义；检查归档成员 T/U 符号，并通过已安装包的消费者链接与运行验证真实闭包。不要仅以归档存在或 make 成功判定通过。

**修复命令**:
```
conan create archives/l/libconvolve/0.0.8 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=libconvolve/0.0.8 -r=ohpcd
```

**验证**:
```
conan create archives/l/libconvolve/0.0.8 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=libconvolve/0.0.8 -r=ohpcd
```
