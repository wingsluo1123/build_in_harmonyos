# E2786: "拆双 profile：-pr:b 用 os=Windows（build profile 描述执行构建的机器），-pr:

## 基本信息
- **严重度**: P2
- **类别**: platform, cross-compile, conan, local-verification
- **作者**: unknown

## 错误特征
```
"'.' 不是内部或外部命令|'.' is not recognized as an internal or external command|Package type is 'library', but no 'shared' option declared|System is unknown to cmake, create: Platform/HarmonyOS"
```

## 根因分析
"在 Windows 宿主本机用 conan 交叉构建 OHOS 包时：① build profile 若照抄 CI 写成 os=OHOS，conan 认为构建机是 POSIX，只生成 conanbuild.sh 并以 POSIX '. source' 前缀执行命令，cmd.exe 把行首 '.' 当程序名报「'.' 不是内部或外部命令」——真实原因是 profile 语义错位，不是 cmake/配方问题；② SDK clang.exe 默认 target 是 x86_64-w64-windows-gnu，直接当 OHOS 编译器会编出错误架构或配置失败。"

## 推荐方案
**方法**: "拆双 profile：-pr:b 用 os=Windows（build profile 描述执行构建的机器），-pr:h 用 os=OHOS。host profile 的 tools.build:compiler_executables 指向一个 .cmd 包装器（SDK clang.exe + --target=aarch64-linux-ohos --sysroot=<SDK>/native/sysroot），并补 ar/ranlib/strip 指向 SDK llvm/bin，generator=Ninja 用 SDK 自带 build-tools/cmake/bin（缺 Platform/HarmonyOS 警告无害）。从 PowerShell 而非 Git Bash 运行（MSYS 会改变 conan 的环境文件选择）。conan 2.29 对只出静态库的配方要求 package_type=static-library 或声明 shared 选项（library 类型无 shared 选项会被拒）。本机 create 通过后、向真机传输包目录前，删除 test_package/build/ 与 CMakeUserPresets.json 生成物并按提交清单核对文件数。"
