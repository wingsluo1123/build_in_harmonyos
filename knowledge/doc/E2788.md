# E2788: "在 conanfile.py source() 用 replace_in_file 加目标架构守卫（#if defin

## 基本信息
- **严重度**: P1
- **类别**: portability
- **作者**: unknown

## 错误特征
```
"This header is only for x86|unknown instruction.*bsf|bsfq.*error|error: unrecognized instruction|output constraint.*must.*register"
```

## 根因分析
"上游在 x86 上开发，源码无守卫地包含 <x86intrin.h> 并使用 x86 专属内联汇编（bsfq）。clang 的 x86intrin.h 对非 x86 目标直接 #error；即使 intrinsic 宏（如 TB_NO_HW_POP_COUNT）有纯 C 回退，裸内联汇编也不受任何宏控制，aarch64 交叉编译必失败。宏守卫只解决 popcount 一半，掩盖了汇编另一半。"

## 推荐方案
**方法**: "在 conanfile.py source() 用 replace_in_file 加目标架构守卫（#if defined(__i386__) || defined(__x86_64__)），x86 保留原路径，非 x86 用 __builtin_ctzll 等语义相同的编译器内建；不要用 __OHOS__ 守卫（回退分支对所有非 x86 目标成立）。打补丁前必须核实上游所有调用点保证输入非零（ctzll(0) 是 UB）。同时沿用上游 Makefile 原配宏（TB_NO_THREADS/TB_NO_HW_POP_COUNT）。test_package 用 helper API（tb_lsb/tb_pop_count 等恰好执行被补丁路径的函数）做实质验证，不需要目标数据文件。"
