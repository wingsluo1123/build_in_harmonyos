# E2799: "Capability probe, not platform branch: at the top of build(

## 基本信息
- **严重度**: 2
- **类别**: platform, hmdfs, cmake, shared-library
- **作者**: unknown

## 错误特征
```
"Operation not permitted.*(symlink|create_symlink|ln -s)|EPERM.*(symlink|link)|cmake.*create_symlink.*(libtiff|\\.so\\.[0-9])|cannot create symbolic link"
```

## 根因分析
"libtiff sets VERSION/SOVERSION unconditionally in cmake/AutotoolsVersion.cmake (plain set() with no platform gate), so every shared build generates a versioned symlink chain. On the HarmonyOS PC device the build tree and package dir live on hmdfs, which lacks symlink support (EPERM), while the Linux farm needs the upstream-identical versioned layout. The two environments require opposite outputs, and upstream offers no switch a plain Linux build would not also trip."

## 推荐方案
**方法**: "Capability probe, not platform branch: at the top of build(), attempt os.symlink() inside the build folder; on OSError append -DCMAKE_PLATFORM_NO_VERSIONED_SONAME=ON (CMake then ignores VERSION/SOVERSION and emits a bare libtiff.so with unversioned SONAME and no symlinks). The Linux farm passes the probe, so its layout stays upstream-identical; zero source patches, one recipe behaves correctly in both environments."
