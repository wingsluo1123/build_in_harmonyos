# E2801: 移植非 glibc 目标时必须成组移除旧版 memcpy 符号绑定与链接包装

## 基本信息
- **严重度**: 3
- **类别**: portability, libc, musl, linking
- **作者**: frj__

## 错误特征
```
undefined symbol: memcpy@GLIBC_2.2.5|RECURSION_PROBE_RC=42
```

## 根因分析
上游把 .symver memcpy,memcpy@GLIBC_2.2.5 强制注入每个翻译单元，并用 --wrap=memcpy 及 __wrap_memcpy 对旧 glibc memcpy 做兼容包装；OHOS musl 只有未版本化 memcpy，链接无法解析 GLIBC_2.2.5。仅去掉 .symver 会使包装函数自己的 memcpy 调用再次被 --wrap 重写，形成递归。

## 推荐方案
**方法**: remove-glibc-versioned-wrapper-as-a-unit

**说明**: 确认包装仅为旧 ABI 兼容后，在非 glibc 构建中一起取消 .symver 强制 include、--wrap=memcpy 和 memcpyWrap.o；让 clang++ 链普通 libc memcpy，并重跑上游测试。

**修复命令**:
```
patch -p1 < 0001-remove-glibc-versioned-memcpy-wrapper.patch; make; make test
```

**验证**:
```
llvm-nm -u <object> | grep -F 'memcpy@GLIBC_2.2.5'; llvm-nm -u <patched-archive> | grep -F 'U memcpy'; make test
```
