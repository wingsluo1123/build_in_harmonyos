# E2811: OHOS/HarmonyOS 运行时在进程启动前预装 SIGILL/SIGSEGV/SIGSYS/实时信号处理器，启动时逐一检查 sa_handler 的程序会 panic

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, portability, syscall, runtime
- **作者**: pc3-19

## 错误特征
```
bad incoming signal value for SIGILL|initsignals: bad incoming signal|panic:.*signal|sa_handler.*SIG_DFL.*SIG_IGN.*SIG_ERR
```

## 根因分析
OHOS/HarmonyOS 运行时（libc/hnp 启动链路）在 main() 之前为 SIGILL、SIGSEGV、SIGSYS 及若干实时信号预装崩溃/回溯 handler。程序启动阶段若用 sigaction(sig, NULL, &sa) 逐一检查并 panic 于"非默认"handler（既非 SIG_DFL 也非 SIG_IGN 也非 SIG_ERR），会把运行时 handler 当作异常状态。es-shell 0.9.2 的 initsignals() 即因此 panic："bad incoming signal value for sigill: %x"（实测 sig=4/11/31/36/37/42/44 有预装 handler）。

## 推荐方案
**方法**: treat-prestalled-handler-as-default

**说明**: 启动期信号检查把"非 DFL/IGN/ERR 的既有 handler"视为 sig_default（平台运行时占用），继续安装本程序自己管理的 handler，而不是 panic。可在 #ifdef __OHOS__/_OHOS 守卫下实现（含实质回退逻辑，符合 R8），或无条件放宽检查（对 Linux 无影响——Linux 上几乎不存在预装 handler）。

**修复命令**:
```
signal.c: else sigeffect[sig] = sig_default;（替代 panic）——标注 OHOS 运行时预装 crash/backtrace handler 的原因注释
```

**验证**:
```
struct sigaction sa; for(sig...) sigaction(sig,NULL,&sa) 检查非 DFL/IGN/ERR handler；或复现 es-shell trip 测试 panic 日志
```
