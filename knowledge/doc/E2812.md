# E2812: 程序自有全局函数与链接库符号重名（如 es 的 getstr 与 ncursesw 的 curses getstr）→ ld.lld duplicate symbol，应改名自有符号

## 基本信息
- **严重度**: 2
- **类别**: portability, linking, dependency, symbol
- **作者**: pc3-19

## 错误特征
```
duplicate symbol: getstr|ld\.lld: error: duplicate symbol|defined at lib_gen\.c.*in archive.*libncursesw\.a|duplicate symbol: \w+.*defined at .*term\.c
```

## 根因分析
程序自带全局函数（如 es-shell 的 `char *getstr(Term*)` 在 term.c 定义）与链接的依赖库符号同名；readline 依赖 terminfo 导致 libncursesw.a 的 lib_gen.o 被整体拉入，其内包含 curses 的 `getstr` → 链接期 duplicate symbol。属自有符号与依赖库归档/共享库符号冲突，非头文件宏污染。

## 推荐方案
**方法**: rename-own-symbol

**说明**: 把自有全局符号改名（es-shell 的 getstr → es_getstr），全项目 15 个 .c + 头文件声明同步替换（机械改名，不改变语义）。禁止用 --allow-multiple-definition 掩盖。

**修复命令**:
```
grep -rl '\bgetstr\b' *.c *.h | xargs sed -i 's/\bgetstr\b/es_getstr/g'
```

**验证**:
```
nm <objfiles> | grep -w getstr; nm libncursesw.a | grep -w 'T getstr'; ld.lld 链接报 duplicate symbol
```
