# E2813: configure.ac 引用 $ac_cpp 但未 AC_PROG_CPP → autoconf 2.72 下 ac_cpp 为空 → 类型/信号检测结果为空 → 编译期宏空值报错

## 基本信息
- **严重度**: 3
- **类别**: detection, portability, build-system, autotools
- **作者**: pc3-19

## 错误特征
```
checking for rlimit type \.\.\.\.\.\. $|define LIMIT_T $|\(LIMIT_T\)n.*expected expression|checking for files to extract signal information from\.\.\. $|cannot guess build type
```

## 根因分析
上游 configure.ac 自定义宏（如 AC_CMDSTDOUT_CPP）内部使用 `$ac_cpp` 做预处理器探测，但脚本从未调用 AC_PROG_CPP（只调 AC_PROG_CC）。autoconf 2.72 下 ac_cpp 在未运行 AC_PROG_CPP 时为空，configure 执行到该宏时把 `-I<path>` 当作命令执行（报 "-I...: No such file or directory"），探测结果为空 → AC_DEFINE_UNQUOTED 生成空值宏（如 `#define LIMIT_T `）→ 编译期 `(LIMIT_T)n` 报 "expected expression"。

## 推荐方案
**方法**: add-ac-prog-cpp

**说明**: 在 configure.ac 的 Checks for programs 段（AC_PROG_CC 之后）补一行 `AC_PROG_CPP`，重新 autoconf 生成 configure 后即可恢复全部基于 $ac_cpp 的探测（rlimit 类型 → rlim_t、信号文件列表等）。

**修复命令**:
```
sed -i '/^AC_PROG_CC$/a AC_PROG_CPP' configure.ac && autoconf
```

**验证**:
```
grep -n "ac_cpp" configure.ac; grep -n "AC_PROG_CPP" configure.ac; grep -n "define LIMIT_T" config.h（空值即命中）
```
