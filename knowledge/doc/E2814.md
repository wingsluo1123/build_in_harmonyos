# E2814: OHOS PC 无运行时（Emacs 未移植）的解释型/数据型软件包：以内容级消费者探针（清单+尺寸防漂移+版本头/功能符号+许可证+负向注入）代替运行时验证

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, testing, recipe
- **作者**: LIMInGZE666 <LIMInGZE666@noreply.gitcode.com>
- **来源 PR**: 13227

## 错误特征
```
emacs.*not found|command not found.*emacs|inform_mode_probe.*FAIL|字节数 [0-9]+ != 63201|site-lisp 目录.*[0-9]+ 文件
```

## 根因分析
解释型软件包（Emacs Lisp 单文件 inform-mode.el）的运行方式依赖 Emacs 运行时，而 OHOS PC 真机未移植 Emacs——"加载运行/byte-compile"类消费者测试在真机不可行。若退化为只断言文件存在，无法区分完整包与截断/篡改包，验证强度不足；且 CI Linux 有 Emacs 而真机无，两类环境若验证口径不一致（运行时路径为唯一验证），真机必挂。

## 推荐方案
**方法**: content-level-probe

**说明**: 以五层内容级断言代替运行时验证：(1) 目录精确计数——防多余/缺失文件；(2) 文件在位+非空+上游字节数精确断言——尺寸防漂移，与 recipe build() 防漂移校验双保险；(3) 文件头元数据（Version/Released/Keywords）+ 功能符号（defun/defvar/defcustom/autoload cookie）逐条断言——证明内容完整且为真实发行物；(4) 许可证全文关键词断言；(5) 截断注入拒绝语义负向用例（把真实文件原地覆盖为截断载荷→尺寸防漂移断言检出拒绝→恢复原载荷→复验字节数+版本头）——证明探针路径真实读写包目录且防漂移断言对截断有实际拦截语义。运行时可用场景（CI Linux 有 Emacs）可叠加 byte-compile 条件路径，但不得作为唯一验证；内容级断言为跨环境一致基线。

**修复命令**:
```
inform_mode_probe <site-lisp-dir> <package-folder>（见 test_package/inform_mode_probe.cpp）
```

**验证**:
```
真机：conan create -pr:h ci/conan/profiles/ohos-aarch64 --build=missing → inform_mode_probe 5 组断言全过、EXIT=0。宿主：MinGW g++ 编译探针 + 按 package() 布局 1:1 模拟包同口径全过。
```
