# E2815: 定点编解码库码流跨架构设计上非位元一致:官方哈希 ref 测试必须按架构分流(位元比对限 x86)

## 基本信息
- **严重度**: 2
- **类别**: cross-compile, testing, arch, audio-codec, determinism
- **作者**: LIMInGZE666 <LIMInGZE666@noreply.gitcode.com>
- **来源 PR**: 0

## 错误特征
```
hash diff vs ref|ref-.*\.txt.*differ|encode hash.*mismatch.*0 failures
```

## 根因分析
FDK_archdef.h:117 将 __aarch64__ 统一映射为 __arm__,ARMv8 路径选择 ARCH_PREFER_MULT_32x16 与 SINETABLE_16BIT / POW2COEFF_16BIT / LDCOEFF_16BIT 等 16-bit 系数表(x86 走 32-bit 表)。编码器心理声学模型虽全程 FIXP_DBL 定点运算,但系数表位宽按架构选择 → 码流跨架构非位元一致是上游刻意设计。官方 ref-stereo.txt / ref-mono.txt 由 x86 生成,其他架构直接 diff 必挂。

## 推荐方案
**方法**: arch-split-hash-gate

**说明**: test.sh 按 uname -m 分流——x86(含 i686/i386)严格 diff 官方 ref;其他架构以上游工具自身质量门禁(退出码 0 = 各模式 avg_diff 全在阈值内)+ 哈希行形状正则校验为准,并打印 NOTE 说明为架构定点表位宽差异,防止被误读为适配缺陷。

**修复命令**:
```
if ! diff -u log-stereo.txt ref-stereo.txt; then if [ "$(uname -m)" = "x86_64" ] || [ "$(uname -m)" = "i686" ] || [ "$(uname -m)" = "i386" ]; then echo FAIL; exit 1; else echo "NOTE: $(uname -m) 哈希与 x86 官方 ref 不同(上游定点表位宽平台差异),以上游工具质量门禁为准"; grep -q '^encode hash: [0-9a-f]\{40\}$' log-stereo.txt || exit 1; fi; fi
```

**验证**:
```
同套件双端对照——x86(MinGW)跑官方 test-encode-decode 哈希与 ref 逐字节一致;aarch64 真机同套件退出码 0、全模式 0 failures 但哈希不同 → 差异来自架构而非构建。查表位宽宏:grep -n "SINETABLE_16BIT\|POW2COEFF_16BIT\|ARCH_PREFER_MULT" libSYS/include/FDK_archdef.h
```
