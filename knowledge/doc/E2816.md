# E2816: OHOS sysroot的dirent.h不声明GNU versionsort(3)时把scandir比较器回退为POSIX alphasort(3)的单库语义回退

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, libc, musl, headers
- **作者**: 主理-70-子代理-mstpd3

## 错误特征
```
use of undeclared identifier 'versionsort'|undeclared identifier.*versionsort
```

## 根因分析
OHOS NDK sysroot（musl系）的 dirent.h 完全不声明 versionsort(3)——整棵 include 树 grep 命中 0 次，_GNU_SOURCE 与 _BSD_SOURCE 两块里只有 getdents/DT_*/星64 别名；本包该文件的真实编译行本来就带 -D_GNU_SOURCE 仍报 use of undeclared identifier，故缺失发生在平台头文件层，不是特性宏没打开

## 推荐方案
**方法**: scandir-comparator-versionsort-to-alphasort-under-ohos-guard

**说明**: 在两枚 scandir 调用点各加 #ifdef __OHOS__ 分支把比较器换成 POSIX alphasort(3)（sysroot 声明的签名 int alphasort(const struct dirent **, const struct dirent **) 与 scandir 第四参数逐字一致），#else 分支保留上游 versionsort；条目集合由过滤器决定、比较器只决定列出次序，故可用性不变而排序语义降级为字典序，必须在 PR 与 notes 里披露

**修复命令**:
```
新增 archives/m/mstpd/0.2.0/patches/0002-ctl-main-versionsort-alphasort-ohos.patch（GNU diff 生成、a/ 与 b/ 前缀走 patch -p1），并在 conandata.yml 的 patches 段登记 patch_type: portability
```

**验证**:
```
grep -r versionsort <ohos-sysroot>/usr/include 命中0；同包真实编译旗标（-D_REENTRANT -D__LINUX__ -D_GNU_SOURCE -D__MUSL__ -Os -Wall）下 scandir(...,versionsort) 最小 TU rc=1 报同错、换 alphasort rc=0 且 stderr 0 字节；整包 conan-verify 的 Verdict 行为 PASS
```
