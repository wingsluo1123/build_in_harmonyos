# E2817: 上游 CMake 在 project() 后覆盖编译器，导致 Clang-only 目标错误调用 GCC

## 基本信息
- **严重度**: 2
- **类别**: cmake, compiler, selection
- **作者**: tank_you

## 错误特征
```
make: gcc: No such file or directory|C_STANDARD is set to invalid value '18'
```

## 根因分析
ud 1.1.0 的 CMakeLists.txt 在 project(ud) 后执行 set(CMAKE_C_COMPILER gcc)，覆盖 -DCMAKE_C_COMPILER=clang；另有 set(TARGET ud PROPERTY C_STANDARD 18) 写法无效，CMake 的标准值 18 不受支持。

## 推荐方案
**方法**: honor-selected-compiler-and-use-supported-c-standard

**说明**: 不要在 project() 后硬编码 CMAKE_C_COMPILER。保留环境/工具链选择的 Clang，将错误的 C_STANDARD 18 写法改为受支持的 CMAKE_C_STANDARD 17；在私有 TMPDIR 中构建并用安装包消费者验证。

**修复命令**:
```
'cmake -S . -B build -DCMAKE_C_COMPILER=clang && cmake --build build -j1'
```

**验证**:
```
cmake -S . -B build -DCMAKE_C_COMPILER=clang; cmake --build build -j1; conan create with OHOS armv8 profile
```
