# E2824: "上游测试运行时打公网端点（httpbin/squid/reqbin）时，用配方自托管的纯标准库回环替身替换端点，使整套 gtest 在 CI/真机上真实执行"

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, testing, http-client, loopback
- **作者**: "TGFAT-1 <tgfat-1@local>"
- **来源 PR**: ""

## 错误特征
```
"(Connection refused|Could not resolve host|Couldn't resolve host name|error:20SSL_?[A-Z_]*HANDSHAKE|CURLE_COULDNT_CONNECT|Problem ssl steering)|0 tests? passed, [0-9]+ tests? failed out of [0-9]+|Test #1.*(httpbin|api\\.reqbin)|ctest .*No tests were found"
```

## 根因分析
"一批 C/C++ 库把'测试端点'写死成公网 HTTP 服务（restclient-cpp 的 51 例里，RestClientTest/ConnectionTest 打 httpbin.org，ConnectionTestRemote 还要求真实 TLS 握手与一个 CONNECT 代理，代理配置来自 test/squid.conf）。这类依赖在集成环境里同时断三条路：CI worker 无公网出口、真机不装 docker/httpbin/squid、即便有网也随时被上游服务限流。表现为整批用例连接失败，或者更糟——为绕过失败而把测试入口整体关掉，交付'0 执行'。知识库既有条目只覆盖构建期取不到测试框架（FetchContent 拉 googletest），没有覆盖'测试运行时的外部服务端'这一类"

## 推荐方案
**方法**: "stdlib-loopback-standin-in-build"

**说明**: "把外部端点收敛成可覆盖的常量（RESTCLIENT_TEST_SERVER / _URL_TLS / _PROXY_URL），再用一个零第三方依赖的 Python 标准库服务在配方 build() 里自托管同一组语义：明文 HTTP(8998) 复刻 httpbin 的 /get /post /put /patch /delete /options /anything /headers /basic-auth/<u>/<p> /redirect/<n> /delay/<s> /status/<code>，TLS(8999) 用仅绑定 127.0.0.1/localhost 的自签名证书（配 SetCAInfoFilePath 编译期注入 CA 路径），代理(3128) 只做 CONNECT 转发——这三层分别覆盖连接、TLS 校验和代理三条独立代码路径，缺一层就有一批用例失去意义。替身必须做 ready-file 握手并有早退检测（进程早退就把它的日志路径抛出来），否则失败会伪装成'全部超时'。关键保真约束：断言按字面比较，所以响应必须是 pretty JSON 且以换行结尾、恒发 Connection: keep-alive、保留请求头原始大小写、url 字段由原始 request-target + Host 头重建。构建期注意 gtest_discover_tests 的 PRE_BUILD 默认会在 build 阶段执行测试程序，交叉构建必须显式改 PRE_TEST。最后：只排除确实无法本地复刻的单例（HTTP/2 版本协商），用 ctest -E 排除并在正文'未执行测试'里逐项写原因，不删用例、不把跳过判成通过"

**修复命令**:
```
"conan create archives/r/restclient-cpp/0.5.3 -pr:h=<ohos-aarch64> -pr:b=<ohos-aarch64>   # -pr:b 同档使 can_run() 为真，套件才在设备本机执行"
```

**验证**:
```
"grep -rnE 'https?://[a-z0-9.-]+\\.(org|com|io)' test/ tests/ 2>/dev/null | head; grep -rln 'squid\\|proxy' test/ 2>/dev/null; <已装替身的配方> conan create ... 2>&1 | grep -E 'Total Tests:|tests passed|tests failed'"
```
