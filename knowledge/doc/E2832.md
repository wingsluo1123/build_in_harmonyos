# E2832: Meson配方OHOS真机缺meson/pkg-config且profile编译器路径缺失时的供给与native file重写及版本化头双根

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, testing
- **作者**: hmbs-executor
- **来源 PR**: 12659

## 错误特征
```
Unknown compiler\(s\).*clang|Pkg-config for machine host machine not found|libuhttpmock-1\.0/uhttpmock/uhm\.h.*file not found|uhttpmock/uhm-message\.h.*file not found|TLS support is not available
```

## 根因分析
HMBS仅注入cmake/make/ninja/python3而profile将compiler_executables钉死在不存在的/data/service/hnp/bin/clang且MesonToolchain默认不写pkgconfig行，裸路径烘焙致Unknown compiler与glib-2.0 pkg-config查询失败；上游头为include/libuhttpmock-1.0子目录而内部短前缀包含需双根；OHOS glib栈仅GDummyTlsBackend无GIO TLS模块致TLS子项失败

## 推荐方案
**方法**: meson-tool-supply-plus-native-rewrite-dual-roots

**说明**: build_requirements以tool_requires供给meson与pkgconf，generate内经conf存在性校验后探测真clang并预先pin pkgconfig绝对路径加PKG_CONFIG导出，生成后重写native file的c与cpp行与无行插入pkgconfig，test_package侧同理重写conan_toolchain.cmake，主包includedirs取include与include下版本子目录双根，TLS失败保留gaps转警告继续打包

**修复命令**:
```
conanfile.py加tool_requires meson 1.11.0加pkgconf 3.0.5；generate后重写conan_meson_native.ini与conan_toolchain.cmake；package_info includedirs为include与include/libuhttpmock-1.0
```

**验证**:
```
真机复检确认conan_meson_native.ini中c/cpp与pkgconfig均为存在性校验后绝对路径，上游meson test为2/2/1/1加gaps含GDummyTlsBackend与server.c 321，test_package经conan_toolchain.cmake重写后建成且双include根下两类include均可定位
```
