# E2834: 纯 Python noarch 包的 staging 目录必须放在源码树之外（否则被 setuptools flat-layout 自动发现当成顶层包）；装 wheel 时应用 pip --target 而非 --prefix（后者实测装出空目录），装源码目录时 --prefix 可用但须断言落点

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system
- **作者**: AtomCode <noreply@atomgit.com>
- **来源 PR**: 13242

## 错误特征
```
Multiple top-level packages discovered in a flat-layout|site-packages not found under staging|packages = find:|staging 空目录（装 wheel 时 pip --prefix 退出码 0 但目录为空）
```

## 根因分析
(A) conan 中未定义 layout() 的配方 self.build_folder == self.source_folder，于是 os.path.join(self.build_folder,'staging') 落在源码树内；pybeam 用 pyproject.toml 且未显式声明 packages，setuptools 走 flat-layout 自动发现，扫到同级 staging/ 与 pybeam/ 构成两个顶层包 -> Multiple top-level packages discovered in a flat-layout ['pybeam','staging']。同理 setup.cfg 里 packages = find 形态的包（pyenchant）也有被纳入风险。(B) pip install --prefix=<dir> 依赖 <dir>/lib/pythonX.Y/site-packages 布局；**装 wheel** 时实测退出码 0 但 <dir> 仍为空（zstandard 0.25.0）；--target=<dir> 语义明确，内容平铺（含 *.dist-info），打包时整目录拷入 site-packages。注意边界：--prefix 并非普遍失效——pybeam 0.8.1 以 --prefix 装**源码目录**实测正常装出 <staging>/lib/python3.12/site-packages/pybeam，故 (B) 的适用范围仅限装 wheel，装源码目录时 --prefix 可用但仍须断言落点。

## 推荐方案
**方法**: staging-outside-sourcetree-then-target-for-wheel

**说明**: staging 一律取 source_folder 的**父目录**（os.path.join(os.path.dirname(os.path.normpath(self.source_folder)), '_staging_' + self.name)），确保落在源码树之外；装 **wheel** 时用 pip install --target=<staging> 而非 --prefix（后者装 wheel 实测为空目录），并在装完后**断言** <staging>/<pkgname> 存在，把「空安装」提前变成显式失败。装**源码目录**时 --prefix 可用（pybeam 0.8.1 实证），同样须在装完断言 <staging>/lib/pythonX.Y/site-packages 下有包。

**修复命令**:
```
pip install --break-system-packages --no-deps --target=<staging> <wheels>/*.whl
```

**验证**:
```
test -d <staging>/<pkgname> || echo EMPTY-STAGING; python3 -c "import os;print(os.path.dirname(os.path.normpath('<source_folder>')))"
```
