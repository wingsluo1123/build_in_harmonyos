# E2835: OHOS 用户态 applet 可用但无同名命令入口时，脚本应 command -v 探测并回退 busybox applet（勿裸调命令名）

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, runtime, shell
- **作者**: unknown

## 错误特征
```
umount: inaccessible or not found|chroot: not found|.*: inaccessible or not found|busybox --list.*(umount|chroot|install)|Signal 31.*core dumped|exit 159
```

## 根因分析
OHOS 用户态由 Toybox/多调用二进制提供，命令可见性取决于 PATH 组成：默认进程 PATH 首段为 /system/bin（提供 install/umount/chroot 等，该目录对普通用户不可 ls，仅 PATH 查找时可执行），而交互 shell 与受限环境常裁剪掉该目录。此时 busybox 1.37 虽含 install/umount/chroot/mke2fs/blkid 等 applet，却往往没有同名命令入口，脚本中裸调 `umount`/`chroot` 会报 "inaccessible or not found" 并中断（在 make 中表现为 Error 127）。这是宿主用户态能力与脚本假设（完整 coreutils 命令集）之间的落差，不是脚本逻辑缺陷。

## 推荐方案
**方法**: in-script-command-v-with-busybox-applet-fallback

**说明**: (待补充)

**修复命令**:
```
在脚本内加入解析函数并替换裸调点：`xcmd() { local c="$1"; shift; if command -v "$c" >/dev/null 2>&1; then "$c" "$@"; elif command -v busybox >/dev/null 2>&1; then busybox "$c" "$@"; else fail "Required command not available: $c"; fi; }`，调用点写 `xcmd umount …` / `xcmd chroot …`。构建期可用无条件方案时，则在 build() 里生成仅含该 applet 同名入口的 shim 目录并前置 PATH。
```

**验证**:
```
1) command -v umount chroot install（观察是否有同名入口）；2) busybox --list | grep -xE 'umount|chroot|install'（确认 applet 存在）；3) 在 PATH 仅含一个指向 busybox 的 install 入口的目录下执行脚本，观察是否走回退分支；4) 回退调用应返回 applet 自身 rc（非 127）
```
