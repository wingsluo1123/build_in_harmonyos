# E2836: OHOS 上 install(1) 可见性取决于 PATH 组成（/system/bin 是否在 PATH 内），Makefile install 目标随机失败 → build() 条件化 install shim

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, make, toolchain, install
- **作者**: unknown

## 错误特征
```
sh: install: inaccessible or not found|install: inaccessible or not found|make: \*\*\* \[Makefile:[0-9]+: install\] Error 127
```

## 根因分析
OHOS 用户态由 Toybox 提供，install(1) 实际由 /system/bin 提供（该目录对普通用户不可 ls，仅在 PATH 查找时命中的可执行文件）。进程默认 PATH 首段即 /system/bin，因此多数构建环境可解析 install；但交互 shell / 受限环境（含本机终端、部分 CI 包装）会把 /system/bin 裁掉，此时 `command -v install` 无输出，上游 Makefile 的 `install:` 目标第一条语句即 `/bin/sh: install: inaccessible or not found` → `make: *** [Makefile:N: install] Error 127`（rc=2）。同一 recipe 在不同 PATH 组成下表现不一致，是环境变量注入差异而非源码问题。

## 推荐方案
**方法**: conditional-busybox-install-shim-in-build

**说明**: (待补充)

**修复命令**:
```
在 conanfile.py 的 build() 里条件化生成 shim：`if shutil.which("install"): return None`（平台已有则不启用）→ 否则找 busybox（shutil.which 或 /usr/bin/busybox、/bin/busybox、/data/service/hnp/bin/busybox）→ 在 build_folder/install-shim 下建指向 busybox 的软链 `install`（HMDFS 不可覆盖，用 lexists 守卫只建一次）→ `self.run('export PATH="<shim>:$PATH"; make install DESTDIR=<staging>')`。并校验上游 install 目标的 4 种形式（-m 644、-m 755 -d、-m 644 -t、-m 755）在 shim 下均可用。
```

**验证**:
```
1) command -v install; echo rc=$?（裁剪 PATH 下 rc=1、无输出）；2) python3 -c "import shutil; print(shutil.which('install'))"（默认 PATH 下输出 /system/bin/install）；3) make install DESTDIR=... 观察 Error 127；4) 前置仅含 install 入口（指向 busybox）的 shim 目录后 make install 应 rc=0 且产物齐全
```
