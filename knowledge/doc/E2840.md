# E2840: Flat openssl 包在 CMakeDeps 下只暴露 openssl::openssl，上游 find_package(OpenSSL)+OpenSSL::SSL 目标名重映射

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, conan, security, dependency-contract
- **作者**: ATOMCODE

## 错误特征
```
Target ".*" links to:.*OpenSSL::SSL.*but the target was not found|openssl::openssl.*OpenSSL::SSL|CMake Error.*target_link_libraries
```

## 根因分析
制品仓 openssl/3.5.6.1.1 是 flat 包（package_info 仅声明 cpp_info.libs = ssl,crypto，无 components、无 cmake_file_name/cmake_target_name 属性）。Conan 2 CMakeDeps 对无导出属性的包按包名生成默认目标 openssl::openssl；而 libftp 上游 CMakeLists.txt 使用 find_package(OpenSSL REQUIRED) + target_link_libraries(OpenSSL::SSL)。CMake 配置期报 Target "ftp" links to: OpenSSL::SSL but the target was not found。此外 libftp 公共头（client.hpp→boost/asio/ssl）在编译期 include <openssl/conf.h>，需要 openssl 头文件可见性传递（transitive_headers=True），否则下游 test_package 编译报 openssl/conf.h file not found。

## 推荐方案
**方法**: cmakedeps-cmake-target-name-remap-plus-transitive-headers

**说明**: 在消费方 conanfile.py 的 generate() 中调用 deps.set_property("openssl", "cmake_target_name", "OpenSSL::SSL")，让 CMakeDeps 直接以 OpenSSL::SSL 为目标名生成 openssl config（config 模式优先于内置 FindOpenSSL 模块，OPENSSL_ROOT_DIR 缓存变量不会生效）；同时在 requirements() 中对 openssl 声明 transitive_headers=True，使 openssl 头文件路径沿依赖链传递到下游 test_package。无需改动 openssl 配方，也不改上游源码。
