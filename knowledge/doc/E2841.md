# E2841: "Layer 1: in build() invoke meson as 'sh <meson pkg>/bin/mes

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, meson, configure, python
- **作者**: unknown

## 错误特征
```
"Error 126 while executing|Error 13 while executing|Unhandled python OSError.*Meson|Permission denied.*bin/meson|hunk no.2 doesn't match source file"
```

## 根因分析
"The HarmonyOS PC kernel refuses shebang script execve at the syscall level regardless of executable bits (EACCES=Error 13; Error 126 when a subprocess wrapper reports it). Meson-based recipes hit this in three stacked layers: (1) Conan's meson package ships bin/meson as a shell wrapper script, so calling it directly dies before the build starts; (2) the upstream source tree executes its own configure-time helper scripts through meson run_command()/configure_file(command:) — Kea 3.0.3 has five such sites (scripts/env.sh, scripts/grabber.py via GRABBER variable, scripts/cd-and-run.sh, the generated config-report.sh, tools/mk_cfgrpt.sh); (3) some scripts are GENERATED by configure_file() itself, so the exec target is a build-dir artifact, not a source file. A second trap sits in patch application: conan's patch-ng engine interprets each hunk header line number against the source as already patched by PREVIOUS patch FILES (so a patch that adds +6 lines before your hunk shifts its coordinates), while git apply uses pristine-file coordinates — a multi-hunk patch validated with git apply --check can still be rejected by conan with 'hunk no.N doesn't match source file at line X, expected ... actual ...'."

## 推荐方案
**方法**: "Layer 1: in build() invoke meson as 'sh <meson pkg>/bin/meson' (sh reads the script without execve; the python3 it spawns is ELF). Layer 2: patch the script VARIABLES, not the call sites — redefine ENV/CD_AND_RUN as ['/bin/sh', <script>] and GRABBER as [find_program('python3').full_path(), <script>], and every run_command keeps passing the variable as first argument; for configure_file(command:) sites patch each command array to ['/bin/sh', <script>, args...]. Sweep the whole tree for remaining direct script execs (grep run_command/command: across every meson.build) including subdir files evaluated AFTER your first crash point. Layer 3 (patch-ng): put multi-hunk patches for the same file in hunk headers whose line numbers are the file state after all EARLIER patch files in conandata (not cumulative over same-file hunks — empirically same-file hunk deltas are not accounted, prior-file deltas are); validate locally with pip-installed patch-ng (fromstring + apply(strip=1)) rather than git apply, which uses different coordinates."
