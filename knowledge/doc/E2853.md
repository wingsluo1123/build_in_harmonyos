# E2853: 同一代理程序的 libcap 与 IP_TRANSPARENT 应分开判定

## 基本信息
- **严重度**: 2
- **类别**: platform, detection
- **作者**: tank_you

## 错误特征
```
Could not find the libcap2 libraries|cap_get_proc in -lcap... no
```

## 根因分析
ProxSMTP 1.10 的 Linux capabilities 与 IP_TRANSPARENT 是不同的可选功能。所测 OHOS PC 缺少 libcap，显式启用 capabilities 时 configure 失败；同机启用 IP_TRANSPARENT 却可配置并编译。用单一 Linux 平台标签或一个头文件探针不能替代逐功能构建和运行验证。

## 推荐方案
**方法**: split-optional-capability-evidence

**说明**: 先解决 E007 的平台识别；分别验证 libcap 链接、IP_TRANSPARENT 编译、普通网络功能以及需要特权的透明模式运行。缺失 libcap 时仅禁用该层，不能据此宣称 IP_TRANSPARENT 也不可用；只编译 IP_TRANSPARENT 也不能宣称特权运行通过。

**修复命令**:
```
--disable-capabilities --enable-tproxy
```

**验证**:
```
CC=clang ./configure --build=aarch64-unknown-ohos --host=aarch64-unknown-ohos --enable-capabilities --disable-tproxy; CC=clang ./configure --build=aarch64-unknown-ohos --host=aarch64-unknown-ohos --disable-capabilities --enable-tproxy; conan create archives/p/proxsmtp/1.10 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 -c tools.build:jobs=1
```
