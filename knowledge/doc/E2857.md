# E2857: 上游 bash 测试器依赖 GNU coreutils（diff -y / [[ ]] / bash 数组）在 OHOS 设备 toybox 不可用 → POSIX 移植驱动 + python 行级容差比较器逐条复刻上游比较语义（含 cut -f1,2 字段名陷阱）

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, gnu-coreutils, test
- **作者**: unknown

## 错误特征
```
diff: invalid option -- 'y'|diff: unrecognized option|Unknown option|sh: \[\[: not found|Syntax error: bad substitution|run_tests: not found
```

## 根因分析
大量上游包的测试执行器是 bash 脚本并依赖 GNU coreutils 特性：diff -a -y --suppress-common-line（并排比对、仅输出差异行）、[[ ]] 条件、source、数组等；OHOS 设备自带 toybox，其 diff 不支持 -y/--suppress-common-line，bash 4 特性缺失，执行器整体不可用（libservicelog 上游 src/tests/run_tests 即如此）。移植的坑在比较语义复刻：上游 diff_with_result_without_timestamp 用 diff -y | cut -d ' ' -f1,2 取差异行的行首字段名，与 5 个易变字段名（Log/Event/Update Timestamp:、Platform:、Node Name:）比较——注意 cut -f1,2 对单词字段名（"Platform:"）后接多空格时第二字段为空串，产出"Platform: "带尾随空格；移植成"取前两个词拼接"会拿 "Platform: ppc64le" 去比 → 平台差异被误报为功能失败（真机迭代 10 实测踩中，scenario 004/005 误 FAIL）。正确语义是**行首字段名前缀匹配**（line.lstrip().startswith(易变字段名)），忽略字段名命中行的值差异，其余差异行任一出现即失败。

## 推荐方案
**方法**: posix-port-plus-tolerant-comparator

**说明**: ① 用 POSIX sh 重写上游执行器的最小驱动循环：逐场景调驱动二进制（同源 C 驱动 test_libservicelog.c 原样编译为消费者）、输出落临时目录；② python 行级容差比较器复刻上游 diff 语义：逐行字节比对，差异行按行首字段名前缀匹配易变字段名集合则忽略，其余差异行计失败，行数不等也失败；③ 比较器随 test_package 提交进包，场景脚本/期望输出用上游原文件，驱动用上游原码——移植只改执行器与比较逻辑，测试内容零改动。

**修复命令**:
```
sh run_upstream_tests.sh ./test_libservicelog <pkg>/share/libservicelog/upstream-tests/tests-results cmp_tolerant.py
```

**验证**:
```
设备执行 sh run_upstream_tests.sh ./test_libservicelog <pkg>/share/.../tests-results cmp_tolerant.py → 断言 SUITE PASS 6/6；比较器单测：'Platform:           ppc64le' vs 'Platform:           aarch64' 必须忽略、'DESCRIPTION:  foo' vs 'DESCRIPTION:  bar' 必须失败、行数不等必须失败。
```
