# E2863: 上游裸 Makefile 把编译器名写成规则正文字面量（全文件无 CC=/CFLAGS= 赋值）⇒ make 命令行变量覆盖无对象；解法是在配方里逐字复刻该条编译命令并把编译器取自 tools.build:compiler_executables

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, make, toolchain, conan
- **作者**: rifiuti-20040505

## 错误特征
```
/bin/sh: (?:gcc|cc): inaccessible or not found|cp: bad '[^']*': No such file or directory|make: \*\*\* \[Makefile:[0-9]+: [A-Za-z][A-Za-z0-9_-]*\] Error 1(?![0-9])
```

## 根因分析
GNU make 的标准交叉手法「命令行变量覆盖 makefile 内赋值」（make CC=<交叉编译器>）成立的前提是规则正文引用 $(CC)。本包上游 src/Makefile 全文 10 行、只有 all/install/installwin/clean 四目标，两条编译命令把编译器名写成字面量（:4 gcc -o rifiuti rifiuti.c -lm -lc;cp rifiuti ../bin、:7 gcc -DCYGWIN -o rifiuti.exe rifiuti.c -lm -lc;cp rifiuti.exe ../bin），

## 推荐方案
**方法**: replicate-recipe-command-with-conf-compiler

**说明**: 不改上游文件、不打补丁：在配方 build() 内逐字复刻上游那条规则正文的编译命令（同一 argv 序列、同一产物名、同一组链接库 -lm -lc），只把命令名换成从 Conan conf 取到的 C 编译器

**修复命令**:
```
self.run('"{}" -o rifiuti rifiuti.c -lm -lc'.format(cc), cwd=self.source_folder + "/src", env="conanbuild")   # cc = self.conf.get("tools.build:compiler_executables", default={}, check_type=dict).get("c") or "clang"
```

**验证**:
```
grep -cE '^[[:space:]]*CC[[:space:]]*[:?]?=' src/Makefile; make -n -C src CC=clang 2>&1 | grep -cE '^[[:space:]]*gcc[[:space:]]'
```
