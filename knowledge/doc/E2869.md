# E2869: 新版 libc++ 的 std::tuple_element 越界 static_assert 击穿 SFINAE 完整性探测

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, toolchain, compiler, c++
- **作者**: SunShine_06
- **来源 PR**: 13207

## 错误特征
```
static assertion failed due to requirement .*Idx < 2|Index out of bounds in std::tuple_element|in instantiation of template type alias 'is_complete'|is_complete<std::tuple_element<
```

## 根因分析
上游 fatal 用 is_complete<T>（内部 sizeof(T) 作模板默认实参）以 SFINAE 探测类型完整性，期望越界索引的 std::tuple_element<2, std::pair<...>> 表现为不完整类型（替换失败 → false）。新版 libc++（OHOS libcxx-ohos / clang 15，libstdc++ 亦然）在 tuple_element 特化中加入 static_assert(Idx < 2)，标准库 static_assert 不处于 SFINAE 上下文，实例化即硬错误，无法被替换失败吞掉，导致该 TU 编译失败、85 个用例全部无法执行。

## 推荐方案
**方法**: guard-the-sfinae-probe-by-implementation-macro

**说明**: 只对那一行断言加 #if !defined(_LIBCPP_VERSION)（或按实现宏组合）守卫，保留对仍 SFINAE 友好实现的检查；绝不删除 FATAL_TEST 用例本身，保持上游用例计数不变。

**修复命令**:
```
#if !defined(_LIBCPP_VERSION)\n  FATAL_EXPECT_FALSE((is_complete<std::tuple_element<2, pair>>::value));\n#endif
```

**验证**:
```
打补丁后执行 clang++ -Wall -Werror -Wextra -O0 -g -pthread -ftemplate-depth-1024 -std=c++17 -I . fatal/type/test/deprecated_transform_test.cpp 应编译成功，运行输出 "succeeded: passed 85/85"；全量复跑应得 TUs=67 compiled=67 executed_cases=839 passed=839 failed=0 skipped=0。
```
