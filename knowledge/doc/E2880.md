# E2880: 嵌套 cmake 以自建产物为编译器自举运行时（CMAKE_Fortran_COMPILER=自建二进制）：编译器透传缺口经环境变量注入、自举产物动态库经链接期 DT_RPATH 解析（禁 LD_LIBRARY_PATH 注入）

## 基本信息
- **严重度**: 2
- **类别**: portability, cmake, autotools, toolchain, fortran
- **作者**: Hawkninja21
- **来源 PR**: 13591

## 错误特征
```
The C compiler.*is not able to compile a simple test program|CMAKE_C_COMPILER:FILEPATH=.*NOTFOUND|No CMAKE_Fortran_COMPILER could be found|error while loading shared libraries: libLLVM|configure_runtime|build_runtime
```

## 根因分析
子模式 A（编译器透传缺口）：lfortran 上游主构建产出 <build>/src/bin/lfortran 后，以嵌套 cmake（custom target configure_runtime/build_runtime）把它当作 CMAKE_Fortran_COMPILER 自举编译 Fortran 运行时模块（src/runtime/*.f90 → lfortran --backend=cpp 转 C++ → 再经 CXX 编译）。嵌套 configure 只透传有限参数（toolchain/prefix/CMAKE_INSTALL_*），**不带 -DCMAKE_C_COMPILER/-DCMAKE_CXX_COMPILER**；嵌套 project() enable_language(C/CXX) 的编译器检测在 OHOS 上找不到默认 cc/c++（无标准路径 gcc/cc 布局，HNP 工具链不在默认搜索）→ configure 失败。修复=外层 build() 以 env 注入 CMAKE_C_COMPILER/CMAKE_CXX_COMPILER（cmake 会把同名环境变量当初始缓存，嵌套 configure 继承外层 self.run 的 env）。子模式 B（自举产物动态库解析）：自建 lfortran 二进制动态链 libLLVM.so（制品仓 clang 包 lib/），嵌套 cmake 执行它编译 .f90 时 OHOS 无系统级动态库搜索（无 ld.so.conf 用户可写路径，SDK libc 不解析包路径）→ 自举产物起不来。修复=链接期烘焙 DT_RPATH 指向 clang 包 lib/（-DCMAKE_EXE_LINKER_FLAGS="-Wl,--disable-new-dtags -Wl,-rpath,<clang 包 lib/>"，与主链接期同源；--disable-new-dtags 强制 RPATH 先于 LD_LIBRARY_PATH，防 profile 的 SDK llvm/lib 里 SDK 版 libLLVM.so 抢先绑定→LLVM_22 版本失配）。禁 LD_LIBRARY_PATH 注入（lfortran #13591 CI 首跑实测）：把 clang 包 lib/ 前置进 LD_LIBRARY_PATH 会让 CI worker 的 HNP cmake 抢绑包内捆绑的 libc++_shared.so（比 worker 工具链旧）→ cmake 自身 relocation 符号风暴（Error relocating /data/service/hnp/bin/cmake: ... symbol not found，顶层/嵌套 cmake 进程均受污染）。真机不发作=真机 HNP 树较旧符号恰好够、CI 树更新即爆——动态库解析只作用于自建二进制本身才是安全界。

## 推荐方案
**方法**: env-injection-bootstrap

**说明**: 不改上游源码，配方 build() 两件套：①env 注入 CMAKE_C_COMPILER/CMAKE_CXX_COMPILER=真机 HNP 工具链路径（或 tools.build:compiler_executables conf 值），嵌套 configure 的 project() 语言检测经环境变量初始缓存命中，无需上游透传 -D；②链接期烘焙 DT_RPATH（defs 加 -DCMAKE_EXE_LINKER_FLAGS="-Wl,--disable-new-dtags -Wl,-rpath,<依赖包 lib/>"），保证嵌套 cmake exec 自建 lfortran 编译 .f90 时 libLLVM.so 可解析且与链接期同源，cmake 进程环境零侵入（禁 LD_LIBRARY_PATH 注入——前置依赖包 lib/ 会让同环境工具链进程抢绑其捆绑 libc++_shared.so → 符号风暴，CI 实测）。主构建限 -j6（lfortran 主二进制链接 libLLVM.so 极吃内存）。

**修复命令**:
```
defs += '-DCMAKE_EXE_LINKER_FLAGS="-Wl,--disable-new-dtags -Wl,-rpath,<dep-pkg>/lib"'；env={'CMAKE_C_COMPILER': cc, 'CMAKE_CXX_COMPILER': cxx}；self.run('cmake --build {bdir} -- -j6', env=env)
```

**验证**:
```
①嵌套 configure 复验：conan create 日志 grep -E 'CMAKE_Fortran_COMPILER|lfortran --backend=cpp|configure_runtime'（编译器检测命中 HNP clang 且 .f90 转 C++ 编译记录在案）；②自举产物复验：<pkg>/lib/lfortran_runtime*.a/.so 与 include/lfortran/*.mod 存在且 llvm-nm 符号正常；③运行期复验：test_package 用产出的 lfortran 编译+运行 Fortran 程序（llvm 后端）ALL_OK
```
