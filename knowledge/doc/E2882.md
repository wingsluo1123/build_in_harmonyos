# E2882: LLVM 系编译器复数按值传递 ABI 统一：非 Windows 平台 complex32 用 C99 float _Complex HFA（返回 {float,float}/实参 [2 x float]），禁用 <2 x float> 向量声明

## 基本信息
- **严重度**: 2
- **类别**: portability, llvm, fortran, abi, codegen
- **作者**: Hawkninja21
- **来源 PR**: 0

## 错误特征
```
ERROR STOP FAIL|C test failed with code: 18|bindc_iso_fb|_lfortran_ctan|_lfortran_csin|float_complex_t|<2 x float>|aimag.*0.00000000
```

## 根因分析
lfortran LLVM 后端在非 Windows/非 macOS_ARM 平台把 complex32(kind 4) 的函数实参/返回类型声明为 <2 x float> 固定向量（llvm_utils.cpp 实参/返回类型两处 + asr_to_llvm.cpp 函数体返回/调用点实参两处 + abi_to_internal 一处，共 5 处三路分支 Windows i64 / macOS_ARM struct / else vector）。而 aarch64 Linux 的 C99 float _Complex 按 AAPCS64 HFA（Homogeneous Float Aggregate）规则实参走 [2 x float]（d0,d1 双寄存器）、返回走 {float,float}——真机 clang 实测 C 侧签名 `define {float,float} @f25_conj([2 x float] %0)`。向量只占单个 d 寄存器，与 HFA 双寄存器错位 → 调用 C 运行时复数数学包装（_lfortran_ctan 等 30 个 C99 complex 包装）与 bind(c) 按值复数子程序时实部幸存（d0 低半）、虚部读到垃圾/被丢弃（d1 从未写入）。真机实录：tan((1.5,0.1))=(14.1014204,0.0) 且随 -O0/-O3 非确定（0.0/12.92/14.10）；bindc_iso_fb_05 f25_conj 断言 C test failed with code 18。x86-64 上向量与 C99 complex 恰好同落 xmm0 侥幸掩盖，aarch64 必然暴露。

## 推荐方案
**方法**: c99-hfa-abi-unification

**说明**: 把 kind-4 复数按值传递 ABI 分支的 else（非 Windows）统一为 C99 HFA：返回 getComplexType(4)= {float,float}、实参 [2 x float]、abi_to_internal 直通。与上游 macOS_ARM 既有分支逐字一致（Apple 打包聚合体故上游已用 struct），Windows i64 路径与 kind-8（{double,double} 结构体）路径不动。x86-64 SysV 对 {float,float}/[2 x float]/<2 x float> 三者 SSE 分类相同（均 xmm0），Linux x86 行为零变化。修复后与目标平台 C 编译器签名逐类型对齐，无需改 C 侧运行时源码。

**修复命令**:
```
无运行时命令；验证=clang -S -emit-llvm 对比 C 侧 float _Complex 签名 + lfortran --show-llvm 对比声明类型
```

**验证**:
```
①签名对齐：clang -S -emit-llvm 编译 float _Complex 函数（实参 [2 x float]/返回 {float,float}）与 lfortran --show-llvm 声明逐类型比对；②行为复验：8 条复数数学内建（intrinsics_04s/18c/49/212/264/265/266/295）+ bindc_iso_fb_01/05 + modules_15 真机 RUN-RC=0；③回归防护：x86 构建 CI 结果不变（SSE 分类等价）
```
