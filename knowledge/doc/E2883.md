## 错误特征
```
non-free license line|0 // !LICENSE|missing CC-BY-4.0 license line|引用.*缺失|missing == 0
```

## 根因分析
自由子集数据包（Debian dfsg 重打包产物）的合规边界由「每文件生效许可行」定义，但文件内常有被注释掉的历史旧许可行（`0 // !LICENSE ... CCAL version 2.0`——LDraw 再授权历史，973pxis01.dat 第 145 行实证）。若消费者测试按「全文不得出现 CCAL 子串」校验，会把合法文件误报为非自由；正确语义与上游过滤工具（gendfsgsrc.py）一致：只认首个 `0 !LICENSE` 生效行。此外子集正确性 = 许可精确匹配 + 剔除不破坏引用完整性（祖先剔除的自包含推论）+ 被剔著名件负向锚点，三者必须一起验。

## 推荐方案
**方法**: operative-license-line-semantics

**说明**: 探针逐文件校验（1）首行以 "0 " 开头 + 含 "0 Name:" 行（格式）；（2）遍历中首个以 "0 !LICENSE" 开头的行必须精确等于目标许可行（CC-BY-4.0 行），命中即 break——被注释的历史旧许可行（"0 // !LICENSE"）因不以 "0 !LICENSE" 开头而天然不参与判定；非精确匹配的生效行直接判非自由。（3）同一遍读取收集全部 type-1 引用（第 15 token），对候选集 {引用名, 引用者目录/引用名, p/引用名, parts/引用名} 校验 0 缺失；（4）被剔著名件负向锚点 + 注入负向用例（CCAL 许可样本必须被拒）；（5）消费者端到端渲染管线用例：载入装配体 → 引用递归解析至图元 → 图元几何载入 → 颜色对照。单遍全读使 3 万+ 文件全树校验在真机秒级完成。

**修复命令**:
