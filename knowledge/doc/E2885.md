# E2885: libc++ 无 std::vector 内部指针 API 时 mmap-backed 派生容器需 resize/swap/clear+shrink_to_fit 适配

## 基本信息
- **严重度**: 3
- **类别**: ohos, libc, syscall, memory, container-internals
- **作者**: atomcode

## 错误特征
```
redefinition of 'mmap_file_identifier'|unguarded header|_M_finish|_M_get_Tp_allocator|_M_deallocate|libc\+\+abi: terminating due to uncaught exception.*Cannot stat file|Cannot stat file
```

## 根因分析
上游 mmappable_vector.h 直接操作 GNU libstdc++ 私有内部成员（Base::_M_impl._M_finish、Base::_M_get_Tp_allocator()、Base::_M_deallocate()）。OHOS 工具链默认 -stdlib=libc++（compiler.libcxx=libc++），libc++ 无这些内部成员：编译期同一无 guard 头文件（mmap_file_pool.h）被直接与间接双路径包含导致类重复定义；运行期 libc++ 下无法推进 finish 指针使 vector 大小不被认可，且 allocator 缺 no-op construct/destroy 时 resize 按值写入 mmap 后备存储。

## 推荐方案
**方法**: libcxx-internal-api-adaptation

**说明**: (1) mmappable_vector.h 在 #if defined(_LIBCPP_VERSION) 分支改用公开 API：mmap_file(n)=reserve(n)+resize(n)；带文件名重载构造已配置 mmappable_vector 后 Base::swap(configured)；munmap_file()=clear()+shrink_to_fit()。(2) mmap_allocator.h libc++ 分支补 no-op construct(U*)/destroy(U*)（不写 mmap 区域）+ 带参 construct placement new + propagate_on_container_swap/move_assignment/copy_assignment=true_type。(3) 补 mmap_file_pool.h include guard（_MMAP_FILE_POOL_H）消除双路径重复定义。(4) 消费者测试须先 munmap 再删除文件（池记账对文件 stat()）。

**修复命令**:
```
按上述四点修改源码；conan create（ohos-aarch64 profile）复验 test_package 1/1 通过。
```

**验证**:
```
conan create . --version=3.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 && grep -q "100% tests passed" <(conan create ... 2>&1)
```
