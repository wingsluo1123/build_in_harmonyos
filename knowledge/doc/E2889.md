# E2889: 上游 CMakeLists 内建 Conan 1 集成块（*_IS_BEING_BUILT_BY_CONAN → include(conanbuildinfo.cmake) + conan_basic_setup()）在 Conan 2 下不可用：不设置该开关即可绕开

## 基本信息
- **严重度**: 2
- **类别**: compat, build-system, cmake, conan
- **作者**: pc7-32
- **来源 PR**: (本轮 PR)

## 错误特征
```
include could not find.*conanbuildinfo\.cmake|Unknown CMake command "conan_basic_setup"|conan_basic_setup|_IS_BEING_BUILT_BY_CONAN
```

## 根因分析
上游（如 google/fruit）在 CMakeLists.txt 中以 `if(*_IS_BEING_BUILT_BY_CONAN) include(conanbuildinfo.cmake); conan_basic_setup()` 形式内建 Conan 1 时代集成：开启该开关后走 Conan 1 的生成器产物与命令。本项目 OHOS 适配版 Conan 2.29.1 无 conanbuildinfo.cmake 生成、无 conan_basic_setup 命令；配方 generate() 若把该开关设为 YES，configure 必然失败。

## 推荐方案
**方法**: skip-conan1-flag-keep-native-cmake

**说明**: 配方 generate() 中不设置上游的 `*_IS_BEING_BUILT_BY_CONAN` 开关（保持默认 FALSE），使上游跳过 Conan 1 分支、走原生 CMake 构建；Release 下 examples/tests 子目录会被加入，但 ALL 默认只构建库本体（tests 若为 pytest/ctest 套件仅注册不构建，可在适配门禁单独构建并运行）。注意：这与「设置开关以裁掉 tests 子目录」的直觉相反——Conan 2 下该开关会触发已废弃的 Conan 1 集成，宁可让子目录存在也不开启。

**修复命令**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
