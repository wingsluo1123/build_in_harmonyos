# E2892: '上游把 x86 SIMD/AVX512 开关默认 enable 且无 CPU 探测，公共编译单元用 x86-only 内建做运行期分发，交叉到 aarch64-OHOS 编译期必挂'

## 基本信息
- **严重度**: blocker
- **类别**: cross-compile, arch-portability
- **作者**: 'hw-9'
- **来源 PR**: ''

## 错误特征
```
"revseqcmp.c:39:2: error: use of unknown builtin '__builtin_cpu_init' [-Wimplicit-function-declaration]"
```

## 根因分析
'configure.ac 的 x86simd 与 avx512 两个 AC_ARG_ENABLE 默认值都是 enabled，且没有任何 CPU 或三元组自动探测，configure 直接按默认值写进 config.h（实测第 5 行 ENABLE_AVX512 1、第 8 行 ENABLE_X86_SIMD 1），于是 libs/Makefile.am、src/Makefile.am、test/Makefile.am 三处条件段把带 SSE2/AVX2/AVX-512 目标码的运行期分发层拉进默认构建；该分发层写在普通 .c 里，调用 __builtin_cpu_init 与 __builtin_cpu_supports——这两个是 x86 专用内建函数，aarch64 的 clang 不提供，于是编译期报 unknown builtin 并被 -Wimplicit-function-declaration 升级为硬错误。关键层次：失败签名不是 -msse2/-mavx2/-mavx512bw 之类编译选项不被支持，而是内建函数在本 target 上根本不存在，按 -m 选项去猜会走偏（本条最初就是那样写的，被真机否掉）。'

## 推荐方案
**方法**: 'configure 显式关掉架构开关，零改上游'

**说明**: '在配方 generate() 的 AutotoolsToolchain.configure_args 追加 --disable-x86simd 与 --disable-avx512，使 config.h 的两个 ENABLE 宏不成立，从 Makefile 条件段就把分发层排除。不要打补丁删分发层源码，也不要改编译参数（会改动上游面并引入无效 diff，且可能连带删掉测试）。前提取证：先确认失败落在内建函数层而非选项层，并确认上游确实提供这两个 disable 开关（grep configure.ac 的 AC_ARG_ENABLE 名称）。'

**修复命令**:
```
'tc.configure_args.append("--disable-x86simd"); tc.configure_args.append("--disable-avx512")'
```

**验证**:
```
'cd <解包后的源码根> && autoreconf -fi -Im4 && env -u CONFIG_SHELL SHELL=/bin/sh ./configure --build=aarch64-unknown-linux-gnu && grep -E "^#define ENABLE_(X86_SIMD|AVX512)" config.h && make -j1'
```
