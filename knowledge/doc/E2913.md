# E2913: 以命令行 make 变量（CFLAGS=…）覆盖手写 Makefile 时，会连同 Makefile 内定义的 OPTS/宏（-DLIBDIR 等）一起被丢弃，导致源码中依赖该宏的标识符未定义而编译失败

## 基本信息
- **严重度**: 3
- **类别**: build-system, make
- **作者**: unknown

## 错误特征
```
use of undeclared identifier 'LIBDIR'
```

## 根因分析
make 的命令行变量优先级最高，会**整体替换** Makefile 中同名变量的赋值（不是追加）。utalk 的 Makefile 把宏集中定义在 `OPTS = $(OPT1)…$(OPT5)`（其中 `OPT5 = -DLIBDIR="\"$(LIBDIR)\""`）并在 `CFLAGS = -O2 -g -Wall -D__USE_FIXED_PROTOTYPES__ $(OPTS)` 中展开；一旦配方用 `make CFLAGS='…'` 覆盖，OPTS 全部失效，`menu.c` 的 `HELPFILE`（=`LIBDIR "/utalk.help"`）展开失败，报 `use of undeclared identifier 'LIBDIR'`。

## 推荐方案
**方法**: 只覆盖必需的命令行变量（CC/LIBS/LDFLAGS 等），**不要覆盖 CFLAGS**，让 Makefile 自带的 CFLAGS+OPTS 生效；确需追加编译标志时，在 Makefile 已有 CFLAGS 文本基础上原样带上其 $(OPTS) 展开内容。

**说明**: 保留 Makefile 的 CFLAGS（含 OPTS），仅覆盖 CC/LIBS/LDFLAGS

**修复命令**:
```
make -j1 CC=<clang> LIBS='-L<ncurses>/lib -lncursesw' LDFLAGS='-Wl,--allow-multiple-definition' utalk
```

**验证**:
```
make -n CC=<clang> CFLAGS='-O2' utalk | grep -c -- '-DLIBDIR'   # 覆盖 CFLAGS 后为 0
```
