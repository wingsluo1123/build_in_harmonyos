# E2914: "测试/运行环境里做一次『陈旧绝对路径修复』：用 readelf -d（OHOS 用 SDK 的 llvm-readel

## 基本信息
- **严重度**: P1
- **类别**: runtime, environment, symlink, relocatable
- **作者**: unknown

## 错误特征
```
"Error loading shared library /[^ ]*/p/(lib|bin)/lib|(needed by )[^ ]*/(\.cache|\.conan2)/conan2/p/|error while loading shared libraries: /[^ ]*/conan[0-9]*/p/"
```

## 根因分析
"已发布的 KF6/Qt6 依赖包里有共享库的 DT_NEEDED 记录的**不是 soname**，而是构建机 conan 缓存里的绝对路径（如 /home/<builder>/.conan2/p/kconf7325dff05dfef/p/lib/libKF6ConfigCore.so）。当被链接库本身没有 SONAME 时，链接器会把命令行上给出的完整路径原样写进 DT_NEEDED。于是：装载器对带 '/' 的 DT_NEEDED 不再查 LD_LIBRARY_PATH 也不查 rpath，而是直接按该路径打开 —— 构建机上（缓存目录恰好存在）一切正常，干净 CI worker 上路径不存在，加载任何 ELF（包括上游测试二进制）都在 main 之前失败。表现极易误判为『编译失败』或『测试本身失败』：本地全绿、CI 全挂（0/N），且报错与被测程序无关。"

## 推荐方案
**方法**: "测试/运行环境里做一次『陈旧绝对路径修复』：用 readelf -d（OHOS 用 SDK 的 llvm-readelf，回退 readelf）扫描构建树产物与各依赖包内 ELF 的 DT_NEEDED，取出所有以 '/' 开头的条目；对路径已不存在的条目，从依赖包（lib/lib64/bin 三类目录）中找同名库，用 os.makedirs(exist_ok=True) 在原路径重建软链，并按传递闭包迭代直到不再出现新的缺失（新暴露的 ELF 同样要扫）。只在测试环境注入，不打包、不改上游源码、不写 /usr/local 等系统共享前缀、不修改 conan 包内容。"
