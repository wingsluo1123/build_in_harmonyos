# E2920: "带运行时数据目录（share/）的工具包，其 test_package 转换断言必须：(1) 从上游 testing/

## 基本信息
- **严重度**: P3
- **类别**: packaging, testing, dsl-tools, xfpt
- **作者**: unknown

## 错误特征
```
"unknown directive line: \.(docbook|book|chapter)|unknown directive.*\.include|Error: unknown directive line"
```

## 根因分析
"xfpt 的 .docbook/.book/.chapter/.section 等看似内建的标记指令实际不是编译进二进制的内建 directive，而是上游分发的 share 数据文件 stdmacs 中定义的宏。test_package 的转换断言若只写 .include stdflags（stdflags 只定义 &*bold*& 等 flag 展开），转换会在第一个结构指令处报 'unknown directive line: .docbook' 退出 1，被误判为二进制功能损坏。"

## 推荐方案
**方法**: "带运行时数据目录（share/）的工具包，其 test_package 转换断言必须：(1) 从上游 testing/infiles 挑最小样例并复刻其完整 include 组合（xfpt 为 .include stdflags + .include stdmacs 成对出现），不要凭直觉裁剪——缺一个 include 就改变指令集语义；(2) 通过 -S <pkg>/share/<lib> 显式绑定包内数据文件（同时验证打包完整性）；(3) 期望输出片段从上游 testing/outfiles 对应文件原样摘取（如 <?xml 声明、<!DOCTYPE book、<book>、<emphasis role=\\\"bold\\\">），不要手写猜测；(4) 分辨指令来源：报 unknown directive 说明指令在数据文件而非二进制内建，先查 share 文件再怀疑移植缺陷。"
