# E2921: "统一在每个 pwsh 会话开头预设 $env:PYTHONIOENCODING='utf-8' 后再调 python 

## 基本信息
- **严重度**: P3
- **类别**: platform, python, environment, ohc-run, tooling
- **作者**: unknown

## 错误特征
```
"UnicodeEncodeError: 'gbk' codec can't encode character|UnicodeEncodeError.*gbk.*illegal multibyte sequence|print.*UnicodeEncodeError"
```

## 根因分析
"Windows 工作站的 Python 默认控制台编码是 GBK（locale 决定，非 UTF-8）。ohc-run.py 的 lang-preflight/prescan/result 等子命令在输出中打印 emoji（🟡 ✅ ❌）或中文摘要时，print 直接触发 UnicodeEncodeError: 'gbk' codec can't encode character '\\\\U0001f7e1'。注意误导点：崩溃发生在打印阶段，实际工作可能已完成（如 prescan 报告已写入 .pre-scan-report.yaml），exit code 非零让人误以为预检失败而放弃流程。"

## 推荐方案
**方法**: "统一在每个 pwsh 会话开头预设 $env:PYTHONIOENCODING='utf-8' 后再调 python scripts/ohc-run.py <子命令>；崩溃后先检查目标产物是否已生成（如 .pre-scan-report.yaml、result.json 草稿）再决定是否重跑，不要把打印崩溃误判为流程失败。同理：读 UTF-8 JSON 文件报 GBK 解码错误时（如 json.load 对含中文的 commands.json），显式 open(..., encoding='utf-8')。"
