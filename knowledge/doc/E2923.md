# E2923: "分级处理：(1) 简单命令用双引号包裹并把所有远端 $ 写成 PowerShell 转义 `$（反引号+美元）；(2)

## 基本信息
- **严重度**: P3
- **类别**: platform, shell, device, ssh, tooling
- **作者**: unknown

## 错误特征
```
"sh: [A-Za-z|_.]+: inaccessible or not found|sh: syntax error: unexpected|sh: -dt: inaccessible|grep: [A-Za-z|]+: No such file"
```

## 根因分析
"从 PowerShell 通过 ssh 在 OHOS 设备执行含 $()、管道、双引号的复合远端命令时，引号在传输链（PowerShell 解析 → Windows OpenSSH 参数拼接 → 远端 sh 再解析）中被逐层剥掉：双引号丢失后远端把 'PASS|FAIL|RESULT' 里的 | 当管道拆成多条命令，$(ls ...) 的 $ 被本地或远端提前展开成空串。症状极具迷惑性：报错是 'sh: FAIL: inaccessible or not found'（把字面词当命令执行），看起来像设备缺工具，实际是命令根本没被完整送达。"

## 推荐方案
**方法**: "分级处理：(1) 简单命令用双引号包裹并把所有远端 $ 写成 PowerShell 转义 `$（反引号+美元）；(2) 含管道/括号的复合命令优先写成一行时仍需转义每个 $；(3) 复杂命令（监控循环、多步调试）写成脚本文件本地保存 → scp 到设备 → ssh 执行脚本，彻底绕开三层引号解析；(4) 出现 'sh: <词>: inaccessible or not found' 且 <词> 是命令片段中的字面词时，第一时间怀疑引号被拆而非工具缺失（真缺工具时报错的是完整命令名且 PATH 可验证）。设备端调试 test_package 推荐 bash -x 直接跑：scp 完整脚本后 /data/service/hnp/bin/bash -x test_<lib>.sh，比远端拼 heredoc 可靠。"
