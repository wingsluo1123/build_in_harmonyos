# E2933: 无本地 MIDI 子系统平台（OHOS）的 rtmidi 适配：上游自动 dummy 后端回退无需补丁，但空后端构建必须用 apinames+消费者契约和完整生命周期证明 dummy 确实编译进来，防止静默产出 0 后端库

## 基本信息
- **严重度**: 1
- **类别**: ohos, portability, cmake, audio, consumer-testing
- **作者**: device-b

## 错误特征
```
dummy|API names by identifier|no functionality
```

## 根因分析
rtmidi 的 CMake 在无 ALSA/JACK/CoreMIDI/WinMM/Web/AMIDI 时既不报错也不登记任何后端（API_LIST 为空继续构建），功能上靠 RtMidi.cpp 头部在无任何后端宏时自动 #define __RTMIDI_DUMMY__ 兜底；由于该回退发生在源码预处理而非 CMake 层，构建日志不体现后端选择，若不显式验证就无法区分"可用的 dummy 库"与"静默 0 后端库"

## 推荐方案
**方法**: dummy-fallback-evidence-contract

**说明**: 无硬件后端平台适配硬件抽象库时：①确认上游是否有源码级自动回退（rtmidi 为 __RTMIDI_DUMMY__，RtMidi.cpp:88-90）而非 CMake 层；②运行上游 apinames（编译 API 名称断言）证明回退生效；③消费者测试固定 dummy 行为契约；④另运行真实链接库的完整消费者生命周期（发现 API、创建会话、开关虚拟端口、投递消息），避免将纯断言误报为端到端用例

**验证**:
```
./tests/apinames && ./test_rtmidi && ./rtmidi_dummy_workflow （前者列出 dummy 且名称映射断言通过，后两者分别验证 dummy 契约与完整消费者生命周期）
```
