# E2939: 配方已合入 main 但制品从未上传：制品上传只发生在合并之后的 release 流水线，合入当时构建失败的版本无法自愈，必须重出修订号触发新的 build+upload

## 基本信息
- **严重度**: 3
- **类别**: conan, dependency, process, release-pipeline
- **作者**: 2301_76770579
- **来源 PR**: 13894

## 错误特征
```
acceleration policy not enabled|no matching recipe|Found 0 pkg/version recipes|dependency_missing
```

## 根因分析
Conan 制品上传与构建是两个阶段：PR 阶段的 CI 只做 conan create + 测试（ci/conan/upload.sh 要求 CI_TASK_TYPE=release，PR 流水线不满足即 exit 1），真正的 conan upload 只在 PR **合并到 main 之后**的发布流程里执行。因此若某版本在合并那一刻构建失败（例如某个依赖的匹配二进制当时尚未产出、conan 回退源码构建又失败），该版本既没有制品、也不会被任何后续操作重试——历史结果已经写死。此后任何消费者解析这个版本都会失败，且修复配方源码也没用，因为触发上传的「合并事件」已经发生过了。

## 推荐方案
**方法**: recut-new-revision-number

**说明**: 保持上游源码与补丁集完全不变，只把 Conan 版本号加一位修订位（1.3.1 -> 1.3.1.1），重出配方目录 archives/<l>/<name>/<ver>/ 并重新提 PR。合并后新的 release 流水线会重新执行 build + upload，制品才真正进仓。同时在重出版本里把当初导致构建失败的条件全部消除（依赖版本上架、force 统一冲突依赖、为依赖合成缺失的构建期辅助文件），否则新的流水线会以同样的方式失败。务必同步更新 conandata/manifest/notes 与 test_package，并在 notes 里写清「为什么重出」——否则评审会认为是无意义的新版本。

**修复命令**:
```
conan list '<pkg>/*' -r=ohpcd ; conan graph info archives/<l>/<name>/<ver> -pr:h=<profile> -pr:b=<profile> -r=ohpcd
```

**验证**:
```
conan list 'libxmu/*' -r=ohpcd
```
