# E2940: Conan 制品只装 .so/.a 不带 libtool .la，而 autotools 依赖链靠 .la 递归解析：在 generate() 里为直接依赖合成 .la shadow 目录，并为被删掉的 .la 从 .so 反推补一个最小副本

## 基本信息
- **严重度**: 3
- **类别**: build-system, autotools, conan, dependency, libtool
- **作者**: 2301_76770579
- **来源 PR**: 13894

## 错误特征
```
"cannot find the library '.*\\.la'|libtool: error: .*\\.la.* No such file|expected one installed .*\\.la, found 0|\\.la.*No such file or directory|references a missing non-Conan libdir|was moved"
```

## 根因分析
autotools 项目用 libtool 链接时，libtool 会顺着依赖的 .la 归档文件里的 dependency_libs 递归解析传递依赖。Conan 打包的依赖（尤其 X11 家族）只有 .so/.a 与头文件，通常不带 .la；当 conan 从源码构建本包、而某个依赖恰好也走源码构建（或用的是会删 .la 的修订版）时，libtool 找不到对方的 .la，链接阶段直接失败。更隐蔽的是同一个库的不同修订版行为不一致：libx11/6.4.0 的 package() 里执行 rm("*.la") 主动删掉，libx11/1.8.13 的 package() 保留——于是「同一个依赖名，换一个 revisions 就构建失败」，本地与 CI 表现还可能不同。

## 推荐方案
**方法**: generate-shadow-dir-with-synthesised-la

**说明**: 在配方 generate() 里对每个直接 host 依赖的 libdir 收集所有 *.la，复制/重写到一个统一的 libtool-shadow 目录：把其中的 libdir= 与 dependency_libs= 改写成 shadow 目录下的绝对路径，再把该目录前置到 LDFLAGS（-L<shadow>），使 libtool 只看见这一份自洽的副本。若某个必需 .la 在依赖制品里根本不存在（对方 package() 删过），从同名 .so 反推合成一个最小可用 .la：dlname 取真实 .so 的 soname（读 DT_SONAME），library_names/old_library 填同名，dependency_libs 留空或只填已进入 shadow 的依赖，installed=yes。这样无论依赖走的是哪个 revisions，链接都能走通。

**修复命令**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
