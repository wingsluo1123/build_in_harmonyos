# E2951: test_package 中原地"窄类型转宽类型"改写会踩掉未读样本：向同一缓冲先写 float 再逐元素读 float 写 double，写入偏移(8i)超前于读取偏移(4i)，i>2 后覆盖尚未读取的源数据——DSP/音频库多精度接口测试必须按目标精度直接生成或经第二缓冲中转（libebur128 sample_peak 断言失败实证）

## 基本信息
- **严重度**: 2
- **类别**: portability, packaging, testing, c, dsp
- **作者**: codex

## 错误特征
```
FAIL - sample_peak tracks 0.8 amplitude input|1 check\(s\) FAILED|Error 1 while executing
```

## 根因分析
为复用正弦生成器，测试代码向 malloc 的 double* 缓冲以 (float*) 强转写入 float 正弦（占前 4N 字节），随后循环 buf[i]=(double)((float*)buf)[i] 原地拓宽——第 i 次迭代读取偏移 4i、写入偏移 8i，i>2 之后每次写入的字节区间 [8i,8i+8) 落在尚未读取的 float 数据 [4i+4,4N) 内，把后面的源样本踩成 double 位模式垃圾，导致 sample_peak 等依赖完整数据的断言失真。本机交叉编译只能证明"编译链接通过"，这类数据层 bug 只有真机运行断言才暴露（shadow CI r3 11 断言仅 1 挂，其余全过，极易误判为库问题）

## 推荐方案
**方法**: generate-directly-in-target-precision

**说明**: 多精度接口测试不要做任何原地类型拓宽：为每种精度提供独立生成器（或模板/宏），直接以目标类型写入；若必须转换，先 malloc 第二缓冲读旧写新，绝不复用同一块内存读写不同宽度

**修复命令**:
```
for (i=0;i<n;++i) buf[i]=0.8*sin(2.0*PI*1000.0*(double)(i/2)/SR); /* double 直接生成 */
```

**验证**:
```
设备端 sh run-conan-heavy.sh（r3 sample_peak FAIL → 改为直接生成 double 正弦后 r4 11/11 全过；本机 python 复算 max=0.800000000 ∈ 容差）
```
