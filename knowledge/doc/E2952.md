# E2952: musl 平台 ctypes.util.find_library() 恒返回 None —— ctypes 纯 Python 库应在 find_library 失败后按确切 SONAME CDLL 兜底并显式注入依赖 lib 目录（案例: legacycrypt 0.3 @ libxcrypt）

## 基本信息
- **严重度**: 3
- **类别**: compat, musl, python, runtime
- **作者**: unknown

## 错误特征
```
ImportError: libcrypt / libxcrypt missing|find_library.*None.*ImportError|OSError: Error loading shared library .*: No such file or directory
```

## 根因分析
musl 发行版（含 OHOS）无 /sbin/ldconfig 且无 gcc/objdump，ctypes.util.find_library() 三条探测路径（_findSoname_ldconfig/_findLib_gcc/_findLib_ld）全部不可用，对任何库——包括设备上真实存在的共享库——恒返回 None；上游按 glibc 生态假设写死的 find_library('crypt') 加载链全失败后在 import 期抛 ImportError。修复在消费库侧：全失败后按确切 SONAME try CDLL（SONAME 用 readelf 实测依赖包产物，如 libxcrypt shared 产物为 libcrypt.so.2，NEEDED 仅 libc.so），且依赖必须以 shared=True 提供（静态归档无法 dlopen）；conan 依赖图不会为 ctypes/dlopen 式消费注入 LD_LIBRARY_PATH，build()/test_package 须显式注入依赖 cpp_info.libdirs。

## 推荐方案
**方法**: source-patch-cdll-soname-fallback

**说明**: 补丁在上游 find_library 全失败的 except OSError 分支加探测式 fallback：先按 libxcrypt 的 crypt_data 布局选实现，再 try CDLL('<实测 SONAME>')，仍失败才抛 ImportError；配方侧 requires 依赖并 default_options 强制 shared=True；build() 与 test_package 显式将依赖 cpp_info.libdirs 前置注入 LD_LIBRARY_PATH（conan 只为链接器/生成器铺路径，不感知 dlopen）。

**修复命令**:
```
补丁随配方交付（conandata.yml patches → apply_conandata_patches），见 archives/l/legacycrypt/0.3/patches/0001-legacycrypt-ohos-fallback-load.patch
```

**验证**:
```
PY=$(command -v python3 || echo /storage/Users/currentUser/usr/local/bin/python3); XP=$(find /storage/Users/currentUser/.conan2/p -maxdepth 5 -name libcrypt.so.2 2>/dev/null | head -1 | xargs dirname); $PY -c "import ctypes.util as u; print(u.find_library('crypt'), u.find_library('m'))"   # → None None; $PY -c "import ctypes; ctypes.CDLL('libcrypt.so.2')"; echo rc=$?   # 无注入时 → OSError（预期，库不在 loader 搜索路径）; LD_LIBRARY_PATH=$XP $PY -c "import ctypes; print(ctypes.CDLL('libcrypt.so.2'))"   # → <CDLL 'libcrypt.so.2'> CDLL OK; readelf -d $XP/libcrypt.so.2.0.0 | grep SONAME   # → libcrypt.so.2
```
