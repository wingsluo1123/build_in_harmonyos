# E2956: CMake 巨型工程拆成多 conan 组件包的生产端构建前提：generate 期 $<TARGET_FILE:> 把可选 target 变硬前提、上游 install() 要求全量 target、测试子模块为空、运行期与配置期依赖需分开判定

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, cmake, dependency, packaging
- **作者**: unknown

## 错误特征
```
Error evaluating generator expression|No target \"(grpc_cpp_plugin|graph_plugin)\"|file COPY cannot find.*third_party/.*\.proto|CMake Generate step failed
```

## 根因分析
把上游单一 CMake 工程拆成多个 conan 组件包（每个只交付一个 target）时，上游构建系统里四个「按全量构建写死」的隐含前提会依次掀翻「只 build 子 target」的做法。①【generate 期 target 硬前提】CMakeLists 用 $<TARGET_FILE:grpc_cpp_plugin> 这类生成器表达式做 add_custom_command 的 COMMAND/DEPENDS；只要该 target 在本次 configure 里未定义（把 gRPC_BUILD_CODEGEN 关掉，或把插件 target 关掉），CMake generate 阶段（不是 build 阶段）就对每个引用点报 `Error evaluating generator expression ... No target "grpc_cpp_plugin"`，整个工程一个 target 都 generate 不出来。上游对选项耦合的注释是「Codegen must be ON when gRPC_BUILD_TESTS=ON」——BUILD_TESTS 打开了会引用插件 target 的代码生成规则，必须同时开 CODEGEN 才能让 generate 通过；而实际 build 时并不需要真去编这个插件（只要不列进 --target）。②【install 脚本要求全量 target】上游 install(TARGETS ... EXPORT ...) 覆盖全量 target；拆分件只存在其中一部分，gRPC_INSTALL=ON 时 install 阶段因缺 target 失败；拆分件必须 INSTALL=OFF，自己 copy 产物。③【测试子模块为空】GitHub release tarball（archive/refs/tags/*.tar.gz）不打包 git submodule，third_party/* 是空目录，而 gRPC_BUILD_TESTS=ON 的 CMakeLists 会 file COPY 这些子模块里的 .proto；缺一个就 `file COPY cannot find ... typed_struct.proto`；必须按 pin 的 commit 下载并放进 third_party/<name> 槽位。④【依赖圈层不清】gRPC_*_PROVIDER=package 时顶层 CMakeLists 无条件 find_package() protobuf / c-ares / re2 / openssl / zlib，但它们不一定被交付 target 引用；照抄「配置期 schema」当 requires 会把一大串包塞进运行期闭包（体积、ABI、rebase 面全膨胀）；判据只能是「该 target 的 target_link_libraries 里有没有它」——gpr 的答案只有 abseil（22 个 absl 组件）。

## 推荐方案
**方法**: split-build-target-closure-with-option-coupling-and-dep-layer-separation

**说明**: 四步一起做：①【保 generate 过】把所有被 $<TARGET_FILE:> 引用的插件/codegen target 的选项打开（grpc 例：gRPC_BUILD_CODEGEN=ON，即便不打算编它），保证 generate 期 target 存在；真正 build 时只 `cmake --build --target <需要的 target>`，不列插件。上游注释（BUILD_TESTS ⟹ CODEGEN）是权威判据。②【手动打包】gRPC_INSTALL=OFF，package() copy 产物（lib*.a/.so、公开头、LICENSE）；公开头清单以上游 CMakeLists 里该 target 的 _hdr foreach 列表为准。③【测试子模块物化】conandata 写每个 third_party 子模块的 pin commit tarball + sha256，source() 解包后 move 进 third_party/<name> 槽位。④【依赖分层】requires 只写交付 target 真正链接的包；纯 find_package 的包标注为「配置期依赖 / 不取符号」；ABI 相关包（abseil vs protobuf）必须锁同一 lts。

**修复命令**:
```
grep -n '\$<TARGET_FILE:' CMakeLists.txt | head; cmake --build <build> --target gpr -j$(nproc); conanfile.py source(): get(self, **self.conan_data['sources']['xds']); shutil.move(glob.glob('xds-*')[0], 'third_party/xds'); awk '/add_library\(gpr/,/^\)/' CMakeLists.txt | grep -A40 target_link_libraries | grep -oE 'absl::[a-z_]+' | sort -u | wc -l  # → 22，只有 abseil
```
