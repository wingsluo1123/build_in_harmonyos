## 根因分析
"The HarmonyOS PC kernel refuses shebang script execve at the syscall level (EACCES/Error 13) regardless of executable bits. This bites not only build-time/configure-time script execution but also RUNTIME command spawning: libraries that fork()+execve() user-configurable commands (logrotate-style prerotate/postrotate, hook commands, notify scripts) with no shell fallback silently lose those commands, because the child's execve of the script path fails and the child exits without any reporting channel (async spawn). Kea's ProcessSpawn (src/lib/asiolink/process_spawn.cc) is exactly this shape: ProcessSpawnImpl::spawn() = fork + execve(executable, args, vars) + _exit(EXIT_FAILURE); the legal-log hook's RotatingFile::rotateFiles() calls it with the user-configured prerotate/postrotate commands, which are shell scripts (upstream's own tests run forensic_prerotate_test.sh / forensic_postrotate_test.sh). On OHOS every such spawn dies in the child: the gtest cases prerotateActions/postrotateActions/prerotateAndPostrotateActions fail because the script side-effect files never appear. Unlike configure-time scripts there is no meson run_command indirection to patch at the call-site layer — the fix must live in the code that owns the spawn, with a compile-time guard so glibc/Linux (upstream CI) keeps the original direct-execve path (where non-script binary commands also work)."

## 推荐方案
**方法**: "Route the spawned command through /bin/sh under a musl-Linux compile guard: #if defined(__linux__) && !defined(__GLIBC__) — push the command itself as the first argument (script path becomes $1 to the shell, preserving the original argv semantics byte-for-byte), push the original args after it, and change the spawn executable to /bin/sh; keep the direct execve in the #else branch. The guard keyed on !__GLIBC__ (not on the OS name) keeps upstream CI on glibc/Linux untouched and matches the family convention used for header conflicts. Verify with the upstream tests that actually execute the scripts (side-effect-file assertions), not just compile. Also check the library for OTHER spawn sites (grep ProcessSpawn across the tree) before declaring the patch complete — the same class of call can hide in adjacent components."
