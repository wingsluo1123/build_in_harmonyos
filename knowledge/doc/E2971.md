# E2971: OHOS 设备沙箱在 syscall 级拒绝进程控制类调用（ptrace/FIFO/unix socket bind）：lldb inferior 启动与 gtest 进程控制用例 EPERM——环境因素非适配缺陷，归因须分三级证据

## 基本信息
- **严重度**: high
- **类别**: platform, testing
- **作者**: ''

## 错误特征
```
"Cannot launch '<path>': ptrace failed: Permission denied"
```

## 根因分析
OHOS 设备内核级沙箱策略在 syscall 层拒绝 ptrace（进程跟踪/attach）、匿名 FIFO（os.mkfifo）、unix socket bind——三者探针均 EPERM（repro-matrix P2/P3 + gtest 原始日志断言行）。命中面：lldb inferior 启动（ProcessLaunch→ptrace，45 例可见 `ptrace failed: Permission denied`）、lldb-server（3 例）、launch 下游错误（5 例）、需目标进程的 FileCheck 类（36 例：15 探针实证 + 21 同族推定）、gtest Host 8（pipe bind）/Target 13（spawn）/DAP 4（mkfifo）。正控：普通 exec 允许（rc=0）→ 被拒的是进程控制 syscall 族而非"不能启动"。09-28/09-30 两日独立全量重跑 120 例失败测试集 byte-identical（签名逐例吻合）= 稳定策略非抖动。重要边界：本构建无 python（SWIG-NOTFOUND → LLDB_ENABLE_PYTHON=Auto），API 套件 1342 例 0 执行——**未观测到任何放行正控上下文**；09-28 报告「SB API 1342/1342 全过」系误读（unsupported≠通过），「沙箱按 tracer 进程上下文生效（python 路径放行）」推论已撤销——无正控不得下上下文级策略结论。

**方法**: attribute-to-env-with-evidence-grading
