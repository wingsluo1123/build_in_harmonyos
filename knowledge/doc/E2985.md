# E2985: AArch64 有符号整数浮点溢出检测不应依赖越界强转结果

## 基本信息
- **严重度**: 2
- **类别**: portability, c++, testing, aarch64, integer
- **作者**: 11156-TINYARRAY
- **来源 PR**: 13660

## 错误特征
```
DID NOT RAISE OverflowError|Float too large to be represented by long
```

## 根因分析
对 64 位 long，numeric_limits<long>::max() 是 2^63-1，但转为 IEEE-754 double 会舍入为 2^63。若先 static_cast<long> 再靠结果符号检查溢出，越界浮点到整数转换的结果受架构/指令影响：AArch64 可饱和为 LONG_MAX，x86_64 常见结果则表现为 LONG_MIN；原比较与符号检查都可能漏掉同一个越界输入。

## 推荐方案
**方法**: compare-exact-power-of-two-before-float-cast

**说明**: 对 64 位有符号目标，在强转前用可表示的 2^63 与 -2^63 边界判断范围；下界按浮点类型精度分别处理，只有确认范围内后才 static_cast。

**修复命令**:
```
# 用目标类型的位宽构造 2^N；先比较浮点输入，再执行 static_cast<Tdest>
```

**验证**:
```
在 AArch64/clang 优化构建中运行 tinyarray.array(float(2**63), int)，必须抛出 OverflowError；tinyarray.array(float(-(2**63)), int) 必须可转换。再检查转换代码的上界先于整数强转。
```
