# E2988: autotools 上游 TESTS 变量为空时 make check 只构建不运行：测试清点必须下探到 check_PROGRAMS 并逐个真实执行，否则误报 N=0 或把"构建成功"当"测试通过"

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, conan, testing, automake
- **作者**: Quas
- **来源 PR**: 13886

## 错误特征
```
Nothing to be done for ['"]?check|#\s*TOTAL:\s*0|#\s*PASS:\s*0|
```

## 根因分析
automake 里有两个语义完全不同的变量：TESTS 是"要执行的测试"列表，check_PROGRAMS 只是"要构建的测试程序"列表。libydpdict 1.0.4 官方 release tarball（40 个成员，无 tests/ 目录）的 misc/Makefile.am 第 1 行只有 check_PROGRAMS = ydpstress ydptest ydpxml gentable，全树 src/include/misc 三个 Makefile.am 均无 TESTS；生成后的 misc/Makefile.in 因此只有 "check-am: all-am" + "$(MAKE) $(AM_MAKEFLAGS) $(check_PROGRAMS)"，没有 $(TEST_LOGS)/$(TEST_SUITE_LOG) —— make check 把 4 个程序编译出来就结束，退出码 0 只表示"构建成功"，一个用例都没跑。两类后果：(1) 清点误报——以"是否存在 tests/ 目录 / 是否有 TESTS 变量 / 是否有 ctest-pytest 注册项"三面判据清点，三面全 0，于是 1.0.4 的申报写成"上游无 check_PROGRAMS、测试总数 N=0"；实际下探 check_PROGRAMS 得 N=4（其中 ydptest_SOURCES=ydpstress.c，与 ydpstress 同源、独立二进制）。(2) 假通过——把 make check 的退出码 0 当成"上游测试通过率 100%"，此时测试程序连运行都没运行；"只构建不执行就宣称已执行"是同一类误报。本条与 DRAFT-10251-libnfc-tools-1.8.0-autotools-test-framework-guard（configure 守卫把套件整体排除，TOTAL: 0）、DRAFT-mpsolve-3.2.3-make-check-green-is-not-deliverable-green（check 只链构建树私有库、SKIP 计入 TOTAL）同属"退出码/汇总面不等于执行面"，但根因是变量语义被混淆：TESTS 空 ≠ 没有测试资产。

## 推荐方案
**方法**: enumerate-check-programs-then-execute-each

**说明**: 清点与执行分两步、都不依赖 TESTS：第一步清点"注册面"——同时检查 check_PROGRAMS、check_SCRIPTS、check_LTLIBRARIES、TESTS 与各框架注册项，任一非空都计入 N，并展开 *_SOURCES 识别同源多二进制（ydptest_SOURCES=ydpstress.c 按 2 例计）、确认程序是否依赖外部测试数据（如 DICT_PATH）；第二步执行——make -C <dir> check 只负责构建，随后逐个直接运行每个 check 程序，逐个记录退出码与原始输出，任一非 0 即让构建失败。数据依赖不可分发时按上游自带合成工具造等价测试数据（libydpdict 用上游 EXTRA_DIST 的 misc/mkdict.py 格式合成 4 本词典），测试程序源码与判定逻辑零改动；环境确实无法提供数据（只读根文件系统）时，必须逐个打印 "skip (no corpus at ...)" 之类的显式理由，绝不允许静默跳过或把跳过计入通过数。
