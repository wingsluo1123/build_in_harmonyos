# E2993: 'OHOS/musl libc 缺 GNU 扩展 on_exit()：头文件不声明（implicit-function-declaration 警告）且动态库无该符号 ⇒ 编译过、链接期 ld.lld 报 undefined symbol: on_exit；改 POSIX atexit() 并以文件级静态变量承载原第 2 个参数'

## 基本信息
- **严重度**: 3
- **类别**: compat, libc, compiler, linking
- **作者**: 8750-MDT
- **来源 PR**: (待回填)

## 错误特征
```
'ld\.lld: error: undefined symbol: on_exit| undefined reference to .*on_exit| call to undeclared function ''on_exit'''
```

## 根因分析
'on_exit(void (*function)(int, void *), void *arg) 是 glibc/GNU C 库的 扩展（注册退出回调时把 status 与调用方的 arg 一并回传），POSIX 只标准化了 atexit(void (*)(void))（无参数）。OHOS PC 的 C 库基于 musl：头文件不声明 on_exit（clang 报 implicit-function-declaration 警告），动态库里也没有该符号 ⇒ 编译阶段能过，链接阶段 ld.lld 报 "undefined symbol: on_exit"。与平台 签名/执行权限无关，是纯 libc API 差异。'

## 推荐方案
**方法**: replace-on-exit-with-atexit

**说明**: 把 on_exit(cb, arg) 改为 atexit(cb_wrapper)：因为 atexit 的回调不带参数， 用文件级静态变量承载原 arg（单注册点场景），回调签名由 `void cb(int status, void *arg)` 改为 `void cb_wrapper(void)`，回调内读该 静态变量。改动只落在源文件，不引入平台宏、不动 libc、不加 stub；语义等价 （本例回调并不使用 status 参数）。

**修复命令**:
```
见 .md 的 before/after 代码块；补丁落点 archives/<首字母>/<包>/<版本>/patches/*.patch 并在 conandata.yml 以 patch_file 引用
```
