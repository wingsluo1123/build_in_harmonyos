# E2994: KF6 托盘 StatusNotifierItem 的同名双配方选型与 Qt6DBus 单提供者基座

## 基本信息
- **严重度**: 2
- **类别**: portability, conan, dependency-graph, kf6, provider
- **作者**: unknown

## 错误特征
```
"find_package could not find KF6StatusNotifierItem|USE_DBUS=OFF: StatusNotifierItem 的 DBus adaptor 被编译掉、托盘静默失效（无构建报错）|Qt6DBus 由 qtbase/6.11.1.1 (FEATURE_dbus=ON) 单提供者给出"
```

## 根因分析
"制品仓按包名首字母分目录存放，同名近似的两份配方（kstatusnotifieritem / statusnotifieritem）上游、版本号、安装产物全部相同，只能靠配方 docstring 区分；选错时 CMake 仍能 find_package 成功、链接也成功，只是 KStatusNotifierItem 的 org.kde.StatusNotifierItem / org.kde.StatusNotifierWatcher / org.freedesktop.Notifications 三个 DBus 适配器被上游 #if HAVE_DBUS 守卫整段编译掉 ⇒ 托盘在 OHOS 上静默失效，没有任何构建期报错（编译通过 ≠ 适配完成 R40）。"

## 推荐方案
**方法**: "KF6 托盘/DBus 消费者选型三步：(1) 打开 archives/<首字母>/<包名>/<版本>/conanfile.py 读 docstring，逐条核对 USE_DBUS / FEATURE_dbus / 依赖基座，不看版本号；(2) 要托盘协议就选 archives/s/statusnotifieritem/6.26.0（USE_DBUS=ON，依赖 qtbase/6.11.1.1 + kwindowsystem/6.18.0），要 Qt6DBus 就选 qtbase/6.11.1.1（FEATURE_dbus=ON）让整张图只有一个 Qt6 提供者、不引入 qtbase-sql-dbus 变体；(3) 交叉核对依赖基座：statusnotifieritem/6.26.0 的 kwindowsystem/6.18.0 与 kio/6.14.0 内部 6.14 钉版冲突时用消费者 override=True 统一到 6.18 闭包。"
