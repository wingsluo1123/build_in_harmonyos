# E3002: 上游 main 分支含文件名带 \r 的文件时，Windows 上 git worktree add 检出失败；用 --no-checkout + sparse-checkout 排除建仓

## 基本信息
- **严重度**: 2
- **类别**: platform, filesystem, git, workflow
- **作者**: unknown

## 错误特征
```
fatal: Could not reset index file to revision 'HEAD'.|error: unable to create file .*Invalid argument
```

## 根因分析
origin/main 的历史提交中存在文件名含控制字符（实测为结尾双 \r，如 archives/g/gama/2.29/patches/0002-dataparser-ungated.patch\r\r）的文件。Windows 文件系统禁止文件名含 CR，检出时 CreateFile 报 Invalid argument，git 在更新完其余全部文件后于写 index 步骤失败（fatal: Could not reset index file to revision 'HEAD'.）并自动回滚删除 worktree 目录。反复重试、禁用 core.fscache、预创建目录均无效。主工作区能存活只是因为该文件长期处于 deleted（git status 显示 D + 引号包裹文件名）状态。这是仓库内容与 Windows 平台的不兼容，与 E007/E122（config.guess 三元组）完全无关。

## 推荐方案
**方法**: no-checkout-sparse-worktree

**说明**: 三步绕行：① git worktree add --no-checkout -b <分支> <路径> origin/main（不检出，先建元数据）；② 写 <主仓库>/.git/worktrees/<名>/info/sparse-checkout，内容为 "/*" 一行加 "!<问题文件路径（\r 用实际控制字符写入）>" 一行，然后 git sparse-checkout init --no-cone（顺序：先 init 再写 patterns 亦可）；③ 在 worktree 内 git checkout 完成检出。补刀：git update-index --skip-worktree "<问题文件>"，防止误把删除提交进 PR。若嫌控制字符难写，可用更宽的目录级排除（!archives/g/gama/2.29/patches/），与 tayga 无关的路径排除不影响交付边界。后续 git status 里该文件不再出现，其余照常。

**修复命令**:
```
git -C <repo> worktree add --no-checkout -b feat/<lib>-<ver>-codex <wt> origin/main && git -C <wt> sparse-checkout init --no-cone && printf '/*\n!<badpath>\n' > <repo>/.git/worktrees/<name>/info/sparse-checkout && git -C <wt> checkout
```

**验证**:
```
git -C <主仓库> status --short | findstr /r "^ D"    # 若看到带引号且含不可见字符的 D 文件名即命中；重试 worktree add 观察是否有 "error: unable to create file ... Invalid argument" 行（GIT_TRACE=1 更清晰）
```
