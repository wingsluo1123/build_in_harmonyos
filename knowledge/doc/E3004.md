# E3004: layout 把 generators 放 "." 时，本机 conan create/test 会把 conanbuild.sh、conanrunenv-*-x86_64.sh 等写进 test_package/；打包传设备前必须清理，否则污染真机包目录

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, device-transfer, workflow
- **作者**: unknown

## 错误特征
```
test_package/ 里出现 conanbuild.sh|conanrun.sh|conanbuildenv-release-x86_64.sh|deactivate_conan*.sh|metadata/；传输后设备 find 列出这些文件
```

## 根因分析
一批配方（kelbt/tayga 式 in-source layout）设置 self.folders.generators = "."。conan create 的 test 阶段会在 generators 目录生成 VirtualRunEnv 产物（conanrun.sh、conanrunenv-release-x86_64.sh、deactivate_*.sh、conanbuild.sh 等），于是这些文件被直接写进 test_package/。它们不会被 .gitignore 逐个排除、git status 有时也看不到（被全局 ignore 规则吞掉），但 tar -czf archives/<l>/<lib> 打包时会全部带上 → 设备端包目录混入 x86_64 命名空间的生成物，轻则 JC 垃圾文件门禁可疑，重则干扰真机 conan 的 generators 步骤。且每次"本机验证→打包"循环都会重新生成，清一次不够。

## 推荐方案
**方法**: clean-before-pack-and-after-verify

**说明**: 两道防线：① **打包前清**：tar 打包命令前删 test_package 下的 conanbuild.sh、conanbuildenv-*.sh、conanrun.sh、conanrunenv-*.sh、deactivate_*.sh、metadata/、__pycache__/（Powerhell Remove-Item 一次列全）。② **验证后清**：Docker 回归命令末尾挂同款清理，保证 worktree 里不留残留（下次 git status/diff 不受干扰）。根治方案（可选）：本机验证不挂载 worktree 本体，把包目录 copy 到临时目录再 conan create，生成物落在副本里。设备端解压后同样 find 复查一遍，发现生成物就地删除再开跑。

**修复命令**:
```
Get-ChildItem <pkg>/test_package -File | Where-Object Name -match '^(conanbuild|conanrun|conanbuildenv|conanrunenv|deactivate_)' | Remove-Item -Force; Remove-Item <pkg>/test_package/metadata,<pkg>/test_package/__pycache__ -Recurse -Force -ErrorAction SilentlyContinue
```

**验证**:
```
find archives/<l>/<lib>/<ver>/test_package -maxdepth 1 -type f | sort    # 出现 conan*.sh / deactivate*.sh / metadata 即中招
```
