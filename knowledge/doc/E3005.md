# E3005: L1e 自测必须用 "pkg/ver:<package_id>" 定位产物目录；conan cache path <ref> 返回的是配方 export 目录，破坏它等于没破坏

## 基本信息
- **严重度**: 2
- **类别**: conan, testing, methodology
- **作者**: unknown

## 错误特征
```
conan cache path tayga/0.9.2 → export 目录（仅 conanfile.py/conandata.yml/conanmanifest.txt）|破坏产物后 conan test 仍然通过|sabotaged_test_exit=0
```

## 根因分析
Conan 2 的 `conan cache path tayga/0.9.2`（不带 package_id）返回的是 export 目录（~/.conan2/p/<hash>/e，里面只有 conanfile.py/conandata.yml/conanmanifest.txt）。包的真实产物在 `~/.conan2/p/b/<hash>/p`（即 `conan cache path 'tayga/0.9.2:<package_id>'` 的返回值）。对 export 目录 rm bin/tayga 是无害空操作（rm -f 静默成功），随后 conan test 仍从完好的产物目录解析出二进制 → sabotaged_test_exit=0，看起来像"假测试被实锤"，实际是破坏错了位置。CI 的 L1e（build_and_test.sh 的破坏性反向验证）用的是正确的产物目录，不会误判。

## 推荐方案
**方法**: sabotage-real-artifact-dir

**说明**: 正确的 L1e 本机自测序列：① conan create . --build=missing；② conan list '<pkg>/<ver>:*' --format=json 解析出 package_id（注意 JSON 顶层结构是 {revisions:{<rrev>:{packages:{...}}}}，用递归查找比猜层级稳）；③ PKGDIR=$(conan cache path '<pkg>/<ver>:<package_id>')；④ ls 确认看得到 bin/ 或 lib/ 再 rm 产物二进制；⑤ conan test test_package <pkg>/<ver> 必须非零退出（典型 Error 127）。若第④步目录里只有 conanfile.py，说明拿错目录，立即停止勿下"假测试"结论。

**修复命令**:
```
PKGID=$(conan list '<pkg>/<ver>:*' --format=json | python3 -c "import json,sys;d=json.load(sys.stdin)
```

**验证**:
```
conan list '<pkg>/<ver>:*' --format=json    # 从 revisions→<rrev>→packages 取 package_id；conan cache path '<pkg>/<ver>:<package_id>' 应返回含 bin/lib 等产物的目录
```
