# E3006: OHOS下go test临时二进制-exec前自签名与column-0顶层诚实计数

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, build-system, testing
- **作者**: hmbs-executor
- **来源 PR**: 14386

## 错误特征
```
go test -v -count=1.*returncode=1|discovered=72/executed=0|executed 83 vs discovered 72|cat.*\/tmp\/parlay-neg-.*No such file
```

## 根因分析
主parlay二进制与Go SDK已自签名，但go test在GOTMPDIR生成的临时.test二进制未经签名被OHOS内核拒绝fork/exec致零--- PASS/FAIL行，旧逻辑又用skipped算术补齐掩盖；另conanfile用strip后判--- PASS把缩进t.Run子测试计入致83大于顶层72，且test.sh负例写死/tmp致重定向失败

## 推荐方案
**方法**: go-test-exec-sign-plus-column0-count

**说明**: 新增go-test-exec.sh在exec前对临时.test二进制自签名后执行，OHOS自动带-exec wrapper；仅计column-0顶层--- PASS/FAIL/SKIP行并删除skipped补齐如实计数加gaps，负例输出改用TMPDIR

**修复命令**:
```
archives/p/parlay/0.11.0/conanfile.py: 新增_write_go_test_exec_wrapper并在OHOS时go test自动带-exec wrapper，_run_upstream_tests改line.startswith仅计column-0；archives/p/parlay/0.11.0/test_package/test.sh: 负例输出改${TMPDIR:-${TMP:-${TEMP:-/tmp}}}/parlay-neg-$$.out并mkdir -p
```

**验证**:
```
真机保留go test -v -count=1 -exec wrapper的returncode与PASS/FAIL/SKIP顶层计数，executed/passed与grep ^func Test顶层数一致且无skipped算术补齐，并附80行日志tail
```
