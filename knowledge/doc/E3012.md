# E3012: PyPI 纯资产包取源决策:sdist 需 node 构建链时改用官方 wheel + 任务号无上游发布时的溯源基线规则

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, build-system, conan, packaging
- **作者**: 0AE8

## 错误特征
```
requires node|webpack not found|npm ERR|sdist.*build|no matching distribution|version not found|Task version has no upstream release
```

## 根因分析
两类可复用问题:(1) PyPI 项目的 sdist 是"构建输入"(CSS/JS 源码+构建钩子),主题/前端资产需 node+webpack 构建后才存在,OH 构建环境无 node 链且不应引入——而官方 wheel 就是上游构建完成的产物(py3-none-any,纯资产);(2) 平台任务版本号按需求时间点编,与上游 tag 不同步,硬凑任务号会引入"上游无此版本"的评审风险。

## 推荐方案
**方法**: official-wheel-as-source-with-task-ref-provenance

**说明**: (1) 用 PyPI JSON API 取 bdist_wheel 的 url+sha256+size 钉进 conandata.yml,wheel 即 zip,get() 校验下载后 unzip() 展开,不依赖 pip/node;(2) 目录/分支/conan 版本用任务号(R40),manifest/notes 写明"任务号无上游对应发布,基线=同时间线最近真实发布"的溯源链;(3) 按 site-packages 布局安装(<pkg>/+dist-info),package_info 导出 PYTHONPATH 与包专属变量,宿主工具(Sphinx entry points)直接发现;(4) 沿用数据/源码包豁免:package_id 清空 noarch + build()/test 双端钉死哈希校验器。

**修复命令**:
```
python verify_furo.py --source-root <unpacked-wheel> && conan create archives/f/furo/2024.8.30 --build=missing
```

**验证**:
```
python verify_furo.py --source-root <unpacked-wheel> && conan create archives/f/furo/2024.8.30 --build=missing
```
