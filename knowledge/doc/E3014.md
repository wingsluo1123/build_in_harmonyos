# E3014: 零编译 shell/配置包配方模式——build() 以 bash -n 全量语法校验+配置键 grep 断言充当构建验证;tarball 权限位混杂须显式 os.chmod 对齐 Debian rules;Debian control 的 Build-Depends 是下游打包依赖不等于上游源码依赖;test_package 用函数库真实执行探针替代不存在的上游套件

## 基本信息
- **严重度**: 3
- **类别**: conan, shell, application-package, debian-layout, zero-compile
- **作者**: 2301_80739235

## 错误特征
```
syntax error near unexpected token|No such file or directory.*etc/acpi|permission denied.*\.sh|expected 7 event configs
```

## 根因分析
①纯脚本/配置类上游不带构建系统(无 configure/Makefile),配方若照搬库模板(build 跑 make/编译器)在 CI 直接失败,而 build() 空置又让截断/损坏的源码静默进入 package。正确形态是"验证即构建":对全部脚本 bash -n、对主配置 grep 关键节、对每份事件/单元配置断言必需键(如 action=),任何损坏在 build 阶段即报错。②上游 git 导出 tarball 的权限位混杂(同为 .sh,644 与 755 并存),conan copy 保留源 mode 直接安装会出现"脚本不可执行"或"函数库带执行位";必须 package() 里显式 os.chmod,对齐 Debian rules 的两行惯例(find -name "*.sh" -exec chmod a+x;函数库 chmod a-x)。③按 Debian control 的 Build-Depends 声明 conan requires 会引入根本不需要的依赖(libsystemd-dev 之类是下游打包依赖,上游源码零引用),R27 下甚至可能因平台无该制品而卡死——依赖必须按上游源码事实(引用了什么头/库)而非下游打包文件。④上游无测试套件时,test_package 用"函数库 source 后真实调用"探针:遍历类函数返回值语义上 0/1 均属正常执行,断言应接受 rc∈{0,1} 而非仅 rc=0。

## 推荐方案
**方法**: validate-as-build-plus-explicit-chmod-plus-source-facts-deps

**说明**: build() 对全部脚本跑 bash -n 并对配置断言必需键;package() 按 Debian 布局安装后显式 os.chmod(处理脚本 0755、配置与函数库 0644);requirements() 留空除非上游源码真实引用;test_package 以 source 函数库+调用函数的探针(接受语义内多返回值)替代缺失的上游套件。

**修复命令**:
```
for s in scripts: self.run('"bash" -n "src/s"'); grep -q "action=" ev; os.chmod(pkg/etc/acpi/f, 0o755); probe: . state-funcs; isAnyWirelessPoweredOn; [ $? -le 1 ]
```

**验证**:
```
本机与 CI 同逻辑:bash -n 全部脚本 + grep 断言;probe.sh 8/8 断言 PASS(布局 3 项、事件键 2 项、语法 1 项、函数执行 1 项、常量表 1 项)。
```
