# E3018: "1) 读模块 Makefile 原文确认探测变量名（不要假设为 <NAME>_BUILDER）；2) 以 make 命

## 基本信息
- **严重度**: P2
- **类别**: build-system
- **作者**: unknown

## 错误特征
```
"链接行出现构建机路径（如 -L/usr/lib -lev 或第三方注入路径）而期望指向依赖包目录；或 make 链接阶段报 cannot find -lXXX / undefined reference 而依赖包实际存在"
```

## 根因分析
"kamailio 模块 Makefile 的外部依赖探测变量名逐模块不同（tls→SSL_BUILDER、gcrypt→GCRYPT_BUILDER、evapi/memcached 等→裸 BUILDER），探测逻辑为『CROSS_COMPILE 为空时 which pkg-config → --exists <dep> 命中则取 --cflags/--libs，未命中则清空变量回退 LOCALBASE』。同一条 make 命令在不同构建机上因此有**两种落点**：若构建机装有同名系统库（带 .pc）则探测命中并指向构建机路径（交叉编译事故）；若依赖包（如 libev/4.33）不提供 .pc 则自动回退 LOCALBASE。套用同族配方的变量名（以为都叫 *_BUILDER）会钉死失败且无任何报错——只有读链接行才能发现。"

## 推荐方案
**方法**: "1) 读模块 Makefile 原文确认探测变量名（不要假设为 <NAME>_BUILDER）；2) 以 make 命令行变量显式钉死（命令行变量优先于文件内赋值，含 `BUILDER=` 置空以直接跳过探测分支）；3) 同时把 LOCALBASE / CPATH / LIBRARY_PATH 三处指向 conan 依赖包目录，保证探测与编译链接两条路径都只可能命中依赖包；4) 用 `make -n` 打印实际编译/链接行核验，并以 PATH 前置假 pkg-config 做 A/B 劫持实验把结论变成可证伪证据。"
