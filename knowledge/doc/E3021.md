# E3021: libbsd 假依赖必须核到符号级：metastore 1.1.2 对 libbsd 的真实依赖面只有 1 个符号 strmode(3)，而 Makefile 里 -lbsd 名义上伺候的 strlcpy/strlcat 其实是 musl 原生自带；且符号存在性探针若链 -shared .so 会把「不存在」误判成「存在」

## 基本信息
- **严重度**: 1
- **类别**: ohos, portability, libc, build-system, link
- **作者**: unknown

## 错误特征
```
fatal error: 'bsd/string.h' file not found|undefined symbol: strmode|cannot find -lbsd|metastore_DLIBS
```

## 根因分析
两层，且第一层直接决定第二层的方法。

## 推荐方案
**方法**: verify-dep-at-symbol-level-then-in-tree-bsd-shim

**说明**: (a) 先把依赖核到符号级再决定策略，不要信台账也不要信 Makefile 的 -l 行：全树 grep 目标 BSD 函数 → 确认树内无定义（即纯导入）→ `nm -D` OHOS libc.so 确认该符号是否已由 musl 提供 → 再 `conan download --only-recipe` 看制品仓是否已发布该兼容库。只有当真实依赖面是「一堆符号」时才值得走 R36 先适配发布 libbsd；只有 1-2 个符号时一律走树内 shim。

**修复命令**:
```
grep -rn 'strmode' src/ ; nm -D "$OHOS_SYSROOT/usr/lib/aarch64-linux-ohos/libc.so" | grep -c strmode
```

**验证**:
```
nm -D <ohos-sysroot>/usr/lib/aarch64-linux-ohos/libc.so | grep -E ' (strmode|strlcpy|strlcat)$'
```
