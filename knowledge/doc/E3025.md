# E3025: 构建期 host 工具的交叉坑——autotools 包自带的代码生成器(libatasmart strpool)被交叉 CC 编译后须在构建机执行必挂;tarball 已自带生成产物时,最小解是 patch 生成规则为 noop + SUBDIRS 摘除,而非引入 CC_FOR_BUILD 工具链

## 基本信息
- **严重度**: 2
- **类别**: autotools, make, cross-compile, conan, host-tool
- **作者**: 2301_80739235

## 错误特征
```
cannot execute binary file.*strpool|Exec format error.*strpool|strpool.*Permission denied
```

## 根因分析
libatasmart 的顶层 Makefile 无条件 `make -C strpool strpool` 编译代码生成器,并执行 `strpool atasmart.c atasmart.strpool.c` 生成字符串表。native 构建无碍;交叉构建时 strpool 被目标链(aarch64 clang)编译,随后在构建机(x86_64)上执行即 "cannot execute binary file",make 中断。关键事实:**发行 tarball 已自带生成好的 atasmart.strpool.c**——生成步骤在交叉场景完全多余,规则 noop 后 make 直接使用捆绑产物。通用判据:tar -tzf <pkg> | grep <generated-name>,若存在则无需任何 host 工具。

## 推荐方案
**方法**: noop-generated-file-rules-plus-subdirs-prune

**说明**: patch(Makefile.in,configure 前应用):①SUBDIRS 摘除 host 工具子目录;②生成目标规则改为仅 echo(使用捆绑产物)。优于 CC_FOR_BUILD 方案:不假设 CI 存在 host gcc、不改动上游工具源码、补丁行数最小。应用顺序在 configure 之前(Makefile.in 是模板)。

**修复命令**:
```
patch(Makefile.in): "SUBDIRS = strpool ." -> "SUBDIRS = ."; atasmart.strpool.c: atasmart.c 规则 -> @echo "using bundled atasmart.strpool.c"
```

**验证**:
```
打补丁前 make 日志含 "make -C strpool strpool; CC strpool.o"(host 构建无害,交叉必挂);打补丁后 make 跳过 strpool 且 atasmart.strpool.c 用捆绑版,产物 libatasmart.so.4.0.5 照常生成;patch -p1 回环验证 Makefile.in 一致。
```
