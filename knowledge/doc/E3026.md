# E3026: 第三方库（gtk/3.24.38 自建 gettext shim）以默认可见性重复导出 g_libintl_*，劫持 libglib 的跨库符号绑定并重入 g_once → 首次译文查找永久 futex 死锁（同时掩盖下游漏链 libintl）

## 基本信息
- **严重度**: 3
- **类别**: ohos, linking, runtime
- **作者**: 232
- **来源 PR**: fix/gtk-3.24.38.1, fix/gtk-3.24.43.1

## 错误特征
```
ld\.lld: error: undefined reference due to --no-allow-shlib-undefined: g_libintl_bindtextdomain|ld\.lld: error: undefined reference due to --no-allow-shlib-undefined: g_libintl_bind_textdomain_codeset|g_libintl_gettext.*libgtk-3\.so
```

## 根因分析
libglib-2.0.so 的 g_libintl_* 是未定义符号（由 glib 包 vendored proxy-libintl 的共享 libintl.so.8 提供）；gtk/3.24.38 配方额外自建 gettext shim 并以默认可见性导出同名符号进 libgtk-3.so，动态链接器按装载顺序（libgtk-3.so → libglib-2.0.so → libintl.so.8）把 libglib 的未定义引用绑到 libgtk 的重复定义；该 shim 回调 glib_gettext/g_dgettext 时，glib 的 gettext 一次性初始化（_g_dgettext_should_translate 的 g_once）仍在进行且仅一个线程 → g_cond_wait 永久等待（musl futex、timeout=NULL）。同一 shim 还掩盖了 libgsf-1.so 漏链 libintl（.dynsym 含 U g_libintl_* 但未进 DT_NEEDED）的链接期缺陷

## 推荐方案
**方法**: link-shared-libintl

**说明**: 首选工程解：让引用 g_libintl_* 的库/可执行文件链接共享 libintl.so（绝对路径 + -Wl,--no-as-needed 保证进 DT_NEEDED），不要自行再定义这些符号。注：该手段同类做法已由 DRAFT-autoreconf-bootstrap-intltool-prefix-and-gtk-lintl 第④坑（“glib 的 g_libintl_* 要单独补 -lintl”）记录，本条不主张为新方案，仅作为工程首选

**修复命令**:
```
-Wl,--no-as-needed <glib 包>/lib/libintl.so
```

**验证**:
```
llvm-nm -D --defined-only <libgtk-3.so> | grep -c g_libintl_   # 期望 0（脏包 7）；llvm-nm -D --defined-only <glib>/lib/libintl.so | grep -c g_libintl_   # 期望 9；探针：只链 libgtk-3 + 一次 g_dgettext，20s 超时
```
