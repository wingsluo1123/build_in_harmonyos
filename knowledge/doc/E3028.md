# E3028: 共享库补丁级 bump 时 soname 未必变，须从上游 ABI 版本变量重算而非按版本号推断

## 基本信息
- **严重度**: 3
- **类别**: ohos, cmake, linking, abi, c
- **作者**: EXPAT
- **来源 PR**: 14453

## 错误特征
```
SONAME|libexpat.so.1|LIBCURRENT|LIBREVISION|LIBAGE|DT_NEEDED|undefined symbol|Error loading shared library
```

## 根因分析
expat 的 soname 由 CMakeLists 的 LIBCURRENT - LIBAGE 派生（13-12=1）。2.8.4→2.8.5 只递增 LIBREVISION(4→5)（libtool -version-info 的 revision 位，不参与 soname），故 soname 恒为 libexpat.so.1、二进制兼容。若 bump 时按版本号字符串推断「版本变了 soname 就变」，会误改 soname 处理或盲目抬下游钉版重链；反之若真 bump 了 LIBCURRENT/LIBAGE 却未察觉，则把不兼容的替换当补丁级发出去。

## 推荐方案
**方法**: recompute-soname-from-upstream-abi-version-vars

**说明**: bump 共享库时不要从版本号字符串推断 soname，而是从上游 ABI 版本变量重算：CMake 工程 soname 版本 = LIBCURRENT - LIBAGE；autotools 工程 = current - age（来自 configure.ac 的 -version-info current:revision:age）。与旧版对比，仅 (current-age) 变化才需动配方 soname 处理或下游钉版；仅 revision/LIBREVISION 变化属兼容补丁级替换。

**修复命令**:
```
grep -nE "set\(LIB(CURRENT|REVISION|AGE)" <src>/expat/CMakeLists.txt；readelf -d 产物核 soname；对比新旧 (current-age)。
```

**验证**:
```
grep -nE "set\(LIB(CURRENT|REVISION|AGE)" <src>/expat/CMakeLists.txt && readelf -d <pkg>/lib/libexpat.so | grep -i soname
```
