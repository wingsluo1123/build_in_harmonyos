# E3032: 无界 `while printf` 管线 fixture 依赖写端进程自身死于 SIGPIPE 才能终止；OHOS /bin/sh（toybox）无 printf 内建导致每轮 fork 外部写端、循环永不终结——应改有限输出生产者（或内建写端 shell）

## 基本信息
- **严重度**: blocking
- **类别**: platform, portability, libc, posix
- **作者**: why6666666

## 错误特征
```
panic: test timed out after .*m0s|os/exec \(\*Cmd\)\.awaitGoroutines|test binary.*hang|conan create failed
```

## 根因分析
`无界生产者 | head -c N` 形态的测试 fixture 在 POSIX 系统上能终止，是因为主流 /bin/sh（bash/dash/mksh）把 printf/echo 作为内建命令执行——循环进程自己就是写端，head 退出后内建写端死于 SIGPIPE，`while` 循环随之终结。OHOS 的 /bin/sh 是 toybox 且无 printf 内建（`sh -c 'type printf'` 输出 "printf is an alias for printf"，指向外部 applet），每轮循环 fork 一个新的外部写端进程；单个写端进程死于 SIGPIPE 不会终止 `while :` 循环，写端无界再生 → 管线永不达到 EOF → 消费方的 cmd.Wait()（os/exec）永不见管道关闭 → go test 默认 10 分钟超时 panic。有界控制探针证实同设备简单管线的 EPIPE/SIGPIPE 投递本身正常（bash 内建写端循环、登录 shell 建管的外部 seq、toybox sh -c 建管的 seq 在读端退出后全部同秒终结；toybox sh 裸 echo 循环因内建执行也同秒终结，而 /bin/echo、/bin/printf 外部循环同样挂死）——决定变量是写端在循环进程内（内建）还是每次 fork 外部 applet，不是内核级 EPIPE 缺失。实测存在两种挂死形态：fork 再生 spin，以及写端阻塞在 write()（D 态、TERM/timeout 免疫，活体残留可存活数小时）；两种形态的确切切换条件（内核满缓冲写与读端可见性的交互、toybox sh 管线 fd 布线）尚未完全定性——作为 open point 如实记录，不得写成已证实的内核级结论。

## 推荐方案
**方法**: 有限输出生产者重写 fixture

**说明**: 用 dd/seq 等有限生产者产出等量字节，彻底消除对"SIGPIPE 杀死写端进程"的终止依赖；不触碰消费方断言，POSIX 与 OHOS 双侧语义保持，且可上游提交（对齐 P005）。

**修复命令**:
```
dd if=/dev/zero bs=$(( 2 << 20 )) count=1
```

**验证**:
```
全部命令在设备新 shell 直接可跑，逐条有界 ≤6s。P1 对照（timeout/KILL 机制正常）: timeout -s KILL 5 bash -c 'while :; do :; done'（耗整 5s 被杀）。P2 内建写端（EPIPE/SIGPIPE 投递正常）: timeout -s KILL 5 bash -c 'while :; do echo xxxxxxxxxx; done' | head -c 10（同秒完成）。P3 登录 shell 建管外部写端: timeout -s KILL 5 sh -c 'seq 1 2000000' | head -c 10（同秒完成，无残留）。P4 toybox sh 建管外部写端: timeout -s KILL 5 sh -c 'seq 1 2000000 | head -c 10'（同秒完成，无残留）。P2-P4 后建议 ps -ef | grep -E 'seq|while :' 复核无残留。P5 机理复现（危险，必须 KILL 包裹）: timeout -s KILL 5 sh -c 'while :; do printf x; done | head -c 10'（挂满 5s 被 KILL = 复现；timeout 只杀顶层 sh，while 子壳/printf 子进程会残留且对 TERM 免疫——事后必须 kill -9 清理全部残留并 ps -ef | grep -E 'printf x|while :' 复核清零）
```
