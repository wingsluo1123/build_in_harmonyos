# E3041: cargo 内置 autotools C 子构建（如 tikv-jemalloc-sys）config.sub 不识 ohos：ac_cv_* 预置跳过，免改上游

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, autotools, cargo, config.sub
- **作者**: OpenDesk

## 错误特征
```
"Invalid configuration `aarch64-unknown-linux-ohos': OS `ohos' not recognized|build-aux/config.sub aarch64-unknown-linux-ohos failed|configure: error: .*config.sub.* failed"
```

## 根因分析
Rust crate 的 C 依赖（如 jemalloc）在 build.rs 里就地跑 autotools configure；其 bundle 的 config.sub 早于 ohos、无法规范化 aarch64-unknown-linux-ohos。与原生 autotools 包不同，cargo-vendored crate 位于 $CARGO_HOME/registry 且每次构建重新解压，无法（也不应）patch config.sub——E007/E205/E268 的"打补丁/换基线"方案在此失效。

## 推荐方案
**方法**: preseed-autoconf-canonical-triplet

**说明**: 在 cargo 构建环境导出 ac_cv_build/ac_cv_host/ac_cv_target=<目标三元组的 -musl 变体>，autoconf 命中缓存即跳过 config.sub；OHOS 即 musl Linux，host_os 仍匹配 jemalloc 的 linux* 分支。零源码修改。

**修复命令**:
```
export ac_cv_build=aarch64-unknown-linux-musl ac_cv_host=aarch64-unknown-linux-musl ac_cv_target=aarch64-unknown-linux-musl && cargo build --release --locked --target aarch64-unknown-linux-ohos
```

**验证**:
```
env ac_cv_build=aarch64-unknown-linux-musl ac_cv_host=aarch64-unknown-linux-musl ac_cv_target=aarch64-unknown-linux-musl CC=<ohos-clang> sh ./configure --host=aarch64-unknown-linux-ohos --build=aarch64-unknown-linux-ohos --disable-cxx --enable-shared=no ; echo rc=$?  → 不再报 config.sub failed（未预置时 rc≠0 且打印 OS `ohos' not recognized）
```
