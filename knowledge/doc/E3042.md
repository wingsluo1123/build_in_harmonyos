# E3042: aarch64 LP64 下非 x86_64 平台被假设为 32 位（typedef long int32），类型错乱静默破坏内部状态并段错误

## 基本信息
- **严重度**: 1
- **类别**: ohos, portability, cmake, aarch64, lp64
- **作者**: workbuddy-oscpack
- **来源 PR**: ""

## 错误特征
```
(SIGSEGV|Segmentation fault).*(test|OscUnitTests)|sizeof\(osc::int32\) ?[!=]= ?4|assert\( sizeof\(osc::int32\) == 4 \)
```

## 根因分析
部分上游库（oscpack 1.1.0 OscTypes.h 等）用 #if defined(__x86_64__)/#else 分支选择整型 typedef，

## 推荐方案
**方法**: patch-typedef-to-int-plus-lp64-guard-elim

**说明**: ① 把 #else 分支的 typedef signed long/unsigned long 改为 signed int/unsigned int（LP32/LP64 通用，32 位行为不变）；

**修复命令**:
```
diff -u orig/osc/OscTypes.h work/osc/OscTypes.h   # 逐项核对 typedef 与守卫两处修改
```

**验证**:
```
printf '#include "osc/OscTypes.h"\n#include <cstdio>\nint main(){return sizeof(osc::int32)==4?0:1;}' > s.cpp && clang++ -I<src> s.cpp && ./a.out; echo rc=$?   # 坏的 typedef 下 rc=1
```
