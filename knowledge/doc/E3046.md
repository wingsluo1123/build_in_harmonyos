# E3046: Imake 遗产 X11 库在 OHOS(无 imake/xmkmf 工具链)下的适配——优先走发行快照自带的 Makefile.std 直编,把 Imake 的 -I/-L 解析替换为 Conan 依赖注入,不引入 imake 工具链假设

## 基本信息
- **严重度**: 2
- **类别**: compat, build-system, make, configure, toolchain
- **作者**: weijiapan

## 错误特征
```
imake: command not found|xmkmf: command not found|make: \*\*\* No targets specified and no makefile found|No rule to make target 'Makefile'
```

## 根因分析
OHOS SDK native 工具链(clang/llvm)不含 imake/xmkmf,CI 亦如是、制品仓无对应 tool_requires;而 1990s-2000s 的 X11 包以 Imakefile(+X11/Imake.rules)为唯一构建描述,Makefile 由 imake 现场生成——工具缺失时源码树里根本没有 Makefile,`make` 直接"No targets specified and no makefile found"。叠加因素:这批包上游多已停更(样例 xli 官网 2006 年后下线,HTTP 404),只能取发行快照。

## 推荐方案
**方法**: imake-snapshot-with-bundled-makefile-std-fallback

**说明**: ①取官方发行快照(源站已死则用发行版 fork 保存的原始 tarball,sha256 固定,见样例 conandata.yml);②源码自带 Makefile.std 时以其为构建入口——把 Imake 的 INCLUDES/LIBS 解析替换为 Conan 依赖注入(展开 self.dependencies 的 cpp_info 头/库路径与库名,样例见 conanfile.py 的 _dependency_flags);③用编译期最小定向修复补齐 musl 缺口(见 DRAFT-xli-1.17.0-ohos-musl-missing-rindex-bsd-legacy),不启用上游 -DSYSV 总开关;④不引入 imake/xmkmf 的 tool_requires(环境内不存在,只会把失败点后移)。

**修复命令**:
```
make -f Makefile.std CC=clang CFLAGS="-I<dep>/include ... -Drindex=strrchr" LIBS="-L<dep>/lib -lX11 -lXext ..."
```

**验证**:
```
①`command -v imake xmkmf` 皆空(实测 OHOS worker 上 MISSING);②`python3 detect_imake_legacy.py --src <src>` 命中 Imakefile 并列出回退构建文件;③样例库 `conan create archives/x/xli/1.17.0-20061110 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64` 全绿(含 test_package 消费者用例)。
```
