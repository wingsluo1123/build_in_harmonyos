# E3049: Qt 6.11 testlib 中 qCritical 按 qFatal 执行 → KF5(2023) 测试套件 qCritical 错误路径整二进制 SIGABRT

## 基本信息
- **严重度**: 2
- **类别**: platform, compat
- **作者**: unknown
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/13869

## 错误特征
```
SIGABRT.*qFatal|Aborted.*qtestcase|qCritical.*fatal
```

## 根因分析
KWayland 5.116（2023）测试在错误处理路径写 qCritical（按旧 Qt 非致命行为假设）；Qt 6.11（2025）testlib 将其路由为致命——qtbase 6.11.1.2 源码 qtestcase.cpp:2599 实证，qtestlog.cpp messageHandler 的 isWarnOrWorse 含 QtCriticalMsg → 测试二进制 SIGABRT（实测实例：testWaylandSeat testPointerSwipeGesture(end)、testPointerConstraints testLockPointer(persistent)，均确定 2/2）

## 推荐方案
**方法**: pre-exclude-qcritical-path-tests

**说明**: 诊断特征 = SIGABRT + 日志含 qtestcase.cpp 帧 → 定性为"Qt 6.11 testlib 行为变化（qCritical→qFatal）"，不是被适配库缺陷；grep 枚举源码中 qCritical 调用点，按测试二进制逐个排除并在 notes 逐项记录触发点

**修复命令**:
```
ctest --output-on-failure 捕获 abort 帧；grep -rn "qCritical" <源码>/tests/  # 枚举风险点
```

**验证**:
```
grep -n "qFatal\|qCritical" <qtbase 源码>/src/testlib/qtestcase.cpp  # 核对目标 Qt 版本的 qCritical 行为
```
