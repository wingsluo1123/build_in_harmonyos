# E3056: 上游测试目标的假通过：cc/cpp/Makefile 的 test 用 ";" 串联 cmp，比对失败仍返回 0；配方必须在 build() 内重新逐项比较并 raise，并用负测试证明其真会失败

## 基本信息
- **严重度**: 2
- **类别**: conan, testing
- **作者**: Yunan0718
- **来源 PR**: 14348

## 错误特征
```
上游测试目标返回 0 但用例实际失败（假通过）
```

## 根因分析
pcc 的 cc/cpp/Makefile.in 里 test 目标以 `;` 串联每个比较（./cpp < tests/testN > tests/runN && cmp tests/runN tests/resN && echo），&& 只影响该条命令的显示分支，整条 for 循环的退出状态不反映任何一次 cmp 的失败，make 恒返回 0。于是「上游测试通过」在退出码意义上毫无信息量：破坏 res5 后期望输出与产物不一致，make 仍返回 0。适配方必须在 build() 里复现上游的调用（原样跑上游目标以保留上游语义），再自行对 runN/runN C 与 resN/resN C 逐项比较，不一致即 raise，才让结果可判定；并用「故意破坏一个期望输出」的负测试证明该判定真会失败。

## 推荐方案
**方法**: re-compare-and-raise-in-recipe

**说明**: build() 中先原样执行上游 test 目标，再按上游同一套输入/期望输出逐项比较并 raise；同时用「故意破坏一个期望输出」的负测试证明该判定真的会失败

**修复命令**:
```
make -C cc/cpp test; python3 -c "逐项比较 runN vs resN，不一致则 exit 1"
```

**验证**:
```
破坏 res5 后 make -C cc/cpp test → rc=0（假通过）；配方内独立逐项比较 → 报 test5: output differs from res5 并 raise ConanException
```
