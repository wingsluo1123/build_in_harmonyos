# E3057: 可变目标编译器没有宿主架构后端时，应按「宿主编译器 + 显式 --target=<异构架构>」交付；host 三元组必须交给 config.guess 原生识别，绝不能传 --host

## 基本信息
- **严重度**: 2
- **类别**: portability, retargetable-compiler
- **作者**: Yunan0718
- **来源 PR**: 14348

## 错误特征
```
'$target' is not (yet) supported by pcc
```

## 根因分析
pcc 的 arch/ 下 16 个后端（amd64、arm32、hppa、i386、i86、m16c、m68k、mips、mips64、nova、pdp10、pdp11、pdp7、powerpc、sparc64、vax）不含 aarch64，configure.ac 在无法把 target CPU 映射到后端时直接 AC_MSG_ERROR 报 "'$target' is not (yet) supported by pcc"。这类工具「能生成哪种机器码」与「自身在哪种 CPU 上运行」是两件事：把它当作在鸿蒙 PC（aarch64）上运行的宿主编译器交付、显式指定 --target=amd64-linux 才是产品定义，而不是平台探测绕过。同时 host 若不交给 config.guess 原生识别（即手传 --host=aarch64-unknown-linux-ohos），configure 会进入交叉分支，把 CC_FOR_BUILD 解析成宿主机自带的 cc/gcc（鸿蒙上并不存在），构建期生成器（pcc 的 mkext）随即失败，需要额外 chmod + 显式传 CC_FOR_BUILD 才能补救。

## 推荐方案
**方法**: host-native-tool-plus-explicit-foreign-target

**说明**: 配方里只加 --target=<需要的异构目标>，从不传 --host；让补好的 config.guess 原生解析 host 三元组

**修复命令**:
```
./configure --target=amd64-linux   # 不传 --host；host 由 config.guess 解析为 aarch64-unknown-linux-ohos
```

**验证**:
```
pcc 实测（默认 target 时）：configure 报 "'$target' is not (yet) supported by pcc"；显式 --target=amd64-linux 后 configure 输出：checking build system type... aarch64-unknown-linux-ohos / checking host system type... aarch64-unknown-linux-ohos / checking target system type... x86_64-pc-linux-gnu，构建通过
```
