# E3058: 官方 scripts/patch-autotools-ohos.pl 对 2014/2015 版 autotools 文件会「exit 0 但完全不生效」：它插入的 config.guess 块只赋值 GUESS、缺 echo+exit，而老版 config.guess 每个分支必须自带 echo+exit

## 基本信息
- **严重度**: 2
- **类别**: autotools, tooling
- **作者**: Yunan0718
- **来源 PR**: 14348

## 错误特征
```
unable to guess system type|machine 'aarch64-unknown-linux' not recognized（脚本 exit 0 但补丁完全未生效）
```

## 根因分析
官方补丁脚本按新版 autotools 的 config.guess 结构编写：新版的系统识别块只负责赋值 GUESS（由外层统一 echo/exit），而 2014/2015 版 config.guess 的每个 case 分支必须自己 echo 三元组并 exit（文件末尾是「unable to guess system type」错误块）。脚本把「只赋值 GUESS」的块插进老文件后，控制流在该分支既不输出也不退出，直接落到错误块；config.sub 的锚点（android-linux / linux-uclibc 等）在老文件中也不存在，于是三处修改全部不命中。结果 perl 脚本退出码为 0、看起来成功，实际一个改动都没落地——pcc 实测只命中 1/5。这是对既有 E007（「用该脚本一键打补丁」）的静默失效修正。

## 推荐方案
**方法**: manual-minimal-rewrite-in-file-style

**说明**: 不要信任该脚本的退出码；先跑 sh ./config.guess 复测是否真的能识别 HarmonyOS，失败则按目标文件自身的分支风格手工最小改写（老版每个分支自带 echo + exit）

**修复命令**:
```
sh ./config.guess; sh ./config.sub aarch64-unknown-linux-ohos   # 补丁前后各跑一次，用输出而非退出码判断
```

**验证**:
```
sh ./config.guess（补丁前）→ rc=1 且报 unable to guess system type；sh ./config.sub aarch64-unknown-linux-ohos（补丁前）→ 报 machine 'aarch64-unknown-linux' not recognized；perl patch-autotools-ohos.pl 后复测结果不变（说明脚本未生效）
```
