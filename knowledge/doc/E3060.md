# E3060: OHOS 上 Conan 构建 Autotools 工具依赖时的 HMDFS 临时目录失败

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, ohos, build-system, autotools, conan
- **作者**: iKalous_OscarP
- **来源 PR**: 13882

## 错误特征
```
config.guess.*unable to guess|config.status.*setup config files machinery|subs1.awk: Permission denied|C compiler cannot create executables|No rule to make target 'check'
```

## 根因分析
Conan 对 m4 等 tool_requires 仅找到 recipe 时会从源码构建；依赖 configure/config.status 在 HMDFS 临时目录中创建后写文件被拒。profile 已提供的 Harmonybrew Autotools 工具可避免这条失败依赖链，但仍需 AutotoolsToolchain 显式传递编译器。

## 推荐方案
**方法**: use-profile-harmonybrew-autotools

**说明**: 确认 profile PATH 已含受控 m4/autoconf/automake/libtoolize 后直接运行 autoreconf；按 E205 用随配方导出的 patch-autotools-ohos.pl 更新 config.guess/config.sub，使设备识别 HarmonyOS；使用 AutotoolsToolchain.generate() 显式映射 clang，不以 --build/--host 绕过系统识别。

**修复命令**:
```
command -v m4 autoconf automake libtoolize && conan create archives/p/puredata/0.56.5 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```

**验证**:
```
CONAN_HOME=~/work/psj/ch-pd9812 conan create archives/p/puredata/0.56.5 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```
