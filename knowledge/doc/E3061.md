# E3061: 已发布版本的适配修复重出（dot-revision）须恢复基础配方曾有的平台修复，否则回归

## 基本信息
- **严重度**: 3
- **类别**: ohos, meson, security, abi, c
- **作者**: FONTCONFIG
- **来源 PR**: 14466

## 错误特征
```
dlopen.*Permission denied|Permission denied.*\.so|Error loading shared library|DT_NEEDED.*/storage/.*/lib(expat|fontconfig)\.so|DT_NEEDED.*\.conan2/p/.*\.so
```

## 根因分析
对已发布上游版本创建适配修复修订（X.Y.Z → X.Y.Z.n）时，若以更简的上游基础配方（如 fontconfig/2.18.3）覆盖，会丢掉此前 dot-revision（fontconfig/2.18.1.1）确立的两项平台修复：(1) package() 后重签共享库——meson install 重写 rpath 会改动链接后的 .so，使链接器自签失效，OHOS XPM dlopen 报 Permission denied；(2) 显式 -Dxml-backend=expat + 用有 SONAME 的 expat——否则 meson 自动探测到系统 expat，链接期把其绝对路径写入本包 DT_NEEDED，产物不可重定位（换 worker / 清 cache 后加载失败）。此外 2.18.3 build() 以 os.environ 硬编码 AR/PATH（R33 违规）、缺 cache-build=disabled（构建期误跑 aarch64 fc-cache）。

## 推荐方案
**方法**: dot-revision-diff-against-prior-revision-recipe

**说明**: 重出修订时不要从上游同版本基础配方直接复制，而应以“最近一次通过验证的 dot-revision”为基线（本例 fontconfig/2.18.1.1），逐条比对并保留平台修复：package() 后重签 .so、显式 XML 后端 + 有 SONAME 的后端库、native file 注入 ar/ranlib、关闭 doc/nls/tests/cache-build；并按包级 commands.json 的交付形态决定是否绑定 bindirs/构建 CLI；仅在上游源码真正变化处调整。

**修复命令**:
```
git show <prev-dot-rev>:…/conanfile.py 与基础版本 diff；readelf -d 比 DT_NEEDED；binary-sign-tool 重签后 dlopen 冒烟。
```

**验证**:
```
readelf -d "<pkg>/lib/libfontconfig.so" | grep NEEDED 应全为 SONAME（libexpat.so.1/libfreetype.so.6/libc.so），不含 /…/.conan2/p/… 或 /storage/… 绝对路径；OHOS 侧 dlopen libfontconfig.so 不应报 Permission denied。
```
