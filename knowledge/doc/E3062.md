# E3062: Self-bootstrapping a Python C-extension package from an sdist that ships no generated C

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, linking, python, conan
- **作者**: unknown

## 错误特征
```
no such file or directory.*\.c|Permission denied.*\.so|ImportError: Error loading shared library
```

## 根因分析
Cython 3.3.0 is self-bootstrapping: setup.py's compiled_modules reference .pyx sources, but the PyPI sdist deliberately ships no pre-generated .c (only wheels do), so build_ext fails looking for Cython/Plex/Actions.c etc. The fix is not to skip compilation (NO_CYTHON_COMPILE=true degrades the package to a slow pure-Python build) but to exploit the fact that Cython's pure-Python form can itself compile .pyx: putting the unbuilt tree on PYTHONPATH makes "from Cython.Compiler.Main import compile" work and transpile .pyx to .c, after which clang produces the .so. Separately, every produced .so is a foreign ELF that OHOS dlopen refuses unless signed, and conan's copy() invalidates an existing signature, so signing must happen after the final file placement.

## 推荐方案
**方法**: pure-python-selfboot-then-sign-after-copy

**说明**: In build(): set PYTHONPATH to the source tree and run "<conan-python> setup.py build_ext --inplace" so the pure-Python Cython transpiles its own .pyx to .c and clang links them; sign every .so immediately after (so upstream tests can dlopen them); then sign the tree AGAIN in package() after copytree, because copy() breaks the signature. Ship the CLI entry points (cython/cythonize/cygdb) to bin/ with a rewritten shebang pointing at the conan python interpreter, and provide a software-level commands.json (R38/L0k).

**修复命令**:
```
PYTHONPATH=<src> <conan-python> setup.py build_ext --inplace
```

**验证**:
```
conan create archives/c/cython/3.3.0 --build=missing && python3 archives/c/cython/3.3.0/test_package/test_cython.py <pkg>
```
