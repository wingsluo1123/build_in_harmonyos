# E3065: OpenGL-Registry main 快照已不含 api/KHR/khrplatform.h，但所有 GL/GLES/GLSC 头均 #include <KHR/khrplatform.h>；打包 Khronos 头文件时须随包 vendor 官方 khrplatform.h（EGL-Registry, MIT）

## 基本信息
- **严重度**: 2
- **类别**: headers, conan, dependency, packaging, khronos
- **作者**: unknown

## 错误特征
```
".*'KHR/khrplatform.h' file not found|fatal error: 'GL/glx.h' file not found"
```

## 根因分析
OpenGL-Registry 主分支快照（2026 年中后内容）不再包含 api/KHR/khrplatform.h（raw 404 证实），而 api/GL/glcorearb.h:63、api/GL/glext.h:37、api/GLES/gl.h:34、api/GLES2/gl2.h:42、api/GLES3/gl3.h:42 等全部 #include <KHR/khrplatform.h>（khrplatform.h 定义 KHRONOS_APICALL/KHRONOS_APIENTRY 与 khronos_int*_t 等平台抽象类型，由 EGL-Registry 仓库 api/KHR/khrplatform.h 维护, MIT）。直接打包上游 tarball 的头文件时，消费者 include 任一 GL 头即 include 解析失败。khronos 头-头依赖链要求头文件包自包含。

## 推荐方案
**方法**: vendor-official-khrplatform-in-header-package

**说明**: 不改上游头文件。在配方 patches/ 增加 git 补丁（0001-add-khrplatform.h.patch）将 EGL-Registry 官方 api/KHR/khrplatform.h（MIT, 11131 字节）以新文件引入源码 api/KHR/，package() 复制整棵 api/ 树到 include/, 使 include/KHR/khrplatform.h 随包分发。conandata.yml 的 sources.url 仍保留官方 github URL（不写镜像, E017 仅用于本地下载提速）。

**修复命令**:
```
"conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64   # 含消费者/test_package 验证"
```

**验证**:
```
curl -sS -L 'https://ghfast.top/https://raw.githubusercontent.com/KhronosGroup/OpenGL-Registry/main/api/KHR/khrplatform.h' -o /dev/null -w '%{http_code}'   # 404
```
