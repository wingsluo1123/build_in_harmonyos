# E3069: autotools 包的上游测试是内核/资源依赖的实时用例、且上游未注册 TESTS= 时，make check 静默零执行——适配须显式驱动，并对不可执行项逐条标记而非删用例/缩分母

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, autotools, security, c
- **作者**: LIBSCTP
- **来源 PR**: 14514

## 错误特征
```
cannot guess build type|OS 'ohos' not recognized|make check.*(nothing to be done|Nothing to be done)|No rule to make target 'check'
```

## 根因分析
autotools 工程若把测试程序写成 noinst_PROGRAMS（而非 check_PROGRAMS/TESTS=），`make check` 不含任何测试目标，会「成功但零执行」，给出虚假的绿色；其真正驱动是上游自定义目标（如 lksctp-tools 的 src/func_tests `v4test`/`v6test`）。这些用例又常是**内核实时（live-kernel）**用例——每条都要 socket(AF_INET, SOCK_STREAM, IPPROTO_SCTP) 起真实关联，依赖内核启用对应协议。CI worker 内核通常未启用该协议，直接实跑会全 FAIL；错误归因成「用例不通过」会误导评审，静默删用例/缩分母则违反规则 4。此外同源平台坑：随包 bin/config.guess 版本过老（2015）在 HarmonyOS 上 `uname -s=HarmonyOS` → cannot guess build type；随包 config.sub 不认 linux-ohos。

## 推荐方案
**方法**: explicit-driver-plus-resource-probe-and-per-case-marking

**说明**: (a) E007 双保险：既打归档自带 config.guess(HarmonyOS 分支)+config.sub(linux-ohos) 补丁，又在 generate() 显式传 --build=<arch>-unknown-linux-gnu、--host=<arch>-unknown-linux-ohos（build 侧 gnu、host 侧 ohos；两侧都写 ohos 会被 config.sub 误判）；不依赖 CI worker 上取不到的 framework patch-autotools-ohos.pl。(b) 测试：--enable-tests 全量编译测试程序，先用上游自带资源探针（checksctp）判定外部资源是否可用；可用则逐条实跑并汇总通过/失败；不可用则逐条标记「资源未执行（附技术原因）」，不删用例、不缩分母。(c) 消费者侧另立确定性断言：选库内**纯用户态** API（如 sctp_getaddrlen，addrs.c 按地址族返回 sizeof，不碰 socket/内核）在 test_package 直接链接调用，验证头闭包+链接+运行期可加载（签名有效）。

**修复命令**:
```
grep -rn '^TESTS\|noinst_PROGRAMS\|check_PROGRAMS' */Makefile.am；./src/withsctp/checksctp；依次 ./src/func_tests/<case>
```

**验证**:
```
(1) grep '^TESTS' */Makefile.am 为空 && grep noinst_PROGRAMS 命中 → 确认 make check 静默；(2) 跑上游探针（如 checksctp）判定资源是否可用；(3) 库侧消费者断言：链接 -lsctp 调用 sctp_getaddrlen(AF_INET)==sizeof(struct sockaddr_in) 应 exit 0。
```
