# E3074: libsoup2（libsoup-2.4）发布二进制静态内嵌 glib2 的 gobject，与共享 glib/2.84 并存 → 双 GObject，实例化 GObject 子类（RestProxy 等）即 SIGABRT；改依赖共享 glib 并以独立版本号重发

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, runtime, dual-glib, glib
- **作者**: 2301_76770579
- **来源 PR**: 14411

## 错误特征
```
g_param_spec_pool_lookup: assertion 'pool != NULL' failed|
```

## 根因分析
已发布的 libsoup/2.74.3 依赖 glib2/2.88.0（该 conan 包默认 shared=False，仅发布静态库），把 gobject 静态链入 libsoup-2.4.so.1（DT_NEEDED 无 libglib-2.0.so.0/libgobject-2.0.so.0，本体导出 4113 个 g_* 定义符号，含 g_type_register_fundamental 强定义）。当依赖图里同时还存在共享 glib/2.84.0.1.1（librest/json-glib 链 NEEDED libgobject-2.0.so.0）时，两份 GObject 类型系统在同一进程各自初始化，池化类型查找失败 → "g_param_spec_pool_lookup: assertion 'pool != NULL' failed" → SIGABRT。触发点是需要实例化 GObject 子类的用例（如 librest 的 RestProxy/RestProxyCall），纯数据用例（xml/params）不崩，易被误判为"测试本身有问题"。

## 推荐方案
**方法**: recipe-level-link-shared-glib-republish-as-new-version

**说明**: 配方级修复（同 libsoup3/3.6.5-r3）：requirements() 用 glib/2.84.0.1.1（options={"shared": True}，transitive_headers/transitive_libs=True）替代 glib2/2.88.0，使 libsoup-2.4.so.1 链接共享 libgobject-2.0.so.0，与消费者链共用同一份共享 glib（单 GObject 副本）。因 cnb.cool 制品仓不允许同一 name/version 并存两个 recipe revision（R37），已发布的 2.74.3 不能原地改，改以独立版本号 libsoup/2.74.3-r1 重发（命名法同平台 libsoup3/3.6.5-r1..r3）。generate() 用官方 glib-2.0.pc 覆盖 PkgConfigDeps 简化版补 -lintl，并把 glib 工具 pin 到 meson [binaries]；package_info() 暴露 glib 的 include/libdirs。取证：修复版 nm -D 的 g_* 定义符号数应 = 0，NEEDED 含 libglib-2.0.so.0。

**修复命令**:
```
conan create archives/l/libsoup/2.74.3-r1 -pr:h=ci/conan/profiles/ohos-aarch64 --build=missing; nm -D <pkg>/lib/libsoup-2.4.so.1 | grep -cE " T (g_|_g_value)"
```

**验证**:
```
nm -D libsoup-2.4.so.1 | grep -cE " T (g_|_g_value)"; readelf -d libsoup-2.4.so.1 | grep NEEDED
```
