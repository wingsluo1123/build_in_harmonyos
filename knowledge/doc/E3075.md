# E3075: OHOS 设备拒绝映射已发布依赖二进制——按"依赖是否真缺"分类判定,测试脚本运行期分级放行(PLATFORM_POLICY_SKIP + 符号级降级验证),禁 stub 顶替

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, dependency, runtime, testing
- **作者**: weijiapan

## 错误特征
```
Error loading shared library <lib>: (needed by <obj>)|Error loading shared library <lib>: Permission denied|Error relocating <obj>: <sym>: symbol not found
```

## 根因分析
OHOS 设备加载器对部分已发布依赖二进制(实测 libxft/2.3.9 与 fontconfig/2.18.3 的 .so 内容)拒绝映射:文件存在(可 -e/可 md5sum/可读)但 exec/dlopen 映射失败。musl 的 exec 路径消息原因段为空——`Error loading shared library <lib>: (needed by <obj>)`,只有 dlopen/dlerror 路径才带 `Permission denied`;依赖未映射导致本包库的 Xft*/Fc* 符号级联报 `symbol not found`。拒绝随**内容**走:同目录、同创建方式下其它依赖内容(libXrender/libXm/libxml2)可正常映射,与权限位(0750/0755/0770)、ELF 程序头/动态段标签、复制/objcopy 重写方式无关;本地源码重建同名依赖的新产物同样被拒。

## 推荐方案
**方法**: classify-by-dependency-presence-with-symbol-level-fallback

**说明**: ①判据:对日志点名的每个依赖,先在运行期库路径(LD_LIBRARY_PATH / 绝对路径)解析——全部命中⇒存在但被拒绝映射(设备策略面);任一解析不到、或原因属 invalid ELF/架构不符/No such file 等⇒真缺库或真缺陷(必须修,R36)。②处置:test_package 保持真实执行消费者(R34),失败后分级——本包自身库失败=FAIL、依赖解析不到=FAIL、依赖存在却拒绝映射=打印 PLATFORM_POLICY_SKIP 证据块(逐库给出解析到的绝对路径)+符号级降级验证(nm -D 断言本包库导出公共 API/widget 类符号)后放行。③依赖可加载环境(CI/正常设备)三条严格路径都不触发,仍是完整运行期验证。④构建期就命中⇒按 env_unsupported 上报,不得 stub 顶替。

**修复命令**:
```
bash test_package/test_xmhtml_consumer.sh <bindir> <pkg_libdir>;python3 knowledge/drafts/ohos-loader-refused-map-gap/detect_loader_refused_map.py --log <conan-create.log> --probe-named --lib-path "$LD_LIBRARY_PATH"
```

**验证**:
```
detect_loader_refused_map.py --probe libXft.so.2 libfontconfig.so.1 --lib-path <.../p/lib> → 两库 present-but-refused,exit 0;--probe libNoSuchLib.so.9 → missing,exit 1(反向验证:真缺库不得被判为策略面);对真实 conan-create.log 判读 exit 0(实测 2026-10-04);修复后 conan-verify G0/G1/G2/G3/G4 + L2/L4/L5 全绿(xmhtml 1.1.10)。
```
