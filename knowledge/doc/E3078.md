# E3078: A packaged Pd external has no link-time dependency on Pd: it exports <name>_setup and imports the whole Pd API (17 functions plus the data symbol s_) from the hosting process. A test that dlopen()s it without providing those host symbols fails on OHOS even though the artefact is perfect (musl binds every relocation eagerly), and the upstream template appends the library name to objectsdir itself, so passing objectsdir=/lib/pd-externals/log yields lib/pd-externals/log/log.

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, conan, testing, puredata
- **作者**: unknown

```
undefined symbol: logpost|dlopen failed: undefined symbol|Error relocating.*symbol not found|RPATH library not found|objectdir.*library_name|No such file or directory.*lib/pd-externals/.*/.*/|undefined symbol: main|make.*\[Makefile:[0-9]+: [a-z_]+\.\] Error 1|UNAME.*uname -s|ifeq \(\$\(UNAME\),Linux\)
```

## 根因分析
Pd externals are position-independent plugins loaded by Pd with dlopen(), not libraries linked against libpd. Verified on pd-log 0.1 / puredata 0.54.1: `readelf --dyn-syms` on each *.pd_linux shows one defined GLOBAL symbol (<name>_setup) plus 18 imports - 17 GLOBAL UND Pd functions (gensym, class_new, class_doaddfloat, class_addbang, class_addpointer, class_addanything, pd_new, logpost, atom_getfloatarg, atom_getsymbolarg, binbuf_new, binbuf_add, binbuf_gettext, binbuf_free, resizebytes, freebytes, floatinlet_new) and the data symbol s_ - and `readelf -d` shows a single NEEDED of libc.so. logpost(3) is declared in puredata's m_pd.h:579 as `EXTERN void logpost(const void *object, int level, const char *fmt, ...)`; all of them are exported by the Pd binary (pd links itself with -rdynamic), so the references are satisfied by the process-global symbol table, not by a DT_NEEDED entry. Two loader behaviours follow. (1) s_ goes through an eager R_*_GLOB_DAT relocation, so even glibc RTLD_LAZY cannot defer it - a loader without host exports always fails there. (2) The 17 functions go through R_*_JUMP_SLOT: glibc defers them under RTLD_LAZY, but OHOS musl has no lazy binding (RTLD_LAZY behaves like RTLD_NOW), so on the device every one of them must resolve at dlopen() time - CI build #73602 failed with "dlopen failed: Error relocating logpost.pd_linux: gensym: symbol not found" for all five externals of a perfectly correct package because the test binary exported nothing. Second, the stock "Pd Makefile template" derives objectsdir from prefix/lib/pd-externals and its install rule appends $(LIBRARY_NAME) itself ($(INSTALL_DIR) $(DESTDIR)$(objectsdir)/$(LIBRARY_NAME)), so a recipe must pass the *parent* (objectsdir=/lib/pd-externals) to land files in lib/pd-externals/<name>/.

## 推荐方案
**方法**: test-with-rdynamic-stub-host-and-rtld-now

**说明**: (a) In test_package, compile a small native C program for the target that plays the Pd host: it defines every Pd symbol the externals import (the 17 functions as no-op stubs plus an s_ data object - enumerate them from the artefacts with readelf, not from memory) and is linked with -rdynamic so the stubs reach the process-global symbol table, exactly like the pd binary itself. Then dlopen() each packaged *.pd_linux with RTLD_NOW and dlsym() "<name>_setup", asserting non-NULL; also assert the ELF is ELFCLASS64 and its e_machine matches the target (183 = EM_AARCH64) so a stray host build is caught. RTLD_NOW, not RTLD_LAZY: OHOS musl defers nothing anyway, and on glibc RTLD_NOW forces the same full resolution instead of hiding missing host exports behind lazy PLT slots. Pass the expected machine number in from the recipe (armv8 -> 183, x86_64 -> 62) rather than hardcoding, so the same test also works on a Linux profile. (b) Assert the packaged layout is <package>/lib/pd-externals/<name>/ so the loader path matches what Pd searches. (c) In the recipe pass objectsdir=/lib/pd-externals (the parent), never the full per-library path.

**修复命令**:
```
grep -c -- '-rdynamic -o pdlog_dlopen_test' archives/p/pd-log/0.1/test_package/conanfile.py
```

**验证**:
```
llvm-readelf --dyn-syms <pkg>/lib/pd-externals/log/debug.pd_linux | grep -E 'debug_setup|logpost|UND'
```
