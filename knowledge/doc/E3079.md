# E3079: HM-MAC (use_task) 策略在 execve 层拦截"自解包类"可执行文件——加壳产物系统性不可执行，而加壳/解包文件操作完全正常

## 基本信息
- **严重度**: 2
- **类别**: platform, runtime, testing, hm-mac, policy
- **作者**: unknown

## 错误特征
```
Process not started \.\.\. \[permission denied\]|BAD_COMMAND|rc=126|rc=127
```

## 根因分析
OHOS PC 的 HM-MAC 强制访问控制（挂载参数含 hmmac=use_task/inherit_parent）在 execve 系统调用层拦截依赖"运行时自重映射/自解包"的可执行文件：UPX 加壳产物的运行机制是 execve 后通过 /proc/self/exe 重映射原始镜像，该类 execve 被策略以 EACCES 拒绝，先于任何程序代码执行。关键鉴别特征：同一目录、同一用户、同一权限位下，未加壳的二进制 execve rc=0，加壳的二进制 Permission denied；/proc/mounts 显示所有相关挂载（/、/data/local/tmp、/storage/Users）均无 noexec——排除 noexec 假说；错误经 ctest 呈现为 BAD_COMMAND "Process not started ... [permission denied]"，手动执行为 rc=126/127。

## 推荐方案
**方法**: disable-self-exec-tests-with-evidence

**说明**: 有上游自有开关的（如 UPX 的 UPX_CONFIG_DISABLE_RUN_PACKED_TEST）用开关关闭该组测试，其余用例改硬失败模式运行（回归必须阻断打包）；无开关的在 ctest 命令行用 -E 正则排除对应用例组。两种方式都必须在 notes.md/PR 正文记录完整证据链（对照实验 + /proc/mounts + 失败签名），定性为平台边界而非测试失败，通过率按实际运行用例计 100%。

**修复命令**:
```
UPX_CONFIG_DISABLE_RUN_PACKED_TEST=True（上游自有 option，CMakeToolchain cache_variables 注入）；或 ctest -E "upx-run-packed"
```

**验证**:
```
真机对照实验（三位置 × 加壳/未加壳）：对构建产物 upx 复制三份——原样（未加壳）、upx 加壳后——分别在构建目录、用户 tmp（mode 755）、/data/local/tmp 执行：未加壳三处均 rc=0；加壳三处均 Permission denied（rc=126/127）。同时 cat /proc/mounts 确认无 noexec（设备无 findmnt，用 /proc/mounts 替代）；readelf -d 确认加壳前后 NEEDED 一致（排除动态 loader 问题）。ctest 侧签名：8 个 run-packed 用例全部 "Process not started ... [permission denied]" BAD_COMMAND。
```
