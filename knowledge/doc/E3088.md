# E3088: 让打包产物与链接器输出逐字节一致，杜绝任何链接后修改。CMake 配方：CMakeToolchain 置 CMAKE_S

## 基本信息
- **严重度**: high
- **类别**: ohos, cmake, linking, loader
- **作者**: unknown

## 错误特征
```
"Error loading shared library <path>/lib*.so: Permission denied（dlopen 失败；同一文件在 cmake --install 之前的链接器输出可正常 dlopen）"
```

## 根因分析
OHOS（musl）加载器对可 dlopen 的 ELF 做整文件内容校验（链接期记录的完整性/签名值，产物带 .note.ohos.ident/.codesign）。任何链接后的文件改动都会使校验失败，dlopen 返回 EACCES「Permission denied」。实测（kodi-pvr-iptvsimple 21.11.0，CMake MODULE）：链接器直接输出 build/Release/pvr.iptvsimple.so 可 dlopen；cmake --install 后的同名文件 dlopen 失败；两者仅差 230 字节——cmake --install 的 RPATH 改写在原地把构建期 RUNPATH 字符串清零并重写若干路径字符串。对可加载文件在任意偏移（含加载器不读取的 .debug_* 节）翻转 1 字节即复现 EACCES，把全部差异字节还原即恢复可加载——证明是整文件完整性校验而非结构/权限/rpath 语义问题。陷阱在于失败发生在 conan test_package 的 dlopen/link 阶段（不是编译期），报错文案指向主库路径，容易被误判为权限/依赖/对齐问题（互见 E077：patchelf/strip/objcopy 显式改 ELF 后签名失效，修复是重新签名；E653：NDK 产物内容级拒载）。本条的独立价值：触发者是 CMake install 的隐式 RPATH 改写（非显式改 ELF 工具），且存在构建期预防修法而非事后签名。

## 推荐方案
**方法**: 让打包产物与链接器输出逐字节一致，杜绝任何链接后修改。CMake 配方：CMakeToolchain 置 CMAKE_SKIP_RPATH=ON，链接器不植入 DT_RUNPATH，cmake --install 不再改写 ELF（安装文件与 build 产物同哈希）。若确需安装后改写 RPATH，则必须按 E077 的四步（去签名→改 ELF→重签名→chmod）处理，不能裸改。
