# E3104: 发布源码归档的版本来源不可依赖 git：无元数据→VERSION 为空（--version 输出 unknown）、构建目录恰在无关 git 仓库内→注入无关标签；打包版本注入必须优先于 git describe；可选文档工具不应成为构建硬依赖

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, cmake, conan, packaging
- **作者**: 9C4A

## 错误特征
```
--version.*unknown|VERSION.*(unknown|empty)|git describe.*fatal|not a git repository.*git describe
```

## 根因分析
上游 CMake 把 add_definitions(-DVERSION=...) 放在 execute_process(git describe) 成功的前提分支里：1) GitHub 发布 tarball 无 .git 元数据 → git describe 失败 → VERSION 宏未定义（源码 #ifndef VERSION → 打印 “unknown”）；2) 更隐蔽的反例：构建目录恰好位于某个无关 git 仓库内时 git describe 成功并返回**无关标签**——本包设备侧实测把另一项目的标签（webp-pixbuf-loader-0.2.7-src-4871-g…）注入成了 ydotool 的版本号（观测记录见 archives/y/ydotool/1.0.4/notes.md 验证结果段）。正确优先级：打包注入（-D<PKG>_VERSION，由配方从 self.version 传入）> git 元数据（仅开发态有意义）> 发布版本兜底。同源问题：可选文档工具（scdoc）被当作无条件 ALL target，工具缺失直接构建失败（应 find_program 门控）；CMake ≥4.0 移除 <3.5 policy 兼容，拒绝 cmake_minimum_required(VERSION 3.4)（用 CMAKE_POLICY_VERSION_MINIMUM=3.5 注入，E103/E187）。

## 推荐方案
**方法**: packaging-version-override-precedence

**说明**: 1) 小补丁把版本解析改为「打包覆盖（-D<PKG>_VERSION）优先 → git describe（开发态）→ 发布版本回退」，无论走到哪个分支都必须定义 VERSION；2) 配方在 generate()/toolchain 里从 self.version 注入该变量（不要在补丁里写死版本而不留覆盖入口）；3) 可选文档工具用 find_program 门控（缺 scdoc 只跳过 man 页，不失败）；4) CMake policy 由配方注入 CMAKE_POLICY_VERSION_MINIMUM（ref E103/E187）。禁止：依赖构建环境的 git 状态产生版本号。

**修复命令**:
```
cmake -S src -B build -DYDOTOOL_VERSION=1.0.4 && cmake --build build && ./build/ydotoold --version   # 期望 1.0.4
```

**验证**:
```
cmake -S <src> -B <build> -DYDOTOOL_VERSION=1.0.4（在 git 仓库目录内运行）→ ydotoold --version == 1.0.4（覆盖优先）；非仓库目录且不带覆盖 → 1.0.4（发布兜底）；带无关标签的仓库且不带覆盖 → 注入无关标签（反例证据）
```
