# E3105: 当消费者测试需要 bind 本地 socket 而平台（OHOS/E461）拒绝时：用能力探针门控协议断言 + 显式跳过计数保持测试诚实性——默认路径语义与负路径断言仍必须执行，绝不伪造接收端

## 基本信息
- **严重度**: 2
- **类别**: detection, ohos, socket, testing
- **作者**: 9C4A

## 错误特征
```
bind: Operation not permitted|Read-only file system.*socket|failed to connect socket.*No such file or directory
```

## 根因分析
平台事实（引用，不重复论证）：OHOS 上 AF_UNIX 路径名 bind 在全部可写文件系统 EPERM、/tmp 只读（E461/E024/E002/E052）。本条解决的是**测试设计问题**：daemon/client 类包的消费者测试通常需要先 bind 一个本地 socket 再驱动客户端断言字节流；在受限执行域该前置步骤必然失败，若把失败当 FAIL 则测试永远红、若静默跳过则测试失真。正确做法是把“平台是否允许 bind”显式建模为能力探针：探针成功→执行全部协议断言；探针 EPERM→记录 errno/strerror 作为平台证据，该组断言按“已跳过”单独计数并说明原因，**其余断言（CLI 契约、产物、负路径、平台边界）仍必须执行**；任何非 EPERM 的 errno 一律 FAIL。附加增量：上游默认 socket 路径（如 /tmp/.ydotool_socket）在 OHOS 不可用，需 -p/XDG_RUNTIME_DIR 指定可写路径；客户端连接失败语义（ENOENT vs ECONNREFUSED）可作为稳定的负路径断言。

## 推荐方案
**方法**: probe-gated-conditional-protocol-tests + explicit-skip-accounting

**说明**: 1) 测试内先运行“用户态对端 bind 能力探针”，把结果打印为可审计标记（如 LISTENING / BIND-FAILED errno=…）；2) 探针成功：执行全部线协议逐字节断言；3) 探针 EPERM：把该组断言登记为 skipped（打印明确计数与平台原因），进程退出码保持成功；除 EPERM/EROFS/EACCES 外的 errno 一律 FAIL（不掩盖真实缺陷）；4) 无论探针结果，CLI 契约、产物完整性、负路径（缺失/非 socket 路径的 rc 与提示）、平台边界断言都必须真实执行；5) 运行时用 -p/XDG_RUNTIME_DIR 选可写路径（默认 /tmp 路径在 OHOS 不可用）；6) 禁止：伪造 socket 接收端、把跳过计入 pass、为让测试变绿改动产品代码或注入平台宏。

**修复命令**:
```
bash test.sh  # 期望: N/N executed passed (M skipped: E024 AF_UNIX bind EPERM)
```

**验证**:
```
YDOTOOL_SOCKET="$TMPDIR/probe.sock" ydotool key 1:1; echo rc=$?   # 无 daemon: rc=2 + "Please check if ydotoold is running."；python3 -c 'import socket,os; s=socket.socket(socket.AF_UNIX,socket.SOCK_DGRAM); s.bind(os.environ["TMPDIR"]+"/p.sock")' 2>&1  # EPERM=1；探针输出 LISTENING 或 BIND-FAILED errno=1
```
