# E3110: CMake 误把 -o aslr 当 ASLR 开关，实际解释为输出目标

## 基本信息
- **严重度**: 1
- **类别**: ohos, portability, build-system, cmake, clang
- **作者**: iKalous_OscarP
- **来源 PR**: 14344

## 错误特征
```
-o[ ]+aslr|unsupported argument.*aslr|aslr.*output file
```

## 根因分析
CMake 的 add_compile_options 会把 -o aslr 原样传给 Clang；Clang 将 -o 解析为后续输出文件名选项，而不是 ASLR 开关。该参数可能改写或干扰目标文件输出，且不能替代 HarmonyOS 的 PIE 与 ELF 签名要求。

## 推荐方案
**方法**: source-patch

**说明**: 从 CMake 编译选项中移除误用的 -o <name>，只保留目标平台支持且经独立核实的编译选项；PIE 与可执行文件签名分别按平台构建和交付规则配置。

**修复命令**:
```
将 add_compile_options(... -o aslr ...) 中的 -o aslr 删除，再用 verbose 构建确认 Clang 命令中没有该输出目标参数。
```

**验证**:
```
grep -nE 'add_compile_options.*-o[[:space:]]+aslr' src/CMakeLists.txt; cmake --build build --verbose 2>&1 | grep -E 'clang.*-o'
```
