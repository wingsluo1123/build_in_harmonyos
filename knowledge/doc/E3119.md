## 根因分析
解释型源码库没有 native 构建产物，但仍有可执行语言语义。逐文件哈希仅验证资产，不能证明真实库功能，也不能据此排除上游 examples 断言入口。旧稿将其可验证性全部等同完整性是错误边界，已由本 PR 的 E2026100505 与真实 ECL 测试纠正。

## 推荐方案
**方法**: data-package-exemption-noarch-integrity-validator

**说明**: noarch 仅定义未编译源码资产的 package_id，不豁免功能测试。保留固定文件 size/SHA256 清单校验和正常生态安装布局，同时用发布的原生语言实现执行未修改上游回归、安装消费者和独立平台测试。Common Lisp 使用标准 CL_SOURCE_REGISTRY 的 (:source-registry (:tree ... ) :inherit-configuration) 语法；不再发布非标准 ASDF_SOURCE_REGISTRY_ADDITIONAL 字段或不合法 glob 表达式。

**修复命令**:
```
python verify_agnostic_lizard.py --source-root <unpacked-tree> && conan create archives/a/agnostic-lizard/0-git20201010.1.fe3a737 --build=missing
```

**验证**:
```
conan create archives/a/agnostic-lizard/0-git20201010.1.fe3a737 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
