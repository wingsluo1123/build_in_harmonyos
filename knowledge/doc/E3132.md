# E3132: OHOS PC 普通进程无法挂载用户态 FUSE：/dev/fuse stat/open 均 EACCES(13)、PATH 无 fusermount（自带 fusermount 执行即 SIGSYS）、mount(2) 被沙箱以 SIGSYS(31) 终止；内核 FUSE 仅系统服务可用（媒体服务挂载 /data/storage/el2/media/Photo）——libfuse 消费端可构建交付但运行时挂载受阻，须按能力探测给出边界结论与恢复条件

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime, filesystem, permissions, capability
- **作者**: unknown

## 错误特征
```
fuse: failed to open /dev/fuse: Permission denied|/dev/fuse.*EACCES|fusermount.*Permission denied|Signal 31 \(core dumped\)|failed to open /dev/fuse|mount\(2\).*SIGSYS
```

## 根因分析
OHOS PC 内核支持 FUSE（/proc/mounts 可见系统媒体服务以 /dev/fuse 挂载），但普通用户进程被三重阻断：① /dev/fuse 的 stat 与 open(O_RDONLY/O_RDWR) 全部返回 EACCES(13)（节点既不可读也不可写，权限/SELinux 策略仅放行系统服务）；② 系统 PATH 无 fusermount/fusermount3，libfuse 制品自带的 fusermount 一执行即被 SIGSYS(31) 终止（rc=159）；③ 绕过 libfuse 直接调用 mount(2)（ctypes libc.mount, fstype="fuse"）同样立即 SIGSYS(31) core dump。进程 CapEff=0x2a（无 CAP_SYS_ADMIN），沙箱把挂载类 syscall 直接以 SIGSYS 杀死而不是返回 EPERM。libfuse 的 fuse_main() 在 fuse_mount 阶段即失败："fuse: failed to open /dev/fuse: Permission denied"（rc=1）。因此所有 libfuse 消费端（mhddfs / tmfs / mtpfs / securefs / kio-fuse 等同簇）当前只能完成构建、打包与 CLI 层验证，无法进行真实挂载运行。

## 推荐方案
**方法**: capability-probe-then-boundary

**说明**: 适配流程先做三层能力探测（/dev/fuse errno、fusermount 可用性、mount(2)/fuse_main 结果），结论写入版本 notes/reports；交付物保持构建+CLI 契约完整（消费者测试只用平台可确定的行为做硬断言），PR 中如实标注"当前挂载不可用"及恢复条件（平台放开 /dev/fuse 访问或提供系统级挂载服务后，本包无需改动即可挂载）。禁止以任何方式绕过沙箱伪造挂载。

**修复命令**:
```
mhddfs d1,d2 mnt -o mlimit=64m   # 期望边界输出: "fuse: failed to open /dev/fuse: Permission denied" (rc=1)
```

**验证**:
```
python3 -c "import os; os.open('/dev/fuse', os.O_RDWR)"  # errno=13 EACCES；grep fuse /proc/mounts  # 系统服务挂载可见；<libfuse>/bin/fusermount -u /tmp/x  # Signal 31 core dumped；python3 ctypes libc.mount(b"none", tgt, b"fuse", 0, b"")  # Signal 31
```
