# E3152: 宿主加载型 C++ 框架库把 ABI/线程模型编码进编译期宏：库与消费者必须使用同一变体选择符（如 flext 的 -DFLEXT_SHARED），否则类名被按 _shared/_single 改名、dlopen 在 BIND_NOW 下报 symbol not found

## 基本信息
- **严重度**: 3
- **类别**: ohos, toolchain, linking, packaging, plugins
- **作者**: frj__

## 错误特征
```
symbol not found|Error relocating|undefined symbol|flext_(base|obj|root)_single|flext_(base|obj|root)_shared|couldn't create
```

## 根因分析
flext 这类"宿主加载型 C++ 框架库"把**编译期宏当作 ABI 选择符**：flprefix.h 依据 FLEXT_SYS 选区宿主（Pd=2/Max=1），依据 FLEXT_SHARED 选"共享+多线程 vs 单线程"变体，并用 FLEXT_CLASSDEF 把基类符号改名（flext_base_shared / flext_base_single，flext_root_single 等）。框架共享库本身用 -DFLEXT_SYS=2 -DFLEXT_SHARED -DFLEXT_EXPORTS 编译，只导出 *_shared 符号；消费者（外接对象）必须带**同样的** -DFLEXT_SHARED（库侧多一个 EXPORTS）。若消费者漏掉该宏，它引用的是 *_single 符号；由于产物是共享对象（允许未定义符号），**编译与链接都不报错**，直到宿主 dlopen 时才失败。OHOS clang 默认 BIND_NOW（readelf: FLAGS_1 NOW），加载即做立即重定位，于是报 `Error relocating ...: _ZN17flext_root_singlenwEm: symbol not found`，Pd 打印 `... couldn't create`。该协议由上游 pd-flext.pc 发布（Cflags 里带 -DFLEXT_SYS=2 -DFLEXT_SHARED），消费者若不走 pkg-config / 不采信包的 cxxflags 就会踩。

## 推荐方案
**方法**: export-abi-selectors-from-library-package

**说明**: 把框架库的编译期变体选择符作为**包的公共接口**发布：在 Conan 里写入 cpp_info.cxxflags（-DFLEXT_SYS=2 -DFLEXT_SHARED -pthread）并生成 pd-flext.pc（Cflags 同款），消费者通过 Conan 生成器或 pkg-config 取到，绝不靠记忆手写；库侧单独加 -DFLEXT_EXPORTS（导出侧），消费者不加。这样库与消费者天然同变体。

**修复命令**:
```
conanfile package_info(): self.cpp_info.cxxflags = ["-DFLEXT_SYS=2","-DFLEXT_SHARED","-pthread"]; 并写 lib/pkgconfig/pd-flext.pc: Cflags: -I${includedir} -I${pdincdir} -DFLEXT_SYS=2 -DFLEXT_SHARED -pthread
```

**验证**:
```
1) readelf -d <pkg>/lib/libflext-pd.so.0.6.4 | grep -E 'SONAME|FLAGS' 应见 SONAME=libflext-pd.so.0.6 与 FLAGS_1 NOW；2) llvm-nm -u <libflext-pd.so> 可见 UND 的宿主符号 class_new/gfxstub_*/outlet_*（宿主 pd 以 -rdynamic 导出，加载时绑定）；3) 用 pd-flext 安装包编外接时带/不带 -DFLEXT_SHARED 各一次，不带者能编能链但 pd -open 时 `symbol not found`。
```
