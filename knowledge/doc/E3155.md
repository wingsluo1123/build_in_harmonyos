# E3155: 裸 Makefile 把运行时行为路径（spool/anacrontab）烧成编译期宏且上游无运行时覆盖口：必须在 make 变量层四路分离注入，再给 spool 补一个环境变量覆盖口

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, build-system, runtime
- **作者**: unknown

## 错误特征
```
Can't chdir to .*spool|Can't open temporary file.*Read-only file system|getpwuid\(\) error.*No such file or directory|tempnam\(NULL, NULL\)|fatal error.*'obstack.h' file not found
```

## 根因分析
anacron 2.3 的 Makefile 用 ALL_CPPFLAGS 把 SPOOLDIR 与 ANACRONTAB 以 -D 烧进二进制，而 main() 起手就 chdir(SPOOLDIR)、失败即 die_e() 中止，上游唯一给的运行时开关 -t 只能覆盖 anacrontab 文件，spool 一个覆盖口都没有。与此同时 installdirs 目标拼的是 $(PREFIX)$(SPOOLDIR) —— 这个双拼只有在 PREFIX 为空、SPOOLDIR 为相对路径时才成立，而编译期宏又要求 SPOOLDIR 是绝对路径，两者互相矛盾。于是在只读根文件系统上（OHOS/HarmonyOS 的 /var/spool 连父目录都不存在）出现「make 覆盖 PREFIX 也救不回来」的死局。另有两个同源的运行时地雷：runjob.c 用 tempnam(NULL, NULL) 取临时文件名，解析到 P_tmpdir=/tmp（只读），且实测本平台 libc 忽略 TMPDIR（设了 TMPDIR 后返回值仍是 /tmp/temp_*），故 E002 常见的「改 TMPDIR」解法在此无效；runjob.c 的 username() 对 getpwuid() 返回 NULL 直接 die_e() 中止，而本平台的 app/sandbox uid 刻意不入 /etc/passwd（文件存在、15382 B，但 uid 20020084 查不到）。第三层是 readtab.c include <obstack.h>：musl/HarmonyOS 不提供 GNU obstack。制品仓并非没有实现——musl-obstack/1.2.3 在库且被 dwarves/dwz/box64/elfutils 等 4 个配方 requires（初版只用 obstack/gnulib/libiberty/gnu-obstack 四个精确名检索、漏检了它）；本包仍选 vendor，理由是 application 包免引入 shared 依赖与 SONAME 打包面，并有 LGPL-2.1 §6 允许重标注为 GPL v2+ 的许可证依据。

## 推荐方案
**方法**: bake-path-four-way-makevar-override-plus-env-fallback

**说明**: (1) 先分清烧死的是「构建期路径」还是「运行时行为路径」——前者 make 覆盖即解（见 similar_to 的 M18），后者覆盖 PREFIX 只改安装落点、运行时仍读编译期宏，必须额外加运行时覆盖口。(2) 上游 installdirs 若拼 $(PREFIX)$(SPOOLDIR) 这类「PREFIX + 绝对路径」，则 PREFIX 保持空串并把 BINDIR/MANDIR/SPOOLDIR/ANACRONTAB 四个绝对路径逐个传，绕开双拼同时让编译宏与安装落点保持一致。(3) 覆盖口优先做成环境变量（本例 ANACRON_SPOOL），语义是「缺省仍用编译期宏」，这样本机与 CI 各自 create 时零配置可用，跨机复用二进制时才有逃生口。(4) 临时文件落在只读 /tmp 且 libc 忽略 TMPDIR 时，不要试图用环境变量解决——改用程序已经 chdir 进入、且由本包自己拥有的可写目录（此处 tempnam(spool, prefix)）。(5) getpwuid 返回 NULL 的分支若上游写的是 die_e()，要收窄成「取不到就退回 $LOGNAME/$USER」，因为该地址只服务于邮件头这类信息性字段。(6) 缺系统头文件（obstack.h）时先查制品仓有没有对应包——检索词要覆盖别名变体（本包首版只用 obstack/gnulib/libiberty/gnu-obstack 四个精确名，漏了 musl-obstack/1.2.3，导致错误地把 vendor 写成唯一出路）；确认有可用包时仍可按包形态取舍（application 包优先 vendor 以免引入 shared 依赖与 SONAME 面，库包则直接 requires），vendor 侧把许可证写进 notes（LGPL-2.1 §6 允许重标注 GPL v2+），配方用 exports_sources 随行、source() 摊平进源码树，由上游 Makefile 的 wildcard *.c 自动纳入 objects。(7) 验收必须真跑一次「建 anacrontab + 建 spool + 跑 job + 查时间戳」，只验编译和 -V 拦不住这类「装完一跑就中止」的包。

**修复命令**:
```
make -j1 CC=<clang> CPPFLAGS=-I. PREFIX= BINDIR=<pkg>/bin MANDIR=<pkg>/share/man SPOOLDIR=<pkg>/var/spool/anacron ANACRONTAB=<pkg>/etc/anacrontab INSTALL_DIR=mkdir -p INSTALL_PROGRAM=cp INSTALL_DATA=cp
```

**验证**:
```
conan create archives/a/anacron/2.3 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
