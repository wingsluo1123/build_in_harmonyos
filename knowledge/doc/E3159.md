# E3159: 子模块测试框架与家族依赖同时缺失时按精确 pin 自建并恢复全量测试

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, cmake, dependency, testing
- **作者**: 328
- **来源 PR**: 14073

## 错误特征
```
Could not find a package configuration file provided by "mbits-args"|Could not find a package configuration file provided by "mbits-mstch"|Could not find a package configuration file provided by "mbits-utfconv"|Could not find a package configuration file provided by "mbits-diags"|include could not find requested file.*googletest|tools/testing.*not exist
```

## 根因分析
上游自测框架在未随标签归档分发的 Git 子模块中，app 与部分测试目标依赖同族 Conan 包；通过核验官方 pin 并在目标真机自建精确版本依赖、恢复精确子模块后，可完成全量 GoogleTest 执行。远端 registry 是否已有依赖与本地源码能否构建必须分开记录。

## 推荐方案
**方法**: pinned-dependency-build-and-full-upstream-test

**说明**: 先核验 registry 与官方 pin；依赖未发布但官方源码可用时在目标真机自建，恢复 pinned 测试子模块后执行全量上游测试。分开报告测试声明数、实例数、命令行 CTest 与消费者用例，并区分本地依赖和 CI registry 状态。

**修复命令**:
```
cmake -S <upstream-source> -B <build> -DLNGS_APP=ON -DLNGS_TESTING=ON -DLNGS_LITE=ON -DLNGS_INSTALL=OFF -DLNGS_LINKED_RESOURCES=ON && cmake --build <build> && ctest --test-dir <build> --output-on-failure
```
