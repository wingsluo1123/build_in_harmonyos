# E3163: OHOS/musl 系 <sys/queue.h> 缺少 CIRCLEQ 家族（FreeBSD 2018 已删除）：使用环形队列宏的软件需在特性守卫下自带标准实现

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, libc, musl, headers
- **作者**: 9C4A

## 错误特征
```
CIRCLEQ_ENTRY\(|CIRCLEQ_HEAD\(|CIRCLEQ_REMOVE\(|CIRCLEQ_FIRST\(|CIRCLEQ_NEXT\(|CIRCLEQ_INIT\(
```

## 根因分析
OHOS 的 <sys/queue.h> 是 FreeBSD 衍生快照，与 FreeBSD >= 13 / musl 系一致地**移除了 CIRCLEQ 家族**（circular queue；FreeBSD 2018 年以极少使用为由删除，OpenBSD/musl 亦不提供），而同文件的 LIST/TAILQ/SLIST/STAILQ 仍在；glibc 至今仍提供 CIRCLEQ。后果：按 glibc/旧 BSD 编写的代码（使用 CIRCLEQ_ENTRY/CIRCLEQ_HEAD/…）在 OHOS 上宏未展开，编译期出现链式错误——结构体成员位置残留 `CIRCLEQ_ENTRY(binding) x;` 触发 "type name requires a specifier or qualifier"、"duplicate member"、"expected function body after function declarator"（proot 实测 12 处同族错误）。与 E091 的 struct 重定义、E194 的 bits/alltypes.h 缺失均不同轴：本条是**纯容器宏家族缺失**，非 libc ABI/类型缺口。

## 推荐方案
**方法**: feature-guarded-standard-macro-fallback

**说明**: 在以 CIRCLEQ 类型定义处（首个使用该宏的头/源文件）包含 <sys/queue.h> 后，用 `#ifndef CIRCLEQ_HEAD` 特性守卫补齐标准 CIRCLEQ 宏族（HEAD/HEAD_INITIALIZER/ENTRY/FIRST/LAST/NEXT/PREV/EMPTY/INIT/INSERT_AFTER/INSERT_BEFORE/INSERT_HEAD/INSERT_TAIL/REMOVE/FOREACH/FOREACH_REVERSE；语义与 glibc/旧 FreeBSD 一致：以自指针为哨兵，`(void *)(head)`）。**纯特性检测，不含平台条件宏（R8/PF5 干净）**；glibc/Linux 构建走原头文件、零影响，同一补丁可在任意 C 库上安全生效。若使用点位于多个 TU，守卫应落在被共同包含的头文件（proot 为 src/path/binding.h；binding.c 中 sys/queue.h 先于该头包含亦被覆盖）。

**修复命令**:
```
|
```

**验证**:
```
grep -rn 'CIRCLEQ_' <src>/ | head; printf '#include <sys/queue.h>\nstruct s { int x; CIRCLEQ_ENTRY(s) link; };\nint main(void){return 0;}\n' > q.c && clang -c q.c -o /dev/null
```
