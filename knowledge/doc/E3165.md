# E3165: OHOS linux/keyctl.h 的 struct keyctl_dh_params 无 private 成员（改为 union）：按上游形状写 .private 设计符即编译失败

## 基本信息
- **严重度**: 2
- **类别**: kernel, portability, libc, headers
- **作者**: unknown

## 错误特征
```
field designator 'private' does not refer to any field in type 'struct keyctl_dh_params'|no member named 'private' in 'struct keyctl_dh_params'|keyctl_dh_params
```

## 根因分析
OHOS 内核 UAPI 头 linux/keyctl.h 把 struct keyctl_dh_params 定义成

## 推荐方案
**方法**: use-upstream-shaped-struct-under-platform-guard

**说明**: 在走系统 struct 的 #else 分支里，用 #ifdef __OHOS__ 守卫重新声明一个与上游同形状的私有 struct dh_params { int32_t private; int32_t prime; int32_t base; }，让 .private 设计符继续成立；不要改调用点去用 .priv（那会让补丁在非 OHOS 平台失效），也不要删除 KEYCTL_DH_COMPUTE 相关代码（会让 DH 能力整体丧失）。等效性依据：OHOS 的 union 内只有一个 __s32 成员，结构体仍是 3 x 4 字节、字段顺序 private/prime/base 一致，syscall(__NR_keyctl, KEYCTL_DH_COMPUTE, &params, ...) 交给内核的仍是同一布局。

**修复命令**:
```
|
```

**验证**:
```
printf '#include <linux/keyctl.h>\nstruct keyctl_dh_params p = { .private = 1, .prime = 2, .base = 3 };\n' | clang -xc -c - -o /dev/null 2>&1 | grep "field designator"
```
