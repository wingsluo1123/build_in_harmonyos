# E3169: 旧版 Autotools config.guess 在 HarmonyOS PC AArch64 上的规避与显式 build 三元组

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, autotools, aarch64
- **作者**: 328
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/merge_requests/13738

## 错误特征
```
config.guess.*syntax error|cannot guess build type|HarmonyOS|aarch64-unknown-linux-musl
```

## 根因分析
libspectre 发行包携带的旧版 config.guess 在 HarmonyOS PC shell 上于 GNU build triplet case 分支报 syntax error，导致 configure 无法猜测 build type。显式 Autoconf --build 三元组可绕开旧脚本。另一个独立的依赖打包陷阱是 Ghostscript 的 gs 命令制品不等于 libgs 开发制品：默认 make/install 不产生 libgs.so；消费者要求共享目标与 iapi.h。

## 推荐方案
**方法**: explicit-autoconf-build-triplet-for-ohos

**说明**: 先用发行包 config.sub 验证 aarch64-unknown-linux-musl，再通过 AutotoolsToolchain.configure_args 传入 --build=aarch64-unknown-linux-musl，跳过自动执行不兼容旧 config.guess。若 Ghostscript 制品只有 gs 命令，需另构建共享库依赖包：运行上游 make so 与 make soinstall，并安装 psi/iapi.h 到 include/ghostscript；libspectre 再声明该包并传播 -lgs、头文件及库目录。目标机分别验证依赖 C API 和真实 PostScript 渲染。依赖包必须提供 libs 为 gs 以及 include/ghostscript/iapi.h。

**修复命令**:
```
config.sub aarch64-unknown-linux-musl；conan create archives/l/libspectre/0.2.12 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```

**验证**:
```
conan create archives/g/ghostscript/10.07.1.1 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing; test -f <ghostscript-package>/lib/libgs.so; test -f <ghostscript-package>/include/ghostscript/iapi.h; conan create archives/l/libspectre/0.2.12 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing; test_package 以真实 PostScript 文件调用 libspectre/libgs 并检查页数、页面尺寸和像素缓冲。
```
