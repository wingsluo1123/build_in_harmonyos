# E3173: contents-API 推送链路将 conanfile.py 精简/字节打乱(13060B vs 本地 17777B) → L0i utf-8-sig 解码抛 UnicodeDecodeError,hint 误导向「带 BOM」;worker git-clone `fatal: not a git repository` 为另一独立故障

## 基本信息
- **严重度**: 2
- **类别**: conan, byte-corruption, contents-api, quality-gate, worker-infra
- **作者**: 856F
- **来源 PR**: 15134

## 错误特征
```
L0i: conanfile\.py AST 解析失败|UnicodeDecodeError|utf_8_sig|fatal: not a git repository|\.buildbot-patched
```

## 根因分析
远端 conanfile.py 经 contents-API 推送时被精简(注释/构建说明剥离,13060B vs 本地 17777B)或转码打乱字节;ci/conan/build_and_test.sh 的 L0i 用 encoding="utf-8-sig" 打开 conanfile.py 做 AST 提取依赖,损坏字节导致 codecs.utf_8_decode 抛 UnicodeDecodeError,门禁输出 hint「带 BOM」——实测本地无 BOM、UTF-8 正常。根因在推送链路字节损坏(与 DRAFT-libkysdk-3.0.1.0 同族),非配方问题。第二类:worker 工作区 .buildbot-patched 缺失 + `fatal: not a git repository`,git-clone/cleanup 秒败,属 Worker 基础设施,与代码无关。

## 推荐方案
**方法**: push-clean-files-verify-bytes

**说明**: 本地跑与 PR 完全相同的 ci/conan/build_and_test.sh(必须注入 CI_BRANCH=feat/viewnior-1.8 + CI_PR_NUMBER,否则 R40 静默跳过),确认本地配方 exit 0;用本地干净 conanfile.py(17777B)经 contents-API PUT 覆盖远端精简/损坏版(必须带 branch=feat/viewnior-1.8 放 body + sha + base64 content 零空格,不带 branch 404 Blob Not Found),推送后字节级对比远端 raw 与本地(cmp 无输出),再触发 /rebuild。

**修复命令**:
```
curl -X PUT -H "Content-Type: application/json" -d '{"branch":"feat/viewnior-1.8","sha":"<旧blob sha>","content":"<base64 零空格>"}' "https://atomgit.com/api/v5/repos/{owner}/{repo}/contents/{path}?access_token=${TOKEN}"; 推送后 curl -sL ".../contents/{path}?ref=feat/viewnior-1.8" 的 raw 与本地 cmp
```

**验证**:
```
python3 -c "open('archives/v/viewnior/1.8/conanfile.py', encoding='utf-8-sig').read()"(本地应 OK);对比远端 raw 与本地 wc -c/cmp(应一致,无输出)
```
