# E3176: Multiple IPC resources must be acquired as a failure-atomic set before fork or another irreversible side effect

## 基本信息
- **严重度**: 2
- **类别**: ipc-resource-failure-atomicity
- **作者**: gcw_vbU49vcA <gcw_vbU49vcA@noreply.gitcode.com>
- **来源 PR**: 15490

## 错误特征
```
pipe\(pipe2\) == -2|fork was called after the second pipe failed|partial pipe set|EMFILE.*fork
```

## 根因分析
A staged IPC setup checks the second pipe failure against an impossible return value and enters fork with only the first pipe valid; the uninitialized second descriptor pair makes black-box behavior nondeterministic and can hide the control-flow violation behind the same final I/O error.

## 推荐方案
**方法**: staged-acquisition-with-pre-side-effect-commit-barrier

**说明**: Check every acquisition against its documented failure value; after an intermediate failure, release previously acquired resources in reverse order; enter fork/thread/register only after the complete resource set is valid. Pair an installed-artifact resource-limit test with deterministic compilation-unit syscall substitution that injects every acquisition/fork failure and records exact close order; also verify the successful parent transfers only the intended handles.

**修复命令**:
```
cc -I. -I$BGLIBS_INCLUDE tests/pipe_failure_atomic.c -o test-pipe-failure-atomic && ./test-pipe-failure-atomic; then run test_package/cvm_pipe_failure cvm_marker_helper MARKER against the packaged shared library
```
