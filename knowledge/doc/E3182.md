# E3182: OHOS 真机将上游 gtest/自测接入 conan build()，以 HMBS_UPSTREAM_TEST_RESULT 三态 + gaps 证据放行，仅真实失败阻断

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, autotools, testing
- **作者**: hmbs-executor
- **来源 PR**: 13669

## 错误特征
```
upstream gtest: discovered=\d+ executed=\d+ passed=\d+ failed=\d+|HMBS_UPSTREAM_TEST_RESULT=\{[^}]*"status":"[^"]*"[^}]*"gaps"|Segmentation fault \(core dumped\).*eventlog_test|test_package_result_absent|rule4[^
```

## 根因分析
无 formal make check/ctest 或上游测试需原生工具链的 autotools/CMake 库，其上 npm/原生 make check 在 OHOS 真机不可直接运行；简单脚本不经统一计量会跑不全或漏报，且环境缺口（如只读 /tmp 使 eventlog 写路径段错误）与真实测试失败不分，导致要么伪造通过、要么误阻断

## 推荐方案
**方法**: add-upstream-tests-in-conan-build-harness

**说明**: 把上游 gtest/自测编入 conan build() 的 _run_upstream_tests，统一计量并上报 discovered/executed/passed/gaps；按三态 status（仅真实 failed 阻断，ohos_feature/environment gap 带证据放行为 incomplete）

**修复命令**:
```
conanfile.py: _run_upstream_tests 逐二进制分日志运行、记录退出码、按 [ RUN ]/[ OK ]/[ FAILED ] 单数据源计数，输出 HMBS_UPSTREAM_TEST_RESULT；MANIFEST.yml: upstream_test_total 按独立盘点填写，gaps 如实列 count/category/detail/evidence
```

**验证**:
```
真机日志保留真实 HMBS_UPSTREAM_TEST_RESULT（discovered/executed/passed/failed/skipped/gaps）与逐二进制退出码，gaps 证据（段错误日志 + 源码行）须连带；环境缺口只能带证据放行，不得伪造成 passed
```
