# E3185: libepoxy 制品仓以 egl=no 构建时不安装 epoxy/egl.h：需要 EGL 的包用 compat 头直连平台 EGL

## 基本信息
- **严重度**: 3
- **类别**: platform, meson, display, graphics, gtk
- **作者**: unknown
- **来源 PR**: ""

## 错误特征
```
epoxy/egl\.h file not found|fatal error: 'epoxy/egl\.h' file not found|egl\.h: No such file or directory
```

## 根因分析
OHOS 无窗口系统（无 X11/Wayland），因此制品仓 libepoxy/1.5.10 以 -Dglx=no -Degl=no -Dx11=false 构建，安装的公开头只有 epoxy/gl.h、epoxy/common.h、epoxy/gl_generated.h —— 不含 epoxy/egl.h。GL 侧（epoxy/gl.h + libepoxy.a）可用，但任何直接 #include "epoxy/egl.h" 建离屏上下文的代码（如 retro-gtk 的 retro-runner/retro-gl-renderer.c）会在编译期缺头，且即使补头也没有 epoxy_egl* 转发实现的链接风险（本用例只调原生 egl* 函数，故无此问题）。

## 推荐方案
**方法**: compat-header-expose-platform-egl

**说明**: 配方内放 compat/epoxy/egl.h（内容：只 #include <EGL/egl.h> + <EGL/eglext.h>，不引入 epoxy_egl* 转发），meson 侧把该目录加入 include 路径并链接平台 libEGL（-lEGL）。依据：OHOS SDK sysroot 自带 EGL/egl.h、EGL/eglext.h 与 stub libEGL.so，裸 clang 默认可见；运行期由 /system/lib64/libEGL.so 提供实现。这与 blur/coin3/astromenace 直链平台 EGL/GLES 的做法同款；GL 侧仍走 libepoxy，未改写依赖。

**修复命令**:
```
# generate(): tc.extra_cflags.append(f"-I{compat}"); tc.c_link_args.append("-lEGL")   # compat/epoxy/egl.h: #include <EGL/egl.h>
```

**验证**:
```
ls <libepoxy_pkg>/include/epoxy（只有 common.h/gl.h/gl_generated.h 即确认缺头）; 修复后 meson configure + compile 通过，且 ldd/readelf -d 产物出现 libEGL.so。
```
