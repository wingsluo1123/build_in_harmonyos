# E3186: Conan MesonToolchain 默认 libexecdir=bin：上游 libexec helper 落错目录且运行时路径常量随之改变

## 基本信息
- **严重度**: 2
- **类别**: build-system, meson, conan, packaging
- **作者**: unknown
- **来源 PR**: ""

## 错误特征
```
libexecdir = 'bin'.*conan_meson_native.ini|install_dir.*libexec.*installed to .*/bin/|Program .*libexec/.* not found at runtime
```

## 根因分析
Conan 2 的 MesonToolchain 在生成的 machine file 的 [project options] 段默认写入 bindir='bin'、sbindir='bin'、libexecdir='bin'（把所有可执行落点归并到 bin/，以便包布局简单）。若上游 meson.build 把内部 helper 装在 `libexecdir`（如 retro-gtk 的 retro-runner），则 (a) helper 会出现在包的 bin/，(b) 任何由 `libexecdir` 派生的编译期常量（如 RETRO_RUNNER_PATH=`/libexec/retro-runner`）与实际安装位置不一致，运行期找不到 helper，(c) 包内出现 bin/ 可执行文件还会让"纯库包"的 CLI/tool 判定（commands.json 门禁）含混。

## 推荐方案
**方法**: set-libexecdir-project-option-explicitly

**说明**: 在 generate() 里 `tc.project_options["libexecdir"] = "libexec"`（或与上游布局一致的值），还原上游安装语义；同时把 helper 暴露方式写进 notes/README（包内 libexec/<helper>，运行期可用环境变量或上游约定定位），保持 package_type=library 且 cpp_info.bindirs 为空，避免误判为 CLI 包。

**修复命令**:
```
tc.project_options["libexecdir"] = "libexec"
```

**验证**:
```
grep libexecdir <build>/conan/conan_meson_native.ini（默认 libexecdir = 'bin'）; 配置 -Dlibexecdir=libexec 后 find <pkg> -name retro-runner 应命中 libexec/。
```
