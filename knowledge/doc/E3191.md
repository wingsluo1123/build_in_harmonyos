# E3191: juce_add_plugin 类多格式插件工程在 OHOS PC 消费已发布 juce conan 包时，必须以包内 JUCEConfig 消费加 FetchContent 源注入去网络化、工具链强制 CMAKE_SYSTEM_NAME=Linux、IMPORTED helper 预注册与 CMAKE_MODULE_LINKER_FLAGS 的 E505 签名 rpath 闭包组合拳完成适配，并以三格式 bundle 布局断言加 dlopen/dlsym 探针作消费式验证。

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, conan, consumer-chain, e505-runtime-closure
- **作者**: unknown

## 错误特征
```
FetchContent.*Download|CPM\.cmake.*file DOWNLOAD|does not contain a CMakeLists\.txt file|make\[2\]: \w+_helper: No such file or directory|Error creating directory .*Contents/Resources|Error loading shared library lib(fontconfig|freetype|asound|xml2)[^:]*: \(needed by .*\.so\)|no member named .exp10.*in the global namespace|X11/Xlib\.h.*file not found
```

## 根因分析
插件类上游把全部依赖置于构建期网络获取，而已发布 juce 包的补丁只覆盖 JUCEModuleSupport.cmake；消费侧存在四个独立断层，各断层独立挂构建：(1) FetchContent/CPM 构建期 github 下载与二跳 submodule（clap-libs/clap、clap-libs/clap-helpers、RTNeural/modules/xsimd）缺位，GitHub 归档不含 submodule 内容；(2) JUCEUtils.cmake 的 VST3 bundle 布局分支直判 CMAKE_SYSTEM_NAME=="Linux"，HarmonyOS 下 VST3 退化为单文件 .vst3 而 POST_BUILD moduleinfo 步骤仍按 bundle 路径建目录；(3) POST_BUILD 以裸命令名调用 helper，make 子进程按 PATH 解析失败 Error 127（recipe 侧 buildenv_info 修改只向消费方传一跳，对本包自身 make 无效）；(4) 插件格式目标是 MODULE 库（CMAKE_SHARED_LINKER_FLAGS 不生效，须 CMAKE_MODULE_LINKER_FLAGS），叠加 musl 无 exp10 家族、已发布 juce 包丢失 vendored oggvorbis 的 libvorbis-1.3.7/lib 源码子树（flac 树完整不受影响，Curator tgz 实锤与包内核实一致）、用户存储未签名 .so dlopen 即 EACCES。

## 推荐方案
**方法**: juce-plugin-consumer-ohos-toolchain

**说明**: (1) JUCE 改消费已发布 conan 包：根 CMakeLists 的 FetchContent(juce) 块替换为 list(APPEND CMAKE_PREFIX_PATH "${JUCE_PACKAGE_DIR}") + find_package(JUCE REQUIRED CONFIG)，包前缀经工具链变量注入（JUCEConfig 设 JUCE_MODULES_DIR，chowdsp_utils 类下游自动走 juce_add_modules 路径）；(2) 其余 FetchContent 源经 conandata fetchcontent 段固定 URL+SHA256 预解包，二跳 submodule 用 GitHub API contents?ref=<commit> 查 gitlink，一律 _staging+rename 落位（conan get() 解包后 mv、destination 已存在即嵌套），完整性 marker 断言存 deps/ 相对全路径；(3) 工具链强制 CMAKE_SYSTEM_NAME=Linux（E092）；(4) 预注册 IMPORTED GLOBAL juce_lv2_helper/juce_vst3_helper 指向包内 bin/JUCE-8.0.5/（POST_BUILD 裸名解析与依赖随之成立）；(5) CMAKE_MODULE_LINKER_FLAGS 注入 $ORIGIN 四级+包内/构建树视图绝对 rpath，package() 物化视图+逐文件 binary-sign-tool selfSign+readelf 断言 NEEDED ⊆ 视图∪系统库且 rpath 非空；(6) 上游零测试以三格式消费式探针验证（运行时 unset LD_LIBRARY_PATH）；(7) juce 包缺陷以下游声明规避：oggvorbis 子树缺失以 JUCE_USE_OGGVORBIS=0 裁剪（flac 侧包内源码完整、保持上游默认启用），VST3 布局断层以 VST3_AUTO_MANIFEST FALSE 兜底，均报上游 run 修复，不越界改包。

**修复命令**:
```
tc.variables["CMAKE_SYSTEM_NAME"]="Linux"; tc.variables["CMAKE_MODULE_LINKER_FLAGS"]=" -Wl,--disable-new-dtags -Wl,-rpath,$ORIGIN/${VIEW}:$ORIGIN/../${VIEW}:$ORIGIN/../../${VIEW}:$ORIGIN/../../../${VIEW}:$ORIGIN/../../../../${VIEW} -Wl,-rpath,${PKG}/lib/${VIEW} -Wl,-rpath,${BUILD}/${VIEW}"; package(): 物化${VIEW}视图+selfSign+readelf 断言; 验证: ctest --output-on-failure -R ${NAME}_bundle_probe
```

**验证**:
```
sh -c 'unset LD_LIBRARY_PATH; python3 -c "import ctypes,glob; b=glob.glob(\"/storage/Users/currentUser/.conan2/p/*/*/p/lib/jc303\")[0]; d={\"VST3\":(glob.glob(b+\"/JC303.vst3/Contents/*/*.so\")[0],\"GetPluginFactory\"),\"LV2\":(glob.glob(b+\"/JC303.lv2/*.so\")[0],\"lv2_descriptor\"),\"CLAP\":(b+\"/JC303.clap/JC303.clap\",\"clap_entry\")}; [(ctypes.CDLL(f), getattr(ctypes.CDLL(f), s)) for f, s in d.values()]; print(\"JUCE_PLUGIN_PROBE_PASS\")"'
```
