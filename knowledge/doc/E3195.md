# E3195: 设备用户分区配额真满（非 inode 耗尽）时，shadow CI 隔离 job 改走"dd 写探针判空间 + git archive HEAD 瘦快照 scp + 手工组装 job 骨架"替代流程 — 顺带免疫 repo-source 缺 ci/、索引污染、大小写路径检出污染三类既有缺陷

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, device-storage, enospc, isolated-job, shadow-ci
- **作者**: unknown

## 错误特征
```
cp: .*No space left on device|can't create .*No space left on device|sh: can't create temporary file /tmp
```

## 根因分析
①ohos-prepare-isolated-conan-job.sh --repo-source 全量 cp 旧 job repo（含 .git 历史，数 GB）空间放大，配额紧的设备必然 ENOSPC；②HMDFS 的 df 输出经 fuse 层失真（显示 tmpfs 16G 或 non_account 数百 GB 可用），唯一可靠判据是 dd 写探针；③设备 /tmp 只读使 ssh heredoc 写 job 文件必败，骨架文件须本机写好 scp；④git archive HEAD 从树对象生成快照，不含 .git 且磁盘无关——顺带解决上游同树含 libXext/libxext 两套大小写路径在大小写不敏感文件系统上无法同时干净检出的问题。

## 推荐方案
**方法**: thin-snapshot-manual-job-bootstrap

**说明**: "①判空间：dd 写探针，不信 df；②清空间：只删自己创建的残缺 job 与 $HOME 顶层散落 tar/log，他人 job 与历史批次未经授权一律不动；③瘦快照：本机 git archive --format=tar.gz HEAD（本仓 115020 文件实测 165MB，磁盘无关、免 .git、免大小写污染），scp 上传解压到 $JOB/repo/build_in_harmonyos；④手工组装契约：6 目录（repo/conan-home/work/artifacts/logs + 根）+ env.sh（OHOS_ISOLATED_USER/JOB、OHOS_JOB_BASE、CONAN_HOME、CI_REPO_ROOT、CI_PACKAGES 指向本包、ohpc-ci-shadow PATH/PYTHONPATH）+ run-conan-heavy.sh 逐字复刻健康 job；⑤远端写文件一律 scp 不用 heredoc（/tmp 只读）；⑥起 runner 前跑等价性自检四连。"

**修复命令**:
```
git archive --format=tar.gz -o snapshot.tar.gz HEAD && scp -P 2222 snapshot.tar.gz <user>@<device>:
```

**验证**:
```
dd if=/dev/zero of=$HOME/.wtest bs=1M count=500 2>&1 | tail -1; rm -f $HOME/.wtest   # 0 B copied = 配额满; ls $JOB; ls $CI_REPO_ROOT/ci/conan/build_and_test.sh; sh -n $JOB/run-conan-heavy.sh; grep CI_PACKAGES $JOB/env.sh   # 起 runner 前的等价性自检
```
