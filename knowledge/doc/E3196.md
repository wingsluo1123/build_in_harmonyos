# E3196: conan 上 C/autotools 库静态传递依赖缺失（.la、版本冲突、override 寻址、头/符号补齐）一体化适配

## 基本信息
- **严重度**: 3
- **类别**: compat, ohos, build-system, autotools, conan
- **作者**: hmbs-executor
- **来源 PR**: 13638

## 错误特征
```
missing automake-[0-9.]+ (--gnu|.*Makefile)|not a valid libtool archive|Duplicated requirement|Version conflict: Conflict between .* in the graph|unable to find library -l.*-.*|fatal error: '.*\.h' file not found|file not found|undefined symbol: g_libintl_gettext|C compiler cannot create executables|Must have .* installed
```

## 根因分析
conan 物化 C/autotools release 后出现四类相互交织的静态传递依赖问题：①源码树经 conan export→copytree 物化时 mtime 丢序，configure.ac/*.am 新于生成的 Makefile.in，唤醒 automake maintainer 重生成规则而缺失 automake 失败；②静态依赖（avahi/glib）只装 .a 不装 .la，libtool 静态归档扫描要读 .la 而报 not a valid libtool archive；③conan 2 对同一包重复声明抛 Duplicated requirement，两 exact-pin 版本冲突改 override=True 后依赖从直接 cpp_info/dependencies 剥离导致 BFS 寻址与 .pc/头/符号补齐失效；④只读 /tmp 使 configure 编译器探测失败，头/符号依赖需手工补齐

## 推荐方案
**方法**: integrated-static-transitive-dep-fix

**说明**: 一体化解法：①autotools mtime 分层归一化（源码 2000/aclocal.m4 2001/生成文件 2002，且在全部补丁后 configure 前作为最后一次源码变更，含 *.make）使 maintainer 规则休眠；②静态依赖缺 .la 时生成 libtool shim 匹配 ltmain.sh func_lalib_unsafe_p 首4行 glob '# Generated by libtool' 并正确拼装 dependency_libs（-L<staging> -l<实际名>，避免 -lavahi- 双前缀）经 -L bake 进 LDFLAGS；③conan 2 对 glib 类冲突改为单一声明 override=True，且依赖不可达时用 BFS 全图寻址取回 package_folder，将 .pc shim 直接落盘 self.generators_folder；④readonly_tmp 写入可写临时根并使 test_package 消费者显式 require+补 -justintl

**修复命令**:
```
conanfile.py: _normalize_bootstrap_timestamps(含 .make)、_fix_avahi_la(libtool .la shim 合规)、_glib_pkg() BFS 寻址、_fix_glib_pc_files() 落盘 generators_folder、_hmbs_writable_tmpdir()；test_package/conanfile.py: 显式 require 直接依赖+CMAKE_EXE_LINKER_FLAGS 补 -L<glib libdir> -lintl；tests/ Makefile 补 $(CHECK_CFLAGS)
```

**验证**:
```
真机日志须保留 configure 阶段 ACC_PROG_CC 通过、make 链接不再触发 automake/不再报 .la not valid、pkg-config 能解析 glib-2.0/avahi、unit-test 真实执行并解析出 Check 汇总行、test_package 消费者 CMake 链接不含 g_libintl_gettext 未定义符号
```
