# E3199: libtool 2.4.x link mode 丢弃 .so 形式 deplibs——产物 DT_NEEDED 仅 libltdl+libc、不带任何兄弟库；消费者必须链接全闭包、musl 全局符号域完成跨库重定位；编译链接全绿不构成可用性证据，终判以真机运行消费者探针为准

## 基本信息
- **严重度**: 2
- **类别**: toolchain, conan, link, runtime-loader
- **作者**: why6666666 <why6666666@noreply.atomgit.com>
- **来源 PR**: pending（feat/globus-openssl-module-5.2 交付 PR）

## 错误特征
```
Error relocating .*: .*: symbol not found|error while loading shared libraries.*cannot open shared object
```

## 根因分析
本平台工具链（libtool 2.4.x ltmain + clang→musl）下，库的 LIBADD 含 .so 绝对路径（".la dependency_libs 陷阱"的标准规避手法）时，libtool link mode 会把这些 .so deplibs 从最终驱动命令中丢弃；产物共享库 DT_NEEDED 仅剩 libltdl.so.7/libc.so，不带它实际调用的任何兄弟库。musl 无惰性绑定、重定位只在全局符号域进行——只要可执行文件（消费者/test）直接链接完整依赖闭包且各依赖 lib 目录在 LD_LIBRARY_PATH 中，跨库符号即可在运行期绑定。GSI 链既有产物（globus-common 18.15 / globus-gsi-openssl-error 4.4 / globus-openssl-module 5.2 实测）DT_NEEDED 一致仅 libltdl.so.7+libc.so，属平台级家族约定而非单包 bug

## 推荐方案
**方法**: consumer-closure-link

**说明**: 不要试图给每个库强行制造 DT_NEEDED（与平台全部既有产物不一致）。配方 cpp_info.requires 全量声明依赖（pkg::pkg + system_libs），下游自然拿到完整链接行；test_package/消费者显式链接全闭包（-lpkg -ldep1 -ldep2 ... -lssl -lcrypto），运行期 LD_LIBRARY_PATH 覆盖全部依赖包 lib 目录；适配完成的终判是真机跑通消费者级运行探针，不是编译链接全绿。适用边界：本条适用于多库互链家族、且平台既有产物一致不带兄弟 DT_NEEDED 的场景（本仓 GSI 链等）；单个远古 libtool（如 1.3.3 old_deplibs 机制）库需自持 NEEDED 时按 E429 的重建产物方案处理，勿混用

**修复命令**:
```
cd /tmp/probe && clang $(for d in $(find full_deploy -type d -name include); do printf -- -I%s $d; done) $(for d in $(find full_deploy -type d -name lib); do printf -- -L%s $d; done) consumer.c -o t -lglobus_openssl -lglobus_common -lglobus_proxy_ssl -lglobus_openssl_error -lssl -lcrypto && LD_LIBRARY_PATH=$(for d in $(find full_deploy -type d -name lib); do printf %s: $d; done) ./t
```

