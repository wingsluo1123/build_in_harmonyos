# E3200: config.sub 年代决定 ohos 补丁形状与失败模式：2013 系响亮失败、同代目标行（118/126-129/1368）字节同一，三 hunk 添加模板可跨库逐字节复用；2018 系 rc=0 静默改写、必须替换对+os 归一化大表 hunk；先 head -3 查年代选型，终判以 config.sub 输出断言为准

## 基本信息
- **严重度**: 3
- **类别**: platform, autotools, configure, detect
- **作者**: why6666666 <why6666666@noreply.atomgit.com>

## 错误特征
```
Invalid configuration.*linux-ohos|unknown operating system .ohos.|checking host system type\.\.\..*linux-gnu
```

## 根因分析
GNU config.sub 的年代（版权年，head -3 可见）同时决定失败模式与补丁形状。2013-04-24 版（autoconf 2.69 / automake 1.11 世代；globus-callout 4.3、globus-gsi-openssl-error 4.4、globus-openssl-module 5.2 三例实测）：对 *-linux-ohos 输入响亮失败（Invalid configuration / unknown operating system），三处目标行（maybe_os 列表 118 行、linux-ohos 子分支 126-129 行、os 归一化大表 1368 行）在三库逐字节同一，一份三 hunk 添加型模板可跨库原样复用（dry-run 零偏移命中）。2018-05-05 版无 kernel-os 校验门，os 归一化大表缺 -linux-ohos* 时 4 段三元组被 -linux* 兜底 sed 静默改写为 <machine>-unknown-linux-gnu-ohos 且 rc=0（行级机理与 hunk 必要性分级见 DRAFT-autotools-config-sub-ohos-table-hunk-tiering），必须换用替换对模板并必补大表 hunk。跨代际不可复制：2013→2018 三 hunk 上下文/行号全漂移，dry-run 全不匹配；toybox patch 对纯插入 hunk 兼容性差，插入写成相邻 -/+ 替换对（细节见 DRAFT-toybox-patch-pure-insert-hunk-unappliable）

## 推荐方案
**方法**: vintage-tiered-patch-templates

**说明**: 按 config.sub 年代选模板：2013 系用三 hunk 添加型（maybe_os 列表行加 linux-ohos*、android-linux 块后插 linux-ohos 子分支、os 归一化大表行尾追加 -linux-ohos*），同代跨库直接复用、不改一字（三例实证）；2018 系用替换对模板且必补 os 归一化大表 hunk（形状与行级依据见 DRAFT-autotools-config-sub-ohos-table-hunk-tiering）。插入一律写成相邻 -/+ 替换对以兼容设备 toybox patch；交付前以 pristine 响亮失败基线 + dry-run + 4 段/3 段双输出断言收口，任何一步不过即停

**修复命令**:
```
head -3 build-aux/config.sub && sh build-aux/config.sub aarch64-unknown-linux-ohos && sh build-aux/config.sub aarch64-linux-ohos   # 年代先行；后两条都必须原样输出 aarch64-unknown-linux-ohos
```

**验证**:
```
# 自包含序列（以 globus-openssl-module 5.2 为例，补丁随仓 archives/g/globus-openssl-module/5.2/patches/，在仓根执行）
```
