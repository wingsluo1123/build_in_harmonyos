# E3203: 上游 CMakeLists 用无条件 ADD_SUBDIRECTORY 把 Qt6 GUI 目标耦合进整棵构建树 —— 无 Qt6 平台上零 Qt 依赖的 CLI 也被连带阻断

## 基本信息
- **严重度**: 2
- **类别**: limitation, build-system, cmake, dependency, qt6
- **作者**: uefitool-adapter

## 错误特征
```
By not providing "FindQt6\.cmake".*|Could not find a package configuration file provided by "Qt6".*|Qt6_DIR.*NOTFOUND|Qt6Config\.cmake.*not found|FIND_PACKAGE\(Qt6 REQUIRED
```

## 根因分析
上游根 CMakeLists.txt 里 GUI 子目录与 CLI 子目录是**平级且都无任何条件保护**的 ADD_SUBDIRECTORY；而 GUI 子目录内第一件事就是 FIND_PACKAGE(Qt6 REQUIRED COMPONENTS Widgets)。CMake 处理 ADD_SUBDIRECTORY 时立即展开该子目录 ⇒ REQUIRED 依赖找不到即 FATAL_ERROR，整个 configure 中止。此时尚未进入任何语言编译阶段，所以「GUI 不需要」这个事实救不了同级的 CLI。本质是**可选目标被硬编码进必需路径**，不是"少了一个开关"。

## 推荐方案
**方法**: 新增一个**适配侧**薄 CMakeLists，只装载那些零 Qt 依赖的子工程；用构建系统自带的"指定构建脚本目录"入口把配置指向它。上游一个字节都不改。

**说明**: (待补充)

**修复命令**:
```
cmake.configure(build_script_folder="cmake")   # conan CMake helper；配合自带的 cmake/CMakeLists.txt
```

**验证**:
```
grep -n "ADD_SUBDIRECTORY" CMakeLists.txt; grep -n "FIND_PACKAGE(Qt6" UEFITool/CMakeLists.txt; cmake -S . -B /tmp/probe-b -G Ninja 2>&1 | grep -B1 -A3 "FindQt6"
```
