# E3212: Conan 自建配方中 configure 与 make 的 cwd 不一致致 Makefile 落错目录及依赖导出头文件路径复位（自动工具类食谱通用解法）

## 基本信息
- **严重度**: 3
- **类别**: detection, headers, build-system, autotools, conan
- **作者**: hmbs-executor
- **来源 PR**: 15420

## 错误特征
```
make: \*\*\* No rule to make target '[^']*'\. Stop\.|fatal error: '[^']+' file not found
```

## 根因分析
自建 autotools 类 Conan 配方中，configure 命令未显式指定 cwd，而 make 使用 cwd=self.source_folder；Conan self.run 默认在 build_folder 执行，configure 生成的 Makefile/config.h 落到 build_folder，make 在仅有 Makefile.in 的 source_folder 中运行即报 No rule to make target；同时依赖（pcap）导出/暂存头文件实际落位与消费方 include 路径不符，导致 fatal error: header file not found

## 推荐方案
**方法**: align-configure-make-cwd-and-reset-export-header-path

**说明**: 为 configure 显式补 cwd=self.source_folder 使其与 make 处于同一目录，确保 Makefile 落在 make 可见目录；并核对依赖导出/暂存头文件实际落位，将消费方 include 路径与 include_dirs 对齐

**修复命令**:
```
conanfile.py: build() 中 configure 命令补 cwd=self.source_folder 与 make linux 对齐；核对 pcap 导出头实际落位目录并加入 include_dirs/includedir，使消费方找到 pcap/funcattrs.h
```

**验证**:
```
真机门禁复跑并确认 compile:compiler_error 消失、依赖头（如 pcap 的 resolvefunc.h/funcattrs.h）位于 include 搜索路径且消费方源码可编译为对象码
```
