# E3222: conan build 环境被清洗（无 HOME）且 PATH 注入共享 ld shim：自举工具链（zig 等）运行时缓存解析与原生 libc 探测双双失败，须烘焙路径+显式缓存目录+最小 PATH 的零 fork 包装器

## 基本信息
- **严重度**: 3
- **类别**: detection, ohos, portability, build-system, toolchain
- **作者**: frj__
- **来源 PR**: 15084

## 错误特征
```
LibCStdLibHeaderNotFound|AppDataDirUnavailable|error: AccessDenied.*zig|unable to create compilation
```

## 根因分析
conan 的 conanbuild 环境按 profile 重建而非继承（HOME 等被清除），zig 的全局缓存默认 ~/.cache/zig 解析失败，表面错误为 LibCStdLibHeaderNotFound/AppDataDirUnavailable（与头文件无关）；同时 work/shared/bin 提供的 ld 是 'lld --code-sign' shim，zig 原生目标 libc 探测 sh 出 PATH 上的 ld 被其破坏，同为 LibCStdLibHeaderNotFound；每编译一次 fork dirname/cd 的包装器在共享机上放大 can't fork 风险

## 推荐方案
**方法**: baked-path-zero-fork-wrapper

**说明**: 包装器内 1) export ZIG_GLOBAL_CACHE_DIR=<构建目录内路径>（HOME 缺失的自足替代）；2) zig 执行路径用最小 PATH（zig 目录+/usr/bin:/bin），隔离共享 ld shim 对原生探测的毒化；3) 所有路径在生成包装器时由 Python 烘焙为字面量（不做 $(dirname)/$(cd) 命令替换），单 exec 零 fork；4) 逐变量 env -i 对照法定位此类"环境面"根因，勿被表面错误（头文件/权限）误导

**修复命令**:
```
参见 archives/w/wasi-libc/0.0-git20260129.ec0effd/conanfile.py 的 WRAPPER_CLANG（ZIGPATH/HERE 烘焙 + ZIG_GLOBAL_CACHE_DIR）
```

**验证**:
```
env -i 最小环境逐变量复现（PATH+HOME/ZIG_GLOBAL_CACHE_DIR 对照）；修复后 conan create 的 CMake 编译器探测与全量编译通过
```
