# E3223: False pytest failure caused by a dot in the source path, misdiagnosed as spaces

## 基本信息
- **严重度**: 2
- **类别**: ohos, python, conan, testing, environment
- **作者**: unknown

## 错误特征
```
assert "ipython-input" in f_cache_relative_directory|test_memory.py:191: AssertionError|test_parallel_call_cached_function_defined_in_jupyter
```

## 根因分析
joblib's func_inspect.get_func_name, for module == "__main__", takes os.path.abspath(inspect.getsourcefile(func)), splits it on os.sep, joins the parts with "-" into the module prefix, and only THEN does module.split("."). Because the join happens before the split, any DOT in the path is treated as a segment separator, so the mangled cache directory name is truncated at the first dot and no longer contains "<ipython-input". The upstream test test_parallel_call_cached_function_defined_in_jupyter therefore fails. This was initially and incorrectly attributed to spaces in the path; a clean path WITHOUT spaces still fails, while a path WITH spaces but no dot passes.

## 推荐方案
**方法**: run-with-a-dot-free-cwd

**说明**: Run the test process with a cwd that contains no dot. inspect.getsourcefile() resolves through os.path.abspath(), so the mangled name is derived from the CWD, not from where the source tree lives: a dot-free cwd plus PYTHONPATH pointing at the dot-containing source tree passes (verified). Do NOT change the recipe and do NOT add the case to ALLOWED_TEST_FAILURES. If the case must be explained, document the four-way experiment (space-no-dot passes, dot-no-space fails, .cache-style dot dir fails, dot-free passes).

**修复命令**:
```
cd <dot-free-dir> && PYTHONPATH=<src-with-dots> python3 -m pytest "<case>"
```

**验证**:
```
B=/tmp/p; mkdir -p "$B/nospace/dot.1.6.0" "$B/cleanpath" "$B/with space nodot"; cp -r <src>/{joblib,conftest.py} "$B/nospace/dot.1.6.0/"; cd "$B/nospace/dot.1.6.0" && PYTHONPATH=$PWD python3 -m pytest "<case>"   # 2 failed;  cd "$B/cleanpath" -> 2 passed
```
