# E3229: Conan 运行时工具依赖须 requires(run=True) 注入 test_package PATH 且上游跳过时标 status=incomplete

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, testing
- **作者**: hmbs-executor
- **来源 PR**: 15315

## 错误特征
```
failed to locate mcpp or gcc pre-processors|HMBS_UPSTREAM_TEST_RESULT=\{[^}]*"skipped":[1-9][^}]*"status":"passed"
```

## 根因分析
Conan 2 对普通 requires 默认 run=False，运行时工具包（如 mcpp/2.7.2 的 bin/mcpp）不会进入消费者 test_package 的 conanrun 环境 PATH；souffle CLI 默认未给 --no-preprocessor，运行时用 which("mcpp") 定位外部 C 预处理器，故已安装依赖图仍抛 failed to locate mcpp or gcc pre-processors。另一面，上游 ctest 存在 ohos_feature 缺口（skipped>0）时 _run_upstream_tests() 仍无条件标 status=passed，98.6% 未执行与 passed 自相矛盾。

## 推荐方案
**方法**: conan-run-trait-plus-incomplete-status

**说明**: 将运行时工具依赖声明为 requires("mcpp/2.7.2", run=True) 使其 bin 注入 test_package 的 conanrun PATH，which("mcpp") 命中后默认解释执行模式跑通端到端用例；上游 marker 在 skipped>0 时改标 status=incomplete 并附 ohos_feature gaps 与 reason，仅当 skipped==0 才标 passed，同时修正 manifest 的 upstream_test_total 与实测 discovered 一致

**修复命令**:
```
conanfile.py: self.requires("mcpp/2.7.2", run=True)；manifest.yaml: runtime: mcpp/2.7.2；_run_upstream_tests(): skipped>0 → status="incomplete" + gaps=discovered-executed
```

**验证**:
```
真机日志保留 HMBS_TEST_PACKAGE_RESULT={"executed":true,"passed":true,"command":"sh test.sh","discovered":2,"passedCount":2} 与 HMBS_UPSTREAM_TEST_RESULT 的 status=incomplete + ohos_feature gaps，且 discovered-executed=skipped 恒等式成立
```
