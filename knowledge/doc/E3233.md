# E3233: OHOS clang 定义 __linux/__linux__/linux，厂商以 #if __linux 开启的 Linux 专有特性块被误激活，进而 #include 仅 Linux 才有的内核/驱动头（<sys/soundcard.h>/<linux/fd.h>）而编译失败；修法应按能力（__has_include）而非平台身份宏收敛

## 基本信息
- **严重度**: 3
- **类别**: platform, compat, kernel, portability, headers
- **作者**: frj__

## 错误特征
```
sys/soundcard\.h.*(file not found|No such file)|linux/fd\.h.*(file not found|No such file)|linux/fdreg\.h.*(file not found|No such file)
```

## 根因分析
OHOS clang 的 target 是 aarch64-unknown-linux-ohos，会预定义 __linux / __linux__ / linux（实测 `clang -dM -E`：三者皆 1）。许多上游库用 `#if __linux` 作为"在 Linux 上启用某特性"的**厂商特性开关**（而非判断 libc/头文件能力）；在 OHOS 上这些块被误判为"在 Linux 上"而编译进去，块内的 #include 指向 Linux 内核/驱动专有头——OSS 声音 <sys/soundcard.h>、物理软驱控制器 <linux/fd.h>/<linux/fdreg.h>。这些头在 OHOS sysroot 中不存在，编译在预处理阶段即报 `fatal error: '...' file not found`。与"musl 缺少某 Linux 专有 API"不同：这里缺的是**内核/驱动头文件**，失败发生在 include 层而非链接/类型层。

## 推荐方案
**方法**: capability-guard-vendor-linux-feature-blocks

**说明**: 用**能力探测**收敛厂商 Linux 特性块：把 `#if __linux` 改为 `#if defined(__linux) && __has_include(<所需头>)`，令块仅在所需内核/驱动头真实存在处编译。**不要**用 `!defined(__OHOS__)` / `defined(__OHOS__)` 等**平台身份宏**判分支（仓库 R8/PF5：补丁新增行不得出现私有平台宏，应以 POSIX/能力探测适配；该写法已被淘汰）。被停用的只是依赖 Linux 内核/驱动的能力（OSS/物理软驱），纯软件路径不受影响。

**修复命令**:
```
sed -i 's|#if __linux|#if defined(__linux) \&\& __has_include(<sys/soundcard.h>)|' trs_cassette.c ; sed -i 's|#if __linux|#if defined(__linux) \&\& __has_include(<linux/fd.h>)|' trs_disk.c
```

**验证**:
```
1) `echo | clang -dM -E -x c - | grep -wE '__linux|linux'` 可见 __linux/__linux__/linux 均为 1；2) `grep -rn '#if __linux' src/` 定位厂商特性块；3) 直接 `make` 复现 `fatal error: 'sys/soundcard.h' file not found`；4) 改为能力探测后重编通过。
```
