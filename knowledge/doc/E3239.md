# E3239: autotools 配方在真机只读/不可写 TMPDIR 下 mktemp -d 生成坏目录导致 config.status 失败时回退到 autoconf mkdir fallback 的通用修复内核

## 基本信息
- **严重度**: 3
- **类别**: platform, detection, hmdfs, ohos, build-system
- **作者**: hmbs-executor
- **来源 PR**: 15159

## 错误特征
```
config.status: error: could not setup config files machinery|can't create \./conf[^ ]*/subs1\.awk: Permission denied|Permission denied
```

## 根因分析
autoconf AS_TMPDIR 在 configure 中执行 mktemp -d "./confXXXXXX" 生成 0700 目录；真机 HMFS 上因 UID 映射/setgid 使该目录对当前进程不可写，但 test -d 通过令 configure 采用坏目录，写 subs1.awk 时 Permission denied，最终 config.status: error: could not setup config files machinery

## 推荐方案
**方法**: autoconf-mktemp-fallback

**说明**: 用独立 hmbs_conf_env 只注入 configure 步骤的 mktemp 包装脚本（exit 1），触发 autoconf 的 mkdir fallback，绕过坏目录；同时修正 configure umask 077→022、显式指定 --build/--host 绕过 config.guess 无法识别 OHOS

**修复命令**:
```
generate(): 创建 mktemp 包装脚本（exit 1）经仅注入 configure 的 hmbs_conf_env 启用 HMBS_AUTOCONF_MKTEMP_FALLBACK；./configure 增加 --build/--host=<triple>；将 autoconf 生成 config.status 中的 umask 077→022
```

**验证**:
```
真机日志确认 configure 成功生成 config.status 且无 mktemp/umask/config.status 错误；再经 make 与 test_package 门禁全绿
```
