# E3242: HarmonyOS PIE-mandatory 拒绝对 ET_EXEC/非 PIE 镜像 exec，修复切换产 PIE 后端或对链接命令打 -pie 补丁，并依 noexec 挂载语义选择可执行产物 cwd

## 基本信息
- **严重度**: 3
- **类别**: compat, ohos, kernel, portability, build-system
- **作者**: hmbs-executor
- **来源 PR**: 13856

## 错误特征
```
Permission denied|execv EACCES|rc=127|Type=EXEC|e_type=2|ET_EXEC
```

## 根因分析
HarmonyOS（类 Android 的 Linux 内核）实行 PIE-mandatory：execve 非 PIE/ET_EXEC 镜像即拒绝并返回 EACCES。zerolang `zero run` 默认 direct 后端经 `z_elf_write_executable64`（emit_elf64.c/emit_elf_aarch64.c）直接写静态、绝对寻址的 ET_EXEC（e_type=2，base_addr=0x400000，单 RX PT_LOAD，无 interpreter），被 OHOS 拒 exec 返回 EACCES→子进程 _exit(127)→rc=127；而 clang 链接路径默认产 PIE/ET_DYN 可执行。只对 clang 链接路径打 `-no-pie`→`-pie` 补丁不会命中 direct 后端，故必先甄别产物实际走哪条后端，再决定切换 `--backend llvm` 还是打 `-pie` 补丁

## 推荐方案
**方法**: switch-to-pie-backend-or-pie-patch

**说明**: 先甄别可执行产物实际由哪条后端/路径产出；若为直接写 ELF 的 direct 后端，改为切到产 PIE(ET_DYN) 的后端（如 `--backend llvm`），并对 clang 链接路径保留 `-pie` 源补丁；若仅 clang 路径，则直接在链接命令打 `-pie` 补丁

**修复命令**:
```
conanfile.py 新增 `_patch_no_pie()` 在 build() 开头把 llvm_toolchain.c/main.c 两处 `" -no-pie"` 改写为 `" -pie"`；test_package/test.sh 将 `zero run` 改为 `zero run --backend llvm`；test_package/conanfile.py 使 ZERO_LLVM_CLANG 解析对齐 `_cc()`（conf→PATH cc→clang）并引入 `shutil`；consumer cwd 改到 conan-home 可执行挂载
```

**验证**:
```
真机日志：`readelf -h <exe>` 验证 Type 从 EXEC 变为 DYN(PIE)；`zero run --backend llvm` 输出 hello（2/2 断言）+ 5 上游 smoke 5/5 全绿；HMBS_UPSTREAM_TEST_RESULT 与 HMBS_TEST_PACKAGE_RESULT 保留真实结果
```
