# E3243: OHOS 大源码 Makefile 构建：命令行变量覆盖 target-specific 赋值致链接标志丢失时改用 env 前缀注入，并用 make -o 跳过超高 fork 的依赖生成规则

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, build-system, make
- **作者**: hmbs-executor
- **来源 PR**: 15482

## 错误特征
```
Depend\.list: No such file or directory|posix_spawn failed: Resource temporarily unavailable|undefined symbol: (bgzf_|bam_)
```

## 根因分析
GNU Make 变量优先级规定命令行变量（make VAR=value）优先于 Makefile 内的 target-specific 赋值与 += 追加。上游 STAR Makefile 用 `STAR: LDFLAGS := $(LDFLAGSextra) $(LDFLAGS_shared) $(LDFLAGS)` 并入 `-Lhtslib -Bstatic -lhts -Bdynamic -lz`，内嵌子 Makefile（htslib）用 `CPPFLAGS += -I. -DSAMTOOLS=1` 追加头路径；配方把 LDFLAGS/CPPFLAGS 当作 make 命令行变量传入时，这些赋值被整条丢弃——链接缺 -lhts 使 bgzf_*/bam_* 全部未定义，.o 编译缺 -I. 使 cram/sam_header.h 找不到。另一独立内核：上游 Depend.list 规则用单条 clang++ -MM 一次性处理约 190 个源文件，每个输入 fork 一个 -cc1 子进程，OHOS worker 进程资源耗尽触发 posix_spawn Resource temporarily unavailable，clang 非零退出、make 删除半成品目标，随后 include Depend.list 报 No such file or directory。

## 推荐方案
**方法**: env-prefix-inject-build-flags-and-skip-depend-list

**说明**: 把 CPPFLAGS/LDFLAGS 从 make 命令行变量改为环境变量前缀注入（`CPPFLAGS="..." LDFLAGS="..." make ...`），使子 Makefile 的 target-specific 赋值与 += 仍生效；同时在 make 调用加 `-o Depend.list` 将该高 fork 依赖清单规则标记为已最新以整体跳过，并显式补回被它带起的 htslib 目标

**修复命令**:
```
conanfile.py build(): `CPPFLAGS="<zlib_inc>" LDFLAGS="<zlib_lib>" make -j1 -o Depend.list htslib all`
```

**验证**:
```
真机 conan create 全量构建；日志中 `clang++ ... -c ... Transcript_convertGenomeCigar.cpp` 等编译行需带 -I.，链接行需含 `-Lhtslib -Bstatic -lhts -Bdynamic -lz`；无 `posix_spawn failed: Resource temporarily unavailable` 与 `Depend.list: No such file or directory`；`STAR --version` 输出 2.7.11b
```
