# E3247: OHOS head 不支持 GNU 负数字节偏移，上游回归截断输入需改 POSIX wc/dd

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, testing
- **作者**: pc2-7

## 错误特征
```
head --bytes=-[0-9]+.*(illegal byte count|invalid number|exit 1)|head: illegal byte count -- -[0-9]+|head --bytes=-20.*failed|giffix.*regress.*Error 1
```

## 根因分析
OHOS 默认 head(1)（toybox 系）只支持 POSIX 语义，不支持 GNU coreutils 的负数字节偏移扩展 `--bytes=-N`（head -c -N）。上游回归套件常用 `head --bytes=-20 <file>` 截去文件末尾 20 字节构造损坏输入，在 OHOS 上该命令直接失败（illegal byte count），使依赖截断输入的回归用例无法运行。

## 推荐方案
**方法**: portable-truncate-wc-dd

**说明**: 用 POSIX 组合替代 GNU 负数偏移：`bytes=$(wc -c <file); dd if=file bs=1 count=$((bytes-N)) 2>/dev/null`，保持"去掉末尾 N 字节"的测试语义，同时兼容 OHOS/其他 POSIX head。

**修复命令**:
```
dd if=$(PICS)/file bs=1 count=$$((bytes - 20)) 2>/dev/null | tool ...
```

**验证**:
```
head --bytes=-20 <file>; echo $?（OHOS 上为 1）；对照 wc -c <file> + dd bs=1 count=$((size-20)) 输出与 GNU head -c -20 逐字节一致
```
