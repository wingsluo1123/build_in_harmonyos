# E3251: PyPI 元数据未报告依赖时，通过官方声明和隔离导入恢复运行依赖闭包

## 基本信息
- **严重度**: 2
- **类别**: python, dependency, packaging, runtime
- **作者**: P16B
- **来源 PR**: 15360

## 错误特征
```
requires_dist.*null|ModuleNotFoundError: No module named .six.|install_requires.*six
```

## 根因分析
旧版本发行元数据可能没有导出 Requires-Dist；API 的 requires_dist=null 只代表该字段未报告依赖。将其当作零依赖会遗漏 setup.py、requires.txt 或 pyproject.toml 中实际声明的运行依赖。

## 推荐方案
**方法**: verify-dependency-declarations-and-isolated-runtime-closure

**说明**: 把空缺元数据标为未知，静态核对官方 setup.py、requires.txt 或 pyproject.toml 与 import；固定已发布运行依赖并显式传播 Conan runenv，在隔离导入中验证真实依赖闭包。

**修复命令**:
```
python3 -I -S -c 'import sys; sys.path[:0] = sys.argv[1:3]; from purl import URL; assert str(URL("https://example.com").add_path_segment("a")) == "https://example.com/a"' "$PURL_SITE" "$SIX_SITE"
```

**验证**:
```
比对同版本 PyPI JSON、官方依赖声明和模块 import；在 python -I -S 中分别只提供目标包、再提供目标包和声明依赖，确认具体缺失模块及真实 API 成功。
```
