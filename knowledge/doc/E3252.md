# E3252: 交叉编译 Boost.Python 扩展时构建解释器不得同时决定目标库名与扩展后缀

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, python, packaging
- **作者**: 431B

## 错误特征
```
unable to find library -lboost_python-py3[0-9]+|ModuleNotFoundError: No module named minieigen|EXT_SUFFIX.*x86_64.*target.*aarch64
```

## 根因分析
旧 setup.py 从正在执行构建脚本的 sys.version_info 选择 Boost.Python 组件，并由同一构建解释器的 sysconfig 生成扩展文件名；目标编译器和目标头库即使已正确注入，构建端后缀仍会使目标 Python 导入器忽略这个有效的 AArch64 ELF。只手改 Boost.Python 库名可让链接成功，却不会修正扩展发现契约。

## 推荐方案
**方法**: target-python-abi-contract

**说明**: 从目标 Python 包的 _sysconfigdata 读取 SOABI 与 EXT_SUFFIX，以同一版本 token 选择目标 Python.h、libpython 和 Boost.Python 组件；构建后联合检查 AArch64 ELF、PyInit 符号、DT_NEEDED、文件后缀，并由该目标解释器真实 import；不泛化到设备上的其他 Python 安装。

**修复命令**:
```
python3 -c 'import glob,runpy; p=glob.glob("<target-prefix>/lib/pythonX.Y/_sysconfigdata*.py"); assert len(p)==1; d=runpy.run_path(p[0])["build_time_vars"]; print(d["SOABI"],d["EXT_SUFFIX"])'
```

**验证**:
```
同时核对目标 _sysconfigdata 的 SOABI/EXT_SUFFIX、扩展文件名、DT_NEEDED 中的 libpython 与 Boost.Python 组件，并用交付的目标 Python 执行 import；错误/正确后缀两臂必须是 SHA256 相同的同一 ELF，任一项不一致即失败。
```
