# E3253: Conan 原生构建渲染空 generic_system 块使 CMAKE_SYSTEM_PROCESSOR 落 unknown，上游按处理器做架构分发时静默把异架构桩实现编入交付 DSO——须前置注入系统名/处理器，并以行为断言验证分支落点

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, build-system, cmake, conan
- **作者**: GoliWie
- **来源 PR**: 交付 PR 后回填

## 错误特征
```
Building for unknown architecture|src/swImpl/.*\.obj|StatusCode\(\) == NOT_SUPPORTED(?!.*grpc)|vector_client_smoke.*Failed [0-9]\.[0-9]+ sec
```

## 根因分析
conan 2.29.1 CMakeToolchain 在 host==build 原生构建下 _get_generic_system_name() 不返回系统名 → generic_system 块渲染为空（工具实现语义，参照 DRAFT-E622 记载），conan_toolchain.cmake 不设 CMAKE_SYSTEM_NAME/CMAKE_SYSTEM_PROCESSOR → project() 时 CMakeDetermineSystem 走宿主分支：uname -s=HarmonyOS 无 Platform/HarmonyOS.cmake 仅告警（System is unknown to cmake，单独出现不构成失败信号——E545 已证多数场合良性），CMAKE_SYSTEM_PROCESSOR 取自 uname -p，本机该命令成功执行但返回字符串 "unknown"（uname -m 正常返回 aarch64；"uname 失败/unavailable"表述不准确）→ 上游 CMakeLists.txt:25 if(CMAKE_SYSTEM_PROCESSOR MATCHES "x86_64|aarch64") 失配 → else() 分支 add_definitions(-DENABLE_SW_ARCH) 仅编 src/swImpl/（STATUS 行 "Building for unknown architecture" + SwClientImpl.cpp.obj 进入构建清单）→ configure rc=0、build rc=0，失败后移至运行期：工厂返回桩实现，全部 API 返回 NOT_SUPPORTED（消费者冒烟 0.04-0.05s FAIL 是唯一可见症状）→ 归类：平台探测语义差异 × 上游架构/后端分发静默落错分支。关键机理补充：仅注入 CMAKE_SYSTEM_PROCESSOR 不够——宿主分支仍会覆写它（R2 实测复现）；必须同时注入 CMAKE_SYSTEM_NAME 使 CMakeDetermineSystem 走交叉分支、尊重工具链的 PROCESSOR 值。

## 推荐方案
**方法**: user_toolchain-preinject-system-name-processor

**说明**: 配方 generate() 以 conan.tools.files.save 写两行片段 set(CMAKE_SYSTEM_NAME HarmonyOS) + set(CMAKE_SYSTEM_PROCESSOR aarch64)（OS 真实系统名 + 与 profile arch 对应的目标处理器，能力探测而非平台名硬编码），经 conf tools.cmake.cmaketoolchain:user_toolchain 注入——该块在 conan_toolchain.cmake 中最先渲染 → CMakeDetermineSystem 见 CMAKE_SYSTEM_NAME 非空走交叉分支并尊重工具链 PROCESSOR 值 → project() 见 aarch64、上游门控命中真实现分支。两行缺一不可（R2 实证仅注入 PROCESSOR 仍被宿主分支覆写）。等价形：tc.blocks['generic_system'].values 直接赋值（pybind11 草稿先例），同样要求在 CMakeToolchain 渲染前就位。

**修复命令**:
```
save(self, os.path.join(self.generators_folder, 'ohos-system-processor.cmake'), 'set(CMAKE_SYSTEM_NAME HarmonyOS)\\nset(CMAKE_SYSTEM_PROCESSOR aarch64)\\n'); self.conf.define('tools.cmake.cmaketoolchain:user_toolchain', [<片段路径>])；验证：configure 输出 grep 'Building for aarch64 architecture' 命中、构建清单无 src/swImpl/ 条目、交付 .so nm -D 含真实现符号
```

**验证**:
```
uname -p（本机得 unknown，命令成功、退出码 0）；最小分发工程复现静默错分支：mkdir -p /tmp/arch-probe && cd /tmp/arch-probe && printf 'cmake_minimum_required(VERSION 3.20)\nproject(p C)\nif(CMAKE_SYSTEM_PROCESSOR MATCHES "x86_64|aarch64")\n  message(STATUS "Building for target arch")\nelse()\n  message(STATUS "Building for unknown architecture")\nendif()\n' > CMakeLists.txt && cmake -B build 2>/dev/null | grep 'Building for'（预期 unknown architecture 且 cmake rc=0——桩分支静默选中，此即危害本质）；修复形：printf 'set(CMAKE_SYSTEM_NAME HarmonyOS)\nset(CMAKE_SYSTEM_PROCESSOR aarch64)\n' > fix.cmake && cmake -B build-fix -DCMAKE_TOOLCHAIN_FILE=fix.cmake 2>/dev/null | grep 'Building for'（预期 target arch）；交付面对照：nm -D --defined-only lib*.so | grep -c <真实现符号>（真实现 >0，桩 =0）；消费冒烟断言：调用工厂后首 API 返回码 Status.Code() != NOT_SUPPORTED（桩全部返回 NOT_SUPPORTED，行为断言直接锁定分支落点）
```
