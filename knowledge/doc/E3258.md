# E3258: Upstream CTest success does not prove an installed static Qt QML plugin can be imported

## 基本信息
- **严重度**: 2
- **类别**: ohos, packaging, api, plugin, qml
- **作者**: tank_you

## 错误特征
```
'module "org.kde.kitemmodels" plugin "itemmodelsplugin" not found'
```

## 根因分析
With BUILD_SHARED_LIBS=OFF, the kitemmodels QML plugin was installed as libitemmodelsplugin.a. The installed consumer used an ordinary runtime import of org.kde.kitemmodels, which does not load that static archive automatically. The upstream 12-case CTest suite still passed, so its result alone did not establish the package's advertised QML behavior.

## 推荐方案
**方法**: ship-verified-shared-qml-module

**说明**: When static QML plugin registration is not implemented and verified, do not advertise a static package option. Set package_type to shared-library, build with BUILD_SHARED_LIBS=ON, retain upstream CTest and an installed-package QML import consumer, and rerun the final shared-only candidate on the target.

**修复命令**:
```
'conan create <recipe> -pr:h=<native-ohos-profile> -pr:b=<native-ohos-profile> -c tools.build:jobs=2'
```

**验证**:
```
'On the authorized OHOS PC, compare full native conan create with shared and static configurations; require upstream CTest N/N and an installed-package C++/QML consumer including ordinary QML import.'
```
