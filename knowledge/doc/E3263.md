# E3263: 原生工具测试的同 SONAME 依赖污染与空设备列表错误路径

## 基本信息
- **严重度**: 2
- **类别**: portability, runtime, testing
- **作者**: D310
- **来源 PR**: 13634

## 错误特征
```
symbol not found|assert -11|scandir|paths == NULL
```

## 根因分析
原生测试图为另一软件获取已发布 libinput/1.26.2，其相同 SONAME 被 LD_LIBRARY_PATH 优先加载，当前1.28.1工具子进程出现缺符号。修正加载路径后，record --all 的真实错误路径暴露：scandir 无可用目录返回NULL，主循环解引用空列表。 实际GUI首次共享映射写失败与/dev/shm容量耗尽同时出现；保留失败，在有真实空间的设备重跑全部原GUI。配置遵守GTK回调返回值和realize前事件掩码；安装CLI使用真实包图生成的runenv，并保留冷运行错误及真实签名私有inode加载专项。

## 推荐方案
**方法**: source-bound-native-test-and-runtime-closure

**说明**: 把当前源码构建目录优先加入所有相关子进程的 LD_LIBRARY_PATH，保留依赖精确 revision；pytest 使用任务私有 --basetemp，避免 HMDFS owner 与进程 UID 不同的默认缓存检查。生产代码在遍历 paths 前检查NULL，输出诊断并沿原 out 清理路径返回已有失败状态，不修改原 pytest 断言或绕过设备权限。 实际GUI首次共享映射写失败与/dev/shm容量耗尽同时出现；保留失败，在有真实空间的设备重跑全部原GUI。配置遵守GTK回调返回值和realize前事件掩码；安装CLI使用真实包图生成的runenv，并保留冷运行错误及真实签名私有inode加载专项。

**修复命令**:
```
设置任务私有 TEMP/TMPDIR 与运行库查找路径；运行原框架，不改断言；按入口与轮次回读 RC。
```

**验证**:
```
核对精确发行源码与候选补丁，执行原测试框架及独立签名 HMDFS 探针，保全进程 RC 和回执链。
```
