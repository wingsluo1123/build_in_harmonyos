# E3273: contents API 推送链路截断 conanfile.py(缺 build/package/package_info 方法) → Conan 默认空包 → test_package CMake 报 include 路径不存在

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, byte-corruption, contents-api, empty-package
- **作者**: 856F
- **来源 PR**: 14631

## 错误特征
```
package\(\): WARN: No files in this package!|Imported target .* includes non-existent path .*\/include|conan create failed
```

## 根因分析
远端 conanfile.py 经 contents API 推送时被截断(4299B vs 本地 20707B,在 requirements() 注释处断掉),缺全部 build()/package()/generate()/package_info() 方法;Conan 对无 package() 的配方默认空操作 → 生成空包 "No files in this package!";CMakeDeps 据此生成 INTERFACE_INCLUDE_DIRECTORIES=<pkg>/include,test_package 配置时报 "Imported target includes non-existent path .../p/include",conan create 失败。本地文件完整、本地 CI 全绿,与 PR CI 矛盾,根因在推送链路而非配方。

## 推荐方案
**方法**: push-clean-files-verify-bytes

**说明**: 用本地干净 conanfile.py(20707B, md5 0cc7ea476a99f8653f72bd425e8ba1db) 与 notes.md(11501B) 通过 contents API PUT 覆盖远端截断版(必须带 branch=<源分支> + sha + base64 content,base64 零空格),推送后字节级对比远端 raw 与本地(cmp 无输出),再触发 /rebuild。

**修复命令**:
```
curl -X PUT -H "Content-Type: application/json" -d '{"branch":"feat/libfprint-1.94.10","sha":"<旧blob sha>","content":"<base64>"}' "https://atomgit.com/api/v5/repos/{owner}/{repo}/contents/{path}?access_token=${TOKEN}"; 推送后 curl -sL ".../contents/{path}?ref=feat/libfprint-1.94.10" | base64 -d | cmp - <本地文件>
```

**验证**:
```
对比远端 raw 与本地字节(cmp 应无输出);grep 远端 conanfile 是否含 def build/def package/def package_info;wc -c 对比大小;conanfile 语法检查
```
