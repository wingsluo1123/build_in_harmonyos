# E3277: Installed Libtool metadata can leak build-private RUNPATH after successful relocation tests

## 基本信息
- **严重度**: 2
- **类别**: autotools, linking, conan, packaging, runtime
- **作者**: XR14

## 错误特征
```
(RPATH|RUNPATH).*build.*linker-view|installed=.yes.*libdir=
```

## 根因分析
A rewritten installed Libtool archive still tells Libtool to hardcode its libdir into dependent shared objects. Redirecting libdir to a build-private copy fixes stale links but can leak that temporary directory into the installed ELF, even when package consumers and migration tests run successfully while the producer cache still exists.

## 推荐方案
**方法**: la-free-shared-library-view-and-installed-ELF-check

**说明**: Copy the actual required .so/.a libraries into the build-private search directory without installed .la files, preserve -L/-l linking, inspect the final installed ELF dynamic section before signing/alias validation and run real consumers from a relocated package.

**修复命令**:
```
llvm-readelf -d <installed-provider.so>; conan create <recipe> -pr:h=<native-host> -pr:b=<native-build> --build=<package>/*
```

**验证**:
```
Clean native shared/static conan create; make check and original source inventory; three CMake/PkgConfig consumers; one native signed relocated-provider test; readelf -d must show no producer RPATH/RUNPATH.
```
