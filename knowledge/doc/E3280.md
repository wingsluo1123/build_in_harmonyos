# E3280: conan 2 运行闭包跳过传递共享库：Skip 判定与 un-skip 的唯一实测杠杆（test_package 显式 requires；配方 package_info 访问不足）

## 基本信息
- **严重度**: 2
- **类别**: ohos, musl, conan, runtime, closure
- **作者**: unknown

## 错误特征
```
"Error relocating .*: .*: symbol not found|Skipped binaries.*libarchive"
```

## 根因分析
"conan 2.29.1 实测：(1) 被 skip 的包 package_folder 为 None——配方 package_info() 里 `if dep.package_folder:` 守卫型 runenv 发布静默失效（不报错不警告）；(2) 仅在被依赖方 package_info 里访问 package_folder 不足以把 Skip 转 Cache：gnome-recipes 测试图中 package_info 确实执行（无条件 PATH 前置落在 conanrunenv export PATH 行、被测包目录出现 2 次、profile os=OHOS），libarchive 仍留在 Skipped binaries、conanrunenv 无其目录；(3) 唯一实测杠杆 = 图根侧消费者显式 requires（test_package.requirements 直接 self.requires('libarchive/3.8.7')，与配方同版去重无冲突）→ Skip 转 Cache、package_folder 可用、装进依赖表。修法顺序：先入闭包，再注入环境。"

## 推荐方案
**方法**: 在 test_package 的 requirements() 显式声明运行期 .so 直依赖（与配方同版本），并在 test() 侧枚举 self.dependencies.host 逐包目录（lib/lib64）注入 LD_LIBRARY_PATH——不能只读 cpp_info（组件化包 root libdirs 可能为空）。经脚本第三参数传入，脚本内前置。配方侧 package_info() 的 runenv 发布保留为真实消费者通道（入闭包后生效），但不能替代 un-skip。
