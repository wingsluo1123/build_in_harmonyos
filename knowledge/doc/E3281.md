# E3281: rest-0.7 缺件时以 libsoup 2.4 重建固定 URL 表单 POST 调用簇——制品仓 librest/0.10.2 属 rest-1.0/libsoup3 世代，对 libsoup2.4 的 GTK3 栈不可消费

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, conan, gnome, libsoup
- **作者**: unknown

## 错误特征
```
"Dependency \"rest-0\.7\" not found|rest-0\.7.*not found|dependency\('rest-0\.7'\)"
```

## 根因分析
OHOS 制品仓没有 rest-0.7 世代（librest 0.8/0.9，libsoup 2.4 系）的包；仓内的 librest/0.10.2 是重命名后的 rest-1.0 API 世代，且链接 libsoup3。gnome-recipes 这类 GTK3 应用整个进程栈建立在 libsoup 2.4 上，libsoup2 与 libsoup3 在同一进程内共用会导致符号冲突（两代导出同名符号），GNOME 明确不支持混链——所以"就近消费 librest/0.10.2"这条捷径不成立。实际调用面通常是"固定 URL 的 x-www-form-urlencoded POST"（RestProxyCall 的 set_form_data 族），与 OAuth 逻辑无关（头文件带 oauth2-proxy.h 不代表用到），因此把这层薄封装直接落回 libsoup 2.4 是代价最小、语义最可控的路线。

## 推荐方案
**方法**: 先对调用面做穷举清单（grep rest_proxy/rest_proxy_call/oauth），确认全部是固定 URL 表单 POST 后整文件移植到 libsoup 2.4；只删上游 meson 的 rest-0.7 依赖行，不动其它源码。
