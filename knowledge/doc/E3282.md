# E3282: glib 跨代际依赖图版本冲突：override 统一到低版 glib/2.84.0.1.1 + zlib/1.3.1.1（按制品仓已发二进制世代选向，保留全栈二进制，libgoa 单节点重编）

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, conan, glib, gnome
- **作者**: unknown

## 错误特征
```
"Version conflict.*glib|glib.*Version conflict|conflict.*glib/2\.(84|88)"
```

## 根因分析
OHOS 制品仓里 GNOME 各库按自身上游节奏建立配方，对 glib 的 requires 钉在不同小版本（2.84.x 与 2.88.x 并存），Conan 默认不做跨 requires 的一致性升级。方向判定不能只看 ABI：GLib 2.x 虽 ABI 向后兼容，但平台制品仓二进制按世代发布——gtk3 全栈（gtk/atk/gdk-pixbuf/pango/gspell/libsoup/harfbuzz/libsoup 等）只在 glib/2.84.x + zlib/1.3.1.1 世代，向上统一到 2.88.3 会作废 13 个已发二进制（package_id 随依赖代际变化）并触发整栈源码构建，实测该路径在 libpng 处死于老配方直接 exec 脚本（OHOS Error 126）。

## 推荐方案
**方法**: 先枚举 ohpcd 上两个世代候选二进制的存在性，选「已发二进制完整」的世代作为统一方向（本例 = 向下到 glib/2.84.0.1.1 + zlib/1.3.1.1）；Conan 2 允许根 override 覆盖依赖声明的硬 pin（实测 Overrides 表 glib/2.88.3 → glib/2.84.0.1.1#5a9bdf1a…，无冲突无告警）。把 glib 同世代公开 pkg-config 闭包（pcre2/libffi/graphite2/xz）显式 transitive 列入（平台默认不向消费者传播 requires），缺口库（本例 libgoa）保留上游版本、单节点源码重编。ABI 兼容性只在同世代内做验证。
