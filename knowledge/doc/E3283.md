# E3283: 消费者侧物化依赖包缺失的 soname 链接名（symlink(2) EPERM 的下游补偿；generate() 全依赖扫描、幂等）

## 基本信息
- **严重度**: 2
- **类别**: ohos, meson, linking, conan, packaging
- **作者**: unknown

## 错误特征
```
"unable to find library -l|ld\\.lld: error: unable to find library"
```

## 根因分析
"meson install 的共享库正常形态 = 实体 libX.so.<全版本> + 两个链接名（libX.so.<major> / libX.so），链接器仅经无版本名解析 -lX。OHOS /storage 沙箱在文件系统层拒绝 symlink(2)，源码重编节点在真机 package() 时两个链接名根本没落盘；制品仓包因解包物化环节不显病——缺口只在『消费者图内有源码重编依赖』时出现，炸点在下游链接命令行（与 E492/kea 的运行期 dlopen 炸点不同）。"

## 推荐方案
**方法**: 在消费者配方 generate()（链接之前、依赖已解包）扫描全部 host 依赖包 libdir，对命中 ^lib.+\\.so\\.\\d+(\\.\\d+)*$ 的实体，用实体拷贝物化缺失的 libX.so.<major> 与 libX.so（os.path.lexists 判在位；非 OHOS 直接 return；幂等——名字齐全或有 symlink 的宿主零动作）。不写死包名：重编节点是哪个由图决定。
