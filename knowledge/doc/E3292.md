# E3292: 上游 target_link_libraries 裸链库名（如 xcb）无法解析到 Conan 包：须补丁改为 find_package(<pkg>) + CMakeDeps 目标名

## 基本信息
- **严重度**: 2
- **类别**: cmake, linking, conan, target-mapping
- **作者**: 9124

## 错误特征
```
cannot find -lxcb|Target.*links to.*libxcb::xcb.*but the target was not found|undefined reference.*xcb_|target_link_libraries.*PUBLIC xcb
```

## 根因分析
上游在非 FreeBSD 的 UNIX 分支写 target_link_libraries(... PUBLIC xcb)，即把 xcb 当作系统库名交给链接器（-lxcb）。OHOS 无系统 X11，libxcb 由 Conan 制品提供；而 Conan 包（libxcb/1.17.0.1）不自带 CMake config，其目标由 CMakeDeps 生成，名称为 libxcb::xcb（组件）/libxcb::libxcb（全局）。裸名既不会自动带上 Conan 的 -L 链接目录，也不会带上头文件 include 目录，于是编译期 'xcb/xcb.h' file not found 或链接期找不到 -lxcb。

## 推荐方案
**方法**: patch-bare-name-to-cmakedeps-target

**说明**: 在补丁里把裸库名替换为 find_package(<pkg> REQUIRED) + 该包 CMakeDeps 生成的目标名（组件优先，如 libxcb::xcb；不确定组件时用全局目标 libxcb::libxcb）。目标名可从制品包 recipe 的 package_info() 里 cpp_info.components[...].set_property('cmake_target_name', ...) 读出，勿凭记忆猜。

**修复命令**:
```
find_package(libxcb REQUIRED)  # 原: target_link_libraries(... PUBLIC xcb)\ntarget_link_libraries(${library_name} PUBLIC libxcb::xcb)
```

**验证**:
```
conan create <pkg> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 | grep -E "xcb.h.*file not found|cannot find -lxcb"
```
