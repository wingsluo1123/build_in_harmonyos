# E3293: 库的公共头 include 传递依赖的头文件时，requires() 必须声明 transitive_headers/transitive_libs，否则消费者编译缺头、链接缺库

## 基本信息
- **严重度**: 2
- **类别**: conan, cpp-info-traits, public-headers, transitive-deps
- **作者**: 679D

## 错误特征
```
fatal error: '.*\.h' file not found|undefined reference.*lib.*\.so|--no-allow-shlib-undefined
```

## 根因分析
Conan 2 默认不把传递依赖的头文件与库传播给下游（transitive_headers/transitive_libs 默认 False），CMakeDeps 生成的消费配置里该依赖的 include 目录为空。若本库的 PUBLIC 头文件（如 QtADS 的 ads_globals.h 在 Q_OS_UNIX 下 include <xcb/xcb.h>）引用了该传递依赖的头，消费者编译即 file not found；若公共头对应的符号由该依赖提供，则链接期还会缺库。注意 Q_OS_UNIX 在 OHOS 的 Qt 移植里是定义的，所以“OHOS 无 X11”并不免除该编译期依赖。

## 推荐方案
**方法**: declare-transitive-traits-for-public-header-deps

**说明**: 对照本库 PUBLIC 头文件的 include 清单，把其中出现的依赖在 requirements() 里声明为 self.requires("dep/ver", transitive_headers=True, transitive_libs=True)。判据：该头文件是否安装在 include/<本包>/ 且被下游 include —— 是则其 include 的第三方头必须可传播。

**修复命令**:
```
self.requires("libxcb/1.17.0.1", transitive_headers=True, transitive_libs=True)
```

**验证**:
```
conan create <pkg> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 | grep -E "file not found|undefined reference"
```
