# E3294: qtbase 设 cmake_find_mode=none 时 CMakeDeps 仍生成 find_dependency(qtbase) 与 qtbase::qtbase —— 消费侧须把该依赖映射为 cmake_file_name=Qt6 / cmake_target_name=Qt6::Widgets

## 基本信息
- **严重度**: 3
- **类别**: cmake, conan, consumer-config, find-mode, qt6
- **作者**: DA34

## 错误特征
```
Could not find a package configuration file provided by "qtbase"|find_dependency\(qtbase\)|Target.*links to.*qtbase::qtbase.*but the target was not found|By not providing "Findqtbase.cmake"
```

## 根因分析
qtbase 配方声明 cmake_find_mode=none（它自带完整 Qt6Config.cmake），CMakeDeps 因此不生成 qtbase 配置；但它仍把 qtbase 写进消费包的 xxx_FIND_DEPENDENCY_NAMES 与 xxx_DEPS_TARGET，且 get_cmake_package_name 在 qtbase 未设 cmake_file_name 时回退为裸名 qtbase，于是消费包 config 出现 find_dependency(qtbase)（无对应配置文件→FATAL），链接接口出现不存在的 qtbase::qtbase。另外配方自写 conan_cmakedeps_paths.cmake 时，CMakeToolchain 会跳过自身 find_paths 块，必须自行把生成器目录加入 CMAKE_PREFIX_PATH/CMAKE_MODULE_PATH，否则 find_package(libxcb 等) 找不到 CMakeDeps 配置。

## 推荐方案
**方法**: consumer-side-cmakedeps-property-mapping

**说明**: 在消费方 generate() 里对 qtbase 设 CMakeDeps 属性：cmake_find_mode=none（不生成 qtbase 配置）、cmake_file_name=Qt6（find_dependency 变成可满足的 find_dependency(Qt6)）、cmake_target_name=Qt6::Widgets（链接接口指向真实且传递 Core/Gui 的 Qt6 目标）；并在 CMakeLists 里先 find_package(Qt6) 使 if(NOT Qt6_FOUND) 短路。自写 conan_cmakedeps_paths.cmake 时补 list(PREPEND CMAKE_PREFIX_PATH "${CMAKE_CURRENT_LIST_DIR}")。

**修复命令**:
```
cmake_deps = CMakeDeps(self); cmake_deps.set_property("qtbase", "cmake_find_mode", "none"); cmake_deps.set_property("qtbase", "cmake_file_name", "Qt6"); cmake_deps.set_property("qtbase", "cmake_target_name", "Qt6::Widgets"); cmake_deps.generate()
```

**验证**:
```
conan create <pkg> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 | grep -E 'Findqtbase|qtbase::qtbase'
```
