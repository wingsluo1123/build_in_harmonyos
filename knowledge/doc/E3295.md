# E3295: CMake 到第一个 project() 才加载 CMAKE_TOOLCHAIN_FILE：上游在 project() 之前读取的变量（如 ADS_VERSION）用 tc.variables 传不进去，必须走 cmake.configure(cli_args)

## 基本信息
- **严重度**: 2
- **类别**: cmake, configure, toolchain, conan, variable-timing
- **作者**: 8E9E

## 错误特征
```
VERSION ".*-NOTFOUND.*" format invalid|HEAD-HASH-NOTFOUND|include could not find requested file
```

## 根因分析
CMake 在第一个 project() 命令处才包含 CMAKE_TOOLCHAIN_FILE。Conan 的 CMakeToolchain 把所有 tc.variables 写进 conan_toolchain.cmake，因此这些变量在 project() 之前的 CMakeLists.txt 语句里不可见。QtADS 4.5.0 顶层 CMakeLists.txt 在 project() 之前用 if(NOT ADS_VERSION) 决定版本来源：变量为空时走 git describe，release tarball 无 .git 得到 HEAD-HASH-NOTFOUND，随后 project(... VERSION HEAD-HASH-NOTFOUND.HEAD-HASH-NOTFOUND.HEAD-HASH-NOTFOUND) 直接 FATAL。同理上游只在 if(NOT ADS_VERSION) 分支里 set(CMAKE_MODULE_PATH <src>/cmake/modules)，而 src/CMakeLists.txt 无条件 include(Versioning)，外部传 ADS_VERSION 时会连带丢失模块路径。

## 推荐方案
**方法**: cli-args-for-pre-project-variables

**说明**: 把必须在 project() 之前生效的变量改用 cmake.configure(cli_args=['-DVAR=value']) 传递（命令行 -D 在配置开始前即成为 cache 项）；同时用 tc.variables 补上上游在分支里才设置的 CMAKE_MODULE_PATH 等路径。判据：该变量是否出现在第一个 project() 之前的 CMakeLists 语句里 —— 是则 cli_args，否则 tc.variables 即可。

**修复命令**:
```
cmake.configure(cli_args=[f"-DADS_VERSION={self.version}"]); tc.variables["CMAKE_MODULE_PATH"] = os.path.join(self.source_folder, "cmake", "modules")
```

**验证**:
```
conan create <pkg> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 | grep -E 'NOTFOUND|include could not find requested file'
```
