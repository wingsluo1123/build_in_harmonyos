# E3299: KF6 QML 应用在 OHOS 上找不到 KLocalizedQmlContext：制品仓 ki18n 只发布核心 KF6::I18n（无 I18nQml 模块），须改用 KLocalizedContext 并把 KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT 归零

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, headers, qml
- **作者**: unknown

## 错误特征
```
KLocalizedQmlContext.*file not found|fatal error: 'KLocalizedQmlContext'|KLocalization::setupLocalizedContext|KF6::I18nQml|klocalizedqmlcontext.h
```

## 根因分析
上游 KF6 应用（kbreakout 26.04.0 src/canvaswidget.cpp、alligator 26.04.0 src/main.cpp）在 KI18N_VERSION >= 6.8.0 时使用 KLocalizedQmlContext / KLocalization::setupLocalizedContext，这两个符号属于 ki18n 仓库单独构建的 **KF6::I18nQml** 模块（src/i18n-qml）。已发布到制品仓的 ki18n/6.18.0 只构建了核心 KF6::I18n：包内 lib/ 仅有 libKF6I18n.so 与 libKF6I18nLocaleData.so，没有 qml/ 目录、没有 KF6I18nQml 目标、include/KF6/KI18n/ 下也没有 klocalizedqmlcontext.h。于是 configure 能过（find_package(KF6 COMPONENTS I18n) 成功），编译到使用点才以 "fatal error: 'KLocalizedQmlContext' file not found" 失败。同一仓库的等价 API KLocalizedContext 就在核心 KF6::I18n 里（include/KF6/KI18n/klocalizedcontext.h），QML 侧 i18n()/xi18n() 上下文对象机制完全一致；但该类自 KI18N 6.8 起被标记 deprecated，且 KDE 应用模板普遍带 ecm_set_disabled_deprecation_versions(KF <ver>)，会把 KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT 设成 6.21 之类，使 ki18n_export.h 里的 KI18N_ENABLE_DEPRECATED_SINCE(6, 8) 归零、头文件内容被整体 #if 掉 —— 只换类名仍然编译不过（KLocalizedContext 未声明）。

## 推荐方案
**方法**: patch-to-klocalizedcontext-keep-deprecation-visible

**说明**: (1) 先确认缺口不在自己的配方而在依赖：`conan cache path ki18n/6.18.0` 后看包内 `lib/`（只有 libKF6I18n.so / libKF6I18nLocaleData.so）、有无 `qml/`、`lib/cmake/KF6I18n/` 里有无 I18nQml 目标、`include/KF6/KI18n/` 里有无 klocalizedqmlcontext.h；三者皆无即为 KF6::I18nQml 未发布，不是配方参数问题。(2) 打补丁把使用点换成核心库的 KLocalizedContext：删除 `#include <KLocalizedQmlContext>` 与 `KI18N_VERSION >= QT_VERSION_CHECK(6, 8, 0)` 分支，统一 `engine->rootContext()->setContextObject(new KLocalizedContext(engine))`（QML 侧 i18n()/xi18n() API 表面不变，功能等价，非 stub）。(3) **必须同时**在目标上放回 deprecated 声明，否则头文件被 #if 掉：`target_compile_definitions(<target> PRIVATE KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT=0)`；不要为了它去掉 ecm_set_disabled_deprecation_versions（那会连带放开全部 KF 弃用面）。(4) 若源码里本就有 `if(TARGET KF6::I18nQml)` 之类的条件链接，保持不动（该目标不存在时自动跳过）。(5) 不要为此在本 PR 里捎带修改 ki18n 配方（W2/R36：依赖问题须独立 PR）；补丁内注释写明"制品仓未发布该模块"与先例包，便于后续 I18nQml 发布后回收补丁。(6) 注意 QML 应用的运行期配套：QML 场景通常装在 share/<app>/qml 并由 QStandardPaths::AppDataLocation 解析，消费方需 `XDG_DATA_DIRS` 指向包 share 目录、`QML2_IMPORT_PATH` 指向依赖 qml 目录（本包 package_info() 的 runenv_info 已导出）。

**修复命令**:
```
grep -rn "KLocalizedQmlContext" <src>/src && patch -p1 < patches/0002-canvaswidget-cpp-use-KLocalizedContext.patch
```

**验证**:
```
grep -rn "KLocalizedQmlContext\|setupLocalizedContext" <src>/src; readelf -d <pkg>/bin/<app> | grep NEEDED; conan create <archive> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --build="<pkg>/*"
```
