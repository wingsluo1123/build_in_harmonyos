# E3303: pip --target 安装 OHOS 平台 wheel 时扩展后缀不匹配导致模块无法导入

## 基本信息
- **严重度**: 2
- **类别**: python, package, pip
- **作者**: 080B

## 错误特征
```
ImportError: cannot import name _imaging from PIL|WARN: pillow via ohos wheel unavailable: pip install failed|ERROR: When restricting platform and interpreter constraints using --python-version, --platform, --abi, or --implementation, either --no-deps must be set, or --only-binary=:all: must be set|PIL unavailable: tests/test_utils.py cannot be collected
```

## 根因分析
鸿蒙 PC 解释器的 importlib.machinery.EXTENSION_SUFFIXES 只有 .cpython-312.so / .abi3.so / .so，而 OHOS 适配版 wheel 里的扩展模块名带完整平台标签，例如 PIL 的 _imaging.cpython-312-aarch64-linux-ohos.so；文件名不在查找后缀列表内，import PIL.Image 就报 cannot import name _imaging。只删 -linux-ohos 会得到 _imaging.cpython-312-aarch64.so，仍不是合法后缀，必须整体重写为本解释器自己的 cpython 标签 _imaging.cpython-312.so。另一半坑在 pip：带 --platform（或 --python-version/--abi/--implementation）约束时 pip 强制要求同时给出 --no-deps 或 --only-binary=:all:，否则直接 ERROR 退出（rc=1），wheel 根本装不上。两件事叠加的结果是本地因宿主已装 pillow 看不出问题，CI 上 pillow 装不上或装上也导入不了，连带把依赖 PIL 的上游测试文件整份丢弃，测试数量被静默裁剪。

## 推荐方案
**方法**: only-binary-all-plus-suffix-normalise

**说明**: 两手同时做：一是带 --platform 装 wheel 时必须同时带 --only-binary=:all:（或 --no-deps），否则 pip 直接拒绝；二是装完遍历目标目录，把 .so 文件名里外来的平台标签（aarch64-linux-ohos 等）重写成本解释器的 cpython 标签（形如 .cpython-312.so），重写规则按 sys.version_info 的 major.minor 生成并锚定，避免误改其他 Python 版本的标签或已合法的文件名；三是在 CI 场景用 python -S 做一条不依赖 site-packages 的导入断言，确认扩展真的可导入，别让宿主已装同名包掩盖问题。

**修复命令**:
```
pip install --no-compile --target=$SITE --platform ohos_aarch64 --only-binary=:all: pillow
```

**验证**:
```
python3 -c "import importlib.machinery as m; print(m.EXTENSION_SUFFIXES)"; pip install --no-compile --target=<dir> --platform ohos_aarch64 --only-binary=:all: pillow && python3 -S -c "from PIL import Image; print(Image.__version__)"
```
