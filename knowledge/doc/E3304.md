# E3304: 纯 Python 包消费者测试覆盖 PYTHONPATH，本地全绿而 CI 全红

## 基本信息
- **严重度**: 2
- **类别**: python, conan, testing
- **作者**: 57EA

## 错误特征
```
ModuleNotFoundError: No module named (click|urwid|tomlkit|soupsieve)|bin/toot: rc=1|Traceback (most recent call last)|Error 1 while executing|conan create failed at test_package
```

## 根因分析
纯 Python 包的 test_package 常把包根塞进子进程环境，写法多为 env[PYTHONPATH] = pkg。这是覆盖而非追加，会把 conanrun（VirtualRunEnv 生成的 conanrunenv-release-*.sh）注入的全部依赖路径整条丢掉。开发机上宿主解释器的 site-packages 往往已有 click/urwid/requests，子进程照样 import 成功，本地 conan create 全绿；CI worker 是干净环境，解释器里没有这些三方包，同一段代码立刻 ModuleNotFoundError，表现为 bin/<tool> 子进程 rc=1、test_package 失败。判别方法：用 python -S（不加载 site-packages）重跑被测二进制，依赖只来自 conanrun 的 PYTHONPATH 时应仍为 rc=0；若覆盖了 PYTHONPATH 则必然 ModuleNotFoundError。注意 conanrun 确实导出了完整依赖路径（实测 17 条，click 在内），不要采信 conanrun 的 PYTHONPATH 只影响子进程、脚本自身不继承 之类判断，据此覆盖环境变量正是缺陷本身。

## 推荐方案
**方法**: prepend-not-overwrite-and-isolated-runtime-assert

**说明**: 测试代码构造子进程环境时，把包根 prepend 到继承来的 PYTHONPATH 之前（保留全部依赖条目），不要整体赋值覆盖；同时在 test_package 里增加一条隔离断言，用 sys.executable 加 -S 重跑被测二进制并要求 rc=0，把本地与 CI 的判别条件固化进测试，避免宿主 site-packages 掩盖缺陷、也避免依赖环境差异导致的假绿。

**修复命令**:
```
PYTHONPATH=<pkg> python3 -S bin/<tool> --version
```

**验证**:
```
PYTHONPATH=<pkg_folder> python3 -S bin/<tool> --version; echo rc=$? ; . conanrun.sh && PYTHONPATH=<pkg_folder>:$PYTHONPATH python3 -S bin/<tool> --version; echo rc=$?
```
