# E3305: Conan 2 未给 python-require 强制 run trait，传递 Python 依赖被 BINARY_SKIP 跳过

## 基本信息
- **严重度**: 2
- **类别**: python, conan, dependency
- **作者**: 8794

## 错误特征
```
SKIPPED|BINARY_SKIP|ModuleNotFoundError: No module named '(requests|chardet|soupsieve|idna|urllib3|certifi)'|ERROR: Missing prebuilt package
```

## 根因分析
Conan 2 的 requires.process_package_type() 只对 application/shared-library/static-library/header-library/build-scripts 五类做 trait 强制（set_if_none），PackageType.PYTHON("python-require") 不在 if/elif 链中 → 该节点的 run trait 保持 None 即视为 False。graph_binaries._skip_binaries() 于是判定“本节点不在 root 的 run 可达集内”，把传递的 python-require 依赖标为 BINARY_SKIP、不拉取二进制也不生成其 runenv。表现：conan create 日志出现 SKIPPED，test_package 或下游 import 时 ModuleNotFoundError；若配方自身的直依赖是 python-require，同样可能因未显式声明 run=True 而丢失运行时环境。旧式 Conan 1.x 配方用 self.env_info.PYTHONPATH.append() 在 Conan 2 已完全失效（no-op），无法补救。

## 推荐方案
**方法**: explicit-run-trait-and-direct-requires

**说明**: 在消费者配方里双重补齐：①对每个 conan 直依赖显式写 self.requires("<name>/<ver>", run=True)，绕过 process_package_type 对 python-require 的 trait 缺口；②把传递的运行时依赖（那些只被依赖包 require、本配方不直接 import 的）逐条提升为本配方直依赖并同样标 run=True，让它们进入 root 的 run 可达集，不再被 BINARY_SKIP。修完用 conan graph info 确认 SKIPPED=0 且外部消费者 conan install 退出码 0。

**修复命令**:
```
conan graph info --requires=toot/0.52.1@ohpcd/stable -pr:a ci/conan/profiles/ohos-aarch64 -f json | grep -o '"binary": "BINARY_SKIP"' | wc -l   # 期望 0
```

**验证**:
```
conan graph info --requires=<pkg>/<ver>@<user>/<channel> -pr:a <profile> -f json | python3 -c "import json,sys; d=json.load(sys.stdin); print([ (k,v.get('binary')) for k,v in d['graph']['nodes'].items() if 'SKIP' in str(v.get('binary'))])"
```
