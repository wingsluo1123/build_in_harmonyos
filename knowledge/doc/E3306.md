# E3306: 上游集成测试需外部服务时以 skip 交差导致执行率不达标——用配方自带 stdlib 桩服务真实执行

## 基本信息
- **严重度**: 3
- **类别**: python, conan, testing, review
- **作者**: unknown

## 错误特征
```
SKIPPED|116 skipped|36 passed|上游测试用例通过率|Rule 4 condition 2|FAIL|TOOT_TEST_BASE_URL not set|ValueError: stderr not separately captured
```

## 根因分析
上游 tests/integration/ 用 fixture 检查外部服务环境变量（如 TOOT_TEST_BASE_URL），缺失时 pytest.skip 整个目录。适配者把它当"上游既有设计、环境不具备"如实申报 skip，于是申报 152 条只执行 36 条（24%），触发审核规则 4 条件 2 FAIL。真实原因不是"跑不了"而是"没人给它搭环境"：无需 Rails/postgres/redis/es，只需要一个能按 Mastodon REST 语义应答的 loopback HTTP 服务。次生陷阱：click 8.1.x 的 CliRunner 默认 mix_stderr=True，取 Result.stderr 抛 ValueError，会让 7 条集成用例以"看似桩的问题"形式失败——测试框架版本问题会伪装成执行率问题。

## 推荐方案
**方法**: recipe-shipped-stateful-stdlib-api-stub

**说明**: 在配方目录新增 test_support/<name>_api_stub.py：纯 stdlib（http.server/socketserver/json/re/struct/uuid/datetime）实现的有状态 REST 桩，ThreadingHTTPServer + HTTP/1.1 + Content-Length，覆盖上游测试所依赖的端点。export_sources() 用 copy(self,"test_support/**",src=recipe_folder,dst=export_sources_folder,keep_path=True) 导出（package() 不拷贝，不进包）。build() 里 Popen 启动 → HTTP 轮询就绪（20s，每轮先查 proc.poll()）→ 设 TOOT_TEST_BASE_URL → 跑 pytest → finally terminate()。桩以 --verbose 落访问日志，构建日志打印 served N request(s) 作为网络真实性留痕；起不来必须抛 ConanException 附日志尾部，禁止退化成 skip。分母口径改为：执行覆盖率=实际执行/收集，通过率=passed/收集。

**修复命令**:
```
python3 test_support/mastodon_api_stub.py --host 127.0.0.1 --port 3000 --verbose &  TOOT_TEST_BASE_URL=http://localhost:3000 python3 -m pytest tests -q -rs
```

**验证**:
```
TOOT_TEST_BASE_URL=http://localhost:3000 python3 -m pytest tests -q -rs; python3 -m pytest tests --collect-only -q | tail -1
```
