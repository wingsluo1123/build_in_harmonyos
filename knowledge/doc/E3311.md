# E3311: 上游改写 CMakeDeps imported target 的 INTERFACE_LINK_LIBRARIES 会抹掉库文件路径本身，链接期该库符号全部未定义

## 基本信息
- **严重度**: 3
- **类别**: cmake, linking, cross-compile, conan, static-library
- **作者**: unknown

## 错误特征
```
ld\.lld: error: undefined symbol: rocksdb::|undefined reference to [`']rocksdb::|undefined symbol: .*::.*\(\).*referenced by.*CMakeFiles
```

## 根因分析
Conan 2 CMakeDeps 把依赖库文件路径（lib<dep>.a）连同传递依赖一起编码在生成的 imported target 的 INTERFACE_LINK_LIBRARIES 属性里（生成表达式形式）。上游若用 set_target_properties(<Dep>::<dep> PROPERTIES INTERFACE_LINK_LIBRARIES "…;Threads::Threads") 改写该属性（常见动机：修正上游自带 CMake config 里写死的传递依赖），会把 CMakeDeps 编码的库路径本身一并抹掉——不是“少链几个传递依赖”，而是整个库不再参与链接，链接期报该库全部符号 undefined（sortmerna 4.3.7 实测：ld.lld 报 undefined rocksdb::DB::Open / ReadOptions / DBOptions::IncreaseParallelism 等，全部 referenced by 本包 .obj）。

## 推荐方案
**方法**: patch-out-interface-rewrite

**说明**: 最小补丁删除（或按条件旁路）上游的 set_target_properties(... INTERFACE_LINK_LIBRARIES ...) 改写块，让 CMakeDeps 生成的完整链接接口生效；若上游本意是裁剪传递依赖，应在消费方 conanfile 里用 CMakeDeps 属性（cmake_target_name / components）或上游自有选项表达，而不是改写 target 属性。

**修复命令**:
```
conan create archives/s/sortmerna/4.3.7 -pr:h=ohos-local -pr:b=ohos-local --build=missing
```

**验证**:
```
grep -Rn "set_target_properties" --include=CMakeLists.txt --include=*.cmake . | grep INTERFACE_LINK_LIBRARIES
```
