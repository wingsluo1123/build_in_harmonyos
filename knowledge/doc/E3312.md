# E3312: Python 复刻构建驱动在受限 OHOS worker 上撞 fork 压力（BlockingIOError EAGAIN）：并发上限 + 免 shell + 瞬时错误有限重试

## 基本信息
- **严重度**: 2
- **类别**: platform, build-system, toolchain, conan, environment
- **作者**: unknown

## 错误特征
```
BlockingIOError: \[Errno 11\] Resource temporarily unavailable|\[Errno 11\] Resource temporarily unavailable
```

## 根因分析
OHOS worker 对进程创建有管控（环境含 AppSpawnCheckUnexpectedExitCall 等），进程/pipe 资源紧张时 fork()/pipe() 返回 EAGAIN。配方 build() 用 ThreadPool(N=CPU 数) 并发执行编译命令，且命令经 shell=True 下发——每条命令因此产生 /bin/sh 与编译器两个进程，瞬时进程数可达 2N；一旦触顶，subprocess.run 抛 BlockingIOError: [Errno 11] Resource temporarily unavailable，异常从 pool.imap 的消费循环冒出，build() 直接失败。同一份代码上一轮 CI 通过、下一轮失败（间歇性）即典型特征：这是环境资源压力，不是代码/源码缺陷。

## 推荐方案
**方法**: cap-jobs-argv-no-shell-bounded-retry

**说明**: 三件事一起做：(1) **并发收敛**：并发取 min(CPU, 4)（build_jobs 只作上限参考，不直接当并发数）；(2) **免 shell**：编译/链接命令用 argv 列表下发（subprocess.run([...])，不用 shell=True），每条命令只产生 1 个进程、也免去手工引用路径；(3) **对瞬时 spawn 错误有限重试**：只对 errno ∈ {EAGAIN, ENOMEM, EMFILE, ENFILE}（BlockingIOError 属 OSError 子类）重试 3 次、退避 1s×n，并把 [retry i/3] 与 errno 写进构建日志；其它 errno（如 ENOENT）立即抛出，编译/链接自身失败照旧判负——**不掩盖真实错误**。实测：本包 68 TU、并发 4，本地与 CI 同型构建稳定通过。

**修复命令**:
```
conan create archives/x/xd/5.00.03 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
conan create archives/x/xd/5.00.03 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
