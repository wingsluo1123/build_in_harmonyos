# E3313: 遍历容器某元素的字符同时 push_back 同一容器（SSO 缓冲随 vector 重分配搬移）——libstdc++ 侥幸通过、libc++/OHOS 读到乱码并 SIGTRAP

## 基本信息
- **严重度**: 3
- **类别**: portability, libc, c++, compilation, memory
- **作者**: unknown

## 错误特征
```
Signal 5 \(core dumped\)|Initial characters of directories:.*[^ -~]
```

## 根因分析
Command::splitBase() 先取 `front().begin()+1 .. front().end()` 迭代器，再在回调里 `push_back(string(1, ch))` 修改同一个 vector< string>。push_back 触发重分配时，vector 会把已有元素（含 string 对象）搬移到新缓冲；而短字符串（本例 "0zzz" 的 "zzz"，SSO）的字符数据就存在 string 对象内部，搬移即让先前取得的迭代器失效。此后回调从失效地址读字符 → 读到乱码（CI 日志 `Initial characters of directories: z z <乱码>`）→ 拼出畸形 glob 模式 → 崩溃（rc=133 = Signal 5 / 128+5）。libstdc++ 的 SSO 布局/搬移顺序不同，常"看起来正常"，因此这类自失效 UB 往往只在 libc++/OHOS 上暴露，且表现为时好时坏。

## 推荐方案
**方法**: copy-before-mutate

**说明**: 先把被遍历的数据拷出来，再修改容器：`string const base{ front() }; for (size_t idx = 1; idx != base.size(); ++idx) push_back(string(1, base[idx])); front().resize(1);`。通用形态：任何 "for_each(container.front().begin(), ..., [&](auto v){ container.push_back(...); })" 都先 `auto snapshot = container.front();`（或先收集到临时 vector，再 append），保证遍历期间不依赖会被搬移的地址。本包以 patches/0002 落地，TC3（`xd 0zzz`，多字符拆分）作为回归检查。

**修复命令**:
```
conan create archives/x/xd/5.00.03 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
conan create archives/x/xd/5.00.03 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
