# E3314: icmake/icmbuild 驱动的上游项目（fbb-git 家族）在无 icmake 的 OHOS 环境下按 icmconf/CLASSES 复刻编译语义

## 基本信息
- **严重度**: 2
- **类别**: build-system, toolchain, cross-compile, conan, compilation
- **作者**: unknown

## 错误特征
```
bad interpreter: /usr/bin/icmake: no such file or directory|icmake: (command not found|No such file or directory)|icmbuild: (command not found|not found)|./build: line [0-9]+: (string|syntax error)
```

## 根因分析
上游（fbb-git: bobcat/xd/bisonc++/flexc++/yodl…）用作者自有构建工具 icmake 驱动：顶层 `build` 脚本本身就是 icmake 脚本（首行 `#!/usr/bin/icmake -t.`），program/libraries 目标再由 `icmbuild` 依据 icmconf/INSTALL.im/CLASSES 决定源集合、对象目录与链接库。OHOS 制品仓没有 icmake 配方、设备与 CI 也没有该工具，且 icmake 是自举型 C++ 程序（无官方预编译二进制可直接替代），于是 `./build program` 立刻以 rc=127 退出；又因为 build 是 icmake 语法而非 shell 语法，改用 `sh ./build` 只会得到 `string: command not found` 与 `syntax error near unexpected token '('` 的二次误导，掩盖真正根因。

## 推荐方案
**方法**: replicate-icmbuild-semantics-in-conanfile

**说明**: 不引入 icmake，在 conanfile.py 内用 Python 复刻 icmbuild 语义（对上游源码零补丁）：(1) 解析 CLASSES（逐行、跳过 // 注释）得模块目录清单；(2) program 模式源集合 = 顶层 MAIN（main.cc）及顶层其余 *.cc + 各模块目录下 *.cc；libraries 模式 = 各模块目录分别产出 .a/.so，且公共头按 `<class>/<class>` 用 catFile 语义（`#include "x.f"` 行内联展开）生成；(3) 每个 TU 以「自身所在目录 + 源码根」为包含根编译（模块内 `#include "xxx.ih"` 依赖同目录，main.ih 形如 `#include "dir/dir.h"` 依赖源码根）；(4) 链接按 icmconf 的 ADD_LIBRARIES（fbb-git 家族多为 bobcat）追加 `-l<bobcat>`，保留 INSTALL.im 的 -Wall/-Werror/-pthread 语义（实测 OHOS clang15 零告警，无需放松 -Werror）；(5) 复刻 `./build clean` 语义：build() 开头清空对象目录，避免残留 .o 参与链接造成重复符号；(6) 编译器/ar 取自 Conan conf（tools.build:compiler_executables），不经 shell 环境变量，并按 E2175 给编译/链接子进程注入 realpath(cxx)/../lib（SDK lld 需要 libxml2.so.16）。

**修复命令**:
```
conan create archives/x/xd/5.00.03 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
sh -c 'cd "$(mktemp -d)" && tar xzf <xd_5.00.03.orig.tar.gz> && cd xd-5.00.03 && ./build program; echo rc=$?'
```
