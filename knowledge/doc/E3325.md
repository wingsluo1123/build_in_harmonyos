# E3325: test_package 逐个 import 上游 C 扩展时不得硬编码"哪些模块需要 numpy"之类的分组——父包 __init__ 也会在缺依赖时 raise（实测 Bio.motifs._pwm 漏网）；应由包自抛异常分类：MissingPythonDependencyError→needs-numpy、E212 加载签名→env-limited、其余→真失败 raise；并加台账断言（三类之和=总数）与 HAVE_NUMPY 矛盾检查

## 基本信息
- **严重度**: 2
- **类别**: python, conan, packaging, testing, dependency-cascade
- **作者**: unknown

## 错误特征
```
Bio\.MissingPythonDependencyError: Install NumPy|ModuleNotFoundError|ImportError while importing|ImportError: .*requires numpy
```

## 根因分析
上游包把"缺某依赖"实现为**包级异常**：不只直接模块，其父包 __init__.py 在 import 子模块时也会先检查依赖并 raise（biopython：Bio/Align/__init__.py、Bio/motifs/__init__.py 都在缺 numpy 时抛 MissingPythonDependencyError）。按"哪些模块需要 numpy"手工分组必然漏——第一轮把 5 个 Bio.Align.* 挪进 numpy 分支后，Bio.motifs._pwm 仍在 CI 实测翻车：Bio.MissingPythonDependencyError: Install NumPy if you want to use Bio.motifs.。名单是开放集合，源码推导不如让运行时自己说话。

## 推荐方案
**方法**: classify-by-raised-exception-with-ledger-assertion

**说明**: import 循环里按异常分类而非按模块名单：type 名为 MissingPythonDependencyError 或消息含 "nstall NumPy" → need_numpy（该能力需 numpy，与本包适配无关）；消息含 "Error loading shared library" 或 "symbol not found" → env_limited（E212 族：HMDFS 拒载用户可写路径 .so）；其余异常 → print 原文并 raise（真失败不吞）。加载成功者校验 __file__ 确为 .so（防把纯 py 垫片当扩展计入）。末尾两道硬断言：①台账——loaded+env_limited+need_numpy 必须等于枚举总数（任何"消失的扩展"不许溜过）；②矛盾——HAVE_NUMPY 为真却仍有模块报缺 numpy 时 raise（探测与包口径打架不许放行）。

**修复命令**:
```
python -c "import importlib; importlib.import_module('Bio.motifs._pwm')"  # 复现漏网形态
```

**验证**:
```
python - <<'PY' 前置 sys.path 后逐个 importlib.import_module(EXTS)，打印三类清单; assert len(loaded)+len(env_limited)+len(need_numpy)==len(EXTS)
```
