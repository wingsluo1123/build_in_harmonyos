# E3328: Spring Boot fat jar（layout=ZIP）MANIFEST 的 Main-Class 是 org.springframework.boot.loader.launch.PropertiesLauncher 而非 JarLauncher，Start-Class 才是应用主类；断言写错 loader 类名会导致 test_package A8 误报

## 基本信息
- **严重度**: 1
- **类别**: compat, build-system
- **作者**: E329

## 错误特征
```
Main-Class: org\.springframework\.boot\.loader\.launch\.PropertiesLauncher|Start-Class:
```

## 根因分析
spring-boot-maven-plugin 的 layout 决定启动器：JAR layout → JarLauncher；ZIP layout（keycloak-config-cli 6.4.0 pom 显式配置，支持 -Dloader.path 追加 classpath）→ PropertiesLauncher；WAR → WarLauncher。Spring Boot 3.x 的 loader 包为 org.springframework.boot.loader.launch.*（2.x 旧包名 org.springframework.boot.loader.*）。应用真正的主类在 Start-Class 头（本包 de.adorsys.keycloak.config.KeycloakConfigApplication，非直觉的 Main）。另外 pom <finalName>${project.artifactId}</finalName> 使产物 jar 名不带版本号（keycloak-config-cli.jar）。这些必须真机实测 MANIFEST 后写入断言，凭经验猜 JarLauncher/Main 类名会写错。

## 推荐方案
**方法**: assert-actual-manifest

**说明**: test_package 断言以实测 MANIFEST 为准（Main-Class 断言到具体 loader 全类名 + Start-Class 断言到应用主类），不凭 Spring Boot 经验假设

**修复命令**:
```
unzip -p "$JAR_PATH" META-INF/MANIFEST.MF | grep -E "^Main-Class:|^Start-Class:"
```

**验证**:
```
unzip -p libexec/<app>.jar META-INF/MANIFEST.MF | grep -E "Main-Class|Start-Class" → 与 test.sh A8 断言逐字一致
```
