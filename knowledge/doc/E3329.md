# E3329: OHOS 真机无 Docker daemon → 依赖 Testcontainers 的 failsafe IT 必须 -DskipITs 跳过；同时 Mockito 5 inline mock maker 在 OHOS 上 JVM 动态 attach 机制不可用，surefire argLine 需预装载 -javaagent:<byte-buddy-agent.jar>

## 基本信息
- **严重度**: 3
- **类别**: platform, limitation, ohos
- **作者**: B32B

## 错误特征
```
Could not find a valid Docker environment|docker\.sock|Mockito.*inline.*(attach|ByteBuddyAgent)
```

## 根因分析
两个独立根因叠在同一测试阶段：(1) 41 个 *IT 集成测试基于 testcontainers 1.20.3（docker-java 3.4.0），需经 Docker Engine API（/var/run/docker.sock）拉起 Keycloak 容器；OHOS 真机未安装 Docker（which docker rc=1），failsafe 阶段必然失败 → 用上游支持的 -DskipITs 参数跳过（上游 CI ubuntu-latest 有 Docker，可正常运行，属平台差异非代码问题）。(2) Mockito 5 默认 inline mock maker 通过 JVM Attach API 动态挂载 byte-buddy-agent；OHOS 环境的 attach 机制不可用（ByteBuddyAgent.install() 失败），surefire 阶段 mock 相关用例报错 → 修复为在 surefire argLine 中显式 -javaagent 预装载本地 m2 仓库中的 byte-buddy-agent jar（keycloak-metrics 7.0.0 已验证同源根因与同修法）。

## 推荐方案
**方法**: skipITs-plus-javaagent

**说明**: 构建命令 -DskipITs 跳过 failsafe；surefire <argLine>（或 -DargLine）注入 -javaagent:$HOME/.m2/repository/net/bytebuddy/byte-buddy-agent/<ver>/byte-buddy-agent-<ver>.jar（版本从 mvn dependency:tree 的 mockito 依赖解析）

**修复命令**:
```
./mvnw -B -ntp clean verify -Djava.version=17 -DskipITs -DargLine="-javaagent:$HOME/.m2/repository/net/bytebuddy/byte-buddy-agent/1.14.x/byte-buddy-agent-1.14.x.jar"
```

**验证**:
```
which docker（rc=1 即无 Docker）；grep -rn "ByteBuddyAgent\|mockito" pom.xml（确认 inline 依赖）；修复后 surefire 90/90 PASS 且 failsafe 被跳过（无 IT 执行行）
```
