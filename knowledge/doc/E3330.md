# E3330: import.files.locations 条目走 Spring glob 解析且 filterExcludedResources 默认排除隐藏目录（dot 目录）下的文件，fixture 位于 .atomcode 等隐藏目录下必须配 --import.files.include-hidden-files=true，否则报 "No files matching"

## 基本信息
- **严重度**: 3
- **类别**: compat, limitation
- **作者**: FBA0

## 错误特征
```
No files matching '.*'!|InvalidImportException
```

## 根因分析
KeycloakImportProvider.readFromLocations 对每个 location 调 patternResolver.getResources(resourceLocation)（Spring glob 解析器，支持 *.json 通配），随后 filterExcludedResources 过滤：当 importConfigProperties.getFiles().isIncludeHiddenFiles()==false（默认）时，file.isHidden() 或 FileUtils.hasHiddenAncestorDirectory(file)（任一祖先目录名以 . 开头）的资源被整体排除，过滤后 0 个资源 → 抛 InvalidImportException("No files matching '<location>'!")。与文件是否存在无关——文件明明存在，只因路径经过隐藏目录（如 /…/.atomcode/skills/…）被排除。另注意：路径完全不存在时走的是另一分支（UrlResource 直读 → FileNotFoundException），两种失败签名不同，排障时先分清。

## 推荐方案
**方法**: include-hidden-files-flag

**说明**: 调用时追加 --import.files.include-hidden-files=true（Spring relaxed binding，等价 includeHiddenFiles）

**修复命令**:
```
java -jar keycloak-config-cli.jar … --import.files.include-hidden-files=true --import.files.locations=$CFG
```

**验证**:
```
对同一文件对比两次运行：不带与带 --import.files.include-hidden-files=true，前者 No files matching、后者进入 Keycloak 连接阶段 → 命中本模式
```
