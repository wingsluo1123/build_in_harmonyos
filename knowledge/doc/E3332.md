# E3332: ohc E017 只对 github.com URL 注入 ghfast.top 镜像且写 .ghfast-bak；镜像不可达时 conan create 下载超时，崩溃残留的 .ghfast-bak 还会在下次启动"恢复"覆盖手工修改的 conandata.yml

## 基本信息
- **严重度**: 3
- **类别**: ohos, network, build-system
- **作者**: 461D

## 错误特征
```
ghfast\.top.*(timed out|timeout)|conandata\.yml\.ghfast-bak
```

## 根因分析
ohc 管线（防 E017 GitHub 网络不稳）在 conan create 前把 conandata.yml 中匹配 github.com 的 URL 临时改写为 ghfast.top 镜像前缀，原文件备份为 conandata.yml.ghfast-bak，构建后回滚。两个陷阱：(1) 注入只匹配 github.com URL，codeload.github.com 形态不命中——在 ghfast.top 从当前设备 connect timeout 不可达的网络环境下，github.com URL 必被劫持到不可达镜像导致下载超时，而 codeload 直连可达；(2) 若构建中途崩溃/被杀，.ghfast-bak 残留，下次 ohc 启动检测到残留会执行"恢复上次崩溃残留"逻辑，用 bak 内容覆盖 conandata.yml——直接吞掉期间的手工修改，且用户无感知（日志仅一行 ℹ️）。

## 推荐方案
**方法**: codeload-url-plus-bak-cleanup

**说明**: 网络侧用 codeload 裸 URL 形态避开注入匹配（配合 E429 的显式 filename）；每次重跑前删除 conandata.yml.ghfast-bak 残留并核对 conandata.yml 内容未被回滚覆盖

**修复命令**:
```
rm -f <archive>/conandata.yml.ghfast-bak && grep -n "url:" <archive>/conandata.yml
```

**验证**:
```
ls <archive>/*.ghfast-bak（存在即有崩溃残留）；grep -c ghfast <archive>/conandata.yml（构建后应回 0）；重跑前对比 conandata.yml 与手工版本差异
```
