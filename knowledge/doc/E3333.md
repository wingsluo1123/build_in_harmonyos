# E3333: codeload 裸 tarball URL 基名无扩展名时，conan get() 按 zip 处理触发 BadZipFile，conandata sources 必须显式声明 filename

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system
- **作者**: 3328

## 错误特征
```
BadZipFile: File is not a zip file|Error in source\(\) method
```

## 根因分析
GitHub codeload 裸 URL（https://codeload.github.com/<org>/<repo>/tar.gz/refs/tags/<tag>）的 URL 基名是 tag 名（如 v6.4.0）而非文件名，不带 .tar.gz 扩展名。conan 2.x 的 get()/unzip() 按下载文件的扩展名识别解压格式，无扩展名时回退按 zip 处理，gzip 内容触发 zipfile.BadZipFile（"File is not a zip file"），conan create 在 source() 阶段失败（Error in source() method, line N）。下载字节本身完全正确（sha256 一致），纯文件名识别问题。

## 推荐方案
**方法**: conandata-explicit-filename

**说明**: conandata.yml sources 段显式声明 filename: "<name>-<ver>.tar.gz"（get() 支持 filename 参数覆盖 URL 基名），URL 保持不变

**修复命令**:
```
编辑 conandata.yml: sources:\n  url: "https://codeload.github.com/<org>/<repo>/tar.gz/refs/tags/<tag>"\n  sha256: "<sha256>"\n  filename: "<repo>-<ver>.tar.gz"
```

**验证**:
```
对已下载文件执行 file <file> 确认为 "gzip compressed data"，同时 URL 基名无 .tar.gz → 命中本模式；修复后重跑 conan create 应通过 source() 阶段
```
