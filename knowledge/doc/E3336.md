# E3336: conan 2 对不可用二进制的兼容性回退只放宽 settings（如 cppstd）、不放宽 options：制品仓缺某个 options 变体时消费方只能每轮源码重编；发布该变体的唯一合规途径是新版本号（R37）

## 基本信息
- **严重度**: 2
- **类别**: conan, artifact-registry, options, package-id
- **作者**: unknown

## 错误特征
```
Forced build from source|posix_spawn: Resource temporarily unavailable|No compatible configuration found
```

## 根因分析
package_id 由 settings+options+依赖闭包共同决定；ohpcd 上 libfuse/3.18.2 只发布过默认变体（shared=False → 21b17f8b…），消费方 saunafs 显式 "libfuse/*:shared=True" 解析出 0726937e… 从未上传。conan 的回退不构造不同 options 的替代变体，于是每轮 Forced build from source；其中一轮死于 ninja posix_spawn EAGAIN（CI 机器资源耗尽），表象像偶发环境失败，实为"该变体缺制品"的确定性结果。版本级 conan list 显示"有制品"与此并不矛盾——有的是静态变体。

## 推荐方案
**方法**: publish-missing-variant-as-new-version

**说明**: 为缺失变体发新版本号（libfuse/3.18.2.1：源码与 4 个补丁和 3.18.2 完全相同，唯一差异 default_options.shared=True）；本地 conan create 产出的 package_id 恰为缺失的 0726937e…。制品发布后消费方把 require 改指新版本即命中制品。不要改消费方选型（退回 shared=False）来"绕开"——那是语义变更；也不要在消费方 PR 里顺手建依赖包（JC6 原子性）。

**修复命令**:
```
conan create archives/l/libfuse/3.18.2.1 -pr:h=<profile> -pr:b=<profile> --build=missing && conan list "libfuse/3.18.2.1:*" -r=ohpcd  # 合入发布后核对出现 0726937e…
```

**验证**:
```
conan list "libfuse/3.18.2:*" -r=ohpcd; conan graph info --requires=libfuse/3.18.2 -o "libfuse/*:shared=True" -pr:h=<profile> -pr:b=<profile> --format=json（两取值 package_id 对照）
```
