# E3339: "Fix at the test layer, keep FAIL semantics on real filesyst

## 基本信息
- **严重度**: P2
- **类别**: platform
- **作者**: unknown

## 错误特征
```
"QStandardPaths: runtime directory .* is not owned by UID|Runtime directory.*not matched|system: exit=35|Failed to create wl_display|Could not ensure runtime directory"
```

## 根因分析
"TWO independent traps make QStandardPaths::RuntimeLocation unresolvable in conan test_package runs on HarmonyOS shared storage: (1) conan's test() executes the test driver with env='conanrun', which REPLACES the host environment wholesale — an XDG_RUNTIME_DIR exported in the launching shell never reaches the test process, so QStandardPaths falls back to scanning $HOME and /tmp for pre-existing stale directories; (2) on hmdfs (the FUSE-style shared storage under /storage/Users), every created directory reports a FIXED owner UID (20001006, the shared-storage service) regardless of which UID created it — a test process running as UID 20020085 can never satisfy Qt's runtime-dir ownership check (owned by current UID + permissions 0700), so mkdir+chmod alone is futile and the check fails with exit 35 on every real filesystem path available (/, /data/local/tmp is inaccessible, /dev/shm unavailable)."

## 推荐方案
**方法**: "Fix at the test layer, keep FAIL semantics on real filesystems: (1) in the test_package conanfile, create the runtime dir under the build folder and inject it ON THE COMMAND LINE ('env XDG_RUNTIME_DIR=...' prefix) because env='conanrun' discards inherited variables; (2) in the test driver, apply the ownership check to whatever XDG_RUNTIME_DIR ended up effective — stat() it and, when st_uid differs from os.getuid(), treat the filesystem as shared-storage-style and degrade the system case to a SKIP with an explicit reason; on CI/real device filesystems the ownership check passes and the case still runs and fails hard if broken. Do NOT special-case the hmdfs UID value — detect the invariant (st_uid mismatch) instead."
