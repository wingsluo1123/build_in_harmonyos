# E3340: Sign a generated Asterisk menuselect host ELF before its first OHOS execution

## 基本信息
- **严重度**: 1
- **类别**: ohos, autotools, linking, security, build-generated-host-tools
- **作者**: ylinz
- **来源 PR**: 7632

## 错误特征
```
Permission denied.*menuselect|menuselect.*Permission denied|Error 126.*menuselect|Operation not permitted.*menuselect
```

## 根因分析
Asterisk builds the target-side menuselect ELF during the make graph and executes it immediately to generate menuselect.makeopts. On OHOS, chmod restores only the mode bit; the kernel still rejects an ELF without a valid .codesign section, so signing after a later build or packaging phase is too late.

## 推荐方案
**方法**: sign-generated-helper-before-first-execution

**说明**: After make creates the helper, classify it as ELF, copy it to a same-directory staging path, remove any stale .codesign section, self-sign to a second temporary path, restore execute bits, atomically replace the original, and only then invoke the make target that executes it.

**修复命令**:
```
build helper; llvm-objcopy --remove-section .codesign helper.signing; binary-sign-tool sign -inFile helper.signing -outFile helper.signed -selfSign 1; chmod a+x helper.signed; replace helper before first execution
```

**验证**:
```
git checkout a23d26ee75 && CI_PACKAGES="archives/a/asterisk-odbc/22.10.1" zsh ci/conan/build_and_test.sh
```
