# E3345: Missing library-owned Qt resources can masquerade as a headless test harness failure

## 基本信息
- **严重度**: 2
- **类别**: packaging, runtime, testing, environment
- **作者**: BAS1

## 错误特征
```
QWidget: Cannot create a QWidget without QApplication|Could not open icon resource file|This plugin does not support propagateSizeHints
```

## 根因分析
A library looks up installed RCC data through QStandardPaths but the isolated Conan prefix is absent from XDG_DATA_DIRS. Its missing-resource error path opens a modal widget even when the tested API is non-GUI, making QCoreApplication tests abort and QApplication tests hang.

## 推荐方案
**方法**: resource-path-before-headless-harness-change

**说明**: Do not infer a GUI requirement from an error dialog in otherwise non-GUI initialization. Verify the exact installed resource and its QStandardPaths search root, expose the relocatable package share directory via runenv_info, and use the same data path for upstream tests before package_info is available. Keep the original GUILESS test harness, strict bounded execution and all assertions; verify consumers with their generated runtime environment.

**修复命令**:
```
self.runenv_info.prepend_path("XDG_DATA_DIRS", os.path.join(self.package_folder, "share"))
```

**验证**:
```
Trace the resource lookup and error path, verify the installed RCC exists, prepend the current package share directory to XDG_DATA_DIRS while preserving prior entries, restore original test main and assertions, then require the full upstream suite and installed API consumer to exit normally.
```
