# E3354: Published wxWidgets 3.2.10 base binary is unlinkable and its wx-config records a foreign prefix

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, linking
- **作者**: iKalous_OscarP

## 错误特征
```
undefined symbol: wxMutex::Lock|undefined symbol: wxAppConsole|wx-config: No such file or directory|libiconv_open
```

## 根因分析
The registry wxwidgets/3.2.10 OHOS binary's bin/wx-config is a symlink to the builder's Conan cache, and the script bakes that absolute prefix plus a CMake generator expression for zlib. The static base archive also omits thread and console-app objects, so a real consumer fails at link with wxMutex, wxThread, wxAppConsole and wxStackWalker. A rebuilt base then needs libiconv.

## 推荐方案
**方法**: rebuild-wx-base-in-consumer

**说明**: Do not link the published base archive. Build wxWidgets 3.2.10 with wxUSE_GUI=OFF, wxUSE_THREADS=ON, sockets and net off, and point WX_CONFIG at a wrapper over that prefix. Link libiconv, zlib and expat, and stub musl's missing pthread_cancel.

**修复命令**:
```
cmake -DwxUSE_GUI=OFF -DwxUSE_THREADS=ON -DwxUSE_SOCKETS=OFF -DwxBUILD_TOOLKIT=gtk3
```

**验证**:
```
ls -l "$WX_PREFIX/bin/wx-config"; "$WX_PREFIX/bin/wx-config" --cxxflags; nm -C "$WX_PREFIX/lib"/libwx_baseu*.a | grep -c wxMutex::Lock
```
