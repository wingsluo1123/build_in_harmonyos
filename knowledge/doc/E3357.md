# E3357: 静态链接一个自身带静态初始化器的库时，可执行文件自己的目标文件总排在静态库之前，其 .init_array 先运行，使程序里依赖该库静态初始化的全局对象在库初始化完成前构造而启动即 SIGSEGV（exit 139、无任何输出）；把程序源码编成 STATIC 库并用 --whole-archive 放在依赖库之后链接即可修复

## 基本信息
- **严重度**: 2
- **类别**: cmake, linking, conan, runtime, static-library
- **作者**: unknown

## 错误特征
```
启动即 SIGSEGV / exit 139，程序无任何输出；gdb 无法 attach(ptrace) 时仍可用「删去全局对象即正常、加回即崩」二分定位；\.init_array 在可执行文件目标文件与依赖静态库中均非空
```

## 根因分析
链接器按输入文件顺序把各目标文件的 .init_array 拼接进最终映像。可执行文件自身的目标文件（如 nex_dome.cpp.o）永远排在它所链接的静态库（如 libindidriver.a）之前，于是程序里依赖框架静态初始化的全局对象（框架 defaultdevice.cpp.o / indilogger.cpp.o / sharedblob_parse.cpp.o 等带 .init_array）会在框架自己的初始化器之前被构造，读到尚未初始化的全局状态而崩溃。共享库场景不触发（加载器先跑共享库初始化），仅「可执行文件自身含全局对象 + 依赖库带静态初始化器 + 静态链接」三者同时成立才触发。最小复现：派生类构造体首行打点未执行，崩溃发生在基类构造器（成员初始化阶段）。

## 推荐方案
**方法**: own-source-as-archive-linked-after-dependency-with-whole-archive

**说明**: 把可执行文件自身的源码编成一个 STATIC 库；链接时用 -Wl,--whole-archive <own-lib> -Wl,--no-whole-archive 把它放在依赖框架静态库之后（可放进同一个 --start-group/--end-group）。这样框架的 .init_array 先执行，程序的全局对象在框架初始化完成后才构造。CMake 中用一个 file(WRITE ...) 生成的空 stub 源文件作为 add_executable 的源，避免 CMake 拒绝无源目标。

**修复命令**:
```
add_library(indi_nexdome_driver STATIC ${indi_nexdome_SRCS}); file(WRITE ${CMAKE_CURRENT_BINARY_DIR}/stub.c "/* empty */"); add_executable(indi_nexdome ${CMAKE_CURRENT_BINARY_DIR}/stub.c); target_link_libraries(indi_nexdome -Wl,--start-group ${INDI_LIBRARIES} ${INDI_NEXDOME_DEPS} -Wl,--end-group -Wl,--whole-archive indi_nexdome_driver -Wl,--no-whole-archive)
```

**验证**:
```
最小复现：clang++ -o t6.o -c t6.cpp；clang++ -o t6 -Wl,--start-group <libs> -Wl,--end-group t6.o  → SIGSEGV(139)；clang++ -o t6b -Wl,--start-group <libs> -Wl,--end-group t6.o 换序后正常。正式驱动：conan create（修复前 exit 139 无输出；修复后 RC=0，test.sh 7/7 + test_ohos.sh 12/12）
```
