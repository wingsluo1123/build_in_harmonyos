# E3360: OHOS/CI：make 直接 exec 上游 #!/usr/bin/env bash 脚本失败（Resource temporarily unavailable / Error 127）

## 基本信息
- **严重度**: P2
- **类别**: platform, ohos, build-system
- **作者**: 4943

## 错误特征
```
make: .*\.sh: Resource temporarily unavailable|Error 127.*make|\./tools/make-[a-z-]+\.sh.*no such|bad interpreter: /usr/bin/env
```

## 根因分析
上游构建脚本（tools/*.sh、Makefile 目标）shebang 为 '#!/usr/bin/env bash'。make 对无 shell 元字符的 recipe 行会直接 execve 该脚本，内核经 shebang 先 exec /usr/bin/env（OHOS 上为 toybox）再由其 exec bash；在 OHOS/CI（AppSpawn 沙箱）下该链失败，make 报 'make: tools/xxx.sh: Resource temporarily unavailable' 并 'Error 127'。本地开发机不受限（/usr/bin/env 可执行），故本地 W3 通过、远端 CI 失败。

## 推荐方案
**方法**: 不要依赖 shebang 执行上游脚本：① 配方改用显式 bash 调用顶层脚本（bash tools/make-xxx.sh），bash 自读脚本不触发 shebang；② 上游脚本内部若仍有 './tools/*.sh' 调用，用 patch 改为 'bash ./tools/*.sh'；③ 或按 E165 将 shebang 直接改为 /data/service/hnp/bin/bash（OHOS 无传统 /bin）。三者取其一即可，①+② 组合最稳（不硬编码设备路径）。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
head -1 tools/*.sh   # 确认 shebang；远端 CI 观察 'make: <script>: Resource temporarily unavailable' + Error 127；修复后 build 日志应出现 'bash tools/xxx.sh' 且脚本正常执行
```
