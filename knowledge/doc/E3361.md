# E3361: OHOS Node.js: WebAssembly-依赖的纯 JS 库禁用 --jitless；npm test.js 不传播 mocha 退出码

## 基本信息
- **严重度**: P1
- **类别**: ohos, testing, node-runtime
- **作者**: A5AD

## 错误特征
```
WebAssembly is not defined|typeof WebAssembly.*undefined|spawn mocha ENOENT|Only a single instance is supported
```

## 根因分析
OHOS 上 node 执行 JS 可能触发 V8 断言崩溃（E400），习惯性用 NODE_OPTIONS=--jitless 规避；但 --jitless 令 V8 关闭可执行内存，typeof WebAssembly 变为 undefined（实测 plain=object / jitless=undefined）。若被测 JS 库依赖 WebAssembly 制品（如 uBlock Origin 的 hntrie/biditrie/publicsuffixlist/lz4 wasm 引擎），--jitless 会让上游 wasm 用例直接 ReferenceError 失败。另：上游 platform/npm/test.js 用 promisify(spawn)('mocha',...) 却不检查子进程退出码，mocha 失败时 test.js 仍 exit 0。

## 推荐方案
**方法**: 对依赖 WebAssembly 的 JS 库：不要注入 NODE_OPTIONS=--jitless；以 plain node + (typeof WebAssembly==='object') 作可用性探针，构建期 fail-fast。运行上游测试时直接调用 mocha（node_modules/.bin/mocha --experimental-vm-modules）取真实退出码，勿依赖 test.js 的退出码。ubO SNFE 为单实例，serialize/deserialize 必须作用于同一实例。

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
node -e 'process.stdout.write(typeof WebAssembly)'   # plain=object / --jitless=undefined；另 node --jitless -e 'typeof WebAssembly' 复现 undefined
```
