# E3365: 自动回复循环抑制策略必须在有界展开后的逻辑邮件头上决策

## 基本信息
- **严重度**: 3
- **类别**: compat, portability, runtime, security
- **作者**: VAC1

## 错误特征
```
folded Auto-Submitted.*reply|folded Precedence.*reply|automatic response loop|policy header continuation bypass
```

## 根因分析
行式解析器在每次 fgets 返回的物理行上立即执行策略；当合法 RFC 5322 字段把值放到续行时，字段首行没有值而被提前忽略，续行也不会重新进入该字段分支，使 Auto-Submitted 或 Precedence 绕过自动回复抑制。单纯增大缓冲或特判某一个字段的一条续行没有建立统一逻辑字段边界，仍会被其他字段、多续行、CRLF 或越界输入绕过。

## 推荐方案
**方法**: bounded-logical-header-before-policy

**说明**: 先在固定上限内把字段首行及连续 FWS 续行重组为一个逻辑头，统一识别 LF/CRLF；只有完整逻辑头形成后才解析字段名和值并允许发送副作用。悬空续行、物理行截断和逻辑头溢出均失败关闭；Auto-Submitted 仅精确值 no 可继续，出站自动回复声明 Auto-Submitted: auto-replied。

**修复命令**:
```
Run the installed-command consumer matrix for ordinary mail, inline/folded policy fields, CRLF, exact no, oversized logical headers, real database throttling, and fork/pipe/exec reply capture.
```

**验证**:
```
Feed the installed responder equivalent single-line and folded Auto-Submitted/Precedence headers; observe the actual send side effect and throttle database; repeat with LF, CRLF and an over-limit logical header; then revert the unified unfold path and require the folded-policy cases to fail.
```
