# E3372: 上游"测试"未必是 pytest 套件：可能是一组自带 runner 的可执行脚本，探测依据不能用文件名 test*

## 基本信息
- **严重度**: 1
- **类别**: compat, portability, build-system
- **作者**: DA16

## 错误特征
```
未在 sdist 内探测到测试目录|no tests ran|file or directory not found: tests/|exit 1
```

## 根因分析
上游的"测试"未必是 pytest 套件：ppft 的 `ppft/tests/` 里是一组**可执行脚本**（auto_diff / callback / dynamic_ncpus / quicksort / reverse_md5 / sum_primes / sum_primes_functor），**没有任何 `test_*.py`**；官方跑法写在其 `tox.ini`（`{envpython} ppft/tests/__main__.py`），该 runner 把目录内除 `__*` 外的每个 `.py` 当**子进程**逐个执行，末尾 `exit 1 if any failed`。若按"文件名以 test 开头"探测（或直接上 pytest），必然"探测不到测试"→ 误判"上游无测试"并响亮失败；同时早期预估的测试期依赖（dill/pytest）也**并不需要**（实测这些脚本只 import math/sys/time/hashlib 与 ppft 自身），多装反而把构建绑上网络。
