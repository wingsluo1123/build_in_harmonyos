# E3383: 上游测试按源码树相对路径取值时，conan basic_layout 的 VPATH 构建会让 make check 假失败：改 folders.build='.' 做源码内构建

## 基本信息
- **严重度**: 2
- **类别**: autotools, conan, testing, layout
- **作者**: 20B5

## 错误特征
```
grep: \.\./src/.*No such file or directory|error: could not load font .*|make check.*FAIL.*check-.*|上游测试.*VPATH.*失败
```

## 根因分析
conan 的 basic_layout 默认把构建目录放在 build-release/ 子目录（srcdir != builddir），而相当多的 autotools 上游测试脚本用源码树相对路径取值（如 grep ../src/main.c、-d ../fonts、make -C ../fonts echo-fonts）。VPATH 构建下这些相对路径落在构建目录里、源码文件不在那儿，测试便以 'No such file or directory' / 'could not load font' 失败——不是平台缺陷，是构建布局错配。

## 推荐方案
**方法**: in-tree-build-via-folders-build-dot

**说明**: layout() 中 basic_layout(self, src_folder='.') 且 self.folders.build='.'，使 source_folder == build_folder（conan 默认 no_copy_source=False，源码已复制进 build_folder），上游测试脚本零改动即可通过（同 archives/a/adjtimex/1.29 先例）。

**修复命令**:
```
def layout(self): basic_layout(self, src_folder='.'); self.folders.build='.'
```

**验证**:
```
在默认 basic_layout 下 make check 应见 ../src/../fonts 路径类失败；改为 folders.build='.' 后同一 make check 原样 2/2 PASS
```
