# E3385: cmake 上游 CACHE PATH 默认绝对系统目录：Conan 前缀打包时 cmake --install 报 file cannot create directory

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, cmake, conan, install
- **作者**: 98B5

## 错误特征
```
file cannot create directory: /usr/lib/sysusers\.d|cmake --install.*cannot create directory.*/usr/lib|CMake Error.*file INSTALL cannot make directory
```

## 根因分析
上游 CMakeLists 用 set(SYSUSERS_DIR "" CACHE PATH ...) 之类的空默认值，随后回退到一个绝对系统路径（rdma-core 64.0 是 /usr/lib/sysusers.d），并用 install(FILES ... DESTINATION ${SYSUSERS_DIR}) 安装。Conan 打包时 cmake --install 以包目录为前缀，但绝对路径绕过了前缀重定位，安装器试图在真实根文件系统下创建 /usr/lib/sysusers.d 而失败（沙箱/无权限），整个 package() 阶段终止。

## 推荐方案
**方法**: override-absolute-cache-path-to-relative

**说明**: 在配方 generate() 里用 CMakeToolchain 覆盖该 CACHE PATH 为相对前缀的路径（tc.variables["SYSUSERS_DIR"]="lib/sysusers.d"），使 install(DESTINATION) 落在 Conan 包前缀内；不要用 DESTDIR（已废弃）或改写绝对路径。

**修复命令**:
```
tc.variables["SYSUSERS_DIR"] = "lib/sysusers.d"
```

**验证**:
```
在配方 generate() 中把该变量覆盖为相对路径后 conan create 应通过；检查产物树：ls <package>/lib/sysusers.d 存在 rdma-sysusers.conf，且没有向宿主根文件系统写入。
```
