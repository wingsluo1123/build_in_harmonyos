# E3389: OHOS sysroot 无 btrfs/ 平铺目录但自带内核 uapi；用两个薄 shim 头（btrfs/ioctl.h→<linux/btrfs.h>、btrfs/ctree.h→<linux/btrfs_tree.h>）+ -DBTRFS_FLAT_INCLUDES 即可编译，无需 libbtrfs-dev 或 btrfs-progs conan 包

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, headers, build-system, make
- **作者**: 2301_76770579
- **来源 PR**: 14867

## 错误特征
```
btrfs/ioctl\.h: No such file or directory|btrfs/ctree\.h: No such file or directory|'btrfs/ioctl\.h' file not found|'btrfs/ctree\.h' file not found|btrfs/kerncompat\.h
```

## 根因分析
btrfs 用户空间头本质是内核同一份 uapi：发行版的 <btrfs/ioctl.h> 即内核 include/uapi/linux/btrfs.h，消费者用到的磁盘结构（BTRFS_EXTENT_DATA_KEY、struct btrfs_file_extent_item、BTRFS_FILE_EXTENT_INLINE/PREALLOC）即 include/uapi/linux/btrfs_tree.h。OHOS SDK sysroot 自带这套 Linux uapi（两个头都在 usr/include/linux/），只是没有发行版惯用的 btrfs/ 平铺别名目录；而 conan 制品仓也没有 btrfs-progs 包。于是「找不到头」缺的不是内容而是路径别名——而 compsize 这类工具只用 ioctl 定义+结构体、不链接 libbtrfs，故纯头文件层面即可解决。

## 推荐方案
**方法**: shim-btrfs-headers-to-ohos-kernel-uapi

**说明**: generate() 里生成两个薄 shim 头：btrfs/ioctl.h -> <linux/btrfs.h>，btrfs/ctree.h -> <linux/btrfs_tree.h>，随 -I 暴露给编译；同时传 -DBTRFS_FLAT_INCLUDES=1 让上游 radix-tree.h 选其自带本地 kerncompat.h。零依赖、零链接库。

**修复命令**:
```
make CC=<clang> CPPFLAGS="-I<shim> -DBTRFS_FLAT_INCLUDES=1" -j1
```

**验证**:
```
printf '#include <btrfs/ioctl.h>\n#include <btrfs/ctree.h>\nint main(void){return 0;}' | clang --target=aarch64-linux-ohos --sysroot=<sdk>/sysroot -I<shim> -x c - -o /dev/null
```
