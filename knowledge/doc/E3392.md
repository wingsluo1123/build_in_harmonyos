# E3392: SIZE 尚未完成时，decoded 空 DATA 与 SUCC0 造成文件零进度

## 基本信息
- **严重度**: 2
- **类别**: python, runtime, testing, filesystem, api
- **作者**: F6EC

## 错误特征
```
"steps": [0, 0]|Unexpected end of file|Received empty file data
```

## 根因分析
trzsz 1.1.5 的文件数据循环只比较 step<size，真实EOF被编码为空DATA，接收端写空数据并返回SUCC0；双方step仍为0。及时空帧可结束每次recv_data并取消alarm，下次重新计时；消息完成不等于文件进度。

## 推荐方案
**方法**: reject-decoded-empty-data-during-incomplete-file

**说明**: sender在send_data前、receiver在file.write和SUCC确认前，均在while step<size循环内拒绝空bytes，抛现有TrzszError(trace=False)并沿原fail协议传播；保留合法空文件和MD5流程。

**修复命令**:
```
应用 archives/t/trzsz/1.1.5/patches 中由官方refresh-patch生成的双端guard补丁，再用同版三发行Conan包执行原unit与定向协议回归。
```

**验证**:
```
在本次Conan runenv运行 python3 progress_regression.py；原版固定源码使用同脚本 --baseline，以有限fail帧停止并留零进度前缀。
```
