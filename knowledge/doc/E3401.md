# E3401: dual-glib-provider-static-shadowing-in-autotools-consumer

## 基本信息
- **严重度**: 2
- **类别**: linking, dual-provider, glib, shadow, static
- **作者**: A458, 66B2

## 错误特征
```
GLib-GObject:ERROR:g_type_register_static: assertion failed: (static_quark_type_flags)|DT_NEEDED missing libglib-2.0.so.0|g_hash_table_lookup: assertion 'hash_table != NULL'
```

## 根因分析
gtk 图(glib shared)与 gstreamer 图(glib2 static)双提供者并存时，pkg-config Libs 中 glib2 目录排在 glib 目录之前，ld 优先拾取 glib2 的 libglib-2.0.a 静态链入消费者二进制；运行期 gtk 的 DT_NEEDED libglib-2.0.so.0 再加载共享 glib，进程内出现两份 glib 实例，GObject 类型系统初始化即 abort

## 推荐方案
**方法**: 全依赖库镜像进 la-free staging 目录（复制 lib*.a/lib*.so* 排除 .la），用 PkgConfigDeps 生成后重写所有 .pc 的 libdir 指向 staging——同目录内 ld 的 .so 优先于 .a 规则使共享 glib 必然胜出，静态 gstreamer/sqlite3/taglib 照常解析，.la stale 元数据（E236）同时被隔离。参考 archives/p/pragha/1.3.4/conanfile.py 的 _stage_dependency_libraries/_rewrite_generated_pkgconfig_libdirs
