# E3409: 测试不得依赖 Check START_TEST 宏生成的内部函数名

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, testing, dependencies
- **作者**: 7A1D

## 错误特征
```
invalid output: test_my_fn: debug|Check-generated test function name.*_fn
```

## 根因分析
Check 0.13 重写 START_TEST 后把测试体的 C 函数从参数原名改为带 _fn 后缀的内部符号；ladvd 仍把旧函数名硬编码为日志期望，而生产日志宏输出当前 __func__，因此使用已发布 check/0.15.2 时真实行为正确但上游测试稳定失败。宏参数形成的用例名是公开语义，宏展开后的 C 符号不是稳定接口。

## 推荐方案
**方法**: derive-self-referential-oracle-from-current-function

**说明**: 当被测日志有意输出当前函数名时，在同一测试函数中用 __func__ 构造期望值；保留对完整日志格式和消息的比较，并在完整上游测试套件中验证。

**修复命令**:
```
Replace the hard-coded generated function spelling with snprintf(expected, sizeof(expected), "%s: debug\\n", __func__), then run make check -j1.
```

**验证**:
```
Compare official Check 0.12.0 and 0.15.2 START_TEST expansions; run ladvd check_util once without patch 0010 to reproduce test_my_fn versus test_my, then with the __func__-derived oracle and run the complete make check -j1 suite.
```
