# E3411: "OHOS 上 /dev/fuse 存在但不可访问（open 返回 EACCES=13，不是 ENOENT）⇒ libfuse/fuse 的 mount 面（fuse_mount/fuse_loop/fusermount）运行期不可用；且 os.path.exists()/access(F_OK) 因 stat 失败返回 False（假阴性），能力面判别必须用 errno 而不能用存在性 API"

## 基本信息
- **严重度**: "3"
- **类别**: platform, detection, runtime, permissions, device-node
- **作者**: "主理-5 <主理-5@local>"
- **来源 PR**: "(本 PR)"

## 错误特征
```
"fuse: failed to open /dev/fuse.*Permission denied|Permission denied.*/dev/fuse|cannot open /dev/fuse.*EACCES|fusermount.*Permission denied|fuse_mount.*NULL|ls: /dev/fuse: Permission denied"
```

## 根因分析
"OHOS 用户态未向本进程开放 /dev/fuse 字符设备（节点存在但 open 返回 EACCES，内核亦未加载 fuse 模块）；平台按 SELinux/权限策略拒绝访问，与被适配包代码无关。叠加两个次生事实：存在性 API 在 EACCES 下返回 False（假阴性），以及 OHOS 忽略 chmod u+s（E046）使 fusermount 无法获得 setuid root。"

## 推荐方案
**方法**: "errno-probe-and-consistency-assert-runtime-capability"

**说明**: "以 open() errno 实测落运行期能力墙结论（EACCES/ENOENT 均记『打不开』），库面离线 API 照常交付并真断言；test_package 用『裸探针 + fuse_mount 一致性断言 + 两条负向对照（/dev/null 必成功、不存在路径必 ENOENT）』，CLI 只断言参数解析文本路径；notes.md/MANIFEST/PR 正文三处同源披露能力墙与未执行项，⛔ 不 mock 设备、⛔ 不谎称可挂载"

**修复命令**:
```
"真机: open('/dev/fuse',O_RDWR) 取 errno + os.path.exists 对照 + ls -l /dev/fuse + grep -i fuse /proc/modules + ls -l <pkg>/bin/fusermount（看 setuid 位）；test_package: 探针+一致性断言+负向对照；库面: fuse_version/fuse_opt_parse/fuse_parse_cmdline/fuse_lowlevel_new 离线真断言"
```

**验证**:
```
"python3 -c \"import os,errno\ntry:\n os.open('/dev/fuse',os.O_RDWR)\nexcept OSError as e:\n print('errno',e.errno,errno.errorcode.get(e.errno))\nprint('exists',os.path.exists('/dev/fuse'))\"; ls -l /dev/fuse; grep -i fuse /proc/modules; ls -l <pkg>/bin/fusermount"
```
