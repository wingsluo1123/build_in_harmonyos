# E3412: Conan路径变量首次define后prepend_path保留标量分隔类型

## 基本信息
- **严重度**: 1
- **类别**: build-system, conan, environment
- **作者**: A139

## 错误特征
```
Can.t locate Test/Harness.pm|define.*prepend_path.*space-joined
```

## 根因分析
Environment.define creates a scalar _EnvValue with space separator; later prepend_path uses setdefault and retains the first value type and separator.

## 推荐方案
**方法**: define-path-semantics-at-first-private-variable-definition

**说明**: Conan Environment先用define建立变量时会保存path=False和默认空格分隔；后续prepend_path通过setdefault沿用已有_EnvValue，不会自动将其改为路径列表。即使最初值已用os.pathsep拼接，追加后仍可能成为带空格的单一搜索目录。对实例私有且明确重建的路径变量，首次用define_path，再prepend_path；传递依赖导出继续采用路径追加，避免覆盖依赖图。

**修复命令**:
```
env.define_path("PERL5LIB", core_arch_value); env.prepend_path("PERL5LIB", source_lib)
```

**验证**:
```
Evaluate actual Conan EnvVars with OHOS settings and identical published Perl; scalar-first import rc2, path-first rc0; full original tests and native consumer/Harmony.
```
