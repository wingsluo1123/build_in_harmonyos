# E3414: OHOS toybox ps rejects BSD 'auxw' and truncates CMD with -A: shim to -ef for process-polling test suites

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, process-inspection, quirk, test-harness
- **作者**: 7206

## 错误特征
```
"ps: bad auxw|bad auxw|Inject shell is not running"
```

## 根因分析
OHOS ships toybox ps. It refuses the BSD-style invocation used widely by upstream bash test suites (ps auxw -> 'ps: bad auxw'), so a polling loop of the form 'ps auxw | grep -v grep | grep <marker> | awk {print $2} | wc -l' can never match. The toybox alternative -A prints only the process name (CMD truncated), so the marker grep still fails even though the process is alive. toybox -ef keeps the upstream assumptions: column 2 is the PID and CMD is the full command line.

## 推荐方案
**方法**: toybox-ps-bsd-syntax-shim

**说明**: Do not patch the upstream test sources. Prepend a PATH shim directory containing an executable ps that maps BSD spellings to toybox -ef (auxw/aux/auxww/empty -> -ef, otherwise pass arguments through unchanged) and exec /bin/ps. This preserves the upstream grep/awk column contract (PID in column 2, full command line) so the harness assertions keep their original meaning. Equivalent shims work for other GNU-only flags; document each one in the adaptation report.

**修复命令**:
```
printf '#!/bin/sh\nargs=""\nfor a in "$@"; do case "$a" in auxw|aux|auxww|"") args="$args -ef" ;; *) args="$args $a" ;; esac; done\nexec /bin/ps $args\n' > bin/ps && chmod +x bin/ps && PATH=$PWD/bin:$PATH ps auxw | awk '{print $2}'
```

**验证**:
```
ps auxw | head -1   # toybox: 'ps: bad auxw' ; then: ps -ef | set -- $(cat); echo $2  # column 2 is the PID
```
