# E3418: 重复Conan create前封存瞬时原始测试记录，防止test_package清理丢证

## 基本信息
- **严重度**: 1
- **类别**: build-system, conan, testing
- **作者**: A139

## 错误特征
```
Removing previously existing.*test_package.*build folder|AUDIT_FAIL_FIRST_HARMONY_RAW_RECORD_NOT_PRESERVED
```

## 根因分析
Repeated Conan create refreshes the same test_package build directory before the next test; collecting only at transaction end loses earlier raw records even when both commands exit zero.

## 推荐方案
**方法**: checkpoint-raw-test-evidence-before-next-create

**说明**: Conan重复create会先删除既有test_package构建目录；应在每次create完成且下一次调用前，以独立不覆盖的相位清单保存原始stdout/stderr/result字节、相对路径、长度和SHA256，再按run/config/phase重验。该方法补足E403仅讲交付清理、E474仅讲消费者与观察回执分离的边界，可用于需要逐阶段复核的Conan包，不将末次汇总冒充前次原始证据。

**修复命令**:
```
after create1: capture owned raw paths, bytes, length, sha256 to exclusive phase manifest outside test build; run unchanged create2; audit both phases
```

**验证**:
```
Verify first-create raw file manifest before next create, then independently decode and hash-check first/last phase records and actual command argv/rc; keep all original test denominators.
```
