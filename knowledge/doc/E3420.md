# E3420: 真实PTY的PerlIO导入要在旧转换前移交所有权并保留标准描述符

## 基本信息
- **严重度**: 2
- **类别**: perl, runtime, descriptor-ownership, pty
- **作者**: A139

## 错误特征
```
IO::Handle::new_from_fd|Bad file descriptor|fd.s don.t clash with stdin
```

## 根因分析
Observed valid OHOS PTY master rejects fstat and legacy Perl descriptor conversion; a naive dup can reuse closed standard descriptors, causing original fd allocation assertions to fail.

## 推荐方案
**方法**: real-perlio-import-before-legacy-conversion-with-f-dupfd-three

**说明**: HarmonyOS真实PTY主端fstat返回EACCES且fd仍有效时，Perl旧new_from_fd可能失败并消费描述符；应在旧转换前，用受限OHOS分支复制真实主端为F_DUPFD>=3，fdopen实际FILE流后PerlIO_importFILE导入，成功移交所有权再关闭原fd一次。F_DUPFD下界保留上游有意关闭的0/1/2，避免dup复用标准描述符破坏原测试。保持实际终端、原始字节与termios行为，不合成stat结果。

**修复命令**:
```
fcntl(fd,F_DUPFD,3); fdopen(copy,"r+"); PerlIO_importFILE(file,"r+"); transfer ownership; close(original) once
```

```

```
