# E3423: 上游 setup.py 的 console_scripts 入口必须落成脚本产物并声明 commands.json；脚本应自定位

## 基本信息
- **严重度**: 1
- **类别**: compat, portability, build-system
- **作者**: 991C

## 错误特征
```
entry_points|console_scripts|bin/ 下无该命令|commands\.json|No module named|wsdump
```

## 根因分析
纯 Python 库容易被当成"只把模块拷进 site-packages 就完事"，但上游 `setup.py` 常声明 `entry_points={"console_scripts": [...]}`（websocket-client 即 `wsdump=websocket._wsdump:main`）——**只拷模块就少了一个上游产物**；而且这类入口默认 `from <pkg> import …` 需要包在 `sys.path` 上，若朴素落成一个直接 import 的脚本，用户在未设 `PYTHONPATH` 时调用会 `No module named websocket`。仓库同时有 R38 约束：产出可执行文件的包必须在**软件级目录**声明 `commands.json`（`type: "tool"`、`name` 与包名一致、`binary: false` 表示是脚本而非预编译二进制），否则 CI L0k/R38 判 fail。
