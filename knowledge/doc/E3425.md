# E3425: 依赖图版本冲突必须 override 时，重建方向要避开「构建系统用 GNU make -j 的依赖」：下游无法给依赖注入 -j1，而 OHOS 上 make -j>1 必炸（E525/E074），应把源码重建推给 meson/ninja 等非 make 依赖，让 make-based 依赖沿用已发布二进制

## 错误特征
```
jobserver mkfifo: .*Operation not permitted|/bin/sh: can't fork - try again|Resource temporarily unavailable.*Error 127|Main binary package .* missing
```

## 根因分析
Conan 的版本冲突只能靠 override 收敛到单一版本，而 override 会改变被覆盖方依赖的 package_id，使其已发布二进制失效、被迫 --build=missing 从源码重建；此时「重建哪一个」不是等价选择——OHOS 的 SELinux 禁止用户进程创建 FIFO，GNU make 的 jobserver 靠 FIFO 传并行令牌，于是任何走 Unix Makefiles 的 make -j>1 构建都会炸（E074/E525），而 ninja 用 pipe、meson 不用 make jobserver，不受影响。本例实测：libcurl/8.5.0 的配方用 CMake + Unix Makefiles，conan 默认按 nproc 传 -j20，CI #93768 上报 `make: jobserver mkfifo: .../GMfifo48803: Operation not permitted` → `make[2]: /bin/sh: Resource temporarily unavailable` → `/bin/sh: can't fork - try again` → `Error 127`，整个 conan create 在依赖阶段即失败，目标包 pacredir 连 source() 都没轮到。关键约束是**下游没有任何杠杆**：-j 由依赖自己配方的 cmake.build() 决定，tools.build:jobs 属 profile/conf 层，消费者改它等于改 ci/conan/profiles/（框架文件），违反 W2 单 PR 原子性，且会串行化全仓构建。因此选型阶段就必须把「哪个依赖会被迫重建」当成一等约束。
