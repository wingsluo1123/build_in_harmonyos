# E3426: 能力探测宏同时罩住 struct 定义与 inline 函数定义时，只凭「sysroot 头里有这个 struct」就注入 -DHAVE_X=1，会让依赖自带的兜底实现被一并跳过；已发布的 DSO 于是带一个悬空符号，自己能建能发布能过 test_package，但每个可执行文件消费者链接时被 lld 的 --no-allow-shlib-undefined 判死

## 错误特征
```
undefined reference due to --no-allow-shlib-undefined: mallinfo2|>>> referenced by \S*/lib/\S+\.so$|referenced by .*libsystemd\.so
```

## 根因分析
能力宏 HAVE_MALLINFO2 在依赖包的 musl 兼容头里同时罩住 struct mallinfo2（类型）与 static inline mallinfo2()（函数实现），而依赖配方只凭「sysroot 的 malloc.h 里 grep 得到这个 struct」这一类型层证据就注入了 -DHAVE_MALLINFO2=1，导致兜底实现被一并跳过、已发布的 libsystemd.so.0.44.0 带上悬空的 U mallinfo2；再叠加 SDK 的 libc.so 是链接桩（.text 仅 336 字节，.dynsym 是 libc.a 的真子集，收了 malloc/mallopt 却漏了 mallinfo 家族），lld 在链接可执行文件时按默认的 --no-allow-shlib-undefined 判死。三层叠加，缺一层都不会暴露：
