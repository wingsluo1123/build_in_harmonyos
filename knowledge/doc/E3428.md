# E3428: musl 缺 glibc 专有类型与函数（loff_t / error_t / qsort_r / secure_getenv）→ 用垫片头统一补齐

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, libc, musl, headers
- **作者**: 4E22

## 错误特征
```
unknown type name 'loff_t'|use of undeclared identifier 'error_t'|call to undeclared function '(qsort_r|secure_getenv)'|undefined symbol: secure_getenv|typedef redefinition with different types
```

## 根因分析
上游按 glibc 写：用了 `loff_t`（内核/glibc 类型）、`error_t`（glibc 在 <errno.h> 里）、`qsort_r`、`secure_getenv`、`program_invocation_short_name` 等。OHOS 的 musl 侧这些要么根本没有（`error_t`、`secure_getenv` 连实现都没有）、要么只在特定 feature 宏下才有、要么与 sysroot 的 bits/alltypes.h 定义冲突；而 clang 15 在 C99 下把"隐式声明函数 + 返回值赋给指针"直接判为**硬错误**（-Wint-conversion），所以不能当普通警告放过。

## 推荐方案
**方法**: musl-shim-header-plus-object

**说明**: 在源码树里放一个垫片头 + 一个垫片 .c：头里用条件编译声明缺失的类型/函数（loff_t 走 musl 自己的 __DEFINED_loff_t 机制守卫），.c 里给出实现（secure_getenv）与 weak 兜底定义（program_invocation_*）。垫片头放在**已在 -I 路径上**的目录（如 <source>/include/），再由构建文件用 `-include <名字>` 引入（不需要绝对路径）。

**修复命令**:
```
构建文件里追加 `-include conan_musl_shim.h`；垫片 .o 经 LDFLAGS 交给链接（对象提供的是定义，与顺序无关）
```

**验证**:
```
grep -rn "loff_t\|error_t\|qsort_r\|secure_getenv\|program_invocation" <源码树> | head
```
