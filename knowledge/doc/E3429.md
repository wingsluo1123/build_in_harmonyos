# E3429: qmake HEADERS-only TEMPLATE=lib 库的 moc 产物需在 CMake 侧显式列为 target source

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, plugin-abi, qt6
- **作者**: 021C

## 错误特征
```
Failed to load libpasswordplugin.so|symbol not found: _ZN19AuthPluginInterface11qt_metacastEPKc|undefined symbol: vtable for .*Plugin|qt_metacall
```

## 根因分析
上游 qmake 工程 signon-plugins.pro 是 TEMPLATE=lib 且只有 HEADERS：qmake 会对 SignOn/authpluginif.h 跑 moc，AuthPluginInterface 的 qt_metacast/qt_metacall/staticMetaObject/虚表全部由 libsignon-plugins.so 承载，插件靠 LIBS += -lsignon-plugins 在 dlopen 时解析。用手写 CMake 复刻时若只 add_library(... <空 TU>)，CMAKE_AUTOMOC 只扫描 target sources、不跟随 #include 链，不会生成 moc_authpluginif.cpp，于是产出空壳库：链接期不报错，运行时 QLibrary/插件加载才报 symbol not found。同类第二坑：qmake CONFIG+=plugin 产出 lib<type>plugin.so，CMake MODULE 目标必须显式 PREFIX lib（宿主按 SIGNON_PLUGIN_PREFIX+type+SUFFIX 拼路径）。

## 推荐方案
**方法**: explicit-moc-source-in-cmake

**说明**: 把上游 qmake HEADERS 中带 Q_OBJECT 的头文件显式列入 add_library/add_executable 的 source 列表（AUTOMOC 只对 target sources 跑 moc），必要时再补一个只 include SDK 头的 TU 保证 include 路径；改完用 llvm-readelf --dyn-syms 核对 moc 符号真的进了库，再用 QLibrary/插件宿主做一次真实加载验证（链接通过不等于插件可加载）。

**修复命令**:
```
add_library(plugin-sdk SHARED sdk.cpp ${TOP}/lib/plugins/SignOn/authpluginif.h); llvm-readelf --dyn-syms lib/libsignon-plugins.so | grep -c AuthPluginInterface
```

**验证**:
```
llvm-readelf --dyn-syms <pkg>/lib/libsignon-plugins.so | grep AuthPluginInterface  # 应出现 _ZN19AuthPluginInterface11qt_metacastEPKc / _ZTV19AuthPluginInterface
```
