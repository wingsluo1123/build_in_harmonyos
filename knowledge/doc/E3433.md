# E3433: OHOS CI worker 进程槽位临界：并发进程需求决定成败（链接步多一层 shell 即 EAGAIN）

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, process-limit, worker
- **作者**: 50EF

## 错误特征
```
posix_spawn failed: Resource temporarily unavailable|clang-15: error: unable to execute command|linker command failed with exit code 1|can't fork - try again|spawn-resource exhaustion
```

## 根因分析
构建机进程槽位长期贴近上限（procs≈668 稳定、load≈21），真正的判据是「该步同时需要几个进程」：普通编译 3 个（shell→clang→clang -cc1，实测 clang 每文件都会 spawn 一个 -cc1，非进程内汇编）能过；link lua 4 个（shell→命令替换子 shell→clang→链接器）能过；tup 最终链接 5 个（多出上游 link.sh 这一层 shell）必失败——即该机只剩约 4 个空闲槽。故失败位置确定、重试（20s×10、三次尝试共 30 次）全部无效：不是负载抖动。

## 推荐方案
**方法**: reduce-concurrent-processes-at-fragile-step

**说明**: 把脆弱步的并发进程数压到与已通过的编译步同级：①不要用 out=$(...) 捕获输出（命令替换会让子 shell 在整个 spawn 期间常驻，恰好多占一槽），改为重定向到文件 + 内建 read/case 判特征；②不要在链路里插入额外 shell（就地展开上游辅助脚本，如 tup 的 link.sh）；③重试窗口按构建预算给足（15 次、退避 20→60s），每次重试前用 /bin/sh -c : 探针记录「能否创建进程」以区分整机槽位耗尽与本步需求过高。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
CI_PACKAGES="archives/t/tup/0.8" zsh ci/conan/build_and_test.sh
```
