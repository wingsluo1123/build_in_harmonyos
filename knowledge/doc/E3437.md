# E3437: stub 机制库（Tk 系）消费者测试必须先绑定宿主 stub 表：未绑定即调 API 直接 SIGSEGV

## 基本信息
- **严重度**: 3
- **类别**: conan, runtime, testing, api
- **作者**: 3477

## 错误特征
```
Signal 11 \(core dumped\)|Segmentation fault.*(libtk|stub)|Error loading shared library.*libtk|undefined reference to .Tk_InitStubs
```

## 根因分析
库以 USE_TCL_STUBS 编译，库内所有 Tcl 调用经 tclStubsPtr 间接表；该表仅由宿主初始化入口（Tk_Init→Tcl_InitStubs）绑定。消费者只链接 libtk 就调 Tk 公共 API 时表为 NULL → 空指针解引用 SIGSEGV，崩溃点落在 API 内部，极易被误判为链接冲突或库损坏。无显示环境下 Tk_Init 必然失败，但它在检查 display 之前已完成绑定，「容忍其失败再调 API」是可用路径。

## 推荐方案
**方法**: host-init-before-api-call

**说明**: 消费者先调宿主初始化入口（Tk_Init）并接受其环境性失败（无显示 rc=1），完成内部 stub 表绑定后再调库公共 API 断言返回值；并把失败原因钉在 display 上，避免与库加载/签名问题混淆。

**修复命令**:
```
可选: 具体命令模板(${VAR}变量引用)
```

**验证**:
```
clang --target=aarch64-linux-ohos -I<pkg>/include test.c -ltk8.6 -ltcl8.6 后运行；未绑定表时 rc=139，先 Tk_Init(容忍失败) 后 rc=0
```
