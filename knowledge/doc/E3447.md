# E3447: 旧版 Autotools 工程在 OHOS HMFS 上的系列兼容：config.status 临时目录迁出构建树（探针钉选可写 TMPDIR）+ AM_SANITY_CHECK mtime 误报降级 + fork/posix_spawn 资源压力重试

## 基本信息
- **严重度**: 3
- **类别**: compat, detection, hmdfs, ohos, portability
- **作者**: hmbs-executor
- **来源 PR**: 15307

## 错误特征
```
configure: error: cannot guess build type|newly created file is older than distributed files|confstat[A-Za-z0-9]+[^\n]*Permission denied|posix_spawn failed: Resource temporarily unavailable|can't fork - try again
```

## 根因分析
puf 1.0.0 内置 2005 版 Autotools 产物在 OHOS 真机 HMFS/HMDFS 用户卷上暴露三类结构性不兼容：① 内置 config.guess 无法识别 HarmonyOS 的 uname 输出（日志 UNAME_SYSTEM = HarmonyOS），configure 报 cannot guess build type；② 生成的 config.status 硬编码在构建树内建 ./confstatXXXXXX 临时目录，HMFS/HMDFS 上新建目录的属主与权限元数据滞后生效，紧接的 in/out/config.h 重定向写全部 EACCES，且该文件系统 HMBS_CAP_CHMOD=0（chmod 不受支持）无法补救，最终无 Makefile；③ AM_SANITY_CHECK 是建议性 mtime 比对，在粗 mtime 粒度/延迟元数据文件系统或 ls -Lt 排序不可靠主机上把新建文件误判为不比 2005 年旧源码新而 (exit 1) 硬中止 configure。叠加共享构建主机瞬态 fork/posix_spawn EAGAIN 资源压力（bash 自身会重试 fork，clang 不会重试 posix_spawn ld.lld）使 make/link 间歇失败。

## 推荐方案
**方法**: relocate-confstat-to-pinned-tmpdir-downgrade-sanity-check-and-fingerprint-fork-retry

**说明**: 把 config.status 的 confstat 临时目录从 HMFS 构建树迁到配方探针验证的可写非 HMFS TMPDIR，将 AM_SANITY_CHECK 建议性 mtime 守卫降级为 WARNING 继续，并对 fork/posix_spawn 资源压力做带指纹识别的有限指数退避重试；三元组与 config.sub 补丁只作配套

**修复命令**:
```
conanfile.py: generate() 传 --build/--host=aarch64-linux-ohos（armv8 守卫）并 --disable-dependency-tracking；build() 前 _pin_tmpdir() 建目录-写-回读探针钉选 TMPDIR；_run_configure()/_run_make_with_fork_retry() 仅命中 fork 指纹时指数退避重试；patches/0001-config.sub-ohos.patch + 0002-configure-confstat-tmpdir.patch + 0003-configure-sanity-check.patch；test_package/test.sh 后台 HTTP server 重定向子外壳并 exec
```

**验证**:
```
真机预检连续通过 configure/make/install/package 与 test_package；日志中 configure 输出 checking whether build environment is sane... yes 且生成 Makefile/config.h，config.status 的 confstat 临时目录落在配方钉选的可写 TMPDIR 而非构建树，make/link 不再出现 fork: retry / posix_spawn failed
```
