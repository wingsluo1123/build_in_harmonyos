# E3448: upstream 脚本常带 `set -e`，当**宿主缺少它的前置条件**（如沙箱里 `/sys/bus/usb/devices` 为空）时脚本会**按设计**返回非 0 —— 消费者校验不能据此判"打包缺陷"，应当在运行前**显式探测该前置条件**，探到缺失才记具名环境 SKIP（有设备时仍严格校验）

## 基本信息
- **严重度**: 2
- **类别**: testing, environment, shell
- **作者**: E82F

## 错误特征
```
usb-list 真实失败（exit=1）|set -e|\[ -d .*\] 返回非 0|空设备树|宿主缺前置条件
```

## 根因分析
installation-report 的 `usb-list` 遍历 `/sys/bus/usb/devices/usb*`：在没有任何 USB 设备的 容器/沙箱里该 glob 不匹配，脚本内部 `[ -d '…usb*' ]` 为假 → `return` 非 0 → 受文件头 `set -e` 影响整脚本以 **1** 退出（实测：直接执行 exit=1；`sh -x` 追踪可见失败点就是那次 `[ -d … ]`）。 脚本本身没错（upstream 走 Debian 安装器/真实机器的路径下总有设备），错的是把"宿主缺前置条件" 当成"产物有问题"。另一方面，若把这类非 0 一律 SKIP，又会掩盖真实缺陷（与 PR #14983 的 aireview P2 同类问题）。

## 推荐方案
**方法**: probe-the-precondition-then-classify-with-named-evidence

**说明**: ①跑之前**显式探测前置条件**（目录/条目数/设备/可选工具是否存在），探测结果就是"具名证据"；②前置条件缺失 → 记 **SKIP 并打印探测到的具体依据**（如"`/sys/bus/usb/devices` 条目数 0"），不要空口 SKIP；③前置条件具备却仍失败 → 按"具名信号才 SKIP、其余判缺陷"的口径严格判 FAIL（超时/无执行权限/权限拒绝可 SKIP）；④在所测脚本带 `set -e` 时，特别注意"最后一个判断为假"也会让整脚本非 0，这是最常见的伪失败来源。

**修复命令**:
```
n=$(ls -A /sys/bus/usb/devices 2>/dev/null | wc -l); [ "$n" -eq 0 ] && echo "SKIP: 宿主无 USB 设备（条目 0）" || ./usb-list; echo $?
```

**验证**:
```
① `ls -A /sys/bus/usb/devices | wc -l`（前置条件是否具备）② 直接执行脚本看退出码：`<pkg>/bin/usb-list; echo $?` ③ `sh -x <script>` 看失败点是否落在"前置条件判断"上
```
