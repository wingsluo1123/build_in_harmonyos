# E3449: `conandata.yml` 里的 `sha256` 值若混入**不可见字符**（零宽字符/非常规空白），Conan 会报 `sha256 hash failed` 并把 `Provided hash` 与 `Computed hash` 打印成**视觉完全相同**的两串——此时不要怀疑下载源，先量哈希串的**长度与字符集**（正确应为 64 个 `[0-9a-f]`）

## 基本信息
- **严重度**: 3
- **类别**: conan, recipe-metadata, tooling
- **作者**: 11A7

## 错误特征
```
sha256 hash failed for|Provided hash: .*Computed hash: .*（两串视觉相同）|hash 长度不是 64
```

## 根因分析
手工把哈希值敲进 YAML 时可能带进零宽/不可见字符（复制自带格式的终端输出、或输入法/编辑器插入的隐藏字符）。 Conan 的校验是按字节比较的，于是： * 报错说 `Provided hash` 与 `Computed hash` 不一致， * 但两串在终端里看起来一模一样（不可见字符不显示宽度），极易误判成"下载源变了/缓存脏了"而白折腾。 实测：某次 conandata 的哈希串长度为 **67**（多 3 个字符）且不是 `[0-9a-f]{64}`；本地文件的实际 sha256 与 预期值一致——问题只在字面量本身。

## 推荐方案
**方法**: measure-hash-length-and-charset-then-write-the-computed-value-back

**说明**: ①遇到 `sha256 hash failed` 且两串"看起来相同"时，**先量长度与字符集**，不要先怀疑网络/缓存；②确认真实文件的哈希（`hashlib.sha256(open(file,'rb').read()).hexdigest()` 或 `sha256sum`）；③把 conandata 里那个值替换成**由文件实算得到**的字符串（避免再次手敲带入不可见字符），替换后立即回校（长度 64 + 十六进制 + 等于实算值）；④顺手记录该现象，避免下次再被"看起来一样"误导。

**修复命令**:
```
sha256sum <tarball> # 与 conandata 的值逐 char 比对；或 python 量 len() 与 fullmatch
```

**验证**:
```
`python3 -c "import re;h=re.search(r'sha256:\s*\"([^\"]+)\"',open('conandata.yml',encoding='utf-8').read()).group(1);print(len(h), bool(re.fullmatch(r'[0-9a-f]{64}', h)))"`（长度必须是 64、且全为十六进制）
```
