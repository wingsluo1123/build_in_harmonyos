# E3453: 以 make 命令行变量传 CFLAGS/LDFLAGS 会覆盖上游 Makefile 的 `+=` 追加，导致 -lX11/-lXrandr 等链接参数整体丢失

## 基本信息
- **严重度**: 2
- **类别**: make, cross-compile, conan, link
- **作者**: pc-agent

## 错误特征
```
undefined reference to [`']?(XOpenDisplay|XRRGetScreenResourcesCurrent|XRRSetCrtcGamma|XRRGetCrtcGammaSize)\b
```

## 根因分析
GNU make 中命令行变量赋值的优先级高于 Makefile 内的普通赋值（包括 `+=`，只有 `override` 指令能压过）。当配方写成 `make CFLAGS="$CFLAGS $CPPFLAGS -std=c99 -Wall" LDFLAGS="$LDFLAGS"` 时，上游 Makefile 的 `CFLAGS += -std=c99 -Wall ${INCS}` 与 `LDFLAGS += -lX11 -lXrandr ${LIBS}` 两行被完全忽略；交叉构建里 conan 只提供 -I/-L 路径，`-lX11/-lXrandr` 本应由 Makefile 自己追加，于是链接行缺少这两个库，报 XOpenDisplay/XRRSetCrtcGamma 等未定义符号。sct 1.0.0 的 Makefile 正是 `LDFLAGS += -lX11 -lXrandr ${LIBS}` 结构。

## 推荐方案
**方法**: export-flags-through-environment-not-make-argv

**说明**: 把 CFLAGS/LDFLAGS 作为 make 的环境变量传入（shell 前缀赋值 `CFLAGS=... make ...`，配合 conan `self.run(..., env="conanbuild")`），不要在 make 命令行上写变量赋值；需要替换 Makefile 的宿主机默认路径时，只把对应变量置空（如 `INCS= LIBS=`），保留含 `+=` 的 CFLAGS/LDFLAGS 行生效。

**修复命令**:
```
self.run(f'cd "{self.source_folder}" && CFLAGS="$CFLAGS $CPPFLAGS -std=c99 -Wall" LDFLAGS="$LDFLAGS" make -j1 INCS= LIBS=', env="conanbuild")
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable；readelf -d package/bin/sct | grep NEEDED 应含 libX11.so.6 与 libXrandr.so.2；test_package 18/18 PASS
```
