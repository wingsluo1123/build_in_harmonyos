# E3456: 顶层 CMake 把测试专用配置头注入库目标编译导致库与消费者结构体布局错位（test_package Signal 11）；配方应只构建库子目录并保持打包头文件与库同配置

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, packaging, runtime
- **作者**: tianyi_wang

## 错误特征
```
\*\*\*Exception: SegFault|Signal 11 \(core dumped\)|0% tests passed, 2 tests failed out of 2
```

## 根因分析
lwgps 顶层 CMakeLists 在 add_subdirectory(tests) 内先 include 测试的 cmake.cmake（set LWGPS_OPTS_FILE=tests/test_parse_sat_det/lwgps_opts.h，其中 LWGPS_CFG_STATEMENT_GPGSV_SAT_DET=1）再 add_subdirectory(lwgps)，使库在编译期看到含 sats_in_view_desc[48] 的 lwgps_t；而 conan 配方打包的消费者头文件 lwgps_opts.h 来自官方空模板（默认 opts，无 SAT_DET 字段），lwgps_t 更小。库按大结构体写入，消费者按小结构体访问 → 静默内存越界 → test_package 两个测试均 Signal 11（同一现象：字段读到垃圾值 course=0 + 段错误）

## 推荐方案
**方法**: library-only-subdir-build-with-default-opts

**说明**: 配方 build() 用 cmake.configure(build_script_folder="lwgps") 只构建库子目录（LWGPS_OPTS_FILE 未设 → 使用默认 lwgps_opts_template.h），package() 从构建目录根复制 liblwgps.a，并打包与库同配置的默认 lwgps_opts.h（由官方模板复制产出）；禁止使用顶层 CMakeLists 构建（会把测试 opts 注入库）

**修复命令**:
```
cmake.configure(build_script_folder="lwgps")
```

**验证**:
```
conan create archives/l/lwgps/2.4.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing && ctest --test-dir <test_package>/build/clang-15-armv8-17-release --output-on-failure
```
