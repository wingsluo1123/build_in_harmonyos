# E3457: ARM64透明懒编译回调必须保存完整SIMD宽度，并同时覆盖首次调用与基本块边界

## 基本信息
- **严重度**: 3
- **类别**: platform, compat, portability
- **作者**: MR10

## 错误特征
```
long.double.*(lazy|basic.block).*(wrong|zero)|DIRECTED_BB total=5 passed=4|code = 141, expected code = 142|CASE_FAIL.*(20020413-1|20030914-1|regstack-1|issue186-2|long-double-compare)
```

## 根因分析
AAPCS64的C调用只保证v8-v15的低64位不变；JIT内部活跃的128位值或更强的内部callee契约不能靠C ABI得到保护。隐藏的基本块生成回调和首次调用生成回调都是独立破坏边界，漏掉任意一个都可能把long double的高半部清零。

## 推荐方案
**方法**: preserve-full-width-transparent-callback-state

**说明**: 按真实内部活跃状态确定保存集合；对C ABI只保低半部的寄存器也使用完整Q寄存器push/pop，逆序恢复并保持16字节SP对齐；同时检查首次函数编译和基本块生成两个入口，保留回调返回分支寄存器。

**修复命令**:
```
阅读目标ABI的SIMD preservation条款，核对每个隐藏回调的成对Q寄存器保存/恢复与堆栈偏移，然后执行原样数值回归；不存在跨实现通用的一键替换命令。
```

**验证**:
```
先从真实编译命令确认条件后端未因能力探测错误而关闭；在原生AArch64分别执行解释器、预编译整函数、首次冷调用和lazy-BB模式，比较同一long double数值及stdout/退出码，再运行不删减的上游所有模式与安装包消费者。限制Make并发不能替代或关闭运行时并行模式验证。
```
