# E3459: OHOS 上让 C 程序的 C++ 运行时自包含：clang -static-libstdc++ 在 -stdlib=libc++ 下是 no-op，须显式链接 clang -print-file-name 解析出的 libc++ 静态归档

## 基本信息
- **严重度**: 3
- **类别**: portability, toolchain, linking
- **作者**: E63F

## 错误特征
```
Error loading shared library libc\+\+_shared\.so|ld.lld: error: undefined symbol: operator new|undefined symbol: __cxa_begin_catch|undefined symbol: __gxx_personality_v0|symbol not found: _ZNSt9exceptionD2Ev|Error relocating .*__cxa_pure_virtual
```

## 根因分析
用 C 驱动 clang 链接一个内含 C++ 静态库（如 taglib 的 libtag_c.a/libtag.a）的产物时，默认把 libc++_shared.so 写进 DT_NEEDED；该库放在 SDK 的 llvm/lib/aarch64-linux-ohos 下，不在 OHOS 加载器默认搜索路径，运行期报 'Error loading shared library libc++_shared.so' 并逐条打印 undefined 符号，或用静态运行时时链接期报 operator new/__cxa_* 未定义。-static-libstdc++ 是 GCC 兼容开关，在 -stdlib=libc++ 下不产生静态链接效果（本任务实测：加该开关链接仍报 32 条 undefined symbol: operator new(unsigned long)/__cxa_begin_catch/vtable for __cxxabiv1::__class_type_info）。

## 推荐方案
**方法**: 显式把 clang -print-file-name 解析出的 libc++.a/libc++abi.a/libunwind.a 三个静态归档追加到链接行末尾，不要依赖 -static-libstdc++

**说明**: 在配方里用编译器自省取路径（避免硬编码 SDK 布局）：三个静态归档加入 LDFLAGS；链接后 readelf -d 校验 NEEDED 仅 libc.so

**修复命令**:
```
参考 archives/v/vitunes/2.3/conanfile.py 的 _cxx_runtime_archives()（vitunes 2.3 实测）
```

**验证**:
```
clang -print-file-name=libc++.a && clang -print-file-name=libc++abi.a && clang -print-file-name=libunwind.a   # 三个静态归档绝对路径；llvm-readelf -d ./<bin> | grep NEEDED   # 期望只剩 libc.so；./<bin> -h   # 不再报 libc++_shared.so 加载失败
```
