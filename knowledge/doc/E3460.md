# E3460: plain char 承接 getopt(3) 返回值：aarch64 上 char 默认无符号，-1 哨兵永不成立，带选项的子命令退化为 usage 报错

## 基本信息
- **严重度**: 3
- **类别**: portability, abi, c-language, cli
- **作者**: E63F

## 错误特征
```
usage: -e .*\[-.*\].*file|option requires an argument|invalid option -- |usage: .*\[-[a-zA-Z:]+\]
```

## 根因分析
getopt(3) 返回 int 并用 -1 表示结束，POSIX 要求接收变量为 int；plain char 的符号性由实现定义。OHOS/HarmonyOS aarch64 的 clang 15 下 plain char 无符号（clang -dM -E 含 __CHAR_UNSIGNED__，CHAR_MIN==0）：返回值 -1 存入 char 变为 255，'while ((ch = getopt(...)) != -1)' 恒真；下一次迭代 getopt 仍返回 -1，控制流落入 switch 的 default 分支，直接打印 usage 并退出（若 default 不退出则为死循环）。x86 上 plain char 有符号，同一份源码表现正常，因此该缺陷在移植到 aarch64 时才暴露。

## 推荐方案
**方法**: 把接收 getopt(3) 返回值的变量声明为 int（不要用 -fsigned-char 掩盖符号性差异）

**说明**: 逐处修改 getopt 使用点：char ch -> int ch；若有 optind=0/optreset 的重入逻辑保持原样即可（musl 支持 optind=0 重置，问题不在重置而在哨兵比较）

**修复命令**:
```
参考 archives/v/vitunes/2.3/patches/0001-e_commands.c.patch（vitunes 2.3 实测：ecmd_check/ecmd_flush/ecmd_tag 三处）
```

**验证**:
```
clang -dM -E - </dev/null | grep -c CHAR_UNSIGNED   # 1=plain char 无符号（本机 aarch64-unknown-linux-ohos clang 15 实测）；grep -nE '^[[:space:]]*char[[:space:]]+[a-zA-Z_]+;' <file>.c 找接收变量并与 getopt 调用点核对；对照运行：未修复时 '-e <subcmd> -s <file>' 打印 usage（探针实测 inner getopt 返回 255 后中断），把变量改为 int 后同一命令正常得到 flag='s'(115)、nfiles=1
```
