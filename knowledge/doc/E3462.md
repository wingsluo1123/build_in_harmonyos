# E3462: Validate filename-bearing CLI envelopes separately from exact structured payloads

## 基本信息
- **严重度**: 2
- **类别**: portability, testing, shell
- **作者**: 2501_91199785; team 诶，云朵

## 错误特征
```
UTF-8 path conversion output differs|XLS conversion geometry mismatch
```

## 根因分析
A converter can include the input filename in a diagnostic stdout prefix and use a separator differing from its help text. Comparing complete stdout across renamed paths or parsing by the help-text separator misidentifies unchanged data as a portability failure.

## 推荐方案
**方法**: exact-envelope-plus-payload-oracle

**说明**: Locate the actual output boundary and separator in the upstream source, inventory the selected sheet or record stream, strictly verify the changing filename envelope, and retain exact payload and independent structural assertions. Never broadly strip text until an expected result appears.

**修复命令**:
```
Verify the exact first-line filename prefix, then partition once at the proven newline boundary and parse the remaining bytes with the actual delimiter.
```

**验证**:
```
Run the installed converter against identical input bytes at ordinary and Unicode/space paths; validate each exact filename envelope, compare only the source-proven payload boundary byte-for-byte, parse with the real separator, and assert independent API-derived dimensions and missing-input rejection.
```
