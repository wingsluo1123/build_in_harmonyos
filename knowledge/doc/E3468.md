# E3468: 手写上下文保存汇编绕过 libc 头文件别名时，应验证并调用目标 libc 的公开接口

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, libc, toolchain, linking
- **作者**: frj__

## 错误特征
```
undefined symbol: __sigsetjmp
```

## 根因分析
glibc 的 C 头文件通常把 sigsetjmp 映射到 __sigsetjmp；手写 .S 直接写死后者，把 glibc 的符号导出契约带入其他 libc。OHOS 的链接环境提供公开 sigsetjmp，不提供 __sigsetjmp，CPU 指令集兼容不能保证 libc ABI 兼容；生产 C/SPP 声明还必须携带 returns_twice，否则测试端单独补属性会掩盖优化器契约缺口。

## 推荐方案
**方法**: public-context-symbol-with-tail-call-abi-validation

**说明**: 用目标编译器链接探测真实sigsetjmp符号，优先公开入口、仅在实际可链接时选择私有备用入口；通用能力定义传入相关AArch64汇编，不新增OS宏。保留尾跳转、寄存器和缓冲ABI，覆盖生产C/SPP双声明层；资源或额外编译错误不得当成能力缺失。

**修复命令**:
```
conan create archives/i/iraf/2.18.1 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```

**验证**:
```
用 OHOS SDK clang 链接原始 IRAF unix/os/zsvjmp.S 与 context consumer，观察 undefined symbol: __sigsetjmp；对补丁后 libos.a 执行 llvm-nm，确认 U sigsetjmp 和 U siglongjmp；在 -O0/-O2 下运行 test_context.c。
```
