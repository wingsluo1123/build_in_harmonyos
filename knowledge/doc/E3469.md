# E3469: "OHOS app 沙箱对 AF_NETLINK 只放行 NETLINK_ROUTE(0)——其余协议号（含内核未分配的）一律在 socket 创建时返回 EACCES(13) 而非 EAFNOSUPPORT，故 generic-netlink 的 nl80211 工具运行期不可达；且上游存在 check 目标不等于存在测试套件，sparse/cgcc 这类 lint 型 check 目标既不可执行也不计入 N"

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, runtime, testing, netlink
- **作者**: 主理-5

## 错误特征
```
"Failed to connect to generic netlink\\.|socket\\(AF_NETLINK.*NETLINK_GENERIC.*(EACCES|Permission denied)|redefinition of 'sockaddr_storage'"
```

## 根因分析
【机制一，netlink 协议号白名单而非设施缺失】OHOS app 沙箱在 socket 创建阶段就按协议号裁决 AF_NETLINK。socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE=0) 成功且可 bind，而 NETLINK_GENERIC=16 直接返回 EACCES(13)。判别性证据是未分配协议号——proto=30 与 proto=31（内核未注册任何协议族）同样返回 EACCES(13) 而非 EAFNOSUPPORT(97)，说明裁决发生在沙箱策略层、按协议号做白名单，先于内核解析协议族是否存在。这与 E237「HongMeng Kernel 缺 NETLINK_GENERIC 协议族」的框架不同：设施缺失的可判别签名是 EAFNOSUPPORT，不是 EACCES。后果是一切经 generic netlink 访问 nl80211 的工具（iw、ethtool 的 netlink 后端、libnl 的 genl API）运行期必然失败于「Failed to connect to generic netlink.」，rc=1；但 CLI 契约面（--version、usage 与命令表）完全可用，可作真实断言。【机制二，check 目标的存在性不等于测试套件】iw 6.17 全树无 tests 目录、无 Makefile.am（仅裸 Makefile）、无 TESTS 与 check_PROGRAMS 变量、无 test*.c、无 ctest 或 add_test、无 RUNTEST 驱动、无 demo 与 examples 目录（R51 六探针全 0）。Makefile 里唯一的 check 目标是让 make 以 CC=CHECK 走 cgcc 重新构建一遍，即 sparse/cgcc **静态分析 lint**（本机 sparse 与 cgcc 均不存在）。它既不是测试执行面、也不构成上游注册用例。若把「存在 check 目标」当判据，会得出相反结论——或照抄 autotools.make 的 check 目标把 lint 当测试跑（失败，或更糟，空跑假绿），或据此申报 N 大于 0（与 rule4 实测口径不符）。

## 推荐方案
**方法**: "probe-classify-sandbox-denial + assert-capability-wall-verbatim + tri-state-test-counting"

**说明**: (1) 先做协议号判别探针，不要只看 EACCES，要同时探一个内核未分配的协议号——未分配号也给 EACCES 说明是沙箱白名单，给 EAFNOSUPPORT 才是内核设施缺失；两句话写进 notes，避免把权限问题误诊成内核裁剪。(2) 运行期断言如实逐字固定能力墙：对需要内核回话的子命令断言 rc=1 且文案含「Failed to connect to generic netlink.」，不要放宽成「rc 非 0 即可」，更不要跳过；平台一旦放开，该断言立刻翻红暴露。(3) 编译期与运行期必须分开记账：redefinition of sockaddr_storage 是 sysroot 头不一致（可修，见 E119 与 E1604），generic netlink 不可达是沙箱策略（不可修）；混为一谈会导致「修了编译以为修好了运行」。(4) 测试清点按三态分类而不是二态「有没有 check 目标」——真测试套件（TESTS 变量、ctest 或 add_test 有注册项）要真跑；无任何测试资产时 N_static 为 0；有 check 目标但语义是 lint、格式或打包时 N_static 仍为 0，并在正文写明该 check 目标不是测试套件、不执行、不计入 N。第三类最容易被误报。

**修复命令**:
```
"make -n check 2>&1 | head; grep -n '^check:' -A2 Makefile"
```

**验证**:
```
"python3 - <<'PY'\nimport socket, errno\nfor p in (0, 16, 30):\n    try:\n        socket.socket(16, 3, p).close(); print(p, 'OK')\n    except OSError as e:\n        print(p, errno.errorcode.get(e.errno))\nPY"
```
