## 错误特征
```
assert locker_1\.has_lock\(\)|Timed out waiting for (Acquired|Released|Send newline to stdin to acquire)
```

## 根因分析
父进程用固定休眠推断子进程已就绪或持锁，在负载下会先启动竞争者或先执行断言；启动成功不等于锁已取得，释放命令发送不等于释放完成。

## 推荐方案
**方法**: ordered-process-phase-barriers-with-delay-falsification

**说明**: 先等 READY，再命令首进程 acquire 并等待 Acquired，才启动竞争者；正向持锁和释放判定等待实际事件。辅助响应有上限且不改产品 timeout。对照延迟实验、全量回归和原测试名/Assert AST 证明语义保留。

**修复命令**:
```
python3 -m pytest -v tests; conan create . --profile:all <device-profile> --build=never
```

**验证**:
```

```
