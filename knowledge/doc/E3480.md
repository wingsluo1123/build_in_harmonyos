# E3480: 遗留 Makefile 探测 /usr/include 而非 sysroot，OHOS 下误判 syscall 头文件缺失

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, syscall, headers, make
- **作者**: PMD1

## 错误特征
```
#error "inotify not supported on this architecture!"|#error Unsupported architecture|error: .*inotify-syscalls\.h|error: .*timerfd-syscalls\.h|__NR_inotify_init.*undeclared
```

## 根因分析
老式 Makefile 用构建机绝对路径 `/usr/include` 探测头文件是否存在，在 sysroot 化的 OHOS 上误判缺失，从而编到 aarch64 不支持的 syscall shim 分支。

## 推荐方案
**方法**: override-make-variable-from-recipe

**说明**: 不改 Makefile：在构建命令里**用命令行变量覆盖**探测结果。

**修复命令**:
```
make -j1 -C <dir> INOTIFY_CFLAGS= TIMERFD_CFLAGS=
```

**验证**:
```
1) grep -n 'test -e /usr/include' Makefile* 定位探测点;
```
