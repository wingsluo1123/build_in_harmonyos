# E3485: OHOS 共享 profile 的 CONFIG_SHELL(hnp bash) 在 HMDFS 上 getcwd 失败致 configure 中止：改写 /bin/sh 并导出 PWD，并对 fork 抖动做标记门控有界重试

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, ohos, portability, build-system, autotools
- **作者**: hmbs-executor
- **来源 PR**: 15854

## 错误特征
```
configure: error: working directory cannot be determined|getcwd: cannot access parent directories|can't fork - try again|Resource temporarily unavailable
```

## 根因分析
共享 ohos-aarch64 profile 的 [buildenv] 导出 CONFIG_SHELL=/data/service/hnp/bin/bash（SHELL 同）；autoconf configure 在 CONFIG_SHELL 非空时无条件 exec $CONFIG_SHELL，而该 hnp bash 在 HMDFS 构建树上 getcwd 失败，产生 shell-init/job-working-directory errno 风暴并以 configure: error: working directory cannot be determined 终止。后续 make/make check 的 can't fork - try again 为同机共享真机进程/线程表瞬时耗尽（EAGAIN），非配方/源码缺陷。

## 推荐方案
**方法**: neutralize-config-shell-and-marker-gated-fork-retry

**说明**: 在 build() 内把 CONFIG_SHELL/SHELL 中立化为 /bin/sh 并导出 PWD 使 pwd 走逻辑路径；对 configure 与 make/make check 套用仅在命中 fork 指纹时才触发的有界重试

**修复命令**:
```
conanfile.py: _neutralize_config_shell() 向 conanbuild.sh 末尾追加 export CONFIG_SHELL=/bin/sh; export SHELL=/bin/sh 并导出 PWD；_configure_with_fork_retry() 用 load_toolchain_args 重建 configure_args，最多重试 3 次退避 15/30s；_run_with_fork_retry(label,cmd,log_path,cwd) 通用化，_make_with_fork_retry() 解析 tools.gnu:make_program 与 make_args 并追加 -j1，build() 的 make 与 make check 均走该重试
```

**验证**:
```
真机 compile 门禁通过；日志中不再出现 working directory cannot be determined；configure 与 make 在 fork 抖动时经标记门控有界重试后成功
```
