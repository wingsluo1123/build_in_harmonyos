# E3491: HarmonyOS 上 JNA 平台识别失效（os.name=HarmonyOS）：Java 应用必须显式识别 HarmonyOS 并禁用 X11/WinAPI native 路径，回退纯 Java/AWT 后端

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, ohos, java, gui
- **作者**: OpenDesk

## 错误特征
```
UnsatisfiedLinkError.*libX11|libX11.so.*(No such file|not found)|Platform.isLinux\(\).*false|RESOURCE_PREFIX.*harmonyos-aarch64|UnsatisfiedLinkError.*libfreetype
```

## 根因分析
JNA 通过 System.getProperty("os.name") 的关键字（linux/win/mac）判定平台；HarmonyOS 的 os.name="HarmonyOS" 不含 "linux"，故 Platform.isLinux()=false、Platform.isWindows()=false，Platform.RESOURCE_PREFIX="harmonyos-aarch64"。JNA 4.2.0 的 jar 内不含 harmonyos-aarch64 的 libjnidispatch，且 OHOS 不提供 LinuxScreenAccessor 依赖的 X11 客户端库(libX11)。若应用按 "Linux -> 调用 native X11" 的常规分支实现，在 OHOS 上会误入 native 路径导致 UnsatisfiedLinkError(libX11)/崩溃；依赖 Platform.isLinux() 的判定还随 JNA 版本对 os.name 的处理而变，行为脆弱。

## 推荐方案
**方法**: explicit-harmonyos-platform-branch

**说明**: 在平台判定处显式识别 HarmonyOS/OHOS（os.name 含 "harmony" 或以 "ohos" 开头），令 native API 可用性返回 false 并跳过 Windows/Linux native 访问器，回退到可移植的纯 Java/AWT 实现；不改变 Windows/Linux 既有行为。

**修复命令**:
```
static boolean isHarmonyOS(){ String os=System.getProperty("os.name","").toLowerCase(); return os.contains("harmony")||os.startsWith("ohos"); } ; if(isNative && !isHarmonyOS()){ ...Platform.isWindows()/isLinux()... }
```

**验证**:
```
java -cp typometer-1.0.1.jar Probe2   # 期望: os.name=HarmonyOS / isHarmonyOS=true / isNativeApiSupported=false
```
