# E3492: OHOS 真机的 Java/Maven（JAR 应用）适配：JDK17+Maven 自取+阿里云镜像跑通 surefire 上游测试并将 uber-JAR 打包到 libexec；Swing/AWT GUI 运行时另需平台 libfreetype（headless 测试不受影响）

## 基本信息
- **严重度**: 2
- **类别**: ohos, network, java, awt, gui
- **作者**: OpenDesk

## 错误特征
```
Connection reset.*repo1.maven.org|Read timed out.*repo1.maven.org|UnsatisfiedLinkError.*libfontmanager.so.*libfreetype|libfreetype.so.6.*(cannot open|No such file|not found)|Failed to connect to github.com
```

## 根因分析
①OHOS 真机 Maven Central(https://repo1.maven.org) 直连不稳定（Connection reset/read timeout），构建须经镜像（阿里云 central 的 settings.xml mirrorOf=central）并带重试+直连回退；GitHub 直连不可达，源码 tarball 需镜像通道。②JDK 为 bishengjdk 17（JAVA_HOME 需定位），Maven 上游无 mvnw，配方自取 apache-maven 3.9.11（sha256 钉校验）。③`mvn package` 经 maven-surefire 执行上游 JUnit 用例（typometer 89 例），maven-shade-plugin 生成含依赖的 uber-jar；JAR 属库包产物，置于 libexec/（R38 不需 commands.json）。④Swing GUI 运行时，JDK 的 libfontmanager.so 依赖系统 libfreetype.so.6，OHOS 开发镜像未预置 → UnsatisfiedLinkError；但 headless 上游测试/消费者测试不做 AWT 初始化，不受影响（GUI 显示属平台运行时环境项）。

## 推荐方案
**方法**: maven-mirror-plus-headless-tests-plus-libexec-jar

**说明**: 配方 build()：定位 JAVA_HOME(bishengjdk17)、自取并 sha256 校验 apache-maven；写 settings.xml 将 central 镜像到阿里云并重试 3 次、失败回退直连；`mvn clean package -B -DskipTests=false` 真实执行上游测试；package() 将 target/*.jar 与 bin zip 拷入 libexec/、LICENSE 拷入 licenses/；package_info() 置 cpp_info.libdirs=["libexec"]。GUI 运行需求在 notes/README 中如实登记为运行时环境项。

**修复命令**:
```
bash -c "cd {source} && sh {maven}/bin/mvn -s {settings} clean package -B -DskipTests=false"
```

**验证**:
```
mvn -s settings.xml clean package -B -DskipTests=false   # 期望 BUILD SUCCESS + surefire 全绿；conan-verify 八门禁 PASS
```
