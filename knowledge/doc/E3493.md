# E3493: greetd greeter 客户端的真构建依赖与 meson i18n 工具注入、werror 终止项补全

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, meson, dependency, i18n
- **作者**: wanderlust_0823

## 错误特征
```
"Program msgfmt found: NO|error: missing field 'short_name' initializer|-Werror,-Wmissing-field-initializers|Unable to find 'gettext' in remotes"
```

## 根因分析
三处独立机制。其一 greetd 族 greeter 客户端（gtkgreet）自带 greetd IPC 协议实现（json-c 编解码 AF_UNIX socket），不链接也不包含 greetd 头文件，所以构建期真依赖只有 gtk+-3.0 与 json-c，greetd 只是运行期配套。其二 meson 的 i18n.gettext 在配置阶段要求 PATH 上有 msgfmt 与 xgettext，而 gettext 放在 host requires 时其 bin 不进 VirtualBuildEnv 的 build PATH，配置阶段即找不到工具。其三上游 meson.build 设 werror=true，clang15 的 -Wextra 含 -Wmissing-field-initializers，GOptionEntry 数组用 { NULL } 收尾被判缺 short_name 字段，警告升级为硬错误。

## 推荐方案
**方法**: deps-audit-and-build-tooling-injection

**说明**: 配方只声明 gtk 与 json-c 为构建依赖，gettext 仅作构建期工具包并在 generate() 里把它的 bin 前置进 PATH，同时给 meson 传 -Dlayershell=disabled -Dman-pages=disabled 固化可选特性，并用补丁把 GOptionEntry 终止项补全为全部字段而非全局压制警告。

**修复命令**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

**验证**:
```
meson setup 日志出现 Program msgfmt found YES 与 Run-time dependency gtk+-3.0 found YES，随后 meson compile 无 missing field 报错；制品内 bin 可执行 --help 退出码 0
```
