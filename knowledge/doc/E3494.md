# E3494: OHPCD CPython 的 stdlib 扩展 _ssl/_sqlite3/_ctypes 无 DT_NEEDED，任何消费者 import 即 symbol not found

## 基本信息
- **严重度**: 2
- **类别**: ohos, musl, linking, python, dependency
- **作者**: 352D

## 错误特征
```
<module ._ssl. from .*/_ssl\.cpython-312[^ ]*\.so.>|undefined symbol: ffi_prep_closure_loc|ImportError: libffi\.so|sqlite3_initialize: symbol not found|SSL_CTX_set_msg_callback: symbol not found
```

## 根因分析
OHPCD 制品仓 / 平台提供的 CPython 发行包把 stdlib 的 _ssl/_sqlite3/_ctypes 编成完全不链原生库的扩展（DT_NEEDED 只有 libc.so），运行时符号靠进程已有映射解析；OHOS musl 不导出解释器符号、且这些 .so 也没把 libssl/libcrypto/libsqlite3/libffi 写进 NEEDED，于是任何 Python 消费者 import 它们都会 symbol not found，与下游库本身无关

## 推荐方案
**方法**: ld-preload-host-native-libs

**说明**: 优先用『带依赖的 wheel/解释器』替换：设备 HNP 解释器与平台 pip 索引的 cp312 ohos wheel 自带 libssl/libsqlite3/libffi 映射；无法替换时把设备上已有的原生 .so 通过 LD_PRELOAD 注入进程（libffi.so / libsqlite3.so.0 在 /data/service/hnp 下）

**修复命令**:
```
LD_PRELOAD="/data/service/hnp/python.org/python_3.12/lib/libffi.so:/data/service/hnp/python.org/python_3.12/lib/libsqlite3.so.0" python3 -c "import ctypes, sqlite3"
```

**验证**:
```
python3 - <<PY
```
