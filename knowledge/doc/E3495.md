# E3495: OHOS 上并存两套 CPython，扩展 ABI 标签由驱动构建的那个解释器决定（.cpython-312-aarch64-linux-ohos.so vs .cpython-312.so）

## 基本信息
- **严重度**: 2
- **类别**: ohos, python, version, runtime
- **作者**: C745

## 错误特征
```
ImportError: dynamic module does not define module export function \(PyInit_.*\)|extension .* not tagged for this interpreter|EXPECTED_EXTENSIONS|cpython-312-aarch64-linux-ohos\.so vs \.cpython-312\.so
```

## 根因分析
OHOS 设备 PATH 上的 /data/service/hnp/bin/python3 的 EXT_SUFFIX 是 .cpython-312.so（HNP 自有 ABI 标签），而制品仓 tool_requires python/3.12.9 的 OHOS CPython 是 .cpython-312-aarch64-linux-ohos.so。用哪个解释器驱动 meson 就决定了扩展落盘的文件名；反过来，校验通道若拿 PATH 上的 python 当基线，会把全部正确命名的扩展判成缺陷

## 推荐方案
**方法**: pin-target-interpreter-tool-requires

**说明**: 构建与校验都显式 tool_requires 平台 CPython（python/3.12.9）并把它交给 meson 的 [binaries] python；校验脚本先取候选解释器的 EXT_SUFFIX，只有当它含 -linux-ohos 时才作为基线，否则跳过并记录备选解释器的实际后缀

**修复命令**:
```
python3 -c "import sysconfig;print(sysconfig.get_config_var(\"EXT_SUFFIX\"))" | grep -q -- "-linux-ohos" || echo "not the target interpreter"
```

**验证**:
```
python3 -c "import sysconfig; print(sysconfig.get_config_var(\"EXT_SUFFIX\"))"  # 设备 HNP: .cpython-312.so ; 制品仓 CPython: .cpython-312-aarch64-linux-ohos.so
```
