# E3504: 命令值编译器的实际路径与必需参数分别绑定

## 基本信息
- **严重度**: 2
- **类别**: cmake, toolchain, consumer
- **作者**: A139
- **来源 PR**: 14388

## 错误特征
```
CMAKE_C_COMPILER is not a full path to an existing compiler tool; command-valued compiler_executables
```

## 根因分析
CMake把整段Python加wrapper命令当作一个编译器路径，导致真实编译器识别失败；必需参数必须独立保留。公开头依赖和消费者可执行文件路径又分别属于传播与运行合同，原多进程测试通过不能替代安装消费者验证。

## 推荐方案
**方法**: bind-physical-compiler-and-mandatory-arguments

**说明**: 读取实际profile的compiler_executables，验证解释器为真实绝对文件；仅对命令值分离首个可执行文件与剩余必需参数，交给CMakeToolchain编译器块和CMAKE_C_COMPILER_ARG1。公开GLib类型通过真实requires的transitive_headers/transitive_libs传递；两个消费者统一使用实际build_folder/bindir绝对路径签名并运行。保留原8入口、15编译程序及严格警告，另验完整API消费者和Harmony UID私有存储。

**修复命令**:
```
CMakeToolchain compiler executable plus CMAKE_C_COMPILER_ARG1; actual native conan create
```

**验证**:
```
original eight GLib entries plus actual CMake test_package and official Finish35
```
