# E3505: Launchpad 时代版本的全网溯源锚 + intltool 死锁包的直驱编译(中型多 TU GLib 库)

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, conan, intltool
- **作者**: 0AE8

## 错误特征
```
intltool-update not found|perl not found|GNU gettext tools not found|Your intltool is too old|config.sub.*Invalid configuration|g_quark_from_static_string.*expected|GETTEXT_PACKAGE.*#error
```

## 根因分析
(1) bzr/daily 时代的 Launchpad 项目不建产品 release,裸版本号的 pristine tarball 只活在未重打包的发行源码包里(openSUSE Factory spec 的 Source0 钉原始 URL 即为字节级未重打包证明),而 launchpad /+download/ 端点已死、发行池只有 daily 版;(2) 该年代 release configure 的 IT_PROG_INTLTOOL 展开含七处独立致命检查(perl/intltool 三脚本/gettext/automake/版本 grep),Makefile.am 裸 PATH 调 glib-genmarshal/xsltproc,config.sub 不识 ohos——CI worker 无法走上游构建。

## 推荐方案
**方法**: obs-pristine-tarball-anchor-plus-direct-drive-compile

**说明**: (1) 版本锚=OBS 公共源 API 直链 + sha256,notes 写全证据链;(2) build() 内嵌 TU 白名单直驱编译,PkgConfigDeps+pkg-config 取依赖 flags,自行落 libtool 版本化 SONAME(-version-info C:R:A → soname .so.(C-A)、file .so.(C-A).A.R),pc/include 按上游 pc.in 镜像;(3) 编译 flags 必带 -DGETTEXT_PACKAGE 与 -DG_LOG_DOMAIN;(4) musl 按 json-glib 先例给 glib .pc 补 -lintl;(5) test_package 真实消费者 find_package 链接做对象级断言。

**修复命令**:
```
conan create archives/l/libdbusmenu-glib/16.04.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
WSL glibc 预验证(11/11 TU+链接+冒烟 5/5)后 conan create archives/l/libdbusmenu-glib/16.04.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
