# E3515: "Wt(emweb) 4.14.0 在 Conan2 CMakeDeps 下的依赖桥接 + 最小依赖面裁剪 + 无 Wt::Test 的端到端测试替代"

## 基本信息
- **严重度**: P2
- **类别**: build-system
- **作者**: j669539
- **来源 PR**: "#15480"

## 错误特征
```
"CMake Error.*WtFindBoost|Could NOT find Boost \\(missing: program_options|Co\\)|Undefined reference.*WServer|fatal error: Wt/WServer"
```

## 根因分析
"Wt 4.x 构建系统有三处与 Conan CMakeDeps 非标准交互的行为：(1) 自带 cmake/WtFindBoost.txt 包装 find_package(Boost 1.66 COMPONENTS program_options thread) 并把命中结果转 Boost::<comp> 目标——需与 CMakeDeps 生成的 BoostConfig 桥接；(2) Boost>=1.69 移除独立 filesystem 组件（并入 system），Wt 默认仍查找该组件致查找失败；(3) 上游 testsuite 依赖随 LIBWTTEST 构建的 Wt::Test harness 与网络服务场景（起监听端口），OHOS CI 沙箱不可行，直接构建 testsuite 会失败。"

## 推荐方案
**方法**: "1) 保留 Wt 自带 WtFindBoost 包装不动——CMakeDeps 产出的 BoostConfig 提供 IMPORTED 目标，WtFindBoost 命中后转 Boost::<comp>，原生兼容；2) 传 WT_CPP17_FILESYSTEM_IMPLEMENTATION=std 绕开 filesystem 组件，conan requires 声明 boost 只取 program_options/thread（Boost>=1.69 不加 system 组件）；3) 最小依赖面裁剪：上游可选组件全 OFF（HARU/PANGO/SQLITE/POSTGRES/FIREBIRD/MYSQL/OPENGL/UNWIND/SAML/LIBWTTEST/LIBWTDBO）+ CMAKE_DISABLE_FIND_PACKAGE_{PNG,GLEW,OpenGL,HPDF,Asciidoctor} 阻断可选查找；4) 测试替代：上游 testsuite 关闭（无 Wt::Test harness），改用 test_package 端到端——真实 WServer + wthttp 连接器在 127.0.0.1 起服务，socket 级取页断言 HTTP 状态行 + 应用标记。"

**说明**: (待补充)

**修复命令**:
```
"cmake.configure(variables={'WT_CPP17_FILESYSTEM_IMPLEMENTATION':'std','BUILD_TESTS':'OFF','LIBWTTEST':'OFF','CMAKE_DISABLE_FIND_PACKAGE_PNG':'ON',...})"
```

**验证**:
```
"grep -n 'WT_CPP17_FILESYSTEM_IMPLEMENTATION' conanbuild.sh; grep -c 'Boost::program_options' <build>/CMakeCache.txt"
```
