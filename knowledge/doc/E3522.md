# E3522: libxml2 2.11+ 对旧消费者的两处破坏：xmlEntity.checked 私有字段被移除、nanohttp 声明被 LIBXML_HTTP_STUBS_ENABLED 隐藏（旧库的默认 www 后端因此不可用且会静默降级）

## 基本信息
- **严重度**: 3
- **类别**: portability, dependency, libxml2
- **作者**: 03BF

## 错误特征
```
no member named 'checked' in 'struct _xmlEntity'|call to undeclared function 'xmlNanoHTTPMethod'|incompatible integer to pointer conversion assigning to 'void \*' from 'int'
```

## 根因分析
libxml2 2.11.0 移除了 xmlEntity 的私有字段 checked（功能并入内部 flags），依赖它做 XXE 防护/去重的老库（raptor2 的 CVE-2012-0037 补丁）编译即失败；libxml2 2.13 起 nanohttp.h 的声明被 #ifdef LIBXML_HTTP_STUBS_ENABLED 包住，OHPCD 的 libxml2/2.15.3.1 未开启 HTTP stubs，因此任何选中 libxml(nanohttp) www 后端的旧库都会得到未声明函数（clang 报 int→void* 转换错误）。raptor2 2.0.16 的 configure.ac 还有一处探测缺陷：只有找到 curl-config 时才置 have_libcurl，仅由 pkg-config 发现 libcurl 时该变量保持 0，于是 --with-www=curl（上游默认）静默退化为 xml 后端。

## 推荐方案
**方法**: ①xmlEntity.checked：把版本守卫改成有上下界 #if LIBXML_VERSION >= 20627 && LIBXML_VERSION < 21100（上游/发行版既定修复，同 SUSE hotfix-libxml-2.11.patch）；②www 后端：不要用 libxml nanohttp，改为 libcurl 后端，并修 configure 的 libcurl 探测守卫 if test "X$CURL_CONFIG" != X || test "X$libcurl_source" = "Xpkg-config"; then（configure.ac 同步，便于日后 rebuild），或在配方里 --with-curl-config 指向可用的 curl-config（注意 Conan 包内 curl-config 可能含陈旧构建路径，实测 OHPCD curl/8.22.0 的 curl-config 指向已失效的 .cache/conan2/p/b 目录，故优先走 pkg-config 分支）。

**说明**: 补丁修 configure 的 libcurl 探测守卫 + raptor_libxml.c 的 checked 守卫上界

**修复命令**:
```
conandata.yml patches 声明后 apply_conandata_patches
```

**验证**:
```
grep -c 'LIBXML_HTTP_STUBS_ENABLED' <libxml2_prefix>/include/libxml2/libxml/nanohttp.h（该宏未定义即 nanohttp 不可用）；grep -n 'have_libcurl=' configure 与 configure.ac（仅 CURL_CONFIG 分支赋值）
```
