# E3523: HarmonyOS PC 上 umask 077 + mktemp -d 生成的 2700 目录属主也无法写入（mkdir/chmod 会归一化为 2771 可写），同时打断 config.guess 兜底与 config.status 文件机制

## 基本信息
- **严重度**: 3
- **类别**: platform, autotools, filesystem
- **作者**: A1EE

## 错误特征
```
config.guess: unable to guess system type + .*dummy.c: Permission denied|config.status: error: could not setup config files machinery|cannot create .*conf[A-Za-z0-9]+/subs1.awk: Permission denied
```

## 根因分析
本机文件系统对目录权限做归一化：mkdir(0700) 或 chmod 700 之后 ls 显示 drwxrws--x(2771) 且可写；而 mktemp -d 在 umask 077 下创建的目录保持 drwx--S---(2700)，写文件返回 EACCES（实测属性为同一 uid）。config.guess 在 uname 未识别时走“编译并运行探测程序”兜底，用 (umask 077 && mktemp -d) 建临时目录 → cat > dummy.c 报 Permission denied，表面症状是 unable to guess system type；autoconf 生成的 configure/config.status 同样用 (umask 077 && mktemp -d "./confXXXXXX") → config.status 无法写 subs1.awk → could not setup config files machinery。

## 推荐方案
**方法**: 补丁化（推荐，可复现可审计）：在 patches/ 中改 configure 的临时目录创建，去掉 umask 077 —— tmp=`mktemp -d "./confXXXXXX" 2>/dev/null` && / mkdir "$tmp" 2>/dev/null（先例 archives/a/aaphoto/0.45/patches/0003-configure.patch）。根本解法是让 config.guess 通过 uname -s=HarmonyOS 直接给出三元组，不再进入兜底路径，见 E007/E160 与 scripts/patch-autotools-ohos.pl。

**说明**: patches/ 中删除 configure 临时目录创建的 umask 077（勿用 sed 就地改生成文件）

**修复命令**:
```
apply_conandata_patches 重放 patches/0003-configure.patch
```

**验证**:
```
cd $TMPDIR && (umask 077; mktemp -d ./mtXXXXXX) 后 ls -lad 得 drwx--S---，touch 该目录内文件报 Permission denied；而 mkdir d && chmod 700 d 后 ls -lad 得 drwxrws--x，touch 成功
```
