# E3524: Do not return -1 through a char: on aarch64 it becomes 255 and any arithmetic or array index built from it goes out of bounds

## 基本信息
- **严重度**: 3
- **类别**: platform, char-signedness, out-of-bounds, wrong-results
- **作者**: plast-2.3.2

## 错误特征
```
Signal 11 \(core dumped\)|SIGSEGV|index out of bounds|wrong nucleotides|garbage characters in translated output|all codons map to the same residue
```

## 根因分析
aarch64 has unsigned plain char by default (x86 is signed). A helper declared as "char f() { return cond ? 1 : -1; }" returns 255 on aarch64, and the value is then promoted to int 255 wherever it is used. When that value is an array index or an index multiplier, every access lands far outside the buffer: reads return garbage (silently wrong results) and writes or larger buffers produce SIGSEGV. The compiler does not flag this because the narrowing happens in the return statement, not in a comparison.

## 推荐方案
**方法**: widen-the-return-type

**说明**: Return the sign/direction value as int (and hold it in an int local). The value is used as an arithmetic operand and as an index offset, so int is its natural type; char was only ever a size optimisation.

**修复命令**:
```
sed -i -E 's/^([[:space:]]*)char([[:space:]]+getDirection[[:space:]]*\\([^)]*\\))/\\1int\\2/' <file>   # then widen the matching local variable too
```

**验证**:
```
grep -rn --include=*.c --include=*.cpp --include=*.h --include=*.hpp -E 'char[[:space:]]+[A-Za-z_][A-Za-z0-9_]*[[:space:]]*\([^)]*\)[^;{]*\{[^}]*-[[:space:]]*1' . ; echo 'static char f(){return -1;} int main(){return (int)f()==-1?0:1;}' > /tmp/p.c && cc /tmp/p.c -o /tmp/p && /tmp/p ; echo "exit=$? (0 on x86, 1 on aarch64)"
```
