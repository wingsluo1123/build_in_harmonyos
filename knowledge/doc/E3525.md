# E3525: Keep fgetc/getc results in an int: on aarch64 char is unsigned, so an EOF sentinel never matches and the read loop spins forever

## 基本信息
- **严重度**: 3
- **类别**: platform, char-signedness, runtime-hang
- **作者**: plast-2.3.2

## 错误特征
```
result of comparison of constant -1 with expression of type 'char' is always true|comparison is always true due to limited range of data type|process hangs while reading a file|no output for minutes during file parsing
```

## 根因分析
aarch64 has unsigned plain char by default (x86 is signed). Code that stores fgetc()/getc() in a char and compares it against EOF (-1) compiles to a comparison that can never be true, because the stored value is truncated to 0..255. When a read loop relies on that sentinel to stop - typically a "skip to end of line" loop after a buffer-length-limited read - the loop spins at end of file instead of terminating. clang reports it at compile time as -Wtautological-constant-out-of-range-compare.

## 推荐方案
**方法**: widen-the-sentinel-variable

**说明**: Keep the byte in an int (or compare before narrowing) so the EOF sentinel survives. The type change is local and has no semantic effect on the byte value itself; also cast the seeding expression from char to unsigned char so the initial value is not sign extended.

**修复命令**:
```
sed -i -E 's/for[[:space:]]*\\(char[[:space:]]+([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*=/for (int \\1 = (unsigned char) /' <file>   # then review each site by hand
```

**验证**:
```
grep -rn --include=*.c --include=*.cpp --include=*.h --include=*.hpp -E '(char|int8_t)[[:space:]]+[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=[[:space:]]*(fgetc|getc|gzgetc)[[:space:]]*\(' . ; printf 'a' > /tmp/nonl.txt ; printf 'x\n' | cat - /tmp/nonl.txt > /tmp/probe.txt
```
