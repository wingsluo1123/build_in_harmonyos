# E3527: 往 /etc/mtab 写挂载条目的用户态挂载助手在 OHOS 链接失败：addmntent(3) 是 glibc 扩展，OHOS libc 的 <mntent.h> 只导出读侧（setmntent/getmntent/getmntent_r/endmntent），且 clang 把隐式函数声明降为 warning，错误面落在 ld.lld 而不是编译器

## 基本信息
- **严重度**: 3
- **类别**: portability, libc, musl, posix, headers
- **作者**: 24E4

## 错误特征
```
ld.lld: error: undefined symbol: addmntent|undeclared function 'addmntent'|implicit declaration of function 'addmntent'
```

## 根因分析
mtab 读写 API 在 libc 里是不对称的。OHOS 用 musl 系 libc，其 <mntent.h> 只提供 POSIX/Unix 读侧四个符号（setmntent/getmntent/getmntent_r/endmntent）；glibc 的写侧扩展 addmntent()（以及 rmmntent 之类）不存在。shfs 0.35 的 shfsmount.c/shfsumount.c 各自实现 update_mtab()，直接调 addmntent() → 链接期 undefined symbol。放大误判的两个因素：(1) clang 15 对未声明函数默认给 -Wimplicit-function-declaration **warning**（不是 error），编译阶段一路绿灯，到 ld.lld 才炸，容易被误读成"少链了某个库"而去找 -l mount / -l mnt；(2) 同头文件里的 MOUNTED 宏在 OHOS sysroot 的 <mntent.h> 中定义为 "/etc/mtab"（不在 <sys/param.h>，那边只提供 MAXPATHLEN=4096），说明可读不可写是刻意的 API 面而非装漏包。

## 推荐方案
**方法**: local-write-side-mntent-shim

**说明**: 在包内补一个 static 写侧 helper，按 mtab(5) 的六字段文本格式（fsname dir type opts freq passno，空格分隔、单行）直接 fprintf，并保持与 addmntent 相同的"出错返回非 0"契约，调用点只换函数名，改动面最小、无平台宏、可原样提交上游。shfs 0.35 落地形态见 archives/s/shfs/0.35/patches/0002-shfsmount-shfsmount.c.patch 与 0003-shfsmount-shfsumount.c.patch：static int shfs_addmntent(FILE *f, struct mntent *m) { return fprintf(f, "%s %s %s %s %d %d\n", ...) < 0; }，同时修掉 update_mtab() 里 if (addmntent(...) == 1) 的判定（helper 用 < 0 判定，须同步改成布尔判非 0）。

**修复命令**:
```
# 上游 shfsmount.c:215 附近插入 helper，并把 addmntent( 调用替换为 shfs_addmntent(
```

**验证**:
```
printf '#include <mntent.h>\n#include <stdio.h>\nint main(void){FILE*f=fopen("/tmp/x","w");struct mntent m={0};return addmntent(f,&m);}\n' > "${TMPDIR:-/tmp}/m.c" && clang "${TMPDIR:-/tmp}/m.c" -o "${TMPDIR:-/tmp}/m"; echo rc=$?   # 期望 warning + ld.lld: error: undefined symbol: addmntent，rc=1
```
