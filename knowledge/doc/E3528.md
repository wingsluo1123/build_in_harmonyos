# E3528: 上游 Makefile 里的 GCC 遗留选项 -I-（include 路径分隔符）被 clang 驱动直接拒绝：'-I-' not supported, please use -iquote instead —— 按语义改写为 -iquote/-I，不是关掉 -Werror，也不是换回 gcc

## 基本信息
- **严重度**: 3
- **类别**: portability, build-system, make, toolchain, clang
- **作者**: 24E4

## 错误特征
```
'-I-' not supported, please use -iquote|error: '-I-' not supported
```

## 根因分析
-I- 是 GCC 4.x 以前的"include 搜索路径分隔符"：出现在命令行时，它之前的 -I 目录只参与 <...> 尖括号搜索，之后的只参与 "..." 双引号搜索（等价于今天的 -idirafter/-iquote 分工）。Clang 从未实现该选项，而鸿蒙 SDK 只有 LLVM/Clang（P010），所以任何把 -I- 硬编码进 Makefile/spec 的老项目，在第一条编译命令就被 clang driver 以 rc=1 拒掉。关键辨别点：这是 driver 参数解析错误，发生在源文件被读取之前——与头文件是否存在、内容是否合法完全无关，日志里不会有文件名和行号。实证（shfs 0.35 shfsmount/Makefile）：SEARCHDIRS := -I- -I. -I../shfs/Linux-2.4/

## 推荐方案
**方法**: rewrite-legacy-include-flag-to-iquote

**说明**: 按 -I- 的原语义把它拆成真实意图：项目私有头目录（需要 "..." 优先命中）改写为 -iquote <dir>；确实只需要 <...> 搜索的目录保留 -I <dir>。shfs 案例里上游意图是"当前目录与 Linux-2.4 头目录优先于系统目录"，等价改写为 -iquote . -iquote ../shfs/Linux-2.4/，只改上游 Makefile 源文件（不是生成文件），遵循上游风格并可用 refresh-patch --auto 落成 patches/0001-shfsmount-Makefile.patch 提交（P005/P011）。

**修复命令**:
```
sed -i 's|^SEARCHDIRS := -I- -I\. -I\(.*\)|SEARCHDIRS := -iquote . -iquote \1|' shfsmount/Makefile   # 已在 scratch Makefile 上干跑，结果与 patches/0001 逐字符一致
```

**验证**:
```
printf 'int main(void){return 0;}\n' > "${TMPDIR:-/tmp}/q.c" && clang -I- -c "${TMPDIR:-/tmp}/q.c"; echo rc=$?   # 期望 rc=1，stderr 出现 '-I-' not supported, please use -iquote instead
```
