# E3531: OHOS 的 <math.h> 不声明、共享 libm 也不导出 GNU 扩展 exp10()（只有静态 libc.a 里有该成员）⇒ 沿用 glibc 的旧 C 代码在链接期报 undefined symbol: exp10；改为 pow(10,x) 等价且必然可用

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, linking, math
- **作者**: unknown
- **来源 PR**: PRE_CREATE

## 错误特征
```
undefined symbol: exp10|undefined reference to .exp10|referenced by .*\.c\.(obj|o)
```

## 根因分析
exp10() 不是 C 标准函数而是 glibc 的 GNU 扩展（glibc 的 math.h 在 _GNU_SOURCE 下声明它、libm.so 导出它），OHOS/musl 这一侧两处都不满足：①sysroot 的 <math.h> 没有 exp10 声明（实测 grep -n exp10 $SYSROOT/usr/include/math.h 无命中），因此源码即使写了 #define _GNU_SOURCE 也拿不到原型（clang 只给隐式声明警告、不成错）；②共享 libm 不导出该符号（实测 llvm-nm -D --defined-only libm.so | grep -c ' exp10$' = 0），llvm-nm --defined-only 只在静态 libc.a 里能找到 ' T exp10'（=1），即符号"存在但不可动态取用"，所以问题只在链接期暴露、编译期毫无提示。实测 pnmixer 用它做 ALSA dB 增益到线性幅度换算（upstream src/alsa.c: normalized = exp10((value - max) / 6000.0)），Linux 开发机（glibc）全绿、OHOS 目标侧报 ld.lld: error: undefined symbol: exp10 / >>> referenced by alsa.c / >>> CMakeFiles/pnmixer.dir/alsa.c.obj:(alsa_card_get_volume)，是典型"本地绿、目标红"的 libc 差异；同族还可能有 exp10f/exp10l 等 glibc-only 数学扩展。

## 推荐方案
**方法**: replace-gnu-exp10-with-pow10

**说明**: 在调用点之前提供一个数学等价、必然可用的回退定义，不做平台宏分支：#ifndef exp10 / #define exp10(x) pow(10.0, (x)) / #endif。四条要点：①#ifndef 守卫——在不缺该函数的 libc 上不覆盖既有定义/宏；②只在"不取 exp10 地址"的代码里可用（&exp10、函数指针赋值会因宏编译失败，先 grep -n exp10 src/*.c 确认用法）；③不引入 __OHOS__ 等平台宏（R8/PF5 合规），回退在全部 POSIX 平台语义相同；④别顺手改成 expl/powl，那是另一族 libc 差异点。

**修复命令**:
```
grep -n 'exp10' src/*.c ; 在 #include <math.h> 之后加 #ifndef exp10 / #define exp10(x) pow(10.0,(x)) / #endif ; 重新 conan create
```

**验证**:
```
llvm-nm -D --defined-only $SYSROOT/usr/lib/aarch64-linux-ohos/libm.so | grep -c ' exp10$' ; llvm-nm --defined-only $SYSROOT/usr/lib/aarch64-linux-ohos/libc.a | grep -c ' T exp10$'
```
