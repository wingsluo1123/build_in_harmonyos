# E3533: OHOS 无系统 ndbm，只能用 gdbm compat 层：其 <ndbm.h> 无 include guard（同一 TU 二次包含即硬错误），且制品仓 gdbm/1.23 与 gdbm/1.24 的 compat 开关相反

## 基本信息
- **严重度**: 2
- **类别**: compat, headers, dependency, packaging
- **作者**: unknown

## 错误特征
```
typedef redefinition with different types \('struct DBM' vs 'struct DBM'\)|unguarded header; consider using|ndbm\.h' included multiple times|fatal error: 'ndbm\.h' file not found|fatal error: 'dbm\.h' file not found|undefined symbol: dbm_open|undefined symbol: dbm_fetch|ld\.lld: error: cannot find -lgdbm_compat
```

## 根因分析
OHOS/musl 根本不提供 ndbm/dbm（没有 <ndbm.h>、<dbm.h>，libc 里也没有

## 推荐方案
**方法**: pick-compat-enabled-gdbm-and-single-include-point

**说明**: 两步，都是最小改动、不引入任何平台宏：

**修复命令**:
```
>
```

**验证**:
```
G=$(conan cache path gdbm/1.23)/p; printf '#include <ndbm.h>\n#include <ndbm.h>\nint main(void){DBM *d=dbm_open("x",0,0600);(void)d;return 0;}\n' > /tmp/ndbm2.c; clang --target=aarch64-linux-ohos --sysroot=$SYSROOT -c /tmp/ndbm2.c -I$G/include -o /dev/null; grep -c 'ifndef\|pragma once' $G/include/ndbm.h; grep -n 'libgdbm-compat' $(conan cache path gdbm/1.23)/e/conanfile.py $(conan cache path gdbm/1.24)/e/conanfile.py
```
