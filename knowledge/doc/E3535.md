# E3535: 上游 CMakeLists 若用**普通 `SET()`** 硬写安装变量为绝对路径（如 `SET(RULES_INSTALL_DIR "/usr/lib/udev/rules.d/")`），toolchain 侧 `tc.variables` 的同名预置会被**目录作用域遮蔽**而失效 → `cmake --install` 试图写宿主机绝对路径并以 `file cannot create directory: /usr/... Maybe need administrative privileges` 失败；修法是打补丁改成相对的 `${CMAKE_INSTALL_LIBDIR}/…`（对照：上游用 `CACHE STRING` 时预置才生效）

## 基本信息
- **严重度**: 3
- **类别**: cmake, conan, packaging
- **作者**: 373D

## 错误特征
```
file cannot create directory: /usr/|Maybe need administrative privileges|tc.variables 预置不生效|安装产物落到宿主机绝对路径
```

## 根因分析
上游 indi-armadillo-platypus/CMakeLists.txt 写的是 `SET(RULES_INSTALL_DIR "/usr/lib/udev/rules.d/")`（普通变量），而 `install(FILES 99-armadilloplatypus.rules DESTINATION ${RULES_INSTALL_DIR})` 用的是它。 CMake 里**普通 `SET()` 在当前目录作用域内会遮蔽同名 cache 变量**，因此无论 Conan 的 `tc.variables["RULES_INSTALL_DIR"]="lib/udev/rules.d"` 怎么预置，配置后该变量的值都被上游改回绝对路径。 `cmake --install --prefix <包目录>` 对**绝对** DESTINATION 不使用 prefix → 直接去创建 `/usr/lib/udev/rules.d`，在无 root 的构建环境里报 `CMake Error at cmake_install.cmake:178 (file): file cannot create directory: /usr/lib/udev/rules.d. Maybe need administrative privileges.` 对照证据（同族、同 repo、同样有 udev 规则）`libfli/CMakeLists.txt`： `set(UDEVRULES_INSTALL_DIR "/usr/lib/udev/rules.d" CACHE STRING "…")` —— **CACHE** 变量可被 `tc.variables` 预置覆盖，所以 libfli 靠预置即可生效。差异不在工具链，而在上游**是否用 CACHE**。

## 推荐方案
**方法**: patch-absolute-install-variable-to-relative-datadir

**说明**: 首选**补丁**把该变量改成相对路径（`GNUInstallDirs` 通常已被 include）： `SET(RULES_INSTALL_DIR "${CMAKE_INSTALL_LIBDIR}/udev/rules.d")` —— 相对 DESTINATION 会随 `cmake --install --prefix <包目录>` 落到包内，产物不丢、也不写宿主机。同时**删除配方里失效的 toolchain 预置**（否则后人会以为它在生效）。若该安装整体不必要，备选是关掉上游自带的开关 （如 `option(INDI_INSTALL_UDEV_RULES …)` 可用 `tc.variables[...]="OFF"` 预置——`option()` 不会覆盖已存在的 cache 变量），但那样辅助产物会被丢弃，需在 notes 里说明。

**修复命令**:
```
patch -p1 --dry-run < patches/000N-<pkg>-CMakeLists-absolute-install-to-relative.patch
```

**验证**:
```
① `grep -nE "SET\\(|<var>" <src>/CMakeLists.txt` 看是否有 `CACHE` 关键字（有 CACHE 才可能被预置覆盖）② 配置后 `grep -n "^<VAR>" <build>/CMakeCache.txt` 确认预置是否仍在 ③ `cmake --install` 输出里核对每个 `-- Installing:` 的目标是否都在 `<包目录>` 内
```
