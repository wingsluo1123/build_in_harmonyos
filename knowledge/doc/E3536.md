# E3536: 一个工程产出**多个**可执行/数据文件时（本包 6 驱动 + 1 XML + 1 udev 规则），消费者校验不能只验"其中一个产物"——应把产物清单化、逐产物做架构审计、并把清单文件（XML/JSON/desktop）与 bin/ 做**双向**比对（缺一条/多一条都判失败），另加辅助产物落点与 best-effort 运行检查

## 基本信息
- **严重度**: 2
- **类别**: packaging, testing
- **作者**: 0173

## 错误特征
```
只校验了一个产物|清单声明与 bin/ 不一致|辅助产物未随包安装|漏检多产物包
```

## 根因分析
单驱动包的消费者校验只要"验一个 bin + 一个 XML"就够，而多产物包极易出现三类漏检： ①只验了第一个可执行文件，其余 5 个即使架构错误/未安装也照样 PASS； ②清单文件（如 INDI 的 `driversList` XML、desktop 文件、pkg-config）与实际 `bin/` 不一致—— 少声明一条（客户端发现不了）或声明的可执行并不存在（运行期才炸）； ③辅助产物（udev 规则、systemd unit、图标等）被安装到包外/被丢弃，单看 bin/ 完全发现不了。

## 推荐方案
**方法**: enumerate-artifacts-and-cross-check-the-manifest

**说明**: 把期望产物写成脚本内的常量元组（`EXPECTED_DRIVERS = (...)`），然后： ①**逐产物**做架构/非空/ELF 审计（AArch64 + 64 位 + 非空 + magic）；②解析清单文件（正则抓 `<driver name="…">EXE</driver>` 之类），做**双向**比对——声明的都要在 bin/ 里找到，bin/ 里的 也都要被声明（缺/多都判失败）；③对每个产物（或按同一链接配置抽样）做 DT_NEEDED 静态闭包审计 （期望依赖库齐备、条目均为裸 soname、且都能在依赖包内找到）；④按落点断言辅助产物； ⑤运行类检查 best-effort，宿主拒绝（沙箱 mmap/未签名/权限）记 SKIP 并打印原文，绝不把平台限制 记成失败、也不把未运行写成通过。输出统一的 `checks=/fails=/skips=` 三计数便于 CI 解析。

**修复命令**:
```
python3 check_all_drivers.py <bindir> <xml> <libindi-pkg>/lib <rules-file>
```

**验证**:
```
python3 check_all_drivers.py <bindir> <resdir>/indi/<manifest>.xml <dep-pkg>/lib [<辅助产物路径>] # 断言：逐 bin ELF + 清单双向比对 + 逐 bin DT_NEEDED + 辅助产物存在 + best-effort 运行
```
