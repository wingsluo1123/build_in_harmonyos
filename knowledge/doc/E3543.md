# E3543: Keep custom Autotools installed-header includes relative to avoid baking pkgincludedir into packages

## 基本信息
- **严重度**: 2
- **类别**: headers, autotools, conan, packaging, relocatability
- **作者**: iKalous_OscarP

## 错误特征
```
'#include.*"/.*(include|headers)/.*\.hpp|header.*absolute.*pkgincludedir|package.*relocat.*include.*fail'
```

## 根因分析
A hand-written install-data-local rule rewrites every quoted include to include $(pkgincludedir). Since configure resolves the install prefix to an absolute Conan package folder, installed headers retain that build-time package path. A consumer can compile while the package remains at that exact location, but package relocation leaves internal header includes pointing at the old prefix. DESTDIR staging does not rewrite the configured prefix embedded in header text.

## 推荐方案
**方法**: keep-installed-header-includes-relative

**说明**: Preserve co-located header include basenames during installation. Rewrite only the generated config.h reference to a package-specific config header, expose the installed include root through package metadata, and add a fail-closed scan for absolute include directives.

**修复命令**:
```
sed -e 's%#include "config.h"%#include "libthreadar_config.h"%g' source.hpp > package/include/pkg/source.hpp; scan installed .h/.hpp files for absolute #include paths; compile a consumer after relocating the package prefix
```

**验证**:
```
Inspect the installed public headers for include directives beginning with an absolute path; move or copy the package to a different prefix and compile a minimal consumer that includes the umbrella header.
```
