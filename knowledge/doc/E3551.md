# E3551: 运行期服务缺失时的清理路径空指针崩溃：宿主程序在无音频/显示服务的平台上以 SIGSEGV 退出而不是优雅失败，需补 NULL 守卫并以「优雅失败」而非「非零退出」做测试断言

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime-resolution
- **作者**: weijiapan

## 错误特征
```
Failed to connect to audio system|Segmentation fault|exit code 139|SIGSEGV
```

## 根因分析
上游把运行期服务（JACK/ALSA/显示服务/DBus）的连接放在初始化中段，把 instance/client/display 一类句柄留成惰性初始化；

## 推荐方案
**方法**: guard-lazy-handle-in-cleanup-path

**说明**: 在失败清理函数的循环里为惰性初始化句柄加 NULL 守卫（守卫只包住解引用本身，保留上游释放顺序；禁止 `if (!h) return;` 提前返回以免泄漏），

**修复命令**:
```
conan create archives/j/jalv/1.10.0 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```

**验证**:
```
无服务环境运行被测二进制并把输出落文件：`timeout 20 <bin> <real-consumer-arg> > host.txt 2>&1; echo rc=$?`；
```
