# E3559: 完整 next URL 与首次 params 重复合并，后续页携带两个 page 值

## 基本信息
- **严重度**: 2
- **类别**: network, python, runtime, testing
- **作者**: CBE1

## 错误特征
```
AssertionError: {'page': ['2', '1'], 'q': ['hello']} != {'page': ['2']}
```

## 根因分析
分页循环把服务端 next 完整 URL 作为新 path，却继续传首次请求的 params；requests 将 params 追加到 URL 已有 query，使 page=2 后再出现 page=1，过滤参数也被重复重放

## 推荐方案
**方法**: next-url-owns-following-query

**说明**: 仅在第一次 get 成功后将局部 params 设为 None，后续完全采用 next 的 query；首请求过滤参数和原同源校验保留。用原 responses 和三页固件验证首参一次、后续页码唯一、50 个唯一结果和三请求终止

**验证**:
```
python3.12 -B -m unittest discover -s tests -t . -v
```
