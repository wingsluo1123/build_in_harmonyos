# E3564: OHOS 真机运行上游自带测试套件的“环境假失败”判定与证据链（GNU 用户态假设 × 平台语义）：toybox grep 不实现 GNU BRE 扩展（`\+` 量词）→ 断言假失败；chmod 只读语义不生效 → “不可删除文件”类目录计数偏差；JVM os.version 含空格 → 平台排除条目失配——三分类归因、最小复现、不改上游断言、如实回填通过率

## 错误特征
```
wrong number of scratch directories found|grep.*did not produce PASS|Test results: passed: 1; failed: 2; skipped: 1|unexpected files found
```

## 根因分析
上游自测脚本按 GNU 用户态假设编写（GNU grep BRE 扩展、POSIX 只读目录语义），而 OHOS 真机是 toybox 用户态 + HMDFS/SELinux 权限模型 + BiShengJDK 属性视图。三类实测：① toybox grep 不实现 GNU BRE 的 `\+` 量词（按字面处理）→ 上游 `grep '... \+Passed...'` 断言 rc=1 假失败（同一 pattern 改 `grep -E '... +Passed...'` 即通过；设备 grep 为 `usr/bin/grep -> toybox`）；② chmod 只读在 HMDFS/SELinux 下不生效 → 上游“不可删除文件”清理类测试的“scratch 目录计数=5”断言失败，而该组 5 个用例本身全部 PASS（jtreg CleanupTests.agentvm.retain）；③ JVM os.version 含空格 → JavaTest ProblemList OSNAME-REV 排除条目失配（详见主条 DRAFT-12683-ohos-jvm-platform-properties-vs-osname-rev-selectors）。三者均非被测库缺陷，但直接决定“上游测试通过率”口径的真实性。

## 推荐方案
**方法**: three-way-triage-and-evidence-chain

**说明**: 在 OHOS 真机跑上游自测套件时按三分类归因并留证据链：① 环境语义差异（工具实现差异/平台权限语义/JVM 属性）→ 不计库缺陷，逐项记录；② 真实回归 → 修复；③ 不可判定（挂起）→ 限时记录并终止（不无限等待）。证据链要求：原始日志行 + 最小复现命令 + 对照实验（同 pattern 的 `grep -E` 复测 / 权限对照 / 属性组对照）。统计口径：上游 CI 初始集（如 quick-test）在构建内复跑作为可复现门禁；真机全量结果按三分类列出 通过/失败/挂起，绝不改上游断言凑绿（R51）。自研测试脚本避免 GNU 扩展（`grep -E/-F`、`case`）。

**修复命令**:
```
printf 'a b\n' | grep 'a \+b' && echo BRE-OK || echo BRE-MISSING   # 判定当前 shell 的 grep 能力
```

**验证**:
```
# toybox grep BRE 扩展探针（设备实测）
```
