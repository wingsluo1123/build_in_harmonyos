# E3565: OHOS 上 JVM 平台属性视图 ≠ 内核 uname 视图：os.name=HarmonyOS、os.version="HongMeng Kernel x.y.z"（含空格/非语义版本号），按 `osname-版本` 约定生成/匹配选择器的 Java 工具静默失配（jtreg/JavaTest ProblemList OSNAME-REV 排除条目未生效；Gradle OperatingSystem 拒识别）——需显式规范化 JVM 属性或改用精确/分组选择器

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, java, testing
- **作者**: 9C4A
- **来源 PR**: "14710"

## 错误特征
```
ExceptionInInitializerError.*OperatingSystem|os\.name.*(HarmonyOS|unrecognized|not supported)|passed: [0-9]+; excluded: [0-9]+.*expected|OSNAME-REV.*(no match|miss)|hongmengkernel[0-9.]+.*(excluded|mismatch)
```

## 根因分析
Linux 生态约定 JVM 平台属性是“内核-发行版”视图（os.name=linux、os.version=x.y.z 无空格），工具据此生成/匹配 `osname-arch`、`osname-版本` 平台选择器。BiShengJDK on HarmonyOS 暴露的是 JVM 自身构建视图：os.name=HarmonyOS（非 linux）、os.version="HongMeng Kernel 1.12.0"（含空格、非 x.y.z）。两类后果：① 生成侧对 os.version 去空白得 `harmonyos-hongmengkernel1.12.0`，与匹配侧语义不一致 → 平台排除/选择条目静默失效（jtreg 自测 ProblemList：期望 passed:1，实得 passed:2; excluded:4，多跑 1 例且全过程无报错）；② 按 os.name 枚举分支的 JVM 工具直接抛错（Gradle OperatingSystem 类不识别 HarmonyOS → ExceptionInInitializerError，archives/g/gradle/8.12 包先例用 wrapper 注入 -Dos.name=Linux）。注意与构建期 `uname -s` 类问题（E007/E160/E140/DRAFT-12718）属不同视图：本条是 JVM 运行期属性面，构建脚本之外的工具/测试同样命中。

## 推荐方案
**方法**: normalize-jvm-os-properties-or-precise-selector

**说明**: OHOS 上适配 JVM 工具/测试的三类手法（按需选用）：① 启动选项规范化——JAVA_TOOL_OPTIONS 注入 `-Dos.name=Linux`（JAVA_TOOL_OPTIONS 会被所有 JVM 进程含 fork/daemon 继承，优于只改单一入口；Gradle wrapper 先例）；② 选择器精度——生成/匹配 `OSNAME-REV` 时不要假设 os.version 无空格或为语义版本，使用完整字符串、通配/前缀分组，或改按 os.name 分支；③ 测试侧归因纪律——把“多跑/漏跑用例”归因为平台属性视图差异并记录（不修改上游断言凑绿），在测试报告中如实注明。

**修复命令**:
```
export JAVA_TOOL_OPTIONS="${JAVA_TOOL_OPTIONS:+$JAVA_TOOL_OPTIONS }-Dos.name=Linux"
```

**验证**:
```
java -XshowSettings:properties -version 2>&1 | grep -E 'os\.(name|arch|version)'
```
