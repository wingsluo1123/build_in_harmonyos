# E3566: "Probe RNDGETENTCNT and a zero-length/zero-entropy RNDADDENT

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, capability-boundary, ioctl
- **作者**: "主理-6"

## 错误特征
```
"RNDADDENTROPY ioctl on /dev/random returns ENOTSUP (errno 95) on HarmonyOS PC"
```

## 根因分析
"The tested HarmonyOS PC device permits a read-only RNDGETENTCNT query but rejects even a zero-entropy RNDADDENTROPY request with ENOTSUP. A successful generator build is therefore not evidence that an entropy daemon can inject into the kernel pool."

## 推荐方案
**方法**: "Probe RNDGETENTCNT and a zero-length/zero-entropy RNDADDENTROPY request before enabling an entropy-injection daemon. If ADD returns ENOTSUP, disable the daemon and expose only independently tested file/stream generation and library APIs. State that kernel injection is unverified/unsupported for this environment."

**说明**: (待补充)

```
"python3 rng-ioctl-probe.py  # O_RDWR|O_NONBLOCK /dev/random; GET before, ADD(0,0), GET after"
```
