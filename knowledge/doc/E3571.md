# E3571: Linux I2C userspace package 在没有真实适配器时：分离无硬件契约检查与总线事务，避免把缺失硬件伪报为测试通过

## 基本信息
- **严重度**: 2
- **类别**: ohos, testing, hardware-free, i2c, linux-kernel-uapi
- **作者**: 328

## 错误特征
```
I2C bus out of range|ioctl.*EBADF|no upstream test/check target
```

## 根因分析
Linux I2C 用户态工具把输入解析、设备枚举、打开 /dev/i2c-* 与 ioctl 事务串在一条命令路径中；无真实适配器时，安全的版本信息、列表和参数拒绝路径仍可验证，但扫描与 SMBus/I2C 事务需要 adapter。上游没有测试源或 check/test 目标，因此必须区分“上游无测试”与“上游测试通过”，并为消费者接口补足可重复检查。

## 推荐方案
**方法**: separate hardware-free contracts from bus transactions and report upstream test absence explicitly

**说明**: 1) audit the exact release tree for test sources and check/test targets; zero findings means upstream denominator 0, not a passing executed suite; 2) run deterministic CLI contracts that exit before opening a bus (version, listing, invalid bus range); 3) link a real consumer against packaged libi2c and verify documented ioctl error propagation with an invalid descriptor; 4) never count build steps as tests or report hardware paths as covered; 5) exercise transactions only when a real adapter or intentionally provisioned i2c-stub exists, recording that setup separately.

**修复命令**:
```
inventory the release Makefile and tree; run only safe CLI checks and invalid-fd consumer checks; log upstream 0/0 separately from the consumer test count; do not invoke scanning or device transactions without an adapter
```

**验证**:
```
make -n check; make -n test; find . -path '*test*' -type f; i2cdetect -V; i2cdetect -l; i2cdetect 1048576; i2cget 1048576 0x50; compile a libi2c consumer that calls i2c_smbus_read_byte(-1)
```
