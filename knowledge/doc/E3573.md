# E3573: Java 包适配有三个易错点——①**运行期依赖容易被当成"构建期 jar"**：源码 `import X.*` 意味着 X 必须在**运行期**也在 classpath 上（本例 `jasmin/*` 实现 `java_cup.runtime.Scanner` → java-cup 必须随包提供，否则只是"编译成功、运行时 NoClassDefFoundError"）；②**老 ant 工程可以不跑 ant**：若 `build.xml` 里代码生成目标（cup/autogen 等）的产物**已随 tarball 提供**，直接用 `javac` 编译即可；③**多源码集要按 import 关系取全**（本例汇编器 `import jas.*` → 必须同时编译 `lib/jas/src`），且自写的包装脚本 classpath **每个条目都要写全路径**（漏前缀会让 JVM 找不到依赖，报错却像"依赖缺失"）

## 基本信息
- **严重度**: 3
- **类别**: java, packaging, dependencies
- **作者**: 8B66

## 错误特征
```
NoClassDefFoundError|ClassNotFoundException|缺类|cannot find symbol|需要生成器才能编译
```

## 根因分析
①Java 的依赖作用域只体现在构建工具的声明里（Maven scope / ant classpath），而"运行时也要"这件事 在只有 `import` 的源码里看不出来；把自取 jar 只放在构建期 classpath 就埋下 NoClassDefFoundError。 ②老工程把"生成代码"与"手写代码"一起纳入版本控制，导致生成器并非必需——不辨此点就会去装/引入 cup、ant 等一串工具。③自写启动脚本时，classpath 由多个路径拼成，容易漏写目录前缀； 而 JVM 对 classpath 里**不存在的条目是静默忽略**的，报错指向"找不到类"而非"路径无效"。

## 推荐方案
**方法**: runtime-jars-shipped-plus-skip-ant-when-generated-sources-present

**说明**: ①**先列源码 import**，据此列出"编译期 + 运行期"都需要的外部包；制品仓没有的按"自取"口径从 Maven Central 取（钉 sha256），并**放进包里**（如 `libexec/`），启动脚本/classpath 同时指向它们；②**判断能否跳过构建工具**：看上游代码生成目标（`build_parser`/`autogen_run` 之类）的**产物是否已随源码发布**（本例 `parser.java`/`sym.java`、`generated/scm/**` 都在）→ 在则 `javac` 直编三处源码即可，不必引入 ant/cup/autogen；③**多源码集按 import 关系取全**（`src` + `lib/jas/src` + `generated`），编译后核对主类存在；④自写启动脚本时**classpath 每个条目都写全路径**，并在消费者校验里做**端到端真跑**（本例：`jasmin Hello.jas` → 校验 `CAFEBABE` → `java Hello` 断言输出），这是唯一能同时证明"运行期依赖齐备 + classpath 正确"的手段。

**修复命令**:
```
grep -rh '^import ' src | sort -u ; grep -n 'classpath' build.xml ; javac -cp <self-fetched.jar> -d classes $(find src lib/jas/src generated -name '*.java') ; sh bin/<tool> <sample> && java <Generated>
```

**验证**:
```
①`grep -rh '^import ' <src> | sort -u`（列出源码真正依赖的包）②`grep -n 'classpath' build.xml`（构建期 classpath）③运行期验证：用**打包后产物**跑一次真实功能（本例：汇编 .jas → 执行生成的类）——只做编译期检查发现不了运行期缺依赖
```
