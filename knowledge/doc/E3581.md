# E3581: Isolate CPython test support namespaces to preserve vendor-adapted standard library behavior

## 基本信息
- **严重度**: 3
- **类别**: platform, compat, detection, testing
- **作者**: M019

## 错误特征
```
No module named .test.|PermissionError.*Operation not permitted|context has already been set
```

## 根因分析
A complete upstream CPython Lib on PYTHONPATH silently replaces vendor-adapted runtime modules even when the installed third-party package origin is correct. Its fork may also retain stale capability and address-selection policies.

## 推荐方案
**方法**: isolate-cpython-test-support-and-verify-runtime-origins

**说明**: Extract the matching official CPython test namespace alone into a build-private support root. Keep runtime stdlib outside that root; test the installed package from another cwd and trace parent and child origins. Apply vendor capability decisions without freezing global context and ensure address producers consume those decisions.

**修复命令**:
```
Copy only Lib/test to test-support/test; inherit test-support plus installed site on PYTHONPATH; python -s -P -m multiprocess.tests
```

**验证**:
```
Record __file__ for test.support, subprocess, multiprocessing.context and multiprocessing.util in parent and fresh children; compare default context and actual AF_UNIX bind capabilities
```
