# E3584: 容器 uid 不在 /etc/passwd 时，调用 g_get_user_name() 的 g_test 二进制 FATAL 启动崩溃、零用例执行

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos
- **作者**: gcw_Pp8UzTBn <2280277721@qq.com>

## 错误特征
```
Bail out!|Signal 6 \(core dumped\)|TAP version 14.*random seed.*(无后续用例输出)
```

## 根因分析
容器 uid（如 20020090）不在 /etc/passwd；g_test 二进制的 main 若调用 g_get_user_name()/g_get_home_dir()（如 totem-plparser 测试 main 的 check_http() → g_get_user_name()），glib 的 g_get_user_name_real 在 getpwuid_r 失败时 FATAL：进程在注册用例前 abort（Signal 6），日志只有 TAP 头 + random seed，零用例执行；LD_PRELOAD 的 .so 若带 libc 外符号则子进程（如 videosite 派生的 /bin/sh）继承后 relocation 错误死亡（rc=127）

## 推荐方案
**方法**: ldpload-getpwuid-shim

**说明**: LD_PRELOAD 纯 C getpwuid_r 拦截器（返回合成条目 pw_name="user"、pw_dir=$HOME、返回 0），.so 只允许带 libc 符号

**验证**:
```
nm -D libshim.so 应只导出 getpwuid_r（U 仅 libc）；LD_PRELOAD=libshim.so HOME=$HOME ./parser 应输出 TAP 用例而非 Signal 6
```
