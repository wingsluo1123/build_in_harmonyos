# E3585: meson install rpath fixup 在 hmdfs 上 in-place 重写 .so 损坏 ELF，dlopen 返回 EACCES

## 基本信息
- **严重度**: 3
- **类别**: platform, hmdfs
- **作者**: gcw_Pp8UzTBn <2280277721@qq.com>

## 错误特征
```
dlopen.*EACCES|cannot open shared object.*Permission denied.*\.so|\.so.*sha256.*mismatch
```

## 根因分析
meson 安装阶段对 staging 目录中的 .so 执行 in-place rpath fixup（重写 RUNPATH 段）；在 hmdfs 文件系统上 in-place 重写损坏 ELF：包内 .so 比构建树小 306 字节、.dynstr/RUNPATH 区被 0x58 填充，dlopen 返回 EACCES（内核拒绝执行损坏 ELF，报权限错误）；ohpcd 下载与 shell cp 复制的 .so 完好，损坏只发生在 in-place 重写路径

## 推荐方案
**方法**: package-sha256-verify-recopy

**说明**: recipe 的 package() 对共享库做 sha256 校验（包目录 vs 构建树），不一致时 shutil.copy2 从构建树重拷（重拷 .so 保留构建树 RUNPATH，本机有效、CI 无害）

**验证**:
```
conan create 后比对包内 lib/*.so 与构建树同名文件 sha256sum（应一致），test_package 二进制 dlopen 应成功
```
