# E3586: OHOS 无 shared-mime-info MIME 数据库，扩展名/内容探测全退化 octet-stream，content-type 路由失败

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos
- **作者**: gcw_Pp8UzTBn <2280277721@qq.com>

## 错误特征
```
g_content_type_guess.*octet-stream|_get_mime_type.*returned 'application/octet-stream'|MIME type.*not found
```

## 根因分析
OHOS 无 /usr/share/mime（shared-mime-info）数据库；glib 2.84 vendored libxdgmime 只读 MIME 目录下 4 种文件格式：globs（v1 文本 "mimetype:glob"）、magic（v1 二进制：12 字节头 MIME-Magic\0\n + [priority:mime] 节头 + >offset=<2字节大端长度><原始值>[+N 扫描范围]，缺文件头整文件被静默拒绝、range_length=0 恒不匹配）、subclasses（每行 "派生 父" 提供 is_a 层级）、aliases；无库时扩展名探测与内容嗅探均退化 application/octet-stream，依赖 content-type 路由的库全部失败

## 推荐方案
**方法**: inject-minimal-mime-db

**说明**: 构建最小 MIME 库目录（globs+magic+subclasses），经 XDG_DATA_HOME 环境变量注入（公开接口，glib 自动读 $XDG_DATA_HOME/mime/）或 g_content_type_set_mime_dirs()（gio 私有 API）

**验证**:
```
构建最小 MIME 库目录(globs+magic+subclasses) 并 export XDG_DATA_HOME 指向它后运行 totem-pl-parser 解析 m3u 文件应成功解析出条目；或 magictest 程序对 <playlist 样本内容调用 _xdg_mime_magic_lookup_data 应返回 application/xspf+xml
```
