# E3590: Conan 2 库消费链上 CMakeDeps 生成的 CMake 视图（版本 major 对齐、命名空间 target、header-only 链接传播、无 config 库 shim）与上游 CMakeLists 期望不匹配，conan create 主包 configure 阶段逐层失败

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, packaging, c++-libraries
- **作者**: gcw_6YxinkyD
- **来源 PR**: (本 PR 提交后回填)

## 错误特征
```
.*in version range .* is not a valid option|Could not find a package configuration file provided by "xeus"|The following configuration files were considered but not accepted.*version: 6.0.5|The link interface of target "OpenSSL::Crypto" contains.*but the target was not found
```

## 根因分析
CMakeDeps 在消费端生成的 CMake 视图与上游 CMakeLists 假设不同：(1) *-config-version.cmake 强制 PACKAGE_FIND_VERSION_MAJOR 与 PACKAGE_VERSION 的 major 相等才 COMPATIBLE，上游 CMakeLists 中残留的旧 major 最低版本声明（xeus-zmq 的 find_package(xeus 5.0.0) vs 实际配套 xeus 6.0.5）被拒；(2) CMakeDeps 生成命名空间 IMPORTED target（xeus::xeus/libzmq::libzmq），上游链接无命名空间 xeus/libzmq 需 alias 桥接；(3) header-only 包装库（cppzmq）不传播底层库（libzmq），私实现链接需显式再链接 libzmq；(4) openssl 配方无 CMake config，消费端 shim 引用 CMakeDeps target 必须先 include openssl-config.cmake 否则生成阶段 target 不存在；(5) 主配方缺 generators="CMakeDeps" 类属性时依赖 config 完全不生成；(6) Conan 2.31 版本范围不接受逗号分隔（[>=6.0,<7.0]），需空格分隔

## 推荐方案
**方法**: consumer-view-alignment

**说明**: 主配方类属性声明 generators="CMakeDeps"；版本范围用空格分隔；patch 上游 CMakeLists 将 xeus_REQUIRED_VERSION 对齐实际 major 并加命名空间→无命名空间 alias（xeus、libzmq），私实现显式链接 libzmq；无 config 依赖（openssl）生成 shim 时先 include CMakeDeps config 再暴露约定 target；签名工具用 shutil.which + 真机双路径 fallback；真机构建设 TMPDIR 并限 -c tools.build:jobs=2

**修复命令**:
```
generators = "CMakeDeps"\nself.requires("xeus/[>=6.0 <7.0]", ...)\n# patch: set(xeus_REQUIRED_VERSION 6.0.0) + alias xeus/libzmq + PRIVATE libzmq\n# shim: include("${CMAKE_CURRENT_LIST_DIR}/openssl-config.cmake") 再暴露 OpenSSL::Crypto\n# sign: shutil.which("binary-sign-tool") or "/storage/Users/currentUser/usr/local/bin/binary-sign-tool"
```

**验证**:
```
conan create archives/x/xeus-zmq/4.0.0 -pr:h ohos-aarch64 -pr:b ohos-aarch64 --build=missing -c tools.build:jobs=2；修复前 configure 逐层失败（版本范围 → find_package → major 拒绝 → OpenSSL target 未定义），修复后 configure/编译/安装/签名/package/test_package 全部通过（真机 frp-tip.com:56267，OHOS 6.0 aarch64 clang15）
```
