# E3591: KF6/Qt6 module matrix gap - choose the version set the repository can actually deliver before adapting

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, dependency-graph, kf6, qt6
- **作者**: 2301

## 错误特征
```
Version conflict: Conflict between qtbase/|NOT COMPATIBLE|KF6_MIN_VERSION|KIOWidgets|KIOFileWidgets|KX11Extras|DocBook|ZLIB::ZLIB|Taglib::Taglib|relocation R_AARCH64_.*can not be used when making a shared object
```

## 根因分析
The OHOS artifact repository splits KF6/Qt6 across two mutually exclusive qtbase ecosystems (qtbase/6.11.1 without DBus, qtbase/6.11.1.1 with it) and its per-module coverage is uneven: kio exists at 6.14.0 (full widgets) and 6.26.0 (KIOCORE_ONLY, no KIOWidgets) while kdbusaddons/kjobwidgets/kconfigwidgets have no 6.26 build at all. A consumer is first adapted, then configured, and only then discovers that one requested module is missing at the required version, that two modules demand different qtbase revisions (graph Version conflict), or that the upstream KF6_MIN_VERSION gate rejects the only module version the chosen ecosystem provides. Each of those is a hard stop after a long build.

## 推荐方案
**方法**: matrix-first-pinning-and-target-wrappers

**说明**: Before writing the recipe, enumerate the consumer's KF6/Qt6 component set and read the live repository matrix for every component; choose ONE qtbase ecosystem, then pin each module to the newest revision that both exists and belongs to that ecosystem (juk: kio/6.14.0 for widgets, the 6.18 line for the shared base, kwindowsystem/6.26.0, zlib/1.3.2 for PIC). Then close the three remaining CMake gaps locally instead of patching upstream: alias the taglib target (Taglib::Taglib -> TagLib::tag) plus an UNKNOWN IMPORTED ZLIB::ZLIB in generate(); drop the DocBook handbook chain by patch; guard the X11-only KX11Extras include with __has_include.

**修复命令**:
```
archives/j/juk/26.04.0/reports/kf6-matrix-gate-check.sh <src-dir> && conan create . --build=missing -pr:h <ohos-aarch64> -pr:b default
```

**验证**:
```
archives/j/juk/26.04.0/reports/kf6-matrix-gate-check.sh <src-dir>   # source signatures + repository matrix; exit 1 when a risk item is found\nconan graph info <recipe-dir> -pr:h <ohos-aarch64> -pr:b default 2>&1 | grep -E "Version conflict|Missing binary"   # graph-level confirmation
```
