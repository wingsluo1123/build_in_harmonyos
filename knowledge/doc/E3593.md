# E3593: autotools 就地构建会把自己分发的文档/打包脚本当作生成物重写（填入实际 --prefix），污染 .orig/.work 差分基线；finish Step 1 无条件重跑 refresh-patch 时补丁数虚高并与 conandata.yml 失配

## 基本信息
- **严重度**: 3
- **类别**: build-system, make, configure, patch, filesystem
- **作者**: Qoder

## 错误特征
```
refresh-patch 生成补丁数与 conandata.yml 不一致|No rule to make target|build_and_test.sh.*patch_file|dry-run 失败|L0c patch 文件路径或格式错误
```

## 根因分析
xine-ui 的 `configure`/`make` 在源码树内直接运行（模式 B 探索编译），会就地重写 tarball 自带的“看起来像源文件、其实是构建产物”的文件：`doc/man/{de,en,es,fr,nl,pl}/*.1`（man 页面里写入实际`$DEFAULT_PREFIX` 路径）、`misc/SlackBuild`、`misc/build_rpms.sh`。`refresh-patch --auto` 的精准模式只比对**它追踪的那批文件**（本例 22 个），无法区分“真实适配改动”与“构建副产物”，于是把这些重写也 diff 成补丁。流程放大点在于 **`finish` Step 1 无条件重跑 `refresh-patch --auto`**（`_SKIP_PATCH_GENERATION`只在 Step 2 close-archive 里生效），所以哪怕 AI 事先已经生成并核对过补丁集，finish 仍会按当前（已被构建污染）的 `.work` 重算：本例 5 个 → 13 个。结果 `conandata.yml` 里的 5 个 patch_file 名字与实际 13 个补丁失配（且 0004 号段重排），`conan-verify` G2 与 W3 `build_and_test.sh` 报 patch 路径/格式错误。同时 17 个被改写的追踪文件里只有 8 个能干净反 apply 生成补丁，另 9 个报 `dry-run 失败`，让补丁编号进一步错位。

## 推荐方案
**方法**: restore-build-artifacts-from-orig-before-finish

**说明**: finish 之前做一次“基线卫生”：用 `diff -rq .orig .work` 枚举差异，把其中**非适配**的构建副产物（man 页面、发行版打包脚本等）用 `.orig` 的原始文件逐个 `cp -p` 覆盖回 `.work`，使两端差异只剩真实改动；再删掉旧补丁目录跑 `refresh-patch --auto`，核对“补丁数 == conandata.yml 条目数 == manifest.patches_count”。判据：`.orig`/`.work` 的差异集合必须等于“你打算提交给上游的可移植性修复集合”，多出来的每一个都必须在 notes.md 里能说出理由。
