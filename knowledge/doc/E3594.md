# E3594: 同一配方本机全绿、远端 CI 在 config.status 写 subs1.awk 时 EACCES——根因是本机 conan home 在应用私有挂载（同一命令得 drwx------ 且可写）而 CI worker 在 HMDFS 挂载（同一命令得 drwx--S--- 且被拒）；附带实测：鸿蒙的 toybox mktemp -d 确实受 umask 影响（GNU coreutils 恒 0700），所以 sed 改 umask 不是空操作

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, autotools, filesystem, permissions, ci-vs-local
- **作者**: Qoder
- **来源 PR**: 16499

## 错误特征
```
config\.status: line \d+: \./conf[A-Za-z0-9]{6}/subs1\.awk: Permission denied|could not setup config files machinery|Error in build\(\) method.*autotools\.configure
```

## 根因分析
两侧 conan home 落在权限语义不同的挂载上（本机 /data/storage/el2/base/files/home/.conan2 属应用私有挂载，(umask 077 && mktemp -d) 得到 drwx------ 且可写；CI worker 用 /storage/Users/currentUser/.cache/conan2 属 HMDFS，同一命令得到 drwx--S--- 并在 config.status 写 subs1.awk 时被拒），于是同一份配方本机全绿、远端红。本条只记这个“同命令两侧结果相反”的实测差异；至于 worker 为什么拒写（属主 uid ≠ 进程 uid 使检查落 group 分支）是 DRAFT-10863 的机理假设，本机既证实不了也证伪不了，不要当事实引用

## 推荐方案
**方法**: mount-diff-diagnosis-then-fix-with-remote-green-record

**说明**: 三步归因，不要先怀疑配方：(1) 比对两侧 conan home 的挂载语义（本机私有挂载 vs CI HMDFS），并在**同一目录**里分别用 umask 077/022/007/002 跑 mktemp -d + 写文件，把 mode 字符串列成表；(2) 检查**生成物**而不是本地结论——复验构建目录里 config.status 的 umask 行，确认补丁到 configure 再到 config.status 的传导链；(3) 修复取值优先找“同族兄弟包在同一站点是否已如此修”（本包即引擎依赖 xine-lib/1.2.13 的 patches/0003-configure.patch 对同一 autoconf configure 的同一站点改成 umask 022，两处替换逐字同形），其次取知识图谱 rec 原值（E129 rec 1 = 022），再次才是仓库内出现频次（按 archives/*/*/*/patches/*.patch 复算：含 -umask 077 删除行的补丁 1382 个，+umask 022 共 2117 行、636 个不同包名，000 为 377/136，002 为 78/30，007 为 49/18）；不要拿“本机也能过”或“本机静态分析看起来更严格”当取值依据。修复动作本体归 E129/E114，本条只记归因法与挂载差异

**修复命令**:
```
for u in 077 022 007 002; do d=$( (umask $u; mktemp -d "./c${u}XXXXXX") ); ls -ld "$d"; ( cd "$d" && : > f ) && echo WRITABLE || echo DENIED; done
```

**验证**:
