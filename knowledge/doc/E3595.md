# E3595: 上游没有自动化测试（make check 全为 Nothing to be done）时，测试分母必须按“程序级入口清点”给出（bin_PROGRAMS/EXTRA_PROGRAMS/bin_SCRIPTS 全覆盖 + 逐个适用性判定），否则 PR 侧被判定少报；EXTRA_PROGRAMS 默认不构建、被平台策略 SIGSYS 的入口只能编译不能执行

## 基本信息
- **严重度**: 3
- **类别**: platform, syscall, autotools, make, testing
- **作者**: Qoder

## 错误特征
```
make check: Nothing to be done for `check'|no TESTS= no check_PROGRAMS|EXTRA_PROGRAMS not built|测试用例少报|L1e 测试空壳
```

## 根因分析
xine-ui 0.99.14 的 release tarball 不含任何自动化测试：`grep -l "TESTS=\|check_PROGRAMS" */**/Makefile.am`无命中，`make check` 在全部 20 个递归 check 目录输出 `Nothing to be done for 'check'`，执行用例数 0。此时若把“上游测试”写成“0 个”，在 PR 口径上等于放弃分母；而真正存在可验证行为的是**入口程序**，它们分散在 `bin_PROGRAMS`（xine、条件性 xine-remote、fbxine/aaxine/cacaxine/dfbxine）、`EXTRA_PROGRAMS`（session_ctrl、test）与 `bin_SCRIPTS`（xine-check、xine-bugreport）三类声明里。三个陷阱叠加：(1) `EXTRA_PROGRAMS` **不被 `make all` 构建**，必须显式 `make -C <dir> <prog>` 才存在，极易被漏数；(2) 部分入口在 OHOS 上**能被平台策略终止**——`session_ctrl` 的 `connect_to_session()` 无条件调用`setreuid()`，OHOS 以不可捕获的 SIGSYS 结束进程（rc=159，无任何输出），所以只能验证“交叉编译+链接”这一半，运行半边必须如实标注不适用；(3) `xine-bugreport` 是交互式程序（菜单 `please select (1..16):`），实测会一直阻塞（420s timeout rc=124），纳入自动化只会造成假红，必须“实测但不入自动化”。分母只有按“入口 × 调用次数 × 适用性”三层写清，才既满足全量测试要求，又不夸大结果。

## 推荐方案
**方法**: program-level-entry-census-with-applicability-and-compile-only-entries

**说明**: 分母写成三层并全文一致（MANIFEST.yml / test-report.md / PR 正文 / notes.md 同一组数字）：①上游入口总数 = 三类声明程序 + 脚本（本例 10）；②实测入口与调用次数（本例 4 个程序 / 9 次调用）；③不适用入口 + 逐个**实测证据**（构建输出、configure 探测行、链接探针），不许只写“环境不支持”。对平台策略终止的入口：配方 `build()` 里**只编译不执行**（保留交叉编译与链接验证），并在三处文档一致声明。对交互式入口：实测量出阻塞点后排除于自动化，改由 test_package 的端到端消费者用例覆盖同段行为。
