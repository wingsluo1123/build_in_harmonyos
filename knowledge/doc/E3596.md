# E3596: E566 推荐的“显式传 --build/--host 跳过 config.guess”在旧 config.sub 上并不成立——config.sub 先拒绝 ohos 内核字段，三元组路线仍以修改 config.sub 为前提

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, autotools, configure, cross-compile
- **作者**: Qoder

## 错误特征
```
Invalid configuration `.*-linux-ohos': OS `ohos' not recognized|cannot guess system type|unable to guess system type|configure: error: cannot guess build type
```

## 根因分析
OHOS 上 build == host，Conan 的 AutotoolsToolchain 不主动下发 `--build/--host` 三元组，于是 autotools 的 configure 会运行随源码分发的 `config.guess` 自行探测。E566 给出的方案是“显式传 `--build=… --host=…` 跳过探测”。但该方案只绕过了 **config.guess**，没有绕过**config.sub**：configure 拿到任何非默认别名后都会 `sh config.sub <alias>` 规范化，而 2022-01-09 版 config.sub 的 OS 表里没有 `ohos`，对 `aarch64-unknown-linux-ohos`直接返回 `Invalid configuration ...: OS 'ohos' not recognized`（实测 rc=1）。因此对携带旧 config.sub 的 tarball，三元组方案与补丁方案**同样要改 config.sub**，并不少改文件，也没有减少源码侵入；两条路线的真实分界点是 config.sub 是否认识 ohos。

## 推荐方案
**方法**: patch-config-guess-and-config-sub-when-sub-rejects-ohos

**说明**: 先用 `sh config.sub <三元组>` 实测，再决定路线：config.sub 已接受 ohos → 用 E566 的显式 `--build/--host`（零源码侵入）；config.sub 拒绝 ohos → 打 config.guess + config.sub 双补丁，此时三元组方案并不更轻。config.guess 加 `aarch64:HarmonyOS:*:*) GUESS=aarch64-unknown-linux-ohos ;;`（放在其它`case $UNAME_MACHINE:$UNAME_SYSTEM:…` 分支之前），config.sub 在 CPU 别名表加 `ohos*`、OS 表加 `linux-ohos*`。选择补丁路线时优先与同上游家族、仓库内已合入的兄弟包保持一致。
