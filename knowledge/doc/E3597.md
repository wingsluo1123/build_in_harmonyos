# E3597: Conan 为依赖包合成的 .pc 只带标准字段，上游 configure 读取的自定义 pkg-config 变量取到空串后被拼成绝对路径，make 以“No rule to make target '/x'”中断

## 基本信息
- **严重度**: 2
- **类别**: build-system, configure, conan, pkg-config, packaging
- **作者**: Qoder

## 错误特征
```
pkg-config --variable=.*returning empty|No rule to make target '/|XINE_MIME|make: \*\*\* \[.*\] Error 1.*desktops
```

## 根因分析
xine-ui 的 configure 用 `$PKG_CONFIG --variable=plugindir libxine` 求插件目录，再拼成 `XINE_MIME="<plugindir>/mime.types"` 作为 misc/desktops 里 xine.desktop 的前置条件。上游发布的 libxine.pc 由 libxine.pc.in 生成、确实带 plugindir；但本仓库里 libxine 由Conan 的 PkgConfigDeps 依据 xine-lib 配方的 cpp_info **合成**，只输出标准字段（prefix/libdir/includedirs/libs/Cflags），不携带上游自定义变量 plugindir。于是 `--variable=plugindir` 返回空串（且退出码为 0，`|| xine-config` 回落分支不触发），shell 拼接结果为绝对路径 `/mime.types`，make 把它当成必须存在的目标文件而报`No rule to make target '/mime.types'`。关键机制在于 pkg-config 对“变量不存在”与“变量值为空”不加区分：两者都输出空串且 rc=0，所以 `cmd || fallback` 形式的短路回落失效，必须显式判空。

## 推荐方案
**方法**: explicit-empty-check-with-in-tree-fallback

**说明**: 不要指望 `a || b` 短路回落：`pkg-config --variable=` 在变量缺失时返回空串且 rc=0。把取值与拼接拆成两步，显式 `test -n` 判空，空值时让上游 Makefile 里已有的“取不到就用树内默认数据”守卫生效（本例 `cat "$(XINE_MIME)" 2>/dev/null || cat "$(srcdir)/mime.default"`），而不是去伪造一个 plugindir。同时保持 .pc 由 Conan 管理，不把依赖路径硬编码进配方。
