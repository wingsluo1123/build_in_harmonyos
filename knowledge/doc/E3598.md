# E3598: 上游自研 m4 宏用 `for i in <硬编码前缀列表>` + `test -f` 探测依赖，完全不看 CPPFLAGS/LDFLAGS/PKG_CONFIG_PATH，Conan 交付的依赖目录必然探测失败；其后续 `-lncurses` 命名假设又与 OHOS 只发布 libncursesw.a 冲突，导致可选功能被静默关闭（假阴性）

## 基本信息
- **严重度**: 3
- **类别**: compat, detection, libc, autotools, configure
- **作者**: Qoder

## 错误特征
```
checking for readline.h... not found|no readline found.*disabled|AC_CHECK_LIB.*ncurses.*no|configure: disabling .* optional feature
```

## 根因分析
xine-ui 的 `m4/readline.m4`（自研宏 AC_CHECK_READLINE，非 autoconf 标准宏）分两道门：第一道是纯文件系统探测：`for i in $with_arg /usr/include: /usr/local/include:-L/usr/local/lib /usr/freeware/include:… /sw/… /cw/…/net/caladium/… /boot/home/config/…; do incl=…; if test -f $incl/readline/readline.h ; then …`—— 命中与否只取决于**这几个字面路径是否存在文件**，既不使用 `$CPPFLAGS`，也不使用 `$PKG_CONFIG_PATH`。因此 Conan 通过 `AutotoolsDeps/PkgConfigDeps` 交付的 `readline/8.3`（位于 build_folder 私有 prefix，R49 要求如此）对这段探测完全不可见。实测：generators 目录里 `readline.pc` 存在、`PKG_CONFIG_PATH` 已注入，configure 仍输出`checking for readline.h... not found` + `*** no readline found, xine network interface will be disabled ***`。第二道门是命名假设：命中 readline 后宏会用`AC_CHECK_LIB([readline],[cbreak])`，若 `LIBS` 仍为空则 `AC_CHECK_LIB([ncurses],[cbreak])`，两次都空就 `have_readline=no`。OHOS 侧 ncurses 包只发布 `libncursesw.a`/`libncurses++w.a`（无 `libncurses.a`、无 `libtinfo`），`-lncurses` 必失败。两道门叠加使“上游可选功能”在 OHOS + Conan 组合下呈**假阴性**：不是依赖不存在，是探测机制看不见它。这类失败不会报错、只会静默关掉功能（`xine-remote` 不构建），因此极易被误记为“OHOS 不支持”。

## 推荐方案
**方法**: classify-as-not-applicable-with-probe-evidence-do-not-patch-m4

**说明**: 先判定该功能是否属于本次交付面：非核心的可选前端/附加程序（本例 xine-remote REPL）→**不改上游 m4**（属上游探测缺陷、且改动会影响其在 Linux 上的行为），而是登记为“不适用入口”，并附上面两条实测证据（configure 行 + 库命名清单），让“为什么没有这个程序”在 PR 里可核。若该功能属于核心交付面，则优先级从下往上选：①在配方显式传该宏认识的入口（本例 `--with-readline=<dir>`，其 `with_arg` 会被放到遍历列表**首位**，从而让第一道门通过）；②传 `LIBS="-lncursesw"`/`ac_cv_lib_ncurses_cbreak=yes` 之类 autoconf 缓存变量越过第二道命名门（需实测）；③最后才考虑补丁 m4，且必须可向上游提交（R8/P005）。禁止为了“功能开着”而把依赖装进共享 `/usr/local`（违反 R49，且 CI worker 与本机结果分叉）。
