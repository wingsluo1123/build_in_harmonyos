# E3600: Route in-dialog SUBSCRIBE and unsubscribe requests to the existing NTA dialog

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, network
- **作者**: 8F61

## 错误特征
```
re.?SUBSCRIBE|nua_i_subscribe.*(timeout|500|100.*200)|test_subscribe_notify\(\).*100.*200|SUBSCRIBE.*(new handle|default leg)
```

## 根因分析
NTA excluded sip_method_subscribe from its existing-leg lookup, so tagged refresh and Expires: 0 requests missed the established dialog. The regression callback must answer each request. Its saved nua_i_subscribe event is a request notification with status 100; the client-side nua_r_unsubscribe event carries the final SIP 200.

## 推荐方案
**方法**: route-subscribe-refresh-by-dialog

**说明**: Allow tagged in-dialog SUBSCRIBE and Expires: 0 requests to use the existing NTA leg lookup. The regression callback explicitly answers refresh and unsubscribe requests before waiting for NOTIFY; assert NUA event status 100 separately from client SIP response 200.

**修复命令**:
```
In nta.c, remove the sip_method_subscribe exclusion from leg_find() when resolving an existing dialog; in test_simple.c answer refresh/unsubscribe using NUTAG_WITH(nua_current_request(nua)) and Expires 365/0, expect nua_i_subscribe status 100 and nua_r_unsubscribe final status 200.
```

**验证**:
```
On HarmonyOS AArch64 run finish sofia-sip 1.13.18 built. Confirm NUA-11.4.3 refresh and NUA-11.4.4 unsubscribe; expect the server nua_i_subscribe request event status 100 and client nua_r_unsubscribe final SIP status 200. Confirm all individual check_sofia items and Conan test_package consumer plus GLib/loopback SIP test pass.
```
