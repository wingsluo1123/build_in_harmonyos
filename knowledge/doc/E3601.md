# E3601: HarmonyOS NUA 快速 100 Trying 使 CANCEL 测试错过 calling 状态并超时

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, socket, network, testing
- **作者**: CA07

## 错误特征
```
TEST NUA-5\.1\.1: FAILED|test_call_cancel\(\) FAILED:.*408 != 487|CANCEL.*(timeout|408)
```

## 根因分析
NTA 将下游 100 Trying 作为逐跳响应消费且不会调用测试代理的 proxy_response()。测试代理仅等待该回调时，NUA 不会及时获知临时响应，排队的 CANCEL 到超时才发出。代理开始转发 INVITE 后应通过原始入站 server transaction 立即生成本地 100 Trying；多线程回调可能先观察到 proceeding，因此取消逻辑需同时覆盖 calling/proceeding 并最多发送一次。

## 推荐方案
**方法**: preserve-100-and-cancel-on-proceeding

**说明**: 在 HarmonyOS 测试代理成功启动 INVITE 转发后，通过原始入站 server transaction 生成本地 100 Trying；NUA 测试回调在 calling 或 proceeding 状态最多发送一次 CANCEL。

**修复命令**:
```
test proxy: after process(t) accepts INVITE forwarding, nta_incoming_treply(irq, SIP_100_TRYING, TAG_END()); callback: state in {calling, proceeding} and !cancel_attempted => nua_cancel(...)
```

**验证**:
```
在 HarmonyOS AArch64 Conan make check 环境运行 test_nua -v -1 -l9；确认 NUA-5.1.1 完成，CANCEL 响应为 200、INVITE 最终响应为 487；随后检查 check_sofia 的 8 个 Check 项均无失败或超时。
```
