# E3604: conan Release 默认注入的 -DNDEBUG 断掉 liburcu <urcu/assert.h> 的 <assert.h> 传递链 ⇒ 共享库留下 UND assert ⇒ OHOS 运行期 relocation 失败

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, build-system, autotools
- **作者**: 4DB5

## 错误特征
```
call to undeclared function .assert.|implicit-function-declaration.*assert|Error relocating .*assert.*symbol not found|undefined symbol. assert|UND assert
```

## 根因分析
liburcu 的 include/urcu/assert.h 是**条件包含**——`#ifdef NDEBUG` 时只定义 `urcu_posix_assert()`（不求值），`#else` 分支才 `#include <assert.h>`。下游包（实测 lttng-ust 2.12.10）有若干 .c **自己没写 `#include <assert.h>`**，只靠 `<urcu/uatomic.h>` → `urcu/uatomic/uassert.h` → `urcu/assert.h` 这条链把 assert.h 带进来。

## 推荐方案
**方法**: drop-ndebug-from-autotools-toolchain

**说明**: 在配方的 generate() 里显式清掉 conan 注入的 NDEBUG（`tc = AutotoolsToolchain(self)` 之后 `tc.ndebug = None`），使 `<urcu/assert.h>` 走 `#else` 分支正常 `#include <assert.h>`；实测 UND 由 `assert` 变为可解析的 `__assert_fail`，运行 rc=0。该做法同时回到上游 autotools 的默认语义——上游自身 CFLAGS 默认是 `-g -O2`，**不定义 NDEBUG**（NDEBUG 是 CMake/发行版打包惯例，不是 autotools 默认）。

**修复命令**:
```
python3 -c "print('tc = AutotoolsToolchain(self); tc.ndebug = None')"   # 落到配方 generate() 内
```

**验证**:
```
产物判据——readelf --dyn-syms <pkg>/lib/<name>.so 里 grep -w assert，正常只应见 UND __assert_fail，出现 UND assert 即命中；运行期 oracle——用该包编一个只 return 0 的消费者并执行，命中时 rc=127 且 stderr 为 Error relocating 加 assert 符号缺失。
```
