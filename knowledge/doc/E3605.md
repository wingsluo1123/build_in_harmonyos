# E3605: OHOS 上 /dev/shm（tmpfs）写满时，POSIX shm 的 mmap 首次访问以 SIGSEGV 呈现（掩盖 ENOSPC/SIGBUS），且信号被屏蔽的线程里不可捕获

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, posix, memory, ipc
- **作者**: 8CAA

## 错误特征
```
SIGSEGV|Segmentation fault|terminated by signal 11|exited with status 139|core dumped
```

## 根因分析
/dev/shm（tmpfs）**写满**时，POSIX 共享内存的 mmap 映射在**首次访问尚未分配的那一页**时无法分配页，本机以 **SIGSEGV** 呈现（rc=139），把真正的 ENOSPC/SIGBUS 完全掩盖掉。

## 推荐方案
**方法**: free-dev-shm-then-retry

**说明**: 先确认 `/dev/shm` 有空间（`df -h /dev/shm` 的 Avail 非 0），再运行依赖 POSIX shm 的程序/测试。这是**环境面**问题，不是包的问题：不要改配方、不要判配方失败；把它当成与「内存耗尽/槽位不可用」同级的可重试环境条件（本仓库口径：等同 conan_verify_round 的 rc=3「环境暂时耗尽」），记录逐字读数后等窗口重跑。

**修复命令**:
```
df -h /dev/shm && python3 -c "import shutil;d=shutil.disk_usage('/dev/shm');print('avail_bytes=',d.free)"   # 先看空间再跑重型用例
```

**验证**:
```
三步取证——① df -h /dev/shm（期望看到 Avail=0、Use%=100）；② 对新建 shm 对象 write()（期望 -1/errno=28 ENOSPC，证明是空间而非映射）；③ mmap 后首次访问（期望先打印 mmap 成功再 Segmentation fault、rc=139）。探针源码与逐字读数见 $TASK_DIR/w0/probe/{shm1.c,shm2.c,shm3.c} 与本条 source_event。
```
