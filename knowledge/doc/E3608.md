# E3608: Separate image-level checks from kernel-facing filesystem validation

## 基本信息
- **严重度**: 2
- **类别**: ohos, kernel, portability, testing
- **作者**: iKalous_OscarP
- **来源 PR**: 16522

## 错误特征
```
F2FS_IOC_.*(ENOTTY|EOPNOTSUPP)|mount.*f2fs.*(EPERM|EACCES|ENODEV)
```

## 根因分析
F2FS image tools can operate on regular files, while ioctl, mount, resize-under-mount, and power-loss paths depend on kernel support, privilege, and a disposable device; build or --version success proves only the user-space binary contract

## 推荐方案
**方法**: split-image-and-kernel-validation

**说明**: Keep regular-file formatter/checker consumers separate from privileged kernel-facing scenarios and report both result sets explicitly

**修复命令**:
```
mkfs.f2fs -f "$TMPDIR/f2fs.img" && fsck.f2fs -f "$TMPDIR/f2fs.img"; run the pinned upstream matrix on an isolated F2FS-capable device
```

**验证**:
```
mkfs.f2fs -f <scratch-image> && fsck.f2fs -f <scratch-image>; separately run the upstream mount/ioctl matrix on a compatible kernel and isolated device
```
