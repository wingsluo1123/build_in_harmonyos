# E3609: OHOS sysroot 无 libcurl 头文件时 C++ 框架网络后端裁剪模式（JUCE_USE_CURL=0 配方级传播）

## 基本信息
- **严重度**: 2
- **类别**: platform, headers, conan
- **作者**: BC6C

## 错误特征
```
curl/curl.h.*not found|undefined symbol: curl_.*|JUCE_USE_CURL
```

## 根因分析
OHOS sysroot(ohos-sdk native sysroot)不含 libcurl 头文件与库; C/C++ 框架(如 JUCE)默认启用 curl 网络后端时编译期报 curl/curl.h not found 或链接期 curl_* 符号缺失

## 推荐方案
**方法**: 在 conan 配方 cpp_info.defines 声明关闭宏(如 JUCE_USE_CURL=0)并随 CMakeDeps 目标传播到消费者; 消费者通过 target_link_libraries 链接 juce::juce 自动获得该 define, 无需逐消费者配置

**说明**: 一句话描述这个推荐方案

**修复命令**:
```
conanfile.py: self.cpp_info.defines = ['JUCE_USE_CURL=0']; test_package CMakeLists: target_link_libraries(test_juce PRIVATE juce::juce)
```

**验证**:
```
echo '#include <curl/curl.h>' | clang --target=aarch64-linux-ohos -x c -fsyntax-only - ; 消费者 test_package 编译链接运行成功且无 curl_* 未定义符号
```
