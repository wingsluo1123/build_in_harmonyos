# E3615: Preserve compile-only targets when replaying a header-library upstream test inventory

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, testing
- **作者**: 2501_91199785; team 诶，云朵

## 错误特征
```
Upstream test/build inventory mismatch|Unknown upstream condition
```

## 根因分析
A source-tag header-library archive may omit bootstrap output, while its original Automake inputs define both compile-only check_PROGRAMS and a smaller runtime TESTS set. Treating the sets as equal either drops compile-only coverage or inflates the runtime denominator.

## 推荐方案
**方法**: separate-compile-coverage-from-runtime-test-count

**说明**: Keep both original sets and their source mappings. Run only the actual TESTS entries but build the full check_PROGRAMS set; do not remove targets or count compile-only programs/inner assertions as runtime cases. Declare optional dependency/standard configurations honestly and reject unsupported inventory syntax rather than guessing.

**修复命令**:
```
Require unique TESTS IDs and TESTS subset-of check_PROGRAMS; retain a runtime_registered flag per compiled target.
```

**验证**:
```
Evaluate original known feature conditions from the selected compiler standard/package configuration; fail on unknown conditions, require TESTS to be a unique subset of check_PROGRAMS, compile every enabled program, run each registered runtime entry and bind source/binary/log hashes.
```
