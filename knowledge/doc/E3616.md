# E3616: 多头文件上游 include/ 树做 header-library 打包前必须逐头审计"用户态可用性"：include 闭包分类 + sysroot 头存在性验证 + test_package 静态断言锁契约

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, packaging
- **作者**: unknown

## 错误特征
```
fatal error: linux/blkdev.h: No such file or directory|fatal error: linux/autoconf.h: No such file|fatal error: scsi/scsi_cmnd.h: No such file
```

## 根因分析
内核框架类上游的 include/ 目录混装两类头：用户态可用（闭包只含 uapi 头）与内核树专用（含 linux/blkdev.h、linux/autoconf.h、scsi/scsi_cmnd.h 等，这些头只存在于内核构建树生成的 include 集合，musl sysroot 没有）。整目录打包会把用户态必然编译失败的头伪装成可用产物；只挑一个头又不利于其他消费者。判定必须基于每头的 #include 闭包，而非文件名猜测；sysroot 头存在性要用 ls 实证，跨发行版/SDK 有差异。

## 推荐方案
**方法**: per-header-include-closure-classification-plus-sysroot-check

**说明**: (1) 对每个头跑 grep '#include <' 列出闭包；凡引用 musl sysroot 缺失的内核树头即判"内核树专用"，在 notes.md 逐头列排除理由；(2) 用户态可用候选头先在 OHOS clang 下单独编译冒烟（echo '#include "x.h"' | clang -fsyntax-only -）再进包；(3) 双分支头（#ifdef INSIDE_KERNEL_TREE）核对用户态分支的实际依赖；(4) test_package 对版本编码宏做 _Static_assert、对字符串常量做 strcmp 断言，锁住 ABI/契约防上游静默漂移；(5) 打包布局对齐消费方的引用方式（上游 make install 装到 $prefix/include/scst/，conan 包平铺 include/，下游用 -I<conan include> 等价对齐）。

**修复命令**:
```
for h in include/*.h; do echo "#include \"$h\"" | clang -fsyntax-only - && echo "USERSPACE-OK: $h"; done
```

**验证**:
```
grep -n "#include <" include/*.h; ls $SYSROOT/usr/include/linux/version.h $SYSROOT/usr/include/scsi/scsi.h
```
