# E3617: Linux 内核框架包（SCST/jool 类）在 OHOS 的分层交付模式：用户态可消费子集做成 conan 包 + 内核态边界如实申报，禁止把内核模块伪装成可交付物

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, kernel, architecture, boundary
- **作者**: unknown

## 错误特征
```
/lib/modules/.*build.*No such file|Module.symvers|kbuild|CONFIG_MODULE|insmod.*not found
```

## 根因分析
SCST 这类 Linux 内核框架的核心产物是内核模块（scst.ko 等），其构建入口是 kbuild（依赖 /lib/modules/$(uname -r)/build 的 Module.symvers、autoconf.h 与内联头如 linux/blkdev.h、scsi/scsi_cmnd.h）。HarmonyOS PC 不公开 Linux 内核构建树，内核模块在 OHOS 上永远不可构建；但这类项目往往附带"用户态可消费子集"（协议常量头、user-kernel ABI 头、管理工具），这些子集可在 OHOS 用户态独立交付。若把整包一刀切判为"无法适配"，会丢掉下游真正需要的用户态接口（如 iscsi-scst usr/event.c 只消费 scst_const.h）；若假装交付内核模块，则是虚标。

## 推荐方案
**方法**: layered-delivery-header-subset-plus-honest-kernel-boundary

**说明**: (1) 审计 include/（或等价接口目录）逐头分类：用户态可用（仅依赖 uapi 头）vs 内核树专用（依赖 blkdev.h/autoconf.h 等）；(2) 用户态可用子集做成 header-library conan 包，test_package 用 _Static_assert 锁版本编码/ABI 序等契约；(3) 内核模块保持上游源码形态（conandata.yml 官方 URL 可复原），在 notes.md/PR 正文用专表逐头申报内核态边界，绝不放进包产物；(4) 下游包（如 iscsi-scst usr）通过 SCST_INC_DIR/依赖 include 路径消费头文件，形成 R36 拓扑序：先发 scst 再发 iscsi-scst。

**修复命令**:
```
grep -n "#include <" include/*.h   # 逐头分类用户态可用性
```

**验证**:
```
find src -iname '*test*' | wc -l; grep -rn "obj-m\|/lib/modules" Makefile | head; find sysroot/usr/include/linux -name version.h
```
