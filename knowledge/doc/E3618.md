# E3618: ocaml conan 包只有 stdlib 的 Stream（stdlib__Stream.cmi），没有 camlp-streams findlib 包（无 lib/ocaml/camlp-streams/META）——依赖 camlp-streams 的 OCaml 包必须先适配该依赖，不能指望 ocaml 包自带

## 基本信息
- **严重度**: 2
- **类别**: conan, dependency, dune, ocaml
- **作者**: unknown
- **来源 PR**: (请填写：随 camlp-streams 依赖项 PR 提交时回填)

## 错误特征
```
Library camlp-streams not found|Error: Program camlp5o not found|camlp-streams|findlib package.*not found|dune.*libraries.*not found
```

## 根因分析
camlp-streams 是独立 opam 包（github.com/ocaml/camlp-streams，承载从 stdlib 拆出的 Stream/Genlex），不随 OCaml 编译器 tarball 的 make install 安装。制品仓 ocaml/4.14.1.1.4 包实测（conan cache path 检查）：lib/ocaml/ 下有 stdlib__Stream.cmi（stdlib 遗留 Stream 模块）与 libcamlstr.a（str 库），但没有 lib/ocaml/camlp-streams/ 目录、没有 camlp_streams.cma、没有 META——dune 的 findlib 解析因此找不到 (libraries camlp-streams)。典型触发者：lablgtk3（tools/dune 的 varcc/propcc 代码生成器声明 (libraries camlp-streams)，而 src/dune-enum.sexp、dune-prop.sexp 内嵌 varcc/propcc 调用规则，属于 -p lablgtk3 的构建硬路径）。

## 推荐方案
**方法**: adapt-camlp-streams-as-standalone-conan-package

**说明**: 需要独立适配 camlp-streams（github.com/ocaml/camlp-streams，版本 >= 5.0，纯 OCaml 库无 C 代码）：参照 archives/o/ocaml-syntax-shims/1.0.0 配方范式（requires ocaml + dune，dune build -p camlp-streams，package() 从 _build/install/default/lib 手工拷贝到 <pkg>/lib，HMDFS 上 dune install 会失败故必须手工 copy）。发布后，下游包（lablgtk3 等）通过 OCAMLLIB 指向 conan 注入的 ocaml 包路径 + 把 camlp-streams 包的 lib 路径并入 dune 查找路径（dune 会在 OCAMLLIB 及 workspace 内解析 findlib 包；下游配方需将 camlp-streams 包内容放到 OCAMLLIB 同级或用 DUNE_CONFIGURE 变量注入）后 dune 才能解析。注意与 stdlib Stream 的区别：stdlib__Stream 是废弃遗留模块，与 camlp-streams 的 Stream 是两个不同的 findlib 提供者，dune 只认后者。

**修复命令**:
```
conan download "camlp-streams/5.0.1" -r=ohpcd --only-recipe ; ls $(conan cache path "ocaml/4.14.1.1.4:<pkg_id>")/p/lib/ocaml/camlp-streams 2>&1
```

**验证**:
```
P=$(conan cache path "ocaml/4.14.1.1.4:<pkg_id>") ; ls $P/lib/ocaml/ | grep -i camlp ; ls $P/lib/ocaml/camlp-streams/ 2>&1
```
