# E3619: 判定 cnb.cool 制品仓包是否存在：conan list 必须用通配符（精确 ref 缺失时 exit 0 易假阳性）；conan download 缺失包报 "system acceleration policy not enabled" 而非标准 404

## 基本信息
- **严重度**: 2
- **类别**: toolchain, conan, dependency, preflight
- **作者**: unknown
- **来源 PR**: (请填写：随 lablgtk3 依赖项/重领 PR 提交时回填)

## 错误特征
```
error:system acceleration policy not enabled|Recipe '.*' not found|There are no matching recipe references|Found 0 pkg/version recipes
```

## 根因分析
cnb.cool 承载的 ohpcd remote 对"包不存在"场景的响应不符合 conan 官方 remote 的标准 404 语义，conan CLI 把它转成两个误导形态：①`conan list <精确ref>` 对缺失包仍返回退出码 0，只在 stdout 打一行 "ERROR: Recipe 'x/y' not found"——用 `| grep -q <版本>` 或判断 $? 都会假阳性；②`conan download <ref>` 对缺失包报 "ERROR: error:system acceleration policy not enabled. [Remote: ohpcd]"（CDN 加速策略层错误文案），与网络抖动、SSL 错误难以肉眼区分，且该文案不含 404/not found 字样。实证矩阵（2026-09-23 本机）：存在包（ocaml/4.14.1.1.4、dune/3.17.0、gtk/3.24.43）download 正常返回 revisions；缺失包（gtk+/3.24.38、cairo2/0.6.5、camlp-streams/5.0.1、zzz-nonexistent-xyz/9.9）download 全部报 acceleration policy 错误、通配符 list 全部 "Found 0"。

## 推荐方案
**方法**: wildcard-list-plus-download-double-check

**说明**: 判定存在性的可靠组合拳：①先 `conan list "<名称>*" -r=ohpcd` 用通配符列出全部同名变体（缺失时明确输出 "Found 0 pkg/version recipes matching"），通配符路径不受精确 ref 的 exit 0 陷阱影响；②对候选版本再 `conan download <name>/<ver> -r=ohpcd --only-recipe` 做最终实证，若报 "system acceleration policy not enabled" 且同一会话内对已知存在包（如 zlib、dune/3.17.0）download 正常，则该错误等价于包不存在（非网络故障，不要按 R41 网络退避无限重试，重试 2 次即可改判 missing）。脚本化判定建议解析通配符 list 的 "Found N" 行而非退出码；grep 校验必须锚定 "not found"/"Found 0" 反向匹配。conan list 精确 ref 的 stdout 形态为 "ohpcd\n  ERROR: Recipe '<ref>' not found"，可做正向解析但绝不能当成功处理。

**修复命令**:
```
conan list "<name>*" -r=ohpcd 2>&1 | grep -E "^Found [0-9]+ pkg" ; conan download "<name>/<ver>" -r=ohpcd --only-recipe 2>&1 | tail -1
```

**验证**:
```
conan list "cairo*" -r=ohpcd | grep -c "cairo2/" ; conan download "cairo2/0.6.5" -r=ohpcd --only-recipe 2>&1 | tail -1
```
