# E3620: conan-init 按包名生成 cpp_info.libs 与库名不一致时的配方修正

## 基本信息
- **严重度**: 2
- **类别**: packaging, recipe
- **作者**: 28FE

## 错误特征
```
cpp_info.libs = ["<包名>"]|No rule to make target.*<包名>|cannot find -l<包名>
```

## 根因分析
conan-init 模板按包名({name})推断 cpp_info.libs 与默认 CMake target 名；当仓库/包名与上游 CMake 项目目标名不一致（如 newuoa-cpp 包的产物是 libnewuoa.a / newuoa::newuoa）时生成错误库名，导致下游链接失败

## 推荐方案
**方法**: 按实际 CMake 产物修正 package_info：cpp_info.libs=[实际库名]，cmake_target_name=实际 target，cmake_file_name 保持包名（find_package 名称）

**说明**: 以 newuoa-cpp 0.1.2 实证：conan-init 生成 cpp_info.libs=["newuoa-cpp"] 但实际产物是 libnewuoa.a、CMake 目标 newuoa::newuoa；修正为 libs=["newuoa"] + set_property("cmake_file_name","newuoa-cpp") + set_property("cmake_target_name","newuoa::newuoa")

**修复命令**:
```
self.cpp_info.libs = ["<实际库名>"]; self.cpp_info.set_property("cmake_file_name", "<包名>"); self.cpp_info.set_property("cmake_target_name", "<包名>::<实际target>")
```

**验证**:
```
conan create 后检查 lib 文件名与 CMakeDeps 生成 target；消费者 test_package 链接实际 target 并运行
```
