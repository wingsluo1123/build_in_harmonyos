# E3623: HarmonyOS 6.1 IME inputStop callback omitted during TextInput handoff

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, testing, lifecycle
- **作者**: D7A3

## 错误特征
```
panel_destroyed.*inputStop|inputStop.*panel_destroyed|Old session cleanup incomplete
```

## 根因分析
On the tested HarmonyOS 6.1 device, moving focus to another real TextInput destroyed the old IME panel without emitting inputStop; stopEditing or stopInputSession return values alone did not prove session closure. The device emitted repeated same-run focus lifecycle markers, but a runner that de-duplicates identical JSON records can discard the second valid interaction unless markers carry an increasing sequence or interaction identifier.

## 推荐方案
**方法**: verify-client-handoff-and-old-panel-destruction

**说明**: Use a second real TextInput to trigger client handoff; require successful focus evidence, old-token panel_destroyed, and a distinct replacement input_start with panel create/show and rendered reset UI. HarmonyOS 6.1 may report replacement input_start before old-panel destruction, so require old destroy before replacement panel create/show rather than before input_start. For terminal cleanup, arm the trace before input and request focus to the second TextInput programmatically. Give repeated markers a monotonic sequence or interaction identifier. If inputStop is emitted, additionally require it precede panel destruction.

**修复命令**:
```
python run_harmonyos_device_test.py
```

**验证**:
```
Run the signed device harness; correlate old session token, TextInput focus callback and panel_destroyed before requiring a distinct new input_start/create/show token and reset Shift UI.
```
