# E3627: 有界线程池的全员集合测试必须绑定实际容量，而不是 CPU 数推算

## 基本信息
- **严重度**: 2
- **类别**: portability, threading, cmake, testing
- **作者**: LD64

## 错误特征
```
dispatch_readsync.*Timeout|all.workers.*rendezvous|workers < n
```

## 根因分析
测试用在线 CPU 数乘经验系数推算并发线程数，并让已经启动的任务等全部任务就绪；当请求任务数超过库内真实线程池容量时，已有线程占满线程池且不返回，排队任务永远无法运行，因此形成夹具死锁而非被测读写锁语义失败。

## 推荐方案
**方法**: bind-rendezvous-to-real-executor-capacity

**说明**: 追踪实际执行器后端和容量定义，拒绝无证据的 CPU 数推算；对常规互斥测试按实际可同时运行容量扣除必要管理线程后配置 N，保留总迭代数、所有独立测试项和随 N 定义的完整并发及互斥断言，并回读真实清单和结果。

**修复命令**:
```
对内部工作队列从实际源码容量定义生成测试编译常量；令 n=min(原先工作量估算, 实际容量-必要保留线程)，保留 LAPS 和读写互斥断言。
```

**验证**:
```
ctest --show-only=json-v1 && ctest --output-on-failure --no-tests=error --parallel 1 --output-junit upstream-junit.xml
```
