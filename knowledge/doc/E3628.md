# E3628: 精简 settings.yml 缺少 Windows 时，Conan 2 会让 `if self.settings.os == "Windows"` 直接抛 "Invalid setting 'Windows'"

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, ci-harness, settings
- **作者**: gcw_hL6s3dcK
- **来源 PR**: 16741

## 错误特征
```
Invalid setting 'Windows' is not a valid 'settings.os' value|Error in config_options\(\) method|Possible values are \['OHOS', 'Linux'\]
```

## 根因分析
Conan 2 在比较 settings 时校验右值：`self.settings.os == "Windows"` 要求 settings.yml 里定义了 Windows 这个取值。影子 CI 的启动脚本为了让 profile 只能选 OHOS，手写了一版极简 settings.yml，os 只有 OHOS 与 Linux；于是任何带 `os == "Windows"` 判断的公开配方（automake/1.18 就是）在 config_options() 阶段直接抛 ConanException，即便当前 profile 是 os=OHOS。触发链可以与被适配库完全无关：test_package 依赖 puredata/0.56.5 → 它的 build_requirements 引入 automake/1.18。

## 推荐方案
**方法**: keep-full-os-list-in-isolated-settings

**说明**: 影子 CI 的隔离 settings.yml 保留 Conan 官方的完整 os 列表（只用 profile 约束目标平台为 OHOS），不要为了「最小化/防误选」删掉 Windows、Macos、FreeBSD 等取值。

**修复命令**:
```
os:\n    OHOS:\n        version: ["6.0"]\n    Linux:\n    Windows:\n        subsystem: [null, wsl]\n    Macos:\n    FreeBSD:\n    Android:\n    ...（其余保持官方默认）
```

**验证**:
```
原版 runner 跑 archives/p/pd-jmmmp/0.61：conan create 走到 test_package 依赖图即失败，日志为 `automake/1.18: Error in config_options() method, line 21` + `if self.settings.os == "Windows":` + `Invalid setting 'Windows' is not a valid 'settings.os' value. Possible values are ['OHOS', 'Linux']`；把 os 列表补全为完整取值后重跑同一包，得到 `Total: 1 / Success: 1`、L0/L1/L4/L5 pass。
```
