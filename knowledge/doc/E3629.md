# E3629: Pd 补丁以「未转义分号」结束一条 record，折行与消息框内嵌子 patch 会让行式解析器误报；测试补丁文本必须转义 ; 与 ,

## 基本信息
- **严重度**: 2
- **类别**: python, testing, data-package, parser, puredata
- **作者**: gcw_hL6s3dcK
- **来源 PR**: 16741

## 错误特征
```
malformed connect line|unbalanced subpatches|[0-9]+ '#N canvas' vs [0-9]+ '#X restore'|no such object|canvas: no method for
```

## 根因分析
Pd 写盘时会把超长 record 折行成多条物理行，节点终止符是「未被转义的分号」；消息框（#X msg）里可以内嵌整段子 patch，内部的分号与逗号写作 \; 与 \,。按物理行解析的验证器会把续行当成新 record，于是把消息文本里的 #X connect 当成真实连接，报出大量「malformed connect」与「#N canvas 与 #X restore 不配对」。同一机制作用在测试补丁上：说明文本（#X text）里的 ; 或 , 若未转义，record 会被提前截断，后半句被当成对象执行，Pd 打印 `xxx: no such object` / `canvas: no method for 'xx'`，看起来像库坏了，其实是测试补丁自己写错。

## 推荐方案
**方法**: record-oriented-parse-and-escape-box-text

**说明**: 验证器按「未被转义的分号」把物理行重组成逻辑 record 再解析（数分号前的反斜杠奇偶性）；生成测试补丁时统一转义说明文本与消息内容里的 ; , 和反斜杠。

**修复命令**:
```
def _ends_record(line): s=line.rstrip(); return s.endswith(';') and len(s[:-1])-len(s[:-1].rstrip('\\')) % 2 == 0  # 记录结束判定；escape_box(text) = text.replace('\\','\\\\').replace(';','\\;').replace(',','\\,')
```

**验证**:
```
对同一批 141 个 .pd：行式解析在 multiarray.pd 上报约 280 条 "malformed connect line" 与 "101 '#N canvas' vs 98 '#X restore'"；改为按未转义分号重组 record 后 0 错误。测试补丁侧：未转义时正跑日志出现 "verify_jmmmp.py: no such object"；转义后正跑日志 0 条 couldn't create / no such object，9 组断言值与预期完全一致。
```
