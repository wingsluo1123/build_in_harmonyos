# E3633: 上游 harness 用 `patch FILE DIFF`（GNU 形式）时，toybox 与 GNU patch 的目标名/调用形式都不通用：改成"改写头部 + patch -p0 -i"即可两边通吃，测试失败 ≠ 输出错误

## 基本信息
- **严重度**: 1
- **类别**: limitation, toolchain, testing, patch
- **作者**: agent-B48D

## 错误特征
```
exit status 1.*edid-decode-check|patch: Unknown option|diff -u .*ref|Ok:\s+0\s+Fail:\s+[0-9]+|SIGTRAP|ref.*Unused space
```

## 根因分析
本平台的 /usr/bin/patch 是 toybox 实现，只接受 -i/-p/-R/-l/-s/-u/--dry-run 等选项，没有 GNU patch 的"目标文件"位置参数语义。给它 `patch <目标文件> <diff>` 时它把第一个参数当作别的东西（读 patch），找不到 hunk 便直接返回 0——不报错、不修改文件。于是 harness 里"先把参考输出套上 .diff 再比对"的步骤被跳过，比对差集恰好是 .diff 的内容。这类失败极易被读成"包的输出不对"，把环境缺陷算到适配质量头上（或反过来把真实缺陷掩盖成"环境问题"）。

## 推荐方案
**方法**: make-harness-patch-invocation-portable

**说明**: ①先判性质：差集恰等于 .diff 内容 = 夹具未套用（工具问题），用 patch_ng 独立复算交叉验证（本例 33/33 一致）；②再修工具而不放宽断言：把 harness 的 `patch <目标> <diff>` 改为 sed 改写头部（--- / +++ 都写成目标文件）+ `patch -p0 -i`——这是 GNU 与 toybox 的公共子集，实测 meson 36/68 → 68/68；③测试资产被改动必须按 R51/PR 模板逐条申报（文件/原因/内容），并说明断言、夹具与阈值未变。

**修复命令**:
```
sed -e '1s|^--- .*|--- ref|' -e '2s|^+++ .*|+++ ref|' "$diff" > "$w/ref.diff" && (cd "$w" && patch -p0 -i ref.diff)   # 交叉复核: python3 -c "import patch_ng,sys; patch_ng.fromfile(sys.argv[1]).apply(root=sys.argv[2])" <diff> <workdir>
```

**验证**:
```
最小判定：printf 'a\nb\nc\n' > t.txt && printf -- '--- t.txt\n+++ t.txt\n@@ -1,3 +1,3 @@\n a\n-b\n+B\n c\n' > t.diff && /usr/bin/patch t.txt t.diff; echo "rc=$?"; cat t.txt   # 期望：rc=0 但 t.txt 未变 → toybox 不生效
```
