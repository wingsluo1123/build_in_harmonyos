# E3634: 本平台 C 库内存流不可用（fclose 返回 EBADF 且丢内容，进程退出时 SIGTRAP）：不要用 open_memstream/fmemopen 收集字符串，改为进程内自增长缓冲

## 基本信息
- **严重度**: 2
- **类别**: limitation, portability, libc, musl, memory
- **作者**: agent-B48D

## 错误特征
```
open_memstream|fmemopen|Trace/breakpoint trap|SIGTRAP|exit status 133|Illegal instruction|exit status 132|Invalid extension checksum|\(\)|== NULL|fclose.*-9|EBADF
```

## 根因分析
open_memstream() 返回的 FILE* 看起来可用（写入正常、fflush 后缓冲区可见），但 fclose() 走的是该 libc 的内存流关闭路径，实测返回 -9（EBADF）、把 *sizeloc 归零并丢掉缓冲区；同一个进程里普通文件流的 fclose() 正常。流对象没有被正确注销，进程退出时 libc 的清理路径踩到残留状态，于是返回用户代码后立刻 SIGTRAP（有时 SIGILL）并 core dump。后果有两层：(a) 依赖 fclose() 取回字符串的代码拿到 NULL/空串（libdisplay-info 的 di_info_get_make/model/serial、CLI 的 join_str）；(b) 即使不取回内容，只要建立过内存流，进程退出就可能崩溃——表现为"库调用成功但进程退出码 133"，极易被误判为"沙箱 exit 清理问题"而放过。

## 推荐方案
**方法**: avoid-libc-memory-stream-use-growable-buffer

**说明**: 把"用 FILE* 收集字符串"改成进程内自增长缓冲：struct { char *str; size_t len, cap; } + puts/printf/vprintf（vprintf 用 vsnprintf(NULL,0,...) 量长度再写），close 只返回缓冲并重置结构。上游若把 FILE* 当接口（如把失败信息汇传进解析器），把该参数类型一起换掉（比伪造一个 FILE* 更省事）。

**修复命令**:
```
见 rec_description；实现参考 archives/l/libdisplay-info/0.4.0/patches/0001-memory-stream-portable.patch
```

**验证**:
```
最小复现（12 行）：printf '#define _POSIX_C_SOURCE 200809L\n#include <stdio.h>\n#include <errno.h>\nint main(void){char*b=0;size_t l=0;FILE*f=open_memstream(&b,&l);fputs("abc",f);errno=0;int r=fclose(f);fprintf(stderr,"rc=%d errno=%d len=%zu buf=%s\\n",r,errno,l,b?b:"(null)");return 0;}' > t.c && cc t.c -o t && ./t; echo "exit=$?"   # 期望 rc=-9 errno=9 len=0，进程退出码 133/132
```
