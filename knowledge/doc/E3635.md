# E3635: 制品仓已有纯数据包（hwdata）时，meson 的 dependency(..., native: true) 需要配方在 generate() 里现写 .pc：conan 合成物无 pkgdatadir，包内 .pc 的绝对路径不可迁移

## 基本信息
- **严重度**: 2
- **类别**: meson, conan, dependency, pkg-config, packaging
- **作者**: agent-B48D

## 错误特征
```
dependency\('?hwdata'?\).*found: NO|File /usr/share/hwdata/pnp\.ids does not exist|Pkg-config variable pkgdatadir|not defined|get_variable\(pkgconfig
```

## 根因分析
conan 的 pkg-config 生成物是从 cpp_info 合成的（prefix/bindir/libdir/includedir 一类），不会带 pkgdatadir 这种"包自定义变量"；而数据包自己在 package() 里写的那份 .pc 把打包时的 package_folder 绝对路径固化进去，换机器/换缓存目录即失效（conan 不做 .pc 重定位）。同时 meson 侧有两个隐藏前提：(a) pkg_config_path 是 meson 的 built-in option，写在 native/cross 文件的 [built-in options] 段，写进 [properties] 会被静默忽略；(b) 上游把这类数据依赖写成 native: true（构建机依赖），交叉构建时 meson 读的是 build.pkg_config_path，而 MesonToolchain 默认把它置 None。三者叠加 = 上游 found 分支拿不到 pkgdatadir、回退分支又指向 /usr/share/...（平台上不存在），configure 直接中断。

## 推荐方案
**方法**: require-data-package-and-write-pc-in-generate

**说明**: ①requirements() 里 self.requires("hwdata/0.411")（不是 tool_requires：上游是 native:true 的构建期查找，而 CI host==build profile，同一份 generators 目录即可满足；用 requires 还能被 PF4/L0i 依赖闸门覆盖）；②generate() 里按 self.dependencies["hwdata"].package_folder 现写 <generators>/hwdata.pc，pkgdatadir 指向包的 share/hwdata，并断言 pnp.ids 存在（缺数据文件直接抛异常，别让 custom_target 静默生成空表）；③MesonToolchain.build_pkg_config_path = generators_folder，让交叉构建下的 native 查找也能命中；④不要依赖 PkgConfigDeps 的合成 .pc，也不要复制数据文件进配方。

**修复命令**:
```
见 conanfile.py 的 generate()/_write_hwdata_pc()：archives/l/libdisplay-info/0.4.0/conanfile.py
```

**验证**:
```
conan install . （需 PkgConfigDeps+MesonToolchain）后：grep -n "pkgdatadir" hwdata.pc || echo "no pkgdatadir（合成物）" ; grep -n "pkgdatadir" $(conan cache path hwdata/0.411:*/p/share/pkgconfig/hwdata.pc)   # 包内 .pc 的绝对路径是否为当前机器路径
```
