# E3639: 运行期设备节点 EACCES 时：先三档判档，编译可过就收窄到信息面 + 设备无关 API 测试，如实披露「功能面未能实测」

## 基本信息
- **严重度**: 2
- **类别**: conan, testing, permissions, capability-wall, device-node
- **作者**: unknown

## 错误特征
```
open\(.*/dev/(input/event\d+|uinput|i2c-\d+)\).*errno=13|Permission denied.*(input|uinput)|EACCES.*/dev/input
```

## 根因分析
测试进程（非 root、CapEff 无 CAP_SYS_ADMIN(21)/CAP_SYS_RAWIO(17)、Seccomp=2）打开硬件设备节点被 DAC/LSM 拒绝，返回 EACCES(13)；节点本身存在（ls /dev 可见），只是当前进程无相应权限。这是「运行期权限面」问题，与「编译/归档期」无关，也与「内核特性缺失」（如 AF_CAN 协议族不存在）性质不同。

## 推荐方案
**方法**: narrow-test-to-info-face-and-device-independent-api

**说明**: ① 三档判档：编译/归档期过不去、交不出二进制 = 直接墙（停下上报，放弃是用户终局裁定）；编译过、二进制交得出而只有运行期设备节点被限 = 本档，继续；唯一功能面被拦且上游无替代又不满足本档 = 真乙，停下上报，不得自行定性「等价交付」。② 继续时把测试面收窄到「信息面」（--help/--version/非法选项触发的 usage 横幅，getopt_long default 分支在任何 open() 之前就返回）与「设备无关 API」（只分配结构体、不 open 节点的入口，如 evemu_new()/evemu_get_name()/evemu_delete()）。③ 断言必须是真实输出匹配 + 显式退出码断言，⛔ 不得写「可录制/可回放事件」类断言，⛔ 不得用 || true 吞错。④ notes 与 PR 正文如实披露，措辞只用「本平台测试进程无相应权限，功能面未能实测」，⛔ 不得写「在某平台上不可用」。

**修复命令**:
```
p = subprocess.run([exe, "--bogus-option"], stdout=subprocess.PIPE, stderr=subprocess.STDOUT); assert p.returncode == 1; grep -q "Usage:" out
```

**验证**:
```
正对照 open("/dev/null") 与 open("/proc/self/status") 应 OK、listdir("/dev") 应有结果；反对照 open("/dev/input/event0") 与 open("/dev/uinput") 应报 errno=13 EACCES；再取 grep -E 'CapEff|Seccomp' /proc/self/status 与 os.getuid() 判定是否缺能力。正反对照必须同时给，否则无法区分「节点不存在」与「有节点但无权限」。
```
