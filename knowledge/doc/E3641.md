# E3641: Early-exit help can conceal a getopt sentinel busy loop across multiple CLI subcommands

## 基本信息
- **严重度**: 2
- **类别**: testing, abi, c-language
- **作者**: BAS1

## 错误特征
```
result of comparison of constant -1 with expression of type .char. is always true|getopt_long.*timed out
```

## 根因分析
getopt_long returns an int with -1 as its end sentinel; narrowing into unsigned plain char on AArch64 converts that sentinel to 255 before comparison, trapping functional commands in their option parsing loop.

## 推荐方案
**方法**: parser-family-int-sentinel-and-data-liveness

**说明**: When help works but ordinary commands time out before output, correlate tautological -1 comparison warnings with parser code before blaming an algorithm. Replace char receivers with int across the matching parser family, retain strict timeouts, and verify actual data products and inverse transformations rather than accepting help/version as functional coverage.

**修复命令**:
```
for (int c; (c = getopt_long(argc, argv, shortopts, longopts, NULL)) != -1;)
```

**验证**:
```
Inventory all parser variables and prove each retains int; run bounded valid-data commands that exhaust options, require artifacts and exact content/multiplicity roundtrips, then run the installed binary through the same data path and test invalid-command rejection. Bind upstream coverage to the exact source inventory and real entry/oracle, not test-substring path counts; production Tester classes and stream-header name coincidences are not test cases, while missing framework registration alone is not proof that no tests exist.
```
