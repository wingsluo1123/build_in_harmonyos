# E3643: 阻塞事件循环的跨线程状态发布必须配对等待集主动唤醒

## 基本信息
- **严重度**: 2
- **类别**: threading, event-loop, latency, power
- **作者**: atomcode
- **来源 PR**: 16641

## 错误特征
```
cross-thread event remains pending while select blocks|fixed periodic scheduler tick during idle
```

## 根因分析
atomic flag 只能让 pending 状态对其他线程可见，不能中断已经阻塞的 select/poll/epoll；依赖固定周期 tick 会在空闲时持续返回，仅删除 tick 又会让外部线程事件无限等待。组合 bitmask 和满通知通道还要求事件循环在每次分派后扫描并重臂剩余 pending，否则通知被排空后其余位会永久休眠。

## 推荐方案
**方法**: publish-then-notify-waitset

**说明**: 先写事件数据，再对每个事件位执行原子 false→true 发布；只对新 pending 位通知非阻塞且 CLOEXEC 的 pipe/socketpair/eventfd，并把读端注册进事件循环等待集。等待线程排空通知，按原轮转策略处理一个 pending 事件，并在仍有可枚举 pending 时重新置为可读。EINTR 重试；EAGAIN 只有在 level readiness 与重臂不变量成立时才能接受；初始化或注册失败必须保留有界轮询回退。

**修复命令**:
```
triggerEvent(bits): publish clientData; notify newly-pending bits; event loop drains readiness, dispatches one pending bit, and rearms while pending state remains
```

**验证**:
```
用同一消费者分别链接原始、仅取消周期 tick、主动唤醒三个制品；在受控空闲、同步跨线程触发、组合全部事件位和并发不同事件位场景下，以单调时钟、watchdog、处理计数执行同一正确行为预言机。
```
