# E3645: Preserve loader tokens across Conan CMake cache arguments and link-time RPATH

## 基本信息
- **严重度**: 2
- **类别**: cmake, linking, conan, runtime
- **作者**: BAS1

## 错误特征
```
Error loading shared library|Library rpath.*\[/../lib\]
```

## 根因分析
A literal loader ORIGIN token placed in a double-quoted CMake cache argument is expanded by the shell before CMake reads it; a valid SONAME cannot repair the resulting wrong runtime search path.

## 推荐方案
**方法**: loader-token-toolchain-not-shell-cache

**说明**: Keep loader tokens in tc.variables so they are written literally inside conan_toolchain.cmake rather than a shell-expanded -D argument. Restore missing ELF platform link rules if independently absent. For signed OHOS ELF use the same final relative RPATH at build/install time, then verify the actual dynamic section and real installed consumers; do not patch signed output or infer unsupported loader behavior from a token already missing before load.

**修复命令**:
```
tc.variables["CMAKE_INSTALL_RPATH"] = "$ORIGIN;$ORIGIN/../lib"; tc.variables["CMAKE_BUILD_WITH_INSTALL_RPATH"] = True
```

**验证**:
```
Compare generated CMake configure argv, toolchain file, CMakeCache.txt and llvm-readelf -d on the actual ELF; require literal $ORIGIN in DT_RPATH/RUNPATH, basename SONAME, all upstream tests and installed consumers. A correct SONAME alone is insufficient. Run the installed CLI through a real data transformation, serialization and inverse transformation in a private UTF-8 path with spaces; verify exact semantic output, bind the installed binary, and count one workflow separately from its internal assertions and API checks.
```
