# E3647: 已发布 Conan 包的"依赖闭包变体"缺失时，不能在同一版本号下改 recipe 补发（cnb.cool 不支持同版本多 revision，R37 拦截）；必须递增版本后缀（6.4.0.1→6.4.0.1.1）建新目录新配方，并把分支名改为精确匹配 包名-新版本（R40），再更新所有下游 requires 引用

## 基本信息
- **严重度**: 2
- **类别**: conan, artifact-registry, dependency-closure, package-id, versioning
- **作者**: unknown

## 错误特征
```
already published with different recipe|version_not_incremented|cnb\.cool.*409|branch name mismatch \(R40\)|branch_name_r40|分支名带额外后缀
```

## 根因分析
Conan package id 由 settings + options + 依赖闭包共同决定。已发布版本（如 libxext/6.4.0.1 只发布过基于 libx11/6.4.0 的变体 e647…）被下游（libxmu/1.3.1.1 以 force=True 钉 libx11/1.8.13）解析出另一个 package id（eab792…）时，制品仓缺该变体。试图在同一版本号下修改 recipe 的 requirements（6.4.0→1.8.13+force）以补发变体，会触发 R37/L0j：制品仓已存在该版本且 recipe 内容变化 → cnb.cool 不支持同版本多 recipe revision（409）→ 必须递增版本后缀。同时 R40/L0n 要求分支名去掉前缀后逐字等于 包名-版本号，带"-variant"等后缀的分支一律硬失败。

## 推荐方案
**方法**: increment-version-suffix-and-exact-branch

**说明**: 把目标依赖声明落到"下一个适配版本"：libxext/6.4.0.1 → 新建 archives/l/libxext/6.4.0.1.1/ 目录（上游源码 tarball 与 sha256 完全不变，唯一差异是 requirements() 中 libx11 改为 1.8.13 并加 force=True），conanfile.py version/conandata.yml 版本键/manifest.yaml/test_package 同步递增；恢复已发布 6.4.0.1 目录原状；分支名改为 feat/libxext-6.4.0.1.1（R40 精确匹配，前缀 feat/ 允许）；并把所有下游 requires("libxext/6.4.0.1") 更新为 6.4.0.1.1（CI hint 明确要求"更新 archives/ 目录和所有下游引用"）。

**修复命令**:
```
cp -r archives/l/libxext/6.4.0.1 archives/l/libxext/6.4.0.1.1 && 修改 version/requires/conandata/manifest → 本地 CI 同款脚本验证 → git push 新分支 → /rebuild
```

**验证**:
```
conan list "libxext/6.4.0.1:*" -r=ohpcd  # package_id 级核对缺哪些变体；conan graph info --requires=libxext/6.4.0.1 --build=never -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64  # 看 force 钉版后解析出的实际 package id
```
