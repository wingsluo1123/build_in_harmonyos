# E3650: OHOS 上 `grep` 可能是 toybox 版（/system/bin 优先）：对二进制文件默认跳过且 `-a` 无效，二进制内容断言（DT_NEEDED 等）会静默恒假

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, toolchain, testing, path
- **作者**: unknown

## 错误特征
```
toybox .* is not GNU grep|grep -aq .* 无输出且返回非 0|Binary file .* matches 未出现|CASE SUMMARY: total=5 passed=4 failed=1
```

## 根因分析
OHOS 同时存在两套用户态工具：toybox（`/system/bin/*`）与 HNP 自带 GNU 工具（`/data/service/hnp/bin/*`）。交互 shell 的 PATH 往往把 HNP 放在前面（conan profile 的 `[buildenv] PATH` 也是 `+(path)/data/service/hnp/bin`），此时 `grep` 是 GNU grep；但 **`conan test` / `conan create` 的 test_package 运行环境（VirtualRunEnv + 继承的父进程 PATH）里 `/system/bin` 排在 `/data/service/hnp/bin` 之前**，`grep` 命中 `toybox 0.8.12`。toybox grep 对二进制文件默认跳过（打印 "Binary file ... matches" 的 GNU 行为不存在），且 `-a` 不被支持/不生效：`grep -aq <pattern> <elf>` 恒返回 1 且无输出，`grep -ao ...` 输出为空。于是"断言二进制 DT_NEEDED 含某库"的测试在 `conan test` 下**恒 FAIL、且失败诊断也为空**（`$(grep -ao ... )` 展开为空），而在开发者交互 shell 里手动重跑却 PASS —— 极易被误判为偶发/环境抖动。判定铁证：脚本里打印 `command -v grep` 与 `grep --version | head -1`（toybox 会打印 "toybox 0.8.12 (is not GNU grep 9.0)"）。

## 推荐方案
**方法**: tr-delete-nul-then-bash-case-substring

**说明**: (1) 断言二进制内容时**不要用 grep**：先 `BIN_TEXT="$(tr -d '\000' < "$BIN")"` 去掉 NUL（`tr` 在 toybox 里可用且行为一致），再用 bash **内建** `case "$BIN_TEXT" in *libQt5Widgets.so.5*) ... ;; esac` 做子串匹配——零外部依赖、与 PATH 无关；(2) 若必须用 grep，显式取绝对路径的 GNU grep（`/data/service/hnp/bin/grep`）或 `command -v` 校验版本后回退，**不要**写 `grep -a` 假设 GNU 语义；(3) 在 test_package 脚本里对"平台工具行为"类断言加一行环境自证（`command -v grep`），让 PATH 差异导致的失败可诊断而非静默空输出；(4) 生成文件仅 2 MB 级时 `tr` + `case` 的开销可忽略（实测 2,587,264 字节 ≈2.5 MB 的二进制 <0.2 s）。

**修复命令**:
```
BIN_TEXT="$(tr -d '\000' < "$XDRAW")"; HAS=no; case "$BIN_TEXT" in *libQt5Widgets.so.5*) HAS=yes ;; esac
```

**验证**:
```
bash -c 'source <test_package>/conanrun.sh; command -v grep; grep --version | head -1; grep -aq libQt5Widgets <pkg>/bin/<bin>; echo rc=$?'   # 期望出现 /system/bin/grep 与 "toybox ... (is not GNU grep)"，rc=1
```
