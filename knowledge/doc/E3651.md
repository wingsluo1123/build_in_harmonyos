# E3651: Qt5 包内 qmake 模块描述（mkspecs/modules/*.pri 与 bin/qt.conf）指向已消失的 conan 构建目录：QT += <module> 全部 Unknown module(s)，须复制改写并经 QMAKEMODULES 暴露

## 基本信息
- **严重度**: 2
- **类别**: build-system, qmake, conan, path, qt5
- **作者**: unknown

## 错误特征
```
Project ERROR: Unknown module\(s\) in QT:|Cannot read .*/p/b/[^/]+/b/mkspecs/modules-inst/qt_lib_.*\.pri|QT_MODULE_LIB_BASE = .*\.conan2/p/b/
```

## 根因分析
qt5-qtbase / qt5-qtsvg 等 Qt5 模块包在 conan 中"就地安装"后被重新打包：包内 mkspecs/modules/qt_lib_*.pri 与 mkspecs/modules-inst/*.pri 里的 QT_MODULE_{BIN,INCLUDE,LIB,HOST_LIB}_BASE 以及 include(...) 语句写的是**构建期**的 conan 私有前缀 <home>/p/b/<hash>/b，随构建目录清理而失效；bin/qt.conf 的 [Paths] Prefix / HostPrefix 同样是构建期路径。消费方用 qmake 构建时，qmake 从 Qt 安装的 mkspecs/modules 读取这些条目：include 的目标不存在（每个模块一条 "Cannot read ..." 警告），QT.<module> 的 libs/includes 解析不出有效路径，于是 `QT += core gui widgets ...` 被判为 Unknown module(s)；同时 QT_INSTALL_BINS/LIBS 指向失效目录，QMAKE_RCC/QMAKE_MOC/QMAKE_UIC 生成 <stale>/bin/rcc（Makefile 把不存在的 rcc 写成 qrc 依赖，make 直接失败），产物 RUNPATH 也写入失效路径。

## 推荐方案
**方法**: copy-rewrite-pri-via-qmakemodules-plus-qtconf

**说明**: (1) 把**每个** Qt5 依赖包的 mkspecs/modules/*.pri 与 mkspecs/modules-inst/*.pri 复制到 <build_folder>/qmake-modules/{modules,modules-inst}，用正则 `/[^\s\"'()]*?/p/b/[^/\s\"'()]+/[bp](?=/|$|\s|\"|')` 把构建期前缀整体改写为对应包的 package_folder（必须以 `/` 起锚，否则 `include(/…` 的 `include(` 会被吞掉）；(2) `Environment().define("QMAKEMODULES", modules_dir)` —— QMAKEMODULES 目录中的同名 .pri 优先于 Qt 安装 mkspecs/modules 内失效条目（无需改动 conan 缓存包，比改包内文件更干净）；(3) 另写只含 [Paths] Prefix/HostPrefix=<qtbase package> 与空 Sysroot 的 qt.conf，用 `qmake -qtconf <file>` 加载（**不可**带 [EffectivePaths] Prefix=..，否则找不到 mkspec），修复 rcc/moc/uic 与产物 RUNPATH；(4) 仍以命令行 `QMAKE_RCC=… QMAKE_MOC=… QMAKE_UIC=…` 兜底（命令行赋值优先级最高）；(5) QT_MODULE_*_BASE 失效还会让 qmake 判定 svg 等外部模块缺失，故 qtbase 与 qtsvg 都要处理（只处理 qtsvg 不够）。残留的 "Cannot read" 警告来自 qmake 仍会遍历 Qt 安装内 modules 目录，非致命。

**修复命令**:
```
python: shutil.copy2(<pkg>/mkspecs/modules/<x>.pri, modules_dir) + _STALE_PREFIX_RE.sub(pkg_root, content); build_env.define("QMAKEMODULES", modules_dir); qmake -qtconf <qt.conf> <pro> -spec linux-clang "QMAKE_RCC=<pkg>/bin/rcc" "QMAKE_MOC=<pkg>/bin/moc" "QMAKE_UIC=<pkg>/bin/uic"
```

**验证**:
```
qmake -qtconf <fixed>.conf <app>.pro -spec linux-clang; # 期望无 "Project ERROR: Unknown module(s)"；grep -n '^CXXFLAGS' Makefile 应含正确的 -I<package>/include/QtCore 而非 <stale>/include；make 后 readelf -d <bin> | grep RUNPATH 不应含 .conan2/p/b/ 构建期路径
```
