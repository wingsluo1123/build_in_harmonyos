# E3652: qmake 命令行 `CONFIG-=debug` 覆盖不了 .pro 内的 `CONFIG += debug`：必须改工程文件，否则 conan Release 档仍产出 -O0 -g3 调试二进制

## 基本信息
- **严重度**: 3
- **类别**: build-system, qmake, packaging, build-type
- **作者**: unknown

## 错误特征
```
CXXFLAGS\s*=.*-O0 -g3|QMAKE_CXXFLAGS_DEBUG|CONFIG \+= debug|Building with -O0|debug build flagged in release profile
```

## 根因分析
qmake 把命令行上的变量赋值放在**工程文件求值之后**应用（对 += 追加型累积变量尤其如此），因此 `qmake app.pro CONFIG+=release CONFIG-=debug` 里的 `CONFIG-=debug` 会被 .pro 中后写的 `CONFIG += debug` 覆盖；配合常见的 `QMAKE_CXXFLAGS_DEBUG += -O0 -g3`，最终 Makefile 的 CXXFLAGS 仍是 `-pipe -g -O0 -g3`，`CONFIG(debug, …)` 分支也保持启用。表现是 conan `build_type=Release` 与 profile 完全正确，产物却是 12MB 级带全套调试信息的 -O0 二进制；不报错、不失败，只在体积/性能/L5 基线对比上露头，容易被"能编过就发 PR"的流程放过。

## 推荐方案
**方法**: patch-out-hardcoded-config-then-drive-from-build-type

**说明**: (1) **先验证**命令行覆盖是否真的失效：跑一次 qmake 后 `grep '^CXXFLAGS' Makefile`，确认不是自己传参写错——不要凭"应该能覆盖"继续调参；(2) 用 refresh-patch 生成上游补丁，删除 .pro 中硬编码的 `CONFIG += debug`（保留 QMAKE_CXXFLAGS_DEBUG 行无副作用：它只在 debug 档生效，同时天然让 Debug 构建仍可用）；(3) 配方在 qmake 命令行按 `self.settings.build_type` 显式传 `CONFIG+=release` / `CONFIG+=debug`，使 conan 的单档构建语义与上游配置解耦；(4) 在 notes.md/manifest 记录"-O0 调试二进制"的前后体积/标志对比作为证据（R52 证据一致性）。

**修复命令**:
```
patch 内容: -CONFIG += debug （仅此一行）；conanfile build(): build_config = "CONFIG+=debug" if self.settings.build_type=="Debug" else "CONFIG+=release"; qmake <pro> -spec linux-clang {build_config}
```

**验证**:
```
qmake <app>.pro -spec linux-clang CONFIG+=release CONFIG-=debug && grep -E '^(CXX|C)FLAGS' Makefile; # 期望不含 -O0/-g3/-g；修复前实测仍为 -pipe -g -O0 -g3
```
