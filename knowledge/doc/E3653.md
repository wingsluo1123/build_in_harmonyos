# E3653: Qt 5.15 的 qlogging.h 只前置声明 QDebug：老工程用 qDebug() << 流式输出却未 #include <QDebug> 时，clang 报 incomplete return type / operator<< 二义性并中断编译

## 基本信息
- **严重度**: 2
- **类别**: portability, clang, header-dependency, qt5
- **作者**: unknown

## 错误特征
```
calling 'debug' with incomplete return type 'QDebug'|calling 'warning' with incomplete return type 'QDebug'|use of overloaded operator '<<' is ambiguous.*QDebug|use of overloaded operator '<<' is ambiguous.*QColor
```

## 根因分析
Qt 5.15 起 qlogging.h 只做 `class QDebug;` 前置声明并在头注释明写 "In order to use the qDebug() stream, you must #include<QDebug>"（qdebug.h 反向包含 qlogging.h，故不存在隐式回环包含）。大量 2010 年代前后的 Qt 工程依赖"碰巧"经由其它 Qt 头（QApplication/QWidget/…）间接引入 qdebug.h，本身并不直接包含 <QDebug>。一旦某个翻译单元的 include 集合里没有引入 qdebug.h（典型：只含 QNetworkAccessManager/QNetworkReply/QUrl/QFile 等），qDebug() 宏展开成 QMessageLogger::debug() 返回不完整类型 QDebug：clang 15 报 "calling 'debug' with incomplete return type 'QDebug'"，并因 QDebug 不完整、重载解析只能看到 QColor/QMatrix/QTransform/QVariant 等**隐式转换构造**出来的 operator<< 候选，追加报 "use of overloaded operator '<<' is ambiguous"。注意同一工程内其它 .cpp 常常没事（它们的 include 集合恰好引入了 qdebug.h），因此该故障表现为"只挂个别文件"，易被误判为语法错误。

## 推荐方案
**方法**: add-explicit-qdebug-include-to-affected-tu

**说明**: (1) 先用 `make -k`（而非 make -jN 首次失败即停）把**全部**失败 TU 枚举出来——该故障只出现在 omit 了 qdebug.h 的 TU，逐个修比猜测快；(2) 在受影响文件按 Qt 惯例补 `#include <QDebug>`（放在其它 Qt 头附近），不要用 `-include QDebug` 之类全局编译开关掩盖（会让所有 TU 隐式依赖未声明的头，且掩盖同一工程的其它头依赖缺口）；(3) 若同类命中很多（>10 个 TU），说明工程整体头依赖不可靠，可考虑统一在自建 precompiled header 或公共头里显式包含 <QDebug>，并在 PR 说明中标注；(4) 上游确有修复分支时可对齐上游写法，避免自造风格。

**修复命令**:
```
sed -i '0,/#include/s//#include <QDebug>\n\n#include/' <file>.cpp   # 仅示意；实际应按文件原 include 顺序插入
```

**验证**:
```
make -k -j1 2>&1 | grep -E "incomplete return type 'QDebug'|operator '<<' is ambiguous" ; # 修复后应为空且编译通过；clang++ -fsyntax-only -I<qt>/include -I<qt>/include/QtCore <file>.cpp
```
