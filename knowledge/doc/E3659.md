# E3659: conandata.yml 源 URL 被替换为本地 file:// 预下载缓存路径，本地通过但 CI 干净环境 FileNotFoundError

## 基本信息
- **严重度**: 2
- **类别**: conan, conandata, local-env-leak, source-url
- **作者**: AtomCode
- **来源 PR**: 10748

## 错误特征
```
Error in source\(\) method.*conan_data\["sources"\]|FileNotFoundError.*predl_cache|No such file or directory.*\.tar\.xz
```

## 根因分析
本地调试时（如临时规避上游站点不可达），把 conandata.yml 的 sources.url 从官方 https URL 改成了指向本机目录的 file:///...predl_cache/xxx.tar.xz，随后忘记还原就提交推送。本地 conan create 因缓存文件存在而通过；CI worker 是干净环境，该绝对路径不存在，source() 下载阶段直接 FileNotFoundError，L1/L2/L4/L5 全部 skip，失败诊断类别为"未知"。这是典型的本地环境状态泄漏进配方，与知识库 E318/E486"本地缓存污染"同族。

## 推荐方案
**方法**: restore-official-url-before-commit

**说明**: 提交前将 conandata.yml 的 sources.url 还原为官方 https URL（sha256 保持实测值不变）；本地调试用临时文件或环境变量，不要把 file:// 写进受版本控制的 conandata.yml。推送后评论 /rebuild 触发 CI（push 不会自动构建）。

**修复命令**:
```
git checkout -- archives/a/aghermann/1.1.2/conandata.yml  # 或手工把 url 改回官方源; grep -rn "file://" archives/ 确认无本地路径残留后再提交
```

**验证**:
```
grep -n "file://" archives/<x>/<pkg>/<ver>/conandata.yml（应无输出）；CI_PACKAGES="archives/x/pkg/ver" CI_BRANCH=feat/pkg-ver zsh ci/conan/build_and_test.sh 全绿后推送，手动 /rebuild 触发 CI。
```
