# E3663: Makefile 仓库把构建产物提交进源码树时，交叉编译必须先清理 tarball 自带预编译 .so 再全量重建

## 基本信息
- **严重度**: 2
- **类别**: make, cross-compile, conan, packaging
- **作者**: pc2-51

## 错误特征
```
(cannot open shared object file|incompatible|wrong ELF class|is not a dynamic library|not found.*\.so)
```

## 根因分析
上游 Makefile 仓库（无 configure，纯 make 驱动）把构建产物（如 x86-64 预编译 lib/*.so）直接提交进源码树并打进 release tarball；交叉编译目标架构（如 OHOS arm64）时，链接器/加载器按默认搜索路径命中这些错误架构产物，报 incompatible/wrong ELF class 或运行时加载失败；产物随 tar.gz 分发，配方若不主动清理，图形化构建（conan create）会基于错误架构产物链接而失败或产出污染包。

## 推荐方案
**方法**: clean-then-rebuild-from-source-in-recipe

**说明**: build() 第一动作显式 `make clean cleanso`（如有 clean 目标），删除 tarball 自带的预编译产物，随后从源码全量重建目标架构；产物架构用 readelf 核验（ELF Class=ELFCLASS64, Machine=AArch64），避免污染包混入错误架构二进制。

**修复命令**:
```
def build(self):\n    self.run("make clean cleanso", cwd=self.source_folder)\n    for t in (...): self.run(f"make {t} CC=clang", cwd=self.source_folder)  # R33: 显式传编译器，不裸用 shell 环境变量
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 --build=missing；readelf -h/readelf -d 核验产物架构为 aarch64（ELF Class/Machine）；test_package 1/1 PASS；消费者用例 src_new/src_process PASS。
```
