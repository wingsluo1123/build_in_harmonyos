# E3665: CMSIS 家族库（CMSIS-DSP 等）在无 CMSIS-Core 平台 standalone 构建：必须 HOST=ON（→ __GNUC_PYTHON__）免 cmsis_compiler.h，且消费者/test_package 需经 cpp_info.defines 传播同一宏

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, cmake, cross-compile, conan
- **作者**: AtomCode
- **来源 PR**: (同 PR 交付)

## 错误特征
```
cmsis_compiler\.h.*not found|arm_math_types\.h:.*fatal error|cmsis_compiler\.h' file not found
```

## 根因分析
CMSIS-DSP 的 arm_math_types.h:126 无条件 `#include "cmsis_compiler.h"`（仅 DOXYGEN 与 __GNUC_PYTHON__ 分支豁免），cmsis_compiler.h 由 CMSIS-Core 提供，standalone 源码树（无 CMSIS-Core）无此头 → 编译首错 fatal error。上游 configDsp.cmake 在 HOST=ON 时向目标注入 PUBLIC __GNUC_PYTHON__（源码注释明示 "the only way to build on a target not supported by CMSIS Core"）；消费者（含 Conan test_package）编译同样必须定义 __GNUC_PYTHON__，否则安装后的公开头仍引用 cmsis_compiler.h——上游 CMake 包通过 INTERFACE_COMPILE_DEFINITIONS 传播，Conan 配方必须用 cpp_info.defines 等价传播。

## 推荐方案
**方法**: upstream-host-option-plus-consumer-define-propagation

**说明**: standalone 构建（无 CMSIS-Core）时用上游 HOST=ON 选项（触发 __GNUC_PYTHON__ 免 cmsis_compiler.h）；Conan 配方 generate() 设 HOST=ON、package_info() 用 self.cpp_info.defines=["__GNUC_PYTHON__"] 向消费者传播（等价上游 INTERFACE_COMPILE_DEFINITIONS）；test_package 消费者直接使用公开头 arm_math.h + libCMSISDSP.a 编译链接运行验证。NEON 可开（aarch64 原生支持），DISABLEFLOAT16 按需。

**修复命令**:
```
tc.variables["HOST"]="ON"; tc.variables["NEON"]="ON"; self.cpp_info.defines=["__GNUC_PYTHON__"]
```

**验证**:
```
cmake -S . -B build -DHOST=ON -DCMSISDSP_INSTALL=ON && make -C build -j4; conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
