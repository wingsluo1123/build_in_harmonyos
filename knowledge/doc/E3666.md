# E3666: CMSIS-DSP Testing 框架的 F16+NEON 套件（TransformNeonCF16 等）编译需命令行注入 ARM_MATH_NEON_FLOAT16 + ARM_FLOAT16_SUPPORTED（含 -Wno-macro-redefined），否则类方法被守卫排除导致链接缺符号

## 基本信息
- **严重度**: 3
- **类别**: build-system, cmake, toolchain, testing, dsp
- **作者**: AtomCode
- **来源 PR**: (同 PR 交付)

## 错误特征
```
undefined symbol: vtable for TransformNeonCF16|TransformNeonCF16::test_cfft_f16|undefined symbol:.*TransformNeonC|ARM_MATH_NEON_FLOAT16
```

## 根因分析
TransformNeonCF16.cpp 顶部守卫 `#if defined(ARM_MATH_NEON_FLOAT16) && defined(ARM_FLOAT16_SUPPORTED)` 在 include 前求值：ARM_MATH_NEON_FLOAT16 不会在 include 前自动定义（arm_math_types.h 的自动定义发生在 include 之后），ARM_FLOAT16_SUPPORTED 依赖 __ARM_FP16_FORMAT_IEEE 且与头文件重复定义时会触发 -Werror macro-redefined；Testing/CMakeLists.txt 的 target_compile_definitions 未传递这些守卫宏 → 类方法整体被条件编译排除（obj 仅 832 字节）→ 链接报 undefined symbol: vtable for TransformNeonCF16。

## 推荐方案
**方法**: command-line-guard-macro-injection

**说明**: 在 Testing 构建的 C/CXX 编译标志中注入 -DARM_MATH_NEON_FLOAT16 -DARM_FLOAT16_SUPPORTED -Wno-macro-redefined（后者抑制与 arm_math_types_f16.h 的重复定义警告），即可实例化 F16 NEON 类方法并成功链接；注入后 NEON 配置 test 可运行（786 项）。

**修复命令**:
```
cmake -S . -B build-tests -DHOST=ON -DNEON=ON -DCMAKE_C_FLAGS="-DARM_MATH_NEON_FLOAT16 -DARM_FLOAT16_SUPPORTED -Wno-macro-redefined" -DCMAKE_CXX_FLAGS="..."
```

**验证**:
```
cmake -S Testing -B build -DNEON=ON -DCMAKE_CXX_FLAGS="-DARM_MATH_NEON_FLOAT16 -DARM_FLOAT16_SUPPORTED -Wno-macro-redefined" && make -C build -j4
```
