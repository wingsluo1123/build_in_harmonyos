# E3668: lang-preflight 的 manifest 扫描对全树任意 Cargo.toml 敏感，tests/ 下辅助差分门禁的 manifest 会把 C/C++ 主库误判为 mixed(cargo)——按 R47 D.4 边界规则以主库主体判定后继续适配

## 基本信息
- **严重度**: 3
- **类别**: build-system, language-detection, manifest, preflight, r47
- **作者**: AtomCode
- **来源 PR**: (同 PR 交付)

## 错误特征
```
detected_language: mixed|任务标记 cpp，实测源码为 mixed|实测源码为 mixed（cargo）|env_unsupported
```

## 根因分析
lang_detect.py _manifest_scan 对 Cargo.toml/pyproject.toml/go.mod 等 manifest 使用全树文件名集合（names = {p.name for p in files}，rglob 全部文件），未限定源码根顶层；当 tests/ 等子目录存在辅助参考工具（如 Rust exrs crate 差分校验门禁 tests/exrs_reference/Cargo.toml）时误触发 rust manifest；再与源码统计（c 占 79%）冲突规则叠加 → detected=mixed。而库主库主体为 C/C++（如 exr_image.h 单头文件 C89 库），辅助工具按 R47 边界规则 D.4 "辅助脚本不算主体" 不应参与主体语言判定。

## 推荐方案
**方法**: main-body-first-then-compat-family

**说明**: lang-preflight 输出 mixed 且任务语言为 c/cpp 时，不要直接接受工具终态 env_unsupported：先核对库主库主体（README/主头文件/主源码统计，辅助参考工具目录排除），主库为 c/cpp 时按 R47 D.4 边界规则判 detected=c/cpp（c↔cpp 兼容族不迁移），记录证据后继续适配主流程；仅当主库主体确为非 c/cpp 时才走 env_unsupported/lang_hold。

**修复命令**:
```
grep -nE "standalone C header|C89-compatible" README.md; grep -rn "Cargo.toml" --include="Cargo.toml" tests/ | head; wc -l exr_image.h
```

**验证**:
```
python3 scripts/ohc-run.py lang-preflight exr_image 0.1.0-rc3 --src <src> ; cat archives/e/exr_image/0.1.0-rc3/reports/lang_preflight.log
```
