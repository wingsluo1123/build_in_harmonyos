# E3673: libhpdf.so 缺少 DT_SONAME：HarmonyOS 无 CMake 平台模块导致 SONAME 链接标志为空

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, cmake, linking, shared-library
- **作者**: pc1-47-executor

## 错误特征
```
readelf -d .*libhpdf\.so.*no SONAME|缺少 DT_SONAME|soname_gate_failed|L5_RESULT=fail: soname_gate_failed|libhpdf\.so 缺少 DT_SONAME
```

## 根因分析
上游 libharu 2.3.0 的 CMake 未为共享库目标设置 VERSION/SOVERSION；且 HarmonyOS/OHOS 目标在 CMake 中没有 Platform/HarmonyOS.cmake 平台模块，CMAKE_SHARED_LIBRARY_SONAME_C_FLAG/-CXX_FLAG 保持为空。即使项目内设置 set_target_properties(... VERSION/SOVERSION ...)，链接命令模板 <SONAME_FLAG><TARGET_SONAME> 中 SONAME_FLAG 为空，链接器不会收到 -Wl,-soname 参数，产出的 libhpdf.so 的 ELF dynamic 段没有 SONAME 条目（readelf -d 显示无 SONAME），W3 CI 的 L5 SONAME 质量门禁失败（L5_RESULT=fail: soname_gate_failed）。

## 推荐方案
**方法**: set-soname-flags-plus-unversioned-soname

**说明**: 在配方 generate() 中针对 OHOS 显式设置 CMAKE_PLATFORM_NO_VERSIONED_SONAME=ON 与 CMAKE_SHARED_LIBRARY_SONAME_C_FLAG/CMAKE_SHARED_LIBRARY_SONAME_CXX_FLAG="-Wl,-soname,"，并伴随一个设置 VERSION/SOVERSION 的最小上游补丁，使 CMake 产出带可重定位 SONAME（未版本化、无版本化符号链接）的 libhpdf.so。

**修复命令**:
```
conanfile.py generate(): tc.variables["CMAKE_PLATFORM_NO_VERSIONED_SONAME"]="TRUE"; tc.variables["CMAKE_SHARED_LIBRARY_SONAME_C_FLAG"]="-Wl,-soname,"; tc.variables["CMAKE_SHARED_LIBRARY_SONAME_CXX_FLAG"]="-Wl,-soname,"; 补丁: set_target_properties(hpdf PROPERTIES VERSION ${LIBHPDF_VERSION} SOVERSION ${LIBHPDF_MAJOR})
```

**验证**:
```
conan create 成功后执行 readelf -d "<package>/lib/libhpdf.so" 应显示 "0x000000000000000e (SONAME) Library soname: [libhpdf.so]"；W3 本地 CI 日志应显示 L5_RESULT=pass；test_package 消费者应能正常运行。
```
