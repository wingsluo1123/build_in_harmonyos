# E3674: OHOS 真机拒绝执行"非预置 ELF"（chmod 后仍 Permission denied）；工具/代码生成器类依赖改为本机预生成构建图/产物再上传

## 基本信息
- **严重度**: 4
- **类别**: hmdfs, ohos, build-system, toolchain, cross-compile
- **作者**: gcw_6YxinkyD
- **来源 PR**: ""

## 错误特征
```
Permission denied|not executable|cannot execute.*binary|exec format error|Failed to exec
```

## 根因分析
HarmonyOS 真机 /storage 为 HMDFS 文件系统，且叠加 SELinux/域标签策略：只有"预置/受信"的 ELF（如 usr/local/bin 下 owner=file_manager 的 clang-15/ninja/python3 等）被允许 execve；用户在会话中拷贝、上传或新放置的 ELF（无论 chmod 755/777、无论放 $HOME/tmp、$HOME/.local/bin、conan cache 目录）都会被 exec 策略拒绝，报 Permission denied。现象与文件权限无关（st_mode 正确、可读），是执行策略层拦截。libskia(146.20260602-git.3476902) 适配中 gn 二进制在真机任何落点均无法执行，成为死路。

## 推荐方案
**方法**: host-pregenerated-build-artifacts

**说明**: 凡真机侧需要运行"非预置 ELF"才能推进的构建步骤，改为在宿主（Windows/Linux 开发机）预生成对应产物再随源码包上传：GN 项目用本机 gn 生成 out/ ninja 构建图（工具链路径直接写成真机绝对路径），真机配方检测到 out/build.ninja 存在即跳过工具调用直接跑预置 ninja；其他构建系统同理（本机跑 bison/flex/protoc 生成 .c/.h/.pb.cc，真机只编译）。真机只执行预置工具链（ninja/clang/ar/ld.lld/python3）。

**修复命令**:
```
本机: gn gen out --args='cc="/storage/Users/currentUser/usr/local/bin/clang" cxx=".../clang++" target_os="linux" target_cpu="arm64" ...'；打包前对图做真机化 rewrite（见 .md 附节）；真机: 配方 build() 检测 out/build.ninja -> 跳过 gn gen，直接 ninja -C out -j2 skia。
```

**验证**:
```
libskia: 真机 conan create（out/ 为本机预生成图）1213/1213 通过 + test_package 冒烟 OK。对照：真机 os.chmod(gn, 0o777) + cp 到 $HOME/tmp/.local/bin/cache 后执行均 Permission denied；同目录预置 clang-15 ELF 可执行。
```
