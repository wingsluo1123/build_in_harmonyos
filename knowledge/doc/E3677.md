# E3677: lang-preflight 的源文件统计把 perl 辅助脚本（tools/*.pl、测试驱动）计入主体占比，且 _manifest_scan 不识别只带生成的 configure+Makefile.in 的 autotools release tarball（build_system=none）→ 纯 C CLI 库被误判 mixed/env_unsupported；按 R47 D.4 边界规则以主语言判定继续适配

## 基本信息
- **严重度**: 3
- **类别**: build-system, language-detection, preflight, r47
- **作者**: pc4-29 <noreply@atomgit.com>
- **来源 PR**: pending

## 错误特征
```
detected_language: mixed|任务标记 cpp，实测源码为 mixed|build_system: none|env_unsupported.*mixed
```

## 根因分析
lang_detect.py 的三级判定在"无 manifest + 无 ≥70% 单语言"时返回 mixed。两类漏判叠加：①_source_stats 把 tools/*.pl（恢复后处理辅助脚本）、tests/tests.pl（测试驱动）计入主体统计（仅 bash 被排除），使 C 占比跌到 52%；②_manifest_scan 只认 configure.ac/Makefile.am/Makefile/CMakeLists.txt 等，而 autotools release tarball 只带生成的 configure + Makefile.in（file 命令确认是 /bin/sh 脚本 + ASCII），→ build_system=none、无 c/cpp 族 manifest 兜底。边界规则 D.4"辅助脚本不算主体"本应排除 perl 辅助工具，且 c/cpp 兼容族（c↔cpp）不迁移。

## 推荐方案
**方法**: aux-script-excluded-main-body

**说明**: lang-preflight 输出 mixed/env_unsupported 且任务语言为 c/cpp 时，不直接接受工具终态：先核对主库主体（configure/Makefile.in 等构建系统证据 + 主源码统计，排除 tools/*.pl、测试脚本等辅助文件），主库为 c/cpp 时按 R47 D.4 边界规则判 detected=c/cpp（c↔cpp 兼容族不迁移），记录证据后继续适配主流程；仅当主库主体确为非 c/cpp 时才走 env_unsupported/lang_hold。

**修复命令**:
```
file configure Makefile.in; ls src/*.c | wc -l; grep -nE '^#!.*perl' tools/*.pl tests/tests.pl | head
```

**验证**:
```
file configure Makefile.in; find . -name '*.pl' | head; python3 scripts/ohc-run.py lang-preflight magicrescue 1.1.10 --src <src>（复现 build_system: none + mixed）
```
