# E3680: OHOS 上适配 XS 版 Perl 模块的范式：构建期可执行的 OHOS perl、进包缓存前的构建树内 ELF 签名、未发布 CPAN 依赖随包闭包、PERL5LIB 消费约定

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, dependency, packaging, testing
- **作者**: unknown

## 错误特征
```
Can.t locate [A-Za-z_:]+ in @INC|Could not find .* among .* total .*|Devel::CheckLib|binary-sign-tool|make.* Error [0-9]|invalid ELF|cannot open shared object file
```

## 根因分析
在 OHOS 上适配 Perl 模块要先分清两类，本仓此前只有第一类范式：纯 Perl 模块（如 perl-file-which/1.27）的配方注释写着"纯 Perl——无编译"，只把 lib/*.pm 拷进 site-lib，甚至不 require perl，因此不存在构建期执行问题；XS 模块（PDL 的核心）必须真跑 Makefile.PL 并编译 C，于是三个连环节点同时成立。①构建期必须有一个"能执行"的 perl：制品仓里的 perl 是 OHOS/armv8 二进制，在 Linux 构建机上跑不起来；本仓的关键事实是 CI worker 本身就是 OHOS 机器（日志里 /data/service/hnp/bin/ruby 可直接执行），所以 OHOS 版 perl 在构建期可直接执行，XS 构建才成立——若 worker 与目标不同 OS，此路不通，必须另找 host 解释器或交叉方案。②编出的 XS 共享库在 OHOS 上必须签名，且签名必须发生在进入 Conan 包缓存之前、于构建树内完成：OHOS 拒绝"先进包缓存后签名"的 ELF（perl 配方注释原话），工具是 /data/service/hnp/bin/binary-sign-tool 配合 /data/service/hnp/bin/llvm-objcopy，顺序反了则设备上加载失败。③模块可见性依赖隐式契约：perl 包通过 buildenv/runenv prepend PATH(bin)、define PERL、prepend PERL5LIB(lib/perl5/{version,site_perl/version,vendor_perl/version}[/archname])；模块包必须把自己的对应目录 prepend 进 PERL5LIB，否则 require 报 Can.t locate ... in @INC。此外 PDL 的 Makefile.PL 在 configure 阶段硬依赖 Devel::CheckLib（探测 libm/libpgplot），这是"依赖未发布到制品仓"的典型：未发布的 CPAN 依赖要么各提一个 perl-* PR（周期长），要么按路线 A 与本体一起以 url+sha256 固定随包 vendor，后者与 Ruby 的 gem 闭包范式同构。 另五关实测（均有 CI 日志）：①Build.PL 发行版必须走 Module::Build 分支；②INSTALL_BASE 的模块在 <base>/lib/perl5，PERL5LIB 只放 <base> 会 Can't locate Module/Build.pm；③Dist::Zilla 生成的 Makefile.PL 会撞核心 warnings 版本错配（undefined &warnings::register_categories），纯 Perl 模块应直接拷 lib/；④Module::Build 的前置读自 Build.PL（不是 META），test 期前置要用补丁从 Build.PL 的 test_requires 与 %fallback_build_requires 去掉；⑤XS 编译报 no compiler detected，根因是 perl Config.pm 的 cc 为 /bin/sh /data/service/hnp/bin/clang，CBuilder 按 shell 拆分后执行 sh <ELF> 必然失败，而 CBuilder/Base.pm:40 认 ENV CC，规范化成单个真实编译器路径即可（CI 的 PATH 不含 /data/service/hnp/bin，须绝对路径）。 本条 2026 年已在本仓 CI 全绿（构建 #90914：L0/L1/L4/L5 全 pass，上游 6 个测试文件 1510 用例全过，test_package 通过，Pass rate 100%）。十条实测坑：①Build.PL 发行版要走 Module::Build 分支；②INSTALL_BASE 的模块在 <base>/lib/perl5，PERL5LIB 必须含它；③PERL5LIB 绝不能把 encoding/ 这类一级子目录当模块根，否则 require warnings 命中 encoding/warnings.pm 使核心 warnings 失效；④Module::Build 前置读自 Build.PL；⑤perl 的 Config.pm 里 cc 带 /bin/sh 前缀，CBuilder 试编译必失败，需用 $ENV{CC} 覆盖；⑥本仓 perl 包不可重定位（archlibexp 写死 /lib/perl5/...），须在 stage 放修正版 Config 并用 CPATH 兜底；⑦sysroot 的 libpthread.a 是空占位导致 pthread 探测假阳性，PDL 会引用 OHOS libc 不导出的 pthread_setcanceltype，应置空 POSIX_THREADS_LIBS；⑧上游 pdlmagic.c 的 no-pthread dummy 缺两个函数，需补丁补齐；⑨binary-sign-tool 须用 -inFile/-outFile/-selfSign 且先清旧 .codesign；⑩package_info 的 PERL5LIB 必须含所有依赖包。

## 推荐方案
**方法**: buildable-ohos-perl-at-build-time-plus-build-tree-elf-signing

**说明**: 六步：①先判定模块类型——纯 Perl 走仓内既有范式（拷 lib/*.pm 即可）；XS 才需要本范式。②在 conanfile 里从依赖包取解释器（self.dependencies["perl"].package_folder + bin/perl），并复刻 perl 包的 PERL5LIB 目录枚举（lib/perl5 下的 version / site_perl/version / vendor_perl/version 及其 archname 子目录）。③未发布的 CPAN 依赖按路线 A：conandata.yml 逐条固定 url+sha256，用 INSTALL_BASE=<私有 stage> 依序 perl Makefile.PL && make && make install 装进 stage。④本体 perl Makefile.PL INSTALL_BASE=<stage> && make。⑤在构建树内对产出的 .so 逐个签名（binary-sign-tool sign -i x.so -o x.so.signed 后替换），再 make install，保证进包的 ELF 已是签名件；同时若构件需要运行才能测试，签完名再跑测试。⑥package() 合并各 stage 的 lib/perl5 与 bin/，package_info() 里 prepend PATH 与 PERL5LIB。

**修复命令**:
```
conandata: https://cpan.metacpan.org/modules/by-module/<Top>/<Dist>-<ver>.tar.gz + sha256; perl Makefile.PL INSTALL_BASE=<stage>; make; /data/service/hnp/bin/binary-sign-tool sign -i foo.so -o foo.so.signed; perl -MTest::Harness -e 'runtests @ARGV' -- t/core.t; make install
```
