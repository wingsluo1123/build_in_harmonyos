# E3681: 远端依赖配方不可达时消费者侧静态内嵌：make-dist免自举+合成缺失pc+命令行强制可用shell重建

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, build-system, autotools
- **作者**: hmbs-executor
- **来源 PR**: 17170

## 错误特征
```
Main binary package .* missing|Unknown compiler\(s\)|unable to find library -lstrophe
```

## 根因分析
远端libstrophe无OHOS二进制需源码重建但其配方缺自举且预检仅同步消费者单包目录致依赖侧改写不可达，消费者无法向依赖构建上下文注入工具，叠加openssl/zlib无pc与毒化SHELL及过期clang路径共同阻塞

## 推荐方案
**方法**: vendored-static-embed-with-synthetic-pc

**说明**: 删除对远端失效依赖的requires改为消费者侧静态内嵌，用上游make-dist发布包免除autoreconf自举，缺失openssl/zlib时按包目录递归搜索合成pc走标准PKG_CHECK_MODULES，configure与make命令行强制可用shell，重定位过期clang并显式构建meson非默认测试目标

**修复命令**:
```
conanfile.py删除requires-libstrophe改requires-expat与tool_requires-pkgconf加meson保留；conandata增加make-dist URL与sha；build内文本替换移植加合成pc加命令行强制shell加编译器重定位加meson显式目标构建
```

**验证**:
```
真机conan create全链通过且日志显示内嵌libstrophe已编完装完、meson主构建与unittests显式目标构建成功，HMBS_TEST_PACKAGE_RESULT与上游计数口径一致
```
