# E3685: CCI依赖链拖入m4源码构建失败时RREV-pin切至ohpcd配方并直编规避工具链及宽字符ncurses链接修正

## 基本信息
- **严重度**: 3
- **类别**: ohos, network, build-system, autotools
- **作者**: hmbs-executor
- **来源 PR**: 15383

## 错误特征
```
m4/1\.4\.19.*ERROR|/data/service/hnp/bin/bash.*inaccessible|ld\.lld: error: unable to find library -lncurses
```

## 根因分析
裸libpcap先命中conancenter autotools配方经bison/flex拖入CCI-m4源码构建且其configure重exec profile钉死的缺失hnp bash导致Error127而本包generate域脚本无法触及依赖构建叠加ncurses宽字符静态包无libncurses致硬编码-lncurses链接失败

## 推荐方案
**方法**: rrev-pin-ohpcd-plus-direct-build-ncursesw-fix

**说明**: 将libpcap RREV-pin至ohpcd cmake配方切断CCI-bison/flex至m4边并删除automake/autoconf/libtool tool_requires改直编7个TU加生成config.h同时将-lncurses修正为随LIBS加-lpcap -lformw -lmenuw -lpanelw -lncursesw兜底

**修复命令**:
```
conanfile.py requirements加RREV-pin libpcap至ohpcd并删tool_requires直编加config.h生成加链接改宽字符集；notes.md加链分析；MANIFEST.yml同步
```

**验证**:
```
真机conan create不再从源码构建m4/1.4.19且链接阶段无unable to find library -lncurses并全部门禁通过
```
