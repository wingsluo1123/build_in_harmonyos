# E3686: C++98 的 `std::ostringstream(char*, openmode)` 在 C++11 被移除：同名调用改选 `ostringstream(const std::string&)`，于是对未初始化定长缓冲做 strlen（堆越界读），且结果根本没写回缓冲区

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, cpp11, cxx, memory-safety
- **作者**: unknown

## 错误特征
```
AddressSanitizer: heap-buffer-overflow.*strlen|READ of size .*strlen|std::_Narrow_char_traits.*length|basic_string.*\{ctor\}|ostringstream\(name, std::ostringstream::out\)|ostrstream .*\(.*, *[0-9]+\)
```

## 根因分析
C++98 允许 `std::ostringstream(char *buf, openmode)`：把流写进调用者提供的定长缓冲区，末尾 `<< std::ends` 落一个 '\0'，是当年常见的"零分配"拼串写法。C++11 删除了这一重载，同一个调用会匹配 `explicit basic_ostringstream(const basic_string&, openmode)`：`char*` 被隐式构造成 `std::string` → 对那块**尚未初始化**（或未终止）的缓冲区调用 `traits::length()` → 堆越界读；同时后续 `<<` 全部写进流自己的内部缓冲，`buf` 里仍是垃圾，之后 `strlen(buf)`/`delete []` 还会再次踩到。

## 推荐方案
**方法**: build-in-std-string-then-copy-out

**说明**: 把"往用户缓冲区写流"改成"先用普通 ostringstream 拼 std::string，再按长度 new[] + 拷贝"：

**修复命令**:
```
nameStream << octave;
```

