# E3687: OHOS 的 bison/flex 工具包 prefix=`/`：运行期到 `/share/bison/...` 找数据、到构建期绝对路径找 m4，在 Conan 缓存里必然失败；构建时导出 BISON_PKGDATADIR 与 M4（并把 m4 显式 tool_requires）

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, toolchain, conan, bison
- **作者**: unknown

## 错误特征
```
/share/bison/m4sugar/m4sugar\.m4: cannot open|bison: m4 subprocess failed|flex: fatal internal error, exec of .*/bin/m4 failed|fatal internal error, exec of  failed
```

## 根因分析
OHOS 适配的 bison/flex 包按 `--prefix=/` 打包，`pkgdatadir` 因此编译进二进制为 `/share/bison`（bison）与相对该前缀的路径；`m4` 同样是 configure 时的依赖，flex 把当时的 m4 绝对路径（例如 `~/.cache/conan2/p/m42d.../p/bin/m4`）编译进二进制。消费端把包解到 Conan 缓存后这些路径都不存在：

## 推荐方案
**方法**: resolve-tool-from-package-folder

**说明**: 在 build() 里从 `self.dependencies.build` 找到 bison/flex/m4 的**包目录**，用包内绝对路径调用，并把数据目录显式指向同一包：

**修复命令**:
```
bison = self._build_tool("bison", "bison")   # <pkg>/bin/bison，找不到才回退名字
```

**验证**:
```
taopm 1.0 真机 conan create：
```
