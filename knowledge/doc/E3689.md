# E3689: CMake install 清除 RUNPATH 会破坏 OHOS --code-sign 嵌入的 ELF 签名，导致内核拒绝 execve

## 基本信息
- **严重度**: 4
- **类别**: cmake, linking, conan, security, cli-tool
- **作者**: gcw_6YxinkyD
- **来源 PR**: ""

## 错误特征
```
Operation not permitted.*vgmplay|exit 126.*bin/|RUNPATH.*missing.*package|sha256.*different.*build.*package
```

## 根因分析
OHOS clang wrapper 在链接时自动传 -Wl,--code-sign，把代码签名数据嵌入 ELF 本身。CMake install(TARGETS) 在 install 阶段根据 CMAKE_INSTALL_RPATH（Conan CMakeToolchain 默认设为空）清除 ELF 的 DT_RUNPATH 条目，这个 .dynamic 段改写操作破坏了签名与 ELF 内容的绑定，导致内核在 execve 时返回 EPERM（"Operation not permitted", exit 126）。build 目录的 ELF 保留链接时的 RUNPATH 和签名，能正常运行；package 目录的 ELF 被 CMake install 改写过，不能运行。两者大小相同但 sha256 不同。

## 推荐方案
**方法**: package-direct-copy-no-cmake-install

**说明**: package() 中不调用 cmake.install()，改用 conan.tools.files.copy 直接从 build_folder 复制最终 ELF 和数据文件到 package_folder/bin，保持 ELF 字节不变，避免 CMake install 改写 .dynamic 段破坏签名。

**修复命令**:
```
from conan.tools.files import copy; def package(self): bin_dir=os.path.join(self.package_folder,"bin"); copy(self,"vgmplay",src=self.build_folder,dst=bin_dir); copy data files
```

**验证**:
```
llvm-readobj -d build_dir/vgmplay | grep RUNPATH; llvm-readobj -d package_dir/bin/vgmplay | grep RUNPATH（package 产物 RUNPATH 消失即确认）; 直接运行 build_dir/vgmplay --version（能跑）和 package_dir/bin/vgmplay --version（Operation not permitted）对比。
```
