# E3690: 无 GPU 的构建机上跑 Vulkan 测试套件的两个必答点：先识破「找不到设备就提前 return ⇒ automake 全记 PASS 而实际零执行」的假绿，再用已发布的 CPU Vulkan 实现（swiftshader）把 ICD 直接命名成 libvulkan.so.1 充当 loader

## 基本信息
- **严重度**: 3
- **类别**: portability, conan, runtime, testing, graphics
- **作者**: unknown

## 错误特征
```
No such file or directory.*libvulkan|libvulkan\.so\.1|VK_ERROR_INCOMPATIBLE_DRIVER|vkCreateInstance|vkEnumeratePhysicalDevices|0 tests executed|tests executed \(0 failures
```

## 根因分析
两个独立机制叠加：测试器在找不到设备时"提前 return"使 automake 把零执行记成全部 PASS（假绿）；同时运行期 dlopen 型 Vulkan 消费者在没有 loader / 没有 ICD 的机器上无法建立实例，需要一个真能提供设备的底衬。

## 推荐方案
**方法**: icd-as-loader-test-substrate-with-zero-execution-guard

**说明**: 三步：先跑一次 make check 识破"零执行默认 PASS"假绿；再把已发布的 swiftshader 声明为 tool_requires 并把 libvk_swiftshader.so 复制成 libvulkan.so.1 前置进 LD_LIBRARY_PATH 充当 loader（另设 VK_ICD_FILENAMES/VK_DRIVER_FILES）；最后在取不到底衬时直接抛异常，从结构上消除假绿。
