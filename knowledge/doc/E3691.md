# E3691: OHOS 上 node 必须 --jitless，而 --jitless 关闭 WebAssembly 会连带击穿 TS transform 与 undici fetch

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime, testing, node
- **作者**: atomcode
- **来源 PR**: 0

## 错误特征
```
Check failed: 12 == \(\*__errno_location\(\)\)|Signal 5|WebAssembly is not defined|ExperimentalWarning: Transform Types
```

## 根因分析
本机 node v24.13.0 不加 --jitless 即 "Check failed: 12 == (*__errno_location())" 并 Signal 5 core dump（hnp 的 npm wrapper 同样崩溃，因为它也是真 JS 脚本）。但 --jitless 关闭 WebAssembly，而 node 自带的 TypeScript transform（amaro）与 undici 的 llhttp 解析器都是 wasm 实现：于是 (a) 任何 .ts 测试/脚本报 "ReferenceError: WebAssembly is not defined"，(b) 任何依赖 fetch() 的断言报 "TypeError: fetch failed [cause]: ReferenceError: WebAssembly is not defined"。二者是同一根因的两个症状，必须一次性识别，否则会把 wasm 缺失误判为"网络不通/库有 bug"。

## 推荐方案
**方法**: precompile-ts-with-tsc

**说明**: 保持 node --jitless（否则无法运行），把 .ts 测试用包内 typescript（devDependency）预编译成 JS 再跑；fetch/TS-transform 依赖类断言按平台豁免显式登记（不删改断言）。

**修复命令**:
```
node --jitless node_modules/typescript/lib/tsc.js --allowImportingTsExtensions --rewriteRelativeImportExtensions --module nodenext --target es2022 --moduleResolution nodenext --skipLibCheck --outDir <outdir> test/{error,log,md,goods}.test.ts
```

**验证**:
```
node -e "console.log(typeof WebAssembly)"            # 不带 --jitless 时进程 core dump
```
