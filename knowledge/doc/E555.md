# E555: 制品仓 puredata 是 application 不含 Pd API 头 m_pd.h：Pd 外部对象配方须在 source() 额外拉 pure-data 源码树并把 PDINCLUDEDIR 指向其 src

## 基本信息
- **严重度**: 3
- **类别**: conan, dependency
- **作者**: LXX0329

## 错误特征
```
"fatal error: 'm_pd.h' file not found / Invalid configuration: Pd API header not found"
```

## 根因分析
制品仓里的 puredata/0.54.1 走的是上游 pure-data 的 `make install`，只安装 `pd` 可执行与数据目录，package_info() 把 includedirs 置空，**不安装 Pd API 头 `m_pd.h`**（以及 g_canvas.h/m_imp.h 等）。而 Pd 外部对象配方（pd-smlib / pd-maxlib / pd-mjlib / pd-creb …）用 pd-lib-builder 构建，源码 `#include <m_pd.h>`，于是 conan create 在编译第一个 .c 时就 fatal error。puredata 包本身不需要头：它是应用，运行时只需要 bin/pd。

## 推荐方案
**方法**: 配方 source() 里额外 get() 与 puredata 同版本的 pure-data 源码树（codeload.github.com/pure-data/pure-data/tar.gz/refs/tags/0.54-1，sha256 19a0e2bfcbb5bad5e6dd016d1cda35464db6de008d1803a14c7e1f1625f31353，与 puredata/0.54.1 的 conandata 一致），strip_root 后 PDINCLUDEDIR 指向 `<source_folder>/pd-api/src`；build() 先断言 m_pd.h 存在再 make。CC 从 tools.build:compiler_executables 取（R33），pd-lib-builder 用 `$(CC) -dumpmachine` 自动选 Linux 分支与 pd_linux 扩展名。

**说明**: source() 拉 pure-data 0.54-1 源码树 → PDINCLUDEDIR=<pd-api>/src

**修复命令**:
```
'get(self, url=PD_SRC_URL, sha256=PD_SRC_SHA256, filename="pure-data-0.54-1.tar.gz", strip_root=True, destination=pd_api)'
```

**验证**:
```
"conan install --requires=puredata/0.54.1 -pr:h=ohos-aarch64-wsl && ls $(conan cache path puredata/0.54.1) | grep -c include   # → 0"
```
