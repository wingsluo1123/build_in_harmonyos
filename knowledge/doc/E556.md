# E556: OHOS 非特权进程 ptrace/进程内存访问被系统策略整体禁用：ptrace 类工具的适配前能力判定与可用子集

## 基本信息
- **严重度**: 3
- **类别**: ohos, runtime, security, capability, ptrace
- **作者**: 9C4A

## 错误特征
```
Unable to attach to pid.*: Permission denied|process_vm_readv.*: Permission denied|PR_SET_PTRACER.*Invalid argument|PTRACE_ATTACH.*EPERM|PTRACE_TRACEME.*EPERM
```

## 根因分析
OHOS 内核/安全域对非特权进程整体拒绝 ptrace 系能力：父→子、兄弟间、祖父→孙的 PTRACE_ATTACH/SEIZE 全部 EPERM；PTRACE_TRACEME 与 process_vm_readv 同为 EPERM；PR_SET_PTRACER 返回 EINVAL（未实现）；yama/pdebug_scope 策略接口存在但读取 ENOSYS（未向用户态开放）；进程处于 seccomp filter 模式（Seccomp:2, Seccomp_filters:1）且 CapEff 无 CAP_SYS_PTRACE。属系统安全策略，用户态无法绕过——与“未实现 syscall 返回 SIGSYS/ENOSYS”（E051/E246）不同：syscall 存在但被策略拒绝，进程不崩、调用方拿到干净 errno。

## 推荐方案
**方法**: pre-adaptation-capability-probe-and-usable-subset

**说明**: 1) 适配前先跑 ptrace 能力探针（每项独立 fork，按 errno 区分“策略拒绝 EPERM”与“未实现 SIGSYS/ENOSYS”，两者降级口径不同）；2) EPERM 成立时盘点工具的“非 ptrace 子集”（如 reptyr -l/-L 的 pty 管理不依赖 ptrace），只对可用子集提供功能与消费者测试；3) 上游 attach 类 E2E：如实申报平台边界并附探针证据，禁止桩化/弱化断言（R34/R51）；4) test_package/CI 不依赖 ptrace 能力；5) 真实调试/附加需求标注平台不可用，并按止损口径说明。

**修复命令**:
```
# 编译并运行探针（源码见触发实例归档）；期望 OHOS: ATTACH/SEIZE/TRACEME/process_vm_readv = -1/EPERM, PR_SET_PTRACER = -1/EINVAL
```

**验证**:
```
最小探针：每场景独立 fork，记录 ptrace/process_vm 调用的 ret 与 errno（ATTACH/SEIZE：父→子、兄弟、祖父→孙；TRACEME；process_vm_readv；PR_SET_PTRACER），并 grep Seccomp/CapEff /proc/self/status。OHOS 实测（uid=20020085 非特权，同一 SSH 会话）：ATTACH/SEIZE/TRACEME/process_vm_readv = -1/EPERM，PR_SET_PTRACER = -1/EINVAL，pdebug_scope 读取 = ENOSYS；reptyr 侧表现：Unable to attach to pid N: Permission denied
```
