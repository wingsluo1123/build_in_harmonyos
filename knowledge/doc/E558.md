# E558: On OHOS getpwuid(geteuid()) returns NULL because app uids have no passwd DB entry: code paths dereferencing the result segfault (rmlint rm_util_get_groupname -> user->pw_gid), the signal handler loops printing "Aborting due to a fatal error" forever instead of terminating, and tools whose default finder/classifier flags unknown-uid files become useless until the type is deselected

## 基本信息
- **严重度**: 1
- **类别**: ohos, libc, runtime, testing
- **作者**: unknown

## 错误特征
```
signal received: Segmentation fault|Aborting due to a fatal error|redefinition of 'sockaddr_storage'|Bad UID\(s\)|chown \(null\)
```

## 根因分析
Three independently measured OHOS facts: (1) HarmonyOS has no passwd entry for application uids (e.g. 20001006), so getpwuid(3) legitimately returns NULL - any code that dereferences it without a check crashes; rmlint 2.10.3 lib/utilities.c rm_util_get_groupname() checks getgrgid's result but not getpwuid's (its sibling rm_util_get_username() does check). The crash fires in the "pretty" formatter INIT callback, i.e. before any scan output. (2) rmlint's SIGSEGV handler prints two lines and returns, relying on SA_RESETHAND to terminate; on the OHOS kernel the handler instead re-delivers endlessly, so one crash wrote ~2.9 GB of "Aborting due to a fatal error (signal received: Segmentation fault)" into redirected stderr within minutes. (3) With the crash fixed, the default type set still flags every scanned file as "Bad UID" (chown (null) ...) because the uid has no name, which starves the duplicate finder: a two-file duplicate fixture reports "0 duplicates" and exit 0. rmlint 2.x also exits 0 after a successful scan regardless of findings, so tests must assert report text, not exit codes.

## 推荐方案
**方法**: null-check-getpwuid-plus-deselect-badid-finder

**说明**: (a) Patch the dereference site: guard rm_util_get_groupname() with if(!user) return NULL; mirroring rm_util_get_username() - a plain POSIX-correct NULL check, no platform macros (patch 0001 in archives/r/rmlint/2.10.3/patches, patch_type portability). (b) In consumer tests/CI invocation use -T df (duplicates only) or otherwise deselect the badid finder on OHOS, and document that default scans on this platform label every file "Bad UID" - it is a passwd-DB absence, not a build defect. (c) Assert scan findings via report text ("are duplicates in", twin paths), never via exit code: rmlint 2.x returns EXIT_SUCCESS for any successful scan. (d) For diagnostics without ptrace (gdb is blocked on-device): bisect with fprintf(stderr) probes across main -> rm_cmd_main -> rm_fmt_set_state -> handler callbacks and rebuild from a debug copy under ~/tmp.

**修复命令**:
```
diff -u lib/utilities.c.orig lib/utilities.c   # shows the minimal if(!user) return NULL; guard
```

**验证**:
```
./rmlint -T df <dir-with-2-identical-files>   # expect: "1 are duplicates in 1 groups", exit 0; default type set instead reports "Bad UID(s): chown (null)" per file
```
