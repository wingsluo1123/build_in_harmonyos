# E559: SCons projects on OHOS: bootstrap SCons into a build-folder private prefix and call python3 -m SCons with inline PYTHONPATH/PKG_CONFIG_PATH, because SCons is absent from the image and the ohpcd registry and aggregated conanbuild env does not carry either path

## 基本信息
- **严重度**: 1
- **类别**: ohos, build-system, python, conan, scons
- **作者**: unknown

## 错误特征
```
No module named SCons|Checking for glib.*not found|AttributeError.*buildenv_info|scons: \*\*\* .* Error
```

## 根因分析
Three stacked facts: (1) OHOS images and the ohpcd Conan registry ship no scons binary/module and Conan does not distribute SCons recipes, so tool_requires("scons/x") is impossible (same conclusion as archives/g/gpsd/3.26). The repo convention is to pip-install SCons into an isolated prefix inside the Conan build folder (self.build_folder/_scons_env) - never --target into user site-packages. (2) Environment(self).save_script("scons_env") writes a separate script that is NOT sourced into the aggregated conanbuild.sh, so PYTHONPATH only carried via save_script dies with "No module named SCons"; the python3 -m SCons invocation needs PYTHONPATH inline on the command line. (3) PkgConfigDeps writes glib-2.0.pc etc. into generators_folder but buildenv_info.append_path("PKG_CONFIG_PATH", ...) is a ConanFile attribute that must be set BEFORE VirtualBuildEnv(self).generate(); on this Conan/platform combination the aggregated conanbuild.sh still does not carry the path, so SConstruct pkg-config probes fail ("Checking for glib-2.0 >= 2.64 ... not found") unless PKG_CONFIG_PATH is also given inline. Additionally SConstruct environments whitelist only PATH/TERM/HOME/PKG_CONFIG_PATH for child processes, which makes PKG_CONFIG_PATH the only viable discovery channel (CFLAGS/LDFLAGS injection is silently ignored).

## 推荐方案
**方法**: sandbox-scons-prefix-plus-inline-env

**说明**: In generate(): (a) pip install --no-input --target=<build_folder>/_scons_env scons==<ver> (private prefix, no --user, no system pollution); (b) patch SCons.Platform.posix SHELL 'sh' -> '/system/bin/sh' with a no-op-if-absent replace (OHOS has no /bin/sh); (c) PkgConfigDeps(self).generate() then derive any missing component .pc files into generators_folder; (d) set self.buildenv_info.append_path("PKG_CONFIG_PATH", self.generators_folder) BEFORE VirtualBuildEnv(self).generate(); (e) in build() invoke PYTHONPATH=<prefix> PKG_CONFIG_PATH=<gens> python3 -m SCons -j1 CC=<profile conf c> AR=.. RANLIB=.. --without-<optional...> with cwd=source_folder. Compilers/AR must come from self.conf tools.build:compiler_executables (R33), never bare shell vars.

**修复命令**:
```
PYTHONPATH=<build_folder>/_scons_env PKG_CONFIG_PATH=<generators_folder> python3 -m SCons -j1 CC=<clang> --without-<opt>
```

**验证**:
```
conan create archives/<x>/<pkg>/<ver> -pr:h ci/conan/profiles/ohos-aarch64 -pr:b ci/conan/profiles/ohos-aarch64 --build=missing   # expect: SCons banner via python3 -m SCons, "Checking for glib-2.0 >= 2.64... yes", full compile
```
