# E564: perf_event_open 编译可用但运行期被拒（EACCES）：编译期头文件门控不足，须运行期探测并优雅降级

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, kernel, portability, syscall
- **作者**: kasumizawa-miyuu <241250031@smail.nju.edu.cn>
- **来源 PR**: 10346

## 错误特征
```
perf_event_open is unavailable|fail to get performance counters|perf_event_open.*(Permission denied|EACCES|EPERM)
```

## 根因分析
编译期 AC_CHECK_HEADERS 只反映 <linux/perf_event.h> 是否存在（OHOS sysroot 存在，故 HAVE_LINUX_PERF_EVENT_H=1 且 syscall(__NR_perf_event_open, ...) 可编译通过），但 OHOS 内核/安全域在运行期以 EACCES 拒绝 perf_event_open（HW 与 SW 事件实测均返回 -1 errno=13，perf_event_paranoid=-1 也不放行）；上游在 fd=-1 时仍 read(m_Fd, &counter, sizeof(unsigned long long)) 读取未初始化栈缓冲，并以 assert(-1 != m_Start && "fail to get performance counters") 兜底：NDEBUG 未定义时可能随机中止，Release 下静默产出伪计数/伪时长（实测 fib(10) 报 156.9 秒且各测量块数值完全一致）。

## 推荐方案
**方法**: runtime-capability-probe-with-graceful-degradation

**说明**: 运行期以 fd 有效位为准：fd<0 时跳过一切 read/ioctl，计数返回 0；计时按"fd 有效→read perf 计数器；否则 clock_gettime/gettimeofday"的运行期分支回退（原实现只有编译期 #if 门控）；首次失败向 stderr 报告一次原因。补丁不引入平台宏、保持通用。

**修复命令**:
```
patch -p1 -i patches/0001-lib-Support-Unix-Perf.inc.patch && patch -p1 -i patches/0002-lib-Support-Unix-Timer.inc.patch
```

**验证**:
```
设备侧最小复现：clang 编译 syscall(241, &attr, 0, -1, -1, 0) 探针，期望 fd=-1 errno=13（HW/SW 均为 EACCES）；再运行框架 PERFORM() 示例：修复前 [ TIME (ns)] 为常数级伪值、[RESULT NUM] 0，修复后为真实递增时长、计数器诚实为 0、无断言中止。
```
