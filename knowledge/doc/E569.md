# E569: Samba waf testonly on OHOS: shell integration + TAP binaries + tdbtorture through one entry point, and the env.disable_python guard required because --disable-python still runs python binding tests

## 基本信息
- **严重度**: 2
- **类别**: ohos, python, testing, waf
- **作者**: unknown

## 错误特征
```
Python test failed: PYTHONPATH=bin/python|python testsuite returned 1|ModuleNotFoundError.*tdb|ImportError.*tdb
```

## 根因分析
The wscript testonly task in Samba-family standalone packages is a fixed pipeline: shell integration scripts -> per-test TAP binaries -> tdbtorture stress -> RUN_PYTHON_TESTS. It does not consult --disable-python: SAMBA_CHECK_PYTHON still records python3 in env.python_interpreters even when python bindings are disabled, so make test runs python/tests/simple.py against a package that has no pytdb module, fails with ImportError and turns the whole upstream test run red. Per-test output is redirected to a single test-output file and only cat'ed on failure, so per-test accounting must be reconstructed from the "..." progress lines plus the wscript test list.

## 推荐方案
**方法**: guard-testonly-python-tests-and-count-from-wscript-list

**说明**: When building a C-only package with --disable-python, guard the testonly python step with env.disable_python and print an explicit skip line instead of running it (patch the wscript, do not touch upstream test cases). Account the pass rate from the authoritative source: count the "..." progress lines and reconcile them with the wscript tdb1_unit_tests list length (37 for tdb 1.4.15), count shell "success:" lines, and take the tdbtorture return code; report the python binding tests separately as "not enabled (optional binding)" rather than "passed" or "upstream has none".

**修复命令**:
```
make test 2>&1 | grep -c '^\.\.\.tdb1-'   # = 37; grep 'testsuite returned'; grep 'python testsuite skipped'
```

**验证**:
```
make test   # expect: "...tdb1-*" x len(wscript tdb1_unit_tests), "testsuite returned 0", "python testsuite skipped (--disable-python)"
```
