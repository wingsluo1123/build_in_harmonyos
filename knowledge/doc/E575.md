# E575: u-boot lib/efi_loader generates capsule_esl_file by invoking the external efitools command 'cert-to-efi-sig-list' - upstream CI installs efitools via apt; OHOS toolchain has neither the command nor OpenSSL development headers, so the rule dies with Error 127

## 基本信息
- **严重度**: 2
- **类别**: external-build-tool-vendor
- **作者**: unknown

## 错误特征
```
/bin/sh: cert-to-efi-sig-list: (inaccessible|not found)|capsule_esl_file.*Error 127|command not found.*efitools
```

## 根因分析
lib/efi_loader/Makefile gates on CONFIG_EFI_CAPSULE_AUTHENTICATE=y (enabled by sandbox_defconfig) and hardcodes `cmd_capsule_esl_gen = cert-to-efi-sig-list $(capsule_crt_full) $@`. Upstream assumes build hosts have efitools (installed via apt in .azure-pipelines); OHOS has no package manager story for it and the tool is a C program built against OpenSSL dev headers, which the OHOS SDK sysroot/HNP toolchain do not provide (same OpenSSL absence documented in notes.md row 11). The rule fails with `/bin/sh: cert-to-efi-sig-list: inaccessible or not found` / make Error 127, killing the whole sandbox build even though the operation itself is trivial data wrapping: read PEM cert (PEM_read_bio_X509), serialize to DER (i2d_X509), wrap in EFI_SIGNATURE_LIST {SignatureType=EFI_CERT_X509_GUID, SignatureListSize, SignatureHeaderSize=0, SignatureSize=PkCertLen-sizeof(EFI_SIGNATURE_LIST)} + EFI_SIGNATURE_DATA {SignatureOwner=all-zero GUID (u-boot passes no -g), SignatureData=DER bytes}. No signing, no crypto - pure bytes.

## 推荐方案
**方法**: vendor-stdlib-python-port

**说明**: Ship a faithful Python port of the exact tool operation as scripts/cert-to-efi-sig-list.py (pure stdlib: base64-decode the PEM body = the same DER bytes i2d_X509 emits for a well-formed cert; wrap per the UEFI spec layout above) and change the rule to `cmd_capsule_esl_gen = python3 $(srctree)/scripts/cert-to-efi-sig-list.py $(capsule_crt_full) $@`. python3 exists on every side that matters: the OHOS device (conan itself runs on python3) and upstream CI. Feature, config, and test surface (test/lib/efi_loader capsule authenticate tests) are fully preserved. Local cross-check with openssl x509 -outform DER proved byte-identical output (787-byte DER for the sandbox test cert; 831-byte ESL with correct GUID/header/owner fields).

**修复命令**:
```
apply patch 0009 and rebuild; run the sandbox `ut efi` capsule tests to confirm the generated ESL parses
```

**验证**:
```
conan create uboot/2026.07 -pr:h=ohos-aarch64.profile -pr:b=ohos-aarch64.profile (OHOS device) and confirm capsule_esl_file rule succeeds; cross-validate the vendored port byte-for-byte against openssl: `openssl x509 -in <crt> -outform DER` must equal the port's embedded DER (i2d_X509 equivalence)
```
