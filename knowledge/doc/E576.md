# E576: 上游烘焙常量=行为语义锚：被静默收敛的测试面里藏着源码重构回归——以测试引入提交的意图判词定性（源码回归 vs 测试过期），约束"测试文件零修改"下恢复源码行为语义并全量回归其余烘焙常量

## 基本信息
- **严重度**: 2
- **类别**: baked-constants, expo, test-surface, upstream-regression, video-console
- **作者**: LIMInGZE666 <LIMInGZE666@noreply.gitcode.com>

## 错误特征
```
cedit.c:413 Expected 0x14a3 (5283), got 0x1496 (5270)|cedit_render_lineedit failure on SDL-enabled surface|bz2 destLen 5270 != baked 5283
```

## 根因分析
v2026.07 expo 文本行（scene_textline）打开态渲染的光标位置回归：scene_textline_render_deps 打开分支先 vidconsole_entry_restore(cons, &scn->entry_save)，把控制台状态回卷到 scene_textline_open 时刻的存档——彼时 set_cursor_pos 已把笔位钉在字段起点（x=250），vidconsole_set_cursor_visible 经 xcur 分支把光标画在字段起点（帧长 5270）；而测试烘焙帧（cedit_render_lineedit 的 bz2 压缩长度 5283，像素级=光标在既存文本 my-machine 末尾）对应的语义是"光标在文本末尾"——test/boot/cedit.c 的引入提交 c43791c4 提交信息明言 The cursor should start at the end（常量在各发行标签间未变：即烘焙之后未 rebake，源码侧行为被后续 scene 重构改变）。该分歧长期不可见：该测试面 depends on VIDEO_SANDBOX_SDL，宿主无 SDL2 时被 Kconfig 按 depends 静默收敛（构建成功零告警；上游 CI 形态亦不执行该面）——源码回归藏在 CI 不跑的测试面里。修复=该处改调 vidconsole_entry_start（清位置历史、不回卷笔位），光标回归刚绘完文本的实时笔位（x=329=末尾），帧逐字节=5283。关键定位方法：帧压缩长度非单射，标量差无法反推像素几何——dump 原始帧（os_write_file 绕 u-boot 控制台写文件，避免 print 观测者效应污染被断言帧）逐像素比对 + 游标 x 环境变量扫描复现 5283 定值。

## 推荐方案
**方法**: source-side-semantics-restore

**说明**: 把 render_deps 打开渲染分支的 `vidconsole_entry_restore(cons, &scn->entry_save)` 改为 `vidconsole_entry_start(cons)`（一行）：清位置历史后 set_cursor_visible 的 index<pos_ptr 分支不成立、光标取 live xcur（刚绘完文本的笔位=末尾）。逐键编辑路径 scene_textline_send_key 的 restore/process/save 配对与 open 时写入的 entry_save 保持原样（其语义独立且正确，勿连带改）。上游测试文件零修改——"源码回归 vs 测试过期"的定性取测试引入提交的提交信息（意图判词），修复方向=恢复被文档化的行为语义而非重烘常量。

**修复命令**:
```
# scene_textline_render_deps() 打开分支：- ret = vidconsole_entry_restore(cons, &scn->entry_save); + ret = vidconsole_entry_start(cons);
```

**验证**:
```
真机（SDL 门控面在位）：`u-boot-sandbox -d test.dtb -c 'ut bootstd cedit_render_lineedit; exit'` → failures: 0，四帧 destLen 5336/5363/5283/5170 全中；回归：`-c 'ut bootstd cedit_render; exit'` → 12 帧逐字节不变、空场帧 4851 不变。
```
