# E578: u-boot net/dhcpv6.c initializes a const array from member access on another const-qualified global (IPV6_ALL_NODE_ETH_ADDR(dhcp_mcast_ip6) -> _ip6_addr.in6_u.u6_addr8[12..15]) - GCC accepts const globals as constant expressions (extension), clang strictly follows C99 6.6 and rejects: 'initializer element is not a compile-time constant'

## 基本信息
- **严重度**: 2
- **类别**: gcc-extension-dependence
- **作者**: unknown

## 错误特征
```
initializer element is not a compile-time constant|expanded from macro.*u6_addr8\[1[2-5]\]|IPV6_ALL_NODE_ETH_ADDR
```

## 根因分析
include/net6.h:97 defines IPV6_ALL_NODE_ETH_ADDR(_ip6_addr) = {0x33, 0x33, _ip6_addr.in6_u.u6_addr8[12..15]} - the macro indexes array members OF ITS ARGUMENT. net/dhcpv6.c:35 passes a declared const-qualified global: `const u8 net_dhcp6_mcast_ethaddr[6] = IPV6_ALL_NODE_ETH_ADDR(dhcp_mcast_ip6);`. In standard C (C99 6.6), an lvalue of a non-literal object is not a constant expression even if const-qualified; GCC accepts const file-scope objects with constant initializers in constant-expression positions as a long-standing extension (same family as static-const array sizes), so upstream CI (gcc-hosted sandbox builds) never sees it. clang implements the standard strictly and rejects with 'initializer element is not a compile-time constant' (verified on OHOS device clang 15.0.4, build.log line 1492; minimal repro t8.c: lvalue form errors, compound-literal form passes).

## 推荐方案
**方法**: compound-literal-instead-of-lvalue

**说明**: Rewrite the initializer to feed the macro the original braced initializer as a C99 compound literal: `IPV6_ALL_NODE_ETH_ADDR((struct in6_addr)DHCP6_MULTICAST_ADDR)`. File-scope compound literals have static storage duration (C99 6.5.2.5p5), and member access with a constant index on a static-duration object is a valid constant expression - clang and gcc both accept it. The byte values are identical because DHCP6_MULTICAST_ADDR is the very initializer of dhcp_mcast_ip6; the const global itself stays untouched for its value users (dhcpv6.c:207/257).

**修复命令**:
```
apply the patch and rebuild: conan create uboot/2026.07 -pr:h=ohos-aarch64.profile -pr:b=ohos-aarch64.profile
```

**验证**:
```
minimal repro with device clang: `clang -fsyntax-only t8.c` where t8.c contains both the lvalue form (must error) and the compound-literal form (must pass); full build via conan create uboot/2026.07 -pr:h=ohos-aarch64.profile
```
