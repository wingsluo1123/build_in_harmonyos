# E580: OHOS musl <bits/alltypes.h> hardcodes 'typedef unsigned wchar_t' (32-bit on aarch64) while clang under -fshort-wchar typedefs __WCHAR_TYPE__ as unsigned short - any TU that mixes system headers with -fshort-wchar fails with wchar_t typedef redefinition

## 基本信息
- **严重度**: 2
- **类别**: musl, clang-incompat
- **作者**: unknown

## 错误特征
```
typedef redefinition with different types \('unsigned int' vs 'unsigned short'\)|bits/alltypes.h|__WCHAR_TYPE__|__DEFINED_wchar_t|__NEED_wchar_t
```

## 根因分析
Two independent wchar_t definitions collide. (1) musl sysroot usr/include/aarch64-linux-ohos/bits/alltypes.h line 15 declares `typedef unsigned wchar_t;` guarded by __NEED_wchar_t/__DEFINED_wchar_t - fixed 32-bit, hardcoded, no compiler introspection. (2) clang's resource-dir stddef.h line 74 declares `typedef __WCHAR_TYPE__ wchar_t;` guarded by __need_wchar_t/_WCHAR_T - and __WCHAR_TYPE__ is `unsigned short` under -fshort-wchar. When one TU includes both (any system header that pulls alltypes.h while the compile line carries -fshort-wchar), the guards differ so both typedefs fire: "typedef redefinition with different types ('unsigned int' vs 'unsigned short')". glibc never trips this because it derives wchar_t from __WCHAR_TYPE__ (no hardcode), so upstream Linux CI is blind to it. Canonical instance - u-boot 2026.07: top Makefile:546 adds -fshort-wchar to KBUILD_CFLAGS unconditionally (deliberate, for u-boot's own wide-string handling), and arch/sandbox/cpu/Makefile's CFLAGS_USE_SYSHDRS mechanism builds four host-style files (initjmp.c/os.c/eth-raw-os.c/sdl.c) with a special syshdrs_rule that drops -nostdinc and converts -I to -idirafter (libc headers win) but KEEPS -fshort-wchar. initjmp.c includes <stdlib.h> which lands in the musl sysroot, alltypes.h fires, resource-dir stddef.h fires - compile fails. Upstream already fixed this exact failure for sdl.o only (comment: "sdl.c also needs -fshort-wchar removed (musl)") via a per-target cmd override `$(CC) $(filter-out -nostdinc -fshort-wchar, $(patsubst -I%,-idirafter%,$(c_flags))) -fno-lto -c -o $@ $<`; the other three files were left with the generated rule.

## 推荐方案
**方法**: extend-upstream-per-target-filter-out

**说明**: Reuse the upstream precedent verbatim: extend the sdl.o-style per-target rule override to the remaining syshdrs files by removing -fshort-wchar (and keeping -nostdinc out) for those targets only. In u-boot's arch/sandbox/cpu/Makefile, after the existing cmd_cc_sdl.o override: `$(foreach f,initjmp.o os.o eth-raw-os.o, $(eval cmd_cc_$(f) = $(CC) $(filter-out -nostdinc -fshort-wchar, $(patsubst -I%,-idirafter%,$(c_flags))) -c -o $$@ $$<))`. The four files use zero wide-char APIs (grep-verified), so dropping the flag hands wchar_t to the C library with no ABI effect; glibc platforms behave identically because the flag only removes the 16-bit typedef that glibc never saw anyway. This is a flag-level fix - header shims are provably unreachable here (see forbid_1).

**修复命令**:
```
apply the Makefile override patch and rebuild: conan create uboot/2026.07 -pr:h=ohos-aarch64.profile -pr:b=ohos-aarch64.profile
```

**验证**:
```
conan create uboot/2026.07 -pr:h=ohos-aarch64.profile -pr:b=ohos-aarch64.profile (OHOS device) and confirm arch/sandbox/cpu/initjmp.o compiles; rebuild on glibc Linux to confirm no behavior change
```
