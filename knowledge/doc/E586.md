# E586: 平台补丁通道是文本通道：PR 差分（gitcode .diff 端点）对二进制文件只输出占位行，含二进制资产的 MR 必触发 git apply 失败

## 基本信息
- **严重度**: 3
- **类别**: platform, packaging, binary-assets, patch-channel
- **作者**: LIMInGZE666 <LIMInGZE666@noreply.gitcode.com>

## 错误特征
```
missing binary patch data|Binary files .* and /dev/null differ|patch does not apply|源码下载超时|类别: 网络问题
```

## 根因分析
平台构建取 PR 内容时下载 https://gitcode.com/<org>/<repo>/pull/<n>.diff 并以 git apply（回退 --3way / patch -p1）应用到基准树；gitcode 的 .diff 端点对二进制文件只输出 "Binary files ... differ" 占位行、不携带 GIT binary patch 数据段（对照：同 PR 的 .patch 端点含完整二进制载荷且可直接 apply），git apply 对「补丁未携带载荷的二进制文件」必然硬错误（error: missing binary patch data for '<path>'），--3way/patch 回退同样无法还原字节 → 确定性 checkout 失败；机器人分类器把该失败误诊为「类别: 网络问题 / 源码下载超时」，掩盖真因。

## 推荐方案
**方法**: binary-assets-as-text-blobs

**说明**: 把二进制资产改为 base64 文本随包：生成 blobs 脚本（每件 sha256 钉死），构建脚本 seed 段解码入工作目录并复验（不符即非零退出硬失败），二进制原文件从仓库移除（diff 中不再出现二进制 hunk）；消费点路径保持不变。

**修复命令**:
```
# 生成：base64 内联 + sha256 钉死 -> fixture-blobs.py; # 构建：python3 $H/fixture-blobs.py $F || exit 1
```

**验证**:
```
本地 round-trip：python3 fixture-blobs.py <dest> 解码产物 sha256 与原始文件全等（钉死值内置任何环境可复验）；端点对照：同一 PR 的 pull/<n>.diff 中 GIT binary patch 计数 0 而 .patch 计数 19；全链：二进制文本化后真机 test_package 复跑全绿 + 设备侧物化 sha256 与本地全等。
```
