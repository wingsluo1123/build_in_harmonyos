# E592: kamailio 插件模块消费者测试：dlopen 契约核验 + core 符号桩层（_shm_root 对象镜像与重定位分类）

## 错误特征
```
undefined symbol: _shm_root|undefined symbol: fork_process|undefined symbol: _pkg_root|dlopen failed|invalid ELF|symbol lookup error|no member named 'id' in 'struct _spi_node'
```

## 根因分析
模块 .so 不编 core，消费侧需自备 core 符号桩层；三个实测陷阱——①符号分类按 st_info/STT 判定在 OHOS clang 产物上失效（函数被判 0 个），须改按重定位类型分类；②libc 前缀过滤误伤 core 符号（fork_process 被 fork 前缀命中），须设 CORE_PREFIX_EXCEPTIONS；③shm_malloc 是宏 #define shm_malloc(s) _shm_root.xmalloc(_shm_root.mem_block,(s))，只提供函数式桩仍会解 NULL 崩溃，须以对象形式按 core/mem/memapi.h 的 sr_shm_api_t 布局镜像 _shm_root/_pkg_root

## 推荐方案
**方法**: core-plugin-dlopen-consumer-test

**说明**: 三层范式：静态 ELF 契约检查（纯 Python 自解析：ELF 身份/DT_NEEDED 归类/RPATH 禁构建机路径/依赖闭包逐符号）→ dlopen+dlsym 端到端消费者（校 exports 描述符、表项计数按源码计数器校准、真实调用 mod_register 并观察 sr_kemi_modules_add 回调、真实算法行为用例）→ core 符号桩层（重定位类型分类 + NEVER_STUB + CORE_PREFIX_EXCEPTIONS + _shm_root/_pkg_root 对象镜像 + 计数观测出口）

**修复命令**:
```
cc -std=c11 test_ims_modules_e2e.c kamailio_core_stub.c -o e2e -I<source_folder> -Wl,--export-dynamic -ldl && LD_LIBRARY_PATH=<module_lib_dirs> ./e2e
```

**验证**:
```
<test_package 编译的 e2e 二进制>; echo rc=$?   # 断言全绿 + dlopen(RTLD_NOW) 无 undefined symbol
```
