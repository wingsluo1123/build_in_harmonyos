# E593: Declaring runenv_info for a variable a dependency already exports overrides the dependency's correct value for every consumer, and the path cannot be recomputed from the dependency in package_info(): when a consumer resolves the package from the cache, the dependency's package_folder is None and its includedirs are relative ("include"), so a path built from them resolves to "share/terminfo" relative to the consumer's cwd.

## 基本信息
- **严重度**: 1
- **类别**: conan, packaging, runenv, terminfo
- **作者**: unknown

## 错误特征
```
ncurses: cannot initialize terminal type|unknown terminal|unable to open terminfo database|TERMINFO=.*No such file or directory
```

## 根因分析
Conan's runenv_info is merged across the whole graph, and the last package to define a variable wins. tmatrix 1.4 defined TERMINFO/TERMINFO_DIRS as <own package_folder>/share/terminfo - a directory its build never creates, because the terminfo database ships inside ncurses/6.6, not in tmatrix. That shadowed ncurses' own correct runenv, so a consumer requiring only tmatrix/1.4 got a TERMINFO pointing at a non-existent path. The obvious "fix" of re-pointing at the ncurses package also fails: during a consumer-side graph resolution the dependency object exposes package_folder=None (verified: DBG2 nc=ncurses/6.6 pkg_folder=None) and includedirs=['include'], so os.path.join(package_folder, ...) raises TypeError and os.path.dirname(includedirs[0]) yields a relative, wrong root. The variable can therefore only be exported correctly by the package that owns the file, and consumers must require that package directly to inherit it.

## 推荐方案
**方法**: do-not-redeclare-dependency-owned-runenv

**说明**: Do not declare runenv_info for a variable a dependency already owns. Let the owning package export it, and have consumers (including test_package) require that package directly so the runenv is inherited. If this package must guarantee the variable for its own consumers, it has to package the file itself (e.g. copy the terminfo database into this package) rather than point at another package's folder.

**修复命令**:
```
grep -n runenv_info <recipe>/conanfile.py   # expect: no entry for a variable a dependency exports
```

**验证**:
```
mkdir -p /tmp/probe && cd /tmp/probe && conan install --requires=<pkg> -pr:h=ohos-aarch64-wsl -pr:b=ohos-aarch64-wsl && cat conanrunenv-*.sh   # expect: no dangling path
```
