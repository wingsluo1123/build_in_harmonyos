# E599: "force-re-sign freshly linked artifacts"

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, linking, go, cgo
- **作者**: unknown

## 错误特征
```
"exec of freshly linked Go/CGO binary fails with 'Operation not permitted' (EPERM, rc=126) even though readelf shows a .codesign section and .note.ohos.ident present; signing helper skipped the file because a substring check for '.codesign' matched the linker-emitted placeholder"
```

## 根因分析
"OHOS-target lld emits a PLACEHOLDER .codesign section (plus .note.ohos.ident) into every freshly linked ELF for the OHOS target. The placeholder carries the section-name bytes (so naive substring checks like reading the file and testing b'.codesign' in data report 'already signed') but is NOT a valid signature — the kernel loader / Seccomp policy rejects exec with EPERM. Recipes that guard their signing step with a has-signature early-exit therefore silently skip real signing for freshly linked artifacts. Static Go toolchain binaries (pure Go, linked without the OHOS lld target flags) come WITHOUT any .codesign section and do need the regular first-time signing path."
