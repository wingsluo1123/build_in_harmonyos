# E608: 单值兜底变量 $(LOCALBASE) 在多依赖模块上结构性失配，且 $(OS) 由 uname 推导致平台条件分支静默失效——kamailio 6.0.6 lost（libxml2 + curl）适配

## 基本信息
- **严重度**: 3
- **类别**: ohos, build-system, toolchain, linking, cross-compile
- **作者**: Yukinoshitaqwq

## 错误特征
```
neither gethostbyname2 or getipnodebyname present|cannot find -lxml2|cannot find -lcurl|undefined reference to .sctp_sendmsg|No rule to make target .cfg-defs.
```

## 根因分析
【现象】多依赖模块（同一模块需两个以上外部库）沿既有先例手法适配时，总有一侧 -lX 找不到；同时 OS=harmonyos 不落在构建系统任何 OS 分支，平台相关判决全部静默失效（配置期不报错，只在编译/链接/运行期以无关报错形式出现）。【机制一：单值兜底 vs N 个依赖】kamailio 模块 Makefile 的第三方库探测（pkg-config 类与 *-config 脚本类）整体包在 ifeq ($(CROSS_COMPILE),) 内——交叉编译时上游自己就跳过宿主探测，两类依赖都直接落到各自 else 分支，而这两个 else 分支共用同一个 $(LOCALBASE)（src/modules/lost/Makefile：libxml2 段 -I$(LOCALBASE)/include/libxml2 -L$(LOCALBASE)/lib -lxml2；curl 段 -L$(LOCALBASE)/lib -lcurl）。$(LOCALBASE) 在 src/Makefile.defs 是按 OS 赋值的单值标量（:483/490/497/504/511/518/527/529/533，最终 ?= /usr/local），只能指向一个前缀；而 Conan 2 给每个依赖一个独立包目录，libxml2 与 curl 不共享前缀，于是「两个 -lX 共用一个前缀」在结构上不可满足。单依赖模块（kamailio-tls 只有 openssl、kamailio-slack 只有 curl、kamailio-snmpstats 只有 net-snmp）恰好吃得下该手法，故先例手法无法迁移到 lost。【机制二：$(OS) 来自构建机 uname】src/Makefile.defs:125 用 OS := $(shell uname -s | sed ... | tr "[A-Z]" "[a-z]") 推导平台；kamailio 6.0.6 源码树内 harmonyos/ohos 出现 0 次，20 处 ifeq ($(OS), ...) 列举的只有 linux/gnu_kfreebsd/freebsd/openbsd/netbsd/dragonfly/solaris/darwin，设备 uname -s 返回 HarmonyOS，于是 OS=harmonyos，全部 OS 判决为假：平台能力宏整体缺失（Makefile.defs:1844-1849 的 linux 分支不给，core/resolve.h:290 直接 #error 硬失败）、模块级条件链接标志被静默丢弃（sctp/Makefile 的 -lsctp 只在链接期才暴露）、安装目录（doc_dir/man_dir/data_dir）也与 linux 分叉。【为什么两者同类】都属静默退化：配置期不报错，错误在两三跳之后以无关形式出现（缺头文件 / 缺宏 / 缺 -l），排查者极易误判为「依赖没装」。【关键补充：两阶段必须同值】make cfg 会把 OS/C_DEFS/LOCALBASE 烘进 src/config.mak，而模块 Makefile 经 src/Makefile.defs:41 include $(COREPATH)/config.mak 读取它，因此只在 make modules 命令行传 OS=linux 不生效（真机实测见正文受控实验 B2）。

## 推荐方案
**方法**: neutralize-shared-localbase-fallback-and-inject-per-dependency-search-paths-with-os-override

**说明**: ① 多依赖模块不沿用 $(LOCALBASE) 兜底：命令行显式置空两侧探测变量（XML2CFG= CURL_BUILDER=，与上游 CROSS_COMPILE 交叉编译语义一致，同时阻止宿主 xml2-config/pkg-config 在交叉编译期把宿主路径混入产物），再把 LOCALBASE 指向一个不存在的目录，使兜底分支产生的 -I/-L 全部落空，改由 CPATH / LIBRARY_PATH 按依赖逐个给出各自的 include/lib —— 每个 -lxml2 / -lcurl 只可能解析到自己那个依赖包（R33：显式注入，不依赖未定义 shell 变量）。② 平台条件失效用命令行变量一次覆盖：make cfg 与 make modules 都要传 OS=linux（命令行赋值优先于 Makefile 内 :=；两阶段必须同值，因为 make cfg 把 OS/C_DEFS 烘进 src/config.mak，模块侧经 Makefile.defs:41 读取）。不要按当前报错逐个复刻 -DHAVE_* 清单。

**修复命令**:
```
CPATH=<dep1>/include:<dep1>/include/libxml2:<dep2>/include LIBRARY_PATH=<dep1>/lib:<dep2>/lib make cfg include_modules=lost OS=linux LOCALBASE=<build>/no-single-localbase-retired XML2CFG= CURL_BUILDER= && make modules modules=modules/lost -j1 OS=linux LOCALBASE=<build>/no-single-localbase-retired XML2CFG= CURL_BUILDER=（同一 CPATH/LIBRARY_PATH 环境）
```

**验证**:
```
cd kamailio-6.0.6 && make cfg include_modules=websocket SSL_BUILDER= CRYPTO_BUILDER= LOCALBASE=<openssl pkg> && make modules modules=modules/websocket -j1 SSL_BUILDER= CRYPTO_BUILDER= LOCALBASE=<openssl pkg>（CPATH=<openssl>/include:<unistring>/include LIBRARY_PATH=<openssl>/lib:<unistring>/lib 环境）
```
