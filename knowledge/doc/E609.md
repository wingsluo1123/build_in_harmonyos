# E609: 官方 conan-verify G4 与 conan 2.29.1 的 conan list --format=json 形状漂移：KeyError 被吞 → L2/L4/L5 静默跳过但 verdict 仍 PASS（平台级假绿）

## 基本信息
- **严重度**: 2
- **类别**: ohos, conan, tooling, verification
- **作者**: unknown

## 错误特征
```
"无法找到程序包 ID|KeyError.*Local Cache|Local Cache.*KeyError"
```

## 根因分析
"Version skew between the runner's expected `conan list --format=json` document layout and conan 2.29.1's actual output: the runner assumes an extra software-name nesting level (['Local Cache']['<name>']['<full-ref>']) while 2.29.1 emits ['Local Cache']['<full-ref>'] flat. The parse failure is swallowed by `except (KeyError, IndexError, StopIteration)` and degrades silently (G4 keeps passed=True), so nothing in the report flags the skipped gates beyond the terse warning line."

## 推荐方案
**方法**: "Do not trust a conan-verify verdict at face value: check G4's detail lines for the '无法找到程序包 ID' warning and each of L2/L4/L5 for '跳过（无 cache 路径）'. To restore full execution, shim the JSON before the runner parses it (transpose ['Local Cache']['<full-ref>'] -> ['Local Cache']['<name>']['<full-ref>']) or patch the runner's parse to accept both layouts. The same shim also protects against multiple cached revisions: purge first (`conan remove <ref> -c`) so exactly one revision/package exists and G4's `list(...values())[0]` pick is unambiguous."
