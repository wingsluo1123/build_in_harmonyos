# E611: "PkgConfigDeps .pc 单一 -Iincludedir 对版本化多级 include 布局的 Cflags 补丁 + musl 无 locale 库的 g_test setlocale 断言中止豁免"

## 基本信息
- **严重度**: P1
- **类别**: ohos, meson, pkg-config, packaging, testing
- **作者**: unknown, Builder (ZCode subagent), Coordinator, SunShine_06
- **来源 PR**: 14412

## 错误特征
```
"fatal error: 'libsoup/soup\\.h' file not found|'setlocale \\(LC_ALL, \"[a-z_A-Z]+\\.UTF-?8\"\\)' should not be NULL|Cflags: -I\"\\$\\{includedir\\}\""
```

## 根因分析
"两个独立缺口：(1) conan PkgConfigDeps 生成的 .pc 只写 Cflags: -I\"${includedir}\"，但 GNOME 系库上游布局把头文件放在版本化多级子目录（include/libsoup-3.0/libsoup/soup.h，消费者 #include <libsoup/soup.h>），单 -I 解析不到子目录导致 fatal error file not found；(2) OHOS musl 无 locale 数据库，上游测试调 setlocale(LC_ALL, \"en_GB.UTF-8\") 等返回 NULL，g_test 断言 'setlocale should not be NULL' 直接中止测试进程（不是行为差异而是数据缺失，无法通过代码修补绕开）。"

## 推荐方案
**方法**: "(1) build() 前定位生成的 libsoup-3.0.pc，把 Cflags 替换为 -I\"${includedir}/libsoup-3.0\" -I\"${includedir}\" 双路径（幂等判断：不含子目录串才替换）；(2) locale 依赖测试项按环境限制豁免如实申报（断言原文+行号在案），其余上游测试二进制以 OHOS 原生 ELF 直跑（LD_LIBRARY_PATH 注入依赖 libdir，libshumate 先例）保证真跑覆盖率。"

**说明**: 三步走：(1) 从 tarball 内 NEWS/ChangeLog 取发布日期，用 GitHub HTML commits 页 until= 日期过滤（API 限流时可靠）取数据仓"发布日前最后提交" SHA；(2) raw.githubusercontent.com 逐文件下载该 SHA 的数据（git clone/tarball 整包在低速通道必断连），纯文本优先、仅 .gz 变体回退；(3) 完整性双校验防截断——voc 与 output 行数必须相等、gz 用 gzip -t，截断的期望文件会产生"尾部整段缺失"型 diff 假失败。验证结果：48/48 数据目标 + stemtest 全过，make check 整体 exit 0。统计口径：CI 内只能跑自包含目标（check_stemtest 进 conanfile build()），数据驱动目标在适配机对快照实测并如实标注"数据仓不入库、CI 不复现"。

**修复命令**:
```
conan create archives/s/snowball/2.2.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing -nr
```

**验证**:
```
cd <src> && STEMMING_DATA=<snapshot> make check && echo OK   # main HEAD 会 Error 1（28/48 假失败），发布日快照 exit 0
```
