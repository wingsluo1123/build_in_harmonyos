# E617: musl 无独立 librt:meson cc.find_library 需 required:false

## 基本信息
- **严重度**: 2
- **类别**: portability, musl, meson, find-library
- **作者**: 2301_80739235
- **来源 PR**: 13399

## 错误特征
```
"ERROR: C library 'rt' not found|C library 'm' not found|find_library.*not found"
```

## 根因分析
glibc 把实时函数放在独立 librt.so,而 musl 全部并入 libc.so,OHOS PC(musl)上不存在独立 librt/libm 链接单元;meson 的 cc.find_library() 默认 required:true,找不到直接中止 meson setup(与 dependency() 的软失败语义不同)。libevdev 库本体不引用 librt 专有符号(clock_gettime 仅测试代码使用,musl 与 glibc>=2.17 均由 libc 提供),查找失败是无害缺席。

## 推荐方案
**方法**: required-false-one-liner

**说明**: 上游补丁把 cc.find_library('m'/'rt') 改为 required:false(musl 缺席无害、glibc 行为不变);conandata.yml 声明补丁;配方 package_info.system_libs 保留 ["m","rt"]。

**修复命令**:
```
meson.build: dep_lm = cc.find_library('m', required: false); dep_rt = cc.find_library('rt', required: false)
```

**验证**:
```
补丁对干净 orig 树 git apply --check 通过;meson setup 应能通过依赖查找段;CI conan create 构建成功。
```
