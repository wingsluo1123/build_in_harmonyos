# E618: program_invocation_short_name 探测链需第三级 musl fallback

## 基本信息
- **严重度**: 2
- **类别**: musl, meson, config-h, glibc-extension
- **作者**: 2301_80739235
- **来源 PR**: 13400

## 错误特征
```
"use of undeclared identifier 'program_invocation_short_name'|program_invocation_short_name.*undeclared|program_invocation_short_name 未定义"
```

## 根因分析
program_invocation_short_name 是 glibc 扩展(errno.h 在 _GNU_SOURCE 下声明),BSD 标准对应物是 getprogname();上游 meson 探测链只有 glibc→getprogname 两级,musl(OHOS PC)两级皆不命中时 config.h 不定义该宏,使用点(tools 的 usage() 输出)编译报未声明标识符。

## 推荐方案
**方法**: meson-third-literal-fallback

**说明**: 在 meson 层给探测链加第三级字面量兜底(config_h.set('program_invocation_short_name', '"<pkgname>"')),一处收敛、不引入逐文件 extern;仅 usage() 输出使用时无功能损失。

**修复命令**:
```
meson.build: if not cc.has_header_symbol('errno.h', 'program_invocation_short_name', ...) \n  if cc.has_header_symbol('stdlib.h', 'getprogname') ... \n  else config_h.set('program_invocation_short_name', '"libinput"') endif endif
```

**验证**:
```
补丁对干净 orig 树 git apply --check;构建后 grep config.h 应含 program_invocation_short_name 定义;CI conan create 构建成功。
```
