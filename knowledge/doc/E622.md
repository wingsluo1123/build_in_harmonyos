# E622: "Add a fallback INSIDE the tool's filetype detection: when '

## 基本信息
- **严重度**: 2
- **类别**: platform, compat, shell
- **作者**: unknown

## 错误特征
```
"file: Unknown option 'mime' (see \"file --help\") / file -L -s -b --mime returns empty output (toybox 0.8.12 has no libmagic MIME support)"
```

## 根因分析
"OHOS ships the toybox implementation of file(1) (toybox 0.8.12: only -bhLs options, no --mime, no libmagic MIME database). Upstream tools that branch on 'file --mime' output (lesspipe filetype(), other shell preprocessors) silently lose all file-type detection: the command substitution returns empty, the parsed ftype is empty, and compressed/archive files are echoed as raw binary."

## 推荐方案
**方法**: "Add a fallback INSIDE the tool's filetype detection: when 'file --mime' returns empty, run the plain 'file -L -s -b' description and map it to the equivalent MIME type with a bash case statement (tar archive->application/x-tar, Zip archive->application/zip, gzip/bzip2/xz/zstd compressed->application/(x-)... ; ar archive->application/x-archive; 7-zip archive->application/x-7z-compressed; *text*->text/plain with charset=utf-8; directory->inode/directory; else application/octet-stream). For types toybox reports as plain 'data', probe magic bytes directly: 'Rar!' in the first 4 bytes -> application/x-rar. For Debian packages (ar archive containing a debian-binary member), read the first 32 bytes and match *debian-binary* -> application/vnd.debian.binary-package. Keep the GNU path untouched (the fallback only triggers when --mime fails), so the same script works on both GNU and OHOS systems."
