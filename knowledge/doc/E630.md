# E630: 含运行期 x86 JIT 的压缩库（zpaq/libzpaq）在 aarch64 上必须显式 -DNOJIT：缺陷只在解压（真正执行 JIT 代码）时显现，编译/压缩阶段全绿

## 基本信息
- **严重度**: 1
- **类别**: platform, ohos, portability, arch
- **作者**: unknown

## 错误特征
```
Illegal instruction.*core dumped|JIT supported only for x86-32 and x86-64|-DNOJIT|ZPAQL::assemble|Predictor::predict
```

## 根因分析
libzpaq.cpp 的 ZPAQL::assemble()（7.15 版本 3035-4585 行，整体被 #ifndef NOJIT 包裹）在运行期生成 x86-32 / x86-64 机器码并直接跳入执行；CPU 特性探测失败时才会走到 error("JIT supported only for x86-32 and x86-64")（3237/3837 行）。在 aarch64 OHOS 上该探测不报错，于是 Predictor::predict() 把 x86 指令当成本机代码执行，进程收到 SIGILL。上游 readme.txt 明确要求非 x86/x86-64 目标使用 -DNOJIT，但这不是编译期强制：不加该宏同样编译通过、同样能完成压缩（method 14 写归档不触发 JIT 路径），只有解压/校验时才崩溃——因此 CI 里"编译成功"不能作为可用性证据。

## 推荐方案
**方法**: build-with-nojit-plus-roundtrip-evidence-on-non-x86

**说明**: (1) 源码里检索 #ifndef NOJIT / JIT supported only for 之类守卫，命中即视为"运行期代码生成"信号；(2) 非 x86 目标一律显式加 -DNOJIT（上游 readme 指定的开关），并同步去掉 -march=native（交叉/非本机原生目标 clang 直接拒绝，且破坏包可移植性）；(3) 验收不能停在编译或 conan create——必须在 test_package 里做一次真实数据往返（add -> extract -> 字节级 cmp）并在 notes/manifest 里留下逐字输出，才能把这类"能编过但不可用"的包拦下；(4) OHOS 上另需 -static-libstdc++，否则运行期报 Error loading shared library libc++_shared.so（SDK 的 libc++_shared.so 是 INPUT(-lc++_shared) 链接器脚本，musl 加载器无法解析）。

**修复命令**:
```
make -j1 zpaq CXX=clang++ CPPFLAGS="-Dunix -DNOJIT" CXXFLAGS="-O3 -DNDEBUG" LDFLAGS="-static-libstdc++"
```

**验证**:
```
zpaq add t.zpaq <file> && zpaq extract t.zpaq <file> -to out && cmp <file> out && echo ROUNDTRIP_OK
```
