# E631: application 包的可用性不能靠 `--version` 断言：上游 CLI 不认 --version/--help 时（zpaq 7.15 一律打印用法并 exit 1），L2 冒烟门禁无效，须改用真实往返断言并如实记录该特例

## 基本信息
- **严重度**: 3
- **类别**: packaging, testing, ci-gate
- **作者**: unknown

## 错误特征
```
--version 和 --help 均失败|Unknown option ignored|Usage: .*-options|bin.*--version.*failed
```

## 根因分析
本仓 L2 冒烟门禁的判据是 `bin/<tool> --version`（失败再试 `--help`）退出码为 0，这默认"所有 CLI 都实现了 GNU 风格版本开关"。上游工具若不实现（zpaq 7.15 对任何未识别参数都打印横幅+用法并以 1 结束），门禁既不能证明可用、也不能证明不可用；把它当作失败又会误伤一个完全正常的包。另外 zpaq 的退出码并非"错误一律 0"：实测「不存在的归档」返回 2、「add 不存在的输入路径」返回 0，因此错误路径的断言既不能只看码、也不能不看码，必须"诊断文本 + 退出码"同时断言。

## 推荐方案
**方法**: assert-real-roundtrip-instead-of-version-flag

**说明**: (1) 先实测上游工具对 `--version` / `--help` / `-v` / 无参数 / 各错误路径的退出码与输出，不要把"应该有版本开关"当默认，也不要假设"错误一定返回非 0"；(2) 若不支持 `--version`，**不要**为了过门禁给上游打补丁伪造该开关（改变上游 CLI 语义、与适配目的无关，还会引入不必要的行为差异）；(3) 把可用性证据换成真实功能往返——test_package 里对安装出来的二进制做 add/extract/字节级 cmp（上游 `make check` 同口径），并补上版本横幅断言（`zpaq v7.15` 字样能证明二进制可执行且版本串正确）；(4) 错误路径用例同时断言诊断文本与退出码，脚本以 `set -euo pipefail` 开头并逐条显式捕获返回值（zpaq 存在"有诊断但返回 0"的路径，`set -e` 会让"期望失败"的调用直接中断脚本）；(5) 在 notes.md / manifest.yaml 的 validation 段如实写明"L2 的 --version 判据对本包不适用"及其原因，避免后续 reviewer 或审计把 CI 侧的 non-blocking 警告误读为适配缺陷。CI 侧 L2 本就是 `[warn] ... (non-blocking)`，不阻塞流水线。

**修复命令**:
```
bash test_package/test.sh <pkg>/bin/zpaq   # 解释器：$CONFIG_SHELL → 固定候选清单；勿用 shutil.which("bash")（会误取调用方自带的 bash，exit 126）
```

**验证**:
```
./bin/zpaq --version; echo "exit=$?"; ./bin/zpaq x no-such-archive.zpaq; echo "exit=$?"   # 期望 1 / 2，而不是版本号或 0
```
