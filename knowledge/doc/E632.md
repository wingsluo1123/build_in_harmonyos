# E632: 编译、链接、conan create 全绿却"CLI 本身不可用"：上游/镜像把 main() 换成硬编码调试驱动，或让打印路径跨压缩/解压两种模式误用状态——只能靠 CLI 冒烟（真实调用 + 退出码）发现

## 基本信息
- **严重度**: 2
- **类别**: portability, runtime, cli, smoke-test, upstream-defect
- **作者**: unknown

## 错误特征
```
Segmentation fault \(core dumped\).*-v|unused parameter 'argc'|ignores argv|PrintInfo|PrintRegExpr|labeldictlist|undefined symbol: errno|BadZipFile
```

## 根因分析
"构建成功"与"工具可用"是两件事，两类缺陷都完全逃过编译器：(a) 入口被打桩——xmill 镜像把 main() 换成了忽略 argc/argv、写死 HandleSingleFile(\"sprot1_2.xml\",0) 的调试驱动（同文件仍保留 PrintUsage()/HandleAllOptions() 的声明，是原入口存在的证据）。此时编译 100% 通过、也能产出可执行文件，但任何命令行用法都不生效；只有跑一次 `xmill <file>` 或 `xmill`（无参应打印 usage）才能发现。(b) 跨模式状态误用——压缩器侧打印函数 LabelDict::PrintLabel() 无条件调用解压侧字典 LookupLabel()，而压缩器里 labeldictlist 恒为 NULL（只在 Load() 里构建）→ xmill -v 直接 NULL 解引用 SIGSEGV。该函数被 PathDictNode::PrintInfo / VRegExpr / FSMEdge / PathTree 多处打印路径共用，非 verbose 时永不执行，故默认流程全绿。这两类的共同点是：编译期零诊断、默认路径不触发、只有把 CLI 当被测对象才暴露。

## 推荐方案
**方法**: cli-smoke-as-first-class-evidence

**说明**: (1) 适配流程必须包含"CLI 冒烟"这一独立证据面，而不是只提交 conan create 结果：无参 usage（含退出码）、真实文件参数是否生效、每个文档化开关各跑一次并记录 rc、每次运行都用 `echo $?` 判定而不是目测输出。(2) 镜像/release 快照的 main() 要单独核验：grep 入口函数里是否出现硬编码文件名、argc/argv 是否被忽略；若入口被打桩，按同文件里既有的 Usage/参数解析接口（如 PrintUsage()/HandleAllOptions()）还原，并在 notes/PR 里写明这是对上游入口的修复而不是新功能。(3) 诊断/打印路径也要跑：-v 类开关常触发非默认分支，是 NULL 解引用与越界读取的高发区；修法是让打印函数按当前模式选择正确的数据源（压缩模式用压缩字典），而不是无条件走另一套状态。(4) 显式登记"文档有、实现无"的开关（如 xmill -h：Usage 文本宣传但解析器无 'h' 分支 → 以 255 退出）；这类缺失功能不要顺手自造，登记为已知瑕疵即可。(5) 判定口径：编译成功、链接成功、test_package 通过都不构成"CLI 可用"的证据，唯一证据是逐条开关的真实调用与退出码。

**修复命令**:
```
for a in "" "-v" "-h" "-1" "-9" "-c" "-m 2"; do ./xmill $a sample.xml; echo "args=[$a] rc=$?"; done
```

**验证**:
```
./xmill ; echo $?              # 无参必须打印 usage 且非 0
```
