# E654: 上游只把 shebang 换成 python3 就叫"支持 python3"：tarfile 的 bytes 未解码 → 整条 --source/解析链路在 python3 下 TypeError（附字节级重写归档格式时的 bytearray 切片位移坑）

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, python, testing
- **作者**: unknown

## 错误特征
```
TypeError: cannot use a string pattern on a bytes-like object|cannot use a string pattern|extractfile\(.*\)\.read\(\)|\.readlines\(\)|xrange|NameError: name 'xrange' is not defined|#!/usr/bin/env python$
```

## 根因分析
tarfile.extractfile().read()/.readlines() 在 python3 返回 bytes，而消费方（正则 re.compile('(\S+):\s+(\d+) kB')、逐行 split 后与 str 字面量比较、bytes.replace('\0',' ')）全按 str 写；上游只改了 shebang，没有在数据入口解码，于是错误不在 import/编译期而在第一次真正解析数据时暴露，且表现为 TypeError 而非"未支持"。同一次移植还常漏掉 xrange() 这类 python2 内建。发行版（Debian/Gentoo/OpenEmbedded）的通行做法是 sed 换 shebang + 只给 --source 补一条补丁，其余路径照旧坏着。

## 推荐方案
**方法**: decode-at-the-single-io-boundary-then-py3-audit

**说明**: (1) 先 grep 出全部 I/O 边界：tarfile / zipfile / os.popen / subprocess / open(...,'rb')，凡是把 bytes 直接交给上层解析的地方，在边界处统一 decode（'utf-8','replace'），并让 _readlines() 从 _read() 派生，避免两个入口行为不一致；(2) py3 语义普查：xrange/map/has_key/iteritems/`<>`、print 语句、dict.keys() 索引、整除、sort(cmp)、except X, e —— 逐项改成 py3 写法；(3) shebang 显式写 python3；(4) 验收不要停在 --help：造一份能触发完整数据通路的输入（这里是按工具自有的归档格式合成一份采集归档），断言真实数值，否则 bytes 泄漏型缺陷会被 --help 全绿掩盖

**修复命令**:
```
grep -n "extractfile\|\.readlines()\|xrange\|iteritems\|has_key" <script> ; python3 -c "compile(open('<script>','rb').read(),'<script>','exec')"
```

**验证**:
```
python3 <script> --help ; python3 <script> -S <fixture.tar> -c 'pid pss' ; python3 -c "compile(open('<script>','rb').read(),'s','exec')"
```
