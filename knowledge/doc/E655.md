# E655: GitHub release tarball + CMake ExternalProject 组合包的 OHOS 交叉适配套路：submodule 空目录要按 .gitmodules 固定 commit 取源，CMake 4 策略闸靠抬版本+CMAKE_ARGS 透传，Ninja 遇 ExternalProject 全路径库须换 Make，OpenMP 分支不命中要配方补标志

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, build-system
- **作者**: unknown

## 错误特征
```
no known rule to make it|CMAKE_POLICY_VERSION_MINIMUM|cmake_minimum_required.*(3\.[01]|2\.8)|implicit declaration of function .(get_current_dir_name|canonicalize_file_name)|undefined reference to .(get_current_dir_name|canonicalize_file_name)|Could NOT find OpenMP|fatal error: .*\.h: No such file or directory.*deps
```

## 根因分析
(1) GitHub 的 /archive/<ref>.tar.gz 不含 submodule 内容，deps/ 下目录全空（mmmulti 还有嵌套 6 项、sdsl-lite 另引 external/libdivsufsort）——configure 期以缺头文件/空目录失败，必须先按 .gitmodules 的固定 commit 逐个取源（本包 13 个 submodule 仓库（conandata 逐条声明：11 个顶层 + mmmulti 的 mio + sdsl-lite 的 libdivsufsort））；(2) CMake 4 移除了 cmake_minimum_required(<3.5) 兼容层，上游 3.1 与子工程 2.8.11 都直接 configure 失败：父工程抬版本，子工程（ExternalProject 拉起的 sdsl-lite）无法直接改时必须把 CMAKE_POLICY_VERSION_MINIMUM=3.5 透传进其 CMAKE_ARGS；(3) 上游把子工程产物的『全路径库文件』写进 target_link_libraries，Ninja 生成器判定 no known rule to make it，换 Unix Makefiles 即通过（上游 CI 亦用 Make）；(4) 上游 OpenMP 仅按 Darwin/Linux 分支探测，OHOS 的 CMAKE_SYSTEM_NAME=HarmonyOS 两个分支都不命中，交叉编译须由配方显式补 -fopenmp 编译与链接标志（平台 libomp.so 在 sysroot/usr/lib/aarch64-linux-ohos/）；(5) glibc 专有 API（get_current_dir_name 等）在 musl 无对应实现，用 POSIX 等价（getcwd）替换即可，**不需要平台条件编译宏**——否则违反平台宏禁令。

## 推荐方案
**方法**: vendor-submodules-by-fixed-commit-plus-cmake-policy-passthrough

**说明**: (1) 取源阶段就把 .gitmodules 里每个 submodule（含嵌套、含子工程自带的 submodule）按固定 commit 下载进源码树，并把 commit 与 sha256 写进 conandata 的 sources.submodules，让 source() 端可复现（不要依赖构建期 git clone，CI 无网/无凭证）；(2) 生成器默认选 Unix Makefiles 而非 Ninja，直到确认所有链接输入都是可推导目标（ExternalProject 的全路径库是 Ninja 的天敌）；(3) 把父工程需要的策略变量/编译标志（CMAKE_POLICY_VERSION_MINIMUM、-fopenmp、-I/-L 依赖路径）一次性塞进 CMAKE_ARGS/CMAKE_C(XX)_FLAGS——ExternalProject 子构建会继承同名变量，避免改子工程文件；(4) 平台特性探测不中时用配方补标志而非改上游判据；(5) glibc 专有 API 一律用 POSIX 等价替换，禁止用 __OHOS__ 之类的平台宏做条件编译（R8）。

**修复命令**:
```
cmake -S . -B build -G "Unix Makefiles" -DEXTRA_FLAGS="-march=armv8-a" -DCMAKE_ARGS="-DCMAKE_POLICY_VERSION_MINIMUM=3.5;-DSDSL_BUILD_TESTS=OFF"
```

**验证**:
```
cmake -S . -B build -G "Unix Makefiles" && cmake --build build -j1 && ls -l build/seqwish
```
