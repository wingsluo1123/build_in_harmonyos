# E659: 上游 CTest 套件的测试数据要求 root 属主（上游显式安全校验），非特权构建沙箱无法满足：以 ctest -E 排除该套件，并在 MANIFEST.yml / notes.md 如实申报（不掩盖、不跳过整轮测试）

## 基本信息
- **严重度**: 2
- **类别**: limitation, hmdfs, build-system, cmake, testing
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
must be.*root|not owned by root|load_data.*fail|ctest.*Failed|Failed.*Required Regular Expression|chown.*not permitted
```

## 根因分析
上游某些测试套件在处理"配置文件/测试数据必须由 root 拥有"的安全语义时会显式校验属主（schroot 的 sbuild-chroot-config 在 load_data() 中拒绝非 root 属主——这是防止低权限用户劫持 chroot 配置的安全设计，不是 bug）。构建沙箱以普通用户运行，且本机 /tmp 只读、HMDFS/FUSE 挂载下 chmod/chown 被忽略（权限固定 660，chown 无效），因此该套件在结构上不可能通过。把它当失败会误判一个功能正常的包；整体跳过 make test 又会丢掉其余套件的验证价值。

## 推荐方案
**方法**: exclude-unrunnable-suite-with-explicit-declaration

**说明**: ①先实测确认原因归属于"环境不可满足"而非代码缺陷：读上游测试源码找到显式校验（如 load_data() 中的属主检查）、尝试 chown 并记录其无效（FUSE/HMDFS）；②不要为了跑过而删改上游测试源码或伪造属主——排除并申报；③在配方 build() 内以等价方式自调 ctest 并 -E 排除该套件（上游 test 目标常不接受额外参数，故自调），其余套件必须全部真跑；④在 test_package/MANIFEST.yml 的 upstream_tests 中列出实跑套件、在 upstream_tests_excluded 中写明排除项与原因，并在 notes.md 同步；⑤如上游提供跳过该套件的官方开关，优先用官方开关。

**修复命令**:
```
ctest --output-on-failure -E sbuild-chroot-config    # 工作目录 = 构建目录
```

**验证**:
```
id -u; ctest -N | grep sbuild-chroot-config; ctest --output-on-failure -E sbuild-chroot-config   # 期望：非 root 环境 7/7 passed
```
