# E661: conan CMakeToolchain 把 CMAKE_INSTALL_LIBEXECDIR 设为 bin，导致上游 helper 程序与 bin/ 内同名可执行文件安装冲突：用上游 CACHE 变量覆盖回 libexec/<pkg> 布局

## 基本信息
- **严重度**: 2
- **类别**: limitation, build-system, cmake, packaging, install
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
destination.*is not a directory|file INSTALL cannot|CMAKE_INSTALL_LIBEXECDIR|libexec.*bin.*conflict|install.*overwrite.*same name
```

## 根因分析
conan 的 CMakeToolchain 为适配 conan 包布局，会设定一批 GNUInstallDirs 变量，其中 CMAKE_INSTALL_LIBEXECDIR=bin（工具链 `cmake_install_dir` 的既定行为）。上游若用 GNUInstallDirs 或把 helper 装到 ${CMAKE_INSTALL_LIBEXECDIR}，helper 程序（schroot 的 schroot-mount / schroot-listmounts）就会与 bin/ 下的主程序争用同一目录；当上游同时 install 该目录本身（DIRECTORY）与其中的文件时，会报 destination is not a directory / cannot install。上游把该路径实现为 CACHE 变量时，配方侧显式覆盖即可恢复 libexec/<pkg> 布局。

## 推荐方案
**方法**: override-upstream-cache-variable-for-libexec

**说明**: ①先查 CMakeCache.txt 中 CMAKE_INSTALL_LIBEXECDIR 的取值（conan 下通常是 bin）与上游实际使用的变量名（可能是自家的 SCHROOT_LIBEXEC_DIR 等 CACHE 变量）；②在 generate() 中用 tc.cache_variables 把上游变量指向 <package>/libexec/<pkg>（保留上游预期的布局），而不是去改 conan 工具链或上游 CMakeLists；③若上游只认 CMAKE_INSTALL_LIBEXECDIR，则覆盖该变量本身，并确认包内 helper 与主程序不再同目录；④验证要看包内实际布局（ls libexec）与安装日志无 destination 冲突。

**修复命令**:
```
tc.cache_variables["SCHROOT_LIBEXEC_DIR"] = os.path.join(self.package_folder, "libexec", "schroot")
```

**验证**:
```
grep -n "CMAKE_INSTALL_LIBEXECDIR" <build tree>/CMakeCache.txt; ls <package_folder>/libexec
```
