# E662: 安装期 RPATH 重链产物在 HarmonyOS 上 execve 返回 EPERM（表现为 Error 126）：让 CMAKE_INSTALL_RPATH 与构建期 RPATH 一致即可跳过重链，必要时用构建树产物覆盖安装副本

## 基本信息
- **严重度**: 3
- **类别**: limitation, ohos, build-system, cmake
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
EPERM|Operation not permitted|Error 126|cannot execute|exec format error|not executable
```

## 根因分析
cmake --install 为让产物可重定位，会在安装期用新的 RPATH 字符串重写 ELF 动态段：新串更长时需追加段并改动文件布局（重链）。构建树中的原产物可正常执行，而该重链产物在 HarmonyOS 文件安全策略下 execve 直接返回 EPERM（上层 conan test_package 呈现为 Error 126 / 无法执行）。判据是构建树产物与安装产物的 md5 不同——一旦不同就说明发生过重链。

## 推荐方案
**方法**: align-install-rpath-with-build-rpath

**说明**: ①构造阶段就让 CMAKE_BUILD_RPATH 与 CMAKE_INSTALL_RPATH 完全相同（包含所有依赖 libdir），安装期无新串可写、自然跳过重链——这是根治；②若上游/工具链仍触发重链，在 package() 中用构建树产物覆盖包内安装副本（shutil.copyfile），以构建树可执行版本为准；③不要用 patchelf/chrpath 事后改写 RPATH 来"修"，那同样会改写 ELF 且不解决根因；④排查时先用 md5sum 对比构建树与安装副本，确认是否真的发生重链，避免误判为缺依赖或权限问题。

**修复命令**:
```
cmake -DCMAKE_BUILD_RPATH="${RPATH}" -DCMAKE_INSTALL_RPATH="${RPATH}" ...   # 二者一致
```

**验证**:
```
md5sum <build-tree>/bin/<tool> <package>/bin/<tool>   # 两者不同 = 安装期重链，OHOS 上该副本可能 EPERM
```
