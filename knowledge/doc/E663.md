# E663: configure 期生成的公共头（如 sbuild-config.h）未被上游 install 规则安装，而已安装的公共头会 include 它——消费者必然编译失败；configure/CMake 生成的对外头须在 package() 中一并装入 include/

## 基本信息
- **严重度**: 3
- **类别**: detection, headers, build-system, cmake, packaging
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
fatal error: .*\.h: No such file or directory|sbuild-config\.h|generated configuration header not found
```

## 根因分析
上游用 configure_file()/AC_CONFIG_HEADERS 生成平台配置宏头，构建树内可见，且公共头（如 sbuild-i18n.h、sbuild-util.h）会 #include 它。但生成的头通常落在构建目录、不在源码树的 install 清单里，上游 install 规则只装 include/ 下的源文件——结果是包内公共头齐全、唯独缺生成头，任何消费者（含 test_package）编译即 fatal error。早期症状更隐晦：构建期自身的编译能过（构建目录里该头存在），只有独立消费者才暴露。

## 推荐方案
**方法**: install-generated-public-header-in-package

**说明**: ①在 package() 中把构建树里生成的公共头复制进 <package_folder>/include/<namespace>/（保持包内目录与上游 #include 路径一致）；②同时用 package_info().includedirs 暴露 include/（本包为 include），确保 CMakeDeps/PkgConfigDeps 能给出正确 -I；③验证不能只看"本包构建通过"，必须有一个独立消费者（test_package）只 include 公共头并编译，才能暴露缺头；④若上游 install 规则可通过变量（如 CONFIGURE_HEADER/HEADER_INSTALL_DIR）补齐，优先在配方里传该变量而非拷贝。

**修复命令**:
```
python: shutil.copyfile(os.path.join(build_tree, "build", "Release", "sbuild", "sbuild-config.h"), os.path.join(package_folder, "include", "sbuild", "sbuild-config.h"))
```

**验证**:
```
find <package_folder>/include -name '*config.h' -o -name 'SCHROOT_*'   # 为空即缺失；再用包内头做最小 include 编译验证
```
