# E664: conan 消费者图中被依赖包的「构建期专用」依赖二进制会被跳过（package_folder=None，头/库取不到）：配方侧转发声明不足以修复，消费者（含 test_package）须显式 require 这些依赖

## 基本信息
- **严重度**: 3
- **类别**: compat, detection, build-system, cmake, packaging
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
Skipped binaries|package_folder.*None|CMake Error.*could not find|missing and it cannot be built|__BOOL_NOT_FOUND|pf=None
```

## 根因分析
conan 2 解析消费者图时，会裁剪掉仅用于构建依赖的二进制包（日志 "Skipped binaries ..."、其 package_folder 为 None）。配方自身 build() 里这些依赖可用（构建图完整），但 test_package / 下游消费者拿到的是裁剪后的图：CPP 组件里的 includedirs/libdirs 指向的目录不存在，CMakeDeps 生成的 *-data.cmake 中 INCLUDE_DIRS/LIBS 为空（本包实证：schroot_INCLUDE_DIRS_RELEASE / schroot_LIBS_RELEASE 皆空、FIND_DEPENDENCY_NAMES 仅有 linux-pam/gettext），于是消费者编译即找不到头/库。诱因常是依赖同时出现在 build_requirements 与 requires、或依赖本身是 header-only/静态工具链组件。

## 推荐方案
**方法**: require-build-only-deps-explicitly-in-consumer

**说明**: ①先在消费者图里定位事实：用一个最小 conanfile（只要 requires 被测包）打印依赖包的 package_folder，确认哪些包 pf=None（Skipped binaries 行是最直接证据）；②在 test_package/conanfile.py 的 requirements() 中显式 require 这些被跳过的依赖（本包：boost、libuuid），使消费者图包含完整二进制；③若下游使用者也依赖这些头/库，则在配方 package_info() 中把关系上升为使用关系（requirements + transitive_headers/transitive_libs 的组合），或把需要暴露的头/库路径写进 cpp_info；④验证手段必须包含"独立消费者 + 真实链接"，仅本包 conan create 通过不代表消费者可用。

**修复命令**:
```
def requirements(self): self.requires("boost/1.84.0"); self.requires("libuuid/2.40.4")
```

**验证**:
```
conan create . ; grep -n "Skipped binaries" <log>   # 出现 Skipped binaries 且 test_package 报缺头/缺库即为本模式
```
