# E665: CMake 4 起不再提供 FindBoost 模块：上游用 ${Boost_INCLUDE_DIRS}/${Boost_<COMPONENT>_LIBRARY_RELEASE} 等旧式变量时，交叉编译须由配方给出 Boost 头/库目录与各组件库文件路径（BoostConfig 只提供 imported target）

## 基本信息
- **严重度**: 2
- **类别**: compat, limitation, portability, build-system, cmake
- **作者**: weijiapan <weijiapan@noreply.gitcode.com>

## 错误特征
```
Could NOT find Boost|Boost_INCLUDE_DIRS.*empty|Boost_.*_LIBRARY_RELEASE|no module named FindBoost|BoostConfig\.cmake not found
```

## 根因分析
CMake 4 移除了 FindBoost 模块，Boost 只能以 BoostConfig.cmake（CONFIG 模式）被找到；BoostConfig 只定义 imported target（Boost::filesystem 等），不设 Boost_INCLUDE_DIRS / Boost_LIBRARIES / Boost_<COMPONENT>_LIBRARY_RELEASE 这些旧式变量。上游 CMakeLists 若依赖旧式变量（尤其交叉编译时还关掉了系统路径搜索），configure 阶段就找不到头或组件库，报 Could NOT find Boost 或后续编译缺头。

## 推荐方案
**方法**: provide-boost-legacy-variables-from-recipe

**说明**: ①配方侧置 CMAKE_FIND_PACKAGE_PREFER_CONFIG=ON 与 BOOST_ROOT=<boost 包目录>，让 BoostConfig 生效；②把 Boost 头/库目录通过工具链 extra_cflags/extra_cxxflags/extra_linkflags（列表）注入，绕开上游找不到头的问题；③显式设置上游读取的旧式变量：Boost_INCLUDE_DIRS、Boost_LIBRARY_DIRS 及各 Boost_<COMPONENT>_LIBRARY_RELEASE / _DEBUG 指向包内 .a/.so 实体路径；④注意 boost ≥1.84 不再有独立 libboost_system（组件为 header-only），给 Boost_SYSTEM_LIBRARY_RELEASE 之类的赋值会导致链接期 -lboost_system 找不到库——须按组件实际产物（有 .a/.so 才赋值）判断；⑤验证要走到链接（只 configure 通过不够）。

**修复命令**:
```
tc.cache_variables["CMAKE_FIND_PACKAGE_PREFER_CONFIG"]="ON"; tc.cache_variables["BOOST_ROOT"]=boost_pkg; tc.cache_variables["Boost_<COMP>_LIBRARY_RELEASE"]=<boost pkg>/lib/libboost_<comp>.a
```

**验证**:
```
cmake -DCMAKE_FIND_PACKAGE_PREFER_CONFIG=ON -DBOOST_ROOT=<boost pkg> ... && grep -n "Boost_INCLUDE_DIRS" CMakeCache.txt
```
