# E681: When an upstream configure knob rewrites the public header and doubles a fundamental type, publish a sibling Conan package instead of an option - and make the variant's test_package assert something the base variant physically cannot produce

## 基本信息
- **严重度**: 3
- **类别**: conan, recipe-variant-design
- **作者**: unknown

## 错误特征
```
--with-scalar-type=complex|PETSC_USE_COMPLEX|PetscScalar.*_Complex|sizeof\(PetscScalar\) == 2 \* sizeof\(PetscReal\)|scalar-type is not a compile option|two consumers.*cannot coexist
```

## 根因分析
PETSc's --with-scalar-type={real,complex} is not a compile switch: it makes PetscScalar C99 double _Complex (2x PetscReal) and regenerates the installed petscconf.h with PETSC_USE_COMPLEX. Under the option approach only one binary per conan ref can exist, so a graph containing one consumer that needs a real PetscScalar and another that needs a complex one is unsatisfiable - the resolver would hand both the same object files. The second, quieter failure is test design: a variant package whose test_package only exercises API that both variants implement (VecCreate/VecNorm/MatMult) passes identically on the base variant, so CI green proves nothing about the variant and a mis-wired recipe that silently built real PETSc would ship.

## 推荐方案
**方法**: sibling-package-with-variant-distinguishing-test

**说明**: Publish the variant under its own name (petsc-complex/3.25.4) built from the identical tarball, and keep the scalar-type switch hardcoded in build()'s configure_args rather than exposed as an option. In package_info() repeat the ABI macro (cpp_info.defines = ["PETSC_USE_REAL_DOUBLE", "PETSC_USE_COMPLEX"]) so CMakeDeps/pkg-config output carries the variant identity even for -D-only consumers, and rename the CMake/pkg-config file names (cmake_file_name / cmake_target_name / pkg_config_name = petsc-complex) so a target accidentally built against the wrong variant fails at link time instead of at runtime. Then make test_package discriminating: (a) #ifndef PETSC_USE_COMPLEX / #ifndef PETSC_USE_REAL_DOUBLE #error guards so the base variant cannot even preprocess; (b) ABI assertions sizeof(PetscScalar) == 2*sizeof(PetscReal) and PETSC_VERSION_*; (c) value assertions whose expected numbers differ between variants - PetscAbsScalar(PetscCMPLX(3,4)) == 5 (real build: 3), VecNorm((2+1i)*[1,1,1]) == sqrt(15) (real build: 2*sqrt(3)), |VecDot(x, i*x)| == |x|^2 with a non-zero imaginary part; (d) an end-to-end Krylov solve where the RHS is computed by MatMult(A, x_true) rather than hand-written, asserting solution[0] == 1+1i and ||sol - x_true||_2 < 1e-10 so the imaginary part must survive the whole GMRES iteration. Print TAP-ish "ok N"/"not ok N" plus a final "assertions: N, failures: M" line for CI grep. Same rule for precision variants: a complex+single build needs a third package, never a new option on this one.

**修复命令**:
```
conan create archives/p/petsc-complex/3.25.4 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing -nr
```

**验证**:
```
conan create archives/p/petsc-complex/3.25.4 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing -nr
```
