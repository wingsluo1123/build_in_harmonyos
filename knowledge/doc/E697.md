# E697: OpenAL Soft 消费者用 ALC_SOFT_loopback 扩展时编译报未声明标识符/隐式函数声明：扩展枚举在 alext.h 无条件定义，但扩展函数原型被 #ifdef AL_ALEXT_PROTOTYPES 守卫

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, packaging, testing
- **作者**: unknown

## 错误特征
```
use of undeclared identifier 'ALC_FORMAT_CHANNELS_SOFT|undeclared function 'alcLoopbackOpenDeviceSOFT'|implicit-function-declaration.*alcRenderSamplesSOFT|ALC_MONO_SOFT|ALC_SHORT_SOFT
```

## 根因分析
OpenAL Soft 的 <AL/alc.h> 只声明核心 ALC API；ALC_SOFT_loopback 等 ALC 扩展的枚举宏（ALC_FORMAT_CHANNELS_SOFT/ALC_MONO_SOFT/ALC_SHORT_SOFT…）在 <AL/alext.h> 中无条件 #define，而扩展**函数**原型（alcLoopbackOpenDeviceSOFT/alcIsRenderFormatSupportedSOFT/alcRenderSamplesSOFT）整段包在 #ifdef AL_ALEXT_PROTOTYPES 内（1.24.1 alext.h L311-315 等 10 处）。只 include alext.h 不定义该宏时：枚举可用（第一轮只报 undeclared identifier 的枚举），但函数调用退化为 C99 隐式函数声明，返回 int 被赋给 ALCdevice* 再报 incompatible integer to pointer conversion——两类错误交替出现，极易误判成"头文件没装全"。

## 推荐方案
**方法**: define-AL_ALEXT_PROTOTYPES-plus-loopback-render-assertions

**说明**: (1) 在 include <AL/alext.h> 之前 #define AL_ALEXT_PROTOTYPES 1（枚举宏不需要，函数原型需要）；(2) 无音频设备的 OHOS 环境做真机级功能验证走 loopback：alcLoopbackOpenDeviceSOFT(NULL) + alcCreateContext(attrs: ALC_MONO_SOFT/ALC_SHORT_SOFT/8kHz) + alcRenderSamplesSOFT 实渲染；(3) 渲染断言用波形特征而非"非零"：0.5 FS 正弦渲染后 peak 应≈0.5×32767（1.24.1 实测 16383），过零次数≈2×频率×时长（正弦每周期升/降各过零一次，220Hz×0.12s≈52.8，实测 54）——按"非零"断言会把静音/坏输出放过；(4) null 后端设备用 setenv("ALSOFT_DRIVERS","null",1) 强制，alGetString(AL_VERSION) 返回 "1.1 ALSOFT <版本>"，可直接断言被测版本号。

**修复命令**:
```
conan create archives/o/openal/1.24.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
printf '#define AL_ALEXT_PROTOTYPES 1\n#include <AL/alext.h>\nint main(void){return alcLoopbackOpenDeviceSOFT(0)!=0;}' | clang -xc - -c -o /dev/null && echo ALEXT_OK
```
