# E719: 任务版本号含连续两点（1.0..1）时 R40/L0n 分支名门禁物理不可满足 —— git 与服务端双双拒绝该 ref，须按 CI 自身 +→- 归一化语义落到 1.0-1

## 基本信息
- **严重度**: 2
- **类别**: platform, branch-naming, ci-gate, metadata
- **作者**: unknown

## 错误特征
```
branch name mismatch \(R40\)|branch_name_r40|分支完全不包含.*包名-版本号|不是有效的分支名|is not a valid branch name
```

## 根因分析
CI 的 R40/L0n 门禁要求「分支名去掉最后一段 / 前缀后，必须逐字等于 <包名>-<版本号>」（ci/conan/build_and_test.sh L0n：EXPECTED_TAG="${pkg_name}-${pkg_ver}"，只做 + → - 归一化）。当平台任务的版本号本身含连续两点（实测 task #6607 mlddc version="1.0..1"，taskBranch="feat/mlddc-1.0..1"）时，期望分支名 mlddc-1.0..1 在 git ref 规范下非法（git check-ref-format 规定 ref 名不得含连续两点，对 refs/heads/feat/mlddc-1.0..1 返回 1），GitCode 建分支 API 同样以 400 拒绝（"Cannot start with - . refs/heads/ ... the end with . / .lock is not supported"）。于是门禁在物理上无法被任何合法分支满足：任何能 push 的分支名都不等于期望名。该缺陷来自任务数据集（同一批次里 mlddc 1.0.1 是独立任务 #6651，1.0..1 是另一条被写坏的版本号），按数据集字面照抄必然 CI 红。

## 推荐方案
**方法**: normalize-version-to-git-legal-and-document

**说明**: 三步处置：(1) 先证伪——git check-ref-format 与服务端建分支 API 各试一次，确认 taskBranch 物理不可 push（不要浪费 CI 轮次去猜）。(2) 取 CI 自身的归一化语义把版本落到 git 合法等价形式：build_and_test.sh 的 R40 注释明确写了「归一化：+ → -（Debian 风格版本后缀如 1.4+dfsg.1 → 1.4-dfsg.1）」，据此把 1.0..1 收敛为 1.0-1（版本目录 archives/<l>/<名>/1.0-1/、conanfile.version="1.0-1"、commands.json 的 versions 键同步），分支名 feat/mlddc-1.0-1 去前缀后精确等于 mlddc-1.0-1，L0n 通过。(3) 在 PR 正文首段写下版本号归一化的完整依据（任务版本、taskBranch、git/服务端双重拒绝的原始报错、所依据的 CI 归一化注释），避免评审误判为「版本号写错」。反例提醒：不要试图把版本目录直接改成同批次另一个任务的版本号（会撞 R37/L0j 版本占用并与他人的既有 PR 冲突）。

**修复命令**:
```
git check-ref-format "refs/heads/feat/mlddc-1.0..1" ; git mv archives/m/mlddc/1.0..1 archives/m/mlddc/1.0-1 && sed -i 's/1\.0\.\.1/1.0-1/g' archives/m/mlddc/1.0-1/*.py archives/m/mlddc/1.0-1/*.yml archives/m/mlddc/commands.json
```

**验证**:
```
git check-ref-format "refs/heads/feat/<包名>-<版本号>"; echo rc=$?   # 非 0 即该任务的 taskBranch 不可 push
```
