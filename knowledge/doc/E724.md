# E724: '手写 sh configure（非 autotools）在 OHOS 上的三个环境缺口全部由 configure.local 单点修复：CC 缺失致全部探测 compilation failed、HMDFS 无硬链接致 ln -f 失败、无 locale 命令致 HAVE_WCHAR=0 并让 utf8 测试成批失败'

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, configure, 'build-system, platform'
- **作者**: unknown
- **来源 PR**: pending

## 错误特征
```
'tested .*: no \(compilation failed\)|FATAL: no endian conversion functions found|FATAL: nanosleep: no|cc: inaccessible or not found|cannot create hard link|Operation not permitted|locale: inaccessible or not found|no UTF8_LOCALE|HAVE_WCHAR 0|utf8:diff|NUMBER OF FAILED TESTS'
```

## 根因分析
'mandoc/mdocml 的构建入口是手写的 sh configure（非 GNU Autoconf 产物，源树无 aclocal.m4/configure.ac/config.guess/config.sub），它通过 . ./configure.local 读取用户变量，再据此生成 config.h 与 Makefile.local。在 OHOS 设备与 CI worker 上三个默认值全部落空：(1) 上游默认 CC="cc"，而设备 PATH 只有 /data/service/hnp/bin/clang 没有 cc → configure 的每一个 runtest 探测都报 cc: inaccessible or not found → 全部 tested * no (compilation failed)，并以 FATAL no endian conversion functions found + FATAL nanosleep no 硬失败、不生成 Makefile.local；(2) install/别名路径用 $(LN) mandoc man，上游默认 LN="ln -f"，HMDFS 拒绝硬链接 → cannot create hard link Operation not permitted → make Error 1；(3) get_locale() 用 locale -a 挑 en_US.UTF-8，设备没有 locale 命令 → UTF8_LOCALE 为空 → 走 HAVE_WCHAR=0 分支 → -T utf8 渲染与 .out_utf8 期望不一致 → 上游 regress 19 个用例全部 utf8:diff 失败（1427 run / 19 failed）。三者都不是代码缺陷，是环境默认值落空，而 configure 的失败措辞（compilation failed / FATAL）极易被误读成源码不兼容而去改源码。'

## 推荐方案
**方法**: 'inject-everything-through-configure-local'

**说明**: '遇到手写 configure 的包，先 head -20 configure 确认它不是 generated by GNU Autoconf（源树无 configure.ac/config.guess/config.sub 即可判定），确认后不要 autoreconf、不要写 autotools 补丁，而是把所有环境差异一次性写进 configure.local（上游官方注入位，. ./configure.local 语义）：CC/AR 从 self.conf.get("tools.build:compiler_executables") 整取 dict 再索引（R33，绝不读 shell 环境变量——CI worker 上为空）；LN="cp -f" 替代硬链接；UTF8_LOCALE="en_US.UTF-8" 手工指定；STATIC=" "（官方 configure.local.example 置空写法）；CFLAGS/LDFLAGS 显式钉死并注入 conan 依赖的 include/lib。两个必须先实测的前置：① 该值是否真的可用——本例先跑 setlocale(LC_CTYPE,"en_US.UTF-8") 探针（返回非 NULL、wcwidth 空格返回 1、sizeof wchar_t 为 4）才敢手工指定，否则会把「locale 真不可用」误判成「探测脚本坏了」；② 含空格的值必须整体加双引号——. ./configure.local 是 shell 赋值语义，裸 LN=cp -f 会被解析成前缀赋值加执行 -f → configure 立即 rc=127（本任务实测踩过一次，错误信息只有一行 -f not found 极难反查）。验收不能只看编过了：要看 config.h 的目标宏翻转（HAVE_WCHAR 1）、Makefile.local 里各变量落地、以及上游测试从 N failed 变成 0 failed——本例 make regress 由 1427 run 19 failed 变成 1427 run 0 failed（约 89 秒）才是缺口修复的正面证据，比跳过 utf8 测试高一档。同理 make install 在本设备必失败（无 install 命令）→ package() 直接从源树收纳产物，不要试图补一个 install 命令。'

**修复命令**:
```
'sh ./configure 2>&1 | grep -E "FATAL|selected" ; grep -E "^(LN|CC|AR|CFLAGS|LDFLAGS|STATIC)[[:space:]]*=" Makefile.local ; grep HAVE_WCHAR config.h ; make -j1 && make regress 2>&1 | grep -E "tests run|NUMBER OF FAILED"'
```

**验证**:
```
'grep -c FATAL config.log ; grep -E "^(CFLAGS|LDFLAGS|LN|STATIC|CC|AR)[[:space:]]*=" Makefile.local ; grep -E "HAVE_WCHAR|UTF8_LOCALE" config.h ; grep -E "tests run|NUMBER OF FAILED" regress.log'
```
