# E727: 格式串里嵌 '\0' 会在 NUL 处截断，转换说明符根本不生效；把变量直接当格式串则是可被污染的格式串漏洞

## 基本信息
- **严重度**: 2
- **类别**: correctness, printf, security-hardening
- **作者**: lxx0329

## 错误特征
```
format string is not a string literal (potentially insecure) [-Wformat-security]|format string contains '\0' within the string body [-Wformat]
```

## 根因分析
两类老代码写法：(a) printf(变量) 直接把运行期字符串当格式串，clang 报 -Wformat-security，一旦字符串含 %n/%s 就会被内容格式化甚至写内存；(b) sprintf(p, "%d\0", n) 把 NUL 写进格式串字面量，C 标准规定格式串在首个 NUL 处结束，于是 %d 从未被求值，printf 打印的是垃圾。

## 推荐方案
**方法**: pass-format-as-argument-and-strip-embedded-nul

**说明**: printf(x) 一律改成 printf("%s", x)；格式串字面量里的嵌入 NUL 用 'x' 字符常量拼接而非 \0 终止；顺手把 sprintf(p, "\0") 这种空操作换成 *p = '\0'。改完重跑上游样本数据确认输出未变。

**修复命令**:
```
'grep -nE "printf\([a-zA-Z_]+\)|\\\\0\"" src/*.c | head -20'
```

**验证**:
```
clang -fsyntax-only *.c 2>&1 | grep -E 'Wformat-security|contains .\\0.'; 用样本输入跑一次输出并与参考比对
```
