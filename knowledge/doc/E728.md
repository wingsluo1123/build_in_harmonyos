# E728: 1990s C 代码漏 include <math.h> 时 sqrt/fabs 走隐式 int 声明，LP64 上 double 结果被截断

## 基本信息
- **严重度**: 1
- **类别**: portability, arch, numeric-correctness
- **作者**: lxx0329

## 错误特征
```
call to undeclared library function 'sqrt' with type 'double (double)'; ISO C99 and later do not support implicit function declarations|format specifies type 'long' but the argument has type 'int'
```

## 根因分析
老 C 源码（K&R/C89 风格）调用 sqrt()/fabs() 却没包含 <math.h>；C89 允许隐式声明且默认返回 int，clang 15 在 C99+ 模式下只发 -Wimplicit-function-declaration 告警并继续编译，于是 double 返回值被截断为 int 参与后续计算——编译全绿、数值静默错误。

## 推荐方案
**方法**: add-math-include-and-rebuild-with-upstream-reference-data

**说明**: 在 source() 阶段补 <math.h>（不是 build()，否则补丁可能打在导出树副本上）；同时把 -Wformat 的转换说明符按实参类型逐条改正；验收必须用上游自带的样本输入 + 作者发布的参考输出比对，而不是只看编译是否通过。

**修复命令**:
```
'grep -c "include <math.h>" src/*.c; clang -D__LINUX -fsyntax-only *.c 2>&1 | grep -c warning:'
```

**验证**:
```
clang -D__LINUX -O2 -fsyntax-only *.c | grep -E 'implicit-function-declaration|-Wformat'; 重新链接后用上游自带样本数据跑真实流程比对参考输出
```
