# E754: OHOS 无窗口系统下 GL 分发库 EGL 启用修订范式：libepoxy egl=no 使下游编译期无 HAVE_EGL、gsk GL 无法走 mesa EGL/GLES2 surfaceless；以 R37 版本后缀启用 egl=yes + mesa EGL 头注入（transitive_headers + egl.pc 复制修正 prefix）+ 进程级 EGL/GLES2 surfaceless 上下文验证收复

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, meson, egl
- **作者**: unknown
- **来源 PR**: (本任务 PR)

## 错误特征
```
GLX not supported|SIGTRAP|HAVE_EGL|epoxy_has_egl|eglGetProcAddress|eglGetPlatformDisplay|surfaceless|egl=no|No provider of .*EGL
```

## 根因分析
libepoxy 在 OHOS 上默认/既有发布（1.5.10.1）构建选项 egl=no，生成的 epoxy.pc 不声明 epoxy_has_egl=1，下游（gtk4 4.22.4）meson 编译期无法得到 HAVE_EGL 定义，gsk GL 走 GLX 路径（OHOS 无 GLX/libGL）运行失败（`GLX not supported` SIGTRAP）。mesa 24.3.4.1.1 客户端栈已能独立创建 EGL/GLES2 surfaceless 上下文，缺的只是 libepoxy 侧的 EGL 分发表与 pkg-config 声明。egl_generated_dispatch.c 编译期强制 include "EGL/eglplatform.h"（gen_dispatch.py），OHOS 无该头，需要依赖 mesa（transitive_headers）提供 EGL/GLES 头；mesa package_info 未设 pkg_config_name，PkgConfigDeps 只生成 mesa.pc，meson 的 dependency('egl') 需复制 mesa 包内 egl.pc/glesv1_cm.pc/glesv2.pc 并修正 prefix（glu 9.0.3 osmesa.pc 同款）。运行期 epoxy EGL 分发表用保守版本检查（无当前 display 时返回 14），EGL 1.5 平台入口（eglGetPlatformDisplay）必须在建立当前 display 后调用。

## 推荐方案
**方法**: egl-enable-revision-with-mesa-header-injection

**说明**: ① R37 版本后缀递增（1.5.10.1 → 1.5.10.1.1），禁止覆盖已发布版本；② generate() OHOS 分支 egl=no → egl=yes（glx/x11 保持），tests 在 conan create 内保持 false（上游 glx_static -static 链动态 libX11、glx_beginend 缺 libGL 会在 OHOS 链接失败，测试套件改由独立验证构建运行并计双口径台账）；③ requirements 增 mesa/24.3.4.1.1（transitive_headers=True）供 EGL 头；④ 复制 mesa 包内 egl.pc/glesv1_cm.pc/glesv2.pc 到生成目录并 replace prefix=/ 为 mesa package_folder；⑤ 进程级验证用 eglGetProcAddress 取 GLES2 函数（勿直调 epoxy GL 分发表——OHOS 无 libGL 时后者 dlopen libGL.so.1 abort）；EGL 1.5 平台入口先以 EGL 1.4 路径（eglGetDisplay+eglInitialize+eglMakeCurrent）建立当前 display 再调用。

**修复命令**:
```
conan create archives/l/libepoxy/1.5.10.1.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing -nr
```
