# E756: meson/autotools 包构建期需要 asn1Parser 等"既属依赖又属工具"的程序时，用 conan tool_requires 同包引用（libtasn1 制品仓包自带 bin/asn1Parser + lib/libtasn1.so）补齐构建机工具缺口，无需在 OHOS 上单独装工具

## 基本信息
- **严重度**: 2
- **类别**: build-system, meson, toolchain, conan, code-generation
- **作者**: unknown

## 错误特征
```
meson\.build.*find_program.*not found|Program or command 'asn1Parser' not found|asn1Parser.*not found.*meson\.build|ERROR: Program.*asn1Parser.*not found
```

## 根因分析
上游 tarball 只发布源码不发布生成产物（GitHub codeload tag tarball 是纯 git archive 产物，不跑上游 dist_generated.py 这类 dist 脚本），meson.build 用 find_program('asn1Parser') 在构建期从 contrib/spnego/spnego.asn1 生成 spnego_asn1.c。asn1Parser 是"既属依赖又属构建工具"的双角色程序（运行期链接 libtasn1.so、构建期做 ASN.1→C 代码生成），conan 生态把它当依赖管理但工具二进制只在包的 bin/ 里，构建机没装系统 libtasn1 工具时 PATH 上找不到，meson find_program 不会去 conan cache 里找

## 推荐方案
**方法**: tool-requires-same-dep-package-for-generator

**说明**: conanfile.py 同时声明 requires（运行期链接）与 tool_requires（构建期工具）同一个包：libtasn1/4.21.0 制品仓包自带 bin/asn1Parser + lib/libtasn1.so.6，conan 的 tool_requires 会把工具包 bin/ 注入构建环境 PATH、lib/ 注入 LD_LIBRARY_PATH（buildenv），meson find_program 直接命中。注意 asn1Parser 动态链接 libtasn1.so.6，脱离包环境裸跑会 Error loading shared library（exit 127），必须在 conan buildenv 里跑。meson 的 dependency('libtasn1') 走 pkg-config 查找，CI clean 环境还需 tool_requires pkgconf/3.0.5 补齐（ayatana-indicator-keyboard/burp2/captagent 合入先例同款）

**修复命令**:
```
def requirements(self): self.requires("libtasn1/4.21.0") ; def build_requirements(self): self.tool_requires("libtasn1/4.21.0"); self.tool_requires("pkgconf/3.0.5")（参考 archives/l/libdsm/0.4.3/conanfile.py）
```

**验证**:
```
1) 现象：本机/CI which asn1Parser → not found；meson configure 阶段报 Program or command 'asn1Parser' not found；2) 探针：conan download libtasn1/4.21.0 -r=ohpcd 后查包内 bin/asn1Parser 存在且 export LD_LIBRARY_PATH=<pkg>/lib 后 --version 正常（4.21.0）；3) 生成实验：asn1Parser -o spnego_asn1.c -n spnego_asn1_conf contrib/spnego/spnego.asn1 → 产物 ~2.2KB；4) 修复后 conan create RC=0 且 test_package 断言全过
```
