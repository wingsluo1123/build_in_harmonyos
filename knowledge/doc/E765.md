# E765: LCMAPS 插件 test_package 须 --whole-archive 静态链接引擎库 + -rdynamic 模拟 LCMAPS 引擎进程映像（框架 .so 不导出 lcmaps_log 等内部符号，链接 .so 版框架永远解析不了插件重定位）

## 基本信息
- **严重度**: 2
- **类别**: packaging, testing, upstream-semantics
- **作者**: unknown
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/14274

## 错误特征
```
Error relocating .*lcmaps_log: symbol not found|Error relocating .*: lcmaps_log|symbol not found.*dlopen
```

## 根因分析
lcmaps 插件引用 lcmaps_log 等框架内部符号，nm -D 证实这些符号不在 liblcmaps_without_gsi.so 的 dynsym（只定义于 .a）。LCMAPS 生产形态是评估引擎静态嵌入消费程序、经 -rdynamic 导出到主程序 dynsym，插件 dlopen 从主程序全局命名空间解析。所以测试程序即使 NEEDED 了框架 .so 也解析不了；且 .a 静态库按需拉取——程序不引用 lcmaps_log 时定义它的 TU 根本不进主程序，-rdynamic 无从导出，必须 --whole-archive。

## 推荐方案
**方法**: static-engine-whole-archive-rdynamic

**说明**: (1) test_package 的 CMakeLists 用 target_link_libraries(... -Wl,--whole-archive ${lcmaps_PACKAGE_FOLDER_RELEASE}/lib/liblcmaps_without_gsi.a -Wl,--no-whole-archive) 全量拉入引擎库；(2) target_link_options(... -rdynamic) 把引擎符号导出到主程序 dynsym（musl 的 dlopen 解析范围）；(3) ${lcmaps_PACKAGE_FOLDER_RELEASE} 是 CMakeDeps 注入的包根变量避免硬编码；(4) conanfile.py 需显式 self.requires("lcmaps/1.6.7")——CMakeDeps 只为直接 requires 生成 config（版本与主配方同步）；(5) test() 运行时 LD_LIBRARY_PATH 只需插件目录 <tested>/lib/lcmaps（引擎已静态进程序）；(6) 验证口令：修复后 test_package 应 RESULT: PASS 且 6 插件 dlopen+dlsym 全过、0 skip。

**修复命令**:
```
llvm-nm -D <pkg>/lib/liblcmaps_without_gsi.so | grep lcmaps_log; cmake --build <test_build_dir> && LD_LIBRARY_PATH=<pkg>/lib/lcmaps ./test_lcmaps_plugins_voms <pkg>
```

**验证**:
```
llvm-nm -D $LCPKG/lib/liblcmaps_without_gsi.so | grep -c lcmaps_log   # 0；llvm-nm $LCPKG/lib/liblcmaps_without_gsi.a | grep -w "T lcmaps_log"   # 有定义
```
