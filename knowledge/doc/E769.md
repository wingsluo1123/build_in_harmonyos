# E769: 上游测试程序打印原始二进制字节（如 inet_aton/inet_pton 打印地址字节）时，把测试输出直接回灌给 conan/工具链会触发 UnicodeDecodeError 导致 verifier 崩溃——批量跑上游测试必须把每个用例输出重定向到独立日志文件

## 基本信息
- **严重度**: 2
- **类别**: compat, conan, packaging, testing
- **作者**: unknown

## 错误特征
```
UnicodeDecodeError: 'utf-8' codec can't decode byte|_translate_newlines|data = data\.decode\(encoding, errors\)
```

## 根因分析
klibc 的 usr/klibc/tests 里 inet_aton / inet_pton 会把解析后的地址按原始字节写到 stdout（含 0xb1 等非 UTF-8 字节）。配方 build() 若用 self.run("timeout 20 <prog>") 让子进程输出回灌到 conan 输出流，工具侧（如 ohc 的 conan_verify._run，subprocess.run(capture_output=True, text=True)）会在解码捕获输出时抛 UnicodeDecodeError，堆栈落在 subprocess._translate_newlines，表象是「conan-verify G2 FAIL」而看不到任何构建错误——极易被误判为编译失败。

## 推荐方案
**方法**: redirect-each-upstream-test-output-to-own-logfile

**说明**: 在配方 build() 里对每个上游用例做 `timeout 20 "<prog>" <args> > "<outdir>/<name>.log" 2>&1`，异常退出码仍由 self.run 返回（用于统计 PASS/FAIL），但内容不再进入上层日志。这样做同时满足 R51 的「逐项用例名称 + 日志路径」留档要求：把 (name, status, log_path) 汇总写成 results.tsv。不要用 text=False 或先解码再转发（治标且丢证据）；也不要因为解码崩溃就把测试整体跳过（会丢失上游测试统计）。

**修复命令**:
```
timeout 20 "<tests>/<prog>" <args> > "<build>/upstream-tests/<prog>.log" 2>&1; echo $? >> "<build>/upstream-tests/results.tsv"
```
