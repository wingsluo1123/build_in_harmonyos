# E776: 纯 Python 包的 python 解释器级依赖（numpy 等）在 OHOS 上必须 conan require + 三段式解析：CI Worker 宿主 python3 无 pip 包（ModuleNotFoundError），制品仓 numpy 二进制需 PYTHONPATH + LD_LIBRARY_PATH=/system/lib64 注入，沙箱拒 dlopen（E212）时软跳过并以真机实测记录为准

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, python, conan
- **作者**: unknown

## 错误特征
```
ModuleNotFoundError: No module named 'numpy'|host python3 \(.*\) cannot import numpy|No module named 'numpy'.*requires numpy
```

## 根因分析
纯 Python 三方包（setuptools 后端、无 C/C++ 扩展、packages=["xxx"] 形态，如 igor2/badread/aiohappyeyeballs）在 OHOS 的消费形态是 python3 解释器 import，其上游运行时依赖（numpy 等）不是 ELF 链接依赖——conan 的 cpp_info/libs 链路完全不适用。devbox/真机上宿主 python3（~/usr/local/bin/python3）带 pip 装的 numpy，所以 badread 0.4.2 先例把 numpy 当"pip 级依赖、非 conan requires"能成立；但 CI Worker 的宿主 python3（/data/service/hnp/bin/python3）是极简环境，没有任何 pip 包——build() 里 subprocess 调宿主 python3 跑上游 pytest 时直接 ModuleNotFoundError（igor2 build #66321 实证，12.9s 快速失败）。另一侧，制品仓 numpy/2.5.2 的 .so 是交叉编译签名件（NEEDED libc++_shared.so，aarch64-linux-ohos ABI），宿主解释器默认路径加载不到，必须显式 LD_LIBRARY_PATH=/system/lib64（系统真 so 提供 __h 命名空间符号，SDK 侧 libc++.so 是链接器脚本会被加载器拒绝——profile 注释实证）。若配方把"宿主无 numpy"当硬失败（ConanException），CI 必红；若当静默跳过，则上游测试形同虚设。

## 推荐方案
**方法**: pypi-numpy-three-stage-resolution

**说明**: (1) requirements() 显式声明 self.requires("numpy/2.5.2")——依赖从制品仓来（audioflux 0.1.9 先例），不要学 badread 的 pip 级依赖（devbox-only）；(2) build()/test() 的 numpy 解析做三段式：先试宿主 python3 自带 numpy（真机快路径）→ 失败则把 conan numpy 依赖的 site-packages 加 PYTHONPATH、LD_LIBRARY_PATH 加 /system/lib64 再试（CI Worker 唯一可行路径）→ 仍失败（E212 沙箱拒 dlopen 用户路径 .so）则软跳过上游 pytest 并 output.warning 说明，全量结果以真机 conan create 实测记录进 test_package/MANIFEST.yml；(3) test_package 同款注入，E212 时走静态校验回退（包布局 + wrapper 可执行 + numpy .so 的 ELF/.codesign 校验，audioflux/pycairo/#2538 家族方案）；(4) 禁止把"宿主无 numpy"设计成硬失败——CI Worker 环境差异不是配方错误。

**修复命令**:
```
conan create archives/i/igor2/0.5.9 -pr:h=/storage/Users/currentUser/.conan2/profiles/ohos-aarch64 --build=missing
```

**验证**:
```
conan create . -pr:h=ohos-aarch64 --build=missing && grep -E "numpy runtime|upstream pytest" 创建日志
```
