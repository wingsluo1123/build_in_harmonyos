# E779: python 出身进程 execve HMDFS 用户区文件一律 EACCES（与 mode 无关、fork/spawn 无差别）：conan 构建 autotools 包必须用解释模式调 configure 并强制 MKDIR_P=mkdir -p；进程内 chmod 静默失效需用 /system/bin/chmod

## 基本信息
- **严重度**: 3
- **类别**: platform, build-system, filesystem
- **作者**: unknown
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/14274

## 错误特征
```
can't execute: Permission denied|bad interpreter: Permission denied|execve.*EACCES|configure.*Permission denied|install-sh.*Permission denied
```

## 根因分析
HMDFS 对用户区文件的 execve 授权按进程出身链判定：python 解释器出身的进程链（fork+execv 与 posix_spawn 行为一致）一律 EACCES，即使 mode 为 0o777；bash/sh 出身链放行，解释器模式（`sh file`）不受影响。conan 是 python 运行时，其 autotools.configure() 直接 exec configure、make 生成的 $(MKDIR_P)=install-sh 直接 exec，全部踩雷；同时 HMDFS 上进程内 os.chmod 可能静默失效（stat 不变、无异常），kernel attr 还有缓存延迟，导致"chmod +x 就能修"的直觉完全失效。

## 推荐方案
**方法**: interpreter-mode-invocation-plus-mkdir-p-override

**说明**: (1) configure 改解释模式：不用 autotools.configure()，改 self.run('sh "<abs>/configure" <args>')，args 取 autotools._configure_args（conanbuild.conf）保持与 toolchain 一致；(2) configure_args 追加 MKDIR_P=mkdir -p——AC_PROG_MKDIR_P 探测会把 MKDIR_P 设成 install-sh -c -d，make exec 它在 python 出身链被拒，系统 mkdir -p 在 HMDFS 可用；(3) automake 其余脚本（install_sh/LIBTOOL/config.status）自带 ${SHELL} 前缀无需处理；(4) 供脚本内 test -x 检查的执行位恢复兜底：读内容→删除+重建→chmod 0o777→/system/bin/chmod 777（进程内 os.chmod 在 conan 进程内静默失效）→短暂 sleep 等 attr 缓存过期；(5) CI 若非 HMDFS 缓存则无此限制，但上述绕法语义等价、保留无害。

**修复命令**:
```
sh "<abs_source>/configure" --enable-shared --disable-static --prefix=/ ...; make -j1 MKDIR_P 可省（configure_args 已覆盖）
```

**验证**:
```
python3 -c "import os; os.execv('<hmdfs>/configure', ['configure'])"   # 期望 EACCES；sh '<hmdfs>/configure' --version 则成功
```
