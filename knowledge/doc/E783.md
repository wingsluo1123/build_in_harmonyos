# E783: gperf 生成的查表函数签名使用 size_t，上游源码手工前置声明使用 unsigned int，64 位目标上 conflicting types 编译失败，应把前置声明改为 size_t

## 基本信息
- **严重度**: 2
- **类别**: portability, headers, compilation
- **作者**: unknown

## 错误特征
```
conflicting types for '.*from_language|conflicting types for '.*from_name|previous definition is here|register size_t len|register unsigned int len
```

## 根因分析
'gperf（≥3.x）生成的查表函数（-N 指定的 lookup 函数）以 size_t 作为 key 长度参数（如 ohcount_hash_parser_from_language(register const char *str, register size_t len)）。部分上游源码在 .c/.h 中手工前置声明同一函数原型，却写成 unsigned int len（32 位下 size_t 与 unsigned int 同宽，编译器不报错；aarch64 下 size_t=unsigned long，两类型冲突，clang 报 conflicting types 并指向 gperf 生成文件中的 previous definition）。上游新版可能已修正（ohcount 4.0.0 的 src/parser.c、src/languages.h 即为 size_t），旧 tag 需要相同补丁。'

## 推荐方案
**方法**: source-patch-forward-declaration-to-size_t

**说明**: 把源码侧手工前置声明的 key 长度参数由 unsigned int 改为 size_t，与 gperf 生成头一致：

**修复命令**:
```
perl -pi -e 's/register unsigned int len\);/register size_t len);/' src/parser.c src/languages.h   # 已实测：ohcount 3.1.1 两处修正后编译通过
```

**验证**:
```
'grep -nE "register (unsigned int|size_t) len" <生成头> <源码声明文件>; clang -c src/parser.c 观察 conflicting types; 修复后 conan create 通过'
```
