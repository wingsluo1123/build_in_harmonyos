# E784: conan 默认 out-of-source 构建会打爆不支持 VPATH 的老式手写 Makefile.in（make: No rule to make target 'Makefile.in'）：症状与配方问题无关，正解是 basic_layout(build_folder=".")

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, conan
- **作者**: unknown

## 错误特征
```
No rule to make target 'Makefile\.in'.*needed by 'Makefile'|No rule to make target.*Makefile\.in|make.*\*\*\*.*Stop
```

## 根因分析
Conan 2 的 tools.layout.basic_layout() 默认把 folders.build 设为 `build-<build_type>`（例如 build-release），Autotools helper 于是在该目录下执行 configure；autoconf 生成的 Makefile 会把「Makefile.in 相对本目录」当作前提写进规则。上游若只有手工维护、无 $(srcdir)/$(top_srcdir) 前缀的 Makefile.in（2000 年代老项目常见），构建目录里并不存在 Makefile.in，make 便以 `No rule to make target 'Makefile.in', needed by 'Makefile'` 立即失败。报错与源码/编译器无关，容易被误判成「源码包不完整」而反复重下源码。

## 推荐方案
**方法**: build-in-source-for-non-vpath-makefiles

**说明**: (1) 先判定 Makefile.in 是否 VPATH 友好：`grep -n 'srcdir\|top_srcdir\|VPATH' Makefile.in src/Makefile.in`；若前提全是不带 $(srcdir) 的相对路径，则该包不能 out-of-source。(2) 配方里改用 in-source 布局：`def layout(self): basic_layout(self, build_folder=".")`，然后照常 `autotools.configure()/make()`（configure 会用绝对路径执行，但生成的 Makefile 落在源码根，前提文件齐全）。(3) 不要用 `make -C <src>` 之类的绕过，package()/patch 阶段依赖的 source_folder 会与构建目录不一致；也不要为此改上游 Makefile.in（与适配目的无关）。(4) notes.md 记一条「该包不支持 out-of-source」以免后续 reviewer 建议改回 basic_layout 默认值。

**修复命令**:
```
python3 -c "import re,sys;print(bool(re.search(r'\\$\\(srcdir\\)|top_srcdir|VPATH', open(sys.argv[1]).read())))" Makefile.in
```

**验证**:
```
conan create <recipe> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing   # 失败日志出现 No rule to make target 'Makefile.in'
```
