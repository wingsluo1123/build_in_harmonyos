# E798: dimeOutput 仅在析构时 flush/关闭文件 — 同进程写完立刻读会读到 0 字节且 dimeInput::setFile 以 filesize>0 为成功条件而失败

## 基本信息
- **严重度**: 3
- **类别**: api-semantics
- **作者**: unknown

## 错误特征
```
FAIL: input file opened|dimeInput::setFile returned false|filesize == 0 after model\.write
```

## 根因分析
dimeOutput::setFilename 用 fopen(filename, "wb") 打开文件，数据写入 libc stdio 缓冲；dimeModel::write() 返回 true 只代表数据进了缓冲，flush 和 fclose 都发生在 ~dimeOutput()。而 dimeInput::setFile → setFilePointer 以 lseek(SEEK_END) 的 filesize > 0 作为成功条件。同进程"写完立刻读"时磁盘文件仍是 0 字节，setFile 返回 false，报错形似"打不开文件"，极易误判为平台文件系统问题。

## 推荐方案
**方法**: scope-block-before-readback

**说明**: 把 dimeOutput 的使用包进独立作用域块（或显式提前析构），确保写文件的代码块结束、析构完成后再用 dimeInput 打开同一文件。dimeOutput 没有公开的 close()/flush() 方法，作用域块是唯一干净写法。写读回环测试请同时断言 setFile 与 read 的返回值，失败信息里带上文件大小以便区分本坑与真实 IO 错误。

**修复命令**:
```
grep -n -A3 "dimeOutput out;" <consumer-test>.cpp
```

**验证**:
```
在 model.write(&out) 后、读取前 ls -l <file>   # 0 字节即中招
```
