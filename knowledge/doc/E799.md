# E799: 2009 时代 configure 把 -fuse-ld=<path> 当未知选项直接报错 — 链接器选择须经 tc.extra_cflags/extra_cxxflags/extra_ldflags 注入而非 configure 参数

## 基本信息
- **严重度**: 2
- **类别**: autotools, linking, cross-compile
- **作者**: unknown

## 错误特征
```
configure: error: unrecognized option: .*-fuse-ld=
```

## 根因分析
老版本 autoconf（dime 0.20111205 快照为 2009 年生成）的选项解析器对无法识别的非 `--` 前缀参数（如 `-fuse-ld=/path/ld.lld`）直接 `configure: error: unrecognized option` 退出，不像新版 configure（如 celt 0.11.3 所用）会静默透传给编译器探测。OHOS 交叉场景必须显式指定 ld.lld（OHOS 无裸 `ld`，且 clang 不会在 PATH 里找链接器），于是该参数无处安放。

## 推荐方案
**方法**: fuse-ld-via-toolchain-flag-lists

**说明**: 把 -fuse-ld=<ld.lld绝对路径> 追加到 AutotoolsToolchain 的 extra_cflags、extra_cxxflags、extra_ldflags 三个列表（不要放 configure_args）。configure 的 "compiler works"/AC_TRY_LINK 探测是编译+链接一步走，flag 经 CFLAGS/CXXFLAGS 照样到达链接器；最终库链接也经 LDFLAGS 生效。纯编译阶段多出的 -fuse-ld 只产生 harmless 的 unused-argument 警告。

**修复命令**:
```
grep -n "extra_cxxflags" <recipe>/conanfile.py
```

**验证**:
```
grep -n "timestamp=" <src>/cfg/config.guess   # 老于 2012 即高概率中招；先小参数试跑 configure
```
