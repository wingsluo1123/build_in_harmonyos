# E801: PR 分支 fork 点残留他人根目录文件时，diff 会带上「删除该文件」的补丁 —— CI shallow clone 上 apply 必然失败（does not exist in index）

## 基本信息
- **严重度**: 2
- **类别**: ci-mechanism, git-diff, shallow-clone
- **作者**: unknown

## 错误特征
```
does not exist in index|error: .*\.md$|checkout-pr|diff 无法应用|git apply --3way|PR 与 main 分支存在冲突
```

## 根因分析
CI 的 checkout-pr 步骤不是 checkout 分支，而是「clone 默认分支 → git reset --hard HEAD && git clean -fdx → curl <PR>.diff → git apply / git apply --3way / patch -p1」。PR diff 由 GitCode 以「分支 fork 点 (merge-base) → 分支 tip」计算。若 fork 点上有某个根目录临时文件（实测为他人 PR 误合并进 main 的 nanoflann 用 pr_body_final.md），而分支 tip 上该文件已被删除（例如分支上曾 add 后又 rm），diff 就会包含一条 `deleted file mode` 补丁；但 worker 的工作树是**当前 main tip**（该文件已不存在），于是 git apply 因找不到待删文件而失败，--3way 因 shallow clone 里没有该 blob 报 "does not exist in index"，patch -p1 亦失败 —— checkout-pr 阶段 exit 1。现象与配方内容零关系：L0/L1 全部不会执行，日志只显示 checkout-pr ❌。

## 推荐方案
**方法**: rebuild-branch-on-current-main

**说明**: 不要试图"重试 CI"（网络型的 checkout-pr 失败重试即可恢复，但本条是确定性的 apply 冲突，重试必然复现）。正确处置是**把分支重建到当前 main tip**，让 merge-base 前移、diff 只含本次新增文件：git checkout -B <branch> origin/main → 从旧 tip 只取本次要交付的文件（如 git checkout <old-tip> -- archives/<l>/<名>/）→ 重新 commit → 强制推送。重建后 diff 不再携带任何删除补丁，checkout-pr 随即通过（实测同一 PR：失败 build #43373/#43388 → 重建后 #43394 起进入 conan 阶段）。附带收益：重建同时消除与 main 的落后，避免后续 rebase 冲突。防复发：不要在仓库根目录放任何临时文件（CI G0e 根目录白名单只允许 .gitignore/.gitattributes/BUILD.gn/CONTRIBUTING.md/KNOW_YOUR_WHY.md/LICENSE/README.md/SKILL.md/SUMMARY.md/oh-package.json），PR 草稿写进 PR 描述或 archives/<l>/<名>/ 下。

**修复命令**:
```
git fetch --depth=1 origin main && git checkout -B <branch> origin/main && git checkout <old-tip> -- archives/<l>/<名>/ && git commit -m "chore: rebuild branch on current main" && git push -f origin <branch>
```

**验证**:
```
curl -sSL https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/<PR>.diff | grep -n 'deleted file mode' -B2 | head    # 看 diff 是否携带根目录文件的删除补丁
```
