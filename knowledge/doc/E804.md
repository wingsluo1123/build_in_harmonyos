# E804: 直编 autoconf 项目的两处隐蔽前提：config.h 被 HAVE_CONFIG_H 门控、能力宏必须与位置敏感功能表自洽（否则功能静默缺失）

## 基本信息
- **严重度**: 2
- **类别**: conan, autoconf, config-h, feature-table
- **作者**: unknown

## 错误特征
```
incompatible integer to pointer conversion assigning to 'char \*' from 'int'|use of undeclared identifier (O_RDONLY|LONG_MAX|INT_MAX)|undefined symbol: comp_[a-z0-9_]+|implicit declaration of function 'getpass'
```

## 根因分析
autoconf 项目绕过 configure 直编时，常以为"生成一份 config.h 就等价了"，但两处前提会让这个等价关系崩塌：(1) **包含被门控** —— 上游头文件普遍写成 `#ifdef HAVE_CONFIG_H / #include "config.h" / #endif`，不传 `-DHAVE_CONFIG_H` 时 config.h **永不被包含**，全部能力宏形同虚设；症状（标准 POSIX 符号 undeclared、隐式声明）与"config.h 内容写错"几乎无法区分。(2) **能力宏与位置敏感表错配** —— 不少项目把可选实现放在一张**固定长度、按下标注册**的函数指针表里，用 `#ifdef` 在"真实实现 / 失败占位"之间切换；此时"定义了哪个宏"必须与"链接了哪些 .o"严格自洽。错配有两种后果：定义了宏却没编对应 .c → 链接期 `undefined symbol`（易发现）；**没定义宏于是走占位分支、但本来能编的实现又没编** → 编译链接全过，运行时该算法静默不可用（难发现，比链接失败更危险）。(3) 附带坑：`AC_REPLACE_FUNCS(f1 f2 …)` 的语义是"libc 有就定义 HAVE_X，没有就编译随包同名 .c"。musl **不声明** `getpass`（glibc 的 `<unistd.h>` 会声明），若沿用"libc 有"的假设，源码就得到隐式 `int` 声明，报 `incompatible integer to pointer conversion assigning to 'char *' from 'int'` —— 看起来像"老代码不兼容 clang"，实为 musl 头文件差异。

## 推荐方案
**方法**: config-h-gated-and-feature-table-parity

**说明**: 三步清单：(1) **先 grep 门控**：`grep -rn 'HAVE_CONFIG_H' *.h` —— 有命中就必须在编译命令里加 `-DHAVE_CONFIG_H`（把它当**编译前提**写进配方注释，不要只写在 config.h 里）。(2) **再核对注册表自洽**：找出"按下标注册可选实现"的表（如 `algorithms[256]`），列出每个 `#ifdef X` 分支引用的实现符号，与配方实际编译的 `.o` 列表**逐项对齐**；**宁少勿多**——不确定时不要定义该宏（走失败占位是显式且安全的），一旦定义了就必须把对应 `.o` 编进去。(3) **处理 AC_REPLACE_FUNCS**：逐个 grep 上游 `configure.in` 的同名函数，到目标 libc 的头文件里确认声明是否存在；**musl 的差异**尤其注意 —— 头文件里没有声明就说明必须编随包实现，并保持对应 `HAVE_<FUNC>` **未定义**（上游头文件通常据此 include 自带声明）。参考实现：archives/d/dact/0.8.42/conanfile.py（CONFIG_H 常量 + CORE_OBJS/ALGO_OBJS 两个列表与宏一一对应）。

**修复命令**:
```
grep -rn 'HAVE_CONFIG_H' *.h ; grep -rn 'AC_REPLACE_FUNCS\|AC_CHECK_LIB.*main' configure.in ; grep -n 'algorithms\[\|_algo,' *.h | head
```

**验证**:
```
grep -rn 'HAVE_CONFIG_H' *.h | head ; grep -rn 'AC_REPLACE_FUNCS' configure.in configure.ac | head ; grep -n 'algorithms\[' *.h
```
