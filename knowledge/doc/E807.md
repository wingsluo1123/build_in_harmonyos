# E807: 消费者测试的"跑完即通过"弱判定会把二进制加载失败（126/127/255）与信号终止误判为通过 —— 必须显式排除并校验 WIFEXITED

## 基本信息
- **严重度**: 2
- **类别**: ohos, ci-gate, exec, test-quality
- **作者**: unknown

## 错误特征
```
exit 126|exit 127|Permission denied|not found|bad interpreter|Error while loading|误判为通过|false pass
```

## 根因分析
在 OHOS 上"程序跑不起来"主要表现为三类退出码：126（无执行权限 / exec 被拒，实测消费级 HarmonyOS PC 的 SELinux 域限制即返回 126）、127（找不到解释器或文件）、255（动态加载器失败）；此外被信号杀死时 WIFEXITED 为假、WEXITSTATUS 取值无意义。若消费者测试写成「system() 返回非 0 即算通过」或「只检查输出非空」，上述三类"根本没跑起来"的情形会被计入 PASS，于是 CI 的 L1 门禁（测试执行验证）表面全绿、实际未验证任何东西。反向也成立：被测工具本身可能**故意**非 0 退出（如 crashme 的崩溃注入、mlddc 的 usage 错误路径 exit 10），于是"断言退出码为 0"同样不可靠。

## 推荐方案
**方法**: explicit-exitcode-and-wifexited-guard

**说明**: 统一用 popen 直读 + 三态判定（同时避免落盘 /tmp——OHOS 的 /tmp 只读，写中间文件本身就会制造 E325/E223 类失败）：(1) 排除"跑不起来"——pclose 返回 -1、!WIFEXITED(rc)（被信号杀死）、WEXITSTATUS ∈ {126,127,255} 一律 FAIL 并把原始码写进断言详情；(2) 语义断言——再检查输出非空且含该工具**确定的**字符串（从源码里抄出真实字面，如 daa2iso 的 "Usage:"），不要泛泛断言"输出不为空"；(3) 工具本身预期非 0 时不要断言 0，而断言"未落在 126/127/255 且未被信号杀死"。参考实现：archives/c/crashme/2.8.5/test_package/test_crashme.c 的 safe_run()、archives/d/devio/1.2/test_package/test_devio.c、archives/d/devmem2/0.2/test_package/test_devmem2.c。对"故意崩溃"型工具（crashme），刻意不执行其崩溃路径，只做静态校验 + 辅助工具的安全调用。

**修复命令**:
```
# 判定模板（C 语言，无中间文件）\nint rc = pclose(fp);\nif (rc == -1 || !WIFEXITED(rc)) FAIL;\nint code = WEXITSTATUS(rc);\nif (code == 126 || code == 127 || code == 255) FAIL;   /* 跑不起来 */\nassert_output_contains(buf, "Usage");
```

**验证**:
```
在 test_package 里临时把被测路径替换为 `/nonexistent`：若测试仍 PASS，则该断言未排除 126/127/255
```
