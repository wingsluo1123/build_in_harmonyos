# E809: conan 2.x AutotoolsToolchain.generate() 无参调用静默丢弃 tc.environment() 的修改（env=None 时内部重建 Environment 实例）：必须 tc.generate(env=env)；同族陷阱——conanrunenv 只聚直接依赖 libdirs、CMakeDeps 只为直接 requires 生成 config

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, dependency-injection
- **作者**: unknown
- **来源 PR**: https://atomgit.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/14274

## 错误特征
```
no LCMAPS basic interface found|checking for .*_INTERFACE... no|PKG_CONFIG_PATH.*丢失|conanautotoolstoolchain.sh
```

## 根因分析
AutotoolsToolchain.generate(self, env=None, scope="build") 的实现是 env = env or self.environment()，而 environment() 每次调用都新建 Environment() 实例（CC/CFLAGS 等在其中逐项 define）。对 tc.environment() 返回实例的 unset()/prepend() 修改因此全部丢失，且无任何警告——PKG_CONFIG_PATH 注入（R49 依赖注入模式）静默失效，configure 探测依赖接口报 "no ... interface found"。

## 推荐方案
**方法**: pass-modified-env-to-generate

**说明**: (1) 显式传回同一实例：env = tc.environment(); env.prepend/unset(...); tc.generate(env=env)；(2) 同族陷阱 A——test_package 的 conanrunenv 只聚合直接 require 的 libdirs，传递依赖包的 lib 不在 LD_LIBRARY_PATH，test() 里手动构造 LD_LIBRARY_PATH='<fw>/lib:<tested>/lib/lcmods' 前缀调用；(3) 同族陷阱 B——CMakeDeps 只为直接 requires 生成包 config，test_package 要 find_package 传递依赖时需显式 self.requires("<dep>/<ver>")（版本与主配方同步维护）；(4) 改完检查生成物 conanautotoolstoolchain.sh 确认注入值已序列化。

**修复命令**:
```
python3 -c "import inspect, conan.tools.gnu.autotoolstoolchain as m; print(inspect.getsource(m.AutotoolsToolchain.generate))"   # 确认 env = env or self.environment()
```

**验证**:
```
grep PKG_CONFIG_PATH <build>/generators/conanautotoolstoolchain.sh   # 修复后应含自定义路径，修复前只有 generators folder 默认值
```
