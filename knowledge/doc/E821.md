# E821: conan global.conf 的 core.download:download_cache 不展开 $HOME — 必须写绝对路径，否则离线源码缓存静默失效并直连上游超时

## 基本信息
- **严重度**: 2
- **类别**: conan, env-offline-cache
- **作者**: unknown

## 错误特征
```
Error downloading file.*timed out|HTTPSConnectionPool.*Connection to .* timed out|Error in source\(\) method
```

## 根因分析
Conan (verified 2.29.1-OHOS) treats [global.conf] values as literal strings: core.download:download_cache=$HOME/tmp/xx-dl creates a cache rooted at a directory literally named "$HOME", which never matches the pre-seeded <sha256[:2]>/<sha256> file, so conan silently attempts a real download; on a device without upstream egress (github.com connect timeout) source() then fails after retries with "Error downloading file ... timed out".

## 推荐方案
**方法**: absolute-path-in-global-conf

**说明**: Write the download cache with an absolute path: core.download:download_cache=/storage/Users/currentUser/tmp/<pkg>-dl (never $HOME or ~). Pre-seed the tarball as <cache>/<sha256[:2]>/<sha256>, verify with sha256sum on device. Then conan source() falls back to the cache after the first (expected) download timeout. Symptom pair to watch: one "WARN: network: Error downloading" followed by "Sources correctly downloaded from ..." = cache hit working; two timeouts + "Error in source() method" = cache path wrong.

**修复命令**:
```
printf 'core.download:download_cache=/storage/Users/currentUser/tmp/csig-dl\n' > $CONAN_HOME/global.conf
```

**验证**:
```
grep download_cache $CONAN_HOME/global.conf  # must show an absolute path, then rerun conan create
```
