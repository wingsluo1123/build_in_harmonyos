# E832: Conan 工具链用普通 CMake 变量注入 C++ 标准，项目内 cache_variables 无法覆盖

## 基本信息
- **严重度**: 3
- **类别**: cmake, toolchain, conan, cxx-standard, libcxx
- **作者**: MTX2
- **来源 PR**: 13832

## 错误特征
```
'operator<=>' is a single token in C\+\+20|'operator<=' cannot be the name of a variable or data member|expected ';' at end of declaration list|no matching function for call to object of type 'std::not_equal_to<>'
```

## 根因分析
Conan 2 的 CMakeToolchain 由 CppStdBlock 依据 profile 的 compiler.cppstd 生成 `set(CMAKE_CXX_STANDARD <N>)`（普通变量，非 cache 变量），并以 variable_watch 监视。CMake 中普通变量优先级高于 cache 变量，因此 recipe 里 `tc.cache_variables["CMAKE_CXX_STANDARD"] = "20"` 不会生效，库仍按 profile 的 cppstd（如 17）编译。cli11 风格的三路比较 `auto operator<=>(...)` 在 C++17 下不再被识别为单个 token，clang 报 "'operator<=' cannot be the name of a variable or data member"（并伴随 "'operator<=>' is a single token in C++20" 警告）；libc++ 的 std::variant 比较还派生 no matching function for call to object of type 'std::not_equal_to<>'。

## 推荐方案
**方法**: 在 recipe 的 generate() 中修改 self.settings.compiler.cppstd，让工具链自身按新标准生成

**说明**: |

**修复命令**:
```
grep -m2 'C++ Standard' <conan-create.log> && grep -c "operator<=>" <src>/include/*.hpp
```

**验证**:
```
grep -m2 'C++ Standard' <conan-create.log>   # 期望出现 C++ Standard 20，而非 17
```
