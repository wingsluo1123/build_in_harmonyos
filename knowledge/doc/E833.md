# E833: OHOS 上 CMake 不实现 VERSION/SOVERSION：目标属性正确仍不产生 -soname 与版本化文件名

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, cmake, linking, packaging
- **作者**: MTX1
- **来源 PR**: 13832

## 错误特征
```
Missing DT_SONAME.*lib.*\.so|IMPORTED_NO_SONAME TRUE|Error relocating.*symbol not found
```

## 根因分析
OHOS 平台的 CMake（实测 4.1.2 + clang 15.0.4）不把 target 的 VERSION/SOVERSION 属性落实为链接器行为：即便 get_target_property 确认 TYPE=SHARED_LIBRARY 且 VERSION=SOVERSION 已正确设置，生成的链接行仍不含 -soname，产出文件名也不带版本号。后果有三：库无 DT_SONAME、install 只写出未版本化文件名、导出的 *Targets-release.cmake 把导入目标标为 IMPORTED_NO_SONAME TRUE（下游被迫按完整路径链接）。最小复现：cmake_minimum_required(3.11...3.13) + project(x VERSION 0.10.1) + add_library(x) + set_target_properties(x PROPERTIES VERSION/SOVERSION)，CMake 打印 TYPE=SHARED_LIBRARY VERSION=0.10.1 SOVERSION=0.10.1，`ls build/` 仍只有 libx.so、link.txt 无 soname。

## 推荐方案
**方法**: 显式把 soname 交给链接器，并让包内同时存在版本化与未版本化两个真实文件名（不依赖符号链接）

**说明**: |

**修复命令**:
```
llvm-readobj --dynamic-table p/lib/libx.so | grep SONAME；并确认 p/lib 下同时存在 libx.so 与 libx.so.<ver>
```

**验证**:
```
cmake --build <build> && llvm-readobj --dynamic-table <build>/libxxx.so | grep SONAME
```
