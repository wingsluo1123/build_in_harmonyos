# E835: 旧版 /proc/cpuinfo 式 FindSSE.cmake：非 Linux/Darwin/Windows 系统名（如 HarmonyOS）落入 ELSE 分支被置 SSE2_FOUND=true，aarch64 交叉编译注入 -msse2 失败

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, cross-compile, aarch64, simd
- **作者**: unknown
- **来源 PR**: feat/libvidstab-1.1.0

## 错误特征
```
xmmintrin\.h.*No such file|
```

## 根因分析
旧式 FindSSE.cmake（vid.stab ≤1.1.0 等）按 CMAKE_SYSTEM_NAME 三分支检测：Linux 读 /proc/cpuinfo、Darwin 走 sysctl、其余一律进最终 ELSE 分支 set(SSE2_FOUND true CACHE BOOL ...)。OHOS conan 的 CMakeToolchain 生成 CMAKE_SYSTEM_NAME=HarmonyOS，命中 ELSE → 顶层 CMakeLists 的 if(SSE2_FOUND) 给 aarch64 编译加 -msse2 -DUSE_SSE2 → x86 头文件/内联函数（xmmintrin.h 等）不存在，编译失败。且该分支是 CACHE 变量但无 FORCE。

## 推荐方案
**方法**: 预置同名 cache 变量拦截止游误判：在 conan 配方 generate() 里 tc.cache_variables["SSE2_FOUND"] = "FALSE"（等价 -DSSE2_FOUND:BOOL=FALSE）。CMake 语义保证：已存在的 cache 项不会被无 FORCE 的 set(... CACHE ...) 覆盖 → FindSSE 的 ELSE 置 true 失效，if(SSE2_FOUND) 为假，走可移植 C 路径。验证：configure 输出应出现 "Could not find hardware support for SSE2 on this machine."，编译命令无 -msse2。上游新版（vid.stab 1.1.2+）已换 try_compile 检测自然失败，无需此项；仅旧版需要。
