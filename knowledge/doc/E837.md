# E837: OHOS libc open_memstream：fclose 丢弃未冲刷缓冲并返回 EBADF——close 前必须 fflush

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, runtime, data-loss, memory-stream
- **作者**: unknown
- **来源 PR**: "!9622"

## 错误特征
```
Assertion failed.*string.*strcmp|fclose.*EBADF|open_memstream.*empty|read_string.*rc=0.*out=\(\)
```

## 根因分析
"OHOS libc（musl 变体）的 open_memstream 实现：fputc/fputs 写入正常，fflush 后缓冲内容立即可见（实测 fputs('hello')+fflush → n=5, s='hello'），但 fclose 返回 EBADF(-9) 且不执行缓冲到内存缓冲的冲刷——未 fflush 就 fclose 的流内容全部丢失（实测 fputs('hello')+直接 fclose → n=0, s=空）。依赖 open_memstream 的库在 OHOS 上表现为'调用成功但返回空串'（c-json 的 c_json_reader_read_string/read_file 即此表象），属静默数据损坏，极易被误判为库自身逻辑错误。"

## 推荐方案
**方法**: fflush-before-fclose-library-api

**说明**: "在 open_memstream 流的每个 fclose/c_fclose 关闭点前补 fflush(stream)（fflush 在 OHOS 行为正确、POSIX 等价、无平台宏，数据在 flush 时安全落盘后 fclose 照常执行）。c-json 补丁 0001/0002 在 read_string 与 read_file 两处实施后上游测试 2/2 全过。与 E302 的边界：E302 面向'能力探测+证据绑定禁用'的 CMake 测试基建场景，其 forbid（pre-flush 留下未关闭的坏 cookie 流）针对探测后仍持续使用坏流的写法；库 API 以 memstream 为核心功能、无上游回退路径可禁用，本方案先 flush 使数据落盘、fclose 照常关闭（cookie 清理仍执行，EBADF 返回值被忽略），不引入泄漏也不跳过任何测试。"

**修复命令**:
```
sed -i "s|stream = c_fclose(stream);|fflush(stream);\\n        stream = c_fclose(stream);|" src/c-json-reader.c（c-json 补丁 0001/0002 同型）
```

**验证**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
