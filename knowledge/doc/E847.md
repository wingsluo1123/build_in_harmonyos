# E847: prover9 无 configure 的手搓 Makefile 被 init-build 误判 autotools：改自定义 build() 直跑 make

## 基本信息
- **严重度**: 2
- **类别**: detection, build-system, autotools, conan
- **作者**: 66AE

## 错误特征
```
BUILD_SYSTEM=autotools.*no configure|init-build.*autotools.*误判|conan create.*autoreconf.*failed|No rule to make target 'configure'|can't find configure
```

## 根因分析
init-build 对"有 Makefile 但无 configure/cmake/meson"的源码树默认猜测 BUILD_SYSTEM=autotools

## 推荐方案
**方法**: 不用 Autotools 工具链。conan-init 生成骨架后手动重写为 application 型自定义 build()：直接 `make all -j1 CC=<R33 注入 clang> XFLAGS="-fPIC -O2"`；上游子 Makefile 为 `CFLAGS = $(XFLAGS) -O -Wall`，附加标志经 XFLAGS 注入而非改 CFLAGS（覆盖变量会被子 Makefile 硬编码丢失）；package() 策略 B 手动布局复制 bin/

**说明**: init-build 判型只是启发式；权威判据是源码树探针（configure*/configure.ac/cmake/meson 均无 + Makefile 在 → 手搓 make 型）。配方放弃模板工具链，自定义 build() 直跑 make，编译器经 R33 conf 注入

**修复命令**:
```
grep -q 'XFLAGS' <src>/Makefile && echo "XFLAGS-style makefile: use make all -j1 CC=$CC XFLAGS='-fPIC -O2'"
```

**验证**:
```
find <src> -maxdepth 2 -name "configure*" -o -name "configure.ac" -o -name "autogen.sh" | wc -l  # =0 而 Makefile 存在 → 误判面；ls Makefile 显示顶层递归结构即实锤
```
