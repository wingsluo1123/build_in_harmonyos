# E849: 从非 C/C++ 大型上游仓库「抽取单个脚本/数据文件」成包时，lang-preflight 默认 cpp 口径必然判为上游语言并自动落 env_unsupported 终态——正确处置是按检测器判定的上游语言显式 --lang 重跑并保留两轮证据，而非放弃适配（也绝不能伪报 cpp）

## 基本信息
- **严重度**: 2
- **类别**: limitation, detection, build-system
- **作者**: nyaco3 <aqjCItYW1QmEJQuF.gcw_XDpqZ8sO@noreply.gitcode.com>

## 错误特征
```
语言不匹配: task=cpp, detected=(rust|go|nodejs|java|python|perl|lua)|env_unsupported.*detected_language|任务标记 cpp，实测源码为 [a-z]+|按协议 v0\.8 §7\.2 交平台语言迁移|"build_system": "(cargo|go|gradle/maven|npm|setuptools)"
```

## 根因分析
lang_detect.py 的判定对象是「源码树整体」（manifest > 构建系统 > 源文件统计），而这类包的适配对象是源码树里的**一个**非主体语言文件（如 rust-lang/cargo 的 src/etc/cargo.bashcomp.sh、docker/cli 的 contrib/completion/bash/docker）。只要仓库里存在 Cargo.toml / go.mod / package.json，manifest 层就直接判定为 rust/go/nodejs；又因规则 D.4 规定 bash 文件不参与主体占比，交付物自身对判定毫无贡献。于是默认任务语言 cpp 与 detected 必然不匹配，lang_preflight_cli 走 mismatch 分支：自动调 result_cli 写 status=env_unsupported 终态回执（draft:false）并 exit 2。此时若按 R47 字面「非 C/C++ 立即终止」处理，会把一个**完全不需要该语言工具链**的纯数据包误判为环境不支持——真正需要终止的是"必须用该语言工具链构建"的包（CI 能力矩阵 Rust ❌ 那一类），两者判据不同：前者看交付物是否需要编译，后者看构建是否需要工具链。

## 推荐方案
**方法**: declare-upstream-language-explicitly-with-dual-evidence

**说明**: 先跑默认口径并把 stdout 存进 archives/<...>/reports/lang-preflight-default.log（rc=2 与 detected_language 都是证据，不要抹掉）；再用检测器给出的上游语言显式 --lang 重跑，rc=0 后继续主流程。配方必须同时满足三条自证：不声明该语言的 requires/tool_requires、build() 不调用该语言工具链、notes.md 与 PR 正文写明「CI 无需该工具链」。默认口径写出的 env_unsupported 终态回执，最后用 result --force 覆盖为真实终态。

**修复命令**:
```
python3 $SKILL_ROOT/scripts/ohc-run.py lang-preflight <软件> <版本> --src $BUILD_SRC_DIR --lang <detected_language 原值>
```

**验证**:
```
python3 $SKILL_ROOT/scripts/ohc-run.py lang-preflight <pkg> <ver> --src $BUILD_SRC_DIR; echo "default rc=$?"; python3 $SKILL_ROOT/scripts/ohc-run.py lang-preflight <pkg> <ver> --src $BUILD_SRC_DIR --lang <detected_language>; echo "honest rc=$?"  # 期望 default rc=2（留证）、honest rc=0（继续）
```
