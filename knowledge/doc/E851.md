# E851: "SCons 构建工具不可用时，从 SConstruct 提取精确源文件与链接图而非盲目安装系统包"

## 基本信息
- **严重度**: 2
- **类别**: ohos, build-system, dependency-path, scons
- **作者**: 2501_91199785

## 错误特征
```
"scons: not found|No module named SCons|talloc.h.*file not found"
```

## 根因分析
"老 SCons 项目的 SConstruct 同时含核心源码清单和与目标机不兼容的 /usr 默认路径；目标机缺 SCons 且制品仓没有配方时，直接安装系统工具或沿用硬编码路径都不可复现。"

## 推荐方案
**方法**: "extract-sconstruct-source-link-graph"

**说明**: "从 SConstruct 枚举库对象、程序入口、LIBS/CPPPATH/LIBPATH；只对这些源文件用目标编译器构建，将第三方头文件/库路径改由 Conan dependency cpp_info 提供。静态/共享产物及 SONAME 必须与上游一致；用安装后公开 API 的真实消费者测试验收。独立的文档/Python Builder 不能默认为 C 核心的必需步骤，但要在功能范围说明中披露未交付模块。"

**修复命令**:
```
"inspect SConstruct lib_src and env.Program; conan create . -pr:h=<ohos-profile> -pr:b=<ohos-profile>"
```

**验证**:
```
"W3 reglookup-w3-20260930T173100Z: libregfi + two CLIs built; installed range_list consumer 8 assertions; receipt 12/12 W3_PASS"
```
