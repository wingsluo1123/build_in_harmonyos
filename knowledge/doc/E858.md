# E858: 已发布混合 CLI/库依赖的下游显式 traits 修复边界

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, linking, conan, packaging
- **作者**: 2501

## 错误特征
```
package_type 'application' is defined|fatal error: 'jellyfish/atomic_gcc.hpp' file not found|CMakeDeps.*empty
```

## 根因分析
上游包真实安装公开头和库且 cpp_info 正确，但 package_type=application 的默认 dependency traits 屏蔽了 headers/libs；CMakeDeps 的目标存在却无所需 include/link 数据。已经发布的上游不能被下游擅自重写或重新上传。

## 推荐方案
**方法**: explicit-downstream-header-library-traits

**说明**: 先确认发布包真实含公开头/库且 cpp_info 完整；仅在下游的 requires 明确 headers=True, libs=True，使 CMakeDeps 消费这些已有安装物，保留 CLI 能力和上游不可变版本。不将此修复推广到 CLI-only 包或 cpp_info 缺失的包。

**修复命令**:
```
self.requires("dependency/version", headers=True, libs=True)
```

**验证**:
```
对比修复前后 CMakeDeps target 数据和 compile/link 命令；不硬编码 -I/-L/-l，仅链接 imported target，原生 conan create 执行全量上游及安装消费者。
```
