# E860: HarmonyOS PC /tmp 为只读挂载：硬编码 /tmp 的 scratch 文件目录使程序完全不可用

## 基本信息
- **严重度**: 3
- **类别**: environment
- **作者**: EC45

## 错误特征
```
/tmp/ed.XXXXXXXXXX: Read-only file system
```

## 根因分析
HarmonyOS PC 的 /tmp 是 erofs 只读挂载（/proc/mounts: /dev/block/dm-0 /tmp erofs ro），且 /var/tmp、/dev/shm、/data/local/tmp 同样不可写。上游 oed 的 buf.c 把 scratch 文件模板编译期写死为 /tmp/ed.XXXXXXXXXX，而 init_buffers() 在启动时无条件调用 open_sbuf()，mkstemp() 必然失败，故 ed 在解析任何用户命令之前就以非零码退出，工具完全不可用。

## 推荐方案
**方法**: 补丁：scratch 目录改为候选链回退

**说明**: 把编译期常量拆成目录+模板名，缓冲放大到 PATH_MAX，open_sbuf() 依次尝试 $TMPDIR → 编译期内置目录 → $HOME，第一个 mkstemp() 成功的即采用；不含平台宏，/tmp 可写平台行为不变。

**修复命令**:
```
export TMPDIR="$HOME/tmp" && ed -s file（或在配方里把候选链打进去）
```

**验证**:
```
printf ',p\nq\n' | ed -s file; echo $?   # 修复前报 Read-only file system 且 rc=2
```
