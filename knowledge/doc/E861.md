# E861: libshout 源客户端（oggfwd/ezstream 类）的 test_package 假服务器：默认 TLS AUTO 探测与无凭据先 401 导致握手卡死

## 基本信息
- **严重度**: 2
- **类别**: ohos, socket, network, testing
- **作者**: B9EA

## 错误特征
```
OPTIONS \* HTTP/1\.1.*Upgrade: TLS/1\.0|User-Agent: libshout/2\.[0-9]+\.[0-9]+.*Connection: Upgrade|WWW-Authenticate: Basic realm=.Icecast|oggfwd: Error connecting|ezstream.*Error connecting|shout_open.*(timed out|Socket error)
```

## 根因分析
libshout 2.4.x 的 HTTP 源协议握手不是"一次 SOURCE 请求 → 200"：(1) 客户端默认 TLS 模式为 AUTO（oggfwd 的 -T auto），先发 "OPTIONS * HTTP/1.1 + Connection: Upgrade + Upgrade: TLS/1.0" 探测，普通 TCP 假服务器若按"读到头就回 200"处理，客户端会一直等待 OPTIONS 应答而无输出、无退出；(2) 关闭 TLS（-T disabled）后，第一次 "SOURCE /mount HTTP/1.0" 请求**不带 Authorization**，只有收到 401 + WWW-Authenticate 后才关闭连接并**重新连接**、带 "Authorization: Basic base64(source:password)" 重试；假服务器对首个无凭据请求直接回 200 时，客户端已关闭首连接并在第二个连接上等应答，测试卡在 pselect 直到超时。二者都不是被测包缺陷，而是消费者测试对协议的建模不足。

## 推荐方案
**方法**: model-icecast-challenge-in-fake-server

**说明**: 假服务器按 Icecast 行为建模：循环 accept，无 "Authorization: Basic" 的请求回 "HTTP/1.0 401 Unauthorized + WWW-Authenticate: Basic realm=..." 并关闭连接，带凭据的请求回 "HTTP/1.0 200 OK"；客户端命令行加 -T disabled（先看 -h 用法是否含 "[-T "）避开 OPTIONS/TLS 升级探测；所有等待处设 alarm() 上限，stdout 用行缓冲以便超时时保留已通过的断言输出。

**修复命令**:
```
oggfwd -T disabled -m meta.txt -n NAME -g GENRE -p 127.0.0.1 $PORT hackme /test.ogg < /dev/null
```

**验证**:
```
qemu-aarch64 ./test_fake_icecast_static ./oggfwd-wrap.sh（静态重链 oggfwd 后，假服务器 11/11 PASS）；python3 - <<< "监听端口 → 运行 oggfwd -T disabled ... → 打印首个请求头"；观察首个请求无 Authorization、二次连接才带 "Authorization: Basic c291cmNlOmhhY2ttZQ=="
```
