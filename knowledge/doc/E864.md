# E864: Bash 工具上游 set -e + x=$(fn) 静默 rc=1：先用 x86 参照 + 最小复现判定为上游行为，不打补丁，测试断言退出码与副作用

## 基本信息
- **严重度**: 1
- **类别**: portability, posix, testing, shell
- **作者**: A8C4

## 错误特征
```
rc=1 out=''|exited with (status|code) 1 and (no|empty) output|silently exits? (with )?(status )?1|set -e.*command substitution.*(exit|abort)
```

## 根因分析
脚本类工具包适配时，某命令在鸿蒙环境「无输出、rc=1」很容易被误归因于鸿蒙 bash/toybox 差异。semtag 0.2.0 的真实根因在上游：脚本 `set -euo pipefail`，`analyze`/`create_tag`/`get_current_version` 路径里写成 `status=$(check_git_status)`，而 check_git_status 在工作区有改动时 `echo "unstaged"; return 1`。errexit 下「赋值语句的退出状态 = 命令替换的退出状态」，非零即令整个脚本立刻退出，后面的 `if [[ "$status" != "clean" ]]; then error ...` 永远走不到——表现为静默 rc=1、没有 ERROR 提示。与平台无关：同一脚本在 Debian bash 5.2.37 上同样复现。

## 推荐方案
**方法**: classify-upstream-behaviour-no-patch

**说明**: ①先在 x86 参照机（原生 bash）上用最小复现确认症状与鸿蒙一致，一致即判为上游行为，不写补丁（保持 patches/ 只含真正的平台适配，例如 shebang）；②在 notes.md 「遇到的问题」表里登记根因与最小复现命令；③test_package 对该路径只断言「退出码非 0 + 没有产生副作用（例如没有创建 tag）」，不断言输出文本，避免把上游缺陷固化成期望值，也避免上游修复后用例失效；④README 的平台约束节如实写明该上游缺陷。

**修复命令**:
```
bash -c 'set -euo pipefail; f(){ echo dirty; return 1; }; s=$(f); echo unreachable'; echo "rc=$?"
```

**验证**:
```
bash -c 'set -euo pipefail; f(){ echo dirty; return 1; }; s=$(f); echo "unreachable: $s"'; echo "rc=$?"   # 期望 rc=1 且不输出 unreachable；对照 `s=$(f) || true` 则输出 unreachable: dirty、rc=0。在 x86 构建机与鸿蒙上结果必须一致，一致即为上游行为
```
