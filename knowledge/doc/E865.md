# E865: musl 系平台（含 OHOS）上 -D_FORTIFY_SOURCE 使二进制装载期 __*_chk symbol not found

## 基本信息
- **严重度**: 3
- **类别**: toolchain
- **作者**: 6D47

## 错误特征
```
Error relocating.*__vsprintf_chk: symbol not found|Error relocating.*__strcat_chk: symbol not found|Error relocating.*__strlen_chk: symbol not found|undefined symbol: __vsprintf_chk
```

## 根因分析
上游 Makefile 硬写 -D_FORTIFY_SOURCE=2。OHOS 的 libc 是 musl 系，nm -D 实测 musl 仅导出 __stack_chk，不提供 glibc 专有的 fortify 变体 __vsprintf_chk/__strcat_chk/__strlen_chk。clang 仍按 glibc 语义把 sprintf/strcat/strlen 重定向到 __*_chk，产物因此引用 OHOS libc 不存在的符号。编译/链接/打包全绿，程序却在装载阶段失败。影响所有上游硬写 -D_FORTIFY_SOURCE 的 C/C++ 项目（musl 系目标，含 OHOS）。

## 推荐方案
**方法**: 在【追加型】CFLAGS 变量里用 -U_FORTIFY_SOURCE 抵消上游宏（必须排在 -D_FORTIFY_SOURCE 之后才生效），并用 -fstack-protector-strong 保留栈保护加固；不要为迁就门禁改上游源码逻辑。

**说明**: 追加 -U_FORTIFY_SOURCE 抵消 glibc 专有 fortify 符号，保留栈保护

**修复命令**:
```
EXTRA_CFLAGS='-U_FORTIFY_SOURCE -fstack-protector-strong'
```

**验证**:
```
nm -D --undefined-only <bin> | grep -i _chk
```
