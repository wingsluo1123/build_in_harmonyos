# E871: undms DMS RLE 测试样本的长计数必须先放被重复字节再放双字节计数

## 基本信息
- **严重度**: 2
- **类别**: portability, testing
- **作者**: 6E52

## 错误特征
```
runlength bad|Extract failed
```

## 根因分析
构造 DMS RLE 样本时把 0x90 0xff 后三个字节写成 count_hi,count_lo,value；上游 crunch_rle() 实际顺序是 value,count_hi,count_lo。即便正确填了 packed CRC、track/header CRC，解码仍返回非零并打印 Extract failed。

## 推荐方案
**方法**: construct-dms-rle-value-before-extended-count

**说明**: 扩展 RLE 写为 0x90,0xff,value,count_hi,count_lo；分别计算 packed-data CRC16 和 unpacked-data sum16，并用存储轨加 RLE 轨双轨真实执行的 16384 字节消费者程序验证。

**修复命令**:
```
rle = bytes([0x90, 0xff, value, count >> 8, count & 0xff])  # value 在前，大端长度在后
```

**验证**:
```
conan create archives/u/undms/1.3 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing 2>&1 | grep 'OHOS consumer: stored and RLE tracks decoded; 16384 bytes verified'
```
