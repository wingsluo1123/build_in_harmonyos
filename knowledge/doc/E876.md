# E876: Update legacy libpng discovery and close the shared-library dependency chain

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, libpng, linkage, shared-library
- **作者**: 2501_91199785

## 错误特征
```
No package 'libpng12' found|undefined symbol: png_|undefined symbol: jpeg_|undefined symbol: uncompress
```

## 根因分析
Old Autotools projects can probe only libpng12 while the published dependency provides libpng 1.6. Even after discovery succeeds, the main libtool library may omit PNG/JPEG/zlib from its LIBADD and therefore contain unresolved imports with no DT_NEEDED entries, leaving consumers unable to load it reliably.

## 推荐方案
**方法**: update-pkg-config-probe-and-libtool-libadd

**说明**: Change the source configure.ac probe to libpng, apply the same change to shipped configure when autoreconf is absent, update removed libpng APIs, and add existing dependency flags to the library's LIBADD in both Makefile.am and shipped Makefile.in. Verify DT_NEEDED and run a linked consumer.

**修复命令**:
```
readelf -d libtwin.so | grep NEEDED
```

**验证**:
```
conan create archives/l/libtwin/13.05.03.15.06-g287d16c --user=ohpcd --channel=stable -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
