# E880: OHOS 未随附 iproute2 的 ip（toybox 未编 ip applet）：上游测试脚本 `command -v ip || exit 1` 直接退出

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, toolchain, testing
- **作者**: A09D

## 错误特征
```
"ip: not found|ip: command not found|testgetifaddr test FAILED|command -v ip.*exit 1"
```

## 根因分析
鸿蒙 PC 的 toybox 未编入 ip applet（/bin/toybox --list 只有 install 无 ip），PATH 内也无 iproute2，因此上游测试脚本里 `IP=`command -v ip` || exit 1` 一类的工具探测在取到空值后直接 exit 1：测试用例本身一行没跑，脚本却以失败/未运行形态出现（miniupnpd 2.3.10 的 testgetifaddr.sh 即此形态，实测 make check 的 validategetifaddr 目标因此无法执行）。设备上 busybox（/data/service/hnp/bin/busybox）带完整 ip applet（`busybox ip -4 route`/`ip -4 addr show` 实测可用），可直接补齐该工具而无需改动上游测试脚本。

## 推荐方案
**方法**: provide-busybox-ip-applet-on-path

**说明**: 在配方 build()/测试执行环境里先 `command -v ip`，缺失时用 busybox 挂一个 ip 链接到任务本地 bin 目录并前置到 PATH（`ln -sf "$(command -v busybox)" "$BINDIR/ip"; export PATH="$BINDIR:$PATH"`）。busybox 的 ip 是真实 iproute2 兼容实现，测试语义不变、上游脚本零改动；测试前打印一行说明来源便于审方复核。

**修复命令**:
```
B="$PWD/.tools"; mkdir -p "$B"; command -v ip >/dev/null || ln -sf "$(command -v busybox)" "$B/ip"; PATH="$B:$PATH" make check
```

**验证**:
```
cd /storage/Users/currentUser/tmp/miniupnpd-2.3.10/w0/trial/b2 && PATH=/storage/Users/currentUser/tmp/miniupnpd-2.3.10/w0/bin:$PATH sh /storage/Users/currentUser/tmp/miniupnpd-2.3.10/w0/src/miniupnpd-2.3.10/testgetifaddr.sh  # 该目录须含 ./testgetifaddr（测试程序所在构建目录）→ 输出 testgetifaddr test OK rc=0；把 bin/ip 从 PATH 摘掉重跑同一命令则无任何输出直接 rc=1（command -v ip || exit 1 提前退出）
```
