# E884: x86 runner 上用 qemu-aarch64 跑「会 fork/exec 被测 CLI 的消费者程序」时子进程 exec 失败（rc=127），用 #!/bin/sh exec qemu-aarch64 <static> "$@" 的 wrapper 脚本充当被测路径

## 基本信息
- **严重度**: 2
- **类别**: cross-compile, testing, qemu
- **作者**: B41D

## 错误特征
```
execv.*failed.*127|exec format error|qemu-aarch64.*(fork|exec|child)|consumer.*exit(ed)? (with )?127|Exec format error
```

## 根因分析
x86_64 runner 上验证 aarch64-linux-ohos 产物靠 qemu-user。测试程序本身用 `qemu-aarch64 ./consumer` 启动没问题（qemu 直接加载 ELF），但消费者再 fork+execv/posix_spawn/popen 拉起**被测 aarch64 CLI** 时，子进程的 exec 由宿主内核处理：本机 /proc/sys/fs/binfmt_misc/ 没有注册 aarch64 handler（qemu-aarch64 文件不存在），且所装 qemu-user 不支持 `-execve` 选项，于是 execv 对 aarch64 ELF 返回 ENOEXEC，子进程走到 `_exit(127)`，消费者里 `--help/无参数/真实组` 等全部断言连锁失败（members 20080128.1-nmu3 实测：35 项断言 22 项 FAIL，全部源于子进程 rc=127，并非被测程序缺陷）。动态链接产物另有 musl loader 缺失问题（见 E544 草稿），本条是它的补充：静态重链也解决不了「子进程 exec」这一层。

## 推荐方案
**方法**: qemu-wrapper-script-as-exec-target

**说明**: 消费者程序与被测 CLI 各自同源 `.o` 用 NDK clang++ `-static` 重链；再写一个 shell wrapper 充当被测可执行文件路径：`printf '#!/bin/sh\nexec qemu-aarch64 /path/members-static "$@"\n' > members-qemu; chmod +x members-qemu`，然后 `qemu-aarch64 ./consumer-static ./members-qemu`。wrapper 是宿主 x86 可直接 exec 的脚本，由它再显式起 qemu，fork/exec 链就通了；消费者源码不需要为此改动，仍在 aarch64 上原样直接 exec 真实 bin/<tool>。

**修复命令**:
```
printf '#!/bin/sh\nexec qemu-aarch64 %s "$@"\n' "$PWD/tool-static" > tool-qemu && chmod +x tool-qemu && qemu-aarch64 ./consumer-static "$PWD/tool-qemu"
```

**验证**:
```
ls /proc/sys/fs/binfmt_misc/qemu-aarch64 2>&1; qemu-aarch64 ./test_consumer-static ./members-static  # 子进程 rc=127 → FAIL；改传 wrapper 后 qemu-aarch64 ./test_consumer-static ./members-qemu → checks=35 failed=0
```
