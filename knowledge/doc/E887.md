# E887: OHOS musl 的 <dirent.h> 不传递包含 <limits.h>，源码只 include <dirent.h> 就用 NAME_MAX 会编译失败

## 基本信息
- **严重度**: 2
- **类别**: portability, musl, headers, autotools
- **作者**: B1C7

## 错误特征
```
use of undeclared identifier 'NAME_MAX'|'NAME_MAX' undeclared|Invalid configuration `aarch64-unknown-linux-ohos': machine `aarch64-unknown-linux' not recognized
```

## 根因分析
POSIX 把 NAME_MAX 定义在 <limits.h>。glibc 的 <dirent.h> 经 bits/dirent.h/bits/local_lim.h 间接带出 NAME_MAX，

## 推荐方案
**方法**: include-limits-h-explicitly

**说明**: 在使用 NAME_MAX 的源文件中显式 #include <limits.h>（一行 portability 补丁，经 refresh-patch --auto 生成），

**修复命令**:
```
sed -i '0,/#include <stddef.h>/s//#include <limits.h>\n#include <stddef.h>/' a/direntdup.c
```

**验证**:
```
grep -n "NAME_MAX" $(grep -rl "NAME_MAX" --include=*.c --include=*.h .) ; grep -n "include" <sysroot>/usr/include/dirent.h ; grep -n "NAME_MAX" <sysroot>/usr/include/limits.h
```
