# E893: 上游 C 程序对 tmpnam+fopen 不判 NULL：OHOS /tmp 只读(EROFS) 下 fopen 返 NULL，随后经该 FILE* 写入即 SIGSEGV(rc=139)——补 NULL 回退 stdout（对齐同文件既有先例）即修

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, runtime, c, null-deref
- **作者**: Awstme
- **来源 PR**: 待回填（草稿随本任务 PR 提交）

## 错误特征
```
'Segmentation fault|SIGSEGV|signal 11|rc=139|printexpr|tmpnam\(tmpfile\)|cur_out=fopen'
```

## 根因分析
print.c:601 `tmpnam(tmpfile); cur_out=fopen(tmpfile,"w"); invoke_pager=true;` 不检查 fopen 返回值。OHOS 设备 /tmp 挂载为只读(EROFS)，fopen 恒返 NULL，下一行开始 printdocument 经 cur_out(FILE*) 写入即解引用 NULL → SIGSEGV(139)。同文件 learn.c:135 与 print.c 另三处分页点均有 `cur_out==stdout→stdout` 回退先例，唯此处缺失——属上游 portability 缺陷而非平台不可移植。判据要点：tmpnam 产名正常（不判空只在 fopen 上翻车），且上游三入口测试 0 命中 `?` 查询（缺陷不在上游断言面上，测试全绿也测不到）。

## 推荐方案
**方法**: portability-null-fallback-stdout

**说明**: 在 fopen 调用后立即判 NULL：失败则 `cur_out=stdout; invoke_pager=false;`（输出直落 stdout、不起分页器），成功才启用 pager 分支——与同文件既有三处 `cur_out==stdout→stdout` 形态完全对齐，纯 portability 补丁、不含 __OHOS__ 平台宏（PF5 免拦）。配套两条判据：①上游测试 0 命中该路径时仍须做 portability 补丁（测试全绿≠消费者不崩），修前 rc=139→修后 rc=0 双证留档；②test_package 用 `?help`/`?dim` 消费者断言把该面固化为回归，防止补丁被后续 refresh 回退。

**修复命令**:
```
printf '?help\n' | lie 2>&1 | grep -q 'Other useful help available' && echo NULL_FALLBACK_OK
```

**验证**:
```
printf '?help\n' | /storage/Users/currentUser/tmp/lie-2.2.2/w0/x/LiE/lie >/dev/null 2>&1; echo rc=$?    # 补丁树 rc=0；同一命令对未打补丁树 rc=139（双证留档 w0/pre.out 0B + w0/post2.out 364B）；补丁三关复验： cd /storage/Users/currentUser/tmp/lie-2.2.2/applychk && patch -p1 --dry-run < /storage/Users/currentUser/ws/worktrees/lie-2.2.2/archives/l/lie/2.2.2/patches/0001-printexpr-null-check.patch && echo PATCH_OK
```
