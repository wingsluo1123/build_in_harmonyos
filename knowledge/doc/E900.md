# E900: OHOS uname -r 为“HongMeng Kernel 1.12.0”破坏 Linux 式版本解析：工具启动门槛报错全面阻断（含非追踪命令）；ptrace 拒绝时 tracer 侧的次生表现（/proc/<pid>/fd ENOENT、seccomp ENOSYS 期望不成立）

## 基本信息
- **严重度**: 2
- **类别**: ohos, rust, testing, ptrace, startup
- **作者**: 9C4A

## 错误特征
```
Failed to parse kernel major ver|Current kernel version is not supported|No such file or directory.*proc.rs.*read_fd|Err(UnknownErrno).*ENOSYS
```

## 根因分析
①OHOS uname -r 返回 "HongMeng Kernel 1.12.0"（首位非数字），按“首段数字”解析的 Linux 版本探针（如 <5.3 校验）解析失败并经 ? 中止，早于命令分发，连 generate-completions 都失败（tracexec main.rs:369 实测）；应把解析失败并入既有“内核不受支持”告警路径继续。②OHOS 对非特权进程禁用 ptrace：不装 tracer 时 tracee 竞速退出，tracer 读 /proc/<pid>/fd/* 得 ENOENT（而非 EPERM），测试台账需按平台边界登记；③seccomp 过滤器加载后的 execve 在 OHOS 不必然返回 ENOSYS（Errno::UnknownErrno 实测），上游 seccomp 断言不适用。

## 推荐方案
**方法**: unparseable-release-treat-as-unsupported-plus-boundary-ledger

**说明**: 解析失败时按“不满足最低内核”走既有告警路径（不中止），让非追踪命令可用、追踪命令继续到平台真实边界；对 ptrace/seccomp 的次生失败逐项做平台边界登记（附探针矩阵），不桩化、不弱化断言。

**修复命令**:
```
cargo build --release --locked --target aarch64-unknown-linux-ohos
```

**验证**:
```
# 设备: uname -r → HongMeng Kernel 1.12.0；tracexec generate-completions bash → rc=1 Failed to parse kernel major ver（打补丁后 rc=0 输出 14008B 补全）；tracexec log -- /system/bin/echo hi → rc=1 干净报错（无 panic/挂起）
```
