# E902: OHOS 内核 /proc/stat 的 btime 恒为 0：依赖 boot-time 的墙钟换算不可用，需能力探测并降级为相对时间

## 基本信息
- **严重度**: 2
- **类别**: ohos, runtime, procfs, time
- **作者**: 9C4A

## 错误特征
```
BOOT_TIME too small: 0|assertion failed: *BOOT_TIME > 0|btime 0|/proc/stat btime
```

## 根因分析
OHOS（HongMeng Kernel 1.12）在 /proc/stat 输出 `btime 0`（设备实测），未提供 Linux 的 boot-time 字段值。任何以 boot_time + 相对计数换算墙钟时间的实现会得到 1970/无效绝对时间；对“自启动以来的间隔”类展示不受影响。上游如直接断言 boot_time>0 的测试在 OHOS 上按平台不适用。

## 推荐方案
**方法**: probe-btime-and-degrade-to-relative

**说明**: 启动/首次使用时探测 btime 有效性（>0 且合理），无效则：①时间列退化为“自启动以来的间隔”并注明；②断言类测试按平台边界登记（如实申报，不弱化）。备选数据源（如 CLOCK_BOOTTIME、/proc/uptime + 当前时间反推）按工具语义谨慎使用。

**修复命令**:
```
grep ^btime /proc/stat
```

**验证**:
```
# 设备实测: grep ^btime /proc/stat  →  btime 0；grep -E "boot_time_is_non_zero|boot_time_is_reasonable" 相关测试在 OHOS 按平台边界登记
```
