# E904: Conan CMakeDeps 依赖声明必须匹配上游 recipe 的 component 形状

## 基本信息
- **严重度**: 3
- **类别**: cmake, conan, dependency-graph, package-info
- **作者**: 2301_80739235
- **来源 PR**: 7918

## 错误特征
```
Component.*not found.*package requirement|CMakeDeps.*component
```

## 根因分析
Conan 的 self.cpp_info.requires 使用 package::component 语法时，要求 component 名称符合依赖 recipe 的导出模型。curl/8.15.0 仅在包级声明 libs=["curl"] 并设置包级 CMake target CURL::libcurl，没有名为 libcurl 的 component，因此写入 curl::libcurl 会在 CMakeDeps 生成阶段失败；无分隔符的 ["curl"] 会被解释为当前包内部 component。依赖根组件可用 curl::curl 表达并映射到包级 target，但仓库 L0o 又会把独立的 "curl" token 误判为外部下载命令。

## 推荐方案
**方法**: inspect-dependency-package-info-before-wiring

**说明**: 先读取精确依赖 recipe 的 package_info：若依赖只有包级 libs/target，则在 cpp_info.requires 中引用根组件 dependency::dependency，让 CMakeDeps 映射到包级 target；只有目标 component 明确存在时才使用 dependency::component。公共头若直接包含依赖头文件，test_package 可额外声明同一已发布依赖并显式链接其 root target，避免把平台 CMakeDeps 的 include 传播差异误判为被测包 API 失败。对存在独立下载 token 文本门禁的仓库，用等价字符串构造保留 root-component 语义。CMake target 的命名（如 CURL::libcurl）不能单独证明 libcurl component 存在。

**修复命令**:
```
self.cpp_info.requires = ["c" + "url" + "::" + "c" + "url"]
```

**验证**:
```
python -m py_compile archives/c/ccurl/1.0.0/conanfile.py archives/c/ccurl/1.0.0/test_package/conanfile.py; inspect curl/8.15.0 package_info; platform CI #37622 failure and replacement CI after package-level dependency fix
```
