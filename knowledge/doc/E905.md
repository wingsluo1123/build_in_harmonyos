# E905: OHOS Worker 缺少 GNU ar 时使用 compiler_executables 的 llvm-ar 回退生成静态归档

## 基本信息
- **严重度**: 3
- **类别**: ohos, toolchain, conan, static-library
- **作者**: 2301_80739235
- **来源 PR**: 7918

## 错误特征
```
FileNotFoundError.*ar|No such file or directory.*ar|L0.*static archive|print-prog-name
```

## 根因分析
目标 OHOS Worker 的 PATH 可能既不提供名为 ar 的 GNU 兼容命令，也不把 llvm-ar 放入 PATH。配方在 tools.build:compiler_executables 未声明 ar 时只使用裸命令，会在静态库打包阶段抛 FileNotFoundError；应从 clang 的 -print-prog-name=llvm-ar 或同目录派生绝对路径。这属于目标工具链命名差异，不是源码或链接逻辑错误。

## 推荐方案
**方法**: configured-archiver-with-clang-probe

**说明**: 优先读取 tools.build:compiler_executables 中显式配置的 ar；缺省时调用配置的 clang -print-prog-name=llvm-ar 并验证绝对路径，再检查编译器同目录和 /data/service/hnp/bin/llvm-ar，最后才保留裸 llvm-ar 兜底。不要回退到主机 GNU ar，也不要把静态归档改成不可替代的临时对象文件。

**修复命令**:
```
probe = subprocess.run([str(cxx), "-print-prog-name=llvm-ar"], capture_output=True, text=True, check=True)
```

**验证**:
```
python -m py_compile archives/c/ccurl/1.0.0/conanfile.py; CI #37603 log (FileNotFoundError: ar); replacement CI after llvm-ar fallback
```
