# E906: 有静态全局初始化保护的 C++ 库必须让目标 probe 运行在独立进程，不能在同一 ctypes 进程串行复用 global

## 基本信息
- **严重度**: 3
- **类别**: ohos, c++, python, runtime, process-isolation
- **作者**: 2301_80739235

## 错误特征
```
Curl already globally initialized|consumer_rc=101|static initialized guard
```

## 根因分析
某些 C++ 库的 global RAII 包装通过静态布尔值阻止重复初始化，但析构路径未恢复该标志。将 upstream 与 consumer probe 都加载到同一 Python/ctypes 进程时，首个 probe 清理后第二个 probe 仍会命中重复初始化异常；该失败属于 harness 生命周期污染，不代表目标库的链接或单个 API 调用失败。

## 推荐方案
**方法**: process-isolated-probe-lifecycle

**说明**: 先把每个独立测试组的生命周期边界建模为单独进程；父 runner 只传递哈希绑定的插件路径/输入并回传子进程终态，不跨组共享 ctypes 模块、C++ global 或静态状态。失败时区分 harness 状态污染与插件装载/符号解析失败，不能通过重置库内部静态变量掩盖真实 API 语义。

**修复命令**:
```
python3 -c "import ctypes,sys; p=ctypes.CDLL(sys.argv[1]); raise SystemExit(p.ccurl_consumer_probe_diag())" <plugin>
```

**验证**:
```
env LD_LIBRARY_PATH=<task-root> python3 <task-root>/runner.py; 其中 runner 为每个 probe 调用独立的 python3 -c 子进程；检查 upstream_rc=0、consumer_rc=0、目标阶段输出和 runner CLEAN_EXIT
```
