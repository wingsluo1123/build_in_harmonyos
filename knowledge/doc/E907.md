# E907: OHOS（musl 系）libc::pthread_t = *mut c_void 非 Send/Sync：跨线程通道/结构体存 tid 需 usize 中转（连锁 tokio::spawn Send 约束）

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, threading, rust, compilation
- **作者**: 9C4A

## 错误特征
```
E0277: `*mut c_void: Send` is not satisfied|E0277: `*mut c_void: Sync` is not satisfied|future cannot be sent between threads safely|SyncSender<pthread_t>|SendError<*mut c_void>
```

## 根因分析
OHOS target_env 采用 musl 系 libc 定义，pthread_t 为 *mut c_void（gnu 为 c_ulong）。*mut c_void 非 Send/Sync，故：SyncSender<pthread_t> 无法移入 spawn_blocking、其 SendError 无法 `?` 转 eyre、含该字段的结构体（RunningTracer）整体非 Send 并使捕获它的 tokio::spawn future 编译失败（tracexec tracer.rs 两处 E0277 实测）。

## 推荐方案
**方法**: carry-usize-and-cast-at-use

**说明**: 把通道与结构体字段改为 usize（`pthread_self() as usize`），仅在实际调用 libc 处 `as pthread_t` cast 回；usize↔pthread_t 的 cast 在 gnu(c_ulong)/ohos(*mut c_void) 均合法，全平台等价，无需平台宏。

**修复命令**:
```
cargo build --release --locked --target aarch64-unknown-linux-ohos
```

**验证**:
```
# OHOS 目标编译含 SyncSender<pthread_t> 的代码 → E0277（Send/Sync）；改存 usize 并在 pthread_kill 调用处 cast 回后编译通过（tracexec 实测）
```
