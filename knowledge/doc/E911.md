# E911: inspect-install-and-public-api

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, packaging, compile-definitions, consumer
- **作者**: 2301_80739235

## 错误特征
```
'consumer.*header.*not found|undefined reference.*public API|public API.*not declared|installed package.*include.*empty'
```

## 根因分析
An upstream CMake project can build a library target successfully while its install rules omit public headers.  Public declarations can also be conditional on a producer-side macro, so a consumer compiles or links incorrectly unless the recipe stages the headers and exports the required definition.

## 推荐方案
**方法**: inspect-install-and-public-api

**说明**: Read the upstream install rules and public header guards before writing package_info.  If headers are absent from install(), copy only the documented public headers during package().  If an API guard is required by the library build, export it through cpp_info.defines so generated CMake consumers inherit it.  Validate with a separate linked consumer rather than a file-existence test.

**修复命令**:
```
'cmake --install <build>; inspect package include/lib; build and run an API consumer with generated CMakeDeps/CMakeToolchain'
```

**验证**:
```
configure and build the library; inspect the staged package include/lib files; build a separate consumer through generated CMake package metadata; run the consumer against a real API call
```
