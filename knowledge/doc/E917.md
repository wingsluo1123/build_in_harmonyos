# E917: CMake dependency and platform header probes must match target layout and host filesystem boundaries

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, cmake, testing, dependency-closure
- **作者**: 2301_80739235

## 错误特征
```
"fatal error: 'openssl/opensslv.h' file not found|postcheck FAILED|negative epoch|DrvFs|9p mount|BadZipFile: File is not a zip file|redefinition of 'sockaddr_storage'"
```

## 根因分析
The OHOS OpenSSL package exposed headers below a child openssl directory, so pointing OPENSSL_INCLUDE_DIR at that child made openssl/opensslv.h unreachable. Separately, WSL /mnt/f uses a DrvFs/9p filesystem that clamps negative Unix mtimes to epoch zero, making upstream tests that require pre-1970 timestamps fail independently of the product code. A codeload URL without a trusted archive suffix also allowed a worker to choose ZIP extraction for a gzip tar response, so tools.files.get() needed an explicit filename while retaining the original URL and hash. Finally, OHOS exposes linux/tcp.h beside sys/socket.h even though the two headers redefine sockaddr_storage, so the target must disable that optional header probe and use netinet/tcp.h.

## 推荐方案
**方法**: bind-package-root-separate-host-fs-boundary-explicit-archive-and-probe-format

**说明**: Bind CMake include and archive paths to the exact frozen package tree, explicitly name remote archive formats when URL suffixes are unreliable, disable only a target-proven incompatible optional header probe, then keep host filesystem limitations as explicit evidence rather than changing upstream assertions or claiming full test PASS.

**修复命令**:
```
"-DOPENSSL_ROOT_DIR=<openssl-package> -DOPENSSL_INCLUDE_DIR=<openssl-package> -DOPENSSL_SSL_LIBRARY=<openssl-package>/lib/libssl.a -DOPENSSL_CRYPTO_LIBRARY=<openssl-package>/lib/libcrypto.a"
```

**验证**:
```
"set OPENSSL_INCLUDE_DIR to the package root and HAVE_LINUX_TCP_H=OFF, rebuild; reproduce the filesystem boundary with Python os.utime on /mnt/f using a negative epoch"
```
