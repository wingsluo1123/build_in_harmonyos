# E919: 上游回归脚本"无输出即通过"、失败只 echo 一行且脚本退出码恒为 0（sng_regress）：配方里 self.run() 不抛错不等于通过，必须捕获 stdout 断言为空；libpng 的 warning 走 stderr，不能并进判据

## 基本信息
- **严重度**: 2
- **类别**: build-system, testing, ci-gate
- **作者**: C8C9

## 错误特征
```
sng_regress|No output is good news|decompilation of the test PNG failed|recompilation of the (decompiled|canonicalized) form failed|generation of the canonicalized form failed
```

## 根因分析
sng 的 `make check` 调用 sng_regress，脚本里的 check() 只在上一条命令失败时 `echo "<file>: ... failed"`，不 exit，脚本末尾也没有汇总退出码，Makefile 靠 `echo "No output is good news."` 约定"无输出=通过"。实测给它一个损坏的 bad.png：4 行 failed 全部打印，`bash sng_regress bad.png` 退出码仍是 0。因此在 Conan 配方里 `self.run("bash ./sng_regress test.sng snglogo.png")` 即使回归全红也不会抛 ConanException，W3/CI 照绿，上游测试"通过率"成了纸面数字。另有一个反向陷阱：正常输入也会让 libpng 往 **stderr** 打 `libpng warning: hIST: out of place`（test.sng 故意含 hIST/tRNS 边界用例），若 2>&1 合并后再断言"输出为空"会把健康运行误判为失败。判据必须是 **stdout 为空**，stderr 只作诊断。

## 推荐方案
**方法**: capture-stdout-assert-empty

**说明**: build()/test() 里用 `self.run(cmd, stdout=StringIO())` 捕获脚本 stdout，`if out.getvalue().strip(): raise ConanException(...)`；不要把 stderr 并入判据（libpng warning 属正常）。脚本需要临时目录时用 $TMPDIR（sng_regress 硬编码 /tmp 且用 diff -c，OHOS 上 /tmp 只读、toybox diff 无 -c，按最小补丁改为 ${TMPDIR:-/tmp} 与 diff -u）。验证时务必先跑一遍反例（损坏输入）确认判据真的会红，再信任它的绿。

**修复命令**:
```
out = StringIO(); self.run('TMPDIR="<dir>" bash ./sng_regress test.sng snglogo.png', stdout=out); assert not out.getvalue().strip()
```

**验证**:
```
echo notpng > bad.png; TMPDIR=$PWD bash ./sng_regress bad.png >out.txt 2>err.txt; echo "exit=$? stdout_lines=$(wc -l <out.txt)"   # 期望 exit=0 且 stdout_lines=4（证明退出码不可信）；再对 test.sng snglogo.png 跑一遍，期望 stdout_lines=0（stderr 里的 libpng warning 不计）
```
