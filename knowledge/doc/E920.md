# E920: libc 的 musl 系 OHOS target_env 缺 PTRACE_GET_SYSCALL_INFO/ptrace_syscall_info（仅 gnu 模块提供）：cfg(target_env="ohos") 局部 uapi shim 补齐

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, rust, compilation, abi-gap
- **作者**: 9C4A

## 错误特征
```
E0432: unresolved imports `nix::libc::PTRACE_GET_SYSCALL_INFO`|no `PTRACE_GET_SYSCALL_INFO` in the root|no `ptrace_syscall_info` in the root
```

## 根因分析
libc 把 PTRACE_GET_SYSCALL_INFO 请求常量与 ptrace_syscall_info 结构只定义在 linux/gnu 模块；musl 系（含 target_env="ohos"）只保留通用 linux_like，故 OHOS 上 nix::libc::PTRACE_GET_SYSCALL_INFO 导入即 E0432（tracexec guards.rs 实测）。内核 uapi linux/ptrace.h 布局与架构无关，可精确复刻；注意 musl 系 libc::ptrace 首参为 c_int（gnu 为 c_uint），shim 常量须取 c_int。

## 推荐方案
**方法**: cfg-target-env-ohos-uapi-shim

**说明**: 引用处加 #[cfg(not(target_env="ohos"))] use nix::libc::{...}；#[cfg(target_env="ohos")] mod shim 按 linux/ptrace.h 精确布局复刻常量与 union 并 use 之。仅 OHOS 走 shim，其余目标保持 libc 原样。

**修复命令**:
```
cargo build --release --locked --target aarch64-unknown-linux-ohos
```

**验证**:
```
# OHOS 目标编译引用 PTRACE_GET_SYSCALL_INFO 的片段 → E0432；加 cfg shim 后编译通过（tracexec 0.17.0 conan create 实测 164/164）
```
