# E923: '`Package ''libargon2'' was not found` 的根因是模块名错位而非路径：上游 PKG_CHECK_MODULES 要 `libargon2.pc`、conan argon2 默认产 `argon2.pc`，消费侧 PkgConfigDeps.set_property(''argon2'',''pkg_config_name'',''libargon2'') 一步改名即可，比 ARGON2_CFLAGS/LIBS 环境覆盖与手写 .pc 垫片都小'

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, dependency, pkg-config
- **作者**: unknown

## 错误特征
```
'Package libargon2 was not found in the pkg-config search path|Perhaps you should add the directory containing `libargon2\.pc'' to the PKG_CONFIG_PATH environment variable|configure: error: Package requirements \(libargon2\) were not found|Package ''libargon2'', required by .* not found'
```

## 根因分析
conan 包默认 pkg-config 文件名=包名，而 argon2 配方 package_info() 未设 pkg_config_name 属性，故 generate() 只产 argon2.pc；上游 configure.ac 用 PKG_CHECK_MODULES([ARGON2], [libargon2]) 按模块名查 libargon2.pc。两个命名体系各自合理，合在一起错位；pkg-config 报错文案（"add the directory to PKG_CONFIG_PATH"）会把排查引向路径而非文件名，路径设对也无济于事。依赖本身在档且 conan install rc=0、argon2.pc 真实存在，是典型的"依赖齐、名字错"配置期假缺依赖。

## 推荐方案
**方法**: consumer-side-pkgconfig-rename

**说明**: 配方 generate() 中 PkgConfigDeps(self) 实例先 pkg.set_property("argon2", "pkg_config_name", "libargon2") 再 pkg.generate()，产 libargon2.pc，与上游模块名对齐；.pc 内容仍由 PkgConfigDeps 从 cpp_info 权威生成，只有文件名被改，无字段双源。配套把 generators 目录 prepend 进 PKG_CONFIG_PATH（正式条目 E468 的修法，AutotoolsToolchain 的 environment() → env.prepend_path("PKG_CONFIG_PATH", self.generators_folder) → tc.generate(env=env)）。被否两案及取舍：ARGON2_CFLAGS/ARGON2_LIBS 环境覆盖需从 dependencies 手工拼 -I/-L/-l（含静态 libargon2 的 rt/dl），与 cpp_info 双源易随 shared/static 选项漂移；手写 libargon2.pc 垫片则 Version/Libs/Requires/soname 全部手工同步，文件面最大。

**修复命令**:
```
python3 - <<'EOF'\nfrom conan.tools.gnu import PkgConfigDeps\nprint("pkg.set_property('argon2', 'pkg_config_name', 'libargon2') before pkg.generate()")\nEOF
```

**验证**:
```
ls <generators>/libargon2.pc && PKG_CONFIG_PATH=<generators> pkg-config --exists libargon2 && echo OK || PKG_CONFIG_PATH=<generators> pkg-config --exists argon2 && echo "only argon2.pc exists - name mismatch"
```
