# E929: configure 补丁让 doc 时间戳链重算，缺 makeinfo 时 make check/install 全挂（mdate-sh 空输出还会把环境写进文档）

## 基本信息
- **严重度**: 3
- **类别**: hmdfs, portability, build-system, autotools
- **作者**: 421B, BCF5

## 错误特征
```
makeinfo.*(missing|inaccessible or not found|No such file)|Error 127|failed parsing 'ls -L -l -d -n /' output
```

## 根因分析
上游 doc/Makefile 链条 stamp-vti（依赖 shishi.texi 与 configure）→ version.texi → shishi.info，对 configure 打过补丁（mtime 变新）后链条重算，make 调 missing 包装的 makeinfo 重建 info 手册；设备与 CI 均无 makeinfo，ohpcd 也未发布 texinfo → make check 与 make install 双双 Error 127。设备上连锁反应更重：mdate-sh 解析 toybox ls 输出失败返回空，stamp 规则里零参数 set 在 mksh 系 shell 下把整个 shell 环境（含 GITCODE_TOKEN）写进 version.texi，refresh-patch --auto 会把它打成补丁准备入库

## 推荐方案
**方法**: 对齐 info 时间戳链

**说明**: 配方 build() 在 apply_conandata_patches 之后、configure 之前，对 doc/stamp-vti、doc/version.texi、doc/shishi.info（含 shishi.info-1..N）只调 os.utime 对齐到当前时刻：stamp 新于补丁后的 configure、info 新于 version.texi，链条不再重算，makeinfo 不再被调用，mdate-sh 也不会跑。只改 mtime 不改内容，零 diff 零补丁

**修复命令**:
```
'# conanfile.py build(): for f in ("doc/stamp-vti","doc/version.texi","doc/shishi.info","doc/shishi.info-1","doc/shishi.info-2","doc/shishi.info-3"): p=os.path.join(self.source_folder,f); os.path.exists(p) and os.utime(p,None)'
```

**验证**:
```
command -v makeinfo; grep -n "stamp-vti" <builddir>/doc/Makefile; grep -c "^+" <package>/patches/*.patch | grep -v ":0"   # 补丁行数异常大即疑似环境泄漏
```
