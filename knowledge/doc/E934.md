# E934: gengetopt 生成的 *_cmd.c 解析器只在 release tarball，git 快照/本地补生成必断

## 基本信息
- **严重度**: 3
- **类别**: limitation, portability, build-system, autotools
- **作者**: 421B

## 错误特征
```
gengetopt.*(not found|No such file|inaccessible or not found)|make\[.*\].*gengetopt
```

## 根因分析
GNU shishi 这类包用 gengetopt 从 *.ggo 生成命令行解析器 src/*_cmd.c 与 *_cmd.h，并登记进 BUILT_SOURCES 显式规则；release tarball 自带这些生成物且 mtime 新于 .ggo 因 make 不重算，git 树只有 .ggo 源定义。设备与 CI worker 都没有 gengetopt（ohpcd 也未发布），一旦源来自 git 快照/归档或时间戳倒挂，make 就在 BUILT_SOURCES 处报 gengetopt not found

## 推荐方案
**方法**: sources 锚定官方 release tarball

**说明**: conandata.yml 的 sources 必须指向官方 release tarball 并 sha256 实核（ftp.gnu.org/GitHub releases），不使用 git snapshot 或 /archive/ 归档；打包后可用 tar tzf 核对生成物在位，tar 内生成物 mtime 新于 .ggo 时 make 不会触发 gengetopt

**修复命令**:
```
tar tzf <release-tarball> | grep -q "src/.*_cmd\.c" && echo "generated parsers present" || echo "NEED gengetopt"
```

**验证**:
```
command -v gengetopt || echo "gengetopt missing - release tarball required"; tar tzf <release-tarball> | grep -c "_cmd\.c"
```
