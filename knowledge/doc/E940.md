# E940: OHOS conan 沙箱中不兼容 libc++_shared.so 遮蔽所致宿主 cmake/qtpaths 符号重定位失败，前置 /system/lib64 修复

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, toolchain, conan, runtime
- **作者**: DAE2

## 错误特征
```
Error relocating /data/service/hnp/bin/cmake: .*symbol not found|Error loading shared library libc++_shared.so.*needed by|Error loading shared library.*libc\+\+_shared\.so
```

## 根因分析
OHOS conan 构建沙箱把各依赖包的 lib 目录 prepend 进 LD_LIBRARY_PATH 后，其中某个不兼容的 libc++_shared.so（如宿主二进制所需 ABI 版本不同）遮蔽了 /system/lib64 下的兼容版本；宿主工具（/data/service/hnp/bin/cmake、ECM KDEInstallDirs 调用的 qtbase qtpaths）运行时报 _ZNSt4__n1* / _ZNKSt4__n119__shared_weak_count 等 libc++ 符号 "symbol not found"，configure/构建直接失败。

## 推荐方案
**方法**: prepend-system-lib64-to-ld-library-path

**说明**: 在配方 build()/test() 环境（Environment）中对 OHOS prepend LD_LIBRARY_PATH=/system/lib64，使加载器优先解析兼容的 system libc++，宿主 cmake/qtpaths 正常重定位。test_package 的 build() 与 test() 同样需要（其 cmake.configure 也跑宿主 cmake）。

**修复命令**:
```
build_env.prepend_path("LD_LIBRARY_PATH", "/system/lib64")  # 仅 settings.os == "OHOS" 时
```

**验证**:
```
conan create archives/k/ksyntaxhighlighting/6.26.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable
```
