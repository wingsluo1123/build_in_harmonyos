# E942: sh+awk 脚本包里的 gawk 专有函数调用（strftime/systime/gensub…）即便被 `if(ARGV[0]=="gawk")` 保护，在没有该函数的 awk 上解析阶段就整体报错，脚本一行都跑不起来

## 基本信息
- **严重度**: 2
- **类别**: portability, toolchain, testing, shell
- **作者**: 06CB

## 错误特征
```
awk: .*Undefined function '?strftime'?|function strftime never defined|awk: [0-9]+ syntax error\(s\)|calling undefined function strftime
```

## 根因分析
awk 在执行任何语句之前先整体解析程序，函数调用在解析阶段就要解析到已定义函数或内建函数；运行期条件（`if(ARGV[0]=="gawk")`）保护不了解析。cascade 1.4 的内嵌 awk 程序末尾有 `if(ARGV[0]=="gawk"){ now = strftime(...) }`：本机 mawk 1.3.4 20250131 内置 strftime，所以本地 conan create 24/24 通过；OHOS CI 构建机上的 awk 没有 strftime，每次运行 `cascade file` 都输出 `awk: file (cmdline) line 0: Undefined function 'strftime'` 和 `awk: 1 syntax error(s)`，报告一行都出不来（CI 上 test_package 11 过 13 败）。`--version`/`--help` 在 sh 层处理、不经过 awk，所以仍然通过，容易让人误判为“包基本可用”。

## 推荐方案
**方法**: drop-gawk-only-awk-block-by-patch

**说明**: 用 conandata 补丁把 gawk 专有函数调用的整块代码删掉（cascade 里是仅在 gawk 下多打一行时间戳，无功能损失），补丁是通用可移植性修复，不含 __OHOS__ 平台宏。test_package 对每次运行都断言 stderr 为空，这样同类解析错误不会被“退出码 0 / 部分输出”掩盖。

**修复命令**:
```
patch(cascade.sh): 删除 `if(ARGV[0] == "gawk"){ now = strftime(...); printf(...) }` 整块
```

**验证**:
```
grep -nE 'strftime|systime|mktime|gensub|asorti?|PROCINFO|BEGINFILE|@include' <脚本>；再用目标环境的 awk 运行最小用例并检查 stderr 为空：`cascade examples/ex1.cas 2>err.txt; test ! -s err.txt`。本机若 awk 是 gawk/新版 mawk 则不会复现，须以远程 CI（OHOS 构建机）结果为准。
```
