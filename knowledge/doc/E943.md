# E943: 纯脚本/文档类 autotools 包的 `all` 与 `install.man` 目标执行 `nroff -man x.1 > x.0` 预排版 cat1 手册页——OHOS CI 工具链没有 nroff，整个构建被一个手册页拖死

## 基本信息
- **严重度**: 2
- **类别**: portability, autotools, make, toolchain
- **作者**: D418

## 错误特征
```
nroff: (command )?not found|nroff -man .*: not found|\*\*\* \[.*\.0\] Error 127|nroff.*No such file or directory
```

## 根因分析
cascade 1.4（sh+awk 脚本，autoconf 2.13 的 configure + Makefile.in）的 `all:: cascade.0` 规则是 `nroff -man cascade.1 > cascade.0`，`install.man` 又依赖 `cascade.0`，所以 `make` 与 `make install` 都要求构建机有 nroff。nroff（groff）不在 OHOS 交叉工具链里（仓内 wiggle/1.3 配方同样记录 “wiggle.man via nroff, which is not part of the toolchain”，trurl/0.16.1 跳过 cd2nroff 手册页），在 CI 环境会得到 `nroff: command not found` / `make: *** [Makefile:NN: x.0] Error 127`。本机 x86 runner 装有 nroff，所以本地构建不会复现——只靠本地 conan create 看不出，是“本地绿、CI 红”的典型来源。手册页本身是纯文档，与二进制/脚本功能无关。

## 推荐方案
**方法**: build-primary-target-only-install-subtargets

**说明**: build() 只构建产物目标（`make cascade`，不跑 `all`）；package() 用上游的细分安装目标（`make installdirs install.bin install.examples install.docs install.lisp`，即 `make install` 去掉依赖 nroff 的 install.man），再用 conan `copy()` 把 roff 源页（cascade.1）装到 share/man/man1，并 `os.rmdir` 掉 installdirs 建出的空 cat1。零新增 tool_requires、零补丁，行为与上游完整安装的差别仅是不带预排版的 cat1 页。

**修复命令**:
```
self.run("make cascade", cwd=self.source_folder); self.run("make installdirs install.bin install.examples install.docs install.lisp", cwd=self.source_folder); copy(self, "cascade.1", src=self.source_folder, dst=os.path.join(self.package_folder, "share", "man", "man1"), keep_path=False)
```

**验证**:
```
grep -nE 'nroff|groff|mandoc' Makefile.in Makefile.am Makefile 2>/dev/null；确认默认 all/install 目标是否传递依赖这些规则。修复后：conan create 的 build() 日志只出现 `make cascade`（无 nroff 行），package 目录含 share/man/man1/cascade.1 源页且无空 cat1 目录。
```
