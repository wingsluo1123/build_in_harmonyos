# E944: LP64(aarch64) 下用 unsigned long 承载 32 位网络协议字段：htonl/ntohl 与按 sizeof 逐字节序列化展开成 8 字节，协议帧畸形且无编译告警

## 基本信息
- **严重度**: 3
- **类别**: portability, libc, socket, network, testing
- **作者**: 6CBB

## 错误特征
```
(ntohl\s*\(\s*\*\s*\(\s*\(?\s*unsigned\s+long|unsigned\s+long(\s+int)?\s+NBR)|(IAC SB (COM-PORT|44) (101|SET-BAUDRATE).*(00 00 00 00|8 bytes|8 字节))|(wire|protocol|frame).*(unsigned long).*(4|four) bytes
```

## 根因分析
32 位网络字段（RFC 2217 波特率、报文长度等）被声明成 unsigned long。ILP32 时代

## 推荐方案
**方法**: fixed-width-wire-types

**说明**: 线缆字段一律改用 <stdint.h> 定宽类型（uint32_t）：序列化侧 uint32_t NBR = htonl(BR)，读取侧 ntohl(*(uint32_t *)&buf[4])；对其余按 sizeof 展开的循环同样核对变量类型。属可移植补丁（无平台宏），可上游化。用消费者用例在 aarch64 上驱动真实协议往返，校验应答帧逐字节相等。

**修复命令**:
```
patch -p1 < patches/0001-sredird.c.patch
```

**验证**:
```
grep -nE "unsigned long[^;]*\b(NBR|BR)\b|ntohl\s*\(\s*\*\s*\(\(?unsigned long" sredird.c ; qemu-aarch64 ./rfc2217_client ./sredird
```
