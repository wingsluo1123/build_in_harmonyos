# E945: Autotools autoreconf under Conan needs the conanbuild env (ACLOCAL_PATH/LIBTOOLIZE/_lt_pkgdatadir); hand-assembled PATH skips libtoolize

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, conan
- **作者**: 5BE4

## 错误特征
```
possibly undefined macro: AC_PROG_LIBTOOL|\$pkgauxdir is not a directory|configure.ac: not using Libtool
```

## 根因分析
conan automake/libtool packages set buildenv_info vars (ACLOCAL_PATH->libtool share/aclocal, LIBTOOLIZE, _lt_pkgdatadir->source-tree-shaped dir) that autoreconf needs to trace AC_PROG_LIBTOOL. Without ACLOCAL_PATH, aclocal cannot find libtool.m4 so the autom4te trace does not see AC_PROG_LIBTOOL and autoreconf prints "configure.ac: not using Libtool" and never runs libtoolize; autoconf then errors "possibly undefined macro: AC_PROG_LIBTOOL". With ACLOCAL_PATH but without _lt_pkgdatadir, libtoolize fails with "$pkgauxdir is not a directory: //share/libtool/build-aux" (baked empty @datadir@).

## 推荐方案
**方法**: use-conanbuild-env

**说明**: Let Conan build the env: call Autotools(self).configure()/self.run(..., env="conanbuild") or `source` the conanbuild.sh generated by conan install (VirtualBuildEnv). Do NOT hand-assemble PATH from package bin dirs; that omits ACLOCAL_PATH/LIBTOOLIZE/_lt_pkgdatadir.

**修复命令**:
```
autoreconf -v -i -f   # 在 conanbuild env 下执行（ACLOCAL_PATH/LIBTOOLIZE/_lt_pkgdatadir 已注入）
```

**验证**:
```
env | grep -E "ACLOCAL_PATH|LIBTOOLIZE|_lt_pkgdatadir" ; sh -c "autoreconf -v -i -f" 2>&1 | grep -i libtool
```
