# E946: PR 新增二进制文件（测试图片/fixture/归档）时 GitCode PR diff 不携带 GIT binary patch 数据，CI checkout-pr 的 git apply 必然失败，conan 门禁全未执行

## 基本信息
- **严重度**: 3
- **类别**: conan, testing, patch
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: 12488

## 错误特征
```
missing binary patch data for|binary patch does not apply to|PR.*diff.*无法应用.*冲突|patch: Unknown option 'fuzz=3'
```

## 根因分析
CI checkout-pr 不 checkout 分支，而是 clone 默认分支→git reset --hard+git clean→curl PR diff→git apply/--3way/patch -p1；GitCode 的 PR diff 端点对新增二进制文件只输出 "Binary files differ" 标记、不含 GIT binary patch 的 base85 数据段，git apply 报 missing binary patch data；随后 fallback 到 patch -p1 仍失败且该 patch 不认识 fuzz=3 选项，脚本判定"PR 与 main 冲突"。失败发生在任何 conan 门禁之前，日志里没有配方信息，且与 main 是否真实冲突无关（merge-base 干净也必死），重试必然复现

## 推荐方案
**方法**: test-time-deterministic-generator

**说明**: 从提交中删除全部二进制文件，改为入库一个纯文本确定性生成器（如 test_package/make_images.py / fixtures/make_fixtures.py），由 CMakeLists.txt 的 add_custom_command(OUTPUT ... DEPENDS generator) 或 test.sh 在测试期调用 python3 重新生成字节级一致的文件；生成器失败必须显式报错，禁止静默当作全部通过。生成内容需满足测试断言（关键像素、尺寸、通道数），并注意 stb 系 DDS 加载器在 SOIL_LOAD_AUTO 下会把全不透明 RGBA 降为 3 通道——需放一个 alpha<255 的像素保住 4 通道路径

**修复命令**:
```
git rm <二进制...> && git commit -m "fix(...): drop binary test data ..." && git push origin <branch>
```

**验证**:
```
curl -sL https://gitcode.com/{owner}/{repo}/pull/{n}.diff | grep -c 'GIT binary patch'  # 新增二进制时为 0 但 diff 里存在 'Binary files /dev/null/... differ' 标记即命中本条
```
