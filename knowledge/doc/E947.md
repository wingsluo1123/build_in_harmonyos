# E947: GNU make 对命令行变量忽略 makefile 内（含目标级）+= 追加——raw Makefile 工程把平台宏放目标级 CC += 时，命令行 CC=clang 会静默丢掉平台定义，需把 -D 宏显式并入命令行 CC

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, build-system, make
- **作者**: unknown
- **来源 PR**: pending

## 错误特征
```
incompatible integer to pointer conversion|implicit declaration|basename|__LINUX|CC +=|target-specific variable|command line variable|'char *' from 'int'
```

## 根因分析
"scalpel 1.60（nolaforensix 维护分支）的 Makefile 是 raw make 工程（无 configure），平台宏靠 linux: CC += -D__LINUX 这类**目标级变量追加**注入，编译规则只有 $(CC) -c < ，没有独立 CFLAGS 通道。GNU make 规定：变量在命令行定义后，makefile 内（含目标级）的 += 追加被**静默忽略**（make 4.4.1 实测：合成 Makefile CC = gcc + goal: CC += -DX，make goal CC=clang 得 CC=[clang]，无 -DX 且无任何告警）。于是 make linux CC=clang 编出的是**没有任何平台定义**的代码：scalpel.h 的 __LINUX 分支（libgen.h/error.h include 与函数声明）整体跳过，helpers.c 里 __progname = basename(...) 的 basename 无原型可查，musl/clang 下报 helpers.c:64:14: error: incompatible integer to pointer conversion assigning to 'char *' from 'int'。这是\"能编过才有错、编不过还是错\"里的隐蔽形态：错误点（helpers.c 的赋值行）与真正根因（make 变量语义）隔了一个抽象层。"

## 推荐方案
**方法**: inject-platform-defines-into-commandline-cc

**说明**: 用命令行 CC= 覆盖编译器时，把工程需要的平台宏/旗标**显式并入命令行 CC**（如 CC="clang -D__LINUX -O2"），不要指望 makefile 里的 += 生效；目标级 CC += 即使部分生效也只是重复 -D（无害），因此显式注入是普适安全的。Conan 配方写法：cc = self.conf.get("tools.build:compiler_executables", default={}, check_type=dict).get("c", "clang")（dict 整取再索引，Conan 2.29 的 conf.get 不支持 ":c" 子键），然后 self.run(f'make linux -j1 CC="{cc} -D__LINUX -O2"')。判别法：看到一个 raw Makefile 工程"命令行传 CC 后报一堆奇怪的隐式声明/整型指针转换"，先 `make -pn` 或用合成 Makefile 实证目标级 += 是否进值，再查源码。

**修复命令**:
```
make linux -j1 CC="clang -D__LINUX -O2"
```

**验证**:
```
cd $HOME/tmp/scalpel-1.60-git20240110.6960eb2 && sh reproduce-E649.sh   # 合成 Makefile 实证 += 丢弃 + scalpel 无 -D__LINUX 的真实报错
```
