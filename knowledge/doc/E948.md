# E948: musl 的 realpath() 要求全路径存在（glibc 解析最长存在前缀）——上游对"尚不存在的输出目录"调 realpath 并无条件复制缓冲区，musl 下未初始化栈垃圾进入路径，表现为 forensic-soundness 假告警

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, portability, libc, musl
- **作者**: unknown
- **来源 PR**: pending

## 错误特征
```
non-empty output directory|forensic soundness|domain string|realpath|outputDirectoryOK|convertFileNames|incompatible integer to pointer
```

## 根因分析
"scalpel（1.60 维护分支，commit 6960eb2 快照，C 语言）在 convertFileNames() 里对 -o 指定的输出目录做 realpath(state->outputdirectory, fn) 后无条件 strncpy 回 state。realpath() 在路径分量不存在时的行为分歧：glibc 会解析\"最长存在前缀\"并把尾部拼回后成功返回；musl（OHOS libc）严格按存在性校验，返回 NULL 且不触碰 resolved 缓冲区（设备实测 realpath(\"/nonexistent/x\",b) 得 r=NULL、b 空、errno=2）。输出目录按 forensic soundness 语义本来就不该预先存在，因此设备上正常使用即命中：未初始化的栈缓冲被拷进 outputdirectory，随后的 outputDirectoryOK() 对垃圾路径 opendir/readdir 触发 \"ERROR: You have attempted to use a non-empty output directory. In order to maintain forensic soundness, this is not allowed.\"（实测 10/10 循环命中；栈垃圾内容非确定，单次运行偶可侥幸通过）——报错文案与真实故障（libc 差异）毫无关联，是典型的\"错误文案误导归因\"。"

## 推荐方案
**方法**: check-realpath-return-before-copy

**说明**: 对 realpath() 的返回值判空后再复制：if (realpath(path, fn)) { strncpy(...); }——失败时保留原路径即可（相对路径由调用方语义保证），不要试图手工拼前缀去模拟 glibc 行为。识别该类缺陷的快速探针：musl 下 realpath("/nonexistent/x", buf) 返回 NULL，glibc 下返回 "/nonexistent/x"；看到"对输出/临时目录的路径在程序里变成随机字符串"或"目录存在性校验报错但路径打印出来是乱码"时优先怀疑这一对差异。补丁保持平台中立（判空），不要写 #ifdef __OHOS__ 之类的平台宏（会被 PF5/上游审查拦截）。

**修复命令**:
```
clang -D__LINUX -O2 -o scalpel helpers.c files.c scalpel.c dig.c prioque.c base_name.c -lm && printf 'html\ty\t100000\t<html\t</html>\n' > scalpel.conf && ./scalpel -c scalpel.conf -o carved_out image.img
```
