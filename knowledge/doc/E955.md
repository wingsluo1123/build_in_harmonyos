# E955: Unix compress(.tar.Z, LZW) 源码包：conan get() 落入 zip 分支报 BadZipFile，init-build 按 gzip 解失败，设备 toybox gzip 无 LZW

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, source-download, url-extension
- **作者**: unknown

## 错误特征
```
BadZipFile.*File is not a zip file.*\.tar\.Z|\.tar\.Z.*BadZipFile|解压失败: not a gzip file|gzip: .*\.Z: not in gzip format|gzip: .*: not gzip
```

## 根因分析
.tar.Z 是 Unix compress(1) 的 LZW 流（魔数 1F 9D），不是 gzip。conan.tools.files.unzip() 只按扩展名识别 tar.gz/tgz/tbz2/tar.bz2/tar/gz/tar.xz/txz，其余一律交给 zipfile，于是 get() 报 "BadZipFile: File is not a zip file"（与 E483 同签名但根因不同：URL 有扩展名，只是格式不受支持）；ohc init-build 的 _guess_tar_format() 对未知扩展名默认 tar.gz，报 "解压失败: not a gzip file"；鸿蒙设备用户态是 toybox，其 gzip 不含 LZW 解码，gzip -dc/zcat 在 CI 设备上同样失败；source() 阶段 profile 的 buildenv 尚未生效，cmake -E tar（libarchive 支持 compress）是否在 PATH 不受配方控制。

## 推荐方案
**方法**: recipe-inline-python-unlzw

**说明**: source() 里不用 get()：download(url, file, sha256=...) 取回 .tar.Z，用配方内置的纯 Python LZW 解码（gzip unlzw.c 的约 50 行移植）得到 tar 字节流，再用 tarfile 逐成员解出（剥顶层目录、拒绝绝对路径与 ..）。不依赖构建机或设备上的 gzip/uncompress/cmake，x86 runner 与鸿蒙设备行为一致；download() 支持 CI 预下载改写后的 file:// URL。

**修复命令**:
```
download(self, src["url"], archive, sha256=src["sha256"]); tar_bytes = _unlzw(open(archive, "rb").read()); tarfile.open(fileobj=io.BytesIO(tar_bytes))
```

**验证**:
```
head -c 2 <archive> | od -An -tx1   # 输出 1f 9d 即 compress(LZW)；1f 8b 才是 gzip
```
