# E956: Bind transfer archive top-level layout to the production wrapper namespace

## 基本信息
- **严重度**: 2
- **类别**: packaging, runtime, evidence, transfer
- **作者**: 2301_80739235

## 错误特征
```
archive transfer RC0 but production wrapper reports missing <task-root>/<bundle>/<entrypoint>
```

## 根因分析
Archive byte identity and successful extraction do not prove that the extracted namespace matches the paths resolved by the production controller. Archiving the contents of a named bundle directory removes its top-level component, so the target receives <task-root>/archives and <task-root>/candidate-manifest.tsv while the wrapper requires <task-root>/bundle/archives and <task-root>/bundle/candidate-manifest.tsv. A strict wrapper must reject this before preparation or launch.

## 推荐方案
**方法**: explicit-top-level-archive-and-postextract-namespace-check

**说明**: Treat the archive root name as a frozen contract field. Add the unique directory with an explicit archive name, compare all members against that prefix, and make the production wrapper validate the same canonical paths. If a wrong-layout transfer has already produced a task root, preserve its receipts, prove the result/execution roots and foreign processes are absent, clean only the task-owned root, and create a successor rather than repairing the consumed run in place.

**修复命令**:
```
python tarfile.add(bundle, arcname="bundle"); inspect names; transfer; read back bundle/w3-transaction.sh and bundle/candidate-manifest.tsv; wrapper preflight
```

**验证**:
```
Inspect archive member names before transfer; require the named root and root-relative members; perform two remote byte-count/SHA-256 readbacks; after extraction read back exact entrypoint, manifest, and cache paths below the expected root; run the wrapper preflight before any prepare or launch.
```
