# E957: Repair generated component pkg-config contracts and mandatory public provider edges

## 基本信息
- **严重度**: 1
- **类别**: conan, pkg-config, components, include-path, provider-contract
- **作者**: 2301_80739235

## 错误特征
```
fatal error: 'opusfile.h' file not found|fatal error: 'ogg/ogg.h' file not found|dependency opusfile found but public provider edge missing
```

## 根因分析
A Conan provider can expose libraries through a named component while its inherited includedirs still point only at the package root include directory. PkgConfigDeps generates that component .pc from component metadata, so mutating a temporary root cpp_info object in the consumer may not affect the generated Cflags. Meson then reports the dependency found although compilation cannot resolve the nested public header. Even when the component include/lib metadata is complete, an early no-repair return can still omit a required public pkg-config edge such as `ogg` for `opusfile.h`'s `ogg/ogg.h` include.

## 推荐方案
**方法**: narrow-post-generation-provider-contract-repair

**说明**: Validate the exact header and library in the dependency package, run PkgConfigDeps normally, then strictly parse and repair only the affected generated component .pc. Preserve Conan-generated name and version, require exact public `Requires` edges, and reject ambiguous or malformed files. Do not take the no-repair fast path when a required edge still needs enforcement.

**修复命令**:
```
PkgConfigDeps.generate(); validate and rewrite only opusfile.pc to include/opus and -lopusfile while requiring exact `Requires: ogg opus`
```

**验证**:
```
Run a strict rewrite matrix and mandatory-edge positive/negative matrix, then require fresh isolated conan install --build=never with regular `ogg.pc` and exact `Requires: ogg opus`; finally require a single-launch target build with all 24 upstream entries and the installed-package flow passing.
```
