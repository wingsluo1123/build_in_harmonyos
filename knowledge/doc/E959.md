# E959: POSIX path conversion must canonicalize case through directory enumeration

## 基本信息
- **严重度**: 2
- **类别**: portability, filesystem, case-sensitivity, evidence, path-resolution
- **作者**: 2301_80739235
- **来源 PR**: 6478

## 错误特征
```
PathConversion.SimpleTest expected canonical lowercase path but received the input case after normalized path_exists succeeded
```

## 根因分析
A POSIX implementation that returns immediately after path_exists() on the separator-normalized spelling cannot distinguish a case-insensitive lookup from an exact directory-entry spelling. On a case-insensitive POSIX mount, an input such as tests\\files\\PATHS\\EMPTY.TXT therefore returns the caller's uppercase spelling and bypasses the glob-based case reconstruction required by the API contract. The same implementation behaves correctly on a case-sensitive mount only because the normalized lookup fails and execution falls through to glob().

## 推荐方案
**方法**: canonical-glob-after-separator-normalization

**说明**: Normalize separators first and always use the existing glob-based resolver on POSIX. Do not short-circuit on path_exists(posix_path), because that predicate reports reachability but not the directory entry's original case. Keep the direct unmodified-path behavior in the Windows implementation, where the API contract explicitly differs.

**修复命令**:
```
apply the patch to the POSIX resolver; run the focused upstream path conversion test and the complete package test command
```

**验证**:
```
Exercise a real existing fixture with exact spelling, separator-only variation, case variation, and missing input on both case-sensitive and case-insensitive mounts. Require path_exists(to_native_path(input)), exact canonical spelling where the contract promises it, deterministic first-match ordering for ambiguous components, and an empty result for no match. Run the production upstream path-conversion test after the patch chain is applied.
```
