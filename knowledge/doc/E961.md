# E961: Conan dependency metadata must bind header and linker contracts together

## 基本信息
- **严重度**: 2
- **类别**: build-system, meson, linking, conan, dependency
- **作者**: 2301_80739235
- **来源 PR**: 6478

## 错误特征
```
dependency found and headers compile but linker reports undefined symbols because generated pkg-config Libs is empty
```

## 根因分析
Meson can report a dependency as found when pkg-config provides a version and include directory, while an incomplete package metadata record emits no library in Libs. The consumer then compiles headers successfully but fails at final link with undefined provider symbols. Header-layout repair alone cannot establish a link closure.

## 推荐方案
**方法**: generated-pkgconfig-link-closure

**说明**: Use a task-local metadata normalizer only when the package folder proves both header and library presence. Set the module name expected by the consumer, append exactly one provider library flag, and fail closed on missing or malformed metadata.

**修复命令**:
```
inspect generated <module>.pc and production linker command; rebuild with the same package revision
```

**验证**:
```
Bind the exact dependency package revision; verify the public header and provider library under the package folder; force the canonical pkg-config module name before generation; inspect generated Cflags and Libs; require a production link that resolves provider symbols.
```
