# E962: SysV 多操作信号量迁移需要跨进程状态机与命名共享段扩容握手

## 基本信息
- **严重度**: 2
- **类别**: ohos, threading, ipc, synchronization
- **作者**: 8B7F

## 错误特征
```
SIGSYS.*shmget|SIGSYS.*semget|shm_open.*No such file or directory.*resize|check-shm-resize.*SegFault
```

## 根因分析
OHOS 沙箱的 seccomp 在 SysV IPC 入口发 SIGSYS；简单 POSIX semaphore 逐操作替换无法保留原 semop 数组对多个计数器的原子状态转移，而命名共享段重建时读端可能在 shm_unlink 与新 shm_open 之间附着并得到 ENOENT 或旧大小映射。

## 推荐方案
**方法**: posix-named-shm-process-shared-state-machine

**说明**: 将私有 SysV 共享段替换为稳定键名的 POSIX shm_open/ftruncate/mmap，把多个 semaphore 计数器放入命名共享映射，以 PTHREAD_PROCESS_SHARED mutex/condition 原子维护读者数与写者标志；按期望大小重试扩容附着，并显式保留原权限判定。

**修复命令**:
```
构建时仅替换私有后端源码；ctest --output-on-failure -j1；安装后运行独立消费者；核对上游注册数和完整 PASS 数相等。
```

**验证**:
```
枚举原 semop 数组的状态转移并以进程共享 mutex/condition 在一个临界区复现；扩容通知传递期望帧大小，读端有界重试 ENOENT/欠长映射；完整运行注册上游跨进程、扩容、权限测试和安装后消费者。
```
