# E963: Header-layout fallback must preserve upstream include contracts

## 基本信息
- **严重度**: 2
- **类别**: headers, build-system, meson, conan, dependency
- **作者**: 2301_80739235
- **来源 PR**: 6478

## 错误特征
```
dependency found but public header missing because package exports nested include layout
```

## 根因分析
A dependency can be resolved by pkg-config and expose a valid library while installing a public header below a vendor or API-family subdirectory. If several consumer headers include the historical basename and the generated Cflags expose only the package include root, compilation fails at whichever translation unit is compiled first even though dependency().found() is true. Changing the dependency version or disabling the feature hides the mismatch rather than repairing the public contract.

## 推荐方案
**方法**: ordered-header-layout-fallback

**说明**: Retain the canonical basename include first at every production boundary, then accept only the known API-family subdirectory path. Emit a hard compile error when neither path exists, so a missing dependency cannot silently become a disabled feature.

**修复命令**:
```
inspect generated Cflags and compile the original production include site against the published package
```

**验证**:
```
Bind the dependency package revision and generated include roots; verify the header at each candidate path; compile every production include site with the same ordered __has_include fallback; require the library and feature dependency to remain enabled.
```
