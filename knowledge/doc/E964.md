# E964: 无 TESTS 的 check-only 示例依赖应定向修正编译路径并实跑文档场景

## 基本信息
- **严重度**: 2
- **类别**: ohos, autotools, dependency, testing
- **作者**: 8B7F

## 错误特征
```
check_PROGRAMS.*example|fatal error.*hunspell.hxx.*file not found|make check.*no tests
```

## 根因分析
Automake 的 check_PROGRAMS 只在 make check 时构建示例，不会自动把它作为 TESTS 运行；示例独有的可选依赖若公开头位于包的嵌套 include 子目录，而生成 pkg-config Cflags 只有 include 根目录，便会在示例编译期失败。全局改依赖元数据会把仅用于示例的修复扩散到库消费者，也无法补足未派发的示例运行证据。

## 推荐方案
**方法**: check-only-include-and-explicit-example-dispatch

**说明**: 保留真实依赖与 make check 构建入口，先以实际包文件证明嵌套头目录，再用上游示例专用的依赖 CFLAGS 覆盖它；根据 README 或上游 runner 的真实输入逐例执行并分别计数，不把构建成功当作测试通过。公共库与其他依赖的编译标志保持原样。

**修复命令**:
```
设置目标示例专用的 FOO_CFLAGS=-I<已证实的依赖头目录>；make check；按上游文档逐例执行 example 并断言退出码和实际语义输出。
```

**验证**:
```
盘点 Makefile.am 的 check_PROGRAMS 与 TESTS、README 的每组输入；证明依赖包头文件确实存在；只给上游示例的依赖 CFLAGS 设置精确 -I；运行 make check 和每条文档示例并校验非空语义输出；安装后用独立消费者调用公开 API。
```
