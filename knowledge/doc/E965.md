# E965: WrapDB auxiliary patch URLs need deterministic mirror projection

## 基本信息
- **严重度**: 2
- **类别**: network, build-system, conan, evidence, test-framework
- **作者**: 2301_80739235
- **来源 PR**: 6478

## 错误特征
```
wrapdb get_patch redirect to GitHub timeout while recipe-level download bypasses CI mirror rewrite
```

## 根因分析
The CI pre-download mirror transform covers URLs visible in conandata.yml only until it restores the official file. A recipe-level download() of a WrapDB get_patch endpoint then follows a redirect to GitHub and can time out on a restricted worker. The WrapDB endpoint exposes a deterministic release identifier, so the byte-equivalent release archive can be projected to an approved mirror without changing the canonical metadata.

## 推荐方案
**方法**: deterministic-wrapdb-release-mirror

**说明**: Preserve the WrapDB URL, filename, and digest as canonical provenance. For an exact /v2/<release>/get_patch URL, try the corresponding mesonbuild/wrapdb release archive through one approved mirror, then the official endpoint. Never accept a proxy response without the declared SHA-256.

**修复命令**:
```
conan create <recipe> -pr:h <ohos-profile> -pr:b default --build=<package> with WrapDB release projection
```

**验证**:
```
Derive the release URL only from the exact WrapDB endpoint shape; download it with Conan's normal hash-verified API; compare bytes and SHA-256 to the declared patch digest; retain the official endpoint as the final fallback and remove only a regular partial destination after failure.
```
