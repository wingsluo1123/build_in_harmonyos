# E967: OHOS SDK 缺可选 llvm-strip 时旧 Makefile 剥离步骤误拦成功链接的 CLI

## 基本信息
- **严重度**: 2
- **类别**: build-system, cross-compile, host-tools
- **作者**: 9142
- **来源 PR**: 13010

## 错误特征
```
OHOS target llvm-strip missing:|strip: Unable to recognise the format of the input file
```

## 根因分析
旧 Makefile 在成功链接后强制剥离可执行文件。x86 宿主 strip 不识别 OHOS AArch64 ELF；本地 NDK 有 llvm-strip，但 CI NDK 的编译器实际路径下没有 llvm-strip，若配方强制要求它就会在 build() 抛出 Invalid configuration。剥离符号不是程序正确性、签名或功能测试的必要条件。

## 推荐方案
**方法**: skip-optional-strip

**说明**: Makefile 只改为可配置 $(STRIP)；OHOS 构建显式传 STRIP=:（shell no-op），不依赖特定 SDK 的 llvm-strip，也不回退 x86 宿主 strip。由 package/test_package 真正运行未剥离的目标程序并验证功能。

**修复命令**:
```
make STRIP=: GPP="$CXX" CPP="$CXX -c $CXXFLAGS" LD="$CXX" LDLIBS='-lm -static'; qemu-aarch64 ./consumer crispr-report.txt
```

**验证**:
```
CONAN_HOME=/data/harmony-compact/.conan2-ohos conan create archives/p/pilercr/1.06 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64; 检查日志 STRIP=:、qemu-aarch64 消费者输出 PASS、exit=0；CI 本机无 llvm-strip 时复查同一用例执行
```
