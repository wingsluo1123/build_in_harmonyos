# E968: 关闭 NLS 的旧 intltool configure 仍误检 XML::Parser，须按 USE_NLS 条件化且保留 po/check 工具

## 基本信息
- **严重度**: 2
- **类别**: compat, ohos, autotools, toolchain
- **作者**: 8B7F

## 错误特征
```
XML::Parser perl module is required for intltool|PL_markstack_ptr: symbol not found
```

## 根因分析
上游生成的 configure 在 --disable-nls 得到 USE_NLS=no 后仍无条件执行 perl -e "require XML::Parser"；当前 OHOS 制品仓的 XML::Parser XS 扩展又与设备 Perl ABI 不兼容，报 PL_markstack_ptr: symbol not found。直接删除整个 intltool/gettext 依赖并不等价，因为无条件 po 子目录的 make check 仍执行 intltool-update --pot/-m。

## 推荐方案
**方法**: conditional-nls-xml-check

**说明**: 在确认 --disable-nls 和 po 的 all-no 语义后，只把生成 configure 的唯一 XML::Parser 检查守卫改为 test "$USE_NLS" = "yes"；保留真实 intltool/gettext 构建工具并修正本任务过时 shebang，不能伪造 XML::Parser 成功。

**修复命令**:
```
在 Conan build() 中先校验生成 configure 目标字符串恰好出现一次，再将 if test "x" != "xno-xml"; then 替换为 if test "$USE_NLS" = "yes"; then；执行 conan create、make check 与 test_package。
```

**验证**:
```
对当前源码精确定位生成 configure 的唯一 XML::Parser 守卫；以 --disable-nls 配置并运行完整 make check，确认无 XML::Parser require、po/check 仍正常执行；再运行安装后消费者测试并核对日志/回执 SHA-256。
```
