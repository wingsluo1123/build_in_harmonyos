# E969: OHOS shell time-zone tools break: no Olson tree (musl resolves TZ names only from packed tzdata, accepts absolute TZ path) and toybox date lacks --date / rejects ISO 'T'

## 基本信息
- **严重度**: 2
- **类别**: ohos, portability, musl, runtime, shell
- **作者**: nyaco3 <aqjCItYW1QmEJQuF.gcw_XDpqZ8sO@noreply.gitcode.com>

## 错误特征
```
Unknown option 'date=|date: bad date [0-9]{4}-[0-9]{2}-[0-9]{2}T|can't cd to /usr/share/zoneinfo|cd: /usr/share/zoneinfo: No such file or directory
```

## 根因分析
三处运行期假设在鸿蒙 PC 上同时失效。①无展开的 Olson 目录：OHOS NDK libc.a 字符串只含 /etc/tzdata_distro/tzdata、/etc/zoneinfo/tzdata、/usr/share/zoneinfo/tzdata（打包格式）与 persist.time.timezone，脚本里 cd /usr/share/zoneinfo 或按目录遍历时区名直接失败（与 E315 设备调查一致）。②OHOS musl 对 TZ=Area/City 只查上述打包库、不认 TZDIR；但 TZ=<绝对路径 TZif 文件> 可用（NDK clang 静态探针 qemu-aarch64 实测：绝对路径 → JST，按名字 → 回落 UTC 且缩写变成 "Asia"）。③用户态 date 是 toybox：date --version 返回 0（GNU 探测误判成立），但没有 --date 长选项（Unknown option 'date=@0'），且 -d 不接受 ISO 'T' 分隔（bad date 2024-07-01T09:00），接受空格形式与 @epoch。

## 推荐方案
**方法**: tzdir-override-absolute-tz-plus-bundled-tzdata

**说明**: 补丁三点且不含平台宏：cd "${TZDIR:-/usr/share/zoneinfo}" 保留 Linux 缺省；TZ=${zoneinfo}/${name} 传绝对路径（参数本身已是绝对路径时原样使用：case ${2} in /*) _tz=${2} ;; *) _tz=${zoneinfo}/${2} ;; esac）；date --date=X 改为 GNU/toybox 共同子集 date -d X，并把 ISO 'T' 分隔替换为空格。配方 requires("tzdata/2026.3", visible=False)，package() 从其 lib/python*/site-packages/tzdata/zoneinfo 复制 TZif 文件到 share/zoneinfo（排除 *.py/__pycache__）；bin/ 下 #!/bin/sh wrapper（E037：鸿蒙可能无 /usr/bin/env） 用 readlink -f 定位前缀，TZDIR 未设置时指向随包 share/zoneinfo 后 exec sh 主脚本。

**修复命令**:
```
sed -i 's#cd /usr/share/zoneinfo#cd "${TZDIR:-/usr/share/zoneinfo}"#; s#date --date=#date -d #' <script>; 按名字的 TZ=${2} 改为 case ${2} in /*) _tz=${2};; *) _tz=${zoneinfo}/${2};; esac; TZ=${_tz}; 然后 refresh-patch --auto
```

**验证**:
```
env -i PATH=<toybox applets> TZDIR=<pkg>/share/zoneinfo sh <pkg>/libexec/tzdiff/tzdiff -HH -N -n 1 -t 2024-07-01T09:00Z Asia/Tokyo   # 期望 2024-07-01 18:00 JST
```
