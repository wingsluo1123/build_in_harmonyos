# E970: OHOS musl：program_invocation_short_name/program_invocation_name 头文件无声明、libc.so 不导出、libc.a 却有弱别名——extern 声明在 -static 下可过可跑，交付的动态链接报 undefined symbol

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, linking
- **作者**: 6822

## 错误特征
```
undefined symbol: program_invocation_short_name|undefined symbol: program_invocation_name|use of undeclared identifier 'program_invocation_short_name'
```

## 根因分析
musl 在 libc 内部把 program_invocation_short_name / program_invocation_name 定义为 __progname /

## 推荐方案
**方法**: progname-from-argv0

**说明**: 补丁里不再引用 program_invocation_*：main() 开头从 argv[0] 取 basename 存入程序自己的静态变量（glibc 的

**修复命令**:
```
static const char *progname = "<tool>"; ... int main(int argc, char *argv[]) { if (argc > 0 && argv[0] && *argv[0]) { const char *s = strrchr(argv[0], '/'); progname = s ? s + 1 : argv[0]; } ...；原 program_invocation_short_name 引用改为 progname，经 refresh-patch --auto 生成补丁
```

**验证**:
```
NDK=<OHOS SDK>/native; L=$NDK/sysroot/usr/lib/aarch64-linux-ohos; $NDK/llvm/bin/llvm-nm -D $L/libc.so | grep -E 'progname|program_invocation'; $NDK/llvm/bin/llvm-nm $L/libc.a | grep -E ' [BV] (__progname|program_invocation)'; printf '#include <stdio.h>\nextern char *program_invocation_short_name;\nint main(void){puts(program_invocation_short_name);return 0;}\n' > p.c; $NDK/llvm/bin/aarch64-unknown-linux-ohos-clang p.c -o p_dyn (ld.lld undefined symbol); $NDK/llvm/bin/aarch64-unknown-linux-ohos-clang -static p.c -o p_sta && qemu-aarch64 ./p_sta (链接成功并打印 p_sta)
```
