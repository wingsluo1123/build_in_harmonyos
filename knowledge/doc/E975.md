# E975: OHOS musl BUFSIZ=1024（glibc 8192）：fgets(buf, BUFSIZ) 把 1024 字节以上的行切段，编译零告警、运行时输出截断/串行

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, runtime
- **作者**: 9A43

## 错误特征
```
define BUFSIZ 1024|, BUFSIZ,|BUFSIZ 1024|BUFSIZ=1024|BUFSIZ is 1024
```

## 根因分析
BUFSIZ 是 libc 的实现常量（C 标准只要求 >= 256），OHOS SDK sysroot 的 musl stdio.h 定义为 1024，

## 推荐方案
**方法**: explicit-line-buffer-size

**说明**: 补丁里为程序自己的行缓冲引入显式常量（如 #define LINEBUF_SIZE 8192，与 glibc 行为一致），缓冲声明与所有对应的 fgets 长度参数统一改用它；不依赖 libc 常量、不需要平台宏，glibc/musl 同一代码路径

**修复命令**:
```
在源码中改 char buf[BUFSIZ + 1] -> char buf[LINEBUF_SIZE + 1]、fgets(buf, BUFSIZ, fp) -> fgets(buf, LINEBUF_SIZE, fp)，经 refresh-patch --auto 生成补丁；用 >1024 字节的输入行回归
```

**验证**:
```
grep -n 'define BUFSIZ' $OHOS_SDK/native/sysroot/usr/include/stdio.h; grep -rnE 'fgets\s*\([^;]*\bBUFSIZ\b' <src>; 构造一条 >1024 字节的输入行，在目标机（或同源静态重链副本经 qemu-aarch64）运行，与输入/glibc 版输出逐字节比对
```
