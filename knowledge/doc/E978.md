# E978: Conan recipe downloads need a bounded hash-verified mirror fallback

## 基本信息
- **严重度**: 2
- **类别**: network, build-system, conan, evidence
- **作者**: 2301_80739235
- **来源 PR**: 6478

## 错误特征
```
test-framework GitHub archive timeout after CI mirror predownload; direct recipe download bypasses mirror transform
```

## 根因分析
A CI wrapper may rewrite conandata.yml for predownload and restore the official bytes before conan create. A recipe-level download() call then consumes the restored single URL directly, so the wrapper's mirror list does not protect test-framework or other auxiliary inputs. When the worker cannot reach github.com, source() fails before compilation even though an approved mirror serves byte-identical content. Treating a non-empty response as success would permit HTML or truncated data to enter the package cache.

## 推荐方案
**方法**: bounded-source-mirror-fallback

**说明**: Keep the official URL and expected digest as the canonical provenance. For GitHub inputs, try the CI-approved gh-proxy.com prefix once through the normal Conan downloader, then try the official URL. On every exception remove only a regular destination file, retain all errors, and fail closed when no candidate passes the same SHA-256 check.

**修复命令**:
```
conan create <recipe> -pr:h <ohos-profile> -pr:b default --build=<package> with source() download fallback
```

**验证**:
```
Download each candidate into the same destination with the declared SHA-256; delete only a regular partial destination after a failed candidate; require the production source() path to succeed and preserve the official URL in conandata.yml.
```
