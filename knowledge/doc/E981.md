# E981: Bind cross-platform capability probes to production backend boundaries

## 基本信息
- **严重度**: 2
- **类别**: detection, portability, runtime, testing, evidence
- **作者**: 2301_80739235

## 错误特征
```
version-only consumer reported as native capability|callback buffer synthesized|dynamic core marker without guest execution|strtoull accepted signed or non-decimal backend hint
```

## 根因分析
A version smoke test and provider-level header inspection can succeed while the packaged application never creates a native window, never delivers mixer PCM to a real audio callback, or falls back to the normal CPU core. Markers placed in a callback or emitted at process startup can also create false positives without proving the preceding production stages. Unsigned numeric conversion alone is also insufficient: strtoull accepts a leading minus sign and can turn it into an unsigned maximum, so backend identifiers and dimensions need an explicit decimal lexical guard.

## 推荐方案
**方法**: production-boundary-capability-probe

**说明**: Gate probes with explicit test-only variables. Validate NativeWindow inputs before SDL initialization using a non-empty all-digits and positive-range parser, then emit a video marker only after SDL_RenderPresent or SDL_GL_SwapWindow. Inject a bounded signal at the application mixer output before final conversion and let the OHAudio callback read finite non-zero samples without writing. Select the dynamic core and require both its production entry marker and output from a guest command.

**修复命令**:
```
SDL_VIDEODRIVER=nativewindow SDL_RENDER_DRIVER=opengles2; SDL_AUDIODRIVER=ohaudio; core=dynamic with guest sentinel
```

**验证**:
```
Build one installed application candidate; run separate video, audio, and dynamic-core invocations; require exact backend names, a marker after the production present/callback boundary, and a guest-produced sentinel; reject missing, dummy, offscreen, synthesized, static-only, signed, non-decimal, zero, and overflow tuple values.
```
