# E986: "i386-only 的 C++ 压缩器移植到 aarch64/LP64 的三类系统性雷区：分配器单元粒度假设（4+4+4 布局溢出）、carryless 区间编码器状态必须钉死 32 位回绕、裸 DWORD 档案头随字长漂移；附 C++11 UDL 词法错误与平台 smoke 发现旗标契约"

## 基本信息
- **严重度**: "2"
- **类别**: portability, memory, aarch64, compression, i386-era
- **作者**: "Awstme"
- **来源 PR**: "pending（feat/ppmd-20050811 交付 PR）"

## 错误特征
```
"Segmentation fault (core dumped) ./ppmd"
```

## 根因分析
"机理链（ppmd 20050811 = PPMd variant I，HarmonyOS aarch64 + clang 15.0.4 实测）：(1) 分配器：SubAlloc.hpp 以 enum UNIT_SIZE=12 为粒度并假设单元内存上的结构是 4+4+4=12 字节（i386 指针 4 字节）；LP64 下 PPM_CONTEXT=4+8+8=20、MEM_BLK=8+8+8=24、STATE=2+8=10，结构溢出单元边界、pm+pm->NU 步长错位，编码立即段错误（rc=139、产物 0 字节）；修法是按 __LP64__ 把粒度提到 3*sizeof(DWORD)=24 并保持两个不变量：sizeof(PPM_CONTEXT)=20<=24、2*sizeof(STATE)=20<=24（每单元 2 状态的 >>1 寻址不变），配套 U2B=UNIT_SIZE*NU、UnitsCpy 按粒度逐字节拷贝。(2) 区间编码器：Coder.hpp 的 static DWORD low,code,range 依赖 32 位回绕丢弃进位（range=DWORD(-1) 必须=2^32-1、low<<=8 高位丢弃、-low&(BOT-1) 进位处理）；LP64 下 range 初值变 2^64-1，ariGetCurrentCount 首次除法得 0，解码从第一个符号失步（文本 5375B 解出 6786B 乱码；二进制偶发侥幸一致不能当通过证据）；修法是把编码器状态与 SUBRANGE 计数钉死 unsigned int——注意与(1)方向相反：分配器要 64 位 DWORD 容纳指针，编码器要 32 位保持回绕，不能全局 typedef 一刀切。(3) 档案头：ARC_INFO{DWORD signature,attrib; WORD...} 用 fwrite(&ai,sizeof(ai)) 整结构落盘，LP64 头从 canonical 16 字节变 24；修法是字段钉死 unsigned int，od 实测前 16 字节为 magic(4)+attrib(4)+info(2)+FNLen(2)+time(2)+date(2)。(4) 编译期：C++11 把紧邻字符串字面量的 __DATE__ lex 成用户自定义字面量后缀，clang 报 no matching literal operator，空格必须加在字面量与宏之间。(5) 平台 smoke 探针只试 --version/--help/-V/-h 并要求 rc=0，上游 CLI 用法错误 return -1(255)；解法是旗标为唯一参数时接受标准发现旗标退出 0，其余调用路径保持上游行为。移植前哨：FreeBSD ONLY_FOR_ARCHS=i386 / Debian Architecture: i386 标注往往同时预言以上多类问题"

## 推荐方案
**方法**: "lp64-granule-plus-32bit-coder-pin"

**说明**: "按体检顺序逐类排查并分别修复：① grep 分配器粒度（UNIT_SIZE/enum）确认落位结构的字长假设，LP64 下把粒度提到 max(落位结构尺寸) 并保持每单元状态数不变量；② grep 编码器状态（DWORD low/static ... range）把回绕敏感状态钉死 unsigned int；③ grep fwrite(& 与 sizeof(结构体) 把落盘结构字段钉死固定位宽保持格式兼容；④ 字符串字面量紧邻 __DATE__/__TIME__/__FILE__ 的加空格修 UDL；⑤ 平台 smoke 探针要求 --version/--help rc=0 时以'旗标为唯一参数'的可移植补丁接受发现旗标。禁止用二进制侥幸一致当通过证据（编码器失步在部分数据上可侥幸一致）；禁止全局把 DWORD typedef 成 32 位（会反过来破坏需要指针宽度的分配器 Stamp/next 字段）"

**修复命令**:
```
"./ppmd --version && printf 'text' > t.txt && cp t.txt t.ref && ./ppmd e -s t.txt && rm t.txt && ./ppmd d -s t.pmd && cmp t.ref t.txt && echo IDENT"
```

**验证**:
```
"clang++ -c -O2 PPMd.cpp && clang++ -c -O2 Model.cpp && clang++ -O2 -o ppmd PPMd.o Model.o; ./ppmd --version; ./ppmd; echo $?; printf 'text' > t.txt && cp t.txt t.ref && ./ppmd e -s t.txt && rm t.txt && ./ppmd d -s t.pmd && cmp t.ref t.txt && echo IDENT; od -A d -t x1 t.pmd | head -2   # 期望：编译零 error；--version rc=0；无参 rc=255；IDENT；前 16 字节为 canonical ppmdi1 头（8f af ac 84 开头）。实测（2026-09-21 HarmonyOS aarch64/clang 15.0.4）：补丁链后 4 文件 x 5 参数组全部 e=0 d=0 IDENT；bin/ppmd sha256 76fcdea0012d087a24521a13159b23032f202175cb0d0557d0498c50c2ef45f0 与纯净树补丁链构建逐字节一致；未修编码器字长时文本 5375B 解出 6786B 乱码、75B 小文件解出 NUL 开头 junk"
```
