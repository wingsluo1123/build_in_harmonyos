# E990: toybox patch 对 CRLF 源码的上下文匹配失败，导致 refresh-patch dry-run 误报"补丁无效"

## 基本信息
- **严重度**: 2
- **类别**: compat, toolchain, patch
- **作者**: 3BCD

## 错误特征
```
dry-run 失败|Hunk [0-9]+ FAILED|patch.*crlf|patch.*line ending|refresh-patch.*无有效新补丁
```

## 根因分析
鸿蒙默认 /usr/bin/patch 是 toybox 0.8.12，其上下文匹配把 CRLF 行尾当作差异，对 CRLF 源码文件应用 LF 补丁时报 "Hunk N FAILED"。refresh-patch 的 dry-run（patch --dry-run -p1）因此失败，丢弃本应有效的补丁（log: "0001-xxx.patch: dry-run 失败"）。注意：Conan 实际应用补丁用的是 patch_ng（纯 Python），对 CRLF 源 + LF 补丁能正确匹配，CI 不受影响——此问题只卡本地 refresh-patch 生成环节。

## 推荐方案
**方法**: 将 orig 与 work 中被改文件的 CRLF 统一归一化为 LF 后重新生成补丁（补丁本身即 LF；CI 用 patch_ng 应用，对 CRLF/LF 源皆正确）。具体：对 orig/<rel> 与 work/<rel> 各做 data.replace(b"\r\n", b"\n")，重建 edit-tracker 基线后重跑 refresh-patch --auto。无需改 conandata/补丁格式。

**说明**: CRLF 源文件归一化为 LF 后再生成补丁，绕过 toybox 匹配缺陷；patch_ng 兼容性不受影响

**修复命令**:
```
python3 -c "for p in ('<orig>/<rel>','<work>/<rel>'): d=open(p,'rb').read().replace(b'\r\n',b'\n'); open(p,'wb').write(d)" && 重建基线 && ohc-run.py refresh-patch --auto <sw> <ver>
```

**验证**:
```
对 CRLF 文件用 toybox patch 应用 LF 补丁，观察 "Hunk 1 FAILED"；换 patch_ng.fromfile(patch).apply(strip=1, root=...) 则返回 True
```
