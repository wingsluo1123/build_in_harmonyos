# E993: init_build._promote_nested_source 在"构建文件位于 projects/ 子目录"的 C 包上误判，把 projects/ 提升为源码根并删除 src/lib/ 顶层文件

## 基本信息
- **严重度**: 2
- **类别**: detection, hmdfs, build-system, make, init-build
- **作者**: A77A

## 错误特征
```
嵌套源码检测: 找到源码在 projects|\.work 顶层只剩 VC6|\.work 只有 projects 内容|提升完成: projects
```

## 根因分析
_promote_nested_source(_find_source_subdir) 仅按 configure/CMakeLists.txt/Makefile/meson.build 标记识别源码子目录；libsoil 这类"构建文件放在 projects/ 子目录、源码在顶层 src/"的 C 包，顶层无标记，递归命中 projects/makefile（HMDFS 大小写不敏感 FS 上 projects/Makefile 与 projects/makefile 目录同名匹配），于是把 projects/ 内容提升到源码根，并删除真正的顶层文件(src/lib/测试图)。

## 推荐方案
**方法**: 手动修复源树：1) rm -rf 误提升的 .orig/.work；2) mkdir .orig && tar xzf --strip-components=1 -C .orig <tarball>（保留顶层布局，勿触发 F068）；3) cp -a .orig/. .work/；4) 写 .orig/.tarball-sha256；5) 重建 edit-tracker 基线（python -c "from ohc.edit_tracker import snapshot; snapshot('<work>')"）。配方 build() 直接 cd 到 projects/makefile 用 make CXX=clang 构建（conanfile 用绝对路径 cwd=self.source_folder/...）。

**说明**: C 包构建文件在 projects/ 子目录时，绕过 F068 嵌套提升，手动重建顶层布局；conanfile 用绝对路径驱动子目录 makefile

**修复命令**:
```
tar xzf --strip-components=1 -C .orig <tarball> && cp -a .orig/. .work/
```

**验证**:
```
ls .work/ | grep -E 'src|lib' && test -f .work/src/SOIL.c   # 修复后应有顶层 src/ 与 lib/
```
