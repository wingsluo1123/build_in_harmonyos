# E999: FUSE 文件系统测试必须拆分无特权 CLI 契约与授权挂载能力

## 基本信息
- **严重度**: 2
- **类别**: limitation, ohos, runtime, testing
- **作者**: 4C48

## 错误特征
```
/dev/fuse.*Permission denied|fuse_session_mount.*Permission denied|open[(].*[/]dev[/]fuse|--version.*non-zero|--help.*non-zero|bad /etc/fstab|prove.*not found|gcc.*Permission denied
```

## 根因分析
FUSE 文件系统程序同时包含可无特权验证的参数解析/可执行性契约和需要内核设备、挂载权限、文件系统镜像的运行时契约。vendored 上游 suite 还可能不接入顶层 make check，必须先完整盘点测试文件，再区分 runner、镜像、mount 和 /dev/fuse 阻塞。通用 CI 的 version/help smoke 还可能把上游约定的非零退出码误报为 warning，不能用单一返回码替代分层测试。

## 推荐方案
**方法**: capability-gated-fuse-tests

**说明**: test_package 固定验证安装后的二进制、版本输出、帮助输出和错误参数路径；递归盘点上游测试并记录 discovered/executed/passed/failed/blocked；单独检测 prove、/dev/fuse、可用 ext2 镜像和挂载权限，满足条件时再执行只读挂载闭环。

**修复命令**:
```
"$BIN/ext2fuse" --version; rc=$?; test "$rc" -eq 9; test -r /dev/fuse && test -w /dev/fuse
```

**验证**:
```
find tests/pjd-fstest-20080412/tests -name '*.t' | wc -l; $BIN/ext2fuse --version; test $? -eq 9; test -r /dev/fuse && test -w /dev/fuse
```
