# DRAFT-11418 — OHOS SDK sysroot 自带 version.h 遮蔽项目 shim 头（-idirafter 降级）：让常规 tools 目标依赖上游已有拷贝规则

- **条目 ID**: `DRAFT-11418-uboot-ohos-sysroot-header-shadow`
- **严重度**: 2（单头文件遮蔽、编译期即暴露；修复方向明确可复用）
- **类别**: toolchain, include-path, build
- **触发工具/阶段**: clang | make | gcc — conan_build
- **来源**: u-boot 2026.07 适配（task #11418，OHOS PC 真机 2026-09-29，上游 denx 发行包 + 补丁）

## 错误特征

```
tools/mkenvimage.c: In function 'main':
error: 'PLAIN_VERSION' undeclared (first use in this function)
```

## 场景

host 工具源文件以**尖括号**包含 `<version.h>`（u-boot 的 shim 头，
转发到生成的 `include/generated/version_autogenerated.h`）。而 host
工具编译的 UBOOTINCLUDE 被 `tools/Makefile:325` 降级为 **-idirafter**
——语义是「系统头目录之后才搜索」。

u-boot host 工具编译的 include 解析顺序（真机实测）：

1. `-I` 路径（objtree 生成头）；
2. clang resource 目录；
3. SDK sysroot 系统头（`/usr/include/aarch64-linux-ohos`、
   `/usr/include`）——**OHOS SDK 自带 `/usr/include/version.h`**
   （clang 默认 include 路径第二级，SDK 兼容性系统头集合）；
4. `-idirafter` 的 UBOOTINCLUDE。

`mkenvimage.c` 的 `<version.h>` 在 objtree 下没有同名文件（常规
tools 目标不生成），落到第 3 级命中 SDK 的 version.h；u-boot 自己的
shim `include/version.h` 在第 4 级（-idirafter），永远搜不到 →
PLAIN_VERSION 未定义。Linux 构建机无系统 version.h，上游无感。

上游只有 `envtools`/`tools-only` 两个目标显式依赖 tools/version.h
拷贝规则（`Makefile:2510`），常规 `tools` 目标缺这个依赖。

## 推荐方案（patch 0004，真机验证）

常规 tools 目标改为 `tools: prepare tools/version.h`，复用上游已有
的拷贝规则（`tools/version.h: include/version.h FORCE` copy，
`VPATH=$(srctree)` 解析 prereq）。修复后 objtree/tools/version.h 进入
`-I` 路径（先于系统目录）命中 shim；shim 再经 -idirafter 找到
objtree/include/generated/version_autogenerated.h（SDK 无同名头，
不冲突）。与 envtools/tools-only 行为完全一致，零新机制。

**通用原则**：OHOS SDK sysroot 是完整的 Linux 兼容系统头集合，任何
「项目自带头与系统头同名 + 项目头在 -idirafter/后段」的组合都会被
遮蔽；修复方向要么把项目头提到 -I 前段（拷贝进 objtree），要么项目
内部改尖括号为引号（`"version.h"` 走源文件相对目录）。

## 影响

适用任何「host 工具构建 + 项目 shim 头与 SDK 系统头同名」在 OHOS 的
适配。SDK sysroot 的系统头集合比 Linux 发行版更大（为兼容性塞了很
多头），同名遮蔽概率高。排查特征：编译报「某宏未定义」且
`clang -###`/`gcc -H` 显示命中的是 sysroot 里的同名头而非项目头。

## 恢复

若 objtree 拷贝不可行（构建系统不支持 VPATH 解析），替代方案：

1. 项目内部把 `<version.h>` 改为 `"version.h"`（相对目录查找先于
   系统目录）；
2. 在 -I 前段强制加 `-include` 或 `-iquote` 项目头目录；
3. 上游若拒绝改动，构建配方在编译前手动 cp 头文件进 objtree。

选型原则：最小 diff 且与上游已有行为一致优先。

## 证据链

真机 2026-09-29（上游 denx 2026.07 发行包 + 补丁，reports/）：

- 真机实证：`mkenvimage.c:25` 尖括号 `<version.h>`，0001-0003 修复
  后构建推进到 mkenvimage 即 PLAIN_VERSION 未定义（build.log）；
- clang 探针证实 SDK sysroot 存在 `/usr/include/version.h`（SDK
  自带系统头），Linux 无此头故上游无感；
- 0004 修复后 `COPY tools/version.h` 出现在构建日志，mkenvimage 等
  host 工具全链编译通过；
- 详见 patches/0004-tools-version-h-for-host-tools.patch。

## 局限

1. 只验证了 version.h 一处遮蔽；其他同名头（如 limits.h、stdint.h）
   需逐个按同法排查；
2. 依赖 SDK 不带同名「第二级」头（version_autogenerated.h 等生成
   头无 SDK 同名者，当前成立）。
