# DRAFT — conan 纯 Python 依赖的 `site-packages` 布局不统一：路径不可写死版本号，否则静默漏依赖

> 触发事件：greenlet 3.5.6（PR #10408）第 2 轮 CI。
> pytest 已能启动，却在收集时报 `ModuleNotFoundError: No module named 'pygments'`
> （2026-10-02 CI 实测）。

## 相关既有条目（同族差异化定位）

| 既有条目 | 收录状态 | 问题面 | 本条的增量（差异化） |
|---|---|---|---|
| `DRAFT-pypi-wheel-vendor-python-dep-closure` | 草稿 | 依赖未发 ohpcd 时，按上游 lock 从 pypi 镜像 **vendor 纯 wheel** 组装 PYTHONPATH；含 pytest/pluggy/iniconfig/packaging/pygments 五 wheel | 那条讲「依赖**要不要 vendor、从哪来**」；本条讲「依赖已有 conan 制品，但**路径怎么定位**」——布局不统一导致静默漏项 |
| `DRAFT-python-ext-pytest-child-missing-ld-library-path` | 草稿 | 同一配方的毗邻失败面：子进程缺 `LD_LIBRARY_PATH` | 同一轮相邻两个失败，但机制不同：那条缺的是 `LD_LIBRARY_PATH`（加载器找 .so），本条缺的是 `PYTHONPATH` 项（解释器找模块） |
| `DRAFT-ohos-python-require-no-host-so` | 草稿 | Python 包不应依赖宿主 .so | 主题不同 |

**结论：本条为真增量**（无条目覆盖「conan 依赖 site-packages 布局不统一 → 静默漏注入」）。

## 错误特征

```
greenlet/3.5.6: upstream pytest: build-context site-packages injected:
  ['iniconfig', 'objgraph', 'packaging', 'pluggy', 'psutil', 'pytest']      ← 缺 pygments
...
  File ".../_pytest/_io/terminalwriter.py", line 13, in <module>
    import pygments
ModuleNotFoundError: No module named 'pygments'
```

**辨识要点**：
1. 报错点在 **pytest 内部**（`_pytest/...`），不在用户的收集目标里 —— 容易被误读为「pytest 自身/版本问题」。
2. 缺的是**一个**依赖而非全部 —— 因为只有部分依赖的布局与配方假设不符。
3. 前一行注入清单是**最直接的证据**：逐项核对名单，缺谁一目了然（所以注入结果必须打印）。

## 根因分析

配方用 `tool_requires` 引入 pytest 后，需把 build 上下文各依赖的 `site-packages`
注入 `PYTHONPATH`。若按固定布局拼路径：

```python
os.path.join(dep.package_folder, "lib", "python3.12", "site-packages")   # 写死版本号
```

则对布局**不是** `lib/python3.12/site-packages` 的依赖，匹配结果为 0 ——
**既不抛异常也不告警**，该依赖被静默漏掉。同图内其余依赖布局恰好匹配，
所以只有它一个缺失，进一步掩盖问题。

**证据（两轮 CI 日志差分）**：

| 轮次 | 路径写法 | 注入清单 |
|---|---|---|
| 第 2 轮 | `lib/python3.12/site-packages` | `[iniconfig, objgraph, packaging, pluggy, psutil, pytest]`（**缺 pygments**） |
| 第 3 轮 | `lib/python*/site-packages` | `[iniconfig, objgraph, packaging, pluggy, psutil, **pygments**, pytest]` |

由差分可断定：pygments 的布局**不等于** `python3.12`（本地未解出该制品，故不臆断其确切目录名）。

## 推荐方案

用 glob 覆盖多种布局，并把一个依赖的**全部**命中目录加入：

```python
_sites = sorted(glob.glob(os.path.join(dep.package_folder, "lib", "python*", "site-packages")))
```

`python*` 亦匹配无版本号的 `python`（`*` 可匹配空串）。配套两点：

1. **让注入可观测**：打印 resolved 依赖名单（本次正是靠它定位）；
2. **关键依赖缺失要告警**：对 pytest / psutil / objgraph 等未命中者显式 warning，
   不静默跳过。

## 禁止做法

- ❌ **不要**写死 `lib/python3.12/site-packages`（或任何具体版本号）——布局不统一是既有事实，
  写死会导致**静默漏依赖**。
- ❌ **不要**把 `No module named '<依赖名>'` 当作 pytest 缺陷去降级/换版本：报错位置在 pytest
  内部，缺的却是你自己注入的依赖，改 pytest 解决不了。

## 验证证据

- CI 两轮日志差分（上表）—— 写入清单从「缺 pygments」变为「含 pygments」。
- 本地契约测试：以两种布局（`python3.12` 与 `python`）模拟同一依赖图，
  修复后 pygments 与其余依赖全部被收录、`python` 仍被跳过、缺 pytest 仍显式告警。

## 查重结论

- 对 `site-packages` 布局、`lib/python/site-packages`、`python*/site-packages` 检索：**0 命中**。
- 对「依赖注入 PYTHONPATH」检索：命中 DRAFT-pypi-wheel-vendor-python-dep-closure（讲 vendor 来源），
  机制不同。
