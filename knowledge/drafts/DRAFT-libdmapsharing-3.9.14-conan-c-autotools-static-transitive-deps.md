# DRAFT-libdmapsharing-3.9.14-conan-c-autotools-static-transitive-deps
> conan 上 C/autotools 库：静态库传递依赖（缺失 .la、版本冲突、override 寻址、头/符号补齐）一体化适配解法

## 问题特征（真实日志片段/标记）
以下症状在同一任务中先后出现，均属静态传递依赖适配域：

- autotools mtime 丢序接管 maintainer 重生成：
  `cd . && /bin/sh .../missing automake-1.18 --gnu`
  `missing[85]: automake-1.18: inaccessible or not found`
  `*** [Makefile:434: Makefile.in] Error 1`（tests/Makefile、doc/Makefile 亦同，Error 127）
- 静态依赖缺 .la 被 libtool 拒绝：
  `libtool: error: '.../libavahi-client.la' is not a valid libtool archive`（先经 conan cache 直读，后经 staging 的 ohos-avahi-la 目录，均报 is not a valid libtool archive）
- conan 依赖图版本冲突与重复声明：
  `ConanException: Duplicated requirement: glib/2.84.0.1.1`
  `ERROR: Version conflict: Conflict between glib/2.84.0.1 and glib/2.84.0.1.1 in the graph. Conflict originates from avahi-glib/0.9_rc5`
- 头/符号补齐缺失：
  `fatal error: 'check.h' file not found`（库本体与 tests/unit-test.c）
  `fatal error: 'libsoup/soup.h' file not found`（test_package 消费者）
  `ld.lld: error: unable to find library -lavahi-avahi-client / -lavahi-avahi-common`
  `ld.lld: error: undefined symbol: g_libintl_gettext`、`dbus_bus_get_private` 等
- readonly_tmp 平台限制：
  `configure: error: C compiler cannot create executables`、`sed: can't read conftest.c`
- 只读 /tmp 测试失败：`tests/unit-test[506]: syntax error: unexpected ')'`（/bin/sh 解析 libtool wrapper 失败）
- package 阶段 automake 复现：`*** [Makefile:565: Makefile.in] Error 127`（doc/Makefile.in 前置 gtk-doc.make，.make 末被归一化）

## 根因

C/autotools 库经 conan materialize 后静态传递依赖呈现一组相互交织的根因：

1. **autotools mtime 分层归一化缺失**：release tarball 自带预生成 configure/Makefile.in，无需 autotools；但源码树经 conan export→source() copytree 物化时，configure.ac/aclocal.m4/*.am 的 mtime 被复制成新于对应生成文件，且 patch 阶段重写文件会再次刷新 mtime，GNU make 依 maintainer 规则唤醒 automake-1.18（OHOS 无 automake）→ 需对 mtime 分层（源码 2000 / aclocal.m4 2001 / 生成文件 2002），并把 *.make（如 gtk-doc.make）一并纳入，且须在全部补丁之后、./configure 之前作为最后一次源码变更，否则补丁重写会再次颠倒层级。

2. **静态库缺 .la**：avahi-glib 等静态包只装 .a 不装 .la，libtool 链接时执行静态归档依赖扫描要读取依赖的 .la。生成 .la shim 必须匹配 ltmain.sh 的 `func_lalib_unsafe_p`——其只接受**.la 前 4 行中某行**匹配 case glob `# Generated by <PACKAGE>*` 且 `$PACKAGE` 是字面 `'libtool'`（首轮写 `# Generated by libdmapsharing ...` 被判 not valid）；dependency_libs 还必须按真实库名拼装（`-lavahi-common`，而非 `-lavahi-avahi-common` 双前缀），并经 `-L<staging>` bake 进 configure 期 LDFLAGS 才能被 libtool 解析。

3. **conan 2 传递依赖版本冲突与 override 寻址**：①同一包在 requirements() 声明两次抛 `Duplicated requirement`；②avahi-glib 精确 pin glib/2.84.0.1 与 libsoup3 精确 pin glib/2.84.0.1.1 在图中冲突，普通 exact 声明不具备覆盖传递 exact pin 的能力，需 `override=True` 全图钉到 2.84.0.1.1；③override 依赖从 recipe 直接 self.dependencies 剥离，`self.dependencies["glib"]` 取不到，必须 BFS 遍历可达全图取回 package_folder，并把 glib/avahi 的 .pc shim 直接落盘到 self.generators_folder（PkgConfigDeps 可达目录），否则 configure 的 PKG_CHECK_MODULES 报 `Must have glib-2.0 installed`。

4. **readonly_tmp 与符号/头补齐**：OHOS /tmp 只读（erofs）致 clang 无法创建 conftest 可执行体（AC_PROG_CC 失败）→ 需检测并导出可写临时根；静态库被消费者链接时还缺 glib 附带 libintl（g_libintl_gettext）与 libsoup/check 头路径 → 需在 test_package 显式 require 直接依赖并经 CMAKE_EXE_LINKER_FLAGS 补 `-L<glib libdir> -lintl`。

## 修复方案（rec）
一体化（编号步骤，均在 conanfile.py / test_package，工作树未提交，由 HMBS 同步复跑真机预检）：

1. **autotools mtime 分层归一化**：新增 `_normalize_bootstrap_timestamps()`，在**所有 `_patch_*` 之后、`./configure` 之前**调用作为最后一次源码变更；按依赖链分层——源码 configure.ac/*.am/m4 设 2000、aclocal.m4 设 2001、生成的 Makefile.in/configure/config.h.in/*.in 设 2002；并**包含 `*.make`（gtk-doc.make）设为 2000**，避免 doc/ 的 maintainer 重生成；200x 远低于当次 configure 产物，`config.status --recheck` 亦不重跑 configure。

2. **静态依赖 .la shim**：`_fix_avahi_la()` 为 avahi-client/avahi-common/avahi-glib/avahi-gobject 生成最小 .la shim——第 2 行写 `# Generated by libtool (shim for avahi-glib, which ships no .la)`（匹配 `func_lalib_unsafe_p` 的首 4 行 glob），`name='lib{b}.la'` 保证结构完整；dependency_libs 用 `-L<staging> -l{d}`（去掉多余 `-lavahi-` 前缀，dbus 依赖加 `-L<dbus libdir> -ldbus-1`、glib gettext 加 `-L<glib libdir> -lintl`），并把 `-L<staging>` bake 进 `_configure_args()` 的 LDFLAGS 到达所有子 Makefile。

3. **conan override 寻址与 .pc 落盘**：requirements() 中 glib 仅保留**单一声明** `self.requires("glib/2.84.0.1.1", override=True)`；新增 `_glib_pkg()` 用 **BFS 遍历可达依赖全图**（经 libsoup3/avahi 链）取回 glib 的 package_folder，替换所有 `self.dependencies["glib"]` 直取；`_fix_glib_pc_files()` 把 glib-2.0/gobject/gthread/gmodule/gio 与 avahi-client/avahi-common 的 .pc shim **直接落盘到 self.generators_folder**（configure 经 conanbuild 的 PKG_CONFIG_PATH 可达），找不到时显式报错列出 BFS 所见。

4. **readonly_tmp 可写临时根**：`_hmbs_writable_tmpdir()` 按 `HMBS_TMPDIR > HMBS_PLATFORM_CAPABILITIES.tmpdir > TMPDIR` 探测可写临时根并导出 TMPDIR/TMP/TEMP，使 clang 能建 conftest 可执行体。

5. **头/符号补齐**：库本体与 tests/ 的 Makefile.{am,in} 补 `$(CHECK_CFLAGS)`/`AM_CPPFLAGS`（check.h）与 `-I`（libsoup/glib）；test_package/conanfile.py 显式 require 直接依赖（glib shared、libsoup3、avahi-glib、check）使 CMakeDeps 生成完整 target，CMakeLists 显式 find_package + target_link_libraries，并在 `CMAKE_EXE_LINKER_FLAGS` 追加 `-L<glib libdir> -lintl` 消除 g_libintl_gettext 未定义符号，嵌入 DT_RPATH 定位共享库。

6. **测试执行**：`_run_upstream_unit_test` 只运行真实 ELF（tests/.libs/unit-test 等取带 `\x7fELF` magic 者）绝不经 /bin/sh 解析 libtool wrapper；上游 13 例 OHOS 平台失败（/etc/services 缺失、无 avahi mDNS 守护进程、只读 /tmp）逐类打 ohos_feature gap，不删断言不跳测。

## 禁止策略
- 禁止用环境瞬态故障（SSH `exec request failed on channel 0`、HTTP 522）伪装成代码修复或空提交重触发——守则要求停止并等待环境恢复。
- 禁止删除测试断言、跳测或伪造通过，以规避 readonly_tmp / 平台能力 gap；平台 gap 应如实分类上报。
- 禁止在 requirements() 中重复声明同一包（Duplicated requirement）；普通 exact 声明不具覆盖传递 exact pin 能力。
- 禁止把 override 依赖写进 cpp_info.requires（其已从直接 cpp_info 剥离），链接信息须经实际依赖链转发或 BFS 取回。
- 禁止把 .pc shim 写进 configure 不可达的独立目录（必须以 generators_folder 可达为准）。

## 与相近条目的边界（查重）
- readonly_tmp / hmbs_platform_capabilities 命中为已有通用样板或相邻异因：本条目聚焦「静态传递依赖一体化」，只读 /tmp 仅为其中一环，不含任务独有内核，故本条目与其边界为「相邻但不同」。
- ccrtp 的 no_tests→demo 回归属 testing 域（测试口径），本条目为 compile/configure/链接域（静态传递依赖），相互独立不重复。
- 现存条目未覆盖的两个新内核：①「autotools mtime 分层归一化」（物化后 mtime 丢序唤醒 maintainer 规则，含 .make 与补丁后置）；②「libtool .la shim 兼容」（func_lalib_unsafe_p 首4行 glob 校验 + dependency_libs 拼装）。

## 适用判断
当且仅当同时满足：conan 打包的 C/autotools 库存在**静态传递依赖**（如 avahi/glib/libsoup 链），且至少出现下列一类症状——
- make 阶段 `missing automake-*`（maintainer 重生成）
- `not a valid libtool archive`（缺 .la）
- `Duplicated requirement` / `Version conflict in the graph`（需要 override 寻址）
- `file not found` / `unable to find library` / `undefined symbol: g_libintl_gettext`（头/符号补齐）
- `C compiler cannot create executables`/`Must have X installed`（readonly_tmp 或 .pc 不可达）

可按本条目 rec 的一体化步骤顺序依次打通；若仅命中其中一环且不涉静态传递依赖，则优先查对应单点条目。
