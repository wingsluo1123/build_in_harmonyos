# DRAFT-profanity-0.18.2-vendored-embed-synthetic-pc-forced-shell
> 远端依赖配方不可达时消费者侧静态内嵌：make-dist免自举+合成缺失pc+命令行强制可用shell重建
## 问题特征（真实日志片段/标记）
- libstrophe/0.14.0: Main binary package missing后触发远端旧配方源码重建
- 远端旧配方裸调自举在真机报毒化shell不可用，同指纹连续多轮复现
- PkgConfigDeps可见清单有expat但无openssl与zlib，标准探测永不通过
- 内嵌打通后暴露meson侧Unknown compiler与主链接unable to find library -lstrophe
- 平台能力恒为shell为单斜杠bin下sh，构建工具仅注入cmake加make加ninja加python3
## 根因
远端libstrophe无OHOS兼容二进制必须源码重建，但其远端旧配方缺autoconf声明且归档无预生成configure；本任务预检仅同步profanity单包目录，工作树内对libstrophe的RREV钉住加tool_requires加PATH前置加直跑链改写永不到执行位，06-41日志新特征串零出现证实不可达；消费者配方无法向依赖构建上下文注入缺失工具。同时PkgConfigDeps不生成openssl与zlib的pc，conanbuild聚合环境复写毒化SHELL，共享profile的clang路径已过期，三者叠加使任何远端重建路线均被同指纹证伪。
## 修复方案（rec）（编号步骤，含具体文件与命令）
1. archives/p/profanity/0.18.2/conanfile.py删除对libstrophe的requires，改加expat直接依赖，保留curl与sqlite3收敛与meson-only策略，requirements中zlib与openssl改为直接依赖以生成pc数据源。
2. archives/p/profanity/0.18.2/conandata.yml新增上游make-dist发布包URL与sha256，彻底摆脱autoreconf自举链，删除autoconf加automake加libtool加m4工具链依赖，改加pkgconf经build context供给真pkg-config。
3. source与build共用标记定位器按configure加src下auth.c双标记在目标本体及一至二级子目录定位真实源根，弃用conan patch改用纯Python词边界文本替换做可移植重命名并逐文件计数校验。
4. build内以package_folder递归搜索头文件与静态库合成缺失的openssl.pc与zlib.pc，已有expat.pc不动；显式导出PKG_CONFIG绝对路径与PKG_CONFIG_PATH为generators目录，预检pkgconf验证后走标准PKG_CHECK_MODULES，不再传下划线旁路变量。
5. configure与make改走命令行变量前缀强制CONFIG_SHELL加SHELL为可用shell，使其在env为conanbuild聚合下仍覆盖毒化值；generate内重定位真实clang并经tc固定，加meson ini缺失路径改写兜底。
6. 主构建修正Meson helper方法名并显式构建非默认unittests目标，补ncurses宏修复WINDOW连带报错，修正手写pc的libdir为归档所在lib目录，test_package弃CMake改编译器直编并做可写TMPDIR透传与只读静态校验。
## 禁止策略
禁止继续改写远端不可达依赖配方或裸调自举链；禁止手写pc时将libdir写成安装前缀根，违者链接报unable to find library -lstrophe；禁止仅接PKG_CONFIG_PATH而不合成缺失pc，违者标准探测永不通过。
## 与相近条目的边界（查重）
既有命中仅为compile_error与hmbs_platform_capabilities等子串命中，无一条覆盖远端不可达依赖的消费者侧内嵌范式；本条目不替代RREV钉住与版本切换类条目，仅在其被同指纹证伪且日志证实改写不可达时启用，可复用于同类autotools依赖失效场景。
## 适用判断
当同时满足远端依赖无OHOS二进制需重建、预检仅同步消费者单包目录致依赖改写不可达、裸自举或毒化shell或缺pc导致重建链证伪时适用；若依赖远端已有可用二进制或依赖改写可达，则优先用收敛与钉住方案，不启用本内嵌组合。
