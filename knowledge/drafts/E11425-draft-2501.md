# E11425：否定版本 banner 与可选工具角色误识别

## 触发特征与根因

构建或测试系统执行工具的 `--version`，只判断输出中是否含品牌字符串，
然后注册一个品牌专属的可选角色。输出含否定声明、兼容性解释或版权引用时，
品牌子串存在并不能证明工具身份。

本次实际 Toybox 0.8.12 输出含 `is not GNU grep 9.0`。原始 configure 的
宽松探测把系统 grep 误注册为 GNU grep，基准框架因此执行两个实为同一实现的
比较器。这与“Toybox 缺某 GNU 长选项”不同：问题在角色分类，而非替代实现
的安装或 PATH 排序。盲目延长超时不会修正重复角色。

## 可复用修复步骤

1. 同时核对真实工具路径、版本首行和最终配置角色，不凭品牌子串推断身份。
2. 在手写配置模板的角色赋值边界采用肯定身份格式。例如 GNU grep/ggrep 的
   首行包含 ` (GNU grep) `；否定、空白和未知 banner 不注册可选 GNU 角色。
3. 保留必需系统工具角色，以及原始测试组、完整输入和迭代次数。若 GNU 工具是
   必需依赖，则应通过已发布依赖解决或报错，而不是套用可选角色置空。
4. 从模板重新配置，再执行完整实际测试。banner 只决定身份候选，工具实际
   选项与行为仍须通过使用它的测试验证，不能把 banner 当成能力证明。

## 适用范围与安全边界

可推广到编译器、链接器、grep/sed 等工具的版本识别及可选测试后端选择。
只适用于明确的可选角色，不允许跳过必需依赖、断言、上游注册测试或缩小语料。
肯定 banner 格式须以该工具官方实现为依据，未知输出 fail closed。

## 查重增量

E010 是 GNU/Toybox 选项能力差异；已有 worker 工具路径知识处理 HNP/PATH
闭包。它们未覆盖否定品牌句仍命中身份子串、同实现被重复注册的机制。
本条新增可选角色的肯定身份边界、正反例与完整不减量验证，最终编号由主编确认。
