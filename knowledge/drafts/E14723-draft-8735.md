# E14723 — Debian-native 源码包抽取单个 C 工具：无 configure + po4a 门禁 + 内置版本号漂移

## 错误特征
- 走 autotools 路线时：`po4a-translate not installed, failing to rebuild changed man page translation; exit 1`
  （上游 `po4a/de/Makefile.am:9` 的 `TRANSLATE = @echo ...; exit 1;`），或 `autoreconf: not found`
  （tarball 没有生成好的 `configure`）。
- 直接编译成功后 `run-parts --version` 打印 `version 5.23.1`，而包版本是 5.23.2。

## 触发条件
- 构建系统: autotools（只有 configure.ac / Makefile.am）
- 阶段: configure / make / test_package
- 构建机无 po4a-translate、autoconf、automake（CI clean 环境同样如此）

## 根因分析
1. debianutils 是 Debian native 包，发布的源码是维护仓库快照，不含 `configure`。
2. 顶层 `Makefile.am` 固定 `SUBDIRS = po4a`；各语言子目录在缺 `po4a-translate` 时让 `make` 直接 `exit 1`。
3. `acinclude.m4` 里 `DEBIANUTILS_VERSION` 在 5.23.2 tarball 中仍是 5.23.1（`debian/changelog` 顶部已是
   5.23.2），`PACKAGE_VERSION` 由它派生，所以二进制自报版本落后于包版本。

## 解决方案

### 推荐方案
run-parts 只有 `run-parts.c` 一个源文件：配方跳过 autotools，用 profile 里的编译器直接编译，并手工提供
config.h 宏：

```bash
clang -O2 -fPIE -fstack-protector-strong \
  -DPACKAGE_VERSION='"5.23.1"' -DHAVE_GETOPT_H -DHAVE_PATHS_H -D_FILE_OFFSET_BITS=64 \
  run-parts.c -o run-parts -static-pie -Wl,-z,relro,-z,now,-z,noexecstack
```

- 禁用 po4a 等路径不需要补丁；唯一补丁是下面「补充」一节的 `--stdin` 临时文件回退。
- 编译器从 `self.conf.get("tools.build:compiler_executables", default={}, check_type=dict)["c"]` 取；
  `conf.get("tools.build:compiler_executables:c")` 会报 `does not exist in configuration list`。
- 静态 PIE 链接：x86 runner 通过 qemu binfmt 可直接执行产物与消费者程序，上游 `debian/tests/run-parts.test`
  对打包产物实跑通过。
- test_package 不用包版本断言 `--version`。

### 禁止做法
- ❌ 伪造 `po4a-translate`（touch/ln -s/`TRANSLATE=true`）——静默产出无效翻译 man 页。
- ❌ 为让 `--version` 等于包版本而改上游 `acinclude.m4`/源码版本串。

### 回退方案
需要完整 Makefile 安装规则时，去掉 `SUBDIRS = po4a` 再 `autoreconf -fvi`（会引入源码补丁，构建机需 autotools）。

## 补充：`--stdin` 的 O_TMPFILE 在 CI 文件系统上失败（真机 CI 实测）
run-parts 的 `open_tmpfile_rw()` 用 `open($TMPDIR, O_TMPFILE|O_RDWR|O_EXCL)`，`copy_stdin()` 不检查返回的 fd。
在 HarmonyOS buildbot worker 上该 `open` 失败，之后 `write(-1, ...)` 报：
`run-parts: failed to write to temporary file` / `run-parts: failed to copy content of stdin`。
本机 x86 的 O_TMPFILE 可用，首轮本地验证没有暴露。用 `O_TMPFILE|O_RDONLY`（open 必然 EINVAL）可在本机复现同样两行报错。
补丁 `0001-run-parts.c.patch`：open 返回 -1 时 `mkstemp("$TMPDIR/run-parts.stdin.XXXXXX")` 后立即 `unlink`；
强制失败变体下未打补丁 rc=1、打补丁 rc=0。注意：失败的具体 errno 未能在真机取得（CI 日志无 errno），只确认了现象与回退有效。
相关草稿：DRAFT-ohos-otmpfile-tmpdir-shim、DRAFT-appstream-1.2.0-r05-ohos-otmpfile-linkat-probe（同族，处理库内 O_TMPFILE；本条是未检查返回值的 CLI 工具）。

## 验证
```bash
grep -n "TRANSLATE = " po4a/de/Makefile.am
grep -n "DEBIANUTILS_VERSION" acinclude.m4
qemu-aarch64 ./run-parts --version | head -1     # Debian run-parts program, version 5.23.1
```
