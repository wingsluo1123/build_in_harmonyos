# E14725 — pip 传递依赖闭包随镜像索引浮动（纯 Python 配方须钉死闭包并断言无原生扩展）

## 错误特征

CI 构建期自检（`conan create` 的 build step）报：

```
ConanException: `tinyprog --help` failed (rc=1)
Traceback (most recent call last):
  ...
  File ".../jsonmerge/resolver.py", line 2, in <module>
  File ".../jsonschema/__init__.py", line 13, in <module>
  ...
ImportError: Error loading shared library
  .../build-release/stage/rpds/rpds.cpython-312-aarch64-linux-ohos.so: Permission denied
```

特征：**报错与依赖本身无关**（权限拒绝），且**本地无法复现**（本地同一配方全绿）。
伴生迹象：本地与 CI 的解析产物文件数不同（本例 `byte-compiled 101` vs CI `158` 个 `.py`）。

## 触发条件

- 构建系统: pip（`pip install --target=<stage>` 装配运行时依赖）
- 阶段: installation（build 期自检 / 消费者测试导入时）
- 前提: 顶层依赖只钉直接 requirement，传递依赖约束很松

## 根因分析

`jsonmerge 1.9.2` 只要求 `jsonschema (>2.4.0)`，选版交给 resolver。而镜像索引对
**`rpds-py`（Rust 扩展）的可见性逐次不同**——实测同一天：

```
$ python3 -m pip install -j... jsonmerge==1.9.2 ...     # 本地
Successfully installed ... jsonschema-2.6.0            # 无依赖的纯 Python 版本

$ python3 -m pip download rpds-py --no-deps -i <mirror>
ERROR: Could not find a version that satisfies the requirement rpds-py
(from versions: none)                                  # 本地视角看不到
```

于是同一份配方：

| 环境 | resolver 轨迹 | 产物 |
|------|--------------|------|
| 本地 | `jsonschema>=4.18` 的依赖 `referencing→rpds-py` 不可满足 → **回溯** | `jsonschema 2.6.0`，零原生扩展 |
| CI | 索引给出 `rpds-py` → 4.26.0 可满足，不回溯 | `jsonschema 4.26.0` + `referencing` + **`rpds` 原生 `.so`** |

CI profile 的 `[buildenv]` 把 `/data/service/hnp/bin` 前置，`conan create` 里的 `python3`
即 HNP python；**HNP 进程不能 dlopen 用户存储路径的 `.so`（E212）**，签名不能改变这一判定
（E502：运行期 dlopen 被拒与签名无关）。因此纯 Python 应用的构建期冒烟被一个
"与它无关"的原生扩展拖死。

**这是可复现性问题，不是平台问题**：修配方即可，无需绕开平台。

## 解决方案

### 推荐方案

1. 顶层依赖与关键传递依赖**全部 `==` 钉死**，并优先选纯 Python 版本：

   ```python
   PIP_REQUIRES = (
       "intelhex==2.3.0", "jsonmerge==1.9.2", "tqdm==4.70.1",
       "pyusb==1.3.1", "packaging==26.3",
       "jsonschema==2.6.0",   # jsonmerge 只要求 >2.4.0；2.6.0 闭包纯 Python
   )
   ```

2. `build()` 内断言 payload **不含任何原生扩展**，让漂移在本地暴露：

   ```python
   for dirpath, dirnames, filenames in os.walk(stage):
       native += [n for n in filenames if n.endswith((".so", ".pyd", ".dylib"))]
   if native:
       raise ConanException(f"pip closure drifted to native: {native[:5]}")
   ```

选版判据：`jsonschema 3.x/4.x<4.18` 需 `pyrsistent`（原生，靠 fallback 兜），
`>=4.18` 需 `rpds-py`（硬原生，无 fallback）；`2.6.0` 是**闭包纯 Python 的最新版**。

### 兜底方案

闭包做不到纯 Python（上游硬依赖原生扩展）时走 E219：优先用非沙箱 python 跑冒烟/消费者
测试，取不到就退化为 ELF 静态校验（DT_NEEDED/签名），**不要把"必须找到非 HNP python"
写成硬门禁**（否则 CI 必红）。

### 禁止做法

- ❌ 顶层依赖不钉版本（`jsonmerge` / `jsonschema` 裸装），把产物交给 resolver 与镜像
  索引决定 —— 本地绿、CI 红且无法复现，只能靠猜修。
- ❌ 把"原生扩展加载失败"当成平台噪声忽略掉（跳过冒烟/测试）—— 掩盖的是产物本身不可用。

## 验证

```bash
# 1) 闭包是否纯 Python（唯一可靠判据：stage 里有没有原生扩展）
find <stage> -name '*.so' -o -name '*.so.*' -o -name '*.pyd' | wc -l     # 期望 0

# 2) 镜像是否提供原生 wheel（解释"为什么 CI 会漂移"）
python3 -m pip download rpds-py --no-deps -i <index> -d /tmp/x | tail -3

# 3) 端到端（本地 W3）
conan create archives/t/tinyprog/1.0.23 -pr:h=... -pr:b=... -r=ohpcd --build=missing
```
