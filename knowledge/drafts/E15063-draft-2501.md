# 保持宽字符公共 ABI，同时修复内部元素宽度假设

## 通用场景与精确根因

旧 C/C++ 库把宽字符定义为 unsigned long 等自定义类型，又把指针强转交给
wcslen/wcscpy/wcscat/wcschr/wcsrchr。平台上公共类型与 wchar_t 宽度不同时，
强转并不完成编码或布局转换。小端 LP64 上一个有效码点的高半部零可被
wcslen 当成终止符，使规范化计算的字符数小于真实输入，分配之后却继续
按公共类型遍历完整输入，形成堆越界。只看到最初几个码点正常不证明安全。

## 可复用决策与修复

1. 从已发布公共头文件确认字符 typedef、消费者参数和对象布局，测实际
   sizeof，不把名称含 UTF32 当成元素一定四字节的证据。
2. 跟踪长度计算、容量分配、转换后可能的字符扩张、复制/查找和释放。
3. 保持公共 ABI；内部长度/复制/连接/查找全部按真实元素类型操作。
   保留查找终止零、查找失败和空串语义，不用字符串字节长度替代字符容量。
4. 对规范化的新堆缓冲区处理分配失败，并在最后一个使用者之后释放。
5. 干净重建库与安装后消费者，验证自动数字系统识别、多码点输入、扩张的
   规范化、往返和超长整数；完整执行原始测试，并单独说明其预期错误结果。

不要把公共类型直接改为 uint32_t/wchar_t 来解决内部问题；这会把修复转化为
对现有消费者的 ABI 变更。也不能只强转更多指针、固定猜测某种数字系统或
跳过会崩溃的用例。

## 本次证据与范围

libuninum 上游 2.7 的公共 UTF32 是 unsigned long；目标 LP64 sizeof 为八字节，
wchar_t 为四字节。原内部强转导致中文规范化失败；修复版 2.7.1 保持公共
类型并采用一致的元素操作。r5 真机完整 Conan create RC0，原始两个 Tcl
脚本全部 70 条目执行，安装后 API/CLI 8/8 PASS，包括中文 77、大写 1234、
Western 自动识别、100 位整数和打包 CLI 双向转换。

日志 SHA256：55d5e18abd907e18f68bbd3f0f6f22b8ac3ead80158c0c2ea90ca1358ea4e727。
70 条目含原始预期非法字符、未实现数字系统和 Tcl 非 BMP 错误；不声称它们
全部成功转换。早期 NormalizeChineseNumbers 返回 alloca 指针的猜测已被
源码否定：返回的是独立 malloc 副本，不应把该猜测写成根因。

本条适用于字符元素类型不一致的通用边界，不证明所有字符编码实现均已
安全，也不替代 ABI 相同场景的算法验证。此前 UTF8in/putu8s 的输入输出
宽度修复只作为相关先例；本次新增结论是内部长度与规范化容量链必须一起
修复且不改变已发布公共 ABI。

## 2026-10-14：库内回归不能替代安装后的文件消费闭环

Installed CLI consumers must validate the complete persisted output and diagnostics, not just exit code or one converted digit: a line-oriented converter can continue after an input error and return zero. A multi-process UTF-8 file roundtrip with an input beyond initial buffer capacity tests input decoding, expansion, output encoding and downstream reuse together. This does not prove that the mechanism is OHOS-exclusive and does not replace the full upstream suite.

在类似行式转换工具中，解析错误可能只打印诊断并继续处理，最终仍 exit(0)；因此消费者必须同时检查退出码、诊断和完整落盘字节。不要只比较第一个字符，或只在库内构造一个 UTF32 数组：这些不能覆盖 UTF-8 文件解码、扩容、编码输出与下一进程再次读取的组合边界。测试目录使用任务私有可写 build_folder，不使用 /tmp；不修改共享制品。保留完整上游测试，将同一端到端流程只计一项。

本次 OHOS 真机证据：5 条记录（含 100 位整数）跨 3 次安装 CLI 文件转换，最终完整还原，新增消费者 1/1，原上游 70/70 与消费者 8/8 保留。日志 SHA256 `ad2e3dd33a7d0030579223ee2ab99a7b2bcf2558f91967e20acdd46dbed3bdeb`。本地完整字节 oracle 定向正反检查通过；未把静态推断的非法输入 exit0 路径宣称为本次运行项。本结论是端到端验证边界增量，不宣称往返测试或文件机制为 OHOS 独占能力。
