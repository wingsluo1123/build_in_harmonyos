# E15130 — C++ 异常宏升级后的 SWIG 绑定语义修复

## 现象与触发条件

核心库与其随附语言绑定同版发布，不代表绑定已跟随所有 C++ API 变化。
若核心错误宏从“错误码参数”改为“异常类型参数”，绑定中的旧枚举调用可出现
`expected expression`、`unexpected namespace name` 等编译错误。
此模式适用于从源接口生成的 C++ 语言绑定，不是缺 Python 开发头或 SWIG 资源的问题。

## 根因

不能只让宏参数在语法上合法。分配失败保护还有语言边界上的异常契约：
真实内存异常应映射为 Python MemoryError，而不是被前面的通用异常捕获映射为 RuntimeError。
修改生成包装器也不可复现，因为下次 SWIG 生成会覆盖它。

## 修复步骤

1. 核对核心宏定义及全部绑定源调用，保留每一处失败条件和保护动作。
2. 对分配失败使用真实类型异常（例如 `std::bad_alloc`），而非删除保护或伪造错误码。
3. 在源 `.i` 接口加入所需声明，并在通用异常 catch 前映射特定内存异常。
4. 使用声明的 SWIG 依赖重新生成包装器，链接已发布核心库和匹配的 Python 开发制品。
5. 执行原始核心测试、完整官方绑定示例、安装后 API 测试；同时核对 Python 层和
   原生扩展层的模块文件来源，避免系统同名模块制造假通过。

## 本次证据

MARISA v0.3.1 核心宏接受异常类型，Python 3 绑定仍有五处旧内存错误枚举参数。
配方保留五处空指针检查，以真实 bad_alloc 替换；源 SWIG 接口先映射 MemoryError。
`marisa-python3-w3-r2-20261013`：原始 C++ 组 5/5、完整 Python 示例 1/1、
安装后消费者 8/8，冻结校验器 W3_PASS。原始测试源未修改。
日志 SHA-256：`84bb95a95c0110be1e7a42d4bc719b42f83d59f38132012657fed5f4302a777c`。

## 安全边界与验证局限

不删除分配保护，不手改生成文件，不以 API 不同的第三方模块替换绑定。
普通成功测试只证明正常接口及安装加载，不证明内存耗尽路径；本次没有进行 OOM 注入，
异常映射的结论来自可核对的源逻辑，不宣称已动态覆盖 MemoryError。
异常 ABI 还必须与实际链接的核心库和解释器匹配。

## 查重差异

四目录扫描命中 gpgmepy 的 SWIG/setup.py 构建入口经验、Python 开发库缺失及语言误判条目；
它们未覆盖核心异常宏参数类型漂移及“特定异常必须先于通用异常”的绑定语义契约。
本条新增该跨库机制，不把 MARISA 名称本身作为触发条件。
