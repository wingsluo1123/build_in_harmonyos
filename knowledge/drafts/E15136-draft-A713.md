# E15136 — Conan 捕获的测试输出必须在异常路径保留

## 场景与根因

配方用 StringIO 捕获 CTest 输出，运行后解析真实用例数。self.run 默认在非零退出时抛异常；若打印缓冲区位于调用之后，异常会跳过它。结果只留下 Error 8 while executing ctest，真正的加载器错误或断言失败留在未输出的缓冲区中。这是诊断信息损失，不是测试通过或失败的根因。

## 可复用修复

```python
output = io.StringIO()
try:
    self.run(command, stdout=output, env="conanrun")
finally:
    self.output.info(output.getvalue())
# 只有命令成功返回后，才解析测试分母和通过数。
text = output.getvalue()
```

如果另外捕获 stderr，也必须在 finally 回放该流。不得捕获异常后继续标记通过，不得把部分输出中的成功行解释为完整套件通过。对于机器解析的 JSON，日志回放不能写回缓冲区。

## 验证方法和边界

成功必须同时满足命令 RC 0、完整清单和完整结果汇总；失败必须保留原异常与已有输出。适用于 Conan 捕获 stdout 后解析结果的工具，不要求把流式输出改成捕获。旧成功日志、仅打印异常字符串或忽略返回码均不能替代当前运行证据。
