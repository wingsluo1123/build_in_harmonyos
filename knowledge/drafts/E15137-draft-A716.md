# E15137 — Conan 下载线程池的 SemLock 失败需真正关闭并行下载

## 现象与精确根因

尚未编译包，Conan 下载已发布二进制时出现 ThreadPool → SimpleQueue → Lock → _multiprocessing.SemLock → OSError [Errno 28] No space left on device。故障是在同步原语初始化，不是源码解压失败，也不能仅凭 ENOSPC 断言磁盘容量满。

Conan 2.29.1 installer._download_bulk 对每个非零 core.download:parallel 使用 multiprocessing.pool.ThreadPool；线程池自身仍创建 multiprocessing 队列和信号量。因此“线程池只用线程”不代表不依赖 POSIX semaphore。设为 1 仍走该分支；此结论来自源码，未虚构另一次 parallel=1 实机失败。

## 修复步骤

1. 保留完整 traceback，区分 SemLock 创建失败、文件写入/解压失败、字节容量或 inode/quota 耗尽。
2. 在任务自己的 CONAN_HOME/global.conf 中设置 core.download:parallel=0。源码的零值分支按顺序调用同一个下载器，不构造线程池。
3. 不写用户全局配置，不删除 /dev/shm、不清理其他任务文件、不吞掉信号量异常。
4. 继续使用发布包而非源码回退，并绑定真实 RREV、PID、PREV、host/build context；完整执行原来的上游和消费者测试。

这是 Conan core 配置，应使用任务 global.conf 或官方 core 配置通道，不放入普通 tools.* profile 配置，也不在库配方中篡改 Conan 内部下载器。worker 若出现相同错误，需由其配置维护者采用相应 core 配置；配方本身不能替平台环境承诺修复。

## 查重和实质增量

四范围检索 graph/drafts/doc/operations。E022 涉及 sem_unlink 清理阶段 FileNotFoundError，忽略清理异常不能修复本条的创建阶段阻塞。coordgenlibs/dmc_unrar 草稿涉及 HMDFS inode 和检出/解压 ENOSPC，稀疏检出不能解除线程池的 SemLock 前置依赖；Eigen pthread_cancel 和 ThreadPoolExecutor 扇出也不是该实现。新增的是非零并行值仍依赖信号量、必须用零值关闭这一分支，以及保持发布包身份的安全配置路径。

## 适用边界与禁止做法

仅适用于具有同一公开零值串行分支、失败栈明确落在 ThreadPool 初始化的 Conan 版本。不得当作所有 ENOSPC 的通用修复；文件系统容量/inode 真满仍须按对应原因处理。若配置后仍发生 SemLock 创建错误，要检查实际配置加载或不同调用点，不能继续盲重试。不得替换/屏蔽上游测试，不能把默认禁用的 MoreThan4GB 压力测试算作通过。正式编号由主编审核分配。
