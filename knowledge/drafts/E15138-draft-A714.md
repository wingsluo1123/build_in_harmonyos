# E15138 — 在同一接收会话上验证认证失败后的重放状态

## 场景与根因

认证数据包接口同时管理认证状态和重放窗口。只做加解密往返，或每个负例都新建接收上下文，不能判断认证失败是否错误消费序号。即使孤立测试都通过，错误状态更新仍可能使随后合法包被当作重放拒绝。这是测试覆盖缺口；本次没有发现或宣称上游存在该缺陷。

## 可复用验证顺序

1. 发送端保护有效包，保留原始密文与长度。
2. 修改副本中认证覆盖的负载字节；对一个接收会话解保护，要求明确的认证失败状态。
3. 不重建接收会话，提交原始包与原始长度；要求成功且明文逐字节一致。
4. 同一会话再次提交原始密文；要求明确的重放拒绝状态。

三个阶段分别使用可写缓冲区和长度变量，避免 API 就地修改影响后续测试。不能只断言“非零”，否则认证失败、参数错误、重放拒绝会混淆。

## 本次证据

archives/l/libsrtp2/2.8.1/test_package/consumer.c 使用同一个 rx：先要求 srtp_err_status_auth_fail，再要求合法包成功且明文一致，最后要求 srtp_err_status_replay_fail。另有真实 SRTCP 往返及鸿蒙私有 TMPDIR 的密文写入、读回、比较、清理。

- 原生默认内部密码后端，完整上游 CTest 12/12，没有关闭上游测试。
- libsrtp2-official-w3-20261013-r3：安装包消费者通过，12 个回执通过，任务进程清零。
- 原始日志 SHA-256：463b7e1aed7072797b3b10ec03499418554b2af9155231c6a19f54f71e38cf87。
- 终态标记：SRTP_SRTCP_AUTHENTICATION_REPLAY_PASS、OHOS_PRIVATE_ENCRYPTED_PACKET_FILE_ROUNDTRIP_PASS。

## 查重与增量

四范围检索未找到同一会话的“认证失败→同序号有效包→重放包”三阶段模式。本条不是已有 clang 签名包装器 warning/Werror 修复，也不是一般加解密往返说明；新增失败恢复和反重放状态更新次序的可复用判据。

## 安全边界

仅适用于 API 约定认证失败不消费有效序号、允许继续使用会话的认证协议。若上游要求失败后销毁或关闭会话，不能强套该顺序。固定密钥仅用于隔离测试，不能用于生产。结果不证明其他密码后端、GCM、网络服务或协议安全审计通过。正式编号由主编审核分配。
