# E16412 — Conan 包装选项的布尔分支必须按值判定

## 触发条件和问题现象

配方公开支持 shared=True/False，并在构建、打包或消费者中用选项控制共享对象与静态归档。若使用 `option is False` 或 `option is not False`，静态配置可能仍构建并安装共享运行时，随后被静态产物校验拒绝。默认共享配置成功不能证明另一条分支正确。

## 精确根因

Conan2.29.1实际的 Options.shared 返回 _PackageOption。以 shared=False 构造时，bool(value) 为 False，value == False 为 True，但 value is False 为 False、value is not False 为 True。身份比较没有读取 Conan 选项值。

本轮源码中的前者使静态分支未提前返回；后者使静态包仍复制共享运行时。消费者也需要按所测依赖的实际选项选择 .so 或 .a，否则会在合法静态配置中要求不存在的共享对象。

## 修复步骤

1. 用 if option 或 if not option 按值判断，保持各分支原有产物契约。
2. 从被测依赖的 options.get_safe("shared") 读取模式，选择正确链接对象。模块仅在共享产物存在时执行；原共享模式的 API、扩展加载与平台测试均保留。
3. 在真实目标执行两个配置。静态包只含预期静态归档，共享包保持原共享运行时；分别核对产物和消费者。
4. 配置重复不增加独立用例数。清楚保留共享消费者、同一 API 的静态复验和平台行为适用范围，不累计生成模式、断言或循环为新用例。

## 适用范围和边界

适用于返回包装值的 Conan 布尔选项，以及其他有自定义布尔转换的配置对象。普通 Python 布尔单例、三态 None 协议或必须区分对象身份的 API 不能机械替换。不能用新测试名掩盖原用例减少，也不能删掉共享运行时、绕过静态产物检查、隐藏失败或修改已发布依赖。

本例没有声明所有链接器的通用行为；前序注释和历史尝试仅属于当时具体构建环境。
