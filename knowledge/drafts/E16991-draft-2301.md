# 可选功能的上游进程计数与真实能力分别绑定

某些库在可选功能禁用时仍注册同名测试程序，测试主体被条件编译排除，
main 仍返回0。因此保持相同上游 N/N 不代表新增启用的格式或插件已经验证。
正式 recipe/binary 发布、源文件编译和上游进程PASS应分别对应它们实际的范围。

修复须保持原上游程序和断言，恢复真实生产者依赖及构建选项，并核对实际
生成配置、运行时 HasFeature/模块注册和代表性文件的数据值。消费者不能只
查字符串、菜单或文件存在。启用功能后必须绑定新源/依赖快照，不能继承旧
功能关闭时的 W3。原始进程数、启用分支与新增数据断言不得混算或重复累计。

本次证据：libspatialite5.1.0 的 test/check_xls_load.c 主体位于
ifndef OMIT_FREEXL 内；test/check_zipshp.c 主体位于 ENABLE_MINIZIP 内。
禁用后仍返回0。前一正式配方5.1.0.2.1还明确要求消费者 HasFreeXL=0、
HasMinZip=0，属于其当时的有限能力合同，不能据此证明完整 GUI 数据格式。
