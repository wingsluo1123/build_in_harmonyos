# E2005 — test_package 的 test() 未调用 self.run() 导致 CI L0d 门禁 stub_test_method 拦截

## 错误特征

Conan 配方 PR 触发 CI，`conan-build-test` 步骤在 L0 质量门禁检查失败：

```
[step] L0: Quality gate checks...
[fail] L0d: test() method has no self.run() call — likely a stub
[fail] wf-utils/0.4.0 — L0 quality gate failed: stub_test_method
L0_RESULT=fail: gate failed: stub_test_method
L1_RESULT=skip: blocked_by_L0
program finished with exit code 1
```

失败类别被诊断为"门禁拦截"。worker 各步骤（worker_preparation / git-clone /
checkout-pr / conan-setup）均 ✅，仅 `conan-build-test` 的 L0d 门禁失败，
且发生在 `conan create` 之前（未进入编译阶段）。

## 触发条件

- 构建系统: meson（或 cmake）
- 阶段: L0 质量门禁检查（conan create 之前）
- 根因代码形态：`test_package/conanfile.py` 的 `test()` 方法只调用构建系统
  测试助手（如 `meson.test()` / `cmake.test()`），没有直接的
  `self.run()` 调用

## 根因分析

CI 脚本 `ci/conan/build_and_test.sh` 的 L0d 检查（R26/R31 配套门禁）：

```bash
# L0d: test_package/conanfile.py 必须有 test() 且有 self.run()
if ! grep -q "def test" "$TEST_PKG_DIR/conanfile.py"; then
    echo "[fail] L0d: test_package/conanfile.py has no test() method"   # no_test_method
elif ! grep -q "self\.run" "$TEST_PKG_DIR/conanfile.py"; then
    echo "[fail] L0d: test() method has no self.run() call — likely a stub"  # stub_test_method
fi
```

门禁用 `grep -q "self\.run"` 做字符串匹配，要求 `test()` 方法内必须出现
`self.run(...)` 调用以实际执行测试程序。仅通过 `meson.test()` / `cmake.test()`
构建系统测试助手驱动测试时，字符串匹配不命中，被判定为"空壳测试"
（stub），L0 门禁直接拦截，不进入 `conan create` 编译阶段。

补充：L1d 还会拦截假测试——`self.run` 不能只是 `echo`/`print`/`true`
（`grep -qE "self\.run.*(echo|print|true)"` 命中即失败），测试程序必须真实
编译、链接并调用被测包 API。

## 解决方案

### 推荐方案

在 `test_package/conanfile.py` 的 `test()` 方法中，用 `self.run()` 直接运行
meson/cmake 构建出的测试程序。参考已合入的 meson 类 test_package 写法
（jsonrpc-glib、gnome-autoar、gtk4）：

```python
import os
from conan import ConanFile
from conan.tools.build import can_run
from conan.tools.meson import Meson, MesonToolchain
from conan.tools.layout import basic_layout

class TestPackageConan(ConanFile):
    settings = "os", "compiler", "build_type", "arch"
    generators = "PkgConfigDeps"

    def requirements(self):
        self.requires(self.tested_reference_str)

    def layout(self):
        basic_layout(self)

    def generate(self):
        tc = MesonToolchain(self)
        tc.generate()

    def build(self):
        meson = Meson(self)
        meson.configure()
        meson.build()

    def test(self):
        test_exe = os.path.join(self.build_folder, "test_xxx")   # 与 meson.build 可执行名一致
        if can_run(self):
            self.run(test_exe, env="conanrun")
        else:
            self.output.info("Cross-building: consumer binary is run on OHOS device")
```

要点：
- `test_exe` 指向 meson 构建产物（`meson.build` 中 `executable('test_xxx', ...)` 的可执行名），
  位于 `self.build_folder` 下
- `can_run(self)` 判断是否可在构建机直接运行（OHOS host=build 时返回 True）
- `env="conanrun"` 注入被测包的运行环境（`runenv_info`）

### 禁止做法
- ❌ `test()` 中只写 `meson.test()` / `cmake.test()` 而不调用 `self.run()`
  （触发 L0d `stub_test_method`）
- ❌ `self.run("echo ok")` 等假运行（触发 L1d fake test）
- ❌ 删掉 `test_package/` 或 `MANIFEST.yml`（触发 L0a/L0e）

## 验证

```bash
# L0d 门禁字符串检查（必须命中 self.run）
grep -q "self\.run" archives/w/wf-utils/0.4.0/test_package/conanfile.py && echo PASS

# L1d 假测试检查（不应命中 echo/print/true 假运行）
! grep -qE "self\.run.*(echo|print|true)" archives/w/wf-utils/0.4.0/test_package/conanfile.py && echo PASS

# 完整 CI 模拟（与 PR CI 一致）
CI_PACKAGES="archives/w/wf-utils/0.4.0" CI_BRANCH="wf-utils-0.4.0" CI_PR_NUMBER="16592" zsh ci/conan/build_and_test.sh

# 本地 conan create（完整构建 + test_package 测试）
conan create . -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 ...
# 期望: L0 pass → conan create pass → L1a/b pass（测试程序编译并运行）
```
