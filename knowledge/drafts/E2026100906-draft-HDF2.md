# CMake 原测试驱动必须保全 argv 类型域及字面环境值

## 通用触发特征

原测试可执行文件直接运行正常，但经过 CMake 测试包装器失败；MPI launcher
及选项被截断、含反斜线的属性路径变化、字面 `${ORIGIN}` 在子进程中丢失。
必须比较实际 argv/环境，而不能按程序名归罪 MPI、加载器或文件格式。

## 精确根因

`cmake_parse_arguments(... ${ARGN})` 在 macro 中把文本再次展开；若把包含
launcher、参数和目标路径的 PROGRAM 声明为单值，列表边界已在解析时丢失。
宏的实参替换还会再次解释字面变量及反斜线。简单多加引号或串成一条 shell
命令并不能恢复已丢失的参数类型，且会引入额外 shell 展开。函数改造若忘记
向调用者传播 RESULT/输出变量，又会让原比较使用错误的作用域。

## 可复用修复步骤

1. 绑定同一可执行文件和失败测试的实际 argv、环境、RC、stdout/stderr。
2. 将驱动改为函数，通过 `cmake_parse_arguments(PARSE_ARGV 0 ...)` 读取
   原实参。明确区分单值配置与多值 PROGRAM/ARGS/EMULATOR；不将 argv
   串回 shell，不删 launcher 或选项。
3. 原执行仍使用 `execute_process(COMMAND ...)`。只把原驱动需要的结果
   和过滤流显式传回 `PARENT_SCOPE`；保留原期望退出码、stderr 与内容 oracle。
4. 用具有反斜线、字面变量和多参数边界的真实子进程逐值比较，然后执行原
   失败组及完整原注册套件。控制用例通过不能替代产品原套件。
