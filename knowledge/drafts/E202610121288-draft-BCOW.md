# 原生语言扩展触发架构安装根提升时的制品身份绑定

## 适配场景、现象和通用触发特征

MakeMaker 输出 `Files found in blib/arch: installing files in blib/lib into
architecture dependent library tree`。真实原生扩展已编译、安装和执行，
但用纯 Perl 根 `lib/perl5/<module>.pm` 进行产物检查会报文件不存在。
更危险的处理是追加共享搜索目录，导致同名模块或旧解释器ABI被加载。

## 精确根因

是否有原生扩展改变安装语义：XS 包的模块及动态库一起进入 SITEARCH，
不是单独把 `.so` 放入架构根。纯模块和原生扩展不能共用未经回读的安装
路径假设。Conan ref/recipe/package revision、实际包根与解释器运行时
共同确定有效制品身份；文件同名或SONAME相同不能证明ABI兼容。

## 可复用修复步骤

1. 保留真实安装记录和收尾失败，分别记录编译、原测试、消费者和整体
   事务结果。收尾失败不能用前面的成功追认为整个运行成功。
2. 比较原构建系统的 INSTALLSITELIB/INSTALLSITEARCH 与实际包目录。
   绑定真正执行构建获得的完整 ref/RREV/PID/PREV，不猜cache前缀。
3. 同时纳入通用模块根和架构根，保留发布解释器核心/架构闭包；消费者
   检查 `$INC` 及真实已加载XS路径确属本包，调用公开API/状态正负控制。
4. 解释型源码可以与官方归档成员逐字节对照；XS必须用当前真实解释器
   ABI和目标编译器构建、签名、实际加载，不复制另一解释器的二进制。
5. 若只是收尾入口路径错误，只纠正这个错误，不搬移官方布局、不改
   系统解释器/共享前缀/原断言。已消费事务保留失败，fresh successor
   在完整原分母、消费者/专项与正式Conan中证明修复。

## 与已有知识的实质增量及安全边界

E155覆盖纯Perl搜索/安装基础。本条新增安装器因XS存在而提升整个模块
根的真实机制，以及源码文件/原生扩展必须分别绑定的制品检查。适用于
同类MakeMaker XS包，不证明未测试架构、Windows、跨编译或所有原生语言
安装器都使用相同布局。显式环境被后置Conan env file覆盖另有已有知识；
只有已构造并核验运行闭包时才用env=None，不能借此去掉必要工具环境。

此必要叶节点通过不证明Clone/SQL/DBI/wallet全栈通过。平台CI、Review、
提审和远端发布仍独立，不能把本地Conan标签或源码下载当发布结果。


### 配方与消费者的临时根生命周期

A build-tree ownership predicate cannot serve as the identity contract of private test/configuration state. Retain the accessible Conan build tree and create a per-instance POSIX root for both production Config projection and consumer fixtures; enforce real UID, canonical path and 0700, release the consumer directory on every exit. Fresh original tests and actual public consumers/Harmony validate this distinct lifetime boundary; no permissions, accounts, package ABI or original assertions are weakened.
