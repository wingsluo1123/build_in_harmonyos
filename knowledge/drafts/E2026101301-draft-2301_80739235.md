# E2026101301 — conan 2.29.1 backup-sources 离线喂源码必须同时提供 sha256 与 sha256.json 元数据

## 触发场景

本机/CI 环境无法直连 GitHub 官方源，按旧方案配置 `core.sources:download_urls`
+ `download_cache` 离线喂源码时，conan create 在 `source()` 阶段报：

```
Checking backup: http://<base>/
NotFoundException: Sources for <url> not found in remote backup http://<base>/
```

即使 `curl <base>/<sha256>` 返回 200 也照样失败（jamulus 3.9.1 W3 实测三连）。

## 根因

conan 2.29.1 `conan/internal/rest/caching_file_downloader.py::_do_download`
对 backup 查找要求**两个文件同时存在**：

1. `<base>/<sha256>` — 源码包本体
2. `<base>/<sha256>.json` — 元数据 `{"references": {ref: [urls...]}, "timestamp": ...}`

缺 `.json` 元数据即 NotFoundException；且本地缓存命中后还会做 URL 交集校验
（`recorded_urls.intersection(urls_set)`），元数据里若缺实际请求的镜像 URL 形态
（如 verify 流程注入的 ghfast.top 前缀 URL），会触发带 warning 的反复重下载。

## 修复

镜像/缓存目录同时放两件；基址用 http(s)（本机 `python -m http.server` 即可）：

```bash
cp <tarball> <缓存目录>/<sha256>
printf '{"references": {"%s/%s": ["<官方URL>", "<镜像注入后URL>"]}, "timestamp": %s}' \
    name ver ts > <缓存目录>/<sha256>.json
```

## 边界

- conan 2.29.1 不支持 `file://`（"No connection adapters"）、纯路径
  （'No scheme supplied'）——旧版离线方案整体失效。
- 与具体三方库无关：任何走 conandata 源下载的包在此环境均会踩中，属共性机制阻塞。
