# 原测试收集器的同名源码漂移与真实输出验收

## 现象与根因

原收集器核对六个文件名、TAP计划和断言数量，却未把实际测试文件字节绑定到官方归档；同名文件发生内容漂移后，旧真实stdout仍能满足这些计数。独立验证归档哈希不能代替结果消费阶段对测试输入身份的验证。

这不是声称旧原生运行使用了篡改输入。本次用真实原生日志构造独立主机对照：保留全部原文件名及断言，仅在受控t/close.t副本追加注释，旧收集器仍接受相同日志，新收集器在日志验收前报Original source hash drift。生产源码和新原生事务输入均未更改。

## 可复用步骤

从已校验官方tar的真实测试成员生成路径及SHA256锁，随配方导出；在读取并验收TAP之前比较实际测试路径集合及每个文件哈希，保持原测试字节和断言；使用同一真实原生日志对照未修改源码正例、旧收集器同名漂移接受和新收集器漂移拒绝，并将主机负对照与原生执行分别记账。

复用E231的已校验归档来源约束，以及E431的Conan源码和消费树区别。本增量把来源约束落实到结果收集器的实际输入，并提供真实输出的旧/新A/B拒绝对照；不重复把已有B::COW元数据发布知识作为新贡献。

## 实际验证

perl-io-string-1.08.2-official-20261016-r657：两个真实正式create各原6程序/43TAP、零失败或跳过、消费者3/3和Harmony1/1；独立冻结验收、唯一launch、own0、release/postrelease通过。观察SHA256 48d95e767be48d33c9ad41ac2ab6f39e54dba7c205882be46c749f96f9a62ee2，W3日志SHA256 30d2acb6692200e5f63458ed5946e9d4d1344de675a8dd6dd4fd7981cd6a8427。

主机收集器对照r664：官方源码正例通过；同名漂移副本被旧收集器接受、新收集器拒绝。该对照使用真实原输出，既不是新的原生运行，也不累加测试分母。

## 边界

包版本1.08.2，上游和模块版本仍为1.08。旧1.08.1发布request121002/build107868在上传阶段拒绝元数据，实际设置包含四项；规范字段写法属于接收兼容性候选，服务端解析根因尚未证明，须合并后正式发布和实际下载另验。此原生结果不证明DBI、wallet或其他父项通过。
