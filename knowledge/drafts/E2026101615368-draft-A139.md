# 模拟命令生成器保留同一 Python 与调用记录的入口适配

## 现象与定位

Testpath默认生成脚本直接以同一Python的shebang作为命令入口；目标中该路径等待，而同一解释器的二进制子进程和显式解释脚本可正常执行。入口路径的可执行性须独立验证，不能把原测试超时等同于整个Python提供者失效，或仅凭vfork标志推定根因。

原始事务r912/r999分别使用已发布Python3.12.9和3.12.9.1，停在原MockCommand调用。r1021实际Python二进制子进程对照全部正常。r1034绑定官方commands.py（SHA25646ea87f901947bee26b645204d95842ad50c86323efde8c92299013cb41da730）：裸命令、绝对脚本、关闭vfork和SDK裸脚本四项等待；同一Python显式解释、系统Shell后exec同一Python两项rc0，stdout、单次调用记录和ARG参数正确。没有据此断言具体内核或安全策略。

## 修复方法

绑定官方commands.py与相同发布Python，分别比较裸命令、绝对脚本、显式解释器、关闭vfork和SDK对照；为实际HarmonyOS的默认生成内容采用系统Shell后exec同一sys.executable的单文件双语入口，用shlex.quote及原$0/$@保留解释器身份、参数和记录内容；自定义content与其他平台沿用原逻辑。全部原始测试与调用点不变，安装后再核对stdout/stderr、非零退出状态、单次记录和参数。

发布源原构建后端依赖先采用实际已发布Setuptools84构建，元数据以原版本0.6.0及完整模块/资源打包；后端实际额外构建依赖为0。两项源码补丁仅通过官方refresh-patch --auto生成并dry-run。原3个测试程序和14个注册ID、参数及断言保持官方字节。显式记录原始与适配后的commands.py哈希，安装七个模块/资源逐项匹配声明源码；六项原字节、一项真实适配，不能将其表述为七项全部未改。

## 既有知识复用与增量

E037/E049处理env缺失或不可迁移的shebang；本次同一实际解释器存在且二进制调用正常。复用DRAFT-11418的显式解释器思路，但不沿用其EACCES/内核结论，本次是Python生成的模拟命令等待且原调用点必须保留。Tcl双语脚本版本探测处理旧解释器名，Perl.PL条目处理生成器实例化，均不是本次动态默认脚本的解释器身份、argv和调用记录合同。新增点为源码绑定对照、生成器层的同解释器单文件入口，以及原套件和安装API的连续验证；通用Shell exec本身不重复申报创新。
