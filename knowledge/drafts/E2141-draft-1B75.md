# E2141 — OHOS libc++ std::sample 与上游全局 struct sample 同名歧义

## 错误特征

```
src/speechPlayer/src/speechWaveGenerator.cpp:197:56: error: reference to 'sample' is ambiguous
        unsigned int generate(const unsigned int sampleCount, sample* sampleBuf)
                                                              ^
/usr/include/c++/v1/__algorithm/sample.h:33:1: note: candidate found by name lookup is 'std::sample'
```

## 触发条件

- 构建系统: Autotools（含 C++ 模块）
- 阶段: compilation（-stdlib=libc++ -std=c++17）
- 前提: 源文件顶部有 `using namespace std;`，且存在全局 `struct sample` 类型

## 根因分析

OHOS libc++ 提供 C++17 range algorithm `std::sample`（头文件
`<__algorithm/sample.h>`）。当 .cpp 文件在 `using namespace std;` 作用下
使用 `sample* sampleBuf` 作为参数类型时，名称查找同时命中全局
`struct sample` 与 `std::sample`（C++17 起 std::sample 是函数模板），
产生二义性编译错误 "reference to 'sample' is ambiguous"。上游源码（如
eSpeak NG speechPlayer 模块）在 glibc/libstdc++ 环境下无此问题，但
OHOS musl+libc++ 环境必然触发。

## 解决方案

### 推荐方案

对冲突 .cpp 打 patch：将参数/局部类型的 `sample` 改为全局限定 `::sample`
（如 `unsigned int generate(const unsigned int sampleCount, ::sample* sampleBuf)`），
或收窄 `using namespace std` 作用域。patch 不得含 `__OHOS__` 平台宏
（PF5 硬闸），纯命名冲突修复天然无需平台宏。

### 禁止做法

- ❌ 在 patch 中加入 `#ifdef __OHOS__` 平台宏（PF5 拦截）
- ❌ 大范围删除 `using namespace std`（可能引入其他隐式依赖）

## 验证

```bash
# 应用 patch 后重新编译
patch -p1 < patches/0001-fix-std-sample-ambiguity.patch
make -j1    # speechWaveGenerator.cpp 编译通过即修复
```
