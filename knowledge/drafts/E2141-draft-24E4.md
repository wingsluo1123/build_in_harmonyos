# E2141 — 上游 Makefile 硬编码 GCC 遗留选项 `-I-`，clang 在参数解析阶段直接拒绝

## 错误特征

第一条编译命令即失败，日志里**没有源文件名、没有行号**（因为源码还没被读）：

```
clang-15: error: '-I-' not supported, please use -iquote instead
make: *** [Makefile:24: shfsmount] Error 1
```

实测复现（设备 clang 15，rc=1）：

```bash
printf 'int main(void){return 0;}\n' > "$TMPDIR/q.c"
clang -I- -c "$TMPDIR/q.c"; echo rc=$?     # rc=1
```

## 触发条件

- 构建系统: 手写 Makefile（选项硬编码，不是 autotools 生成的搜索路径）
- 阶段: make → clang 命令行参数解析
- 高发族群: 2000 年前后的 FUSE/用户态文件系统工具（shfs 0.35 的 `shfsmount/Makefile` 为首个实证，sshfs/fuse-utils/smbnetfs 同代代码同形）
- 排查命令: `grep -rn -- '-I-' Makefile* '*.mk'`

## 根因分析

`-I-` 是 GCC 4.x 以前的 **include 搜索路径分隔符**：命令行里它**之前**的 `-I` 目录只参与 `<...>` 尖括号搜索，**之后**的只参与 `"..."` 双引号搜索。Clang 从未实现这个选项，而鸿蒙 SDK 只有 LLVM/Clang（P010，原生 aarch64 环境不存在可用的 GNU 工具链，也不该按交叉编译处理，见 P001）。

因此这是 **driver 层的参数解析错误**，与头文件缺失、头文件内容错误、`-Werror` 升级全都无关。辨别要点就是"零文件名零行号"——把它误判成头文件问题会带偏整个排查方向。

上游原文（shfs 0.35）：

```make
SEARCHDIRS := -I- -I. -I../shfs/Linux-2.4/
```

## 解决方案

### 推荐方案（priority 1）：按原语义改写为 `-iquote`

上游意图是"当前目录与 `../shfs/Linux-2.4/` 的项目私有头优先于系统头"，等价改写：

```make
SEARCHDIRS := -iquote . -iquote ../shfs/Linux-2.4/
```

只改上游 Makefile **源文件**（它不是 configure 生成的，不需要 P003 的生成文件流程），保持上游编码风格、英文注释，用 `refresh-patch --auto shfs 0.35` 落成
`archives/s/shfs/0.35/patches/0001-shfsmount-Makefile.patch`（P005 可向上游提交、P011 补丁元数据 header）。

### 回退方案（priority 2）：只删 `-I-`，保留其余 `-I`

当同一条 SEARCHDIRS 里已有 `-I.` 等目录、去掉分隔符后所有头文件仍能命中时可行。风险：双引号/尖括号搜索优先级变化可能命中同名系统头（参见 E584：OHOS sysroot 自带 `version.h` 遮蔽项目 shim 头）。采用后必须重跑完整构建 + `test_package`，不能只看链接通过。

### 禁止做法

- ❌ `CFLAGS += -Wno-error` / `-w`：driver 参数错误不是 warning，加了完全无效 —— 只会掉进 R43 调参螺旋（同一错误类别连续 5 次仍失败即止损）。
- ❌ 把 `CC := gcc` / `LINKER := gcc` 改回 GNU：设备与 CI clean 环境都没有可用 gcc，等于把"参数错误"换成"找不到编译器"，且违反 P001/P010。

## 验证

```bash
grep -- '-I-' archives/s/shfs/0.35/patches/0001-shfsmount-Makefile.patch   # 只在 - 行出现
conan create archives/s/shfs/0.35 --profile=ohos-arm64                     # make 越过第一条编译命令
```
