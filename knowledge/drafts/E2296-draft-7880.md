# E2296 — 终止态 NOTIFY 不得提前销毁待回应的 SUBSCRIBE

## 错误特征
```
test_nua test_event_fetch() FAILED: (e->data->e_status == 202 || e->data->e_status == 200)
Responding to a Non-Existing Request
nua_r_subscribe status 500 Internal Server Error
```

## 触发条件
- 阶段：NUA event-fetch / notifier 测试
- 初始 `SUBSCRIBE` 尚未收到最终响应时，终止态 `NOTIFY` 已经收到 200

## 根因
`nua_notify_client_request()` 会在发现 pending `SUBSCRIBE` 时将其 `sr_terminating` 标记设为 1，表示应在 `SUBSCRIBE` 最终回应后结束 usage。但它没有清除 NOTIFY 自己的 `cr_terminating` 标志。NOTIFY 收到 200 后，`nua_client_response()` 把 `cr_terminated` 设为 1，`nua_client_report()` 随即移除 notifier usage。`nua_dialog_usage_remove_at()` 会销毁该 usage 关联的 pending server request，因此后续的 `nua_respond()` 找不到原 SUBSCRIBE，客户端收到 500。

如果删除延迟的 `nua_respond()`，原请求没有最终响应，同样会以 500 结束。

## 修复
当终止态 NOTIFY 发现关联的 SUBSCRIBE 仍待回应时，保留 `sr_terminating = 1`，并清除 NOTIFY 的终止标记：

```c
sr->sr_terminating = 1;
nua_client_set_terminating(cr, 0);
```

这样 NOTIFY 的成功响应不会提前删除 usage；NUA 会在应用发送 SUBSCRIBE 最终响应后，依据 `sr_terminating` 清理 usage。

## 验证
在设备上的完整 NUA runner 中确认 `NUA-11.6.2` 的 SUBSCRIBE 最终状态为 202 或 200：

```bash
. conan/conanbuild.sh
make -j2
make -C tests test_nua
SOFIA_OHOS_TEST_NUA_NO_NAT=1 \
SOFIA_OHOS_TEST_NUA_EXTENDED_TIMEOUT=1 \
./tests/test_nua -e
```

使用静态构建时，库修改后必须重链 `test_nua` 再执行；只重建顶层库不会更新已有测试二进制。

随后由设备上的 Conan `test-package` / W3 验收覆盖 `check_sofia` 复用该用例的矩阵项。
