# E2296 — KF6 6.18 闭包 registry 二进制漂移（conan graph 报 `Missing packages: kiconthemes`）

## 错误特征

`conan graph info` 在图解析成功、无版本冲突的情况下，末尾给出缺包警告（退出码仍为 0，极易被忽略）：

```
WARN: There are some error(s) in the graph:
    - Missing packages: kiconthemes
```

紧接的 `conan create` 才会以更晦涩的方式失败（`Package 'xxx' not resolved` / 配置期找不到 KF6IconThemes）。
典型上下文：KDEGames6 应用（libkdegames 26.04 + KF6 6.18 闭包）。

## 触发条件

- 构建系统: CMake + Conan 2（OHOS 适配版 conan 2.29.x）
- 阶段: configuration（`conan graph info` / `conan create` 的依赖解析）
- 前置: 配方 `requires()` 里同时出现
  - `knewstuff/6.18.0`（其 recipe 要求 `karchive/6.18.Z`）
  - `karchive/6.18.0` 的显式 pin 或 override（libkdegames 闭包先例）
  - `kiconthemes/6.18.0`（registry 上该版本的**二进制**已被重建为依赖 `karchive/6.19.0`）

## 根因分析

`Missing packages` 与「版本冲突」是两类不同故障，必须区分：

| 现象 | 含义 |
|---|---|
| `ERROR: Version conflict: Conflict between A/x and B/y` | recipe 层的版本区间互相矛盾（图解析失败，退出码非 0） |
| `WARN: ... Missing packages: <pkg>` | 图解析成功，但**该 pkg 计算出的 package_id 在制品仓没有对应二进制** |

本例属后者：`kiconthemes/6.18.0` 的 recipe 仍是 6.18.0，但制品仓中该版本只有一个二进制 revision，
其 `requires` 记录为 `karchive/6.19.0`（重建时间晚于同批 KF6 包）。而 `knewstuff/6.18.0` 的二进制
`requires` 仍是 `karchive/6.18.Z`。两条线在 `karchive` 上互斥：

- 保留 `karchive/6.18.0` → `kiconthemes/6.18.0` 的 package_id 找不到（缺包）
- 改用 `karchive/6.19.0` → `knewstuff/6.18.0` 的 package_id 找不到（换一个包缺）

实测证据（lskat 26.04.0）：

```
$ conan list "kiconthemes/6.18.0:*" -r=ohpcd
  revisions  f82185f3a6daed7a2bae8d5f14a6e773
    packages  68da9b6f71843f6180aff75c81513a96ba64b986
      requires  karchive/6.19.0#d6233ee0…:952b2781…
$ conan list "knewstuff/6.18.0:*" -r=ohpcd
      requires  karchive/6.18.Z
```

影响面不止一个库：当前 registry 状态下，仓库内已合入的 `kbreakout` / `kfourinline` / `kgoldrunner` /
`knavalbattle` / `kjumpingcube` 配方跑 `conan graph info` 都会报缺 `kiconthemes`。

## 修复方法（推荐）

选**与 karchive 6.18.Z 同源构建**的修订 `kiconthemes/6.18.0.1`，并显式 override，使 `kxmlgui` /
`knewstuff` 的 `6.18.Z` 区间统一解析到该修订：

```python
# conanfile.py requirements()
self.requires("karchive/6.18.0", override=True)
self.requires("kiconthemes/6.18.0.1", override=True)
```

定版前必须先核对二进制 requires，而不是只看 recipe 存在：

```bash
conan list "kiconthemes/6.18.0.1:*" -r=ohpcd | grep -E 'karchive|revisions'
# 期望看到 karchive/6.18.Z
```

## 验证

```bash
conan graph info archives/l/lskat/26.04.0 \
  -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 \
  --format=text | grep -A2 'Missing packages'
# 修复前：Missing packages: kiconthemes
# 修复后：无输出（0 missing，62 节点图）
```

lskat 26.04.0 实测：改 pin 后 `conan create` 一次通过，`test_package` 6 用例 / 8 断言全绿。

## 回退方案

若 6.18.Z 线确实没有可用修订，只能整体升级 KF6 到 6.26 线，并按 R36 拓扑序重建并重新发布
`libkdegames` 依赖链（A→B→C）后再回到目标库；该路径会改动下游全部 package_id，成本远高于方案 1。

## 禁止做法

- `--build=missing` 绕过：违反 R36（依赖必须先发布），且掩盖 registry 漂移，CI 会超时或红。
- 把 `Missing packages` 当警告忽略：会在配置/链接阶段以更难定位的错误复发。

## 适用范围

任何「同一版本包被重建、依赖线发生变更」的 Conan registry 漂移场景；本例为 KF6 6.18 闭包，
同一判据可用于 Qt6 拆分包、KF5→KF6 混线、以及自研多模块库链。
