# E429 — codeload 裸 URL 无扩展名触发 conan BadZipFile

## 错误特征

`conan create` 在 source() 阶段失败：

```
ERROR: <pkg>/<ver>: Error in source() method, line N
...
zipfile.BadZipFile: File is not a zip file
```

下载本身成功（"Sources correctly downloaded from https://codeload.github.com/…"），字节 sha256 正确，纯解压格式识别错误。

## 触发条件

- conandata.yml 的 sources.url 为 codeload 裸形态：`https://codeload.github.com/<org>/<repo>/tar.gz/refs/tags/<tag>`（URL 基名 = tag 名，无 `.tar.gz` 扩展名）
- conan 2.x 的 get()/unzip() 按下载文件扩展名识别格式，无扩展名回退按 zip 处理

## 根因分析

conan 以文件名扩展名判断解压器：`.zip`→zipfile、`.tar.gz/.tgz`→tarfile、无扩展名→回退 zip。codeload 裸 URL 的基名是 tag（如 `v6.4.0`），下载文件名为 `v6.4.0`，gzip 内容被 zipfile 解析即抛 BadZipFile。

## 解决方案

### 推荐方案

conandata.yml sources 显式声明 `filename`（get() 支持该参数覆盖 URL 基名）：

```yaml
sources:
  url: "https://codeload.github.com/<org>/<repo>/tar.gz/refs/tags/<tag>"
  sha256: "<sha256>"
  filename: "<repo>-<ver>.tar.gz"
```

### 禁止做法

- ❌ 把 tarball 手工放到 conan source 缓存里"绕过"下载（sha256 与 CI 复现性均失守）

## 验证

```bash
file <下载文件>   # 应为 "gzip compressed data"，而 URL 基名无 .tar.gz → 命中
```

修复后 `conan create` 通过 source() 阶段。
