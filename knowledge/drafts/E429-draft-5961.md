# E429 — Python 应用配方的未发布依赖三级处置

## 错误特征

```
ModuleNotFoundError: No module named 'jsonpatch'
ERROR: Recipe not found: yt-dlp/...
[L0i] Dependencies not published to registry (R36): yt-dlp/...
```

## 触发条件

- 构建系统: python（Conan `python-require` 配方，常见于 CLI 应用）
- 阶段: installation / runtime

## 根因分析

纯 Python 应用的上游依赖可分三类，混在一起处理必然踩坑：

1. **已发布到制品仓**：正常声明 `requires`。
2. **未发布但功能可降级**：声明进 `requires` 会被 R36 的 CI L0i 与 PR 前置 PF4 闸
   拦截（"Dependencies not published to registry"）；而它又不是可选项之外的可替代物。
3. **未发布且必需（含传递依赖）**：例如某已发布依赖在 import 期就需要一个仓库里
   根本没有的包——此时既不能声明（闸拦），也不能假设运行环境提供（干净消费者会崩）。

## 解决方案

### 推荐方案

按可得性分三级处置：

| 类别 | 处置 | 手段 |
|------|------|------|
| 已发布 | 声明 `requires` | 正常 Conan 依赖 |
| 未发布但可降级 | 守护补丁 | `try/except ImportError` + 仅在实际使用路径抛受控错误 |
| 未发布且必需/传递依赖 | pip 钉版本打入本包 | `pip install --no-compile --target=<stage> <pkg>==<ver>`，再复制进 site-packages |

配套：`package_info()` 必须用 `runenv_info.append_path("PYTHONPATH", site)`
把包内 site-packages 导出（只 `print` 路径不够，消费者 import 不到）；
test_package 用 `sys.executable` 调用脚本（`conanrun` 的 PATH 不含 python3）。

### 禁止做法

- ❌ `pip install --break-system-packages` 装进构建机系统环境：包内容不完整、
  不可复现，干净消费者 import 失败。
- ❌ 把未发布依赖直接写进 `requires`：CI L0i/PF4 直接拦截，PR 建不出来。
- ❌ 用 dummy 包顶替缺失依赖。

## 关联

- 预检命令：`bash ci/scripts/preflight_check.sh <pkg>/<ver> --deps "..."`
- 参考实现：`archives/t/tubeup/2026.5.8/`（internetarchive 已发布→requires；
  yt-dlp 未发布→守护补丁；jsonpatch/jsonpointer 不可获取→pip 钉版本打入包）
