# E429 — 流到数据报桥接必须区分错误、EOF 与有效载荷

## 一句话

面向文件或管道的 `read()` 是三态接口：负值是错误，零是正常 EOF，正值才是有效载荷。
若流到数据报的发送循环只判断 `< 0`，就会把 EOF 送入帧长度计算，出现无符号下溢、
伪错误退出或空包；回归测试必须同时断言进程成功、数据报数量及最后一帧边界。

## 失败现象与最小复现

vban/g20201011 的文件后端在输入耗尽时按 POSIX 契约返回 0，但上游发送循环只处理
`size < 0`，随后执行：

```c
format_nbs = payload_size / frame_width - 1;
```

64 字节有限 PCM 输入实际先发出唯一正确报文，然后 EOF 路径令 `format_nbs` 下溢为
255，报文被自身校验器拒绝，程序打印 `packet prepared is invalid` 并以 234 退出。
这不是理论风险：未修复上游构建的隔离探针实测 `rc=234, packets=1`；同一输入在修复后
`rc=0, packets=1`。

## 根因与可迁移解法

1. 在读取循环边界显式分派三种结果：`size < 0` 保留错误码，`size == 0` 正常结束，
   `size > 0` 才允许进入分帧、序列化和发送。
2. 不要把 EOF 特判藏进文件后端。文件、FIFO、管道和 stream socket 都以零长度表达
   流结束，应由消费读取结果的状态机统一处理；datagram socket 的零长度数据报是合法
   消息，不能套用此规则。
3. 回归预言机必须检查三个维度：进程退出码为 0、有效输入对应的报文数量精确、每个
   报文的样本数字段和载荷正确。只核对输出文件内容会漏掉“数据已发送但最终伪失败”。
4. 用有限输入覆盖边界；持续音频设备的成功路径不会自然产生 EOF，无法证明修复。

## vban/g20201011 一手证据

- 原始源码隔离构建对 64 字节、16-bit、双声道输入执行文件发送：唯一有效报文为 92
  字节，但进程在下一次读取后以 234 退出，并报告 `packet prepared is invalid`。
- 补丁在发送循环中将 `size == 0` 处理为正常结束，避免将 EOF 交给
  `packet_set_new_content()`。
- 新增测试使用独立 UDP socket 捕获有限输入，断言恰好一个数据报、样本数 16、帧号
  1、64 字节载荷原样，并要求发送程序以 0 退出；恢复上游循环后该测试稳定失败。
- 目录输入使文件后端稳定返回读取错误，测试要求非零退出且零数据报，证明负错误不会被
  正常 EOF 分支吞掉。
- 文件/FIFO 回环在无声卡环境中复用同一数据面；ALSA、PulseAudio 与 JACK 仍完整参与
  默认构建，没有通过关闭后端绕过依赖。

## 与既有知识的边界

- `E464` 是被调用的 `DataStream::read()` 在 EOF 后错误地继续返回非零，导致调用者按
  正常契约自旋；本条恰好相反：后端正确返回 0，调用者遗漏 EOF 分支，并把零长度送入
  协议长度算术，造成下溢和“先成功传输、后错误退出”。修复层分别位于被调用者与调用者。
- `E230` 关注 socket 宏矩阵不能替代真实回环；本条新增的是有限流跨入数据报协议时的
  三态状态机和精确报文基数预言机。
- `E285` 通过关闭外部音频后端保留 Null/loopback；本条保留全部默认后端，只以文件/FIFO
  触发同一发送状态机的 EOF 边界。
- `E6511-draft-6CBB` 已覆盖固定宽度网络字段与逐字节序列化，因此 vban 的显式线格式
  仅作为移植回归，不作为本条新增知识申报。

## 禁止做法

- 不得用 `size <= 0` 统一返回成功，否则会吞掉真实读取错误。
- 不得只验证首个报文或最终载荷；这无法发现尾部空包、伪错误状态和持续发送。
- 不得以禁用音频后端代替测试公共数据面；构建依赖与无设备运行验证是两个维度。

## 适用边界

适用于把文件、FIFO、管道或流式 socket 分块封装为 UDP、消息队列记录或磁盘帧的程序。
若接口以显式枚举而不是字节数表达 EOF，应按其契约分派；若协议明确定义零长度帧，则必须
另设 EOF 信号，不能直接把 `read()==0` 等同于一个合法空帧。
