# E430 — OHOS/CI：make 直接 exec `#!/usr/bin/env bash` 上游脚本失败

## 错误特征

```
make: tools/make-chromium.sh: Resource temporarily unavailable
make: *** [Makefile:27: dist/build/uBlock0.chromium] Error 127
```

- 同类：`make: <script>: Resource temporarily unavailable` + `Error 127`；
  或 `.sh: no such file` / `bad interpreter: /usr/bin/env`。
- 特征：**本地开发机 W3 通过，远端 CI 失败**（环境差异）。

## 触发条件

- 构建系统: make（Makefile recipe 直接引用 `tools/xxx.sh`）
- 阶段: build（`make <target>` 首次执行目标脚本时）

## 根因分析

上游构建脚本 shebang 为 `#!/usr/bin/env bash`。GNU make 对**不含 shell 元字符**的
recipe 行会走「直接 exec」优化（不经 `/bin/sh`），于是 `execve("tools/xxx.sh")`：
内核读 shebang → 先 exec `/usr/bin/env`（OHOS 上是 toybox 软链）→ 再由 env 按名 exec bash。

在 OHOS/CI（AppSpawn 沙箱）下该执行链失败，make 报出 EAGAIN
（`Resource temporarily unavailable`）并按其约定以 `Error 127` 终止。
`/usr/bin/env` 在本地开发机可正常执行，故**本地 W3 复现不到**，仅在远端 CI 暴露。

（对照：make 的 `$(shell ...)`、以及显式 `bash script.sh` 均正常 —— 因为前者经 shell、
后者 exec 的是 bash 自身而非脚本，均不触发脚本 shebang 链。）

## 解决方案

### 推荐方案

1. **配方改用显式 bash 调用顶层脚本**：`bash tools/make-xxx.sh`
   （bash 自行读取脚本，不触达 shebang 链）。仓库既有约定见 `archives/u/uglify`
   （`bash run_upstream_tests.sh`）、`archives/l/leaflet-markercluster`（`bash test.sh`）。
2. 若上游脚本内部仍有 `./tools/*.sh` 调用，用 **patch 改为显式 bash**：
   `bash ./tools/make-nodejs.sh "$DES"`；避免任何一层再触发 shebang。
3. 或按 **E165** 将 shebang 直接改为 `/data/service/hnp/bin/bash`
   （OHOS 无传统 `/bin`；`/data/service/hnp/bin/bash` 为稳定软链）。
   注意：若失败根因是「脚本文件所在挂载点不可 exec」，仅改 shebang 无效，须用 1+2。

### 禁止做法

- ❌ 用 `--build=.../--host=.../--target=...` 绕过（OHOS 为 native 编译，见 E165）。
- ❌ 把失败归因于「源码编译错误」而改源码（本例根本不是编译问题，是脚本执行问题）。

## 验证

```bash
head -1 tools/*.sh                     # 确认 shebang 为 #!/usr/bin/env bash
grep -n '^bash ./tools/' tools/make-npm.sh   # 补丁后应为显式 bash
# 修复后 build 日志：出现 `bash tools/xxx.sh` 且脚本正常输出（无 Resource temporarily unavailable）
```
