# E4300 — HMDFS 大小写不敏感：构建目录的 VERSION 文件顶替 C++20 `<version>` 标准头

## 错误特征

```
In file included from .../libcxx-ohos/include/c++/v1/cstddef:42:
../version:1:1: error: a type specifier is required for all declarations
VERSION="0.10.2"
^
../version:1:17: error: expected ';' after top level declarator
In file included from .../libcxx-ohos/include/c++/v1/new:192:79:
error: no type named 'size_t' in namespace 'std'; did you mean simply 'size_t'?
error: no type named 'nothrow_t' in namespace 'std'
error: no type named 'align_val_t' in namespace 'std'
fatal error: too many errors emitted, stopping now [-ferror-limit=]
```

只有 `.cpp` 编译单元中招；同一目录下的 `.c` 文件全部正常。报错面看起来像
libc++ 头自己坏了。

## 触发条件

- 构建系统：autotools / automake，且 `configure.ac` 里有 `AC_CONFIG_FILES([VERSION ...])`
- 文件系统：大小写不敏感（HMDFS；`os.path.samefile('MAN','man')` 为 True）
- 只要编译含 libc++ 标准头的 C++ 源文件即可命中

## 根因分析

1. `AC_CONFIG_FILES([VERSION ...])` 在**构建根目录**生成文件 `VERSION`
   （lirc 的 tarball 里还另外带了一份 `VERSION`）。
2. libc++ 的 C++20 头在 `cstddef`、`string`、`new`、`type_traits` 等 70 个文件里
   写 `#include <version>`（无任何宏守卫）。
3. automake 给每个子目录的编译单元注入 `DEFAULT_INCLUDES = -I. -I$(top_builddir)`，
   构建根目录排在 C++ 标准库之前。
4. HMDFS 大小写不敏感 ⇒ `-I..` 下的 `version` 命中 `VERSION` ⇒ clang 把一个
   文本文件当 C++ 头解析。

`AM_CPPFLAGS = -I$(top_srcdir)` 在 **out-of-tree 构建**里会展开成绝对路径
（`-I/storage/.../b`），字符串与 `-idirafter ..` 不同、不会被去重，所以只改
`DEFAULT_INCLUDES` 仍会中招 —— 必须同时处理源树里的那份 `VERSION`。

## 解决方案

### 推荐方案

```python
# conanfile.py build()：删除源树里 tarball 自带的 VERSION（构建目录会重新生成）
os.remove(os.path.join(self.source_folder, "VERSION"))
```

```make
# 同时把构建根目录降级到系统头之后
make "DEFAULT_INCLUDES='-I. -idirafter ..'"
```

`config.h` / `paths.h` 这类唯一名字经 `-idirafter` 仍可解析；`make install` 的
`dist_doc_DATA = VERSION` 规则是 `if test -f "$$p"; then d=; else d="$(srcdir)/"; fi`，
先用构建目录的同名文件，所以删源树副本不影响安装。

### 禁止做法

- ❌ 改 `-std=c++11/17` 或加 `-Wno-error=*`：与标准版本无关（引擎实测会误判成
  E130「libcxx 头需要 C++17」）。
- ❌ 只 `rm VERSION`：out-of-tree 构建里构建目录的那份仍会通过
  `-I$(top_builddir)` 命中；in-tree 构建里删构建目录那份又会让 install 失败。

## 验证

```bash
printf '#include <version>\nint main(){return 0;}\n' > "$TASK_DIR/probe_ver.cpp"
clang++ -c -I. -I.. -o /dev/null "$TASK_DIR/probe_ver.cpp"; echo rc=$?
# 目录里存在 VERSION 时 rc=1 且复现 "type specifier is required"
```

lirc 0.10.2 实测：修复后 `conan create` rc=0，上游 CppUnit 套件 35 条全部执行
（Run: 35）。
