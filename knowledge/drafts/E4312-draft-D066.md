# E4312 — 鸿蒙 PC 无并口/打印机设备节点：编译能过的 linux/lp.h + linux/ppdev.h 面在运行期无物可测

## 错误特征

典型症状分三类，**构建日志里一条都没有**：

```
# 运行期（真实设备路径）
No access to device file or no attached printer.
ioctl: No such file or directory
/dev/parport0: No such file or directory
open: No such file or directory

# 而构建期是干净的
configure: ... checking for linux/lp.h ... yes
make: Compile cmd.c / Compile d4lib.c / Link mtink   (0 error)
```

两个面必须一起看：
- **设备面**（本机实测，2026-10-18，HarmonyOS PC / aarch64）
  `ABSENT: /dev/lp0 /dev/lp1 /dev/parport0 /dev/usb/lp0 /dev/usblp0`
  `PRESENT: /dev/tty /dev/null /dev/urandom /dev/watchdog`
- **头文件面**：sysroot **有** `linux/lp.h`、`linux/ppdev.h`、`linux/parport.h`，
  许多包还自带 `detect/parport.h`、`detect/ppdev.h` 副本。

⇒ `LPIOC_GET_DEVICE_ID`、`PPCLAIM`、`PPNEGOT`、`PPSETMODE` 这些 ioctl
**编译通过、链接通过**，但运行期一次都执行不到真语义。这就是「假绿面」：
全绿不代表功能被验证过。

## 触发条件
- 构建系统: 任意（手写 Makefile / autotools / cmake 均可命中，本例为上游手写 `Configure` + `Makefile.ORG`）
- 阶段: runtime（编译/链接阶段不报任何错）
- 软件类型: 并口/USB 打印机的状态监视器、CUPS backend、任何用
  `linux/lp.h` / `linux/ppdev.h` ioctl 或写死 `/dev/lp*`、`/dev/parport*`、
  `/dev/usb/lp*` 节点的用户态程序

## 根因分析

1. 鸿蒙 PC 不提供 lp/ppdev/usblp 三条设备链，设备节点整片缺失；
2. 但 OHOS sysroot 保留了对应的**内核 uapi 头文件**，所以包含与 ioctl 宏
   全部可编译——构造上「编译期无法暴露」；
3. 上游老代码把设备节点列表硬编码进源码（mtink `cfg1.c` 的 `deviceList[]` 实测
   **54 条**（去重 53：上游自身重复 `/dev/usb/lp9`、漏 `/dev/usb/lp8`）：
   `/dev/lp0-3`、`/dev/usb/lp0-15`、`/dev/usblp0-15`、`/dev/ecpp0-4`、
   `/dev/lpt0-2` …），在鸿蒙上 100% 落空，而失败措辞指向「打印机没接/没开机」，
   把归因带偏到硬件而非平台能力；
4. 于是最常见的错误结论是「跑不起来，跳过」——它既不是配方缺陷也不是平台
   适配缺陷，而是**未覆盖范围**；写成跳过就丢失了「编译通过但运行期零覆盖」
   这个真实风险。

## 解决方案

### 推荐方案：用无头入口/探针取退出码（headless-entrypoint-probe-with-exit-codes）

(a) **先走不碰硬件的真实入口**并量化：
```bash
ttink -v     # rc=0  → "ttink   : V 1.0.16"
ttink -l     # rc=0  → 90 行型号表（== 数据文件 91 条 .PRINTER 记录减上游 off-by-one）
ttink -h     # rc=0  → "Arguments for ttink" + "-d device_file --device device_file"
ttink        # rc=1  → 用法打 stderr（fail-closed）
```

(b) **再对真实设备路径取退出码与逐字措辞**，两条都要（这是本条的判据核心）：
```bash
ttink -d /dev/lp0  -i   # rc=1 节点 ABSENT
ttink -d /dev/null -i   # rc=1 节点 PRESENT 但非打印机
# 两者都以 "No access to device file or no attached printer." 收口
# 后者证明失败点在「打印机应答」而不是 open()，即设备逻辑真的跑到了
askPrinter /dev/lp0      # rc=1 并口面：access("/dev/parport0") 失败
askPrinter /dev/usb/lp0  # rc=1 USB 面：open("/dev/usb/lp0") 失败
```

(c) **把设备节点存在性本身写成测例**（逐节点 PRESENT/ABSENT 打印），
使「并口 ioctl 面已走通到确定的失败」在 test_package 里可复核
（mtink 1.0.16 的 `test_package/test_mtink.sh` 即此形态，29/29 通过）。

上游没有无头入口时，按 rfdump 的 `--probe-reader` 手法补一个「只跑初始化、
不开窗、按失败类别给不同退出码」的探针入口，补丁类型标 `test`。

### 回退方案
设备链完全不可得且上游无任何无头入口时，用同协议的**独立参考实现**在同一输入
上做差分（例如把 `Recv:` 报文喂给上游自带的文件回放模式），把「只能跑不能判」
补成真 oracle；差分阈值与行覆盖率必须写进证据表。

### 禁止做法
- ❌ 用「跑不起来 / 无法测试」当结论并跳过——那会让一个构建全绿、运行期零
  覆盖的包看起来像已完成适配。

## 验证

```bash
conan create archives/m/mtink/1.0.16 \
  -pr:h=ci/conan/profiles/ohos-aarch64 \
  -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
# → rc=0；HMBS_TEST_PACKAGE_RESULT {"discovered":29,"passed":29}
# 其中包含 /dev/lp0（ABSENT）与 /dev/null（PRESENT 非打印机）两条真实设备路径的退出码断言
```
