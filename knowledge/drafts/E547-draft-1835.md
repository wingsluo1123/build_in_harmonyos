# E547 — Conan 缓存残缺二进制包被误视为完整导致 test 假失败

> 软件事件: r-base 4.5.1.2（鸿蒙PC aarch64, conan 2.x）
> 日期: 2026-10-11 | 状态: DRAFT（待主编审核合入）

## 错误特征
- `conan create ... --build=missing` 显示 `r-base/4.5.1.2: Already installed! (Cache)`，
  test_package 阶段 `bin/R RHOME` 返回 `//lib/R` 而非移动包内 R home；
- 直接检查缓存包目录：整棵 `lib/R/bin/`（exec/R、Rscript 等）缺失，
  但 conan 仍认为该 binary 完整、可直接命中缓存；
- 同一配方重跑 create 结果不变（二进制被反复复用）。

## 触发条件
- 构建系统: conan 2.x（任何以大目录 `copytree` 实现 package() 的配方）
- 阶段: installation（package() 中途被 kill/OOM/超时中断）→ 之后的 testing
- 前提: 本地或 worker 共享同一 `CONAN_HOME` 缓存；中断后未清理缓存再次 create。

## 根因分析
conan 以 package_id 的存在判定 "Already installed"，不校验包目录内容完整性。
package() 内 `copytree(stage → package_folder)` 被中断时留下部分拷贝，
该残缺目录被缓存机制视为成品，后续 create/test 全部复用，产生"假绿/假红"：
症状指向配方或测试脚本，实际是缓存产物残缺。

## 解决方案

### 推荐方案
1. 对比 staging 与缓存包目录树确认缺失：
   `diff <(cd $STAGE && find . | sort) <(cd $PKG && find . | sort)`
2. 清除该 ref 的全部二进制缓存后从源码全量重建：
   `conan remove "name/ver:*" -c && conan create . -pr:h=$P -pr:b=$P --build=missing`
3. 以重建产物为权威验证依据（W3 必须基于真实重编译）。

### 禁止做法
- ❌ 仅凭 test 日志改配方/测试脚本重试——缓存命中不变，纯属空转；
- ❌ 手工向缓存包目录补拷文件——违反产物真实性（结果必须来自完整构建）。

## 教训
缓存命中 ≠ 产物完整。验证类工作流（W3/CI 模拟）前，若本地缓存二进制来自
可能被中断的运行，必须清除后重build；"Already installed" 只是缓存结论，
不是完整性证明。
