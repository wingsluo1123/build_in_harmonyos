# QSharedDataPointer 前置声明类型的复制赋值需要 out-of-line 定义

状态：草稿；来源为 HarmonyOS PC aarch64 上 kdsoap-ws-discovery-client 0.4.0 的 Conan 消费者编译失败。

## 错误特征

独立消费者在把 `probeMatchReceived` 的 `const WSDiscoveryTargetService &` 参数赋值到另一个 `WSDiscoveryTargetService` 对象时，Qt 6 报 `member access into incomplete type 'WSDiscoveryTargetServiceData'`。库本身及其上游测试已经成功编译。

## 根因

公开类将 `QSharedDataPointer<WSDiscoveryTargetServiceData>` 作为成员，数据类只在 `.cpp` 中定义。头文件显式声明了复制构造函数和析构函数，但没有声明复制赋值，因此编译器生成的赋值运算符在包含公开头文件的消费者翻译单元中内联实例化 `QSharedDataPointer` 代码，触及不完整类型。

## 修复方式

在类定义中声明 `WSDiscoveryTargetService &operator=(const WSDiscoveryTargetService &other);`，然后在 `WSDiscoveryTargetServiceData` 定义之后于 `.cpp` 中写 `WSDiscoveryTargetService &WSDiscoveryTargetService::operator=(const WSDiscoveryTargetService &other) = default;`。用独立消费者的对象赋值覆盖回归。

如果对象赋值不是库 API 需求，测试回调也可以只复制 endpoint 与 XAddr 等独立字段，但这只是绕过该调用路径，不代表公开类型已支持复制赋值。

## 验证

HarmonyOS PC 6.0 aarch64 上应用补丁后，Conan `test_package` 的安装 API 消费者和 UDP loopback SOAP 测试均通过；Conan create 以及 W3 本地 CI 均通过。原始构建日志在对应版本的 `reports/conan-create.log`。
