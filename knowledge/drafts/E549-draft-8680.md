# 字符匹配结果转整行区域时，验证文本内容守恒

本条来自 manuel 1.13.0 普通公开文档区域 API。适用场景是解析器按字符偏移
确定开始/结束标记，但登记区域或删除原文时按整行操作。不能只验证行号、行数
相等：同一行尾部的字符可能已经丢失。不是 OHOS 专属，也不是正则匹配失败。

## 原问题与触发条件

```python
import re
import manuel
text = 'BEGIN block\nbody\nEND block\ntail\n'
document = manuel.Document(text)
[region] = document.find_regions(re.compile(r'^BEGIN.*$', re.M),
                                 re.compile(r'^END', re.M))
document.claim_region(region)
assert ''.join(part.source for part in document) == text
```

固定原源码在Windows原探针中，region.source为 `BEGIN block\nbody\nEND\n`，
重组为 `BEGIN block\nbody\nEND\ntail\n`，没有异常但少了 ` block`。
结束正则改为 `^END.*$` 或 `^END block$` 的同源正常对照则保留全部文本。
可将失败的不变量诊断为 `MANUEL_REGION_CONTENT_LOSS`；本条匹配此明确诊断，
不把一般 AssertionError、正常行数或 find_regions 方法名单独当成错误签名。
历史复现来源是当日已保留的原探针，本轮未重跑该未变探针。

## 根因与修复

`find_regions()` 原本试图将 end_match.end() 扩到完整行尾。
`find_end_of_line()` 的循环上界反向，end从0开始，扫描从不执行。
`claim_region()` 则按区域包含的换行数切掉原行，故行数断言通过而字符丢失。

修复扫描上界前，还必须区分偏移是否已经是行边界：结束正则可能自身吃掉换行，
此时偏移是下一行起点，继续扫描会错误吞入下一行。第一次仅修循环上界时，
完整原suite在解析代码块发生IndentationError；这个真实失败说明原suite是必要对照。

最终局部修法为：

```python
def find_end_of_line(s):
    end = 0
    while end < len(s) and s[end] != '\n':
        end += 1
    return end

# 在 find_regions 内，取得结束匹配后：
end_position = end_match.end()
if end_position == 0 or region.source[end_position - 1] != '\n':
    end_position += find_end_of_line(region.source[end_position:])
```

保留原字符数据、原行数断言以及原suite，不用放宽原断言、跳过代码块或
将结束正则强制改为整行来掩盖API缺陷。补丁文件在
`archives/m/manuel/1.13.0/patches/0001-src-manuel-__init__.py.patch`。
这是人工核查并执行的局部补丁，rec_auto_fix=false，不声明任何未实现的自动修复。
