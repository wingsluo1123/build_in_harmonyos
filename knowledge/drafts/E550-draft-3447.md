# E550 — 非 C/C++ 主体语言库（Node.js/npm 前端）误入 Conan 适配流程

> 草稿状态（knowledge/drafts/，待评审委员会审核后由主编 promote 转正式条目）
> Agent: 3447 · 日期: 2026-10-15 · 触发案例: jellyfin-web 10.11.11

## 1. 问题签名（error_signature）

```
语言不匹配: task=cpp, detected=nodejs
package.json + package-lock.json + webpack/vite/babel/tsconfig
detected_language = nodejs
```

## 2. 根因（root_cause）

部分三方库（典型如 jellyfin-web——Jellyfin 的 Web 前端）构建主体是
**npm + webpack/vite** 等 JavaScript 工具链，而非 C/C++ 编译器。将其纳入
本仓库的 Conan 适配流程时存在三重不可行：

1. **CI 无 Node.js 工具链**：远端 clean 环境的 CI 能力矩阵中
   gcc/clang/cmake/make ✅、OCaml 可用 `tool_requires` 补齐、但
   Node.js/npm ❌ 且无法从 conan 制品仓补齐；
2. **依赖生态不匹配**：npm 库依赖数百个 npm 包（jellyfin-web 的
   package-lock.json 含上千条目），全部不在 conan 制品仓内，
   R36「依赖必须先发布再构建下游」的拓扑序无法建立；
3. **产物形态不匹配**：前端库产物是静态 JS/CSS/HTML 资源包，
   不产出 aarch64-linux-ohos 的 ELF 二进制，conan 的
   L4/L5（NX/PIE/RELRO）门禁无适用对象。

若跳过语言预检直接动手（手写 conanfile 调 npm、或伪造配方），会在
configure/build 阶段反复失败，浪费整段任务预算（历史教训：0828 报告
~20% 任务浪费在非 C/C++ 源码上）。

## 3. 推荐处置（rec_approach = lang-preflight-gate）

**在 checkout 源码后、进入适配主流程前强制执行 R47 语言预检**：

```bash
python3 $SKILL_ROOT/scripts/ohc-run.py lang-preflight <name> <ver> --src $BUILD_SRC_DIR
```

- **exit 0**（c/cpp 兼容族）→ 正常进入 W0-W5 主流程；
- **exit 2**（判定 nodejs 等非 C/C++ 主体）→ **立即止损**：
  - 终态上报 `env_unsupported` + `detected_language=nodejs`
    + `language_evidence` 三项（build_system / manifest / source_stats，
    各 ≤200 字符）——协议 v0.8 附录 D 强制字段，缺失 = PROTOCOL_VIOLATION；
  - 平台按 **lang_hold 挂起等生态**（激励口径，非失败记录）；
  - **禁止**硬着头皮适配、禁止手写绕过 CLI 的 result.json。

## 4. 判定细则（一类问题的通用判定）

满足以下任一组合即判定为 nodejs 主体（lang_detect.py 已自动实现）：

| 信号 | 权重 |
|---|---|
| 根目录 `package.json` | manifest 级（最高优先） |
| `webpack.config.*` / `vite.config.*` / `babel.config.*` / `tsconfig.json` | build-system 级 |
| src/ 下 JS/TS 文件占比 ≥ 70% | source-stats 级 |

边界规则：C/C++ 混编按主体判；pybind11 绑定包判 cpp；辅助脚本不算主体；
manifest 与统计矛盾判 mixed。

## 5. 兜底与未来出路

- 平台未来若立项 **Node.js 工具链包**（参照 pdfsandwich 正例：
  `tool_requires ocaml/4.14.1.1.4` 路线），此类库可重新评估适配；
- 评估后确认无法适配的，按任务口径以 Issue 报告释放，不产出 PR。

## 6. 验证案例

- jellyfin-web 10.11.11（官方 tag v10.11.11）：259 个源文件中
  JS/TS 占 255（98%），lang-preflight exit 2 → 已按协议上报
  `env_unsupported` + `detected_language=nodejs` + 三项证据，
  未消耗任何编译预算。
- **上游测试实证补充（2026-10-15，鸿蒙PC 真机）**：本机具备
  Node.js v22.23.2（OHOS 适配版）时，上游测试**可以真实运行**——
  `npm ci --ignore-scripts` + 自签名原生 ELF（binary-sign-tool，
  鸿蒙 ELF 签名门禁）+ rollup 原生绑定换 `@rollup/wasm-node`
  （native .node 在 OHOS node 上 dlopen 段错误）后，
  `vitest run` **12 个测试文件 / 160 个用例全部通过（160/160，100%）**。
  教训：R47 语言判定与止损结论不受影响（主体语言仍为 nodejs，
  conan 配方路线仍不可行），但「上游测试从未运行」不应作为默认陈述——
  具备 Node 环境时应真实执行并如实申报（R51 上游测试三步法）。
