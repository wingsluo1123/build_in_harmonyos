# E550 — Conan CMakeDeps imported targets need bridging for legacy CMake variables

**撞车判定**：`Boost_PROGRAM_OPTIONS_FOUND`、`FFTW3_LIBRARIES`、`LIBSAMPLERATE_FOUND` 与 “CMakeDeps imported target” 的组合在正式条目中没有精确覆盖；E278/E392 只覆盖相邻症状。

## Scope

- 上游 CMake 使用 `find_package(Boost COMPONENTS ...)` 后检查 `Boost_*_FOUND`
- 上游 CMake 使用 `pkg_check_modules(... fftw3)` 或自定义 `FindLibSamplerate.cmake`
- 依赖由 Conan `CMakeDeps` / `PkgConfigDeps` 提供
- 典型症状是配置阶段报 “required but not found”，或链接阶段报 `unable to find library -l...`

## Symptom

```text
CMake Error at CMakeLists.txt:31 (message):
  libboost_program_options is required but not found

CMake Error at CMakeLists.txt:68 (message):
  libsamplerate not found, but required

ld.lld: error: unable to find library -lfftw3
```

## Root Cause

Conan 2 的 `CMakeDeps` 在 config 模式下导出 imported targets，例如 `Boost::program_options`、`fftw::fftw`、`libsamplerate::libsamplerate`。但上游 CMake 若按 module/pkg-config 时代的写法检查 `Boost_PROGRAM_OPTIONS_FOUND`、`LIBSAMPLERATE_FOUND`，或把 `FFTW3_LIBRARIES` 里的裸 `-lfftw3` 传给 `target_link_libraries`，这些 legacy 变量和裸名称不会自动携带 Conan 的 imported target 语义或私有 libdir。于是依赖实际存在，配置或链接仍然失败。

## Workaround / 修复

优先在 Conan 配方 `generate()` 里桥接，而不是改上游源码：

1. 上游调用 `find_package` 时，把 legacy cache 变量设置为 imported target，例如：
   - `Boost_PROGRAM_OPTIONS_FOUND=True`
   - `Boost_PROGRAM_OPTIONS_LIBRARY=Boost::program_options`
2. 上游只走 `pkg_check_modules` 时，不要假设 imported target 已被加载；用依赖包的绝对库路径和 include 路径填充 `FFTW3_LIBRARIES`、`FFTW3_INCLUDE_DIRS`
3. 自定义 Find 模块同理，填充 `LIBSAMPLERATE_FOUND`、`LIBSAMPLERATE_LIBRARY`、`LIBSAMPLERATE_INCLUDE_DIR`

若桥接过于复杂，回退方案是补丁上游 CMake，改为 `find_package(... CONFIG REQUIRED)` 并直接链接 imported target。

## Prevention

- 先读上游 CMake 的变量使用方式，再决定是桥接还是补丁
- 不要把 `CMakeDeps` 生成日志中的 target 名直接塞给未调用 `find_package` 的上游链接行
- 不要用裸 `-lfoo` 名承担 Conan 私有库路径
