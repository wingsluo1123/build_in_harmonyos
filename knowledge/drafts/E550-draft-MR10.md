# ARM64 透明懒编译回调必须保存完整 SIMD 宽度

## 场景与触发特征

解释器、预编译整函数正常，lazy/basic-block 后端却在 long double 比较或算术上静默出错。错误可能只出现于首次冷调用，热路径并不必然重现。遇到这种模式，先区分数值运算本身、参数 ABI、隐藏编译回调和完整值保存；不要把所有 ARM64 浮点错误都归为同一种原因。

## 精确根因

[AAPCS64 §6.1.2](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst#612simd-and-floating-point-registers)规定外部 C 调用只须保持 v8–v15 的低 64 位。Q/D/S 是同一寄存器的不同宽度视图，不能把“callee-saved”理解成完整 128 位保留。

对透明插入的 JIT 编译回调，程序和分配器并不知道发生了一次 C 调用。基本块边界的活跃 Q 值、以及内部 JIT callee 更强的完整宽度保存契约，都必须由回调 wrapper 自己承担。函数首次编译回调与基本块首次编译回调是两个独立入口；修复后者不会自动修复前者。

## 可复用决策与修复

1. 用同一数值输入比较解释器、预编译整函数、lazy-function、lazy-BB 的冷/热执行。保留 stdout、精确退出码与类型宽度，不只看进程是否启动。
2. 从生成后的 IR/汇编找到跨回调仍活跃的寄存器；区分外部 C ABI、生成代码内部调用契约和基本块边界契约。
3. 枚举所有不可见回调入口。按完整值宽度保存 caller-clobbered 状态；v8–v15 上半部不能因其下半部是 callee-saved 就被遗漏。
4. 使用成对 Q 寄存器 push/pop，逆序恢复，保持 SP 16 字节对齐。检查旧栈偏移仍与原保存槽对应，并避免覆盖回调返回的跳转地址。
5. 先复跑真实失败项，再跑完整上游模式、bootstrap 和安装包消费者。中间的 4/5 只能作为失败定位证据，不能包装为适配通过。

## 本次证据及反例

MIR 1.0.0 的 OHOS ARM64 `r15` 中，解释器与整函数模式各1069/1069，但 lazy-BB 的1073项有5项失败。原基本块回调保存 Q0–Q7 与 Q16–Q31，却遗漏 Q8–Q15。补齐它后，`r16` 的定向回归只有4/5；这直接否定“只改基本块 wrapper 就够了”。

`r18` 同一打印用例解释器/整函数退出142，而 lazy-BB 退出141，第二次传入的22.5打印为0。`r19` 生成 IR 显示主函数把该值保存在 Q8，首次编译被调函数的 C 回调发生在真正 callee prologue 之前，另一入口同样只保存 Q0–Q7。补齐首次函数入口后，`r20` 的5项定向回归均通过。完整套件及正式 Conan 结果单独保存在软件版本报告，以真实终态为准；定向5/5不代表7544/7544或平台CI通过。

随后 `r20` 完整执行并通过7544/7544项配置内上游测试及消费者1/1，12阶段回执全部完成、runner退出并release/postrelease通过。该探索性完整原生日志SHA-256为 `a5e604b19cc53f55b20bfa1880beb98745816d460e2dc8583f996ac3c7979ecd`。正式Conan与比赛worker CI仍须各自的真实证据，不从探索性结果推导。

独立正式 Conan `mir-conan-w3-20261014-r5` 随后在shared/static两种构建中各通过7544/7544与安装包消费者1/1，完整12阶段收尾通过；原始日志SHA256 `d7dad87c0df2a050b23c33f712c38b056a353640a401e9e3f00081c85bc333e1`。这验证同一修复经官方源码解包和配方补丁可复现，不代表比赛worker CI或评审已通过。

## 适用与安全边界

### 条件后端必须实际启用，测试入口数量不是能力证明

历史证据纠正：回读 r5 原始正式日志也找到该签名路径异常，且没有 `-DC2MIR_PARALLEL`。其7544/7544和原PASS回执保留为当时实际配置下的结果，不再把这个计数直接解释成条件并行后端已验证；不能改写旧回执来掩盖这一限制。

验证透明回调或并行生成器前，先检查构建探测是否真正启用了对应后端。MIR CI92782 中，签名包装器只允许 out-of-source 构建根，而原线程探测把 `__tmp.out` 放在任务拥有的源码根；编译成功后的签名检查抛出异常，被上游 `check-threads.sh` 转为能力探测失败。这可能静默去掉 `C2MIR_PARALLEL`，不能仅凭已注册并运行 parallel 测试入口就宣称线程后端已验。

可复用处理是明确列出任务拥有的源码/构建根，在编译前拒绝外部或符号链接输出，而不是取消签名检查或放开公共父目录；再从实际编译日志检查条件宏。另按既有 E074 处理 Make FIFO 限制，只把构建调度设为 `-j1`，保持运行时 parallel-generation/bootstrap 用例。签名范围、构建任务并发和被测运行时线程是三个独立契约。当前修复的完整真机终态和日志哈希以版本测试报告为准；不能从此前 r5 或单独探测结果推导新候选通过。

修复后的正式原生 r6 已在 shared/static 中各通过7544/7544与消费者1/1，确认实际编译启用 C2MIR_PARALLEL，原并行 bootstrap/生成测试保持执行。合并日志有62次真实编译宏，探测签名路径异常和FIFO错误均为0；12阶段与release/postrelease通过，原始日志SHA256为 `ae9c0d873ed93e5142948e0499c52e62b1810c8d81395f3e9e0b90ed93082b9b`。这提供当前功能配置的正式证据，仍不等于比赛worker CI或平台评审通过。

该模式可用于 AArch64 JIT、透明 instrumentation、FFI 或 runtime 编译回调，不依赖 MIR 的名称或某个版本。必须证明隐藏边界与活跃128位状态；普通C调用并没有保存全部Q寄存器的普遍义务。仅有64位double时也不能凭本条盲目扩展保存集合。

不覆盖 SVE/SME 可伸缩状态，不覆盖 C99 HFA 参数签名错位或 softfloat 字序。查重命中的 `DRAFT-lfortran-complex32-c99-hfa-abi` 与 `DRAFT-PCCLIBS-AARCH64-SOFTFLOAT-FPA-WORD-SWAP` 分别处理这两类不同根因，本条的新知识是“隐藏回调、完整寄存器宽度、双入口闭环”。

禁止把 long double 降为double、修改期望退出码、删掉失败测试或把lazy-BB替换为整函数后端来获得绿色结果。任何 opcode 修改仍须经过完整真实目标测试，不把ABI文档或静态阅读当成运行通过。
