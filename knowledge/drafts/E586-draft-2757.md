# E586 — 新建文件的补丁必须带 `/dev/null` 源标签，否则 Conan 的 patch_ng 拒绝应用

## 错误特征

```
ERROR: kitchen/1.2.6: Error in source() method, line 61
	apply_conandata_patches(self)
	ConanException: Failed to apply patch: .../patches/0003-kitchen3-extra-upstream-tests.patch
```

`patch_ng` 的原始报错是 `source/target file does not exist: --- b'kitchen3/tests/...'`，
而同一补丁在本地用 `patch -p1` **成功**应用，给出假绿。

## 触发条件

- 工具链: Conan（`apply_conandata_patches` / `export_conandata_patches`）
- 阶段: source
- 补丁类型: **新建文件**（hunk 头为 `@@ -0,0 +1,N @@`），但 `---` 侧写成了 `a/<新路径>`

## 根因分析

Conan 用 `patch_ng` 应用补丁。`PatchSet.apply()` 只在这一个分支里创建新文件：

```python
if "dev/null" in source:          # patch_ng.py:1059-1063
    save(target, new_file)
```

`--- a/<新路径>` 会走普通分支：`findfiles()` 在源码树里找不到源侧文件，直接报
“source/target file does not exist”。GNU `patch -p1` 因为 `-0,0` 这个 hunk 头而
推断“新建文件”，所以**只用 `patch -p1` 验证会漏掉这个缺陷**，直到 CI 里
`conan create` 才炸。

## 解决方案

### 推荐方案

用 `/dev/null` 作为源侧标签生成补丁：

```bash
diff -u --label /dev/null --label "b/kitchen3/tests/nose/tools.py" \
     /dev/null kitchen3/tests/nose/tools.py > patches/0004-nose-shim.patch
```

并用 **Conan 同款解析器**复验（注意 Conan 默认 `strip=0`，`a/`、`b/` 前缀由
`patch_ng` 自己剥离；传 `strip=1` 会把路径首段剥掉，写错位置却仍返回 `True`）：

```bash
python3 -c "import patch_ng; \
print(patch_ng.fromfile('patches/0004-nose-shim.patch').apply(strip=0, root='/tmp/tree', fuzz=False))"
```

### 禁止做法

- ❌ 新建文件补丁的 `---` 侧写 `a/<新路径>`（GNU patch 假通过，CI 必挂）
- ❌ 只用 `patch -p1` 验证就认为补丁没问题
- ❌ 给 `patch_ng.apply()` 传 `strip=1`（路径首段被剥掉，会把文件写到错误位置）

## 验证

```bash
patch_ng.fromfile(p).apply(strip=0, root=<解压后的源码树>)  # 期望 True，且目标文件出现在正确的仓库相对路径下
```

实测：kitchen 1.2.6 的 `0003`/`0004`（新建执行器与 nose 垫片）改用 `/dev/null` 头后
`conan create` 正常应用；改回 `a/` 头即复现上述报错。
