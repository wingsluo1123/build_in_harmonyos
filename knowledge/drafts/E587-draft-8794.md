# E587 — Conan 2 未给 python-require 强制 run trait，传递 Python 依赖被 BINARY_SKIP 跳过

- **严重程度**: 🟡 medium (2)
- **分类**: python, conan, dependency
- **触发工具**: conan create / conan install
- **阶段**: testing / runtime
- **状态**: 草稿（draft，contributor 8794）
- **来源任务**: toot 0.52.1 HarmonyOS PC aarch64 适配

## 现象

`conan create` 构建成功，但日志出现 `SKIPPED`（BINARY_SKIP）行；进入 test_package 阶段报：

```
ModuleNotFoundError: No module named 'requests'
```

或换任意一个传递的 Python 依赖名。外部消费者执行
`conan install --requires=<pkg>/<ver>` 后，运行时报同样的 ImportError。

## 根因

Conan 2 在图构建阶段通过 `conan/internal/model/requires.py` 的
`process_package_type()` 为不同包类型强制 trait。该函数只覆盖五类：

| package_type | run trait |
|---|---|
| application | True |
| shared-library | True |
| static-library | False |
| header-library | False |
| build-scripts | True |

**`PackageType.PYTHON`（字符串 `"python-require"`）不在 if/elif 链中**，因此该节点的
`run` trait 保持 `None`，等价于 `False`。随后
`conan/internal/graph/graph_binaries.py::_skip_binaries()` 判定该节点不在
root 的 run 可达集内，将其标记为 `BINARY_SKIP`：既不拉取二进制，也不为其生成
runenv（PYTHONPATH）。

对纯 Python CLI/库而言，所有运行时 Python 依赖都是"run 时才需要"，
一旦被 SKIP，消费端必然 ImportError。

**旧式补丁无效**：Conan 1.x 的 `self.env_info.PYTHONPATH.append(...)`
（部分历史配方如 `chardet/5.2.0`、`soupsieve` 仍在使用）在 Conan 2 中已是 no-op，
无法把依赖重新拉回图里。

## 修复方案（推荐，优先级 1）

在**消费者配方**里双重补齐，不改依赖包配方：

1. 对每个 conan 直依赖显式声明 `run=True`：

```python
def requirements(self):
    for ref in CONAN_REQUIRES:
        self.requires(ref, run=True)
```

2. 把**传递**的运行时依赖提升为直依赖，并同样标 `run=True`。
这些包本配方不直接 import，但依赖包会在运行时 import 它们
（例如 requests → chardet/idna/urllib3/certifi，beautifulsoup4 → soupsieve）：

```python
CONAN_REQUIRES = [
    "beautifulsoup4/4.15.0",
    "click/8.4.2",
    "python-dateutil/2.9.0.post0",
    "requests/2.22.0",
    "wcwidth/0.2.12",
    # 传递运行时依赖显式提升（python-require trait 缺口）
    "chardet/5.2.0",
    "soupsieve/2.4.1",
    "idna/3.18",
    "urllib3/2.7.0",
    "certifi/2026.7.22",
]
```

要点：`run=True` 让节点进入 root 的 run 可达集；提升为直依赖保证即使中间层
不再 require 也不会丢。

## 验证

```bash
conan graph info --requires=toot/0.52.1@ohpcd/stable \
  -pr:a ci/conan/profiles/ohos-aarch64 -f json \
  | python3 -c "import json,sys; d=json.load(sys.stdin); \
      print([(k, v.get('binary')) for k,v in d['graph']['nodes'].items() if 'SKIP' in str(v.get('binary'))])"
# 期望输出: []        （修复前: 9 个 → 直依赖 run=True 后 6 个 → 提升传递依赖后 0 个）
```

外部消费者端验证退出码：

```bash
conan install --requires=toot/0.52.1@ohpcd/stable \
  -pr:a ci/conan/profiles/ohos-aarch64 --build=missing; echo "exit=$?"   # 期望 0
```

## 回退方案（优先级 2）

在 conan 内部给 `process_package_type()` 补 `PackageType.PYTHON → run=True`
分支，从根上消除缺口。但这属于修改工具链，需上游 conan 或社区适配版发版，
不能作为本仓库配方的交付路径，仅记录为长期修复方向。

## 禁止做法

- ❌ 用 `print`/`pass` 空壳测试掩盖 ModuleNotFoundError（PF3/CI L0c 会拦，且
  失败在发布后才暴露）
- ❌ 继续用 Conan 1.x `self.env_info.PYTHONPATH` 打补丁（Conan 2 下 no-op）
- ❌ 手改 `.ci-result.json` 或伪造验证结果绕过 SKIPPED 断言
