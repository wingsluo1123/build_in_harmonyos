# 并行阶段吞吐必须先归约关键路径耗时，不能取最大或平均局部速率

> 状态：DRAFT（路径 B 知识库扩展候选）｜来源：mdtest/1.9.3 HarmonyOS PC 适配｜日期：2026-10-16
> 候选编号：E591｜机器可读层：`E591-draft-2789.kv`

## 结论

对屏障协调的并行阶段，整体吞吐是：

```text
所有参与者完成的总操作数 / 阶段关键路径耗时
```

不能先让每个 rank 用总操作数除以本地耗时，再对这些局部速率取最大值或平均值。倒数是非线性变换：最大局部速率选择的是最快 rank；局部速率算术平均也不等于总操作数除以 makespan。应保留时间，再在时间域归约。若每个 rank 的分子完全相同且耗时为正，取局部速率最小值与取最大耗时数学等价；本知识不把这一特例误判为错误，但仍推荐时间域表达以保留明确的阶段契约。

## 稳定症状与机械触发条件

典型症状不是崩溃，而是各参与者计时窗口或生产耗时存在差异时，基准报告明显高于端到端墙钟可实现的吞吐。源码同时满足下列条件时应审计：

1. 多个 rank/worker 由 barrier 或 phase completion 同步；
2. 每个执行单元先计算 `operations / local_elapsed`；
3. 后续对该 rate 做 `MAX`、`SUM/size` 或其他局部统计；
4. 输出却命名为整体阶段吞吐，而非 rank-local 分布。

可先扫描：

```sh
rg -n 'MPI_(All)?Reduce|MPI_MAX|MPI_SUM|rate|throughput|elapsed|Barrier' src
```

## mdtest 根因

mdtest 1.9.3 的目录和文件阶段在每个 rank 执行：

```c
local_rate = items * communicator_size / local_elapsed;
```

随后 `summarize_results()` 对所有 rank 的 `local_rate` 取最大值。若 rank 0 用时 0.7 ms、rank 1 用时约 1 s，汇总选择 rank 0，虽然整个屏障阶段必须等待 rank 1。

正确实现先在同一个 `testcomm` 内执行：

```c
MPI_Allreduce(&elapsed, &critical_elapsed, 1, MPI_DOUBLE, MPI_MAX, testcomm);
rate = total_operations / critical_elapsed;
```

无屏障 `-B` 模式继续保留局部速率语义，不扩大修复范围。

## 三臂真机实证

共同条件是 HarmonyOS PC aarch64、MPICH 2 ranks、每 rank 创建 4 个文件、一次迭代。签名 PMPI interposer 在文件阶段起始 barrier 已返回、rank 1 采集起始时间并执行首个文件操作之前延迟一秒，并输出 `rank=1 wtime_call=3 usec=1000000`；它不替换生产统计实现。rank 0 已进入生产阶段并最终在结束 barrier 等待，因此其本地 elapsed 覆盖该阶段关键路径。本实验明确复现 barrier 邻近的调度偏斜，不声称已实测慢目录或慢存储。

| 臂 | 算法 | 结果 |
|---|---|---:|
| A 原始 | 局部速率取最大值 | 11208.406 ops/s |
| B 伪修复 | 局部速率取算术平均 | 5291.072 ops/s |
| C 正确 | 最大 elapsed 后计算 `8/max_elapsed` | 7.994 ops/s |

理论值约为 `8 operations / 1 second = 8 ops/s`。原始臂和伪修复臂均把等待最慢 rank 的阶段报告成数千 ops/s；正确臂与关键路径一致。共同命令、对象哈希、Arm B 精确差异和证据边界见 `archives/m/mdtest/1.9.3/reports/path-b-evidence.md`。

消费者回归直接执行最终包内 `mdtest`，断言 `0 < File creation rate < 12`。撤销耗时归约补丁后，同一输入恢复为虚高速率并稳定失败。

## 正确修复模式

同步同起点、局部只记录 elapsed 时：

```c
global_elapsed = allreduce_max(local_elapsed);
global_rate = total_operations / global_elapsed;
```

各执行单元起点也可能不同，且时间戳来自统一或已校准、可跨执行单元比较的时间基准时，可使用：

```c
global_start = reduce_min(local_start);
global_finish = reduce_max(local_finish);
global_rate = total_operations / (global_finish - global_start);
```

barrier 只协调执行顺序，并不自动同步不同节点的时钟。若时间戳不可比较，应先完成时钟校准，或改用各执行单元本地 elapsed 及符合产品定义的关键路径归约，不能直接相减跨节点时间戳。

现代 IOR 的生产结果归约提供独立源码佐证：它在 communicator 中分别归约最早开始和最晚完成，再用总操作量除以全局时间跨度。它证明这一机制跨并行文件系统基准复用，但不替代 mdtest 的目标端三臂。

## 为什么直觉修复错误

### 取最大局部速率

`max(total/local_elapsed)` 等价于 `total/min(local_elapsed)`，恰好采用最快参与者的时间，与 barrier 阶段的关键路径相反。

### 取局部速率平均

`mean(total/local_elapsed)` 仍是倒数的平均；只要执行时间不完全相同，就不等于 `total/max(local_elapsed)`。本次反例仍高估约 500 倍。

### 取最小局部速率的特例

当所有 rank 使用完全相同的正分子 `total` 时，`min(total/local_elapsed)` 等于 `total/max(local_elapsed)`，因此数值上可以得到正确结果。但它把正确性隐含在“分子相同”的前提中；工作量不均衡或需归约起止时间时不再通用，所以生产修复仍应直接表达时间域契约。

### 给所有 rank 同时 sleep

所有参与者等量变慢不能证明聚合器选择的是最慢 rank。回归必须只对一个已知 rank 制造可控偏斜，并验证最终报告随该 rank 变化。

## 适用与不适用边界

适用于 MPI collective、线程池批次、GPU/多设备同步阶段、分布式 map/reduce 阶段，以及任何整体完成必须等待最慢参与者的 benchmark。

不适用于：

- 明确输出每 rank 独立速率分布；
- 没有阶段同步语义的异步稳态流；
- 统计目标是 p50/p99 局部延迟而非整体吞吐；
- 工作量不均衡且 `total_operations` 尚未先正确求和的场景，此时还需同时归约工作量；
- 使用跨节点开始/结束时间但时钟没有统一或校准的场景，barrier 不能替代时钟同步。

## 查重差异

检索覆盖正式图谱、`knowledge/drafts/`、MPI/MPICH 归档笔记和既有 benchmark 条目。现有 MPICH 条目验证 `MPI_Allreduce` 能工作，但没有讨论“先算速率再归约”导致的统计语义错误；现有关键路径条目多指依赖或构建顺序，也不涉及并行 makespan。未发现同时覆盖“局部速率最大/平均伪修复、时间域归约、确定性慢 rank 回归”的既有知识。
