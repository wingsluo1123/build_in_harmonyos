# E671（草稿）: KCountry 运行时数据依赖进入构建期测试——iso-codes 直接依赖 + GenericDataLocation 数据部署组合（kcontacts5 5.116.0 实证）

> 来源：PR #14832（任务卡 #14897，j669539）· kcontacts5/5.116.0 · 2026-10-07
> 触发器：④构建组合方案

## 一、问题面（什么时候撞上）

KDE/KF5 库的链接关系不需要 iso-codes（无 ELF 依赖），但其上游 autotest 里
存在 KCountry 系函数（`Address::countryToISO` / `Address::ISOtoCountry`、
`AddressFormatRepository` 校验）——KCountry 在**运行时**经
`QStandardPaths::GenericDataLocation` 读 iso-codes 的 JSON 国家表与翻译目录。
「库本身零依赖、测试却要数据」的组合在 OHOS conan 交叉构建图里暴露两层独立故障：

| 层 | 故障 | 表象 |
|---|---|---|
| 依赖图层 | iso-codes 仅作 ki18n5 传递依赖入图 | `self.dependencies.get("iso-codes")` 的 `package_folder` 为 **None**，部署函数直接 **TypeError** |
| 数据根层 | 测试未启用 QStandardPaths 测试模式 | 数据根是 **XDG_DATA_HOME**（非 ki18n5 自测试的 `.qttest/share`），部署位置错则 KCountry 读不到数据、countryToISO 系测试失败 |

## 二、根因

1. **conan 图语义**：传递节点（仅经他人 requires 入图）对直接消费者的
   `self.dependencies.get()` 返回节点的 `package_folder` 解析为 None——任何
   要读取依赖包内文件的部署逻辑都被迫失败；
2. **QStandardPaths 语义**：GenericDataLocation 的数据根随「被测代码是否
   调 `setTestModeEnabled`」分叉：启用→`.qttest/share`（ki18n5 自测试）；
   未启用→XDG_DATA_HOME（默认 `~/.local/share`，kcontacts 测试）。两库同
   走 iso-codes 数据注入但**部署根不同**，照抄先例必错位。

## 三、解法（可复制）

1. **requirements() 显式声明 iso-codes 直接依赖**（版本与 ki18n5 pin 一致，
   不引入图分裂）→ `package_folder` 物化，部署函数可用；
2. **_run_upstream_tests() 构造 per-test 环境**：HOME/XDG_DATA_HOME 指向
   `<build>/test-home/.local/share`，`_deploy_iso_codes_test_data()` 把
   iso-codes 包内 `share/iso-codes/json`（JSON 国家表）与 `share/locale`
   （翻译目录）**成对** copytree 进去；配 `QT_QPA_PLATFORM=offscreen` 头less
   执行 QTEST_MAIN 系用例；
3. JSON 表与翻译目录**缺一不可**——缺翻译目录时国名查询仍退化。

完整代码见 kcontacts5/5.116.0 `conanfile.py`（PR #14832）：
`requirements()` + `_run_upstream_tests()` + `_deploy_iso_codes_test_data()`。

## 四、与先例的增量（查重结论）

- **ki18n5/5.116.0**（iso-codes 直接依赖同款先例）：其**自测试**启用
  QStandardPaths 测试模式走 `.qttest/share`——本条证明**消费者测试**（kcontacts）
  未启用测试模式时部署根是 XDG_DATA_HOME，部署根判定规则首次成文。
- **DRAFT-kde-pim-testdata-iso-codes-tzdata**（main 已合入，khealthcertificate
  #10745 先例）：KF6 线走 tool_requires + XDG_DATA_DIRS 双通道注入——本条为
  KF5 线 conan 依赖图语义版（requires 直接依赖、package_folder 物化条件），
  重叠的 iso-codes 注入主题作融合上下文，KF5 线增量独立成立。
- **传递依赖 package_folder=None TypeError**：knowledge/graph/index.tsv 与
  drafts grep 零命中，全新增量。

## 五、关联知识（同 PR 验证）

1. 传递依赖节点 package_folder 语义（见 .kv related_knowledge）；
2. QStandardPaths 数据根判定速查：测试模式→`.qttest/share`；非测试模式→
   XDG_DATA_HOME。逐条核对被测库测试源码是唯一可靠判定法；
3. 后续 KF5 PIM 系列（kcaladdons、akonadi 系等同样依赖 KCountry 的库）
   可直接复用「iso-codes 直接 requires + per-test XDG_DATA_HOME 部署」组合对。

## 六、验证

- PR #14832：本机 conan create 三轮全绿（第二轮起 100% passed、第三轮
  `conan remove` 后干净重跑可复现）：BUILD_TESTING=ON 注册上游 32 例
  ctest 全部真实执行，KCountry 系 addresstest（countryToISO/ISOtoCountry）
  与 addressformattest（repository 校验）在 iso-codes 数据部署后真实跑通，
  **无任何豁免**；test_package 26/26（消费者二进制 OHOS 真实执行）。
- 第一轮失败实录：`_deploy_iso_codes_test_data` 从传递依赖取 None folder
  报 TypeError → 显式直接依赖后第二轮全绿（notes.md 踩坑记录 1）。
