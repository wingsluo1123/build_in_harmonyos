# E688 — Qt6 qmake 工程 OHOS 构建：QMAKE_LRELEASE 显式指向 qttools 的 lrelease + host 工具运行期注入 SDK libc++_shared.so

## 错误特征

1. **qmake 生成 Makefile 后 make 阶段失败**：
   ```
   <qtbase>/bin/lrelease qabc_en.ts -qm locale/qabc_en.qm
   make: <qtbase>/bin/lrelease: No such file or directory
   make: *** [Makefile:414: locale/qabc_en.qm] Error 127
   ```
2. **conan create 干净环境中 qmake6/lrelease 运行期加载失败**：
   ```
   Error loading shared library libc++_shared.so: (needed by <qtbase>/bin/qmake6)
   Error loading shared library libc++_shared.so: (needed by <qtbase>/lib/libQt6Core.so.6.11.1)
   Error relocating <qtbase>/lib/libQt6Core.so.6.11.1: _ZTISt12length_error: symbol not found
   ```

## 触发条件

- 构建系统: qmake（qmake6），Qt6 工程
- 阶段: make（翻译编译 updateqm 目标）/ conan create 构建工具运行期
- 依赖: qtbase/6.11.1 + qttools/6.11.1（ohpcd 制品仓）
- 平台: HarmonyOS PC（OHOS，aarch64）

## 根因分析

1. **qtbase 包不含 LinguistTools 工具**：qtbase conan 包只装 Core/Gui/Widgets 及 moc/rcc 等基础工具，lrelease/lupdate 由 **qttools** 包提供。qmake 生成 Makefile 时，`updateqm` 规则取 `$$[QT_INSTALL_BINS]/lrelease`（即 qtbase 包内 bin/），该路径不存在 → make 执行翻译编译时失败（Error 127）。
2. **host 工具是 OHOS 本机 ELF**：qtbase/qttools 的 bin 工具（qmake6/lrelease/moc）与 libQt6Core.so 都是 OHOS 本机动态 ELF，DT_NEEDED 含 `libc++_shared.so`，该库只在 OHOS SDK `llvm/lib/aarch64-linux-ohos/` 目录提供（编译器工具链目录，不在 qtbase 包 lib 内）。conan build 环境若未将该目录加入 LD_LIBRARY_PATH，工具运行即报 symbol not found。

## 解决方案

### 推荐方案

1. **QMAKE_LRELEASE 显式覆盖**：qmake 命令行传 `QMAKE_LRELEASE=<qttools>/bin/lrelease`，使生成 Makefile 的 updateqm 规则指向 qttools 包内的 lrelease：
   ```bash
   qmake -config release "QMAKE_LRELEASE=$QTT/bin/lrelease" $SRC/qabc.pro
   make -j1
   ```
2. **SDK libc++ 目录注入**：在 conanfile 的 generate()/build()/test_package 的 test() 中用 Environment 将 SDK libc++ 目录（glob `/data/service/hnp/ohos-sdk.org/*/ohos/native/llvm/lib/aarch64-linux-ohos`）与 qtbase/qttools 的 lib 目录 prepend 到 LD_LIBRARY_PATH（fingerterm 1.4.16 同款做法）：
   ```python
   env = Environment()
   for sdk_lib in self._ohos_sdk_lib_dirs():
       env.prepend_path("LD_LIBRARY_PATH", sdk_lib)
   for pkg in ("qtbase", "qttools"):
       dep = self.dependencies[pkg]
       if dep and dep.package_folder:
           env.prepend_path("LD_LIBRARY_PATH", os.path.join(dep.package_folder, "lib"))
   env.vars(self).save_script("conanbuild_qt_libs")
   ```
3. **test_package 同样注入**：test_package 的 test() 运行 qabc 二进制时，同样需要 SDK libc++ + Qt 库路径（与构建期相同问题），在 test() 中注入后以 `env="conanrun"` 运行 test.sh。

### 禁止做法

- ❌ 不修改 qtbase 包内容、不向 qtbase 包 bin 复制 lrelease（违反制品仓只读/发布物一致原则）
- ❌ 依赖本机 shell 已有 lrelease（CI 干净环境不保证存在）
- ❌ 硬编码 SDK 路径而不 glob（不同 SDK 版本目录不同）

## 验证

```bash
# 构建（qmake + make，QMAKE_LRELEASE 指向 qttools）
QT_INSTALL_LIBS="$QBASE/lib" "$QBASE/bin/qmake6" -config release "QMAKE_LRELEASE=$QTT/bin/lrelease" qabc.pro
make -j1            # → exit 0，生成 qabc ELF arm64 + locale/qabc_en.qm + qabc_fr.qm

# 运行验证（offscreen 平台，注入 SDK libc++ + Qt 库）
QT_QPA_PLATFORM=offscreen ./qabc --version   # → "QAbc 1.16 (stable)" exit 0
QT_QPA_PLATFORM=offscreen ./qabc --help      # → 用法帮助 exit 0

# conan-verify 全部门禁
ohc-run.py conan-verify qabc 1.16            # → G1-G4 全部 PASS
```

实测结果：qabc 1.16 conan-verify G1-G4 全部通过；test_package 自研 3 项断言（--version/--help/offscreen 渲染快照）全部通过。

## 适用边界

- 适用：Qt6 qmake 工程（含 TRANSLATIONS/updateqm），通过 qtbase+qttools conan 包在 OHOS 构建；任何需要运行 qtbase/qttools host 工具的 OHOS conan 构建。
- 不适用：纯 Qt5（qt5-qtbase 自带 lrelease 或路径不同）；CMake Qt 工程（走 Qt6LinguistTools_DIR 配置，见 E487/E542）。
