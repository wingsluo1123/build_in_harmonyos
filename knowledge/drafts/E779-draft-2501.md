# Initialize a dependency's default runtime context before a consumer constructor

An installed-library consumer may compile, link and enter `main()` successfully but still crash when its first object is constructed. In this case the consumer printed its entry and read the library version, then crashed inside `nvnc_new()`. The constructor calls `aml_require_workers(aml_get_default(), -1)`. The default AML context is null until the application sets it; upstream NeatVNC examples call `aml_new()` and `aml_set_default()` before `nvnc_new()`.

The correction is in the consumer fixture, not the library package: declare the AML dependency, create an AML context, make it the default, construct and destroy the NeatVNC object, then clear and unref the context. This is a reusable diagnostic for event-driven libraries whose public constructors obtain a default event loop, scheduler, allocator or similar process-local dependency. After proving the binary loads, inspect constructor call order and upstream application examples before changing linker flags or signatures. It does not apply when the crash occurs before `main()`, during dynamic loading, or after a valid context has already been installed; those need their own loader or library diagnosis. The consumer check does not replace or inflate the upstream test denominator.
