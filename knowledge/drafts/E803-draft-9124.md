# E803 — 上游 target_link_libraries 裸链库名无法解析到 Conan 包：须改为 CMakeDeps 目标名

## 错误特征

```
fatal error: 'xcb/xcb.h' file not found
```
或链接期：
```
ld.lld: error: unable to find library -lxcb
```
上游 `src/CMakeLists.txt` 里是 `target_link_libraries(${library_name} PUBLIC xcb)`。

## 触发条件

- 构建系统: cmake（Conan 交叉编译，目标平台无该系统库）
- 阶段: configuration / compilation / linking
- 上游特征: 把系统库名直接写进 `target_link_libraries`（不 `find_package`），而该库
  在目标平台上改由 Conan 制品提供

## 根因分析

`target_link_libraries(... PUBLIC xcb)` 把 `xcb` 当**库名**交给链接器（`-lxcb`）。
OHOS 无系统 X11，libxcb 由 Conan 制品提供；而 Conan 包（libxcb/1.17.0.1）不自带
CMake config，其目标由 CMakeDeps 生成，名称为 `libxcb::xcb`（组件）与
`libxcb::libxcb`（全局）。裸名既不会自动带上 Conan 的链接目录，也不会带上头文件
include 目录，于是编译期缺 `xcb/xcb.h` 或链接期找不到 `-lxcb`。

注意目标名必须以**制品 recipe 的 `package_info()`** 为准：
libxcb 实际是 `libxcb::xcb`，不是想当然的 `xcb::xcb`。

## 解决方案

### 推荐方案

在补丁里把裸库名替换为 `find_package(<pkg> REQUIRED)` + 该包 CMakeDeps 生成的目标名
（组件优先；不确定组件时用全局目标）：

```cmake
  else()
    find_package(libxcb REQUIRED)
    target_link_libraries(${library_name} PUBLIC libxcb::xcb)
  endif()
```

目标名从制品 recipe 的
`cpp_info.components[...].set_property("cmake_target_name", ...)` 读出，勿凭记忆猜。

### 禁止做法

- ❌ 猜测目标名（如写成 `xcb::xcb`）。
- ❌ 在配方里手工 `-I`/`-L` 拼接依赖目录绕过。

## 验证

```bash
conan create <pkg> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 2>&1 \
  | grep -E "xcb.h.*file not found|cannot find -lxcb|unable to find library -lxcb"
# 无输出即修复
```
