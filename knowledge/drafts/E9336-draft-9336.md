# E9336 — Unicode CLI选项与反斜杠转义的文本层边界

草稿，未纳入正式知识库。来源：pawk 0.8.1 / 上游v0.8.1 commit `d60f78399e8a01857ebd73415a00e7eb424043ab`。发行版本为0.8.1，内部模块与pyproject为0.8.0，保留该差异。

## 错误特征与触发条件

Python CLI通过optparse取得的选项已是Unicode `str`。这些选项又承诺支持字面反斜杠转义（如 `\t`），直接将str送入 `codecs.decode(value, 'unicode_escape')` 会隐式转成UTF-8字节再按escape解码，损坏非ASCII字面文本。pawk将同一模式用于输入分隔符 `-F`、输出分隔符 `-O`、输出行分隔符 `-L`。

实际保存的主机原例：输入 `a汉b\n`，选项 `-F 汉 'repr(f)'`，原版rc0却输出 `['a汉b']`，未拆为 `['a', 'b']`。退出码0不能证明消费者语义正确。这是跨平台解码层问题，未证明OHOS独有，也不是缺locale/iconv数据。

草稿签名 `PAWK_UNICODE_DELIMITER_MISMATCH` 是本次安装包消费者仅在stdout与既定预期不同时输出的诊断标识；它不是原上游stderr或已观察到的OHOS日志。原失败不抛异常，需要实际输入/输出比较；无该诊断时不能只靠正常输入含Unicode匹配本条。

## 根因与最小修复

保持文字层，将已经Unicode的选项先编码为 `raw_unicode_escape` 字节，再解释 `unicode_escape`：

```python
codecs.decode(value.encode('raw_unicode_escape'), 'unicode_escape')
```

修复仅应用到 `Context.from_options` 的三行：`options.delim`、`options.delim_out`、`options.line_separator`；不改原命令解析、表达式执行、版本或上游测试assert。该编码对字面Unicode提供escape decoder能还原的表示，同时保留原ASCII反斜杠语义。不要改成UTF-8 encode后再unicode_escape，也不要删转义支持只让汉字场景通过。

## 近邻增量与边界

领前核对的正式E039讨论musl iconv的IGNORE/TRANSLIT差异，E023讨论locale/collation数据；均未覆盖已Unicode选项仍需兼容ASCII反斜杠语义的解码层。增量在于同时保留两个已有CLI合同，以真实消费者输出核验rc0的静默语义错误；限定已有近邻证据，不声称全库独占或保证B接受。

适用范围为Python3.7+已经Unicode的CLI文字选项，且明确要求escape语法；不用于任意二进制、未知外部编码或未经约定的escape协议。只验证上述四个场景，不宣称覆盖所有Unicode与转义组合，也未提供自动修复工具。
