# 无序集合进入连续整数分组后的长度过滤误丢

来源为 port-for 1.0.0 的 PyPI sdist，SHA256 `404d161b1b2c82e2f6b31d8646396b4847d02bf5ee10068c92b7263657a14582`，GCW task9665。上游 <https://github.com/fizyk/port-for>，Python>=3.10，MIT。本条是跨环境的数据顺序前置条件，不声称鸿蒙特有缺陷。

## 症状与触发条件

`good_port_ranges(ports, min_range_len=20, border=3)` 应保留足够长的连续端口区间。传入 `set(range(1000,1040))` 时，本次Windows Python3.11.0rc2迭代次序实际为1024..1039、1000..1023，原版返回 `[]`，预期为 `[(1003,1036)]`。回归测试实际失败行是 `E assert [] == [(1003, 1036)]`。

集合不保证数值排序，具体迭代次序取决于实现和集合状态；有序低值集合偶然通过并不能建立API正确性。仅在输入进入连续数值分组时需要排序，集合的其他用途无须一概排序。

## 根因

`port_for/api.py` 将set转list后交给 `utils.to_ranges`。实际源码使用 `itertools.groupby(enumerate(lst), lambda t: t[1]-t[0])`，即value-index（与index-value只差符号）。数值递增的连续整数段键值相同；任意无序序列没有该不变量。

示例 `[2,1,3]` 的键为2、0、1，得到三个单点段；先数值排序后键都为1，得到 `[(1,3)]`。本次40个连续端口因迭代折返被拆为长度差15和23的两段。原算法门槛为 `min_range_len + border*2 = 26`，两段都被丢弃。这里保留原算法使用端点差的长度定义，不趁本次修正改变包含边界或长度语义。

## 最小修法与使用

在调用边界把 `utils.to_ranges(list(ports))` 改为 `utils.to_ranges(sorted(ports))`。utils分组器、端口排除、范围包含、border、最小长度、长段排序及socket策略保持原字节。对应补丁：`archives/p/port-for/1.0.0/patches/0001-sort-port-set-before-range-grouping.patch`，同时给原tests/test_cases.py追加一条回归，原22项测试的断言与原跳过条件保持。

在准确sdist根应用补丁后执行：

```sh
patch -p1 < 0001-sort-port-set-before-range-grouping.patch
python -m pytest tests -ra
```

输入为唯一整数端口集合；输出为沿用原API语义、剔除边界并按原策略排序的区间列表。适用于无序整数来源的连续区间识别，例如编号段压缩、空闲块或ID池；不用于字符串排序、自定义比较、不连续数据填洞，或依赖输入顺序的业务分组。输入带重复值的通用Iterable不在本次set API修正范围内。

禁止通过删除原断言、模拟set迭代已排序、减少min_range_len或修改端口探测来掩盖故障。修复不提供自动化改写：`rec_auto_fix=false`。
