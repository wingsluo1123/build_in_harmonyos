# E9945 — 已发布混合 CLI/库依赖的下游 traits 边界

## 错误特征
依赖包含真实公开头和库，CMake imported target 也存在，但下游编译找不到头文件；生成目标里的 include/lib 数据为空，同时 Conan 提示 `package_type 'application' is defined`。这与未发布 binary、错误头名、损坏安装物不同。

## 触发条件
- Conan 2 + CMakeDeps，已发布混合 CLI/开发库包。
- 下游要消费开发接口，而上游仍按 application 建模。

## 根因分析
Conan 的 dependency traits 决定是否向当前消费者传播头和链接库。`application` 的默认值不承诺开发接口，即使上游的 `cpp_info` 正确、包内也确有头和库，默认依赖边仍可阻止生成器传播。只改 CMake `find_package()` 不会改变 traits。

## 解决方案

### 推荐方案
1. 核对已下载 binary 的公开头、库、ABI 与实际 `cpp_info`。仅有工具或内部库的包不适用。
2. 如果修复上游需要等待重新发布，且其公开接口确实完整，在当前下游窄声明 `self.requires("dependency/version", headers=True, libs=True)`。
3. 继续仅用 CMakeDeps imported target，不加缓存绝对 `-I/-L/-l`。
4. 对比修复前后生成目标、编译和链接命令，执行完整原生上游测试和安装包消费者。traits 不修复 ABI、不补缺头/库，也不替代上游长期正确建模。

### 禁止做法
- 不擅改、覆盖或重新发布已发布依赖。
- 不将库从系统目录或其他缓存复制进当前包；不硬编码缓存路径假装传播已修复。
- 不对纯 CLI 包盲目启用开发能力。
